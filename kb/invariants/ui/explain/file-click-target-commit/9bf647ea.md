# Explain 'files affected' clicks navigate to the VIEWED (active) commit, not the open fact's anchor commit

In the Explain history panel, a click on a 'files affected' row MUST navigate to the commit whose changeset that file belongs to (the viewed/active commit shown in the panel), NOT the currently-open fact's commit_hash anchor. FactHistoryPanel renders the file rows from the detail of `activeCommit` and passes it through onFileClick(path, activeCommit); ExplainView navigates to {path, commit: activeCommit}.

The bug (PR #77): onFileClick navigated to fact.commit_hash (the open fact's anchor). When the active/viewed commit differed from the anchor — which happens whenever the panel falls back to the latest version, or you browse across commits — the sibling file often did not exist at the anchor commit, so the fact read 404'd (and /incoming /outgoing 500'd/404'd). Always anchor a file-row navigation to the commit you are viewing, where that file provably exists. Related: the history panel also selects the active commit on open with a prefix-tolerant hash match, falling back to the latest version when the opened commit is not one of the fact's versions.

# Timeline 'files affected' clicks navigate to the VIEWED (active) commit, not the open fact's anchor commit

In the history timeline (LeftPanel -> TimelineNav), a click on a 'files affected' row MUST navigate to the commit whose changeset that file belongs to — the viewed/active commit shown in the panel — NOT the currently-open fact's anchor. TimelineNav renders the file rows from the detail of `activeCommit` and calls `onOpenFileAt(f.path, activeCommit)`; LeftPanel passes `activeCommit={selectAnchorCommit(state)}`; `useTimeTravel.openFileAt(path, commit)` dispatches `APPLY_NAV` with `asOf:{ mode:'history', commit }`. Self rows and deleted-file rows are disabled (`isDisabled = isDeleted || isSelf`), so navigation only targets a commit where the file provably exists.

The bug (PR #77): the old implementation navigated to `fact.commit_hash` (the open fact's anchor). When the viewed commit differed from the anchor — the panel fell back to the latest version, or you browsed across commits — the sibling file often did not exist at the anchor, so the fact read 404'd (and /incoming /outgoing 500'd/404'd).

WHAT THIS DOES NOT MEAN: the original ExplainView.tsx / FactHistoryPanel.tsx / onFileClick / history-file-row named in this fact's earlier revisions NO LONGER EXIST — they were deleted in commit 0074f640 ('unify now/history into one surface; delete ExplainView overlay'). Do not look for onFileClick or a history-file-row test id; the current surface is TimelineNav.tsx with onOpenFileAt and data-testid='timeline-file-row'. The INVARIANT (anchor to the viewed commit, never the fact's commit_hash anchor) is unchanged; only the components moved.

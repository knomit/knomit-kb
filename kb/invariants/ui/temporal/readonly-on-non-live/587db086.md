# !isLive(state) MUST disable all mutating endpoints — anchor not live = refuse repo mutations

When state.asOf.mode != 'live', every mutating endpoint in the UI is disabled with tooltip 'Read-only — anchor is not live.' (READ_ONLY_TITLE in web/src/state.ts): POST/PUT/DELETE /facts (CRUD), POST /synthesis-runs, POST /index-rebuilds, PUT/DELETE /origin, POST /origin-sessions/.../apply, POST .../commit. Origin and jobs flows are gated for the same reason fact CRUD is — they all write to repo state. RULE (forward-looking): any keyboard shortcut added later that triggers a mutation MUST check isReadOnly in the same handler path that disables the equivalent button — single source of truth, no drift. As of HEAD no mutating keyboard shortcuts exist (RightPanel's only keydown handlers are Escape/Enter for the retract-confirm modal and ArrowLeft to blur the panel); the retract button itself gates on isReadOnly. isLive and isReadOnly are equivalent today but exist as distinct named selectors so isReadOnly reads honestly at call sites when mode:'diff' (also read-only) is added.

# SET_CONTEXT to the repo already in state keeps branch and headCommit, because App's status bootstrap is keyed on the repo name and would not re-run

In web/src/state.ts, `SET_CONTEXT {kind:'repo', repo}` with `repo === s.repo` resets navigation (filters, open fact, nav stack, remote errors) but keeps `branch` and `headCommit`. A different repo clears both, and that clearing is what makes App's bootstrap effect (deps `[state.repo, bootNonce]`) fetch the new repo's status.

The same-repo case arises when leaving a lens for its own write repo (the remote banner's Reconnect, a rail pick), because a lens context already sets `state.repo` to its write repo. Clearing the branch there stranded Browse on its "Opening..." placeholder for good, with the head poll and the branch event stream stopped (they bail on an empty branch).

Consequence: any new route that must force a status re-read for the SAME repo cannot rely on SET_CONTEXT; bump `bootNonce` instead.

WHAT THIS DOES NOT MEAN: it is not "SET_CONTEXT preserves the branch". A switch to another repo still clears it.

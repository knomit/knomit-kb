# knomit_update's gates on every call: argument checks first (unknown `updates` keys, updates.title non-blank and single-line); the write is a compare-and-swap on the blob it read; the final serialised bytes must parse and re-serialise identically (a CR LF in the body fails); an edit must not turn an even count of ``` fence lines odd; title and body edge spaces are trimmed, not rejected; ontology rules still skip .knomit/ paths

`knomit_update` (internal/mcp/update.go) applies these, on BOTH the `updates.body` path and the `ops` path:

0. **Argument checks, before the file is even looked up.** Unknown keys in `updates` are refused (rejectUnknownObjectKeys, naming every key and the valid set), then `updates` and `ops` are decoded strictly, then `updates.title`, when sent, must pass `fact.ValidateTitle`: not blank, and no line break (\n or \r) ANYWHERE, checked on the raw value — a leading or trailing newline is refused, not trimmed away. So a bad key or a bad title is reported as that even when the path is also wrong, and a later ontology or refs error cannot mask it. SerializeFact applies ValidateTitle again for every write path.
1. **Edge whitespace is trimmed, not refused.** `ParseFact` trims the title and body, so the file format cannot store leading or trailing whitespace on either. The handler trims both before the gates below, so edge spaces and tabs on a title, and trailing newlines on a BODY, are not errors. `ops[].delta` is measured on the trimmed form, so it reports bytes actually stored.
2. **Fences — judged on the EDIT, only when the body changed** (`updates.body` or `ops` present): `fact.CheckFenceEdit(before, after)` refuses only when the body had an EVEN number of lines whose first non-blank characters are ```` ``` ```` and now has an ODD number. `before` is the existing body on both paths. A body that was already odd (valid CommonMark can be: a ```` fence quoting a ``` line, ``` inside a ~~~ fence, indented code) is never refused, and odd→even is a repair. It is a parity count, not a CommonMark parse.
3. **Ontology rules** (`fact.ValidateFact`) run for public facts and are skipped for `.knomit/<area>/` paths, unchanged.
4. **Roundtrip on the FINAL bytes** (`checkRoundtrip`, after the refs gate and `SerializeFact`): `ParseFact` then `SerializeFact` must reproduce the serialised string byte for byte. A CR LF pair in the body (ParseFact normalises it) fails it; the error names the field (title, body, else frontmatter) and quotes where sent and read-back first differ. It runs on every update, frontmatter-only ones included. A newline in the title no longer reaches it — step 0 refuses it first.
5. **The write is a compare-and-swap.** The handler reads the fact with `ReadFactOpts{WithHash: true}` and commits through `FactIndex.WriteFactIfUnchanged`, which re-checks that the path's blob on the branch tip is still the one read INSIDE the branch write lock. If another write landed in between, nothing is written and the call is refused with `current_commit` = the write-branch tip. This holds with or without `if_commit`: without it, ops computed from stale bytes would otherwise silently overwrite the newer write. `if_commit` itself (bytes at that commit must equal bytes now) is checked before the write; the CAS is what makes it atomic.

Consequence: a REST or pipeline write path that wants the same bar should call `fact.CheckFenceEdit`, do the same parse/re-serialise compare, and write through `WriteFactIfUnchanged` with the blob it read. The order in code is argument checks → file lookup → if_commit → fences → ontology → refs gate → roundtrip → CAS write, so when several fail, the earliest is reported.

WHAT THIS DOES NOT MEAN: only knomit_update runs the fence and roundtrip gates — knomit_learn, the pipelines and REST do not, and SerializeFact does not (SerializeFact DOES run ValidateTitle, for every write path that serialises a Fact). Moving the fence and roundtrip gates into SerializeFact is a known follow-up, deliberately not done in the PR that introduced them. There is no shrink guard, no anchor-mid-word check, no dry run — those were rejected in the ops decision.

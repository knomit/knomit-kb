# knomit_learn `settles: [{path, outcome}]` is per-fact, request-only and never stored; a declared outcome beats similarity subsumption, and a second fact matching a settled or already-taken hypothesis gets a note and no citation

THE CONTRACT (#648, merge 2782d21c; internal/edge/mcp/learn_settles.go, learn.go).
- `settles` lives INSIDE a fact object (facts[i].settles), exactly like distinct_from. It is request-only: not stored on the fact. A TOP-LEVEL `settles` (or distinct_from) is refused by the unknown-arguments check, never silently dropped.
- Each entry is {path, outcome}; outcome must be `confirmed` or `refuted`. The fact cites the hypothesis in its refs and the hypothesis is deleted by the SAME BatchWriteFacts commit, whose last paragraph carries `Knomit-Outcome: <path> <outcome>`.
- REFUSED (whole call, nothing written): a bad outcome; an empty path; a path that is missing on the branch or is not a hypothesis; a settler that is itself a hypothesis; the path also in THAT fact's distinct_from (settling retracts, distinct_from keeps apart); the path also in the call's own `retract` (drop it from retract); two facts giving CONFLICTING verdicts for one hypothesis.
- A declared outcome WINS over similarity subsumption: settled paths are added to `retracting`, so the dedup merge and the same-subject stage decline them and the hypothesis is not reported a second time. Undeclared similarity subsumption keeps its `settled:` commit line and response note and writes NO trailer.
- NOTES, never silent declines. A different fact whose nearest dedup match is a hypothesis another fact settles in the same call gets ONE note and no citation: `fact N: matched hypothesis <path>, settled by fact M in this call.` A fact whose nearest match an EARLIER fact already took (merge or hypothesis subsumption) gets `fact N: matched <path>, already taken by fact M in this call.`; `consumed` records the taker's index. Each such fact is written at its own path.
- LOCK. Every settled path is a mustExist precondition checked under the branch write lock (BatchWriteFactsMustExist), so two concurrent settles of one hypothesis cannot both commit; the loser's whole call is refused. The check at validation time (ReadFact) is NOT the lock.

WHAT THIS DOES NOT MEAN. `settles` is not a way to retract with a reason: a path in `retract` is a different instruction and conflicts. A note is not a citation: the second matcher does NOT cite the hypothesis. The undeclared similarity path is unchanged in behaviour and still records no verdict; see kb/gotchas/mcp/learn-hypothesis-report/612294ef.md.

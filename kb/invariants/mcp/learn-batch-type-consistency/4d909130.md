# knomit_learn REJECTS batches mixing observed types and inferred (hypothesis/methodology) types

knomit_learn REJECTS batches that mix observed types (observation, concept, process, principle, pattern, reference, synthesis, insight) with inferred/fabricated types (hypothesis, methodology) in a single call. Returns mcpgo.NewToolResultError('cannot mix observed types ... and inferred types ... in a single learn call') BEFORE any writes. Enforced via two booleans (hasObserved, hasInferred) populated by walking factInputs and checking 'fact.Type(fi.Type) == fact.Hypothesis || == fact.Methodology' for the inferred bucket. CRITICAL: the inferred test names ONLY Hypothesis and Methodology, so EVERY other type — including the newer `insight` (added PR #70) — falls into the observed bucket. insight is grounded (a conclusion connecting trusted facts), so it is correctly mixable with observations but NOT with hypothesis/methodology. See [[insight]]. WHY: a single cognitive operation cannot span both modes — mixing them in one commit confuses provenance and dedup. The agent must split into two separate learn calls. Empty type defaults to fact.DefaultEpistemicType (= observation) for the classification. Anti-pattern: relaxing this check — the type-safety invariants (hypothesis can't be evidence for hypothesis, etc.) depend on batch-level separation.

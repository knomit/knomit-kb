# What an MCP call leaves for a later call to resume — a tool-session cursor (knomit_query, knomit_explain, knomit_materialize) or an MCP task (tasks/get, tasks/result, tasks/cancel, tasks/list) — belongs to the ENDPOINT it was made on AND the PRINCIPAL that made it; any other owner reads it as expired / "task not found"

Rule (user ruling G2, PR fix/mcp-token-audience). The owner is ONE string, `mcp.callerOwner(ctx)` (internal/edge/mcp/owner.go): the MCP endpoint's URL path (recorded by `mcp.WithEndpoint` in the web layer's `mcpHTTPContext`, trailing `/` dropped) plus `auth.Principal.String()`.

- Tool-session cursors: `tool_sessions.owner` is written at mint (`ToolIndex.CreateToolSession(..., owner)`) and compared on resume in queryResume, explainResume and materializeResume. A mismatch answers the same expiry text as a dead cursor, and consumes nothing (the owner's next page is intact). This is IN ADDITION to the binding pin (`repo:<uid>`/`lens:<uid>`) and the read-set fingerprint, not instead of them.
- MCP tasks: mcp-go v0.45.0 keeps ONE server-wide task map keyed by MCP session id only, and knomit accepts any well-formed session id (kb/gotchas/mcp/sessions/stateless-id-manager), so the session id is not an owner. `taskOwners` records the owner in a TaskHooks OnTaskCreated hook; an OnRequestInitialization hook refuses tasks/get, tasks/result and tasks/cancel for any id the caller does not own — INCLUDING ids that never existed — with "task not found", so foreign and nonexistent are byte-identical (same JSON-RPC error object); an AfterListTasks hook filters tasks/list. tasks/* are not tool calls: neither gateBinding nor gatePermission ever sees them, which is why this lives in hooks.

The principal is the IDENTITY, not the transport: a socket/pipe peer is its OS user (`uid:<n>`/`sid:<SID>`), an OAuth token is `host:<subject>@token` (kb/architecture/oauth/token-subject). So two bridges of one user on one endpoint share cursors and tasks; one user on two endpoints, or two users on one endpoint, do not.

CONSEQUENCE: any new resumable state (a new cursor table, a new long-running job id handed back to the caller) must store callerOwner at creation and compare it on every resume. A new MCP transport must record WithEndpoint, or every call it serves owns as `" " + principal` and cannot resume across a reconnect with a different path.

WHAT THIS DOES NOT MEAN: it does not make binding HANDLES owned — a handle still belongs to the endpoint's mount and is not authorization (kb/decisions/mcp/session-binding/scoped-endpoint-bind/3408dd94.md). It does not cover knomit_review / knomit_hypothesize `session_id` (pipeline_sessions), which is looked up in the write repo's own store and is shared on purpose by work-stealing workers; that session_id is confined by BRANCH instead (Pipeline.activeSession refuses a session opened on another branch than the caller's binding write branch, reading exactly as not found; knomit_review and knomit_hypothesize pass that branch on start, current and continue alike). It does not cover self-contained cursors (knomit_changes, explain history) that hold no server state. A finished task's owner is forgotten after taskOwnerRetention (1h) and the task then reads as not found to everyone, its owner included — fail closed.

The ownership hook FAILS CLOSED (review N6): a tasks/get|result|cancel whose params it cannot decode is "task not found", and a request it cannot decode at all is refused ("invalid request") rather than waved through to mcp-go. Pinned by TestTaskOwnerHook_FailsClosedOnAnUnreadableRequest.

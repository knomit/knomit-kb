# A handle-routed call on a URL-scoped mount must not see the connection's mount session state: WithoutMountState masks BOTH the mount-session marker and the lapsed mark, and each half is separately load-bearing

On a URL-scoped mount, once a handle routes the call, the gate (resolveHandle in binding_gate.go) strips both context values with repos.WithoutMountState (experiment_binding.go): the mount-session marker AND the lapsed-experiment mark.

MARKER. Without it knomit_experiment commit/rollback through the handle runs clearMountExperiment and pulls the handle-less caller on the same connection out of ITS session-keyed experiment (and open would key on the connection): one caller's action moving another on a shared connection, the 2026-09-17 shape bounded to one repo. Removing it fails TestScopedBind_TwoHandlesOnOneConnectionAreIsolated.

LAPSED MARK. Without it, when the connection's session-keyed experiment is swept or rolled back, knomit_repos through a handle reports `lapsed_experiment` for an experiment the handle was never in: a false "you were moved". Removing it fails TestScopedBind_HandleDoesNotInheritTheConnectionsLapsedMark. (In round 1 of review this half was untested; sabotaging only it stayed green until that test was added.)

CONSEQUENCE. Checks made AFTER the gate must not rely on MountSessionFromContext alone: a resolved handle (bindingHandleFromContext != "") also proves the mount takes one (see endpointOf in repos.go). WHAT THIS DOES NOT MEAN: the mask is applied only on a scoped mount with a resolved handle; handle-less calls still see the mount state, by design.

# knomit_learn, knomit_update and knomit_retract refuse a moment_name that is not one line (any unicode.IsControl rune, U+2028, U+2029, invalid UTF-8) — it is copied into the commit message, and before #349 a line break in it let any agent write an unchecked `Knomit-Trigger:` paragraph that TrailerValue and the loop guard read

Probe P2 in the #349 RCA (origin/dev c6c2625b): the UNCHANGED learn handler with moment_name 'x\n\nKnomit-Trigger: wake\nKnomit-Trace: forged' committed 'learn: x\n\nKnomit-Trigger: wake\nKnomit-Trace: forged', and store.TrailerValue read Trigger=wake, Trace=forged — a forged loop-guard entry through the back door. checkMomentName (internal/edge/mcp/trace.go, sharing multiLineRune with the trace value rule) now refuses it in all three handlers before anything is written, so the `trace` argument, which IS validated, is the only way an agent puts a Key: value line into a commit. All three copy it into the commit message, each in its own shape: learn `learn: <moment>` (move `move: <moment>`), retract `retract(<moment>): <file>`, update `update(<moment>): <fact title>` — update dropped it (`update: <title>`) until the fix for first-mission rehearsal finding F7 (PR #396, merged as 13a785e6), which is why a corroborate:/contradict: label passed to update was unrecoverable before it. The refusal also covers a script's knomit.learn/update/retract (the host passes its moment_name to the same handlers); the host's default 'trigger:<name>' is one line. Consequence: a caller that used multi-line moment names now gets 'moment_name must be one line: U+000A at byte N'. Note that `git log --grep` matches ANY line of a message, not only the trailer paragraph, which is why every piece of agent text in a message must stay single-line.

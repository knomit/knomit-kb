# Which mounts take session state is decided from the ROUTE, never from the binding: re-pin ONLY where the URL names this repo's own agent branch, or a lens's default — never main, never a foreign agent branch, never a mount naming an experiment

Session state may choose a branch ONLY on a mount whose URL names the repo's own agent branch, or a lens's default. Never `main`, never a foreign agent branch, never a mount that names an experiment. Each exclusion is a hole that was open during review.

WHY THE BINDING CANNOT DECIDE THIS. `Binding.WriteBranch()` returns "" whenever the mount is not writable, so a URL naming `main` looks EXACTLY like a URL naming nothing. A predicate reading the binding therefore fell through and re-pinned a READ-ONLY mount onto a writable experiment — a bigger hole than the feature closed. Measured through the real router: a learn on /repos/X/branches/main/mcp is refused with no experiment and SUCCEEDS on exp/<name> after one open.

AND THE BINDING IS WRONG IN THE OTHER DIRECTION TOO. A session already inside an experiment has a binding whose write branch IS an experiment, so the same reading refused the ordinary act of opening a SECOND one. The distinction is carried by a marker set in the middleware, before the session-id check, so presence answers "does this mount take session state" and the session id separately answers "can it right now" — two refusals with two different fixes.

THE LENS ROUTE HAS NO {branch} SEGMENT. A predicate spelled only for the repo route silently disables experiments for every `kb --lens` bridge, and no repo-mount test can catch it.

A mount whose URL NAMES an experiment serves that one and keeps its 404, or …/exp:a/mcp could serve exp/b. An absent session id fails closed at both the middleware and `open`: keying on ("", mount uid) would pool every anonymous caller of a mount into one shared experiment.

DISTINCT FROM decisions/experiments/mcp-surface, which records THAT a URL-scoped mount carries session state keyed by (session id, mount uid) and that it may choose a branch only within the URL's repo. This fact is the PREDICATE: which mounts qualify, decided from the route, and the two ways reading the binding instead gets it wrong. The decision can be implemented exactly as written and still admit `main`.

DISTINCT FROM invariants/repos/write-branch-threading, which says every write path must ASK Binding.WriteBranch(). That is about consumers honouring the answer; this is about what may set it.

# An experiment that vanishes under a live caller must NOT fail the call — resolution falls back to the branch the caller would otherwise be on and the result SAYS SO (lapsed_experiment), because being moved silently is how the next write is attributed to the wrong branch; since #685 the HANDLE is the only carrier, and only a mount whose URL NAMES an experiment 404s instead

Clearing happens in TWO layers, and the lazy one is load-bearing.

EAGER: commit and rollback clear the caller's OWN handle, so its very next call is back on the agent branch with no round trip. Best effort — by then the experiment is already gone from the store, so a failed clear self-corrects on the next resolution.

LAZY: every OTHER carrier heals at resolution. `ResolveSessionBindingOnExperiment` (handle path) and `applyMountExperiment` (mount path) each apply a stored experiment only when the write repo may actually write it, so a name that no longer resolves falls back to the ordinary binding and the request is marked via `WithLapsedExperiment`. This is not a courtesy: an experiment disappears through paths that never see the carrier — the expiry sweeper, a rollback from the REST API or the UI, and another session committing an experiment two sessions share (which the design allows). Eager clearing cannot reach any of them, so correctness has to come from the one place every later call passes through.

TWO CONDITIONS, NOT ONE. Existence and ELIGIBILITY both trigger the fallback: if the repo's agent branch moved out from under the carrier, the row still exists but `WritableBranch` says false. A guard that only checked existence would keep serving a writable binding onto a branch this instance no longer owns.

THE SECOND CARRIER (PR #240). A URL-scoped mount now stores the caller's experiment in `mount_experiments`, keyed on `(session_id, mount_uid)`. Everything above applies to that row unchanged — the same two conditions, the same `lapsed_experiment` reporting — plus ONE MORE WAY IT VANISHES: the session's own `client_sessions` row being purged takes the mount row with it (`DELETE FROM mount_experiments WHERE session_id NOT IN (SELECT id FROM client_sessions)`). That path is invisible to the caller, which is exactly why the heal must be lazy and must be reported.

Two more mount-path rules that fall out of it: a read FAILURE is not "no experiment" — `""` is a routing ANSWER, and taking it from a failed query would move the session back onto the agent branch mid-work, so the mount logs and stays put. And an EMPTY session id fails closed, because keying on `("", mount_uid)` would pool every anonymous caller of that mount into one shared experiment.

AND IT MUST BE REPORTED. `knomit_repos` surfaces `lapsed_experiment` on the bound section. "The call did not fail" is not the goal — an agent returning to a session after the sweeper ran has been MOVED, and a move it is not told about is exactly how its next fact gets attributed to the agent branch while it believes otherwise.

WHAT THIS DOES NOT MEAN: it is not the rule on a mount whose URL NAMES an experiment (`/repos/{repo}/branches/exp:<name>/mcp`, `/lenses/{lens}/experiments/{name}/mcp`). There the experiment is an ADDRESS, so an unknown one is a 404 rather than a heal — serving a different branch than the endpoint names would be the silent misroute this whole design removes. Those mounts never install `MountExperimentMiddleware` and must keep not installing it. A URL-scoped mount that does NOT name an experiment — the repo's own agent branch, or a lens's default — heals like a handle, which is the part PR #240 changed. The permitted region, in reviewer2's words: **session state may choose a branch ONLY on a mount whose URL names the repo's own agent branch, or a lens's default — never `main`, never a foreign agent branch, never a mount naming an experiment.**

UPDATE 2026-10-29 (#685, PR #686): "THE SECOND CARRIER" is gone. mount_experiments is no longer read or written, so applyMountExperiment and its heal are deleted; the purge now drops every mount_experiments row (legacy rows), not only orphans. The handle is the only carrier, and the handle-path heal above is unchanged: TestScopedDefault_OutOfBandRollbackHealsTheHandle pins it for the handle `open` mints on a URL-scoped endpoint, and asserts the connection default (never inside the experiment) is NOT told it lapsed.

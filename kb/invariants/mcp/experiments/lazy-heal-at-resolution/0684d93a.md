# A HANDLE's experiment that vanishes under a live caller must NOT fail the call — resolution falls back to the agent branch and the result SAYS SO (lapsed_experiment), because being moved silently is how the next write is attributed to the wrong branch; a URL-scoped mount has no handle and 404s instead

Clearing happens in TWO layers, and the lazy one is load-bearing.

EAGER: commit and rollback clear the caller's OWN handle, so its very next call is back on the agent branch with no round trip. Best effort — by then the experiment is already gone from the store, so a failed clear self-corrects on the next resolution.

LAZY: every OTHER handle heals at resolution. ResolveSessionBindingOnExperiment applies a stored experiment only when the write repo may actually write it, so a name that no longer resolves falls back to the ordinary binding and the request is marked via WithLapsedExperiment. This is not a courtesy: an experiment disappears through paths that never see a handle — the expiry sweeper, a rollback from the REST API or the UI, and another session committing an experiment two sessions share (which the design allows). Eager clearing cannot reach any of them, so correctness has to come from the one place every later call passes through.

TWO CONDITIONS, NOT ONE. Existence and ELIGIBILITY both trigger the fallback: if the repo's agent branch moved out from under the handle, the row still exists but WritableBranch says false. A guard that only checked existence would keep serving a writable binding onto a branch this instance no longer owns.

AND IT MUST BE REPORTED. knomit_repos surfaces `lapsed_experiment` on the bound section. "The call did not fail" is not the goal — an agent returning to a session after the sweeper ran has been MOVED, and a move it is not told about is exactly how its next fact gets attributed to the agent branch while it believes otherwise.

WHAT THIS DOES NOT MEAN: it is not the rule on a URL-scoped mount. There the experiment is named by the URL, so an unknown one is a 404 rather than a heal — serving a different branch than the endpoint names would be the silent misroute this whole design removes.

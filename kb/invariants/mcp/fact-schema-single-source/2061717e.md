# Fact-schema enums derive from internal/domain/fact; their DESCRIPTIONS live in internal/edge/mcp and a completeness test is what keeps them in sync

The knomit_learn / knomit_update JSON schemas and the server instructions all read from ONE place. Split of ownership, deliberate:

- ENUM VALUES derive from internal/domain/fact — AllEpistemicTypes(), AllPragmaticTypes(), AllOrigins(). internal/domain/fact is authoritative for what exists.
- DESCRIPTIONS live in internal/edge/mcp/factschema.go (factTypeDocs, factKindDocs, factOriginDocs). internal/domain/fact stays FREE OF PROSE.

**Why descriptions do not belong in internal/domain/fact.** Their wording is tuned for one audience — LLM tool-callers reading a JSON schema — and is driven by prompt-engineering concerns, not domain semantics. Putting them in the domain package would mean editing internal/domain/fact for prompt-tuning reasons, which is the wrong coupling. Do NOT 'consolidate' them into internal/domain/fact later; that is a regression, not a cleanup.

**The completeness test is the load-bearing part, not the shared table.** TestFactSchema_DescriptionsAreComplete asserts every member of the authoritative sets has a description, AND that no description exists for a value internal/domain/fact no longer knows about (dead prose still shown to agents). Without it this design degrades straight back to drift: someone adds a type to internal/domain/fact and the schema silently omits it, which is precisely how the contract came to be defined in three places with a fourth copy in update.go. A shared table alone does not enforce anything.

**Consequence:** adding a Type or Origin to internal/domain/fact WILL fail the mcp test until you add its description. That failure is the design working, not an obstacle — the message names the file and the exact entry to add.

**What this does NOT mean:** query.go's type/origin filter descriptions are deliberately NOT routed through this table. They are illustrative ('e.g. observation, policy') and describe filtering semantics rather than the vocabulary; forcing exhaustive 12-item lists into a filter description reads worse.

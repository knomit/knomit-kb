# clientsessions.Store.RecordRequest is the ONE request recorder: HTTP dispatch (web.recordClientSession) and the in-process chat transport both call it; a binding-set row is written only when a request resolved a handle AND a pin

What a request leaves in client_sessions (Touch) and in the session's binding set (RecordSessionBinding) is decided in clientsessions.Store.RecordRequest(ctx, Observation, handle, branch). internal/edge/web/client_sessions.go calls it after the HTTP response and internal/edge/mcp/inprocess.go calls it after each in-process request. Do not add a second Touch or RecordSessionBinding call site for a new transport; call RecordRequest.

Rule: Touch always runs; the binding-set row is added only when handle != "" AND Observation.Binding != "". A URL-scoped request has a pin but no handle and adds no row. A Touch error is returned before the set is written.

Does NOT mean: that the binding set gates anything (it is observational, like all client_sessions columns).

# A hook's knomit binding is read from the MCP entry's ARGS alone, parsed the way `kb` runs them (knomitapi.ClassifyArgs: --log peeled, stop at the first positional, "-" or "--"): neither flag is UNBOUND whatever the key or directory says, and a flag with a missing or empty value is BROKEN — never a basename fallback

Since the bridge gained its unbound mode (PR #209), `kb` with neither `--repo` nor `--lens` is a working server that the agent binds per call with knomit_bind. The hooks (Claude session-start, Antigravity pre-invocation) and a flagless init must classify an MCP entry the same way the bridge will run it: from its ARGS, and only its args.

**One parser.** `knomitapi.ClassifyArgs(args)` returns a `Scope` and is the ONLY grammar; nothing else parses these args. It reads them as the bridge does: `--log`/`-log` (either form) is skipped with its value, because main.go peels it before flag.Parse; parsing STOPS at the first positional argument, a lone `-`, or `--`, exactly where flag.Parse stops — so `["http://host:8080", "--repo", "x"]` is UNBOUND, because that is how it runs; `--lens` wins over `--repo` and clears it; a flag-shaped token is never consumed as a repo name. `Scope.RepoFlag`/`LensFlag` record that the flag APPEARED, value or not; `Scope.Unbound()` is true only when neither appeared.

**One rule.** `knomitapi.SingleScope(entries, repos.IsValidName)` reduces a config's knomit entries to one scope or a skip, for BOTH hosts' hooks and for BOTH inits' keep decision: all entries must agree (an unbound entry beside a bound one is ambiguous); neither flag → `unbound`; `--lens` with no value → `lens_unusable`; `--repo` with no value → `no_binding`; a name failing IsValidName → `invalid_scope`. Both hosts inject `knomitapi.UnboundNote` for unbound and SAY SO for a broken entry (Claude session-start prints a DISABLED notice; Antigravity its configSkips notice).

**A broken entry is never a basename.** Before the #342 review, Claude's classifyArgs returned the directory basename for `--repo` with no value, and before #341 it did the same for an args-less entry: in a directory named `knomit-kb`, session-start injected the real knomit-kb repo's principles while the MCP server was bound to nothing. The basename is now reached ONLY when the project has no knomit entry at all (deferred, C3).

**Read the file leniently.** Claude reads .mcp.json with `knomitEntries`, built on `indexJSON` — the merge's own parser — decoding each entry from its own bytes (a non-string command reads as "", a non-string arg as its raw JSON text). A strict struct decode failed on any unrelated server with `"args":["-y",5]` or an array command, saw no knomit entry, and then (hooks) fell back to the basename or (init) unbound the same-key entry it should have kept. Antigravity's pluginBinding still decodes strictly; its failure mode there is a visible no_binding notice, not a wrong read.

**Consequences to act on.**
- Never derive a scope from a config KEY or a DIRECTORY name when an entry exists. Pinned by TestMcpBinding_KeyLooksBound_ArgsUnbound / TestPluginBinding_KeyLooksBound_ArgsUnbound, TestMcpBinding_PositionalBeforeFlag_IsUnbound / TestPluginBinding_PositionalBeforeFlag_IsUnbound, TestMcpBinding_BrokenEntry_NoBasenameFallback, TestMcpBinding_OddUnrelatedServers_StillBindsTheKnomitEntry, and the ClassifyArgs/SingleScope tables.
- Pipe init's own output into the consumer when testing — hand-built fixtures are how producer/consumer splits have slipped through before.
- Adding a flag to the bridge's own flag set (main.go) means teaching ClassifyArgs its arity, or a value will read as the first positional and stop parsing.

**WHAT THIS DOES NOT MEAN.**
- Not "the Claude hooks never use the basename": the no-entry fallback is unchanged and deliberately deferred.
- Not "args-less means broken": since #209 it means unbound, a supported mode.
- Not a faithful flag.Parse clone: an unknown flag (`--verbose`) is skipped rather than treated as the bridge's exit-2 error, and `--repo --repo x` binds `x` where flag.Parse would take `--repo` as the value. The positional stop is the part that must match.
- The key tier (a non-`kb` command such as a `go run` wrapper) is parsed with the same grammar, so a wrapper whose own positional precedes `--repo` reads as unbound — the fail-safe direction (bind note instead of a possibly wrong repo).

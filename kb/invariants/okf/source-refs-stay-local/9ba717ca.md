# knomit-okf keeps fetched source history at refs/knomit-okf/source/*, outside refs/heads — structurally unpushable by git's default refspec

knomit-okf makes ONE directory both the OKF export and its own source: it fetches the knowledge base with refspec `+refs/heads/*:refs/knomit-okf/source/*` into the same .git as the bundle.

That namespace choice is the whole safety property, and it is STRUCTURAL rather than guarded. Because refs/knomit-okf/source/* is outside refs/heads/*, git's default push refspec cannot match it, the source tree is never checked out into the working tree, and no code has to police anything. Verified by a test that pushes to a bare remote and asserts only refs/heads/* arrives.

The consequence for a consumer: `git push` from an OKF repo publishes the bundle branches and nothing else, so a PRIVATE knowledge base can be the source of a PUBLIC export without leaking its history.

The one leak path, documented and deliberately NOT defended in code: `git push --mirror`, or any explicit `refs/*` refspec, WILL publish the source refs.

What this does NOT mean: it is not the older rule about generated okf/* branch refs — those no longer exist anywhere, because nothing generates refs any more. This is about the SOURCE history the tool fetches into its own repo.

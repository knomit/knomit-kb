# knomit-okf owns exactly index.md, log.md, kb/, views/, .knomit-okf.yaml — it prunes inside them and must never touch anything else

knomit-okf manages a FIXED set of paths in the output repo — index.md, log.md, kb/, views/, .knomit-okf.yaml — and reconciles them exactly: when it finishes, those paths hold the rendered bundle and nothing else.

State the invariant as CONVERGENCE, not as rewriting. reconcile skips files whose content already matches on disk (and staging skips files the index already records correctly), so a sync touching 44 of 3038 documents writes 44. The guarantee is about the END STATE, not about how many files were opened.

Both halves of the boundary are load-bearing, for opposite reasons.

Deleting is mandatory because overlaying files can never REMOVE them. Without the prune, a retired fact's document stays published forever, contradicting the views/retired.md sitting in the same bundle. A planted stale file was confirmed to survive a re-extract.

Not deleting anything else is equally mandatory: everything outside the owned set belongs to the publisher. A README.md, LICENSE, or .github/ must survive a sync. The naive implementation — clean the working tree, then write the bundle — destroys a publisher's work, which is why the boundary is enforced in code (reconcile REJECTS an unowned path rather than writing it) and not left to convention.

The same boundary governs staging: only owned paths are added to the index, so a publisher's uncommitted edits are never swept into an okf commit.

What this does NOT mean — two misreadings, both live:

(1) It is not a licence to add paths to the owned set casually. Each one the tool claims is a directory it will happily delete files from.

(2) "Skips unchanged files" is not "trusts the working tree". The skip is safe only because content is compared byte-for-byte, and because anything reconcile actually wrote is staged unconditionally — so a hand-edited bundle file cannot be skipped on a stale index hash. An incrementally staged sync is pinned to produce a tree byte-identical to a full re-stage (TestCLI_IncrementalStagingMatchesFullRestage).

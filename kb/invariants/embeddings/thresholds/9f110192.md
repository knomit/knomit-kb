# A cosine cutoff is a point on ONE model's similarity distribution under ONE rendering — so thresholds are model-owned data delivered from whichever model loaded, never a user config key, re-swept on any model or template change, and a consumer that cannot name the model refuses to evaluate rather than borrowing another model's geometry

A cosine cutoff has meaning only as a point on one model's similarity distribution under one input rendering, so every threshold is owned by the model that produced the distribution, is delivered from whichever model actually loaded, is re-swept whenever the model or the rendering changes, and is never applied by a consumer that cannot identify which model it is judging.

The instances:
- OWNERSHIP AND HOME. The six absolute cutoffs (Dedup, ReflectNovelty, SimilarTo, SearchFloor, RerankHigh, RerankLow) plus DefaultModelID live in `internal/embeddings/params`, a cgo-free child of embeddings; they are fields on `embeddings.Model`, delivered via `Embedder.Thresholds()`, and there is deliberately NO TOML key for them — `Dedup` set without recalibration silently over-merges facts, which is data-lossy. `TestParamsHasNoDependencies` bans every non-stdlib import so the child can never link ONNX into store/config; do not weaken it to a banned-package list.
- EVERY MODEL'S GEOMETRY AS DATA. `params.ForModel(id) (Thresholds, bool)` — the bool is load-bearing: a silent `Defaults()` fallback would judge an unknown or typo'd model id against nomic geometry with nothing red. Presence is a map-key probe (comparing to `Defaults()` would report nomic itself as missing), absence does not license validating ids, and on absence the safe branch is the NON-AGGRESSIVE one (the same-subject gate does not refuse the write). `applyDedupMerge` deliberately reads `Dedup` from `store.EmbedderThresholds` instead, because dedup must keep working for embedders params does not know; do not 'harmonise' the two sources.
- RENDERING IS PART OF THE CALIBRATION. Short strings are anisotropic and model-dependent: centering over the vocabulary is required before any threshold means anything, nomic cannot separate true from false short-string pairs at all, and the shipped `title: {content} | text: none` template on embeddinggemma is what made the research operating point transfer to production within 0.001 — changing the template silently invalidates every threshold measured through it, with no error and no test failure. The template is calibrated for embeddinggemma only.
- A FLOOR CAN STOP BINDING. Under embeddinggemma the SimilarTo floor of 0.18 is cleared by 99.6% of all fact pairs, so the SIMILAR_TO edge set is created by K, not by the cutoff; 'not similar' means 'not in each other's top-10'. Any analysis or test that reasons about edge existence via a cosine cutoff is wrong under this model — reconstruct the top-K neighbourhood instead.

WHAT THIS DOES NOT MEAN: the floor is not useless (it still drops the anti-correlated tail); 'config is not for numbers' is not the argument — config already holds tuning floats, the argument is OWNERSHIP (user-owned TOML vs model-owned calibration); and this does not settle whether CohFloor/QualityFloor, which are derived from SIMILAR_TO edges drawn with `Thresholds.SimilarTo`, are mis-homed in config — that is an open behaviour question. Porting a threshold across models by value is meaningless; a band's two endpoints must also come from the same distribution.

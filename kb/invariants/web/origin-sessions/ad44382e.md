# A session's cloned RemoteStore and folder are touched only by a handler holding the session's exclusive use (sessionManager.Use) or by finalize; finalize closes the store BEFORE removing the folder and runs once, when the session is dropped and no handler holds its use, else when the handler releases

DROP PATHS. Delete, replace (a new Create for the repo), idle expiry and lifetime end all call retire, outside the manager's mutex. retire closes `gone` (so waiting acquires give up), marks the session dropped, and finalizes now if no use is held; otherwise the use's release finalizes. The commit handler's own sm.Delete therefore finalizes when the handler returns. finalize closes the cloned RemoteStore first (an open store holds files in the folder, which Windows cannot remove), then removes the folder.

HANDLERS. test, preview, apply and commit take the use with r.Context(). The use is exclusive (busy has room for one): two steps of one session never run at once, a second request waits. A step whose request ends while waiting answers 404, and so does a step on a session dropped while it waits. GET session and list only read state, through Get.

LIFETIME END. close() waits (WaitGroup `live`) for every session to finalize before it removes the run and releases the lock, so a slow commit still running after Shutdown's 5 s grace keeps its folder until it returns.

NO IO UNDER sm.mu. Folders are made before it is taken; stores are closed and folders removed after it is released. Lock order is sm.mu, then sess.mu; runMu is never held with either.

EXPIRY VS USE. runCleanup skips a session whose use is held, and release restarts the idle clock (LastAccess = now). So a step longer than 10 minutes is never evicted mid-step, and the 10 minutes count from the END of the step. Test: TestSessionManager_S6_InUseSessionIsNotIdle.

/test RUNS ONCE PER SESSION. /test on a session that has a RemoteStore, or whose state is tested, previewed, applied or committed, answers 409 problem+json ("Session state conflict") before it opens anything; the session's state and store stay unchanged. Before this a re-run opened a second handle on clone.db, its CloneFrom failed ("repository already exists") and a good session went to stateError, which /apply and /commit refuse. A session in stateError (a failed first /test) is NOT refused by this check (see the known-defect gotcha on re-testing it, issue #629). To test again, create a new session (POST replaces the old one). Test: TestHandleTestConnectivity_RerunIsRefusedAndLeavesTheSessionGood.

DOES NOT MEAN: that the use is RepoInstance.Acquire (the LOCAL repo store). It pins only the session's clone, so the repos rule 'never hold an Acquire across SwapStore' (77005364) is unaffected. Nor does 'finalize closes the store' mean any code may Close sess.RemoteStore itself: a close outside finalize races a handler using it.

Tests: TestSessionManager_DroppingASessionClosesItsStore, TestSessionManager_DropWaitsForTheHandlerUsingTheSession, TestSessionManager_StoreNeverClosedUnderAUser (run with -race -count=50), TestHandlers_StoreStepsTakeTheSessionsUse.

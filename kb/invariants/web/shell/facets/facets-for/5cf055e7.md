# facetsFor is the only authority on which tabs a target has; a missing facet is omitted, never disabled

`facetsFor(target, repos, lenses, creates)` returns the tabs in order:
- a repo with an active (non-terminal) create: Settings only. This check comes FIRST, before the not-listed short-circuit, so a repo whose create is running is Settings-only whether or not the listing carries it yet;
- an available repo with no active create: Browse, Activity, Settings;
- a listed repo with no store: Settings only;
- a repo the listing does not carry yet (no create running): all three, because the list lags a rename by one refresh;
- a lens whose mounts are all readable: all three;
- a lens with a broken mount (`brokenLensMember`): Activity, Settings;
- a pinned target (archived, pending create, unavailable repo, broken lens): Settings only;
- a draft: nothing.

TopBar draws exactly this list and App renders a facet only if it is in it.

Consequence: never gate a facet anywhere else (TopBar, App, the rail); change facetsFor and its test.

WHAT THIS DOES NOT MEAN: "Settings-only" does not mean read-only. The Settings page's own gates (serverReadOnly, a subscription's mode, creating mode) still decide what can be edited.

# Revoking a chat grant removes exactly the grant the row names; the Settings button sends {target, kind, tool, action} as listed and drops the row on 204 or 404, and nothing else changes

The Revoke button on each Settings grant row calls DELETE /chats/{id}/grants with that row's grant exactly as GET /chats/{id}/grants listed it (target, kind, tool, action). The server (chat.revokeGrant) removes the grants equal to that grantInfo and nothing else: the next call of the same tool and action on the same target asks again, and a grant for another target, tool or action stays in force (TestChat_RevokedGrantAsksAgainAndLeavesTheOtherInForce). A grant the chat does not hold is 404, an incomplete body is 400, another principal's chat is 404.

The page removes the row on 204, and also on 404 (the grant is not held, so the row is stale); any other failure keeps the row and shows the error. Misreadings to avoid: revoke does not cancel a call already waiting for approval, does not end the chat, and does not 'deny' anything the grant already allowed. The key is the displayed (target, kind, tool, action), not the internal pin: two repos can never share a name, so the display key identifies one grant.

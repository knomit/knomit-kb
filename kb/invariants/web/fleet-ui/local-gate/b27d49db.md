# GET /fleet `local` is the ONLY input that decides whether the Fleet pages draw any fleet mutation control: never __KNOMIT_DESKTOP__, never a 403 discovered after a click

Built in PR #528 (verified at merge e417fd76). Every fleet mutation route is served on the local listener only (RequireLocalVia), so a browser over TCP gets 403 from them. The pages therefore draw a mutation control (enroll, revoke, save bundle, export/import root key, Host here, Point at, Leave, Decommission, the New fleet wizard step, the rail's + for a fleet) ONLY when GET /fleet says `local: true`; over TCP (local false) they show state and a plain statement of what is desktop-only, and that statement lists exactly the actions that really are local-only (master: enrolling and revoking members, hosting the fleet here, pointing this copy at a new host, exporting the root key, standing down and decommissioning; member: pointing this copy at a new host, importing the root key and leaving the fleet). The rail + reads `locked || local !== true` and nothing else; FleetWizard has its own `local` guard.

CONSEQUENCE: a new fleet action must be added to that local-only statement as well as to the route group, and its control must be gated on `local`. MISREADING: `local` is not "running in the desktop app": a browser reaching the local socket through a forwarder is local, and the desktop webview over TCP would not be. The server decides; the page compares nothing itself.

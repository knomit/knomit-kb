# A NAMED server address (kb's argument or KNOMIT_SERVER) is used EXACTLY as given for every call: a named local socket/pipe is the only place kb connects (missing, dead or foreign, the call FAILS, never TCP, never the lockfile), a named http(s) address is never rerouted onto the local socket; only an address nobody chose (lockfile, default) keeps 'local listener first, TCP after'

tools/bridge/knomitapi/server.go NewServerClient picks the transport from the resolved Server, and the rule is the same for the MCP proxy, the agent-branch discovery before it, the closing DELETE and every hook (newLazyHooksClient re-resolves per dial):

- named local listener (unix:///abs/path.sock, npipe:////./pipe/<name>): localOnlyDialer dials ONLY that listener through auth.DialLocal; any failure is the request's error and names the address. No TCP fallback, no lockfile.
- named http(s): plain TCP (with kb login's bearer for its host), never the local socket.
- not named (lockfile port or http://localhost:19278): the socket-preferring dialer — local listener at config.SocketPath first, TCP after (missing = quiet debug fallback, present-but-unreachable = one WARN then TCP, foreign owner = fail).

WHY a named socket never falls back: falling back to the lockfile or a TCP port is the 2026-10-02 rehearsal bug in a new shape — a session meant for one instance silently served by another. WHY a named http address is not rerouted: the user pointed at a particular (maybe remote) server; a local listener answers a different question.

Consequence for a change here: a 'helpful' fallback on the named path, or treating a named address as a preference, re-opens the wrong-instance bug. Tests: TestBridge_NamedMissingSocketFailsWithoutFallback and TestNewServerClient_NamedMissingLocalListenerFails (missing named socket: error names it, lockfile server sees 0 requests), TestNewServerClient_NamedHTTPIsNeverReroutedToTheSocket (live default socket ignored), TestNewServerClient_DefaultStillPrefersTheSocket (the default path keeps the preference).

WHAT THIS DOES NOT MEAN: it does not mean kb never uses the local socket — the default path still prefers it, and naming the socket (KNOMIT_SERVER=unix://<home>/knomit.sock) is the recommended way to reach a specific instance WITH a verified identity.

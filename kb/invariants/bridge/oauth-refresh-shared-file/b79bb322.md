# kb's token refresh re-reads the credentials file UNDER A CROSS-PROCESS LOCK and uses a pair another kb already rotated — several bridges share one file, and presenting an already-rotated refresh token makes the server revoke the whole family for all of them

`kb login <base-url>` saves one pair per HOST at <knomit home>/credentials/<host>_<port> (KNOMIT_HOME honoured; port explicit; every char outside [a-z0-9.-] becomes '-', so an IPv6 literal or ':' never reaches a Windows file name), 0600 in a 0700 dir, written via temp file + rename. Every kb bridge process for that host (one per agent session) reads the SAME file, and the server rotates refresh tokens with reuse detection: a rotated refresh token presented again revokes the family (kb/decisions/oauth/token-storage).

SO the refresh path is: bearerTransport reads the file PER REQUEST (never caches it), sends the access token, and only on a 401 whose WWW-Authenticate contains invalid_token calls refreshShared, which takes an exclusive lock on <file>.lock (flock on unix, LockFileEx on Windows — both conflict between two open files even inside one process), re-reads the file, and if the access token on disk is no longer the one this request sent, USES THE DISK PAIR without calling the token endpoint; otherwise it refreshes once, saves, releases. The request is replayed once with the new token (body via GetBody; a body that cannot be re-read is not replayed and the caller gets the 401). A failed refresh returns the original 401: no loop, credentials kept for `kb login`.

THE LOCK WAIT HONOURS CTX (phase 3b, 3a review N5): withCredentialsLock(ctx, …) takes the lock with a NON-blocking try (flock LOCK_EX|LOCK_NB; LockFileEx with LOCKFILE_FAIL_IMMEDIATELY on Windows) polled every lockPollInterval (25 ms, a latency choice) until it succeeds, fails, or ctx ends — so a holder that is SIGSTOPped or stuck in its 30 s refresh cannot stall another kb past that request's own deadline. TestCredentialsLock_WaitHonoursContext holds the lock through a second handle and runs on every OS; the Windows implementation is exercised ONLY by the windows CI job (it does not compile on darwin).

CONSEQUENCES: a caching bearer client, a refresh outside the lock, or a refresh triggered by ANY 401 (a proxy's own Basic challenge) each reintroduce family-wide logouts or needless rotation; tests pin all three (TestBearer_ConcurrentRefreshesAreSerialised — exactly one token-endpoint hit for six concurrent refreshers — TestBearer_UsesARefreshAnotherProcessSaved, TestBearer_OnlyInvalidTokenRefreshes). The header is added by withBearer in BOTH knomitapi client constructors and discoverAgentBranch now uses NewHTTPClient; over the local socket the server ignores it.

LOGIN refuses BEFORE opening a browser unless: the protected-resource document (RFC 9728, path-inserted) names exactly the base URL as its resource; its issuer passes config.NormalizeIssuer and sits at the base URL's origin (else the user must confirm); the AS document (RFC 8414, path-inserted) names that issuer exactly and advertises S256 and authorization_response_iss_parameter_supported. The loopback callback (127.0.0.1:ephemeral/callback, the built-in kb client's registration) must carry the state kb sent and iss equal to the discovered issuer. Nothing is ever written to .mcp.json. `kb logout` revokes the refresh token at the stored revocation endpoint (best effort) and deletes the file.

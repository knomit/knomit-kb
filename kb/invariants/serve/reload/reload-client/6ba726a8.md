# serveraddr.RequestReload is the ONLY client that asks a running server to reload, and exactly three production files reference it or SignalReload: cmd/reload.go, internal/serveraddr/reload.go and tools/desktop/native.go - an archtest pins the list

INVARIANT (knomit#504, merge 1c6a0934). The reload client moved from `cmd` to `internal/serveraddr/reload.go` (+ reload_unix/windows/other.go): `RequestReload(ctx, home, wait)`, `SignalReload`, the typed errors `ReloadRefusedError` / `ReloadTimeoutError` / `ReloadListenerError`. Reason: the desktop cannot import `cmd` (it pulls internal/app; TestDesktopLinksNoServer, kb/invariants/desktop/links-no-server/afc136f3.md). `cmd/reload.go`'s `runReload` is a thin wrapper and `knomit reload` messages and exit codes are unchanged (kb/decisions/serve/reload/6679f9ff.md).

CALLERS: test/archtest `TestReloadRequestHasOnlyTheCLIAndTheSettingsBindingAsCallers` requires that, among non-test Go files that import internal/serveraddr (plus the package's own files), the files that REFERENCE (selector or identifier, not only call) RequestReload or SignalReload are exactly cmd/reload.go, internal/serveraddr/reload.go and tools/desktop/native.go (the Settings binding stores the function in a field so tests can fake it, and that field is still the call site). A fourth file fails the test (the reviewer added a call in internal/web: red with the full list). This is the CLIENT half of the pin whose SERVER half is TestListenersApplyHasOnlyTheSignalLoopAsCaller (kb/decisions/serve/reload/f44e4370.md): no HTTP route, no handler package, no other binding may ask for a reload.

THE ACK: SaveSettings reads the outcome from server.json, not from the signal: generation advanced, `reload_error`, per-listener reasons and `restart_needed`. 'applied' requires the generation to advance AND no failed listener (a higher generation does not mean everything applied, kb/architecture/bridge/server-address/server-json/4d299314.md). Outcomes: applied, restart_needed, listener_failed, refused, timeout, not_running, unavailable. A reload that did not apply is an ack outcome, never an error: the file is already saved. Settings reloads after EVERY save, because a retry after a freed port writes the same bytes and must still reach the server.

MISREADINGS: (1) 'the desktop can reload any server' - RequestReload refuses a lock without `reload: true` and signals nothing; it works on an attached CLI server too. (2) Moving the file does not change the window gate: SaveSettings is still Settings-window-only (kb/invariants/desktop/fleet/install-surface/a46bbb69.md). (3) A test file may reference the names freely; the pin is on production files.

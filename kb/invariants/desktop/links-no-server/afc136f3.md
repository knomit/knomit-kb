# knomit-desktop must link NONE of internal/app, internal/web, internal/embeddings, onnxruntime_go or tokenizers - on darwin, linux and windows, transitively - and TestDesktopLinksNoServer enforces it; the desktop gets a model name or a log setting from those areas only through cgo-free homes

THE RULE (PR #503, merge 8be999a0): the desktop is a supervisor and a UI proxy; the server lives in the separate `knomit` process it spawns or attaches to. So `go list -deps -tags desktop ./tools/desktop` must list no package under `knomit/internal/app` or `knomit/internal/web`, and must not list `knomit/internal/embeddings` (EXACT match), `github.com/yalue/onnxruntime_go` or `github.com/daulet/tokenizers`, for GOOS=darwin, linux and windows. test/archtest/desktop_no_server_test.go (TestDesktopLinksNoServer) checks the transitive closure, so a helper package that imports internal/app also trips it. Test files that import internal/app (the logging-options parity test, logging_parity_test.go, built `desktop && !windows`) are allowed because test imports are not part of the shipped binary.

WHY: a second construction path for the server inside the desktop is how F19 phase 1's socket went missing on desktop-served machines (the retracted two-boot-paths gotcha). Linking the server would also bring back the inference stack: the desktop binary was 50,676,626 bytes on darwin/arm64 with internal/embeddings linked and 32,492,898 bytes without (-18.2 MB); the Windows exe went from 129.5 MB (in-process server) to 33.8 MB (measured on one Windows machine, dated support). It also lets `GOOS=windows go vet -tags desktop ./tools/desktop/...` run cgo-free.

CONSEQUENCES for whoever needs something from a forbidden package: move the small piece to a cgo-free home rather than import the package. Done so far: config.ResolveKeyPath (internal/config), pki.PublicKeyLine and pki.AuthorizedKeyLine (internal/pki), the model registry in internal/embeddings/params (the model-registry decision under decisions/architecture/internal-package-layout), and desktopLoggingOptions in tools/desktop/logging.go duplicating app.LoggingOptions with a parity test that fails when they drift.

A companion test, TestOnlyServeRecordsItsAddress (test/archtest/knomit_server_test.go), pins cmd/serve.go as the only production file that references Manager.SetServerAddress.

NOT MEANT: 'the desktop is cgo-free' - on Linux it still needs cgo for Wails/GTK, and on darwin/windows for the webview; only the inference stack is gone. 'internal/embeddings/params is forbidden' - it is stdlib-only and allowed (the exact-match list exists for that reason).

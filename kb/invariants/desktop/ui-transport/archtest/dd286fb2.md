# TestDesktopUIPathNeverDialsTCP derives the UI path and fails any bare http.Client, http.Transport or ReverseProxy in it, not just named TCP selectors

The UI path is not a hand-kept list. TestDesktopUIPathNeverDialsTCP derives it: every non-test .go file under tools/desktop (subpackages included, ui/dist excluded) that imports net/http OR names uiUpstream, newUpstreamTransport or apiProxy. uiproxy.go, uistreams.go and supervisor.go must be in the derived set (anchors), so a rename or a broken rule cannot make the set empty and pass.

In every derived file the test forbids: (1) the named TCP selectors (net.Dial*, tls.Dial*, http.DefaultClient, http.DefaultTransport, http.Get/Head/Post/PostForm); (2) an http.Transport literal (also &literal, new(http.Transport), a zero-value `var t http.Transport`) unless its DialContext is a func that calls auth.DialLocal; (3) an http.Client literal (or new/zero-value) unless its Transport is newUpstreamTransport(...) or a checked http.Transport literal; (4) an httputil.ReverseProxy literal (or new/zero-value) unless its Transport is newUpstreamTransport(...) or a checked http.Transport literal (same provenance as the Client rule), and any call to httputil.NewSingleHostReverseProxy (nil Transport means http.DefaultTransport); (5) a struct field of non-pointer type http.Client, http.Transport or httputil.ReverseProxy (a zero value that dials TCP). Positive controls: uiproxy.go calls auth.DialLocal; uistreams.go and supervisor.go use newUpstreamTransport. Self-tests run the checker on synthetic sources and the derivation on a fixture tree.

CONSEQUENCE: a new file that carries or probes UI traffic is checked automatically with no list to edit; a bare &http.Client{} or &http.Transport{} there fails CI even when the same file also uses the shared transport, because an unset dial is a TCP dial. Build clients from newUpstreamTransport. Legitimate non-UI HTTP (e.g. a future self-updater) must live in a package outside tools/desktop, or get an explicit, reviewed allowlist entry in the test; HTTP code under tools/desktop is treated as UI path.

MISREADING to avoid: the rule does not check non-HTTP desktop files (tray, autostart, paths) and does not prove a runtime dial goes through the socket; it is a syntactic check on the derived files. A client whose Transport is a variable of unknown origin is rejected on purpose, so assign through newUpstreamTransport inline.

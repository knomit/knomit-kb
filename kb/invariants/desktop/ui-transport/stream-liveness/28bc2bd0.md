# Every knomit-sse stream carries a desktop ping every 15 s (ssePingInterval, TrySend), and WailsEventSource reopens a socket that has carried no frame for 45 s (STALE_STREAM_MS): onclose alone does not detect a stream Wails dropped

RULE: the desktop's serveSSEStream starts pingStream once the subscribe frame is valid; it sends {t:'ping'} every ssePingInterval (15 s) with TrySend (never Send: a ping must not block or queue behind a backlog) until the StreamConn context ends. WailsEventSource stamps lastFrameAt when a socket is created and on EVERY frame (ping, open, event, error, even an unreadable one) and runs one interval (STALE_STREAM_MS / 9, 5 s) that, when a socket exists and nothing arrived for STALE_STREAM_MS (45 s = three pings), drops the socket, goes CONNECTING, dispatches error and reopens with the normal backoff and the last event id. close() clears the interval.

WHY: Wails v3.0.0 reaps a stream session after 10 min without a poll and recreates it empty on the next poll with no close for the old connections (kb/gotchas/desktop/wails/streams/session-reap), so before this the page's chat stream stayed OPEN with nothing behind it and every new chat ended on stream_grace 60 s after it started.

CONSEQUENCES: a desktop change that removes or slows the ping below STALE_STREAM_MS / 3 makes every quiet stream reconnect every ~45 s (each reconnect is a ready, so every chat on screen and the rail reload); change ssePingInterval and STALE_STREAM_MS together. The browser build is untouched (native EventSource, no watchdog). After a suspension shorter than the reap but longer than 45 s the page may reconnect once spuriously before the queued pings arrive; that is harmless (ready, reload).

WHAT THIS DOES NOT MEAN: it does not reconnect a stream the server REFUSED (error closed:true stays final, as for EventSource), and chatEvents.ts's hub still never reopens a stream that went CLOSED; the stale bound (45 s + up to 5 s check + 0.5 s backoff) is under the server's 60 s chat grace only for a chat created while the stream was ALREADY dead and unnoticed, which after a resume lasts at most one check interval.

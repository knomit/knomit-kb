# A mission inbox copy's `expires` is a LEASE, never a deadline: the `lease` trigger (on: due, inbox/{agent}/**, do: run work-task) re-wakes a session for a copy still there, nothing may retract a copy at its lease, and every re-wake must push the lease out because a STARTED due fire is marked processed

Since feat/mission-drain-inbox the mission template (examples/mission/) leases every copy in inbox/<agent>/ (working/ and active/). The ontology's inbox validation `expires` refuses a copy without one.

Rules a consumer must act on:
1. A lease is NOT an expiry. No `on: due` trigger with `do: script` may match inbox/** (TestMissionTemplate_Lease fails if one does). The copy stays until a session acknowledges it (ack = learn acks/<task id>/ + retract the copy, one commit).
2. The `lease` trigger runs the SAME recipe as `wake`. A due fire dropped as `busy` (the recipe at its `concurrent` limit) is retried at every sweep (dueRetry; kb/invariants/repos/triggers/due-marks). A learn fire (`wake`) dropped as busy is gone for good — that is why the lease exists.
3. A due fire that STARTED a session is marked processed for that expires instant. If the session then dies without acking, the copy fires again ONLY if its expires changed. So the recipe calls knomit.update(task_path, {expires: <session lease>}) BEFORE it runs claude (session lease = now + the recipe's TIMEOUT_MS + 60 s), and the work-task skill writes that same lease on every copy it takes into active/. A recipe that skips the re-arm leaves a dead session's copy stuck forever.
4. An acknowledged copy is no longer live, so it never fires (pinned by TestMission_ActiveCopyLockAndLease).
5. Lease lengths: working/ copies get LEASE_SECONDS = 300 s from the take (claims.js decide, awards.js takeAward, same constant in both); an assigned copy gets what its poster sets (post-task skill: about 5 minutes).

Tradeoff (README "The queue"): a shorter working lease picks up a dropped copy sooner, but while a session holds the slot every copy waiting past its lease logs a `busy` row on every sweep (each tick and each write) until it is taken; the fire log keeps 10,000 rows per repo.

MISREADING: "the lease trigger replaces wake" — no: wake still starts the session on a new copy; the lease only covers what wake cannot (a busy-dropped wake, a dead session). And the recipe's Date is the real clock (RunRecipe gets time.Now), not the dispatcher's test clock.

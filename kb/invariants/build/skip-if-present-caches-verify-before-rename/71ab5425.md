# Every skip-if-present cache in knomit must verify BEFORE the atomic rename — a corrupt file that lands is permanent

Two independent download caches share one shape: the embedding-model cache (`internal/embeddings/download.go`, `<Home>/models/<id>/`) and the native-library cache (`tools/fetchlibs`, `dist/<goos>-<goarch>/lib/`). Both SKIP IF THE TARGET PATH EXISTS.

That skip is what makes a bad write permanent. A truncated file at the final path is never re-fetched; it resurfaces later as a cryptic ONNX load failure or a dlopen/link error, on every subsequent boot or build, with no self-healing path short of manually deleting the cache directory. The failure is separated from its cause by days.

CONSEQUENCE — the rule for any such cache: write to a temp file IN THE SAME DIRECTORY (os.Rename is only atomic within one filesystem), verify, `Sync`, and only then rename into place. Never `os.Create(finalPath)` and stream into it.

Verification available before the rename, in strength order:
1. A pinned SHA-256, when one exists. `Model` carries optional `ModelSHA256`/`DataSHA256`/`TokenizerSHA256` and the downloader checks them when non-empty. They are UNSET in the registry because the URLs point at mutable HuggingFace `main` refs — a pin would break on any upstream republish. Setting them requires also moving the URLs to an immutable revision.
2. Content-Length, whenever the server declares one. This is the check that catches the real failure mode: a 200 response whose body is cut short mid-transfer, which `io.Copy` reports as SUCCESS.

A response with neither is accepted — there is nothing left to compare against, and refusing would make the downloader depend on server behaviour we don't control.

Separately, on hanging: embeddings are MANDATORY (`app.New` treats embedder construction as fatal), so the model download runs before the server listens and a silent mirror used to hang boot forever. The fix is deliberately NOT `http.Client.Timeout` — the model is hundreds of MB and a whole-request deadline kills legitimate slow-link transfers. It is bounded dial/TLS/response-header phases (fast regardless of size) PLUS a stall watchdog that cancels the request context after 90s with zero bytes received. `EnsureModel`/`NewEmbedder` take a `context.Context` so a boot abort also aborts the fetch.

WHAT THIS DOES NOT MEAN: "there is a timeout" is the wrong summary. A total timeout was rejected on purpose; the guarantee is against a STALLED transfer, not against a slow one.

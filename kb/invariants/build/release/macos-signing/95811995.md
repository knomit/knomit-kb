# On macOS the post-sign loop asserts Authority, Timestamp AND the hardened-runtime flag (`codesign -dv` shows `flags=...runtime`) on dylib, kb, knomit-okf, knomit, knomit-desktop and the .app, only when CODESIGN_IDENTITY is set; ad hoc builds skip it, and the first real-identity run is still owed

Notarization rejects a nested Mach-O without a Developer ID signature, a secure timestamp and the hardened runtime. The `desktop-app-macos` recipe signs six paths with `$(CODESIGN_FLAGS)` (`--force --options runtime --timestamp --sign <identity>` when `CODESIGN_IDENTITY` is set): libonnxruntime.dylib, kb, knomit-okf, knomit (new in #500), knomit-desktop and the .app. Inside `ifneq ($(CODESIGN_IDENTITY),)`, one `for f in` loop over those same paths then asserts (1) `codesign -dvvv` shows `Authority=Developer ID Application`, (2) it shows `Timestamp=`, and (3) `codesign -dv` shows a `CodeDirectory ... flags=...(...runtime` line, i.e. `flags=0x10000(runtime)` or `0x10002(adhoc,runtime)`; plain `flags=0x2(adhoc)` and `flags=0x0(none)` fail. The runtime assertion was added in #500's fix round after review found the loop checked Authority and Timestamp only.

**Consequence:** if someone drops `--options runtime` from `CODESIGN_FLAGS`, the build now fails at the loop ("lacks the hardened runtime flag") instead of publishing green and failing at Apple. Add any new nested binary to BOTH the sign list and this loop.

**What this does NOT mean:** an ad hoc build (no identity) passes without running any of these assertions, so `make desktop` rc=0 on a dev machine proves nothing about notarizability. The assertions have been checked against real `codesign` output and expanded under a fake identity with `make -n`, but NO run with a real Developer ID identity or Apple round trip has happened yet; that first run is still owed. The final echo still says only "Developer ID + secure timestamp".

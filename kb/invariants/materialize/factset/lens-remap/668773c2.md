# A lens FactSet's sub-FactSets number in LOCAL units; the facade remaps EXACTLY four fields at emission (node unit, first component of node number, link unit, first component of link number), on pages AND in the export, and nothing stored holds a global number

In internal/corpus/materialize/factset_lens.go (feat/lens-factset-facade), each lens member's sub-FactSet plans, reserves and numbers in ITS OWN local units (sections 'l', 'l.k', the reserved table's unit/k, plink.unit/number). The map global = globalOf[sub][local-1] is a pure function of the frozen order (lensFrozen.Order). lensEntry.remap applies it after inflate, before JSON or render, to EXACTLY: FactSetNode.Unit; the first dotted component of FactSetNode.Number; FactSetLink.Unit (forward links, Unit > 0); the first component of FactSetLink.Number. A back link carries the anchor only and needs nothing (anchors are FactHash(repo, path), already repo-qualified), and link direction is preserved because local a < b iff global a < b within one sub. builds_on[].n is an ordinal inside the unit and is not touched; a frame ancestor's '' number stays ''.

CONSEQUENCES:
- Any new field that carries a unit number or a number string must be added to remap, or it leaks a local number (a wrong 'see N'). TestLensFactSet_RemapsTheFourNumberFields fails on each of the four removed (sabotaged once each); TestLensFactSet_ExportHasGlobalNumbers fails if the export skips remap.
- The export must remap before renderFactSetNode (its '## <unit>.' and '### <number>' headings and the (see N) of forward links come straight from those fields).
- repo_name (ruling Lens 7) is set by remap on the node whose number equals its unit (the unit root), so it depends on remap running first.

WHAT THIS DOES NOT MEAN: the cursor is NOT remapped: it is built by the facade in GLOBAL units from the start (<id>.<global unit>.<section>); the subs never see a cursor.

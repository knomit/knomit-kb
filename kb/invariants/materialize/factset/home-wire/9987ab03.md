# FactSet HOME vs WIRE: the home repo (where the roots live) keys fact hashes, local-ref classification, reservation, read-ahead and unavailable roots; the wire repo (the binding's write repo) alone decides bare vs kb://<id12>/ paths

In internal/corpus/materialize (since refactor/factset-pinned-seam), a FactSet has two repo ids:
- HOME = factsetFrozen.HomeRepo (JSON name still "write_repo"): FactHash(home, path) of roots and local targets, fact.ClassifyRef(raw, home) in the reservation, the reserved table's repo for local direct refs, the planner's homeID (which keys the read-ahead: prefetch rows/metas are used only for nodes whose mount is the home, and the window itself carries its home: prefetch.covers(home, u)), the repo of an unavailable root.
- WIRE = factsetFrozen.wireID() = WireRepo when set, else the home: the planner's wireID, used ONLY by planner.wire: a key in the wire repo renders bare, every other repo (the home included when it is not the wire) renders kb://<id12>/path, the one canonical form (10a3bcc0).
For a repo FactSet and a single-fact Plan, home == wire == the write repo and WireRepo is never set (json omitempty), so the frozen row is unchanged. A lens sub-FactSet (F3) has home = a read member R and wire = the lens write repo, so R's sections go out kb://R/....

CONSEQUENCES:
- Never key a hash, a classification or the read-ahead by the wire id: a sub over R would reserve W-keyed entries nothing matches (no N.k numbering) or lose the read-ahead. Never decide bare vs kb:// by the home: R's paths would come out bare, as if they were the write repo's.
- TestFactSet_Pinned_HomeIsNotTheWireRepo pins both: the reserved table holds FactHash(R, path) at blob64 of R's version (sabotage 'reserve by wire' fails 'reserved as an R fact'), and the sub's pages equal R's own repo FactSet's pages with paths rewritten to kb://R/ (sabotage 'wire by home' fails).

WHAT THIS DOES NOT MEAN: the env's search.path (the request) is not a fact path and is not rewritten; and cross-KB (foreign) targets are unaffected: they were always kb:// unless they are the wire repo.

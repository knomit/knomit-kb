# materialize follows a cross-KB ref into a repo OUTSIDE the binding only when the CALLER's recorded reach covers it; auth.ReachesRepo is DEFAULT-DENY and every principal-minting edge records a reach; unreachable reads exactly like nonexistent (kb_unavailable)

The user ruling 'cross-KB refs follow ANY repo registered on the server' is about AVAILABILITY. It does not authorize reading a repo the caller could not read itself.

The rule, as built on feat/materialize:
- The binding's own mounts (the write repo and a lens's read mounts) are always readable.
- Any other repo, found by root-commit id through repos.Manager.ByRootID, is read only when `materialize.Request.MayRead(repoName)` says yes. Both edges (knomit_materialize, REST facts/*/materialize) pass `auth.ReachesRepo(ctx, name)`.
- auth.ReachesRepo is DEFAULT-DENY, like auth.Allowed (kb/invariants/auth/one-principal-one-check/8d5cc79d.md): a context with no recorded reach reaches nothing. So EVERY edge that mints a principal must record one with auth.WithRepoReach:
  - AuthMiddleware (auth disabled, socket or named-pipe peer, TLS certificate, loopback anonymous): auth.AllRepos, because grants carry no repo dimension and these callers can already call every repo's routes. A request that gets no principal gets no reach.
  - BearerMiddleware (the OAuth listener) records the token's reach from its audience (tokenRepoReach): a token whose audience covers a repo's routes (/, /api/v1, /api/v1/repos) reaches it; a token for one repo's endpoint (/api/v1/repos/<name>/...) reaches that repo only (a '/' boundary: alpha does not reach alphabet); a token for the UNSCOPED MCP endpoint — /api/v1/mcp or ANY path under it (/api/v1/mcp/<suffix>, which the router also serves as the unscoped endpoint; `httpx.IsUnscopedMCP`, user ruling 2026-10-29) — reaches EVERY repo, because its client binds a repo or lens after the token is issued and that endpoint may bind any (kb/decisions/mcp/session-binding/scoped-endpoint-bind/3408dd94.md: only the URL-scoped endpoints are confined); a lens endpoint's token reaches no repo by name (its own mounts are readable through the binding).
  - mcpHTTPContext copies the reach with the principal and ceiling.
- Resuming a cursor re-checks the RESUMING caller's reach (ReadBodies goes back through MayRead): the cursor's binding pin is not per principal, so a narrower credential could otherwise page through nodes a wider caller snapshotted. A refused resume answers the plain expiry error and puts the page back on the queue.
- Refused and nonexistent answer the SAME reason, `kb_unavailable`, so a caller cannot probe which repos exist.
- A nil Manager or nil MayRead reaches nothing outside the binding.

CONSEQUENCE: any new edge that mints a principal must call auth.WithRepoReach, or its callers silently lose cross-KB (fail closed); any new server-side read that leaves the request's own repo must ask auth.ReachesRepo. TestEveryAuthEdgeRecordsARepoReach (internal/edge/web) pins the edges.

WHAT THIS DOES NOT MEAN: ReachesRepo is not a permission check; read permission is still Allowed's question. And it is not the binding: knomit_bind on the unscoped endpoint does not consult reach (pre-existing; out of scope of PR #675).

NON-EDGE CONTEXTS (audit G5): a ctx built inside the server, where no edge records a reach, must record one itself. The trigger dispatcher's script and recipe host ctx (RepoInstance.hostContext, internal/corpus/repos/manager.go) carries the repo's own binding AND a reach of THAT repo only, never all repos: a trigger is the server acting on one repo's own events, not a caller whose access covers the server. Pinned by TestScript_HostContextReachesOnlyItsOwnRepo (sabotaged both ways: no reach, all repos). Recipes' spawned agents call back over the local socket edge and get that edge's reach. Background jobs (synthesis, index rebuild, review) do not call ReachesRepo today; one that ever reads beyond its own repo must record a reach the same way.

LENS REACH (PR #680): the same edges also record `auth.WithLensReach` (AuthMiddleware: AllLenses; BearerMiddleware: tokenLensReach — a token for /api/v1/lenses/L… reaches L, /api/v1/lenses or wider and /api/v1/mcp or any path under it reach every lens, a repo token none), and mcpHTTPContext copies it. It is default-deny too, and it does NOT widen ReachesRepo: a lens token still reaches no repo by name, so materialize still treats a lens token's non-member repos as kb_unavailable. Its consumers are knomit_repos (which lists a reached lens and its members) and, through ReachesRepo, lens membership edits (kb/invariants/lens/membership/add-needs-reach/bc6a8362.md).

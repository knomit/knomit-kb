# Per-branch write lock is held through NotifyCommit — readers never see torn state

The per-branch RWMutex held by lockBranch(branch) is held for the FULL mutation — from initial ref resolution through SetReference AND notifyCommit's index sync — NOT released between the git write and the SQL update. The mutex map is the branchMu sync.Map of vcs.Repo (internal/engine/store/internal/vcs/branch.go since hier-07; formerly repoHandler.branchMu), keyed by branch name with *sync.RWMutex values. Writers take Lock through LockBranch; Verify takes RLock via LockBranchRead (formerly lockBranch/lockBranchRead; the parent reaches both as rh.LockBranch/rh.LockBranchRead through the embedded *vcs.Repo). Holding the write lock through notifyCommit prevents any reader (including a concurrent Verify) from observing the torn-state window where git HEAD has advanced but branch_facts / facts_vec / graph haven't yet caught up. Anti-pattern: releasing the branch lock between SetReference and notifyCommit — makes Verify race against the mutation and observe inconsistent state.

WHERE IT HOLDS NOW (verified at f3c32912, after the store split and PR E4): the lock is vcs.Repo.LockBranch / LockBranchRead on branchMu (internal/engine/store/internal/vcs/branch.go). The writers reach it as fi.rh.vr.LockBranch in the facts child (facts/fact_write.go: each of WriteFile, DeleteFile and batchWrite takes the lock, defers the unlock and calls fi.rh.vr.NotifyCommit before returning) and as rh.vr.LockBranch in the merge child (merge/branch_merge.go: mergeIntoBranchResolved takes the destination lock, then the Locked cores call rh.vr.NotifyCommit after moving the ref). The Service-level MergePushed and MergeConsensus take the lock themselves with rh.LockBranch and call MergeIntoBranchLockedOpts under it. The exported Locked cores run WITHOUT taking the lock, which is why test/archtest TestStoreMergeCores_OnlyInsideStore forbids them outside internal/engine/store: a caller that took no lock would reintroduce the torn-state window. The Verify reader is fsck (fsck/integrity.go, LockBranchRead). The older refs to internal/store/branch.go and internal/engine/store/facts/fact_write.go were pre-split paths that no longer exist and were dropped.

# Per-branch write lock is held through notifyCommit — readers never see torn state

The per-branch RWMutex held by lockBranch(branch) is held for the FULL mutation — from initial ref resolution through SetReference AND notifyCommit's index sync — NOT released between the git write and the SQL update. The mutex map is repoHandler.branchMu sync.Map keyed by branch name with *sync.RWMutex values. Writers take Lock; Verify takes RLock via lockBranchRead. Holding the write lock through notifyCommit prevents any reader (including a concurrent Verify) from observing the torn-state window where git HEAD has advanced but branch_facts / facts_vec / graph haven't yet caught up. Anti-pattern: releasing the branch lock between SetReference and notifyCommit — makes Verify race against the mutation and observe inconsistent state.

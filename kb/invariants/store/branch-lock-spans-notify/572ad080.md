# Per-branch write lock is held through NotifyCommit — readers never see torn state

The per-branch RWMutex held by lockBranch(branch) is held for the FULL mutation — from initial ref resolution through SetReference AND notifyCommit's index sync — NOT released between the git write and the SQL update. The mutex map is the branchMu sync.Map of vcs.Repo (internal/store/internal/vcs/branch.go since hier-07; formerly repoHandler.branchMu), keyed by branch name with *sync.RWMutex values. Writers take Lock through LockBranch; Verify takes RLock via LockBranchRead (formerly lockBranch/lockBranchRead; the parent reaches both as rh.LockBranch/rh.LockBranchRead through the embedded *vcs.Repo). Holding the write lock through notifyCommit prevents any reader (including a concurrent Verify) from observing the torn-state window where git HEAD has advanced but branch_facts / facts_vec / graph haven't yet caught up. Anti-pattern: releasing the branch lock between SetReference and notifyCommit — makes Verify race against the mutation and observe inconsistent state.

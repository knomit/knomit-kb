# Interpolating any value into a cypher('...') string MUST use escapeCypherKey, never json.Marshal

GraphQLite queries run as a SQL string `SELECT cypher('<query>')` — a DOUBLE-LAYER context. The Cypher query is a SQL single-quoted literal, and string values inside it are Cypher double-quoted literals. Interpolating a value therefore has to escape BOTH layers: `\` and `"` for the inner Cypher `"..."`, AND `'` for the outer SQL `cypher('...')`.

`escapeCypherKey` (internal/store/search_graph.go) is the single helper that does this: it strips NULs, escapes `\` → `\\` and `"` → `\"`, and STRIPS `'` entirely. Every `cypher('...')` query in search_graph.go (MERGE/MATCH/SET on Fact, Entity, Domain, Ontology nodes) uses it. `escapeCypherVal` is the SET-value variant (encodes `'` as `'`).

ANTI-PATTERN that bit us: `json.Marshal(path)` to quote a value. JSON escapes `"` and `\` but NOT `'`, so a value containing a single quote breaks out of the outer SQL `cypher('...')` literal — a real SQL/Cypher injection. `SubgraphEdges` (added by PR #98) built its OR-chained `a.path = <json>` predicates this way; fact paths are partly freeform (categories via knomit_learn), so a quoted path was exploitable. Fixed by switching to `escapeCypherKey` and pinned by TestSubgraphEdges_QuoteInPathDoesNotInject. Rule: NEVER hand-quote or json-encode for a cypher() context — always route through escapeCypherKey (keys/MATCH) or escapeCypherVal (SET values).

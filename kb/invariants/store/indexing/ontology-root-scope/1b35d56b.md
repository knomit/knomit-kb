# Index membership is decided by LOCATION (under the ontology root), never by whether a file parses as a fact

A .md file enters the fact index ONLY if it sits under the configured ontology root (cfg.OntologyRoot, default "kb"). The single predicate is repoHandler.isFactPath(path) = strings.HasPrefix(path, ontologyRoot()+"/") AND strings.HasSuffix(path, ".md"), applied at all three admission points: searchIndex.Sync's full-rebuild branch, Sync's incremental added/modified branch, and rebuildFacts when populating _rebuild_entries. The root reaches the store via Service.SetOntologyRoot, wired from cfg.OntologyRoot at all four sites that also wire SetNetworkTimeout (repos/builder.go, repos/lifecycle.go x2, repos/swapstore.go); store.Open does not restore it, and an unset factRoot falls back to the package const defaultOntologyRoot = "kb".

WHY location and not parseability: fact.ParseFact accepts ANY file that opens with '---\n', closes the frontmatter, holds valid YAML, and whose body starts with an '#' heading — the ordinary shape of a markdown document. A parse-based rule therefore hands index membership to whoever authors the file. That went live when the repo description became user-editable through PATCH /api/v1/repos/{repo}, which commits verbatim markdown to kb.md at the TREE ROOT: a manifest written with frontmatter parsed, indexed as a fact at path 'kb.md', and was then reported by knomit verify as a 'branch_facts row for path not present in tree at HEAD (ghost)' Error, because checkFactsCoherence builds its expected set from the ontology root alone.

CONSEQUENCE for anyone adding a new writer or a new index entry point: gate on isFactPath, and put non-fact artifacts (kb.md, index.md, log.md, views/) anywhere OUTSIDE the ontology root — placing one inside it is what makes it a fact, regardless of intent. Verify (checkFactsCoherence, checkFactFormat) uses the SAME predicate, so the writer's rule and the integrity checker's expectation cannot drift, and a custom ontology_root is honoured by both.

WHAT THIS DOES NOT MEAN: (1) It is not a replacement for the parse-failure skips in indexFile and rebuildFacts' 'WHERE pe.parsed IS NOT NULL' — location bounds WHERE a fact may live, parsing still decides whether a file in that place is a well-formed one; both checks remain. (2) It does not apply to DELETIONS: Sync's deleted branch is deliberately NOT scope-filtered, because a row admitted by an older build or under a previous ontology root must still be evictable, and si.delete on a never-indexed path is a no-op. (3) Changing the root does not re-scope an existing index — rows admitted under the previous root survive until the next Rebuild, which is the repair path.

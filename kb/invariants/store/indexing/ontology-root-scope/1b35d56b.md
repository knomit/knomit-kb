# Index membership is decided by LOCATION — under the ontology root AND with no dot-prefixed segment at any depth — never by whether a file parses as a fact

A .md file enters the fact index ONLY if it sits under the configured ontology root (cfg.OntologyRoot, default "kb") AND no `/`-separated segment of its path begins with ".". The single predicate is repoHandler.isFactPath(path) = strings.HasPrefix(path, ontologyRoot()+"/") AND strings.HasSuffix(path, ".md") AND !fact.IsPrivatePath(path), applied at all three admission points: searchIndex.Sync's full-rebuild branch, Sync's incremental added/modified branch, and rebuildFacts when populating _rebuild_entries. The root reaches the store via Service.SetOntologyRoot, wired from cfg.OntologyRoot at all four sites that also wire SetNetworkTimeout (repos/builder.go, repos/lifecycle.go x2, repos/swapstore.go); store.Open does not restore it, and an unset factRoot falls back to the package const defaultOntologyRoot = "kb".

WHY location and not parseability: fact.ParseFact accepts ANY file that opens with '---\n', closes the frontmatter, holds valid YAML, and whose body starts with an '#' heading — the ordinary shape of a markdown document. A parse-based rule therefore hands index membership to whoever authors the file. That went live when the repo description became user-editable through PATCH /api/v1/repos/{repo}, which commits verbatim markdown to the ROOT MANIFEST at the TREE ROOT: a manifest written with frontmatter parsed, indexed as a fact at its root path, and was then reported by knomit verify as a 'branch_facts row for path not present in tree at HEAD (ghost)' Error, because checkFactsCoherence builds its expected set from the ontology root alone. (That manifest was `kb.md` when this was discovered. PR #68 renamed it to README.md — repos.ReadmePath — as a clean break with no legacy fallback, and added a read-only LICENSE beside it. The filename changed; the reason it must stay out of the index did not.)

THE DOT-SEGMENT EXTENSION (PR #68): the location test now ALSO excludes any path segment beginning with ".", at any depth, INCLUDING under the ontology root. So a well-formed fact hand-placed at kb/.drafts/x.md is deliberately not indexed, and kb/.drafts/ works as a private stash. This EXTENDS the rule rather than replacing it — membership is still decided by where a file sits, never by whether its bytes parse. isFactPath is only ONE of seven discovery guards enforcing the private half; the full enforcement surface, and the traps around it, are in kb/invariants/fact/private-paths/b6babb00.md.

CONSEQUENCE for anyone adding a new writer or a new index entry point: gate on isFactPath, and put non-fact artifacts (README.md, LICENSE, index.md, log.md, views/) anywhere OUTSIDE the ontology root — or, if one must live under it, under a dot-prefixed segment. Placing one inside the root under an ordinary name is what makes it a fact, regardless of intent. Verify (checkFactsCoherence, checkFactFormat) uses the SAME predicate, so the writer's rule and the integrity checker's expectation cannot drift, and a custom ontology_root is honoured by both.

WHAT THIS DOES NOT MEAN: (1) It is not a replacement for the parse-failure skips in indexFile and rebuildFacts' 'WHERE pe.parsed IS NOT NULL' — location bounds WHERE a fact may live, parsing still decides whether a file in that place is a well-formed one; both checks remain. (2) It does not apply to DELETIONS: Sync's deleted branch is deliberately NOT scope-filtered, because a row admitted by an older build or under a previous ontology root must still be evictable, and si.delete on a never-indexed path is a no-op. (3) Changing the root does not re-scope an existing index — rows admitted under the previous root survive until the next Rebuild, which is the repair path. (4) "Excluded from the index" is not "invisible to knomit": README.md, LICENSE and .domains/ontology.yaml are all read by name on ordinary code paths. This rule governs what gets WALKED into the index, not what may be OPENED.

# facts rows are IMMUTABLE; content-addressed by (path, blob_hash); branches hold junction pointers

facts rows are IMMUTABLE once created — content-addressed by UNIQUE(path, blob_hash). Same content at same path — regardless of which branch or commit — ALWAYS resolves to the same row. Branches hold lightweight junction pointers in branch_facts(branch_id, path, fact_id, commit_hash) with UNIQUE(branch_id, path). Two branches sharing the same content at the same path point to the SAME facts row. COW semantics: when one branch modifies a fact, a new row is created with a different blob_hash; the old row stays for branches still referencing it. Merge between branches copies junction POINTERS, not fact data. Drop branch deletes junction rows then GCs orphaned facts (those with no branch_facts referrers). LOAD-BEARING CONSEQUENCES: (a) Graph nodes for a fact version are immutable — once built, never updated. Upsert SKIPS graph sync on COW hits. (b) Embeddings are immutable. Upsert SKIPS embedding on COW hits. (c) SIMILAR_TO edges are stable; only NEW fact versions trigger edge computation. (d) Syncing a branch that shares most content with an already-indexed branch is nearly free. Anti-pattern: do not UPDATE a facts row in place; instead insert a new row and update the branch_facts pointer.

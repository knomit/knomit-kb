# receive-pack fast-fails, in EVERY verify_signatures mode, a push whose new commit's dot-path content differs from its merge base with the host's upstream (any best base suffices) — early feedback only; the merge-time guard is the authority

`receivePack.privatePathClosure` (internal/store/httphandler_receivepack.go) runs between `reachableNew` and `verify`. For EACH new commit C (newCommits: the walk that stops at commits the host holds), it diffs C's tree against the tree of each best merge base of C and the host's upstream tip (`object.Commit.MergeBase`; no merge base = the EMPTY tree, so an unrelated-history commit may carry no dot path at all). C passes when its private paths (`fact.IsPrivatePath`: any segment beginning with `.`: `.knomit/`, but also `.gitignore`, `.github/`, `kb/.drafts/`) match ANY of those bases. Otherwise the WHOLE push is refused with the ERR `knomit: commit <C> changes <path> relative to <upstream>; ...`. Nothing reaches the host (the closure runs before promote), and it runs before the signature judge, so a refused push never reads the fleet.

IT IS EARLY FEEDBACK, NOT THE AUTHORITY. It judges only the commits a push SENDS: a push whose tip the host already holds brings none and passes untouched, and branches already on the host are never re-judged. The authority is the merge-time guard in MergePushed and MergeConsensus, which refuses any merge whose RESULT changes the dot paths of the host's AGENT branch (kb/invariants/store/git-serve/pushed-branch-merge/private-path-guard/fbd12444.md). The upstream/main follows that agent branch; nothing merges a pushed branch into main directly.

Consequences at push time:
- a branch that never merged the upstream passes (its base is its own fork point), even when the upstream has since changed `.knomit/`;
- a merge of the upstream passes (its base is the merged upstream commit);
- a criss-cross merge of main passes when it matches either base. An earlier "must match EACH base" rule wedged a member branch for good: the benign merge stayed new on every later push (PR #511 review F1);
- an evil merge and a merge that keeps an OLDER `.knomit/` from a host-held parent are refused. "Differs from every parent" (git's combined-diff notion, the first implementation) was WRONG: the old version equals one parent, yet a three-way merge into the agent branch applies it as a revert (security review, HIGH).
- "Any base" alone would be unsafe: the merge machinery uses bases[0], so a commit matching only the other base could revert through it. It is safe ONLY because the merge-time guard judges the result.
- Every new commit is checked, and the ERR names the first offender in newCommits order, which is TIP FIRST.

Cost: one go-git MergeBase walk per new commit (each walks the newer side's history), so O(new commits x history), not O(push). Accepted for now.

WHAT IT DOES NOT MEAN: it is not tied to verify_signatures (off included) and not limited to `.knomit/`; passing it does not mean a branch will merge.

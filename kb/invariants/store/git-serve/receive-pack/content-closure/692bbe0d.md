# A receive-pack push is refused, in EVERY verify_signatures mode, when a new commit's dot-path content differs from its merge base with the host's upstream — not merely when it differs from every parent

`receivePack.privatePathClosure` (internal/store/httphandler_receivepack.go) runs between `reachableNew` and `verify`. For EACH new commit C (newCommits: the walk that stops at commits the host holds), it diffs C's tree against the tree of every best merge base of C and the host's upstream tip (`object.Commit.MergeBase`; no merge base = the empty tree) and refuses the WHOLE push with the ERR `knomit: commit <C> changes <path> relative to <upstream>; ...` if any changed path satisfies `fact.IsPrivatePath` (any segment beginning with `.`: `.knomit/`, but also `.gitignore`, `.github/`, `kb/.drafts/`). Nothing reaches the host (the closure runs before promote), and it runs before the signature judge, so a refused push never reads the fleet.

In words: a pushed branch must carry exactly the private state of where it forked off the upstream. Consequences:
- a branch that never merged the upstream passes (its base is its own fork point), even when the upstream has since changed `.knomit/`;
- a merge of the upstream into the branch passes (its base is the merged upstream commit, whose `.knomit/` it carries);
- an evil merge (private content differing from both parents) is refused;
- a merge of the NEWER upstream that keeps the OLDER `.knomit/` of its other parent is refused. This last case is why the first implementation's rule, "refuse paths that differ from EVERY parent" (git's combined-diff notion), was WRONG: the old version equals one parent so it passed, and a three-way merge into main (`consensus: auto`, `MergePushed`) then applies it as a revert of the newer `.knomit/`. A security review rated it HIGH before merge.
- Because every new commit is checked, a commit that changes `.knomit/` refuses the push even if a later commit restores it, and the ERR names the FIRST offending commit in newCommits order, which is TIP FIRST (a test asserting the commit that introduced the change will fail when later commits still carry it).

WHAT IT DOES NOT MEAN: it is not tied to verify_signatures (off included) and not limited to `.knomit/`; it does not refuse a pushed branch for lagging behind the upstream's `.knomit/`. Cost: one merge-base walk per new commit (go-git MergeBase is not O(push)), unlike newCommits which is.

# rebuildGraph reads its `facts` snapshot INSIDE its write transaction: facts rows and graph Fact nodes are version-keyed and shared by every branch while lockBranch is per branch, so a snapshot taken before BEGIN lets a concurrent cross-branch delete be resurrected as a live node with no facts row

internal/engine/store/index/search_index.go rebuildGraph (index.Index.rebuildGraph since #557; PR #414, issue #411). The rebuild of branch B holds lockBranch(B) only. `facts` rows and graph Fact nodes are keyed by (path, blob_hash) and shared across branches, so a writer on another branch is NOT excluded. Before the fix rebuildGraph ran `SELECT … FROM facts f` (and built currentSet) BEFORE BeginTx. A delete on another branch (searchIndex.delete: remove the facts row, soft-delete the node) landing in that window was undone: the transaction re-MERGEd the node from the stale snapshot via graphSyncFactTx and flipped it live. Verify then reports 'live graph Fact node … has no facts row (delete path left node live)'. It surfaced as the CI failure TestReconcile_G8_AdoptOriginAgentAfterMainAdvanced once the lifecycle machine ran Sync concurrently with the index heal.

RULE: the facts snapshot and currentSet are read through the transaction, after BeginTx. Under _txlock=immediate the transaction holds the write lock from BEGIN, so any other writer lands wholly before the read or wholly after the commit. What may stay before BEGIN: the commit_log events query for THIS branch and the git-read cache (go-git reads touch no table the transaction writes, and keeping them out keeps git I/O off the write lock).

General form, same shape as the similarity-layer race (TestRebuild_DoesNotDestroyConcurrentCrossBranchSimilarityEdges, beforeSimTx): any Rebuild step that reads SHARED cross-branch state (facts, graph nodes, edges) and then writes from that read must read inside the write transaction, or scope its writes so a concurrent writer's changes cannot be overwritten. lockBranch does not protect shared tables (kb/invariants/store/index/branch-locking/f4911495).

Regression test: TestRebuild_GraphSnapshotDoesNotResurrectAConcurrentCrossBranchDelete (rebuild_graph_race_test.go) deletes another branch's only version of a fact from the test-only beforeGraphTx hook (fired between the git-read cache and BeginTx) and asserts Verify{Deep:true} is clean; red without the fix, green with it.

# branch_facts.commit_hash (the anchor of HEAD explain/Connections) must HOLD the path's blob: it is the path_changes entry live at the branch tip, computed by ONE function (recordedCommit) for the incremental index and the rebuild

ExplainFact (HEAD explain, REST Connections) anchors on branch_facts.commit_hash (kb/conventions/store/active-commit-via-branch-facts). If that commit does not contain the path, OutgoingAtCommit / IncomingAtCommit find 'path never written in the ancestry' and Connections is EMPTY.

THE RULE: the commit recorded for (branch, path, blob) is recordedCommit (index/search_index.go):
- the path_changes change live on the tip's first-parent line, AS THE ENTRY IT RESOLVES TO (vcs.LiveChange), when that entry's blob is the path's blob. A merge carrying the content resolves to the commit that wrote it; a revert resolves to the revert commit (the LIVE introduction, not the first one);
- else LastCommitForPath, ONLY if it holds the blob;
- else the tip (the file was read there).
indexFile records it on every sync (COW hit, rename, restore, experiment commit in FF or merge mode, remote reconcile: they all reach upsert only through indexFile). rebuildFacts computes the same function per path, before its transaction (the fallbacks read git). CreateBranch copies the parent's rows (vcs/branch.go), and they are the same answer for the child.

BUG IT FIXES (PR #693 round 3, P1; also on dev): X written on branch A, merged into B after B moved on. indexFile recorded LastCommitForPath's commit, B's last non-merge commit, which lacks kb/x.md, so explain for X on B was empty. The old rebuild recorded the latest commit_log row instead (the merge), so rebuild != incremental.

EXISTING STORES: the GraphSchemaVersion 8 rebuild rewrites the rows of the branches it rebuilds (rebuildFacts). The drain of the other branches runs repairRecordedCommits first: a per-row guarded UPDATE (only if the row still has the fact and commit it was read with, because no lock is held) before the pending mark is cleared.

OPERATIONAL CONSEQUENCE: never write branch_facts.commit_hash from LastCommitForPath, the branch tip or the latest commit_log row directly. Go through recordedCommit, so the anchor holds the blob and rebuild == incremental.

WHAT THIS DOES NOT MEAN: it is not the blob's EARLIEST introduction (that is introducingCommit, for reference edges). A revert records the revert commit, while the blob's edges stay at its first introduction; both commits hold the blob, so explain still finds the edges by blob.

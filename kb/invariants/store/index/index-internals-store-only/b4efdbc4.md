# Service.IndexManager() returns the concrete *index.Index, but outside internal/store only SyncLocked, Rebuild, SyncWatermark and NeedsRebuild are for callers: SetSyncSuspended, GC, EnsureFactsVecDefault and PersistedEmbedModelID/PersistedEmbedDim are the store's own, and the lock-free Sync assumes the branch lock

Since E7a (PR #584, merged as 32414d74; re-read there) the model.IndexManager interface (Sync, SyncLocked, Rebuild, SyncWatermark, NeedsRebuild) is gone and Service.IndexManager() returns the concrete *index.Index (internal/store/service.go), so every exported method of it is reachable from every package that holds a Service. The five names that are the store's own: SetSyncSuspended (makes every Sync a silent no-op; Replay sets it around a bulk replay into a transient store, internal/store/replay.go), GC (deletes index rows for facts the index believes are orphaned), EnsureFactsVecDefault (creates the vector table before an embedder exists; store.Open calls it once), and PersistedEmbedModelID / PersistedEmbedDim (feed the integrity report). The lock-free Sync is the in-lock primitive and assumes the caller holds the branch lock (kb/invariants/store/index/branch-locking/f4911495.md); callers outside the store use SyncLocked.

THE GUARD: TestStoreIndexInternals_OnlyInsideStore (test/archtest/store_write_internals_test.go) parses every .go file outside internal/store/** (>= 500 files walked) and fails (a) on any selector of the five names, test files included (runtime.GC, the standard library's, is excepted), and (b) in NON-test files only, on a lock-free `Sync` whose receiver it can tell is an *index.Index. TestStoreIndexInternals_GuardDiscriminates runs the detector on inline source. Non-vacuity: each of the five names is still declared as a method in internal/store/index and still selected by a non-test file elsewhere in internal/store, and Sync is still declared.

MISREADING (named): the guard does NOT prove that no outside lock-free Sync exists. The Sync half is SYNTACTIC and PER-FILE. It recognises a receiver only as a call chain ending in IndexManager(), an identifier or field the SAME file declares as *index.Index (parameter, struct field, `var x *index.Index`) or assigns from IndexManager() (assignment or composite-literal key). Known misses, verified by reading the detector at 32414d74: a package-level or local `var x = svc.IndexManager()` (a ValueSpec with no declared type is not bound), a helper function that returns *index.Index (its result is not tracked), and a field declared as *index.Index in ANOTHER file of the same package. It proves only that no lock-free Sync is written in the recognised shapes. Also: it does not forbid SyncLocked or Rebuild, and tests outside the store may call the lock-free Sync to build fixtures (none does today). The five-name half has no such gap: it matches the selector name on any receiver.

CONSEQUENCE: do not hand the *index.Index to code outside the store and rely on the guard alone for the Sync rule; review any new outside use of IndexManager() by reading. A new store-only method on index.Index that must not leak is added to indexInternals in the same PR. Sabotage reported by the PR author, not re-run by the curator: each of the five names and Sync, in a new internal/web file, fails the test; Sync in a _test.go file passes.

# Three-way merge with tree identical to dst MUST be reported as noop, never as merge

Inside mergeIntoBranch, after the three-way merge produces mergedTreeHash, if mergedTreeHash == dstCommit.TreeHash the result is reported as Mode=ModeNoop (NOT 'merge') and NO merge commit is synthesized: the function returns AgentReconcileResult{Mode: ModeNoop, NewTip: dstHash} WITHOUT calling SetEncodedObject / SetReference / notifyCommit (internal/store/branch_merge.go:146-152). This preserves the commit-log parity invariant: zero-diff merge commits never enter history. It is what makes the squash-merge case fast-forward correctly — when the remote squashes agent's commits, the re-merge yields a tree identical to dst and is suppressed.

WHAT THIS DOES NOT MEAN: the noop check is specifically the THREE-WAY-merge-tree comparison (merged tree == dst tree). It is NOT a general 'nothing changed on this branch' signal — it fires only on this equality after mergeTreesWithStrategy; the real-merge path immediately below (154+) writes the commit, moves the dst ref, and runs populateCommitLog + notifyCommit. NewTip on a noop is dstHash unchanged, so callers must not treat a noop as advancing the branch.

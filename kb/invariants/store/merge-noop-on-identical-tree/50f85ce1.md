# Three-way merge with tree identical to dst MUST be reported as noop, never as merge

Inside mergeIntoBranch, after the three-way merge produces mergedTreeHash, if mergedTreeHash == dstCommit.TreeHash the result is reported as Mode='noop' (NOT 'merge') and NO merge commit is synthesized. This preserves the commit-log parity invariant: zero-diff merge commits never enter history. This is what makes the squash-merge case fast-forward correctly — when the remote squashes agent's branch into main, the agent's tree already equals main's tree, so a three-way merge yields a no-op. If a future refactor synthesizes a merge commit for an identical-tree case, G9 (squash-merge) regresses to N orphan commits per sync tick.

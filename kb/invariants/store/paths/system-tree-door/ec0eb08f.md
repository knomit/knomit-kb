# Service.WriteSystemTree is the ONE write door that keeps the case of a nested path; it accepts only README.md and paths under .knomit/, refuses two paths differing only by case, and is never on the MCP surface

RULE: every fact write door lowercases nested paths (kb/gotchas/store/paths/lowercased-nested-writes), so a template's `.knomit/skills/x/SKILL.md` and `README.md` written through BatchWriteFacts land as `skill.md` and `readme.md`. F24 needed the template copied byte for byte, so `Service.WriteSystemTree` (a one-line forward in internal/store/service_facts.go) writes WITHOUT lowercasing through facts.Index.WriteSystemTree (internal/store/facts/system_files.go). (The old pin on internal/store/templates.go@bf1d141c is HISTORICAL: that file no longer holds this door.) Because it goes around that normalization it takes the narrowest set that works: exactly `README.md` and paths under `.knomit/` (`fact.TemplatePathAllowed`), and no two paths equal under lowercasing; anything else is `ErrSystemTreePath` before any object is written. Otherwise it is batchWrite: read-only refused (by its OWN gate: it calls batchWriteLocked (facts/fact_write.go; unexported since E2, #573, it was BatchWriteLocked) directly, below the shared writeFileExact/deleteFile/batchWrite seam, so that copy is the only thing keeping a subscription's store from committing through this door; pinned in TestReadOnlyStore_RefusesAuthoredWritesOnEveryBranch, CONSEQUENCE: never delete it as 'unreachable through create'), validatePath per path, `batchWriteLocked` (signer taken first, ctx trailers stamped, one commit), `notifyCommit` under the branch lock.

CONSEQUENCE FOR NEW CODE: do not widen it to 'root-level files': a root LICENSE, .gitmodules or a readme.md beside README.md is a file knomit never writes (internal/repos/manifest.go), and a case-duplicate is resolved by forges as the README. Do not expose it through MCP or REST: `.knomit/` stays closed to the fact tools (F25); the door exists for knomit's own server act of creating a repo from a template.

MISREADING: it is not a general 'exact path' write; WriteRootFile (root-only) is still the door for a root file rewrite.

LOCATION (refactor-store-slim-d-orchestration): the door's body is facts.Index.WriteSystemTree in internal/store/facts/system_files.go; Service.WriteSystemTree is a one-line forward. It is deliberately not in facts/fact_write.go or facts/triggers.go, which text-scanning guards read by path. The checks (read-only refusal, fact.TemplatePathAllowed, case-fold duplicates, ValidatePath) run before the branch lock, exactly as before the move.

VERIFIED at the PR #573 merge 2a5bcadf (internal/store/facts/system_files.go): facts.Index.WriteSystemTree refuses read-only with fi.rh.vr.ReadOnly(), checks fact.TemplatePathAllowed, the case-fold duplicate and ValidatePath, then takes fi.rh.vr.LockBranch, calls fi.batchWriteLocked and fi.rh.vr.NotifyCommit under the lock. The only change from E2 is the spelling (batchWriteLocked unexported, rh.vr.X); the door's contract is unchanged.

UPDATE (refactor/store-e3-facts-handles, PR #575; state of the branch head 399b0546, recorded before the merge): Service.WriteSystemTree no longer exists. The door is facts.Index.WriteSystemTree, called as svc.Facts().WriteSystemTree(...), and it is reachable from every package that holds a Service, so the rule 'never on the MCP or REST surface' is now enforced by a test and no longer by the Service having no such method: TestStoreSystemTreeDoor_OnlyFromRepos (test/archtest/store_write_internals_test.go) parses every .go file outside internal/store/** and fails on a selector `x.WriteSystemTree` in a non-test file other than the top level of internal/repos (today the one caller is internal/repos/lifecycle.go, creating a repo from a template). It asserts at least 500 files walked, at least one allowed use and that internal/store/facts/system_files.go still declares the method, and TestStoreSystemTreeDoor_GuardDiscriminates runs the detector on inline source. Sabotage on a throwaway worktree at 399b0546: `s.facts.WriteSystemTree(...)` added to internal/mcp/learn.go fails it with `internal/mcp/learn.go line 1202`. Test files anywhere may call it (fixtures); the check is about production reach. The 'Service.WriteSystemTree (a one-line forward in internal/store/service_facts.go)' wording in RULE and LOCATION above is HISTORICAL (service_facts.go is deleted). The read-only refusal, the case-fold check and the lock placement are unchanged (facts/system_files.go), and TestReadOnlyStore_RefusesAuthoredWritesOnEveryBranch calls svc.Facts().WriteSystemTree. MISREADING: the guard does not make the door safe for any internal/repos file; it is a reach limit, and widening it to another package needs a new ruling.

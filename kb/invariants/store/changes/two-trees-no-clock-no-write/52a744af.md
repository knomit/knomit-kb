# knomit_changes (and GET …/branches/{branch}/changes) is a read of TWO TREES — tree at `since` vs tree at head under one folder — with no clock, no commit_log, no write; `since` must be head or its ancestor, a missing folder is the empty tree

`store.ChangesUnder` answers "what is different under this folder since commit C" by diffing the tree at `since` against the tree at head (subtrees at the prefix) with go-git `object.DiffTree`. The answer is a pure function of (tree(since), tree(head), prefix), so two machines holding the same two commits return byte-identical rows. It reads NO timestamp, NO commit_log row and NO index row, and it WRITES NOTHING — the caller keeps `head` in its own state and passes it back as `since` (the user's F05 decision, 2026-09-26).

Load-bearing rules, each pinned by a test in internal/store/changes_test.go with a sabotage that fails it:
1. `since` must be head or an ANCESTOR of head (`commit.IsAncestor`), else `ErrSinceNotBehind` (MCP tool error / REST 409). A reversed or sideways diff reports paths as DELETED that nobody removed — in a task pool, a fabricated take. Honest callers hit it with a bookmark from a machine whose main was further ahead, a head taken from the agent branch (REST twin) and replayed at main (MCP), or a reconfigured Remote.Branch.
2. A prefix folder MISSING at either end is the EMPTY tree (`subtreeOrEmpty` maps object.ErrDirectoryNotFound to nil) — a lane's first post reads as `added`, its last removal (git drops the empty folder) as `deleted`. Never an error, never "no change".
3. The prefix is relative to the ontology root, lowercased, stripped of leading/trailing `/`, never given `.md`, refused on `..` or any dot segment (`NormalizeChangesPrefix`). It must NOT go through `fact.NormalizePath`, which appends `.md` and turns `tasks/a` into the single file `kb/tasks/a.md` — every read then silently returns nothing.
4. Rows drop private paths (any dot segment below the prefix) and non-`.md` files; they sort bytewise; a rename/move is `deleted` + `added` (DiffTree does no rename detection).
5. Paging is a STATELESS cursor carrying (since, head, prefix, last path), shared by MCP and REST; page 2 re-diffs the SAME pinned head. A pinned head must be on the branch's history (else ErrInvalidChangesCursor).
6. An unknown or malformed `since` is `ErrUnknownSince`, an unknown branch `ErrBranchNotFound` (404) — never an empty page, because an empty page reads as "nothing changed".

Anchor: the MCP tool reads the WRITE repo's `UpstreamBranch()` (main) — not the binding's read mount (the agent branch) and not an experiment pin — because every machine's agent branch differs and main is the history two machines share. The REST twin reads the branch in its URL.

Structural guard: `TestChanges_NoWritePathNoClock` walks the AST of the three files and fails on any store writer (WriteFact, BatchWriteFacts, DeleteFact, SetReference, notifyCommit, CommitLogSync, …), any clock (`time.Now`, `.When`) or any commit-log read (CommitLogQuery, LogPaginated).

Misreadings to avoid: (a) "changes is an event log" — it is the NET difference; an add-then-delete between two reads is invisible by design, and op/author are not on the rows (read the fact for them). (b) "extend it with commit_log ordering for per-event rows" — commit time is committer-set, ties break on the instance-local SQLite rowid, and a fast-forward over an agent's merge puts an older deleting commit behind the bookmark (the reviewer's P3d shape; TestChangesUnder_DeletionSurvivesFastForwardOverOlderCommit fails under a time-ordered replay). (c) "a missing since or folder can just return empty" — see rules 2 and 6.

Measured on a backup of live knomit-kb (2465 commits on main): IsAncestor 27 µs one commit back, ~10 ms to the root, ~75 ms on the refusal path (full walk); a first page from the root 48–71 ms, one-commit incremental 14–28 ms.

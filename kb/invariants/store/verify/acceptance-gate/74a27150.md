# store.CheckRange (the F09 acceptance gate) reads verify_signatures at main's tip FIRST and returns before touching the fleet when it is off; when on, each commit in candidate∖main must be signed by the FULL current key of the ONE active member record at its author's opaque agent id

CheckRange(RangeInput{KBDir, Main, Candidate, FleetDir, FleetRev, FleetRoot}) runs over plain git checkouts (no knomit instance), so a CI merge job can run it.

Order: (1) verify_signatures at Main's tip via fact.ReadVerifySettings; off/absent -> verdict off, nothing else runs, no fleet needed (the ontology is not even parsed); an unknown value is an error. (2) LoadFleet: the fleet checkout's ontology must be the fleet preset (ErrNotFleet), member records under <root>/members/ are loaded; a malformed record is SKIPPED and logged at ERROR once per (fleet, path, blob) process-wide (malformedLogged), never failing the load. A missing fleet (ErrNoFleet) or unreadable one is an error = could not run. (3) Every commit in Candidate minus Main: an unsigned merge passes only M3 (adds nothing beyond its parents); otherwise the SSHSIG must verify; the author address <id>[+op]@agents.knomit.io gives the OPAQUE id (agentIDOfAuthor, never parsed further); exactly one record at that id (0 = no-record, >1 = ambiguous); the signing key must equal that record's CURRENT key by full wire bytes (key-mismatch) and be no other record's current key (duplicate-key); state must be active (inactive).

RangeVerdict.ExitCode: 0 for off, clean, or log with refusals (reported only); 1 for enforce with refusals. Errors are exit 2 in the command. MISREADINGS: a key-only lookup (find the record by the signing key) is WRONG: author X signing with another active member's key is refused (TestCheckRange_AuthorMustOwnTheKey). After a rotation the OLD key is refused at the gate (current key only); history-aware attribution is the audit's job, not the gate's.

UPDATE (PR #514, verified at the merge commit): when verification is on, the ontology at Main must also PARSE (ParseOntology; an unparseable one, for example a bad artifacts: value, is exit 2 / a push refusal until fixed), and after the signer rules accept a commit judgeCommit runs artifactRules against that ontology's artifacts section for every changed artifacts/ path, diffed against EVERY parent (see kb/invariants/store/verify/artifact-rules/fd3ab8ab.md). With the fleet's declared root present at the fleet revision, a commit that passes the record rules must also pass rule B (the id's leaf is issued to the id, names the record's key, chains and is not on the CRL: no-cert, key-mismatch, revoked; kb/invariants/store/verify/rules-ab/73f5bf62.md), and rule A can admit a refused no-record/key-mismatch/inactive self-registration (kb/invariants/store/verify/rules-ab/self-registration/26588c65.md). The id is compared, never parsed: agentIDOfAuthor is pki.AgentIDOfEmail, ids are lower case and nothing is case folded (kb/invariants/pki/agent-id-binding/efad10db.md). MISREADING: the 'exactly one active record' summary above is the record rule only; with a PKI present a record alone is no longer enough.

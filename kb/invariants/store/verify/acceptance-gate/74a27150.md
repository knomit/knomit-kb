# store.CheckRange (the F09 acceptance gate) reads verify_signatures at main's tip FIRST and returns before touching the fleet when it is off; when on, each commit in candidate∖main must be signed by the FULL current key of the ONE active member record at its author's opaque agent id

CheckRange(RangeInput{KBDir, Main, Candidate, FleetDir, FleetRev, FleetRoot}) runs over plain git checkouts (no knomit instance), so a CI merge job can run it.

Order: (1) verify_signatures at Main's tip via fact.ReadVerifySettings; off/absent -> verdict off, nothing else runs, no fleet needed; an unknown value is an error. (2) LoadFleet: the fleet checkout's ontology must be the fleet preset (ErrNotFleet), member records under <root>/members/ are loaded; a malformed record is SKIPPED and logged at ERROR once per (fleet, path, blob) process-wide (malformedLogged), never failing the load. A missing fleet (ErrNoFleet) or unreadable one is an error = could not run. (3) Every commit in Candidate minus Main: an unsigned merge passes only M3 (adds nothing beyond its parents); otherwise the SSHSIG must verify; the author address <id>[+op]@agents.knomit.io gives the OPAQUE id (agentIDOfAuthor, never parsed further); exactly one record at that id (0 = no-record, >1 = ambiguous); the signing key must equal that record's CURRENT key by full wire bytes (key-mismatch) and be no other record's current key (duplicate-key); state must be active (inactive).

RangeVerdict.ExitCode: 0 for off, clean, or log with refusals (reported only); 1 for enforce with refusals. Errors are exit 2 in the command. MISREADINGS: a key-only lookup (find the record by the signing key) is WRONG: author X signing with another active member's key is refused (TestCheckRange_AuthorMustOwnTheKey). After a rotation the OLD key is refused at the gate (current key only); history-aware attribution is the audit's job, not the gate's.

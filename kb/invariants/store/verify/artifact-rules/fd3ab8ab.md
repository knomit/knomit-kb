# The judge enforces the JUDGED repo's artifact rules (its ontology at main) on every commit, against EVERY parent: files with a change rule are never deleted; write-once never modified; append-only by exact byte prefix; replace only under crl-newer (root-signed, Number strictly greater, and with revoked_set: superset every old serial still listed) or leaf-renewal; max_size; a declared path holds a regular file and nothing sits under it (artifact-not-a-file); a pki file, when ADDED, holds as its role (root CA, root-signed CRL, leaf for its file's id, canonical issuance record that chains, root-signed revocation statement)

store.judge.artifactRules (internal/store/verify_artifacts.go) runs after the signer rules accept. Diff: object.DiffTree against each parent (empty tree for a root commit), no rename detection. PKI context (root, CRL, member records) is read from the commit's OWN tree. Refusal rules: artifact-write-once, artifact-append-only, artifact-replace, artifact-size, artifact-pki, artifact-not-a-file, artifact-rules (ambiguous rules, unreadable blob, or a blob above the judge's read bound).

A FIRST ADD of a declared file is allowed, but an added root must be a CA cert, an added CRL root-signed, an added leaf must chain, be unrevoked and be issued to its file's id, an added issuance record must pass pki.CheckIssuance and an added revocation file pki.VerifyRevocation (both against the tree's root). CheckIssuance admits exactly ONE canonical CERTIFICATE PEM block: the file must be byte-equal to pem.EncodeToMemory of its own block, so leading or trailing junk, a second block, headers, CRLF and a missing final newline are refused artifact-pki. Issuance and revocation records are NOT cross-checked against the CRL or the leaves, and their file names mean nothing. Undeclared paths have no rule. Log mode reports, off judges nothing.

ARTIFACT-NOT-A-FILE (squat): a tree, symlink or submodule AT a declared path is refused, and so is any entry UNDER a directory that a pattern declares a FILE, e.g. certs/<id>.pem/x squatting a leaf's name (review F6). Under a directory d, the entry p is a squat only when some pattern matches d but NOT p (fact.Ontology.ArtifactFileAt). So fleet/** (which matches both fleet/issued and fleet/issued/x.pem) declares a family and squats nothing, while fleet/* DOES declare fleet/issued a file and refuses adds beneath it. MISREADING: 'any pattern that matches a directory makes it a file' (the pre-round-4 behaviour) refused every add under fleet/** and was fixed in round 4.

RESIDUAL: a fleet with NO root yet accepts any member's first root.crt (trust on first add; review F5); write-once makes a wrong first add irreversible inside the gate. The mitigation is procedural, not code: the documented setup order commits root.crt and crl.pem when the fleet repository is created, before any member exists. A stale-branch merge that reverts a protected file is refused (diff against every parent). No re-judge at merge time (R5).

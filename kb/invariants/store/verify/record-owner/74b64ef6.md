# Record-owner rule (`not-owner`, fleet repository only): a commit may change only members/<own id>/ and DECLARED artifact paths, measured against EVERY parent (the union of the per-parent diffs), may delete nothing in its own folder, and every member record it writes there must have `agent:` equal to the folder id; so a member's merge that settles a conflict with main is refused

Built in PR #523 (merge commit 3ac59b57); replaces the old onlyUnder path check. judge.recordOwner (internal/store/verify_range.go), refusal rule `not-owner` (RuleNotOwner, verify_walk.go).

WHERE IT APPLIES. Only in the fleet repository (the judge's membersDir is non-empty); in every other repository the rule does not exist (TestRecordOwner_OnlyInTheFleetRepository). It is baked into the judge, not declared in any ontology, so no attribute switches it. It runs for a commit the record rules and rule B admit as an active member, and it is rule A's shape check for a self-registration. A two-parent merge that M3 admits never reaches it (see the M3-first decision).

THE RULE, all parts. For the commit's author id, against EVERY parent (the union of the per-parent DiffTree results; the empty tree for a root commit):
1. every changed path (both the From and the To name) must start with members/<id>/ under the judged repository's member root (compared with the trailing slash, so members/ab/ is not members/a/), UNLESS it is a DECLARED artifact path: under artifacts/ AND matched by an artifacts: pattern of the judged repository's ontology at main (an ambiguous match counts as declared; artifactRules then refuses it). An undeclared path under artifacts/ is NOT exempt: on the fleet repository a member may not add, modify or delete it.
2. no change removes a path under members/<id>/ (a member leaves by writing state left, never by removing its record).
3. every .md the commit adds or modifies under members/<id>/ that parses as a member record must have agent: equal to <id>. A file that does not parse as a record is no record (the loader skips it too).
A tree or diff that cannot be read is a refusal.

THE CONSEQUENCE TO PLAN FOR. A member's merge that settles a conflict with main is refused not-owner: it fails M3 (both sides changed), and against main's side it changes other members' paths. This is deliberate: the union, not the intersection (paths that differ from EVERY parent), because the intersection would admit a merge that takes the OLD side of another member's record, reverting it once merged into main (the reasoning of privatePathClosure).

THE MASTER'S COMMITS PASS because they change declared artifact paths only (enroll: leaf plus issuance record; revoke: newer CRL plus revocation statement).

MISREADINGS. 'artifacts/ is exempt' is wrong: only DECLARED artifact paths are, and they still go through artifactRules. 'The folder may hold only the record' is wrong: extra files in the own folder are allowed (rule A still needs exactly one record there). 'Path ownership alone stops one member locking out another' was the review's blocker B1: an active member could write a record for ANOTHER agent into its own folder; clause 3 plus the loader's folder binding close it together. 'A record can be removed with knomit_retract' is false on the fleet repository: every delete under members/<id>/ is not-owner, so removal needs someone who writes main outside the gate.

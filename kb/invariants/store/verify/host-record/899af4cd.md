# Host-record rule (`host-record`, fleet repository, a MEMBER's branch entering it only): a signed commit that is not a clean merge and changes artifacts/fleet/host (any case spelling), measured against EVERY parent, is refused; CheckRange (`knomit verify ci`) does not run it

RULE (PR #527, verified at merge commit c6e282db). judge.hostRecord refuses (Rule `host-record`) a signed commit when ALL of these hold: the judged repository is the fleet repository (judge.membersDir non-empty); the commit belongs to a member's branch ENTERING this repository (judge.entry, which only repoHandler.judgeIncoming sets: receive-pack on a knomit host, and the master's JudgePeerBranch / AdmitPeerBranch of a fetched or local agent/* branch); the commit is not a clean merge (M3 admits a member's merge of main that adds nothing before this rule runs); and the diff against ANY parent changes a path that EqualFold-matches fact.FleetHostPath (artifacts/fleet/host). It runs after M3 and before the record rules and rule A, for every signed commit. The path is a DECLARED artifact in the baked fleet ontology (fleet/host, 4KiB), which the record-owner rule exempts, so this rule, not record-owner, is what refuses it.

WHY: the host record says where the fleet is hosted, and only the fleet's master writes it (at create and when it becomes the host). The master's own commits never enter through a member's branch (the hub moves main onto its own agent branch; a forge-hosted master publishes it), so a member commit that changes it can only be redirecting every member's fleet URL.

CONSEQUENCE: a check for "may this commit change the host record" must go through judgeIncoming. Moving the rule into CheckRange would refuse the master's own create commits (the forge create test judges them).

EVERY PARENT: the reverting-merge row of TestHostRecord_AMemberMergesTheMastersChange pins that a merge which differs from one parent on the host record is refused, so measuring only the first parent (parents[:1]) goes red there; the forge path (the fetch judge) is pinned by TestFleetMaster_FetchedHostRecordIsRefusedNamingItsAuthor.

MISREADINGS. (1) "`knomit verify ci` refuses a member PR that writes the host record": it does not. CheckRange never sets entry, so on a forge fleet whose PR gate is `knomit verify ci` alone, a member's change to artifacts/fleet/host passes that gate; the product's forge path is the master's fetch judge, which does run the rule. TestHostRecord_ReceivePackRefusesCheckRangeAdmits pins the split. (2) "A member can never have the host record changed on main": the master changes it, and a member's clean merge of main brings the master's change in unrefused. (3) "It protects against a malicious master": it does not; it only stops a member branch.

UPDATE (branch fix/fleet-switch-replay, verified at a78d1b22; re-pin at the merge commit): the rule's path list is now TWO paths: artifacts/fleet/host (fact.FleetHostPath) and artifacts/fleet/master (fact.FleetMasterPath, the acting master's marker, kb/invariants/fleet/master-marker/13dcd692.md), each in any case spelling, against every parent, same rule name (host-record), entry only. Nothing else in the judge changed. Pinned by TestHostRecord_AMemberBranchNeverWritesIt's three marker rows (add, rewrite, delete); dropping the marker check turns them red.

VERIFIED AT THE MERGE (PR #531, squash commit 8ca72760 on dev, 2026-10-16): verify_range.go compares each changed name with strings.EqualFold against fact.FleetHostPath and against fact.FleetMasterPath, under the one rule name host-record, for entry (member branch) commits only; the ontology declares fleet/master (max_size 1KiB) beside fleet/host. TestHostRecord_AMemberBranchNeverWritesIt exists at the merge.

UPDATE (PR #533, squash commit 6f241959 on dev, verified there): 'The master's own commits never enter through a member's branch' is still true, but no longer means they are unchecked. The master's own range is judged before main moves (kb/invariants/store/verify/own-range) and carries the MASTER'S side of this rule, ownHostRecord, in verify_own.go: a commit authored by this instance that changes artifacts/fleet/host or artifacts/fleet/master is admitted only if the marker it leaves names its author or is deleted (never another agent), and, while main's marker names ANOTHER agent, only if the marker it leaves names the author (Host here writes the marker first). When main names self or nobody the master's writes are admitted. Members' commits merged into the master's branch are judged with entry set, so the member rule above applies to them there too. `knomit verify ci` still does NOT run host-record (CheckRange never sets entry); misreading (1) above stands. MISREADING: 'the master can write any host record or marker': not while main names another acting master. Pinned by the forged-marker rows of TestFleetJudgeOwn_AForgeMasterRefusesItsOwnInvalidWritesBeforePublishing and TestFleetMaster_LegacyFleetIsClaimedOnceByTheRootHolder, and the ownHostRecord rows of TestJudgeOwn_TheMastersOwnCommitsAreJudgedBeforeMainMoves.

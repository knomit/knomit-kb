# Rule A admits a commit only when ALL hold: the record rules refused it as no-record, key-mismatch or inactive; the id has NO active record AND the signing key is not the current key of a record for a DIFFERENT id, in any state (R4, O3); the judged repo is the fleet repo; the commit keeps the record-owner rule (every path it changes outside DECLARED artifact paths, vs EVERY parent, is under <root>/members/<author id>/, none under it is deleted, every record written there has agent == the id); the id's leaf is issued to the id, names the signing key, chains and is unrevoked; and the folder then holds exactly one active record for the id with that key

mayRegister (verify_range.go) is R4 / review F2 as clarified by the user (O3): an ACTIVE record under another key is never overwritten through rule A (the takeover), and a key that is the current key of ANOTHER id's record (active, left or revoked) never becomes this id's too. The id's OWN left record holding the same key does NOT block: that is a same-key rejoin. Leave = revoke (a master duty, P5, not built in #514), so the old leaf is on the CRL and rule A admits the rejoin only on a FRESH leaf the master issued after the leave; that leaf is the approval. A same-key rejoin whose certs/<id>.pem is still the revoked leaf is refused revoked by rule A itself.

MISREADING: not 'the key is no record's current key' (that refuses every same-key rejoin, the pre-O3 behaviour), and not 'no ACTIVE record holds the key' (that lets a left id's key be taken by another id).

The other conditions are unchanged from P3 except the path shape, which since PR #523 (merge 3ac59b57) is the record-owner rule (judge.recordOwner, replacing onlyUnder; see the record-owner invariant) against every parent: declared artifact paths are judged by the artifact rules instead of dropped, a delete under the own folder is refused, a record for another agent is refused, and there is no 'changes at least one path' requirement (selfRecord still needs exactly one record in the folder). The rest is unchanged: leafFor (id-bound, R2), selfRecord (one file, parses, agent == id, active, key == signing key). Refusals keep the record rule's verdict with a 'self-registration not admitted: ...' reason, except a leaf for another key (key-mismatch) and a revoked leaf (revoked). When mayRegister is false rule A is not consulted at all (no 'self-registration' text in the reason).

Tests: TestRuleA_OnlyWithoutAnActiveRecordAndForAKeyNoOtherIDHolds (rows: left/old key admitted; active/other key key-mismatch; left/same key + fresh leaf admitted; left/same key + revoked leaf revoked by rule A; key is boss's no-record; key is another id's LEFT record's no-record). Sabotage-checked: any-record key check, no key check, active-only key check, mayRegister=true all red.

UPDATE (PR #523, verified at 3ac59b57): on refusal by the owner rule rule A keeps the record rule's verdict (TestRuleA_RecordMustMatchTheLeaf). A member's merge that settles a conflict with main is not admitted by rule A either (union of the per-parent diffs). Rule A re-checks the CRL through leafFor/verifyLeaf, so a revoked leaf is refused `revoked` here whatever readers derive.

# Rule A admits a commit only when ALL hold: the record rules refused it as no-record, key-mismatch or inactive; the id has NO active record AND the signing key is not the current key of a record for a DIFFERENT id, in any state (R4, O3); the judged repo is the fleet repo; every changed path vs EVERY parent is under <root>/members/<author id>/; the id's leaf is issued to the id, names the signing key, chains and is unrevoked; and the folder then holds exactly one active record for the id with that key

mayRegister (verify_range.go) is R4 / review F2 as clarified by the user (O3): an ACTIVE record under another key is never overwritten through rule A (the takeover), and a key that is the current key of ANOTHER id's record (active, left or revoked) never becomes this id's too. The id's OWN left record holding the same key does NOT block: that is a same-key rejoin. Leave = revoke (a master duty, P5, not built in #514), so the old leaf is on the CRL and rule A admits the rejoin only on a FRESH leaf the master issued after the leave; that leaf is the approval. A same-key rejoin whose certs/<id>.pem is still the revoked leaf is refused revoked by rule A itself. A rejoin under a NEW key is blocked at the artifact layer unless the master also replaces the leaf through the leaf-renewal rule (P5 scope).

MISREADING: not 'the key is no record's current key' (that refuses every same-key rejoin, the pre-O3 behaviour), and not 'no ACTIVE record holds the key' (that lets a left id's key be taken by another id).

The other conditions are unchanged from P3: onlyUnder against every parent, leafFor (id-bound, R2), selfRecord (one file, parses, agent == id, active, key == signing key). Refusals keep the record rule's verdict with a 'self-registration not admitted: ...' reason, except a leaf for another key (key-mismatch) and a revoked leaf (revoked). When mayRegister is false rule A is not consulted at all (no 'self-registration' text in the reason).

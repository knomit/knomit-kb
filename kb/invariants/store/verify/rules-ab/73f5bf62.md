# Once the fleet revision holds its declared root, the judge (CheckRange and receive-pack) admits a member's commit only if the leaf for its id is issued to that id, names the record's key, chains to the root and is not on the CRL (rule B, fail closed); without a declared and present root the rules are the pre-P3 record rules

judgeCommit (internal/store/verify_range.go) = judgeSigner then artifactRules. judgeSigner runs the record rules (one record at the author's opaque id, signing key = its current key and no other record's, state active); a commit that passes them goes to certified() (rule B). No PKI (the fleet ontology declares no pki: root, or the root file is absent at the fleet revision) -> accepted as before. With PKI it FAILS CLOSED: the leaf at the declared leaf path for the id must exist, its key equal the record's (= signing) key, VerifyInstanceChain against the declared root and CRL must pass, and its email id must equal the id. Refusals: no leaf, a rogue or other-id leaf, an unreadable/oversized root, CRL or leaf -> no-cert; a leaf for another key -> key-mismatch; a listed serial -> revoked.

CONSEQUENCE: when the root lands on main every active member needs its leaf on main (land them in ONE commit or add the root first and members after: the bootstrap is admitted, TestArtifactRules_Bootstrap); a root alone makes every member's next commit no-cert.

Expiry is NOT judged: the chain is verified at max(leaf.NotBefore, root.NotBefore), so an expired leaf still vouches until it is revoked or replaced. MISREADING: rule B is not an expiry check; revocation (the CRL at the fleet revision) is the only thing that ends a leaf's standing.

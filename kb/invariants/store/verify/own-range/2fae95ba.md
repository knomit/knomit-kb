# The master's OWN commits are judged before the fleet's main moves (judgeOwnRange, four store paths, fleet repository only): validations first in every mode, members' merged-in commits judged as at their entry, own commits against the fleet at main OR at this instance's agent tip, signer = self, and the master's side of host-record; a refusal leaves main where it is and the commit stays on the agent branch until it is dropped

RULE (PR #533, squash commit 6f241959 on dev, verified there; ruling: kb/decisions/store/verify/own-commits-judged/30a40f91.md). store.repoHandler.judgeOwnRange(upstream, base, tip, own, vouch) runs BEFORE main moves, over the commits of tip minus the history of base, in exactly four places: AdvanceLocalUpstream (the hub's local reconcile loop, create, Host here, a hub claim and stand-down, and local main following a forge publish), PublishUpstream (a forge-hosted master's publish), PublishUpstreamChange (a forge claim, stand-down or decommission; its signature gained `from`) and PublishTo (the seed of a forge the fleet moves onto). No other code writes the fleet's upstream ref.

IT RUNS ONLY WHEN THE JUDGED ONTOLOGY IS THE FLEET ONTOLOGY (read at base; at tip while base holds none, i.e. the first publish of a fleet created onto a forge). Every other repository returns nil at once: a knowledge base's main still follows its own agent branch unjudged (TestJudgeOwn_AKnowledgeBaseMainFollowsUnjudged). Why that is acceptable: every in-process writer validates at the source (kb/invariants/store/fact-write/validate-write), so the unvalidated writers that made a judge there necessary are gone, and judging there would stall a knowledge base's main behind one bad write.

THE RULES, in order, for the range:
1. RuleValidation on the range's NET change (branchFactsValid, kb/invariants/store/verify/validation-net-change), in EVERY verify_signatures mode, members-are-policy included.
2. judgeCommit. A commit NOT authored by `own` is a member's, merged in: judged against the fleet at base (at tip while base holds no root) with judge.entry set, so host-record applies, and with NO signer rule (it has no pusher here). A commit authored by `own` is admitted when judgeCommit admits it against the fleet at base OR against the fleet at `vouch` (this instance's agent-branch tip; zero = tip). The vouched fleet is needed in two flows that are otherwise refused: create (main holds no root or record yet) and a root holder claiming before any master merged its join (TestFleetMaster_AForgeDecommissionLetsAnotherHolderTakeOver). For an own commit the record-owner rule also admits the ontology file (judge.ownOntology: create and refreshFleetOntology write it).
3. For an own commit: signer = self (signerIsPusher against this instance's key, RuleNotPusher) and ownHostRecord, the master's side of host-record: a commit that changes neither artifacts/fleet/host nor artifacts/fleet/master is not its business; a marker change may leave the marker naming ITS AUTHOR or delete it, never name another agent; while main's marker names ANOTHER agent, a host-record or marker change is admitted only when the marker it leaves names the author (Host here writes the marker first, so its host-record commit sees itself named); when main names self or nobody the master's writes are admitted.
verify_signatures at the judged ontology decides 2 and 3 as everywhere (enforce refuses, log logs, off checks nothing); 1 is not mode-dependent.

REFUSAL. *OwnCommitRefusedError (errors.Is ErrOwnCommitRefused), text `knomit: main was not moved: commit <hash> refused by ...`. Main does not move. The repos layer records it as the fleet's last error through Manager.noteOwnJudge (callers: the hub loop's after-hook fleetMainAdvanced, publishFleetMainNow, publishMarkerChange, the move's seed, the forge round through fleetPushed) and clears it when main next moves. FleetStatus gains last_error_main_held and last_error_main_held_commit, parsed from that text; last_error_commit_refused is deliberately NOT set (its member advice, leave / revoke / rejoin, is wrong for the master).

CONSEQUENCES. (1) A refused own commit stays on the master's agent branch and every tick re-refuses it (WARN each tick plus last_error). There is no auto-rewind and no retry that helps; the way out is Drop (kb/architecture/fleet/drop-commit). Nothing written on the branch AFTER the refused commit reaches main either. (2) writeRecord has no guard of its own: it hard-codes pragmatic/policy and the fleet ontology is product-owned, so a guard there could never fire; its output is judged where it leaves the instance (this range, or receive-pack / fetch judge for a member). (3) Fixture rule for tests: an invalid commit on a fleet branch can no longer be made through the store (validateWrite refuses it at the source); use TestingCommitFiles, the raw-commit helper.

MISREADINGS. 'The judge only guards members': no, since #533 the master's own root, leaves, CRL, revocations, host record, marker, record and merges pass it. 'A refusal fixes itself': no, see consequence 1. 'verify ci judges the master's own commits with this': verify ci is a separate gate (kb/invariants/store/verify/ci-merge-result). 'Other repositories are judged here too': they are not.

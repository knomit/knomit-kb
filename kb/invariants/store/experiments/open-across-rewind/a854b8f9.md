# An experiment open across a rewind of its agent branch is rebuilt, at its next commit or sync, as ONE squashed single-parent commit on the new branch tip (three-way merge, base = merge-base(experiment tip, the agent tip recorded before the FIRST rewind)); conflicts are refused with the three real commits; rewinds that ran before #538 left no record and cannot be recovered

RULE (PR #538, merge 3f254262; internal/store/experiment_rewind.go). A rewind (reconcileAgentRebase, ModeRewound) rebuilds the agent branch on an upstream that may have scrubbed content. An experiment forked before it still holds the scrubbed commits, and a plain commit would merge them back: the three-way merge from the old ancestor re-adds the content AND makes the scrubbed commit reachable from the agent branch, so the next push sends it to the origin that removed it. So:
1. RECORD. Before the rewind moves the branch, markExperimentsRewound writes the agent's pre-rewind tip to refs/knomit/experiment-rewound/<name> for every experiment of that branch that has none (a bookkeeping ref outside refs/heads, never advertised by /git). The FIRST record is KEPT: a later tip would count the commits the first rewind removed as the experiment's own.
2. OPEN. OpenExperiment holds lockBranch(parent) from CreateBranch to the experiments INSERT (the rewind lists experiments as rows under the same lock; without it a fork at the pre-rewind tip could land with no row and no record). It first clears a stale record of the same name.
3. REBUILD. The next CommitExperiment or SyncExperiment of a recorded experiment, under lockBranch(parent) then lockBranch(experiment) (the rewind's order), rebuilds it first. 'Own' commits = reachable from the experiment tip and not from the recorded tip. Rebuild happens only when some boundary commit (an own commit's non-own parent, or the tip itself when it has no own commit) is missing from the new parent history; otherwise the record is dropped and the commit or sync proceeds as before.
4. HOW. ONE three-way merge: base = merge-base(experiment tip, recorded tip) (where the experiment last met the old branch: its fork or latest sync), src = experiment tip, dst = parent tip, written as a SINGLE-PARENT commit on the parent tip. What the rewind removed is equal at base and src, so it stays removed; what a sync merge settled is in src, so it stays settled. An experiment that adds nothing becomes the parent's tip (no empty commit). The old experiment commits are not parents, so the scrubbed commit stays unreachable.
5. CONFLICTS ARE REFUSED, never settled silently, because the experiment's own version is unrecoverable once its old commits are unreachable. A path the experiment changed that the agent branch also changed since (an edit of a scrubbed file included) refuses with the paths and the three REAL commits (base, experiment tip, parent tip; MergeConflictError.Rewound = true). Commit takes `resolutions` and the repo's `conflicts` setting exactly as a plain commit; a resolution naming a path that does not conflict is refused. Sync refuses outright (it passes StrategyRefuse, no resolutions) instead of letting the parent win. The experiment and the agent branch are untouched until the rebuild succeeds.
6. AFTER. experiments.fork_commit moves to the parent tip; a pipeline watermark at the old experiment tip moves to the rebuilt tip and any other watermark moves to the new fork point (the next review re-reads the whole rebuilt delta). dropExperiment (commit, rollback, expiry) clears the record.

THE COST, stated plainly: the experiment's per-commit history is squashed into one commit (its message says how many and that history is not kept). Chosen over a commit-by-commit replay (which lost a sync merge's settlement) by the coordinating session after review round 1; the PR body states it.

IN PRACTICE MOST open experiments are rebuilt, not only those that held scrubbed content: a rewind re-hashes the agent's own commits, so the boundary commit of any experiment forked after an own agent write is missing from the new history.

NOT COVERED. A rewind that ran BEFORE #538 left no record. An experiment open across one merges as it always did; the pre-rewind tip is gone, so nothing can tell its own work from what was scrubbed, and it cannot be recovered.

MISREADINGS.
- 'A rewind rebuilds experiments': no, it only records them; the commit or sync rebuilds.
- 'Sync after a rewind settles parent-wins': no, it refuses on a conflict.
- 'Only experiments that held scrubbed content are rebuilt': no, see above.
- 'The experiment's commits are kept': no, one squashed commit replaces them.
- The refusal text still says the experiment is 'replayed'; it is merged as one squashed commit.

Proven by internal/store/experiment_rewind_test.go and experiment_rewind_more_test.go (TestExperimentAcrossARewind_*: CommitKeepsTheScrub, SyncKeepsTheScrub, FastForwardSyncBeforeTheRewind, EditOfAScrubbedFileIsAConflict, TwoRewindsBeforeTheCommit, RollbackClearsTheRecord, NoScrubbedOverlapCommitsNormally, SyncSettledPathStaysSettled, OursCannotRevertASyncSettledPath, SecretThroughASyncMerge, RebuildIsOneSquashedCommit, NoEmptyCommit, OpenRacingTheRewind, OpenClearsAStaleRecord, PipelineWatermarksFollow).

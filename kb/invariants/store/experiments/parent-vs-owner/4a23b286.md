# Commit and sync refuse an experiment whose recorded parent is not AgentBranchOwner() — but an EMPTY owner is UNKNOWN, not a mismatch, or every commit on a pre-key or never-booted database is refused

Before either merge, the store compares the experiment's recorded `parent_branch` against the agent branch this DATABASE records as its owner (meta `agent_branch_owner`), and refuses with ErrStaleExperimentParent — naming both branches and changing nothing — when the repo was taken over between the fork and now.

This is the STORE's half of a two-layer refusal, the same shape as the subscription one: RepoInstance.WritableBranch answers a client from the live instance, and this answers from the record, so an IN-PROCESS caller that never passed a binding gate cannot merge an orphaned experiment into a branch this database has stopped writing. The store has no instance to ask, which is why it asks the record (invariants/store/branch-roles).

THE PART THAT DECIDES THE IMPLEMENTATION: an empty owner means UNKNOWN. AgentBranchOwner's own contract says so — "a database created before this key existed or one that has never completed a boot; callers must treat it as unknown, not as no previous branch" — and verify.go applies the same `owner != ""` guard to the same value. Treating empty as a mismatch would refuse every commit on such a database. So the check bites only on a KNOWN, DIFFERENT owner.

ROLLBACK IS DELIBERATELY UNGATED. Discarding orphaned work is always safe, and after a takeover it is the only way out of the state — gating it would strand the experiment with no exit.

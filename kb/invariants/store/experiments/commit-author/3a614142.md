# A commit on an experiment branch is authored AND committed by the experiment's owning agent (its recorded parent), never `exp/<name>` — and when that agent cannot be named (no experiments row, a parent that is not an agent branch, or a parent that is not the database's KNOWN owner) the write or merge is REFUSED before any object is stored, any commit is built or any ref moves, in the single-file AND batch write paths (#394, #554)

commitAgentID (internal/store/internal/vcs/branch_commit.go since hier-07; formerly internal/store/branch_commit.go) resolves the identity for every authored commit through CommitSigs (formerly commitSigs; the parent's writers reach it as rh.CommitSigs through the embedded *vcs.Repo). For a branch in the exp/ namespace it reads the experiments row and resolves the agent for the recorded parent branch through OwnAgentID (this instance's persisted agent id; never parsed from a branch name). The commits it covers: learn/update (writeFileExact), retract (deleteFile), batch writes — learn's atomic move, review answers and review-start dedup, hypothesize (batchWriteLocked) — and SyncExperiment's merge commit on the experiment (mergeIntoBranch with dst = exp/<name>). CommitExperiment's merge commit was already authored by the agent (dst is the parent); its FAST-FORWARD carries the experiment's own commits unchanged, which is why the experiment's commits themselves must carry the agent's name.

Refusals (never a fallback to the experiment's name): no experiments row (an orphan ref; ErrOrphanExperimentRef); a recorded parent that is empty or itself exp/*; a recorded parent that differs from a NON-EMPTY AgentBranchOwner (taken over since the fork; ErrStaleExperimentParent, the same check CommitExperiment/SyncExperiment run). An EMPTY owner is unknown, not a mismatch: the recorded parent names the agent (kb/invariants/store/experiments/parent-vs-owner).

Consequences: (1) the F09 acceptance gate (CheckRange → AgentIDOfAuthor) now finds the owning agent's member record for an experiment-written range instead of refusing RuleNoRecord 'no member record for agent exp/...'; (2) per-author measures (`git log --format=%an`) show agent ids, not experiment names; (3) a test fixture that wants content on an orphan exp ref must write it while a row exists and then delete the row (writeOnOrphanRef in experiment_test.go) — a direct write onto an orphan ref is now refused. What this does NOT mean: history written BEFORE the fix still carries `exp/<name>` authors and is not rewritten; changeReader decides a commit is local by its SIGNER, not its author, so such commits stay local. The pre-#394 deriveAgentID(branch) helper no longer exists; identity comes from OwnAgentID, and AgentIDOfAuthor (author email to agent id) is what the acceptance gate reads.

Tests: TestExperimentCommits_AuthoredByOwningAgent, TestExperimentCommits_EmptyOwnerUsesRecordedParent, TestExperimentCommits_NoOwnerNoWrite, TestCheckRange_ExperimentRangeNamesTheOwningAgent (internal/engine/store/experiment_author_test.go). Sabotage verified: resolving from the branch written turns all four red (the gate refuses `exp/gated`).

WHEN THE REFUSAL HAPPENS (corrected 2026-10-20 against ad7059d2; an earlier version said 'before any object is built'). The write or merge is REFUSED before any COMMIT is built and before any ref moves. Single-file writes (writeFileExact, deleteFile in internal/engine/store/facts/fact_write.go) resolve CommitSigs (at the top of each, in internal/engine/store/facts/fact_write.go) before any blob, tree or commit object is written. The batch write (batchWriteLocked) now does the same (fixed for issue 554): CommitSigner and CommitSigs are both resolved at the top, before the first SetEncodedObject / BuildTree / DeleteFromTree. Before the fix it called CommitSigs only after its blobs and trees were stored, so a refused batch left unreachable blob and tree rows in the SQLite objects table, never reclaimed (INSERT OR IGNORE, no GC) and reported by Verify as an orphan-objects warning; databases written by a pre-fix build can still carry such rows (space only, not corruption).

CONSEQUENCE: a refusal never advances a ref, adds a commit_log row, touches the index or adds a row to objects, for WriteFact, DeleteFact and every BatchWriteFacts shape (learn's atomic move, review answers, hypothesize). A new write path must resolve CommitSigs before its first object write.

WHAT THIS DOES NOT MEAN: it covers refusals by CommitSigs/CommitSigner only; a batch refused for another reason later (e.g. a store I/O error mid-batch, or a delete on a branch with no tree after earlier blobs were stored) can still leave unreachable rows, as can PublishUpstreamChange's refused push. Rows written before the #554 fix are not cleaned up. The commit-timestamp (When) is now stamped before the tree work in a batch, which is harmless: nothing compares it to the work in between. Enforced by TestExperimentWriteRefused_LeavesNoObjects (internal/engine/store/experiment_refusal_objects_test.go: orphan ref and stale parent; WriteFact, DeleteFact and three BatchWriteFacts shapes; the batch cases fail with the object count growing (7 to 14 for two writes, 14 to 16 for a write plus a delete) if CommitSigs is moved back below the tree work; the delete-only batch is a control that passes either way). ErrNoSigner is raised by CommitSigner before any object in every path (see kb/invariants/store/signing/fail-closed/cef1dd4d.md).

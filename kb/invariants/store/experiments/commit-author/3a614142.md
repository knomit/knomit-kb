# A commit on an experiment branch is authored AND committed by the experiment's owning agent (its recorded parent), never `exp/<name>` — and when that agent cannot be named (no experiments row, a parent that is not an agent branch, or a parent that is not the database's KNOWN owner) the write or merge is REFUSED before any commit is built or any ref moves (#394; a refused batch can still leave unreachable blob and tree rows, #554)

commitAgentID (internal/store/internal/vcs/branch_commit.go since hier-07; formerly internal/store/branch_commit.go) resolves the identity for every authored commit through CommitSigs (formerly commitSigs; the parent's writers reach it as rh.CommitSigs through the embedded *vcs.Repo). For a branch in the exp/ namespace it reads the experiments row and uses deriveAgentID(parent_branch). The commits it covers: learn/update (writeFileExact), retract (deleteFile), batch writes — learn's atomic move, review answers and review-start dedup, hypothesize (batchWriteLocked) — and SyncExperiment's merge commit on the experiment (mergeIntoBranch with dst = exp/<name>). CommitExperiment's merge commit was already authored by the agent (dst is the parent); its FAST-FORWARD carries the experiment's own commits unchanged, which is why the experiment's commits themselves must carry the agent's name.

Refusals (never a fallback to the experiment's name): no experiments row (an orphan ref; ErrOrphanExperimentRef); a recorded parent that is empty or itself exp/*; a recorded parent that differs from a NON-EMPTY AgentBranchOwner (taken over since the fork; ErrStaleExperimentParent, the same check CommitExperiment/SyncExperiment run). An EMPTY owner is unknown, not a mismatch: the recorded parent names the agent (kb/invariants/store/experiments/parent-vs-owner).

Consequences: (1) the F09 acceptance gate (CheckRange → agentIDOfAuthor) now finds the owning agent's member record for an experiment-written range instead of refusing RuleNoRecord 'no member record for agent exp/...'; (2) per-author measures (`git log --format=%an`) show agent ids, not experiment names; (3) a test fixture that wants content on an orphan exp ref must write it while a row exists and then delete the row (writeOnOrphanRef in experiment_test.go) — a direct write onto an orphan ref is now refused. What this does NOT mean: history written BEFORE the fix still carries `exp/<name>` authors and is not rewritten; changeReader decides a commit is local by its SIGNER, not its author, so such commits stay local. deriveAgentID/AgentIDOf did not change meaning (the fleet identity code reads them).

Tests: TestExperimentCommits_AuthoredByOwningAgent, TestExperimentCommits_EmptyOwnerUsesRecordedParent, TestExperimentCommits_NoOwnerNoWrite, TestCheckRange_ExperimentRangeNamesTheOwningAgent (internal/store/experiment_author_test.go). Sabotage verified: resolving from the branch written turns all four red (the gate refuses `exp/gated`).

WHEN THE REFUSAL HAPPENS (corrected 2026-10-20 against ad7059d2; an earlier version said 'before any object is built'). The write or merge is REFUSED before any COMMIT is built and before any ref moves. Single-file writes (writeFileExact, deleteFile in internal/store/fact_write.go) resolve CommitSigs (L171 and L244) before any blob, tree or commit object is written. The batch write (batchWriteLocked) resolves CommitSigner first (L368) but calls CommitSigs only at L480, after its blobs (L433-L448) and trees (L451) are already stored and before the commit object (L494) and the ref move (L503); so a refused batch leaves unreachable blob and tree rows in the SQLite objects table (issue 554, https://github.com/knomit/knomit/issues/554), never reclaimed (INSERT OR IGNORE, no GC); Verify reports them as an orphan-objects warning that costs space only.

CONSEQUENCE: a refusal never advances a ref, adds a commit_log row or touches the index. The object store is NOT guaranteed unchanged for batch writes (learn's atomic move, review answers, hypothesize).

WHAT THIS DOES NOT MEAN: it does not mean 'no object exists after a refused write' (false for batches until 554 is fixed), and leftover unreachable rows are not corruption. When issue 554 is fixed (CommitSigs resolved before the first blob in batchWriteLocked), restore the stronger claim 'refused before any object is built' in the title and this section. The same ordering does NOT apply to the signer: ErrNoSigner is raised by CommitSigner before any object in every path (see kb/invariants/store/signing/fail-closed/cef1dd4d.md).

# A branch holds a role (consensus upstream, this instance's write target) only because an explicit record says so — every role inferred from a git-level signal another actor controls has cost data, because reconcile acts destructively on the assignment

A branch fills a role only because an explicit record assigns it, and every path that instead infers the role from a git-level convention another actor controls — a hardcoded name, the remote's symbolic HEAD, the local HEAD, the shape or count of branch names — can hand the role to the wrong branch, and because reconciliation then acts destructively on that assignment the error costs data rather than raising an error.

Two roles exist, each with its own record:
- The CONSENSUS upstream is `Remote.Branch` in the DB, read fresh on every sync tick. Hardcoding 'main' broke every 'master' repo silently; adopting the remote's symbolic HEAD adopted another machine's agent branch whenever the remote's default branch was an agent branch. Resolution order at clone is therefore: caller-provided → 'main' if the remote has it → detected remote HEAD → 'main' with a warning; this only changes behaviour when a non-main HEAD coexists with a main branch.
- THIS instance's write target is the `agent_branch_owner` meta row. Local HEAD is not lineage: other agents' branches land in refs/heads through fetch, so seeding a renamed agent branch from HEAD can fork the instance onto another agent's lineage silently. When no usable record exists the code falls back to the agent branch itself so `CreateBranch` fails loudly rather than seeding from a guess.

The destructive consequence is what makes the record mandatory rather than tidy: with upstream == agent branch, `reconcileMain` sees local ahead of origin after every write and force-resets the local agent branch to origin, destroying just-written unpushed facts (a fact appears in the UI, then vanishes a cycle later). The guard for that state makes the branch push-only; recovery is repointing the upstream through `SetUpstreamBranch`.

WHAT THIS DOES NOT MEAN: many local `agent/*` branches with different tips and fact counts are the distributed design converging through origin, not drift or data loss — a review finding that rests on 'these branches should be the same' is a misread of intent and must be confirmed with the user before it is reported. It also does not add local reconciliation of sibling agent branches, ancestry checks, or branch GC; divergence between per-identity branches is handled by origin/sync, and the only supported takeover is 'derived name no longer matches → new branch seeded from the recorded owner'.

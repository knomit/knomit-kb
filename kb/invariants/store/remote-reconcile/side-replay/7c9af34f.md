# The rewind replay's side collection depends on two load-bearing parts: the own-key filter (key = the INSTANCE key, deps.Signer) and the held set; 'every merge's content is replayed now' is false

RULE (PR #535, verified at merge 48e7d8d5). At each merge on the rewind replay's first-parent walk, sideOf looks at the non-merge commits behind the merge's NON-FIRST parents that are held by none of: the upstream's history, the stop point's history (the watermark), the first-parent chain, an earlier merge's side. It sorts them into own (signed by an own key), foreign (any other key, or unsigned) and marker-only own (changes only replay-skip paths). Then:
- no own commits (a reconcile merge; a hub's consensus merge of members' work): the merge is skipped, as before;
- CLEAN side (own commits only, no foreign, no marker-only, and no held commit off the first parent's history): the merge is replayed as ONE commit, its change against its first parent, so a CommitExperiment resolution (a dst choice, a written body, a conflicts-setting field merge) comes back as decided;
- MIXED side (own next to foreign, marker-only, or held-off-line): only the own non-merge commits are replayed, one by one, parents first, ahead of the commits above the merge, and a Warn names the merge and says its own resolution is not replayed.

THE KEY IS THE INSTANCE KEY. 'Own' is checkOwnLineage's (E4) set: the key this store signs with, which is the INSTANCE key (deps.Signer, rh.signer), shared by every repository and branch on the instance, plus every key the instance's fleet member record has held. It is NOT 'this agent branch's' key. Nothing but experiments merges another same-instance branch into an agent branch, so no loss is known from this, but do not reason from 'own = this branch'.

LOAD-BEARING PARTS. (1) The own-key filter: without it a hub master replays members' commits re-signed as itself, the #528 N1 class, refused for good by the new host. Sabotage (filter off) is red in ForeignMergedCommitsStayOffTheReplay, AMixedMergeReplaysOnlyItsOwnCommits and the scrubbed-behind-a-mixed-merge subtest. (2) The held set, including the stop point's history: without it an own commit BELOW the watermark (a G6 scrub) is resurrected on the one-by-one path. Pinned by the 'behind a mixed merge, replayed one by one' subtest of ScrubbedOwnCommitBehindAnExperimentStaysScrubbed. The experiment-shaped arm cannot catch it, because there the secret commit is an ancestor of the merge's first parent and the merge's change never carries it.

KNOWN LIMITS (reasoned or probed in review, not all pinned by a test). (a) An own commit that EDITS a foreign file carries that file's whole content: when a mixed side holds a foreign commit F creating member.md and an own commit O editing it, the one-by-one replay applies O against a base lacking F, so member.md lands in full, foreign lines included, re-signed as this instance. 'Commits signed by anyone else are never replayed' is true of the commits, not of the content of an own commit that edits their files. Same class as an own first-parent commit editing a file a reconcile merge brought in; found by the re-review (probe Q4), no test, no Warn naming the path. (b) A commit the upstream holds under a DIFFERENT hash (squash-merged) is replayed again, local side winning, and can revert a later upstream edit to that path; the existing first-parent behaviour, not new. (c) Content made inside the merge commit itself (a resolution) is replayed only for a CLEAN side; for a mixed side it is not, and the Warn says so.

MISREADINGS. (1) 'Every merge's content is replayed now': no, only a clean side's merge is replayed as the merge, and a mixed side replays only own non-merge commits. (2) 'Foreign commits are never replayed, so foreign content never reaches the new branch': false for limit (a). (3) 'A mixed side loses the instance's own work': no, own commits are replayed; only the merge's own resolution is dropped, with a Warn.

WHAT THIS DOES NOT CHANGE: the empty-walk no-op is unchanged. A branch whose only divergence is a clean own experiment merge no longer has an empty walk, so in an ordinary repository it is now rebuilt on the upstream with the merge replayed as one commit (ModeRebase) instead of kept as it stands (ModeNoop).

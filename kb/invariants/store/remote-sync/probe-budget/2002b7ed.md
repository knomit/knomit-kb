# Both remote probes (the attach guard's ProbeBranchHistory overlay and the create probe's budgetedStorage) bound the RAW fetched pack as it arrives via storer.PackfileWriter (remotesync.NewBudgetedPackWriter), then parse it with a seekable scanner; SetEncodedObject still bounds the inflated objects

RULE (PR #682, merge b038ab37 on dev, re-read there; closes review N2 of PR #676). [git].max_probe_bytes is applied TWICE by both in-memory probe stores: (a) to the raw pack bytes as go-git streams them into the store's PackfileWriter (packfile.UpdateObjectStorage takes that path whenever the storer implements storer.PackfileWriter; go-git v5.18.0 remote.go fetchPack); past the budget Write returns the store's too-large error (remotesync.ErrHistoryProbeTooLarge, repos errProbeTooLarge), io.Copy stops and the fetch fails, and NOTHING is parsed or inflated; (b) to the inflated objects the parse stores, counted in SetEncodedObject as before. Close parses the buffered pack with packfile.NewScanner over a bytes.Reader (seekable), targeting the outer store, so a thin pack's bases still read through to the local store for the attach probe.

WHY: without a PackfileWriter, go-git parses the non-seekable stream itself and its parser keeps every delta's raw bytes in p.deltas (buf.Grow from the header's declared length) until the whole pack is read; inflated bytes are counted only in resolveDeltas. So an all-delta pack was read whole before the inflated budget fired (measured by the test: 1,057,409 of 1,057,409 bytes read at a 262,144-byte budget with the writer removed).

WHAT IS BOUNDED, AND WHAT IS NOT: the raw pack is bounded by the budget, and the objects admitted are bounded by the budget. This is NOT a hard memory cap and NOT 'about twice the budget': go-git inflates ONE object fully (scanner copyObject, an unbounded io.CopyBuffer into a MemoryObject) before SetEncodedObject counts it, so a highly compressible object is held transiently beyond the budget before it is refused (PR #682 review N1, measured: a 4 MiB blob of zeros packs to 8,254 raw bytes and, at a 1 MiB budget, 4,194,304 bytes were held before ErrHistoryProbeTooLarge). Nothing is admitted unchecked. Also NOT bounded: the parser's per-object bookkeeping sized from the pack header's object count (make([]*objectInfo, count)) and a delta's declared target size in patch application; both are go-git internals, read from the remote's bytes (open question, not addressed).

CONSEQUENCE: a new in-memory probe store must implement PackfileWriter through NewBudgetedPackWriter (target = the store itself) or its budget does not bound the transfer. Do not drop the SetEncodedObject count: a highly compressible pack inflates past a raw budget.

MISREADING: 'the budget is the pack size': it is both the raw size and the inflated size, each checked separately. MISREADING: 'max_probe_bytes caps the probe's memory': it caps what is read and what is admitted; one object in flight can exceed it.

Both assert where the read stopped (at most budget + one 32 KiB io.Copy chunk of a 4x-budget pack) and that nothing was inflated; the within-budget counterparts prove the fixture parses.

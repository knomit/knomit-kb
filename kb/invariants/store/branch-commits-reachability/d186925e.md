# Any first-parent ancestor of an on-branch commit is itself on-branch

branch_commits is populated by full-reachability walk from the branch tip (populateCommitLog uses gogit.LogOrderDefault, which follows ALL parents). Therefore the set of indexed commits in commit_log for a branch is closed under first-parent ancestry. The first_parent_chain vtab walks parents unconditionally; the SQL JOIN against commit_log implicitly restricts the result set to indexed (on-branch) commits, so off-branch commits cannot appear. This is the schema invariant that LETS the vtab approach work without an in-walk branch_commits membership check. If branch_commits is ever populated by something OTHER than a full-reachability walk from the tip, this invariant breaks and resolveActiveCommitForPath silently returns wrong commits.

# Any first-parent ancestor of an on-branch commit is itself on-branch

branch_commits is populated by full-reachability walk from the branch tip (populateCommitLog uses gogit.LogOrderDefault, which follows ALL parents). Therefore the set of indexed commits in commit_log for a branch is closed under first-parent ancestry.

resolveActiveCommitForPath walks the parent DAG via a recursive CTE over commit_parents (parent_order = 0); the SQL JOIN against commit_log implicitly restricts the result set to indexed (on-branch) commits, so off-branch commits cannot appear. This is the schema invariant that LETS the resolver run without an in-walk branch_commits membership check on every step. If branch_commits is ever populated by something OTHER than a full-reachability walk from the tip, this invariant breaks and resolveActiveCommitForPath silently returns wrong commits.

Historical note: this rule was originally written for the first_parent_chain virtual table (retired in PR #67). The CTE replacement has the same dependency on this invariant — see [[cte-over-commit-parents]] for the new walk pattern.

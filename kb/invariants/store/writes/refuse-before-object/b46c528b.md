# Every store write path that stores blobs, trees or a merge tree must resolve CommitSigs (author and committer, which can REFUSE an experiment write) before its first SetEncodedObject/BuildTree/DeleteFromTree, because objects are never deleted

Rule: in a store write path, resolve CommitSigner() AND CommitSigs(ctx, branch, operation) before the first object is stored (SetEncodedObject, vcs.BuildTree, vcs.DeleteFromTree, or a merge's tree walk). CommitSigs -> commitAgentID refuses a write on an experiment branch whose owning agent cannot be named (ErrOrphanExperimentRef: no experiments row; a recorded parent that is empty or itself exp/*; ErrStaleExperimentParent: recorded parent is not the database's non-empty AgentBranchOwner), and on any branch it fails with ErrNoAgentID when the store has no agent id. The objects table is append-only (INSERT OR IGNORE, no GC), so every blob or tree stored before such a refusal stays as an unreachable row that Verify reports as orphan_objects. Operational consequence: when adding or reordering a write path, put CommitSigs next to CommitSigner at the top, and add the path to TestExperimentWriteRefused_LeavesNoObjects.

Holds today (#554 fixed): writeFileExact, deleteFile, batchWriteLocked (was the one violator: it called CommitSigs after storing its blobs and trees), mergeIntoBranch (dst = exp/<name> for sync) and the experiment rewind (experiment_rewind.go, 'rebuild').

What this does NOT mean: (1) It is not a promise that a refused write of ANY kind stores nothing. Other refusals after the first object write (store I/O error, a delete on a branch with no tree) can still leave rows; this covers CommitSigs/CommitSigner refusals only. (2) PublishUpstreamChange (internal/engine/store/remotesync/remote_sync.go) still calls CommitSigs after storing its blob and tree, and that is safe by analysis rather than by rule: it signs for the upstream branch, which is never an experiment, so the orphan/stale-parent refusals cannot occur there; only ErrNoAgentID could, and a store that publishes has its agent id set. It also already leaves an unreachable commit when the push is refused, by its own documented design. Do not copy its ordering into a path that can target an exp/* branch. (3) Moving CommitSigs earlier stamps the commit's When before the tree work; nothing orders or compares that timestamp against the work in between, so it is harmless. (4) Rows written by pre-fix builds are not cleaned up.

# All domain/entity comparisons MUST use the canonical tokenized fuzzy-matcher (canonicalizeDomain/domainTokens/stemDomainToken), never raw string equality

Any code that decides whether a fact's domain or entity tags match a caller-supplied domain/entity MUST route through the shared canonical/tokenized matching machinery in internal/store/domain_match.go — NEVER raw string comparison (==, slices.Contains, map lookup on the authored tag).

The machinery and what it normalizes:
- canonicalizeDomain: NFC -> Unicode case-fold -> de-hyphenize (so 'Remote-Sync' == 'remote sync'). Case-insensitivity is non-negotiable; the fact_domains/fact_entities junction tables are COLLATE NOCASE for the same reason.
- domainTokens: splits on whitespace AND '/', so hierarchical tags are token-searchable ('store/sqlite' matches 'sqlite').
- stemDomainToken: singularizes via go-pluralize ('migrations' == 'migration', 'indices' == 'index'), with len<=3 and -ics guards.
- fact_domain_tokens provides containment matching in SQL; SearchOptions.Domain (default, token-containment) vs DomainExact (opt-in exact) is the canonical query surface.

WHY load-bearing: raw matching makes the SAME domain/entity argument select DIFFERENT fact sets depending on which code path handles it, and silently returns empty/partial pools on any case/hyphen/plural/hierarchy mismatch. A user passing domain=['Store'] or ['migrations'] or ['store/sqlite'] expects the same facts knomit_query would return; a raw comparator misses all three.

KNOWN VIOLATION (fix required): synthesize.ScopeFilter.Matches (internal/synthesize/effort.go) uses slices.Contains for both domains and entities — raw, case-sensitive, no canonicalize/stem/de-hyphenize/'/'-split. This is the scope filter for knomit_review/knomit_hypothesize (domain/entities args). It must be rerouted through the tokenized matcher so scoped review/hypothesize pools match the same semantics as knomit_query. The canonicalize/token/stem functions are pure-Go and reusable in-memory — there is no in-memory-vs-SQL excuse.

# refs → [:DERIVED_FROM] graph edges are enforced INSIDE graphSyncFact — callers cannot skip

Every fact in the index MUST have [:DERIVED_FROM] edges that exactly reflect its rec.Refs field (filtered to local non-http/https). The invariant is enforced INSIDE graphSyncFactTx, NOT at call sites. Every Upsert path flows through graphSyncFactTx which (a) cleans up stale DERIVED_FROM edges and (b) re-adds edges from rec.Refs. GraphAddDerivedFrom was REMOVED from the synthesize/SearchIndex interface so it's STRUCTURALLY IMPOSSIBLE for callers to bypass the invariant. The explicit GraphAddDerivedFrom calls in synthesize/decision.go are deleted. TestDerivedFromInvariant in internal/store/ pins it: upsert facts with refs, query graph, assert every local ref has a corresponding edge with NO extras — must pass after upsert, after re-sync, AND after rebuild. graphDeleteFactTx already deletes outgoing edges on retraction. Incoming edges pointing to a retracted fact remain until the referrer is next synced — harmless because /explain query filters NOT f.deleted = true. Anti-pattern: do NOT add a public 'add edge' API to bypass Upsert.

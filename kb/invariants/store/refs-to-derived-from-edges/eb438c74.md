# refs → [:DERIVED_FROM] edges are driven from rec.Refs through Upsert, written POST-COMMIT as immutable time-aware historical edges (callers cannot bypass)

Every fact's LOCAL refs (rec.Refs filtered to non-http/https) become [:DERIVED_FROM] graph edges. The write is driven from the Upsert path and callers cannot inject edges another way: there is NO public 'add edge' API — the sole writer is the UNEXPORTED graphAddDerivedFromAtCommitTx (internal/store/index/derived_from.go since #557), reached only via si.writePostCommitDerivedFrom. GraphAddDerivedFrom was removed from the synthesize/SearchIndex interface, so bypass is structurally impossible.

MECHANISM (this is the CORRECTED version — the 2026-03-26 explain-view design that seeded this fact has since been replaced; the old 'clean-and-rebuild inside graphSyncFactTx' model is GONE):
- Edges are written POST-COMMIT, NOT inside graphSyncFactTx. graphSyncFactTx handles only current-state edges (TAGGED / IN_DOMAIN / UNDER / SIMILAR_TO) and does NOT touch DERIVED_FROM. (Before PR fix/graph-blob-edges it DID delete the version's outgoing DERIVED_FROM in its step 2, contrary to this sentence; that delete is gone.) Post-commit is required because graphAddDerivedFromAtCommitTx needs target node IDs only visible after the source Fact's MERGE has committed.
- CALL SITES (locate these by grepping `writePostCommitDerivedFrom`, NOT by line number — see the citation-rot note below): TWO in upsert (internal/engine/store/index/search_crud.go) — one on the COW-hit path, one at the tail of the COW-miss path — plus ONE in the Sync path's Pass 2 (internal/engine/store/index/search_index.go), which re-runs the ref writes for every fact indexed in that batch so intra-batch targets that did not yet exist on the first attempt get their edges.
- Edges are TIME-AWARE and IMMUTABLE, and (since PR fix/graph-blob-edges, GraphSchemaVersion 8) written ONCE PER SOURCE BLOB, at the commit that introduced it (claimBlobRefs; node prop refs_commit). A COW hit, merge carry, branch copy, experiment commit, rename or restore of the same blob writes none. A fact's edge set is the union over its BLOBS (each version once), not over commits. Edges join two blobs present in the object table, or are not written (kb/invariants/store/graph/reference-edges-real-blobs). graphAddDerivedFromAtCommitTx has a dedup guard that makes repeated writes idempotent, but distinct ref-events at distinct commits produce distinct edges. It uses graphInsertEdgeReturningID (plain INSERT INTO), NOT graphInsertEdge (INSERT OR IGNORE) — see kb/decisions/store/derived-from-time-aware-edges/a5222e48.md.
- Edges are NEVER deleted on retraction. graphDeleteFactTx (internal/engine/store/index/search_graph.go) deletes only TAGGED / IN_DOMAIN / UNDER and incoming SIMILAR_TO; DERIVED_FROM (incoming AND outgoing) is preserved as immutable historical lineage. /explain hides retracted endpoints at query time via NOT f.deleted = true.

WHAT THIS DOES NOT MEAN (documented misreadings):
- NOT 'a fact's DERIVED_FROM out-edges are a clean mirror of its CURRENT refs.' FALSE — the out-edge set is the UNION of every (path, commit) ref-event in the fact's history; a fact whose refs changed over commits still has edges for the OLD refs. To read current refs, read the fact record, never the graph. There is no 'no extras' guarantee (the deleted TestDerivedFromInvariant that once asserted it no longer exists).
- NOT 'retracting or updating a fact cleans up its DERIVED_FROM edges.' FALSE — they are immutable; both directions survive retraction ON PURPOSE (removing them would erase the temporal lineage rail). No cleanup runs; the query layer hides deleted nodes instead.
- CITATION ROT — do not trust line numbers in facts about this code. This fact previously pinned the call sites at search_crud.go:123/:258, search_index.go:304/:1165 and search_graph.go:305. At HEAD the search_crud sites are at 244/364, there is only ONE search_index site (and it is in Sync's Pass 2, NOT in rebuildGraph as this fact claimed), and graphDeleteFactTx starts at 298. Grep the symbol.

Anti-pattern: do NOT add a public 'add edge' API, and do NOT move DERIVED_FROM writes into graphSyncFactTx — the post-commit two-pass order is load-bearing. Current pinning tests: derived_from_test.go, edge_props_test.go, search_graph_query_test.go (two-commit time-aware edge semantics).

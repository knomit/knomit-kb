# ONNX inference must NEVER run inside a store write transaction — _txlock=immediate makes an open tx a process-wide write lock

The main store DB is opened with `_txlock=immediate` (internal/store/service.go), so EVERY `BeginTx` issues `BEGIN IMMEDIATE` and takes SQLite's process-wide write lock for the transaction's whole lifetime. Embedding takes SECONDS. Running inference inside a write tx therefore blocks every writer on every branch, in every repo sharing that DB, for the duration of the inference.

CONSEQUENCE: resolve the vector BEFORE opening the transaction. `searchIndex.embedRecord` exists for this and its doc says so; `rebuildEmbeddings` has always followed the rule (it embeds outside its tx), and `upsert` was fixed to follow it too.

The non-obvious part is WHY this isn't just "move the embed call up": the embed was deliberately placed AFTER the in-tx COW check so that re-indexing content already in `facts` (same `path` + `blob_hash`) pays no inference at all. Hoisting it naively would trade a lock-contention bug for an inference-on-every-reindex bug. The resolution is `searchIndex.cowProbe` — a READ-ONLY probe run before the tx that mirrors the in-tx COW condition (`fact_entities` rows exist, OR the record has no entities AND some branch already points at the fact) and answers only "will an embedding be needed?".

WHAT THIS DOES NOT MEAN: cowProbe is NOT the COW decision. It runs outside the lock, so a concurrent writer can invalidate it; the authoritative check is still the in-tx one, and it is unchanged. Both wrong answers are safe by design — a false "already indexed" costs one in-tx embed on the miss path (the rare fallback), a false "not indexed" costs a wasted vector the COW-hit path discards. Do not "simplify" by deleting the in-tx fallback: without it a probe that raced a concurrent writer would commit a VECTORLESS fact, breaking the separate invariant that no fact is ever indexed without a vector when an embedder is configured.

Caller-donated vectors (`WithPrecomputedEmbeddings`, used by mcp/learn's dedup pass) stay on the in-tx path on purpose: applying one costs nothing, so there is no lock-hold to avoid, and validating a donation on a path that would have taken the COW hit and never read it would fail an otherwise-fine upsert.

Enforcing test: `TestUpsert_EmbedsOutsideWriteTransaction` — its embedder attempts `BEGIN IMMEDIATE` on an independent connection on each call, which can only succeed if upsert is not holding the write lock. It was verified to FAIL against the pre-fix ordering.

# Every branch-ref mutation MUST call vcs.Repo.NotifyCommit (rh.NotifyCommit from the parent) while holding the branch lock

Every mutation that advances a branch ref MUST call NotifyCommit(ctx, branch, hash) — vcs.Repo.NotifyCommit in internal/store/internal/vcs/branch_commit.go since hier-07, reached from the parent as rh.NotifyCommit through the embedded *vcs.Repo (formerly repoHandler.notifyCommit), and from the facts, merge and remotesync children as rh.vr.NotifyCommit since E2 (PR #573: those children hold the vcs handle in a named field vr and no longer embed it) — while still holding the per-branch write lock. NotifyCommit does four things in order: (1) AppendCommitLog(ctx, branch, hash) — branch-agnostic commit_log row + branch_commits visibility row; (2) im.Sync(ctx, branch) — brings branch_facts / facts_vec / graph in sync with the new tree (skipped when no index manager is set); (3) touchExperimentActivity(ctx, branch); (4) onCommit(branch, hash) external observer (e.g. SSE). The index manager and onCommit are injected by the parent as values (SetIndexManager, SetOnCommit); the child never calls up. Mutation paths that call it (verified at the #573 merge 2a5bcadf, where the spelling in the three children is rh.vr.NotifyCommit): facts.Index.writeFileExact / deleteFile / batchWrite in internal/engine/store/facts/fact_write.go (the facts child; fi.rh.vr there is the same shared vcs.Repo), merge.Repo.MergeIntoBranchLockedOpts in internal/engine/store/merge/branch_merge.go (the fast-forward and the 3-way merge; reconcileAgentMerge in remote_reconcile_merge.go reaches it through rh.MergeIntoBranchLocked and has no NotifyCommit call of its own), remotesync.Repo.replayOntoUpstream in internal/engine/store/remotesync/remote_reconcile_rebase.go. Skipping notifyCommit leaves SQL stale relative to git — trips Verify's facts-coherence check. The list above is not exhaustive: at 2a5bcadf NotifyCommit is also called from internal/engine/store/merge/experiment_rewind.go (the rebuilt experiment), internal/engine/store/gitserve/httphandler_receivepack.go (the receive-pack registration, as rp.rh.NotifyCommit: gitserve.host still embeds *vcs.Repo, unexported and built per Service.Handler call), and in internal/engine/store/remotesync/: peer_admit.go, remote_reconcile.go, remote_reconcile_rebase.go, local_reconcile.go and drop.go; and internal/engine/store/facts/system_files.go (facts.Index.WriteSystemTree, which calls batchWriteLocked (unexported since E2) under fi.rh.vr.LockBranch and then fi.rh.vr.NotifyCommit itself). NO production file of the parent package internal/engine/store calls NotifyCommit any more: the earlier claim that service_sync.go and service_facts.go call it was true before the facts, merge and remotesync children took those paths, and those two files now mention it only in comments. Consequence: audit a new ref mutation by grepping the CHILD packages (facts, merge, remotesync, gitserve, vcs), not the parent's service_*.go files; a grep of the parent finding nothing does not mean a path skips NotifyCommit. Anti-pattern: advancing a ref via storer.SetReference without immediately calling NotifyCommit.

RE-VERIFIED at the PR #577 merge b4d232ee (E5; a grep of every non-test, non-comment `NotifyCommit(` call under internal/).

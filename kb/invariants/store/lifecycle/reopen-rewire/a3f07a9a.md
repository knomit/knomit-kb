# Open.Enter is the ONE wiring function for a repo's first open and every reopen (a SwapStore rewinds to Open) — there is no second list to mirror; any new per-store process-level config is added there and only there

Rewritten for issue #411; rewireStore, reinjectOrigin, reattach, repoBuilder and swapstore.go are gone.

`store.Open` restores NONE of the per-store process-level wiring (it is derived from Manager deps and control.db, not persisted in the repo DB). Under the lifecycle machine every open goes through openStage.Enter (internal/repos/stages.go): the first Mount, a reboot, and every SwapStore (whose target is the Open stage, so it exits Open and re-enters it after the apply copied the new DB in). Enter reads the origin from control.db's Origins row, then applies, in one place: store.Open, SetNetworkTimeout, SetOntologyRoot, SetReadOnly, SetOrigin, SetEmbedder, SetSigner, SetAcceptList, SetOwnKeys, OpenRepo, rehydration of the upstream, ConfigureRemote, the read branch, the commit observer and SetOnCommit, then attaches the store to the instance. Exit cancels hub tasks, stops the observer, detaches the store and drains its refcount, then closes it.

CONSEQUENCE. There is no second list (the old rewireStore checklist that had to mirror repoBuilder) and no recovery path that reopens differently: a failed swap reopens through the same Enter. Add any new per-store wiring to openStage.Enter and nowhere else.

The historical failure this fact guarded: rewireStore omitted the ORIGIN on the recovery path, so a failed swap came back with origin == nil and the reconcile loop exited silently. That class is structural now: one function, one order.

WHAT THIS DOES NOT MEAN: not 'a reopened Service needs its Crypt restored' — since migration 000017 the store holds no credentials; control.db's Origins owns token and Crypt. Not 're-injecting the origin re-reads the repo DB' — the repo's remotes row carries sync/push status only.

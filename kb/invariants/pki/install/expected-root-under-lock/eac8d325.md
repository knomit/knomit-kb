# pki.InstallBundle(dir, keyPath, raw) installs ONLY where no fleet trust material is installed, decided under the cross-process <pki>.lock: any installed root refuses (another root RootDiffersError naming both, the bundle's own root ErrAlreadyInstalled), an unreadable root.crt fails closed; there is no option to replace a root (ExpectInstalledRoot was removed in fleet PR8)

RULE (fleet PR8, branch feat/fleet-tick-duties; it REPLACES the knomit#299 contract `InstallOptions{ExpectInstalledRoot}`, which is gone with its parameter). `pki.InstallBundle(dir, keyPath, raw)`:
1. before any lock: the bundle-and-key checks (shape `ErrMalformedBundle`, key `ErrKeyMismatch`, chain under the bundle's own root and CRL);
2. under a cross-process exclusive lock on `<pki>.lock` (flock / LockFileEx, `lockInstall`), it reads `InstalledRoot(dir)`:
   - root.crt present but unreadable or not Ed25519: refused ALWAYS, the error names the file (removing it is the way out);
   - another root installed: `*RootDiffersError{Installed, Bundle}` (errors.Is ErrRootDiffers);
   - the bundle's OWN root installed: `ErrAlreadyInstalled`, not RootDiffers;
   - nothing installed: the per-root CRL watermark check (`ErrCRLRollback`), then the writes and the watermark record, still under the lock.
Every refusal writes nothing. The lock is held from the read through the writes, so "nothing installed" is what the writes land on.

WHY THE OPTION WENT. Every production caller (internal/repos/fleet_create.go and fleet_membership.go, the join; pinned by test/archtest installCallers) passed `InstallOptions{}` after its own trust_installed pre-flight; the desktop binding that showed and confirmed a root was removed in PR7b; the root-replace branch had no product path (another fleet = leave, then join). PR #528 nit 2 recorded it as dead.

CONSEQUENCES for a caller:
- Read the installed root with `pki.InstalledRoot(dir)` (zero RootInfo for a MISSING root.crt, an error for an unreadable one) before showing anything; `pki.Status` reports an unreadable root as absent and must not decide.
- Run `pki.PreviewBundle(keyPath, raw)` before asking anyone to trust a root.
- Never retry on RootDiffersError or ErrAlreadyInstalled: surface it.
- A renewed leaf for the installed root cannot go through InstallBundle; the CRL alone moves with `pki.InstallCRL`.
- Tests that need the per-root watermark across fleets go through `pki.Uninstall` (which keeps crl.number) between installs.
- The lock file is a SIBLING of <pki>; only <pki>'s parent is created (0700), so a refusal leaves <pki> as it was, and that parent must be writable ("install lock <path>: ...").

MISREADINGS:
- "Atomic renames make concurrent installs safe": they keep the FILES consistent, not the decision; the lock does that (TestInstallBundle_RootInstalledSinceReadIsRefused: a root installed by another process between a caller's read of 'nothing installed' and its install is refused, naming it).
- "ErrAlreadyInstalled means the same bundle twice": it means the bundle's ROOT is installed, whatever leaf or CRL it carries.
- "A confirmed caller can still replace a root": there is no parameter for it.

Proven by internal/pki/install_test.go: TestInstallBundle_InstalledMaterialIsNeverReplaced, TestInstallBundle_RootInstalledSinceReadIsRefused, TestInstallBundle_RefusalsAreClassifiedAndWriteNothing (its rollback row on an uninstalled home), TestInstallBundle_UnreadableInstalledRootFailsClosed, TestInstallBundle_FirstInstallLocksBesideThePKIDir, TestInstallBundle_WaitsForTheInstallLock, TestInstallBundle_UnwritableParentNamesTheLock, TestInstalledRoot_MissingIsNoneUnreadableIsAnError.

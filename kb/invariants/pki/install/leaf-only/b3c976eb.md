# pki.InstallLeaf installs a RENEWED instance certificate alone: only for the key at keyPath and the installed identity, only if it verifies NOW against the INSTALLED root and CRL, and only with a NotBefore strictly later than the installed one's; root.crt and crl.pem are never touched; its one production caller is the tick (archtest installLeafCallers)

RULE (fleet PR8b, branch feat/fleet-tick-renewal). `pki.InstallLeaf(dir, keyPath, raw)`:
1. raw is exactly one CERTIFICATE block (else ErrMalformedBundle class);
2. it certifies the key at keyPath (ErrKeyMismatch), checked before the lock;
3. under the install lock: an instance certificate, root and CRL are installed; `VerifyInstanceChain(leaf, installed root, installed CRL, now, client)` (ErrUntrustedRoot / ErrExpired / ErrRevoked); the email SAN equals the installed certificate's ("a renewal keeps the identity"); NotBefore strictly later than the installed one's (ErrLeafNotNewer);
4. only then instance.crt is replaced atomically (0600). The running mTLS listener adopts it on its next handshake or tick.

WHY a separate function: since fleet PR8 `pki.InstallBundle` is first-install only and refuses the installed root's own bundle (ErrAlreadyInstalled), so a renewal had no install path.

CONSEQUENCES. The only production caller is internal/repos/fleet_tick.go (test/archtest installLeafCallers); a second caller is a reviewed decision. A leaf of another fleet root can never be installed this way, even for this key. Proven by internal/pki TestInstallLeaf (another key, another root, revoked, not newer, two blocks, another identity, nothing installed: all refused writing nothing).

MISREADING. "InstallLeaf can move an instance to a new root if the leaf chains to one": it verifies against the INSTALLED root only.

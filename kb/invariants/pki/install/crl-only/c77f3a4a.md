# pki.InstallCRL installs a CRL alone only when its root is the INSTALLED root and its Number is STRICTLY above that root's watermark; an equal or lower Number is refused with ErrCRLRollback and crl.pem stays byte-identical

RULE (fleet design D13). `InstallCRL(dir, rootCert, raw)` takes the install lock (`<dir>.lock`, the one InstallBundle uses) and then: (1) the installed root (`InstalledRoot(dir)`) must have rootCert's RootID — otherwise `*RootDiffersError`, including when NO root is installed: a CRL never installs or changes a root; (2) raw must be exactly one `X509 CRL` PEM block, signed by rootCert (`CheckCRL`) — else `ErrCRLInvalid`; (3) its Number must be STRICTLY greater than `AcceptedNumber(dir, rootCert)` — lower or EQUAL is `ErrCRLRollback`; only then crl.pem is written (0600) and the watermark raised.

WHY EQUAL IS REFUSED. `CheckCRL` alone accepts Number == watermark (it refuses only lower). For a CRL-only install an equal Number is either the CRL already held or a different list re-using a Number; neither may replace crl.pem.

CONSEQUENCES. The member tick (M3) should call InstallCRL only when the fleet repo's crl.pem Number exceeds the watermark, and treat ErrCRLRollback as 'nothing to do', not as an incident, when the Number is equal. A refused call leaves crl.pem and crl.number untouched (TestInstallCRL_OnlyAboveTheWatermark, sabotage-checked: removing the equality check, the root check or the watermark record each turns a test red).

MISREADING. This is not InstallBundle's rule: InstallBundle still uses CheckCRL's 'not lower' test for a bundle's CRL.

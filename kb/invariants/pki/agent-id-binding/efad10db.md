# An agent id is opaque, LOWER CASE and only compared, byte for byte: the ONE string operation is pki.AgentIDOfEmail (domain exactly agents.knomit.io, local part, drop +<op>, return it only if ValidAgentID accepts it; nothing is case folded); commit author id, leaf email id, members/<id>/ folder, leaf file id and the record's agent: must all be EQUAL; an id holding '+', '@', '/', white space or an upper-case letter is refused at minting, at issuance, and, when stored, at boot

D18 bans PARSING an id (no fp8, nothing derived), not BINDING it (R2). store.agentIDOfAuthor is pki.AgentIDOfEmail, so the commit author and the certificate can never disagree.

LOWER CASE, NO FOLDING (round 3 ruling, applied everywhere): pki.ValidAgentID refuses empty, '+', '@', '/' (since PR #523: an id names exactly one folder members/<id>/ and one file certs/<id>.pem), white space, control characters and ANY upper-case letter, so every id it accepts reads back as itself. AgentIDOfEmail does no ToLower: Vic@agents.knomit.io and vic@AGENTS.KNOMIT.IO are NOT agent addresses (an upper-case author is refused no-record 'not an agent address'; a certificate carrying one is an OPERATOR certificate). IssueLeaf refuses an agent address whose local part fails ValidAgentID and refuses the agent domain in any other case spelling (agentDomainSpelling: case is folded there only to refuse). app.sanitizeHostname lowercases the hostname (and replaces '+' and '@'), so ids and the host label are minted lower case; repos.resolveIdentity refuses to mint an invalid id and writes nothing. The judge (byAgent index, mayRegister, selfRecord, recordOwner (formerly onlyUnder), leafFor, validLeaf, leafRenewal), the fleet reader (FleetPKI.Cert, FleetKeysOf), `knomit verify audit` (agent ids; the --key fingerprint-prefix filter is not an id and is still lowercased) and repos (fleet status, memberRecordPath, reconcile) compare ids EXACTLY.

OPTIONS the user decided between: fold case at the comparison points (accept Vic as vic) vs refuse upper case at the door. CHOSEN: refuse, because every fold point is a place where two spellings can disagree (the gate, the reader, the audit and the filesystem each folding differently was the review's finding), and a case-insensitive checkout would make certs/Vic.pem and certs/vic.pem one file.

NO LEGACY: a control.db whose stored agent id fails ValidAgentID stops boot with repos.ErrStoredAgentIDInvalid, whose message says a fresh start is required (stop knomit, delete control.db); the stored id is never rewritten or lowercased. `knomit identity show` is a display command and prints such an id with an `(invalid: ...)` note instead of failing.

The judge binds: leafFor requires VerifyInstanceChain's Identity.AgentID == id (rule A and rule B); the leaf-renewal and pki-add primitives require it equal the id the leaf's FILE name stands for, so certs/Vic.pem can hold no leaf. A leaf the root issued to another agent, planted at this id's path, vouches for nothing (review probe P4).

MISREADING: 'D18 means the id is never looked at' is wrong: it is compared for equality everywhere identity meets identity. MISREADING: 'ids are case-insensitive' is wrong: Vic and vic are different strings and Vic is not a valid id at all. An existing upper-case id minted before this change is not migrated: boot refuses it.

UPDATE (PR #523, verified at merge commit 3ac59b57): the 'folder and the record's agent: must be EQUAL' part is now ENFORCED, on both sides: the judge's recordOwner refuses (not-owner) a record written under members/<id>/ whose agent: is not <id>, and the loader (loadMembersOfTree) loads a record only when its agent: equals the folder directly under members/ (others skipped and logged once). See kb/invariants/fleet/member-loader/folder-binding/07d6a7a2.md. Test-only: testsigner.FixtureAgentID maps a leftover '/' to '-'.

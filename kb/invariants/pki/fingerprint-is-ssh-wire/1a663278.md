# An instance key's fingerprint is hex(sha256(SSH WIRE encoding)) — never SPKI DER, never the raw 32 bytes — and principal IDs carry all 64 hex while the branch name and certificate SAN carry only the first 8

THE ONE DEFINITION: `pki.Fingerprint(pub) = hex(sha256(ssh.NewPublicKey(pub).Marshal()))`, 64 hex characters. It is the same hash `internal/app/identity.go` `fingerprint()` computes over `signer.PublicKey().Marshal()` and truncates to 8 for the agent branch name `agent/<host>-<fp8>`. Two things compare against it and both must use this computation: the agent branch name and the principal ID of an instance (`instance:<64 hex>@cert`, the grants key).

FORBIDDEN alternatives, both of which look reasonable: sha256 over the X.509 SubjectPublicKeyInfo DER (what most PKI tooling calls "the key fingerprint"), and sha256 over the raw 32 Ed25519 bytes. Each yields a different value. Using either for anything compared to a branch name or a principal does not fail loudly: a grants row silently names no one and the agent branch name no longer matches its key.

FULL vs SHORT: `pki.Short` (8 hex, 32 bits) is a display value only (the agent branch name, messages); the certificate no longer carries it, because its one email SAN names the agent id (PR #514). It is never an identity, because 32 bits can be ground. Anything that authorizes (grants rows, Principal.ID) uses all 64.

ENFORCED BY TESTS, each verified to fail when Fingerprint was sabotaged to sha256(raw key): `TestFingerprint_IsSSHWireNotSPKIOrRaw` (pins the value AND asserts inequality with both forbidden forms), `TestShort_EqualsTheBranchNameFingerprint` (reproduces identity.go inline), and `TestEnsureKeyPair_FingerprintIsPrefixOfPKIFingerprint` in internal/app (calls the real ensureKeyPair). If you change identity.go's fingerprint, the last one fails — that is the point; changing it also renames every agent branch.

MISREADING TO AVOID: the older decision fact says the branch fingerprint is 'SHA256(public_key_bytes)'. 'public key bytes' there means the SSH wire encoding (length-prefixed 'ssh-ed25519' + length-prefixed key), not the 32 raw bytes. Also: LoadSigner turns the OpenSSH-format key into an in-memory crypto.Signer; it never writes the key in another format, so ~/.knomit/id_ed25519 remains the only on-disk copy.

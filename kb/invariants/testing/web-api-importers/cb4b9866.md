# In the parent package internal/edge/web, only router.go and server.go may import a package under internal/edge/web/api; TestWeb_OnlyRouterAndServerImportAPI enforces it and is non-vacuous even before any api package exists

Guard R (12a of the web split, PR #621, merged on dev as 7dccaa09; re-read there): TestWeb_OnlyRouterAndServerImportAPI in test/archtest/web_split_test.go.

RULE. router.go mounts each api package with `<pkg>.Mount`. server.go is the router's other half (Server.Handler mounts the API router) and is the one other allowed importer; under the Mount ruling server.go needs no api field type, so dropping it from webAPIImporters after 12d is a one-entry change. Any other non-test file of the parent that imports internal/edge/web/api or anything under it fails, whatever the import form (named, blank or dot). Build-constrained files are scanned (go list GoFiles + CgoFiles + IgnoredGoFiles). Test files are not.

NON-VACUITY, since it holds today when no api package exists: the file list comes from go list and the scanned count must equal go list's; every package clause must be web; router.go and server.go must both have been scanned; and router.go's import of github.com/go-chi/chi/v5 must have been recorded. TestWeb_APIImportDetector_Discriminates pins the detector on synthetic source.

CONSEQUENCE: a handler, middleware or helper in the parent that wants an api package's name is a design error; route through router.go's Mount.

DOES NOT MEAN: that test files of package web are checked; or that edges between api packages are covered. Those are TestLayers' business: each needs a sameLayerEdges entry.

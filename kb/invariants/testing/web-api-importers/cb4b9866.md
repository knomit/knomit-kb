# In the parent package internal/edge/web, only router.go and server.go may import a package under internal/edge/web/api; TestWeb_OnlyRouterAndServerImportAPI enforces it, and its non-vacuity does not depend on any api package existing (at 01e405e4 only router.go imports one, api/origins)

Guard R (12a of the web split, PR #621, merged on dev as 7dccaa09; re-read at 01e405e4, PR #624, for the update below): TestWeb_OnlyRouterAndServerImportAPI in test/archtest/web_split_test.go.

RULE. router.go mounts each api package with `<pkg>.Mount`. server.go is the router's other half (Server.Handler mounts the API router) and is the one other allowed importer; under the Mount ruling server.go needs no api field type. 12d (PR #624) removed Server.SessionManager, yet server.go stays in webAPIImporters because the ruling names the pair; dropping it is a one-entry change once api/jobs lands without a server.go import. At 01e405e4 server.go imports no api package. Any other non-test file of the parent that imports internal/edge/web/api or anything under it fails, whatever the import form (named, blank or dot). Build-constrained files are scanned (go list GoFiles + CgoFiles + IgnoredGoFiles). Test files are not.

OBSERVED STATE at 01e405e4: api/origins now exists and router.go is the one non-test file of the parent that imports it (router.go also mounts it via origins.Mount, once per Server). The guard passes because router.go is in webAPIImporters, not because there is nothing to import. api/kb, api/manage and api/jobs do not exist yet.

NON-VACUITY, which does not need any api package (the guard was written when none existed and the checks are unchanged): the file list comes from go list and the scanned count must equal go list's; every package clause must be web; router.go and server.go must both have been scanned; and router.go's import of github.com/go-chi/chi/v5 must have been recorded. TestWeb_APIImportDetector_Discriminates pins the detector on synthetic source.

CONSEQUENCE: a handler, middleware or helper in the parent that wants an api package's name is a design error; route through router.go's Mount.

DOES NOT MEAN: that test files of package web are checked; or that edges between api packages are covered. Those are TestLayers' business: each needs a sameLayerEdges entry.

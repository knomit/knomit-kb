# No web-family package declares a forward into another web-family package, exported or unexported, siblings included, including through a method expression; TestWebFamily_NoForwardsWithinFamily enforces it and closes guard P's unexported gap for the web family

Guard F (12a of the web split, PR #621, merged on dev as 7dccaa09; re-read there): TestWebFamily_NoForwardsWithinFamily in test/archtest/web_split_test.go, using forwardsInto in parent_forwards_test.go.

RULE. For each package of the web family (internal/edge/web and every package under it), forwardsInto(isTarget, files, strict=true) flags: a type alias of another family package's name; a var or const whose initializer is only the target's name; and a func or method, EXPORTED OR NOT, whose single statement is a call into another family package with the parameters passed through (possibly interleaved with receiver state). Strict mode turns on fwdCfg.unexported and fwdCfg.methodExprs, so a method expression of a target type counts as the target's name both as a call (`return hal.URLBuilder.Repos(b)`) and as a var initializer (`var reposOf = hal.URLBuilder.Repos`). The canonical case is `func writeStoreError(w, r, err) { httpx.WriteStoreError(w, r, err) }`: delete the shim and call the owner directly.

TARGETS: every other web-family package, children and siblings alike (after the split a shim in api/kb pointing at httpx is a sibling edge guard P never sees). SCOPE: the web family only; widening the unexported check to all of internal/ would rule on engine and corpus helpers no split plan has reviewed.

GUARD P UNCHANGED: parentForwards is now forwardsInto(childPackages(parent), files, false); fwdCfg.unexported and methodExprs default to false, so guard P and A2 behave as before. The unexported and method-expression gaps named in ba1210d3 still hold for internal/ as a whole; guard F closes them for the web family.

NON-VACUITY, per package: go list's file count, the package clause, and the package's webKnownTypes each seen in its own file (the same file map forwardsInto reads). The detector, including a multi-file case with the shim in the file that sorts last, is pinned by TestWebFamily_ForwardDetector_Discriminates.

STATED GAPS (each needs data flow): a parameter copied into a local before the call; closures and func-typed vars; method values; named results assigned from the call; wrapped or computed arguments. A helper that adds an argument is not a forward. A green run is not proof that no shim exists; the reviewer still reads new helpers.

UPDATE (12d, PR #624, merge commit 01e405e4 on dev; re-read there): the pointer method expression is NO LONGER a gap. Guard F now also matches (*pkg.T).M, as a call (`return (*hal.URLBuilder).Repos(b, r)`) and as a var initializer (`var repos = (*hal.URLBuilder).Repos`); unwrapParenStar strips the parens and star so it reads as pkg.T.M. Pinned by the 'pointer method expr call/var' cases of the detector test. The STATED GAPS list above no longer includes it; the remaining gaps (locals, closures, method values, named results, wrapped arguments) still hold.

# Every package under internal/edge/web/api exports exactly func Mount (positional parameters, no exported Deps type, no results), counting members reached through an alias or an embedded type; TestWebAPI_ExportsOnlyMount enforces it and limits the web family to web, hal, httpx and the six api packages chat, jobs, kb, manage, origins and secrets (a webAPIExportAllowlist key whose package go list does not return FAILS the test)

Guard M (12a of the web split, PR #621, merged on dev as 7dccaa09). Updated for 12f (PR #630, squash merge 33eb0307 on dev; re-read there): TestWebAPI_ExportsOnlyMount in test/archtest/web_split_test.go. The web split's api packages are complete: kb, manage, jobs and origins all exist and the pending state is gone.

RULE. Every package go list returns under internal/edge/web/api exports exactly one name, the package-level func Mount, Mount takes positional parameters (there is no exported Deps type), and Mount returns nothing (checked since PR #624). Every per-package list in webAPIExportAllowlist is EMPTY; a future exported name needs a reviewed entry with a non-empty reason. The rulings behind it are in kb/decisions/web/api-packages-export-only-mount.

WHAT COUNTS AS AN EXPORT (exportedNames): package-level funcs, types, vars and consts; and every exported method or field reachable through an exported type T: T's own members; members reached through an alias of a local type (`type JobRegistry = jobRegistry` reaches jobRegistry's exported methods and fields); and members promoted from every local type T embeds, transitively, whether the embedded type is exported or not (pointer and generic embeds included; a field T declares itself shadows a promoted one). Exported methods of an unexported type that no exported type aliases or embeds are NOT counted, so ServeHTTP on an unexported handler is fine. Members of a type from another package that an exported type embeds are not walked; only local types are.

POLICY (apiExportProblems): Mount must be declared, as a package-level func with NO RESULTS. A var, const or type named Mount fails ("Mount is a <kind>"); a func Mount with one or more results, named or not, fails as "func returning N" ("Mount registers its routes on r and returns nothing"); a package with no func Mount fails ("declares no func Mount"). A method named Mount is not the package's func and does not satisfy it. The result count is checked, not the result types, so returning a handler, router, closer or error is refused whatever its type. Any other exported name fails unless listed with a reason. A listed name that is not exported fails as stale.

LAYOUT (webLayoutProblems): an api/* package must be a webAPIExportAllowlist key (so a bare `api` package and `api/zz` both fail). Any other web-family package must be a webFamilyLayout key: the parent, hal or httpx. A resource package outside api/, for example internal/edge/web/jobs, fails. Guard W (web-no-interfaces) does not cover this, because it only needs a webKnownTypes entry, which any new package can add for itself.

NO PENDING STATE (since 12f). The four webAPIExportAllowlist keys are api/kb, api/manage, api/jobs and api/origins, and all four are live: each is scanned and policed for real. A key whose package go list does NOT return now fails the test with t.Errorf "webAPIExportAllowlist names api packages go list does not return: ...; a removed or renamed package takes its entry with it". The earlier behaviour (a t.Logf "pending api packages" that allowed and failed nothing) and the "no api packages yet" Logf were removed. So a removed or renamed api package must take its key with it in the same PR.

NON-VACUITY for each api package: the file list comes from go list and the scanned count must equal go list's; the package clause must be the last element of the import path; Mount must be found. TestWebAPI_ExportDetector_Discriminates pins the detector and both policies on synthetic source (alias, embedding including transitive, pointer and generic embeds, shadowing, the ServeHTTP exemption, the layout rule). PR-reported sabotage (not re-run here): adding an `"api/zz": {}` key turns the test red.

MOUNT SIGNATURES at 33eb0307. api/kb: Mount(branch, lens chi.Router, ontologyRoot string, emb model.Embedder), four parameters (kb/architecture/web/api-kb/). api/manage: Mount(top, repoOuter, repo, branch, lens chi.Router, rm, agentBranch, embeddingsEnabled, expiryDays, operator) (cf88da62). api/jobs: Mount(r, rm, llmAdapter). api/origins: Mount(ctx, r, rm, agentBranch, sessionsDir). The subrouter parameters are the user ruling in kb/decisions/web/route-tree-built-by-router/ab86ee4f.md.

CONSEQUENCES: a helper two api packages need goes in httpx; Mount's dependencies arrive as positional parameters; tests that touch an api package's internals live in that package.

DOES NOT MEAN: (1) a green run proves nothing about a package that is not an allowlist key: a new api package with no key fails LAYOUT, not export policy, until a reviewed key is added. (2) Mount's whole signature is policed. Only its kind (func) and result count (zero) are checked. Its parameter list and types are NOT: 'positional parameters, no exported Deps type' is enforced indirectly (an exported Deps type fails as an extra export), not by inspecting Mount's parameters, and the 'more than about 5 parameters' flag is a review matter. The Mount parameter lists of kb and manage contain chi.Router subrouters, which this guard does not inspect. (3) Cross-package embedded members are walked.

Addendum (PR5, feat/chat-api): there are now SIX api packages and six webAPIExportAllowlist keys: api/kb, api/manage, api/chat, api/jobs, api/origins and api/secrets (the 12f text above, which counts four, is history). internal/edge/web/api/chat has an empty webAPIExportAllowlist entry (exports only Mount, positional parameters, no Deps type), webKnownTypes entries (manager, chat, chatStore, sessionLog, each in its own file) and the layer edges edge/web/api/chat -> edge/web/hal, edge/web/httpx and edge/mcp. A shim that re-exports another web-family package's names is refused (the origins package's RunPrefix aliases were removed). httpx's run-directory layout names (runPrefix, runLockSuffix, isChild) are unexported because only httpx uses them; api/origins' tests that plant a dead run by hand spell the layout ("run-" and ".lock") as literals of their own, so a change to the layout fails them instead of silently following it.

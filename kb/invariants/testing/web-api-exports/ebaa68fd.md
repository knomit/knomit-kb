# Every package under internal/edge/web/api exports exactly func Mount (positional parameters, no exported Deps type, no results), counting members reached through an alias or an embedded type; TestWebAPI_ExportsOnlyMount enforces it and limits the web family to web, hal, httpx and the api packages kb, manage, jobs, origins (origins, jobs and manage exist at a8bf8d7a; only kb is pending)

Guard M (12a of the web split, PR #621, merged on dev as 7dccaa09). Updated for 12d (PR #624, merge commit 01e405e4 on dev; re-read there): TestWebAPI_ExportsOnlyMount in test/archtest/web_split_test.go.

RULE. Every package go list returns under internal/edge/web/api exports exactly one name, the package-level func Mount, Mount takes positional parameters (there is no exported Deps type), and Mount returns nothing (checked since PR #624). Every per-package list in webAPIExportAllowlist is EMPTY; a future exported name needs a reviewed entry with a non-empty reason. The rulings behind it are in kb/decisions/web/api-packages-export-only-mount (written with this fact).

WHAT COUNTS AS AN EXPORT (exportedNames): package-level funcs, types, vars and consts; and every exported method or field reachable through an exported type T: T's own members; members reached through an alias of a local type (`type JobRegistry = jobRegistry` reaches jobRegistry's exported methods and fields); and members promoted from every local type T embeds, transitively, whether the embedded type is exported or not (pointer and generic embeds included; a field T declares itself shadows a promoted one). Exported methods of an unexported type that no exported type aliases or embeds are NOT counted, so ServeHTTP on an unexported handler is fine. Members of a type from another package that an exported type embeds are not walked; only local types are.

POLICY (apiExportProblems): Mount must be declared, as a package-level func with NO RESULTS. A var, const or type named Mount fails ("Mount is a <kind>"); a func Mount with one or more results, named or not, fails as "func returning N" ("Mount registers its routes on r and returns nothing"); a package with no func Mount fails ("declares no func Mount"). A method named Mount is not the package's func and does not satisfy it. The result count is checked, not the result types, so returning a handler, router, closer or error is refused whatever its type. Any other exported name fails unless listed with a reason. A listed name that is not exported fails as stale.

LAYOUT (webLayoutProblems): an api/* package must be a webAPIExportAllowlist key (so a bare `api` package and `api/zz` both fail). Any other web-family package must be a webFamilyLayout key: the parent, hal or httpx (httpx was allowed before it existed). A resource package outside api/, for example internal/edge/web/jobs, fails. Guard W (web-no-interfaces) does not cover this, because it only needs a webKnownTypes entry, which any new package can add for itself.

PENDING. The expected api packages are the four webAPIExportAllowlist keys api/kb, api/manage, api/jobs and api/origins (created in 12c to 12f). At 97ae7c19 (12c, PR #627, re-read there) api/origins (12d; func Mount(r chi.Router, rm *repos.Manager, agentBranch string)) and api/jobs (12c; func Mount(r chi.Router, rm *repos.Manager, llmAdapter llm.LLMAdapter)) exist, both with no results, so both are scanned and policed for real. (At 97ae7c19 api/kb and api/manage were both PENDING; api/manage landed in 12e, see UPDATE below.) A PENDING key is one whose package go list does not return: a key whose package go list does not return allows nothing and fails nothing; the test only t.Logf's "pending api packages (planned, not created yet; each allows nothing)" listing them. The separate "no api packages yet" Logf fires only when go list returns none, so it no longer fires. END STATE (a code comment, not yet true): after 12f the pending Logf becomes an Errorf, so a planned package that never lands fails the test instead of staying parked.

NON-VACUITY for each live api package: the file list comes from go list and the scanned count must equal go list's; the package clause must be the last element of the import path; Mount must be found. TestWebAPI_ExportDetector_Discriminates pins the detector and both policies on synthetic source (alias, embedding including transitive, pointer and generic embeds, shadowing, the ServeHTTP exemption, the layout rule).

CONSEQUENCES: a helper two api packages need goes in httpx; Mount's dependencies arrive as positional parameters; tests that touch an api package's internals live in that package.

DOES NOT MEAN: (1) a green run proves the rule holds for every planned api package. Only api/origins and api/jobs are scanned at 97ae7c19; api/kb and api/manage are skipped with a log line, so a green run says nothing about them until they exist and the Logf becomes an Errorf. (2) Mount's whole signature is policed. Only its kind (func) and result count (zero) are checked. Its parameter list and types are NOT: 'positional parameters, no exported Deps type' is enforced indirectly (an exported Deps type fails as an extra export), not by inspecting Mount's parameters, and the 'more than about 5 parameters' flag is a review matter. (3) Cross-package embedded members are walked.

UPDATE (12e, PR #628, merged on dev as a8bf8d7a; re-read there): internal/edge/web/api/manage now exists. Its only export is func Mount(top, repoOuter, repo, branch, lens chi.Router, rm, agentBranch, embeddingsEnabled, expiryDays, operator) with no results (kb/architecture/web/api-manage/cf88da62.md), so it is scanned and policed for real. The webAPIExportAllowlist key for api/manage is live and empty; only api/kb is still PENDING (planned 12f), and the DOES NOT MEAN (1) above now applies to api/kb alone. The Mount parameter list contains five chi.Router subrouters, which this guard does not inspect (it checks kind and result count only); that is the user ruling in kb/decisions/web/route-tree-built-by-router/ab86ee4f.md.

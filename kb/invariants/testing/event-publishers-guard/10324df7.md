# TestEventPublishers_NotExposed (name-based) and TestEventPublishers_NotLeakedTyped (go/types) keep the event publishers inside repos; neither follows a publisher through a local variable, helper, bare named return, channel, map, reflection or a non-default build tag

RULE (PR #631, merged as 37dc65d5; re-read there). No code outside package events may hand out an events.TaskPublisher or events.RepoEventPublisher (the split is the decision in kb/decisions/repos/events/hub-publisher-split/f6d5c104.md). Two archtests enforce it.

1. test/archtest/event_publishers_test.go TestEventPublishers_NotExposed (NAME-based). For every non-test file outside events, build-constrained files included (go list IgnoredGoFiles), it flags: an exported func or method with a publisher in its results; an exported struct field (embedded or named) of a publisher type; an exported package-level var or const of a publisher type; an exported type alias or definition naming a publisher. Parameters are not exposure (a constructor may TAKE a publisher). Non-vacuity: events must still declare both publisher types and some scanned file must import events. TestEventPublishers_GuardDiscriminates runs the detector on inline source with a flagged and a clean case per shape.

2. test/archtest/event_publishers_typed_test.go TestEventPublishers_NotLeakedTyped (go/types, packages loaded with golang.org/x/tools/go/packages, imports read from export data). In every non-test file of a package that imports events it flags: (a) a return statement of an EXPORTED func or method, closures inside it included, whose result expression has a publisher type, is a method value bound to a publisher, is a func literal using a publisher-typed expression, or is a composite literal with a publisher-typed element, whatever the declared result type (so func (ri *RepoInstance) Publishing() any { return ri.pub } and Announcer() func(events.IndexEvent) { return ri.pub.BroadcastIndex } are red); (b) an assignment, keyed composite-literal field or var initializer that puts a publisher-typed expression or bound method value into an EXPORTED struct field or package-level var. TestEventPublishers_TypedGuardDiscriminates covers each shape.

WHAT THE GUARDS DO NOT CATCH (stated in the test's own comment). The typed guard follows no data flow: a publisher passed through a LOCAL VARIABLE or a HELPER's result before it is returned; NAMED results assigned and BARE-returned; publishers sent on CHANNELS or stored in MAPS or slices and returned; REFLECTION. Files behind build tags other than the default are not type-checked by the typed guard (the name-based guard still scans them). Neither guard catches an exported one-call wrapper like func (ri *RepoInstance) Announce(ev) { ri.pub.BroadcastIndex(ev) }: that is red under guard P (ba1210d3, verified by the round-2 review sabotage), not under these. A green run is therefore not proof that no publisher is reachable; the remaining shapes need deliberate code in the repos parent and are reviewer-enforced.

CONSEQUENCE. A change in repos that adds an exported accessor near ri.pub, ri.repoEventPub or m.repoEventPub needs a human read even when both guards are green. DOES NOT MEAN: that these guards stop a handler from calling TaskHub.Start with a rebuild op name; the hub-side surface is deliberately open to consumers.

AT 14c (PR #632, merged as ee850fd6; re-read there): both guards select every package that imports events, so the new child internal/corpus/repos/trigger is scanned with no scope edit. trigger.New takes the repo's *events.TaskPublisher as a parameter and stores it in the unexported Dispatcher.pub, which is not exposure. Sabotages run against the branch: an exported Publisher() *events.TaskPublisher on Dispatcher fails TestEventPublishers_NotExposed, an exported Publishing() any returning d.pub fails the typed guard (worker proof), and the reviewer's `func (d *Dispatcher) Announcer() func(string) { return d.pub.BroadcastStatus }` fails TestEventPublishers_NotLeakedTyped ('exported Announcer returns a publisher'). The same capability-by-construction rule now also covers the dispatcher's run func (kb/decisions/repos/triggers/run-func-capability/03d92e7a.md), which no name-based guard enforces: it is enforced by the run func being unexported and by TestTriggerNew_OnlyFromRepos.

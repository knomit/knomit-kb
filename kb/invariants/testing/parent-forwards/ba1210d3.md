# No parent package under internal/ declares an alias, var, const, or exported one-call func/method that forwards a child package's names; TestParents_NoForwardsIntoChildren enforces it with a go-list-derived, non-vacuous scan

RULE (PR #599, merged as 83f3374b; re-read there). For every internal/ package that has go-list children (any depth, internal/ children included), its non-test Go files, build-constrained ones included (go list GoFiles + CgoFiles + IgnoredGoFiles, so a windows-only file is scanned), must declare no alias, var or const of a child's name and no exported func or method that is ONE call into a child. Test: test/archtest/parent_forwards_test.go TestParents_NoForwardsIntoChildren. It generalises the store-only guards A1/A2 (a4f375c0) and shares the method-forward detector with A2 (methodForwards in store_reexports_test.go).

FORWARD RULE for a package-qualified call: the args are the function's own params in order, interleaved with receiver-state expressions (the receiver, a field chain on it, or a no-arg method call on one: recv, recv.f, recv.f.M()). A child function named New* or Open* is a constructor and keeps the strict params-only test, so fsck.NewChecker(s.repo) and control.NewLensRegistry(m.ControlDB()) are NOT forwards while control.ControlUp(m.ControlDB()) in repos is RED. In the store the state-injecting Service methods are exempted by reusing injectsStoreState keys (one source of truth); SyncDSNParam is the one parentForwardAllowlist entry (a stale entry fails; each needs a reason). Hit labels use the receiver name.

NON-VACUITY (derived from go list): every parent with children must have at least one parsed file (blinding one parent, e.g. repos, is RED and names it), and every layer containing such a parent is covered.

CONSEQUENCE: when a new child is split out of a parent, point callers at the child; do not leave a convenience forward. DOES NOT MEAN (misreadings): the guard does NOT catch method values, closures, wrappers that add or compute arguments (child.F(a, 1)), unexported forwards, a non-constructor child function named New* or Open*, or children outside internal/; a green run is not proof of no facade.

UPDATE (12a, PR #621, merged on dev as 7dccaa09; re-read there): the 'unexported forwards' and method-expression gaps above remain gaps of guard P for internal/ as a whole, but for the web family TestWebFamily_NoForwardsWithinFamily (kb/invariants/testing/web-family-forwards) closes both, plus forwards into siblings. Guard P itself is unchanged: the detector is factored as forwardsInto(isTarget, files, strict) and parentForwards is forwardsInto(childPackages(parent), files, false); fwdCfg.unexported and methodExprs default to false. An unexported web shim into hal, or a method-expression shim, is red under F and green under P.

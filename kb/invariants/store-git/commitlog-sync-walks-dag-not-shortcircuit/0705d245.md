# CommitLogSync MUST skip-and-continue on dedup hits (never short-circuit) to handle merge DAGs

CommitLogSync(branchName, iter) iterates commits one at a time. For each commit hash returned by iter(), it checks branch_commits WHERE branch_id=? AND commit_hash=? for dedup. CRITICAL: when the dedup hit returns cnt > 0, the loop CONTINUES (skips this commit) rather than SHORT-CIRCUITING the entire walk. Why: for LINEAR history a dedup hit means all ancestors are recorded too, so short-circuit would be safe. But for MERGE commits the iterator walks a DAG — hitting a known commit on ONE parent's line says NOTHING about the OTHER parent's ancestry. Short-circuiting would leave half a merge commit's parents unindexed, breaking branch_commits parity (which Verify's commit-log check would correctly flag). branchName empty is a programming error (returns error); EnsureBranch MUST run first so the branches row exists for the SELECT id FROM branches lookup. Anti-pattern: optimizing CommitLogSync to break out on first dedup hit 'for speed' — would silently lose merge-parent visibility rows.

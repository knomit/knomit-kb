# CommitLogSync MUST skip-and-continue on dedup hits (never short-circuit) to handle merge DAGs

CommitLogSync(branchName, iter) iterates commits one at a time. iter() returns (hash string, payload CommitLogPayload, err error) — the payload is a THUNK, not a value. For each hash, CommitLogSync checks branch_commits WHERE branch_id=? AND commit_hash=? for dedup. CRITICAL: when the dedup hit returns cnt > 0, the loop CONTINUES (skips this commit) rather than SHORT-CIRCUITING the entire walk. Why: for LINEAR history a dedup hit means all ancestors are recorded too, so short-circuit would be safe. But for MERGE commits the iterator walks a DAG — hitting a known commit on ONE parent's line says NOTHING about the OTHER parent's ancestry. Short-circuiting would leave half a merge commit's parents unindexed, breaking branch_commits parity (which Verify's commit-log check would correctly flag). branchName empty is a programming error (returns error); EnsureBranch MUST run first so the branches row exists for the SELECT id FROM branches lookup. Anti-pattern: optimizing CommitLogSync to break out on first dedup hit 'for speed' — would silently lose merge-parent visibility rows.

SHORTER WALK vs CHEAPER STEP — the distinction this invariant implies but did not previously spell out. What is forbidden is ending or truncating the walk: every commit iter() yields must still be visited, and every merge-parent line must still be followed. What is NOT forbidden is making a visited-but-skipped commit cost less. PR 71 is the worked example: the dedup check now runs BEFORE payload(), so a known commit costs one indexed branch_commits lookup instead of an object.DiffTree (~307 SQLite object loads, ~2 ms). The walk length is byte-for-byte unchanged — row counts and an md5 over every (commit_hash, path, action) row were verified identical — only the per-commit payload became lazy. Regression anchor for the invariant under the lazy shape: TestCommitLogSync_WalksPastDedupHits in internal/store/commitlog_lazy_payload_test.go, which sees a known commit mid-iteration and still computes and inserts the commit after it.

# privdir.Verify refuses (ErrNotPrivate) any directory that is not private to the current user, and the fleet root key's two entry points call it: NewRoot runs Ensure THEN Verify before any key exists, LoadRoot Lstats root.key, runs Verify, then refuses a symlinked, non-regular or (unix) wider-than-0600 key with ErrUnprotectedRootKey; Verify cleans its path first

Built in PR #519 (merge 72919aa0), in internal/platform/privdir (no new package) and internal/pki/root.go. Verify exists because privdir.Ensure is warn-not-fail BY DESIGN (011eee48): over a symlink, a foreign owner, a filesystem without ACLs or a DACL someone protected on purpose it only logs and carries on. That is right for the data root and WRONG for the one directory whose protection is the ONLY thing between a plain root key and other local users.

VERIFY (privdir.Verify(path) error; changes nothing; wraps ErrNotPrivate and names the path, the reason and, where there is one, the fix):
- It runs verify(filepath.Clean(path)). Lstat of `link/` (a trailing separator, which shell tab-completion appends) resolves the link, so without the Clean a symlinked directory passed the symlink check (review finding N1, fixed in the merge).
- Every OS: refuse a symlink (Windows: any reparse point, ModeSymlink|ModeIrregular, which also catches junctions and cloud-file placeholders), anything that is not a directory, and an owner who is not this user.
- Unix: owner must be the effective uid, and ANY group or other bit (mode & 0o077) is refused; the error names `chmod 700 <dir>`.
- Windows: owner must be this user, SYSTEM or Administrators; a NULL DACL is refused; so is any allow ACE for an account that Ensure's warning also counts as foreign (foreignGrants/notForeign; SYSTEM, Administrators, CREATOR OWNER and OWNER RIGHTS are NOT foreign). It does not require the DACL to be Protected: an inherited DACL that grants only me and SYSTEM is private. Deny ACEs are ignored.

ORDER AT THE CALLERS (internal/pki/root.go):
- NewRoot: refuse an existing root.key or root.crt; privdir.Ensure(dir) (so what Ensure can fix is fixed: 0700 on unix, a protected DACL on Windows); then privdir.Verify(dir) ("refusing to write the fleet root key"); only then generate and write. O_EXCL on root.key is separately the refusal of a dangling root.key symlink.
- LoadRoot: Lstat(root.key) first, a missing key is ErrNoRootKey and Verify is NOT consulted; then privdir.Verify(dir) ("refusing to read the fleet root key"; LoadRoot never tightens, it did not create the directory); then the key must be a regular file, so a symlink is refused with ErrUnprotectedRootKey; on unix (the check is skipped on Windows, where Perm() reads 0666) mode & 0o077 != 0 is ErrUnprotectedRootKey naming `chmod 600 <path>` (0400 is accepted); then read and parse. An ENCRYPTED key (ssh.PassphraseMissingError) is refused with an error naming `ssh-keygen -p -N '' -f <path>`; it is not ErrNoRootKey.

WHY LoadRoot CHECKS TOO: the master switch is 'copy the directory'. A copy made with cp -r without -p, an unzip, a git checkout or a FAT backup lands root.key at 0644 in a 0755 directory, and ssh refuses the same key ('UNPROTECTED PRIVATE KEY FILE').

CONSEQUENCES. Any new caller that reads or writes the fleet root key must go through NewRoot/LoadRoot, not read the file itself. Any other secret whose only protection is a directory should call Ensure then Verify, not rely on Ensure.

MISREADINGS. 'Verify tightens the directory': no, it changes nothing; Ensure tightens, and only a directory this user owns. 'Verify checks only the last path component': yes, it Lstats the cleaned path, so a symlinked ANCESTOR (macOS /var -> /private/var, a symlinked $HOME) is not refused. 'LoadRoot ensures the directory': no. 'The Windows file mode is checked': no, the directory DACL is.

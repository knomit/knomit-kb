# GET /chat-providers key_source is the NAME of an env var that is actually SET, is a valid variable name and is the key source in effect; host carries no userinfo, query or fragment

The provider list's key_source (llm.keySource) is p.APIKeyEnv only when api_key_file and api_key are both unset, api_key_env is a valid environment-variable name AND that variable is set in the environment. A value that is not a variable name yields none; so does a name that is not set: a key pasted into api_key_env that happens to be only letters, digits and underscores passes the name check, and only the is-it-set check keeps it out. A provider whose key comes from api_key_file or a plaintext api_key also has none. host (Ollama) is shown as scheme, host, port and path: userinfo, query and fragment are dropped (displayHost), since any can carry a secret. Consequence: a new provider field that carries config text must go through the same gate; never copy a config string into /chat-providers without asking whether it can be a secret. Does NOT mean an unset api_key_env hides the variable name from the user everywhere: the model reason (no API key configured) still says why. Enforced by TestRegistry_KeySourceIsNeverTheKey, TestRegistry_KeySourceNeedsTheVariableToBeSet and TestRegistry_HostDropsCredentials (sabotage: drop the os.Getenv check, or keep RawQuery and Fragment, and they fail).

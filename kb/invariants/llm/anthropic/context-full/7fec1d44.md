# Anthropic context overflow ends as ErrContextFull two ways: HTTP 400 'prompt is too long' (input alone exceeds the window) and a normal 200 stream ending stop_reason model_context_window_exceeded (input + max_tokens exceed it); cache writes are split 5m/1h from message_start cache_creation

internal/engine/llm/anthropic.go (formerly anthropic_v2.go): a 400 invalid_request_error whose message contains 'prompt is too long' is returned wrapping ErrContextFull (not retryable). On current models (4.5+) a request whose input plus max_tokens exceeds the window is ACCEPTED and ends with stop_reason model_context_window_exceeded; the adapter returns a *StopError with Reason StopContextWindowExceeded that Is ErrContextFull and carries the partial Response (usage included). The loop keeps its text, ends the turn with the context-full sentence, and the next turn is refused before sending from the reported usage. Source: platform docs 'Context windows' > overflow behavior, checked 2026-11-04.

Usage: message_start's usage.cache_creation {ephemeral_5m_input_tokens, ephemeral_1h_input_tokens} fill Usage.CacheWrite5m/CacheWrite1h (SDK v1.26.0); message_delta usage has no split. Usage.CacheWrite stays the total; the unsplit remainder is priced at the 5m multiplier. Ollama has no cache writes.

Does NOT mean the window is known to the adapter: AnthropicOptions.ContextWindow defaults to 200000 while current models have 1M; the caller must set it per model, otherwise the pre-send budget refuses early.

# Preload is an optimisation only: a failed or wrong guess costs no model request and no turn, the model can always call load_tools, and a preloaded tool is approved no more than a loaded one

Preload runs once per user turn, after the user entry is added and before the first request, with that turn's message text (not the history). It adds zero model requests. A ranker error is recorded on a preload ToolsChange (RankerError) and TurnResult.RankerError and the turn proceeds with hook 1 = [load_tools]; it is never a user-visible error. NewFallbackRanker(primary, lexical) answers with the lexical ranker when the embedder errors. Consequences: no code may depend on a tool having been preloaded (the model may need one the guess missed and loads it with load_tools in the same turn); preloading approves nothing, so every call to a preloaded tool still goes through CallGate.Decide (loader-bypasses-gate invariant 14f7949c, on the PR 2 branch). Guarantee boundary: the ranker is NOT guaranteed to rank the needed tool first (a message like 'bind to X' names no tool); TurnResult.PreloadHits against Preloaded is how the hit rate is measured. Plumbing the embedder into chat.Mount is a later PR; until then the engine has the ranker type and the edge has the embedding ranker, neither wired.

# A turn the model never answered is dropped whole from hook 7 (settle): a refusal or any error on the first request, a truncation with no text, a cancel before any reply; a turn in which tool calls ran is flushed so results stay paired

internal/engine/llm/agent.go Loop.settle ends every turn: it first removes a trailing assistant entry whose tool_use has no recorded result, then drops the whole turn from hook 7 when no assistant entry is left, otherwise flushes it to hook 6. Unanswered means: refusal on the first request, any adapter error on the first request, a truncation or context-window stop whose partial has no text (reasoning-only partials included: reasoning blocks and tool_use from a cut-off reply are never stored), a cancel before any reply or partial text, a budget refusal before the first request. The budget baseline (last measured tokens) is restored on a drop.

Why: hook 6 is append-only and every later request resends it. A refused user text left in it is resent on every later turn (Anthropic guidance after a refusal is to leave out or rephrase the turn, not resend it), and a dangling user text produces two user messages in a row, which Ollama renders unmerged. The chat cannot recover because history has no edit UI.

Does NOT mean every refusal drops the turn: once tool calls ran in the turn (Requests > 1 with an assistant entry in hook 7) the user text, the tool_use and its result are flushed, so side effects stay visible to the model and every tool_use stays paired. N5: no path leaves two text user entries in a row (TestLoop_NoConsecutiveUserTextEntries); results entries followed by a user text render as tool then user on Ollama, which is fine.

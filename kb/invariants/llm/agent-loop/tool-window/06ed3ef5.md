# A loaded tool is evicted between requests under pressure and inside load admission (load_tools or a not-loaded call), only when room is needed, least recently used first, and never a tool called or loaded in the current turn nor a call of the response being answered: the pinned set is what keeps a pending call from meeting an eviction

For a provider with Caps.StablePrefix false the loop sends Window.Project(Builder.Snapshot()). Loop.relieve runs at the top of each RunTurn iteration, after the projected view is built and before checkBudget, and evicts loaded tools while estimate + reply reserve > window. It stops when the request fits or nothing may be evicted; only then does checkBudget refuse with ErrContextFull. Order: least recently used (the tick of the last load or call), ties to the larger definition, then name. Never evictable: the loader itself (it is not in the loaded set), every tool loaded since BeginTurn, and every tool with a tool_use anywhere in hook 7 (Loop.pinnedTools), which includes the calls of the response currently being answered because the assistant entry is added to hook 7 before runCalls. So eviction cannot meet a pending call. Eviction runs in two places: between requests under pressure (Loop.relieve), and inside load admission (ToolWindow.admit, while a load_tools or not-loaded call of the current batch is answered, so mid-batch). Both exclude the same pinned set: tools called or loaded this turn and this response's own calls. A load that needs room evicts only as many unpinned tools as it takes, and evicts none if that would not make room. It never evicts a tool called or loaded this turn or named by a call of this response.

Consequence: when the tools a turn has already used are the only thing left to shed and the request is still too big, the turn is refused with the ordinary context-full message; it does not evict a tool it just used. There is no idle rule: a tool nobody calls stays loaded until pressure removes it (decided 2026-11-05).

Does NOT mean: eviction touches history or tool_use/tool_result pairing. It changes only the tools block of the sent view; the stored conversation is whole and pairing is by id (da80d551 still holds; TestLoop_PairingHoldsAcrossEvictionAndReload).

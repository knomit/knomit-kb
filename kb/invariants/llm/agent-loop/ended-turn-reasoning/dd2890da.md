# An adaptive request is sent without the reasoning blocks of ended turns (hook 6), the running turn keeps its own, stored history and log turn records stay whole; it is gated on Loop.Window, never on the provider's name, so an Anthropic chat's signed thinking blocks are never dropped

Live acceptance: the last request of a long adaptive chat carried about 11K characters of reasoning from 24 earlier assistant steps. Loop.view now returns Window.DropEndedReasoning(Window.StubEnded(...)): every reasoning block of hook 6 is left out of the sent copy; hook 7 (the running turn) and every other hook are untouched. tool_use and tool_result blocks are never touched, so pairing by id holds (da80d551). An assistant entry that holds only reasoning is left whole (dropping its blocks would send an empty assistant message). The Builder's history is not edited (it stays append-only, 80e22727), the session log's turn records are written from the stored entries and keep the reasoning, and projection.saved_tokens_est counts the saving because it is stored bytes minus sent bytes.

Why it is safe: a Window exists only for a provider whose Caps().StablePrefix is false (ErrWindowWithStablePrefix refuses anything else), and today that is Ollama, whose `thinking` is plain text: Reasoning.Native is {"thinking": text} with no signature (ollama.go renders it back as message.thinking). Anthropic's thinking blocks carry signatures bound to the history before them (80e22727), so they must be replayed as stored; an Anthropic loop has no Window and the drop is never called (TestLoop_StaticRequestKeepsEndedReasoning). The gate is the Window, not a provider-name check.

Does NOT mean reasoning is dropped inside the running turn (the model's own earlier reasoning in that turn is still sent), nor that a future provider with signed reasoning and a Window would be safe: such a provider must set StablePrefix.

# The agent loop never edits the conversation hook: a turn is built in hook 7 and Added to hook 6 when it ends; long chats are measured, warned about once, and refused BEFORE sending, never trimmed

internal/engine/llm/agent.go: RunTurn puts the user text, each assistant reply and each tool_result entry into hook 7 (HookTurn). When the turn ends (answer, cancel, error, call limit) settle flushes: it Removes each entry from hook 7 and Adds it to hook 6, in order, and returns the first Remove/Add failure as the turn error (never swallowed). Nothing calls Builder.Replace or Remove on hook 6 (the Builder refuses with ErrHistoryAppendOnly). Every tool_use has a tool_result before the turn leaves hook 7; if a result entry cannot be recorded (a repeated caller-supplied NewID) the trailing assistant tool_use is removed and the turn ends with that error.

A turn that got no assistant entry is DROPPED from hook 7 whole (hook 6 untouched): refused before its first request, refused or failed on the first request for any reason, truncated with no text, cancelled before any reply. See the refused-turn drop-rule fact. A turn in which tool calls already ran is flushed.

Budget, before each request: est = max(Snapshot.Record() token sum, last response prompt+output + bytes/4 of entries added since); reserve = Caps().MaxOutput, or ContextWindow/4 when MaxOutput <= 0 or >= ContextWindow; refused with ErrContextFull (the model gets no request) when est + reserve > Caps().ContextWindow. The reserve exists because the window covers input and output together (Ollama num_ctx). A model reporting ContextWindow 0 is not pre-checked; the adapter's ErrContextFull then ends the request.

Warning: ONE structured LoopEvent{Kind: LoopWarning, Warning: *PriceWarning{Threshold, PromptTokens, TierTokens, Model, BeforeSend}} per Loop (chat): the first time the pre-send estimate (same est as the budget) OR a response's reported prompt (input + cache read + cache write) reaches PriceCard.WarnTokens; never again, never below the threshold. The loop carries no wording; the chat layer words it. Price cards are injected by the caller; the loop holds no model names or prices.

Cost is ONE exact figure (llm.Cost{USD}): Usage carries CacheWrite5m and CacheWrite1h (Anthropic cache_creation), each priced at its own multiplier; any part of CacheWrite not split is priced at the 5m multiplier. pause_turn continuations count against MaxCalls together with tool calls.

Does NOT mean: hook 7 is append-only too (it is cleared each turn), or that an over-long chat can be shortened by the loop (server-side compaction is deferred work).

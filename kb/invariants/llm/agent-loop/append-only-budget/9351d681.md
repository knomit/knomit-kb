# The agent loop never edits the conversation hook: a turn is built in hook 7 and Added to hook 6 when it ends; long chats are measured, warned about once, and refused BEFORE sending, never trimmed

internal/engine/llm/agent.go: RunTurn puts the user text, each assistant reply and each tool_result entry into hook 7 (HookTurn). When the turn ends (answer, cancel, error, call limit) flush Removes each entry from hook 7 and Adds it to hook 6, in order. Nothing calls Builder.Replace or Remove on hook 6 (the Builder refuses with ErrHistoryAppendOnly). Every tool_use gets a tool_result before the turn leaves hook 7, so a cancelled or failed turn still leaves valid history.

Budget, before each request: need = max(Snapshot.Record() token sum, last response prompt+output + bytes/4 of entries added since) + Caps().MaxOutput; if need > Caps().ContextWindow the turn is refused with ErrContextFull and the model gets no request. MaxOutput is reserved because the window covers input and output together (Ollama num_ctx). A model reporting ContextWindow 0 is not pre-checked; the adapter's ErrContextFull then ends the request. A turn refused before its FIRST request is dropped from hook 7 (hook 6 untouched); one refused later is flushed.

Warning: ONE LoopWarning per Loop (chat), the first time a response's prompt (input + cache read + cache write) reaches PriceCard.WarnTokens; never again, never below the threshold. Price cards are injected by the caller; the loop holds no model names or prices. Cost is two numbers (cache writes at the 5m multiplier, and at the 1h multiplier) because Usage does not split write TTLs.

Does NOT mean: hook 7 is append-only too (it is cleared each turn), or that an over-long chat can be shortened by the loop (server-side compaction is deferred work).

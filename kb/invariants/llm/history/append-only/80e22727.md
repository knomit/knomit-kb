# The neutral chat history is APPEND-ONLY: llm.Builder.Replace and Remove refuse HookConversation items with ErrHistoryAppendOnly, because Claude 5.1+ thinking blocks are bound to the exact system, tools and earlier messages before them

No code may edit, reorder, trim or remove an earlier conversation entry (hook 6), its tool results included. llm.Builder.Replace and llm.Builder.Remove return an error wrapping ErrHistoryAppendOnly for any HookConversation item and leave it in place; Remove now returns error (ErrUnknownItem when the id is absent) instead of bool. Adding to hook 6, and Remove/Replace in the other hooks, still work: moving a finished turn from hook 7 into the history is Remove(hook 7) + Add(hook 6). Pinned by TestBuilder_ConversationIsAppendOnly.

Why (user decision, 2026-11-04; Claude API preserved-thinking docs): on Claude 5.1+ models each thinking block's signature binds the top-level system, the tool set and every earlier message. Clearing or shortening an earlier tool_result, or changing an earlier tool_use input, invalidates every later thinking block; on accounts created on or after 2026-08-31, replaying such a block is a 400 invalid_request_error (older accounts get no error unless they opt in). An edit also misses the prompt cache from that point.

Consequences: (1) long chats are not trimmed client-side; the intended later path is the API's server-side context editing (clear_tool_uses_20250919, beta context-management-2025-06-27) or compaction, which the check does not count as edits. (2) Hooks 1-5 render into system and tools, so changing them mid-conversation is the same edit: the guard covers only hook 6, and hook 5 (working set) must be kept fixed per conversation by its callers. What it does NOT mean: it is not a claim about which edits the API tolerates; the builder offers no edit to hook 6 at all, and nothing here relies on the API accepting any particular one. Adding cache_control markers at render time does not edit an entry, and is not covered by the guard.

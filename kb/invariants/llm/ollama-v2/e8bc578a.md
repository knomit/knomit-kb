# Ollama v2 sends num_ctx and keep_alive on EVERY request, fails the capability probe closed, and treats done_reason length as a StopError (never a success)

Every /api/chat body from OllamaChat carries keep_alive (default 30m) and options.num_ctx (default 32768, also Caps().ContextWindow) plus options.num_predict (-1 unless a MaxOutput is set). Reason: when num_ctx is not sent Ollama runs the model with its own default context and silently drops the oldest messages of a prompt that does not fit, with no error; the API docs say nothing about prompt truncation for chat. The /api/show probe fails CLOSED: any probe error, non-200 or missing "tools" capability returns a usable-looking adapter with Caps().Tools=false and a non-empty UnusableReason(), and Stream refuses without calling /api/chat; it never assumes tool support. done_reason "length" returns a *StopError (Is ErrTruncated) holding the partial Response, no EventDone. Does NOT mean the adapter detects a prompt that silently overflowed num_ctx: nothing here checks that; the pre-request refusal of an over-window request belongs to the loop's context budget (plan PR4 Task 4.2). The v1 /api/show probe in ollama.go is copied, not moved; deleting ollama.go must keep the v2 copy.

# The Ollama adapter sends num_ctx, keep_alive, truncate:false and shift:false on EVERY request, maps llama.cpp's 'exceeds the available context size' 400 to ErrContextFull, fails the capability probe closed, and treats done_reason length as a StopError

Every /api/chat body from OllamaChat carries keep_alive (default 30m), options.num_ctx (the configured value, else one derived at chat open; there is NO 32768 default any more, see kb/decisions/llm/ollama/num-ctx-derivation/d54e62b3.md), options.num_predict (-1 unless a MaxOutput is set), and the top-level fields truncate:false and shift:false. Why truncate:false: ChatRequest.Truncate exists at v0.30.0 and later (api/types.go); when it is unset or true Ollama's chatPrompt drops the oldest messages until the prompt fits num_ctx, with no error (server/prompt.go, server/routes.go truncate := req.Truncate == nil || *req.Truncate, v0.40.14). Sending false keeps the whole conversation in the rendered prompt, so overflow is no longer a silently different conversation. Why shift:false: see the context-shift gotcha (kb/gotchas/llm/ollama/context-shift/60f9f3ed.md): a generation-time overflow ends done_reason length, not a silent KV cut.

What a prompt over num_ctx does with truncate:false, from source (Ollama v0.40.14, which vendors llama.cpp b11963): Ollama's completionPromptForRequest returns the prompt unchanged, so its own promptTooLongMessage 400 ('the prompt is longer than the context length currently available to the model; ...') is NOT reached (it sits after that early return and needs truncate:true with context shift off). The prompt reaches llama-server, which refuses any prompt with n_tokens >= n_ctx at slot start, whether or not context shift is on: it sends 'request (N tokens) exceeds the available context size (M tokens), try increasing it' with ERROR_TYPE_EXCEED_CONTEXT_SIZE (llama.cpp b11963 tools/server/server-context.cpp:4080-4086), which server-common.cpp:125-128 maps to HTTP 400. Ollama forwards it as api.StatusError{400, text}: an HTTP 400 with {"error":"..."} (nothing was streamed yet). Line numbers are dated support for b11963; the version is the claim. The adapter classifies a 400/413 or an error line whose text contains 'available context' (the llama.cpp text, the branch a real Ollama hits) or 'context length' (Ollama's own message, a cheap guard for the truncate:true path) as ErrContextFull (wrapped, so the 'ollama: HTTP 400: ...' text and isRetryable stay intact); PR4 maps ErrContextFull to 'context full'. The test fixture uses the llama.cpp text and was sabotage-checked: deleting the 'available context' alternative fails it. Confirmed live on Ollama 0.40.14, 2026-11-04: HTTP 400 {"error":"request (8024 tokens) exceeds the available context size (2048 tokens), try increasing it"} maps to ErrContextFull.

num_ctx is also capped by Ollama at the model's trained context (server/sched.go effectiveContext, v0.40.14), so Caps().ContextWindow = min(num_ctx, the trained context from /api/show model_info[<arch>.context_length]) when reported, else num_ctx; and num_ctx covers input plus output, so PR4 must reserve output room. The /api/show probe fails CLOSED: any probe error, non-200 or missing tools capability returns a usable-looking adapter with Caps().Tools=false and a non-empty UnusableReason(), and Stream refuses without calling /api/chat. done_reason length returns a *StopError (Is ErrTruncated) holding the partial Response, no EventDone. Does NOT mean the adapter checks a prompt's size before sending: the pre-request budget belongs to the loop (plan PR4 Task 4.2). Does NOT mean shift:false prevents prompt-too-long 400s: those are ErrContextFull. The /api/show probe was copied from the deleted earlier adapter; ollama.go (formerly ollama_v2.go) now holds the only probe.

Confirmed live on Ollama 0.40.14, 2026-11-04 (OllamaChat.Stream at dev 014ca530, models qwen35 and lfm2): every request carried keep_alive "30m", num_ctx, shift:false and truncate:false; done_reason "length" gave a StopError that Is ErrTruncated; the probe failed closed on a 404 model; and Caps().ContextWindow = min(num_ctx, trained length).

Consequence: with a thinking model, an overrun can spend the whole budget on reasoning, so the StopError partial then holds only a reasoning block and no text. Callers must not assume the partial text is non-empty.

# Ollama v2 sends num_ctx, keep_alive and truncate:false on EVERY request, maps a prompt-over-context refusal to ErrContextFull, fails the capability probe closed, and treats done_reason length as a StopError

Every /api/chat body from OllamaChat carries keep_alive (default 30m), options.num_ctx (default 32768), options.num_predict (-1 unless a MaxOutput is set) and truncate:false. Why truncate:false: ChatRequest.Truncate exists at v0.30.0 and later (api/types.go); when it is unset or true Ollama's chatPrompt drops the oldest messages until the prompt fits num_ctx, with no error (server/prompt.go, server/routes.go truncate := req.Truncate == nil || *req.Truncate, v0.40.14). Sending false keeps the whole conversation in the rendered prompt, so overflow is no longer a silently different conversation. The API docs say nothing about this; the source does. What happens to an over-long prompt then: Ollama v0.40.14's own refusal is a 400 StatusError 'the prompt is longer than the context length currently available to the model; ...' (llm/llama_server.go promptTooLongMessage), delivered as an HTTP status with {"error":"..."} or, once output has started, as an {"error":...} line. The adapter classifies a 400/413 or an error line whose text mentions 'context length' or 'available context' as ErrContextFull (wrapped, so the 'ollama: HTTP 400: ...' text and isRetryable stay intact); PR4 maps ErrContextFull to 'context full'. NOT verified live: that every Ollama setup turns a too-long truncate:false prompt into that error rather than letting llama-server handle it (in v0.40.14 the 400 above is produced on the truncate path with context shift off; completionPromptForRequest returns the prompt unchanged when Truncate is false). Treat truncate:false as 'Ollama no longer drops history itself', not as proof of a refusal. num_ctx is also capped by Ollama at the model's trained context (server/sched.go effectiveContext, v0.40.14), so Caps().ContextWindow = min(num_ctx, the trained context from /api/show model_info[<arch>.context_length]) when reported, else num_ctx; and num_ctx covers input plus output, so PR4 must reserve output room. The /api/show probe fails CLOSED: any probe error, non-200 or missing tools capability returns a usable-looking adapter with Caps().Tools=false and a non-empty UnusableReason(), and Stream refuses without calling /api/chat. done_reason length returns a *StopError (Is ErrTruncated) holding the partial Response, no EventDone. Does NOT mean the adapter checks a prompt's size before sending: the pre-request budget belongs to the loop (plan PR4 Task 4.2). The v1 /api/show probe in ollama.go is copied, not moved; deleting ollama.go must keep the v2 copy.

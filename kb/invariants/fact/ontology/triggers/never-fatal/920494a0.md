# A trigger problem is NEVER fatal to the ontology: every problem is a WARNING, the trigger is recorded `invalid` with its error and a name@blob key, and its NAME stays declared so its bookmark freezes

Ontology `triggers:` (F07) are parsed by `TriggerList.UnmarshalYAML` (internal/fact/triggers.go), which NEVER returns an error, and validated by `CompileTriggers`/`triggerDiags`, which emit only `SeverityWarning`.

WHY: an error-severity Diagnostic fails `ParseOntology`; `repos/builder.go loadOntology` then sets `ontologyErr`, and the repo opens with NO ontology and refuses every write. A trigger that is merely absent loses nothing (in the 1b dispatcher its bookmark freezes and it catches up once fixed), whereas a fatal one would stop writes on every machine that pulls the typo. User rulings, 2026-09-27: D-a "yes" (warning and drop, not a fatal ontology), and "invalid / malformed triggers and recipes should be skipped and at least logged as errors". The ERROR log line (once per repo, name and blob) belongs to the dispatcher, which knows the repo; internal/fact has no logger.

THE TRAP THIS AVOIDS: decoding `triggers:` straight into typed struct fields makes go-yaml raise a TypeError for `on: 5` or `triggers: foo`, which `ValidateOntologyYAML` turns into a FATAL parse diagnostic via `parseErrDiags`. So the list keeps each entry as `Raw map[string]any` plus the original yaml node, and reads the typed fields leniently.

WHAT A CONSUMER MUST DO:
- Read `TriggerSet.States` (`active` | `invalid`, error verbatim, `Key` = name@<ontology blob>) and `TriggerSet.Declared`.
- Delete a trigger's bookmark ONLY when its NAME is absent from `Declared`. `decodeTriggerSpec` reads `name` before any other check, so an entry with an unknown key or a bad value is still declared.
- `do: script|push|run` are KNOWN but inactive in this version: `invalid` with "not active in this knomit version", so they freeze and do not run. An UNKNOWN `do`/`on`/key is also `invalid`.

MISREADING: "warning" does not mean "runs anyway". An invalid trigger never runs, and no stale compiled program stands in for it.

Pinned by TestTriggers_OneBadTriggerSiblingsStillActive and TestTriggers_MalformedNeverFatal (17 malformed shapes). Sabotages that make any trigger diagnostic error-severity, or make the non-list case return an error, fail them.

# All times are UTC (maintainer ruling 2026-09-28, 'all times MUST BE UTC - expire, due, everything'): SerializeFact normalises `expires` to the same instant in UTC with an explicit Z at whole seconds, the REST PUT (the one path that commits the client's bytes) forces the rewrite when the offset differs, the index stores Unix seconds, the dispatcher's clock is time.Now().UTC() once per run, and every F07 timestamp rendered (fired_at) is RFC 3339 with a Z — no local-time formatting anywhere in F03/F07

F07 PR 2 (ruling 5). What changed from F03's 'kept as written (offset and all)':
- WRITE: fact.NormalizeExpires(s) parses RFC 3339 and returns t.UTC().Truncate(time.Second).Format(time.RFC3339); SerializeFact calls it after validation, so knomit_learn, knomit_update, synthesize and the REST POST (all through SerializeFact) store `2026-10-01T02:00:00+02:00` as `2026-10-01T00:00:00Z`. Sub-second input is truncated to the second, the granularity every comparison uses. The REST PUT commits the client's bytes verbatim unless a gate changed something; an `expires` whose normalised form differs is now such a change (expiresChanged) and forces the SerializeFact rewrite.
- READ: ParseFact stays lenient and keeps what a file says (an older fact written with an offset by a pre-PR-2 build still parses and indexes to the same instant); it is rewritten to Z the next time it is serialized (an update, replay's dead-ref repair). fact_expires.expires therefore holds Z for anything this build wrote, and F03's reads return the stored string.
- INDEX: expires_at is Unix seconds (an instant; UTC by definition); the sweep compares `expires_at <= now.Unix()` with `<=`.
- CLOCK: the dispatcher reads its clock ONCE per run as time.Now().UTC().Truncate(time.Second) (the `now` test hook replaces it); the due marks' fired_at is that instant; trigger_fires.fired_at is time.Now().UTC().Unix() at flush.
- RENDER: TriggerFire.FiredAt is a string, store.UTCStamp(unix) = time.Unix(n,0).UTC().Format(time.RFC3339), so GET …/triggers shows `2026-09-28T12:34:56Z` whatever the process's TZ; the OpenAPI field is date-time and no longer says 'Local Unix seconds'. The SSE `trigger` event carries no timestamp; the web UI renders no F07 timestamp yet (nothing to fix there); the statistics are durations.

What this does NOT mean: it does not reject offsets — an offset is accepted and converted; it does not rewrite files nobody touches; it does not change expires_at values already indexed (same instant).

Tests: TestExpires_RoundTrip (fact, offset → Z, byte-stable re-serialization), TestExpires_ParseKeepsAnOlderOffset, TestSearch_ResultsCarryExpiresAsWritten (store, now the Z form), TestREST_WritesValidateExpires (PUT with +02:00 stored as Z), the mcp expires test, TestTriggerFires_FiredAtIsUTCWithZ (store; identical rendering under time.Local = UTC and America/New_York), TestDue_UTCEverywhere (repos; the whole due scenario under both zones yields identical stored values). The reviewer runs the suite with TZ=America/New_York.

Two stamps to tell apart, both UTC Unix seconds: the fire-log row's fired_at is the FLUSH time (tx1, write-behind), the due mark's fired_at is the RUN clock. Merged to dev in #337 (merge commit 5e303652); refs pinned there.

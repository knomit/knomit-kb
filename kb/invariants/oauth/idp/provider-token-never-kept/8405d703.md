# The provider's access token lives only inside idp.GitHub.Identify — exchange (secret and PKCE verifier in the POST body), ONE /user lookup, best-effort revoke, return the subject — and is never stored, logged, returned or echoed; an unasked refresh_token is never even decoded

knomit is an OAuth CLIENT of GitHub for one purpose: learn which account is at the browser (F19 phase 3c). The Provider interface makes exchange + lookup + revoke ONE call, Identify(ctx, code, verifier, redirectURI) → Subject{ID: github-<id>, Login}, so the token cannot leak through the flow code — it is a local variable of Identify.

RULES, each with a test in internal/oauth/idp/github_test.go against the in-process fake (idptest):
- PKCE S256 AND the client secret (GitHub supports S256, refuses plain, and still requires the secret). code, code_verifier, client_secret and redirect_uri go in the form BODY, never the URL (the fake refuses a query string; *url.Error prints URLs).
- Accept: application/json. GitHub reports a refused code as HTTP 200 with an error field: error present or access_token absent → ErrProviderRefused, named by the error code only, strconv-quoted and capped at 64 bytes; error_description and error_uri are not decoded.
- Apps with expiring tokens get a refresh_token unasked: the response struct has no field for it, so it is dropped at decode.
- Scope is EMPTY: /user returns the public profile, id included, to a token with no scope.
- Subject = github-<id> where id is a positive JSON INTEGER (a string, float, zero, negative or absent id is ErrProviderRefused); never derived from the login.
- After the lookup, DELETE /applications/{client_id}/token with basic auth id:secret; a failure is a WARN with the status only and the identity still stands.
- Outbound client: its own http.Client (NOT the CIMD fetcher, whose SSRF guard refuses the 127.0.0.1 fake and which guards a requester-chosen URL): no redirects, 64 KiB cap refused not truncated, JSON Content-Type required, 10 s per call, HTTPS_PROXY honoured (hosts are pinned in code: github.com and api.github.com; ruling W5).

MISREADING TO AVOID: 'we revoke the token' is best-effort, not a guarantee — a network failure leaves a scope-less token alive at GitHub until the user or GitHub expires it. What IS guaranteed is that knomit keeps no copy.

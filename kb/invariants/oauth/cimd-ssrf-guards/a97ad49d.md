# A Client ID Metadata Document is fetched ONLY from an https URL whose host resolves ENTIRELY outside the forbidden ranges, dialled at the address that was checked with a re-check in Dialer.Control, no proxy, no redirects, verified TLS, 64 KiB, one 5 s deadline, JSON — each guard has its own test that fails when that guard alone is removed

With CIMD the client_id IS a URL the requester chooses, so the authorization server fetching it is an SSRF target (kb://bc6eac5f37df/kb/gotchas/ai/agents/tools/mcp/security/ssrf/59a75c06.md). oauth.cimdFetcher refuses in this order: not https / no path / userinfo, query or fragment (isCIMDURL, before ANY network); ANY resolved address in loopback, private (10/8, 172.16/12, 192.168/16), CGNAT 100.64/10, 0/8, link-local (169.254/16 incl. the cloud metadata address, fe80::/10), ULA fc00::/7, multicast or unspecified (IPv4-mapped IPv6 judged as its IPv4 — net.IPNet.Contains converts); then it dials ips[0] (never re-resolving the name) and Dialer.Control re-checks the address actually connected to. Transport: Proxy nil, CheckRedirect refuses, TLS with system roots and ServerName from the URL's NAME, body read through LimitReader(64 KiB + 1) and refused (not truncated) when over, Content-Type must be JSON, and ONE context deadline (5 s) covers DNS, connect, TLS, headers and body — there are no per-phase timeouts beside it because they were redundant.

AMPLIFICATION BOUND (phase 3b, 3a review N1): /oauth/authorize is public and resolves the client BEFORE the pending cap applies, so Resolver bounds the fetches it causes: concurrent resolutions of the SAME client_id share one fetch (singleflight, run detached from any one caller's cancellation so a browser that gives up cannot fail the others, and bounded by the 5 s fetch timeout, which also bounds the wait for a slot), and at most maxCIMDFetches (4) fetches are in flight across ALL ids. Tests: TestResolver_BoundsConcurrentFetches (peak exactly 4), TestResolver_SameIDSharesOneFetch (10 callers, 1 fetch), TestResolver_SharedFetchSurvivesACancelledCaller — each fails when its mechanism alone is removed.

NO PROXY, TESTED (3b, N2): TestResolver_IgnoresProxyEnvironment re-executes the test binary with HTTPS_PROXY/HTTP_PROXY set before anything reads them (http.ProxyFromEnvironment caches the environment once per process) and asserts the fetch SUCCEEDS and the proxy sees no connection. Note what the sabotage looks like: with Proxy: http.ProxyFromEnvironment the pinned DialContext still dials the metadata server, which receives a CONNECT and the fetch fails — the proxy is never reached either way, so 'no proxy connection' alone could not tell the guard's presence from its absence; 'and the fetch succeeds' does.

The document must name client_id equal to the fetched URL, carry redirect_uris, and be a public client (token_endpoint_auth_method absent or none). It is cached for its Cache-Control max-age capped at ONE HOUR (no-store/no-cache or no max-age = not cached), at most 256 entries. Resolution order: a pre-registered [[oauth.client]] (including the built-in kb) wins even when its id is itself a CIMD URL; then CIMD; else invalid_client. There is no DCR (kb/decisions/oauth/no-dynamic-client-registration). Claude Code's live document (https://claude.ai/oauth/claude-code-client-metadata, max-age=300) is TestResolver_ClaudeCodeCIMDAcceptsItsLocalhostRedirect's fixture.

TESTABILITY CONSEQUENCE: the resolve-time check and the dial-time check refuse with DIFFERENT sentinel errors (errResolvedForbidden vs errDialForbidden) precisely so a test can tell which guard refused — with one error, removing either guard alone would stay green because the other still refuses. lookup, allow and roots are fields only for tests; production uses newCIMDFetcher's values.

MISREADING TO AVOID: a verified CIMD proves the requester controls the client's DOMAIN, not that the process on the user's machine is that client (any local program can present the id with a loopback redirect). It is not consent; the operator's approval is.

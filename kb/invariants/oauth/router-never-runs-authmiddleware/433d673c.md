# The OAuth router NEVER runs AuthMiddleware — NewAPIRouter is apiRouter(edge, grants) and the OAuth listener passes BearerMiddleware + Require(read) as the edge — because for a loopback peer AuthMiddleware REPLACES the token principal with anonymous@none, and a test from httptest's 192.0.2.1 cannot see it

NewAPIRouter used to hard-code r.Use(AuthMiddleware(...)). Reusing it under the bearer middleware would run AuthMiddleware SECOND: for a loopback peer (a same-host reverse proxy) with require = false it attaches anonymous@none — overwriting the token principal — and anonymous holds loopback_default, admin included. For a NON-loopback peer AuthMiddleware's last step passes the request on untouched, so the token principal survives and every test built with httptest.NewRequest's default RemoteAddr (192.0.2.1) stays green while the real deployment is wide open. The split: s.apiRouter(edge, g) is the tree; NewAPIRouter() = apiRouter(AuthMiddleware(s.Auth, s.authDisabled), s.grants()), byte-for-byte the old behaviour; OAuthHandler passes edge = BearerMiddleware then Require(g, read) and g = auth.TokenGrants{Inner: s.Grants} — no loopbackGrants, no CertGrants, since nobody there is anonymous or holds a certificate.

CONSEQUENCES a consumer acts on:
- The regression test for this MUST use a LOOPBACK RemoteAddr (rpcAt / fromLoopback) with require = false and the default loopback set, and assert the TOKEN principal survives (a read-ceiling token is not offered knomit_learn; a mutation is refused naming host:<subject>@token). Removing the split makes exactly that test fail.
- Anything added to the OAuth listener goes through apiRouter's edge or the public issuer routes, never through Handler() or AuthMiddleware.
- A bad bearer never falls through to anything: there is no anonymous principal on that listener to fall to.
- READ IS REQUIRED there (R6), unlike the plain listener where nothing gates read: a token whose grants ∩ ceiling lacks read is 403 on every API and MCP route.
- The ceiling rides the request context (auth.WithCeiling). auth.TokenGrants gives a token principal with NO ceiling on the context nothing, and is also composed in Server.grants() (loopbackGrants{CertGrants{TokenGrants{store}}}), which the shared MCP handler's tool filter and gate consult — at mcp-go v0.45.0 the tool-call context derives from r.Context(), so the ceiling arrives there.
- A ceiling narrows, never widens: rows without write stay without write whatever the token was approved for.

AUDIENCE, judged by oauth.Verifier on the path the listener sees, has TWO halves and both are required: (1) the token's resource must be under the CURRENT issuer (oauth.resourceUnder) — a token minted for https://host is not valid once the issuer is https://host/knomit, although every request URL there extends the bare origin (found by TestOAuthListener_IssuerWithPath; pinned by TestVerifier_IssuerGainedAPath); (2) issuer + path must equal the token's resource or extend it at a '/' boundary (/api/v1/repos/work/.../mcp does not cover /api/v1/repos/workshop/...). The path must be canonical first — no '..', no '//', no encoded '/' (chi routes on RawPath, so %2F is one segment to the router and two to a decoded check) — else 400.

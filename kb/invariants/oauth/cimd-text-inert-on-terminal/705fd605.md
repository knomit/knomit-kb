# Nothing from a Client ID Metadata Document reaches a terminal unescaped: a client_name with a control or format character (or over 100 runes) and a non-printable-ASCII redirect URI are refused at INGEST, and `knomit oauth pending` additionally prints every field %q-quoted

`knomit oauth pending` is the ONLY consent screen in 3a, and the operator judges a request by what it shows: client name and id, requester address and user agent, redirect URI, scopes, resource. A CIMD client_name is free text from an attacker-hosted JSON document; review B2 reproduced a name containing ESC[8m (conceal) that hid the real client id, redirect and resource lines, leaving only a trusted-looking name visible (the general rule: kb://bc6eac5f37df/kb/invariants/ai/agents/security/output-handling/9e5bfe91.md).

INGEST (internal/oauth/client.go): a CIMD is refused whole, with errUnsafeClientMetadata, when client_name is not valid UTF-8, contains any rune for which unicode.IsPrint is false (every Cc control incl. ESC, CR, LF, TAB; every Cf format char incl. the bidi overrides U+202E etc.; any whitespace but the ASCII space), or exceeds maxClientNameRunes (100); or when any redirect_uri is not printable ASCII (0x21–0x7e). A CIMD client_id (isCIMDURL) and any resource (resourceUnder) must also be printable ASCII. Only what passed is stored. Printable non-ASCII names (accents, CJK) pass.

RENDER (cmd/oauth.go): every displayed field is printed with %q, so even a pre-registered name from knomit.toml (never checked at ingest) or a User-Agent carrying a UTF-8 bidi override (Go's server refuses control bytes in headers but NOT Cf characters) comes out escaped. Both layers are required: ingest keeps stored data clean; quoting keeps a field added later from regressing. TestOAuthCLI_PendingDisplayIsInert asserts on the output bytes (no raw 0x1b or U+202E, escaped forms present).

IT COVERS EVERY BYTE THE CLI RECEIVES FROM AN ISSUER, NOT ONLY CIMD FIELDS (phase 3b, review B1): `knomit oauth approve|deny --sign` and `approve --signed` talk to an issuer whose URL reached the operator from whoever relayed the request, or that a --signed blob names in its UNSIGNED issuer field — so response bodies (in errors, which cobra prints to stderr), the issuer URL itself, the description's fields and the decision and id printed on success are all %q-quoted (cmd/oauth_sign.go fromIssuer, which also caps a body at 512 bytes), and the success line names the URL it posted to. The local server's problem detail and the approve summary in cmd/oauth.go are quoted the same way. Tests: TestOAuthSign_IssuerErrorBodyIsEscaped, TestOAuthSigned_IssuerErrorBodyIsEscaped, TestOAuthSigned_SuccessOutputIsEscapedAndNamesTheIssuer (all red at 71cf5353), TestOAuthSign_PrintoutIsEscaped. The rule for any new print site: if the bytes came off the network, they reach the terminal through %q.

MISREADING TO AVOID: the waiting page and logs are not the risk here — html/template escapes the page and zerolog JSON-escapes log fields; the terminal is. And 'the description was escaped' did not make the command safe: the gap B1 found was the ERROR paths.

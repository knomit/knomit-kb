# OAuth approvals are accepted ONLY from a local-listener principal (Via == auth.LocalVia: the unix socket, or the named pipe on Windows) — not the anonymous loopback principal, which holds admin by default, not a bearer, not a certificate even with an admin row — and only on the plain router

GET /api/v1/oauth/pending, POST …/{id}/approve and …/{id}/deny exist only when [oauth] is configured, only on the PLAIN router (NewAPIRouter adds them after apiRouter; the OAuth listener's router never has them), behind web.RequireLocalVia, which admits a principal only when p.Via == auth.LocalVia (ViaSocket on unix, ViaPipe on Windows) — NOT Require(admin) (master ruling R5). writeGate still runs first, so the local principal also needs write (the boot seed gives the server's own account the full loopback_default set).

WHY: the anonymous loopback principal holds admin by default ([auth].loopback_default), and a browser page can reach loopback TCP but not the socket — so any 'admin' gate would let a page the operator visits approve a request (CSRF), and a same-host proxy would be loopback too. The socket is the credential.

CLI: `knomit oauth pending|approve <id> --as <subject> [--scopes …]|deny <id>` talk to the running server through localAPIClient, which dials auth.DialLocal(cfg.Socket) and NOTHING ELSE — no TCP fallback, since over TCP the server cannot tell who is asking and refuses. That is unlike `knomit grants`, which opens control.db directly: approvals must wake the browser's /wait long-poll inside the server process. Approvals record granted_by / decided_by = the local principal's String().

TESTING CONSEQUENCE: an 'anonymous is refused' test cannot tell this gate from an 'ID must be non-empty' check — anonymous has no id. TestPendingAPI_OnlyLocalPrincipals also drives an OPERATOR CERTIFICATE holding admin by row (a verified principal with an id), which is what makes RequireLocalVia's Via test falsifiable. The 3b web-UI panel must bring its own CSRF story (a local principal plus a same-origin token); it cannot reuse this gate from a browser.

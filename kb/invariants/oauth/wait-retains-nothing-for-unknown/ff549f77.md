# The public /oauth/authorize/{id}/wait retains NOTHING for an id nobody parked: shape check first, store lookup BEFORE any waiter is registered, one refcounted entry per known undecided request released when each wait returns — no pruning scan

Review B1 reproduced: /wait used to register a waiter-map entry for ANY id before looking it up, and a 404 never removed it; entries lived 10 min and the id length was attacker-chosen (Go's 1 MiB default header limit), so 200 unauthenticated requests pinned ~101 MiB and past 200 entries every call scanned the map under the mutex. maxLivePending (100) did not help: it counts pending ROWS, not waiters.

NOW (internal/oauth/issuer.go): (1) an id that is not the pending-id shape (43 base64url chars, pendingIDRE) is a 404 before the store or the map is touched — with lookup-first this no longer changes the map property; it spares the store a lookup on an attacker-sized key; (2) GetPending FIRST, and only a known, undecided, unexpired request registers; (3) waiters.wait returns (ch, release): each parked wait holds a reference and releases it on return, the entry is deleted at zero, notify closes and deletes it — every operation O(1), nothing to prune; (4) after registering, the handler RE-READS once, because a decision made between the first read and the registration notified nobody (tested through the test-only beforeRegister hook; without the re-read the browser waits out the 30 s window).

CONSEQUENCE: the waiter map's size is bounded by concurrent connections to real undecided requests, not by what strangers send. Tests: TestWait_UnknownIDsLeaveNoWaiter (unknown ids of both shapes leave len 0), TestWait_KnownIDOneEntryRemovedAfter (exactly one entry while parked; zero after a decision, a closed window, an expired request), TestWait_DecisionBetweenReadAndRegisterIsSeen.

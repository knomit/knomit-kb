# /oauth/authorize answers a PAGE, never a redirect, until client_id and redirect_uri have validated; after that every error goes to the redirect_uri with state and iss — and PKCE S256, a resource under the issuer, and permission-name scopes (no admin) are mandatory

ORDER in Issuer.authorize: resolve client_id, then check redirect_uri against it. Any failure there is a 400 HTML page: redirecting to an unvalidated URI would make the issuer an open redirector. Only then do errors travel to the redirect_uri, ALWAYS with iss = the issuer (RFC 9207 — MCP's mix-up defence fails open without it; kb://bc6eac5f37df/kb/invariants/ai/agents/tools/mcp/security/authorization/mix-up/bdb36fce.md) and with state when the client sent exactly one. A repeated parameter is invalid_request (a repeated OPTIONAL one must not be silently dropped and the request parked as if it had not been sent); a repeated client_id or redirect_uri reads as empty and is refused as a page.

REDIRECT MATCHING (Client.RedirectAllowed): exact string, except that a registered http://127.0.0.1/…, http://[::1]/… or http://localhost/… accepts any port (RFC 8252 §7.3), with scheme, host spelling, path and query still exact. The host must be the SAME spelling on both sides: a 127.0.0.1 registration never accepts a localhost redirect, nor the reverse. Only those three exact hosts are loopback (isLoopbackHost): localhost., LOCALHOST, sub.localhost and localhost.evil.example are ordinary hosts that match only exactly.

WHY localhost (phase 3b ruling R1, 2026-09-24, reversing 3a's 'localhost is NOT a port wildcard'): Claude Code 2.1.281's Client ID Metadata Document (https://claude.ai/oauth/claude-code-client-metadata) registers http://localhost/callback and http://127.0.0.1/callback and then SENDS http://localhost:<random>/callback, so 3a answered every Claude Code login with a 400 'redirect_uri is not registered'. RFC 8252 §8.3 only prefers the literal; the added risk is nil in practice because the code is PKCE-bound (a re-pointed name receives a code it cannot redeem) and local-process impersonation is identical for every loopback spelling (kb://bc6eac5f37df/kb/gotchas/ai/agents/tools/mcp/security/client-identity/066a9dad.md).

MISREADING TO AVOID: 'localhost is loopback now' does not mean any name resolving to 127.0.0.1 is; the rule is a string comparison on the registered host, never a DNS lookup. And the lookalike check lives on the REGISTERED host: a lookalike REDIRECT is already refused by the same-host comparison, so only TestClient_RedirectAllowed_LocalhostAnyPort's lookalike-registration block can catch a widened isLoopbackHost.

REQUIRED: response_type=code; code_challenge_method=S256 (absent or plain refused — OAuth 2.1 would default absent to plain); a 43-char base64url challenge; resource that is the issuer or a canonical URL under it (resourceUnder: printable ASCII only — since the review-B2 fix, so a resource is always inert on the consent screen — issuer origin byte-for-byte, no userinfo/query/fragment/escapes/'..'/'//', not a bare trailing '/', path at a '/' boundary under the issuer path — a same-length foreign host such as 127.0.0.2 for 127.0.0.1 is refused); every scope in ScopesSupported (read, write, push:own, merge:main, operator — admin is never grantable to a token). Absent resource is invalid_target, not defaulted.

TOKEN ENDPOINT: the code is SPENT before client_id, redirect_uri, the S256 verifier (43–128 unreserved chars, constant-time compare) and resource are checked, so a failed exchange burns it and a verifier cannot be guessed at; a spent code presented again revokes its family. Refresh checks client, resource (absent = the family's; different = invalid_target) and scope (subset of the family's ceiling, never wider) BEFORE rotating. Responses carry Cache-Control: no-store.

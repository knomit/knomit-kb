# [oauth].issuer has ONE spelling, fixed by config.NormalizeIssuer at Load — https (http only on localhost/127.0.0.1/[::1]), no userinfo/query/fragment, canonical path, no trailing slash — and issuer and addr are one switch: both set or both empty

The issuer is the `iss` a client checks (RFC 9207), the `issuer` both discovery documents must carry exactly, the base of every endpoint URL, and the root every token's audience must sit under — all byte-for-byte comparisons. So it is normalised ONCE, in config.Load, before Validate, and everything downstream uses cfg.OAuth.Issuer verbatim: scheme and host lower-cased, trailing slash removed, path already canonical (path.Clean-stable). Validate re-applies the rules and ALSO refuses a non-normalised value, so a Config built in code (tests, future callers) cannot smuggle in a second spelling.

http is allowed only when the HOSTNAME is localhost, 127.0.0.1 or ::1 — never a LAN address and never a name that merely starts with localhost. Anything else must be https.

`[oauth].issuer` and `[oauth].addr` must be set together: an issuer with no listener advertises endpoints nothing serves, and a listener with no issuer has no audience. Both empty is the default and means OAuth is OFF.

CLIENTS: EffectiveClients = configured `[[oauth.client]]` plus the built-in `kb` client (redirects http://127.0.0.1/callback and http://[::1]/callback, port ignored per RFC 8252 §7.3) unless `default_client = false` or a configured client already uses id `kb`, which REPLACES the built-in rather than duplicating it.

MISREADING TO AVOID: an issuer WITH a path (https://host/knomit) is allowed, but it does not mean knomit mounts its routes under /knomit. The reverse proxy strips that prefix. The discovery documents live at the RFC 8414 / 9728 INSERTED locations (/.well-known/oauth-authorization-server/knomit, /.well-known/oauth-protected-resource/knomit/...), which do not start with /knomit and must be forwarded UNSTRIPPED; oauth.WellKnown answers 404 at the origin-root documents for such an issuer.

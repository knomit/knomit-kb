# Every transport becomes an auth.Principal at the EDGE and auth.Allowed is the only permission check — default deny on a zero principal, an unknown principal AND a store error alike

A request's identity is decided ONCE, at the edge, and never re-derived downstream. `AuthMiddleware` in internal/edge/web/auth_middleware.go (earlier internal/web) turns a transport into an `auth.Principal` and puts it on the context (on the OAuth listener `BearerMiddleware` does, and AuthMiddleware never runs there); `auth.Allowed(ctx, grants, principal, perm)` in internal/foundation/auth/permission.go (earlier internal/auth) is the ONLY function that answers whether it may do a thing. Its enforcement points — `writeGate` on mutating HTTP routes, `gatePermission` on MCP write tools, `Require(read)` over the whole OAuth API tree (oauth_router.go), and `requireOperator` (readonly.go) on the routes router.go mounts it on (branch merge) — all consult the SAME `auth.Grants` value, built once per `Handler()` by `Server.grants()`, so they cannot come to disagree about what anonymous holds.

DEFAULT DENY, and the compound condition matters: `Allowed` returns false for a ZERO principal, for a principal with no grants row, for a nil Grants, AND for a grants STORE ERROR. The last one is the one that gets designed away — a database that is down must refuse, not fall open, and the error is deliberately not returned because no caller could do anything with it but refuse anyway.

CONSEQUENCE a consumer must act on: a new mutating surface is NOT protected by existing code. It is protected only if it sits behind one of the two enforcement points. `writeGate` covers the API router and, separately, the `/git` mount on the outer router; anything mounted elsewhere in `Handler()` is ungated and adding it there is a silent hole.

THE MISREADING TO AVOID: this does not say every permission is enforced. Six permissions exist as constants and as grants rows — read, write, push:own, merge:main, operator, admin. In phase 1 only `write` had an enforcement point; since then `read` is required on the OAuth listener (and only there: a plain-listener request has already passed the transport boundary) and `operator` gates branch merges. Reading a permission's presence in the vocabulary as protection would still be wrong: check that an enforcement point names it.

REACH IS THE SECOND DIMENSION, not a permission (PR #675, extended by fix/mcp-token-audience): `auth.ReachesRepo` / `auth.ReachesLens` (internal/foundation/auth/tokengrants.go) say WHICH repos and lenses a credential may address, recorded ONCE at the same edges (AuthMiddleware: all; BearerMiddleware: from the token's audience) and DEFAULT-DENY exactly like Allowed. A caller needs both: the permission for the act and the reach for the target. See kb/invariants/materialize/cross-kb/caller-reach/89b26b07.md.

`ParseSet` rejects an unknown permission name as an ERROR rather than dropping it, so a typo in `[auth].loopback_default` fails at wiring time instead of silently granting less than the operator wrote — or, after a future rename, more.

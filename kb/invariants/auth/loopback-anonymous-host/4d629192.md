# A loopback TCP peer becomes anonymous@none ONLY when its Host header names this machine — absent, localhost, any IP literal, the effective bind host, or an [auth].loopback_hosts name; any other DNS name is refused with 421 before a principal exists, because that is what a DNS-rebound web page sends

RULE: in AuthMiddleware's anonymous branch (`!cfg.Require && isLoopback(r.RemoteAddr)`), the request is refused with 421 "Misdirected Request" unless `loopbackHostOK(r.Host, cfg.LoopbackHosts)` holds. loopbackHostOK admits:
- an absent Host (HTTP/1.0);
- `localhost`, compared case-insensitively;
- ANY IP literal, bracketed or not. DNS rebinding needs a name the attacker answers DNS for, so an IP-literal Host cannot come from it;
- a name in the list, which must already be lower-cased.

It compares the NAME, never the port: vite's dev proxy forwards `Host: localhost:5173` to 19278. Matches are exact, so `localhost.attacker.example`, `app.localhost`, `127.0.0.1.nip.io` and `localhost.` are all refused.

WHY: a DNS-rebound page connects to 127.0.0.1, so before #281 it WAS anonymous@none. With the default loopback_default that meant every read, fact writes, git receive-pack, and MCP write tools. Plain-listener reads are not permission-gated at all, so even `loopback_default = []` leaked every fact.

WHERE THE LIST COMES FROM: `app.New` sets `Server.Auth.LoopbackHosts = cfg.Auth.EffectiveLoopbackHosts(cfg.Host)`. That is the configured names lower-cased, plus cfg.Host when it is a DNS name (a wildcard or IP bind adds nothing). It MUST be computed there, from the post-override cfg.Host, and never at config.Load: `knomit serve --host` is applied after Load (cmd/serve.go). TestApp_BindHostIsALoopbackHost's --host case exists to catch that.

SCOPE: only the anonymous branch.
- A socket/pipe peer returns earlier; `knomit oauth` sends `Host: knomit.local`.
- The TLS listener returns earlier.
- The OAuth listener never runs AuthMiddleware. A same-host TLS proxy delivers the public issuer host from loopback there, and must keep working.
- A non-loopback peer never gets a principal, so its Host is irrelevant.
- With `require = true` the branch is never entered.

MISREADINGS:
- (1) This is not CSRF protection. A cross-site simple POST sent to http://127.0.0.1:19278 carries a legitimate Host and still runs as anonymous (#287).
- (2) The 3b approval gate's ownHost is a STRICTER, separate check (three spellings + arrival port + Origin). Do not replace one with the other.
- (3) Test fixtures: httptest.NewRequest's default Host `example.com` is a foreign name. A loopback-RemoteAddr test without `Host: localhost` now gets 421, and an assertion of `!= 403` passes vacuously. fromLoopback sets it.

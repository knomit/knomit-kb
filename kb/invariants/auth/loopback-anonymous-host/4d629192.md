# A loopback TCP peer becomes anonymous@none ONLY when its Host names this machine (absent, localhost, any IP literal, the effective bind host, or an [auth].loopback_hosts name; else 421) AND, on any method but GET/HEAD/OPTIONS, it carries no Origin or an Origin equal to http(s)://<Host> or in the CORS allowlist (else 403 "Cross-origin request refused")

RULE: in AuthMiddleware's anonymous branch (`!cfg.Require && isLoopback(r.RemoteAddr)`), two checks run, in this order, before anonymous@none is minted.

1. HOST (#281), 421 "Misdirected Request" unless `loopbackHostOK(r.Host, cfg.LoopbackHosts)`. It admits:
- an absent Host (HTTP/1.0);
- `localhost`, compared case-insensitively;
- ANY IP literal, bracketed or not. DNS rebinding needs a name the attacker answers DNS for, so an IP-literal Host cannot come from it;
- a name in the list, which must already be lower-cased.
It compares the NAME, never the port: vite's dev proxy forwards `Host: localhost:5173` to 19278. Matches are exact, so `localhost.attacker.example`, `app.localhost`, `127.0.0.1.nip.io` and `localhost.` are all refused.

2. ORIGIN (#287), 403 "Cross-origin request refused" unless `loopbackOriginOK(r, trustedOrigins)`. GET, HEAD and OPTIONS are exempt; EVERY other method is judged, PUT/PATCH/DELETE included, so no method list ages. For those:
- no Origin header passes: curl, the CLI, the bridge and every non-browser client send none, and a browser always sends one on a non-GET;
- an Origin whose scheme is http or https and whose authority equals r.Host passes. It is compared case-insensitively, with the scheme's default port ignored on both sides;
- an Origin in trustedOrigins passes, compared byte-exactly. That is Server.CORSOrigins, i.e. the desktop's `wails://localhost` and `http://wails.localhost`;
- everything else is refused: `null`, a malformed Origin, one with userinfo, a path (even `/`), a query or a fragment, and a repeated Origin header.
It compares against r.Host, NEVER the arrival port: the vite proxy sends Origin http://localhost:5173 with Host localhost:5173, and an https proxy for a loopback_hosts name presents https://<Host>.

WHY: a DNS-rebound page connects to 127.0.0.1, so before #281 it WAS anonymous@none. With the default loopback_default that meant every read, fact writes, git receive-pack, and MCP write tools. Plain-listener reads are not permission-gated at all, so even `loopback_default = []` leaked every fact. A cross-site page does not even need rebinding to WRITE: its form or text/plain fetch is a CORS simple request (no preflight), carries a legitimate loopback Host, and the handlers decode JSON regardless of Content-Type. That was a 201 fact write before #287. Its Origin is the one thing it cannot forge.

WHERE THE LISTS COME FROM:
- `app.New` sets `Server.Auth.LoopbackHosts = cfg.Auth.EffectiveLoopbackHosts(cfg.Host)`. That is the configured names lower-cased, plus cfg.Host when it is a DNS name (a wildcard or IP bind adds nothing). It MUST be computed there, from the post-override cfg.Host, and never at config.Load: `knomit serve --host` is applied after Load (cmd/serve.go). TestApp_BindHostIsALoopbackHost's --host case exists to catch that.
- trustedOrigins is Server.CORSOrigins, threaded by `Server.authEdge()` into BOTH AuthMiddleware invocations on the plain listener: the outer router (Server.Handler) and the API router (NewAPIRouter). If only one carries it, the desktop's write passes one check and is refused by the other. TestApp_OriginGuardWiring and TestOriginGuard_DesktopWailsOriginWrites pin that. The exported `AuthMiddleware(cfg, disabled)` trusts no cross-origin page; a listener must use authEdge.

SCOPE: only the anonymous branch.
- A socket/pipe peer returns earlier; `knomit oauth` sends `Host: knomit.local`.
- The TLS listener returns earlier.
- The OAuth listener never runs AuthMiddleware. A same-host TLS proxy delivers the public issuer host from loopback there, and must keep working.
- A non-loopback peer never gets a principal, so its Host and Origin are irrelevant.
- With `require = true` the branch is never entered.

MISREADINGS:
- (1) Neither check is authentication. They say 'a page on another site is not asking'. Any local process can still send any Host and Origin, or none; the residual is pre-2019 browsers (Firefox before 70 sent no Origin on same-origin-policy-exempt POSTs).
- (2) The 3b approval gate's ownHost/Origin rule is a STRICTER, separate check: three loopback spellings, the ARRIVAL port, Origin exactly http://<Host>, required on mutations. Do not replace one with the other. Since #287, five of TestBrowserGate_EachMissingProofRefuses's mutation rows are refused one step earlier by this Origin check (still 403 and still undecided), and the test lists them explicitly.
- (3) The Origin check is NOT a Content-Type rule. text/plain from the page's own origin or from curl still decodes as JSON; hardening the shared decoder is a separate follow-up.
- (4) Test fixtures: httptest.NewRequest's default Host `example.com` is a foreign name. A loopback-RemoteAddr test without `Host: localhost` gets 421, and an assertion of `!= 403` passes vacuously. fromLoopback sets it.

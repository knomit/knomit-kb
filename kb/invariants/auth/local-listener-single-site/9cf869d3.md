# auth.ListenLocal is the ONLY place the local authenticated listener is opened — a unix socket, or a named pipe on Windows — and EVERY serving path must call it, set ConnContext: auth.ConnContext, call the cleanup, AND consult auth.RequireLocalListener (`knomit serve` is the only such path since #503); skipping any of the four ships anonymous bridges or a silent lockout

THE RULE: the local authenticated listener is opened in exactly ONE function, `auth.ListenLocal(path)` in internal/auth/listen.go. WHAT it is differs by platform and that difference is the only thing the per-platform halves decide:

- **unix** — a domain socket whose kernel-reported peer uid becomes `bridge:uid:<n>@socket`. The length pre-check, the fallback-dir check, stale removal, listen, chmod 0600, the flock liveness lock and cleanup live in listen_unix.go / socketdir_unix.go.
- **windows** — a named pipe whose impersonated client SID becomes `bridge:sid:<SID>@pipe` (knomit#245). SDDL, the FILE_CREATE liveness refusal and cleanup live in listen_windows.go. There is NO lock file there; the pipe namespace is the lock.

It is the only non-test `net.Listen("unix", …)` and the only non-test `winio.ListenPipe` in the repo.

FOUR STEPS, ALL REQUIRED at every serving path. There are two server boot paths and they share only the handler (see the desktop boot-path gotcha): `cmd/serve.go` (`knomit serve`, via `openLocalListener` in cmd/listen.go) and `tools/desktop/boot.go` `bootServer` (the desktop app, the normal install). EACH must:

1. call `auth.ListenLocal(cfg.Socket)` and serve the returned listener on its `http.Server`;
2. set `ConnContext: auth.ConnContext` on that `http.Server` literal;
3. keep the returned cleanup for the listener's life and CALL it on shutdown;
4. call `auth.RequireLocalListener(require, ln, path, err)` straight after listening.

Step 1 without step 2 is the quiet failure: the listener exists and answers, the bridge connects happily, and every request still carries NO peer credential, so the principal is anonymous exactly as if there were no listener. `TestBootServer_OpensLocalSocketWithPeerCreds` asserts the peer arrives through the desktop's server, not merely that the listener answers — dropping the ConnContext line fails it.

Step 4 is the one added by knomit#245, and skipping it ships the SILENT LOCKOUT: with `[auth].require = true` there is no anonymous path, so a boot that took one of the benign branches below would answer every request 403 while looking healthy. app.checkLocalListener cannot see this — it asks what is CONFIGURED, not what was BOUND. See the require-needs-a-bound-listener invariant.

CALLER CONTRACT for the results of ListenLocal:
- `(ln, cleanup, nil)`: serve `ln`; keep `cleanup` and call it on shutdown (serve.go defers it; the desktop stores it as `server.closeSocket` and calls it in `shutdown()` after `http.Shutdown`). Both halves matter. Dropping `cleanup` lets the GC close the unix lock descriptor early. Not calling it keeps the lock after the listener is gone — and `http.Server.Shutdown` alone already unlinks the socket FILE, so a missing call is invisible to any "file is gone" check; what breaks is the successor, e.g. the desktop's `RestartApp` relaunch, which finds the lock held, gets `ErrSocketInUse` and serves TCP only (anonymous bridges) until a manual restart. On Windows the same call is what frees the pipe NAME for a successor.
- `ErrSocketInUse`: another live PROCESS holds the path. WARN and serve TCP only; NEVER fatal, NEVER remove — unless step 4 says otherwise. It is "another live process" and not "another knomit": on unix the .lock file is knomit's own so the owner almost certainly is knomit, but on Windows the pipe namespace is world-creatable and ERROR_ACCESS_DENIED is what the OS returns for ANY foreign owner.
- `ErrPathTooLong` and `ErrUnsafeSocketDir` (unix only, knomit#253; declared on every platform so callers compile): the path cannot be a socket address, or it lies in the shared fallback dir `/tmp/knomit-<euid>` and that dir is not ours with mode 0700. SAME treatment as `ErrSocketInUse`: WARN and serve TCP only, then step 4, which means under `[auth].require = true` the boot IS REFUSED (named cause), never served TCP-only. "Never fatal" is about the length or the directory ALONE, not about require. Both callers have ONE branch for the two. Neither creates any file. A squatted `/tmp/knomit-<euid>` therefore stops a long-root server with require on, which is the intended fail-closed trade.
- any other error: a real failure. Both callers fail the boot — serve.go by RETURNING it from `openLocalListener` (not log.Fatal, so the deferred cleanups and the crash marker run), the desktop by returning it from `bootServer`.
- `(nil, noop, nil)`: path "" only — skip; no platform branch in callers. NOTE: this is no longer the Windows case. Windows opens a real pipe, and a path outside the pipe namespace is an ERROR there, not a silent skip, because CreateFile would otherwise open an ordinary path as a FILE and the server would report a listener while accepting nothing.

ORDERING in the desktop: ListenLocal and the step-4 check both run BEFORE `lockfile.Write`, so a listener failure never leaves a discovery lockfile advertising a TCP port nothing serves (`TestBootServer_SocketFailureWritesNoLockfile` on unix, `TestBootServer_PipeFailureWritesNoLockfile` on Windows; both fail if the order is swapped). A benign branch DOES write the lockfile, because TCP is serving (`TestBootServer_PathTooLongServesTCPOnly`).

HOW TO APPLY: adding a third way to serve knomit (another binary, a test harness that stands in for production, a new listener type) means doing ALL FOUR steps there too, with all THREE benign errors in the benign branch. Grep for `http.Server{` in any new boot code and check all four are present. Do not copy the listener steps inline — that is how phase 1 ended up with a socket the desktop never opened.

MISREADING TO AVOID: this is not "all listeners go through ListenLocal". The TCP listener (`netutil.Listen` in the desktop, `ListenAndServe` in serve.go), the runtime diagnostics port and the mTLS listener (`auth.ListenTLS`, its own http.Server with `auth.TLSConnContext`) are separate and stay separate; the rule covers the local AUTHENTICATED listener only.

UPDATE (PR #488, merge 2104fd6d, 2026-10-12): 'NEVER fatal' in the ErrSocketInUse and ErrPathTooLong/ErrUnsafeSocketDir bullets is no longer true for the DESKTOP APP, though it stays true for `knomit serve` and for bootServer itself. New condition: bootServer still takes the benign branch (WARN, TCP only, lockfile written) and now records `server.local`, the path THIS server bound, empty on any of those three errors; tools/desktop/app.go bootKnomit then shuts the server down, closes the app and FAILS the boot with a message naming the socket path whenever `srv.local == ""`. REASON: the webview's only route to the server is that local socket/pipe (the archtest forbids a TCP route for the UI); dialing a path another process holds would put the window on a foreign server while this process's tray, lockfile and Settings describe its own (split-brain), and a TCP fallback for the UI contradicts the design. Fires with [auth].require false too, and on Windows for any foreign owner of the pipe name. Interim: it disappears when the desktop attaches to a separate server process. The four steps and the benign errors for bootServer are otherwise unchanged (TestBootServer_SocketInUseServesTCPOnly now also asserts server.local == ""). WHAT THIS DOES NOT MEAN: a third serving path must still treat the three errors as benign inside its own bootServer-like step; whether the CALLER of that step may carry on without a local listener depends on whether it has any other route for its client (the desktop UI has none). Why and test gap: kb/gotchas/desktop/boot (held-socket-fails-the-boot).

SINCE #493 (merge 9860c726): `cmd/listen.go` (openLocalListener) is gone; for `knomit serve` the four steps (ListenLocal, ConnContext: auth.ConnContext, the cleanup, RequireLocalListener) now live ONCE in openLocal / app.OpenListeners (internal/app/listeners.go), with the moved tests (TestOpenLocalListener_HonoursAuthRequire and the others, names unchanged). 'BOTH server binaries' stays true until PR 5: the desktop's bootServer still has its own call site. Caller contract for ErrSocketInUse: unsupervised it is a WARN (serve TCP only, never fatal, never remove the file, and no server.json is written); `knomit serve --supervised` turns it into exit 3 by design (kb/decisions/serve/supervised-mode) - a deliberate change of the caller's policy, not of this contract.

UPDATE (PR #503, merge 8be999a0, 2026-10-12): THERE IS NOW ONE SERVER BINARY. The desktop's in-process server (tools/desktop/boot.go bootServer, bootKnomit, server.local, closeSocket, the TestBootServer_* tests) is deleted; every statement above about 'BOTH server binaries', 'two server boot paths', the desktop calling ListenLocal itself, the desktop 'FAILING the boot on a held socket' (the #488 update) and the desktop's ordering before lockfile.Write describes code that no longer exists. The four steps live once, in app.OpenListeners (internal/app/listeners.go), called from cmd/serve.go. The desktop runs that same code as a child: `knomit serve --supervised`, where a held socket/pipe is exit 3 and the desktop's answer to exit 3 is to ATTACH to the holder (poll up to 5 s for it to answer, then attach; if it never answers it counts as a crash) - kb/decisions/desktop/supervisor and kb/decisions/serve/supervised-mode. TestDesktopLinksNoServer (test/archtest/desktop_no_server_test.go) keeps a second server out of knomit-desktop by forbidding internal/app and internal/web in its link closure.
WHAT THIS DOES NOT MEAN: the four-step rule is not relaxed - a new way to serve knomit (another binary, a harness) still needs all four steps and all three benign errors; only the desktop stopped being one. The supervised socket is MANDATORY: under --supervised the local listener must bind or the process exits 3 (held) or 2 (any other error), it never degrades to TCP-only.

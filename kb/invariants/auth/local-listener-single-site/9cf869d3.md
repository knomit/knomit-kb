# auth.ListenLocal is the ONLY place the local unix socket is opened, and BOTH server binaries — cmd/serve.go and the desktop's tools/desktop/boot.go — call it and set ConnContext: auth.ConnContext; a new serving path that skips either half ships anonymous bridges

THE RULE: the local authenticated listener — the unix socket whose kernel-reported peer uid becomes the `bridge:uid:<n>@socket` principal — is opened in exactly ONE function, `auth.ListenLocal(path)` in internal/auth/listen.go. Stale removal, listen, chmod 0600, the liveness lock and cleanup all live there. It is the only non-test `net.Listen("unix", …)` in the repo.

TWO HALVES, BOTH REQUIRED at every serving path. There are two server boot paths and they share only the handler (see the desktop boot-path gotcha): `cmd/serve.go` (`knomit serve`) and `tools/desktop/boot.go` `bootServer` (the desktop app, the normal install). EACH must (1) call `auth.ListenLocal(cfg.Socket)` and serve the returned listener on its `http.Server`, AND (2) set `ConnContext: auth.ConnContext` on that `http.Server` literal. Half (1) without half (2) is the quiet failure: the socket exists and answers, the bridge connects happily, and every request still carries NO peer credential, so the principal is anonymous exactly as if there were no socket. `TestBootServer_OpensLocalSocketWithPeerCreds` asserts the peer uid arrives through the desktop's server, not merely that the socket answers — dropping the ConnContext line fails it.

CALLER CONTRACT for the three results of ListenLocal:
- `(ln, cleanup, nil)`: serve `ln`; keep `cleanup` for the listener's life and call it on shutdown (serve.go defers it; the desktop stores it as `server.closeSocket` and calls it in `shutdown()` after `http.Shutdown`). Dropping `cleanup` lets the GC close the lock descriptor early.
- `ErrSocketInUse`: another live knomit owns the path. WARN and serve TCP only; NEVER fatal, NEVER remove. The bridge will talk to the other instance.
- any other error: a real failure. serve.go is fatal; the desktop fails the boot.
- `(nil, noop, nil)`: path "" or windows — skip; no platform branch in callers. The windows named pipe (#245) goes INSIDE ListenLocal.

ORDERING in the desktop: ListenLocal runs BEFORE `lockfile.Write`, so a socket failure never leaves a discovery lockfile advertising a TCP port nothing serves (`TestBootServer_SocketFailureWritesNoLockfile`, which fails if the order is swapped).

HOW TO APPLY: adding a third way to serve knomit (another binary, a test harness that stands in for production, a new listener type) means calling ListenLocal and setting ConnContext there too. Grep for `http.Server{` in any new boot code and check both lines are present. Do not copy the socket steps inline — that is how phase 1 ended up with a socket that the desktop never opened.

MISREADING TO AVOID: this is not "all listeners go through ListenLocal". The TCP listener (`netutil.Listen` in the desktop, `ListenAndServe` in serve.go) and the runtime diagnostics port are separate and stay separate; the rule covers the local AUTHENTICATED listener only.

# The local listener path is decided ONLY by config.socketFor — KNOMIT_SOCKET > knomit.toml `socket` > localListenerName(tilde-expanded home) — reached by BOTH config.Load (server) and config.SocketPath (bridge); the bridge never resolves any layer itself

knomit#271. `config.socketFor(home, fromTOML string) string` in internal/config/paths.go is the ONE place the local authenticated listener (unix socket, or Windows named pipe) is chosen from its inputs: KNOMIT_SOCKET if set, else the knomit.toml `socket` value, else `localListenerName(home)`. `home` must already be tilde-expanded.

BOTH resolvers reach it:
- `config.Load` (what `knomit serve` and the desktop pass to auth.ListenLocal): `cfg.Socket = socketFor(cfg.Home, cfg.Socket)` after the tilde-expansion loop, with cfg.Socket holding the TOML-decoded value. There is no separate `envOr("KNOMIT_SOCKET")` line in Load any more — do not re-add one.
- `config.SocketPath` (what `tools/bridge/knomitapi.SocketPath` delegates to): ResolveHome → expandTilde → decode ONLY `socket` from findConfigFile(home) → socketFor.

Where the listener is OPENED is a separate invariant (auth.ListenLocal, local-listener-single-site); this one is about which PATH both sides compute.

CONSEQUENCES:
- Adding a new layer (another env var, a flag) means changing socketFor, never Load or SocketPath alone. Changing one side only reproduces #271: the bridge dials a path the server never opened, finds nothing, falls back to TCP, and silently loses the verified identity. No error is raised anywhere.
- `knomitapi.SocketPath` stays a thin delegate. Any bridge-side reading of KNOMIT_SOCKET, TOML or HOME is a violation even if it happens to compute the same answer today.
- A knomit.toml that SocketPath cannot decode is an error (the bridge logs WARN and uses TCP), not a fall-through to the default, because Load refuses the same file.

ENFORCED BY: internal/config/socket_agreement_test.go (platform-neutral; each case asserts Load().Socket == SocketPath() == expected for KNOMIT_SOCKET, TOML socket, env-beats-TOML, `~/` in KNOMIT_HOME, plus malformed TOML → error) and tools/bridge/knomitapi/socketpath_test.go (delegation pinned with KNOMIT_SOCKET), alongside the existing long-home agreement test.

WHAT THIS DOES NOT MEAN:
- Not that the chosen socket value is tilde-expanded. `socket = "~/x.sock"` stays literal on BOTH sides (Socket is not in Load's tilde list). Parity holds; the missing expansion is a pre-existing bug left as a follow-up.
- Not full parity for a knomit.toml placed BESIDE THE EXECUTABLE. findConfigFile checks `filepath.Dir(os.Executable())/knomit.toml` before `<home>/knomit.toml`, and the server and the bridge are different executables, possibly in different directories. Only a `<home>/knomit.toml` (or one beside both binaries) is guaranteed to be seen by both.

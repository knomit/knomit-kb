# The local listener path is decided ONLY by config.socketFor(home, fromTOML, fromEnv) — KNOMIT_SOCKET > knomit.toml `socket` > localListenerName(home), an explicit value passed through the per-platform checkExplicitSocket (unix: ~ expanded, must be absolute; Windows: must be a \\.\pipe\ name, no ~) — and BOTH config.Load (server) and config.SocketPath (bridge) start from config.homeAndConfig (ResolveHome's tilde-expanded, absolute root; <home>/knomit.toml only); the bridge never resolves any layer itself

Three unexported functions in internal/config decide the local authenticated listener (unix socket, or Windows named pipe), plus the exported ResolveHome. They came in with knomit#271 / PR #272 and were tightened by knomit#274 / PR #293.

1. `ResolveHome()` (paths.go:113) returns KNOMIT_HOME, else KNOMIT_REPO, else DefaultHome, then expandTilde, then `filepath.Abs`. EVERY caller gets that normalised root: homeAndConfig, and also `knomitapi.CredentialsPath` (the credentials for `kb login` and the bridge). Before PR #293 ResolveHome returned the raw string and only homeAndConfig normalised it, so credentials still resolved against the literal `~/...` or the process cwd.
2. `homeAndConfig() (home, configPath string, err error)` (paths.go:138) is ResolveHome, then findConfigFile, which looks ONLY at `<home>/knomit.toml` and never beside the executable (toml-beside-executable gotcha).
3. `socketFor(home, fromTOML, fromEnv string) (string, error)` (paths.go:207) picks fromEnv (the caller passes os.Getenv("KNOMIT_SOCKET")) if non-empty, else fromTOML, else `localListenerName(home)`. An EXPLICIT value goes through `checkExplicitSocket`, which is per platform:
   - unix (paths_unix.go): expand a leading `~/`, then require `filepath.IsAbs`. Error: `socket "<v>" must be an absolute path; set KNOMIT_SOCKET or the knomit.toml socket key to one`.
   - Windows (paths_windows.go): require the `auth.PipePrefix` (`\\.\pipe\`) form, with NO tilde expansion, because auth.ListenLocal and auth.DialLocal refuse anything else. Error: `socket "<v>" must be a pipe name \\.\pipe\<name>; set KNOMIT_SOCKET or the knomit.toml socket key to one`.
   socketFor is NOT pure: on unix, expandTilde reads os.UserHomeDir.

BOTH resolvers use these:
- `config.Load` (what `knomit serve` and the desktop pass to auth.ListenLocal): homeAndConfig (config.go:510), decode knomit.toml into cfg, …, then `cfg.Socket, err = socketFor(cfg.Home, cfg.Socket, os.Getenv("KNOMIT_SOCKET"))` (config.go:647), with the error returned as `config: …`. Its env-overlay block has a comment saying KNOMIT_SOCKET is applied in socketFor. Do not add an envOr for it there.
- `config.SocketPath` (paths.go:178; what `tools/bridge/knomitapi.SocketPath` delegates to): homeAndConfig, decode the file into a zero `Config` and read `.Socket`, then socketFor, with the error wrapped identically. So both sides refuse a bad socket with the SAME message, and the bridge logs it once and uses TCP. A decode error is returned wrapped with the file's path.

Where the listener is OPENED is a separate invariant (auth.ListenLocal, local-listener-single-site). This one is about which PATH both sides compute.

CONSEQUENCES:
- A new layer (another env var, a flag) goes into socketFor's inputs at BOTH call sites, never into one resolver. Changing one side only reproduces the original drift: the bridge dials a path the server never opened, finds nothing, falls back to TCP, and silently loses the verified identity. No error is raised anywhere.
- Any normalisation or validation of the socket value goes INSIDE socketFor / checkExplicitSocket, never in Load's path loop or in SocketPath. A per-platform difference goes in the platform file.
- Any change to how the data root is found or normalised goes in ResolveHome, so that credentials, config and socket all see it. How its knomit.toml is found goes in homeAndConfig.
- `knomitapi.SocketPath` stays a thin delegate. Any bridge-side reading of KNOMIT_SOCKET, TOML or HOME is a violation even if it happens to compute the same answer today. Its WARN on failure fires once per process (sync.Once), but the path itself is resolved on every call and never cached (ambient-state-at-package-init).
- A socket change takes effect only after the SERVER restarts. The server resolves once at startup, the MCP bridge once at its own startup, and the lazy hooks client on every dial. After a TOML edit the hooks dial the new path, find no listener, and use TCP without the verified identity; they do NOT lose connectivity. This is documented on the Config.Socket field.
- The bridge's startup does not resolve the listener at all when an explicit URL is given (CLI argument or KNOMIT_BASE_URL). The lazy hooks client skips it for the same reason.
- A knomit.toml that SocketPath cannot decode is an error (the bridge logs WARN and uses TCP), not a fall-through to the default, because Load refuses the same file.

ENFORCED BY:
- internal/config/socket_agreement_test.go (every KNOMIT_* cleared per test) asserts Load().Socket == SocketPath() == expected for: KNOMIT_SOCKET, the TOML socket, env beats TOML, `~/` in KNOMIT_HOME (alone and with a TOML socket), and a relative KNOMIT_HOME under t.Chdir. Explicit values come from config.ExplicitSocket: a temp path on unix, a pipe name on Windows. _RelativeSocketRefused requires both sides to error identically with this platform's rule.
- socket_tilde_unix_test.go covers `~/x.sock` via env and TOML (unix only).
- tilde_windows_test.go (windows tag) covers: `~\x.sock`, `~/x.sock`, `C:\abs\x.sock` and `rel.sock` refused by both sides with an error naming the pipe form; an operator-named pipe agreed; and `~\` and `~/` still expanding (joined with the separator) in `[remote] known_hosts`.
- tools/bridge/knomitapi/credentials_path_test.go pins CredentialsPath under Load().Home for `~/` and relative KNOMIT_HOME.
- TestFindConfigFile_OnlyHome pins the config location.

WHAT THIS DOES NOT MEAN:
- Not that a relative socket is made absolute. It is REFUSED, because `filepath.Abs` would resolve against each process's own cwd, which is exactly the disagreement. The data root, by contrast, IS made absolute, once per process, in ResolveHome.
- Not that `~\` works for a socket on Windows. It is refused there; `~\` is expanded only in the other path fields.
- Not that TOML edits propagate live (see the restart consequence above).

# The local listener path is decided ONLY by config.socketFor(home, fromTOML, fromEnv) — KNOMIT_SOCKET > knomit.toml `socket` > localListenerName(tilde-expanded home) — and BOTH config.Load (server) and config.SocketPath (bridge) start from config.homeAndConfig; the bridge never resolves any layer itself

knomit#271 / PR #272 (merged as 5fd001bd). Two unexported functions in internal/config/paths.go together decide the local authenticated listener (unix socket, or Windows named pipe):

1. `homeAndConfig() (home, configPath string, err error)` (paths.go:123): ResolveHome, THEN expandTilde, THEN findConfigFile on the EXPANDED home. It is the one place that order lives. Load no longer tilde-expands Home in its later path loop; Home is expanded exactly once, here.
2. `socketFor(home, fromTOML, fromEnv string) string` (paths.go:194), PURE: fromEnv (the caller passes os.Getenv("KNOMIT_SOCKET")) if non-empty, else fromTOML, else `localListenerName(home)`.

BOTH resolvers use both:
- `config.Load` (what `knomit serve` and the desktop pass to auth.ListenLocal): homeAndConfig (config.go:426) → decode knomit.toml into cfg → … → `cfg.Socket = socketFor(cfg.Home, cfg.Socket, os.Getenv("KNOMIT_SOCKET"))`. Its env-overlay block has a comment saying KNOMIT_SOCKET is applied in socketFor (config.go:447). Do not add an envOr for it there.
- `config.SocketPath` (paths.go:166; what `tools/bridge/knomitapi.SocketPath` delegates to): homeAndConfig → decode the file into a zero `Config` and read `.Socket` → socketFor. A decode error is returned wrapped with the file's path (`config: <path>: …`, paths.go:179), because findConfigFile may have chosen the file beside the executable.

Where the listener is OPENED is a separate invariant (auth.ListenLocal, local-listener-single-site). This one is about which PATH both sides compute.

SERVER BEHAVIOUR CHANGE, DELIBERATE (found in the #272 review): before this, Load called findConfigFile(cfg.Home) BEFORE tilde-expanding Home. A data root given as `KNOMIT_HOME=~/kh` therefore searched a literal "~/kh" directory and silently ignored `$HOME/kh/knomit.toml`, for EVERY setting and not only the socket. Since #272 the server reads that file. The first version of #272 had the bridge expand first while Load did not, so with a "~/" root plus a TOML socket the two sides disagreed. homeAndConfig exists so that order cannot diverge again.

CONSEQUENCES:
- A new layer (another env var, a flag) goes into socketFor's inputs at BOTH call sites, never into one resolver. Changing one side only reproduces #271: the bridge dials a path the server never opened, finds nothing, falls back to TCP, and silently loses the verified identity. No error is raised anywhere.
- Any change to how the data root or its knomit.toml is found goes in homeAndConfig, not in Load or SocketPath.
- `knomitapi.SocketPath` stays a thin delegate. Any bridge-side reading of KNOMIT_SOCKET, TOML or HOME is a violation even if it happens to compute the same answer today. Its WARN on failure fires once per process (sync.Once), but the path itself is resolved on every call and never cached (ambient-state-at-package-init).
- The bridge's startup (tools/bridge/main.go) does not resolve the listener at all when an explicit URL is given (CLI argument or KNOMIT_BASE_URL), so a broken local knomit.toml cannot log a misleading warning for a bridge aimed at another server. The lazy hooks client skips it for the same reason.
- A knomit.toml that SocketPath cannot decode is an error (the bridge logs WARN and uses TCP), not a fall-through to the default, because Load refuses the same file.

ENFORCED BY: internal/config/socket_agreement_test.go. It is platform-neutral, and every KNOMIT_* variable is cleared per test. Each case asserts Load().Socket == SocketPath() == expected, for: KNOMIT_SOCKET; TOML socket; env beats TOML; `~/` in KNOMIT_HOME (asserting on the value under test, not the reference); `~/` in KNOMIT_HOME together with a TOML socket in the expanded root. A malformed TOML must make SocketPath return an error that names the file. tools/bridge/knomitapi/socketpath_test.go pins the delegation, and the existing long-home agreement test still stands.

WHAT THIS DOES NOT MEAN:
- Not that the chosen socket value is tilde-expanded. `socket = "~/x.sock"` stays literal on BOTH sides (Socket is not in Load's tilde list). The two sides agree; the missing expansion is a pre-existing bug.
- Not full parity for a knomit.toml placed BESIDE ONE EXECUTABLE, for a RELATIVE KNOMIT_HOME/socket path (resolved against each process's cwd), or across a TOML edit without a server restart (the hooks client re-reads per dial; the server reads once). All four remaining gaps are tracked in knomit#274; see the gotcha on the beside-the-executable lookup.

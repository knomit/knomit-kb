# An eval output directory belongs to ONE pool (pool.json); a train run admits only worlds under worlds/ that carry no F15/F18 family (spec or question) and no heldout- ontology file; every spec run is hashed into its records and the summary; each run's experiment is rolled back after grading unless keep; each endpoint lane gets its own loaded copy of the world

Enforced in internal/synthesize/eval_config.go (EvalConfig.admit, SelectWorlds) and eval_runner.go (lockPool, existing, runChain, runWorld), tested by TestEvalRunner_PoolGuards, TestEvalRunner_OracleSmoke and TestEvalRunner_KeepLeavesTheExperiments. Since 20434db7 TestEvalRunner_PoolGuards covers every train-run refusal in clause 1: a world under a held-out directory, a world declaring F15, a training-family world with ONE question of family F15 ("question q2 is of held-out family F15"), and a training-family world whose ontology_file is under ontologies/heldout-<name>/ ("its ontology ... is held out"); each was sabotaged once (the check disabled) and the test went red.

1. Pools are the scenarios repo's directories: train = worlds/, heldout-families = heldout-families/, heldout-ontology = heldout-ontology/. A world outside the run's pool directory is refused. A train run additionally refuses a world whose families or any question's family is F15 or F18, or whose ontology_file contains `heldout-`.
2. <out>/pool.json records the pool on first use; a run of another pool into that directory is refused (pools never share an output directory).
3. spec_hash = sha256 over spec.yaml plus its ontology file; it is in every record and in summary.spec_hashes. A record written for another spec_hash, or another engine script sha, is refused on resume.
4. The engine writes answer facts only into the experiment it opens; after each run the runner checks the world branch head is unchanged (a moved head is a fatal error), grades, then rolls the experiment back and reads back that it is gone (rolled_back). keep: true leaves the experiment and keeps the world store under <out>/worlds/<id>/<time>/.
5. Worlds are loaded one at a time (the only batch embedding the runner causes; the embedder's own batch gate bounds it). Arms on different endpoints run concurrently, arms on one endpoint (two Ollama models) serially, and EACH LANE RUNS ON ITS OWN LOADED COPY of the world.

What this does NOT mean: the pool check is not content-based beyond families and the ontology file name; a held-out world copied under worlds/ with its families relabelled would be admitted. The guard is against mistakes, not against deliberate relabelling.

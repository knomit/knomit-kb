# TestConformance_ReviewPipelineOnly intends that edge/mcp and edge/web must not import synthesize/restatement, but enforces it only by a string match on the import path

Since 13c (PR #601, merged 52604c5d; re-read there) TestConformance_ReviewPipelineOnly lives in internal/corpus/synthesize/restatement/restatement_conformance_test.go. Besides its original rule (the abstraction axis is review-time derived state; it scans internal/edge/mcp, internal/edge/web and the store tree for identifiers, selectors and STRING literals naming abstraction/restatement), it now carries the intended rule that edge/mcp and edge/web must NOT import internal/corpus/synthesize/restatement: restatement's API takes step.Deps and sessions that only the engine constructs, so edge reaches it through Pipeline/Reviewer.

HOW IT IS ENFORCED TODAY: by accident of the match. An ImportSpec path is a string literal containing 'restatement', so an edge import turns the test RED (review sabotage); TestLayers stays GREEN on the same sabotage because a downward edge -> corpus import is allowed. The test's doc comment now says the rule is intended.

CONSEQUENCE: do not narrow codeMentions to skip import specs, or rename the package, without replacing this with an explicit forbidden-edge check; either change would silently drop the rule. DOES NOT MEAN: that the layering guard forbids the import, it does not.

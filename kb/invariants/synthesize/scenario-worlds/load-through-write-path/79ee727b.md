# A scenario world is materialised only by replaying its history through knomit_learn/update/retract (mcp.NewScriptTools), never by writing files; any refusal, dedup merge into another world fact or unlisted hypothesis subsumption makes the world invalid — and only the EXPERT_SPEC_DIR run with the embedder on proves a world passes

LoadScenario (internal/synthesize/scenario_load.go) writes only the ontology at init (InitRepo on agent/scenario) and then replays each history step through the ScriptTools handlers, so every fact passes ValidateFact, ref resolution, the type-mix rule, dedup and the same-subject gate and has a real git history. Never add a path that writes fact files directly. A world is INVALID (a *ScenarioError naming the step, the fact and the server's text) when: the write path refuses; knomit_learn's dedup merge lands a fact at another world fact's path or merges two facts of one call; a learn note says 'merged into existing fact' or 'dropped'; or a fact the step did not list in `retracts` is no longer live at the step's commit (an incoming observation subsumed a hypothesis: list it in retracts or reword). The fix is to regenerate or reword the spec, never to patch the loader around the refusal.

Misreading to avoid: a green load without an embedder does not prove a world. With no embedder (nil Embedder, NewScriptTools(nil)) the dedup merge and the same-subject gate fail OPEN, so a spec that would be refused in production loads. Only the TestScenarioSpecDir run (EXPERT_SPEC_DIR set, embedder on) exercises both gates, and CheckGold (which refuses gold support that is retracted) runs there too. Unit tests using a nil embedder prove the loader, not the worlds.

# Reviewer is per-call — NEVER store session-scoped state on its struct

ReviewHandler constructs a fresh Reviewer per MCP call (internal/mcp/review.go). Storing any sessionID-keyed state on the Reviewer struct (e.g. the old reflectChecked map[string]bool at internal/synthesize/review.go) is by construction wrong: the map starts empty on every continuation, so the dedup it was meant to do never fires. Symptom: reflect step loops forever, remaining counter freezes at 1, agent inserts a new reflect work item every cycle. Fix: keep Reviewer stateless (just ri, onProgress); persist session-scoped state on the pipeline_sessions row via a `phase` column. Generalisation: any synthesize/MCP handler object that's constructed per call must NOT carry per-session caches — use the persistent session row.

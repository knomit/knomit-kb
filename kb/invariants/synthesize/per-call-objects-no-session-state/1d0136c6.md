# Reviewer is per-call — NEVER store session-scoped state on its struct

ReviewHandler constructs a fresh Reviewer per MCP call (internal/mcp/review.go:59, via synthesize.NewReviewerWithOptions). Storing any sessionID-keyed state on the Reviewer struct (e.g. the old reflectChecked map[string]bool at internal/synthesize/review.go) is by construction wrong: the map starts empty on every continuation, so the dedup it was meant to do never fires. Symptom: reflect step loops forever, remaining counter freezes. Session-scoped state MUST live in store.PipelineSession (persisted in pipeline_sessions and reloaded each continuation), never on the Reviewer.

WHAT THIS DOES NOT MEAN: 'per-call' does NOT mean the Reviewer struct must be fieldless. It legitimately holds CONSTRUCTION-TIME config that is re-supplied on every call — ri, onProgress, effort, scope (see the current struct at review.go:27). The forbidden thing is state that must PERSIST ACROSS continuations of the SAME session; that state cannot survive on a per-call object and must go to pipeline_sessions. Test for a new field: is it re-derivable from the MCP call's arguments? If yes it may live on Reviewer; if it accumulates across continuations, it may not.

Anti-pattern: adding a map keyed by sessionID (or any cross-continuation accumulator) to the Reviewer struct.

# Reviewer is per-call — NEVER store session-scoped state on its struct

ReviewHandler constructs a fresh Reviewer (and so a fresh Pipeline) per MCP call, via synthesize.NewReviewerOnBranch (internal/mcp/review.go). Storing any sessionID-keyed state on the Reviewer or Pipeline struct (e.g. the old reflectChecked map[string]bool) is wrong by construction: the map starts empty on every continuation, so the dedup it was meant to do never fires. Symptom: the reflect step loops forever and the remaining counter freezes. Session-scoped state MUST live in store.PipelineSession (persisted in pipeline_sessions and reloaded each continuation), never on the per-call objects. The session marks added by PR #291 (planning, advancing, and the per-item applying) follow this rule: they are columns, not fields.

WHAT THIS DOES NOT MEAN: 'per-call' does NOT mean the structs must be fieldless. They legitimately hold CONSTRUCTION-TIME config that is re-supplied on every call. Reviewer holds ri and its Pipeline; Pipeline holds ri, onProgress, effort, scope, strategy, the branch override, and test-only hooks. The forbidden thing is state that must PERSIST ACROSS continuations of the SAME session; that state cannot survive on a per-call object and must go to pipeline_sessions. Test for a new field: is it re-derivable from the MCP call's arguments? If yes it may live on the struct; if it accumulates across continuations, it may not.

Anti-pattern: adding a map keyed by sessionID (or any cross-continuation accumulator) to the Reviewer or Pipeline struct.

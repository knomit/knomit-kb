# A registering fleet on the instance that holds the fleet root becomes registered only after main is published (fleetPushed publishes it first and stays registering with last_error while that fails); a member's registering still completes on any successful push of its agent branch

PR #518 (merge 537f2019); fleet.go fleetPushed, fleet_chokepoint.go holdsFleetRootAt, fleet_create.go publishFleetMain. Before #518, fleetPushed completed registering -> registered on ANY successful push of the fleet repository's agent branch. For a forge create that was wrong: a create whose publish of main failed stayed registering, and the sync loop's next agent-branch push flipped it to registered while the forge's main was still unpublished.

THE RULE, all parts: when the state is registering AND this instance holds the root of the fleet repository (holdsFleetRootOf: <home>/fleet/root.key is a regular file AND the root.crt beside it equals artifacts/fleet/root.crt on the AGENT branch; isFleetMaster is the same test against main), fleetPushed calls publishFleetMainNow (PublishUpstream, never forced, then local main follows). If that fails it records the attempt (last_error), logs, and the state STAYS registering. Only a publish that succeeds lets it enter registered. publishFleetMain (the create's own step) sets registering explicitly on failure, whatever a concurrent loop push did meanwhile.

THE OTHER ARM IS UNCHANGED: an instance without the root (a member registering through PUT /api/v1/fleet) has nothing to publish; its registered still means 'my agent branch was pushed'. fleetPushed still ignores non-fleet repos and ignores state standalone, which is why a create in progress (state set only at the end) is never published.

CONSEQUENCES. For the root holder 'registered' means main is on the origin; for a member it does not mean the record is on main (the master merges later; the status shows record_state pending). A hosted-here create is registered at the point of no return and then advances local main, so 201 vs 202 is decided by record_state (kb/architecture/fleet/create/sequence). It runs on the reconcile loop's goroutine (m.ctx, under WithRead), after Push has released the push lock, so PublishUpstream can take it.

KNOWN LIMITS. The S1 test (TestCreateFleet_ForgePublishFailureStaysRegistering) drives the arm through FleetRetry, which takes the same fleetPushed path, not through a real loop tick. A later master tick (PR6) that publishes main needs isFleetMaster, which needs main to hold the root, so after a failed create publish THIS arm is the only first publisher; keep or fold it. MISREADING: 'registered means the fleet is live on the forge' holds for the root holder only.

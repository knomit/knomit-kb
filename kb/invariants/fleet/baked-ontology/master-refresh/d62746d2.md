# The fleet ontology is refreshed WHOLESALE and ONLY by the master — the instance whose <home>/fleet/root.key is a regular file AND whose local root.crt equals artifacts/fleet/root.crt on the fleet repository's main; a stray root.key from another root is not mastership

RepoInstance.loadOntology sends a fleet-id ontology to refreshFleetOntology BEFORE the preset loop; the fleet is not a preset and never goes through refreshDivergence. The refresh writes the built-in ontology (fact.FleetOntology) over the stored one, wholesale, in a commit on the read branch ('ontology: refresh to the built-in fleet ontology'), only when ALL hold: the repo is not a subscription; its mount has the fleet door (so a refused restore or an unrecorded fleet-id row writes nothing, even on the master); isFleetMaster is true; and the serialised stored ontology differs from the built-in one. Members never write it: a member's dot-path commit would be refused by the push gate's dot-path closure and wedge its branch.

MASTER means all of: (1) <home>/fleet/root.key exists and is a regular file (the directory name is the one constant pki.FleetRootDirName, shared by internal/repos and cmd; the key is NEVER read or opened here); (2) <home>/fleet/root.crt loads; (3) that certificate Equals the root held at artifacts/fleet/root.crt on the fleet repository's main (UpstreamBranch(), which falls back to the local consensus branch when there is no origin, so a no-origin host is still recognised). Every error answers 'not master'.

CONSEQUENCES: a stray root.key (another fleet's, an undecommissioned one) or a root.crt without its key does not make an instance the master. A fleet whose main declares no PKI or holds no root.crt (a fleet predating the trust-file rules) has no master, so its ontology is never refreshed. Mastership here is a local files test, not a proof that the key opens; a later change may add 'and opens'.

DOES NOT MEAN: members stay on the old ontology forever. They receive the master's refreshed ontology through the normal sync of main like any file. Nor does it mean the fleet ontology follows the preset subset rule: a master replaces it even when the stored one is not a subset of the built-in one.

UPDATE (PR #524, verified at merge commit 9db8c106): the same master predicate (RepoInstance.isFleetMaster = fleet door AND fleet repo AND Manager.isFleetMaster) now also gates (a) the consensus merger on the fleet repository, with or without an origin, and (b) the master's origin round (fetching agent/*, admitting, publishing main). It is decided ONCE per round / per merger run, so copying root.key in or out takes effect on the next round with no restart. The refresh itself now has one more visible effect: it rewrites a pre-#524 fleet's ontology without `consensus: auto` (the built-in text no longer declares it). Two instances satisfying the predicate at once is unsupported; see kb/decisions/fleet/two-masters-unsupported/daea77c9.md and kb/architecture/fleet/master-merges/91e3f6da.md. MISREADING: 'a stray root.key from another root merges' remains false; the merger gate also requires the local root.crt to equal main's (TestFleetMaster_MergerGateIsTheMasterPredicate/stray).

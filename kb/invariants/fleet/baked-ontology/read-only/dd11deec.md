# The fleet repository is read-only for every authored write (MCP, fact REST routes, experiments, synthesis-runs, repo PATCH) and may be a lens READ mount only; it is never archived, deleted, restored or connected through the generic doors; its origin DETACH and UPSTREAM change are gated (R3.3, #525: a member cannot detach, nobody changes the upstream) while origin ATTACH/PUT stays open, and the pushed-branch merge is exempt from the write gate only for the master, which re-judges

A mounted repo whose ontology id is fleet (RepoInstance.IsFleet) is read-only for authored writes, through one seam plus named gates:
- RepoInstance.WritableBranch returns false for it on every branch (checked right after the ontology-error check), and binding writeOK, MCP learn/update/retract/review/hypothesize and the REST fact create/update/delete routes all derive from it. REST answers 403 through refuseUnwritableBranch with the text 'the fleet repository changes only through the fleet API (/api/v1/fleet/..., the Fleet page)' (ErrFleetReadOnly; PR #525 reworded it, the `knomit fleet` verbs it used to name are gone).
- MCP experiment tool: every action except `list` is refused on the fleet repository. REST experiment open: 409.
- POST /repos/{repo}/branches/{branch}/synthesis-runs and PATCH /repos/{repo} (it commits README.md and LICENSE) answer 403 through refuseUnwritableBranch(ri.AgentBranch()). The gate is on the AGENT branch because that is what those handlers write, not the branch in the URL. A subscription now also gets the named 403 on those two routes.
- A lens naming the fleet repository as its WRITE repo: ErrLensWriteFleet (422 'Lens write repo is the fleet repository'). As a READ mount it is fine, and it appears in the repo list and REST reads.
- Lifecycle: guardFleetRemoval answers 409 fleet_repository in EVERY fleet state for archive and delete, pointing at `POST /api/v1/fleet/leave` (Fleet page) for a member and `POST /api/v1/fleet/decommission` for the master (the old archive escape for a stuck unregistration, the 'use_unregister' arm and the state switch are gone); restore and connect are refused by the reserved-id rule (see the baked-ontology reserved-id invariant).
- The ONE exemption: handlePushedMerge (the operator's merge of a pushed branch) is not refused by the write gate on the fleet repository. Since PR #525 it is refused by `RepoInstance.FleetMergeRefusal` unless this instance is the fleet's MASTER (409 `not_master`), and on the master it re-judges the branch with `svc.JudgePeerBranch(branch, own, expected_tip, nil)` (tip minus main, the merger's own judge) and refuses with 409 `judge_refused` and the reason before `MergePushed` runs; the check runs inside the handler's existing read, before the merge (verified at fd991d4f).

GATED SINCE PR #525 (R3.3; the first version of this fact said none of the origin routes were gated): DELETE /repos/{fleet}/origin goes through `Manager.DetachRepoOrigin`, which takes fleetOpMu and checks and detaches as one step: a MEMBER's detach is 409 `member_keeps_origin`, and the MASTER's detach (which makes its copy the hub) needs `[tls].addr` and `external_addresses` (`listener_required` / `addresses_required`, 422). PATCH /repos/{fleet}/origin/upstream is 409 `fleet_upstream_fixed` for everyone.

STILL NOT GATED: origin ATTACH / PUT origin (and the origin-session commit that is not a swap). They change git config and control.db, not repository content, and PUT origin is how a member's forge token is rotated AND how the master switch repoints a hub (a stand-down is refused while the copy has no origin, so the old hub must be pointed at the new master first). MISREADING: 'the fleet repository's origin cannot be touched' is false; only detach and upstream are refused.

CONSEQUENCE: the fleet repository has NO store-level read-only flag (a subscription has one: see the two-layer write refusal decision), so a new REST route or tool that writes repository content (facts, files, git) must call refuseUnwritableBranch or WritableBranch itself; nothing underneath will refuse it. The synthesis-runs and PATCH routes were found missing in review of this PR, so audit every new mutating route in router.go the same way.

DOES NOT MEAN: knomit's own fleet code cannot write the repository. It writes through the store and never asks WritableBranch.

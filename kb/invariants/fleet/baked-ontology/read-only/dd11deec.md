# The fleet repository is read-only for every authored write and changes only through the /fleet API: ONE middleware (fleetRepoRefused) answers 409 `fleet_repository` to every non-read request naming it under /repos/{repo}, for every caller (the local socket included); MCP writes are refused by WritableBranch, it may be a lens READ mount only, and generic archive, delete, restore and connect are refused

A mounted repo whose ontology id is fleet (RepoInstance.IsFleet) is read-only for authored writes and changes only through the /fleet API. Since PR #528 (verified at merge e417fd76; user ruling 2026-10-16, see the decision that the fleet repository is changed only through /fleet) that is enforced at ONE door plus one seam:

1. THE GATE. `r.Use(fleetRepoRefused(...))` on the `/repos/{repo}` route (internal/web/router.go, handlers_fleet.go): any method other than GET, HEAD or OPTIONS whose {repo} resolves to the fleet repository answers 409 with code `fleet_repository` and the text FleetRepositoryRefusal ("this is the fleet repository: it changes only through the Fleet page (Fleet -> Settings: Host the fleet here, Point at the new host, Leave, Decommission), never through a repository's own actions"); the handler does not run. It covers rename, archive/delete, repo PATCH (README/LICENSE), PUT and DELETE origin, PATCH origin/upstream, origin sessions, index:cancel, experiments, the pushed-branch merge, branch and fact writes, synthesis runs and index rebuilds (30 mutating routes at merge). It applies to EVERY caller, the desktop app on the local socket included; it is not a local gate. A name that resolves to no repository passes to the handler's own 404.
2. THE MCP MOUNT is exempt by exact shape (isRepoMCPMount: .../repos/{name}/branches/{one segment}/mcp), because MCP is a POST for reads too. Its WRITES are refused by RepoInstance.WritableBranch, which returns false for the fleet repository on every branch; binding writeOK and MCP learn/update/retract/review/hypothesize derive from it; the MCP experiment tool refuses every action except `list`. The unscoped /mcp is gated by WritableBranch/writedest the same way.
3. A lens naming the fleet repository as its WRITE repo: ErrLensWriteFleet (422). As a READ mount it is fine and appears in the repo list and REST reads.
4. Lifecycle: guardFleetRemoval (a Manager chokepoint, also used by create cancel) answers 409 fleet_repository for archive and delete in every fleet state, pointing at POST /fleet/leave (member) or POST /fleet/decommission (master); restore and connect are refused by the reserved-id rule.
5. What replaced the old per-door arms: DELETE origin is POST /fleet/host (Manager.HostFleetHere), PUT origin is POST /fleet/follow (Manager.FollowFleetHost) (see the host/follow guards fact); the upstream change and the operator's manual merge no longer exist for the fleet repository (the fleet_upstream_fixed, not_master and judge_refused codes, FleetMergeRefusal and ErrFleetUpstreamFixed were removed); the master's consensus merger re-judges and merges automatically.

READS stay open: GET on the repo, origin, facts and branches (200 on socket, TCP and mTLS), MCP reads, and git fetch/push (/git is mounted outside /repos/{repo}).

CONSEQUENCES. A new mutating route under /repos/{repo} is covered by the gate with nobody remembering to; TestFleetRepo_EveryGenericMutationIsRefused walks the real route table so a route added later is asserted too. A new REST route that writes repository content OUTSIDE /repos/{repo} (or the MCP mount) still has no store-level read-only flag underneath (a subscription has one; the fleet repository does not), so it must call refuseUnwritableBranch/WritableBranch itself. A new operation the fleet needs is a /fleet route, never an exemption in the gate (see the configuration-parity decision).

MISREADINGS. "The fleet repository's origin cannot be touched": it can, through POST /fleet/host and POST /fleet/follow only. "The gate is local-only": it is for everyone. "A forge token can still be rotated with PUT origin": it cannot (409); since PR #529 (verified at merge 60ddfb1c) the rotation is POST /fleet/follow with the stored forge URL (or no url) and the new credential, the page's Update access (kb/invariants/fleet/follow/credential-vs-move/7b230fe8.md); the earlier 'no route rotates it' gap is CLOSED. DOES NOT MEAN: knomit's own fleet code cannot write the repository: it writes through the store and never asks WritableBranch.

UPDATE (PR #529, verified at merge 60ddfb1c): POST /fleet/follow is the ONLY attach door and now carries a forge URL and its credential (a member's follow, a credential rotation, and on the master the move of the fleet onto a forge); the generic index-rebuilds route is still refused here and POST /fleet/index-rebuild is its /fleet equivalent (kb/architecture/fleet/index-rebuild/fd9e69d0.md). The rebuild route's gate text names the Fleet page's Index action. The configuration-parity ruling is delivered for origin, access tokens and index rebuild (kb/decisions/fleet/config-parity/97277085.md). Gate texts (FleetRepository refusals) are asserted per route class in TestFleetRepo_EveryGenericMutationIsRefused. Nothing else about the gate changed.

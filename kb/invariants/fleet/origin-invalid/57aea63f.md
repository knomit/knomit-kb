# refuseFleetOrigin (F1): the fleet repository's origin must be a URL a member's join could clone (https://, ssh://, git@host:path or file://); a forge create and POST /fleet/follow refuse anything else with 422 `origin_invalid` before anything dials

The bundle carries the master's origin URL, and a join refuses every shape bundleURLProblem refuses (plain http, another scheme, no host or no path). So the choice is made where the origin is chosen: a forge create (fleet create pre-flight) and POST /fleet/follow call refuseFleetOrigin first and answer 422 `origin_invalid` naming the credential-free URL, instead of letting the operator create a fleet nobody can join. Since PR #528 the attach arm that used to carry this check (guardAttach's fleet F1 arm) is gone with the generic PUT origin; follow runs F1 itself, before ResolveOrigin dials. Pinned by TestFleetREST_HostAndFollowOnAMember (an http URL is 422 origin_invalid and the origin is unchanged). Verified at merge e417fd76.

MISREADING: origin_invalid is about the URL's SHAPE only; reachability and same-fleet are separate refusals (unreachable, not_this_fleet).

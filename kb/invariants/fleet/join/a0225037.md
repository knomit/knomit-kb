# POST /api/v1/fleet/join is all or nothing: it installs the bundle, clones through the fleet door, records the uid, writes the own record and pushes ONCE, and ANY refusal (the push's included) undoes the repository, the installed material and the record and leaves the state standalone; success is `registered` and carries root_fingerprint

RULE (PR #525, verified at merge commit fd991d4f, internal/repos/fleet_membership.go). Under fleetOpMu: recoverFleetCreate first (create_unfinished if an earlier create's rollback is incomplete), then the PRE-FLIGHTS, nothing written: `fleet_present` (409: not standalone, a fleet repository mounted or recorded; text points at POST /fleet/leave), `trust_installed` (409: any of root.crt, crl.pem, instance.crt is already in [tls].dir), `bundle_invalid` (422: not leaf + root + CRL, or does not verify), `key_mismatch` (422: the leaf is not for THIS instance's ssh-ed25519 key, pki.ErrKeyMismatch), `agent_mismatch` (422: the leaf's email SAN id is not this instance's agent id). Then the writes, in order: pki.InstallBundle (InstallOptions{}), clone of the fleet URL through the fleet door (`clone_failed` 502), the ontology must be the fleet ontology (`not_a_fleet` 422), the root on the fleet's main must equal the bundle's root (`root_differs` 422), recordFleetRepo (`record_failed` 500), the own record (state active), and ONE push of the agent branch (`join_refused` 409 when the fleet did not take it, with 'Nothing is kept; join again').

UNDO. A refusal at or after the clone runs `undoJoin`: a best-effort retract of the agent branch on the origin (lease on the last tip this instance saw), delete of the repository, pki.Uninstall; the errors of the last two are appended to the refusal text; the attempt is recorded in last_error. The state was never moved off standalone. Success sets `registered` (never `registering`) and answers 200 with the installed root's fingerprint as `root_fingerprint` (the operator's confirmation that the bundle was for the root they meant).

CONSEQUENCES. Registered here does NOT mean admitted: the record counts once the fleet's master merges it into main, and the master admits it only if a leaf the master issued is on MAIN (a join before the enroll's publish reaches main is not admitted, and the retry after a publish works: the join text says a leaf issued just now reaches main on the next round). A refused join on a KNOMIT-HOSTED fleet leaves the hub's `agent/<id>` ref that the mount's first round pushed (main's tip, no record) because receive-pack refuses deletes; no member row results and a retry fast-forwards it. A successful join makes TWO ref updates at a hub: the mount's round, then the record.

MISREADINGS. 'Join retries until it succeeds' (the old PUT /fleet did via the sync loop): it does not, one push, then the caller joins again. 'A refused join is invisible to the master': the master logs the refusal; on a forge-hosted fleet it has no row to hang last_refusal on.

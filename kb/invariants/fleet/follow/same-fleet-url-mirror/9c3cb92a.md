# The browser's sameFleetURL (web/src/fleetText.ts) mirrors Go's sameFleetURL (internal/repos/fleet_host.go); both are held to internal/repos/testdata/same_fleet_url.json, so a change to one must change the fixture and both tests; the browser verdict is a pre-check only

As of PR #530 (4bdcf031). Two implementations compare a typed forge URL with the stored one: Go sameFleetURL (the server's own comparison, which makes POST /fleet/follow answer `unchanged`/credential rather than move) and the TypeScript sameFleetURL in web/src/fleetText.ts (used by FleetFollowFlow in move mode). Both normalise the same way: credentials dropped, scheme and host lowercased, default port (443 on https, 80 on http) dropped, trailing slash ignored, path otherwise exact (case-sensitive, no .git stripping, '//' differs from '/'), and a string that is not a URL with a scheme compared as it is. The shared table is internal/repos/testdata/same_fleet_url.json (rows typed/stored/same). The Go test in internal/repos/fleet_membership_test.go reads it (it trims the typed side as the server and the page do) and requires at least 30 rows; web/src/connectNarrow.test.tsx reads the same file through ../internal/repos/testdata/same_fleet_url.json.

CONSEQUENCE: change the normalisation on either side and you must change the fixture AND both tests in the same PR; adding a fixture row the other side does not satisfy fails that side's test. The fixture, not either implementation, is the contract.

MISREADING: the browser verdict is a PRE-CHECK that only decides whether the Move page says 'The fleet is already on this forge'. The server's `change: unchanged` stays authoritative; a browser 'different' never authorises a move and a browser 'same' never replaces the server check. Query strings and fragments are ignored by both sides (the fixture holds rows for them); do not read 'path exact' as 'query exact'.

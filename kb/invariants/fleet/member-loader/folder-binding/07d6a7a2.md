# The fleet loader counts a member record only when its `agent:` equals the folder directly under members/ (others are skipped and logged once), and fails the whole load on a malformed fleet tree instead of returning fewer members; ValidAgentID refuses '/' so an id names exactly one folder and one certs/<id>.pem

Built in PR #523 (merge commit 3ac59b57). fleetrec.LoadMembersOfTree (internal/store/fleetrec/read.go since PR 08 of the internal/ hierarchy stack; before it, store.loadMembersOfTree in internal/store/fleet_read.go) is the one loader behind the judge (FleetAtMain, LoadFleet), the readers (FleetStatus, /fleet/members) and the audit.

FOLDER BINDING. A record (an .md under the member root that parses as a member record) is loaded only if the folder directly under members/ equals its agent: field. A record whose agent: differs from its folder, or that sits in no folder (directly under members/), is SKIPPED and logged at ERROR once per (fleet, path, blob) through the same malformedLogged latch as a malformed record. So a record one member planted in its own folder for ANOTHER agent (the review's blocker B1) makes nobody ambiguous and pre-empts nobody's rule A, even if it is already on main. The judge side of the same binding is clause 3 of the record-owner rule, which keeps new ones off main. Both use the same parse chain (.md suffix, fact.ParseFact, fact.ParseMember), so a file one sees as a record the other does too. Hiding a real record is not possible: a real record has folder = agent and is never skipped, and only <x> can write members/<x>/.

A MALFORMED TREE FAILS THE LOAD. LoadMembersOfTree runs vcs.CheckTreeShape (formerly checkTreeShape) over the whole tree first and returns an error (`fleet <id>: malformed tree: ...`), never fewer members: go-git's walkers end silently at a malformed directory entry, which would make every member sorting after the bogus entry vanish (see the go-git TreeWalker gotcha). A fleet main that holds such a tree makes the gate unable to run (CheckRange returns an error, exit 2): it fails closed and hides no member.

ValidAgentID REFUSES '/'. pki.ValidAgentID (internal/pki/issue.go) already refused empty, '+', '@', whitespace and control characters; it now also refuses '/', because an id names one folder members/<id>/ and one file certs/<id>.pem, and an id with '/' would name a nested path (TestIssueLeaf_RefusesAnAgentIDThatDoesNotReadBack: alice/x, /alice, alice/). Test-only consequence: testsigner.FixtureAgentID maps a leftover '/' to '-' (reached only through store.TestFallbackAgentID, which returns empty outside testing.Testing()); production never derives an id from a branch name.

MISREADINGS. 'The loader trusts the record's agent: field alone' is false since #523: the folder must agree. 'A skipped record is an error' is false: it is logged once and ignored, so one bad file cannot lock the fleet. 'The loader skips a malformed tree' is false: only a malformed RECORD is skipped; a malformed TREE fails the load.

# FleetStatus.record_state is computed by ONE rule, recordStateOf: the own record on the agent branch but not on main in the same state is `pending`; on main in the branch's state (or on main only) it is main's state, `revoked` when main's CRL lists the leaf; on neither it is absent

RULE (PR #532, verified at a1b0ca5d; recordStateOf in internal/repos/fleet.go; the user's ruling is in kb/decisions/fleet/membership/join-pending-vs-accepted). Inputs: the own record at the head of this instance's agent branch (onBranch), the record on the fleet's MAIN as written (onMain), and whether main's CRL lists the leaf. (1) On the branch AND (main holds none OR main holds it in another state, e.g. a rejoin's `active` while main says `left`): `pending`. (2) Else on neither: no record_state (omitted; before #532 this read pending). (3) Else main's CRL lists the leaf: `revoked` (derived, never written: kb/decisions/fleet/derived-revoked/504782ff.md). (4) Else main's state (`active`, `left`). If main cannot be read and the record is on the branch: `pending`. The inputs are STATES, not blobs: a newer branch version that differs only in advertised fields leaves the state active and sets record_pending_update (onBranch AND onMain AND state not pending AND blobs differ).

READERS, all through FleetStatus.RecordState: GET /fleet, the POST /fleet/join answer (the same FleetStatus), the CLI (`record: pending (...)`, `record: X (on the fleet's main)`, `record: none`), the wizard landing (FleetMembers: 'Join pending' tone ask until record_state is present and not pending, then 'Joined the fleet' tone good, following the poll), Fleet Settings, the rail chip, and createdFleetStatus (wants active). On the hub the master merges on receive, but the joiner's own copy still reads pending until ITS next round fetches main.

MISREADINGS. (1) `state: registered` in the join answer is acceptance: no, it only means the fleet repository is here. (2) pending is a refusal or an error: no; a refusal after the push never reaches the joiner (gotcha kb/gotchas/fleet/join/refusal-invisible-to-joiner). (3) record_state sees `enrolled` rows: no, it reads member RECORDS only. (4) A member's chip follows ITS OWN copy of main on the sync interval (kb/gotchas/fleet/member-view-lag/4c144c40.md).

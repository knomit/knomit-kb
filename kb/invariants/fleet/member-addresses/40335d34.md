# A fleet member's addresses come ONLY from the operator's top-level knomit.toml `external_addresses`, copied verbatim: never derived from host, port, auth.loopback_hosts, hostnames or certificates, and never probed

knomit.toml top-level `external_addresses` (config.Config.ExternalAddresses, beside host/port, not under [auth]) is the list of URLs PEERS use to reach this instance, not what knomit listens on: e.g. knomit listens on 127.0.0.1:19278 while peers reach it through `tailscale serve` at https://h1v302.tail5113a7.ts.net (443). Only the operator knows that mapping, so only the operator writes it (user ruling 2026-09-28: "no, no magic guesses. could we instead have this defined in knomit.toml"). Validation at boot (validateExternalAddress, next to the loopback_hosts check): scheme://host[:port] only, any scheme (http, https, knomit+https...), no path (not even `/`), query, fragment, userinfo or whitespace; a bad entry fails the boot naming itself. Default empty; empty is valid: registration still succeeds with `addresses: []` and a notice.

CONSEQUENCES: the member record's `addresses` line is exactly this list (TestFleetRecord_RegisterCopiesAddressesVerbatim asserts no loopback_hosts, bind host or listen port leak in). Capabilities are likewise only host-DETECTED values (os/arch from the Go runtime, version.String(), read_only); there is no instance-wide subscribe-only flag (subscribe is a per-repo origin mode), so none is advertised.

MISREADINGS: this is NOT a probe or reachability claim — nothing checks that an address answers (probe-before-use belongs to its future consumers, F13/F16). And it is NOT auth.loopback_hosts: those are Host-header names a same-host proxy forwards, a security setting; listing a name there must never make it an advertised address.

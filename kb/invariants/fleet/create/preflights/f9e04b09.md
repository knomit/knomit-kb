# Fleet create's pre-flights all run before any write: recover an unfinished create, then fleet_present, trust_installed, root_present, a valid agent id and ssh-ed25519 key, then listener_required + addresses_required (no origin) or knomit_origin (origin) and the repo create's own checks; a knomit+https origin is refused because the hub is always the master

PR #518 (merge 537f2019), fleet_create.go fleetCreatePreflight. Nothing is written (no marker, no key, no repository) until every one of these has passed; each refusal is a FleetError with a machine-readable code, and the message names an existing way out.

ORDER: (0) recoverFleetCreate: a marker left by a create that did not finish is rolled back first; if that rollback fails the answer is create_unfinished (409). Then:
- fleet_present (409), when ANY of (PR #525: the check is `refuseFleetPresent`, shared with the join, and the `unregistering` case is gone with that state): fleet_state is not standalone (leave first: POST /api/v1/fleet/leave), a fleet repository is mounted although the state is standalone (a join that did not finish: POST /api/v1/fleet/leave removes it), or a fleet repository uid is recorded in instance_fleet_repo but not mounted (archive it with DELETE /api/v1/repos/<name> if listed, then DELETE /api/v1/archived/<uid>).
- trust_installed (409), when ANY of root.crt, crl.pem or instance.crt exists in [tls].dir (Lstat): this instance holds another fleet's certificate, which a create would replace. Way out: move those three files out of [tls].dir.
- root_present (409), when <home>/fleet exists AND is not empty. An absent or EMPTY <home>/fleet passes. This is stricter than checking root.key alone, on purpose: the create moves its staging root into <home>/fleet and its rollback removes the root it made, and neither may ever touch a directory that holds someone's root.
- the instance's agent id is valid (pki.ValidAgentID) and its key is ssh-ed25519 (a signer is present).
- NO origin (this instance hosts): listener_required (422) when [tls].addr is empty, addresses_required (422) when external_addresses is empty (`refuseNoHubListener`, shared since PR #525 with the master's detach of the fleet repository's origin; its text now ends 'then run `knomit reload`'). Only 'is it set' is checked, not 'is the listener open'.
- ORIGIN given: knomit_origin (422) when the URL is a knomit+https fleet URL (pki.IsFleetURL, case-insensitive). The message: a knomit-hosted fleet is hosted by its master, so create it without an origin or give a forge URL. A fresh root's holder is the master, and the master is the hub (no origin) or the one that publishes main to a forge; a knomit+https origin would name a host that is not the root holder.
- then the repo create's own CreatePreflight: valid name, origin not already in use, the origin reachable (the probe is the only I/O), a branch to cut from, not already a knowledge base. These come back as the ordinary create errors (not FleetErrors).

Only after all of them: the marker is written (kb/invariants/fleet/create/marker-and-rollback).

MISREADINGS. 'trust_installed is about root.crt': it is any of the three files. 'root_present is about root.key': it is any entry in <home>/fleet. 'listener_required means the mTLS listener is up': it means [tls].addr is configured; a listener that was off at boot for lack of a certificate stays off after create. 'A knomit-hosted fleet cannot exist': it can, with no origin; only a knomit+https ORIGIN on create is refused. 'These pre-flights make the create safe against a concurrent one': they do not; the lock does (kb/invariants/fleet/create/fleet-op-lock).

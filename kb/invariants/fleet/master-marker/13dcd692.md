# artifacts/fleet/master (fact.FleetMasterPath) on the fleet's main names the ACTING master's agent id on one line: create and Host here write it, Stand down deletes it (no file = no acting master), a fleet without it gets it once from the root holder's round; it is a marker for readers and Host here's check, NOT a credential: isFleetMaster still decides by the root key

RULE (branch fix/fleet-switch-replay, verified at a78d1b22; re-pin at the merge commit). Format: the agent id and a newline, nothing else (fact.RenderFleetMaster / ParseFleetMaster; the fleet ontology declares fleet/master, max_size 1KiB).

WRITERS (all on the master's agent branch, then main): (1) CreateFleet, after the host record (the create's last commit); (2) Host here (hostFleetHere), after the detach, naming this instance (a confirmed takeover overwrites another instance's marker); (3) claimFleetMasterOnce, the once-only claim for fleets created before the marker: the hub's fleetHostRound and a forge master's origin round (fleetPeers.claim -> fleetMasterClaimRound), only while actsAsFleetMaster, and only when main AND the agent branch hold no marker (a marker naming anyone is never overwritten there). DELETER: Stand down (deleteFleetMaster), only when the marker names this instance and this instance does master work; it then publishes main (a retry after a failed publish publishes the deletion it already committed).

READERS: GET /fleet acting_master (absent = no acting master); Fleet -> Settings 'Acting master' row ('no master'); Host here's check refuseOldMasterActive: on this copy's main, no marker or one naming this instance proceeds, one naming another instance is 409 old_master_active unless confirm_loss.

JUDGE: the existing host-record rule (store judge.hostRecord, entry only: receive-pack and the forge fetch judge) refuses any member-branch commit that changes artifacts/fleet/master, as it does artifacts/fleet/host. No other rule reads it; CheckRange admits the master's own marker commits (declared artifact).

CONSEQUENCES. (a) A stood-down master never resumes by itself: Stand down deleted its root key, so isFleetMaster is false. (b) A master that was replaced while it was down (the confirmed takeover) still holds the root and its own main still names it; it pauses only once it points at the new host (fleetMasterPause not_hosting). (c) Switching back is the same protocol (TestFleetMasterSwitch_StandDownFirst runs A -> C -> A).

MISREADINGS. (1) 'The marker makes an instance the master': no, isFleetMaster is unchanged (root key + root.crt on main). (2) 'No marker means a broken fleet': no, it is the stood-down state, or a fleet whose root holder has not run a round since upgrading. (3) 'A member can name itself master by writing the file': no, the host-record rule refuses it at entry.

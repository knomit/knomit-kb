# artifacts/fleet/master on the fleet's MAIN names the master (user ruling 6, 2026-10-16): isFleetMaster = holds the root AND main's marker names this instance; a root holder main does not name does no master work on any hosting; while main names no master, root holders are candidates and the first claim published to main wins; stand-down and a forge decommission delete it

RULE (branch fix/fleet-switch-replay, verified at c86b0d6e; re-pin at the merge commit). Format: the agent id and a newline, nothing else (fact.RenderFleetMaster / ParseFleetMaster; fleet ontology fleet/master, max_size 1KiB).

WHO IS MASTER (ruling 6, verbatim: "If each puts their own key in their own branches, it means they're both candidates. Whoever the merge sets in main, that is the true master, and the second one will be demoted to a member."). Manager.isFleetMaster = holdsFleetRoot (root key file here AND root.crt equals main's root) AND fleetMasterOn(main) == this agent id. Every master duty asks it (through actsAsFleetMaster, which also requires no fleetMasterPause): the merger, the forge round's admit and publish (publishesFleetMain, plus the #518 arm: root and marker on the agent branch while main never held the root), enroll/revoke/decommission (masterFleet), the hub's host-record round, the ontology refresh. A root holder main does not name merges, admits, publishes, enrolls, revokes and writes nothing (GET /fleet master false, root_held true).

CANDIDATES AND THE RACE. fleetCandidate: holdsFleetRoot, main names NO master, and the copy does not follow another instance (cert origin: that copy becomes master only by Host here). A candidate claims in its round after the fetch (claimFleetMaster): on a FORGE one commit, main's tip plus the marker naming itself, is pushed straight onto the forge's main WITHOUT force (store PublishUpstreamChange); the agent branch is never touched, so a loser (the push is refused: not a fast-forward of the main it had) keeps nothing, its next fetch shows another name, and it is a member with a clean branch. On the HUB the claim is a commit on its agent branch that its own main follows (it always lands). Fleets created before the marker are claimed the same way by their root holder.

WRITERS/DELETERS: CreateFleet (last create commit); Host here (after the detach, naming this instance; overwrites another name only after confirm_loss); the candidate claim; Stand down (deleteFleetMaster: on the hub a commit on the agent branch then local publish, on a forge one commit straight onto the forge's main); a forge Decommission (user ruling 7: the deletion is published BEFORE the fleet is removed here, refused decommission_unpublished otherwise, so another root holder can take the fleet over; a hub decommission is unchanged).

REPLAY: the fleet repository sets store SetReplaySkipPaths(fact.FleetMasterPath): a rewind replay never carries a commit that changes only the marker, and rebuilds the branch on the new upstream when it dropped one. So a demoted copy never re-submits its own claim or its stand-down (the dead-master fallback 'stand down before pointing' trap and the legacy returned-master claim are clean now).

READERS: GET /fleet acting_master, master, root_held; Settings 'Acting master' row; Host here's check (refuseOldMasterActive: no marker or self proceeds, another name is old_master_active unless confirm_loss).

JUDGE: unchanged except the path list of the host-record rule (entry only) includes the marker.

MISREADINGS. (1) 'Holding the root key makes an instance master': no, main must name it. (2) 'No marker means the old master stood down': on a fleet created before the marker it also means 'never written'; Host here then asks no confirm (the user's rule: absent -> proceed). (3) 'Two root holders on a forge can both act as master': no, the one main does not name does no master work; their claims race and git decides. (4) 'Two masters are now impossible': a master that is down cannot learn it was replaced (dead-master fallback) and acts on its own stale hub main until it points at the new host; it is then demoted.

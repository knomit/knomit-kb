# A master switch FLUSHES first: GET /fleet/root (root export) and DELETE /fleet/root (stand-down) on the acting master publish its fleet branch and refuse with 409 unpublished_changes while main still lacks any commit of it; the dead-master fallback (Host here with confirm_loss) knowingly loses those commits

RULE (fleet PR8b, branch feat/fleet-tick-renewal; user ruling as relayed 2026-10-17: "flush" all changes, "block any new incoming changes, THEN give up the master role"). `flushBeforeSwitch`, called under fleetOpMu by `FleetRootFiles` (GET /fleet/root) and `StandDown` (DELETE /fleet/root, which also holds the consensus merger's run lock), on the ACTING master only (actsAsFleetMaster):
1. `publishMasterWrite` (forge: push the agent branch, publish main; hub: main follows locally);
2. `fleetBranchPublished`: the agent branch tip must be main's tip or an ancestor of it (Triggers().IsAncestor);
3. otherwise 409 `unpublished_changes` with a plain message ("Let the publish succeed first ... then try again"); StandDown keeps the root and main's master marker.
The master duties TryLock fleetOpMu, so nothing new is written meanwhile.

WHY (PR #537 re-review R1). A forge stand-down publishes ONLY the marker deletion straight onto the forge's main (deleteFleetMaster -> PublishUpstreamChange); the agent branch's other commits stayed behind. A revoke whose publish had failed then never reached the main the new master worked from: its renewal re-certified the revoked member, or its CRL re-sign took the same Number and the old revocation could never land (crl-newer). The reviewer's probe is kept as internal/repos TestFleetSwitch_AnUnpublishedRevokeSurvivesAMasterSwitch (fails with the pre-fix code: renewal-due and CRL-due cases leave bravo unrevoked); TestFleetSwitch_ExportAndStandDownWaitForTheFlush pins the refusal.

CONSEQUENCES.
- A root holder cannot claim while main still names the old master (fleetCandidate needs a main naming no master); taking over WITHOUT the old master's stand-down is Host here with `confirm_loss` (the dead-master fallback, hub path), which knowingly leaves out whatever the old master never published. KNOWN GAP, not recovered: a revocation made by a master that then died unpublished is lost; revoke again on the new master. If the old master later returns and pushes its branch, its unpublished CRL (Number N+1) is refused by the judge's crl-newer rule against the new main's equal or later Number, so it can never un-revoke or replace a newer list; it is refused, not merged.
- This SUPERSEDES the 2026-10-16 "no flush" wording of kb/decisions/fleet/master-switch/stand-down-first/9efa08ef: stand-down still comes first, but it flushes before giving up the role.

MISREADING. "Stand-down needs nothing first": it needs the fleet branch published; on a forge that is unreachable it is refused.

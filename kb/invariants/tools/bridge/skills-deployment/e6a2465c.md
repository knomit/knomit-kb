# Knomit skills are deployed by `kb claude init` from embedded templates in tools/bridge/skills/templates — never edit .claude/skills/ directly

The source-of-truth for the `/knomit-*` slash commands is `tools/bridge/skills/templates/<skill-name>/SKILL.md`. It is its own package, `tools/bridge/skills` (`//go:embed all:templates` as `skills.FS`, `skills.Root = "templates"`), because the templates are shared by every agent host (claude, antigravity) and `//go:embed` cannot reach a sibling directory (moved there in PR #98). `kb claude init` (tools/bridge/claude/init.go) walks `skills.FS` and writes each file to `.claude/skills/<rel>` in the target project. The OTHER Claude templates — `CLAUDE-md-block.txt`, `settings.json.tmpl`, `mcp.json*.tmpl` — stay in `tools/bridge/claude/templates/` and are walked separately. There is no `tools/bridge/claude/templates/skills/` any more; a path naming it is stale.

Deployment semantics (init.go):
- **Owned files** (`.claude/skills/**`) — ALWAYS overwritten on re-run. `isOwnedByIntegration` matches the prefix. Delete + re-run init = restore.
- **Merge-required files** (`.mcp.json`, `.claude/settings.json`, `CLAUDE.md`) — since the init-merge work (PR #213) init MERGES into an existing file and replaces the versioned CLAUDE.md block in place; a `<file>.knomit` companion survives only for the narrow cases named in the init-merge decision. Earlier behaviour was to always drop a companion when the destination existed.

WORKFLOW for adding/editing a knomit skill:
1. Edit/create `tools/bridge/skills/templates/<name>/SKILL.md`.
2. If adding a NEW skill that changes the workflow narrative, update `tools/bridge/claude/templates/CLAUDE-md-block.txt` too.
3. If the skill needs a new hook, also edit `tools/bridge/claude/templates/settings.json.tmpl` (hook commands are spelled `kb claude hook <event>`) and add the corresponding Go handler in `tools/bridge/claude/hook_*.go` (wired through `hook.go`'s `runHook` dispatch).
4. Rebuild the bridge (`go build` / `make`).
5. Re-run `kb claude init` in the target project to deploy. Owned files overwrite; merge-required files merge. In THIS repo the deployed `.claude/skills/` copies are checked in, so a template edit must also land in the matching `.claude/skills/<name>/SKILL.md` in the same commit (they are byte-identical to what init would write), or the repo's own sessions run stale skills until someone re-runs init.

ANTI-PATTERN: writing skill markdown directly under `.claude/skills/` in a project and not in the template. It will work for that project until the next `kb claude init`, which overwrites it. Always update the template source so the change propagates to all projects on next init.

Template variables available inside any template: `{{.RepoName}}`, `{{.Source}}`, `{{.Profile}}` (passed to `text/template` by `runInit` in init.go). Skill SKILL.md files generally don't use these — they're plain markdown — but they CAN.

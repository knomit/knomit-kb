# Knomit skills are deployed by `knomit-bridge init` from embedded templates — never edit .claude/skills/ directly

The source-of-truth for the `/knomit-*` slash commands is `tools/bridge/claude/templates/skills/<skill-name>/SKILL.md`. The Go binary `knomit-bridge init` embeds these via `//go:embed all:templates` in `tools/bridge/claude/init.go`, then walks the FS and writes them to `.claude/skills/` in the target project.

Deployment semantics (init.go):
- **Owned files** (`.claude/skills/**`) — ALWAYS overwritten on re-run. `isOwnedByIntegration` matches the prefix. Delete + re-run init = restore.
- **Merge-required files** (`.mcp.json`, `.claude/settings.json`, `CLAUDE.md`) — if the destination exists, init drops a `<file>.knomit` (or `CLAUDE.md.knomit-block`) companion next to it instead of overwriting, so the operator merges manually.

WORKFLOW for adding/editing a knomit skill:
1. Edit/create `tools/bridge/claude/templates/skills/<name>/SKILL.md`.
2. If adding a NEW skill that changes the workflow narrative, update `tools/bridge/claude/templates/CLAUDE-md-block.txt` too.
3. If the skill needs a new hook, also edit `tools/bridge/claude/templates/settings.json.tmpl` and add the corresponding Go handler in `tools/bridge/claude/hook_*.go` (wired through `hook.go`'s `runHook` dispatch).
4. Rebuild the bridge (`go build` / `make`).
5. Re-run `knomit-bridge init` in the target project to deploy. Owned files overwrite; merge-required files drop companions.

ANTI-PATTERN: writing skill markdown directly under `.claude/skills/` in a project. It will work for that project until the next `knomit-bridge init`, which overwrites it. Always update the template source so the change propagates to all projects on next init.

Template variables available inside any template: `{{.RepoName}}`, `{{.Source}}`, `{{.Profile}}` (passed to `text/template` by `runInit` in init.go). Skill SKILL.md files generally don't use these — they're plain markdown — but they CAN.

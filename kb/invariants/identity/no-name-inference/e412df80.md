# No production decision infers an identity or any part of a fingerprint from a NAME (agent id, branch, author email, cert SAN, file name): identity is the SSHSIG signer key, the mTLS cert key, member records (agent/key), and the persisted instance_identity (agent_id, branch, host)

Designer rule D18, enforced by P1b. Where each identity now comes from:
- Commit author: store.Service.SetAgentID(instance_identity.agent_id), set at every SetSigner site (repos stages and lifecycle, the origin wizard's replay store). repoHandler.ownAgentID returns it; with none set a production store refuses the write (ErrNoAgentID) before any object is written. deriveAgentID and store.AgentIDOf are deleted.
- Own fleet member record: repos.Manager.AgentID() (= Deps.AgentID, from the persisted row).
- Trigger {agent}/{host}: fact.TriggerIdentity built by the Manager from Deps.AgentID and Deps.AgentHost; {fp8} is gone (unknown placeholder).
- Certificate: Identity.Fingerprint is computed from the leaf's public key. The certificate NAMES the agent id: its one email SAN is <agent id>@agents.knomit.io (PR #514; the old knomit://<role>/<label> URI SAN and 'nothing compares the label' are gone). The id is BOUND, not parsed: pki.AgentIDOfEmail (domain exactly agents.knomit.io, local part, drop +<op>, ValidAgentID) is the one string operation, and its result is compared for EQUALITY with the commit author's id, the members/<id>/ folder, the leaf's file name and the record's agent: field (kb/invariants/pki/agent-id-binding/efad10db.md).
- Pushed-branch classification: exact equality with ri.agentBranch (the persisted branch).
- Receive-pack: no ref is owned by anyone; signer = pusher compares full fingerprints.

CONSTRUCTION IS ALLOWED: app.newIdentity BUILDS host, id = <host>-<fp8> and branch = agent/<id> once at first boot; repos.ResolveIdentity persists all three and every later boot reads them back. Nothing parses them back out of each other.

TEST-ONLY EXCEPTION: inside a test binary, store.SetTestFallbackAgentID (installed by testsigner.Install and store's TestMain) maps a fixture's branch to 'branch minus agent/' so the ~300 fixtures that pass only an agent branch keep matching their member records. test/archtest TestFallbackAgentIDOnlyInstalledFromTests keeps production source from naming the setter.

ALSO REMOVED in the same PR: app.AgentSlug (turned a branch into a category key by stripping agent/; no production caller) and the web's getAgentBranch fallback that took the first agent/* branch as this machine's (web/src/api.ts): the UI now uses the server's RepoDetails.agent_branch (the persisted branch), for a subscription its read_branch, or, failing both, only an unambiguous single-branch list, else it throws. (Follow-up, not in #513: drop the single-branch-list fallback and show the error instead.)

WHAT IT DOES NOT MEAN: the ONE remaining name-shaped helper is display only: web/src/utils.ts shortBranch trims a trailing -<8 hex> from a branch LABEL in the branch picker; it decides nothing. An 8-hex label derived FROM A KEY (FleetRootLabel, pki.Short in messages) is not inference either. An id or branch may still contain the fp8 as construction. The agent/ prefix is still read as a NAMESPACE (receive-pack, pushed-branch listing), never as an identity.

CORRECTION (PR #514, user ruling): D18 bans PARSING an identity out of a name (no fp8, nothing derived, no fingerprint recovered from an id), NOT BINDING a name to a key. The agent id is opaque but it IS the unique identity of a fleet member; the certificate, the commit author, the folder and the record must carry the SAME id, compared byte for byte, and the id's key is still the key the record and the leaf name. #513 misread D18 as 'the certificate must not name the id'. MISREADING TO AVOID: 'no identity from a name' does not mean a name is never looked at; it means an id is never decomposed. Ids are lower case and nothing is case folded.

# The agent branch (and so the commit author id) is computed ONCE and persisted in control.db instance_identity; every later boot reads it, so a key rotation or hostname change keeps the id; recreating control.db is a fresh start

F09 PR 5 (D1, user ruling). Before: app.go re-derived agent/<host>-<fp8> from the current key and hostname at every boot, so rotation changed the id. Now app.New calls repos.ResolveIdentity(cfg.Home, agentBranch(fp)): it opens control.db through OpenRegistry (the one migrate path), returns instance_identity.branch if the row exists, else writes the derived value (agent_id = store.AgentIDOf(branch)) and returns it. The author id follows because it is derived from the branch (store.AgentIDOf / deriveAgentID).

Consequences: the fp8 inside the id is inert decoration; nothing in verification parses it. Deleting control.db recomputes the id as before (same id if key and hostname are unchanged) and the instance must re-register with its fleet. The same row carries the fleet state machine (fleet_state standalone|registering|registered|unregistering, since, registered_at, last_attempt, last_error).

Test: TestBoot_AgentIdentityIsPersisted boots twice with the key file replaced; it goes red if app.go re-derives.

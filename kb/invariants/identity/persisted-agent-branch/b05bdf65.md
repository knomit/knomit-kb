# The agent branch (and so the commit author id) is computed ONCE and persisted in control.db instance_identity; every later boot reads it, so a key rotation or hostname change keeps the id; recreating control.db is a fresh start

F09 PR 5 (D1, user ruling). Before: app.go re-derived agent/<host>-<fp8> from the current key and hostname at every boot, so rotation changed the id. Now app.New calls repos.ResolveIdentity(cfg.Home, fresh) with fresh = app.newIdentity(fp): it opens control.db through OpenRegistry (the one migrate path), and returns the stored (agent_id, branch, host) if the row exists, else writes fresh and returns it. agent_id is the id BUILT by app.newIdentity (<host>-<fp8>), not derived from the branch (store.AgentIDOf and deriveAgentID are deleted, PR #513, D18). The author id does NOT follow from the branch: the author of every commit is Service.SetAgentID(agent_id), plumbed via Deps.AgentID. The host is stored in instance_identity_host (kb/architecture/identity/persisted-host-label/aaede5b4.md).

Consequences: the fp8 inside the id is inert decoration; nothing in verification parses it. Rotation keeping the id no longer contradicts receive-pack (the fp8-suffix rule is gone, no branch is owned). Deleting control.db recomputes the id as before (same id if key and hostname are unchanged) and the instance must re-register with its fleet. The same row carries the fleet state machine (fleet_state standalone|registering|registered|unregistering, since, registered_at, last_attempt, last_error).

Test: TestBoot_AgentIdentityIsPersisted boots twice with the key file replaced; it goes red if app.go re-derives.

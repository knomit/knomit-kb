# The remote repo-event fires only when a persisted status column changes: the row before the round is compared with the row re-read after it, never in-memory counters

`runReconcileLoop`'s `doTick` defers `publishRemoteEdge(events, svc, prevSync, prevPush, &lg)` right after the "both breakers skipped" return. `events` is a `remoteEdgeSink{hub, name func() string}`, and the name is read when the event is published, never captured when the loop starts. `RenameRepo` does not restart the loop, so a captured name would stamp the OLD name on every later edge (pinned by `TestRemoteEvents_CarryTheNameAtPublishTime`).
- `prevSync`/`prevPush` come from `fresh.LastStatus/LastPushStatus`, snapshotted before Sync/Push overwrite the columns.
- The "after" value is a fresh `GetRemote("origin")`.
- It publishes a `RemoteEvent` only when either value differs.

Consequences:
- Steady state is silent, whether healthy or failing.
- After a server restart, the first healthy round over a row that still says `error` publishes the recovery edge, because the prior value is the row and not the zeroed `syncFails`/`pushFails` counters.
- A step that writes no status (the `refusePush` test hook, an abandoned tick) publishes nothing, so the stream and `GET /repos` agree by construction.
- A round where both breakers are open attempts nothing, writes nothing and re-reads nothing.

WHAT THIS DOES NOT MEAN:
- It is not "publish on every successful tick". `TestRemoteEvents_EdgesOnly` and the web `TestRepoRemoteEvents_EdgesOnly` pin a second healthy round as silent.
- It does not cover status writes made OUTSIDE the loop: the connect commit's push in `lifecycle.go` and the fleet push in `fleet.go`. The next loop round snapshots the already-changed value, so those changes never become edges. The client's list refetch (after a connect, and on every `/repo-events` reconnect) is the fallback.

Testing note: assert "no frame" by publishing a marker on the same hub (or triggering a later `index` event) and waiting for it; goob delivers to one subscriber in publish order.

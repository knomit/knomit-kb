# A remote status that goes error→ok MUST broadcast sync_ok/push_ok even when nothing moved — the UI banner has no other way down

The reconcile loop (runReconcileLoop.doTick, internal/repos/sync.go) used to broadcast `sync_ok` only when `mainChanged || agentChanged`, and `push_ok` only when `pushResult.Pushed`. Both are one-shot SSE events that are never replayed. The web client raises `state.remoteError` on `sync_error`/`push_error` and lowers it ONLY on a clean remote event.

Consequence: a transient outage (DNS blip, expired-then-refreshed token) that healed on a tick with nothing to pull or push emitted NO event, so the banner stayed up for the life of the window — while `remotes.last_status` in SQLite already read `ok`. Observed 2026-08-04: desktop window showing "Remote sync failed — dial tcp: lookup github.com: no such host" hours after `select last_status from remotes` returned `ok`. A freshly loaded web tab looked fine, because a fresh client starts with `remoteError: ''` — which is exactly why this reads as "the desktop is broken" rather than "the event is missing".

RULE: any tick that ends in success while the PERSISTED prior status was `error` must broadcast, regardless of whether anything moved. The edge is computed from `fresh.LastStatus` / `fresh.LastPushStatus` snapshotted BEFORE Sync/Push run (their deferred `updateRemoteStatus` overwrites the column on the way out), NOT from the loop's in-memory `syncFails`/`pushFails` counters — those start at zero after a server restart, where the recorded status is still `error`. See `shouldBroadcastSyncOK` / `shouldBroadcastPushOK` / `remoteStatusIsError`.

WHAT THIS DOES NOT MEAN: it is not "broadcast sync_ok on every successful tick". A steady-state tick with nothing to do and no prior failure stays silent — that quiet is deliberate, and the recovery edge fires at most once per outage because Sync/Push write `ok` unconditionally on success.

The same shape is a general trap: any UI latch raised by a one-shot event needs either a broadcast recovery edge or a poll-able source of truth. Both were added here — the client also re-reads `GET /origin` on repo switch, on SSE reconnect, and when the repo manager closes, and clears the banner when that read says ok or reports no remote at all.

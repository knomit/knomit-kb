# The index heal (RepoInstance.planIndex, run by the index stage) MUST cover BOTH the read/agent branch AND upstreamMain for a repo with a stored origin — cfg.Git.Origin is gone, and a ref that does not resolve is skipped

For a repo with an origin, the initial index heal MUST cover BOTH the agent branch AND upstreamMain. Reason: InitFromRemote populates commit_log for both agent/* AND the upstream during clone, but without an explicit index sync the upstream's branch_facts / facts_vec / graph tables would be EMPTY even though the cloned tree has content — and Verify's facts-coherence check correctly fires on the upstream branch. Anti-pattern: assuming clone-time commit_log population implies index population; clone only does git-side work, the SQL index needs an explicit sync per branch.

WHAT "HAS AN ORIGIN" MEANS (PR #73): NOT cfg.Git.Origin — that config key was REMOVED along with the special "core" repo. The test is `r.upstreamMain != ""` (RepoInstance, planIndex), and upstreamMain is read back from the STORED remotes row by rehydrateUpstreamMain (stages.go) (SetRemote never stores an empty branch; DeleteRemote removes the row). Never default upstreamMain to "main": that guess rewrote the persisted upstream and aimed the heal at a nonexistent branch for every master-convention repo.

THE ONE EXCEPTION (PR #73): a branch whose git ref does not RESOLVE is dropped from the heal by dropUnresolvableBranches before any work is scheduled. This does not weaken the invariant — a ref with no tree has nothing for the index to hold — and it is the honest reading of a stored upstream naming a branch this repo does not have (remotes row disagrees with the repository, e.g. a locally-created repo later pointed at a master-convention origin). Leaving it in made Rebuild fail at HeadCommit on every boot, forever. If the reconcile loop later creates the ref, notifyCommit indexes it normally. The AGENT branch is never dropped: a failing Rebuild there must surface as index-failed.

MECHANISM (current; the repoBuilder.setupIndex / openOne / activate sequence of PR #82 was replaced by the repo stage machine): indexStage.Enter (internal/corpus/repos/stages.go) calls RepoInstance.planIndex, which lists the read branch plus upstreamMain (non-empty exactly when a stored origin exists), drops an upstream ref that does not resolve (dropUnresolvableBranches; the read branch is never dropped), and asks IndexManager.NeedsRebuild ONCE PER BRANCH, because the schema version is keyed per branch (see kb/architecture/store/graph-schema-version). The heal then runs as a job on the Index life's goroutine (healIndexBranches), not on the boot path, so the HTTP server / web UI come up IMMEDIATELY instead of blocking on a heavy rebuild. Stale branches are Rebuilt, current ones SyncLocked (never bare Sync - the heal is out-of-band and must hold lockBranch). Only index 0 (the read/agent branch) is fatal: its failure makes the job report errHealIncomplete; an upstream-only failure is logged and retried. Index status (ready|indexing|error with done/total) is reported by the Machine. Any future path that calls InitFromRemote must route through healIndexBranches (or notifyCommit) so neither branch is left unindexed.

UPDATE (E7a, PR #584, merged into dev as 32414d74; test coverage only, the invariant above is unchanged): internal/repos/builder_heal_test.go no longer uses gomock for the index. Its six healIndexBranches tests (TestHealIndexBranches_UpstreamRebuildFailureIsNotOkButIsNotFatal, _AgentRebuildFailureIsNotOk, _RebuildsOnlyTheStaleBranches, _AllRebuildsSucceed, _SyncsWhenNotStale, _AgentSyncFailureIsNotOk) boot a real repo and pass its real *index.Index (healIndexBranches takes the concrete type now that model.IndexManager is deleted). A branch that exists succeeds, a name that exists nowhere fails at the ref lookup, and a recorder on the `graph` phase start (reported once per completed Rebuild, never by Sync) tells a rebuild from a sync. Sabotage reported by the PR author, not re-run by the curator (each fails exactly the tests that pin the property): upstream rebuild failure made fatal, every branch rebuilt, stale branches never rebuilt, agent rebuild failure ignored, agent sync failure ignored.

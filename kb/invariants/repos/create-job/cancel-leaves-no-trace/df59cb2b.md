# Cancelling a create leaves NO trace, and "archived" is a trace: CreateCancelled promises no live instance, no registry row, no database file, no archive row, and no repo_origins / repo_subscriptions row — a running create unwinds through cleanup(), a registered one is removed with Manager.DeleteRepo (Archive then Purge), and a done job is deleted only if m.Get(name) is the very instance that job registered

Manager.CancelCreate(id) (internal/corpus/repos/create_job.go) ends a job in CreateCancelled, and that state is a promise that the repo is not there in any form. Running job: cancelRequested is set, the job's own context is cancelled, state flips to CreateCancelling; Create unwinds at its next step boundary through its own cleanup() (partial .db, registry row). Past m.Add there is no boundary that honours the context (mirrorIndexing only stops narrating), so the worker goroutine in StartCreate checks cancelRequested when Create returns and, if a RepoInstance came back anyway, calls Manager.DeleteRepo(name) = Archive(name) then Purge(uid) in one motion, so no archive row is left to find, restore or forget. Done job (repo live): the same DeleteRepo runs on a goroutine registered with createWg, and ONLY if m.Get(name) is pointer-equal to the instance the job registered — a same-named repo created later is never this job's to remove and answers ErrCreateFinished. Failed or already-cancelled jobs answer ErrCreateFinished (nothing to undo; dismiss is the operation for the row). repo_origins and repo_subscriptions rows go by ON DELETE CASCADE on repos(uid) (internal/engine/store/migrate/control/000001_control_baseline.up.sql, 000002_repo_subscriptions.up.sql), which depends on the control DB opening with `_foreign_keys=on` (internal/corpus/repos/lens.go) — turning that pragma off would silently orphan them and make Origins.ActiveRepoWithURL answer for a repo that no longer exists. If Purge fails after Archive succeeded the job ends FAILED with the reason, never cancelled, because cancelled promises the repo is gone. Enforcing tests: internal/corpus/repos/create_job_cancel_test.go (requireNoTrace covers live/registry/file/archive; TestCancelCreate_LeavesNoOriginOrSubscriptionRow reads repo_subscriptions directly because Origins.Get LEFT JOINs it and would be blind to an orphan; the replaced-repo case pins the same-instance guard); internal/edge/web/handlers_repos_create_cancel_test.go. Misreading to avoid: DismissCreateJob is NOT cancel — it refuses running AND cancelling jobs, and reapCreateJobsLocked skips cancelling jobs even though FinishedAt may already be stamped.

Since #450 an archive also writes a repo_archive_reasons row (DeleteRepo now takes a reason, recorded as source system). It is part of the trace too, and goes with the registry row: its uid FK is ON DELETE CASCADE, the same _foreign_keys=on dependency as repo_origins. If the purge half fails, that reason ("create cancelled after it completed") is what the user sees on the archived row.

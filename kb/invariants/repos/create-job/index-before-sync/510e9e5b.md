# A sync round takes lockBranch(upstream), which the index heal holds while indexing that branch, so the round waits behind it — background on background, harmless; foreground events that would exit Sync (Attach/Detach/Swap) are refused while the index job runs, so the driver never waits on that lock

Rewritten for issue #411. The create-job ordering this fact used to pin (narrate the index, THEN emit `sync` and call ActivateSync) is gone with ActivateSync: Sync is a stage of the mount walk and starts right after Index launches its job, so CREATE_STEPS in web/src/CreateProgress.tsx has NO sync step for any mode, and the create job only observes the index.

THE CONTENTION THAT REMAINS. Sync's first round (and every round) reconciles the upstream under lockBranch(upstreamMain) (internal/store/remote_sync.go). The Index job holds that same lock for as long as it rebuilds the branch (Rebuild self-locks; kb/invariants/store/index/branch-locking). So on a fresh clone the first sync round parks behind the index. That is background waiting on background: nothing the user is looking at waits, and the round proceeds when the branch is done.

WHY IT NEVER REACHES THE FOREGROUND. Every event that would exit Sync while the index runs — AttachOrigin, DetachOrigin (restart Sync) and SwapStore (rewinds to Populate, a no-op there under mount mode none, so Open and everything above re-enter) — is refused with ErrIndexing before its guard runs (kb/decisions/repos/lifecycle/indexing-exclusive-with-attach-detach-swap). Exits that cannot be refused cannot park the driver behind it either: Unmount cancels all affected lives before draining any (kb/invariants/repos/lifecycle/exit-cancels-all-then-drains), so the index job returns at its next batch boundary and releases the lock the parked round needs; a crash restart drains in a waiter goroutine, never in the driver; Rebuild and CancelIndex exit only Index.

Incident history: PR #230 — the create job sat on '95% activating sync' for a whole index because ActivateSync's synchronous reconcile parked on this lock.

Misreading: this does not mean sync is delayed until the index is ready in general — only rounds that touch a branch the index job currently holds wait.

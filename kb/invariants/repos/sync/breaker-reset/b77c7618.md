# Only RepoInstance.credentialChanged resets the origin loop's breakers early: it bumps a reset generation the loop checks at the top of every round; a plain wake (wakeSync) never resets them

The origin loop's fetch and push circuit breakers (breaker.go) are never closed early, with ONE scoped exception: a credential change. RepoInstance.credentialChanged() (credential.go) calls syncBreakers.requestReset(), which increments an atomic generation, and then wakeSync(). runReconcileLoop records the generation at start (seenReset) and, at the top of doTick right after the kick defer and before anything can skip the round, compares it: on a new value it zeroes fetchBrk, pushBrk, syncFails and pushFails, publishes, and logs INFO "reconcile: breakers reset by a credential change". So the woken round attempts both steps at once.

Call credentialChanged for exactly these events: a stored secret's value replaced (Manager.ReplaceSecretValue, for every ACTIVE linked repo), the pasted-credential swap (Manager.ChangeOriginCredential), and, once it exists, a link or unlink. As of the merge of PR 1 (ff756c8d) only the first two call it: linking is refused (errLinkNotSupported, and the endpoint answers 400 to secret_id), so link/unlink wiring arrives with a later PR. Never call it for a URL or branch change, a plain wake, a timer round, or a trigger push: those must keep respecting an open breaker (TestSyncBreaker_PlainWakeDoesNotReset guards this).

What this does NOT mean: the reset does not restart the loop or the Sync stage, and it does not make an auth failure on the next round free; a failing new credential charges the breakers again from zero.

Test seam: RepoInstance.BreakerResetGenForTest(). NewTestInstanceWithDeps carries breakers and a wake slot so the seam works on test instances.

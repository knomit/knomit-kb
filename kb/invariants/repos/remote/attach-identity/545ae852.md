# Every origin attach passes guardAttachIdentity, and every route that chooses a repo's origin requires `operator`: a new origin entry point must send AttachOrigin (or SwapStore) and sit behind requireOperator or RequireLocalVia

RULE (PR #676). Two halves, both load-bearing:
(1) WHO: a route that sets, re-points or removes a repo's origin, or that clones/previews a remote on a repo's behalf, is the host operator's. Today: PUT/DELETE /repos/{repo}/origin, PATCH /origin/upstream and every /repos/{repo}/origin-sessions route behind requireOperator (api/manage/mount.go, web/router.go); the fleet routes that attach origins behind httpx.RequireLocalVia. route_table.golden shows the gate as `require` on those eight routes. A collection-level route (POST /repos create-with-origin, the :probe-* routes, archive restore) is not gated by it because a token reaches it only with an audience covering all of /repos, which already reads every repo; create runs its own one-local-copy checks.
(2) WHAT: an attach is the AttachOrigin lifecycle event, and its guard ends with guardAttachIdentity (internal/corpus/repos/events.go): another ACTIVE repo's knowledge base is refused (repo-id claim, held tip, or the remote branch's root commit), and a remote branch with no merge base with the consensus branch is refused while that branch holds a fact unless the event is AttachOriginReplacing (PUT body replace_main). A disjoint-history connect that replaces the whole store is SwapStore, whose guard (guardSwap) is the swap's one-local-copy site.

CONSEQUENCE: do NOT point a repo at a new origin by calling ConfigureGitRemote / Origins.Set / Remote().SetOrigin directly from a handler (setOriginUpstream does so only for the SAME origin's branch, and is operator-gated); do not add an origin-choosing route outside requireOperator. Re-derive the route list from route_table.golden rather than trusting this one.

MISREADINGS: 'the operator gate makes the identity check redundant': no, the identity check also protects the operator from silently importing another local repo's knowledge base and clobbering its agent branch on the shared origin. 'guardAttachIdentity judges the origin's main on every sync': no, only at attach; the sync loop still trusts the chosen origin's main as fetched (#524). 'An unreadable remote passes': no, unlike CheckOriginOntology, an identity read that fails or exceeds [git].max_probe_bytes refuses the attach.

# Every route that chooses or reads a caller-named origin requires `operator` (or is local-only), and every AttachOrigin passes guardAttachIdentity; PATCH /origin/upstream and create do NOT run that guard, by design

RULE (PR #676, revised after review). Two halves, both load-bearing:

(1) WHO. A route that sets, re-points or removes a repo's origin, or clones, probes or previews a remote the caller names, is the host operator's:
- behind requireOperator: PUT and DELETE /repos/{repo}/origin, PATCH /origin/upstream, every /repos/{repo}/origin-sessions route (api/manage/mount.go, web/router.go), /repos:probe-origin and /repos:probe-initialized (mount.go);
- POST /repos when the body carries `origin` (modes clone, initialize, subscribe): handleHALReposCreate applies the same operator gate after decoding, because only the body tells a create with an origin from one without; a create with no origin stays `write`;
- the fleet routes that attach origins: httpx.RequireLocalVia.
Archive restore (POST /archived/{id}/restore) takes only new_name: it re-mounts the origin row stored for that uid, which an earlier (now gated) attach or create chose, so it chooses nothing and stays `write`. route_table.golden shows the route-level gate as `require`; the create gate is in the handler and pinned by TestOriginEscalation_CreateWithAnOriginNeedsTheOperator.

(2) WHAT. guardAttachIdentity (internal/corpus/repos/events.go, at the end of guardAttach) runs for EVERY AttachOrigin event: PUT /origin, the wizard's shared-history commit, and the fleet move/follow/restore attaches. It refuses another ACTIVE repo's knowledge base (knomit-repo-id claim, an advertised tip another repo holds, or the remote branch's first-parent root), and a remote branch with no merge base with the consensus branch while that branch holds a fact, unless the event is AttachOriginReplacing (PUT body replace_main). It is the ONE one-local-copy site for an attach: the wizard's commit handler no longer re-checks (for a shared-history commit the remote's root is the repo's own, which the unique index already makes unreachable).
Paths that do NOT run it, each with its own reason:
- PATCH /origin/upstream (setOriginUpstream) rewrites only the branch of the SAME, already-chosen origin via ConfigureGitRemote. Decided to keep it out of the guard (not routed through AttachOrigin): the remote was vetted when it was chosen, what it serves is trusted by ruling 3a19b2d3, the route is operator-only, and routing it through the event would also make it exclusive with indexing and restart Sync, a behaviour change outside this fix. Consequence: an operator can point a repo at an unrelated branch of its own origin without the unrelated-history refusal.
- Create (clone, initialize, subscribe) runs the create-path layers instead (CreatePreflight's advertisement layers, then the fresh clone's root before registration; kb/decisions/repos/identity/three-layer-duplicate-refusal/2d0be18a.md). It has no unrelated-history question: there is no main to replace.
- A disjoint-history connect that replaces the whole store is SwapStore, whose guard (guardSwap) is the swap's one-local-copy site.

CONSEQUENCE: do NOT point a repo at a new origin by calling ConfigureGitRemote / Origins.Set / Remote().SetOrigin from a handler; send AttachOrigin (or SwapStore). Do not add a route that chooses or reads a caller-named origin outside requireOperator or RequireLocalVia. Re-derive the route list from route_table.golden and the create handler rather than trusting this one.

MISREADINGS: 'every origin change passes guardAttachIdentity': no, PATCH upstream and create do not (above). 'The operator gate makes the identity check redundant': no, it also stops the operator silently importing another local repo's knowledge base and clobbering its agent branch on the shared origin. 'guardAttachIdentity judges the origin on every sync': no, only at attach (#524 trust). 'An unreadable remote passes': no, an identity read that fails or exceeds [git].max_probe_bytes refuses the attach. 'A collection-audience token may pick origins at create because it reads every repo': no, it reads every REGISTERED repo, not an unregistered knowledge base under local_origin_root (review B1).

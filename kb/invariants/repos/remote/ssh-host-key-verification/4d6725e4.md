# SSH remotes verify host keys against known_hosts: TOFU on first contact, HARD REJECT on a changed key, and no insecure fallback anywhere

`resolveAuth` (internal/repos/auth.go, ssh branch) installs the callback from `hostKeyCallback` (internal/repos/knownhosts.go) on the go-git `PublicKeys`. It previously set `ssh.InsecureIgnoreHostKey()` unconditionally, meaning every SSH clone and every reconcile-loop sync accepted any host key presented — a standing MITM hole on all SSH remotes.

The callback's contract has THREE parts, and dropping any one of them re-opens the hole:
1. UNKNOWN host (not in known_hosts) is ACCEPTED and PINNED — trust-on-first-use, logged with the SHA-256 fingerprint. Syncs run unattended, so the interactive prompt OpenSSH would show is not available.
2. KNOWN host presenting a DIFFERENT key is REJECTED. Detected as a `knownhosts.KeyError` with `len(Want) > 0`. Silently re-pinning here would make the whole mechanism decorative.
3. An UNUSABLE known_hosts path is a HARD ERROR from resolveAuth — it must never fall back to InsecureIgnoreHostKey, which would silently restore exactly what this replaced.

WHAT THIS DOES NOT MEAN: TOFU is not "verification is optional". First contact is the only moment a key is accepted unseen; every subsequent connection is checked against the pin.

Path resolution: `config.RemoteAuthConfig.KnownHosts` (TOML `remote.known_hosts`, env `KNOMIT_REMOTE_KNOWN_HOSTS`), defaulted in config.Load to `<Home>/known_hosts` after tilde expansion. `Manager.ResolveAuth` back-fills it when empty, because `authConfigFromSpec` builds a per-request config carrying only the credential — without the back-fill a spec-driven clone would pin to a different file than the sync loop. With a fully zero-value config (tests, embedded callers) resolveAuth falls back to `<dir of the ssh key>/known_hosts`, never to no verification.

The file is re-read on EVERY callback invocation, so pins written by another connection or by the user are seen without a restart; appends are serialised by a package-level mutex since clones and syncs run concurrently.

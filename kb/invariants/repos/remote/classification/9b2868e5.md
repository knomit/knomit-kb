# pki.ClassifyOrigin fails closed in both directions and an origin stored with method cert is never re-classified: a revoked, expired or refusing peer is an error, never 'not a peer', and a misjudged peer still dies at its own TLS handshake before any request or credential is sent

RULE (verified at merge 0488c05d, internal/pki/client.go ClassifyOrigin, repos/auth.go ResolveOrigin). The answers, in the order the code decides them:
1. the URL uses the internal scheme (any case): error pki.ErrUnsupportedOriginScheme, no dial.
2. not an https:// URL (http, ssh, git@, a path): not a peer, no dial.
3. no root.crt in [tls].dir (this instance holds no fleet trust): not a peer, no dial.
4. ClientConfig fails (trust files unusable): error, no dial. This includes root.crt present WITHOUT instance.crt or the CRL (kb/gotchas/pki/classify/d9157923.md).
5. no TCP connection (refused, DNS, timeout, or ctx expired before our verifier ran): ErrOriginUnreachable (D1). ResolveOrigin wraps it, so callers see repos.ErrOriginUnreachable with the cause reachable by errors.Is.
6. our verifier reported ErrUntrustedRoot (a forge, another fleet): not a peer.
7. any OTHER verifier verdict (ErrRevoked, ErrExpired, a CRL or key error) or the peer refusing our certificate (ErrRefusedByPeer): an error, NEVER 'not a peer'. A revoked peer can therefore never be re-classified onto stock https.
8. a handshake that failed before our verifier ran (no TLS 1.3, not TLS, no certificate): not a peer.
9. a completed handshake that the peer then does not answer as HTTP: an error.

THE TWO MISCLASSIFICATIONS BOTH FAIL CLOSED. A peer judged 'not a peer' (e.g. case 8) is stored with the caller's auth and goes over go-git's stock https, whose system pool never holds a fleet root, so the handshake fails before any request or Authorization header. A forge judged a peer cannot happen: only a certificate chaining to the installed fleet root passes. Against a forge the verifier fails before our client certificate is sent, and no HTTP request is made. ClassifyOrigin uses ClientConfig, the one config the no-InsecureSkipVerify invariant allows.

A STORED cert ORIGIN IS NEVER RE-DECIDED. remoteAuthFromRecord keys on the stored METHOD (cert inherits nothing from the global [remote] credential), never on the URL. pki.GitURL(url, authMethod=="cert") is the only place that maps a stored origin to the internal scheme (resolveAuthWithOrigin and repos.ConfigureGitRemote both call it), and it refuses a URL that already carries the scheme, so an origin stored with it fails at open and sync before any dial. After pki.Uninstall a stored cert origin fails with ErrNotEnrolled and the peer sees no request; with the peer revoked, sync fails with ErrRevoked and the origin stays cert.

CONSEQUENCE for anyone touching it: do not add classification to the sync path, do not key any credential decision on a URL scheme, and do not map a classification error to 'not a peer' to make a flaky network pass. KNOWN WORDING GAP (review nit N9): a forge with an EXPIRED certificate is refused with ErrExpired (x509 checks the date before the root), and the message reads 'presents a certificate of this fleet that is refused', which is imprecise; it still fails closed.

MISREADINGS. 'Not a peer means the host is a forge': it means 'not judged an instance of this fleet', and includes http, ssh and an instance without trust. 'Unreachable and refused are the same': unreachable means no TCP or no completed exchange before the deadline; a refusal means the host WAS reached.

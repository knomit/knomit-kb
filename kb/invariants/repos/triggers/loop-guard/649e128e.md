# The loop guard is decided on the COMMIT, not the advance: a fire is `self-caused` (counted, no `if`, no row, bookmark moves) when the path's toucher carries `Knomit-Trigger: <this trigger's name>`; it applies to tree episodes in `advance` ONLY and NEVER to a `due` fire, so a script may re-arm its own due trigger; chains across triggers pass on purpose

F07's sentence "a write made by a trigger does not re-fire the same trigger on the same path within that advance" is vacuous as written: a script's write is a NEW commit → notifyCommit → triggerKick → the NEXT run, never the same advance. The operational rule (internal/corpus/repos/triggers.go, the matched-trigger loop of `advance`) compares `pendingFire.byTrigger` — the toucher's Knomit-Trigger, read by `changeReader.metaOf` from the same CommitInfo that yields Knomit-Trace and Knomit-Cause — with the trigger being fired: equal → `d.stats.recordSelfCaused(name)` and `continue`. Zero extra I/O; the trailer travels with the commit, so the rule holds after a restart and on EVERY OTHER MACHINE (B's copy of T does not re-run on a write A's T made). A human's later edit carries no trailer and fires; another trigger's write carries ITS name and fires this one.

NEVER on due [M3]: `sweepDue` has no such check. A due fire is caused by time; its toucher is simply the last writer of the fact, so a script that changes its own fact's `expires` ("remind me again tomorrow") would otherwise be self-caused on every later sweep and could never fire again. The due marks (once per trigger, path, instant) remain the only once-rule for due fires; the update episode the script makes IS self-caused (count 1), the due fires are not.

Retract: in a linear advance the deleting commit is the toucher and carries the trailer (self-caused); in a NONLINEAR advance a retract's toucher is the head fallback, which carries no trailer, so the guard cannot see who deleted it and the retract fires once more (at-least-once; TestScript_LoopGuardOnRetract).

Consequences: two triggers whose scripts write each other's paths run forever, bounded only by the per-minute rate cap; a self-caused fire is NOT an evaluation (no `if` ran) and has no duration.

Misreading to avoid: the guard is keyed by trigger NAME, not by "a script wrote this" — a path written by trigger A's script DOES fire trigger B on the same path.

# Trigger watermarks are per (trigger NAME, branch) in trigger_watermarks: first appearance bookmarks the head of that advance (no back-fill), an invalid trigger's bookmark is FROZEN (kept, not advanced), an unsupported trigger holds NO bookmark, and a row is deleted only when the name leaves the ontology

internal/repos/triggers.go phaseA, table trigger_watermarks (migration 000029; 000028 went to F09 PR 5's drop of verify_context, which merged first). The rules, each pinned by a dispatcher test:

1. FIRST APPEARANCE (TestDispatch_FirstAppearanceNoBackfill): an active trigger with no row gets W = the head of the advance where it first appeared, and nothing fires. So facts committed together with the trigger (or merged in the same advance) NEVER fire for it. Renaming a trigger is a new name, so a fresh bookmark.
2. ADVANCE: after a run, every active trigger evaluated against watermark W moves to the head H — written in tx2, AFTER tx1 logged the fires, so a crash between them re-fires the range on restart (TestDispatch_CrashBetweenFireAndWatermark).
3. FROZEN (M3, TestDispatch_InvalidTriggerFreezesNotForgets): a trigger whose name is present but INVALID (a typo, a bad glob, an if that does not compile, an unknown value from a newer knomit) keeps its row untouched; a first appearance while invalid sets W = H and then freezes. When it becomes valid it resumes from the frozen W and fires everything since. The endpoint shows it as `frozen`.
4. UNSUPPORTED (user ruling 2026-09-27, TestDispatch_UnsupportedNoBackfill): a trigger whose values are valid but not acted on in this version (`do: script|push|run`, or any `due` in `on`) holds NO row — an existing row is deleted. When a later version (or an edit) makes it active, it starts at the head of THAT advance: no back-fill, no flood of script runs on upgrade. It is not an error: no warning diagnostic, no ERROR log, state `unsupported` on the endpoint.
5. FORGOTTEN (TestDispatch_RemovedTriggerForgets): a name absent from the head's ontology has its row deleted, so re-adding it never back-fills.
6. A missing watermark commit (garbage-collected) resets W = H with a WARN and fires nothing.

The table is SEPARATE from pipeline_watermarks on purpose: OpenExperiment copies every pipeline watermark onto exp/<name>, and trigger bookmarks must never fork onto a branch nothing fires on (TestTriggerWatermarks_RoundTrip). Rows for branches other than the agent branch never exist.

Misreading: 'a bad trigger is dropped, so its bookmark is dropped' — no; dropping the bookmark is exactly how a typo would silently lose a day of fires (reviewer M3). Only the NAME leaving deletes it.

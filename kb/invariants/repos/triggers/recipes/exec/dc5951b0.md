# `exec` exists ONLY in the recipe tier: os/exec is imported by no non-test file of the repos tree except internal/corpus/repos/trigger/trigger_recipe_exec.go and its _unix/_windows twins, and recipeHostFunctions (script map + exec) is the only place the two host maps differ — a `do: script` sees typeof knomit.exec === 'undefined'

F07 PR 5 [F2]. Pinned by TestRecipe_OSExecOnlyInExecFile (internal/corpus/repos/triggers_run_test.go; a recursive walk of the repos tree that parses every non-test .go file, imports only, and since 14c, PR #632, merged as ee850fd6, expects exactly trigger/trigger_recipe_exec.go, trigger/trigger_recipe_exec_unix.go and trigger/trigger_recipe_exec_windows.go; the child's own recipe_exec_test.go drives recipeExec.call directly with a small helper binary, see kb/gotchas/repos/triggers/testing/recipe-helpers/4cea735c.md) and TestScript_NoExecInSandbox (a script fire sees knomit.exec, exec and globalThis.exec all undefined; a recipe — the positive control — sees knomit.exec as a function). TestScript_HostFunctions / TestScript_NoIOPrimitives still pin the script map at exactly eight names.

exec's contract (trigger/trigger_recipe_exec.go; recipeHostFunctions is in trigger/trigger_recipe.go): argv only (a non-empty array of strings, run as argv[0] with argv[1:], cmd.Args[0] kept verbatim, never a shell, never joined or split; argv[0] without a separator is resolved against the CHILD's PATH); env MERGED over knomit's own plus KNOMIT_SERVER / KNOMIT_HOME / KNOMIT_TRACE / KNOMIT_CAUSE / KNOMIT_RUN (never replaced — `kb` needs PATH to be found and KNOMIT_SERVER to reach THIS server; a key the recipe's `env` names wins, KNOMIT_SERVER included). CORRECTION (2026-10-02): this fact used to say `kb` needs KNOMIT_HOME to reach this server's socket. It never did — `kb` took its server from its argument or the desktop lockfile, and its discovery was plain TCP — so with several instances on one machine a recipe's session reached the lockfile's instance. KNOMIT_SERVER (recipeEnv, from Manager.ServerAddress) is what carries the address now; KNOMIT_HOME still names the instance's folder and chooses nothing. The base env is built PER exec CALL (recipeExec.env is a func): it waits, bounded, for the server's own address and THROWS 'server address not ready' rather than start a child without it (kb/invariants/repos/triggers/recipes/server-address); stdout/stderr capped at 1 MiB each by a writer that never fails (a failing writer stops the copy and the child blocks on a full pipe); WaitDelay 2 s; a start failure or timeout THROWS, a non-zero exit is `exit`.

Consequence for anyone adding a host function: put it in scriptHost.functions() only if a repo script may call it; anything that starts a process belongs to recipeHostFunctions and to the exec file.

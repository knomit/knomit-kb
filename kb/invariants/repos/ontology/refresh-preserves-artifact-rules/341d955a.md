# The boot refresh never adds, changes or drops artifact rules (SubsetDivergence counts them, refreshDivergence adds ArtifactRulesEqual), exactly as it treats root attributes (77ad0332); and since refreshDivergence is also the template preset-identity rule, a template claiming id fleet must carry the preset's root attributes and artifacts section identically

A stored fleet ontology whose taxonomy is a subset of the preset but whose verify_signatures or artifacts section differs is divergence (DivergenceAttributes): the refresh is skipped. Artifact rules are repository policy like root attributes; the refresh commit is signed by this instance and never changes policy.

TEMPLATES: create-from-template refuses a template ontology with a preset's id that refreshDivergence says is not that preset (ErrTemplatePresetID, 422). The knomit-playbooks fleet template must therefore change in lockstep with the fleet preset: knomit/knomit-playbooks#4 and #5 replaced it with the preset, and the knomit submodule pin (third_party/knomit-playbooks) must point at a playbooks commit containing it, or TestCreateFromTemplate_Fleet, TestPostRepos_Template and TestPostRepos_FleetTemplateTitles fail. Editing the template's ontology at all makes create-from-template refuse it.

MISREADING: this is not a migration path; no fleet repos predate the preset change (the feature is new), so an existing repository built from an older preset is simply never refreshed and keeps its stored policy (verify_signatures off unless it wrote one).

Tests: TestRefreshDivergence_FleetPolicyIsNeverAddedByRefresh, TestArtifactRules_AreRefreshDivergence.

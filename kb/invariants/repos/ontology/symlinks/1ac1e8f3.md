# A symlinked ontology (any rung: .knomit/ontology.yaml, .domains/, domains/) is an ERROR naming its path at every reader — never "no ontology", never its link text parsed, and a regular legacy rung does not cover for it

User ruling 2026-10-08, "d": a symlinked ontology.yaml makes the repo fail to open with a clear message. Built in fix/loader-symlinks.

THE ERROR: fact.ErrSymlinkNotFollowed, built by fact.SymlinkNotFollowed(path): "<path> is a symlink, and knomit does not follow symlinks: commit the file itself in its place". Test with errors.Is.

THE RULE: the readers walk fact.OntologyPathsNewestFirst and stop at the FIRST rung PRESENT. If that entry is a symlink, the read fails with the named error. A regular file on a later rung is NOT used instead (that would be a silent substitute taxonomy).

EVERY READER, and what the error does there:
- store.OntologyAtCommit (internal/store/triggers.go): the trigger dispatcher logs it and keeps its last compiled set; the guidance reader (repos/guidance.go) warns once per commit with the message and gives no guidance.
- store.treeOntology / Service.OntologyAt / Service.OntologyFileAt (internal/store/fleet_read.go, pushed_merge.go): fleet membership (LoadFleet, FleetMembersAt, FleetKeysOf), the receive-pack verify mode (verifyModeAt) and the verify range gate return it; the consensus setting reader warns with it and reads as off, the sync setting reader warns with it and reads as interval.
- repos.loadOntology (stages.go, the identify stage) now reads through Service.OntologyFileAt: the repo OPENS readable but unwritable, and RepoInstance.OntologyError() carries the named error (it surfaces wherever OntologyError is shown, e.g. the branches and experiments endpoints).
- repos.branchHasOntology: clone, initialize and subscribe refuse with it.
- repos.ProbeInitialized (the create wizard's remote probe): Initialized is UNKNOWN (the empty field) and Detail is the message.
- okf export (okf/source okfOntologyDoc): degrades to the embedded default, as it does for any unusable ontology, with a warning carrying the message.
- Template create: the template walk refuses it as ErrTemplateNotRegular wrapping the same error.

TWO READERS STILL ABSORB IT, pre-existing and out of this PR's scope: the conflicts setting reader (store/conflict_merge.go) reads ANY ontology read error as off without a log, and the fleet audit (verify_audit.go) maps any ontology read error to ErrNotFleet.

NOT AN ONTOLOGY READER: POST /api/v1/ontologies/validate validates the YAML it is sent, not a git file.

BEHAVIOUR CHANGE WORTH KNOWING: loadOntology used to walk the rungs with ReadFact and skip an EMPTY file to the next rung. It now takes the first rung present; an empty canonical file is "no ontology" even if a legacy rung holds one.

CONTRAST: optional .knomit/ files (trigger scripts, recipes, guidance, skills, system files by path) read a symlink as ABSENT with their existing not-found errors; only the ontology fails loudly.

Tests (each sabotaged red at e21d2191): store TestOntologyReaders_SymlinkIsANamedError, TestOntologyReaders_SymlinkedLegacyRungIsANamedError; repos TestLoadOntology_SymlinkedOntologyFailsTheOpenNamingThePath, TestProbeInitialized_SymlinkedOntologyIsUnknownNamingThePath, TestCreateFromTemplate_SymlinkedOntologyNamesThePath, TestConsensusGuidance_Symlinks; okf TestOntology_SymlinkIsNotFollowedAndIsWarned. Each fixture's link TEXT is itself a parseable ontology, so a reader that parsed it would pass silently.

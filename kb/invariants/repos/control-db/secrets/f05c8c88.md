# control.Secrets never returns a value except through Reveal, and Reveal fails loudly (ErrSecretUndecryptable naming the secret) where Origins.Get falls back to ciphertext-as-plaintext

control.Secrets (internal/corpus/repos/control/secrets.go) is the stored-credential tenant of control.db, opened in Manager.Start right after Origins with the SAME *model.Crypt (Manager.Secrets()).

Rules a consumer must keep:
- Only Reveal returns plaintext. List/Get return SecretMeta (no value) and work even with a nil or wrong Crypt.
- Reveal on a row that does not decrypt returns an error wrapping ErrSecretUndecryptable whose text names the secret by NAME ("stored secret \"x\": cannot decrypt ..."). Never copy Origins.Get's lenient fallback (it uses an undecryptable token as plaintext) into anything that resolves a secret.
- A nil Crypt (instance key unreadable) makes Create, ReplaceValue and Reveal return ErrEncryptionUnavailable; the API maps it to 503.
- control.SecretValue prints and JSON-encodes as "[redacted]" (String, GoString, Format, MarshalJSON), including inside a containing struct printed with %+v or %#v. Read its fields only to authenticate.
- Validation errors wrap ErrSecretInvalid and name the field, never the value.
- basic secrets are stored as user:password (first-colon convention) and Reveal splits them back.

What this does NOT mean: a redacting SecretValue does not make a request struct that holds the raw strings safe to log; only the SecretValue type redacts.

# Every secret-link write re-checks the secret's hosts list inside the same BEGIN IMMEDIATE transaction as the write, and Secrets.Update's host-list change runs in one too, so a link and a host removal can never interleave into a stranded link

control.setLink (internal/corpus/repos/control/origins.go), reached by Origins.Set, Replace, Restore and SetCredential, checks in the SAME transaction that the secret exists (ErrSecretNotFound) and that its hosts list allows the host of the url stored in repo_origins for that repo (ErrSecretHostNotAllowed, naming the secret). Those four writers and Secrets.Update all run under control.immediateTx (control/immediate.go): BEGIN IMMEDIATE on a connection of its own, so the write lock is held before the first read. A host removal (Update's checkHostsKeepLinks) either sees the new link and refuses with HostInUseError, or the link sees the new list and refuses. A linked origin also carries no auth token (errLinkWithToken).

Consequences: an attach (applyAttach) or swap that re-points a linked repo to a host off the secret's list fails on the link write and changes nothing; a caller does not need its own precheck for safety, only for a nicer error (PUT /origin prechecks to answer 422). Rule: code inside an immediateTx callback must use only the tx handle: a call on the *sql.DB waits on the single connection (MaxOpenConns 1) the transaction holds and deadlocks.

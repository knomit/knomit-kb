# Origins.Set is a full replace of URL, branch, credential, Mode AND the secret link: an Origin with an empty SecretID DELETES the repo's repo_origin_secrets row; change only the credential with Origins.SetCredential

A repo's link to a stored secret lives in its own control.db table, repo_origin_secrets(repo_uid PK -> repo_origins ON DELETE CASCADE, secret_id -> secrets ON DELETE RESTRICT), not as a column on repo_origins (control up-migrations admit only CREATE ... IF NOT EXISTS). control.Origin carries it as SecretID, which Origins.Get fills with a LEFT JOIN.

Origins.Set writes the repo_origins row, the subscription row (Mode) and the link (SecretID) in one transaction. Empty Mode deletes the subscription row and empty SecretID deletes the link. So any read-modify-write caller must carry BOTH Mode and SecretID from Get; building a fresh Origin{URL, Branch, AuthMethod, AuthToken} silently demotes a subscribed repo to sync AND silently unlinks a linked repo, with no error and no log. A SecretID with no secrets row makes the whole Set fail on the foreign key and nothing is written.

Origins.SetCredential(uid, url, method, token, secretID) is the credential-only write: it updates auth_method, auth_token and the link in one tx, only WHERE repo_uid = ? AND url = ? (the caller's vetted url), else ErrOriginChanged and nothing is written. URL, branch and Mode are never touched by it.

What this does NOT mean: deleting the origin does not need to clear the link by hand (Origins.Delete and DeleteAttached delete the link row in the same transaction, and the FK cascades as a backstop; DeleteAttached refuses a linked origin unless replaceLink, see kb/invariants/repos/control-db/secret-link/f7d454a9.md), and SetCredential is not a way to change the URL or branch (those go through AttachOrigin/SwapStore).

Attach and swap no longer call Origins.Set directly: applyAttach uses Origins.SetAttached and applySwap uses Origins.Replace, which are Set plus a same-transaction guard that refuses with ErrOriginLinked (nothing written) when the stored origin is linked and the new one carries no SecretID, unless the caller passes replaceLink (OriginSpec.ReplaceLink). Origins.Set itself is unchanged and still silently unlinks on an empty SecretID.

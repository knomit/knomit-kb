# DetachOrigin() refuses (control.ErrOriginLinked, 409 on DELETE /origin) to drop a stored-secret link, checked inside the delete's own transaction; only DetachOriginUnlinking() may drop one, and only after the admin gate or on the local-only fleet routes

A detach removes the repo's origin row, and with it the repo_origin_secrets link. `repos.DetachOrigin()` runs `Origins.DeleteAttached(uid, false)`: in ONE BEGIN IMMEDIATE transaction it refuses with `control.ErrOriginLinked` (nothing deleted) when the repo is linked, then deletes the link row, the origin row and the subscription row. `repos.DetachOriginUnlinking()` passes replaceLink=true and drops the link.

Operational consequence: a handler that reads the stored origin to decide whether the admin gate applies (DELETE /repos/{repo}/origin does) uses that read ONLY to pick the gate. If the read saw no link, it sends `DetachOrigin()`; a link written between the read and the delete then makes the detach fail with 409 'Linked to a stored secret', never silently unlinks. Send `DetachOriginUnlinking()` only after `httpx.Admits(admin, ...)` passed, or from the local-only fleet paths (fleet host takeover, restoreFleetOrigin back to the hub).

applyDetach deletes the git remote first; when DeleteAttached refuses it puts the git remote back (restoreRemote) and leaves the injected origin in memory untouched.

Not meant: `Origins.Delete(uid)` is still unconditional (it is DeleteAttached(uid, true)) and is for tests and callers that already decided to drop the link; do not use it from a request path that has not passed the admin gate. Pinned by TestCarry_DetachRacingALinkIsRefused (hook beforeDetachOriginWrite).

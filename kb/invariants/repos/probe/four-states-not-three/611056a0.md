# An origin probe has FOUR outcomes, not three — auth-required is its own state, and treating it as "not empty" silently routes a private empty remote back into the bug seed mode exists to fix

# The rule

`Manager.ProbeOrigin` returns `{reachable, empty, auth_required, upstream_branch, branches, detail}`. Consumers MUST branch on **four** states:

1. **reachable, has refs** → join it (`clone`)
2. **reachable, empty** → seed it (`seed`)
3. **reachable, auth_required** → NOT YET KNOWN. Ask for credentials and **RE-PROBE**.
4. **unreachable** → no remote to build on

# Why state 3 is the trap

An unauthenticated probe of a PRIVATE repository cannot see whether it is empty. `ProbeOrigin` returns `auth_required:true` with `Empty` at its **zero value, false**. Code that tests `!empty` to mean "has content" therefore classifies every private empty repo as populated — which routes it to `clone`, which seeds the hardcoded default ontology, never pushes, and never starts a sync loop. That is exactly the bug `seed` mode was built to fix, reintroduced silently: no ontology step ever appears, so nothing tells the user their choice was discarded.

This shipped in the create wizard and was caught in final review. The original design modelled only three outcomes and assumed a READ probe's credential needs equal the WRITE path's — they do not. A public empty repo probes fine anonymously but still needs a credential to PUSH, and would have offered no field to enter one.

# Consequences a consumer must act on

- **Send credentials WITH the probe.** `probeOriginRequest` accepts `auth_method`/`auth_token`; a probe without them answers a different question.
- **Re-probe after credentials are entered**, or the step list stays computed from the unauthenticated answer.
- **Never gate the credential UI on `auth_required`.** Credential fields must be available on any remote flow, optional under auto-detect. Hiding them means a public empty repo — which reports `auth_required:false` — offers no way to supply the token its PUSH needs. The form this wizard replaced had that field unconditionally, and its regression test existed BECAUSE hiding it once already broke private HTTPS.
- **`branches` being empty does not mean the remote has none** when `auth_required` is set; it means the listing was refused. Do not render "no branches were found".

# What a probe may never claim

A probe is `remote.ListContext` — REFS ONLY. It cannot report fact counts, commit counts, or the remote's ontology id without a real fetch. No pre-create UI may display them.

# Known gap

`classifyProbeError` maps go-git's HTTP auth sentinels and an SSH message substring to `auth_required`. A host that answers 404-to-hide-existence for a private repo lands in the unreachable arm instead. GitHub answers 401, so the common case routes correctly.

# Related

The probe is advisory, never authoritative: `Create` re-asserts emptiness itself, because refs can appear in between.

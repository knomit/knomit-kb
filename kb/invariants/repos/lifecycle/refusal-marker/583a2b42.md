# repos.IsRefused(err) is true only for an error the lifecycle machine returned BEFORE it queued or applied the event (Machine.Send snapshot refusals, handleExternal refusals incl. every guard result, Manager.Send's ResolveOrigin failures): the caller's own resources are untouched and it may reuse them and retry

repos.Refused(err) wraps an error with a marker (message text, errors.Is and errors.As identity unchanged); repos.IsRefused(err) is errors.As on that marker. It is applied ONLY where the refusal happens before the event is queued or applied: Machine.Send's snapshot refusals (ErrClosed, unavailable, ErrNotOpen, ErrIndexing), handleExternal's refusals and the guard result (guardSwap and guardAttach, before exitStages), and the ResolveOrigin failures in Manager.Send.

Consequence: a caller that handed the machine a resource it had to close first (the origin session's clone.db) may reopen it and retry when IsRefused is true, because nothing touched it. A NEW refusal path in the machine or in Manager.Send must wrap with repos.Refused, or the caller's retry logic silently stays on its 'no remote store' path.

WHAT THIS DOES NOT MEAN: (1) IsRefused true does not mean the error was a guard error rather than an I/O error: a ResolveOrigin or guard TIMEOUT is wrapped too, and a context error INSIDE a Refused wrapper is still refused (an earlier draft excluded these and left #416 in place for them). (2) A bare, unwrapped context.Canceled or DeadlineExceeded from Machine.Send (returned when it stops waiting, after the event may be queued or applied) is NOT refused and must not be reopened on. (3) applySwap failures, the unwrapped ErrClosed on the <-m.done path, and a reply racing ctx in Send are not marked: a session that hits them keeps its clone closed, as before (follow-up to #416, not handled).

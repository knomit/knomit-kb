# A template is refused, by named error and before anything is written, unless: kebab name; source an ACTIVE mounted repo; folder present at the source's consensus tip; only README.md and .knomit/** inside; plain 100644 files only; at most 256 files and 4 MiB; .knomit/ontology.yaml parses as a NEW ontology; no preset id unless it IS that preset; at most one describing fact; a fleet id only with initialize and no fleet already

Each rule and its sentinel (internal/repos/template.go, internal/store/templates.go): name not kebab-case → ErrTemplateName (400); `template.repo` unknown, archived or a lens name → ErrTemplateSourceNotFound (404); source mounted but its store not open (populating, closing) → ErrTemplateSourceUnavailable (503); no folder at the source's consensus tip, no consensus branch yet, or a describing fact with no folder → ErrTemplateNotFound (404); any path other than README.md and .knomit/**, or two paths equal under lowercasing → ErrTemplateLayout; a symlink, submodule or EXECUTABLE (100755) file → ErrTemplateNotRegular; more than 256 files or 4 MiB → ErrTemplateTooLarge; no .knomit/ontology.yaml → ErrTemplateNoOntology; ontology not valid under ParseNewOntology → ErrTemplateOntology; ontology id of an embedded preset while `refreshDivergence(o, preset) != ""` (the boot refresh's own test) → ErrTemplatePresetID; two `part: template` facts for one name → ErrTemplateDescribedTwice; these seven (ErrTemplateLayout, ErrTemplateNotRegular, ErrTemplateTooLarge, ErrTemplateNoOntology, ErrTemplateOntology, ErrTemplatePresetID, ErrTemplateDescribedTwice) are 422 "Template invalid". A fleet-id ontology in local `template` mode → ErrTemplateFleetLocal (409 "Fleet template needs initialize"); in `initialize` mode while this instance already has a fleet repo or a fleet registering/unregistering → ErrTemplateFleetPresent, which WRAPS ErrTemplateFleetLocal (409 "Fleet already present": the createErrStatus arm for it comes first, so an initialize is never told to use initialize). The in-flight check FAILS CLOSED: a fleet state that cannot be read → ErrTemplateFleetStateUnavailable (503 "Fleet state unavailable", not a fleet refusal); a MISSING identity row refuses the same way, because app.New and Manager.Start both write that row before any create can run, so a missing row was lost and 'nothing in flight' cannot be known (MISREADING: do not special-case sql.ErrNoRows as standalone; TestCreateFromTemplate_Fleet deletes the row and expects the 503 sentinel). Missing `template.repo`/`template.name` or a template on a mode that refuses it → ErrInvalidName (400).

Every refusal happens before any repo file exists; CreatePreflight returns it before the 202 and Create re-checks it, and a create that fails later is rolled back by Create's cleanup (no .db/-wal/-shm, no registry row): TestCreateFromTemplate_Refusals asserts both for every row. Since the #433 follow-up every rule is pinned by a sabotage: the `not-new` row's fixture is accepted by ParseOntology and refused by ParseNewOntology; the limits are inclusive (exactly 256 files / 4 MiB accepted, TestTemplateFilesAt_LimitBoundaries); both in-flight states and the fail-closed read are rows of TestCreateFromTemplate_Fleet.

PRESET IDENTITY IS refreshDivergence, NOT SubsetDivergence (user ruling). The two differ only when the PRESET declares a root attribute the template lacks, and no embedded preset declares one today, so no real template can tell them apart. ResolveTemplate therefore reads the preset through the package variable templatePresetByID (= fact.EmbeddedPresetByID), and TestCreateFromTemplate_PresetIdentityIsTheRefreshRule stands in a preset WITH a root attribute. CONSEQUENCE: do not inline fact.EmbeddedPresetByID back into ResolveTemplate; the test would lose its only handle on the rule.

WHY FLEET: a LOCAL repo with ontology id `fleet` becomes this instance's fleet (fleetRepo, fleet.go) and `knomit fleet register <url>` then answers already_registered; initialize on the fleet's git URL sets the origin that register later matches (user ruling 2026-10-07). The preset mode's local `fleet` behaviour is NOT changed.

MISREADING: 'regular files only' here excludes the executable mode too, so a copy never silently changes a file's mode; and a fact WITHOUT a folder is refused, while a folder WITHOUT a fact is creatable by name (it is only not listed).

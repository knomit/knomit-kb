# An exp/* branch is writable only because an experiments RECORD names this instance's current agent branch as its parent — and BOTH sides of that comparison must be guarded non-empty, or a subscription makes every experiment writable

WritableBranch now admits a second class: an `exp/<name>` branch whose experiments row records `parent_branch` == this instance's agent branch. Everything else is unchanged — the consensus branch and foreign `agent/*` are still never writable, and the ontology gate still refuses every branch on a repo whose ontology could not be established, experiments included.

THE TRAP, and it is why the guard reads the way it does. A subscription's agent branch IS the empty string (invariants/repos/subscription/flag-and-branch-paired). A widening written as `parent == ri.agentBranch` therefore finds `"" == ""` for any experiment row with an empty parent, and every exp/* branch becomes writable on a repo that accepts no writes on ANY branch. The code guards `branch != "" && ri.agentBranch != ""` BEFORE comparing, and that pair of checks is load-bearing rather than defensive.

The answer comes from the RECORD, never from the ref name (invariants/store/branch-roles). A bare `exp/*` ref with no row is not writable; neither is one whose recorded parent is another machine's agent branch. The lookup FAILS CLOSED: an unavailable store or a failed read returns false, so a write is refused rather than admitted on a shrug. The shape test runs first, so an ordinary branch costs a prefix compare and no query.

TWO NEIGHBOURING FACTS ANSWER DIFFERENT QUESTIONS. conventions/repos/subscription/read-branch-for-content is about READS — a content question asks ReadBranch(), never AgentBranch(). decisions/repos/subscription/two-layer-write-refusal is about WHERE a subscription's refusal is enforced (semantic classification plus the structural store flag). This fact is about WHICH BRANCHES the classification admits, and the widening is the only part of it experiments changed.

WHAT THIS DOES NOT MEAN: it is not a second eligibility mechanism. WritableBranch remains the ONE classification every write gate funnels through — the MCP tools via Binding.WriteOK, REST via refuseUnwritableBranch — which is exactly what decisions/lens/writes-agent-branch-only promised the extension point would be.

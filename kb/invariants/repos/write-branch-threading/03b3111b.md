# Every write path asks Binding.WriteBranch() — including the READS it performs while deciding (dedup, existence, ref resolution) — because an experiment is an isolated world, not a diff against the agent branch

WriteBranch answers WHERE a write lands; WriteOK answers WHETHER it may. It returns the write repo's agent branch unless that repo is pinned at an experiment it may write, and "" on a read-only view — so a caller that skipped the gate gets nothing it could mistake for a destination.

THE NON-OBVIOUS HALF: the handlers' own reads move with it. learn's dedup search, update's and retract's existence checks, and the refs gate all run against WriteBranch, not the agent branch, because inside an experiment the corpus IS the experiment. A handler that wrote to exp/* but deduped against the agent branch would merge a fact into a path the experiment cannot see.

The review engine keeps invariants/synthesize/session-branch-binding intact: the branch is still read exactly ONCE, in Pipeline.StartSession, onto the session row. It is now SUPPLIED by the caller (NewReviewerOnBranch / NewHypothesizerOnBranch), with an empty value meaning "ask the repo", so every pre-existing caller behaves as before and internal/synthesize still has exactly one non-comment AgentBranch() reference.

THE LENS RULE IS NARROW, and widening it is the regression to avoid. A lens may legitimately pin its write member at the consensus branch FOR READS while writing to that member's agent branch, so writeOK and WriteBranch consult the pin ONLY when it is an experiment the member may write; otherwise the agent-branch rule stands. Deriving writeOK from the pin unconditionally would turn every such lens silently read-only. A regression test for this is unreachable unless the write member is pinned EXPLICITLY in Reads — Lens.normalize gives an unpinned write member the agent branch, so the obvious version of the test passes for the wrong reason.

Sites deliberately NOT changed: the knomit_repos catalogue row and repoMode, which ask whether a repo could write AT ALL rather than where this binding writes; ConfigureRemote's refspec, since an experiment is never pushed; and WriteMountBranch, which is a READ question.

# ALL RepoInstance fields are unexported; svc accessible ONLY via WithRead

ALL RepoInstance fields are UNEXPORTED. The current set (internal/repos/instance.go): mu, name, dbPath, agentBranch, ontology, embedder, ontologyRoot, methodologyMinScore, clusterResolution, clusterMinCommunity, the discovery knobs (discoveryEffortDefault, discoveryConfidenceThreshold, discoveryBlastRadiusThreshold, discoveryBridge, discoveryCohFloor, discoveryMaxMembers, discoveryQualityFloor, discoveryWCoh, discoveryWGap, discoveryWSpec), onCommit, svc, hub, syncCancel, syncWg, indexCancel, indexWg, startSync, closeFn, and the atomic index-state fields (indexState, indexDone, indexTotal). External code reaches svc ONLY via ri.WithRead(func(*store.Service)) — there is no direct accessor and no public RLock/RUnlock. The compile error from touching `ri.svc` outside the repos package is the load-bearing enforcement of the SwapStore stale-pointer safety contract: a caller can never hold a svc pointer across a SwapStore. Immutable fields (name, agentBranch, ontology, embedder, ontologyRoot, methodologyMinScore, hub, and the cluster/discovery knobs) have simple getters that return without locking, since they are set once at construction and never mutated.

The write path: ri.withWrite(fn) takes the write lock; it is used only inside the repos package. Mutations of ri.svc always happen under the write lock.

WHAT THIS DOES NOT MEAN:
- NOT 'withWrite is the sole internal writer of ri.mu-guarded state.' FALSE at HEAD — withWrite has exactly ONE call site: SwapStore's in-memory swap (swapstore.go); the file-backed swap takes ri.mu.Lock() DIRECTLY. The startSync closure (builder.go) also does NOT use withWrite — it takes ri.mu.RLock() directly to snapshot svc and ri.mu.Lock() directly to reassign ri.syncCancel; DeactivateSync (instance.go) likewise takes ri.mu.Lock() directly. Do not grep for withWrite expecting to find every writer of ri.mu-guarded state.
- NOT 'the field list above is exhaustive or frozen.' The struct has grown (index-heal lifecycle fields, discovery quality knobs) and will keep growing; the invariant is that NONE are exported, not that the census is fixed. Verify against internal/repos/instance.go before relying on a specific field being present or absent.

Anti-pattern: adding a public accessor for svc, exporting any field, or exposing RLock/RUnlock — all defeat the SwapStore stale-pointer safety contract.

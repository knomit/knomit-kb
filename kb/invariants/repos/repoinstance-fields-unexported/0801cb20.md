# ALL RepoInstance fields are unexported; the store is reachable ONLY via Acquire/WithRead/Pin

ALL RepoInstance fields are UNEXPORTED. The current set (internal/repos/instance.go @ c6ca9344): mu, name, dbPath, agentBranch, idMu, id (lazy root-commit identity), ontology, embedder, ontologyRoot, methodologyMinScore, clusterResolution, clusterMinCommunity, the discovery knobs (discoveryEffortDefault, discoveryConfidenceThreshold, discoveryBlastRadiusThreshold, discoveryBridge, discoveryCohFloor, discoveryMaxMembers, discoveryQualityFloor, discoveryWCoh, discoveryWGap, discoveryWSpec), onCommit, handle (*storeHandle — the refcounted store generation; there is NO svc field anymore), closed (teardown tombstone), hub, syncCancel, syncWg, indexCancel, indexWg, startSync, closeFn, and the atomic index-state fields (indexState, indexDone, indexTotal).

External code reaches the store ONLY via ri.Acquire() (service + release func), ri.WithRead(fn) (scoped over Acquire; returns ErrRepoClosed/ErrStoreUnavailable instead of calling fn without a store), or ri.Pin() (hold the generation without the service). There is no direct accessor and no public RLock/RUnlock. The compile error from touching ri.handle outside the repos package is the load-bearing enforcement of the store-lifetime contract: a caller can never reach a service without the refcount that keeps it open (see the store-lifetime invariant). Immutable fields (name, agentBranch, ontology, embedder, ontologyRoot, methodologyMinScore, hub, cluster/discovery knobs) have simple getters that return without locking, set once at construction.

WHAT THIS DOES NOT MEAN:
- NOT 'there is a withWrite helper.' withWrite was DELETED in PR #20; internal mutators (detachStore, attachStore, DeactivateSync, the startSync closure) take ri.mu.Lock directly. Do not grep for withWrite.
- NOT 'the field list above is exhaustive or frozen.' The struct keeps growing (idMu/id arrived with lenses, handle/closed with the lifetime refactor); the invariant is that NONE are exported. Verify against internal/repos/instance.go before relying on a specific field.
- NOT 'holding the RLock is what makes access safe.' The refcount on storeHandle is the lifetime guarantee; the lock only serializes handle attach/detach against acquisition.

Anti-pattern: adding a public accessor for the service or handle, exporting any field, exposing RLock/RUnlock, or returning the *store.Service from a helper without its paired release.

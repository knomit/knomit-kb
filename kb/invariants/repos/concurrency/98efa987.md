# closeFn detaches the storeHandle under the write lock, then drains its refcount before svc.Close()

The closeFn closure built in repoBuilder.build() tears the store down in three ordered steps: (1) obs.Stop() — stop the commit observer's debounce; (2) ri.detachStore(true) — under the ri.mu WRITE lock, set the closed tombstone and take the storeHandle out of the instance, so every later Acquire/WithRead fails with ErrRepoClosed instead of reaching a dying store; (3) h.wg.Wait() then h.svc.Close() — drain every in-flight acquirer (HTTP handlers that resolved ri from middleware before Archive removed it from the map, MCP tool calls, an observer callback already mid-SyncLocked, background rebuild/synth tasks) and only then close the SQLite handle.

Why the refcount and not the lock: the write lock only drains callers currently holding the RLock — it cannot cover a caller that acquired earlier, released the lock, and is still using the service (the dominant real pattern: long store calls, background tasks). The pre-PR-#20 version of this fact claimed the write lock alone was the drain; that was insufficient and Archive could close the store under an in-flight request. The refcount drain plus the closed tombstone is the complete mechanism.

Ordering notes: shutdown() cancels index/sync contexts, waits indexWg BEFORE syncWg, shuts the TaskHub (cancelling hub tasks so their releases arrive), and only then calls closeFn — hub cancellation before the drain is what guarantees the drain terminates. closeFn is idempotent: a second call sees detachStore return nil and returns. No caller holds ri.mu when invoking closeFn.

Anti-pattern: closing the service anywhere without first detaching the handle and draining its WaitGroup — including 'quick' paths like swap failure recovery; SwapStore follows the same detach→drain→close discipline for the old generation.

NAMES SINCE ISSUE #411 (the rule is unchanged): closeFn, repoBuilder and RepoInstance.shutdown are gone. The same ordered teardown is openStage.Exit (internal/repos/stages.go): cancel hub tasks, stop the commit observer, detachStore (with the closed tombstone only when the machine is unmounting; a SwapStore rewind detaches without it, so acquirers get ErrStoreUnavailable until the new store is attached), drain the handle's refcount, then svc.Close(). The machine's exitStages has already drained Sync, Serve and Index (newest-first) before Open exits, so no background stage still holds the store.

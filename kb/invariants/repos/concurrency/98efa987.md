# RepoInstance closeFn write-locks ri.mu to drain in-flight WithRead readers before svc.Close()

The closeFn closure built in repoBuilder.build() acquires the ri.mu WRITE lock before reading ri.svc and calling svc.Close(). This drains all concurrent ri.WithRead(fn) readers (which hold the RLock while running fn(svc)) before the store handle is closed — otherwise a runtime Manager.Archive (or SwapStore) could close the SQLite handle while an in-flight HTTP handler is still executing fn(svc) under a compatible RLock, a use-after-close race. Before the repo-lifecycle work closeFn closed under RLock; the write-lock is now load-bearing because Archive closes a single live repo while the server is serving requests (unlike Manager.Close at shutdown). shutdown() releases its own RLock (taken only to read syncCancel) before calling closeFn, so there is no self-deadlock; no caller holds ri.mu when invoking closeFn.

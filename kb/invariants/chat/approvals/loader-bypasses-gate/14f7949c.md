# The load_tools loader and a call to a tool that is not loaded are answered inside the agent loop before the approval gate, and loading never approves anything: every call to a loaded tool still goes through CallGate.Decide, and a grant (pin, tool, action) outlives the tool's definition

Loop.runCalls asks ToolWindow.Handles(name) before the gate. Handles is true for the loader (load_tools) and for a catalogue tool that is not loaded, or that the loader of the SAME response just loaded. Such a call never reaches CallGate.Decide and never reaches ToolHost.CallTool: the loader only changes which definitions the next request carries (it calls no tool, writes nothing, reads no corpus), and a call to an unloaded tool is answered with an error (NotLoadedCallResult) and the tool is loaded for the next request, because its arguments were written without its schema. [MASTER CALL 2026-11-05] This holds in the same batch: [load_tools(X), X(args)] does not run X.

The loader's own approval is recorded as decision auto (Approval entry and session log); a not-run call has no approval entry. Every later call to a loaded tool that is RUN, a write tool included, goes through Decide exactly as on the static path (TestLoop_LoadedWriteToolStillAsksApproval: gate before host; a declining gate leaves the host untouched). Grants are keyed (binding pin, tool, action) (9b26dd4b) and do not depend on whether the tool's definition is currently loaded: evicting a tool does not revoke a grant and loading one does not create one.

Does NOT mean: the loader is exempt from limits. Loader calls count toward MaxCalls and pass through the repeat-failure guard like any answered call (c09ba08f).

EXCEPTION (review N3, PR 5 v2). The title's 'every call to a loaded tool still goes through CallGate.Decide' is true of every call that is run. An identical repeat of a call that just succeeded (same tool, byte-identical arguments, ShortCircuit true) is answered by the no-progress guard from the earlier result plus NoProgressNote, is NOT run and does NOT reach Decide: no second card, no second write (TestChat_AnAllowedWriteRepeatedIsNeitherAskedNorWrittenAgain). A call to a STUB (PR 5 v3, 7d36bd78) is the loader's kind of call: it is a call to a catalogue tool that is not loaded, so Handles is true, it is never run and never reaches Decide; the model's next call to the now-loaded tool does. Does NOT mean a one-time Allow is stretched: the repeat writes nothing.

# A chat ends when no events stream has been attached for 60 seconds (chatStreamGrace), on DELETE, or when the server's lifetime ends; ending unwinds a blocked approval, records ended_at on the MCP session, removes the temp dir, and never touches the persistent session log; each process keeps its temp files in one lock-guarded run directory that the next start sweeps

Heartbeat (P11): the grace timer starts when the chat is created and again whenever the last events stream detaches; an attached stream stops it; a reconnect within the grace keeps the chat and its first frame is event: ready. The page sends DELETE with fetch keepalive on pagehide, so a closed tab normally ends the chat at once and the grace is the fallback.

chat.end runs once, whichever caller wins: it forgets the chat (later requests are 404), cancels the chat context so a blocked Decide and a running turn return, waits for the turn goroutine (bounded at 10s), sends chat_end to streams, closes the InProcessSession (clientsessions End: ended_at), writes chat_end to the session log and removes <run>/<chatID>. Skipping the session close leaves a row that never ends; a test fails on it.

Server shutdown (the third way a chat ends): App.Close ends the Server's Lifetime, which starts the chat manager's shutdown on its own goroutine (every chat's end runs in parallel, then the run directory is released). App.Close then calls web.Server.WaitReleased(shutdownReleaseWait = 15s) BEFORE manager.Close, because manager.Close closes control.db and the teardown writes to it (the client_sessions row's ended_at, then the chat_end log line). The bound is 10s (maxTurnEndWait: the longest one chat waits for a turn that ignores cancellation, chats end in parallel) plus 5s (the serveUntil graceful-shutdown grace) for closing the session and writing the log line; a teardown stuck past it is logged and abandoned so a stop cannot hang. WaitReleased covers the origin-session manager too. After App.Close returns, every chat's row has ended_at, its log's last line is chat_end and no turn is still running. TestApp_CloseEndsALiveChatBeforeControlDBCloses runs a chat mid-turn through the real App and reads control.db and the log after Close; it was shown red with the WaitReleased call removed. The in-package TestChat_ShutdownEndsEveryChatAndRemovesTheRun cannot see this ordering because its harness keeps the store open.

Does NOT mean the wait is unbounded or that a hung model call delays the stop past 15s: past the bound the chat is left half torn down (row open, log without chat_end) and the next start's sweep removes only the temp dir.

Temp layout (P12): <sessionsDir>/run-<id>.lock + run-<id>/<chatID>/{transcript.jsonl,calls/<callID>.json}, dirs 0700 and files 0600. The run-lock and sweep scheme is httpx.AcquireRunDir / SweepDeadRuns, extracted from api/origins (which uses it too): liveness is an OS lock, never a pid, and the sweep removes only runs whose lock it can take. Mount sweeps once, synchronously, before serving. The session log directory is separate (<home>/chat-logs) and nothing here removes it.

# A chat ends ONLY on DELETE or when the server's lifetime ends (no page-stream grace any more); ending unwinds a blocked approval, records ended_at on the MCP session, removes the temp dir, and appends a chat_end record to the persistent session log and closes it (the log FILE is never removed); each process keeps its temp files in one lock-guarded run directory that the next start sweeps

WHAT ENDS A CHAT: DELETE /chats/{id} (reason "deleted"), the server's lifetime ending (reason "shutdown"), and the one create-time path where the chat's opening turn is refused (handlers.go, reason "first turn refused"). NOTHING ELSE. In particular a page events stream closing does not end a chat, and there is no clock at creation: a chat created with no page stream attached lives too. Decision and rationale: kb/decisions/chat/lifetime/outlives-page/bd2a87a7.md (user, 2026-11-09).

HISTORY: until fix-chat-outlives-page a chat ended 60 s (chatStreamGrace) after its owner's LAST page stream closed, or 60 s after creation with none attached (startGrace / graceFired, reason stream_grace). That is gone with all its machinery (chatStreamGrace, startGrace, graceFired, the grace timer, the afterGraceStep seam, manager.pageCount). Do not reintroduce a liveness clock: the tests below go red on one shortened to a fraction of a second, whether on detach or at creation.

Page streams (P11) are still per page, not per chat: ONE events stream per tab (GET /chats/events, every chat of the caller, each event tagged with its chat id). attachPage only lets each chat of the owner replay the turn end no stream received (missedEnd, once, right after ready); detachPage only removes the stream. A reconnecting page gets ready, reloads from GET /chats (each row carries the same state a chat_state frame does: title, state idle|running|awaiting_approval|error, turns, cost) and gets chat_state on the next change. A turn with no page attached runs; its end is parked for the next page. A turn blocked in Decide waiting for approval with no page attached keeps waiting with no timeout (Decide selects only on the answer channel and the turn context); the row says awaiting_approval and a page that comes back answers it. Stop (cancel), DELETE or shutdown unwinds it.

chat.end runs once, whichever caller wins: it forgets the chat (later requests are 404), cancels the chat context so a blocked Decide and a running turn return, waits for the turn goroutine (bounded at 10s, maxTurnEndWait), sends chat_end (tagged with the chat id) to the owner's page streams, which stay open, closes the InProcessSession (clientsessions End: ended_at), appends a chat_end record to the session log and closes that file (sessionLog.End; the file itself stays) and removes <run>/<chatID>. Skipping the session close leaves a row that never ends; a test fails on it.

Server shutdown: App.Close ends the Server's Lifetime, which starts the chat manager's shutdown on its own goroutine (every chat's end runs in parallel, then the run directory is released). App.Close then calls web.Server.WaitReleased(shutdownReleaseWait = 15s) BEFORE manager.Close, because manager.Close closes control.db and the teardown writes to it (the client_sessions row's ended_at, then the chat_end log line). The bound is 10s (maxTurnEndWait) plus 5s of headroom; a teardown stuck past it is logged and abandoned so a stop cannot hang. After App.Close returns, every chat's row has ended_at, its log's last line is chat_end and no turn is still running (TestApp_CloseEndsALiveChatBeforeControlDBCloses). Chats are NOT persisted: after a restart they are gone from GET /chats; only their session logs remain.

Does NOT mean the shutdown wait is unbounded: past 15s the chat is left half torn down (row open, log without chat_end) and the next start's sweep removes only the temp dir. Does NOT mean an idle chat is immune to every server-wide expiry: its paging cursors are reaped after session.tool_idle_ttl and its binding handle after session.client_retention, like any MCP client's (kb/gotchas/chat/idle/server-expiries/cea18d95.md).

Temp layout (P12): <sessionsDir>/run-<id>.lock + run-<id>/<chatID>/{transcript.jsonl,calls/<callID>.json}, dirs 0700 and files 0600. The run-lock and sweep scheme is httpx.AcquireRunDir / SweepDeadRuns: liveness is an OS lock, never a pid, and the sweep removes only runs whose lock it can take. Mount sweeps once, synchronously, before serving. The session log directory is separate (<home>/chat-logs) and nothing here removes it.

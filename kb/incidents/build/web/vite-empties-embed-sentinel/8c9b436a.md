# vite's default emptyOutDir deletes the committed web/dist/.gitkeep embed sentinel; fixed with a closeBundle plugin, NOT emptyOutDir:false

`web/embed.go` embeds the UI with `//go:embed all:dist`. Build assets are gitignored, so a fresh checkout's `web/dist/` contains only the committed `.gitkeep` sentinel — without it the directory has no embeddable files and the Go build fails. CI builds Go directly, without `make web`, so the sentinel is load-bearing for CI, not a convenience.

vite's `emptyOutDir` defaults to true for an outDir inside the project root, so EVERY `npm run build` (or `make web`) deleted the sentinel, showing up as `D web/dist/.gitkeep` in git status and a red `go test ./web/`. `web/embed_test.go` is the guard that catches it.

Two fixes were considered and REJECTED:
- `emptyOutDir: false` — dist/ then accumulates stale hashed assets across builds, and all of them get baked into the embedded FS. Trading a red test for permanent binary bloat.
- Re-touching the sentinel from the Makefile `web` target — leaves a bare `npm run build` (what you actually run while developing the UI) still deleting it.

The fix in place is a `knomit-keep-embed-sentinel` vite plugin in `web/vite.config.ts`: it reads `.gitkeep` at CONFIG-EVALUATION time and rewrites it in `closeBundle`. Snapshotting at config-eval matters — the config module is loaded before vite empties outDir, whereas `buildStart` is not guaranteed to be. Reading the existing file rather than hardcoding the text keeps the plugin and the committed sentinel from drifting; a fallback constant covers a build run when it is already missing.

CONSEQUENCE: emptying still happens (no stale-asset accumulation) and the sentinel survives regardless of entry point. If you ever restructure vite.config.ts, keep the snapshot in the plugin factory body, not in a build hook.

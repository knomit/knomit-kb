# syncStage.Enter ran ensureLocalUpstream INLINE on the driver, and EnsureLocalUpstream takes lockBranch(upstream) before it checks the ref exists, so when the Index job's Rebuild won the lock the whole mount walk parked behind the index: the create sat on step "register" and never narrated "indexing", and every queued machine event waited (#411 to #586)

Found as a flake of TestCancelCreate_DuringIndexLandsWithoutWaitingForTheIndex on the PR #584 merge; fixed by PR #586 (merged into dev as 8a96c89b; every claim below re-read at 8a96c89b unless marked as a measurement).

MECHANISM. The mount walk enters Index (launches the job goroutine; Index.Rebuild takes the branch lock as its FIRST statement and holds it for the whole rebuild), then Serve, then Sync. Before #586, syncStage.Enter called r.ensureLocalUpstream(ctx, svc) on the DRIVER goroutine before starting the loop. remotesync.Index.EnsureLocalUpstream takes rh.vr.LockBranch(upstream) BEFORE it checks whether refs/heads/<upstream> exists. For a subscription the read branch IS the upstream, so the heal's Rebuild holds exactly that lock. Who gets it first is goroutine scheduling: driver first -> a no-op in microseconds; index first -> the driver waits for the whole Rebuild. lockBranch is not ctx-aware, so nothing on the driver could cancel the wait (kb/invariants/store/index/branch-locking).

CONSEQUENCES when the index wins the lock. (1) The create never narrates the index: Mount cannot reply Ready until the walk returns, so watchIndex (internal/corpus/repos/lifecycle.go) starts only after the index has left "indexing", and the job sits on step "register" then goes to done with no "index" step (the PR #230 symptom shape). (2) The driver (Machine.drive, a single goroutine) handles no external event meanwhile: a CancelIndex sent in that window returned only after the index finished (measured on the pre-fix tree: 577 ms of a 580 ms index in a forced repro; 0.36 ms with the fix; a measurement, not re-run at 8a96c89). Unmount and a create cancel are NOT affected: Machine.Send(Unmount) cancels all lives before draining any, the index job stops at its next batch and releases the lock (kb/invariants/repos/lifecycle/exit-cancels-all-then-drains).

INTRODUCED by #411 (cd980a94), which moved the bootstrap from repoBuilder.activate (it ran before any index job existed) into syncStage.Enter, AFTER Index launches its job. Not caused by E7a (#584).

FIX (#586). ensureLocalUpstream now runs inside the Sync life's work closure (internal/corpus/repos/stages.go): on the life's goroutine immediately before the loop's first round, and inline on the driver only under Options.Synchronous, where the driver runs the round anyway. Ordering against the first network round is unchanged and is pinned by TestOpen_BootstrapsAMissingLocalUpstreamFromOrigin (Synchronous) and TestOpen_BootstrapsAMissingLocalUpstreamFromOrigin_Background (the life's goroutine). EnsureLocalUpstream got NO lock-free pre-check, by decision: off the driver, the only goroutine still waiting on it is the reconcile goroutine, whose first round takes the same lock straight afterwards, so a pre-check would change nothing observable. Where the local upstream is actually MISSING (the case the bootstrap exists for) the index cannot hold that lock for long: planIndex drops an unresolvable upstream and a Rebuild of a missing branch fails at HeadCommit.

REGRESSION TEST: TestCreate_StageEnterDoesNotParkBehindTheIndexRebuild (internal/corpus/repos/stage_enter_index_lock_test.go). It forces the losing interleaving: an embedder released only by cancel holds Rebuild inside its embeddings phase, and a hook on (StageServe, enter) holds the driver there until the embedder has started, so Serve.Enter and Sync.Enter both run while the lock is held. It asserts the job reaches step "index" with IndexState indexing while running, that the phase at release was "embeddings" (anti-vacuity), and that CancelIndex returns while the index is still held. It does NOT cover the stages entered before Index (Populate, Open, Identify): no index job exists while they run. The e2e test's sawSync check was deleted in the same PR (the create has had no "sync" step since #411, so it could never fire).

WHAT THIS DOES NOT MEAN. It is not "the cancel test is timing-flaky": the assertion (a running create reports an in-flight index) is the done-means-indexed product contract and the failing runs were the product actually parking (about one run in seven under -race, never with GOMAXPROCS=1, per the test's own comment). The rule it broke is in kb/invariants/repos/create-job/index-before-sync: a stage Enter on the driver must not take lockBranch on a branch the index job may hold.

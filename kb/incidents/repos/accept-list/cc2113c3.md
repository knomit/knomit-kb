# repos.Manager.AcceptListFor was a call-on-call forward of VerifyAccepts().For; the generic parent-forwards guard found it and it was deleted, callers use m.VerifyAccepts().For(uid)

Before PR #599 (merged as 83f3374b) internal/corpus/repos had `func (m *Manager) AcceptListFor(uid)` whose body was one call, `m.VerifyAccepts().For(uid)`: a call-on-call forward kept after 14a moved VerifyAccepts into repos/control. The #594 review had judged it should stay exported because internal/edge/web/handlers_origin_session.go called it; #599 removed it anyway: the generic guard (kb/invariants/testing/parent-forwards) treats a one-call method on a parent that hands on a child's value as a forward, and the callers were pointed at the child. At 83f3374b the three lifecycle.go call sites use `svc.SetAcceptList(m.VerifyAccepts().For(uid))` (nil-safe). REGRESSION ANCHOR: TestParents_NoForwardsIntoChildren. Fact f6c03f1f (accept-list location) is updated for the rename.

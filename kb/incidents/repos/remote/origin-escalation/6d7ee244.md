# Origin escalation (fixed in PR #676): a caller confined to repo X could change X's origin to another knowledge base on the same host and then read it through X, because the origin routes needed only `write` and the attach guard never asked WHICH knowledge base the remote holds

WHAT HAPPENED (confirmed by in-process repro at dev 09acedd6, 2026-10-28; fixed on branch fix/origin-escalation, PR #676). A principal whose authority is ONE repo (an OAuth token with audience /api/v1/repos/X and read+write) could set X's origin. Two independent gaps together made that an escalation:
(1) AUTHORIZATION: PUT/DELETE /repos/{repo}/origin, PATCH /origin/upstream and the /origin-sessions wizard were gated by `write` only (writeGate), not by `operator`, so any repo writer could choose the repo's origin.
(2) IDENTITY: the attach guard (repos guardAttach) checked only the local-origin policy, reachability and the ontology id (CheckOriginOntology, which passes the SAME id). It never ran the one-local-copy check that guardSwap runs, and never compared the remote branch's history with the repo's main. The next sync then adopts the origin's main AS FETCHED (the #524 trust ruling), so X's main became the other knowledge base.

PATHS (all needed only the token): P2, the server's own plaintext /git/<Y> mount as origin (needs [git].serve on, the default, and require=false on loopback, the default); P1, a foreign knowledge base under local_origin_root (needs the operator to have set that root); P1b, the origin of another registered repo Y under that root. Effects: X's token read Y's main; in P1/P1b X's push also wrote X's agent branch into the foreign origin, and in P1b force-overwrote Y's agent branch there each round (same agent-branch name per instance). P2 push-back was refused (anonymous loopback cannot push).

FIX: operator gate on all origin write routes and the whole wizard; attach identity checks (another active repo's knowledge base refused by repo-id claim, held tip, or root commit; unrelated history over a main with facts refused unless replace_main). See the decision and invariant written with this fact.

REGRESSION ANCHORS: internal/edge/web/origin_escalation_test.go, TestOriginEscalation_P1_LocalOriginIsRefused, _P1b_OtherReposOwnOriginIsRefused, _P2_SelfGitMountIsRefused (red without the gate, verified by sabotage).

MISREADING: 'the local-origin gate (426d64a7) covered this': no, that gate is a filesystem-path policy only and P2 is a network URL; and with local_origin_root set, P1 paths are inside the root by design. 'Fixed by the operator gate alone': the gate stops repo-scoped callers, but an operator could still silently import another registered repo's knowledge base; the identity checks close that for everyone.

SECOND VARIANT (found in review of PR #676, closed on the same branch at 859d25bd): POST /repos with an origin needed only `write`. A token whose audience is the whole /api/v1/repos collection (no operator) could create a repo cloning an UNREGISTERED knowledge base under local_origin_root and read it, and in initialize mode push into that origin. The collection audience reads every registered repo, which is why the first round wrongly judged the route harmless. Now gated by operator when the body carries an origin; pinned by TestOriginEscalation_CreateWithAnOriginNeedsTheOperator.

RESIDUALS accepted at review (details in the decision fact): merge-carried history passes the first-parent root layer (N1); the probe budget bounds admission, not peak memory (N2); the check is point-in-time.

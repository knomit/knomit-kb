# A leave admitted by the fleet master but not yet merged by the consensus merger was renewed: renewFleetLeaves now also reads members/<id>/ on every pushed branch and skips only an id whose OWN `left` record names its CURRENT serial (#651, #654)

The master's origin round admits a member's branch (on a forge the fetch judge promotes it to a local agent/* branch; on a hub receive-pack does) and then runs its duties in the same round. The consensus merger, which merges that branch into the master's agent branch, runs on its OWN goroutine. leafRenewalDue checked only main and the agent branch. A `left` record that was admitted but not merged yet was on neither, so the renewal duty re-issued the leaver's leaf whenever it read the agent branch before the merge landed. The merge then brought in the `left` record naming the OLD serial. The leave duty revokes only the leaf whose serial the record names (leftLeafDue), so it never revoked the renewed leaf. Main ended with a valid, unrevoked leaf for a member that had left.

The fix (pushedLeaves): renewFleetLeaves also reads every pushed branch. For each due agent id it reads ONLY members/<id>/ (fleetrec.AgentRecordsAt, reached through Service.FleetAgentRecordsAt: no ontology, no PKI, no other folder) and skips id's renewal when that folder holds id's OWN `left` record (agent == id) naming id's CURRENT serial. This is the same per-agent, per-serial match as leftLeafDue.

Why the matching is per agent AND per serial:
- A forged serial. A member's `left` record naming ANOTHER agent's serial lives in that member's own folder (only commits authored by id may change members/<id>/, the record-owner rule: another member's branch can CARRY id's commits, never write that folder, which is also why reading every branch is safe), so it blocks no one else. The first revision of #654 matched by serial alone, and any member could have stopped any leaf's renewal for good, the master's included (review B1).
- A stale record. A `left` record from an earlier membership names an earlier serial and blocks nothing.
- Missing branches. All agent/* branches are read, not only agent/<id>: the judge admits id's commits on any agent/* branch, and a member's branch name is its own choice.

Fail closed PER AGENT: if members/<id>/ cannot be read on some branch, only id's renewal is skipped for that round, with a WARN; everyone else is renewed (review S1; a missed renewal is retried next round). A failure to list the branches at all renews no one. A folder whose tree object is missing is an error, not "no records": go-git's Tree.Tree reports a missing subtree as ErrDirectoryNotFound, so AgentRecordsAt uses FindEntry and GetTree instead.

Measured: the regression test failed 10 of 256 runs before the fix (8 parallel -race processes, -count=8, -cpu=1,2,4,8) and 0 of 256 after. It parks the merger (consensusHooks.beforeMerge) for the due round, so the window is open on every run. Sabotage of each guard turns its test red.

WHAT THIS DOES NOT COVER (another PR is fixing it): a member whose leave is pushed AFTER the master's fetch, in a round that renews its leaf. The renewal is published and the `left` record arrives next round naming the superseded serial. pushedLeaves cannot see it.

WRONG FIXES, so nobody re-proposes them. (1) Matching leftLeafDue by member instead of by serial reopens the rejoin bug of e9e7bab2. (2) The reviewer-proposed lineage rule, "the left serial is not on the CRL and the leaf on main has the same key, so it is a renewal", is UNSOUND. Counterexample: a renewal takes S_old to S_1; the operator's manual revoke revokes S_1; the member re-enrolls with the same key and gets S_2; the stale `left` naming S_old merges; the rule would revoke S_2, the rejoiner's fresh leaf. A sound rule must also prove that no leaf issued to id after S_old is on the CRL, read from the issuance records (issued/<serial>.pem).

Consequence: a fleet duty that must not act on what a peer branch is about to bring in has to read the pushed branches as well as main and the agent branch, per agent as the record-owner rule scopes them. The merger is asynchronous, so "admitted this round" does not mean "on the agent branch".

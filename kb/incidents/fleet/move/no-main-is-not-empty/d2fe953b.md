# A forge is EMPTY only when it advertises no ref at all (no branch, no tag): a repository with no main but a trunk, a master or a tag is someone else's, and the fleet move into it was taken for an empty-forge seed in PR #529 review until B1

INCIDENT (PR #529 review, finding B1, before merge; reproduced live on a rig). The same-fleet check of the master's move (remoteFleetRoot) first treated a remote as empty when it had no `main` (the condition was 'advertisement is empty OR the branch is not advertised'). A forge repository holding only someone else's `trunk` (or `master`, or only a tag) therefore counted as an empty repository, and the master's move seeded the fleet into it: PublishTo pushed the fleet's main and agent branch into a repository that belonged to something else. FIX: advEmpty is true only when the advertisement has no reference other than HEAD (a new repository advertises a HEAD pointing nowhere) and no peeled tag; a remote with other refs but no main is the distinct state remoteNoMain, answered 422 `not_this_fleet` ('holds another repository: it has no main, but other branches or tags ... The fleet moves only to an EMPTY forge repository (no branch, no tag) or to the one this fleet lives on'), for the master as for anyone, and NOTHING is pushed (the live check: the foreign repository still held only its trunk, and the master was still the hub). The tag-only case holds too (422, the forge still holds only its tag).

INVARIANT. 'Empty' means the remote advertises NO ref at all. 'No main' is not 'empty'. The copy that moves must hold THIS fleet's root on the remote's main, or the remote must be empty.

MISREADING TO AVOID: 'no main means a fresh repository'. A default-branch name other than main (master, trunk) is the ordinary way a foreign repository looks like that.

REGRESSION TESTS. internal/repos TestFleetFollow_ARepositoryWithoutMainIsNotEmpty (sabotage: the old condition, `advEmpty || !advHasBranch`, turns it red) and TestFleetFollow_AForgeMustHoldThisFleet.

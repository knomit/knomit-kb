# The review step's push-access notes rendered in subscribe mode, contradicting the list above them — and the reducer's preselect made that the DEFAULT rendering of the case the note exists for

What happened: StepReview's two push-access notes (review-write-denied, amber, and review-write-unknown, grey) were guarded only on choice === 'remote' and the probe's write_access value. That guard predates subscribe mode. A subscription never pushes anything — its own consequence list says "nothing is ever pushed" — so the note reading "the steps above push knomit's own branch" appeared directly under a line saying the opposite.

Why it was the default, not an edge: wizardState's PROBE_OK reducer preselects access: 'subscribe' when the probe reports write_access === 'denied'. So the exact input the denied-note exists for (refused push) landed the user in subscribe mode with the contradictory note showing, every time.

Fix (PR #193): a `subscribing` predicate (choice === 'remote' && initialized === 'yes' && access === 'subscribe') and both notes guarded on !subscribing. The initialize path (initialized === 'no') always pushes the agent branch and keeps both notes; the join path keeps both notes.

Regression anchors in web/src/StepReview.test.tsx: "says nothing about pushing when subscribing, because nothing is pushed" (denied probe, subscribe → neither note) and "says nothing about an unestablished push either, when subscribing" (NO write_access, subscribe → no unknown note). The second test exists because the first is vacuous for the unknown note: a denied probe already makes !write_access false, so the unknown note was absent for an unrelated reason. The reviewer proved it by deleting !subscribing from the unknown-note guard and watching all tests stay green; the added test is the one that now fails under that mutation.

General shape: when a mode is added that changes what an existing warning claims, every guard on that warning must be re-read; a warning that was true for every prior mode does not announce that it is now false for one.

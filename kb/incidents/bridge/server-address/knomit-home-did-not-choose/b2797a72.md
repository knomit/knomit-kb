# Incident (first-mission rehearsal, 2026-10-02): `KNOMIT_HOME=<rehearsal home> kb --repo X` reached the MAIN instance — kb chose its server from its argument or the desktop lockfile (server.json -> 19278), never from KNOMIT_HOME, and its first call (agent-branch discovery) was plain TCP; the hooks' old variable only switched their socket off. Fixed by KNOMIT_SERVER

WHAT HAPPENED: a rehearsal knomit instance ran beside the user's main (desktop) instance. The mission recipe started a Claude Code session whose `kb` was meant to reach the rehearsal instance; the recipe env carried KNOMIT_HOME for exactly that, and two facts (the exec contract and the mission session fact) said KNOMIT_HOME made kb reach 'THIS' server. It reached the main instance.

WHY (at origin/dev f9cb7d46): tools/bridge/main.go took the base URL from the positional argument, else the desktop lockfile (server.json, port 19278), else localhost:19278 — KNOMIT_HOME was never consulted for the address, only for the default socket path; discoverAgentBranch then dialled that URL with an explicit-URL client (plain TCP), so the socket under KNOMIT_HOME was never even tried for the first call. The hooks read KNOMIT_BASE_URL (historical name, retired in the fix), but only to turn the socket preference off.

FIX (PR fix/knomit-server): KNOMIT_SERVER names the server for every call (facts under kb/architecture/bridge/server-address/resolution and kb/invariants/bridge/server-address/named-used-as-given); the server sets it for its recipe children (kb/invariants/repos/triggers/recipes/server-address). KNOMIT_HOME keeps its meaning — the instance's folder — and chooses no server. Regression tests: TestBridge_KnomitServerBeatsTheLockfileForEveryCall (lockfile -> A, KNOMIT_SERVER -> B; discovery, POST and DELETE reach B, A sees none) and TestBridge_KnomitHomeDoesNotChooseTheServer.

LESSON: a fact that says 'X makes it reach THIS server' must name the code that reads X for the address. Two facts asserted it from the variable's name; nothing read it.

CLOSED AT THE LOCKFILE LEVEL TOO (knomit#493, merge 9860c726): the incident's first leg - kb with KNOMIT_HOME=<rehearsal> falling to level 3 and reading the USER's server.json (port 19278) - is now also impossible by construction. config.LockfilePath() resolves through ResolveHome: a non-default KNOMIT_HOME reads <home>/server.json, so only the default home's file lives in the per-user state dir that every home used to share. KNOMIT_SERVER remains the mechanism that NAMES a server and is still used exactly as given; the per-home file is the second line of defence for a kb that was given only KNOMIT_HOME. A serve that does not hold its home's socket writes no file, so a TCP-only sibling cannot repoint kb either. Pin: TestLockfilePath_KeyedByHome (internal/config/http_test.go). NOT MEANT: KNOMIT_HOME still does not choose a server by its name - 'KNOMIT_HOME makes kb reach THIS server' remains a claim to verify against the code that reads it, as the lesson says; here the code is LockfilePathFor.

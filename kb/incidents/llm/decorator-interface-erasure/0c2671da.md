# A decorator that returns a concrete type silently ERASES an optional interface of what it wraps — the v1 TracingAdapter dropped BatchAdapter that way (the v1 wrappers are deleted; the lesson stands for any wrapper)

internal/engine/llm uses optional-interface extension: LLMAdapter is the base, BatchAdapter adds CompleteBatch/BatchEnabled, and consumers discover batch support with a type assertion. A decorator returning a concrete type therefore DROPS that capability — and the loss produces no error, no log, no compile failure. The assertion simply returns false and the caller quietly takes the non-batch path.

TracingAdapter committed exactly this bug and shipped with it: when KNOMIT_LLM_TRACE was set, a batch-capable Gemini adapter lost BatchAdapter for the whole process. It went unnoticed only because CompleteBatch had ZERO consumers repo-wide — the capability was erased but nothing was asking for it. Found by code review during P1.2 (2026-07-21), not by any test.

**Fix, and the pattern for any future decorator:** wrap conditionally — `if ba, ok := inner.(BatchAdapter); ok { return &xBatchAdapter{...} }` — and note this forces the constructor to return an INTERFACE, not a concrete type, since a concrete type cannot conditionally implement BatchAdapter. NewTracingAdapter now returns TracingCloser for this reason. Pinned by TestNewAdapter_PreservesBatchAdapter, which fails against the pre-fix TracingAdapter.

**Consequence:** before adding any decorator to internal/engine/llm (metrics, caching, fallback, routing), check what optional interfaces the inner adapter may satisfy and preserve each one. The decorator stack is Tracing(Resilient(Provider)), so an erasure at ANY layer erases it for everything above.

**What this does NOT mean:** it is not an argument against optional interfaces. It is a warning that they are invisible to the compiler at the wrap point — the type checker cannot tell you a capability was dropped, so only an explicit assertion test can.

STATUS AFTER PR7 (chore/remove-synthesis-job, Q3 of the harness plan): every type this incident names is DELETED. LLMAdapter, BatchAdapter, TracingAdapter, TracingCloser, resilientBatchAdapter, wrapResilient, NewAdapter and TestNewAdapter_PreservesBatchAdapter no longer exist, and neither does the Gemini adapter that was the only BatchAdapter. The resilience.go, trace.go, resilience_test.go and adapter.go refs pin ddb66b59, the last commit that has the pre-deletion code; the _v2 refs pin the PR7 merge 5ad35415. The LESSON is not retired: the replacement wrapper, `llm.WrapChat` (internal/engine/llm/resilience_v2.go), returns the `ChatModel` interface and delegates every method, and ChatModel has no optional interfaces, so there is nothing to erase today. The v2 test to read is TestWrapChat_KeepsCaps in resilience_v2_test.go, which pins that the wrapped model reports the inner model's Caps; the stack is now WrapChat(provider) and, when KNOMIT_LLM_TRACE is set, a tracingChat (trace_v2.go) around it.

WHAT THIS DOES NOT MEAN: that the hazard went away with the code. If a ChatModel ever gains an optional interface (a batch or cache-control extension asserted by type), WrapChat and tracingChat must conditionally preserve it, or the capability vanishes with no error.

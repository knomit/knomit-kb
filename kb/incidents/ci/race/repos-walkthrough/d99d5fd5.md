# Race workflow flaked 8 times between 2026-10-24 and 2026-10-26 in internal/corpus/repos: TestWalkthrough_Detach 7 times (Mount-reply-while-indexing window) and TestWalkthrough_WorkerCrashDuringIndexing once (a stray merger pass parked on the Rebuild's lockBranch); both test-fixture defects, fixed together in PR #653

The Race workflow failed 8 times between 2026-10-24 and 2026-10-26 in internal/corpus/repos, from two independent causes. Both fixes shipped in PR #653 (branch fix/walkthrough-and-script-flakes, merged 2026-10-27 as 0156f299); commits 5e893b28 and 2d981828 are in origin/dev.

1. TestWalkthrough_Detach, 7 failures. Example: run 40350626564 at sha 231e5711, failing at machine_test.go:424 with "expected 'a subscription requires its origin', in chain: 'repo is indexing'". Cause: a Mount reply can arrive while IndexRunning is still true under Options.Synchronous (see the gotcha under corpus/repos/machine/tests), so DetachOrigin was answered ErrIndexing before the origin rule. Fix: commit 5e893b28 adds waitIndexSettled before the Detach.

2. TestWalkthrough_WorkerCrashDuringIndexing, 1 failure. Run 40238806352 at sha e84e937c, failing at machine_test.go:662 with "the merger reached its merge" never satisfied. Cause: host.settle returns when a consensus pass has ENDED, but a second queued pass could start before the beforeMerge hook was installed; that pass parked on the Rebuild job's lockBranch(agent) and, because passes are serialized under consensusMerger.runMu, blocked every later pass, so the hook never fired. Fix: commit 2d981828, where the test holds host.ri.consensus.runMu from before the Rebuild until the hook is installed. The commit records about 21/1000 failures under stress before the fix.

LESSON: settle is not merger-idle; hold runMu to install hooks deterministically. And a Mount reply is not index-idle; waitIndexSettled before Attach/Detach/Swap.

CONSEQUENCE: a red run of either test on a head containing #653 is a real signal, not this known flake. WHAT THIS DOES NOT MEAN: the fixes did not land in #659 or #661, and neither flake was a production bug (test fixtures only; the ErrIndexing-first check order is deliberate).

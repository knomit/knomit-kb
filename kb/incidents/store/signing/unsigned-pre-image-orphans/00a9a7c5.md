# Every signed write left its UNSIGNED pre-image as an unreachable object (store-then-sign-then-store) — so `knomit verify` on real repos always warned orphan-objects; the tests never saw it because they wrote unsigned

SYMPTOM: once F09 PR 2 made test suites sign (the fallback test signer), four strict-Verify tests went red with WARN orphan-objects: store TestVerify_NoGeneratedRefs and storytests TestVerify_CleanRepoIsClean, TestReplay_ResultIsIntegral, TestConcurrency_ParallelReadsDuringWrites.

CAUSE: `signCommitInPlace` read a commit that the caller had ALREADY stored (writeFileToStore / deleteFileFromStore / batchWrite / merge / rebase replay each called `SetEncodedObject` first), signed it, and stored the signed re-encoding under a new hash. The unsigned original stayed in the objects table, reachable from no ref: one orphan per signed write, in production since signing existed. The tests had always written UNSIGNED (no signer, and a nil signer was a no-op), so the path that makes the orphan never ran under test.

FIX (F09 PR 2): `storeCommit(s, signer, *object.Commit)` signs IN MEMORY over `EncodeWithoutSignature` and stores exactly one object; `signCommitInPlace` is gone; the plumbing writers take the signer. Regression anchors: nosignertest TestSignedWrite_LeavesNoUnsignedPreImage plus the four strict-Verify tests (sabotage: re-store the unsigned encoding first turns the first red).

CONSEQUENCES FOR EXISTING REPOS: the fix is FORWARD-ONLY. Repos written before it carry one orphan object per signed commit. They cost space only; they were never pushed (only reachable objects are pushed). Objects live in knomit's SQLite store, not a .git directory, so `git gc`/`git prune` does not apply, and knomit has no object GC (verify.go checkOrphanObjects: the count is informational). No action is needed; do not read the warning as corruption.

DOES NOT MEAN: that the unsigned 'twin' commits reachable on knomit-kb main (584, 2026-05..08) came from this. Those are REACHABLE commits with different trees and parents; these orphans are unreachable and never left the machine.

PATH NOTE at dev tip 8218a187 (verified there 2026-10-20): checkOrphanObjects, named above as living in verify.go, is now Checker.checkOrphanObjects in internal/store/fsck/integrity.go (line 1315; the fsck child, PR #562, kb/architecture/store/fsck-child/bbc2a811.md), still informational. The fix itself moved earlier, with the vcs child (PR #550): the in-memory signer is vcs.StoreCommit(s, signer, commit) in internal/store/internal/vcs/sign.go, whose comment still says no unsigned pre-image is left (it signs over EncodeWithoutSignature and stores one object), and the plumbing writers are in internal/store/internal/vcs/plumbing.go; the old internal/store/sign.go and plumbing.go paths no longer exist. The regression anchors are unchanged in place: nosignertest TestSignedWrite_LeavesNoUnsignedPreImage (internal/store/nosignertest/nosigner_test.go) and the strict-Verify tests (internal/store/verify_generated_refs_test.go, test/storytests/verify_test.go, replay_test.go, concurrency_test.go). The incident's claims are unchanged.

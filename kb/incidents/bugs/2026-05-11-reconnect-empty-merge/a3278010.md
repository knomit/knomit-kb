# Reconnect-after-token-expiry hits unimplemented shared-history merge — Preview Merge shows 0 facts

Symptom: user refreshes expired GitHub token via 'Connect Remote' on same URL; preview shows sensible counts (e.g. 209 local-only, 8 remote-only, 61 shared, 14 dead refs); clicking Preview Merge displays '0 total facts: 0 local, 0 remote' for both 'Local wins' and 'Remote wins'. Root cause: handleApply at internal/web/handlers_origin_session.go:557-564 has a branch on tr.History == 'disjoint' that calls store.Replay; the 'else' (shared history) branch returns an empty applyResult{} with a 'TODO: implement full shared-history merge' comment (commit e87f8445, 2026-03-19, intentionally deferred to v1). Conflict strategy is READ but never consulted on the shared branch. HasSharedHistory returns true whenever local+remote share any commit (bounded 1000-commit walk), so any previously-synced remote ALWAYS lands in the unimplemented branch. Reproduces on every legitimate reconnect attempt, not specific to GitHub. Surfaced design issue: 'Connect Remote' flow conflates first-time-connect with reconnect/credential-refresh — reconnect should bypass test/preview/apply (just SetRemote with new creds; sync loop handles the rest). Also: in single-machine model, local-agent ⊇ remote-agent is the expected reconnect state — it's a fast-forward, not a merge. Status: investigation only, no fix applied as of 2026-05-11.

# Drop tools/motifannex and tools/refprobe; keep tools/calibrate as the one surviving measurement tool

**Options considered:** (1) keep both as lab tools in tools/; (2) drop them; (3) move them to a separate lab repo.

**Rationale for dropping:**
- The motif research phase they served is finished. motifannex was built for phase 2 (#102) and extended in phase 4 (#106). Its last functional change was 2026-08-26. Every later commit was a sweep refactor, and there has been no motif phase work since. The .claude/plans documents it supported are gone.
- Neither tool has a consumer. No Makefile target, CI job, doc or code referenced either one.
- refprobe was a one-shot ref-resolution probe from #102, with one commit, no tests and no flags.
- Deleting them orphans no internal code. motifannex's only unique callees are synthesize.MotifComponentReport, ScoredMotifBridge and MotifReport in internal/synthesize/bridge_motif_report.go. They stay live because `calibrate bridges --kind motif` calls MotifComponentReport. repos.TestQualityConfig stays live through synthesize tests.
- `go mod tidy` was a no-op.
- Moving them to a lab repo was rejected: nothing would run them there either, and git history already preserves them (last present at the parent of the deletion commit).

**The choice:** delete both directories; keep tools/calibrate and update its README.

**CONSEQUENCE (load-bearing):** tools/calibrate is now the ONLY non-test caller of synthesize.MotifComponentReport. If calibrate is ever dropped, or loses its `--kind motif` path, internal/synthesize/bridge_motif_report.go becomes dead production code and should go in the same change. Its only other reference is internal/fact/motif_conformance_test.go.

**Non-scope:** this does not mean research harnesses should never live in tools/. It means a harness whose campaign has ended and that has no consumer should be deleted rather than kept "just in case".

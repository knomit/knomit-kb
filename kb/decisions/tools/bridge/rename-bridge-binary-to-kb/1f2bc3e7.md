# The bridge binary is named `kb`, not `knomit-bridge`, with NO compatibility alias — a clean rename in one step

## Options considered

1. Keep `knomit-bridge` as the binary name.
2. Rename to `kb` and ship `knomit-bridge` as a compatibility alias for at least one release: both names in dist and in the desktop app's bin link, `IsKnomitCommand` accepting both basenames, init rewriting or tolerating old commands in existing .mcp.json / settings.json.
3. Rename to `kb` outright — every template, hook command, Makefile target, desktop link, log-file name, User-Agent string and identity check switches to `kb` in one change; no alias, no migration path.

## Rationale

`kb` won over `knomit-bridge` because the binary is the user-facing CLI of every integration (`kb claude init`, `kb claude hook post-edit`, the MCP `command`), and "bridge" names an implementation detail. `kb` also matches the corpus root folder `kb/`, the `kb://` ref scheme and the knomit-kb repo, so the name pulls the same direction as the rest of the product.

The compatibility alias (option 2) was rejected by the designer: at this stage there is one primary user who owns every installed configuration and can re-run init or hand-edit .mcp.json / settings.json. A compat window would double the surface in `IsKnomitCommand`, the desktop bin-link installer and the init merge for nobody's benefit.

Known consequences accepted with the choice:
- Existing installs' MCP-config entries and hooks that spell `knomit-bridge` become unrecognised by init's idempotence check (`IsKnomitCommand` compares the command basename) — re-running init on such a checkout would ADD a second server and duplicate hooks rather than merge. The fix is to update the configs, not the code.
- `kb` is a two-letter name on a global PATH; a Python package also installs a `kb` command. Accepted.
- "the kb" already means the corpus in facts and docs; the tool now shares the word. Accepted.
- Repos outside this one (OpenClaw plugin, docs site, knomit-kb) still spell `knomit-bridge` and need a separate sweep.

## The choice

Rename the binary output to `kb`. Every occurrence of `knomit-bridge` that names the executable — build outputs, macOS app bundle, server package, AppImage, `.gitignore`, `bridgeExecName`, `IsKnomitCommand`, templates, usage text, hook command strings, log-file default, User-Agent, this repo's own `.mcp.json` and `.claude/settings.json`, READMEs — changes to `kb`. No alias. The Go package path `tools/bridge/` and the `bridge` vocabulary in code comments may stay; only the executable name is the subject of this decision.

## Non-scope

This does not rename the `knomit` server binary, `knomit-okf` or `knomit-desktop`, and does not rename the `tools/bridge` source directory. It does not authorise a migration/rewrite of existing user configs by init — the designer updates those by hand.

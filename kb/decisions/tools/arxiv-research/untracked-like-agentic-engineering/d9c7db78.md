# The arxiv-research job is deliberately untracked in git — there is no history for it, and that is a choice, not an oversight

**Options considered.** (a) Track the job by adding a `.gitignore` negation for `.claude/harness/`, giving the Python package and its ~53 tests normal version history. (b) Track it with `git add -f` on every commit. (c) Leave it untracked, matching `agentic-engineering`.

**Rationale.** `.gitignore:56` ignores `.claude/*`, with negations only for `skills/` and `settings.json`, so nothing under `.claude/harness/jobs/` is tracked today. The human partner chose to keep that consistent rather than carve out an exception for one job.

**Consequence worth knowing before you go looking for it:** there are no commits and no diffs for this job. `git log` will never show its implementation, and a code review of it cannot be driven from a branch diff — a reviewer has to read the working tree. When this was built under subagent-driven development, the per-task review loop was adapted for exactly this reason: reviewers received an explicit file list to read instead of a `git diff` package, because a diff-based review would have silently reviewed nothing while appearing to run.

**The choice.** Untracked, matching `agentic-engineering`. Work happens in place on whatever branch is checked out — which is safe precisely because the files are ignored, so they cannot contaminate an unrelated feature branch.

**Non-scope.** This is not a claim that harness jobs should never be tracked. It is consistency with an existing precedent; a job that grew a larger test suite or multiple contributors would be a reasonable place to revisit it. If it is ever revisited, prefer a `.gitignore` negation over `git add -f`: the force flag is silently forgettable, and a contributor who forgets it commits nothing at all.

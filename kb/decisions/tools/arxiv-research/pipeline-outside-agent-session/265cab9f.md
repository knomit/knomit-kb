# arxiv-research runs harvest/triage/fetch BEFORE Claude starts, which collapses the agent's tool grant to Read+Glob+Grep and removes its entire network surface

**Options considered.** (a) The agent drives fetching from inside its session with `curl`/`WebFetch`, as agentic-engineering does. (b) A Python pipeline runs in the entry point before the agent, materialising ranked shortlist and paper texts into `$WORKDIR`, and the agent only reads local files.

**Rationale.** With fetching moved out, the agent needs no network tool at all: its grant becomes `Read`, `Glob`, `Grep` plus the knomit MCP tools. Three consequences follow, and the third is the one that pays daily:

1. The permission-pinning question disappears rather than being solved. There is no need to determine whether a rule like `Bash(python3 /path/triage.py:*)` survives `;` chaining or `-c`, because nothing is pinned.
2. The prompt-injection surface shrinks to "can cause a bad fact to be written". The agent still reads ~16 untrusted paper texts a day, but holds no tool an injected instruction could act through. A bad fact is already surfaced by the run report for review.
3. The triage filter becomes runnable at zero model cost. Tuning the interest-profile regexes is a diff of two shortlists, not a paid session — which is impossible when the filter lives inside the agent's context.

**The choice.** Stages 0-2 (OAI harvest, abstract triage, full-text fetch) are Python and complete before the agent is invoked. Stage 3 is the agent, reading local files and writing facts.

**Cost accepted.** The agent cannot chase a citation mid-run. It writes `wanted: <arxiv-id>` into the queue and the next day's pipeline honours it — adaptive behaviour survives, one day delayed.

**Non-scope.** This does not generalise to jobs whose work IS the browsing. It applies where the fetch set can be computed deterministically before the model is needed.

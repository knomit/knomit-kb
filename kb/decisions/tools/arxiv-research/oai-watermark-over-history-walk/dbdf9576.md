# arxiv-research tracks crawl progress with an OAI datestamp watermark, not agentic-engineering's revision-history walk

**Options considered.** (a) Mirror agentic-engineering: reconstruct the crawled-URL set each run by walking `crawl-state`'s revision history backwards and unioning every revision's body. (b) Record the OAI-PMH datestamp harvested through, and have the next run resume from it.

**Rationale.** The history walk is a set union whose failure is silent: a partial walk makes old sources look uncrawled and re-fetches them, and it is only detectable if the run reports how far it got. It has already failed once — agentic-engineering's 13th run read 13 revisions, declared "COMPLETE, NO GAPS", and there were more. Measured 2026-08-11, the API was not the culprit; the walk itself stopped early, because `explainHistoryDisplay = 3` means a long history needs several sequential calls each re-anchored at the oldest commit seen.

arXiv removes the need for the walk entirely. OAI-PMH `from`/`until` gives a server-side high-water mark, so progress is a scalar rather than a reconstructed set — there is no walk, therefore nothing that can stop early. Paired with filtering on `<created>`, a v2 metadata bump cannot re-enter as a new paper either.

**The choice.** `harvest-state` carries the watermark. No revision-history walk anywhere in the job.

**Non-scope.** This does NOT mean agentic-engineering should drop its walk. That job crawls arbitrary web feeds which expose no equivalent server-side high-water mark; the walk is the only mechanism available to it. The watermark is available here because arXiv offers OAI-PMH, not because walks are wrong.

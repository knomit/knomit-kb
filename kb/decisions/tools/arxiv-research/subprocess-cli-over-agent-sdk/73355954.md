# arxiv-research drives Claude by subprocessing the CLI rather than using the Claude Agent SDK, because the SDK documents only API-key auth and this machine has no API key

**Options considered.** (a) The `claude-agent-sdk` Python library. (b) Subprocess the `claude` CLI with `-p --output-format json`, which is what the existing bash runner already does.

**Rationale.** Every authentication method the Agent SDK quickstart documents is an API key or a cloud provider: `ANTHROPIC_API_KEY`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_USE_ANTHROPIC_AWS`. Subscription login is not among them, and both the overview and quickstart carry the same note: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Please use the API key authentication methods described in this document instead."

Verified on this machine 2026-08-12: `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` are both unset, `claude` is at `~/.local/bin/claude`, and credentials live in the macOS Keychain. The existing job already runs entirely on the Claude Code login. The Agent SDK overview names the subprocess route as the supported alternative: "To drive the same agent loop from another language, run the CLI as a subprocess with the `-p` flag and `--output-format json`." Moving the caller from bash to Python therefore changes nothing about auth.

**The choice.** One Python entry point that subprocesses the CLI. No SDK dependency.

**The headless and interactive paths differ in three ways, not one** — you cannot both capture output and hold a TTY:

| | headless (cron) | interactive |
|---|---|---|
| prompt | stdin (`input=`) | positional argv |
| flags | `-p --output-format json` | neither |
| stdio | captured | inherited |

Use `subprocess.run`, not `os.execvp` — exec replaces the Python process and loses every step after it. `--permission-mode manual` is correct for both: with no TTY it refuses unlisted tools and continues; with a TTY it prompts.

**Non-scope.** This is not a claim that the SDK is worse. It is an auth constraint specific to a subscription-only machine; a deployment with an API key would face a different tradeoff.

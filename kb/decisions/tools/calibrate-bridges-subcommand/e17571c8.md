# Bridge-quality tuning is a `calibrate bridges` cobra subcommand (dev-only), not runtime telemetry

Options considered: (a) a new standalone tools/ binary for the bridge eval; (b) reuse and enhance tools/calibrate into a cobra root with subcommands (`calibrate embeddings` = today's threshold porting, `calibrate bridges` = new); (c) a subcommand on the shipped knomit binary.

Rationale: both operations DERIVE a tunable from the corpus distribution. `calibrate embeddings` ports retrieval thresholds by preserving percentiles. `calibrate bridges` derives cohFloor/qualityFloor from the corpus's cohesion/Q distribution in the same way. So bridges genuinely IS calibration, which is why it belongs under `calibrate` rather than in a separate 'eval' binary. The project keeps dev and diagnostic tools in tools/, not cmd/ (the shipped binary). `calibrate bridges` needs NO ONNX/ORT libs because it reads precomputed SIMILAR_TO edges and clusters, unlike `calibrate embeddings`.

An earlier idea, runtime outcome telemetry in a persisted `bridge_outcomes` table, was REJECTED. The sessions DB is ephemeral, so the data has no durable home. The data also serves only development (no real knomit consumer), which makes it dev scaffolding, not a product feature.

Choice: restructure tools/calibrate into a cobra root; migrate the existing threshold logic to `calibrate embeddings`; add `calibrate bridges` (a per-bridge component report plus cohFloor/qualityFloor derivation). Dev tool only: no runtime telemetry, schema or storage was added to the product. It tunes the mechanism in decisions/synthesize/bridge-quality-mechanism.

As built (verified 2026-09-23):
- The root is plain cobra with no viper. Flags are read with cmd.Flags().Get*, and the Q-knob flag defaults come from config.Defaults().Discovery.
- `calibrate bridges --kind motif` runs the separate motif report (synthesize.MotifComponentReport), not a variant of the entity/domain table. Since tools/motifannex was deleted, calibrate is that report's only non-test caller.
- Flags are pflag long flags (`--db`, `--cache`). tools/calibrate/README.md documents both subcommands.
- `calibrate bridges` does NOT open its DB read-only. `calibrate embeddings` opens its DBs with mode=ro&immutable=1, but bridges goes through store.Open, which opens read-write, runs migrate.All, and creates the file if the path is wrong. Point --db at a copy of a live index. The help text used to say "read-only" and was wrong until this branch.

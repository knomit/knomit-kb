# OKF frontmatter carries meaning in standard keys, knomit specifics in knomit_* — type maps from fact type, not kind

Options considered for the required OKF `type` field: knomit's `type` (observation/decision/invariant/gotcha/...) vs knomit's `kind` (epistemic/pragmatic) vs a namespaced value like "knomit:decision". For knomit-specific metadata: encode into tags/body, drop it, or use OKF's explicitly permitted custom frontmatter keys.

Rationale: OKF's `type` is a descriptive string for the kind of thing a document is (the spec's example is "BigQuery Table"); epistemic/pragmatic is an axis describing how a fact is USED, not what it is, so it belongs in tags and knomit_kind. The spec permits producer-defined keys and requires consumers to tolerate unknowns, which makes knomit_* the correct channel for confidence/sources/origin/kind/evidence_weight/path — and that same block is what makes the deferred OKF→knomit importer possible, since a foreign bundle lacking it still imports with defaults. knomit refs are code anchors (file:line) and the spec has a named `# Citations` section for exactly that, so putting them there also means a human reading the bundle on GitHub sees them.

The choice: type←knomit type verbatim; title←the body's `# Heading`; description←first sentence of body; resource←`knomit://<repo-id>/<fact-path>`; tags←domain + entities + kind; timestamp←authoring commit time; knomit_* ←confidence, sources, origin, kind, evidence_weight, path. Refs render as a `# Citations` section, not frontmatter. Tree shape: kb/<topic>/<category>/<uuid8>.md flattens the trailing <slug>/<uuid8>.md into <slug>.md, appending the uuid8 only on within-directory collision (in sorted order, so it is stable).

resource deliberately uses repo ID, not repo name (names are per-machine aliases) and deliberately is not an HTTP URL: baking the request host into blobs would make identical knowledge produce different commit SHAs on localhost versus a hosted instance, breaking the determinism the marker depends on.

Non-scope: this does not authorize inventing further knomit-flavored extensions beyond the knomit_* block — every standard OKF key must carry its standard meaning, because the acceptance bar is a foreign ingester.

# knomit.io /explore embeds the real read-only knomit instance full-bleed in an iframe

Decision for the knomit.io live-demo experience (the /explore page).

Options considered:
- Data source: a bespoke React showcase over a baked KB snapshot vs the real knomit web UI against a hosted instance.
- If real instance: launch-out to a demo subdomain, a native demo-mode affordance, or an embedded iframe.
- If iframe: boxed-in-page vs full-viewport with a floating exit widget.

Rationale:
- The real web UI (not a reimplementation, not a snapshot) was chosen so the product proves itself; the previously-considered KbDataSource/baked-snapshot showcase subsystem was dropped entirely.
- Full-bleed iframe (100vw x 100vh) + a position:fixed floating exit widget in the parent page was chosen so the app gets its full canvas (no boxed/cramped feel) while the URL stays knomit.io/explore and the visitor can always return to the marketing site.
- A full public knomit-kb (read-only) is served; the owner accepted exposing internal facts.

The choice: /explore renders demo.knomit.io (a real knomit instance with repos mounted READ-ONLY via a new flag) in a full-viewport iframe with a floating 'back to site' widget. This adds three prerequisites OWNED BY THE KNOMIT REPO (not the site): a read-only repo mount flag, Content-Security-Policy: frame-ancestors https://knomit.io (and not X-Frame-Options: DENY), and CORS for https://knomit.io. The demo instance needs no LLM key (synthesis is a write path, disabled by read-only). This is Phase 2; the static site (Phase 1) ships independently with /explore as a 'coming soon' teaser until then.

# Build knomit.io with Astro in a separate repo, deployed on Cloudflare Pages

Decision for the knomit.io marketing/docs/blog website.

Options considered:
- Framework: (a) Astro + React islands, (b) Next.js static export, (c) Vite + React SPA.
- Repo placement: in the knomit monorepo vs a new standalone repo.
- Reference-content sourcing: fetch from GitHub at build vs vendored copies vs git submodule.
- Hosting: Cloudflare Pages vs Vercel vs Netlify.

Rationale:
- Astro chosen because the site is marketing/content-first: MDX authoring, ships ~zero JS by default (top Lighthouse/SEO), with React islands only where interactivity is needed and Starlight for the docs section. Next.js/Vite-SPA fight a content site on SEO/perf/authoring.
- Standalone repo (NOT the monorepo) chosen so the website's commit history doesn't pollute knomit's, and vice versa.
- Build-time fetch from GitHub chosen for OpenAPI/README so the REST API reference is generated from internal/web/static/openapi.yaml and cannot drift; no hand-copied tables.
- Cloudflare Pages chosen for free, fast static hosting with PR previews.

The choice: Astro (static) + React islands + Starlight, in a new `knomit-site` repo, syncing canonical content from github.com/knomit/knomit at build, deployed to Cloudflare Pages. knomit will be open-sourced at launch so the primary CTA is View on GitHub + clone/make Quick start.

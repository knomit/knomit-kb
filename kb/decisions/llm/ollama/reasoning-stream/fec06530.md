# Ollama Stream builds response blocks in stream order: a thinking run and a content run each close when the stream switches kind or a tool call arrives

OllamaChat.Stream has no per-block indices, so it segments by kind. Thinking lines accumulate in a thinking run and content lines in a text run; opening one run closes the other. A closed thinking run becomes one BlockReasoning (Native {"thinking": ...}) and is sent to the sink as EventReasoning at that moment. A closed text run becomes one BlockText. Tool calls are appended as BlockToolUse in place. The stop reason still reads whether any tool call arrived. Consequence: Response.Blocks, the sink events and the KNOMIT_LLM_TRACE blocks all keep the thinking, content and tool-call order of the stream. Consecutive thinking lines with no content or tool call between them form one block, so a thinking run is not one block per chunk. Anthropic emits one block per content block; Ollama has no block indices, so the run is the unit. This does not change ReplayFor (same-provider reasoning is kept). On replay, ollamaAssistant joins the thinking runs of one assistant entry with a newline (commit 9a045f91); a single run is sent unchanged. DropEndedReasoning does not exist in this repo at HEAD.

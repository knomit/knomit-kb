# Ollama num_ctx: a configured value always wins; unset on a loopback host it is min(trained length, a quarter of usable memory / KV bytes per token) read from /api/show only; unset on any other host, or when KV size or memory cannot be computed, the model is unavailable; no automatic value is claimed safe

Rules, in order (llm/numctx.go): (1) a configured num_ctx wins, capped at the trained length by Caps(); (2) unset on a loopback host (localhost or a loopback IP): num_ctx = min(trained, floor(memory/4 / k)) rounded down to a multiple of 1024, where trained and k (KV bytes per token = layers x head_count_kv x (key_length + value_length) x 2 bytes f16; layers = block_count / full_attention_interval for hybrid models) come from /api/show model_info, and memory = memlimit.Detect() minus the model's size from /api/tags; (3) unset on any other host, or k or memory not computable, or a result below 1024: the model is UNAVAILABLE with OllamaNumCtxUnavailableReason (approved copy), nothing is guessed. A failed /api/show is the ordinary probe-failed unusable path, not an error at boot. The memory share (a quarter) is a policy fraction: a KV cache is allocated at load for the whole window and must leave most memory to the OS, the weights and other work.

Never warm the model: no /api/generate and no /api/ps before the first real /api/chat request. After the first successful chat stream exactly one /api/ps reads size_vram < size and only REPORTS a CPU spill (session log, Settings); it never reloads.

Why no automatic value is safe: free memory, the server's KV cache type and flash-attention setting, other resident models, a discrete GPU's separate VRAM and whether the host is this machine are all invisible to knomit. f16 is assumed, which over-estimates a q8_0 server (the safe side). The config key is the answer where the guard is wrong, and the copy says so.

Does NOT mean the derived window is guaranteed to fit in memory or VRAM. Does NOT mean the example config or code has a default num_ctx: the 32768 default is removed everywhere; any test needing a window sets one. Does NOT apply to the Anthropic provider.

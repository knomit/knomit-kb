# A missing LLM API key is a configuration, not a fault: the adapter wraps llm.ErrNoCredentials and app.New logs it ONCE at info; any other adapter init failure keeps its two warnings

Every first-mission instance logged `WRN LLM adapter init failed: GEMINI_API_KEY ... required` plus `WRN synthesis disabled`, though none needed a key: knomit_review and knomit_hypothesize hand the LLM work to the calling agent, and only the server's own synthesis jobs (the web RunAll) use the server adapter.

Since #412 (merge 55a47911):
- `NewGeminiAdapter` returns `fmt.Errorf("%w: GEMINI_API_KEY ...", llm.ErrNoCredentials)` (internal/llm/resolver.go declares the sentinel; NewAdapter passes it through).
- `logLLMSetup` (internal/app/llm_log.go), called once from app.New: adapter present -> info "synthesis enabled"; `errors.Is(err, ErrNoCredentials)` -> ONE info line saying server-side synthesis is off and review/hypothesize still work; any other error -> warn "LLM adapter init failed" + warn "synthesis disabled".
- "Once" is per process: app.New runs once per serve; nothing logs it per call.

CONSEQUENCE for a new provider: return an error wrapping ErrNoCredentials when its key is absent, or it will be reported as a fault.

WHAT THIS DOES NOT MEAN: a bad or rejected key is still a warning; only an absent one is info.

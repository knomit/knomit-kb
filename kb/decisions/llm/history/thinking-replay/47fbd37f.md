# Anthropic thinking blocks are replayed UNCHANGED (signature included) to ANY Anthropic model; llm.Entry.ReplayFor(provider) drops reasoning only for a DIFFERENT provider (user decision, 2026-11-04)

llm.Entry.ReplayFor(provider string) keeps every block of an entry in order and drops a BlockReasoning only when its Reasoning.Provider differs from the request's provider (or it has no Reasoning). Reasoning.Model still records which model produced the block, but it no longer limits where the block is replayed. renderAnthropic calls ReplayFor("anthropic"), so a thinking block produced by claude-haiku-5-5 is sent, byte for byte, to claude-sonnet-5-5 or claude-opus-5-5 too. That includes display-omitted blocks whose thinking text is empty (replayed as "thinking":"" with their signature) and redacted_thinking blocks.

Why: per the current Claude API docs (preserved thinking), callers should keep sending the full history with thinking blocks and let the API drop what the target model cannot read; dropped blocks are not billed and not counted in input_tokens. Stripping them client-side loses reasoning the target could have read (readability is one-way upward: Haiku 5.5 blocks are read by Sonnet 5.5 and Opus 5.5 on the Claude API and Google Cloud, Sonnet 5.5 blocks by Opus 5.5) and is itself an edit of the history later blocks are bound to.

Consequence: never filter Anthropic reasoning by model in an adapter, router or retry path. What it does NOT mean: it does not mean a moved conversation keeps its reasoning. A downward or sideways switch (Opus 5.5 → Haiku 5.5, say) runs without it, because the API drops those blocks; and reasoning never crosses providers (ReplayFor("ollama") drops it). This replaced the PR2 rule "replayed only to the exact Provider+Model".

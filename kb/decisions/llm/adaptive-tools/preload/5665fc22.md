# The preload budget is P = (window - reply reserve) / 8 capped by the room left: a policy fraction that bounds what a wrong guess can cost, not a measurement, and preload only adds, never evicts

PreloadDivisor = 8 is a policy fraction like the reply reserve's quarter: the guess is a guess, so the most a wrong one may cost is an eighth of the usable room whatever the window. The budget actually applied is min(P, roomLeft) where roomLeft is window - reserve - estimate after the turn's user entry is added, so preload can never push a request over budget and never makes the opening refusal fire; if nothing fits it loads nothing. Each tool's cost is rounded UP to whole tokens (Snapshot.Record() floors the whole tools hook, so the sum of ceilings bounds the real growth of the estimate). Preload does not evict: loaded tools stay, already-loaded ranked tools cost nothing and are skipped, and the first ranked tool that does not fit ends the loop (a cheap low-ranked tool never jumps a big high-ranked one). A preloaded pick is NOT pinned when loaded: it is pinned only once the model calls it this turn (Loop.pinnedTools). Until then it is the first victim of pressure eviction, before any older tool and within the same turn, both between requests (relieve) and inside load admission (load_tools), so a wrong guess of up to P tokens cannot make a turn fail that would have succeeded without preload. Tools the MODEL loaded or called this turn stay unevictable (tool-window eviction invariant 06ed3ef5, on the PR 2 branch). A model that reports no context window gets no preload (P cannot be derived). Does NOT mean 1/8 is tuned or justified by a measurement; do not derive it from a toolset's size.

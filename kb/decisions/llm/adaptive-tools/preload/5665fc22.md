# The preload budget is P = (window - reply reserve) / 8 capped by the room left: a policy fraction that bounds what a wrong guess can cost, not a measurement, and preload only adds, never evicts

PreloadDivisor = 8 is a policy fraction like the reply reserve's quarter: the guess is a guess, so the most a wrong one may cost is an eighth of the usable room whatever the window; pressure eviction removes an unneeded preload later. The budget actually applied is min(P, roomLeft) where roomLeft is window - reserve - estimate after the turn's user entry is added, so preload can never push a request over budget and never makes the opening refusal fire; if nothing fits it loads nothing. Preload does not evict: loaded tools stay, already-loaded ranked tools cost nothing and are skipped, and the first ranked tool that does not fit ends the loop (a cheap low-ranked tool never jumps a big high-ranked one). Preloaded tools join turnLoaded, so they are pinned for the turn (tool-window eviction invariant 06ed3ef5, on the PR 2 branch). A model that reports no context window gets no preload (P cannot be derived). Does NOT mean 1/8 is tuned or justified by a measurement; do not derive it from a toolset's size.

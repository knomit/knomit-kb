# llm.WrapChat retries only while NO event has reached the sink, and its AttemptTimeout bounds the time to the FIRST event, not the stream; the latency histogram still observes one logical request

internal/engine/llm/resilience_v2.go is the v2 twin of resilientAdapter and reuses isRetryable, retryBackoff and the policyFor budgets (anthropic: MaxRetries 0 because the SDK retries the initial HTTP request itself; ollama: 2). Semantics that differ from v1 because a v2 request streams:

- Once any event has been delivered to the caller's sink, a failure is returned as is; replaying would deliver that text or tool_use a second time. Pinned by TestWrapChat_NoRetryAfterFirstEvent (1 attempt, sink saw "par" once).
- AttemptTimeout arms a timer that cancels the attempt (cause errAttemptStalled) only if no event has arrived; the first event stops it. A stream that keeps talking past AttemptTimeout is not cut off. A stall surfaces as an error wrapping context.DeadlineExceeded and errAttemptStalled, which isRetryable treats as retryable.
- observeLLMRequest is deferred once per Stream call, i.e. per LOGICAL request including retries and backoff, matching knomit_llm_request_seconds' documented meaning in metrics.go. (The PR2 plan text said "once per attempt"; that would have contradicted the metric's help text, so the worker kept per-request.)

Caps, Provider and Model delegate, and v2 has no optional interfaces, so the v1 decorator-erasure trap (BatchAdapter lost through a wrapper) has nothing to erase; TestWrapChat_KeepsCaps pins Caps through both WrapChat and NewTracingChat. If an optional interface is ever added to v2, every wrapper must preserve it explicitly.

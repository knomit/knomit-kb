# llm.WrapChat retries only while NO event has reached the sink, and its AttemptTimeout is a liveness check: ANY stream event (a provider event via StreamOptions.Progress, or a sink event) resets the stall timer; the latency histogram still observes one logical request

internal/engine/llm/resilience.go (formerly resilience_v2.go) holds resilientChat, which replaced the deleted resilientAdapter, and reuses isRetryable, retryBackoff and the policyFor budgets (anthropic: MaxRetries 0 because the SDK retries the initial HTTP request itself; ollama: 2). Semantics that differ from the deleted non-streaming adapter because a ChatModel request streams:

- Once any event has been delivered to the caller's sink, a failure is returned as is; replaying would deliver that text or tool_use a second time. Pinned by TestWrapChat_NoRetryAfterFirstEvent (1 attempt, sink saw "par" once).
- AttemptTimeout arms a timer that cancels the attempt (cause errAttemptStalled) only if the attempt has shown NO ACTIVITY. Activity is either a sink event or a call to StreamOptions.Progress, which the Anthropic adapter makes for EVERY provider stream event it reads (message_start, content_block_start/stop, thinking_delta, signature_delta, input_json_delta, message_delta, message_stop; the SDK swallows pings). The first activity disarms the stall timer for that attempt. Consequence: a turn whose model thinks for minutes, or streams a long tool argument, before its first sink event is NOT cut off, because its thinking/signature/input_json deltas count. Only a provider that sends nothing at all for AttemptTimeout (after the HTTP request) is a stall. A stall surfaces as an error wrapping context.DeadlineExceeded and errAttemptStalled, which isRetryable treats as retryable.
- What it does NOT mean: Progress does not forbid a retry. Only a delivered sink event sets the no-retry flag, because only that would be delivered twice; a failure after progress alone may be retried (TestWrapChat_ProgressCountsAsActivity: 2 attempts). And the timer does not bound the rest of the stream: after message_start (the first provider event), a mid-stream stall is bounded only by the caller's context, so a caller that needs a mid-stream deadline must set it on the context.
- Pinned by TestWrapChat_AnthropicThinkingIsNotAStall (httptest: thinking_delta, then 4× AttemptTimeout of silence toward the sink, then text: succeeds in 1 request; headers-only silence: errAttemptStalled) and TestAnthropicChat_ProgressOnEveryStreamEvent (exact Progress/sink interleaving). Removing the o.progress() call in AnthropicChat.Stream turns both red. A new adapter MUST call o.Progress per provider event, or WrapChat will cut off its long-thinking turns.
- observeLLMRequest is deferred once per Stream call, i.e. per LOGICAL request including retries and backoff, matching knomit_llm_request_seconds' documented meaning in metrics.go. (The PR2 plan text said "once per attempt"; that would have contradicted the metric's help text, so the worker kept per-request.)

Caps, Provider and Model delegate, and ChatModel has no optional interfaces, so the decorator-interface-erasure trap of the deleted adapter interface (BatchAdapter lost through a wrapper) has nothing to erase; TestWrapChat_KeepsCaps pins Caps through both WrapChat and NewTracingChat. If an optional interface is ever added to ChatModel, every wrapper must preserve it explicitly.

What stays in resilience.go for it: Policy, policyFor (cases for anthropic and ollama only; bedrock and gemini had cases and lost them because they have no adapter yet), isRetryable, isOverloadedErr, retryBackoff and cancelledErr.

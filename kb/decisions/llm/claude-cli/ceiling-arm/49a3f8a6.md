# The expert ceiling arm (Opus) is served by the claude CLI under the user's Claude Code login through a loopback OpenAI-compatible shim (llm.ClaudeCLIChatHandler over ClaudeCLIAdapter.CompleteSchema) — no API key; the engine's model host function and its schema validation are unchanged

Options: (1) an Anthropic API key arm — ruled out (frontier work runs as Claude Code under the user's plan, ruling 2026-10-12); (2) a Claude Code session answering judgments by hand — not repeatable at eval volume; (3) the internal/llm claude CLI mechanism behind the chat-completions wire the engine already speaks. Chosen (3). CompleteSchema runs `claude -p --output-format json --json-schema <the judgment's schema> --tools "" --strict-mcp-config --setting-sources "" --safe-mode --no-session-persistence --system-prompt <system> [--model opus]` with the user briefing on stdin and the OS temp dir as cwd (no project, no CLAUDE.md, no tools, no MCP), and returns the CLI's structured_output. ClaudeCLIChatHandler serves POST .../chat/completions one request at a time; stop_reason max_tokens becomes finish_reason length (the engine refuses it as truncated); an is_error result is HTTP 502 (a failed judgment). The eval runner starts it on 127.0.0.1:0 for an arm with `claude_cli: opus`. Schema enforcement stays in engine_model.go: the CLI's schema is a mechanism, the host's validation the guarantee.

Measured 2026-10-12 on one question (f01-code-indexer-rollover q2, mode H): 22 calls, 113 s, 2 failed (both `seek`: exit 1, empty stderr; the same request succeeded when replayed by hand) — the shim now reports the CLI's stdout result on a non-zero exit. Consequence: ceiling-arm records must be read with failed_judgments; a transient CLI failure is a failed judgment, not a model error.

# AnthropicChat.Stream returns a *llm.StopError (with the partial Response) for stop_reason max_tokens (Is ErrTruncated) and refusal (Is ErrRefused, plus the stop_details category); pause_turn and the rest are normal Responses

llm.StopError{Reason, Category, Response} is what AnthropicChat.Stream returns, with a nil *Response, when the stream's message_delta ends with stop_reason "max_tokens" or "refusal". Response is never nil: it holds the blocks streamed before the stop and the usage. errors.Is(err, llm.ErrTruncated) holds for max_tokens and errors.Is(err, llm.ErrRefused) for refusal. Category is delta.stop_details.category read from the raw event (SDK v1.26.0 has no stop_details field), or "" when absent; it is informational only, so branch on Reason. No EventDone is emitted for either. "pause_turn" (and end_turn, tool_use, stop_sequence) return the Response with EventDone. The error strings carry no overload marker, so isRetryable is false and WrapChat never retries them. NewTracingChat records a StopError's response (stop_reason, blocks, usage) next to the error.

Why: thinking counts against max_tokens, so a truncated turn can end before any text, and a truncated tool_use may carry partial arguments; a refusal is a normal HTTP 200. Returning either as a plain Response would let a cut-off or declined answer pass for a finished one (the same failure-as-success shape as Ollama's done_reason length, which P8 surfaces as an error).

Consequence for the agent loop (PR4): a StopError ends the turn with a clear message and keeps the partial text; Haiku 5.5 has no server-side fallback, so a refusal is retried only by the user (on Sonnet 5.5). pause_turn is continued by resending the conversation with that response appended, never with a new user message. Pinned by TestAnthropicChat_StopReasons and TestTracingChat_RecordsStopErrorResponse.

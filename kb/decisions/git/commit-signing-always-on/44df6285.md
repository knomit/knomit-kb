# Every commit is signed with SSHSIG when a signer is present; init commits are unsigned by design

Commit signing is ALWAYS ON when a Store has a signer — NO config toggle. SSHSIG envelope (OpenSSH binary format) is used: magic 'SSHSIG' + version + pubkey + namespace 'git' + reserved + hash_algo 'sha512' + signature_blob, base64-armored between BEGIN/END SSH SIGNATURE lines. signCommitInPlace helper: loads commit → encodes without signature (commit.EncodeWithoutSignature) → hashes payload → signer.Sign → sets commit.PGPSignature → re-encodes → stores under NEW HASH (signature changes the hash). Callers MUST update branch refs with the new hash. Signing happens at Store METHOD level (WriteFile, DeleteFile, BatchWrite, merge in sync), NOT in low-level plumbing (writeFileToStore, deleteFileFromStore) — plumbing functions take *storegit.Storer and have no access to signer. INIT COMMITS (creating kb.md, ontology) are UNSIGNED by design — they're created before SetSigner is called on the Store. Bootstrap-only exception. No passphrase-protected keys (machine-local).

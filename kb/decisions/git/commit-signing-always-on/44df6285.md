# Every authored commit is signed with SSHSIG; a Service without a signer refuses to commit (ErrNoSigner); init commits are unsigned by design

Commit signing is ALWAYS ON, with NO config toggle. Since F09 PR 2 it is also mandatory: a Service without a signer returns `store.ErrNoSigner` on every authored write instead of committing unsigned (see kb/invariants/store/signing/fail-closed).

The SSHSIG envelope (OpenSSH binary format) is used: magic 'SSHSIG' + version + pubkey + namespace 'git' + reserved + hash_algo 'sha512' + signature_blob, base64-armored between BEGIN/END SSH SIGNATURE lines. The signer's public key travels INSIDE the envelope, and stock `git verify-commit` with an allowed_signers file accepts it.

MECHANISM (since F09 PR 2): `storeCommit(s, signer, *object.Commit)` encodes the commit without a signature (`EncodeWithoutSignature`), hashes and signs that payload IN MEMORY, sets `PGPSignature`, and stores exactly ONE object. The plumbing writers (`writeFileToStore`, `deleteFileFromStore`) take the signer as a parameter; batchWrite, the merge commit and the rebase replay call storeCommit directly. The old `signCommitInPlace` read an already-stored commit and stored a signed copy under a new hash, which left the unsigned pre-image unreachable (kb/incidents/store/signing/unsigned-pre-image-orphans). Callers still update branch refs with the signed hash, because the signature is part of the hashed object.

WHERE: signing happens at the Store METHOD level (WriteFile, DeleteFile, BatchWrite, merges, replay), where `repoHandler.commitSigner()` resolves the signer before any object is written.

INIT COMMITS (README, ontology) are UNSIGNED by design: the plumbing layer writes them with an explicit nil signer, before any agent-branch work. They lie below every F09 anchor, so no verifier walks them. No passphrase-protected keys (machine-local).

# Git author email subaddressing encodes operation type; replaces git tags entirely

Learning episodes (learn, retract, update, subsume, sync) are encoded in the git AUTHOR field via email subaddressing (+tag). Convention: Author='<agentID> <<agentID>+<operation>@<domain>>', Committer='<agentID> <<agentID>@<domain>>'. Examples: 'dev-a1b2c3 <dev-a1b2c3+learn@agents.knomit.io>', 'Bob <bob+learn@gmail.com>'. Operations: learn, retract, update, subsume, sync. Query via `git log --author='+learn@'` for all learn ops; `git log --author='dev-a1b2c3+learn'` for a specific agent's learn ops. WHY: tags are unique (fragile collision handling with name-<unix> fallback), not pushed/pulled by default, accumulate unboundedly, no efficient operation-type queries. Sync no longer includes 'refs/tags/*:refs/tags/*' in RefSpecs or Tags: gogit.AllTags in FetchOptions — tag push/pull DELETED. MCP handlers (learn, retract, update) no longer call s.store.Tag(); the moment_tag field is removed from tool response JSON. moment_name stays in commit messages. commit_log table gained `operation` and `author_email` columns; populateCommitLog/appendCommitLog parse `+<operation>@` from author email to derive operation. Indexed on (operation, committed_at DESC).

# DiffFacts, the trigger dispatcher's two-tree diff, is a vcs-backed Service operation (Service.DiffFacts), not a facts.Repo method: the facts handles hold no vcs methods, and a forward on facts.Repo would break the no-facades rule

DECISION (PR E3, project owner via the master session, 2026-10-21, under ruling part 2 of kb/decisions/store/pr-e/handles/a6726f14.md). The trigger dispatcher (internal/corpus/repos/triggers.go, advance) needs the whole-ontology-root two-tree diff between a watermark commit and the head, with NO ancestry check (the advance may be a rewind replay, which ChangesUnder refuses). That diff is vcs.Repo.DiffFacts (internal/engine/store/internal/vcs/changes.go): a read of the git layer. It was reachable as tr.DiffFacts only because facts.TriggerIndex listed it and the parent's repoHandler (which embeds *vcs.Repo and *facts.Repo) satisfied the interface. E2 (#573) removed the *vcs.Repo embed from facts.Repo, and E3 deletes TriggerIndex, so facts.Repo no longer has DiffFacts.

OPTIONS CONSIDERED. (a) A forwarding method facts.Repo.DiffFacts calling rh.vr.DiffFacts: rejected, it is exactly the pass-through the no-facades convention (kb/conventions/go/package-boundaries/no-facades/44ec3b17.md) forbids on a facts type. (b) Move the diff body into facts: rejected, it is a git-tree read with no fact-specific logic, it lives with the other changes readers in vcs/changes.go (guarded by TestChanges_CallsAreAllowlisted, which reads that file by path), and moving it would drag the guard and its tests. (c) Keep it in vcs and expose it as a vcs-backed Service operation, like OntologyAt, OntologyFileAt and HasSharedHistory: chosen.

WHAT WAS BUILT. Service.DiffFacts(ctx, from, to plumbing.Hash) ([]PathChange, error) in internal/engine/store/service_vcs.go calls s.rh.DiffFacts (the embedded *vcs.Repo). The dispatcher's advance takes the *store.Service and calls svc.DiffFacts; its other store reads go through the *facts.Repo it gets from svc.FactsRepo().

CONSEQUENCE. (1) The repos dispatcher guard (internal/corpus/repos/triggers_guard_test.go) lists `svc.DiffFacts` where it listed `tr.DiffFacts`; the key is as narrow as before (an exact receiver.method, not the anonymous `?.DiffFacts`). (2) Do not add DiffFacts to facts.Repo or facts.Index, and do not hand the dispatcher a *vcs.Repo: it would regain every git-layer method. (3) A future vcs read the dispatcher needs follows the same route: a Service method over rh, with its own allowlist key.

MISREADING. This does not make DiffFacts a write door or a general git door: it is a read that returns path changes, takes no lock, and the Service method is the whole of its surface.

VERIFIED at the PR #575 merge f41adda1 (re-read there): Service.DiffFacts(ctx, from, to plumbing.Hash) ([]PathChange, error) is in internal/engine/store/service_vcs.go and is one call, s.rh.DiffFacts, the embedded *vcs.Repo; the dispatcher's advance calls svc.DiffFacts (internal/corpus/repos/triggers.go) and its other store reads go through the facts.Repo bound as tr from svc.FactsRepo(); the dispatcher allowlist in internal/corpus/repos/triggers_guard_test.go lists svc.DiffFacts. The vcs body is unchanged in internal/engine/store/internal/vcs/changes.go. This Service method is one of the vcs-backed operations the no-facades convention (kb/conventions/go/package-boundaries/no-facades/44ec3b17.md) exempts.

UPDATE (E7a, PR #584, merged into dev as 32414d74; re-read at 32414d74): DiffFacts is no longer the only worked example of a vcs-backed Service operation. The ten branch operations HeadCommit, ListBranches, CreateBranch, DropBranch, DefaultBranch, SetDefaultBranch, AgentBranchOwner, SetAgentBranchOwner, BranchInfo and GetExperiment follow the same route: a one-line Service method over s.rh in internal/engine/store/service_vcs.go and an exact allowlist key. In the dispatcher's allowlist (internal/repos/triggers_guard_test.go, used by internal/repos/triggers.go) the keys `svc.Branches` and `?.HeadCommit` were replaced by the exact `svc.HeadCommit`; this is strictly NARROWER, because `?.HeadCommit` matched ANY x.y.HeadCommit() call in the file while `svc.HeadCommit` matches only that receiver. Do not read the dispatcher's use of svc.HeadCommit as licence for a bare `?.X` key.

MOVED (PR #632, 14c, merged as ee850fd6): the dispatcher cited here now lives in internal/corpus/repos/trigger (triggers.go; its no-write allowlist is trigger/triggers_guard_test.go); file and identifier names in the text above are the pre-move ones (triggerDispatcher is trigger.Dispatcher). The dispatcher still calls svc.DiffFacts once per distinct watermark in phase A. The refs are re-pinned to ee850fd6; behaviour is unchanged (kb/architecture/repos/triggers/dispatcher/a01f40fc.md).

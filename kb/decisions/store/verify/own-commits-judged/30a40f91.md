# User ruling 2026-10-16, item 2: "Fix" — the fleet master's own commits are judged before they move main, on every path that moves or publishes the fleet's main (BUILT by PR #533)

THE QUESTION. Every judge (receive-pack, the master's fetch judge, the merger's re-judge) ran only where a MEMBER's branch enters the fleet repository. The master's own writes (root, leaves, CRL, revocations, host record, master marker, its own record, the merges of members' branches) reached main with no judge at all, so a master bug or a bad merge could publish a commit that every member's host would have refused. The question put to the user was whether to close that gap; the answer was the single word "Fix".

THE DECISION. Build judgeOwnRange and run it before main moves in AdvanceLocalUpstream, PublishUpstream, PublishUpstreamChange and PublishTo (BUILT, PR #533, squash commit 6f241959 on dev). Rules, scope and refusal behaviour: kb/invariants/store/verify/own-range. Fleet repository only; a knowledge base's main stays unjudged.

CONSEQUENCE OF THE CHOICE, accepted with it: a refused own commit holds main where it is until an operator drops it, and nothing written after it reaches the members. That made a way out necessary, which no tool offered (the store cannot remove a commit from a branch; receive-pack refuses a push to the own branch; a revert or stand-down would be judged with the refused commit still in the range), so the same PR built Drop (kb/architecture/fleet/drop-commit).

SIDE EFFECTS found while building it, kept because they follow from the ruling: (1) the #532-era shape 'revoke then re-enroll within one second' produced two leaves with the same NotBefore and leaf-renewal refused the replacement; pki.IssueTimeAfter now issues the new leaf strictly later. (2) Enroll of an id that was revoked but never joined (no member record) is refused 409 never_joined up front, because leaf-renewal needs that id's one member record and the judge would refuse the leaf commit (kb/invariants/fleet/enroll/5c5a3bef.md). (3) A merge bringing a pki file another parent already holds adds nothing (kb/invariants/store/verify/artifact-rules/fd3ab8ab.md), because the master's own merge of a member's older branch was refused by its own judge.

WHAT THIS DOES NOT DECIDE: it does not judge other repositories' own writes (they are validated at the source instead, kb/decisions/fact/validation/enforced-everywhere), and it does not make the master's refusal a member-style 'commit refused' notice.

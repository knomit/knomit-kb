# Decision (user, 2026-10-18): the switch itself is the signal. The first sync with a DIFFERENT origin takes the ordinary merge path and is never rewound; the rewind runs only when the SAME origin's main moved back (#544)

DECISION (PR #544, merged into dev as 8a01d3ca, read there). When the origin's identity differs from the one recorded at the last full round, the round is a SWITCH (remoteIndex.sync: switched = recorded != "" && recorded != identity). Local main still reconciles to the new origin's main as always; the agent branch then takes the ordinary merge path (reconcileAgentMerge, kb/decisions/store/origin-sync-merge-based/fae61208.md) EVEN WHEN main's reconcile reported ModeRewound (reconcileNowSwitched sets rewound = false on a switch). The new origin's main is merged in, everything the branch holds is kept, and the loop pushes the branch. The rewind replay (reconcileAgentRebase) runs only when the SAME origin's main moved back; those files are byte-identical to dev before #544.

USER RULING (2026-10-18), quoted: "when I swtich the main I already have locally (the consensys) from O1 is obvious ahead of O2 - so there IS a way to detect switch vs remove: I am switching NOW and the O2's main is behind my local main"; and "anytihng else that was added that does some funky stuff should go away". Reasoning: at the moment of a switch local main is the OLD origin's consensus, so a new origin whose main is behind or beside it is another repository's state, not a removal. Removals happen on the SAME origin.

EXCEPTION KEPT: unrelated histories (the agent branch and the new main share no commit; branchSharesHistory false) keep the pre-existing rules, unchanged from dev (issue #541 will handle them).

WHY THE EARLIER CROSS-ORIGIN DESIGNS WERE REMOVED (built on the #544 branch over several rounds, never merged, no fact was written for them): a forget step with marks, flags, signing and own-key filters, snapshot sets with classification, left-out refs, derived reports and replay lists. Each automatic rewrite of the branch on a switch lost information (signatures, merge resolutions, authorship) and each fix opened another failure window; this is the pattern guideline kb/decisions/store/sync-design/snapshot-and-reconcile/8f04bc80.md names. The merged design rewrites nothing: nothing is rebuilt, replayed, re-signed, left out or paused.

CONSEQUENCE (accepted by the ruling): on a switch the branch keeps everything it held, including commits that came from the OLD origin (other writers' commits, an old fleet master's writes). They are pushed to the new origin inside this copy's branch, unchanged and not re-signed, so a fleet's new host may refuse some of them (#528 N1 class, kb/invariants/store/remote-reconcile/replay-stop/5482c3ab.md). Residuals: the gotcha 'Known residuals of the origin-switch design (#544)' under kb/gotchas/store/remote-reconcile/origin-switch-residuals/.

MISREADINGS. (1) 'The rewind is gone': it runs unchanged for the same origin. (2) 'A switch is any change of the stored URL': no, a respelling or a credential change of the same origin is not one (the origin-identity invariant under kb/invariants/store/remote-reconcile/origin-identity/). (3) 'Nothing is ever dropped after a switch': the SAME origin's later rewind still drops consumed commits it lacks.

PINNED BY (store, remote_origin_switch_test.go, full Sync and Push against real bare remotes; sabotaged against the branch head): TestSync_SwitchToAnOriginBehindDropsNothing, TestSync_SwitchToADivergedOriginMergesNormally (both red on dev), TestSync_SwitchToAnUnrelatedOriginKeepsTheExistingRules (guard; red if the merge path is also taken for unrelated histories), TestSync_SameOriginMovedBackStillRewinds (guard; red if every round counts as a switch). Rewinding on a switch turns the first two and the failed-round test red.

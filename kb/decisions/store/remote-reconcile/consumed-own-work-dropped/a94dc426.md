# Decision (user, 2026-10-17): when an origin moves main back, the rewind drops the branch's CONSUMED own commits that the new upstream lacks, own experiment merges included, idle branch or not; accepted as git's normal behaviour, the same as `git pull --rebase` with fork-point

DECISION (the user's ruling on the residual raised by the #539 review, S1; 2026-10-17). In the user's words: "I think this is how git works".

THE QUESTION. Since #539 an idle branch's CONSUMED own work (commits at or below the watermark) that the new upstream lacks is dropped: the branch is rebuilt on the upstream and the next force-push removes the work from the origin's agent branch too. That includes an own committed experiment merge that was pushed and consumed, when nothing was written after it (review constructions R1: origin moves back to an ancestor; R2: diverged upstream). Before #539 the empty-walk no-op kept such work, but only on an idle branch: one write on top already dropped it (R3), so the new behaviour is the existing stop rule applied consistently. The shape is identical to an origin that LAGS rather than scrubs (re-attaching to a backup or mirror; the dead-master fallback, where a member's own commit x that only the old master's merge held is below its watermark and is not replayed), so the rewind cannot tell the two apart.

OPTIONS. (1) Keep the drop: consumed work the origin no longer holds is not replayed. (2) Keep consumed work through a signal separating 'consumed from an origin that later scrubbed it' from 'consumed from a master that died'; no such signal exists in the store.

THE CHOICE: option 1. Accepted as git's normal behaviour (the user's comparison: `git pull --rebase` with fork-point).

CONSEQUENCES. (a) Treat an origin that moves main back as authoritative about what is consumed. (b) A re-attach to a lagging backup or mirror drops the consumed work the mirror lacks. (c) The test for the dead-master fallback deliberately leaves x unasserted.

WHAT THIS DOES NOT MEAN. 'No own work is lost by a rewind' is true only for work ABOVE the watermark. It does not decide the other residuals (kb/gotchas/store/remote-reconcile/rewind-residual-leaks/): the disjoint case is issue #541, the no-watermark case is being fixed (PR #542), and an own edit of a removed file is accepted separately.

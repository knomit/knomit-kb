# #364: knomit_changes reads ONE repo per call, chosen by `repo` (12-hex id, default the bound write repo) at `branch` (default that repo's BOUND branch) or `consensus: true` (the repo's recorded upstream, whatever it is named); the prefix stays ontology-root-relative and refuses kb://; the bookmark is `<repo12>:<commit40>` and carries the repo but NOT the branch

DECISION (designer, 2026-10-02, issue #364). Through a lens, knomit_changes could only read the write mount at its upstream; nothing addressed another mount.

CHOICE:
1. ARGUMENTS. `repo`: 12-hex repo id from knomit_repos, must be a mount of the binding; default = the bound write repo. Names are refused (ids only in the API, per 10a3bcc0). `branch`: a git branch name (main, agent/<id>, exp/<name>); default = the BOUND branch of that repo (write repo: the agent branch, or the experiment the session is in; read mount: the branch the lens reads it at). Refused if the branch does not exist in that repo. `consensus: true`: read the repo's recorded consensus branch (Service.UpstreamBranch: origin branch, else recorded consensus) — the per-repo way to ask for consensus without assuming `main`; mutually exclusive with `branch`. `prefix`: unchanged, ontology-root-relative; a `kb://` prefix is refused with a pointer to `repo` + `prefix`.
2. BOOKMARK. Response returns `bookmark` = `<repo12>:<commit40>`; `head` stays the raw 40-hex (it is still knomit_explain's `commit`). `since` accepts the bookmark form or a raw hash (meaning the target repo). A bookmark whose repo differs from the target is refused BY NAME; the repo is NOT inferred from the bookmark (`repo` still defaults to the write repo). The bookmark deliberately carries no branch: a since from main used against an experiment forked from it is a legitimate question, and the existing ancestry check refuses what is not.
3. RESPONSE gains `repo` (12-hex) and `branch` (always the RESOLVED name, so a consensus:true caller learns it). Rows are kb://<id>/... iff the repo is not the write repo (the 10a3bcc0 one-form rule still governs fact paths).
4. CURSOR always records repo AND branch; a cursor missing either is INVALID (no legacy-cursor compatibility: designer ruling 2026-10-02, no cursor had been minted before this change). A cursor passed alone routes to its recorded repo/branch; an explicit repo, branch or consensus that contradicts it is refused. REST /repos/{repo}/branches/{branch}/changes keeps its shape; its cursor also records repo+branch and refuses one minted for another repo or branch. A bookmark with an empty or malformed commit half (e.g. `<repo12>:`) is refused as an unknown since, never treated as 'omit since'.

BEHAVIOUR CHANGE ACCEPTED: the default used to be the write repo's CONSENSUS branch; it is now the BOUND branch (normally the agent branch). An agent sees its own writes immediately, and the default answer is machine-local — two synced machines get identical answers only with consensus:true. Coordination agents that need the shared history must pass consensus:true; the tool description says so. No MCP caller existed when this changed.

EXCEPTION TO 10a3bcc0: that decision rejected a `repo` argument on MCP tools because a fact path plus a repo argument can disagree (misrouting). For knomit_changes the repo is the SUBJECT of the call and the prefix is a folder, not a fact path, so a repo argument is allowed here — scoped to knomit_changes only; it is not a precedent for fact-path tools.

REJECTED: kb://<id>/ in prefix (repo-relative vs root-relative ambiguity; a wrong base silently reads an empty tree); probing other mounts for an unknown since (unnecessary once the bookmark carries its repo); an opaque bookmark token hiding the hash; consensus as the default (designer chose binding-follows); a reserved branch value like `@consensus` (git permits that ref name, so it could collide); multi-mount fan-out (WriteFirstWinners would hide a shadowed mount's change).

WHAT THIS DOES NOT MEAN: the tool still reads exactly two trees with no clock, commit log or write; a per-commit history walk is a separate issue.

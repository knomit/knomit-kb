# The agent keeps its `changes` bookmark (the returned `head`, a commit hash) in its OWN state — knomit writes nothing for F05; a knomit-written private-state cursor fact was rejected

**Options considered** (same proposal and approval as the net-difference decision):
- A. knomit saves each agent's cursor as a private-state fact at `.knomit/inbox/<slug>/cursor.md`, updated after every check (the F05 design-set draft; the write path exists since `.knomit/<area>/` became writable).
- B. The agent stores `head` wherever it keeps its own state and passes it back as `since`; knomit offers nothing and writes nothing.

**Rationale.** A costs one commit per check per agent on the agent branch; each is pushed, merged into main via the PR flow, fetched and indexed by EVERY instance, would wake an F06 wait on any prefix covering `.knomit/`, and would fire F08's root `push-now` triggers — pure noise at fleet scale; a non-unique `<slug>` makes two instances write one path and conflict on main. B needs no write path at all, and with net-difference semantics the bookmark is only a HINT, not a correctness requirement: losing it costs one call without `since`, which returns the folder as it is now. The agent's durable truth is already in git (its working queue), and skills re-derive from state at task boundaries. This follows the F03 lesson: the simplest shape, no automation, knomit stores nothing on the agent's behalf.

**The choice.** B, approved by the user on 2026-09-26. The user's confirmation, as relayed by the master session (verbatim user words not available to the recording worker): "the agent keeps the bookmark (a commit hash), knomit writes nothing, no clock anywhere." Enforced in code by an allowlist guard and snapshot tests that fail on any write from the changes read (see the cited invariant).

**Non-scope.** This does not forbid an agent from choosing to keep its own bookmark in a `.knomit/<area>/` fact it writes itself — it forbids knomit writing one for it. It does not decide how F08's skills store the bookmark.

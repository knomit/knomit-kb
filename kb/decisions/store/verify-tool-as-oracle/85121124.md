# Verify is production debugging tool AND test oracle; it checks 13 categories and only over the branches the index maintains

Service.Verify(ctx, opts) returns an IntegrityReport that BOTH the knomit verify CLI and the invariant test suite use.

# BRANCH SCOPE (changed 2026-08-12 — read this before the category list)

Parity checks run ONLY over branches the index maintains, NOT over every refs/heads/* ref. The maintained set is the union of meta.last_commit:<branch>, HEAD's target, and meta.agent_branch_owner — see kb/architecture/store/index/maintained-branch-oracle. Every other local ref (another machine's agent branch arriving by fetch, generated okf/* residue) is listed in IntegrityReport.Skipped and NOT parity-checked. VerifyOpts.AllBranches restores the old behaviour deliberately.

This is not a loosening for convenience. Before it, Verify demanded SQLite parity for refs the indexer never touches, and on a live five-repo home produced 8128 errors of which 8128 were false, exiting 1 permanently.

# THIRTEEN CATEGORIES (constants in internal/store/verify.go)

Per maintained branch: (1) git-reachability — full walk from the branch ref, every tree entry resolves; (2) commit-log — branch_commits visibility parity, PLUS a repo-global orphan scan for commit_log rows whose commit is not an object; (3) commit-parents — stored DAG edges vs the commit objects' parents; (4) facts-coherence — three-way branch_facts/facts/tree blob_hash triangle; (5) fact-format — Warning severity, Deep:true only.

Repo-global: (6) branches-table — ref→row for MAINTAINED branches only, row→ref for ALL refs (asymmetric on purpose); (7) embeddings-coverage; (8) embedding-identity — meta.embed_model_id / embed_dim vs the configured model, which coverage's row counting cannot see; (9) graph-coherence — live Fact nodes keyed by (path, blob_hash) vs the facts table; (10) derived-tables — fact_domains / fact_domain_tokens / fact_entities; (11) database — PRAGMA quick_check and foreign_key_check; (12) schema-version — schema_migrations missing or dirty; (13) orphan-objects — objects unreachable from any ref, Warning + a COUNT.

The branch-facts-table category and its checkBranchFactsParity stub are GONE (the stub was `return nil`, and facts-coherence already covers the triangle).

# WHAT THIS DOES NOT MEAN

1. "Verify is NEVER atomic across branches — it locks per branch and releases before the next" is FALSE and is the DANGEROUS reading. Verify acquires lockBranchRead for EVERY branch it checks up front and defers every unlock, so ALL of those read locks are held SIMULTANEOUSLY for the ENTIRE run. That is deliberate — it is what makes the report a consistent cross-branch snapshot instead of a torn one. The operational consequence is the opposite of the old wording: a Verify on a busy repo BLOCKS EVERY WRITER on every branch it covers until it finishes, and a concurrent index Rebuild (which holds the write side of the same per-branch RWMutex) BLOCKS Verify. Do not treat Verify as a cheap incremental probe you can fire on a live repo. (Skipped branches are NOT locked — no check reads them.)

2. The commit-log category does NOT check a TWO-table index. The commit index is THREE tables — commit_log (per-path) + branch_commits (visibility) + commit_parents (DAG edges). All three now have coverage, but in different directions: branch_commits bidirectionally, commit_parents by edge comparison, and commit_log by ORPHANS ONLY. The missing direction on commit_log is deliberate — a no-op commit legitimately has zero commit_log rows, which is why parity moved off it in the first place.

3. embeddings-coverage is NOT unconditional: checkEmbeddingsCoverage returns early with zero issues when no embedder is configured. A no-embedder store reports clean because it was never checked.

4. "Clean" does not mean "everything was examined". Warnings never affect IsClean, and unindexed branches are skipped by design — IntegrityReport.Skipped and the Format header are where that is stated. Read them.

5. Verify itself writes NOTHING. PruneGeneratedRefs (the --prune-generated-refs repair for okf/* residue) is a separate call the operator asks for by name.

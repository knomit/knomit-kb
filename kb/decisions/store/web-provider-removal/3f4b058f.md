# W0g1 deleted commitsProvider: logPaginated and commitDetail are package functions in internal/edge/web, and the commits tests read a real store whose requested branch is not the agent branch

W0g1 (PR #613, merged as f0b81155; re-read there) deleted commitsProvider and defaultCommitsProvider. Their method bodies are now the package functions logPaginated and commitDetail in internal/edge/web/handlers_commits.go, with the same bodies:
- logPaginated uses ri.WithRead; a repo with no live store (nil svc) yields no entries and a nil error; a store error is returned unchanged.
- commitDetail uses ri.Acquire (not WithRead, because the per-file title resolution reads after the closure would end). An error from Acquire, a nil svc or a missing commit reaches handleHALCommitDetail, which answers 404 'Commit not found' with err.Error() as the detail.
handleHALCommitsList(b, ontologyRoot) and handleHALCommitDetail(b, ontologyRoot) take no provider, and storeProviders lost its commits member (4 remain: factReader, factWriter, factSub, origin). webInterfaceAllowlist went from 6 to 5 names: FactReader, FactWriter, factSubProvider, originProvider, RefResolver. No new test hook was needed: the stubs never failed a commits read, and a real failure pins the list error path (an unknown `after` cursor gives a 500 whose detail contains 'LogPaginated: CommitLogQuery: after lookup').

CONSEQUENCE: a commits test writes real commits on a real store; the helper newCommitsFixture is in handlers_commits_test.go, and newSpacedCommitsFixture (stamps c5, c6 and c7 in distinct seconds via awaitNextSecond, costing about two seconds) is for the test that pins dates only. Commit authors come from the store: the name is the last segment of the writing branch and the email is <name>+<operation>@agents.knomit.io. A detail fixture needs at least two files under the root in EVERY commit whose title source a test pins (see kb/conventions/testing/web/99f75ede.md, fourth instance).

DOES NOT MEAN: (1) that the branch of commitDetail's at-commit and before-commit title reads is tested: those reads ignore the branch by design (kb/gotchas/store/anchored-read-ignores-branch/2b146823.md). (2) that handleHALCommitsList's `entries == nil -> []` guard is exercised: it is dead, because items is built with make(..., 0); the mutant is equivalent. (3) that the remaining five interfaces are the recommended pattern; W0g2 to W0i delete them.

UPDATE (12f, PR #630, merge 33eb0307; re-read there): logPaginated, commitDetail and the two handlers moved to internal/edge/web/api/kb/handlers_commits.go. Two clauses above describe the W0g1 state and are no longer true: (1) logPaginated returns ri.WithRead's error as-is (there is no nil-svc branch); (2) an Acquire refusal in commitDetail (httpx.StoreUnavailable) is answered 503 by handleHALCommitDetail, and only a missing commit (detail == nil) reaches the 404 'Commit not found'.

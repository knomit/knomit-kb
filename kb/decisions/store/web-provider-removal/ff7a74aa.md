# W0i deleted originProvider and storeProviders: getOrigin and setOriginUpstream are package functions in internal/edge/web, web declares no interface, and the origin and repo-listing tests run on real stores

W0i (PR #619, merged as 585974c5 on dev; re-read there) deleted originProvider, defaultOriginProvider, providers.go (storeProviders and withDefaults), the Server.providers field and the `p := s.providers.withDefaults()` line in apiRouter. This COMPLETES the W0 series: webInterfaceAllowlist is empty and internal/edge/web declares no interface type. Verified at 585974c5: git grep finds none of originProvider, storeProviders, withDefaults or defaultOriginProvider in any .go file except a comment in the archtest, and providers.go does not exist.

- defaultOriginProvider.GetOrigin is the package function getOrigin(_ ctx, ri) in handlers_origin_hal.go, same body: ri.WithRead, then svc.Remote().GetRemote("origin"). An Acquire failure is RETURNED as errOriginNoStore (acquireFailed wraps it), not swallowed. The ctx parameter is unused (Remote takes none) and kept so a later store-layer ctx needs no second signature change.
- defaultOriginProvider.SetOriginUpstream is the package function setOriginUpstream(_ ctx, m, ri, branch), same body: originsOf(m) first (ErrManagerStopped on a stopped manager), then under WithRead: GetRemote, refuse "no origin configured", ConfigureGitRemote (refspec first), Origins.SetBranch (restore the refspec on failure), svc.Remote().SetOrigin. An Acquire failure returns errOriginNoStore. The ordering (refspec before stored branch) is load-bearing and documented on the function.
- handleHALGetOrigin(b), handleHALSetOrigin(b, m), handleHALSetOriginUpstream(b, m), handleHALDeleteOrigin(b, m), remoteHealthOf(ctx, ri) and handleHALRepos(b, m) no longer take a provider.
- A saved "cert" auth method is DELIBERATELY not carried into a partial PUT's attach (handleHALSetOrigin: `existing.AuthMethod != "cert"`): a stored cert is knomit's decision, not an input, the attach decides again (Manager.ResolveOrigin), and carrying it would hit repos.ErrCertNotAnInput and answer 400 "Invalid origin".

PR-REPORTED TESTS (not re-run): GET /origin and GET /repos read real stores (newRealStoreManager) with the origin injected by svc.Remote().SetOrigin and status written by real store calls (a real Push to a local bare remote for "ok", a Push to a missing path for "error", Remote().RecordSyncError for a sync error). PATCH and PUT run on newControlDBTestServer (started Manager, control.db) with real attaches to local bare remotes; PATCH upstream is pinned by two different branches (the echo is not a constant); PUT records the requested branch; PATCH keeps the injected AuthToken; a partial PUT does not carry a stored "cert". Failure paths are real states, see kb/gotchas/web/origin-endpoints-no-store-status-matrix/. UNREACHABLE without a new hook (stated in the PR): a GetRemote status-row query error in getOrigin and in setOriginUpstream; no remotesync fault hook exists and W0i adds none.

CONSEQUENCE: new origin code takes *repos.RepoInstance / *repos.Manager and is tested on a real store; do not reintroduce an origin seam. Both origin helpers return WithRead's error (unlike the web read helpers, see kb/gotchas/web/read-helpers-drop-withread-error/88e05f43.md).

DOES NOT MEAN: that web has no injected test seams of any shape. A function-typed seam is still not detected by the guard (kb/conventions/go/package-boundaries/web-no-interfaces/d36fa222.md). Nor does it mean the origin endpoints agree on what a missing store looks like.

# Web failure-path tests fail a read through a fail-only mustBeTest hook in the package that OWNS the read, not through a provider stub or a widened index.Overrides.Reads

DECISION (project owner, 2026-10-22; built in W0a, PR #598, merged as eef4ca7a; re-read there). Web tests that made a read fail through a provider stub now fail it through a mustBeTest hook in the package that OWNS the read, installed per store.Service (tests in package store, internal/engine/store/owner_fault_hooks_test.go, because a child package cannot build a *Service). Hooks: index.Facade.SetReadFaultForTest (reads Stats, Activity, Completions, RecentFacts, Search, ExplainFact, FactLiveAtCommit), facts.Index.SetReadFactFaultForTest / SetListDirFaultForTest / SetWriteFaultForTest (beside the pre-existing SetDeleteFaultForTest), vocab.MotifIndex.SetReadFaultForTest (ClustersUnder, Definitions, VocabularyHealthUnder, AliasRows). Each is FAIL-ONLY: it returns the injected error from the read before any work and never fakes an answer.

OPTIONS: (a) widen index.Overrides.Reads to error on every read; (b) per-owner fail-only hooks; (c) real failures only (closing the store). CHOSEN (b). REJECTED (a): E8 deliberately kept Overrides an observer except for four reads (kb/decisions/store/pr-e/e8-test-doubles/0272840a.md); the fault is a separate field next to Overrides, so Overrides.Reads can still observe and sleep for a per-mount delay on the same Facade. REJECTED (c): closing the store may hit the 503 acquire-refusal path instead of the 500 read-error path and lose coverage.

AFTER REVIEW (e85b983b): read names are typed (index.ReadName, vocab.ReadName, one const per faultable read; the hook is func(ReadName) error); the restore funcs of the facts and vocab setters put back the PREVIOUS hook (SetDeleteFaultForTest still restores nil); hook closures can run on several goroutines (lens fan-out), so recording closures must be goroutine-safe. Guard TestFaultHookSettersDeclaredInTestseams (test/archtest/test_seams_test.go) is keyed by (package, receiver, name), because SetReadFaultForTest exists on both index.Facade and vocab.MotifIndex (a name-only check stayed green when one moved out of testseams.go), and requires each setter declared exactly once in <pkg>/testseams.go with mustBeTest("<name>") as its first statement. The facts reader is NOT observed by Overrides.Reads: a 'must not be called' check on ReadFact uses SetReadFactFaultForTest.

NOT BUILT, because no web test fails them through a stub: remotesync GetRemote, index LogPaginated, CommitDetail, GetByPath, Highlights, Incoming/OutgoingAtCommit, FactExistsAt. A later W0 PR that needs one adds a failRead line at the read and a setter to the doc.

MISREADINGS: (1) nested reads fire the fault: a Search fault also fails RecentFacts with Text set; a ReadFact fault also fails the write path's prior-refs read. (2) A fault on one Service never touches another; it is not store-wide like Overrides. (3) A 'must not be called' stub (incomingErr, readErr) is not a fault: it is an observer.

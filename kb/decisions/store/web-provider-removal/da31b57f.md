# W0c deleted statsProvider and activityProvider: loadStats, loadHighlights and loadActivity are package functions in internal/edge/web, and a web test needing a failing, slow or counted stats/activity read hooks the real store instead of stubbing the data source

W0c (PR #602, merged as 58949ece; re-read there) deleted statsProvider and activityProvider. The default* implementations became package functions loadStats and loadHighlights (handlers_stats.go) and loadActivity (handlers_activity.go) with the same bodies: ri.WithRead, a nil svc yields the zero result and a nil error, errors pass unchanged to writeStoreError. handleHALStats, handleHALActivity and handleHALLensStats take no provider; handleTopicStats calls loadStats directly (it already bypassed injection). The lens stats fan-out reads each mount through loadStats then loadActivity, and loadHighlights only for the axis-correction pass (when the requested axis normalises to empty and the mounts disagree). No new interface, func-type seam or forward was added; webInterfaceAllowlist is down to 10 names.

CONSEQUENCE: a web test that needs a failing or slow stats/activity read installs a per-Service hook on that mount's store.Service: index.ReadStats / index.ReadActivity fault via SetReadFaultForTest, or an index.Overrides.Reads observer that sleeps or counts 'Stats' / 'Highlights'. It does NOT stub the handler's data source.

DOES NOT MEAN: that per-mount canned StatsResults are still available. Lens tests write real facts (syntheses with refs give impact; observation out-edges move the pooled axis). Review sabotage showed the observer and hooks are really driven (making them no-ops turns the tests RED).

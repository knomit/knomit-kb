# W0h deleted FactWriter: factResolves, priorRefs, writeFact and deleteFact are package functions in internal/edge/web, and the REST fact write tests run on a real store whose request branch is an experiment

W0h (PR #617, merged as 660cc910; re-read there) deleted FactWriter, defaultFactWriter and the storeProviders.factWriter member (storeProviders then had 1 member: origin; W0i, PR #619, deleted storeProviders entirely, kb/decisions/store/web-provider-removal/ff7a74aa.md). The four methods are package functions in internal/edge/web/handlers_fact_write.go with the same bodies:
- factResolves(ctx, ri, branch, path): FactExistsAt(ctx, branch, path, "") at the head of the request branch; the predicate writerGate(ri, branch) hands to refs.New.
- priorRefs(ctx, ri, branch, path): ReadFact at the head of branch; a missing path (model.ErrPathNotFound) and an unparseable stored version yield nil refs and a nil error; any other read error is returned (PUT answers 400 "Invalid path" for facts.IsInvalidPath, else writeStoreError with title "Failed to read fact").
- writeFact(ctx, ri, branch, path, content, message): WriteFact with operation "update"; returns the commit hash, which both callers (POST and PUT) discard.
- deleteFact(ctx, ri, branch, path, message): DeleteFact; model.ErrPathNotFound maps to errFactNotFound (DELETE answers 404 "Fact not found", detail naming the path as sent and the request branch).
- (At 660cc910) all four ignored ri.WithRead's error, so a repo with no store yielded zero values and a nil error. SUPERSEDED by PR #618 (merged 54d6c65b; re-read at 585974c5): they now return WithRead's error and the REST writes answer 503 (kb/decisions/web/rest-write-store-unavailable-503/5ce4cfbc.md); the `svc == nil` branches are deleted. The historical note is kb/gotchas/web/rest-write-store-unavailable/c725a955.md.
handleFactCreate(b, ontologyRoot), handleFactUpdate(b, ontologyRoot), handleFactDelete(b) and writerGate(ri, branch) take no writer. webInterfaceAllowlist was down to 1 name, originProvider, which W0i then deleted: the allowlist is now empty. The providers.go ref below is pinned at 660cc910, the last commit where the file existed (dated support; it is gone at 585974c5).

TESTS: newFactWriteFixture (handlers_fact_write_test.go) opens a real store and the experiment exp/rest-write forked from the agent branch, and installs facts.Index.SetWriteFaultForTest and SetDeleteFaultForTest PASSING (they return nil) to record the path of every write and delete a request makes; seeds bypass the record. The request branch is never the agent branch (REST writes are accepted only on the agent branch and the instance's own experiments), with same-path decoys on the agent branch so a handler that used ri.AgentBranch() lands on the wrong branch visibly. Failure paths use SetWriteFaultForTest (PUT and POST), SetDeleteFaultForTest (DELETE) and SetReadFactFaultForTest (the PUT prior-version read). TestHandleFactDelete_MissingPath_Returns404 runs on this fixture.

PR-REPORTED (not checkable in code): the W0h sabotage run found two EQUIVALENT mutants, the returned commit hash of writeFact / deleteFact (discarded by every caller) and the `svc == nil` branches of the four functions (unreachable: RepoInstance.WithRead never calls its closure without a store); review mutants that changed the 404 title to "Not found" or dropped the branch from the 404 detail turned the delete test red.

DOES NOT MEAN: that the fixture's hooks fake an answer; they are fail-only hooks used here as pass-through recorders, and the writes really land.

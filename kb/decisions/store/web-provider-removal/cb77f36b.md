# W0e deleted motifsProvider: motifClusters, motifDefinitions, motifVocabularyHealth, motifAliasRows and motifClusterKey are package functions in internal/edge/web, and a web motif test builds its vocabulary on a real store instead of stubbing clusters

W0e (PR #611, merged as b261c400; re-read there) deleted motifsProvider and defaultMotifsProvider. Their method bodies became the package functions motifClusters, motifDefinitions, motifVocabularyHealth, motifAliasRows and motifClusterKey in internal/edge/web/handlers_motifs.go, with the same bodies: ri.WithRead; a nil svc returns the zero value and a nil error; a store error passes through unchanged to the caller, which hands it to writeStoreError. No new interface, func-type seam or forward was added.

The handlers no longer take a provider: handleHALMotifs(b), handleHALMotifCluster(b), handleHALLensMotifs(b), handleHALLensMotifCluster(b), handleHALLensFacts(emb) and handleHALLensSearch(emb). gatherLensMotifs and expandLensMotifs take the request, the lens binding and their other arguments but no provider; expandLensMotifs lost its `provider == nil` early return (it keeps the `len(terms) == 0` one), which no caller could reach. webInterfaceAllowlist went from 8 to 7 names (FactReader, FactWriter, TopicLister, commitsProvider, factSubProvider, originProvider, RefResolver).

CONSEQUENCE: a web test that needs a motif vocabulary builds it on the real store, in this order: (1) write facts carrying motifs; (2) optionally record a judge merge and then rebuild aliases (RecordJudgeMerge, then RebuildAliases); (3) call PutDefinition only AFTER the last rebuild, because a rebuild retires definitions whose cluster it no longer finds. A test that needs a failing motif read installs vocab.MotifIndex.SetReadFaultForTest on the mount it targets (faultable reads: ClustersUnder, Definitions, VocabularyHealthUnder, AliasRows). The helpers live in handlers_motifs_test.go: withMotifIndex, judgeMerge, rebuildAliases, defineMotif, failMotifRead, requireFailedWith.

DOES NOT MEAN: (1) that ClusterKey can be failed: it has no fault hook (its ReadName does not exist), so the error branch around motifClusterKey in handleHALMotifCluster is untested. (2) that canned clusters, definitions or health are still available: a vocabulary is derived from the facts written. (3) that the lens handlers read a different source: the lens fan-out calls the same five package functions once per mount.

# W0g3 deleted FactReader: readFact is a package function in internal/edge/web, readerRefResolver calls factExistsAt directly, and the fact-read tests run on real stores, failing reads through facts.Index.SetReadFactFaultForTest

W0g3 (PR #615, merged as abcd5536; re-read there) deleted FactReader, defaultFactReader and the storeProviders.factReader member (storeProviders now has 2 members: factWriter, origin).

- defaultFactReader.Read is now the package function readFact(ctx, ri, a, path, fallback) in internal/edge/web/handlers_fact_read.go, with the same body: ri.WithRead; a nil svc yields errFactNotFound; a HEAD anchor reads the branch tip and stamps the branch head commit into the view's as_of; a commit anchor reads at that commit and stamps the pinned sha; with fallback set, a commit-anchored read that fails with ErrPathNotFound walks back with BeforeCommit from the pinned commit and stamps the ancestor commit it found; other store errors are returned unchanged for the handler to answer 500.
- readerRefResolver keeps its baked-in anchor (ctx, ri, branch, commit). Its Exists calls factExistsAt (W0g2, kb/decisions/store/web-provider-removal/868a61dd.md) and keeps the old logging: ERROR on failure, DEBUG when the error is context.Canceled or context.DeadlineExceeded, and the ref degrades to broken (Exists returns false).
- handleHALFact, handleCommitAnchoredFact and handleHALLensFact take only the URL builder (no reader parameter).
- webInterfaceAllowlist goes from 4 to 3 names: FactWriter, originProvider, RefResolver.

TESTS:
- newFactReadFixture (handlers_fact_read_test.go) gives each choice readFact and the handlers make two candidates that answer differently: the branch of a HEAD read (the requested branch, never the agent branch), the head stamped into a HEAD view, anchor vs HEAD, fallback vs not, a walk-back from the pinned commit vs from HEAD (kb/r.md v3 written at e9b), and the commit the ref resolver checks (the fallback's commit vs the URL's sha vs HEAD).
- hookReadFact records each ReadFact a store serves as "head <path>", "at <sha> <path>" or "before <sha> <path>" (through facts.Index.SetReadFactFaultForTest, which sees the read opts) and can fail exactly one read. Tests pin the full read log; that is how "the fallback was not taken" and "the read was mount-relative" are observed.
- The commit-anchored sub-resource tripwire (anchoredServer in handlers_commit_anchored_incoming_test.go) is a ReadFact fault that fails every read; the test fails at cleanup if it was hit even once.
- TestReaderRefResolver_Exists_ExpiredDeadlineLogsDebug (handlers_fact_read_ctx_test.go) pins DeadlineExceeded -> DEBUG with an already-expired context and no hook.

CONSEQUENCE: a new fact-read or fact-view test builds on newFactReadFixture (or a real lens mount) and observes or fails ReadFact through the hook; it does not reintroduce a reader seam.

DOES NOT MEAN: (1) that the store's branch is observable for anchored reads: the review sabotage runs A13 (anchored ref resolver on the agent branch) and A14 (anchored readFact on the agent branch) stayed GREEN as equivalent mutants (PR-reported from those runs; mechanism in kb/gotchas/store/anchored-read-ignores-branch/2b146823.md, to which a commit-anchored FactExistsAt belongs through ResolveActiveCommitForPath). (2) that FactExistsAt has a fault hook: it does not; W0g4 (PR #616, merged as ed6aefc2; kb/decisions/store/web-provider-removal/98dc6014.md) reaches Exists' ERROR branch through an unknown branch at HEAD instead (TestReaderRefResolver_Exists_StoreErrorLogsError), so the non-cancellation ERROR branch is tested. (3) that as_of.date on the commit-anchored fallback view is pinned: it needs spaced commit times and is a known unbuilt follow-up. (4) that the remaining interfaces are the recommended pattern: W0g4 (RefResolver, PR #616) has since landed, leaving FactWriter and originProvider, which W0h and W0i are planned to delete.

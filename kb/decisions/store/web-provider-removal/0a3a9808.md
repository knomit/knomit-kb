# W0d2 deleted factsCollectionProvider: recentFacts is a package function in internal/edge/web, and a web test needing a failing, slow or counted facts read hooks the real store instead of stubbing the data source

W0d2 (PR #610, merged as c3571f43; re-read there) deleted factsCollectionProvider. recentFacts is now a package function in internal/edge/web (handlers_facts_collection.go) with the body of the old default implementation: ri.WithRead; a nil svc yields no rows, a zero total and a nil error; otherwise it returns svc.FactQuery().RecentFacts unchanged, and the handler passes errors unchanged to writeStoreError. Callers: the repo facts collection handler, the two motif cluster-carrier previews (handlers_motifs.go and handlers_lenses_motifs.go) and every mount of the lens facts fan-out (handlers_lenses_read.go). webInterfaceAllowlist is down to 8 names (FactReader, FactWriter, TopicLister, commitsProvider, factSubProvider, motifsProvider, originProvider, RefResolver). No new interface, func-type seam or forward was added.

CONSEQUENCE: a web test that needs a failing, slow or counted facts read hooks the real store: index.ReadRecentFacts via failMountRead (SetReadFaultForTest), or countMountReads / slowMountRead with the method name "RecentFacts" (index.Overrides.Reads). A text read (q=) reaches Search through the store's recentFactsSearch, so it also fires "Search" probes and a Search fault fails it.

DOES NOT MEAN: that per-mount canned RecentFactEntry lists or totals are still available. Lens tests write real facts. A recency order across mounts needs one commit per group and a wait for the next second (awaitNextSecond: committed_at has one-second resolution); facts that must tie share one commit (writeFactsInOneCommit) and are listed by path.

# W0g4 deleted RefResolver: BuildRefViews and BuildFactView take the concrete readerRefResolver value, and the ref-view tests resolve refs on a real store

W0g4 (PR #616, merged as ed6aefc2; re-read there) deleted the RefResolver interface (ref_view.go). BuildRefViews(b, repo, a, raw, resolver, localRepoID) and BuildFactView(b, repo, a, headCommit, f, resolver, localRepoID) now take `readerRefResolver` by value: the struct in handlers_fact_read.go that bakes in (ctx, ri, branch, commit) and whose Exists calls factExistsAt. It was the only production implementation. The five response builders construct it per request with the request branch: handleHALFact (commit ""), handleCommitAnchoredFact (the view anchor's commit), handleFactCreate and handleFactUpdate (commit "") and handleHALLensFact (commit ""). No interface or function-typed seam replaced it. (PR-reported rationale: a struct keeps the anchor bundled with the request context and needs no change at those call sites, versus passing ctx, ri, branch and commit loose.)

webInterfaceAllowlist goes from 3 to 2 names: FactWriter, originProvider.

TESTS:
- stubRefResolver and recordingResolver are gone. ref_view_test.go and fact_view_test.go build a readerRefResolver over newRefResolverFixture (a real store): agent/elsewhere (E) forks from agent/test (A) after g2; kb/aonly.md is on A only, kb/late.md on E only after the anchor x0, and kb/gone.md is retracted on E (still resolves: FactExistsAt steps over retractions). TestReaderRefResolver_Exists_AnchorAndBranch pins Exists at E HEAD, E at x0, A HEAD, A at g2 and A at a1.
- TestBuildRefViews_EveryKindInOrder: 12 refs, two of every kind, interleaved, compared as whole RefView values (Raw, Kind, Path, Links).
- TestBuildRefViews_SelfQualifiedResolvesByRelativePath proves the resolver is asked for the relative path: the raw kb://<id>/... string names no fact in the store.
- TestReaderRefResolver_Exists_StoreErrorLogsError reaches Exists' ERROR branch WITHOUT a fault hook: a HEAD lookup on a branch the store does not know fails in FactQuery.FactExistsAt's BranchID. It pins ERROR (not DEBUG) and the branch, path and commit log fields.
- TestFactWrite_ResponseRefsResolveOnTheRequestBranch (handlers_fact_refs_test.go, server from newWriteRefsServer) posts and puts through the REAL writer on an own experiment branch (exp/write-refs) whose ref targets exist there only. RepoInstance.WritableBranch accepts only the agent branch and an experiment forked from it, so an experiment is the only way to give a write a request branch that differs from the agent branch. The write gate stores refs in the canonical kb://<id>/... form, so the test compares RefView.Path, not Raw.
- Sabotage results are PR-reported, not checkable in code; see the 2b146823 fourth instance for the equivalent mutant.

CONSEQUENCE: a new ref-view test builds a readerRefResolver over a real store (newRefResolverFixture, newFactReadFixture or a lens mount); it does not reintroduce a resolver seam. A test that needs Exists to fail and is not about cancellation can use an unknown branch at HEAD; there is still no FactExistsAt fault hook, and none is needed for that path.

DOES NOT MEAN: (1) that the branch of an ANCHORED lookup is observable: FactExistsAt with commit != "" delegates to ResolveActiveCommitForPath without a BranchID lookup, and that walk discards the branch (`_ = branch` under the SCHEMA INVARIANT in vcs/revisions_before.go), so the resolver of handleCommitAnchoredFact on ri.AgentBranch() is an equivalent mutant (kb/gotchas/store/anchored-read-ignores-branch/2b146823.md). (2) that a ref can be present at an anchor and absent at the same branch's HEAD: FactExistsAt steps over retractions, so on one branch existence never turns false later; that direction exists only across branches. (3) that the off-branch anchor case is defined: the tests use on-branch anchors only. (4) that the remaining two interfaces (FactWriter, originProvider) are the recommended pattern; W0h and W0i are planned to delete them.

UPDATE (12f, PR #630, merge 33eb0307; re-read there): ref_view.go, fact_view.go, handlers_fact_read.go and the ref-view tests now live in internal/edge/web/api/kb (package kb), and the identifiers are unexported there: buildRefViews, buildFactView, refView and factView. They take the concrete readerRefResolver value as described above.

# The origin-synchronisation child package is internal/store/remotesync, not internal/store/sync (renamed before the hier-11 stack merged)

CONTEXT (2026-10-20): the hier-11 PR (#560) extracted the origin-synchronisation cluster as internal/store/sync. Because the name collides with the standard library's sync, every importer aliased it (storesync), and the write-path guard TestVerifyIsNeverInTheWritePath needed the regex `\b(storesync|sync)\.\w+\(`, which also matches stdlib calls such as sync.OnceFunc( and would flag them in the two guarded files.

OPTIONS: (1) `sync`, kept and aliased storesync; (2) `remotesync`; (3) `originsync`; (4) keep `sync` now and rename later.

RATIONALE: the alias is a permanent tax on every importer and on every text scan keyed to a package qualifier; the alias spelling also hid the collision from the guard's author (the regex had to list both spellings). Renaming later (4) costs a second stack of PRs touching every importer and every fact that names the path, whereas before the merge it is one commit. Decision #191 had already rejected `runtime` for a child package for the same stdlib-collision reason. `remotesync` names what the package is (sync with the origin remote) and `originsync` was equally unambiguous but less aligned with the existing Remote/RemoteIndex vocabulary.

CHOICE (user, 2026-10-20): `remotesync`, done before merging #560/#561/#562 as a rename commit on #560 (git mv of the directory, package clause remotesync, seam file sync_seam.go -> remotesync_seam.go, no import alias), merged forward into #561 and #562. The guard rule is now `\bremotesync\.\w+\(`; the JudgeOwnRange entry in the name list is kept.

NON-SCOPE: this does not rename the types (Index, Repo) or the embedded repoHandler field `syncRepo`, and it is not a rule that every child package avoid stdlib names in general beyond the stdlib collisions already rejected (runtime, sync); it does not change proposal 4.3's logical name `sync` for the cluster.

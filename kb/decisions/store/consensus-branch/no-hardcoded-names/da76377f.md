# No consensus-branch name is hardcoded anywhere (product, CLI, CI template, web UI, dev tools): one named default only at creation, everything else from a request, the remote's HEAD or the recorded branch, else refuse. Chosen over git's init.defaultBranch and over leaving the literals in place

THE USER'S RULINGS (verbatim): "Hardcoded values are never good". On the follow-up list from #358 (the remaining hardcoded "main" defaults, and detaching an origin starting the local loop immediately), the user said: "ok".

SCOPE: the user's "ok" approved the #358 worker's list of sites. The reviewer's grep found more: the `verify ci --upstream origin/main` default, the shipped CI template tools/ci/verify-signatures.yml, the web UI fallbacks (StepBranch, StepReview, RemoteStatus, api.getAgentBranch), and two dev tools (tools/okf's main/master preference, tools/calibrate's --branch default). WIDENING the scope to cover them was the MASTER's call under the user's "Hardcoded values are never good". It was not a separate user ruling.

OPTIONS CONSIDERED for the one name a brand-new repo needs:
- (A) Leave the literals in place, now that #358 records the branch. Rejected: each literal is a guess that is wrong for any trunk/master/develop repo the moment its path is reached (a fleet reading main, an origin row stored as main, a CI gate checking origin/main), which is exactly the class of bug #358 fixed.
- (B) git's init.defaultBranch from the running account's gitconfig. Rejected: the name matters only at birth (it is recorded and read back). Two hosts created by the same request would disagree. A daemon or desktop app often has no gitconfig. Tests would depend on the machine.
- (C) CHOSEN: one constant, store.DefaultConsensusBranch, defined once and used only where a consensus branch is CREATED with nothing to detect it from: a local create, the empty-remote seed path, and the probe's mirror of that path. Every other path takes the name from a request, from the remote, or from the recorded branch, or refuses with ErrNoConsensusBranch.

FOR A REMOTE, the rule that chose a branch BY NAME ("prefer main, else HEAD, else main") was replaced by the remote's own HEAD, unless HEAD is an agent/exp/okf branch, then the single other branch, else refuse (kb/decisions/store/consensus-branch/remote-rule-head-not-name). The #82 hazard (a forge whose default branch is an agent branch) is handled by the HEAD branch's ROLE, not by another branch's NAME.

NON-SCOPE: prose and UI copy that say "main" meaning the consensus ROLE stay (the principle that main names the role). The scan test covers Go string literals only, not computed strings (kb/invariants/store/consensus-branch/one-named-default, reviewer N1). Existing repos are not re-resolved; a mixed-version fleet can disagree on a multi-branch remote (reviewer N2).

Shipped in #362, merged at 4e262b61.

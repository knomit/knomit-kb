# Upstream main branch name is configurable via Remote.Branch — not hardcoded 'main'

SetRemote used to hardcode upstreamMain='main' even though Remote.Branch was in the DB — a repo with consensus branch 'master' silently broke at sync time. The fix threads upstreamMain as a parameter through every reconcile primitive (SetRemote, InitFromRemote, configureRemote, fetchOrigin, reconcileMain, reconcileAgent + its merge/rebase variants). Source of truth: Remote.Branch in DB, read once per Sync tick via GetRemote('origin'). Detection in InitFromRemote: (1) caller-provided upstreamMain; (2) inspect remote symbolic HEAD (strip refs/heads/); (3) fall back to 'main' with warning. Defaults: InitRepo → 'main'; HAL PUT /origin uses req.Branch → existing → 'main'; Sync per-tick reads Remote.Branch. Internal-only API change, no migration needed — existing 'remotes' rows with branch='main' continue to work.

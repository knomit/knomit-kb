# Suspend clone index sync during disjoint-apply Replay via opt-in ReplayConfig.SkipIndexSync

Context: connecting a repo to a new origin with disjoint history runs store.Replay (handleApply, internal/web/handlers_origin_session.go:529), which does ~N WriteFact calls into the transient clone store (TempDir/clone.db). Each WriteFact fires notifyCommit -> searchIndex.Sync; the first hits a fresh DB with no watermark and does a FULL rebuild (indexing all ~791 cloned facts) plus a spurious 'schema version mismatch — run knomit rebuild' warning, then every subsequent write does an incremental Sync. Immediately afterward handleCommit (:793) runs IndexManager().Rebuild on the swapped-in store — a full reindex AGAIN. The Replay-time indexing is therefore 100% wasted: verified Replay only git-reads the clone (target.rh.ListAll / gits.Reference), never queries its search index, and SwapStore reopens via store.Open (no auto-Verify/auto-index) so nothing reads the clone index between Replay and Rebuild.

Options considered: (A) opt-in ReplayConfig.SkipIndexSync that toggles a per-searchIndex suspend flag around the write loop [CHOSEN]; (B) null out rh.im on the clone (rejected — coarser, also kills AppendCommitLog reasoning and is less explicit); (C) design-doc-only, no code (rejected — user wanted both fixes implemented).

Rationale: the suspend must NOT affect regular WriteFact on real repos. SkipIndexSync defaults false (existing single Replay caller unaffected), is set true ONLY in the disjoint-apply handler, is scoped to the transient clone *Service instance* (its si.syncSuspended atomic.Bool), and is auto-restored via defer. The real repo is a separate Service with its own repoHandler.im, never touched. AppendCommitLog still runs while suspended (notifyCommit order: AppendCommitLog -> im.Sync -> onCommit), so commit history is preserved for the final Rebuild to reconstruct branch_facts/graph/vectors from git.

Second fix (independent): searchIndex.Sync's 'schema version mismatch — run knomit rebuild' WARN conflated a MISSING graph_schema_version row (fresh/empty DB) with a genuine version mismatch. Split into a 3-state schemaVersionState (current/missing/stale); warn only on stale; NeedsRebuild keeps its bool contract (missing still => rebuild needed) so repoBuilder heal is unaffected.

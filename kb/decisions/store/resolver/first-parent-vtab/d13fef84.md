# Resolver uses first_parent_chain SQLite vtab to eliminate per-step SQL roundtrips

resolveActiveCommitForPath in internal/store/derived_from.go was rewritten from a Go-side per-step walk (one branch_commits + commit_log roundtrip per ancestor) to a single SQL statement over a streaming first_parent_chain virtual table. The vtab is registered per-connection in the ConnectHook (sqlite3_knomit driver) as an eponymous-only module: 'SELECT * FROM first_parent_chain(<hash>)' is the table-valued-function call form — NOT CREATE VIRTUAL TABLE. SQLite joins the streamed (commit_hash, depth) rows against commit_log with a LIMIT 1, so the git walk amortises naturally into the join and bails at the first match.

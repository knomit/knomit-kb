# resolveActiveCommitForPath uses recursive CTE over commit_parents; vtable retired due to pool-reentrance deadlock

The first_parent_chain SQLite virtual table was retired. resolveActiveCommitForPath now uses a recursive CTE over a precomputed commit_parents(commit_hash, parent_order, parent_hash) table.

WHY THE VTABLE WAS WRONG: its cursor's Next() callback re-entered the same *sql.DB pool from inside an active query — each step called go-git's Storer.EncodedObject → s.db.QueryRow to read the next commit's parent. With db.SetMaxOpenConns(4), four concurrent vtable scans each held one connection and waited forever for a fifth, wedging the whole pool. GET /branches and other WithRead handlers blocked indefinitely. Captured live from a goroutine dump showing every stuck goroutine blocked at database/sql.(*DB).conn on the same *sql.DB. The vtable approach was an attractive nuisance: it pushed walk-state into SQLite (good) but Go-side callbacks pulled DB work back through database/sql (bad).

WHY THE CTE IS RIGHT: pure SQL, no Go callbacks inside SQL execution, no pool re-entrance possible. EXPLAIN QUERY PLAN shows `CO-ROUTINE fpc` (lazy/pull-based) and `SEARCH cp USING INDEX sqlite_autoindex_commit_parents_1`, so streaming + short-circuit semantics are preserved — same memory profile as the vtable (O(walk-depth-before-match)), faster per step (PK lookup vs go-git roundtrip per step), and faster overall on the contended path.

POPULATION: parents are written in the same transaction as commit_log + branch_commits inside Storer.CommitLogSync. Every commit-add path already routes through CommitLogSync, so there is a single chokepoint. The iterator signature gained a `parents []string` return; the two callers (populateCommitLog and AppendCommitLog) already have go-git Commit objects in hand and extract ParentHashes for free.

BACKFILL: existing repos boot with commit_log populated but commit_parents empty. A one-off backfillCommitParents runs at OpenRepo, guarded by a meta-table sentinel (commit_parents_backfilled = '1') so it executes at most once per database. Empty repos still mark the sentinel.

RETIRED ARTIFACTS: vtab_first_parent.go + its test + the path-keyed *repoHandler registry + the bindVTabRepo/unbindVTabRepo/registerVTabs call sites + the sqlite_vtable build tag. Net diff was negative (~280 LOC removed, ~80 added).

Replaces [[first-parent-vtab]] and [[vtab-repo-registry]] (both retracted).

# commit_log SQL operations live on storegit.Storer, NOT on git.Store

All commit_log SQL operations are owned by storegit.Storer as named methods: CommitLogAvailable() bool, CommitLogSync(iter) error, CommitLogQuery(path, cursor, limit), CommitLogFileCounts(hashes), CommitLogActivity(path, cutoffs), CommitLogWalkChanged(prefix, seen, limit). The storer owns SQL; git package retains go-git walk logic only (populateCommitLog builds an iterator over commits using gogit.Log, calls changedFilesInCommit per commit, passes the iterator to s.storer.CommitLogSync). git.Store NO LONGER has a *sql.DB field — it accesses commit_log via the storer's named methods. CommitLogSync's iterator pattern: returns ('', nil, nil) to signal done; stops early when it sees an already-indexed hash (backfill dedup); inserts batches in one transaction per call; sets the internal commitLog available flag after first successful write. Used identically for startup backfill (many commits) and per-write append (single-commit iterator).

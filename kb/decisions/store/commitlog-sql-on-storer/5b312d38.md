# commit_log SQL operations live on storegit.Storer, NOT on git.Store

All commit-index SQL operations are owned by storegit.Storer as named methods. The storer owns SQL; the git package retains go-git walk logic only (populateCommitLog builds an iterator over commits using gogit.Log, calls changedFilesInCommit per commit, passes the iterator to s.storer.CommitLogSync). git.Store has NO *sql.DB field — it reaches commit_log only through the storer's named methods.

METHOD SET AT HEAD (internal/store/git/commitlog.go, verified 2026-07-22) — FIVE methods:
CommitLogAvailable() bool; CommitLogSync(branchName, iter) error; CommitLogQuery(branchID, path, cursor, limit); CommitLogFileCounts(hashes); CommitLogActivity(branchID, path, cutoff7, cutoff30, cutoff90).

CommitLogSync's iterator signature (post PR #67): `func() (hash string, parents []string, entries []CommitLogEntry, err error)`. The `parents` return was added when commit_parents was introduced — the iterator yields parents alongside per-path entries so all three tables (commit_log, branch_commits, commit_parents) are populated atomically inside the same transaction per commit. Sentinel for done is `('', nil, nil, nil)`. Dedup: stops processing a hash already in branch_commits but CONTINUES iterating (skip-and-continue, not short-circuit) so merge DAGs index correctly — see kb/invariants/store-git/commitlog-sync-walks-dag-not-shortcircuit/0705d245.md. Sets the internal commitLog atomic on first successful write. Used identically for startup backfill (many commits) and per-write append (single-commit iterator).

WHAT THIS DOES NOT MEAN (corrected 2026-07-22):

1. `CommitLogWalkChanged` DOES NOT EXIST. This fact previously listed it as a sixth Storer method. It was removed along with knomit_explore's browse-by-recency git walk (see kb/architecture/store/tool-sessions-unified-schema/be09558e.md, which independently records that the explore-only LastCommit/WalkChangedFiles walk is gone). Do not write code against it or assume a walk-changed-files primitive exists on the storer.

2. `CommitLogActivity` is NOT `(path, cutoffs)`. It takes `branchID` FIRST: (branchID, path, cutoff7, cutoff30, cutoff90). Activity is branch-scoped — calling it without a branch id is not merely a signature mismatch, it is a category error about what activity means here.

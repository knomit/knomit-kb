# commit_log SQL operations live on storegit.Storer, NOT on the vcs.Repo (formerly git.Store) that walks git

All commit-index SQL operations are owned by storegit.Storer as named methods. The storer owns the commit_log SQL; the go-git walk logic lives in vcs.Repo (internal/engine/store/internal/vcs/branch_commit_log.go: PopulateCommitLog collects the commits reachable from a branch tip, prepares each commit's parents and entries from git, and passes them as CommitLogItems to rh.gits.CommitLogApply). vcs.Repo, the successor of the old git.Store, reaches commit_log writes only through the storer's named methods.

METHOD SET AT HEAD (internal/engine/store/git/commitlog.go, verified 2026-07-22) — FIVE methods:
CommitLogAvailable() bool; CommitLogApply(ctx, branchName, items, opts) error (it replaced CommitLogSync); CommitLogQuery(branchID, path, cursor, limit); CommitLogFileCounts(hashes); CommitLogActivity(branchID, path, cutoff7, cutoff30, cutoff90).

HISTORICAL: CommitLogSync was replaced by CommitLogApply, which takes []CommitLogItem{Hash, Parents, Entries} prepared by the caller before its transaction opens plus CommitLogApplyOptions with a REQUIRED Derive hook, and still skips an item already in branch_commits and continues with the next. CommitLogSync's former iterator signature (post PR #67): `func() (hash string, parents []string, entries []CommitLogEntry, err error)`. The `parents` return was added when commit_parents was introduced — the iterator yields parents alongside per-path entries so all three tables (commit_log, branch_commits, commit_parents) are populated atomically inside the same transaction per commit. Sentinel for done is `('', nil, nil, nil)`. Dedup: stops processing a hash already in branch_commits but CONTINUES iterating (skip-and-continue, not short-circuit) so merge DAGs index correctly — see kb/invariants/store-git/commitlog-sync-walks-dag-not-shortcircuit/0705d245.md. Sets the internal commitLog atomic on first successful write. Used identically for startup backfill (many commits) and per-write append (single-commit iterator).

WHAT THIS DOES NOT MEAN (corrected 2026-07-22):

1. `CommitLogWalkChanged` DOES NOT EXIST. This fact previously listed it as a sixth Storer method. It was removed along with knomit_explore's browse-by-recency git walk (see kb/architecture/store/tool-sessions-unified-schema/be09558e.md, which independently records that the explore-only LastCommit/WalkChangedFiles walk is gone). Do not write code against it or assume a walk-changed-files primitive exists on the storer.

2. `CommitLogActivity` is NOT `(path, cutoffs)`. It takes `branchID` FIRST: (branchID, path, cutoff7, cutoff30, cutoff90). Activity is branch-scoped — calling it without a branch id is not merely a signature mismatch, it is a category error about what activity means here.

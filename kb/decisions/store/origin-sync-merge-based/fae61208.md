# Agent branch reconciles via real git merge, NOT by replaying every commit

Origin sync was reworked from replay-based to merge-based reconciliation. reconcileAgent(agentBranch, strategy, mainRewound) dispatches: mainRewound=false (steady state) → mergeIntoBranch('main', agentBranch, StrategyLocalWins), producing FF / no-op / single merge commit — O(1) work regardless of how many commits main absorbed; mainRewound=true (origin/main force-rewound) → watermark-based replayOntoUpstream fallback so G6 scrub semantics still work on disjoint histories. Hash rewriting ONLY happens on the rebase path. The watermark is still seeded by all bootstrap paths but only consulted on the rewind branch. Push is unchanged (force-push agent branch — only this machine writes to agent/<host>). The rework fixed the O(N) re-replay disaster when a remote squash/rebase merge absorbed an agent's commits back to main (G9 regression test pins the fix).

UPDATE (branch fix/fleet-switch-replay, verified at b4874ee2; re-pin at the merge commit): the rebase fallback's walk also stops at the first commit the new upstream's history holds, whatever the watermark says. (An earlier version also moved a diverged branch with only merges beyond upstream onto it; the PR #531 review showed that drops a committed experiment, and it was removed at b25765bd.) A copy with no origin (a hub) never advances its watermark, so without this the first rewind after it attached an origin replayed its whole history (#528 N1). See kb/invariants/store/remote-reconcile/replay-stop/5482c3ab.md.

VERIFIED AT THE MERGE (PR #531, squash commit 8ca72760 on dev, 2026-10-16): the rebase fallback's walk stops at the watermark or at the first commit the new upstream's history holds, whichever comes first (unpushedCommitsDropping in remote_reconcile_rebase.go); the shape-3 move of a merges-only branch onto upstream is not in the code. The fleet repository additionally never replays a commit that changes only artifacts/fleet/master (SetReplaySkipPaths).

UPDATE (PR #542, merge 637960bc on dev, read there): 'seeded by all bootstrap paths' is no longer the whole story. Sync also seeds a MISSING watermark: remoteIndex.sync reads refs/remotes/origin/<main> before the fetch and seedMissingWatermark writes the watermark there when the agent branch has none (a repo made before the watermark existed and not synced since); the next reconcile advances it as usual. An existing watermark is never overwritten, and with no tracking ref (a truly first sync) nothing is written. The watermark is still consulted only on the rewind path. See kb/invariants/store/remote-reconcile/watermark-seed/0f9cc562.md.

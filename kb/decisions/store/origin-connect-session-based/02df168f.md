# Origin connection is session-based, ephemeral, with 10-min idle expiry; session folders live in <home>/origin-sessions/run-<id>/ (a private os.TempDir dir only for a Server with no OriginSessionsDir)

Origin connection workflow uses a session model: ONE active session per repo, held in MEMORY (a plain map[repoName]*originSession under ONE mutex in the unexported sessionManager of internal/edge/web/api/origins; it was a sync.Map before PR #626, see kb/invariants/web/origin-sessions/ed7f4928.md), with 10-minute idle expiry (`sessionExpiry = 10 * time.Minute` in api/origins/session_manager.go; a cleanupLoop ticks every 60 s and evicts sessions idle longer than that, and runs only while a session exists, see kb/decisions/web/origin-sessions/sweeper-lifetime/d8cd6872.md). Session fields: ID (UUID), repo name, remote URL, auth config, temp dir path, state, created timestamp. Session folders live in `<home>/origin-sessions/run-<id>/session-*` (Server.OriginSessionsDir, set by internal/app; one run directory per process, guarded by an OS lock, see kb/invariants/web/origin-sessions/8bab8ef0.md). A Server with no OriginSessionsDir (tests) keeps them in a private dir under os.TempDir() (knomit-origin-sessions-*). They are NEVER inside a repo's data or git directory (prevents accidental commits/corruption); <home>/origin-sessions is a separate sibling of the repos. NO database storage — entirely ephemeral; lost on server restart. Creating a new session for a repo cleans up any existing one (deletes its temp dir). Session folders ARE cleaned up on shutdown since PR #626 (merge c3c293b0): the manager lives as long as the ctx given to origins.Mount, which internal/app ends first in App.Close; it then closes each session's cloned store and removes its folder and its run (kb/architecture/web/origin-sessions/57c881e2.md, kb/invariants/web/origin-sessions/ad44382e.md). Removal is asynchronous, so a process that exits immediately can leave its run; the next start reclaims runs whose process has died. Idle expiry, replace-by-repo, and delete also remove a session. (From PR #624 until #626 this fact said shutdown did NOT clean up; that is no longer true.)

Workflow steps are progressive: POST /session creates instantly (no git ops), GET /session/{id}/test clones and analyses (SSE-streamed), GET /session/{id}/preview shows merge result with chosen strategy, POST /session/{id}/apply mutates the clone, POST /session/{id}/commit promotes the clone to real repo. User can bail at any step.

Re-verified at the merge of PR #624 (01e405e4): the session type, manager and expiry live in internal/edge/web/api/origins/session_manager.go; the handlers in api/origins/handlers.go (before 12d: internal/edge/web/origin_session.go and handlers_origin_session.go). Routes are /repos/{repo}/origin-sessions (see kb/architecture/web/api-origins/53e6213b.md). Note for consumers: because state is in-process only, a session ID is NOT durable — any handler resuming a workflow must tolerate a missing session after a restart or a 10-minute idle gap, and the disjoint-apply path's Replay runs against the TRANSIENT clone store, not the live repo (see kb/decisions/store/origin/suspend-clone-index-sync-during-replay/fe72b62a.md).

# Origin connection is session-based, ephemeral, with 10-min idle expiry under os.TempDir()

Origin connection workflow uses a session model: ONE active session per repo, held in MEMORY (sync.Map[repoName]*OriginSession), with 10-minute idle expiry (background goroutine ticks every 60s). Session fields: ID (UUID), repo name, remote URL, auth config, temp dir path, state, created timestamp. Temp dirs live under os.TempDir()/knomit-origin-<uuid> — NEVER inside the knomit data directory (prevents accidental commits/corruption). NO database storage — entirely ephemeral; lost on server restart. Creating a new session for a repo cleans up any existing one (deletes its temp dir). All sessions cleaned up on server shutdown. Workflow steps are progressive: POST /session creates instantly (no git ops), GET /session/{id}/test clones and analyses (SSE-streamed), GET /session/{id}/preview shows merge result with chosen strategy, POST /session/{id}/apply mutates the clone, POST /session/{id}/commit promotes the clone to real repo. User can bail at any step.

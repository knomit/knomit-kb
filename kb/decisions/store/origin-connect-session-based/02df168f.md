# Origin connection is session-based, ephemeral, with 10-min idle expiry under os.TempDir()

Origin connection workflow uses a session model: ONE active session per repo, held in MEMORY (sync.Map[repoName]*originSession in the unexported sessionManager of internal/edge/web/api/origins), with 10-minute idle expiry (`sessionExpiry = 10 * time.Minute` in api/origins/session_manager.go; a cleanupLoop ticks every 60 s and evicts sessions idle longer than that, and runs only while a session exists, see kb/decisions/web/origin-sessions/sweeper-lifetime/d8cd6872.md). Session fields: ID (UUID), repo name, remote URL, auth config, temp dir path, state, created timestamp. Temp dirs live under os.TempDir()/knomit-origin-<uuid> (os.MkdirTemp pattern knomit-origin-) — NEVER inside the knomit data directory (prevents accidental commits/corruption). NO database storage — entirely ephemeral; lost on server restart. Creating a new session for a repo cleans up any existing one (deletes its temp dir). Session temp dirs are NOT cleaned up on server shutdown: the manager has no Shutdown (the exported one, which production never called, and Server.SessionManager were removed in PR #624), so a session still held at process exit leaves its knomit-origin-* dir under os.TempDir(). That is a KNOWN DEFECT being fixed in a follow-up; only idle expiry while the process runs, replace-by-repo, and delete remove a dir. An earlier version of this fact claimed shutdown cleanup; that was never true of production code.

Workflow steps are progressive: POST /session creates instantly (no git ops), GET /session/{id}/test clones and analyses (SSE-streamed), GET /session/{id}/preview shows merge result with chosen strategy, POST /session/{id}/apply mutates the clone, POST /session/{id}/commit promotes the clone to real repo. User can bail at any step.

Re-verified at the merge of PR #624 (01e405e4): the session type, manager and expiry live in internal/edge/web/api/origins/session_manager.go; the handlers in api/origins/handlers.go (before 12d: internal/edge/web/origin_session.go and handlers_origin_session.go). Routes are /repos/{repo}/origin-sessions (see kb/architecture/web/api-origins/53e6213b.md). Note for consumers: because state is in-process only, a session ID is NOT durable — any handler resuming a workflow must tolerate a missing session after a restart or a 10-minute idle gap, and the disjoint-apply path's Replay runs against the TRANSIENT clone store, not the live repo (see kb/decisions/store/origin/suspend-clone-index-sync-during-replay/fe72b62a.md).

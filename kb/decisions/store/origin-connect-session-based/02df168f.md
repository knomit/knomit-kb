# Origin connection is session-based, ephemeral, with 10-min idle expiry under os.TempDir()

Origin connection workflow uses a session model: ONE active session per repo, held in MEMORY (sync.Map[repoName]*OriginSession), with 10-minute idle expiry (`sessionExpiry = 10 * time.Minute` in internal/web/origin_session.go; a background cleanupLoop ticks and evicts sessions idle longer than that). Session fields: ID (UUID), repo name, remote URL, auth config, temp dir path, state, created timestamp. Temp dirs live under os.TempDir()/knomit-origin-<uuid> — NEVER inside the knomit data directory (prevents accidental commits/corruption). NO database storage — entirely ephemeral; lost on server restart. Creating a new session for a repo cleans up any existing one (deletes its temp dir). All sessions cleaned up on server shutdown.

Workflow steps are progressive: POST /session creates instantly (no git ops), GET /session/{id}/test clones and analyses (SSE-streamed), GET /session/{id}/preview shows merge result with chosen strategy, POST /session/{id}/apply mutates the clone, POST /session/{id}/commit promotes the clone to real repo. User can bail at any step.

Verified at HEAD 2026-07-22 (the session type and its expiry live in internal/web/origin_session.go; the handlers in internal/web/handlers_origin_session.go). Note for consumers: because state is in-process only, a session ID is NOT durable — any handler resuming a workflow must tolerate a missing session after a restart or a 10-minute idle gap, and the disjoint-apply path's Replay runs against the TRANSIENT clone store, not the live repo (see kb/decisions/store/origin/suspend-clone-index-sync-during-replay/fe72b62a.md).

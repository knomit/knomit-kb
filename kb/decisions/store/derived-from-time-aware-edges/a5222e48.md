# DERIVED_FROM edges are time-aware: one edge per ref-event with (source_commit, target_commit)

DERIVED_FROM edges in the graph carry two text properties: source_commit and target_commit. Multiple edges between the same (source Fact, target Fact) are EXPECTED — one per ref-event — because the GraphQLite edges table has NO (source_id, target_id, type) uniqueness constraint. Each edge encodes 'at commit source_commit, the version of source-path that was committed pointed at the version of target-path that was active at that commit (target_commit)'. The lifetime-overlap test is enforced at WRITE TIME by recording target_commit on the edge — read time becomes a single property match, no overlap CTE needed. The half-built FactVersion/PREV_VERSION node/edge subsystem was retired (one writer, zero readers); the Z-axis (a fact's history over time) is served by commit_log ordered by committed_at per path.

WHAT THIS DOES NOT MEAN — THE HELPER NAME MATTERS (corrected 2026-07-22): this fact used to say "graphInsertEdge uses INSERT INTO (not INSERT OR IGNORE)". That is WRONG at HEAD and inverting it silently breaks the one-edge-per-ref-event guarantee. There are TWO helpers and they differ exactly where it counts:
  • `graphInsertEdge` (internal/store/search_graph.go) — `INSERT OR IGNORE INTO edges`. DEDUPES. Correct for at-most-one-edge types.
  • `graphInsertEdgeReturningID` (internal/store/edge_props.go) — plain `INSERT INTO edges`, returns the new edge id so properties can be attached. This is the one DERIVED_FROM actually uses (graphAddDerivedFromAtCommitTx, internal/store/derived_from.go).
If you write DERIVED_FROM — or any other multi-edge, property-carrying type — through `graphInsertEdge`, the second and later ref-events for the same (source, target) pair are silently swallowed and their commit properties never written. Reach for `graphInsertEdgeReturningID`. (The original observation that OR IGNORE is a no-op against a table with no unique constraint is beside the point: what matters is which helper you call and that only one of them returns the id you need for props.)

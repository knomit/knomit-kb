# DERIVED_FROM edges are time-aware: one edge per ref-event with (source_commit, target_commit)

DERIVED_FROM edges in the graph gained two text properties: source_commit and target_commit. Multiple edges between the same (source Fact, target Fact) are EXPECTED — one per ref-event — because the GraphQLite edges table has NO (source_id, target_id, type) uniqueness constraint. Each edge encodes 'at commit source_commit, the version of source-path that was committed pointed at the version of target-path that was active at that commit (target_commit)'. The lifetime-overlap test is enforced at WRITE TIME by recording target_commit on the edge — read time becomes a single property match, no overlap CTE needed. graphInsertEdge uses INSERT INTO (not INSERT OR IGNORE — the OR IGNORE was a no-op since there was no constraint to violate, and misleading). The half-built FactVersion/PREV_VERSION node/edge subsystem was retired (one writer, zero readers, TODO(verify)); the Z-axis (a fact's history over time) is served by commit_log ordered by committed_at per path.

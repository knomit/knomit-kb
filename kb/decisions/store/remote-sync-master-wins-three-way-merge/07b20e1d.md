# Remote sync uses three-way merge with master-wins via DiffTree(merge_base, origin)

Remote sync (initial implementation) used a three-way merge with 'master wins' semantics. Algorithm: (1) configure go-git remote (refspec: +refs/heads/<branch>:refs/remotes/origin/<branch>); (2) Fetch; (3) resolve refs; (4) fast-path: same hash → no-op, origin ancestor of agent → no-op (already merged), agent ancestor of origin → fast-forward (no merge commit); (5) merge base = agentCommit.MergeBase(originCommit) (go-git v5.17.0 built-in); (6) DiffTree(merge_base_tree, origin_tree) → master's changes since common ancestor; (7) apply diff to agent tree: added/modified → origin's blob overwrites agent (master wins), deleted → remove from agent tree (log WARN if agent had modified it); (8) create merge commit with two parents [agent_HEAD, origin_HEAD]. Agent-only files (not in master, not in merge base) are PRESERVED. Lock scope: s.mu held from fetch through ref update; RELEASED before notification and status update to avoid deadlock risk — the onCommit callback triggers idx.Sync which calls back into git Store for reads. Trigger: startup (immediate) + time.Ticker at configured interval. NOT tied to MCP tool calls — all Sync() calls in MCP handlers were REMOVED.

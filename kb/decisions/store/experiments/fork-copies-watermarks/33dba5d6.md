# The experiment fork is a SIBLING of CreateBranch, not a flag on it — so "CreateBranch does not copy pipeline_watermarks" stays literally true while an experiment still inherits them

A fresh AGENT branch should be full-corpus dirty on its first pipeline run; an experiment should not, because its whole point is to review its own delta. Those are opposite requirements on the same primitive.

Rather than add a condition to CreateBranch, OpenExperiment CALLS it and then copies the parent's `pipeline_watermarks` rows itself — every tool's rows, not just review's, since hypothesize keys its own under the same branch. The consequence is that architecture/synthesize/pipeline-watermark stays true as written instead of acquiring an exception, and a reader of either fact gets a complete answer.

OpenExperiment also reads `fork_commit` from the NEW BRANCH after creating it, never from the parent beforehand. CreateBranch resolves the parent itself and neither step holds the parent's lock, so a commit landing in between would record a fork point that is an ANCESTOR of where the branch actually starts — and fork_commit is the only anchor a "changed since the fork" view has.

WHAT THIS DOES NOT MEAN: CreateBranch was not changed and still inherits only the git ref, branch_commits, branch_facts and the meta sync watermark. Anything else that forks a branch and wants the pipeline watermark must copy it too.

# Index.DB() and Service.DB() are DELETED — no escape hatch to raw *sql.DB

Both Index.DB() and Service.DB() getters are DELETED. There is NO public escape hatch from *Service to the raw *sql.DB. Replacements: (1) proper domain methods for what callers needed via DB (LastCommitForPath returns the commit hash for a path, CommitTimestamp returns committed_at for a hash); (2) NewFactsIter takes the index, not a *sql.DB; (3) web test helpers that did raw INSERT INTO facts were rewritten to use the public Upsert(FactRecord{...}) API; (4) store-internal tests are SAME PACKAGE (package store) so they touch idx.db / svc.db directly — no public getter needed.

Anti-pattern (FORBIDDEN): adding a new DB() method or any other raw-SQL escape hatch on Service or a sub-index. If a caller needs raw SQL, add a proper domain method instead.

WHAT THIS DOES NOT MEAN (clarified 2026-07-22): "there is no *sql.DB getter anywhere in the codebase" is FALSE. `storegit.Storer` still exposes `func (s *Storer) DB() *sql.DB` (internal/store/git/storer.go), and store-package code reaches the handle as `rh.db` / `rh.gits.DB()`. That is the deliberate package-privilege exception this policy always carried — it is NOT a loophole to route application code through. The rule is about the *Service boundary*: nothing outside internal/store may obtain the handle. Finding Storer.DB() is not evidence the policy lapsed, and it is not license to plumb it outward.

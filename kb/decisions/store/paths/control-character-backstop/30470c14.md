# Paths go-git cannot read back are refused by ONE check in store.validatePath, which asks go-git itself, not by per-field checks at learn/REST/synthesize

**Problem (#384).** A caller-supplied segment that go-git refuses to READ back was accepted on WRITE. Examples: a line feed in knomit_learn's `category`, `git~1`, `a\.`, or a zero-width-joined `.git`. go-git's ValidTreePath first runs in notifyCommit's im.Sync, after SetReference. So the write committed, reported failure, and every later write on the branch did the same while the index froze.

**Options considered (round 1).**
- (A+B) A store backstop in store.validatePath, plus boundary checks in learn, REST create/PUT and synthesize that name the offending field.
- (A only) The store backstop alone, its error quoting the path with %q.
- (B only) Boundary checks alone.

The user chose A only because they wanted a single check. B's only advantage was naming the field; its cost was NOT the reason it lost. B-only was never viable: it leaves every future write door unguarded.

**Round 2 (#386).** Round 1 refused control characters only; review reproduced the same poisoning with `git~1`, `a\.` and a ZWJ `.git`. The user approved widening the SAME single check to go-git's complete read-back rule: never refuse what git reads back, never allow what it refuses.
- The store ASKS go-git instead of restating the rule. gitReadablePath runs the whole path, and each '/'-separated name, through `(&object.Tree{}).FindEntry` on an empty in-memory tree.
- go-git's sentinel lives in an internal package, so it is recovered by unwrapping a NUL-byte probe.
- The round-1 fileExists addition was dropped.
- writeStoreError maps ErrInvalidPath to 400. REST PUT maps go-git's refusal from its prior-version read to 400 via store.IsInvalidPath.
- The empty-path and '..' refusals also wrap ErrInvalidPath.

**Round 3 (#392).**
- The sentinel recovery fails closed: it panics at package init if the probe unwraps to nil.
- The per-name gate is what refuses a backslash-only name (`a/\/b`), on Linux too.
- Empty segments (`kb//x.md`, `/kb/x.md`, `kb/x/`) are skipped by validatePath. deriveBeforeAdvance's tree decode still refuses them before the ref moves, so they cannot poison a branch, but the client gets a 500.

**The choice now.** One check, store.validatePath, run by writeFileExact, deleteFile and batchWrite before the branch lock. The error is `invalid path "<path>": <go-git's reason>`, wrapping store.ErrInvalidPath.

**Non-scope.**
- It does not authorize per-field checks at the boundaries later 'for a better message' without revisiting this decision.
- It does not cover empty segments; a 400 for them would be a separate decision.
- It does not repair a branch already holding such a commit.
- It does not license store.validatePath to absorb knowledge-layout rules such as the private-path rule (kb/decisions/fact/kb-repo-layout/private-dot-paths/b3425b43.md).

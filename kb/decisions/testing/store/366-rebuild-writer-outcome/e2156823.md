# TestPathHistory_RebuildDoesNotBlockWriters asserts the OUTCOME (a write succeeds at each rebuild pause point, via deriveObjectHook) instead of 'worst concurrent write < 5 s'; test-only, no production change

Context (#366): the test flaked on Windows CI with a 6.8 s write against its 5 s limit while the rebuild took 3.06 s. The RCA found no lock contention; the 6.8 s had two other sources.
- Fixture artifact: clearDerived wipes commit_fp/path_changes and branch `writer` shares main's 2000-commit history, so the writer's FIRST WriteFact re-derives the whole closure itself (deriveBeforeAdvance), in parallel with the rebuild. It takes about as long as the rebuild.
- The first commit after the rebuild pays the WAL auto-checkpoint of the rebuild's backlog (gotcha under kb/gotchas/store/sqlite/wal-checkpoint-after-bulk-write/).
The 5 s duration cannot tell either of these from the guarded regression (derivation moving inside the swap transaction). The test's stated intent ('a writer never sees database is locked') is already asserted by require.NoError(werr).

Chosen (per kb/meta/methodology/measure-outcome-not-the-race/eae2bb22.md):
- Pause the rebuild mid-derive and mid-stage through the existing test-only deriveObjectHook, outside any transaction, and at each pause require a WriteFact on `writer` to succeed. A derivation inside the swap would make it fail deterministically with 'database is locked' (busy_timeout 5 s).
- Keep swap < elapsed/4. Drop worst < 5 s.
- Stop the writer re-deriving the history (orphan branch, or a warm-up write).
- Prove it: forcing derivation into the swap turns it red; it passes under disk load.

Rejected:
- widening the limit (the tail reached 6.8 s idle and 26 s loaded);
- timing only writes inside the rebuild window (a 14.6 s mid-rebuild write was seen under load);
- a production checkpoint as the fix: split out to #403, which the test fix does not depend on.

Non-scope: no production code changes for #366. If deriveObjectHook cannot pause where needed, that is escalated, not worked around in production code.

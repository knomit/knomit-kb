# knomit-bench is a separate top-level Python project (no shared code with knomit), not an in-repo test package

**Options considered**

1. In-repo Go package: `test/mcpbench` + a `knomit bench` subcommand sharing the engine (the initial draft of proposal 21).
2. Separate top-level project in Go, extracting/vendoring `test/testenv` fixture helpers.
3. Separate top-level project in **Python**, sharing no code with knomit at all.

**Rationale**

The benchmark's core principle is measurement at the MCP boundary — the real interface every agent uses. As an in-repo package that holds only by review discipline; as a separate project with no knomit import it holds by construction. Taking the target binary as an argument enables cross-version scoring (v(N) vs v(N−1) scorecard diffs) and a possible public benchmark. Python won over Go for the medium because half the bench is data analysis (append-only run dataset, pandas/DuckDB, paired deltas, bootstrap CIs, trend lines) and because nothing actually needs sharing — the bench speaks the MCP protocol and shells out to `git` and the `claude` CLI, which dissolves the testenv-extraction cost the Go variant carried. A working seed already exists: `.claude/plans/run_ab.py` implements the two-arm A/B (with/without knomit) with authoritative usage accounting from the CLI JSON result, engagement counting from transcript tool_use blocks, blind rubric + both-orderings pairwise judging, and a quality-gated cost verdict. User chose explicitly: "Could be in Python as well - I believe that may actually be a better medium."

**The choice**

knomit-bench is a standalone top-level Python project: two modes (mechanical: direct MCP stdio client, deterministic, gates knomit CI; model: agent-in-the-loop headless `claude` runs under a corpus-condition matrix, nightly), five ground-truth mechanisms (golden task sets, git-history replay, mutation testing, planted-structure corpora, and curated **fact packs with expected task effects** tested causally via injection/ablation), reporting a three-axis scorecard (Actionable / Trustable / Discovery) that defines per-phase exit criteria for the refinery roadmap. Full design: `.claude/future/21-benchmark.md`; roadmap integration: `.claude/future/ROADMAP.md` ("The measurement workstream").

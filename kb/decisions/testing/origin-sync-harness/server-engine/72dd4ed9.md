# Origin-sync fault harness runs REAL git behind pure-Go fault front-ends (go-git ships no HTTP/SSH server glue)

For the adversarial origin-sync test harness (test/testenv/gitserver), the smart-HTTP git server runs the REAL `git http-backend` in-process via net/http/cgi against local bare repos, behind a pure-Go http.Handler front-end that owns auth checking and a mutable FaultPlan (status/hang/throttle/truncate/basic-auth/expire-after-N). SSH (first-class, Phase 0+) will likewise pipe the SSH channel to real `git-upload-pack`/`git-receive-pack` subprocesses behind an x/crypto/ssh front-end.

WHY (rationale): go-git v5.19.1 provides a server-side PROTOCOL package (plumbing/transport/server: NewServer, MapLoader, upload/receive-pack sessions) but ships NO HTTP smart-protocol handler and NO SSH server — its transport/http and transport/ssh are client-only. So "in-process go-git server" would mean hand-writing the smart-HTTP pkt-line glue (info/refs advertisement framing, request/response body parsing) ourselves — fiddly, bug-prone, and ironically LOWER fidelity than real git (the hand-rolled glue is exactly where it could diverge from what GitHub does, which is what bit users in production). The fault middleware — where all the cruelty lives — is pure-Go and identical regardless of the engine behind it.

OPTIONS CONSIDERED: (A) real git (git http-backend CGI + upload/receive-pack subprocess) behind pure-Go fault front-ends — CHOSEN: highest fidelity, least glue, reuses the git binary tests already depend on; runs in-process (net/http/cgi), not an external service. (B) hand-write go-git smart-HTTP pkt-line glue as primary, CGI as conformance backstop — rejected: significant fiddly plumbing, lower real-world fidelity. (C) third-party in-process git-http lib (e.g. gitkit) — rejected: adds a test-only dependency for less fidelity than real git.

The earlier-session pick of "in-process go-git primary + CGI conformance" was REVISED to (A) once it was discovered go-git ships no HTTP glue. Also decided: TEST-HARNESS-FIRST (build the injection harness, let it expose the real bugs, then fix), and a full operation×fault CONTRACT MATRIX where each cell asserts graceful behavior (typed error, bounded by timeout, no partial state, actionable status, idempotent-recoverable). Trade-off accepted: the harness requires the `git` binary at test time (already a test dependency). Requires go-git CLIENT only. (Path note: this harness lives under test/testenv/gitserver — the test tree was moved out of internal/ to the sibling test/ dir; see kb/decisions/testing/package-layout.)

Credential assertions: while RequireBasicAuth is on, FaultPlan.AuthAttempts() returns every credential presented (user, password, whether it was accepted), oldest first. Use it to prove which credential reached the server and that one never did (the stored-secret tests assert a secret is never sent to a host off its list). git http-backend serves receive-pack only for an authenticated REMOTE_USER, which the CGI env does not set, so a test that pushes over this server enables it on the bare repo with `git config http.receivepack true`. The same server reached as `localhost` instead of `127.0.0.1` is a second host name for host-binding tests.

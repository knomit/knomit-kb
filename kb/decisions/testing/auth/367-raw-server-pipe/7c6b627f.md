# TestDialLocal_RejectsAForeignOwner observes the server end through a test-owned raw overlapped pipe with ConnectNamedPipe pending BEFORE the dial, not through ListenLocal+Accept; bounded waits are failure bounds only

Context (#367): the test hung 10 minutes on Windows CI twice because go-winio's Accept drops a client that connects and hangs up before ConnectNamedPipe is issued (gotcha under kb/gotchas/windows/named-pipes/accept-drops-early-hangup/), and DialLocal's refusal path does exactly that.

Options:
1. Test-owned raw server: CreateNamedPipe (overlapped), start ConnectNamedPipe (ERROR_IO_PENDING), then DialLocal, then wait on the connect event, then ReadFile expecting 0 bytes + ERROR_BROKEN_PIPE. CHOSEN. The pending connect completes even after the client's hang-up, so the race cannot occur. Prototype: 500/500 with a forced 200 ms ConnectNamedPipe delay; a client that writes 1 byte then closes is caught (n=1). The owner check still runs DialLocal's real path; the listener was always a stand-in (owners are narrowed to none).
2. Bound the wait on Accept and skip when it never fires. REJECTED: loses the positive control whenever the race hits, and ERROR_NO_DATA cannot distinguish write-then-close from a clean refusal.
3. Change go-winio upstream to surface ERROR_NO_DATA connections. REJECTED: it is intended library behaviour.

The new waits (about 10 s for the connect event, 5 s for the read) exist only so 'DialLocal never connected' fails cleanly instead of hanging. They are NOT the fix and must not be presented as one.

Non-scope: this does not authorise replacing ListenLocal with raw pipes in other tests; tests that keep the client open until Accept returns are not exposed.

OUTCOME (PR #401, merged as f42ebf2f): shipped as designed.
- An ERROR_PIPE_CONNECTED returned before DialLocal is called is a test failure: a client connected before DialLocal ran.
- A clean close makes ReadFile fail synchronously with ERROR_BROKEN_PIPE and n=0.
- Verified on Windows 10. Under a forced 200 ms ConnectNamedPipe delay, the new test passed 500 of 500 and the old one hung at :179. A count=1000 run passed.
- Forced failures were all caught: write-then-close gives n=1; bypassing the owner check fails; never connecting fails at the 10 s bound; a leaked connection fails at the 5 s bound.

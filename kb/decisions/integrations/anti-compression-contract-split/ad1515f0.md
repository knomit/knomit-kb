# Anti-compression authoring contract is split: domain-neutral wording in MCP server surfaces, code-specific wording in bridge-deployed skills

**Options considered:**
1. Put the full code-flavored authoring contract (src:// refs, enforcing code, HEAD verification) on every surface — server instructions, knomit_learn schema, synthesize prompts, and skills alike.
2. Split by deployment surface: server-side surfaces carry a domain-neutral formulation; bridge-deployed skills and the code profile addendum carry the code-specialized formulation.

**Rationale:** The MCP server (internal/edge/mcp/instructions.go base text, knomit_learn body schema in internal/edge/mcp/learn.go, prune/distill prompts in internal/corpus/synthesize/prompts/large/) serves facts about ANYTHING — the chat and generic profiles have no skills and no /knomit-harden, so the server instructions are the only hardening lever those hosts ever see; code-specific language would be wrong there. The skills deployed by `knomit-bridge claude init` (tools/bridge/claude/templates/skills/) are coding-context only, so they can and should demand src:// refs to enforcing code. User-directed choice (2026-07-04).

**The choice:** One contract at two zoom levels, derived from a single canonical phrasing: "state the operational consequence, name the foreseeable misreading, reference the authoritative source" — where "authoritative source" specializes to "enforcing code via src://<source>/<path>@<commit>" in code contexts (skills + the `code` profile addendum in instructions.go profileAddenda). Skills refine the base contract; they must never contradict it.

**WHAT THIS DOES NOT MEAN:** It does not mean the synthesize prompts are code-specific — they run server-side over facts from any domain, so their fidelity clauses (preserve every condition component, scope qualifier, and "WHAT THIS DOES NOT MEAN" clause across merges/synthesis) are deliberately domain-neutral. And it does not authorize adding code-flavored text to baseInstructionsText — code specialization goes only in profileAddenda["code"] or the skills.

# Antigravity v1 ships ONE hook (PreInvocation context injection) — post-edit/post-ask/pre-compact are blocked by PostToolUse returning {}

**Options considered.** (1) Full parity with the four Claude Code hooks — session-start, post-edit, post-ask, pre-compact. (2) Context injection only — the session-start equivalent alone. (3) No hooks at all: MCP tools and skills, with recall left entirely opt-in by the user.

**Rationale.** Option 2 won on a hard platform constraint, not on effort. Antigravity's `PostToolUse` hook MUST return an empty JSON object `{}` — it has no channel to inject anything into the model's context. Every one of the three deferred Claude Code hooks uses the same detect-and-nudge shape: observe a tool call, then say something about it. That shape is simply not expressible on this platform. Delivering them requires new spool-and-drain machinery — `PostToolUse` writes a nudge to a disk spool keyed by `conversationId`, and the next `PreInvocation` drains it into `injectSteps` — which is a design worth building only after the `PreInvocation` injection path has proven itself in real use. Option 3 was rejected because it gives up the single highest-value behaviour: a session that starts already knowing the project's principles and recent work.

**The choice.** v1 registers exactly one hook, `PreInvocation`, which emits the corpus-context block once per conversation and `{}` on every other invocation.

**Non-scope.** This does NOT establish that Antigravity hooks are generally unsuitable for nudges, and it is NOT a judgement that post-edit/post-ask/pre-compact are unwanted. It is scoped to the absence of the spool machinery. Two facts settled during the work make the deferred hooks tractable later: `PostToolUse` input DOES carry `toolCall.args.AbsolutePath` (the shipped `hooks.md` omits this field; the web docs are correct), and `ask_question` is a real step type, so post-ask has a genuine analogue. Only pre-compact has no equivalent event at all.

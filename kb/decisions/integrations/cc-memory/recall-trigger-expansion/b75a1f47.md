# knomit-recall triggers extended to brainstorming + softer implement phrasings; note-and-proceed on empty

## Options considered

**Brainstorm trigger scope:**
- (a) Only when the `brainstorming` skill is about to be invoked — strict chain.
- (b) Only on natural exploratory phrasings ("how should we...", "what are our options...").
- (c) Both — explicit skill invocation AND exploratory phrasings.

**Implement trigger breadth:**
- (a) Keep the narrow phrase list ("implement X", "add support for Y", "build a new Z").
- (b) Broaden with softer phrasings ("make X work", "set up Y", "get Z working", "wire up W", "add a way to do X", "change behavior of Y").
- (c) Replace phrase list with a meta-rule ("any user request to write/modify non-trivial code in an unfamiliar area").

**Empty-recall behavior** (`knomit_query` returns zero facts):
- (a) Suggest `/knomit-bootstrap` when empty + about-to-do-non-trivial-work.
- (b) Note "no prior facts in this area — proceeding" and continue.
- (c) Silent on empty; let the agent decide.

## Rationale

- **Brainstorm = both (c) chosen.** Strict-chain (a) alone misses informal exploratory chats that never reach a `/brainstorming` invocation but still benefit from prior facts. Natural phrasings alone (b) skip the cleanest signal we have. Both is low-cost and catches both cases.
- **Implement = broaden (b) chosen.** Real user asks frequently skip the word "implement" — "make X work", "set up Y", "get Z working" are very common and meant the same thing. The meta-rule (c) was rejected as too vague — concrete example phrases give the LLM dispatcher clearer trigger signal than abstractions.
- **Empty = note-and-proceed (b) chosen.** `/knomit-bootstrap` has its own strict trigger ("area has zero existing facts AND first-time work driver"). Auto-suggesting it from recall would blur the boundary and risk cascading skill invocations. Better to let the agent judge whether bootstrap fits, rather than wire that logic into recall.

## The choice

Applied all three:

1. New trigger group **Brainstorming / design exploration** in recall's trigger list: covers `brainstorming`-skill invocation AND natural exploratory phrasings ("let's brainstorm X", "how should we approach Y", "what's the best way to Z", "design X", "should we use A or B").
2. **Implementation requests** group keeps explicit verbs and adds softer phrasings.
3. Empty-result paragraph under `## How`: "Note 'no prior facts in this area — proceeding' and continue. Empty results are common in unfamiliar areas; not a blocker."

Frontmatter `description` strengthened to lead with "Use BEFORE brainstorming sessions, implementation requests, or any non-trivial work" so the LLM dispatcher fires more eagerly. Anchored at HEAD `b417390`; template change requires bridge rebuild + `knomit-bridge init` to propagate to other projects (see [[skills-deployment]]).

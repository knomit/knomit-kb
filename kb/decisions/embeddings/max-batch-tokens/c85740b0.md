# embeddings.max_batch_tokens: padded-token budget, default 16384, with 0 as an auto sentinel that must stay absent from Defaults()

PR #175 replaced the fixed `docBatchSize = 32` with `embeddings.max_batch_tokens` / `KNOMIT_EMBED_MAX_BATCH_TOKENS`, a budget on PADDED tokens per `session.Run`.

Default 16384. Grounds: worst-case delta at that budget is MEASURED at the boundary shape 8×2048 (1820 MiB), not extrapolated; and rebuild's short-chunk behaviour stays byte-identical to the old code.

THE CONFIG SHAPE IS LOAD-BEARING. `MaxBatchTokens` is deliberately ABSENT from `Defaults()`, so its zero value means 'operator set nothing'. `Defaults()` runs BEFORE the TOML and env layers, so a value written there could not be distinguished from an operator who explicitly chose the same number. This follows `Remote.KnownHosts`, which is resolved after the overlay for exactly this reason. `Validate` therefore rejects only NEGATIVE values; 0 is valid and documented.

Resolution of 0 lives at the APP layer (`internal/app/app.go`), not in config — config must not grow a `/sys/fs/cgroup` dependency when the resolver later derives a value from machine memory.

CURRENT STATE, and what a follow-up changes: 0 currently resolves to the fixed `DefaultMaxBatchTokens`. A planned follow-up (PR 2) changes only the RESOLUTION — deriving a smaller budget on memory-constrained hosts and in containers — never the sentinel's SEMANTICS, so no operator config breaks across versions. Auto-sizing is clamp-DOWN only: never size up, because above 16384 per-run amortization is exhausted while retained arena memory grows linearly.

DO NOT add a second document-count knob. The one-knob decision was taken deliberately; the per-row cost the token budget misses is handled by `minRowCharge`, an unexported const.

# All 6 absolute cosine thresholds become per-model fields on embeddings.Model; distribution-preserving port for soft knobs

DECISION (PR #72, pluggable embedder): the six absolute cosine thresholds scattered across the codebase are model-dependent (they were implicitly calibrated for nomic) and must travel with the embedding model. They move onto the `embeddings.Model` descriptor as per-model fields, exposed to consumers through the `store.Embedder` interface (mcp/store/synthesize already reach the embedder via that interface and none import the embeddings package directly, so the descriptor is the clean single source of truth). Each registered model carries its own values: nomic-v1.5 keeps today's literals, embeddinggemma gets calibrated values, qwen gets sensible defaults.

**AS BUILT — where the six actually live now.** The values are a `params.Thresholds` struct (`internal/domain/modelparams/thresholds.go`) hung off `embeddings.Model.Thresholds`, read through `Embedder.Thresholds()` and the `store.EmbedderThresholds(emb)` helper (re-exported by `internal/engine/store/vcs_seam.go`, implemented in `internal/store/internal/vcs/embedder.go`, which supplies `params.Defaults()` when no embedder is configured). The pre-decision literal names are gone; the mapping is:

| Original threshold | Field | Consumer at HEAD |
|---|---|---|
| learn dedup 0.92 | `Dedup` | internal/edge/mcp/learn.go, internal/corpus/synthesize (dedup + discovery) |
| synthesis dedup 0.92 | `Dedup` (same field) | internal/corpus/synthesize/review_strategy.go |
| SIMILAR_TO knn 0.60 | `SimilarTo` | internal/engine/store/index/search_graph.go, index/search_index.go |
| search recall floor 0.40 | `SearchFloor` | internal/engine/store/index/search_query.go |
| rerank tiers 0.70/0.50 | `RerankHigh` / `RerankLow` | internal/engine/store/index/search_query.go |
| reflect novelty 0.85 | `ReflectNovelty` | internal/corpus/synthesize/review_strategy.go |

Note the first two collapsed into ONE field: learn-time and synthesis-prune dedup share `Dedup`, so changing it moves both.

**OPTIONS CONSIDERED (via AskUserQuestion):** (a) all six [CHOSEN]; (b) dedup + hard gates only (4); (c) just the two dedup (2). RATIONALE: all six are the same class of silent mis-calibration when the default model changed from nomic to embeddinggemma, not just dedup — so fixing only dedup leaves the rest quietly wrong. Dedup is the load-bearing one because over-merge is DATA-LOSS (distinct facts collapsed at write/prune).

**CALIBRATION METHOD:** dedup/similar-to/novelty are gates calibratable from the corpus by measuring the doc-doc cosine distribution (distinct vs near-duplicate separation). The soft ranking knobs (`SearchFloor`, `RerankHigh`/`RerankLow`) CANNOT be rigorously calibrated without labeled query→relevant-doc judgments the corpus lacks; DECISION: distribution-preserving port — set embeddinggemma's value to the same percentile of its query→doc cosine distribution that the nomic value occupied. Existing env overrides (`KNOMIT_REFLECT_NOVELTY_THRESHOLD`) are preserved layered on top of the descriptor default.

**WHAT THIS DOES NOT MEAN.** *Not* "grep for `dedupThreshold` / `knnThreshold` / `defaultDedupThreshold` / `defaultReflectNoveltyThreshold`." None of those symbols exist any more — they were the scattered literals this decision removed. Read `params.Thresholds` for the current set, and note the struct is the whole surface: adding a seventh knob means adding a field there, not a new constant beside its consumer.

# The small-model prompt tier (prompts/small/ plus Profile/ResolveProfile) was deleted 2026-03-18; prompts/large is the model-size tier name, not a prompt-length label, and RenderTemplate hardcodes it

What existed: between 2026-03-13 and 2026-03-18 the synthesis code had two prompt tiers selected per model. Commit 8f6046c4 (2026-03-13, "add small profile prompt templates") added internal/synthesize/prompts/small/ with six templates (prune and distill, each with system, user and retry): few-shot examples, explicit criteria, a <think> preamble for chain-of-thought and direct language, written for small models. Commit 51e70a9a added a Profile struct and ResolveProfile, which chose the tier from a ":Nb" parameter-count suffix in the model name; a small profile turned ForceJSON off and enabled a retry-on-passive pass using the *_retry templates (wired into the prune step by 3fcbc70e).

What removed it: commit 2443012c (2026-03-18, "refactor: delete old pipeline, recipes, profiles — Reviewer is the sole engine"). The stated reason is engine consolidation: the headless prune/distill pipeline, the recipe/profile system, batch adapters and the small-model prompt templates were deleted together because the Reviewer multi-turn orchestrator became the only synthesis engine. The message gives no reason specific to small models (no measurement that the tier failed); the tier went as part of the pipeline it served. The same commit simplified RenderTemplate by dropping its profile parameter and hardcoding "large".

State at HEAD: internal/synthesize/prompts/ contains only large/, embedded by go:embed prompts/large/*.txt, and RenderTemplate builds the path as fmt.Sprintf("prompts/large/%s_%s.txt", operation, promptType) (internal/synthesize/prompts.go lines 10 and 54). Nothing in the repo selects a template by model. No later plan or commit reintroduces a tier; the .claude/future/expert design set (a knomit-native small model) only notes the removal as history.

Consequence for anyone adding a local small model to synthesis today: it receives the large-tier prompts, which assume a capable multi-turn tool-using model. There is no per-model prompt switch, no Profile, no ForceJSON toggle and no passive-retry pass to configure. A small-model path means restoring a tier selector in RenderTemplate (and a data path for the model's size) deliberately, using commits 8f6046c4 and 51e70a9a as the prior design, not flipping a setting.

Misreading to avoid: "prompts/large means a large prompt" is false. "large" was the model-size tier (large models versus small models); the directory name survives only because deleting its sibling left it as the single tier. Equally, its presence does not mean a tier system still exists.

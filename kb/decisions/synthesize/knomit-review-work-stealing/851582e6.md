# knomit_review steals cycles from calling model for KB maintenance; additive to headless pipeline

knomit_review is a work-stealing MCP tool that opportunistically uses the calling model's cycles for KB maintenance — NO separately configured LLM adapter needed. Flow: model calls with no session_id → tool creates a session, computes dirty facts, builds scoped clusters, returns the highest-priority work item with {prompt, response_schema}; the model reasons and returns JSON decisions via session_id+response; the tool applies and returns the next item; repeat until done.

WATERMARK SEMANTICS (still current): on first run (no watermark) the full KB is clustered; subsequent runs use scoped clustering — dirty-fact detection via git diff against the watermark, then candidate neighbors, then Louvain over the scoped input. ABANDONED sessions do NOT advance the watermark (only completed sessions do); decisions already applied during an abandoned session REMAIN committed — they were valid when applied. That asymmetry is deliberate: re-running after an abandon re-examines the same range, and applied decisions must be idempotent under that replay.

WHAT THIS DOES NOT MEAN (corrected 2026-07-22 — two layers of drift):

1. The tables are NOT `review_sessions` / `review_work_items` / `review_watermarks`. Those names do not exist anywhere in the tree. They were renamed to `pipeline_sessions` / `pipeline_work_items` / `pipeline_watermarks`, with a `tool` column distinguishing 'review' from 'hypothesize' — see kb/decisions/synthesize/pipeline-infrastructure-unification/e1ff6cd3.md. Also note sessions and work items live in the EPHEMERAL session DB (recreated on every Open), while pipeline_watermarks stays in the main durable DB — see kb/architecture/store/tool-sessions-unified-schema/be09558e.md.

2. This fact describes the tool's BEHAVIOUR, not the current architecture. The 'ClusterBuilder / PromptRenderer / DecisionParser / DecisionApplier extracted from prune/distill' decomposition and the 'additive to the headless POST /synthesize pipeline' framing are both superseded: there is now ONE engine (`synthesize.Pipeline`) with review and hypothesize as `Strategy` implementations, and the old POST /synthesize pipeline, recipes, and profile selection are DELETED. Read kb/decisions/synthesize/one-engine-two-drivers/19c69b3f.md for the authoritative structure before writing code here — in particular, a new synthesis tool implements Strategy; it must not grow its own session lifecycle.

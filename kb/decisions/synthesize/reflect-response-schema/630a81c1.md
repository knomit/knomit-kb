# Reflect schema: structured (reinforce, propose) with HARD-CAPPED propose + novelty check

The reflect step's response replaced the informational methodology_facts array with a structured schema enforcing rarity at the SCHEMA level. Fields: reasoning (string), reinforce (array of {methodology_path, transition_paths, rationale}), propose (array CAPPED at 1, configurable via KNOMIT_REFLECT_PROPOSE_CAP, items include {title, body, topic_path, transition_paths, novelty_argument}). The novelty_argument field is deliberately hostile-to-write — it forces the model to articulate why no existing methodology fits before it can propose. Server-side validation order (short-circuit on first error): parse → transition-path validity (must be in session's recorded transitions) → reinforce-target validity (path exists + type=methodology) → propose novelty (embedding cosine vs IncludeTypes:[methodology], threshold default 0.85 via KNOMIT_REFLECT_NOVELTY_THRESHOLD, reject pointing at closest existing) → propose well-formedness (server FORCES type=methodology, agent cannot set it) → apply via single BatchWriteFacts commit covering both arms atomically. Validation failures do NOT mark the work item answered — agent retries cleanly while phase stays at reflect.

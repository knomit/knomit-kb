# Pipeline is the SINGLE synthesis engine; review and hypothesize are Strategies over it, MCP and HTTP are drivers

Synthesis has ONE engine, TWO tool strategies, and TWO drivers.

ENGINE — `synthesize.Pipeline` (internal/synthesize/pipeline.go) owns everything both tools share: session lifecycle and scoped-marking, the work→reflect→done phase machine (CAS transitions), the seed scan and per-branch watermark gate including the scoped exemption, completion and watermark advance, and the work-item claim protocol (peek → decode/validate → CAS-claim → apply). First-run seeding uses the INDEX (idx.Search with Limit 100_000), NOT a git tree walk — gatherAllFacts was eliminated; incremental runs use DiffFiles since the watermark.

STRATEGIES — the per-tool variation surface is the `Strategy` interface (internal/synthesize/strategy.go): Tool, SeedQuery, AcceptSeed, Plan, OnPhaseAdvance, Decode, Apply, Render. `reviewStrategy` (prune/distill/reflect/discover-forward) and `hypothesizeStrategy` (per-synthesis-fact + discover-backward) are both ZERO-SIZE structs — everything reaches them through `Deps` or off the pipeline_sessions row, which is how invariants/synthesize/per-call-objects-no-session-state is enforced by the type system rather than by comment. The `discover` step is implemented ONCE in strategy.go and shared by both.

DRIVERS — (1) MCP: knomit_review and knomit_hypothesize are thin adapters that construct a Pipeline per call and convert PipelineResult into their own wire shape. Their wire types (ReviewResult/ReviewItem, HypothesizeResult/HypothesizeItem) are DIFFERENT and both are public API; the engine is deliberately wire-agnostic. (2) HTTP automated: RunAll(ctx, adapter) loops internally — render prompt, adapter.Complete, feed to ContinueSession — until done. `synthesize.Reviewer` survives as a thin FACADE over Pipeline so existing callers (internal/web/handlers_jobs.go) and the test suite keep working; it is not a second engine.

HISTORY AND THE MISREADING THIS FACT EXISTS TO PREVENT: this fact previously said the Reviewer struct was the sole engine. That was the INTENT, but the code had drifted — hypothesize reimplemented the entire session lifecycle inside internal/mcp/hypothesize.go, and the two copies made OPPOSITE idempotency choices (review applied then marked; hypothesize marked then applied), which was a live duplicate-synthesis-fact hazard. Do NOT read 'one engine' as a description that polices itself: the drift took months to surface and was found by code review, not by a test. If you add a third synthesis tool, it implements Strategy — a new tool that grows its own StartSession/ContinueSession inside a transport package is the exact regression this fact is here to catch.

The old POST /synthesize pipeline, recipes, profile selection, and the 'small' prompt set are DELETED; the 'large' prompt set is hardcoded for all rendering.

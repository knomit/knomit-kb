# Reviewer is the SINGLE synthesis engine; MCP and HTTP are two drivers over it

Synthesis has ONE engine and TWO drivers. The Reviewer struct is the sole engine, owning watermark tracking (per-branch via ReviewIndex/PipelineIndex), dirty fact detection (DiffFiles since watermark), scoped clustering, work item queue (prune + distill with RAPTOR), dedup pre-pass, decision application. DRIVERS: (1) MCP — knomit_review tool calls StartSession()/ContinueSession(); an external model processes one work item per call, sending JSON responses back. (2) HTTP automated — reviewer.RunAll(ctx, adapter) loops internally: render prompt, call adapter.Complete(), feed response to ContinueSession until done. The old POST /synthesize pipeline, recipes, profile selection, and 'small' prompt set are DELETED. Hardcode 'large' prompt set for all rendering. First-run dirtyFacts uses INDEX (idx.Search(SearchQuery{Limit: 100_000})), NOT git tree walk — gatherAllFacts was eliminated. Incremental runs use DiffFiles since watermark.

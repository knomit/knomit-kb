# Bridge-quality defaults from the trunk stress test: maxMembers=5, cohFloor≈0.5

Decision on the seed defaults for the bridge-quality config knobs.

**Options considered:** guess the floors/cap a priori, vs. derive them from an offline stress test against a real worst-case corpus.

**Rationale:** validated offline against a snapshot of the trunk corpus (793 live facts, 37 clusters, 12,399 SIMILAR_TO edges) — a near worst case (topical news, a few mega-tokens blanket the base). On the UNWEIGHTED SIMILAR_TO edge density scale, grab-bags scored 4-11% cohesion while reshaped cohesive subsets scored 50-100% — clean separation, so cohFloor≈0.5 cleanly divides them. maxMembers=5 produced clean near-cliques. SIMILAR_TO stores no weight (edge_props_real empty) and binary density already discriminates, so no persisted weights / facts_vec cosine are needed at ranking time.

**The choice:** DiscoveryConfig seed defaults coh_floor=0.5, max_members=5, quality_floor=0.0, w_coh=w_gap=w_spec=1.0. These are SEEDS to be tuned via the `calibrate bridges` dev tool (component report + percentile-derived floor suggestions), not final values.

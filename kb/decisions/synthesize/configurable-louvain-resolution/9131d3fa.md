# Louvain resolution is config-driven (default γ=2.0) and threaded as single-source-of-truth to checker + read path

DECISION (PR #70): the Louvain clustering resolution (γ) and min community size are configurable, defaulting to γ=2.0 / min_community_size=2 — was a hardcoded γ=1.0 + a hardcoded 'len(c) > 1' filter.

WHY γ=2.0: γ=1.0 produced an over-large mega-cluster; on the real corpus γ=2.0 broke it up (largest community 54->26, top-3 share 25%->14%). Higher γ = more, smaller communities.

CONFIG: config.ClusterCacheConfig gained Resolution float64 + MinCommunitySize int (TOML [cluster_cache] resolution / min_community_size; env KNOMIT_CLUSTER_CACHE_RESOLUTION / KNOMIT_CLUSTER_CACHE_MIN_COMMUNITY_SIZE; defaults in config.Defaults()).

SINGLE-SOURCE-OF-TRUTH THREADING (load-bearing): the SAME (resolution, min_community_size) must reach BOTH the background cluster checker (clusterKeys / CachedClusterFacts) AND the synthesize read path, because the cluster_cache is keyed on (branch, resolution, min_community_size) — a mismatch causes cache THRASH (warm writes one key, read misses it). Path: config -> RepoInstance.clusterResolution/clusterMinCommunity (via clusterResolutionOrDefault/clusterMinCommunityOrDefault in repoBuilder.build) -> RepoInstance.ClusterResolution()/ClusterMinCommunitySize() -> synthesize.ScopedCluster(... resolution, minCommunitySize ...) -> idx.CachedClusterFacts(ctx, branch, resolution, minCommunitySize). synthesize keeps its OWN const fallbacks (defaultScopedResolution=2.0, defaultScopedMinCommunitySize=2) used ONLY when a caller passes a non-positive value — kept as plain constants because synthesize must NOT import repos; they must stay in sync with repos.defaultCluster*. filterSmallClusters now takes minCommunitySize (drops clusters with len < min) so the category-fallback paths drop the same small communities the Louvain path does, instead of the old hardcoded '> 1'.

# Louvain resolution is config-driven (default γ=4.0) and threaded as single-source-of-truth to checker + read path

DECISION (PR #70): the Louvain clustering resolution (γ) and min community size are configurable, defaulting to γ=4.0 / min_community_size=2 — was a hardcoded γ=1.0 + a hardcoded 'len(c) > 1' filter.

DEFAULT γ HISTORY: originally set to 2.0 (γ=1.0 produced an over-large mega-cluster; on the old corpus γ=2.0 broke it up, largest community 54->26, top-3 share 25%->14%). RECALIBRATED to 4.0 for the new (SIMILAR_TO scoped) graph in commit bd3bffc — the denser graph needed a higher γ to keep communities from re-merging into a mega-cluster. Higher γ = more, smaller communities. config.Defaults() now sets ClusterCache.Resolution=4.0.

CONFIG: config.ClusterCacheConfig carries Resolution float64 + MinCommunitySize int (TOML [cluster_cache] resolution / min_community_size; env KNOMIT_CLUSTER_CACHE_RESOLUTION / KNOMIT_CLUSTER_CACHE_MIN_COMMUNITY_SIZE; defaults in config.Defaults()).

SINGLE-SOURCE-OF-TRUTH THREADING (load-bearing): the SAME (resolution, min_community_size) must reach BOTH the cluster checker AND the synthesize read path, because cluster results are keyed on (branch, resolution, min_community_size) — a mismatch causes cache THRASH (warm writes one key, read misses it). Path: config -> RepoInstance.ClusterResolution()/ClusterMinCommunitySize() -> synthesize.ScopedCluster(... resolution, minCommunitySize ...). BOTH default-fallback constant pairs are now 4.0/2.0 and MUST stay in sync: synthesize defaultScopedResolution=4.0 / defaultScopedMinCommunitySize=2 (internal/synthesize/cluster.go, kept as plain consts because synthesize must NOT import repos) and repos defaultClusterResolution=4.0 / defaultClusterMinCommunitySize=2 (internal/repos/cluster_config.go). They are used ONLY when a caller passes a non-positive value. filterSmallClusters takes minCommunitySize (drops clusters with len < min) so the category-fallback paths drop the same small communities the Louvain path does, instead of the old hardcoded '> 1'.

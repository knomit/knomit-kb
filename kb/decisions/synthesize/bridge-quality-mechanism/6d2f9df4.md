# Bridge quality: replace breadth-rewarding strength with cohesion-gated reshape ranked by composite Q

Options considered: (a) keep token-anchored bridges, just cap members / drop broad tokens; (b) re-rank by a composite quality score AND reshape broad token groups into their cohesive cross-community core; (c) invert to pure semantic-pair detection.

Rationale (empirically validated on the trunk corpus, 793 facts): the old `strength = (1/freq) × communities × members` rewards breadth — with members≈freq the `1/freq` cancels, so broad domain tags dominate (`ai` = 319 members spanning 36/37 clusters; 10/12 surfaced bridges were grab-bags). Cohesion measured as SIMILAR_TO edge density cleanly separates grab-bags (4–11%) from cohesive subsets (50–100%). Reshape — seed from a cross-community SIMILAR_TO pair, grow by cohesion, cap members, require sep>=2 — rescued ALL 12 trunk grab-bags into tight subsets, 0 dropped. Two refinements the stress test forced: (1) cross-community seeding is ESSENTIAL — the densest subset is otherwise intra-cluster, because Louvain groups by exactly that similarity; (2) sep (community span) is a GATE (>=2), NEVER a ranking reward — rewarding it was the original bug. coh uses UNWEIGHTED SIMILAR_TO edges (no weight is persisted; binary density already discriminates), so no facts_vec cosine is needed at ranking time.

Choice: replace `strength` with composite `Q` = hard gates (coh>=cohFloor, sep>=2, members<=maxMembers) then rank survivors by coh/gap/spec (+ at most a small sep term); reshape oversized token groups into their cohesive cross-community subset. Trunk-calibrated default starting points maxMembers=5, cohFloor≈0.5; final weights/floors are tuned via the `calibrate bridges` tool (see decisions/tools/calibrate-bridges-subcommand). `normal` effort stays byte-identical (bridgeSeeds returns nil at EffortNormal). spec rarity is supplied by query-time TokenDF (see decisions/store/discovery-spec-df-query-time).

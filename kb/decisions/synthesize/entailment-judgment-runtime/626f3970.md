# Extend the ONNX runtime with a cross-encoder entailment model; entailment (not cosine) becomes the dedup/novelty/tension judgment primitive

**Options considered:** (a) keep bi-encoder cosine thresholds as the only local judgment (0.92 dedup gate) and compensate with prompt engineering (show neighbors, ask the agent to self-police novelty); (b) add a cross-encoder NLI model to the in-process ONNX runtime and make directed entailment the judgment primitive for restatement, subsumption, and contradiction.

**Rationale:** Bi-encoder cosine structurally cannot distinguish restatement from consequence from contradiction — all three embed close. This is the root cause of the documented gotcha that the 0.92 dedup gate only catches verbatim dupes (kb/gotchas/synthesize/discovery/90d69628) and of same-event near-duplicate bridge seeds (kb/gotchas/synthesize/discovery/8ebd5d90). With a cross-encoder: bidirectional entailment = restatement (mechanical novelty/dedup verdict, proposal 08); one-directional entailment = weakening/subsumption (forward dedup-not-append); contradiction mass = measured tension seeds (proposal 04's reconcile direction); pairwise entailment detects redundant bridge members directly (proposal 09). The single-purpose BERT-WordPiece tokenizer and fixed vec dimension are named as changeable in the pre-release principle; the runtime should host N models. Judgment stays auditable — a local cross-encoder score is as replayable as a cosine; 'model-less' seeding was never the point, auditability was.

**The choice:** One local-inference work stream (model selection + per-model calibrated thresholds alongside the existing embedder thresholds registry) underlies proposals 04, 08, 09 and corpus-wide dedup. Status: proposed direction, pre-refinement; no implementation yet.

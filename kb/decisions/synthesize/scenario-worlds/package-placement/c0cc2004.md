# The scenario-world loader and graders live in internal/synthesize, not a new package: internal/mcp imports synthesize, so the loader takes a repos.ScriptTools, and tests sit in package synthesize_test

Options: a new package for scenario worlds (rejected: the project rule is no new package for this), or internal/synthesize. Chosen: internal/synthesize (scenario.go, scenario_load.go, scenario_chain.go, scenario_grade.go). Because internal/mcp already imports synthesize, the loader cannot build the in-process write path itself without an import cycle; it takes the repos.ScriptTools as ScenarioLoadOptions.Tools and the caller passes mcp.NewScriptTools(embedder). The same reason puts the tests in package synthesize_test (scenario_load_test.go, scenario_grade_test.go), which may import internal/mcp. The chain types mirror repos.ReasonResult rather than importing it, keeping this package free of the engine's runtime.

Consequence: do not make synthesize import internal/mcp, and do not move the loader into mcp to avoid passing the tools; a new scenario helper that needs the write path takes the tools as a parameter. Misreading to avoid: this placement is a consequence of the import direction, not a claim that scenario worlds are part of the synthesis pipeline.

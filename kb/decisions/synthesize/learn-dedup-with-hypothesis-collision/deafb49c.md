# On dedup collision with an existing hypothesis: write the observation, cite the hypothesis and retract it in one commit (it is SETTLED; the verdict comes only from `settles` or a review settle)

When knomit_learn detects a near-duplicate of an existing fact AND the existing fact has type=hypothesis: apply retract-and-link instead of a normal dedup merge. Specifically: (1) write the new observation as normal; (2) retract the hypothesis; (3) add the hypothesis's path to the observation's refs (provenance: hypothesis X, settled by this observation; the branch fires on similarity, not on a verdict, so it records none -- see the #648 UPDATE below). This is the canonical 'hypothesis settled by observation' lifecycle. The change lives in internal/edge/mcp/learn.go's dedup branch. Dedup between observations (no hypothesis involved) is unchanged — normal merge. Distinct from the symmetric case where reflect/review identifies a hypothesis as confirmed/retracted via the transition-detection pass.

CONSEQUENCE: because both halves must land together — the observation write AND the hypothesis retraction — this path goes through BatchWriteFacts so it is one commit. See kb/invariants/store/batch-write-atomicity/71c6dd17.md; this is the motivating case for that invariant.

WHAT THIS DOES NOT MEAN — THE TRIGGER IS NOT '≥0.92' (corrected 2026-07-22): this fact previously pinned the collision trigger at ≥0.92 similarity. That literal is stale. internal/edge/mcp/learn.go reads `store.EmbedderThresholds(batchEmb).Dedup` at call time — a PER-MODEL calibrated cutoff, currently 0.82. Do not reimplement this test with a hardcoded number: against a model calibrated lower than your literal, the collision branch simply never fires and confirmed hypotheses pile up un-retracted alongside the observations that confirm them. See kb/decisions/synthesize/dedup-merge-tiebreak/02422cde.md.

UPDATE (#642, merge 77896f0a): two corrections. (1) The title and the lifecycle text above say 'confirmed hypothesis', but the branch fires on SIMILARITY to the stored hypothesis, not on a verdict, so it equally retracts a hypothesis the new observation REFUTES. 'Settled' is the accurate word; the wording here was wrong and was tracked in issue #641 (https://github.com/knomit/knomit/issues/641), which #648 closed (see the next UPDATE). (2) The retraction is no longer silent: learn adds a response note per subsumed hypothesis ('retracted hypothesis <path> (settled by this fact, cited in refs); to keep it, re-learn it with distinct_from: [<new fact path>]') and a 'settled: <path>' commit line; `retracted` and `commit` stay the caller's own retract paths. The undo is re-learning with distinct_from, never knomit_update. See kb/gotchas/mcp/learn-hypothesis-report/612294ef.md and the ruling in kb/decisions/mcp/learn-hypothesis-report/e8f1082b.md.

UPDATE (#648, merge 2782d21c; closes issue #641): this fact's policy now has two halves. (1) UNDECLARED, the similarity path described above is unchanged in mechanics (cite in refs, retract in the same BatchWriteFactsMustExist commit, one note, one `settled:` commit line) and it only SETTLES: it writes NO verdict, because textual similarity cannot tell a confirmation from a refutation. Read 'confirmed hypothesis' anywhere above as 'settled hypothesis'. (2) DECLARED, a verdict comes from exactly three sources: knomit_learn's per-fact request-only `settles: [{path, outcome}]`, review's prune `settle`, and distill's `settle`; each cites the hypothesis, retracts it in the same commit and records `Knomit-Outcome: <path> confirmed|refuted` in the commit trailer, never in a fact field. A declared settle wins over similarity subsumption. The same cite-and-retract shape (no trailer) also applies to review's dedupCluster when a hypothesis loses to a non-hypothesis winner. See kb/decisions/mcp/learn-hypothesis-report/55bfa96f.md (the user ruling), kb/invariants/mcp/learn/settles/3bf57718.md and kb/invariants/synthesize/settle/51a99ac3.md.

WHAT THIS DOES NOT MEAN. Similarity subsumption is not a verdict and still must not be reported as one; a caller who knows the outcome should declare it with `settles` rather than rely on the similarity path.

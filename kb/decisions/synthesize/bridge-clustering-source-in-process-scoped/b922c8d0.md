# Bridge community assignment comes from in-process ScopedCluster; ClusterResult lives in synthesize, not store

Decided while merging the emergent-fact-discovery branch (PR #97) on top of PR #98, which replaced GraphQLite's graph-wide `louvain()` + cluster-cache with in-process gonum Louvain over a scoped subgraph and DELETED `store.ClusterResult`, `ClusterFacts`, and `CachedClusterFacts`. The bridge/discovery engine still depended on all three, so the merge had to re-home them.

**Options considered:**
1. Change the bridge engine's currency to dev's `[][]factForLLM` and drop `ClusterResult` entirely — but the bridge tests inject community partitions as lightweight `ClusterResult{Clusters: map[int][]string{...}}` fixtures (path-only), and the engine collapses everything to a path→community map anyway; switching currency means heavier `factForLLM` fixtures everywhere.
2. Re-add a graph-wide in-process clustering for the bridge callers — fights PR #98's whole point (no global clustering; scoped only).
3. **(chosen)** Relocate `ClusterResult` + `ClusterOf` from `store` → `synthesize` (its only consumer is the bridge engine) and add `clusterResultFromGroups([][]factForLLM)` to adapt `ScopedCluster` output to it.

**Rationale:** option 3 keeps the carefully-tuned, heavily-tested bridge logic (cohesion gate, separation-as-gate, reshape, Q scoring) byte-identical — only the SOURCE of the partition changes. `ClusterResult` is a synthesize concept now that store no longer clusters; keeping it in store would be a dead type in the wrong layer.

**The choice:** the two remaining global-clustering callers — backward discovery (`BuildBackwardBridges`) and the calibrate tool (`BridgeComponentReport`) — now call in-process `ScopedCluster` instead of the deleted `CachedClusterFacts`, matching the forward (review) path which was already scoped. CONSEQUENCE: backward + calibrate community assignment is now SCOPED (seeds + nearest neighbors) rather than GLOBAL. This is the only option (global clustering no longer exists) and makes all three discovery paths consistent. `clusterResultFromGroups` produces no Noise (ScopedCluster pre-filters sub-floor groups); facts absent from every group get distinct synthetic negative ids in `bridgePathCommunities`, preserving the prior per-noise-fact community separation. Supersedes the cluster-cache clustering source described in [[bridge-seeding]].

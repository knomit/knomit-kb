# A judged prune merge in review never takes its type from the judge: the type is derived from the members via the dedup tiebreak, and cross-kind, all-hypothesis and apply-time-unreadable merges are refused

DECISION (PR #644, merge 13abafd3; closes gap 2 of kb/gotchas/mcp/learn-hypothesis-report/99e43740.md). ApplyPruneDecisions (internal/corpus/synthesize/decision.go) no longer lets the judge supply a merged fact's type. The type comes from the MEMBERS via mergedTypeFromMembers: the shared type when members agree, otherwise the type of the member the dedup tiebreak picks (mergeFacts: non-hypothesis over hypothesis, then higher confidence, then more sources; kb/decisions/synthesize/dedup-merge-tiebreak/02422cde.md). The prune prompt no longer asks for `type`; MergedFact.Type is still parsed only so a differing value is reported as a warn ("judge type ... ignored").

The winner is picked by comparing each member to the best so far with mergeFacts but keeping the ORIGINAL member, because mergeFacts pools Sources into its return value; the result therefore does not depend on member order or accumulated sources beyond a full tie (the earlier member keeps it).

REFUSED MERGES (each a warn; members stay, nothing is written): (a) members not all of one known kind (sameKnownKind, whoever wins the tiebreak; 94172e81); (b) every member is a hypothesis (review never creates hypotheses); (c) no member readable when the type is derived; (d) no member readable AT APPLY TIME. Members are snapshotted before the decision loop but ComputeTransfer reads at apply time, and one judge response may both retract a path and list it in a merge or have two merges share members; a merge whose members are all gone then is refused instead of written from the stale snapshot. A merge with SOME members gone still applies. Members of a non-epistemic kind (policy) cannot be prune-merged: they fail the kind check or, if all pragmatic, fail at serialization (invalid type for kind epistemic).

CONSEQUENCE: a merge can no longer promote a hypothesis to synthesis (or any type). A mixed hypothesis plus non-hypothesis merge absorbs the hypothesis into the non-hypothesis type. Distill's route remains: a hypothesis confirmed by a batch is retracted and cited in the new synthesis fact's refs.

WHAT THIS DOES NOT MEAN. It is review's PRUNE merge only: it does not cover distill, and it does not make mixed non-hypothesis types safe: a concept member and a pattern member still merge into whichever type the tiebreak picks (see the user ruling in this category). The 'none of the subsumed facts could be read' warn was not dead code; it is kept as a refusal. Tests that pin it: decision_merge_type_test.go (UnreadableMembersAreRefused, MembersRetractedInTheSameCallAreRefused, CrossKindMembersAreRefused_WhoeverWinsTheTiebreak, ThreeWayTieUsesEachMembersOwnSources); removed as unreachable: MergeWarnsWhenSourcesUnreadable, MergeOverHypothesesDoesNotWarnUnreadable.

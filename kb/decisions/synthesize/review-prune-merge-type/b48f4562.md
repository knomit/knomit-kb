# User ruling (PR 644): a prune merge of members with different non-hypothesis types takes the dedup tiebreak winner's type 'for now'; refusing such merges was considered and deferred

USER RULING on PR #644 (merge 13abafd3), option (a): when a judged prune merge's members are non-hypotheses of DIFFERENT types (say a concept and a pattern), the merged fact takes the type of the member the 02422cde tiebreak picks (higher confidence, then more sources), 'for now'. Option (b), refusing the merge and keeping both facts, was considered and deferred, not rejected: it is the stricter reading of 'a dedup merge never changes a stored fact's type' because the losing member's content survives under another type. Review has no stored side to prefer (learn keeps the STORED fact's type whoever wins), so the tiebreak is the same rule review's mechanical dedup already applies.

CONSEQUENCE: do not treat the tiebreak as settled design or as a bug. If mixed-type merges prove lossy in practice, option (b) is the known next step and needs a new ruling; the code site is mergedTypeFromMembers (internal/corpus/synthesize/decision.go).

WHAT THIS DOES NOT MEAN. It does not extend to hypotheses (hypothesis members never decide the type of a mixed merge) or to mixed kinds (those are refused).

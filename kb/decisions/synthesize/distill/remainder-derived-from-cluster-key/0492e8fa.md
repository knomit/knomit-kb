# The distill remainder ask is derived from the work item's ClusterKey by isRemainderItem — the ONLY derivation, deliberately not a column, because a column could disagree with the key

A `distill-rest` item is the seeds that landed in NO multi-seed cluster — a leftover set, not a group. Until PR #190 the prompt asked it the same "identify patterns across these facts" it asks of a real cluster. On one observed session that item held ~60 facts spanning AI funding, security CVEs, a psychology study on punctuation, and interstellar governance, delivered across 3 pages. There are no patterns across those facts.

WHAT THE AGENT DID INSTEAD, and the system had no record of it: silently sub-clustered the bucket, synthesized two coherent sub-groups, and ignored the other ~50. That is the signature of a prompt bug rather than an agent bug — whenever an agent's best available move is one the prompt does not describe, the prompt is what needs fixing, because the behaviour is unauditable by construction.

THE REMAINDER BRANCH says the set is unclustered, asks for coherent SUB-GROUPS of two or more facts, states that most members belonging to none is expected and an empty `synthesize` is the common correct answer, and scopes the "share NO motif, skip" rule PER SUB-GROUP — in a leftover set motifs are shared in scattered pairs, not set-wide. `subgroups_considered` records every sub-group weighed INCLUDING rejected ones; nothing branches on it.

THE DERIVATION, and why there is no column. Remainder chunks are enqueued as `"<distillGroup.Key>-<chunk>"` with the key `"distill-rest"`; every other distill item is a promoted cluster (`promotedDistillKeyPrefix`, `"distill-promoted-"`) or a RAPTOR follow-up (`"raptor-d<depth>-c<i>-<chunk>"`). The render site reads the item back from the store and holds ONLY the item, so the flag must be derivable from what the key already records. `isRemainderItem(clusterKey)` is that derivation and must remain the only one: a column would duplicate state the key already carries, and duplicated state can disagree — at which point the prompt and the queue would describe different items.

WHAT THIS DOES NOT MEAN: it is not a general licence to encode flags in keys. It holds because the key is ALREADY the authoritative record of how the item was enqueued, and the enqueue sites are few and named. A property not already implied by the key needs somewhere real to live.

COSTS ENVELOPE BYTES. The remainder ask is the LARGER of the two branches, so it — not the cluster ask — is the worst case any page-budget test must measure. See the page-envelope-reserve fact: a test that renders only the cluster branch stays green while measuring the wrong thing.

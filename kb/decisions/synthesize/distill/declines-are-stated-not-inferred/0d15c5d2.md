# declined_reason is an optional plain string in the response column, and the session states which of four things happened — absence of the health line now means exactly ONE thing

`{"synthesize": [], "retract": []}` is byte-identical whether the agent read every member and judged honestly that no mechanism joins them, or skimmed and gave up. Eight of fifteen distill items declined that way in one reviewed session, and at least one decline was probably wrong — two facts in different topic trees that jointly supported a real claim about agent containment failing on the INFRASTRUCTURE side rather than the model defeating it. Nothing recorded that it had been considered.

THE FIELD. `declined_reason` (enum in the schema) plus `declined_note` (one sentence). Both OPTIONAL: only `synthesize` is probed by `requireResponseKey`, so a response written before they existed still parses — see the response-envelope invariant. The enum lives in the SCHEMA and the Go field is a PLAIN STRING, so an unknown value is kept as written rather than rejected or blanked, and a future prompt can add one without a parser change. Storage needed nothing new: the response column already held it.

THE FOUR-WAY SIGNAL, which is the part worth preserving. At session completion the health lines say which of these happened:

  declined some     -> "distill declines: 2 of 2 items (no-shared-mechanism 1, unstated 1)"
  declined none     -> "distill declines: none of 1 items"
  read failed       -> "distill declines: unavailable (store read failed)"
  no distill items  -> the line is ABSENT

So an absent line has EXACTLY ONE meaning: the session ran no distill work. It reached that state in three steps, and the intermediate states are the instructive part — first the line appeared only when something declined, so silence meant any of three things; then zero was stated, leaving two; then the failed read was named. A signal that cannot distinguish its cases is not yet an observability feature, and "it logs a warning" does not count because the log is not on the wire the agent reads.

RENDERING DETAIL THAT BITES: the zero case needs its own branch. Joining an empty per-reason breakdown prints `"distill declines: 0 of 9 items ()"`, so zero renders as `"none of N items"` with no parentheses. An item that declined WITHOUT a reason counts as `unstated` rather than being dropped — that item is precisely the case the field exists to surface.

WHAT THIS DOES NOT MEAN: no throttle is built on it and none should be without calibration. Prune has a resolution-rate throttle; this deliberately is not one. The purpose is visibility, and throttling an uncalibrated signal acts on noise. A parse failure skips its item rather than failing the session, per the failure-isolation convention: the mutations are already committed and a summary that errors is strictly worse than one that undercounts.

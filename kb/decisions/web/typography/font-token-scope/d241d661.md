# Web app routes all fonts through three --k-font-* tokens mirroring the marketing site

When bringing knomit.io's typefaces (Space Grotesk display, JetBrains Mono mono) into the knomit/web React KB app, three tradeoffs were resolved in conversation.

**Options considered**
1. Migration scope: (a) one token, no exceptions — migrate the 45 bare `fontFamily: 'monospace'` literals PLUS fold in Console.tsx's hardcoded `'JetBrains Mono, ...'` (8x) and `'Inter, ...'` literals and VersionBadge's reference to an undefined `--mono` token; (b) recipe-as-written — only the 45 bare literals, leaving Console/VersionBadge on their own idioms; (c) mono-only subset, skipping Space Grotesk.
2. Token naming: mirror the site's `--k-font-*` names vs. the recipe's `--font-*` names.
3. Display-font targets on headings.

**Rationale**
- Chose (a) one-token-no-exceptions: the originating recipe framed the work as 'replace the string monospace', which silently misses non-literal mono references — Console.tsx hardcoded JetBrains/Inter (fonts never loaded, so they fell back to ui-monospace) and VersionBadge's `var(--mono, monospace)` where `--mono` was never defined. Option (b) would ship three different ways to ask for mono. The real invariant is 'all mono text resolves through ONE token', not 'replace a literal string'.
- Chose `--k-font-*` naming to match knomit-io/src/styles/theme.css (`--k-font-mono`/`--k-font-display`/`--k-font-body`), reinforcing 'same product family'.
- Display font (Space Grotesk 600) applied ONLY to genuinely large heading-level type: the fact-detail title (RightPanel `data-testid=fact-title`) and StatBox figures (FactBody). Deliberately NOT applied to the uppercase tracked mono micro-labels (LIBRARY/TIMELINE) — those are an intentional mono-caps system where the LIBRARY header mirrors the history rail's TIMELINE header shape; Space Grotesk there would break that parallel and the site's own eyebrow/label convention.

**Constraint (hard)**: typeface-only. No fontSize, padding, gap, or lineHeight changed — the KB stays dense. The only size-adjacent additions were two recipe-sanctioned heading `letterSpacing` tweaks.

**The choice**: define `--k-font-mono` (JetBrains Mono), `--k-font-display` (Space Grotesk Variable), `--k-font-body` (system-ui stack) in web/src/index.css `:root`; load fonts via @fontsource at the app entry (main.tsx); route every font reference in src/ through one of these tokens or `inherit`.

**Verification corrected the recipe**: the recipe's step 7 claimed TopBar/FactBody tests assert on `fontFamily: 'monospace'` and would need updating — FALSE. No test asserts on font-family; all 360 tests passed untouched.

# The origin-session idle sweeper runs only while the manager holds a session; Shutdown and Server.SessionManager were removed, so session temp dirs are NOT cleaned on shutdown (known defect, follow-up pending)

Options were: start the cleanup goroutine in Mount (lives forever; one leaked goroutine per router a test builds), start it lazily with sync.Once on first Create (lives forever after), or tie it to a context (none exists at Server.Handler()). Chosen: the sweeper runs only while the manager holds at least one session. Create stores its session and THEN calls ensureSweeper, which starts the goroutine when none is running; cleanupLoop exits on the first tick (every cleanupInterval, 60 s) after which the map is empty. The exit check (stopIfEmpty) and the sweeping flag share sweepMu, so a concurrent Create is never left unswept. Expiry is unchanged (sessionExpiry, 10 min idle, checked every 60 s). A manager with no sessions owns no goroutine, so a dropped one leaks nothing.

The exported Shutdown and Server.SessionManager were removed in PR #624. CONSEQUENCE: a session still held when the process exits keeps its temp dir under os.TempDir() (knomit-origin-*); nothing cleans them on shutdown. Nothing in production called the old Shutdown either, so this is not a regression, but it is a KNOWN DEFECT, being fixed in a follow-up. DOES NOT MEAN: that sessions are cleaned on shutdown, or that removing Shutdown made them safe; only idle expiry (while the process runs) and replace-by-repo remove them.

Tests that create sessions point TMPDIR/TMP/TEMP at t.TempDir() (isolateOriginSessionTemp) or drain the manager (origins tests).

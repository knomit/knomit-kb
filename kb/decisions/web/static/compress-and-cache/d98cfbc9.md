# Remote-browsing slowness is fixed server-side with ONE shared compressor allowlist (hal+json and problem+json included) applied to both the API router and the SPA/asset mount, plus immutable caching for /assets/* and no-cache+ETag for the rest — not with brotli, precompressed bundles, or a frontend boot refactor

**Context (measured 2026-09-18 against 0.5.3.fd2640b7).** Browsing over Tailscale showed assets taking up to 8 s and 'Loading...' for seconds on section navigation. From the dev box every request completes in <40 ms, so the cost is bytes and hops, not server CPU. On the wire: vendor js 583,550 B, index js 334,042 B, react js 192,472 B, ~100 KB of API JSON at boot, motifs?path=kb alone 55,965 B — all uncompressed, none cacheable. Gzip would take the bundles to ~340 KB and the motifs call to ~6 KB.

**Two root causes.** (1) `middleware.Compress(5)` in `internal/web/router.go` is installed with no content types, so chi's default allowlist applies, and that list has `application/json` but NOT `application/hal+json` or `application/problem+json` — the only two types knomit's API emits. Compression has therefore been silently off for the whole API since hal+json became the content type, while the comment beside it and the hal-response-hard-rules convention both say it is mandatory. (2) The SPA and `/assets/*` are mounted on the OUTER router in `Server.Handler()` (`internal/web/server.go`), which carries only Recoverer and CORS, and `http.FileServer` over `embed.FS` sets no Cache-Control, no ETag and (zero modtime) no Last-Modified, so every load re-transfers ~1.25 MB and the browser cannot even revalidate.

**Options considered.** (a) One compressor helper with an explicit, complete allowlist, used at both mount sites, plus cache headers keyed on Vite's content-hashed filenames. (b) Build-time precompressed .gz/.br assets served by a custom file handler. (c) Brotli via `Compressor.SetEncoder`. (d) Frontend refactor to collapse the ~5 sequential boot hops (version/repos/lenses → repo/origin → branch → topics/stats/activity → motifs).

**Rationale.** (a) is one mechanism for API and assets, agrees by construction (one list, two call sites — the codebase convention), and with `immutable` caching the runtime gzip of the bundles happens once per client per build, so its CPU cost is irrelevant. (b) adds a second serving path and a build step for a saving that caching already delivers. (c) is ~50 KB more on a 340 KB cold load; marginal, revisit only if measured. (d) is real (~0.5 s at 100 ms RTT) but is a frontend change with its own risk and design — it is a FOLLOW-UP, not part of this fix.

**The choice.** Define `compressibleTypes` once in `internal/web` (text/html, text/css, text/plain, text/javascript, application/javascript, application/json, application/hal+json, application/problem+json, image/svg+xml) and a compressor helper used by BOTH `NewAPIRouter` and the static/SPA routes in `Server.Handler()` (via `r.With`/group — the API mount must not be double-wrapped). Passing types to chi's `Compress` REPLACES its defaults, which is why the list must be complete. `/assets/*` → `Cache-Control: public, max-age=31536000, immutable` (Vite content-hashes every name there). `/`, `/index.html`, `/config.js`, `/favicon.svg` and the SPA fallback → `Cache-Control: no-cache` plus a strong ETag equal to the quoted build identity that `/api/v1/version` already reports; `http.ServeContent` honours If-None-Match against a pre-set ETag and answers 304. Tests use `fstest.MapFS`, never the embedded dist (which is only `.gitkeep` without `make web`).

**Non-scope / what this does NOT mean.** `text/event-stream` must NEVER be added to the allowlist — SSE dies under compression (see the proxy-compression-stalls-streams gotcha). Already-compressed types (woff2, png) stay off the list. `no-cache` means revalidate-every-time, not do-not-store. The desktop `APIOnly` path never mounts the static handler and is untouched.

# Remote-browsing slowness is fixed server-side with ONE shared compressor allowlist (hal+json and problem+json included) applied to both the API router and the SPA/asset mount, plus immutable caching for /assets/* and no-cache+ETag for the rest — not with brotli, precompressed bundles, or a frontend boot refactor

**Context (measured 2026-09-18 against 0.5.3.fd2640b7).** Browsing over Tailscale showed assets taking up to 8 s and 'Loading...' for seconds on section navigation. From the dev box every request completes in <40 ms, so the cost is bytes and hops, not server CPU. On the wire: vendor js 583,550 B, index js 334,042 B, react js 192,472 B, ~100 KB of API JSON at boot, motifs?path=kb alone 55,965 B — all uncompressed, none cacheable. Gzip takes the bundles to ~340 KB and the motifs call to ~6 KB.

**Two root causes.** (1) `middleware.Compress(5)` in `internal/web/router.go` was installed with no content types, so chi's default allowlist applied, and that list has `application/json` but NOT `application/hal+json` or `application/problem+json` — the only two types knomit's API emits. Compression had been silently off for the whole API since hal+json became the content type, while the comment beside it and the hal-response-hard-rules convention both said it was mandatory. (2) The SPA and `/assets/*` were mounted on the OUTER router in `Server.Handler()` (`internal/web/server.go`), which carried only Recoverer and CORS, and `http.FileServer` over `embed.FS` set no Cache-Control, no ETag and (zero modtime) no Last-Modified, so every load re-transferred ~1.25 MB and the browser could not even revalidate.

**Options considered.** (a) One compressor helper with an explicit, complete allowlist, used at both mount sites, plus cache headers keyed on Vite's content-hashed filenames. (b) Build-time precompressed .gz/.br assets served by a custom file handler. (c) Brotli via `Compressor.SetEncoder`. (d) Frontend refactor to collapse the ~5 sequential boot hops (version/repos/lenses → repo/origin → branch → topics/stats/activity → motifs).

**Rationale.** (a) is one mechanism for API and assets, agrees by construction (one list, two call sites), and with `immutable` caching the runtime gzip of the bundles happens once per client per build, so its CPU cost is irrelevant. (b) adds a second serving path and a build step for a saving that caching already delivers. (c) is ~50 KB more on a 340 KB cold load; marginal, revisit only if measured. (d) is real (~0.5 s at 100 ms RTT) but a frontend change with its own design — a FOLLOW-UP.

**AS MERGED (PR #223, dev aa37eb35) — the review changed two parts of the original design; do not simplify back.**
- `compressibleTypes` in `internal/web/compress.go`, spelled from `hal.ContentType` and `hal.ProblemContentType` (exported for this) so the writers and the allowlist cannot drift, plus text/html, text/css, text/plain, text/javascript, application/javascript, application/json, image/svg+xml, AND `application/yaml` + `text/yaml` (review finding: openapi.yaml, 173 KB, sat uncompressed INSIDE the compressed router). chi matches the media type exactly after cutting at ";", so `text/yaml; charset=utf-8` matches the bare entry — pinned by a table test. `TestCompressibleTypes_CannotCoverSSE` asserts no entry is `text/event-stream` and none ends in `/*` (chi treats `family/*` as a wildcard, so `text/*` would sweep SSE in without naming it).
- `compressor()` is used by `NewAPIRouter` and by the static group in `Server.Handler()`; the API mount is not double-wrapped. `identityForRangeRequests` sits outermost in the static group and hides Accept-Encoding when `Range` is present (see the range-under-compression gotcha).
- `/assets/*` → `public, max-age=31536000, immutable`, stamped by `immutableWriter` ONLY on 200/304/206 (a year-long cached 404 on a hashed URL would outlive the deploy that fixed it). Directories under /assets/ 404 before any stamp (the bare listing enumerated every bundle name AND was cacheable for a year).
- Non-hashed files (`/`, index.html, config.js, favicon.svg, SPA fallback) → `no-cache` plus a strong ETag that is the **sha256 of the file's own bytes** (`etagger`), NOT the build identity as first designed: `version.String()` is "dev" for bare builds and the SHA does not move on dirty-tree rebuilds, so a build-keyed tag 304s onto a stale index whose bundles no longer exist (see the etag-from-build-identity gotcha). 304 comes from `http.ServeContent` against the pre-set tag, never hand-rolled.
- The SPA fallback no longer re-dispatches to `http.FileServer` (which 301s any path ending in index.html to "./" — a redirect loop for deep paths, dormant only because the UI has no client-side router); index.html is served via `http.ServeContent`. `StaticHandler()` is gone; build-tagged files expose `embeddedStaticFS() fs.FS` (nil under noembed) and the handler logic lives in untagged `static.go` with a `Server.staticFS` test seam.

**Non-scope / what this does NOT mean.** `text/event-stream` must NEVER be added to the allowlist. Already-compressed types (woff2, png) stay off. `no-cache` means revalidate-every-time, not do-not-store. The desktop `APIOnly` path never mounts the static handler. Still uncompressed and known: `/docs` (Swagger UI, 8 KB, registered outside the group); `HEAD /` returns 405 (pre-existing). Plan: .claude/plans/2026-09-18-remote-browsing-perf.md.

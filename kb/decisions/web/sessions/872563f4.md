# Activity reads a target's sessions filtered server-side by ?binding=repo:<uid>|lens:<uid> and shows only that target's binding groups; there is no unfiltered sessions reader

`useTargetSessions(target, showHidden)` calls `listClientSessions({binding, includeHidden})` with the repo's or lens's registry uid. A target with no uid reads nothing, because an empty binding would mean every session. It adds the 30s poll, a focus re-read and the change stream (one stream per mounted reader, closed on unmount).

`SessionsTable` trims each row's binding groups and handle list to `kind:uid` of the target, so a session also bound elsewhere shows only this target's line and count. The policy line is the table's last child and the table is a `minHeight: 0` flex column that scrolls inside. The counts and the truncation note live in the Activity toolbar.

There is NO unfiltered reader: the global sessions view went with Manage's Sessions tab (PR E), so a session bound to nothing is listed nowhere. That removal was accepted in the spec.

Consequence: the one-sessions-stream-per-tab rule holds by construction, because only the mounted Activity facet reads sessions and it closes its stream when the server pages open over it.

WHAT THIS DOES NOT MEAN: the filter is server-side. The client-side trim only removes the OTHER bindings of sessions the server already matched; it is not what scopes the list.

# The Sessions table groups a session's bindings into one line per target with a handle count and an expandable per-handle list, moves experiment attribution onto the target line as the top bar's flask chip, drops the Branch column, and remembers Show hidden in localStorage

## Context

A lens-mode bridge (local-agent-mode) presented 18 handles across two repos in one MCP session, and the Binding column rendered one line per handle (18 lines) while the Branch column was `—` on every row (see the 2026-09-22 screenshot dist/sessions.png). Designer asked for expandable rows, visual parity between experiments and ordinary branches, a persisted Show hidden, and then asked whether the always-empty Branch column should go.

## Options considered

1. **Group by target, expandable detail (chosen).** Collapsed: one line per distinct binding target (repo or lens) with `×N` handle count and a branch chip when every handle on that target writes to the same branch. A `N handles` chevron toggle opens a sub-row listing every handle: handle (short, full on hover), target, write branch, first seen, last seen, request count.
2. Keep one line per handle but cap at 3 and add `+15 more`. Rejected: still hides which targets are involved, and the per-handle first/last-seen and request counts the server already sends stay invisible.
3. Keep the Branch column and only style it. Rejected: its content is the bridge's SELF-DECLARED branch from the X-Knomit-Client header, which tools/bridge/main.go fills only in `--repo` mode; in lens mode and unscoped mode it is empty, i.e. every row in practice. When set it repeats the agent branch the binding already names. Its only live content was the `mounts` experiment attribution.

## Rationale

- Eighteen lines become two plus a toggle; the expanded view is a net GAIN of information (per-handle timings and counts were returned by the API and never rendered).
- Experiment attribution comes from `mounts`, which is per MOUNT, not per session — so it belongs beside the target it applies to, where two targets on one session can disagree, rather than in a session-wide column.
- Branch flare copies the top bar's branch button verbatim rather than inventing a vocabulary: GitBranchIcon in `#8af` on transparent for an ordinary branch; FlaskIcon in `#7c9` on `#11201a` with a `#2a4a3a` border for an experiment. Target glyphs are the top bar's BookIcon (repo, `#6a8`) and LayersIcon (lens, `LENS.accent`) — these mark the binding TARGET inside a row; the Sessions TAB itself keeps BroadcastIcon per kb/decisions/web/manage/server-pages-as-tabs.
- Show hidden persists under a `knomit.sessions.showHidden` localStorage key, read in the state initializer and written on change, both in try/catch, following repoSelection.ts's last-context pattern.

## The choice

Remove the Branch column and the `session-write-branch` cell; render the experiment (from `mounts`, joined to the binding target by uid) and the per-handle `branch` as chips on the target line; add a per-row expanded state (not persisted, per page load) revealing every handle; persist Show hidden.

## Non-scope

This does NOT remove `branch` from the wire format or the bridge header — the server and bridge are untouched; only the table stops showing the session-level field. It does NOT change the singular-binding fallback for a URL-scoped session that presented no handle. It does not say the top bar's chip styles must be extracted into a shared module; duplicating them is acceptable if extraction would touch TopBar.tsx.

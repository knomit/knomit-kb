# P1.2 design: Exists stays bool; ctx baked into readerRefResolver; embedder ctx reduced to EmbedDocuments

Design decisions for P1.2 context threading (see .claude/plans/2026-07-21-p1.2-context-threading-design.md): (1) FactReader.Exists and RefResolver.Exists keep their bool-only signature — defaultFactReader.Exists already swallows errors by design (handlers_fact_read.go:149-167, unknown collapses to ref kind 'broken'), and under cancellation the response is discarded anyway; the only required change is downgrading the error log to DEBUG when the error is context cancellation, or client disconnects spam ERROR logs. (2) ctx reaches RefResolver by baking it into the per-request readerRefResolver struct alongside ri/branch/commit — acceptable because the struct never outlives the handler invocation; BuildRefViews stays unchanged. (3) Boundary B is reduced form: ctx added ONLY to BatchEmbedder.EmbedDocuments (per-batch ctx.Err() check in the docBatchSize=32 loop); Embedder.EmbedQuery/EmbedDocument stay ctx-free because sess.Run (embedder.go:234) is not cancellable in the ort binding — full ripple deferred until a cancellable inference path or a remote embedder exists. (4) LLM boundary is a resilience decorator (retry/timeout/metrics), not ctx threading — ctx was already threaded; retry gated on 'nothing emitted yet' per the gemini cache-retry precedent; anthropic/bedrock get MaxRetries:0 because their SDKs retry internally.

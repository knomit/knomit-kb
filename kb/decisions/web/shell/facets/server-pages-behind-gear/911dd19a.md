# The server pages (Logs, Authorizations; Fleet left the gear in PR #528) are a view OVER the displayed target, not a target: the gear and any other route to a target leave them, and the target and facet underneath are never changed by opening or closing them

`ViewState.server` (web/src/facets.ts) is set by `TOGGLE_SERVER` (lands on Logs since PR #528; it was Fleet) and cleared by `TOGGLE_SERVER`, `SELECT_CONTEXT_TARGET`, `SELECT_PINNED`, `OPEN_DRAFT`, `SHOW_DRAFT` and `SET_FACET`. Nothing else in the view changes on the way in or out, which makes "the gear returns you to the target and facet you left" true by construction. It is not persisted.

While it is set the drafts stay mounted hidden, and since PR #799 so does the Settings facet when it is the facet underneath (repo/lens SettingsFacet, and the fleet's pages while on its Settings), wrapped in a div that is display:none under the pages and display:contents otherwise, so a credential picker's 'Access → Secrets' and the way back keep a half-filled connect wizard, credential box or restore prompt; Browse and Activity are unmounted (Activity's sessions stream closes). Consequence for tests: under the server pages a Settings element is hidden, not absent (not.toBeVisible, not toBeNull), and `browseShown` is false, so every browse key, Escape included, is a no-op: Escape does not leave the server pages, the gear does. Since PR H the rail is hidden too (see the rail-hidden decision).

The app's own corrections (the auto-unpin of a vanished pin, the repair of a broken lens) pass `keepServer: true`, so an automatic correction to the target underneath never closes the pages the reader chose.

Which tabs exist is `serverPagesFor(serverReadOnly)`: none on a read-only server, otherwise Logs and Access (Authorizations is a tab inside Access, shown only when the OAuth probe `useOAuthAvailability` saw an issuer). The tab bar shows `knomit | Logs Access`, no target crumb.

Consequence: a new route back to a target must clear `server` in the reducer, not in App, or the pages stay on top.

WHAT THIS DOES NOT MEAN: this is not "Manage moved to the top bar". There is no mode, no lock of its own and no Escape exit; the connect lock (`view.locked`) only disables the gear.

UPDATE (PR #528, verified at merge e417fd76): Fleet is no longer a server page. serverPagesFor gives Logs, plus Authorizations when there is an OAuth issuer; the fleet is a rail target (Members, Activity, Settings). FleetPage and ManageFleet.tsx are gone. The "view OVER the displayed target" rule is unchanged for Logs and Authorizations.

Update: the server pages are now Logs and Access. Authorizations is a tab inside Access (with Secrets), shown only with an OAuth issuer; serverPagesFor takes only the read-only flag. See kb/architecture/web/shell/server-pages/access/e55abbe4.md. The over-the-target rules above are unchanged.

Since PR #799 (re-review): what stays mounted under the server pages is display:none, which in a browser drops every scroll position inside it and the focus. App therefore takes a ReturnPoint (web/src/serverReturn.ts, takeReturnPoint(document, from?)) in the two handlers that open the pages from a target, onGear and the AccessSecretsLink `open(from)` of a credential picker. It records every element with a scrollTop/scrollLeft and, for the link, the link and its closest [data-return-focus] (the picker root). A useLayoutEffect on serverOpen puts it back when the pages close, scroll on elements still connected, focus on the link, else the picker's first control. App also counts closes (AccessSecretsLink.returns, a render-time 'adjust state on change' counter): the SecretPicker list, useRemote (a QUIET re-read: no loading state, so an open credential box is not unmounted, and errors keep the last origin) and FleetSettings' origin read re-read on it, so a secret renamed, replaced or deleted in Access shows on return. Consequence: a new way to OPEN the server pages from a target must take a ReturnPoint first (reading scrollTop after the commit is too late; it is already 0), and anything kept under the pages that shows Access-owned data should re-read on `returns`.

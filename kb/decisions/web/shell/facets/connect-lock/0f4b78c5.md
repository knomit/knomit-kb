# The connect-commit lock survives as view.locked: while a connect commit writes, the rail rows, the facet tabs and the gear refuse; command-B still works

RepoSettings runs the connect flow as a local sub-flow and relays the wizard's commit lock upward with a LAYOUT effect that calls `onBusyChange(true)` while busy and `false` in its cleanup, so the owner sees exactly [true, false] and an unmount mid-commit releases it. App maps it to `SET_LOCKED`.

While locked: TargetRail rows and `+` buttons are disabled and dimmed, TopBar tabs and the gear are disabled ("A remote is being connected - leave it running"), and `onSelectTarget` and the gear handler refuse. Command/Ctrl+B still toggles the rail, because hiding it unmounts nothing in the body.

Why: the commit stream has no abort and no undo; unmounting its page orphans it. The create needs no lock because its progress survives navigation.

Consequence: any new way off the Settings page must check `view.locked`.

WHAT THIS DOES NOT MEAN: the spec's "nothing needs locking" is about the create, not the connect.

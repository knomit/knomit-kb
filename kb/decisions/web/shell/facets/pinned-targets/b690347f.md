# Only storeless targets (archived, unavailable, a create not yet registered, a lens with a broken mount) are pinned over the browse context; normal targets ARE the context

A normal target (an available repo, a lens whose mounts all have stores) IS the browse context: picking it dispatches `SELECT_CONTEXT_TARGET` and its reads run. A target with no store to read is a `PinnedTarget` (`archived`, `pending` create, `unavailable` repo, `brokenLens`) shown OVER the context: `SELECT_PINNED` applies the facet rule with `['settings']`, and the context's reads keep running underneath, untouched. `SELECT_CONTEXT_TARGET` clears the pin.

App unpins automatically when the pinned thing vanishes (a deleted or restored target) by dispatching with `keepServer: true`, so a correction never takes the reader off the server pages. A repaired broken lens (no broken member left) becomes the context and the reader stays on its Settings. Archive-from-unavailable pins the archived row by the id the server returns. A pin is never persisted: a reload lands on the remembered context.

A broken lens is pinned rather than entered because a lens binds all its members or none, so every read under it answers 503 and a context switch would fire them; its Settings page re-reads the lens record, which is not a read through the lens.

WHAT THIS DOES NOT MEAN: a pin is not a context switch; picking a pinned row does not change `state.context`, the persisted context or the branch. A broken lens is never entered.

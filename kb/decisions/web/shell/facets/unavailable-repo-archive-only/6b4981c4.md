# An unavailable repo's Settings offers only what the server supports, which is Archive

Context (facets plan section 7, item 3, E2): the mock for an unavailable repo shows 'Check again', 'Locate store...' and 'Clone from remote'. None has a server operation: `Manager.openRegistered` checks only at boot, and the way out the corpus records is Archive.

Options: (1) ship the three buttons (they would do nothing or lie); (2) show the problem and offer only Archive, with a note; (3) build the server operations first (a separate feature).

Choice: (2), CONFIRMED by the user on 2026-10-12 ('ok'). `UnavailableSettings` has a Store section (the problem in words) and Archive in the Danger zone; E2's Description and Remote sections are omitted because their reads 409 for a storeless repo.

Revisit when the server gains check-again, locate or clone operations. WHAT THIS DOES NOT MEAN: it is not a promise that those operations will never exist.

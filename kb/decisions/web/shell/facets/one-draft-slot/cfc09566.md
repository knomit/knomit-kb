# There is one draft slot: opening the other kind of draft (repository or lens) discards the first

Context (PR E review, finding 8): the plan's view state has `draft: 'repo' | 'lens' | null`, a single slot, so clicking the lens `+` while a half-filled repository wizard is open replaces and unmounts the wizard's form.

Options: (1) one slot, as planned; (2) two slots, so a half-filled repo wizard survives a lens detour (and the reverse).

Choice: (1), left as built by the reviewer and master, CONFIRMED by the user on 2026-10-12 ('ok'). Rationale: the loss is small once the late-result bug is fixed (the repo create itself continues server-side and shows as a row), and two slots would double the hidden-but-mounted forms and the registration cases.

Consequence: `DRAFT_REGISTERED` carries its kind and retires only the draft of its own kind, because a repo create can finish after the lens draft took the slot (see the drafts decision). Source: PR E verdict, 'For the user' item 2, and the status card.

WHAT THIS DOES NOT MEAN: it does not discard a draft when the reader merely picks another rail row; the draft stays mounted and hidden. Only opening the OTHER kind's draft replaces it.

UPDATE (PR #528, verified at merge e417fd76): the slot is `'repo' | 'lens' | 'fleet' | null` (DraftKind gained 'fleet'); it is STILL one slot, so opening the New fleet wizard discards a half-filled repository or lens draft and the reverse.

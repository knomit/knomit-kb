# The Settings tab's remote-failure red dot shows only in a repo context, never for a lens

Context (PR D review, deviation 5): the facets spec says the Settings tab shows a red dot whenever the remote error is set (`remoteErrorText(state)`). A lens's Settings page has no Remote block for the dot to point at, and Reconnect from a lens switches to the write repo's Settings.

Options: (1) follow the spec's letter: dot whenever the error is set, in a lens context too; (2) dot only when the context is a repo, so the dot always points at a Remote block that exists.

Choice: (2), built by worker D, accepted by the reviewer and CONFIRMED by the user on 2026-10-12 ('ok'). `settingsDot = !state.serverReadOnly && state.context.kind === 'repo' && (remote error set || the current repo's listing remote is failing)`. Never under `serverReadOnly`.

Source: the PR D verdict, 'For the user', and the status card.

WHAT THIS DOES NOT MEAN: a lens context with a failing write-repo origin still has its failure visible in the app banner and on the rail; only the Settings-tab dot is suppressed.

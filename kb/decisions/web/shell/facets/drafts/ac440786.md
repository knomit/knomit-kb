# A + is a draft target kept mounted while hidden; Cancel restores returnTo; registration lands on Settings (repo) or Browse (lens) only if the draft was on screen

The rail's `+` opens a draft target (`OPEN_DRAFT`): a form, not a thing with pages (`facetsFor` gives it no tabs). The draft's body stays mounted while hidden, so picking another rail row keeps what was typed and any probe in flight; SHOW_DRAFT brings it back. Cancel (`CANCEL_DRAFT`) restores `returnTo`: the context, pin and facet shown before the draft opened.

Registration: the create's result lands the new target on Settings (a repo, creating mode) or Browse (a lens), but ONLY if the draft was on screen; registered while the reader was elsewhere, the draft row gives way to the real one and nobody is moved. `DRAFT_REGISTERED` carries its `kind` and retires only the draft of its own kind. The registration callbacks read the view AFTER the list refresh and do nothing when their draft has left the rail (a repo create finishing while the lens draft holds the slot must not clear or navigate it).

Zero repos is not a special screen: it is the repository draft as the fallback target, with no Cancel, and the rail is forced open for it.

WHAT THIS DOES NOT MEAN: there is one draft slot, not two; opening the other kind of draft discards the first (confirmed 2026-10-12, see kb/decisions/web/shell/facets/one-draft-slot/cfc09566.md). The server pages keep the draft mounted and hidden too.

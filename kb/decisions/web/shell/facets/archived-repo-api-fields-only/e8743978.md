# PROVISIONAL: an archived repo's Settings shows only what the archive API carries (date, origin, size, reason)

Context (facets plan section 7, item 4, E1): the mock for an archived repo shows store path, last commit and facts-at-archive, and an editable Description. `ArchivedRepo` carries only date, origin, size and reason, and the Description is not readable for an archived repo.

Options: (1) show only what the API carries; (2) extend the archive API (a server change outside the spec's intent that most bodies are existing components re-parented).

Choice: (1), PROVISIONAL. The user answered 'ok for now' on 2026-10-12, so more archive metadata may be added later. `ArchivedSettings` shows an Archived section and a Danger zone (Restore, and Purge with the typed name), Description omitted.

WHAT THIS DOES NOT MEAN: it is not a decision against showing store path, last commit or fact count; do not argue from this fact that they should not be shown.

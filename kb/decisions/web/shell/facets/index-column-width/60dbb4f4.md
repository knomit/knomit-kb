# The Settings index column is exactly the Library's width and shares its splitter handler, so the splitter sits at the same x on Browse and Settings

App provides `{ width: leftPanelWidth, onSplitterDown: startSplitterDrag }` through `FacetLayoutProvider` (web/src/facetLayout.ts). `FacetColumns` renders [left at that width | `FacetSplitter` | scrolling right column (`settings-scroll`)], and BrowseFacet uses the same `FacetSplitter`. Dragging either moves both (measured 682 to 742 on both). Outside the provider the index is 200px with no splitter.

Consequence: a new page with an index (Fleet, Authorizations, the drafts) must use FacetColumns, not its own grid.

WHAT THIS DOES NOT MEAN: the spec's "340px" is the Library's width, not a constant. The width is `leftPanelWidth` (default 35% of the window, persisted).

UPDATE 2026-10-29 (PR #678): this no longer holds for Settings. SettingsPage passes indexMaxWidth=240 to FacetColumns, so its index is capped at 240px, has no splitter while the cap applies, and its divider sits at a different x than Browse's. Browse and the other FacetColumns users still follow leftPanelWidth. See kb/decisions/web/ui/settings/nav-width-cap/e7bbf8b4.md.

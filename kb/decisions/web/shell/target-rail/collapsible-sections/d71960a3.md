# Rail sections collapse by clicking their header (variant C, user 2026-11-09): no chevron, a collapsed header shows a muted count and, for Chats, an amber dot for a hidden chat awaiting approval; Archived matches by losing its chevron

The user picked variant C of three mockups (A: chevron first, + last; B: chevron on hover; C: no chevron) on 2026-11-09 for collapsible sections in the target rail (web/src/TargetRail.tsx).

As built:
- Every section header (Chats, Repositories, Lenses, Fleet) is its own toggle: the section icon and title together are ONE button (data-testid rail-<section>-toggle) carrying aria-expanded. There is NO chevron. The `+` stays a separate button beside it and still asks for the draft.
- At rest the header looks exactly as before. Hover lightens the title to #d0d0d0 (open or collapsed); keyboard focus gets the app's ring (index.css button:focus-visible, 2px #4a7ab5).
- Collapsed: the title dims to #6a6a6a and is followed by a muted count of the rows the section holds (11px, #5a5a5a, tabular-nums). The count is EVERY row, not the shown ones: Chats counts all chats even past the five-row cap; Repositories counts listed repos plus pending creates, excluding the fleet repository and the archived ones; Fleet counts 1 or 0.
- Chats only: when Chats is collapsed and any of its chats is in rail state 'attention' (server state awaiting_approval), an amber dot (#e8c27a with a 2px rgba(232,194,122,.18) ring) follows the count. Its accessible name is the existing approved rail string RAIL_STATE_ATTENTION ('Waiting for your approval'); no new wording was added. No other rail state raises the dot.
- Archived (under Repositories) lost its chevron; it keeps its count, always shown, and still opens and closes in place with aria-expanded.

WHAT THIS DOES NOT MEAN: the count and the dot are not shown on an OPEN section, and the dot does not flag chats hidden behind 'N more' in an open Chats section.

# Collapsed rail sections: a search reveals matches only in the sections it filters (Repositories with Archived, and Lenses), leaving Chats and Fleet as they are; a draft row appearing by any route opens its section; the Chats N-more cap is unchanged

Rulings for the collapsible rail sections (2026-11-09), as built in web/src/TargetRail.tsx:

1. SEARCH: while the rail Search has text, a collapsed section shows its MATCHING rows only if the search filters that section's rows, which means Repositories (with Archived) and Lenses (SEARCH_FILTERED). rowsShown = !collapsed || (query non-empty && section in SEARCH_FILTERED). The header then reads expanded (aria-expanded true, no count). Clearing the search returns the section to collapsed. The search never writes the remembered collapsed state.
   Chats and Fleet are NOT filtered by the search and so have no matches. A search leaves a collapsed Chats or Fleet collapsed, with its count and (for Chats) its attention dot. An OPEN Chats still shows its rows unfiltered while searching. Chat title filtering was deliberately not added.
2. DRAFTS: when a draft row APPEARS in a collapsed section, by any route, that section opens and is stored open. Routes include the section's `+`, the zero-repo shell forcing the repository draft, and a chat draft opened elsewhere. The rule fires only on appearing (a false-to-true change of the section's draft flag, or a draft already present when the rail mounts), so the reader can collapse the section again while the draft stays. The `+` also opens its section directly before asking for the draft.
   Bug this fixed (reproduced 2026-11-09): with Repositories collapsed in storage and zero repos, the app forced the repository draft but the rail hid its row.
3. N MORE: RAIL_CHATS_SHOWN (5) and the 'N more' expander keep working inside an open Chats section. Collapsing hides the expander along with the rows.

WHAT THIS DOES NOT MEAN: a selected NON-draft target inside a collapsed section (a pinned chat, the context repo or lens) is NOT auto-revealed. That was left out of scope. A pinned archived repo still opens Archived, but not a collapsed Repositories.

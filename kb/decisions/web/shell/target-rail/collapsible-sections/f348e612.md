# Collapsed rail sections: a search with text shows a collapsed section's matches (clearing it re-collapses), a section's + opens it, and the Chats five-and-N-more cap is unchanged inside an open Chats

Three rulings made for the collapsible rail sections (2026-11-09), as built in web/src/TargetRail.tsx:

1. SEARCH: while the rail Search has text, every section shows its matching rows even when collapsed (rowsShown = !collapsed || query non-empty), and its header reads expanded (aria-expanded true, no count, no dot). Clearing the search returns the section to collapsed. The search never writes the remembered collapsed state. This is the rule Archived already followed (archivedRowsShown).
   Consequence for Chats and Fleet: their rows are NOT filtered by the search at all, so ANY search text shows every chat (up to the five-row cap plus 'N more') and the fleet row in a collapsed Chats/Fleet section.
2. PLUS: clicking a collapsed section's `+` opens that section (and remembers it open) before asking for the draft, so the new draft row is visible. On an open section the `+` changes nothing but the draft.
3. N MORE: RAIL_CHATS_SHOWN (5) and the 'N more' expander keep working inside an open Chats section; collapsing hides the expander with the rows.

WHAT THIS DOES NOT MEAN: a selected target inside a collapsed section is NOT auto-revealed (unlike a pinned archived repo, which still opens Archived); that was left out of scope.

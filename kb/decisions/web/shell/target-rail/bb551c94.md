# The target rail replaced the top-bar repo/lens dropdown: a pushing column, absent from the DOM when hidden, whose open state is UI chrome outside AppState

Repos and lenses are picked from `TargetRail` (web/src/TargetRail.tsx), a 236px column that App renders as the FIRST column of the body row, beside the page column. Showing it pushes the page right; it never overlays. Hidden means NOT RENDERED (absent from the DOM), not display:none.

The reader's preference is `ViewState.railOpen` (web/src/facets.ts), persisted as `knomit.rail` = '1'/'0' (`loadRailOpen`/`saveRailOpen` in repoSelection.ts); missing or any other value means closed. What is on screen is `railShown(view, noRepos)`: false over the server pages, otherwise the preference, forced open (not persisted) while there are no repositories. New code that shows or hides the rail reads `railShown`, never `view.railOpen`.

⌘B (or Ctrl+B) toggles it. ⌘K opens it AND focuses `rail-search` through a counter prop (`focusRequest`); the rail focuses once and reports back through `onFocusHandled`, so a later mount (toggle, ⌘B, leaving the server pages) does not steal focus again. Both keys are handled before the keyboard handler's input guard. Nothing closes the rail on Escape. A row pick dispatches the context change, is a no-op on the target already shown, blurs the search so page shortcuts work again, and leaves the rail open. Only targets that can be the browse context are picked as context; storeless targets are pinned (see the pinned-targets decision).

The state is deliberately NOT on AppState: AppState feeds navStack/NavEntry and the rail is not a way of looking at facts.

Consequence: code that needs the rail's DOM (a test, a focus call) must show it first and must not assume a hidden element exists.

WHAT THIS DOES NOT MEAN: "the rail is a menu" is wrong. It has no dismiss-on-pick and no dismiss-on-Escape, and adding either breaks the behaviour pinned in App.rail.test.tsx. It is also not true that the rail is "closed" over the server pages: it is hidden, and the preference is untouched.

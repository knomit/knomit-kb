# In a chat's top bar only the title gives way: it shrinks and ends in an ellipsis with the whole name in its title attribute, while the model name, the Chat/Settings tabs and the stats pill never shrink (chat review 2026-11-08, reversing 'the model name gives way first')

TopBar.tsx: the crumb's name span (target-label-name, barName) is flex 0 1 auto with min-width 0, overflow hidden, text-overflow ellipsis, nowrap, and title = the full name. The grey model name (k-bar-sub, barSub) has flexShrink 0; for a chat target the facet tab strip uses chatFacetTabs (flexShrink 0), and the stats pill wrapper (k-bar-pill) has flexShrink 0. Before this the sub had flexShrink 100 so the MODEL NAME gave way first; the user asked that the model name, tabs and stats stay whole and only a long title truncate.

Scope: desktop widths. At the phone breakpoint (App.css, max-width 640px) the earlier rules still apply: k-bar-sub and k-bar-pill are display:none and k-bar-label keeps min-width 96px, which is what stops the label collapsing now that a chat's two tabs do not shrink (see kb/gotchas/web/ui/top-bar-narrow/7691b179.md). A repo or lens target keeps the shrinking, scrolling tab strip (facetTabs, flexShrink 1). Does NOT mean the tabs never shrink anywhere: only a chat's do.

The same name span is the top bar's rename target: a double-click opens ChatTitleEdit in its place (kb/decisions/web/chat/titles/f1405441.md). Pinned by chatRail.test.tsx 'only the title gives way'.

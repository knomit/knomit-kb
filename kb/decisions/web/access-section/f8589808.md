# New Access UI section consolidates Authorizations with Secrets and later Connected accounts

Shipped in #729 (serverPagesFor and accessTabsFor in web/src/facets.ts, AccessPage.tsx; see kb/architecture/web/shell/server-pages/access/e55abbe4.md). Connected accounts is not built yet.

Choice: a new top-level Access section replaces the existing Authorizations entry (MCP client OAuth approvals) and hosts tabs: Secrets (always), Authorizations (only when the server has an [oauth] issuer, as today), and Connected accounts (added later in project 2).

Rationale: all three are 'what credentials does this instance hold or grant', so one home avoids scattering new top-level entries.

Non-scope: moving Authorizations does not change its behaviour or visibility rules.

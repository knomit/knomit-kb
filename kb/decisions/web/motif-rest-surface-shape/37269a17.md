# Motif REST surface is a dedicated paged /motifs collection + /motifs/{key} detail; pivot rides the existing search/facts filters — motifs stay OUT of /stats

Options considered: (A) dedicated paged `/motifs` collection plus `/motifs/{key}` detail, with pivot as `motifs`/`motif_match` params on the existing /search and /facts (repo and lens); (B) mirror domains exactly — motif histogram folded into /stats plus a /domains/{name}-style pivot endpoint; (C) one RPC-style endpoint with modes.

Rationale: /stats ships complete, unbounded histograms and the FacetPanel depends on that contract, while a motif vocabulary entry carries members + a definition — folding it in would bloat every summary load. The /domains/{name} pivot endpoint proved to be dead code client-side (the UI pivots via filter chips re-issuing /facts), so copying it would copy the unused half of the domain surface. Pivot-as-filter-param is how entity pivoting actually works today. Cluster-level pivot is the DEFAULT because the store's exact tier already resolves spellings through the alias table. Vocabulary default ranking is document frequency (df desc, canonical asc — the order store Clusters already returns); subject-spread and recency ranking were rejected for v1.

Choice: A, shipped on feat/motif-api (7 commits ending 7a0d2c31). URLs and self links key on cluster_key (stable); canonical is display-only.

Non-scope AS DECIDED AT THE TIME: this did NOT authorize a lens-level /motifs (vocabulary was per-repo only; lens motif FILTERING resolved per mount — no cross-mount cluster identity), did not add motifs to /stats, and did not include web UI wiring (FilterBar chips waited for the motif UI design).

**SUPERSEDED IN PART (recorded 2026-09-15).** Two of those three non-scope items were later done by separate decisions, and this fact must not be read as forbidding them: a lens-level motif surface now EXISTS (`/lenses/{lens}/motifs` and `/lenses/{lens}/motifs/{key}`, rendered by the same `renderMotifCollection` as the repo handlers) with a read-only cross-mount cluster identity — see kb/decisions/lens/motif/cross-mount-cluster-identity/1d35c7b0.md — and the web UI is wired through a single `MotifEndpoint` derivation — see kb/decisions/web/ui/motif/endpoint-not-context-branch/bbdb89e7.md. What still holds from this decision: the paged collection + detail shape, pivot as a filter param on /search and /facts, cluster_key as the stable identity, df ranking, and motifs staying OUT of /stats on both the repo and the lens surface.

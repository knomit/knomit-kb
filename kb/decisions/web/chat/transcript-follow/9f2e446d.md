# The chat transcript follows a streaming answer only while the reader is at the bottom (within 24px); a scroll up stops following and nothing moves the view until the reader returns by hand, the 'Jump to latest ↓' pill, End, a send, or the chat coming on screen

Decision (user picked it from a mockup, 2026-11-09). Before this, ChatPanel set `scrollTop = scrollHeight` on EVERY change to `state.turns` or `state.approvals`, unconditionally, so a reader who scrolled up during a streaming answer was pulled back to the bottom by the next delta.

The rule now, all of it:
- FOLLOWING (the start state) means: after each render that changes turns or approvals, and on any ResizeObserver growth of the transcript, ONE write per animation frame sets scrollTop to the bottom (rAF-coalesced, so many deltas in one frame cost one write).
- A scroll event whose scrollTop DECREASED (by more than 1px) while the bottom is more than FOLLOW_SLACK_PX = 24px away stops following. Nothing else stops it.
- While not following, no code writes scrollTop: new output is appended below and the text being read does not move. Native scroll anchoring is left on (default `overflow-anchor`); measured in Chrome it kept a paragraph at the same viewport top (229.8px) for 5.6s while the page grew 1581 -> 1901px.
- While not following, a pill `Jump to latest ↓` floats centred over the bottom of the transcript, just above the composer; it shows whether or not a turn is streaming and hides as soon as following resumes. Style: the composer's raised surface (#171717) and 1px #2e2e2e edge, radius 999, 13px, shadow 0 4px 12px rgba(0,0,0,0.5); focus ring is the global `button:focus-visible` (not `.k-bare`, whose :focus-visible sets border-radius 4px and would square the pill).
- Following resumes when: the reader scrolls back to within 24px of the bottom; clicks the pill (smooth scroll, instant under prefers-reduced-motion); presses End with focus on the body or inside the chat column and NOT in a textarea/input/select/contenteditable (the composer keeps its own End; focus in the side panel or elsewhere is left alone); sends (submit, Retry, Continue all go through `send`, which jumps instantly); or the chat comes on screen (`onScreen` false -> true, which also covers returning from the Settings tab).

Consequence: never reintroduce an unconditional scroll-to-bottom in a render effect; route any new 'jump to the newest' through jumpToLatest so the follow flag and the pill stay in step.

Not meant: this is not 'any scroll event away from the bottom stops following'. See the companion gotcha for why only a decrease counts.

# A chat tool result (every non-materialize Result, and the Arguments tab) renders in JsonView, a read-only CodeMirror 6 view: parsed JSON pretty-printed at 2 spaces, anything else plain text in the same view, errors in #e0a0a0 unhighlighted (user-approved design, 2026-11-09)

ChatResultPanel shows a call's Result (when it is not a successful knomit_materialize, which stays markdown) and its Arguments in JsonView (web/src/JsonView.tsx). jsonViewText.resultText(raw) JSON.parses the result: if it parses, the view gets JSON.stringify(unpackJson(value), null, 2) with JSON highlighting and folding (json: true); if not, it gets the raw text unchanged, with no language, no fold gutter and no highlighting (json: false). The Arguments tab gets jsonText(call.arguments): the arguments are already a value, so nothing is parsed; they are unpacked and pretty-printed the same way (json: true). Every step is guarded (review fixes, PR #819), so a structure deep enough to overflow the stack (a 20000-deep array) never crashes the panel: resultText falls back to the raw result as plain text; jsonText falls back, in order, to compact JSON.stringify(v), then String(v), then an empty view, each as plain text (json: false). String(v) is guarded too because it recurses through nested arrays and overflowed on node 22's smaller stack. On the Result tab a failed call (is_error) is drawn in #e0a0a0 with highlighting off, whether or not its text parses, and the host div carries data-error; the Arguments tab of a failed call is not in the error tone.

The view is EditorState.readOnly but still contenteditable (EditorView.editable stays true): that is what keeps keyboard selection, Mod-F and copy (CodeMirror's copy handler copies state.sliceDoc, so a copy across a folded block yields the folded text, not the pill). It has no line numbers, no active line, EditorView.lineWrapping, drawSelection, and no default keymap (only Mod-F). Colours come from codePalette.ts.

Consequence: a result that is JSON FOLLOWED by other text (e.g. JSON then markdown) does not parse as a whole, so it renders as plain text, unhighlighted and unfolded; that is the approved behaviour, not a bug. Misreading to avoid: 'read only' does not mean editable=false; turning editable off breaks focus, Mod-F and the find bar.

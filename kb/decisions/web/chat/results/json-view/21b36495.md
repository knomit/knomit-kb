# JSON view folding: blocks at depth >= 3 (outermost container is depth 0) start folded behind an 'N keys' / 'N items' pill drawn like a fact chip; the fold mark is the chat's own › (#555, 11px) turned 90deg when open (user-approved, 2026-11-09)

jsonViewText.initialFolds(text) lists multi-line blocks with depth >= FOLD_DEPTH (3), skipping blocks inside one already folded, and JsonView dispatches a foldEffect for each when the view is built. Ranges are just inside the brackets (after '{' to the '}'), the same ranges lang-json's fold service gives, so the gutter and the initial folds agree. The pill's label is foldLabel(): the count of entries at the block's own level, worded by chatCopy.foldedCount ('1 key', '3 keys', '1 item', '2 items'); a click on the pill unfolds it (CodeMirror's placeholder onclick). The pill uses the .k-fact-link colours (#161a21 ground, #263041 border, hover #1b2332/#4f6a96). The gutter mark is a span '›' (class k-json-fold, data-open), the same glyph ChatToolGroup's group header uses.

Consequence: changing the depth means FOLD_DEPTH plus the tests that pin it (jsonViewText.test, JsonView.test). The initial fold is computed from the text, not the syntax tree, so it does not wait for the parser. Plain-text results never fold.

# A chat's tool results are fetched lazily when a row is selected, and a materialize result renders as a fact in the result panel on the right; no result panel exists until a row is selected

The SSE tool_call event and the GET /chats/{id} transcript carry no tool RESULT (the server keeps it in a temp call file). ChatFacet therefore fetches GET /chats/{id}/calls/{callId} only when a finished row is selected (ChatResultPanel mounts on selection and fetches in its effect); opening a tool group, or merely loading the transcript, fetches nothing, and a running call's row is disabled because its call file does not exist yet. The panel sits in FacetColumns' right slot (where Browse's single fact sits) and is absent until a row is selected; selecting the same row again closes it with no second fetch. A knomit_materialize result that is not an error is rendered as markdown in a 'k-prose' block (materializedMarkdown: its JSON 'text' when that is a string, else its 'facts' titles and bodies joined; the anchor lines a document carries are dropped; text that is not JSON is shown as it came); any other result, and a materialize error, is shown as plain text in a pre block, errors in the error tone. The call's arguments are listed under the result when it has any. The chat panel (left) never contains a result.

Why: results can be large; the design requires that they not bloat the page. Consequence: do not prefetch results (for example when a call turns 'done'), and do not render results in the chat panel.

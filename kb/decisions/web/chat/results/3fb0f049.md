# A chat's tool results are fetched lazily when a row is selected, and a materialize result renders as a fact in the result panel on the right; no result panel exists until a row is selected

The SSE tool_call event and the GET /chats/{id} transcript carry no tool RESULT (the server keeps it in a temp call file). ChatFacet therefore fetches GET /chats/{id}/calls/{callId} only when a finished row is selected (ChatResultPanel mounts on selection and fetches in its effect); opening a tool group, or merely loading the transcript, fetches nothing, and a running call's row is disabled because its call file does not exist yet. The panel sits in FacetColumns' right slot (where Browse's single fact sits) and is absent until a row is selected; selecting the same row again closes it with no second fetch. A knomit_materialize result that is not an error is rendered as markdown in a 'k-prose' block (its JSON 'text' for audience agent, or its 'facts' titles and bodies for audience human); any other result is shown as plain text, errors in the error tone. The chat panel (left) never contains a result.

Why: results can be large; the design requires that they not bloat the page. Consequence: do not prefetch results (for example when a call turns 'done'), and do not render results in the chat panel. The materialize JSON shape was written from the tool's description, not observed live; the milestone's live run confirms it.

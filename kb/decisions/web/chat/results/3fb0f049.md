# A chat's tool results are fetched lazily, only when a finished row is selected, and shown in the chat side panel (ChatSidePanel), which holds one entry at a time; with nothing selected there is no side panel, and a materialize result renders as markdown

The SSE tool_call event and the GET /chats/{id} transcript carry no tool RESULT (the server keeps it in a temp call file). So the page fetches GET /chats/{id}/calls/{callId} only when a finished row is selected:
- A row's button is enabled only once its call is `done` (ChatToolGroup, `canOpen`). A running call's row is disabled because its call file does not exist yet.
- Selecting a row dispatches `open` with a `result` entry (ChatFacet's onSelect). ChatSidePanel then mounts ChatResultPanel, which fetches in its effect. Selecting the same row again dispatches `close`, with no second fetch.
- Opening a tool group, or merely loading the transcript, fetches nothing.

**Where it shows.** The result is one of three kinds of entry in the chat's side panel (ChatSidePanel, on the right of the chat column, 470px by default and resizable): a tool result, a fact, or a commit (chatPanelState's PanelEntry). The panel holds ONE entry at a time, with no back stack: opening a fact link or a commit chip replaces the result, and the reader reselects the row to see it again. ChatFacet renders the side panel only while an entry is open, so with nothing selected there is no panel and the chat column takes the width. A result entry gets a header with a breadcrumb (the repo and the path's directories when the call names a file, else the repo and the row's label) and the close button.

**How it renders.** ChatResultPanel is headed by the call's own timeline row (ToolCallHead) and has two tabs, Result and Arguments. On Result, a knomit_materialize result that is not an error is rendered as markdown in a 'k-prose' block (materializedMarkdown: its JSON `text` when that is a string, else its `facts` titles and bodies joined; anchor lines are dropped; text that is not JSON is shown as it came). Any other result, and a materialize error, is plain text in a pre block, errors in the error tone. The Arguments tab shows the call's arguments as JSON. The chat column itself never contains a result.

Why: results can be large, and the design requires that they not bloat the page. **Consequence:** do not prefetch results (for example when a call turns `done`), and do not render results in the chat column. A new way to open a result should dispatch a `result` entry into the same panel, not draw its own.

**What this does NOT mean:** not that a result fetched once is cached. Reopening a row remounts ChatResultPanel and fetches again; only reselecting the row that is already open avoids a fetch, because it closes the panel.

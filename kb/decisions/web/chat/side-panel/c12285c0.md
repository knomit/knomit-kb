# Esc in a chat: while a turn runs it is Stop and never closes the side panel; with no turn running it closes the panel unless focus is in a text field

Two window-level keydown listeners both see Escape in a chat: ChatPanel's (PR 2: Stop, only while state.running) and ChatSidePanel's (mounted only while the panel is open). The panel's listener reads the chat's `running` and returns early when a turn runs, AND ChatPanel calls preventDefault when its Esc was Stop, which the panel's listener honours. Both are needed: a browser runs microtasks between listeners, so React has already rendered running:false by the time the panel's listener runs, and without the mark the one key both stopped the turn and closed the panel. jsdom does not run them there, so only a real browser shows this. Stop always wins and the panel stays open. The panel's materialize Focus takes Esc in the capture phase, ahead of both (kb/gotchas/web/ui/materialize-focus/3fedfce6.md), and yields it while a turn runs (MatFocusScope.yieldsEsc): Focus stays on and the key is Stop. With no turn running in Focus, the first Esc leaves Focus and the next closes the panel. The chat column is folded rather than undisplayed in Focus, because ChatPanel reads display to know its chat is on screen. ChatPanel treats the side panel as part of the chat: its focus test is against the nearest [data-chat-scope] element (ChatFacet's chat-columns row, holding the column AND the panel), so Esc while a turn runs with focus on a panel tab or button is Stop too (before this, focus inside the panel made Esc do nothing). With no turn running, Esc closes the panel unless document.activeElement is a TEXTAREA, INPUT, SELECT or contentEditable (the composer), where Esc does nothing. A chat that is not on screen (Settings tab, display:none ancestor) ignores both. The panel has no history, so Cmd+[ does nothing there (kb/decisions/ui/chat/panel-browse-chrome/64aa3076.md). App.tsx's own Escape (CLEAR_FILTERS / return-to-now) and Cmd+[ (NAV_BACK) are gated by browseShown, so they never run over a chat. Consequence: a person who wants to close the panel during a running turn must stop it first (one Esc), then Esc again. Does NOT mean Esc is swallowed: after the turn ends the same key closes the panel. A dialog that listens on window without preventDefault is invisible to both listeners.

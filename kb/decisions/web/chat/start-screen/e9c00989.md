# The chat start screen's composer (Start chat, Cancel) is a flex:none sibling BELOW the scrolling card grid, never inside it; Cancel sits left of Start chat in the composer's action row; there are no suggestion chips

Ruling (2026-11-06): the person never scrolls to reach Start chat. ChatStartForm is a flex column: data-testid chat-start-scroll (flex 1, overflowY auto, holds the heading and every provider's cards) and, as its SIBLING, chat-start-dock (flex none, holds the composer, the error line, Cancel and Start chat). Moving the composer back inside the scroller, or giving the form a single overflow:auto root, brings back the scroll-to-reach bug on any screen with more cards than fit (4+ local models on a 813px viewport is enough). Cancel (when the caller passes onCancel) is in the composer row, before Start chat; the chips and their SUGGEST_* copy were deleted, and with them the repoNames prop. Does NOT mean the dock overlays the grid: it is docked, so the scroller simply ends above it. Guarded by the jsdom test 'docks the composer' (scroller does not contain the dock; Start chat, input and Cancel are in the dock).

# Chat approval card is style B1: one grey card for every approval; a destructive one is marked ONLY by its action word in amber; the three answers are one line of text links (Allow green) split by aria-hidden muted dots

Chat review, 2026-11-09: the user picked option 'B1' from a mockup for ChatToolGroup's ApprovalCard.

- Card: always background #1a1a1a, border 1px solid #2a2a2a — destructive or not. The red ground/border (#2b1c1c / #5c2a2a) for destructive approvals is gone. data-destructive stays on the card.
- Destructive marker: the action word (data-testid chat-approval-action) is drawn AMBER (#e8c27a, the file's AMBER constant) when destructive, #ccc otherwise. Nothing else marks it.
- Answers: a row (data-testid chat-approval-answers) of <button>s with class .k-approval-answer (App.css): no border, no ground, padding 1px 5px, radius 3px, colour #8a8a8a; Allow adds .k-approval-answer--allow (#9fd4b4). Hover: colour #e2e2e2 on #232323. Keyboard focus: the app's ring (2px solid #4a7ab5, offset 2px) on :focus-visible only. Between answers an aria-hidden '·' in #444. Order and words unchanged: Allow · Decline · Allow for session (the last only when grantable). Test ids unchanged.
- Arguments unchanged: the 120px scrolling pre.

Consequence: the hover and focus live in App.css because inline styles cannot express :hover; do not move the answers back to inline style objects. What this does NOT mean: destructive approvals are not treated differently in behaviour — Allow for session is still offered only when the server says grantable.

# The chat page says No response yet only after the slowest first-reply time this server run has seen for the model (expected_first_token_ms); with none observed it never says it, and there is no fixed constant

The manager records, per provider and model, the slowest time from a turn's acceptance (startTurn) to its first sign of life (reasoning delta, text delta, reasoning, or tool call). It is exposed as expected_first_token_ms on the chat snapshot and on each model in GET /chat-providers; absent until one reply has been observed, and in-memory only (it resets with the server). The placeholder compares elapsed time since acceptance (strictly greater than) with the snapshot's value. Consequence: the first turn of a model in a fresh server never shows No response yet, and a cold Ollama load that was slow once raises the bar for later turns.

This replaces the design's fixed 30s. Master's design for it; the value is a MAX, so one outlier stays until restart.

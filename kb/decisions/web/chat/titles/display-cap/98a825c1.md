# A chat's title is DISPLAYED capped at 20 characters (graphemes) + '…' at a word boundary in BOTH the rail's CHATS row and the top bar, via one helper chatTitleShown (utils.ts, CHAT_TITLE_SHOWN = 20) — the user's choice on 2026-11-09, lowered from 24; the stored title (server titleOf, 300 runes) is unchanged

Chat review, 2026-11-09. The top bar showed a chat's whole title while the rail row showed what its CSS ellipsis allowed, so a long first message ran across the bar. The user picked one character cap for both places: first 24, then lowered to 20 the same day, because at the rail's 236px width a 24-character cut ("I am wondering what the…", ~163px at 13px) did not fit the row's ~149px title box and the rail's CSS ellipsis cut it again, so the two places showed different text.

chatTitleShown(title) in web/src/utils.ts:
- counts GRAPHEMES (Intl.Segmenter, granularity 'grapheme'), never code points or UTF-16 units, so what a reader sees as one character is never split: a ZWJ-joined family emoji, a flag (two regional indicators), a letter with a separate combining accent. (It counted code points until the #815 review reproduced all three broken.) Intl.Segmenter needs Safari 14.1+ / Chromium, which the desktop webviews meet;
- 20 characters or fewer: returned unchanged;
- longer: cut at the last word boundary within the first 20 (all 20 when the 21st character is whitespace); a first word longer than 20 is hard-cut at 20; trailing whitespace and punctuation are trimmed; then '…'.
Applied over the same `title || name || model` choice: ChatRailRow's title span, and TopBar's target-label-name for chat targets only (repo/lens/fleet labels are not capped).

Unchanged: the server's titleOf (300 runes) and the stored title; rename edits the whole title; the rail's hover tooltip and the top bar's title attribute still hold it whole; the CSS ellipsis on both stays as the narrow-width fallback; the model name and the Chat/Settings tabs never shrink.

Measured at 20 (Chromium, 2026-11-09): 'I am wondering what…' needs 149px in a 149px rail title box and 139px in the top bar, so neither is CSS-cut and both show the same visible text. The fit has no spare width: a 20-character title of wider glyphs (capitals, W/M) can still be cut further by the rail's CSS ellipsis. What this does NOT mean: the cap is not a storage or API limit.

Tests: utils.test.ts 'chatTitleShown'; App.facets.test.tsx 'a long title is the same capped string in the rail row and the top bar'.

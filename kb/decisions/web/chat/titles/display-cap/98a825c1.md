# A chat's title is DISPLAYED capped at 24 characters + '…' (word boundary, code points) in BOTH the rail's CHATS row and the top bar, via one helper chatTitleShown (utils.ts, CHAT_TITLE_SHOWN = 24) — the user's choice on 2026-11-09; the stored title (server titleOf, 300 runes) is unchanged

Chat review, 2026-11-09. The top bar showed a chat's whole title while the rail row showed what its CSS ellipsis allowed, so a long first message ran across the bar. The user picked option 3: one character cap for both places.

chatTitleShown(title) in web/src/utils.ts:
- counts code points (Array.from), never UTF-16 units, so an emoji is never split;
- 24 characters or fewer: returned unchanged;
- longer: cut at the last word boundary within the first 24 (all 24 when the 25th character is whitespace); a first word longer than 24 is hard-cut at 24; trailing whitespace and punctuation are trimmed; then '…'.
Applied over the same `title || name || model` choice: ChatRailRow's title span, and TopBar's target-label-name for chat targets only (repo/lens/fleet labels are not capped).

Unchanged: the server's titleOf (300 runes) and the stored title; rename edits the whole title; the rail's hover tooltip and the top bar's title attribute still hold it whole; the CSS ellipsis on both stays as the narrow-width fallback; the model name and the Chat/Settings tabs never shrink.

Known consequence (measured 2026-11-09 in Chromium): at the rail's 236px width the row's title box is about 149px, so a 24-character cut at 13px (about 163px) is still trimmed further by the rail's CSS ellipsis; the DOM strings are identical, the visible rail text can be shorter than the top bar's. What this does NOT mean: the cap is not a storage or API limit.

Tests: utils.test.ts 'chatTitleShown'; App.facets.test.tsx 'a long title is the same capped string in the rail row and the top bar'.

# A chat's title is auto-written once by its own model after the first completed turn AND can be renamed by the person (PATCH /chats/{id}); the user chose auto-title + rename over rename-only and over auto-only, and a person's title is never overwritten

User decision (chat review, 2026-11-08). Options considered: (a) rename only, the first message stays the name until the person changes it; (b) auto-title only, the model names every chat and the person cannot; (c) auto-title plus rename. The user chose (c).

How it works (internal/edge/web/api/chat/title.go):
- Auto: after a chat's FIRST COMPLETED turn (finishTurn with no error calls maybeAutoTitle), the chat's OWN configured model is asked ONCE for a 3-6 word title, from the turn's user message plus the answer's text (cut to 2000 runes) followed by titlePrompt as the last user message. No tools, no system prompt, StreamOptions{MaxOutput: 32, NoThinking: true}. A usable answer (cleanTitle: first non-empty line, quotes and a closing full stop trimmed, at most 12 words and 100 runes) replaces the first-message name. A failed call, a cut-off one or an unusable answer keeps the first-message name. titleTried makes it once per chat: there is NO retry on a later turn.
- Rename: PATCH /chats/{id} {"title"} (an extension of the existing chat route family, not a new one) sets the title through titleOf (whitespace collapsed, 300-rune cap) and sets userTitled. Empty, blank or missing title is 400.
- Never overwrite the person: maybeAutoTitle skips a user-titled chat, and autoTitle re-checks userTitled under the lock before applying, so a rename that lands while the request is in flight wins.
- Cost: the request's usage (also from a StopError's partial response) is priced by the chat's price card and added to the view item of the turn it followed (addSideUsage), where every request's cost is summed, so rowState.cost_usd and the page's sessionCost include it. It is announced as a usage event with side: true; the page adds it to the turn but does not take its prompt for the context meter.
- Storage and live update: the title lives on the chat (c.title, server side), is written to the persistent session log as a "title" record (source auto|user), and goes out through chat_state, the existing rail-row event, which the rail and the top bar both read.

Consequences: do NOT add a second title source or a client-side title; do NOT retry the auto call; a chat's title can now differ from its first message, so code that assumed rowState.title == titleOf(first message) after the first turn is wrong. Does NOT mean every chat gets a model title: a failed or unusable answer leaves the first-message name for good.

The chat package had no existing side-call helper; title.go's titleStreamer (a manager seam, default: the chat's own loop model) is the first. The test harness turns auto-title OFF by default (a failing titleStream), because the extra request would take a step a test scripted for its next turn; title_test.go turns it on.

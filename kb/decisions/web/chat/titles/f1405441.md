# A chat's title is auto-written once by its own model after the THIRD completed turn AND can be renamed by the person (PATCH /chats/{id}); the user chose auto-title + rename over rename-only and over titling after the first turn, and a person's title is never overwritten

User decision (chat review, 2026-11-08). Options considered: (a) rename only, the first message stays the name until the person changes it: rejected, a chat that is never renamed is named by its setup line; (b) auto-title after the FIRST completed turn: built first, then rejected by the user, because people typically bind first ("bind to X") and only then start the real work, so after one turn there is nothing to infer the subject from; (c) auto-title after the THIRD completed turn plus rename. The user chose (c). (Auto-only, with no rename, was never on the table.) The title prompt text (titlePrompt) was approved by the user verbatim.

How it works (internal/edge/web/api/chat/title.go):
- Auto: finishTurn calls maybeAutoTitle only for a turn that finished NORMALLY (no error); maybeAutoTitle counts them (turnsDone) and, at the third (titleAfterTurns = 3), asks the chat's OWN configured model ONCE for a 3-6 word title. A turn that errored or that the person stopped does NOT count. A chat with fewer than three completed turns never gets an auto-title and keeps its first-message name until renamed. The request carries the conversation up to and including the triggering turn: every user message (failed and stopped turns' too), each cut to 600 runes and placed first, then each turn's assistant text in what is left of a 4000-rune total (titleContextRunes, titleMessageRunes), then titlePrompt as the last user message. No tools, no system prompt, StreamOptions{MaxOutput: 32, NoThinking: true}. A usable answer (cleanTitle: first non-empty line, quotes and a closing full stop trimmed, at most 12 words and 100 runes) replaces the first-message name; an answer cut off at the budget counts when its first line was finished (firstLineEnded). A failed call, one cut mid-line, or an unusable answer keeps the first-message name. titleTried makes it once per chat: there is NO retry on a later turn.
- Rename: PATCH /chats/{id} {"title"} (an extension of the existing chat route family, not a new one) sets the title through titleOf (whitespace collapsed, 300-rune cap) and sets userTitled. Empty, blank or missing title is 400.
- Never overwrite the person: maybeAutoTitle skips a user-titled chat, and autoTitle re-checks userTitled under the lock before applying, so a rename that lands while the request is in flight wins.
- Cost: the request's usage (also from a StopError's partial response) is priced by the chat's price card and added to the view item of the turn that triggered it (the third completed one; addSideUsage), where every request's cost is summed, so rowState.cost_usd and the page's sessionCost include it. It is announced as a usage event with side: true; the page adds it to the turn but does not take its prompt for the context meter.
- Storage and live update: the title lives on the chat (c.title, server side), is written to the persistent session log as a "title" record (source auto|user), and goes out through chat_state, the existing rail-row event, which the rail and the top bar both read.

Consequences: do NOT add a second title source or a client-side title; do NOT retry the auto call; do NOT move it back to the first turn (the reason above). A chat's title can differ from its first message after three completed turns, so code that assumed rowState.title == titleOf(first message) is wrong for such chats. Does NOT mean every chat gets a model title: a short chat, a failed or an unusable answer leaves the first-message name for good.

The chat package had no existing side-call helper; title.go's titleStreamer (a manager seam, default: the chat's own loop model) is the first. The test harness turns auto-title OFF by default (a failing titleStream), because the extra request would take a step a test scripted for its next turn; title_test.go turns it on.

RENAME EDITOR (web, as merged): ChatTitleEdit.tsx is the one inline editor, used by the rail row (ChatRailRow) and the top bar's crumb (TopBar). A double-click on the name opens it with the name selected; Enter or blur saves, Esc cancels, an empty or unchanged name saves nothing. onDone is called exactly once (a done ref), with the new name or null. Taken off screen without Enter, Esc or blur (another chat was opened) it is CANCELLED and a late blur cannot save it; the top bar therefore holds the id of the chat being renamed, not a boolean, so showing another chat ends the edit cancelled (a rail click does not blur the input). React StrictMode (dev) mounts, cleans up and mounts effects again, so the editor's effect sets done.current = false at the START of every run: without that reset the first cleanup's done.current = true leaves the live editor dead (Enter and blur do nothing). Do not move the reset out of the effect start. Pinned by ChatTitleEdit.test.tsx.

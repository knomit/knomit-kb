# The chat cost card's per-row dollars are computed on the server per request, because the tier is chosen per request and the page only holds turn sums; this supersedes the earlier 'per-row cost is not shown' decision

PriceCard.Estimate (internal/engine/llm/agent.go) returns Cost{USD, Rows, High}: Rows is input, cache read, cache write (5m, 1h and unsplit writes each at their own multiplier) and output in USD, and USD is exactly their sum. The price tier is chosen PER REQUEST on that request's whole prompt (input + cache read + cache write), but the page only holds a turn's summed tokens, so pricing the sums in the browser would pick the wrong tier for a multi-request turn whose requests are each under the boundary but whose sum is over it. So the server sums the rows per turn (view item cost_rows, usage event cost_rows) and flags high_tier when ANY request fell in the higher tier; the page does no pricing. The card header 'Turn N · <model> · tier ≤100K' takes the boundary from GET /chats/{id}/context tier_tokens (the price card's first-tier boundary, absent with one tier or no card) and the model name from chat.name || chat.model; a turn with high_tier reads '>' instead of '≤' (new wording, flagged for the designer). Consequence: never reprice a turn in the page from usage sums. Does NOT mean the rows are shown rounded-to-sum: each row is formatCost'ed on its own, so displayed rows can differ from the displayed total in the last digit; the underlying values add up exactly.

# FactSet links show a short title, not a number (user, 2026-11-02, replaces Q-UI7): every link stub, forward and back, reads "see <short title>"; back links carry only their first-writing unit; a click scrolls or seeks to link.unit

QUESTION: Q-UI7 (factset-ui-plan) had back links show the target's section number and seek on click, with a server task adding unit + number to back links, assumed cheap since #702 records the first appearance per fact. Building it showed the first-writing UNIT is recorded but the NUMBER is not (gotcha kb/gotchas/materialize/factset/back-links/9086db9c.md).

OPTIONS:
(a) store the first writer's ordinal beside its unit and look the number up per page through planUnitOf (a re-plan of each distinct earlier unit not in the kept-plan LRU);
(b) store the number string per written fact (memory against session.factset_memory_mib);
(c) back links carry the unit only, and the UI shows a number once the target has been loaded after the click;
(d) no numbers on links at all: every stub shows "see" and a very short form of the target's title.

CHOICE: (d). RATIONALE: the user's words, "see" plus a shortened title, and "Users really do not care about the numbers"; and the back-link number was not stored, so (a) and (b) cost reads or memory for something nobody reads. The server task shrank to back links carrying the free first-writing unit (the click needs it to seek).

AS BUILT (#710, merged at c785c88e): web/src/factsetAnchors.ts stubLabel = 'see ' + the title cut to STUB_TITLE_CHARS at a word boundary (the length and the ellipsis are PLACEHOLDERs: the user set no length); FactSetAnchors.resolve scrolls when the written section is on screen, else seeks to link.unit (falling back to a unit the map remembers) and lands on the anchor. Section headings keep their numbers (Q-UI8), the server-rendered export is unchanged, and the Q-UI12 tooltips apply to the link's different_version mark.

WHAT THIS DOES NOT MEAN: it does not remove numbers from section headings or from the export's '(see N)'; forward links still carry number on the wire (the UI just does not show it).

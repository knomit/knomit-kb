# Exiting Focus closes the FactSet (user, 2026-11-02, #710 review M2): the FactSet view exists only in Focus; the Exit focus toggle and Esc in Focus do exactly what Back does (close the view, best-effort DELETE, URL flag cleared); the single-fact view is unchanged

QUESTION (#710 review M2): with Focus off, the FactSet view only replaced the right panel, so the library list beside it stayed live: what should happen to an open FactSet when a row is clicked or the repo/lens changes?

OPTIONS:
(a) keep a non-Focus FactSet view and close it on a row click or a repo/lens switch;
(b) no Focus toggle at all: the FactSet view is always full screen;
(c) exiting Focus IS closing the materialization: the toggle and Esc close the view like Back.

CHOICE: (c). RATIONALE: the user's mental model: materializing a search is a full-screen mode opened from the search list, and leaving it means going back to the list. With no non-Focus state, the row-click and repo/lens-switch case cannot arise.

AS BUILT (#710, merged at c785c88e): useMatFocus(onExit?) (web/src/useMatFocus.ts) runs onExit on Esc instead of turning Focus off when one is given; FactSetView passes its onBack (RightPanel: factsetView.close(), which clears factset=1; the view unmounts and FactSetStream.dispose closes the FactSet with DELETE …/search/factset?cursor=). The toggle (fs-focus) calls the same close. Esc in a text or number field still only leaves the field (holdsEsc, gotcha 3fedfce6). MaterializeView passes no onExit: its Esc and toggle only turn Focus off and its view stays open. Reload behaviour is unchanged (a reload closes the FactSet). The toggle keeps the single-fact wording "Exit focus" and is now always pressed (aria-pressed true): it never shows the off state.

WHAT THIS DOES NOT MEAN: it does not change the single-fact view, and it does not change useMatFocus's default (no onExit = Focus off).

# FactSet Back pill (design §5, label ruling 2026-11-02 "back to title"): following any in-document link records the reader's origin; a floating pill "Back to <short title>" returns there exactly, re-seeking the origin's unit if the jump dropped its run; ONE origin is kept, the latest

SOURCE: book-materialize-design.md §5 [user]: "Click scrolls to the written appearance and flashes it; a floating Back pill ... returns to the exact scroll position" and "Forward links to an unloaded page: the UI jumps by asking the cursor to continue from the target's unit (seek), renders it, scrolls and flashes; Back returns to the origin, re-rendering the origin's pages if needed." It went unbuilt in #710/#726 and the user reported it missing on 2026-11-02.

LABEL: the design's "Back to Fact 8 (8.1) · title…" was replaced by a user ruling on 2026-11-02, "back to title". The label is exactly "Back to <title>", where <title> is the origin's title shortened by the link stubs' rule (stubLabel without its "see "; STUB_TITLE_CHARS is still a PLACEHOLDER length). There are no numbers, matching the link ruling 7bc287ba. This is final copy, not a placeholder. The origin's title is the clicked section's own title when that section is WRITTEN. A stub carries its TARGET's title, so for a stub the pill names the nearest written section above it in its tree (the parent chain up to the unit root). Otherwise the pill would name the place you just jumped to.

CHOICES (#736):
- What counts as a link: a forward or back stub, or a builds-on link. Not the Unit stepper and not Back to top.
- The origin is recorded as the section the click was in (else the section at the top of the pane), its offset from the pane's top, and scrollTop. Back puts that section back at that offset. Matching the section rather than scrollTop survives prepends and re-seeks.
- If the origin section is not in the run, Back calls seek(unit, undefined, n, back=true). The stream marks that landing `back`, so the view restores the offset instead of handling it as a builds-on landing: it does not follow the origin stub and does not flash. Pressing Back clears the pill.
- LATEST ORIGIN ONLY, not a stack: a second link followed before Back replaces the origin. The design speaks of one position, and this is the simplest reading of it. A stack would need another rule for when the pill disappears.
- The flash on arrival: a link target, or a builds-on target, gets a FLASH_MS (1.2 s) Web Animations highlight plus data-fs-flash. A landing on a unit alone (the Unit stepper, Back to top, a restart or a refresh) does not flash.

CONSEQUENCE: a new kind of jump in the FactSet view must decide whether it records an origin. A new landing must keep the land-once rule (60d4ace8 LANDING). A Back landing is an ordinary new land object and must never be re-triggered by mutating it.

WHAT THIS DOES NOT MEAN: the pill is not browser history, and the browser Back button is untouched. It does not survive closing the FactSet. Back to top and option changes do not clear it; only pressing it does.

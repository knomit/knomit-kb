# DECISION (2026-10-24): each internal/edge/web/api package exports one Mount with positional parameters and no exported Deps type, and owns its route table; origins.Mount owns the session manager, so Server.SessionManager goes away

Rulings by the user on 2026-10-24 for the web split (step 12), enforced in code from 12a (PR #621, merged on dev as 7dccaa09) by guard M, kb/invariants/testing/web-api-exports.

DECIDED: (1) Resource packages (api/kb, api/manage, api/jobs, api/origins) each export ONE func Mount and keep their own route table, so about 4 handler exports are needed instead of about 102. The route table leaves router.go for each package; router.go just mounts them. (2) Mount takes positional parameters; there is no exported Deps type. If a package needs more than about 5 parameters, its PR flags that to the user. (3) api/origins' Mount creates and owns the session manager, including its cleanup; the Server.SessionManager field is removed (planned for 12d, the 7 test files that set it move to origins then). (4) Consequence: every api/* package exports exactly Mount and every per-package allowlist in guard M is empty.

OPTIONS REJECTED: exporting about 102 handlers from the resource packages; an exported Deps struct passed to Mount; keeping the session manager as a Server field with an api/origins type exported for server.go.

BUILT vs PLANNED. BUILT at 7dccaa09: only the guards (M, R, F, generalised W). PLANNED, not built: the api packages themselves (12c to 12f), the Mount signatures, moving the route tables out of router.go, and removing Server.SessionManager (12d). Until each lands, the guard logs the package as pending; after 12f pending becomes an error. 12d, 12e and 12f are not plain moves, so each gets an Opus review and a user merge.

NOT RECORDED HERE: the ruling on the job registry, which was still in flight when this was written.

DOES NOT MEAN: that the api packages exist, or that Server.SessionManager is already gone.

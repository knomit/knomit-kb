# The Manage rail (Repositories, Archived, Lenses) renders only when the pane is ABOUT entities — Overview, a repo, a lens, the create forms, Archived; server pages such as Sessions (and future Audit, auth, jobs) render full width with no rail

**Context (2026-09-15):** after PR #192 put Overview and Sessions in a tab strip and left entities in the rail (kb/decisions/web/manage/server-pages-as-tabs/f4fda365.md), the maintainer noticed that on the Sessions tab the rail was still showing: 'the data sessions shows has nothing to do with the repos'.

**Options considered:**
1. Keep the rail everywhere for a stable layout (status quo). Rejected: on a server page nothing in the rail is selected and nothing in it explains or filters the content, so it is a column of exits next to an unrelated table. The house rule stated in RepoManager.tsx's Archived comment applies: a dead control is worse than an absent one.
2. Keep the rail but dim it on server pages. Rejected for the same reason: dead controls kept on screen.
3. Keep the rail and make a rail click FILTER Sessions by binding (the API supports ?binding=). Rejected: it would change what a rail click means on one tab only.
4. Hide the rail on server pages, keep it on Overview. CHOSEN (maintainer: 'rail stays for overview, is gone for sessions').

**Rationale:** the rule is about CONTENT, not about which tab is lit: the rail is the index of the entities you own, so it belongs beside panes whose content is those entities. Overview's content is the entity summary ('Needs attention', 'How things are wired'), so the rail is contextual there and both lead to the same repo/lens pages. Sessions is about the server. The rule therefore extends unchanged to every future server-level tab.

**Costs accepted:** a visible layout jump between the Overview and Sessions tabs (the tab strip spanning both columns anchors the top, and the eight-column Sessions table uses the width), and one extra click (Overview tab, then a rail row) to reach a repo from a server page.

**Misreading to avoid:** this does NOT mean 'server pages have no navigation' — the tab strip stays on every Manage page. It also does NOT mean the rail hides whenever a tab is selected: Overview is a tab and keeps the rail because its content is entities.

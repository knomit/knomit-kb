# REST API is HATEOAS / HAL+JSON with commit-anchored URIs that mirror storage

The /api/v1 surface was redesigned from flat RPC-style to HATEOAS with HAL+JSON everywhere. Core principles: (1) URIs mirror storage — a fact's canonical URI is its git path under a branch or commit; (2) graph is commit-anchored — anchor lives in the URI (/branches/{b}/facts/... resolves at HEAD; /branches/{b}/commits/{sha}/facts/... resolves at that commit); outgoing links preserve the anchor, so 'rewind and walk' just works; (3) every response is application/hal+json with mandatory _links.self; clients navigate by following links, not by string-building URIs; (4) async actions are RESOURCES (synthesis-runs, index-rebuilds, origin-sessions) — POST to create, GET to poll, sub-POST for workflow steps, DELETE to cancel — no one-off action endpoints; (5) server owns identity — clients never generate UUIDs; (6) scope lives in the path, not query params. ONE factView Go type serializes all fact responses — the only thing that changes is the anchor passed to the serializer.

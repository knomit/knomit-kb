# Decided (knomit#264, 2026-09-26): the windows-2025 build-test leg runs the WHOLE tools/desktop -tags desktop suite, not a -run allowlist, after a by-hand run on a Windows box showed all 151 Windows-compilable tests pass (132 had never run on Windows in CI); the one by-design Windows skip (settings file permissions) is tracked as knomit#301 rather than widened around

**Context.** Since the Windows leg was added (PR #212) the desktop step ran `-run 'TestWritable|TestBootServer_'` only, with a comment saying to widen only after making the suite pass there on purpose. knomit#264 (found reviewing #251) asked for exactly that: run it by hand, fix what fails, widen.

**What the by-hand run showed (worker session, 2026-09-26, dev 131376e3, Windows 10, Go 1.26.8, mingw gcc 16.2, elevated session-0 shell).** `go vet -tags desktop ./tools/desktop/...` clean; `go test -tags desktop -count=1 -v ./tools/desktop/` = 150 pass, 1 skip, 0 fail, test binary 9.4 s. The tag compiles with no Wails or WebView2 install. No test in the package constructs a Wails application, window or tray, so no display is needed and session 0 did not matter. The existing CI filter matched 19 of 151 tests; the other 132 had never run on Windows anywhere and all pass, because the original Windows-support PR (54f45452) had already given the tests capability probes (symlinks in bundled_test.go), GOOS branches (exe suffix) and a Unix-mode skip (settings_test.go:396).

**Options.** (a) Keep the allowlist and add names one PR at a time: every future desktop test is untested on Windows until someone remembers, the exact gap #264 describes. (b) Widen to the whole package now: the compile is already paid in that step, the tests cost ~10 s, and the first CI run is the windows-2025 confirmation of a run that was local. (c) Move the tests to a separate Windows job: another 10+ minutes of toolchain setup for 10 s of tests. CHOSEN: (b), keeping `-count=1` and the go-test-capture.sh stream so the fault guard (knomit#279) covers it.

**What this does NOT mean.** It does not test the Windows ACL of knomit.toml: TestApplySettingsFilePermissions skips on Windows by design because Perm() there is synthesised from the read-only bit, and nothing in the tree sets ACLs; that is knomit#301, not a reason to keep the allowlist. The symlink-gated tests SKIP (not fail) on an unelevated box without Developer Mode; GitHub's runner is admin so they run in CI, and a local skip is not a regression. A green step still names no test: the -json stream in $RUNNER_TEMP is where 'which tests ran' lives (kb/gotchas/ci/verbose-for-platform-only-tests). This decision is about test COVERAGE on the Windows leg; the hardware-fault guard decision (kb/decisions/ci/windows/hardware-fault-guard) is about heap SAFETY of the same leg, and the two share the capture script only.

# Decided (knomit#264, 2026-09-26, PR #302): the windows-2025 build-test leg runs the WHOLE tools/desktop -tags desktop suite, not a -run allowlist, after a by-hand run on a Windows box showed every Windows-compilable test passes (165 compile, 136 had never run on Windows in CI); the one by-design Windows skip (settings file permissions) is knomit#301, and go-test-capture.sh now prints skipped tests by name so the skip set is observed, not inferred

**Context.** Since the Windows leg was added (PR #212) the desktop step ran a -run allowlist only ('TestWritable|TestBootServer_', later '|TestFleetIdentity_' from #296), with a comment saying to widen only after making the suite pass there on purpose. knomit#264 (found reviewing #251) asked for exactly that: run it by hand, fix what fails, widen.

**What the by-hand run showed (worker session, 2026-09-26, Windows 10, Go 1.26.8, mingw gcc 16.2, elevated session-0 shell).** `go vet -tags desktop ./tools/desktop/...` clean; the whole package passes with one skip; test binary ~10 s; the tag compiles with no Wails or WebView2 install. No test in the package constructs a Wails application, window or tray, so no display is needed and session 0 did not matter. Measured after the rebase onto dev dc28adda: `go test -tags desktop -list .` gives 165 tests; 29 matched the allowlist, so 136 had never run on Windows anywhere, and all that do not skip pass (164 pass, 1 skip). They pass because the original Windows-support PR (54f45452) had already given the tests capability probes (symlinks in bundled_test.go), GOOS branches (exe suffix) and a Unix-mode skip in settings_test.go.

**Options.** (a) Keep the allowlist and add names one PR at a time: every future desktop test is untested on Windows until someone remembers, the exact gap #264 describes (and #296 had just added a third name to the list). (b) Widen to the whole package: the compile is already paid in that step, the tests cost ~7-10 s (CI measured 6.98 s), and the first CI run is the windows-2025 confirmation of a run that was local. (c) A separate Windows job: another 10+ minutes of toolchain setup for 10 s of tests. CHOSEN: (b), keeping `-count=1` and the go-test-capture.sh stream so the fault guard (knomit#279) covers it. Merged as b3a9ec46; the merged run's Windows leg printed `pass knomit/tools/desktop 6.984s` and exactly one skip line.

**Two things review added.** (1) go-test-capture.sh prints every test-level skip as `skip <pkg> <Test>` after the package summary: a green step names no test (kb/gotchas/ci/verbose-for-platform-only-tests), and the skips are the one test-level fact worth a line each, so the comment's claim that the symlink-gated tests RUN on the elevated runner is now something the step log shows (the merged run's desktop skip set was TestApplySettingsFilePermissions only). The same lines now appear for every capture step on every OS; on the Windows leg that is 28 skips, including six storytests property tests and seven internal/embeddings tests, an inventory nobody had before. (2) The desktop test sandbox (native_test.go sandboxHome) set HOME and XDG_STATE_HOME only; on Windows the state dir comes from LOCALAPPDATA, so the four TestWriteFile_ tests had been writing note.txt and pwned.txt into the REAL %LOCALAPPDATA%\knomit\exports of whoever ran them. Fixed in its own commit (3fe80a57) by setting LOCALAPPDATA too. Widening a suite onto a new OS is when a fixture's unstated platform assumptions surface; look for them before the first CI run, not after.

**What this does NOT mean.** It does not test the Windows ACL of knomit.toml: TestApplySettingsFilePermissions skips on Windows by design because Perm() there is synthesised from the read-only bit, and nothing in the tree sets ACLs; that is knomit#301, not a reason to keep an allowlist. The symlink-gated tests SKIP (not fail) on an unelevated box without Developer Mode; a local skip is not a regression, and the CI skip lines are where to check that the runner is still elevated. A green step still names no PASSING test; the -json stream in $RUNNER_TEMP is where 'which tests ran' lives. This decision is about test COVERAGE on the Windows leg; the hardware-fault guard decision (kb/decisions/ci/windows/hardware-fault-guard) is about heap SAFETY of the same leg, and the two share the capture script only.

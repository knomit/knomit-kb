# SUPERSEDED — migrate-registry's schema-then-rows split; the atomicity it traded away caused silent lens loss

**SUPERSEDED by [[ddl-in-tx-not-migrator]]. Recorded here because the reasoning that led to it was plausible and should not be re-run.**

`applyControlDB` built all three tenants plus every row in ONE transaction, so an abort left no half-built registry. golang-migrate opens its own transactions and cannot nest inside a caller's, so something had to give.

**Options considered.** (a) Migrator first, then rows in one tx. (b) Keep the tx untouched using the exported `*SchemaSQL` constants, then run the migrator after it commits purely to stamp. (c) Keep the constants but generate them from the embedded .sql at init.

**What was chosen, and why it was wrong.** (a) was chosen, on the reasoning that the row inserts stay atomic and "a failed run leaves empty-but-correct tables rather than none — indistinguishable from a fresh home, and control.db.bak still rolls back in full".

That last clause is where it broke. The `.bak` existed but NOTHING restored from it, and the failure was silent: with the legacy DROP committing outside the transaction, an abort left the lens tables recreated and empty while the rollback restored `repo_settings`, so the home still looked unconverted. The operator re-ran, `planLenses` read the empty new-shape table, and the second run reported SUCCESS having discarded every lens definition. "Covered by a backup" is not coverage when nothing tells anyone to reach for it.

**The reasoning error worth keeping.** The premise "the migrator cannot be in the transaction, therefore the schema step cannot be in the transaction" conflated the migrator with the DDL. Only the migrator is excluded; the DDL is just text, and an idempotent baseline can be executed directly inside the caller's transaction. Option (c) was closest to right and was passed over as fiddly — before the cost of (a) was visible.

**Superseding decision:** `applyControlDB` drops and rebuilds the lens tables from `migrate.ControlBaselineSQL` inside one transaction, and calls `migrate.Control` after the commit only to stamp.

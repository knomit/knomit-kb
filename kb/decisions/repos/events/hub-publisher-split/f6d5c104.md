# events.NewTaskHub and NewRepoEventHub return (hub, publisher): every announcing method lives only on the publisher, which only the repos parent holds in unexported fields; consumers get the hub (Subscribe, Task, Tasks)

User ruling 2026-10-25 (PR #631, step 14b of the internal/ hierarchy, merged as 37dc65d5; re-read there).

DECISION. events.NewTaskHub returns (*TaskHub, *TaskPublisher) and events.NewRepoEventHub returns (*RepoEventHub, *RepoEventPublisher). Every method that ANNOUNCES lives only on the publisher: TaskPublisher.BroadcastIndex, BroadcastStatus, BroadcastTrigger, BroadcastSyncOK/Error, BroadcastPushOK/Error, PublishTask, CancelTasks, Shutdown, and RepoEventPublisher.Publish. The publishers are held only by the repos parent, in unexported fields (RepoInstance.pub, RepoInstance.repoEventPub, Manager.repoEventPub, remoteEdgeSink.pub). Consumers (web handlers, other packages) get the hub: TaskHub has Start, Subscribe, Task, Tasks and Cancel; RepoEventHub has Subscribe. RepoInstance.TaskHub() and Manager.RepoEventHub() return hubs, never publishers.

WHY. The first cut of 14b exported the old unexported publish methods on the hubs, which silently removed the package boundary that enforced the publish chokepoint (4110015c). The reviewer sabotaged it against the commit: handler code calling ri.TaskHub().BroadcastIndex(...), PublishTask(...) and m.RepoEventHub().Publish(...) compiled and left the archtests green. Failure scenarios: (1) BroadcastIndex{ready} while the machine is indexing shows a fake ready chip; (2) RepoEventHub().Publish paints any repo's fleet chip with any state; (3) PublishTask{Op: synth, Status: running} puts an entry in active[synth] with no cancel func and no terminal, so every POST synthesis-runs answers 409 (Start's single-flight, a346c69c) and DELETE cannot cancel it (Cancel needs a hub-started task); a fabricated done for a running rebuild makes GET report done and DELETE answer 409 already-finished for a job still running, breaking the #623 DELETE contract (c514ec1b); (4) CancelTasks from a handler kills every running task without going through DELETE. With the split, the sabotaged calls no longer compile (no field or method BroadcastIndex/PublishTask/Shutdown on *events.TaskHub).

REJECTED. (a) A name-based archtest over the exported hub methods (BroadcastIndex, PublishTask ... plus a renamed generic Publish): the methods stay exported and enforcement is by a test that a new name or alias slips past. (b) Keeping the hubs in the parent and making events a types-only child: the hubs would stay unexported, but the child would own nothing and consumers would still need the types.

OPERATIONAL CONSEQUENCE. A new child or package that needs to PUBLISH receives the publisher as a constructor parameter from the repos parent (as runReconcileLoop takes the repoEventPub through remoteEdgeSink). It must never be exposed: no exported func, method, field, var or alias may yield a publisher, directly or via any, a method value or a closure. Enforcement is the pair of archtests TestEventPublishers_NotExposed and TestEventPublishers_NotLeakedTyped, which have stated limits.

MISREADINGS. TaskHub.Start is still exported on the consumer hub (the synthesis handler starts its task through it) and is unchanged: a task Started from web always has a cancel func and a terminal, so it cannot create the phantom running entry; Start accepts any op name, including rebuild, which is pre-existing. A getter that returns the publisher, however well named, defeats the split. A test instance built with NewTestInstanceWithDeps takes only the consumer hub, so its pub is nil.

EXTENDED AT 14c (PR #632, merged as ee850fd6): the same capability-by-construction shape was applied to the trigger dispatcher's run loop. trigger.New returns (*Dispatcher, run func); the run func is held only in the unexported RepoInstance.runTriggers and started only by serveStage.Enter; there is no exported Run. The general rule: a repos child hands out what consumers may use (a hub, a dispatcher handle with Kick, Report and FiresByRun) and receives what only the parent may hold (a publisher, a run func, a lease func) by construction; none of those is ever exposed (kb/decisions/repos/triggers/run-func-capability/03d92e7a.md). The dispatcher takes its *events.TaskPublisher as a constructor parameter in an unexported field.

CHANGED BY PR #791 (chore/taskhub-unused, merged as 02d41850, re-read there): TaskHub.Start, TaskHub.Cancel and TaskPublisher.CancelTasks are deleted (no production caller since PR7 removed the synthesis job; CancelTasks only cancelled Start's tasks). The consumer TaskHub now has Subscribe, Task and Tasks only; TaskPublisher keeps the Broadcast* methods, PublishTask and Shutdown. The MISREADINGS paragraph above about Start being exported on the consumer hub is history, and failure scenario (4) no longer exists. The split itself is unchanged and still enforced by TestEventPublishers_NotExposed / NotLeakedTyped. MISREADING: "the archtests would stop someone re-adding Start": no, they guard only publisher exposure; a sabotage restoring a consumer-side Start with a production caller stayed green.

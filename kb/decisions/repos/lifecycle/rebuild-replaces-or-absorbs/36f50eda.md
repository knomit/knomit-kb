# A manual rebuild never conflicts: it REPLACES a running index job (heal, or a rebuild of another branch) with a new job (201) and is ABSORBED by a running full rebuild of the same branch (200, that job's id); the 409 of PR #221 is retired

Supersedes kb/decisions/repos/index-state/rebuild-marks-serialised/49debc0d (issue #411). The 409 existed because the index state was a cell with several writers (heal marks, rebuild bracket) and serialising by refusal was the safest way to keep one writer. With the lifecycle machine there is exactly ONE Index life and the state is derived from it, so there is nothing to contend for: Rebuild is an event targeting the Index stage.

RULE (handleExternal, machine.go): if a full rebuild of the SAME branch is running, answer Reply{JobID: the running job, Absorbed: true} — HTTP 200. Otherwise exit the Index stage (cancelling a heal or another branch's rebuild) and enter it with indexSpec{full, branch} under a fresh job id rebuild-N — HTTP 201. The replaced job's TaskEvent ends with status error 'replaced by another index job' (or 'indexing cancelled' after CancelIndex), published from publishRebuildTask.

Accepted costs carried over: no force flag (there is nothing to force); an error from a rebuild and an error from a heal share index_state 'error' (index_reason now names the job's error).

Misreading: 'absorbed' is not 'refused' — the caller gets the running job to follow. A rebuild during a create keeps the create card on indexing until the full rebuild ends (the create job observes the derived state).

MOVED (12c, PR #627, merge 97ae7c19, re-read there): handleStartRebuild is in internal/edge/web/api/jobs/handlers.go; it still sends Rebuild(branch) and answers 201, or 200 with the running job's id when Reply.Absorbed.

PUBLISHER (14b, PR #631, merge 37dc65d5, re-read there): publishRebuildTask (machine.go) now records the rebuild TaskEvents through the repo's events.TaskPublisher (pub.PublishTask), which only the repos parent holds; the consumer-facing *events.TaskHub cannot publish or fabricate a rebuild task. Replacement and absorption behave as described. See kb/decisions/repos/events/hub-publisher-split/f6d5c104.md.

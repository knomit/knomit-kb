# Repo lifecycle REST design: delete=archive (recoverable)+purge, single NDJSON create endpoint, top-level /archived

Design choices resolved for remote repo management (so they aren't re-litigated):

- Delete = archive, not hard delete. DELETE /repos/{repo} moves the repo to an archive holding area (recoverable); permanent deletion is a separate explicit Purge (DELETE /archived/{id}). Restore (POST /archived/{id}/restore) brings it back. Chosen for recoverability matching the 'no shell access' goal.
- ONE create endpoint, mode-driven. POST /repos takes a single body with a mode param (preset|custom|clone) and per-mode fields — NOT separate endpoints per creation kind.
- Create streams progress as newline-delimited JSON (Content-Type application/x-ndjson), NOT SSE. Each line is {type: progress|done|error, ...}; the terminal line carries the created repo or the error. Pre-stream rejections (bad name 400, name-active/in-flight/origin-in-use 409) are sent as problem+json BEFORE the stream starts, because once 200+stream begins the status can't change.
- Archived repos live under a TOP-LEVEL /api/v1/archived collection (sibling of /repos), NOT nested under /repos/{repo}, because 'archived' is a valid repo name ([a-z0-9_-]+) and would collide with the {repo} param; archived items also aren't resolvable by RepoMiddleware (they're not active repos).
- Origin-uniqueness: two active repos may not share an origin URL; enforced on clone-create and on restore (409).

Note: the restore action uses a slash route /archived/{id}/restore rather than the AIP colon-verb style (POST /collection:verb) used by /repos:rescan — see [[aip-custom-action-routes]]; this was a conservative default and is a candidate to align to :restore for consistency.

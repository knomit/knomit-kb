# Decided (user, 2026-10-03): a mounted repo's whole lifecycle is ONE per-repo state machine — foundation stages Populate→Open→Identify then worker stages Index→Serve→Sync that launch background work and return; every change is an event sent to it; status is a projection; indexing never blocks anything and Attach/Detach/Swap are refused while it runs

Context: ~10 consecutive tickets (#377/#397, #400/#404, #402, #406, the clone-create stuck-indexing incident, #362 detach-no-loop, the DisableBackgroundSync smuggle, the stale index chip, the rebuild 409) were each fixed by a local patch to call-site discipline in internal/repos (activate, startSync/startLocalSync closures, SwapStore, lifetimeGuard, scattered index marks) and internal/web handlers. The owner judged this was accreting spaghetti because nothing owned 'what work is this repo running'.

Options considered:
(1) Keep patching case by case (#402, #406 patches) — rejected: each patch adds another call site that must sequence start/stop/mark correctly.
(2) First review (Fable): Command/Composite for transitions + supervisor with reconcile() + index job slot + unit primitive + per-scenario methods, migrated in 4-5 strangler PRs — rejected by the owner as still spread across many objects and methods; and a migration plan is wrong pre-release (principle solution-quality-pre-release 7d042030).
(3) One explicit state machine that every mounted repo is driven through — CHOSEN, refined over several rounds.

Choice (final):
- Stages, in order: foundation Populate → Open → Identify (build the repo; fatal on error → Unavailable), then worker Index → Serve → Sync, each of which launches background work under its own Life (ctx+WaitGroup) and returns immediately. Index = heal/rebuild job; Serve = trigger dispatcher, consensus merger, experiment sweep; Sync = the reconcile loop chosen by the origin (its first round replaces recoverFromOrigin). One wiring function (replaces openStore/openGit/rewireStore) and one RecordRepoID site.
- Events name a target: a foundation target REWINDS (exit from the top down, apply, walk forward again); a worker target RESTARTS only that stage. Mount, AttachOrigin, DetachOrigin, SwapStore(tmp, origin) [origin carried in the same event, one apply], Rebuild, CancelIndex, Unmount, plus internal indexDone/crashed/drained/reenter.
- One driver goroutine per repo is the only writer of lifecycle state; it never waits for background completion. Multi-stage exits cancel ALL affected lives first, then drain newest-first (lockBranch is a plain RWMutex the heal holds). Crash restart: cancel the life, a waiter posts drained, a timer posts reenter — never sleeps the driver.
- NO QUEUEING: indexing is background, so no foreground event waits on it. Attach/Detach/Swap are EXCLUSIVE with indexing: refused 409 'repo is indexing — wait or cancel indexing' (with a cancel link) before any guard or network read. CancelIndex (POST /api/v1/repos/{repo}/index:cancel) exits Index only; status error, reason 'indexing cancelled'. The connect-origin wizard may send CancelIndex then SwapStore ('cancel indexing and continue'). Rebuild replaces a running index job; an identical rebuild already running is absorbed (same job id) — the rebuild 409 is retired.
- Status (stage, index indexing|ready|error + reason, sync running) is a projection of the machine, published from one point by the driver; no status cells. The create job keeps 'done = indexed' as a pure observer (Watch).
- PUT /origin fail-fast: the Attach guard's CheckOriginOntology network read (bounded by NetworkTimeout) yields an immediate 502 and NOTHING is persisted.
- The dispatcher's on:due sweep (reads index tables) is gated on index ready; change triggers (git DiffFacts), merger, sweep and sync run during indexing (sync waits behind the heal on lockBranch — background on background, harmless).
- No stage or background goroutine may Send to its own machine (deadlock); enforced by construction (stages get *Repo and *Life, no Send).
- Implemented in ONE PR, no migration steps or shims.

Accepted degradation (decided, do NOT 'fix' by blocking on the index): while indexing, request paths that read the index — search, knomit_learn near-duplicate dedup, lens queries — may return partial results or let a duplicate through; /knomit-review's prune reconciles later.

Non-scope: internal/store beyond adding ctx to the Init* clone/subscribe/initialize functions; loop/round bodies; dispatcher/merger/sweep internals beyond run(ctx) and an indexReady gate; TaskHub for synthesis. Supersedes the patch plans for #402 and #406.

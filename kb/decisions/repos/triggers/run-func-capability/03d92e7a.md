# trigger.New returns (*Dispatcher, run func): the run loop is a capability held only in the unexported RepoInstance.runTriggers and started only by serveStage.Enter; the trigger package has no exported Run, and only the repos parent may select trigger.New

Review ruling on PR #632 (step 14c of the internal/ hierarchy, merged as ee850fd6; re-read there). Same shape as the publisher split (f6d5c104): enforce a boundary by what a package hands out, not by a name-based test.

DECISION. trigger.New(...) returns (*Dispatcher, func(context.Context)). The second result is the run loop (d.run). It exists only as that return value: Dispatcher has no exported Run, no getter and no seam returns it (RunOnceForTest runs one pass and is gated by mustBeTest). The repos parent stores it in the unexported RepoInstance.runTriggers (nil exactly when RepoInstance.triggers is nil) and serveStage.Enter starts it with life.Go("triggers", run). RepoInstance.Triggers() hands callers the concrete *trigger.Dispatcher, which exposes Kick, Report and FiresByRun only.

WHY. The first cut of 14c exported Run on the dispatcher that Triggers() hands out. The reviewer sabotaged it against the commit: adding `go ri.Triggers().Run(r.Context())` in internal/edge/web/api/kb/handlers_triggers.go built and left every archtest green. Failure scenarios: (1) two Run loops on one dispatcher race on d.runCtx and consume the same 1-slot kick; both read the same watermark-to-head range before either buffers phase C, so the same paths fire twice (duplicate emits, duplicate recipe starts), breaking 'one actor per writable repo' (a01f40fc); (2) on a read-only server or a subscription Triggers() is nil and the old Run was not nil-safe, so the handler panicked; (3) trigger.New(..., ri.Acquire, ...) called from web builds a rogue dispatcher whose trigger-table writes come from trigger/triggers.go, which TestFactsRepoTriggerWrites_OnlyFromDispatcher (keyed by file) permits.

ENFORCEMENT. With the run func unexported, scenario (1) no longer compiles. Scenario (3) is closed by test/archtest TestTriggerNew_OnlyFromRepos: only a top-level NON-TEST file of internal/corpus/repos may select trigger.New (any import name; a dot import of trigger is flagged); non-vacuity: manager.go must still select it and at least 500 files are walked; TestTriggerNew_GuardDiscriminates runs the detector on inline source. The guard skips test files ON PURPOSE: TestDispatch_PhaseBHoldsNoLease builds a second dispatcher over a counting acquire. Consequence: a test in another package could still build one; tests do not ship, and the reviewer accepted that. Sabotages the reviewer ran at 03c56e27: `go ri.Triggers().Run(...)` no longer builds; trigger.New or `var rogueNew = trigger.New` in the web handler is red; manager.go selecting trigger.NewX instead is red (non-vacuity).

GENERAL RULE now visible in the repos tree: a repos child receives its capabilities BY CONSTRUCTION from the parent and never exposes them. Two so far: the event publishers (events.NewTaskHub returns hub plus publisher, f6d5c104) and the dispatcher's run func (this fact). A new child that owns a loop or an announcer returns it from its constructor, the parent keeps it in an unexported field, and no exported func, method, field, var or alias may yield it, directly, via any, via a method value or via a closure.

MISREADINGS. This does not hide the dispatcher: Triggers() stays an exported getter (a handle, like TaskHub()), and Kick, Report and FiresByRun are safe for any holder (Kick coalesces; the other two read). It does not mean Dispatcher is unconstructable in tests: the parent's tests reach it through *ForTest doors and may call trigger.New.

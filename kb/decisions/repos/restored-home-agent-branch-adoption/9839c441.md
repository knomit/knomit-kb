# On a restored/copied home, adopt the previous agent branch as seed and retain the orphan

When a knomit home is restored onto a different machine (or a repo DB is copied), the fresh SSH key yields a different agent branch name (derived from the key fingerprint), so the configured agent branch is ABSENT in the copied database. ensureBranch (internal/repos/builder.go) must seed it via CreateBranch from a source that exists; seeding from itself (the old CreateBranch(agent, agent)) failed and broke every write path (issue #32).

**Options considered** for the seed source: (a) adopt the repo's current HEAD branch — the previous machine's agent branch; (b) seed from the upstream consensus branch (main/master). For the orphaned previous branch: retain, adopt, or garbage-collect.

**Rationale**: Seed = HEAD (option a), NOT upstream main. For local-only repos (the dominant case, including knomit's own memory) main sits at the init commit, so seeding from main would DISCARD every accumulated fact. HEAD points at the previous agent branch, which carries all knowledge; CreateBranch already clones git ref + branch_commits + branch_facts, so adoption inherits everything. This mirrors how a fresh clone bootstraps its agent ref from origin/main. The orphaned previous branch is RETAINED (not GC'd): nothing writes to it and it is outside the fetch refspec so it is never pushed; GC risks deleting the only copy of data.

**The choice**: seedSourceForAgentBranch() returns the agent branch when present (CreateBranch no-ops), else the HEAD/DefaultBranch when it differs, else falls back to the agent branch itself (so CreateBranch fails loudly on a detached/broken HEAD rather than seeding from a broken source). ensureBranch also now runs BEFORE loadOntology in manager.openOne so the restored instance loads the adopted branch's ontology on first boot instead of the default. A missing sync watermark on the adopted branch self-heals via reconcileAgentRebase's MergeBase fallback.

**HEAD MUST FOLLOW THE ADOPTION.** After a successful adopt, ensureBranch calls SetDefaultBranch(agentBranch). This is load-bearing, NOT cosmetic — the initial version of the fix got this wrong. HEAD is the seed source read by seedSourceForAgentBranch, and it is otherwise written ONLY at init (store.InitRepo / InitFromRemote; SetDefaultBranch had no other production caller). Left unmoved, HEAD stays pinned to the branch of the machine that FIRST created the repo, so a home that is restored, used, and restored AGAIN adopts the original branch on the second hop and silently discards everything the intervening machine wrote — no error, no warning. Regression test: TestEnsureBranch_ChainedRestoreAdoptsMostRecentBranch.

**Non-scope**: The orphan branch is still not garbage-collected — only the HEAD pointer moves off it. No explicit agentBase seeding is added for origin repos (the reconcile MergeBase fallback covers it). Note that DropBranch does not guard HEAD, so deleting a branch HEAD points at would dangle it and fail OpenRepo; DropBranch has no API/CLI/MCP caller today, so this stays latent.

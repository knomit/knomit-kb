# EMIT files the answer under the MAJORITY topic of the supporting facts (category of the highest-ranked support in it), picks the type from the type table (≥2 supports synthesis with origin authored, 1 insight, a lone restates writes nothing), and on any write-path refusal returns the fact unwritten and ends on a gap

E02 leaves open how EMIT picks the target topic, and a topic's rules can refuse the default type. PR 1's rule (coordinator ruling, 2026-10-12): topic = the majority topic among the supporting facts (ties to the earliest-ranked), category = that of the highest-ranked support in that topic, so the answer sits beside its evidence. Type from the type-semantics table: two or more supports -> synthesis (origin set to authored explicitly, since omitting origin on a synthesis means distilled), one -> insight; a single fact the model judged `restates` is returned as existing_answer and nothing is written (dedup, not append). The GAP hypothesis uses the same placement over the supports, else the top gathered facts.

The write path is the validator: if knomit.learn refuses (ValidateFact / the topic's validations, dedup, refs gate), the script records a gap whose reason carries the refusal text, puts the fact in unwritten_facts, and goes to GAP (whose hypothesis may still be written). The host logs the refusal at Warn.

Misreading to avoid: the majority-topic rule is a PR 1 placeholder for placement, not a claim that answers always belong in their evidence's topic.

# The engine's `model` host function speaks OpenAI-compatible chat completions with response_format json_schema (llama-server and Ollama /v1 alike), validates every reply against the schema in Go, and throws on finish_reason=length — it does not use the internal/llm Ollama adapter

Options considered: (1) the existing internal/llm OllamaAdapter with ForceJSON; (2) a minimal client for llama-server's OpenAI-compatible API. Chosen: (2), as an OpenAI-compatible client, because the same wire is served by llama-server (E07's shipping runtime) AND Ollama's /v1 (what the gating tests use by ruling), so one host function serves both with no per-runtime branch. The adapter was rejected on result quality, not effort: CompletionOptions carries no schema (ForceJSON only means 'parseable JSON', met by a prompt on a reasoning model, kb/decisions/llm/ollama/forcejson-mechanism-per-model), and it reads Ollama's /api/chat, not llama-server.

What the host owns: the endpoint ([engine] model_url, default http://127.0.0.1:8080/v1 = llama-server; [engine] model, needed by Ollama; env KNOMIT_ENGINE_MODEL_URL / KNOMIT_ENGINE_MODEL) — never a script argument; the schema (required: a call without one is refused before any request); inline <think> blocks stripped; the reply validated with github.com/google/jsonschema-go — a reply outside the schema is THROWN, because the server-side constraint is a mechanism and the host check is the guarantee; finish_reason == "length" is thrown as truncated and logged at Warn with the run key (kb/gotchas/llm/ollama/generation-budget-and-truncation: truncation arrives as a successful response). No max_tokens is sent unless the script passes one: a cap only truncates on a local model.

Misreading to avoid: this does NOT replace internal/llm for the synthesis pipeline; it is the engine's call only. Running against Ollama requires setting [engine] model_url to http://127.0.0.1:11434/v1 and [engine] model to the pulled model's name.

Dependency note: github.com/google/jsonschema-go v0.4.3 is already required by wails v3.0.0-beta.28, so a future wails bump can move the validator's version silently (same lesson as kb/invariants/build/dependencies/genai-shared-with-production-llm/e0974901.md).

PR 5 (local branch fix/expert-harness-defects, commit c62c8456): the request now carries the engine's thinking switch, [engine] think (env KNOMIT_ENGINE_THINK, default false). Off sends BOTH reasoning_effort "none" (Ollama /v1 maps it to think=false) and thinking_budget_tokens 0 (llama-server ends the thinking at once); each runtime ignores the field it does not know. The host sums prompt and completion tokens over the run's calls and counts replies that carried a thinking segment (a reasoning or reasoning_content field, or an inline <think> block with text), and logs the first such reply of a run at Warn when the switch is off; ReasonResult carries prompt_tokens, completion_tokens and thinking_replies. The eval runner's arms take `think` (default false, so the local arms run with thinking off). marshalReasoningFirst now orders `rationale` first (the judgment schemas' new name for their reasoning field; `reasoning` is still honoured). Misreading to avoid: the switch does NOT stop a model whose chat template forces a thinking segment; see the gotcha on the LFM2.5-2.6B GGUF under Ollama.

# Manager.Rescan() is discovery-only — adds new repos, never removes or replaces

POST /api/v1/repos:rescan globs <home>/repos/*.db and registers any *.db file not currently in the Manager. It does NOT detect removed .db files and does NOT detect replaced .db files (same name, different content) — explicitly out of scope. rescanMu sync.Mutex on Manager serialises concurrent Rescan calls to prevent the same .db being opened twice in a race. No ctx parameter: Manager.Add/openOne don't take one and the operation is short. No auth on the endpoint — knomit API is unauth'd by design (localhost only).

UPDATE (repo-lifecycle work, 2026-06): Rescan is NO LONGER the only runtime way to add a repo. Manager.Create (POST /api/v1/repos, see kb/architecture/repos/lifecycle/9c43d8bd.md) now creates AND registers a repo in-process at runtime, and Manager.Archive removes one at runtime. Rescan remains the discovery path for .db files created out-of-band (e.g. `knomit init` against a running server, or a restored backup dropped into <home>/repos/), and it still never removes or replaces. Note: Rescan's repos/*.db glob is non-recursive, so it correctly ignores the new repos/archive/ subdir where archived repos live.

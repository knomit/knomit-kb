# A create job's `done` means the repo's index status LEFT `indexing`: the job observes the lifecycle machine through Watch and nothing in the machine waits for it; an index error is `done` with index_state=error, never a failed job; the transfer phase is indeterminate and carries NO pct

Decided 2026-09-16 (PR #208); mechanism rewritten for issue #411.

CreateStatus carries Phase (validate|transfer|index|register|done), Indeterminate, IndexState. InitSubscription and InitFromRemote forward the remote's sideband lines as transfer-phase events with Indeterminate=true. After Mount succeeds, Manager.Create calls watchIndex(ctx, ri, emit): it ranges over ri.Watch and emits index-phase events (done/total scaled into the job's pct band) until the status's Index.State is not `indexing`, then returns that state. `ready` → done; `error` → done with index_state=error — the repo exists, so failing the job would misdescribe it. The repo itself serves immediately; only the CREATE JOB waits to call itself done.

WHY THE INFERENCE IS NOW SAFE. 'Left indexing, therefore the work finished' used to rest on mark ordering plus the rebuild 409. Now the state is derived from the one Index life (kb/invariants/repos/index-state/publish-chokepoint): Watch's first value is taken under the same lock publish holds, so the job cannot miss the transition, and the state leaves `indexing` only when the current Index job posts its verdict. A Rebuild during a create REPLACES the heal with a full rebuild, so the state stays `indexing` and the card stays on index until the full rebuild ends.

OBSERVER ONLY. watchIndex returning early (job deadline, cancel, shutdown) changes nothing about the index job, which runs under the machine's Index life. Nothing in the machine waits on the create job.

Wire contract: `indeterminate:true` → the "pct" KEY IS OMITTED from the status body; otherwise pct is present. Do NOT zero pct instead: a zero would run the latest value 5 → 0 → 70 and send a monotonic client bar backwards. Both UI components treat a missing pct as indeterminate.

Test note: tests run with Options.Synchronous, which no longer short-circuits the index — the index job still runs in the background, so a test of this property observes a Phase==index event with total > 0 from the emit callback (not by sampling job.Status()).

# The commit that writes a template carries Knomit-Template: <name> and Knomit-Template-Source: kb://<source repo ID>@<commit> — the 12-hex ID (root commit) and the full consensus-tip commit, never the source's name — stamped through the trailers seam inside the signed bytes; agents can never forge them

Decided with the user 2026-10-06 (F24 provenance: yes; source by ID). `store.Trailers` gained `Template` and `TemplateSource`, rendered after Run, and both count in `IsZero` (a set with only them is stamped; TestTrailers_TemplateOnlySetIsStamped). `writeTemplate` builds the trailer ctx locally (`WithTrailers`) for the one WriteSystemTree call and never returns it, so no later write inherits it. The value is `kb://<ri.ID()>@<UpstreamTip>`: the ID survives a rename or an unmount of the source, while the request names the source by NAME (TestCreateFromTemplate_CopiesTreeSignedWithTrailers renames the source afterwards). The commit is signed by the creating instance's key, recording WHO instantiated a template that brings recipes running exec.

Agents cannot set either key: MCP's trace argument refuses every `Knomit-` key but Trace, Cause and Run, in any case (TestTrace_RefusesTemplateTrailerKeys).

MISREADING: the trailer is provenance only; nothing reads it to keep the repo in sync with its template. A later template change never touches a repo created from it.

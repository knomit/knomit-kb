# Secrets scope includes fleet repos with a forge origin, the connect wizard, and secret_id on create/clone/probe/origin-session

Shipped: the fleet and REST endpoint parts in the linking PR (#722; see kb/architecture/repos/fleet/stored-secrets/89e683fe.md), the connect, create and fleet wizard access steps and the settings UI in PR 3 (#729; see kb/conventions/web/wizard/stored-secret-method/d4cbf6ce.md).

Choice: fleet repos with a forge origin are in scope (creating a new fleet on a forge origin, fleet join, fleet move, and the fleet Update access path changeFleetCredential offer the stored-secret option). A stored secret is selectable both in repo settings and in the connect/create wizard's access step, and the create, initialized-with-origin, clone, probe and origin-session (test/commit) endpoints accept a secret_id as an alternative to a pasted credential.

Rationale: leaving the wizard or fleet paths out would force a paste at exactly the moments users onboard repos, undermining the single-rotation goal.

Constraints: cert (peer) origins still cannot link a secret, and a secret is never sent to a fleet peer. Every origin rebuild path (restoreFleetOrigin in fleet_move.go, re-attach handlers, events re-attach) must carry secret_id, otherwise the link silently degrades to the pasted token or anonymous.

Non-scope: does not extend secrets to cert/fleet-peer origins.

# Secrets are host-bound and linking is admin-only, checked at link time and at every resolution

Describes the agreed design for feat/access-secrets, not shipped behaviour.

Options considered: host binding only; admin-only gating only; both.

Rationale: the operator permission can be held by remote OAuth bearer and certificate clients and permits changing a repo's URL. With a linked token, an operator could repoint the repo at a host they control and receive the token. Host binding alone does not stop a caller from linking a secret to a repo they should not; admin-only alone does not stop a later URL change from exfiltrating the token. Both are needed.

Choice: each secret carries an allowed-host list. The repo's remote host must be on the list when linking AND at every resolution; a later URL change to an unlisted host makes resolution fail as a sync error and the secret is never sent. Linking, unlinking, and URL changes on a linked repo require the admin permission plus the local-or-same-origin gate (requireLocalOrSameOriginAdmin), same as the secrets API.

Non-scope: the host check at resolution is not optional or link-time only; operator alone is not enough for any link-related action.

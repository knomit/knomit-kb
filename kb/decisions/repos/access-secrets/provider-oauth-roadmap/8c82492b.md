# Roadmap: project 2 is a per-user GitHub App connected account; project 3 is GitLab then Bitbucket

A plan, not shipped behaviour: project 1 (the secrets store, links and Access UI) shipped in #714, #722 and #729; projects 2 and 3 below are not built.

Choice: project 1 (secrets store) is built so a repo's link target is a generic credential source, a secret now and a connected account later. Project 2: a GitHub connected account where each user creates their own GitHub App via the manifest flow, authenticates with device flow, and the server holds and refreshes the expiring user tokens; repos link to the account as they link to a secret. Project 3: GitLab, then Bitbucket connected accounts.

Rationale: per the OAuth research report, each user registering their own app avoids knomit shipping a shared OAuth client and its secret, and device flow suits a self-hosted server without a stable callback. Providers differ in token lifetime and refresh, so they are sequenced separately.

Non-scope: nothing of projects 2-3 is built in project 1.

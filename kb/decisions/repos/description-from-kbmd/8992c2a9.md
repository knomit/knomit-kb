# Repo description = verbatim kb.md read at HEAD, exposed on single-repo GET only, rendered collapsible in detail pane

Repos gained a "description" sourced from the repo's kb.md root manifest (PR #91).

**Options considered (resolved via AskUserQuestion):**
1. *Extraction* — (a) first paragraph after the H1 title, (b) a YAML frontmatter `description:` field with fallback, (c) the WHOLE file verbatim. → chose (c) whole file.
2. *UI placement* — (a) list + detail pane subtitle, (b) detail pane only, truncated with an expandable scroll panel. → chose (b).

**Rationale:** The user wants the entire kb.md rendered, not a parsed/extracted summary, so no first-paragraph/frontmatter heuristic. Showing it only in the detail pane (not the /repos collection items) keeps embedded collection items minimal per the HAL hard rule (§3 #7: embedded items carry only _links.self + minimal display fields) and avoids N git reads on the list endpoint. A few-line clamp with Show more/Show less expanding into a fixed-height scrollable panel keeps a long manifest from taking over the pane.

**The choice / implementation:** `handleHALRepo` reads kb.md per-request (always fresh, no caching on RepoInstance) via `svc.Facts().ReadFact(ctx, ri.AgentBranch(), "kb.md", nil)` — the agent branch IS where HEAD points, so this reads kb.md at HEAD. The field is OMITTED when no kb.md is readable (nil store / missing file / empty branch) so the UI shows it only when available. The /repos collection endpoint is unchanged. Web: api.getRepo() hits the single-repo GET; RepoManager's new RepoDescription component renders markdown via react-markdown with a collapse/expand toggle (overflow detected by scrollHeight>clientHeight while collapsed). OpenAPI Repo schema documents `description` and the previously-undocumented `agent_branch`.

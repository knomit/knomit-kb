# Decided (user, 2026-10-02; issue #377): the experiment sweep gets its OWN context from b.ctx, started once in activate(), reaching the store through ri.Acquire per tick — not a relaunch added to startSync

Problem: runExperimentSweepLoop ran on syncCtx/syncWg. ActivateSync (ri.startSync) cancels syncCtx to restart the reconcile loop and relaunches ONLY runReconcileLoop, so every origin attach (clone-mode Create, PUT origin, origin-session handlers) killed the sweep for the life of the process and experiments stopped expiring. Detach (startLocalSync, PR #362) had already compensated by relaunching the sweep inline; attach never did. Same failure shape as the index-heal incident (kb/incidents/repos/clone-create-index-stuck-indexing), which was fixed by giving the heal its own indexCtx/indexWg.

Options considered:
(A) Give the sweep its own lifetime like the trigger dispatcher: own ctx derived from b.ctx + own WaitGroup, started once in activate() with the existing gates (not subscribed, ExpiryDays > 0, not DisableBackgroundSync); removed from startSyncLoops and startLocalSync; the loop reaches the store via ri.Acquire per tick instead of holding a raw *store.Service; stopped (cancel + wait) in RepoInstance.shutdown() and Manager.Close before closeFn.
(B) Add the relaunch to startSync, copying startLocalSync — ~6 lines.

Choice: (A).

Rationale: the sweep is origin-independent (an experiment is local-only), so tying it to the origin loop's lifetime is the bug, not a detail. (B) would leave the launch condition copied in three places and every future restart path would reintroduce the bug — it already happened twice (index heal, sweep). The sweep currently holds a raw *store.Service, which kb/invariants/repos/store-lifetime forbids; it was only safe because every teardown drained syncWg first. Moving it off syncWg therefore REQUIRES Acquire per tick. With Acquire, SwapStore needs no change: the handle refcount drain covers an in-flight tick, and a tick that lands mid-swap gets ErrStoreUnavailable and logs-and-retries, matching the sweeper's never-exit shape. Manager.Close duplicates shutdown's teardown and currently stops neither the dispatcher nor the consensus merger; the new sweep must be stopped there too (and Close should stop all three).

Non-scope: this does NOT mean every loop leaves syncCtx — runReconcileLoop and runLocalReconcileLoop are origin-dependent and must keep restarting with it. It does not change the sweep cadence (defaultExperimentSweepInterval stays a const; a test-only seam is allowed).

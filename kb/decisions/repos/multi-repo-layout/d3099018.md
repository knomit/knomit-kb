# Multi-repo layout: ~/.knomit/repos/*.db; shared identity/embedder/LLM; per-repo Service/Index/TaskHub

Knomit manages multiple repos from a single server. Storage layout: ~/.knomit/repos/*.db (every .db file is a repo, named by stripping .db), ~/.knomit/models/ (shared ONNX), ~/.knomit/id_ed25519 (shared SSH identity). Repo names must match [a-z0-9_-]+ — files with invalid names are SKIPPED with a warning. The 'knomit' repo is always auto-created if repos/knomit.db is missing. NO auto-migration from old single-repo layout: if repos/ has no .db files AND old-location knomit.db exists at cfg.RepoPath/knomit.db, log error with manual move instructions and exit. SHARED resources across all repos: SSH identity (single keypair, single agent branch name), embedder (one ONNX model attached to every repo's index), LLM adapter, signer, ontology (loaded once from the default knomit repo's git store). PER-REPO: store.Service, git.Store, store.Index, web.TaskHub, MCP server instances (one per profile), SynthDeps, sync/push goroutines, observer. New top-level endpoint: GET /api/v1/repos returns all repos sorted alphabetically (mounted alongside /api/v1/openapi.yaml, OUTSIDE the {repo} subrouter).

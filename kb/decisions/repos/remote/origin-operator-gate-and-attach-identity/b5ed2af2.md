# Decision (user-approved, PR #676): choosing a repo's origin is an operator act (requireOperator on every origin write and the whole origin-session wizard), and every attach runs identity checks: never another active repo's knowledge base, and never unrelated history over a main with facts unless replace_main

CONTEXT: the origin escalation (kb/incidents/repos/remote/origin-escalation/). Options weighed (the repro's list): (1) operator-gate the origin routes; (2) token-aware check: a bearer may only set an origin that does not resolve to a repo it lacks audience for (precise, but needs a URL -> local repo resolver for /git, files and aliases, easy to get wrong); (3) a self-origin URL guard (closes P2 only; DNS/alias tricks); (4) one-local-copy + unrelated-history checks in guardAttach; (5) treat the server's own /git fetches as non-loopback or require auth on loopback /git (may break local subscribe-to-self and the desktop bridge); (6) lease instead of force push (changes rewind/replay semantics). CHOSEN by the user: (1) AND (4), both in one PR. (2), (3), (5), (6) out of scope.

WHAT WAS BUILT:
(1) PUT /origin, DELETE /origin, PATCH /origin/upstream and EVERY /origin-sessions route (reads too: a session clones and PREVIEWS the remote it names) sit behind requireOperator, like the pushed-branch merge (kb/decisions/fleet/f11/ui-merge/operator-permission/d9def531.md). GET /origin stays a read. writeGate still adds `write`. Local principals keep working unchanged because loopback_default and the boot seed of the socket/pipe principal include `operator`; a bearer token needs `operator` in its approved scopes.
(4) guardAttachIdentity, called at the end of guardAttach, so EVERY AttachOrigin (PUT /origin, the wizard's shared-history commit, the fleet move/follow paths) runs it: (a) refused ErrKnowledgeBaseAlreadyLocal (409) when the remote's knomit-repo-id claim, an advertised tip another active repo holds (tipHeldLocally now excludes the attaching repo), or the ROOT COMMIT of the remote branch names another active repo; replace_main never admits this. (b) refused ErrOriginUnrelatedHistory (409) when the remote branch shares no merge base with the repo's consensus branch AND that branch holds at least one fact; admitted with the PUT body field replace_main:true (AttachOriginReplacing). A consensus branch with no fact (new repo, first origin) and an origin with no such branch (empty/backup remote) pass. The remote branch is read by remotesync.Index.ProbeBranchHistory: a fetch into a memory overlay over the store (writes nothing; store heads are offered as haves, so a related remote costs only its new commits); past [git].max_probe_bytes the attach is refused ErrOriginNotInspected (409), fail closed.

HOW IT FITS THE #524 RULING (kb/decisions/fleet/trust-the-forge-main/3a19b2d3.md; and the #544 switch decision 5269d61e): those rulings say the sync loop adopts the CHOSEN origin's main as fetched, unjudged. Untouched: no reconcile, rewind or switch code changed. The new checks run once, at attach time, and judge only whether this remote may be CHOSEN; after that its main is trusted exactly as before. Replacing main with unrelated history remains possible, as an explicit operator act rather than a side effect of re-pointing a URL.

REJECTED: fail-open on an unreadable/too-large history (the probe file's usual 'establishes nothing, refuses nothing'), because an origin of unknown identity is exactly the one this guard exists to stop. Gating only PUT and leaving the wizard on `write` (its /test and /preview read the remote's content).

REVIEW ROUND (PR #676, branch commit 859d25bd). (1) Create with an origin is gated too: POST /repos whose body carries `origin` (clone, initialize, subscribe) passes the operator gate in handleHALReposCreate; the first round left it ungated on the argument that a token reaching it already reads every repo, which the review falsified: it reads every REGISTERED repo, not an unregistered knowledge base under local_origin_root (P1 through a collection-audience write token). /repos:probe-origin and /repos:probe-initialized are gated the same way (they read a caller-named remote). Archive restore is not: it re-mounts the stored origin and chooses none. (2) PATCH /origin/upstream now runs the attach guard for the new branch (round 3, branch commit 149bd3d5), through Manager.CheckOriginBranch: a guard-only entry point, not an AttachOrigin event, so no indexing exclusivity and no Sync restart; same 409s, replace_main accepted for (b). Round 2 had kept it outside on the argument that the remote was already vetted; review B2 falsified that: the ruling 3a19b2d3 trusts the chosen origin's MAIN, the origin identity is URL-only (3b684cad), and a second branch of the same remote holding another active repo's knowledge base was adopted unchecked (two local copies, reproduced). (3) The wizard's commit-time one-local-copy re-check was removed; the attach guard is the one site.

ACCEPTED RESIDUAL RISKS (reviewed, not closed by this PR):
- N1, merge-carried history: the root layer walks FIRST parents only (RootCommit's rule, the same as create and swap). An origin whose main is a merge with this repo's main as first parent and another repo's main as second parent passes all three one-local-copy layers (no claim from plain git, a tip nobody holds, root = this repo's own) and shares history, so it is admitted and the next sync serves the other knowledge base. Same for an orphan first parent, and for a re-rooted or squashed copy when main is empty or replace_main is set. Accepted because only the operator can attach, building such a remote needs read access to the other knowledge base already, and the chosen origin's main is trusted as fetched (3a19b2d3). A later fix: refuse when ANY parentless commit of the fetched history, or any fetched commit, is held by another active repo; no history check can catch a squash.
- N2, budget bounds admission, not memory: ProbeBranchHistory counts inflated objects as they are stored; on this non-seekable fetch path go-git v5.18.0 buffers every delta's raw bytes before resolving them, so peak memory is the budget plus one object plus all deltas. Over budget is still refused (fail closed). The same weakness exists in the pre-existing create probe (budgetedStorage). A later fix: a counting PackfileWriter on the overlay, then a seekable parse.
- Time of check vs use: the check is point-in-time; the remote can change between the guard and the first sync round, and after that its content is trusted by ruling.
- N3, first-attach size: an unrelated origin (a new repo's first) is fetched whole; at the 64 MiB default that is roughly 5,000 commits of a typical knowledge base (measured: ~1,000 commits inflate to ~11 MiB). A larger one is refused "Origin not inspected" until [git].max_probe_bytes is raised (documented on config.GitConfig.MaxProbeBytes and in the PUT /origin spec). The wizard's disjoint path (SwapStore) is unaffected.

MISREADINGS: 'replace_main overrides every check': no, only (b). 'Operators can now import any knowledge base': not another ACTIVE repo's on this instance; a foreign unregistered one, yes, deliberately. 'The check makes the later sync safe': it is a point-in-time check; the remote can change before the first round (residual, accepted).

CLOSED LATER (PR #682, merge b038ab37 on dev, re-read there; src refs re-pinned to it):
- N2 is CLOSED. Both probe stores bound the raw pack before parsing (storer.PackfileWriter via remotesync.NewBudgetedPackWriter), as well as the inflated objects. This is still not a hard memory cap: one object is inflated whole before it is counted. See kb/invariants/store/remote-sync/probe-budget/2002b7ed.md.
- The replace_main identity gap (review round 1, found-not-fixed item 1) is CLOSED for the replace case: the round that force-updated main records the read branch's new root at once (kb/decisions/repos/identity/reidentify-after-rewind/20b0d973.md). An empty repo attached to an unrelated origin is NOT covered (#541).
- The PATCH /origin/upstream fall-through and compare-and-set (review round 3, item 2) are CLOSED: it answers 409 "No origin", 503 or 500 when the origin cannot be read, and 409 "Origin changed" when the vetted URL is no longer stored (kb/invariants/repos/remote/upstream-change/6a1447e1.md).
- Still open: N1 (the merge-carried history; the all-roots check is issue #677), and the UI control for replace_main.

# Decision (user-approved, PR #676): choosing a repo's origin is an operator act (requireOperator on every origin write and the whole origin-session wizard), and every attach runs identity checks: never another active repo's knowledge base, and never unrelated history over a main with facts unless replace_main

CONTEXT: the origin escalation (kb/incidents/repos/remote/origin-escalation/). Options weighed (the repro's list): (1) operator-gate the origin routes; (2) token-aware check: a bearer may only set an origin that does not resolve to a repo it lacks audience for (precise, but needs a URL -> local repo resolver for /git, files and aliases, easy to get wrong); (3) a self-origin URL guard (closes P2 only; DNS/alias tricks); (4) one-local-copy + unrelated-history checks in guardAttach; (5) treat the server's own /git fetches as non-loopback or require auth on loopback /git (may break local subscribe-to-self and the desktop bridge); (6) lease instead of force push (changes rewind/replay semantics). CHOSEN by the user: (1) AND (4), both in one PR. (2), (3), (5), (6) out of scope.

WHAT WAS BUILT:
(1) PUT /origin, DELETE /origin, PATCH /origin/upstream and EVERY /origin-sessions route (reads too: a session clones and PREVIEWS the remote it names) sit behind requireOperator, like the pushed-branch merge (kb/decisions/fleet/f11/ui-merge/operator-permission/d9def531.md). GET /origin stays a read. writeGate still adds `write`. Local principals keep working unchanged because loopback_default and the boot seed of the socket/pipe principal include `operator`; a bearer token needs `operator` in its approved scopes.
(4) guardAttachIdentity, called at the end of guardAttach, so EVERY AttachOrigin (PUT /origin, the wizard's shared-history commit, the fleet move/follow paths) runs it: (a) refused ErrKnowledgeBaseAlreadyLocal (409) when the remote's knomit-repo-id claim, an advertised tip another active repo holds (tipHeldLocally now excludes the attaching repo), or the ROOT COMMIT of the remote branch names another active repo; replace_main never admits this. (b) refused ErrOriginUnrelatedHistory (409) when the remote branch shares no merge base with the repo's consensus branch AND that branch holds at least one fact; admitted with the PUT body field replace_main:true (AttachOriginReplacing). A consensus branch with no fact (new repo, first origin) and an origin with no such branch (empty/backup remote) pass. The remote branch is read by remotesync.Index.ProbeBranchHistory: a fetch into a memory overlay over the store (writes nothing; store heads are offered as haves, so a related remote costs only its new commits); past [git].max_probe_bytes the attach is refused ErrOriginNotInspected (409), fail closed.

HOW IT FITS THE #524 RULING (kb/decisions/fleet/trust-the-forge-main/3a19b2d3.md; and the #544 switch decision 5269d61e): those rulings say the sync loop adopts the CHOSEN origin's main as fetched, unjudged. Untouched: no reconcile, rewind or switch code changed. The new checks run once, at attach time, and judge only whether this remote may be CHOSEN; after that its main is trusted exactly as before. Replacing main with unrelated history remains possible, as an explicit operator act rather than a side effect of re-pointing a URL.

REJECTED: fail-open on an unreadable/too-large history (the probe file's usual 'establishes nothing, refuses nothing'), because an origin of unknown identity is exactly the one this guard exists to stop. Gating only PUT and leaving the wizard on `write` (its /test and /preview read the remote's content).

MISREADINGS: 'replace_main overrides every check': no, only (b). 'Operators can now import any knowledge base': not another ACTIVE repo's on this instance; a foreign unregistered one, yes, deliberately. 'The check makes the later sync safe': it is a point-in-time check; the remote can change before the first round (residual, accepted).

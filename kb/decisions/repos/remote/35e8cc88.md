# Clone/InitFromRemote prefers 'main' over a remote agent-branch HEAD as the consensus upstream

When a repo is cloned with no explicit upstream branch, store.InitFromRemote resolves the consensus upstream by PREFERRING 'main' whenever the remote has it (remoteHasBranch on refs/remotes/origin/main after the wildcard fetch), falling back to the remote's symbolic HEAD (detectRemoteUpstream) only when there is no 'main', then to 'main' as a last resort. Rationale: a knomit remote's GitHub default branch can be an agent branch (e.g. knomit-kb's HEAD was agent/mindev.local-8ef0cd32); the OLD code adopted that remote HEAD as the local upstream, making another machine's agent branch the local 'consensus' — wrong, since by convention main is consensus and agent/* are per-agent. Adopting an agent branch as upstreamMain is what triggers the reconcile force-reset data-loss bug (see gotchas/repos/remote-sync). This only changes behavior when a non-main HEAD coexists with a main branch; a master-convention repo without main still uses the detected HEAD.

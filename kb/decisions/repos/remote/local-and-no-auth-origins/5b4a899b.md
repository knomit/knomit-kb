# Local-path + anonymous origins: 'none' sentinel, root-gated abs paths, auto-detect default

Decision to let knomit clone/use a local filesystem repo as origin and use remote URLs with no auth. Originally shipped in PR #84/#87; refined twice after post-PR reviews (this fact reflects the refined state at HEAD).

**Options considered:**
1. Local path format — (a) accept bare absolute paths + file://, normalizing in a helper; (b) file:// only. CHOSE (a).
2. Entry points — (a) both the New-repo Clone form and the Connect-remote wizard; (b) New-repo form only. CHOSE (a) both.
3. Anonymous semantics — (a) explicit 'None' = truly anonymous (never auto-infer SSH); (b) keep auto-detect where empty method infers SSH on git@/ssh:// URLs. CHOSE BOTH: 'none' exists AS an explicit choice, but auto-detect ('') is the DEFAULT (see refinement R2).
4. Local-origin safety — (a) accept any absolute path the web user supplies; (b) gate behind a configured root. CHOSE (b) (refinement R1).
5. WHERE to enforce the gate — (a) at each web handler edge; (b) once at the clone boundary. CHOSE (b) (refinement R3).

**Rationale (original):**
- go-git's transport.parseFile runs filepath.Abs on any scheme-less, non-SCP string, so bare absolute paths already work natively in go-git (v5.18.0). The web-layer blocker was isGitURL rejecting them; relax isGitURL to also accept filepath.IsAbs(s). Relative paths stay rejected (they'd resolve against the SERVER's cwd).
- Anonymous already works at the store layer: resolveAuth returns (nil,nil) when no creds. resolveAuthWithOrigin auto-forces SSH only when AuthMethod=='' for git@/ssh:// URLs; a 'none' sentinel forces anonymous even there. resolveAuth gains `case "", "none": return nil,nil`. No data-model change/migration — just a new recognized auth_method value.

**Refinements (post-review):**
- R1 (security): isGitURL still accepts abs paths/file:// SYNTACTICALLY, but a separate policy gate `validateLocalOrigin(url, root)` enforces that local origins resolve WITHIN config.LocalOriginRoot. Empty root (the DEFAULT) DISABLES local origins entirely — without it a web user could steer the server to clone arbitrary repos off its own disk. Config field config.LocalOriginRoot, toml `local_origin_root`, env KNOMIT_LOCAL_ORIGIN_ROOT, tilde-expanded.
- R2 (default): both web forms now DEFAULT to auto-detect (''), NOT 'none'. The earlier default-'none' broke the common git@github SSH case (it disabled resolveAuthWithOrigin's auto-promotion, so a pasted SSH URL silently failed anonymous). 'none' is now an explicit, secondary choice for forcing anonymous on an SSH-style URL. RemoteConnectWizard authMethod type is `'' | 'none' | 'ssh' | 'token' | 'basic'` default ''; handleTest sends `authMethod || undefined` so '' is omitted and the backend auto-promotes. Prefill restores a stored 'none' too.
- R3 (altitude + symlink hardening, second review): the gate moved OUT of the web edge DOWN to the clone boundary in package `repos`. `validateLocalOrigin`/`localOriginPath` now live in internal/repos/origin.go (NOT internal/web/helpers.go). Enforcement: `Manager.ResolveAuth` calls the gate, which covers BOTH immediate-clone paths in ONE place (repo-create via lifecycle, and origin-session /test) since both resolve auth right before cloning. The one DEFERRED-clone path — PUT /origin (SetOrigin) persists a URL the sync loop clones later, NOT via ResolveAuth — keeps a WRITE-TIME check via `Manager.ValidateLocalOrigin` wired into defaultOriginProvider. Server.LocalOriginRoot and the three threaded handler params were REMOVED; the Manager reads the root from deps.Cfg.LocalOriginRoot. Out-of-root local origins now surface at clone time (NDJSON/SSE error phase) instead of the initial request. Containment is now checked against SYMLINK-RESOLVED real paths (resolveSymlinks → filepath.EvalSymlinks, resolving the longest existing prefix so intermediate symlinks are followed): a purely lexical filepath.Rel check let a symlink INSIDE the root that points outside it escape, because go-git follows symlinks when cloning. A residual TOCTOU window (re-point between check and clone) is accepted. DELIBERATELY NOT gated: admin-configured origins (cfg.Git.Origin via builder) and the background sync loop resolve auth through the internal resolveAuthWithOrigin free function (NOT Manager.ResolveAuth), so trusted config paths are unchanged.

**The choice:** (1) isGitURL accepts absolute local paths syntactically; (2) validateLocalOrigin (in internal/repos/origin.go) gates them by config.LocalOriginRoot, symlink-resolving before the containment check; (3) the gate is enforced at the clone boundary — Manager.ResolveAuth for immediate clones, Manager.ValidateLocalOrigin at write time for the deferred PUT /origin path — NOT scattered across web handlers; (4) resolveAuth has `case "", "none"`; (5) both web forms default to auto-detect '' and expose 'none' as an explicit anonymous override.

# Local-path + anonymous origins: 'none' sentinel, root-gated abs paths, auto-detect default

Decision to let knomit clone/use a local filesystem repo as origin and use remote URLs with no auth. Originally shipped in PR #84/#87; refined repeatedly after post-PR reviews.

**Options considered:**
1. Local path format — (a) accept bare absolute paths + file://, normalizing in a helper; (b) file:// only. CHOSE (a).
2. Entry points — (a) both the New-repo Clone form and the Connect-remote wizard; (b) New-repo form only. CHOSE (a) both.
3. Anonymous semantics — (a) explicit 'None' = truly anonymous (never auto-infer SSH); (b) keep auto-detect where empty method infers SSH on git@/ssh:// URLs. CHOSE BOTH: 'none' exists AS an explicit choice, but auto-detect ('') is the DEFAULT (see refinement R2).
4. Local-origin safety — (a) accept any absolute path the web user supplies; (b) gate behind a configured root. CHOSE (b) (refinement R1).
5. WHERE to enforce the gate — (a) at each web handler edge; (b) once at the clone boundary; (c) at EVERY origin entry point uniformly. CHOSE (b) then (c) (refinements R3, R4).

**Rationale (original):**
- go-git's transport.parseFile runs filepath.Abs on any scheme-less, non-SCP string, so bare absolute paths already work natively in go-git (v5.18.0). The web-layer blocker was isGitURL rejecting them; relax isGitURL to also accept filepath.IsAbs(s).
- Anonymous already works at the store layer: resolveAuth returns (nil,nil) when no creds. resolveAuthWithOrigin auto-forces SSH only when AuthMethod=='' for git@/ssh:// URLs; a 'none' sentinel forces anonymous even there. resolveAuth gains `case "", "none": return nil,nil`. No data-model change/migration — just a new recognized auth_method value.

**Refinements (post-review):**

- **R1 (security):** isGitURL still accepts abs paths/file:// SYNTACTICALLY, but a separate policy gate `validateLocalOrigin(url, root)` enforces that local origins resolve WITHIN config.LocalOriginRoot. Empty root (the DEFAULT) DISABLES local origins entirely. Config field config.LocalOriginRoot, toml `local_origin_root`, env KNOMIT_LOCAL_ORIGIN_ROOT, tilde-expanded.

- **R2 (default):** both web forms DEFAULT to auto-detect (''), NOT 'none'. The earlier default-'none' broke the common git@github SSH case (it disabled resolveAuthWithOrigin's auto-promotion, so a pasted SSH URL silently failed anonymous). 'none' is now an explicit, secondary choice for forcing anonymous on an SSH-style URL. RemoteConnectWizard authMethod type is `'' | 'none' | 'ssh' | 'token' | 'basic'` default ''; handleTest sends `authMethod || undefined` so '' is omitted and the backend auto-promotes. Prefill restores a stored 'none' too.

- **R3 (altitude + symlink hardening, second review):** the gate moved OUT of the web edge DOWN to the clone boundary in package `repos`. `validateLocalOrigin`/`localOriginPath` live in internal/repos/origin.go (NOT internal/web/helpers.go). localOriginPath delegates classification to go-git's own transport.NewEndpoint — the SAME parser the cloner uses — so the gate can never disagree with what go-git actually clones (only Protocol=="file" is treated as local; network origins pass through). Server.LocalOriginRoot and the threaded handler params were REMOVED; the Manager reads the root from deps.Cfg.LocalOriginRoot. Containment is checked against SYMLINK-RESOLVED real paths (resolveSymlinks → filepath.EvalSymlinks, resolving the longest existing prefix so intermediate symlinks are followed): a purely lexical filepath.Rel check let a symlink INSIDE the root that points outside it escape, because go-git follows symlinks when cloning. A residual TOCTOU window (re-point between check and clone) is accepted.

- **R4 (ABSOLUTE & UNIFORM gate, third review — PR #87 final):** the gate is enforced at EVERY origin entry point, including the previously-exempt trusted paths. SUPERSEDES the earlier R3 statement that admin-configured origins and the background sync loop were deliberately ungated — that exemption is GONE. A filesystem origin is permitted only inside LocalOriginRoot, full stop: unavailable everywhere (API, UI, AND operator config) when the root is unset.

**The enforcement points AS THEY EXIST AT HEAD (commit 4baae4ed) — FIVE, all calling validateLocalOrigin against cfg.LocalOriginRoot:**
1. `Manager.ResolveAuth` (manager.go) — immediate clones (repo create via initClone, origin-session /test).
2. `Manager.ValidateLocalOrigin` (origin.go), called by handlers_origin_hal — write-time for the deferred PUT /origin path.
3. `repoBuilder.build`'s sync-activation path (builder.go) — re-asserts before the synchronous reconcile and before teardown, so a now-forbidden stored origin is rejected without orphaning a running loop.
4. `repoBuilder.recoverFromOrigin` (builder.go) — the startup reconcile (LOG-AND-SKIP, fail-open).
5. `runReconcileLoop` (sync.go) — re-checked EVERY tick (defense-in-depth: policy or an in-root symlink can change after the URL was written).

Runtime fails open so a config tightening does not tear down an already-serving repo.

- **R5 (basic-auth credential plumbing, same review):** basic auth carries credentials as 'user:password' in the SINGLE auth_token field/column — the convention assembleAuthToken produces and remoteAuthFromRecord splits via strings.SplitN(...,2). authConfigFromSpec ALSO splits user:password (strings.Cut) for the IMMEDIATE clone; previously it set Password=token with an empty Username, so a basic-auth clone via repo-create always failed against real hosts (GitHub/GitLab reject an empty username). CreateRepoForm gained a dedicated Username field for basic and BLOCKS submit (disabled Create button + inline 'Basic auth requires a username' hint) until a username is supplied, so it can never send a colon-less token the backend would read as an empty-username credential. token auth is unaffected (resolveAuth defaults Username to 'x-token').

**WHAT THIS DOES NOT MEAN.** *Not* "there are six gates, one of them `repoBuilder.initDefaultGit`, and boot fails closed." This decision said exactly that until this audit, and it is FALSE at HEAD: `initDefaultGit` NO LONGER EXISTS, and neither does the operator-configured origin it gated — `internal/config` has no `Git.Origin` field at all, so there is no first-boot clone to fail closed on. Origins are attached PER-REPO (`CreateSpec.Origin`) or afterwards. The gate did not go missing; the entry point was removed along with the feature. See [[no-default-repo]] (kb/invariants/repos/no-default-repo/1fd5dad8.md) and the invariant [[local-origin-gate]] (kb/invariants/repos/remote/local-origin-gate/426d64a7.md), which carries the authoritative enumeration.

**The choice:** (1) isGitURL accepts absolute local paths syntactically; (2) validateLocalOrigin (internal/repos/origin.go, classifying via go-git transport.NewEndpoint) gates them by config.LocalOriginRoot, symlink-resolving before the containment check; (3) the gate is ABSOLUTE and enforced at every origin entry point that exists, fail-open at runtime; (4) resolveAuth has `case "", "none"`; (5) both web forms default to auto-detect '' and expose 'none' as an explicit anonymous override; (6) basic auth plumbs 'user:password' through the single auth_token column end-to-end, and CreateRepoForm requires a username before allowing submit.

# Support local-path + anonymous origins via a 'none' auth sentinel and abs-path acceptance in isGitURL

Decision to let knomit clone/use a local filesystem repo as origin and use remote URLs with no auth.

**Options considered:**
1. Local path format — (a) accept bare absolute paths + file://, normalizing in a helper; (b) file:// only. CHOSE (a).
2. Entry points — (a) both the New-repo Clone form and the Connect-remote wizard; (b) New-repo form only. CHOSE (a) both.
3. Anonymous semantics — (a) explicit 'None' = truly anonymous (never auto-infer SSH); (b) keep current auto-detect where empty method forces SSH on git@/ssh:// URLs. CHOSE (a).

**Rationale:**
- go-git's transport.parseFile runs filepath.Abs on any scheme-less, non-SCP string, so bare absolute paths already work natively in go-git (v5.18.0). The ONLY web-layer blocker was isGitURL rejecting them. So the fix is to relax isGitURL to also accept filepath.IsAbs(s); relative paths stay rejected because they'd resolve against the SERVER's cwd (surprising).
- Anonymous already works at the store layer: resolveAuth returns (nil,nil) when no creds. The gap was (i) resolveAuthWithOrigin auto-forcing SSH when AuthMethod=='' for git@/ssh:// URLs, and (ii) CreateRepoForm having no 'None' option (defaulted to 'token'). The Connect-remote wizard already had 'None' but sent '' (=auto), which would auto-SSH.
- Chose a NEW 'none' sentinel rather than overloading '': '' stays = auto-detect (backward compatible with stored remotes + existing tests); 'none' = force anonymous. resolveAuthWithOrigin's `if cfg.AuthMethod == ""` guard already leaves 'none' untouched. No data-model change, no migration — just a new recognized value of the existing auth_method string.

**The choice:** (1) isGitURL also accepts absolute local paths; (2) resolveAuth gains `case "none": return nil,nil`; (3) both web forms expose a 'None' option whose value is the 'none' sentinel (CreateRepoForm defaults to it), with placeholders hinting local paths.

# Separate the background index-heal lifecycle from the reconcile-loop lifecycle (own ctx + waitgroup)

When a repo is created at runtime via clone (Manager.Create, mode=clone), the background index heal launched by openOne was being killed by the immediately-following ri.ActivateSync. Both shared one syncCtx/syncWg: startSync calls syncCancel()+syncWg.Wait() to restart the reconcile loop, which cancelled the heal's context. The heal goroutine then hit `if b.syncCtx.Err() != nil { return }` (manager.go) and exited WITHOUT markIndexReady/markIndexFailed, pinning IndexStatus at "indexing" (done=0/total=0) forever. Restarting the server fixed it because Start/Rescan open repos via openOne only — no inline ActivateSync — so the heal ran to completion. Reliable to reproduce because a many-commit clone's embed takes far longer than the gap between Add returning and ActivateSync firing.

Options considered (AskUserQuestion):
1. Separate heal lifecycle — give the heal its own cancellation (indexCtx) + waitgroup (indexWg), cancelled only on real teardown (shutdown/Close/Archive/SwapStore); startSync/DeactivateSync touch only the loop's syncCtx/syncWg. CHOSEN.
2. Defer sync to post-heal (drop inline ActivateSync) — loses Create's synchronous bad-token feedback.
3. ActivateSync waits for heal — blocks the create request until the full index build finishes, defeating the fast-UI design.

Rationale: option 1 keeps the open->fast-UI contract AND synchronous credential feedback, and respects the existing teardown invariant. Every site that waits before svc.Close must now wait BOTH indexWg and syncWg; wait indexWg BEFORE syncWg because the heal's activate() does syncWg.Add(1) for the loop, so indexWg.Wait() must complete before syncWg.Wait() to avoid the wait counter transiently hitting zero. startSync's loop-restart cancel must no longer reach the heal — that is the load-bearing change.

Teardown sites to update: RepoInstance.shutdown (Archive), Manager.Close, SwapStore. Loop-only cancels that must NOT touch the heal: builder startSync, DeactivateSync.

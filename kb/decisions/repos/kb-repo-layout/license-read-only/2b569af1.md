# LICENSE at the KB repo root is READ and exposed only — no write path, no seeding, no OKF export, and rendered preformatted rather than as markdown

A KB repo's content needs stated terms in the file a git host and a human both already look for. A `LICENSE` file at root is already inert to every code path — not `.md`, not under the ontology root — so 'support LICENSE' had to mean something active.

**Options considered.** (a) Read it and expose it on the API/UI. (b) Seed one at repo creation via a license picker. (c) Full editable round-trip like the README, with its own byte cap. (d) Carry it into the OKF export as bundle-level metadata so federated facts travel with their terms.

**Rationale.** (a) alone was chosen. A licence is authored by whoever owns the repo; knomit reports it rather than offering to write one, which keeps knomit out of the business of generating legal text. (b), (c) and (d) were all explicitly declined for now — none is blocked by this decision, they were simply not the ask.

**The choice.** `LicensePath = "LICENSE"`, `ReadLicense(ctx)` mirroring `ReadReadme` — verbatim content at the agent-branch tip, missing returns `("", nil)`. Surfaced as a `license` field on the SINGLE-REPO GET only, matching how `description` is already scoped; the repo LIST stays a cheap index and must not grow a second per-repo git read. `MaxRepoDescriptionBytes` (64KB) is reused as a RESPONSE guard, not an input check — there is no write path to reject on, and GPL-3 at ~35KB leaves ample headroom.

**The detail that separates a correct implementation from a plausible one.** The UI must render LICENSE as preformatted text, NOT markdown. A markdown renderer reflows single newlines, so the MIT text loses every line break.

**Non-scope.** Read-only is a statement about knomit's write surface, not about the file's importance. Adding OKF export or repo-creation seeding later does not contradict this decision — it extends it.

# LICENSE at the KB repo root was READ-only from PR #68 through PR #91 — SUPERSEDED: a write path landed (see license-write-path/401a296b.md); still rendered preformatted, never markdown

SUPERSEDED as of the LICENSE write path (`kb/decisions/repos/kb-repo-layout/license-write-path/401a296b.md`). The claims below describe the ORIGINAL decision and are kept for historical rationale — they are no longer true of the current code and must not be read as current behavior. In particular: LICENSE now HAS a write path (`WriteLicense`/`WriteRootFile`, PATCH via `patchRepoRequest.License`), `MaxRepoDescriptionBytes` is now an INPUT check for LICENSE too (not just a response guard), and the two source comments this fact's rationale depended on (`internal/repos/manifest.go`'s "read-only by design", `web/src/RepoManager.tsx`'s `if (license)` guard, `web/src/ManageOverview.tsx`'s "Deliberately NOT here" note) have all been corrected to describe the write path.

What is STILL true: LICENSE is surfaced on the single-repo GET only (never the list), and the UI renders it preformatted (`<pre>`), never through the markdown pipeline — a licence's single newlines are meaningful and markdown reflows them away. That rendering rule is unchanged and is now more exposed, since an editor makes "just reuse the Description block" a tempting (wrong) shortcut.

--- ORIGINAL DECISION (historical, options/rationale as they stood before the write path) ---

A KB repo's content needs stated terms in the file a git host and a human both already look for. A `LICENSE` file at root is already inert to every code path — not `.md`, not under the ontology root — so 'support LICENSE' had to mean something active.

**Options considered.** (a) Read it and expose it on the API/UI. (b) Seed one at repo creation via a license picker. (c) Full editable round-trip like the README, with its own byte cap. (d) Carry it into the OKF export as bundle-level metadata so federated facts travel with their terms.

**Rationale at the time.** (a) alone was chosen. A licence is authored by whoever owns the repo; knomit reports it rather than offering to write one, which keeps knomit out of the business of generating legal text. (b) and (d) remain declined. (c) is what `license-write-path/401a296b.md` later did — declining it was never a hard block, per this fact's own Non-scope note below.

**The choice (as originally shipped).** `LicensePath = "LICENSE"`, `ReadLicense(ctx)` mirroring `ReadReadme` — verbatim content at the agent-branch tip, missing returns `("", nil)`. Surfaced as a `license` field on the SINGLE-REPO GET only, matching how `description` is already scoped.

**Non-scope (as originally written — this is the note that authorized the later extension).** Read-only is a statement about knomit's write surface, not about the file's importance. Adding OKF export or repo-creation seeding later does not contradict this decision — it extends it.

# LICENSE gains a write path — a BLANK editor, never a template picker; this extends the read-only decision rather than reversing it

**The choice.** `WriteLicense` mirrors `WriteReadme` exactly (same `WriteRootFile` primitive, same 64 KiB cap, same read-compare-write skip so a byte-identical save makes no empty commit, commit subject `docs: update LICENSE`). `patchRepoRequest` gains `License *string` with the pointer semantics `Description` already has: omitted = leave alone, `""` = empty the file. The UI shows the License block whenever there is something to read OR the user could write one, with an **Add** action on an absent licence that opens a BLANK editor.

**Relationship to the prior decision.** `kb/decisions/repos/kb-repo-layout/license-read-only/2b569af1.md` chose "read and expose only" and explicitly declined "(c) full editable round-trip like the README, with its own byte cap". This does (c). That is an EXTENSION, not a reversal: that decision's own Non-scope says read-only "is a statement about knomit's write surface, not about the file's importance", and of the declined options that "none is blocked by this decision, they were simply not the ask." They are now the ask.

**The part of the old rationale that still binds.** Its reason for declining option (b), a license picker, was to keep knomit "out of the business of generating legal text." That still holds and is why the editor starts BLANK — no template dropdown, no bundled MIT/Apache/GPL texts. The user brings their own terms. A future template picker would be a new decision, not an implementation detail of this one.

**What goes stale in the old fact.** Two of its claims: that there is no write path, and that `MaxRepoDescriptionBytes` is a RESPONSE guard for LICENSE "because there is no write path to reject on." It now serves as an input check as well. Three source comments existed only to explain the missing write path and must be corrected rather than left to mislead: `internal/repos/manifest.go` (LicensePath's "read-only by design"), `web/src/RepoManager.tsx` (the `if (license)` guard's rationale), and `web/src/ManageOverview.tsx` ("Deliberately NOT here: a 'no licence' check").

**The detail that separates a correct implementation from a plausible one — unchanged and now MORE exposed.** LICENSE renders preformatted, NEVER markdown: a markdown renderer reflows single newlines and the MIT text loses every line break. Adding an editor makes this easier to get wrong, because the obvious move is to reuse the Description block wholesale — and Description's non-editing view renders markdown. Reuse `useDescriptionEditor` (the draft hook, whose textarea is already monospace) but keep the read view as `<pre>`.

**Why the write is safe for the index.** LICENSE sits at the tree root, outside the ontology root, so index membership rules exclude it: writing it moves the file and its commit-log row, never the fact index or the fact-commits history UI.

**Non-scope.** Not authorized by this: seeding a licence at repo creation, carrying LICENSE into the OKF export, widening `LicensePath` beyond the single exact spelling `LICENSE` (still no `License`, `LICENSE.md`, `LICENSE.txt` or `COPYING`), or a "no licence" attention row on the Manage overview — a local-only KB with no stated terms is a legitimate steady state.

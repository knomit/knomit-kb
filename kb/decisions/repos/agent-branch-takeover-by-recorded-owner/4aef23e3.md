# On agent-branch change, take over the repo by seeding from the recorded owner — never from HEAD

The agent branch name is agent/<hostname>-<key-fingerprint> (app.agentBranch, internal/app/identity.go). It is PER-AGENT BY DESIGN and moves when the SSH key is regenerated OR the machine is renamed. knomit is a distributed system: multiple agents work the same repo, each writes its own agent branch, and branches converge through the shared origin. Other agents' branches are present LOCALLY (in refs/heads, fetched from origin), not just as remote-tracking refs. When this instance's derived name changes, its configured branch is absent and every write path breaks (HeadCommit -> resolveRef -> branch not found) — issue #32.

**Options considered** for the seed source when the configured agent branch is absent: (a) seed from the repo's git HEAD branch [this was PR #35, now REVERTED]; (b) seed from a branch recorded in the DB as the repo's owner [PR #39, chosen]; (c) seed from upstream main [rejected: local-only repos have main at the init commit, so it discards all accumulated facts].

**Rationale — why NOT HEAD (why #35 was wrong):** because agents share a repo through origin and their branches land in refs/heads, HEAD does not reliably identify the branch THIS database writes to. Seeding from HEAD can fork the instance off ANOTHER agent's lineage — silent and wrong, with no restore scenario involved. #35 needed a whole apparatus (alignHeadWithAgentBranch repointing HEAD on every boot, a chained-restore argument, an 'HEAD == this machine's agent branch' invariant) purely to keep its own HEAD-based seed lookup trustworthy. That apparatus was self-referential: nothing else in knomit reads local HEAD. Verified by test: TestEnsureBranch_DoesNotTakeOverAnotherAgentsBranch parks HEAD on a foreign agent's branch and FAILS against #35's logic, passes under #39.

**The choice (#39):** each repo DB records its owning agent branch in a meta row, key agent_branch_owner (store.AgentBranchOwner / SetAgentBranchOwner in internal/store/branch.go). seedSourceForAgentBranch(): if the configured agent branch exists -> return it (CreateBranch no-ops); else read the recorded owner -> if it exists, TAKE OVER by seeding the new branch from it (CreateBranch clones git ref + branch_commits + branch_facts) and recordAgentBranchOwner then claims ownership. HEAD is NO LONGER load-bearing — all alignHeadWithAgentBranch / SetDefaultBranch machinery is deleted. ensureBranch still runs BEFORE loadOntology in Manager.openOne so the taken-over branch exists before its ontology is read.

**Fail loudly, don't guess:** when there is no usable record (none stored, it names the missing branch itself, or the branch it names is gone), fall back to the agent branch itself so CreateBranch fails loudly rather than seeding from a guess. Recovery is git's job: origin is the source of truth and re-cloning rebuilds the DB. Tests: TestEnsureBranch_NoRecordedOwnerFailsLoudly (also asserts the repo still OPENS after a failed takeover), TestEnsureBranch_AdoptsAgentBranchOnRestoredHome, TestEnsureBranch_ChainedRestoreAdoptsMostRecentBranch.

**Non-scope / boundary (the user's explicit 'this is where it has to stop'):** the ONLY supported takeover is 'derived name no longer matches -> create a NEW branch seeded from the recorded owner and claim it.' Moving repo DBs between machines is NOT a common supported path (git is the source of truth; pointing at origin recreates the DB). This decision does NOT add: local reconciliation of diverged sibling agent branches (that is what origin/sync is for — divergence between per-identity branches is by design, not a bug; this is why issues #36/#37/#38 were closed), ancestry checks, branch GC, or any remote-facing behavior (push/sync address the agent ref by name and never consult HEAD). The retained previous branch is left in place, not garbage-collected.

# A repo keeps its consensus branch when its origin is removed: the name is recorded in the repo database and read back, never defaulted to a hardcoded "main" — chosen over documenting the knomit-hosted route as main-only

THE USER (2026-09-30, verbatim): "Hardcoded values are never good" and ""hardcoded main" - agreed with your proposed solution." This extends the standing F08 addendum ("when you say "main" what are you referring to, the branch that is marked as the consensus per repo, correct ? Not something hardcoded "main"").

THE PROBLEM (review of F08 PR D, blocker B1): store.Service.UpstreamBranch answered a literal "main" for any repo with no origin row, so the mission README's knomit-hosted route (clone a trunk or master repository, DELETE its origin) switched the host to a zero-tip main: skills, recipes and settings read from nothing, peers failed to clone.

OPTIONS: (a) fix the product: record the consensus branch with the repo; (b) document that the knomit-hosted route requires a branch named main.

THE CHOICE: (a), in PR D itself (#358 → 771967d2). The name lives in the repo database's meta table (key consensus_branch): written by local init, clone, subscription and every SetOrigin with a branch; UpstreamBranch returns the origin's branch, else the recorded one; a legacy repo resolves its single non-agent/exp/okf branch and records it. Pinned by cmd/mission_route_test.go (the README route on trunk and master, host restart included) and TestConsensusBranch_RecordedNotDefaulted.

REJECTED: (b) documenting main-only.

FOLLOW-UPS (not done, stated): the other literal "main" defaults in the code (InitRepo's default created name, empty-name defaults in the sync/reconcile paths, resolveUpstream's preference, repos/fleet.go, repos/origins.go, the web origin handlers, store/replay.go); and DELETE origin starts no local reconcile loop until the repo reopens (kb/gotchas/repos/origin/detach-starts-no-local-loop).

# D1: knomit code chooses no take strategy; the mission template ships BOTH patterns as examples — claim/wait/take (a heuristic plus the dup-check backstop) and host-awarded exactly-once — and the operator ("coder") picks one

THE USER (2026-09-29, verbatim, D1): "1) yes, we have all the primitives to implement both so it will be up to the "coder" to decide the pattern they want to follow."

OPTIONS: (a) the claim/wait/take heuristic only (the RCA's recommendation: announce, wait X, the first by rank takes with the F04 move, losers wait, a duplicate check afterwards); (b) exactly-once by letting one instance (normally the host) decide and hand out awards, which makes it a leader in effect and costs a round trip; (c) build a take strategy into knomit.

THE CHOICE: both (a) and (b), as template files only, no code (examples/mission/, F08 PR D #358 → 771967d2). claims.js: rank by FNV-1a of task|agent-id with the agent id as a total tie-break; the winner's take is one knomit.learn with retract (working copy + task + own and dead claims); losers re-arm; a claim more than 2X past its expires stops ranking (the re-offer); dup-check undoes a double take. awards.js: the award trigger matches bids/{agent}/**, so only the awarder writes awards, and each award is the F04 move 'write the award, retract the offer', so a second award for the offer is refused under the awarder's branch lock. The README gives the trade-off table (guarantee, latency, what each needs).

RELATED RULINGS the template honours (verbatim in the RCA brief, .claude/plans/2026-09-29-rca-brief-F08-mission-repo.md): R1 composition, not implementations ("I do not want specific implemntations, I want generic operations that can be composed.") — the template is ontology + triggers + skills + a recipe, no Go; R2 expiry is a script ("A) a script." → "A) ok") — the inline `expire`/`expire-offer` triggers; R4 mission repo = coordination repo, separate from knowledge KBs, waking composable ("D) ok", "C) ok") — `wake` is do: run of the work-task recipe.

REJECTED: (c) a built-in take strategy; shipping only one pattern.

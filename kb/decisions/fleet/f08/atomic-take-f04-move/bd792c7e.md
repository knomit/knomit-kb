# F04 ships inside F08 as an atomic learn+retract (`retract` on knomit_learn and knomit.learn) — atomic per BRANCH, never exclusive across agents

User ruling R3 (2026-09-29, verbatim from the F08 RCA brief): "B) Yes, it should." (F04 inside F08) and "For specifically assigned tasks (for a specific agent) that will not happen. For generally available tasks, isn't there a way to coordinate - like announce my intention to grab a task, wait X seconds / minutes or wait for Y acks, then pick it up ?" → "B) this is the atomic learn and retract we're adding now, correct ?" (answered yes).

OPTIONS CONSIDERED
- Where F04 lives: (A) F04 stays a separate, later feature; (B) build it inside F08 now. CHOSEN (B).
- How "take" is made atomic: an existence check before the write, as knomit_retract does (REJECTED: outside the branch lock, so it goes stale — two local takes both commit, because a delete of an absent leaf is silently accepted); vs a precondition checked INSIDE the branch write lock (CHOSEN: store.BatchWriteFactsMustExist → *RetractMissingError, nothing written).
- Surface: MCP knomit_learn + script host knomit.learn (CHOSEN); a REST batch route (REJECTED: no REST batch-learn exists; F04's own proposal already allowed MCP-only).
- A path both written and retracted: delete wins silently (REJECTED) vs refused (CHOSEN); dedup folding into a retracted path (REJECTED: excluded).

RATIONALE
The move is the one missing primitive the claim protocol needs (R1: generic operations, composed). One commit makes the working copy and the task's removal land together or not at all, and the under-the-lock precondition makes two takes on one branch serialise.

THE CHOICE
`retract: [paths]` on knomit_learn (operation `move`, or `retract` with `facts: []`) and `knomit.learn(facts, {retract})` on the script host, merged in PR #348 (merge commit 53d102e9).

NON-SCOPE — what this does NOT mean: it is atomic per BRANCH only, NOT exclusive across agents. Two agents on two branches can both move the same task; their deletions merge clean (delete/delete) and both working copies survive. Cross-agent exclusivity exists nowhere in knomit. The claim protocol (announce, wait X, decide by rank, backstop) is a heuristic plus a backstop built on top of this primitive, in the template (PR D), not in code.

THE PROBLEM. A `do: run` wake that finds the recipe at its `concurrent` limit is dropped as `busy` with no queue, and only due fires are retried (N3 in the #383 live check); claims.js checked CAPACITY only at claim time; the session could reach only the mission repo (recipe MCP = `kb --repo <mission>`) and inherited the user's MCP servers.

OPTIONS CONSIDERED
- Gap 1, dropped wakes: (A) the session drains the inbox and a due-trigger lease re-wakes a session for a copy still there — CHOSEN; (B) a knomit change so busy learn/run fires are retried or queued — REJECTED (programming knomit with what exists beats a new primitive; due fires are already retried as re-derived state).
- Gap 2, capacity: re-check the backlog in decide() before taking — CHOSEN; refusing an award in takeAward — REJECTED by the coordinator (the offer is already retracted, so refusal loses the task; an over-capacity award is backlog).
- Gap 3, re-offer: knomit-side re-offer (a script that re-posts untaken or failed tasks) — REJECTED; the coordinator re-offers by posting under a new task id in one move.
- Gaps 4/5, session reach: a BOUND recipe server (`kb --repo`/`--lens`, or several bound servers) — REJECTED; an UNBOUND `kb` with dynamic knomit_bind of the mission repo and the task's knowledge base, --strict-mcp-config, a temporary cwd, and one knomit_experiment per task on the KB handle — CHOSEN.
- Per-copy exclusivity (coordinator, after the reviewer's phase-1 plan): pin concurrent: 1 — REJECTED; take each copy with an atomic move working/ -> active/ so a second session is refused and concurrent > 1 is safe — CHOSEN.

THE CHOICE, as built in #388 (merge 56da0d0e): the work-task skill drains inbox/<agent>/working/; every inbox copy carries an expires LEASE (validated); the `lease` trigger (on: due, inbox/{agent}/**, do: run) re-wakes; the recipe re-arms the woken copy's lease to the session's end; decide() withdraws when the backlog (working + active) is full; takeAward always takes; the recipe derives the mission repo from mcp.config args, starts `kb` unbound with --strict-mcp-config, allowed tools mcp__knomit,WebFetch,WebSearch, --max-budget-usd, in a fresh mktemp -d.

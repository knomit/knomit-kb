# The 'processed once' mark for `on: due` is a dispatcher table trigger_due_fires keyed (branch, trigger, path) + the due instant (migration 000030), not a fired_at column on fact_expires and not per-fact-version keying; the migration-budget argument was moot ('no one is using that table yet … Change away.') and the per-trigger, per-instant key won on semantics

OPTIONS (F07 PR 2 RCA D1, 2026-09-28). (A) the design's literal shape: a fired_at column on fact_expires — per fact VERSION, per instance, trigger-agnostic; two `due` triggers on one fact share a mark; a `due` trigger declared later never fires for already-marked facts; ANY edit (a typo fix) mints a new version with fired_at NULL and re-fires; and a rebuild's INSERT OR REPLACE of fact_expires would wipe it (the reviewer's P8). The RCA also argued the ADD COLUMN budget was spent (the migration recovery path tolerates one duplicate-column collision, 000019 used it). (B) a new dispatcher table trigger_due_fires(branch, trigger, path, expires_at, fired_at, PRIMARY KEY(branch, trigger, path)) — per (trigger, path, due instant): fires once per trigger per due date; body-only edits do not re-fire; changing `expires` re-arms (the design's words); each `due` trigger keeps its own marks like the bookmarks; dispatcher state in the dispatcher's own tables (the 1b rule); the key starts with branch so the per-run read is an index range. The reviewer's own fact_due(fact_id) proposal was withdrawn in the critique in favour of (B).

RATIONALE: (B) has the fewest surprises and is truer to 'changing expires re-arms'; a mark means PROCESSED whatever `if` said (M2), or an if-false fact would be re-evaluated every run forever.

CHOICE (maintainer, verbatim): "no one is using that table yet, we have not completed building the feature. Change away." — the F03 table MAY be changed freely, so the migration-budget argument is moot; the mark is nevertheless keyed per (branch, trigger, path, due instant) in the dispatcher table trigger_due_fires, migration number whatever is free (000030). Built in #337.

NON-SCOPE: 'change away' does not mean fact_expires was changed — it was not; it means the budget argument no longer constrains a future change to it. Sibling ruling: decisions/fleet/f07-triggers/due-live-facts-only.

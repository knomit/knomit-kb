# F07 PR 3 (D-mint): only the commits a SCRIPT makes carry the causal-trace trailers; human, session, REST and review-pipeline writes get none, and a fire's trace is derived (trailer → task id → firing commit), never minted as a random id

Ruling, verbatim (maintainer, 2026-09-28): "D-mint: agreed, no."

Options considered:
- (a, chosen) Stamp only script writes. The fire's trace is derived by the dispatcher: the firing commit's Knomit-Trace if it has one, else the task id when the firing fact is an F01 task (a pragmatic `signal` with one entity), else the firing commit's own hash. A story rooted in a human write is then found in `git log` by that write's hash, which the first script commit names as both its trace and its cause.
- (b, rejected) The design's letter now: every uncaused knomit write (MCP, REST, synthesize/review) mints a trace and every commit gains a `Knomit-Trace:` line in every KB from this PR on.

Rationale: (b) changes what `git log` shows on every KB for every write, and joining an existing story from an MCP session only arrives with PR 5 either way. (a) gives each cause one deterministic story id on every machine and on every re-fire, with no generator.

Consequences: `store.WithTrailers` is set only by the script host (internal/repos/trigger_script.go); the write path mints nothing. `change.trace` and the fire-log `trace` are never empty since PR 3.

Non-scope: this does not forbid minting for session writes later. That is PR 5's MCP session/argument path, a separate decision.

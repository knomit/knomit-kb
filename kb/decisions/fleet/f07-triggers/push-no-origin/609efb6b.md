# D-local: on a repo with no origin a push fire wakes the LOCAL loop (main catches up with this machine's own writes ~1 s after the write), outcome `kicked` — not a no-op recorded as `no-origin`

User ruling (2026-09-28, verbatim): "1) yes." — the answer to 'when a repo has no origin, should a push trigger make this machine's main catch up at once?'.

Options considered:
(a) CHOSEN — the push wake also wakes the origin-less local loop: after the 1 s countdown it runs the ticker's body (kickTriggers, ownsMain with its exit on a definite origin, AdvanceLocalUpstream). No network cost; one outcome (`kicked`); no 'is a loop listening' state. Matters most for an F11 host, which usually has no origin and whose main is what peers fetch.
(b) REJECTED — a no-op recorded as `no-origin`: needs an atomic 'remote loop running' flag on the instance, a second outcome and a `no_origin` counter on the endpoint, for no gain.

Non-scope: main follows only THIS machine's agent branch; the wake never publishes facts other machines pushed here any sooner.

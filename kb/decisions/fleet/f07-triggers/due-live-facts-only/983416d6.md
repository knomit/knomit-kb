# A `due` trigger fires only for facts still ALIVE on the observed branch at HEAD: the sweep's candidates are the liveness join branch_facts(agent) ⋈ fact_expires, confirmed at the HEAD tree; rejected sweeping fact_expires alone and a literal 'the table holds only live rows' that F03's shared per-version table cannot provide

OPTIONS (F07 PR 2 RCA, 2026-09-28). The design's first wording said 'the fact_expires table holds rows only for facts live at HEAD of the observed branch and is kept in sync by every path that removes or replaces a fact'. The RCA and the reviewer's independent probes both found that this letter cannot be made true: fact_expires is keyed by the content-addressed facts row (one row per dated fact VERSION, shared by main, the agent branch and exp/*, orphans never collected), so a row the agent branch dropped must stay while main shows that version. Options: (A) prune fact_expires per branch to match the letter — breaks F03's reads on main and exp/* (they LEFT JOIN the shared table) and needs a branch column and a migration; (B) sweep fact_expires alone — fires for a fact whose author cleared its date, for superseded versions, for a fact retracted here but still on main, and for main-only facts; (C) make the candidate set the liveness join branch_facts(agent) ⋈ fact_expires and confirm each candidate against the HEAD tree before firing, one test per removal path asserting both 'not in the join' and 'no fire'.

RATIONALE: liveness on a branch IS branch_facts, maintained synchronously by every write path under the branch lock; the join answers 'alive at HEAD' exactly, and the HEAD confirmation closes the ms window between a moved ref and the index Sync, so 'a removed fact never fires' holds by construction. No F03 maintenance path lags and none is changed.

CHOICE (maintainer, verbatim, 2026-09-28): "what I meant was, matches only facts that are still alive - I do not want to trigger for facts that have been retracted for example." → (C). The design text was reworded to say so. Built in PR 2 (#337, merge 5e303652): DueCandidates + sweepDue; TestDue_RemovedBeforeItsDateNeverFires covers retract, delete, batch, update_clear, update_change, merge_delete, merge_rewrite, rewind, removed_then_rebuilt.

NON-SCOPE: this does not authorise deleting fact_expires orphans (the same row can be live on another branch) or wiring GC; fact_expires stays F03's version-keyed table.

# Decision (user ruling 2026-10-27): a leave pushed after the master's fetch, in the round that renews the leaf, is ACCEPTED, not fixed - the current leaf is still revoked, the renewed leaf is not chased

THE RACE. A member's leave is pushed AFTER the master's fetch, in the round that renews its leaf S_old to S_1. The `left` record names S_old, so the leave duty, which matches main's current serial exactly (leftLeafDue), never revokes S_1. The member that LEFT keeps a working renewed certificate until it expires.

RULING (user, 2026-10-27): this is ACCEPTED, not fixed.

WHY ACCEPTED. (1) A certificate is useless without its agent's private key, so nobody can impersonate or commit as the agent through it. (2) The only exposure is that the member who left keeps a working renewed certificate until it expires: at most one leaf lifetime. (3) #654 already stops renewal once a leave is pushed on any branch (per-agent pushedLeaves), which narrows the window. (4) Fleet membership is eventually consistent, not immediately consistent.

REJECTED. (a) PR #663 (closed unmerged): follow the renewal chain through issued/<serial>.pem records and the CRL, then revoke the renewed leaf too. It added a lot of complexity; review found it created a griefing vector of its own (issuance record names are not serials, so a member could plant a root-signed certificate under an unused issued/*.pem name to get a rejoined member's fresh leaf revoked); and its remaining limit (two renewals before the leave lands) would need even more. (b) Delete the cert from the fleet repo instead of revoking: peers trust any root-signed leaf not on the CRL (pki.VerifyInstanceChain), so the repo copy is not the credential. Revocation via the CRL stays the leave mechanism for the CURRENT leaf.

DOES NOT MEAN: that leaves are not revoked (the current leaf still is, per kb/decisions/fleet/membership/leave-must-revoke/e9e7bab2.md); nor that renewal can be added back for left members.

CONSEQUENCE. Do not rebuild #663's lineage rule. Do not file issues for the two-renewals case or for the same key under two agent ids; both were considered and accepted for the same reason. Reopen only if the threat model changes, e.g. certificates gain power that does not require the key.

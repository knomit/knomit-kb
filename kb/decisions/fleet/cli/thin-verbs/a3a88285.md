# `knomit fleet` is a tree of thin verbs, one request to one existing route each (user rulings 2026-10-27/28, PR #666): status | create | join [--check] | leave | decommission | members [enroll|revoke] | master export|import|resign | hosting here|follow | sync [drop] | index rebuild; the CLI never does fleet work itself, never prompts, and takes credentials as plain flags

DECISION (user, 2026-10-27). Trigger: the web UI on a non-local page says 'Not in a fleet — create or join from the desktop app', and the user wanted to run fleet operations from a terminal against a running instance, as `knomit fleet ...`.

OPTIONS PUT TO THE USER: (a) thin named verbs — create, enroll, join (+ join:check), leave, revoke, decommission, root get/put/delete — each a client of the existing local-socket route: CHOSEN. (b) one generic passthrough (`knomit fleet api POST /fleet/join < body.json`), which keeps the letter of the 2026-10-15 ruling: NOT TAKEN. (c) status only, operators curl the socket: NOT TAKEN.

SCOPE CHOSEN: every route in the RequireLocalVia fleet group in one PR (not only the join/enroll path).

WHAT IT SUPERSEDES: the 'no new `knomit fleet ...` CLI verbs' half of kb/decisions/fleet/create/rest-first-local-only/b001bb23.md. WHAT IT KEEPS: that fact's other half — every fleet operation is a REST endpoint first, the gate is the RequireLocalVia group on the server, and a CLI that does the work itself (mints keys, writes control.db, installs a bundle in-process — the pre-#525 `identity init-root|enroll|install` shape) is still not allowed.

CONSEQUENCES: the verbs dial the same local listener `knomit fleet status` uses, so they work only where a server is running and only on its own machine; the authorization is the socket's, unchanged. A new mutating fleet route still goes inside the server's RequireLocalVia group first; its CLI verb, if any, follows.

MISREADING: 'the CLI may now do fleet operations' — it may only REQUEST them from the running server; with no server running, every verb fails rather than acting offline.

UPDATE (user rulings 2026-10-27/28; built in PR #666, merged as bf166c68; every claim below re-read at bf166c68). THE FINAL TREE is not the option-(a) list above (create, enroll, join, leave, revoke, decommission, root get/put/delete, flat). Verbs are grouped by subject, each leaf one request to one route over the local listener (cmd/fleet.go fleetVerbs): status (GET /fleet, printed as text) | create (POST /fleet/create) | join <bundle-file|-> (POST /fleet/join; --check sends the SAME body to POST /fleet/join:check) | leave (POST /fleet/leave) | decommission (POST /fleet/decommission) | members (bare = GET /fleet/members, outside the RequireLocalVia group) with members enroll <agent-id> <public-key> (POST /fleet/enroll) and members revoke <agent-id> (POST /fleet/revoke) | master export (GET /fleet/root), master import <json-file|-> (PUT /fleet/root), master resign (DELETE /fleet/root) | hosting here (POST /fleet/host, --confirm-loss) and hosting follow <url> (POST /fleet/follow) | sync (GET /fleet, text) and sync drop [<commit>] [--leave-out h1,h2] (POST /fleet/drop-commit) | index rebuild (POST /fleet/index-rebuild).

RULINGS. (1) Credentials (--auth-token, --password) are plain command-line flags; a user who wants them out of shell history passes "$VAR". No stdin or prompt path exists. (2) join is ONE POST: the CLI does not check first; --check is the way to look without joining. (3) No confirmation on any destructive verb (leave, decommission, master resign, master import): running the verb is the request. This is about the CLI not prompting; the server's own body fields still apply (hosting here --confirm-loss maps to the route's confirm_loss, and sync drop --leave-out maps to leave_out_merge plus left_out). (4) Names follow the user's mental model: `sync`, not `main`; `master`, not `root`; `hosting`, not `origin`, because origin collides with repo origins and `hosting here` does more than drop an origin (it makes this copy the hub).

SYNC. `knomit fleet sync` reads GET /fleet and prints blocked or not blocked from last_error_main_held plus last_error_main_held_commit (blocked needs BOTH: the flag true and a non-empty commit); `sync drop` with no commit argument drops that reported commit and, when not blocked, returns the error 'sync is not blocked: there is no commit to drop' and sends NOTHING to /fleet/drop-commit. A refused drop whose problem document carries leave_out prints the detail, one line per commit (8-hex, agent or else author, subject) and the exact command `knomit fleet sync drop <commit> --leave-out <hashes>`; passing --leave-out sends leave_out_merge:true and left_out (the confirmation described in kb/architecture/fleet/drop-commit/5fe93618.md).

TERMINAL SAFETY. That refusal text echoes requester-supplied strings (detail, agent, author, subject). cmd/fleet.go plainLine REPLACES C0, DEL, C1 and the bidi controls (U+200E/F, U+202A-202E, U+2066-2069) with a space. The user chose replacement over the oauth convention (cmd/oauth.go localError.Error prints the detail %q-quoted) for readability. Pinned by TestFleetCLI_RefusedDropTextCarriesNoControlRunes. MISREADING: this is not the oauth quoting rule applied everywhere in cmd/; a verb whose answer is the server's JSON prints it indented, unmodified.

GUARD. TestFleetCLI_EveryVerbIsOneRequestToItsRoute (cmd/fleet_test.go) pins the verb set to the RequireLocalVia group: fleetLocalOnlyRoutes parses internal/edge/web/api/manage/mount.go with the regexp `(?m)^\s*r\.(Get|Post|Put|Delete)\("(/fleet[^"]*)"` and requires the method+path set of the verb table to EQUAL it, so a route added to the group without a verb (or a verb whose route went) fails. MISREADING: a route registered in another spelling (a different router variable than `r`, a Handle/Method call, a path not starting /fleet, a line not starting with `r.`) is invisible to the regexp and escapes the pin; the test only fails closed on an empty match. The rule above still holds: a new mutating fleet route goes inside the RequireLocalVia group first.

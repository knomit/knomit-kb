# The fleet repository is changed only through the /fleet API (user ruling 2026-10-16): no generic /repos/{repo} route creates, updates or deletes it, for ANY caller including the local socket; reads, MCP included, stay open

RULING (the user, 2026-10-16, verbatim): "It should not be able to change (create, update or delete) the fleet repo through the normal repo routes - only through the /fleet api. All reads (incl. MCP) are OK." Rename is refused outright (the fleet repository keeps its name).

OPTIONS CONSIDERED. (a) Keep per-handler fleet arms and gate only some doors (what #525 did: detach and upstream gated, attach/PUT origin open, manual merge exempt); (b) refuse every generic mutation for non-local callers only (the first fix commit of PR #528, superseded); (c) refuse every generic mutation for EVERY caller and give each legitimate operation a /fleet route. Chosen: (c).

WHAT IS BUILT (PR #528, verified at merge e417fd76). ONE middleware, `r.Use(fleetRepoRefused(...))` on the `/repos/{repo}` route in internal/web/router.go: any method other than GET, HEAD or OPTIONS that names the fleet repository answers 409 with code `fleet_repository` and the handler does not run. It replaced the per-handler fleet arms. The MCP mount is exempt by its exact path shape (isRepoMCPMount: .../repos/{name}/branches/{one segment}/mcp); MCP writes on the fleet repository are still refused by RepoInstance.WritableBranch. The two operations that used to ride generic routes now live on the fleet API: DELETE origin became POST /fleet/host and PUT origin became POST /fleet/follow (the origin-guards invariant, kb/invariants/fleet/origin-guards/fd617ead.md, holds their guards and codes). The pushed-branch merge is refused too; the master's merger is the only merger.

CONSEQUENCES. (1) A NEW mutating route under /repos/{repo} is covered with no one remembering to: TestFleetRepo_EveryGenericMutationIsRefused walks the real route table (30 mutating routes at merge) and asserts each answers 409 over the socket, TCP and mTLS. (2) A new operation the fleet needs must be a /fleet route, not an exemption in the gate. (3) The refusal text names the Fleet page, never a REST route.

MISREADINGS. (1) "This is a local-listener gate": it is NOT; the local socket (the desktop app) gets 409 too. Only the /fleet routes themselves sit behind RequireLocalVia. (2) "The fleet repository is unreadable through /repos": GET, MCP reads and git fetch/push (/git is a separate mount) are unchanged. (3) "knomit's own fleet code cannot write it": it writes through the store and never asks the gate.

KNOWN GAP (reads false once PR7c lands): configuration a regular repository has through its own routes (origin credentials, forge URL changes) has no /fleet equivalent yet; see the configuration-parity decision.

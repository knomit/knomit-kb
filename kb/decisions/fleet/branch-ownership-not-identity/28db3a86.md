# Branch ownership is NOT an identity property and nothing replaces the receive-pack fp8-suffix rule: any enrolled pusher may push any agent/* ref except the host's own; content is bound to the pusher by signer = pusher (enforce) and judged at merge time

DESIGNER RULINGS (2026-10-13, round 2): the P1b 'first-push' rule (a record in the pushed tip must name the branch) was REJECTED: a forge cannot enforce branch ownership at push time, so no knomit hosting may depend on it (D19, proposed). Signer = pusher (PR #511) STAYS as the knomit-host-only check.

OPTIONS CONSIDERED (audit fleet-no-name-inference-audit.md): (1) self-attested member record in the pushed tip naming the branch; (2) host-local claim table; (3) the fleet root assigns the branch in the cert; (4) cert-artifact id == ref. All rejected with the first-push rule.

CHOICE (built in P1b): receivePack.judgeRequest keeps only rules that are not identity: exactly one command, no delete, never the repo's upstream (refused by its OWN rule, name == refs/heads/<upstream>, before and independent of the prefix check), the ref under refs/heads/agent/ (a namespace guard; every non-agent ref is refused), and never the host's own persisted agent branch (exact name). The '-<Short(pusher)>' suffix check is deleted. PushPolicy.Pusher stays the FULL cert-key fingerprint, used only by signerIsPusher.

CONSEQUENCES: under verify_signatures=off (the default) any enrolled instance can create or move any peer's agent/* branch on a host, INCLUDING a non-fast-forward (rewind) of another peer's branch: the ModeRewound path is accepted in every mode, and a peer B's commits the host had not merged yet disappear from H's copy of B's branch until someone pushes them again (availability, not content: nothing forged reaches the host's agent branch). A pusher can also put its own commits on a branch NAMED like another member's, so the operator's merge dialog, which labels a pushed branch by its name, can mislead (UI follow-up: show the signer/author ids of the commits); under enforce it can only push commits its own key signed (a commit another member signed is refused not-pusher), but it can still point a branch at commits the host already holds (no new commits, no judge: the PR #511 F2 gap). The authority for what reaches the host's agent branch is MergePushed / MergeConsensus with the merge-time dot-path guard, plus judgeCommit.

WHAT IT DOES NOT MEAN: it is not 'pushes are unauthenticated' (mTLS cert + push:own still required) and not 'any ref' (main and non-agent refs stay refused). The permission is still NAMED push:own; it no longer means a branch is owned.

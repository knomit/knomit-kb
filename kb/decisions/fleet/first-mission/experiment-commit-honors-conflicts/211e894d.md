# Experiment commits honor the repo's `conflicts` setting (user ruling 6 after the first mission): read at the consensus branch, parent = consensus side, off key still refuses, caller resolutions overlaid per path, and every drop reported

THE USER (2026-10-02/03, verbatim, post-run rulings): "6) explain how knomit experiment merge would fix the problem." then "6) agreed, experiment merging should honor the repo configuration." and, on the work list, "it's a go".

CONTEXT: in the first mission every experiment commit ran `(refuse)` even in repos set to `conflicts: merge`, so parallel cross-check experiments that touched the same hypotheses could not all land (F-R3, gotchas/missions/experiments/parallel-updates-conflict).

OPTIONS CONSIDERED:
(a) keep CommitExperiment on StrategyRefuse always (status quo);
(b) apply the setting, reading it from the experiment's or parent's ontology;
(c) apply the setting read at the consensus branch's tip like every other merge site, parent as consensus side, Refuse for off keys;
(d) as (c), but caller resolutions switch the setting off for that call;
(e) as (c), with caller resolutions overlaid per path on the setting.

CHOICE: (c)+(e), shipped in #412 (merge 55a47911). Rationale: (b) would let an experiment vote itself a merge policy; (d) was rejected at plan review because a refusal lists only what the setting left, so a retry naming those paths would turn the setting off and be refused again for paths it had already settled; the result and summary name every settled path and say when the experiment's version was DROPPED, because the experiment is deleted on success and "merged" alone would hide a loss nobody chose.

CONSEQUENCE: every `consensus: auto` repo without an explicit `conflicts` now field-merges experiment commits by default.

NON-SCOPE: does not change sync/consensus merges (ruling 3: no change), does not let MergePushed/MergeConsensus take resolutions alongside the setting, and does not surface `settled` in the web UI (its experiment commit returns 204; a possible follow-up).

# Fix the first mission's findings in the mission TEMPLATE only (each mission programs knomit with its own skills and ontology); cross-check verdicts are new facts folded by one writer; the hypothesis format travels in the task body and is enforced by ontology validations, not by per-call free-text instructions

User rulings (verbatim, 2026-10-02/03):
- "4) no, template only. I want missions to be able to have different skills. we may review later."
- "6) agreed, experiment merging should honor the repo configuration. What do you mean \"writing verdicts as new facts\" - I thought that's the default behavior when you call \"learn\"."
- "1). wouldn't allowing random instructions to be added open it for risk of injection ?"
- "it's a go"

Options considered:
- Mission skills: ship built-in skills in knomit (or derive them from the skills deployed in the harness) vs keep them in the template so each mission carries its own. Chosen: template only.
- Hypothesis format: let a caller pass free-text `instructions` to knomit_hypothesize/review vs carry the format in each task body and enforce it with the knowledge base's own ontology validations (repo trust level). Chosen: task body + validations; per-call free text rejected for injection (task-body data would become instructions).
- Parallel cross-checks (F-R3): serialise them, or let them update shared hypotheses and rely on conflict settlement, vs write NEW verdict facts and fold them with one writer. Chosen: verdicts under verdicts/<task id>/ (learn_dedup: off) + one fold task posted after the round's acks. The knomit-side fix (experiment commit honouring the repo's `conflicts` setting) is a separate PR.
- Authorship (F-R4): 'do not check your own' vs exact paths. Chosen: the task lists check: <path> lines, picked by the coordinator from git authorship.

Rationale: no knomit code change was needed; existing primitives (per-topic validations, learn_dedup, skills, the recipe prompt) are enough, and missions stay free to carry different skills. On 'I thought that's the default when you call learn': learn does write a new fact, but with dedup on a near-identical fact is merged into an existing one, which is why forecast and verdicts are learn_dedup: off.

The choice, as built: knomit PR #410 (merged into dev at 8bbd7963): examples/mission skills + examples/mission-kb ontology. See kb/architecture/examples/mission/knowledge-base/005163fe.md and kb/architecture/examples/mission/cross-check/d70b0d8c.md.

Non-scope: this does NOT decide against built-in mission skills or ontologies forever ('we may review later'; the recipes-KB / create-from-template proposal is pending user review), and it does NOT fix F-R2 (dedup merging a counter despite distinct_from) or experiment-commit conflict handling; both are knomit work outside the template.

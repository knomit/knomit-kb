# Configuration parity: ANY configuration a regular repository has and the fleet repository needs must be reachable through the /fleet API (user ruling 2026-10-16); DELIVERED by PR #529 as origin and access (POST /fleet/follow), hosting (POST /fleet/host), index rebuild (POST /fleet/index-rebuild) and the hub-to-forge move

RULING (the user, 2026-10-16, verbatim): "ANY AND ALL configuration that is usually done for a regular repo and is needed for the fleet repo has to be available via the /fleet endpoint. "fleet" is a repo, but is a special one, so we have to isolate it and protect it appropriately, but outside of that it has similar needs with regular repos - change origin, update access tokens, etc."

RULE. The fleet repository is isolated from the generic repo routes (every mutation there is 409 fleet_repository; see the decision that the fleet repository is changed only through /fleet). So every setting a regular repository gets through its own routes and that the fleet repository also needs (origin, access tokens, and whatever a future repository setting adds) MUST have a /fleet equivalent. CONSEQUENCE for new work: when you add a repository setting, ask in the same change whether the fleet needs a /fleet equivalent; shipping the generic route alone silently leaves the fleet without it, because the gate refuses the route for the fleet.

KNOWN GAPS: CLOSED by PR #529 (verified at merge 60ddfb1c): POST /fleet/follow now takes forge URLs and credentials, so forge token rotation and a forge URL change are possible (kb/invariants/fleet/follow/credential-vs-move/7b230fe8.md, kb/decisions/fleet/config-parity/update-access-credentials-only/d71c2a95.md). They are kept below as history. WHAT WAS TRUE at merge e417fd76 of PR #528: (N2) forge token rotation is impossible. PUT origin was how a member of a forge-hosted fleet rotated its token, and it is now refused; POST /fleet/follow accepts only a URL that classifies as a peer of THIS fleet (cert chains to this root) and answers 422 `not_this_fleet` for a forge URL, and a credential is refused for a peer (auth_invalid), so no route updates the origin's auth. Until /fleet/follow takes forge URLs and credentials (PR7c), an expired forge token on a member means every sync fails and the only recovery is Leave, a revoke by the master and a re-enroll. (Related) a forge-hosted fleet's origin URL cannot be changed either.

MISREADINGS. "Parity means the generic routes are reopened for the fleet": no, the gate stays; parity means /fleet routes. "Parity is already there because /fleet/follow exists": was true of #528, when follow covered only repointing at a peer; PR #529 extended it (below).

AUDIT OUTCOME (PR #529, verified at merge 60ddfb1c; each generic setting got a verdict: (a) a /fleet route, (b) already a /fleet route, (c) deliberately not available). (a): origin URL/method/token = POST /fleet/follow extended (a forge URL and/or credential; on a forge copy the url may be omitted; anonymous is auth_method none); index rebuild = POST /fleet/index-rebuild (user ruling; no DELETE); hub to forge = a mode of follow on the hosting master (user ruling). (b): DELETE origin and the origin sessions = POST /fleet/host / POST /fleet/follow; archive/delete = POST /fleet/leave or /fleet/decommission. (c): upstream branch (fixed to main), index:cancel (indexing ends on its own; fleet refusals answer 409 indexing naming the Fleet page), rename (the name is fixed), description/license, facts, experiments, synthesis, manual merge and MCP writes (authored writes are read-only by design, dd11deec; the master's merger merges member branches), the sync interval (not a setting on any repo), and the instance-wide [remote], [embeddings], [llm], [git] config. The two rulings are recorded in kb/decisions/fleet/config-parity/index-rebuild/a58307da.md and kb/decisions/fleet/config-parity/hub-to-forge-follow-mode/90af59e0.md. The standing rule is unchanged: when a repository setting is added, ask in the same change whether the fleet needs a /fleet equivalent.

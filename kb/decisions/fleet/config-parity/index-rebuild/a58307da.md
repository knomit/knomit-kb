# Index rebuild for the fleet repository is a /fleet operation (POST /fleet/index-rebuild), not a reopened generic route: the user ruled it in during the PR #529 parity audit

DECIDED (user, 2026-10-16, in the PR #529 configuration-parity audit; see kb/decisions/fleet/config-parity/97277085.md). QUESTION: the repository Settings has Index -> Rebuild; the fleet repository's generic index-rebuilds routes are 409 fleet_repository. Does the fleet get a rebuild? OPTIONS: (a) no, indexing is automatic and the fleet page needs nothing; (b) exempt the rebuild route from the gate; (c) a /fleet route. CHOSEN (c), by user ruling, verdict (a) in the audit table: POST /fleet/index-rebuild, local-only, under fleetOpMu, no cancel (the generic UI never cancels a rebuild; index:cancel is judged unnecessary because indexing ends on its own). RATIONALE: the parity rule says a setting the fleet needs is a /fleet route and never a gate exemption; the gate stays total. The mechanism and job link: kb/architecture/fleet/index-rebuild/fd9e69d0.md. MISREADING: 'rebuild reopened the generic route for the fleet': it did not; the generic route still answers 409.

# Update access changes credentials only and never pushes; any URL change on the master goes through 'Move the fleet to another forge...' (PR #529 review S3)

DECIDED (master ruling on PR #529 review finding S3, 2026-10-16). QUESTION: review finding S3 asked what 'Update access' on the master may do when the URL differs: a forge-to-forge URL change is a full move (seed, host record, publish), which a screen that reads as a credential edit must not run. OPTIONS: (a) keep one action that moves when the URL differs; (b) Update access changes credentials only and never pushes, and any URL change on the master is the explicit 'Move the fleet to another forge...' action. CHOSEN (b). RATIONALE: a token rotation must never be able to rewrite the host record or push, and a move must be an explicit act that lists its member consequence. Server rule: the stored URL (or none) on a forge copy is a credential change; a different URL is the move (kb/invariants/fleet/follow/credential-vs-move/7b230fe8.md). UI: Update access has no URL field, opens on Access, prefills the stored method, sends nothing while unchanged, and its Review says 'Nothing is pushed, and main, the host record and every member stay as they are'; the master on a forge gets Move to another forge and NO Point at; a member on a forge gets Update access and Point at.

CONSEQUENCE accepted: re-submitting the forge a move stopped on is `unchanged`, so an interrupted move is repaired by going back or hosting here, not by retrying (kb/architecture/fleet/move/interrupted-move/e9c7d31c.md). Nit left: choosing the forge's own URL in the Move flow previews a full move and only the answer (`unchanged`/`credential`) says nothing moved.

# The both-changed-field rule that takes the consensus side is named `merge:consensus` (trailer strategy=merge_consensus), not PR 1's `merge:upstream`

THE USER (2026-09-30, verbatim): "I don't like "merge:upstream", use something better like "merge:consensus" or a similar name to say we'll pick the consensus."

OPTIONS: keep `merge:upstream` (PR 1); `merge:consensus`; another name.

THE CHOICE: `facts: merge:consensus`.
- The fact rule is now `MergeTakeConsensus` = "merge_consensus", and the confidence rule is `MergeConfidence` = "merge".
- `MergeStrategy.Upstream` became `.Consensus`.
- The Knomit-Merge trailer's `strategy=` values follow: merge | merge_consensus. The form is unchanged.

RATIONALE: the side it picks is the CONSENSUS side, the version that is on or will reach the repo's consensus branch. 'Upstream' suggests an origin, and on a knomit host with no origin the consensus side is the host's own agent branch. The same word now names the whole-version value (`consensus`) and the per-field one (`merge:consensus`).

REJECTED: the `merge:upstream` name.

NON-SCOPE: commits written by PR 1 binaries keep `strategy=confidence|upstream`, and a reader of old history must accept both.

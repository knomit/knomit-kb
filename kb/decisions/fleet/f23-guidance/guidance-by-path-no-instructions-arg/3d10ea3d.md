# F23 ruling: synthesis-prompt guidance is repository policy declared in the ontology BY PATH to files under .knomit/guidance/, read at the consensus tip; there is NO per-call instructions argument (injection), and no inline guidance text in the ontology

User rulings (2026-10-03, verbatim, from the post-run decisions log):
- "1) what exactly would we need to extend for knomit hypothesis in order to have it follow some instructions ?" (the question; excerpt of a longer multi-item message)
- "1). wouldn't allowing random instructions to be added open it for risk of injection ?" (excerpt; item 6 of the same message is about F22)
- "F23) ok, let's just make sure that does not mean we pollute the ontology with 200 lines of text for each. If that's the case, I would actually prefer the guidance to be a path to the actual guidance text stored into a file under .knomit/guidance or something similar maybe"
- "F23 approved. F24 approved, proceed" — which accepted the remaining details as recommended: 16 KiB per file and per rendered section, any path escaping .knomit/guidance/ refused (warning on open, fatal for a new ontology), a missing or bad file skipped with one warning per (path, commit).

OPTIONS weighed: (a) a per-call free-text `instructions` argument on knomit_hypothesize / knomit_review; (b) inline guidance text per topic in the ontology; (c) ontology-declared guidance by path to files, read at the consensus branch's tip, with the existing ontology validations enforcing the format.

WHY (c): (a) promotes task-body data (which may quote fact bodies or web pages) into instructions inside knomit's own prompt — knomit cannot tell the two apart, which is the injection the user named. (b) bloats the ontology (the user's "200 lines of text for each"). (c) keeps the ontology to one line per key, puts guidance at the trust level of skills and recipes (whoever can change the consensus branch), and leaves enforcement to validations: guidance explains, validations gate.

THE CHOICE as built: PR #423, merge commit 3bb2c230 on dev (details: kb/decisions/fact/ontology/guidance-block/8b3a8135.md and kb/invariants/synthesize/guidance/consensus-tip-only/003522bb.md). Its safety on a repo with no origin depends on F25 having closed .knomit/ to every fact tool (finding R1, resolved by F25 rather than a guidance-specific reservation).

NOT DECIDED HERE: per-step review keys (prune/distill/reflect separately), guidance for other tools, templating in guidance, and enforcing validations on review's own writes — all out of scope. Tightening the consensus-branch trust (consensus: auto admits any peer) is to be done for skills, recipes and guidance together, later if needed.

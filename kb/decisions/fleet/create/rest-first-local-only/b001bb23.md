# Fleet create is REST on the LOCAL listener only and has no CLI verb (user ruling 2026-10-15): every fleet operation is a REST endpoint first, root-key operations stay behind RequireLocalVia, and remote use waits for a master-password second factor (issue #521)

DECISION (user, 2026-10-15; built in PR #518, merge 537f2019). OPTIONS: (a) a `knomit fleet create` CLI verb that does the work in the CLI process (the pre-rework #518 had one): NOT TAKEN, cut with the passphrase/keychain pieces. (b) a REST endpoint that any write-capable caller may use, including over mTLS: REJECTED for now, because create mints the fleet root key and installs a certificate; every route is also served on the mTLS listener, so a remote peer with write could found a fleet on this instance. (c) A REST endpoint served on the unix socket / Windows named pipe only (RequireLocalVia): CHOSEN.

THE RULING AS GIVEN: every fleet operation is a REST endpoint first (Fleet UI + API); no new `knomit fleet ...` CLI verbs; the existing CLI is only a thin client or is removed. It matches kb/decisions/fleet/registration-model/bcbf76e4.md (REST on the running server, CLI thin). Root-key operations (create, enroll, revoke, decommission, host) keep RequireLocalVia for now; enhancement #521 would add a master password as a second factor so they could be used remotely (it authorizes, it does not encrypt the key).

CONSEQUENCES. cmd/ is untouched by #518. ErrFleetOntologyReserved now says the fleet repository is one 'which only the fleet API (/api/v1/fleet/...) creates or joins' (it used to name `knomit fleet`, a CLI that never creates). Two texts still name the CLI and were left for the membership PR: ErrFleetReadOnly ('changes only through `knomit fleet`') and the fleet_repository refusal ('leave the fleet with `knomit fleet unregister`'). A caller that wants to create a fleet must reach the local socket or pipe; a browser page on loopback TCP is 403.

MISREADINGS. 'Local-only means any local page may call it': RequireLocalVia refuses loopback TCP, so a browser page cannot. 'No CLI verb means the CLI cannot create': a thin CLI client of the socket route is allowed; a CLI that does the work itself is not.

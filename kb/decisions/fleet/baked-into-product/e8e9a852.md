# Decision: the fleet is baked into knomit, not a template, because it is tightly coupled to how knomit works; created only through the fleet API/UI, visible and lens-mountable but read-only for MCP; and once decided, no dead weight — the template, shape-check and exact-preset machinery was deleted, not kept

OPTIONS CONSIDERED
1. Keep the fleet as a template (and preset) that a user can pick at create, with shape checks and exact-preset identity rules so a customised copy could not pose as the fleet.
2. Bake the fleet ontology into the product: one embedded definition, not selectable at any generic create door.

RATIONALE (the user's): the fleet is tightly coupled to how knomit works: its judge rules, member records, trust-file artifact rules, root-signed PKI files and `consensus: auto` all assume exactly that ontology. A template is a copyable, editable thing; the fleet must not be. Baking it in means there is nothing to declare, copy, drift or shape-check.

THE CHOICE
- The fleet is a product feature: one embedded ontology, changed only by a knomit release and applied to an existing fleet repository by the master only (see the baked-ontology master-refresh invariant).
- It is created only through the fleet API/UI (today `RegisterFleet`; fleet create and join later); `fleet` is a reserved ontology id at every generic door (the baked-ontology reserved-id invariant).
- The fleet repository is VISIBLE in the repo list and REST, can be mounted by a lens for reading, and is read-only for MCP and for every authored write (the baked-ontology read-only invariant).
- Principle that followed the decision: NO DEAD WEIGHT. Once the fleet stopped being a template, everything that only served the old shape was deleted in the same change rather than left in place: ErrTemplateFleetLocal/Present/StateUnavailable and checkTemplateMode, the fleet arms of OntologyByPreset and EmbeddedPresetByID, fact.ArtifactRulesEqual and its use in refreshDivergence, the archive escape hatch for a stuck unregistration, the fleet template in the playbooks repository, and the tests for all of these. templatePresetByID stays because it still serves default and code.

NON-SCOPE: this does not say the fleet repository is invisible, only that it is not authored or created like a knowledge base. It does not decide the later fleet create/join/leave verbs, which must still record their repository (reserved-id invariant). The pre-release interim cost (an unregistration whose push never succeeds cannot be stopped until immediate leave lands) was accepted knowingly.

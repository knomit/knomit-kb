# The enroll bundle is a document, '# knomit fleet bundle v1' with url, agent, root and serial lines then the PEM, and join takes {bundle, auth?} and reads the fleet URL from it; the url line is NOT authenticated, so hosting 'master' proves only 'an instance of the bundle's fleet'

Decided for PR #526 (merge 0488c05d). It REVERSES the earlier design 'the bundle is auth material only (leaf + root + CRL) and the joiner types the fleet URL'. The user: "the bundle should probably have the fleet repo url as well, if we do that we can combine multiple steps into one."

THE DOCUMENT. POST /fleet/enroll returns the bundle as: the line `# knomit fleet bundle v1`, then exactly `url:`, `agent:`, `root:` (fingerprint) and `serial:` lines (each once; unknown, duplicate, missing and non-`key: value` lines are refused), then the leaf, root and CRL PEM blocks (exactly one of each). pki.FleetBundle builds it from the bare PEM; pki.SplitBundle parses either form. POST /fleet/join takes {bundle, auth_method?, auth_token?}, no url: the URL is Bundle.FleetURL. A bundle with no url line is bundle_invalid ('names no fleet repository URL: enroll this instance again'); a join request without a bundle is bundle_required (400). A BARE PEM bundle still splits and installs (fleet create's own install and the desktop's Settings install use it); it just cannot be joined with.

WHAT IS CHECKED AND WHAT IS NOT (review N6). SplitBundle compares the header's agent, root and serial against the PEM blocks (a mismatch is bundle_invalid), so they cannot disagree with what is installed. The `url` line CANNOT be checked against any certificate: nothing signs it. Its guards are (1) classification against the BUNDLE's root (join:check and the join's clone), (2) `root_differs` after the clone (the fleet repository's root on main must equal the bundle's root), and (3) the operator seeing `host` and the root fingerprint in join:check before joining. CONSEQUENCES: `hosting: master` proves only 'the URL answers as an instance of the bundle's fleet' (a certificate chaining to the bundle's root), not that it is the fleet's master. A tampered url naming a forge would send a FORGE joiner's token to that forge (join passes the joiner's auth to a non-peer origin), and a url naming another member of the same fleet classifies as hosting master. Anything that shows a bundle to an operator for confirmation (the PR 7 Review step) must show host next to the root fingerprint.

WHY A HEADER AND NOT JSON OR A SIDE FIELD. One artifact now carries everything the joiner needs, so enroll -> join is a copy-paste and join:check can classify before anything is installed. Gotcha: Go's pem.Decode silently SKIPS any text before the first '-----BEGIN', so a header would pass unread if left to it; splitHeader therefore parses the header explicitly up to the first PEM block, and the S6 sabotage (SplitBundle not comparing the header) is red on agent, root and serial rows.

OPTIONS REJECTED: keep the URL a separate join field (an extra step and a typo/phishing surface); sign the URL (would need the root key at join time and a new signed format, out of scope).

MISREADINGS. 'The header is part of what is verified': only agent, root and serial are. 'A bundle for the hub works for any address': the master chooses ONE address at enroll (see the enroll-address fact); there is no try-in-order.

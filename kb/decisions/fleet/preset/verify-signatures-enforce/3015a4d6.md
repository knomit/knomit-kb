# The built-in fleet ontology DECLARES verify_signatures: enforce and consensus: auto in its own text (user ruling R7: 'everything is explicit'); the judge's behaviour is never inferred from the ontology id, and a fleet repository at off or log gets no enforcement or only logging by its OWN declaration

OPTIONS: (a) leave the fleet ontology without verify_signatures, so a new fleet repository is unjudged (off) until its creator writes the attribute (the pre-#514 preset): REJECTED, because the fleet's trust files would then be unprotected by default; (b) make the fleet id imply enforcement in code: REJECTED, because the behaviour of a repository would be read from a name instead of from its own policy; (c) the ontology declares `attributes: { verify_signatures: enforce }` in its own text: CHOSEN, the user's reasoning being that everything is explicit: the policy a repository runs under is the text in its .knomit/ontology.yaml and nowhere else.

SINCE PR #520 (verified at merge commit 1a6c03f7): the fleet ontology is built into knomit (fact.FleetOntology), not an embedded PRESET; the text above is the same embedded ontology_fleet.yaml, which now ALSO declares `consensus: auto` in the same attributes block (the master merges accepted member branches into its own agent branch by itself; it needs verify_signatures: enforce beside it; pinned by TestFleetOntology_DeclaresConsensusAuto). The knomit-playbooks fleet template that once carried the same text no longer exists.

CONSEQUENCES. A NEW fleet repository judges every change that enters main (record rules, rules A/B once there is a root, and the artifact rules) from its first push. An EXISTING fleet repository is no longer protected from changes to its stored policy by the preset refresh guard (refreshDivergence is not used for the fleet at all): on the MASTER the boot replaces the stored ontology wholesale with the built-in one, so enforce, the artifacts section and consensus: auto reach an existing fleet repository there (kb/invariants/fleet/baked-ontology/master-refresh/d62746d2.md); a member never writes its ontology.

MISREADING: 'the fleet id implies enforcement' is wrong; the judge reads the repository's own attribute. MISREADING: 'enforce on the fleet ontology means artifact rules run everywhere' is wrong; they run only in a repository whose own ontology has verify_signatures log or enforce AND declares an artifacts: section. MISREADING: a fleet repository's verify_signatures can no longer be set to off by editing its ontology and surviving: on the master the next boot replaces the file with the built-in text.

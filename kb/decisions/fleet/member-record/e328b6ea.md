# A fleet repository is the one mounted repo whose ontology id is the embedded preset `fleet`; its member records are policy facts at kb/members/<agent-id>/ whose BODY starts with `field: value` lines (agent, state, key, host, branch) holding only the agent's CURRENT state and key

F09 PR 5 (user rulings 2026-09-27). The fleet ontology preset is embedded like the KB presets (internal/fact/ontology_fleet.yaml, id `fleet`; fact.FleetOntology, OntologyByPreset("fleet"), EmbeddedPresetByID("fleet"), fact.IsFleetOntology). Recognition is by that id alone: no reserved repo name, no role attribute, and NOTHING in any KB's ontology names a fleet, so the fleet repo can be rebuilt without touching a KB.

Member record: topic `members`, category = the agent id, type policy (pragmatic, so never deduplicated or synthesized; a validation `members-are-policy` enforces kind/type). The body's leading `field: value` lines are agent (OPAQUE id: the one in the agent's commit author address), state (active | left | revoked), key (the current ssh-ed25519 authorized-key line), host, branch; free text follows. fact.ParseMember returns ErrMalformedMember for a missing agent/state/key, an unknown state, or a non-ed25519 key; unknown fields are ignored. fact.SameKey compares the FULL wire key, never a fingerprint prefix.

The body-line format is a worker choice where the design was silent (the design named the fields, not their encoding).

MISREADINGS: the record holds no key list and no per-key flags. Earlier keys and states are earlier VERSIONS of the same fact (knomit explain), which is where history lives. A record is never deleted: leaving or revoking is a state change; knomit_retract is for a mistaken registration only.

# A fleet repository is the one mounted repo whose ontology id is `fleet` (the built-in fleet ontology, not a preset); its member records are policy facts at kb/members/<agent-id>/ whose BODY starts with `field: value` lines (agent, state, key, host, branch, addresses, git, capabilities) holding only the agent's CURRENT values

F09 PR 5 (user rulings 2026-09-27). The fleet ontology is embedded in the binary like the KB presets (internal/fact/ontology_fleet.yaml, id `fleet`; fact.FleetOntology, fact.IsFleetOntology) but, since PR #520 (merge commit 1a6c03f7), it is NOT a preset: OntologyByPreset and EmbeddedPresetByID have no fleet arm and the id is reserved (kb/invariants/fleet/baked-ontology/reserved-id/4cdcf99e.md). Recognition of a mounted repo is by that id alone: no reserved repo name, no role attribute, and NOTHING in any KB's ontology names a fleet, so the fleet repo can be rebuilt without touching a KB.

Member record: topic `members`, category = the agent id, type policy (pragmatic, so never deduplicated or synthesized; a validation `members-are-policy` enforces kind/type). The body's leading `field: value` lines are agent (OPAQUE id: the one in the agent's commit author address), state (active | left | revoked), key (the current ssh-ed25519 authorized-key line), host, branch, and since F10 addresses, git, capabilities (one line each, e.g. `addresses: https://a https://b`, `git: /git`, `capabilities: arch=arm64 os=darwin read_only=false version=0.5.0.abc`, capabilities rendered sorted so an unchanged instance renders identical bytes); free text follows. Each F10 field is optional and on its own line, so an F09 reader (which ignores unknown fields) still parses an F10 record. addresses are the operator's knomit.toml `external_addresses` verbatim (line omitted when empty, parsed back as []); git is written only when the instance actually mounts /git; capabilities are only host-detected values. Someone else's odd addresses/capabilities are parsed leniently and kept as written: they never make a record malformed.

ADVERTISED vs OWNED-BY-STATE: key, host, branch, addresses, git, capabilities are the ADVERTISED fields (fact.Member.AdvertisedDiff / SameAdvertised compare exactly these); the instance rewrites them on its own at boot and on re-registration (kb/architecture/fleet/registration/05e5af16.md). agent, state and the free-text notes are NOT advertised: the instance never changes them on its own; state changes only by registering (active) and unregistering (left). fact.ParseMember returns ErrMalformedMember for a missing agent/state/key, an unknown state, or a non-ed25519 key; unknown fields are ignored. fact.SameKey compares the FULL wire key, never a fingerprint prefix.

The body-line format is a worker choice where the design was silent (the design named the fields, not their encoding).

MISREADINGS: the record holds no key list and no per-key flags. Earlier keys and states are earlier VERSIONS of the same fact (knomit explain), which is where history lives. A record is never deleted: leaving or revoking is a state change. Since PR #523 this is ENFORCED, not a convention: on the fleet repository the record-owner rule refuses every delete under members/<id>/ (`not-owner`), so a member record cannot be removed through the gate, a mistaken registration included, and knomit_retract does NOT remove one there (an earlier version of this fact said retract was for a mistaken registration; that is false for the fleet repository). Removal is possible only for someone who writes main outside the gate (a host-local write, or a forge admin push). The record also may not name another agent: a record under members/<x>/ whose agent: is not <x> is refused and, if already on main, skipped by the loader.

OPTIONS CONSIDERED AND RULING. Rejected: a `keys:` list accumulating every key the agent ever held, and a per-key `revoked: true|false` flag (both in the pre-master design revisions). The user ruled (2026-09-27, verbatim): "why not leave the agent history to the fact history itself, why clobber ALL keys EVER used by the agent in one fact ? Just use the goddam history … have the fact store the current agent state (active, left, etc) then use knomit explain to pull the history". Chosen: the record holds the CURRENT state and CURRENT key only, and the gate admits only that key. The audit (kb/decisions/store/verify/audit/e4caa34f.md) reads the record's versions to attribute old commits. Why the fleet repo is the source of truth at all: kb/decisions/fleet/source-of-truth/6ddfdd1a.md.

BRANCH IS INFORMATIONAL (PR #513, D18/D19): the record's branch field stays a display/advertised value; nothing makes it load-bearing for branch ownership. A proposal to make a pushed tip's record name the branch (a 'first-push' rule) was rejected, see kb/decisions/fleet/branch-ownership-not-identity/28db3a86.md.

UPDATE (PR #523, verified at merge commit 3ac59b57): the state `revoked` is accepted by fact.ParseMember but is never WRITTEN by knomit; readers (FleetStatus.record_state, GET /fleet/members) show `revoked` when the CRL at the same main lists the member's leaf (kb/decisions/fleet/derived-revoked/504782ff.md). The record on main still says what its owner wrote, and the judge reads the records as written.

UPDATE (PR #532, squash commit a1b0ca5d on dev, verified in fact/fleet_member.go there): the record grew one more optional field, `leaf_serial` (fact.Member.LeafSerial, in memberFields; rendered after `capabilities`, only when non-empty; parsed lowercased and trimmed). On a `left` record it is the serial in lowercase hex of the leaf the instance held when it left (writeOwnRecord, from the certificate installed in [tls].dir); an `active` record never carries it. It is NOT an advertised field (AdvertisedDiff and SameAdvertised do not compare it) and, like every unknown field, older readers ignore it, so an older judge or reader still parses the record. It is the key of the master's leave duty (kb/invariants/fleet/leave/master-revokes-left/d2132d6b.md). The sentence above that 'state changes only by registering (active) and unregistering (left)' stands; 'the free-text notes' stay unadvertised. MISREADING: 'leaf_serial is a second source for which key the member has': it is the leaf's serial, never compared with `key`.

# A pushed branch is merged ONLY into the host's own agent branch — never main, never a caller-chosen target (user ruling D2, F11 UI merge)

USER, VERBATIM (2026-09-29): "1) agreed 2) agreed 3) agreed 4) no, no warnings - remember the principle, we should operate like a chain of trust ? If I trust this agent A and  agent A trusted agent B and it accepted its commits then we should trust them." This fact records answer 2.

OPTIONS (open decision 2, 'where does a merge land?'): (a) always this host's own agent branch; (b) main, on a host with no origin.

CHOICE: (a). The merge endpoint takes the target from ri.AgentBranch(); it is not a request parameter, so there is no 'merge into main' door at all.

RATIONALE: R1 said 'into this host's agent branch'. On an origin-backed host the host's ordinary sync pushes the agent branch upstream and a human merges main on the forge; on an origin-less host runLocalReconcileLoop → AdvanceLocalUpstream already fast-forwards main to the agent tip, so merging into main directly gains nothing and would need `merge:main` enforcement plus a second code path.

REJECTED: merge into main.

NON-SCOPE: this does not make the host merge anything on its own; only the operator's click merges (kb/decisions/fleet/f11/merge-path-ui-follow-up).

# Hosted knomit ships as bring-your-own-cloud, not resale — the operator never holds the provider account

Goal that prompted the fork: let users run their own cloud knomit reachable at a stable hostname, connect it to GitHub and to claude.ai over MCP, and have it cost nothing when idle — with the knomit operator paying none of the hosting bill.

Options considered: (a) resale plus a prepaid credit wallet — operator owns the provider account, bills users with markup, suspends tenants at zero credit; (b) bring-your-own-cloud — operator ships a deploy artifact into the USER's own provider account; (c) pure post-paid resale — conventional metered SaaS invoicing; (d) hybrid, hosted shared-process free tier plus BYOC for heavy users.

Rationale: whoever owns the provider account receives the invoice, so only (b) actually satisfies 'the operator pays nothing'. Every resale variant merely routes the cost through the operator, who then carries provider float, unpaid and idle tenants, merchant-of-record duties, and compliance. (a) caps that exposure but does not remove it; (c) leaves it uncapped; (d) requires building and maintaining two tenancy models at once. BYOC's real cost is UX: the operator does not control the user's hostname, so a <uid>.knomit.io subdomain is not available for free, and one-click signup degrades to a guided deploy wizard.

The choice: (b) bring-your-own-cloud. The operator distributes a deployment artifact and the user's own cloud account is billed directly.

What this does NOT mean: it does not settle the target provider, the artifact format, or whether knomit.io offers hostnames via delegation or proxy — those remain open. It also does not remove the need for authentication inside knomit: internal/web/server.go applies only Recoverer and CORS middleware today, so a publicly reachable instance has no login and no MCP token auth regardless of who pays for the box. Finally, BYOC does not soften knomit's runtime shape — the mandatory embedder eagerly loads a ~600MB ONNX model in NewEmbedder and all state is SQLite under KNOMIT_HOME, so the deploy target must still be a container with a persistent volume, not a serverless function.

# An approved login's 'last used' is DERIVED (MAX(oauth_tokens.created_at) for the family: the code exchange, then each refresh), never written per request; and its client name comes from side table oauth_family_clients (000020) written in Collect's family-creating transaction, while who approved it was already in oauth_family_approvals (000011)

Last used: Store.ListLogins computes it as the newest oauth_tokens row's created_at for the family. Consequence: it is the time the client last GOT a token, not the last request; a client reusing one access token shows that token's mint time, stale by at most the access TTL (2 h). Null (Go zero, JSON null) means the code was never exchanged. Chosen over a write per bearer request so the verifier's hot path stays read-only. Client name: oauth_families has no client_name column and control migrations admit only CREATE ... IF NOT EXISTS, so 000020 adds oauth_family_clients(family_id PK, client_name). createFamilyTx writes it when FamilySpec.ClientName is non-empty, and Collect passes the pending row's client_name in the SAME transaction that creates the family. Absence (families from before 000020, CreateFamily callers that pass no name, a request without a name) reads as '' and the UI falls back to client_id. The name is what the CLIENT said about itself, never an identity. Approver: NOT a new column or table: FamilySpec.ApprovedBy -> oauth_family_approvals already existed (3c) and familyCols already selects it; a family with no row lists approved_by ''.

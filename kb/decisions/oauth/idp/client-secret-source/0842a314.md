# The IdP client secret is NEVER plaintext in knomit.toml: it comes from client_secret_file (owner-only, mode 0600 or stricter, checked) or from KNOMIT_OAUTH_IDP_CLIENT_SECRET (wins when both are set); a client_secret key is refused at load; not the control.db Crypt

OPTIONS (F19 phase 3c, worker Q3 + reviewer S1, master rulings 2026-09-24): (a) plaintext client_secret in TOML with an env override, as [remote].token and [llm].api_key already are; (b) the control.db Crypt (AES-GCM keyed from the agent SSH key) that encrypts forge tokens set through the API; (c) a file path or a fixed env var, plaintext TOML refused.

CHOSEN: (c). The existing convention does not forbid plaintext secrets in TOML, but this secret authenticates knomit to GitHub as the app whose sign-in approves requests, and knomit.toml is routinely copied and pasted. The Crypt was rejected because 3c is config-file only: nothing would write a ciphertext, a new CLI would be needed to set it, and a missing agent key would make path 3 unbootable.

MECHANICS (config.OAuthIDPConfig.loadIDPSecret, run in Load after the TOML, before Validate):
- client_secret present in TOML → load error naming both accepted forms and NOT echoing the value.
- else env KNOMIT_OAUTH_IDP_CLIENT_SECRET if non-empty;
- else client_secret_file: stat, refuse if mode & 0o077 != 0 (POSIX only — Windows reports synthetic bits, so there is no check there), read, trim whitespace (an editor's trailing newline is not part of it);
- neither → load error.
The value lives in config.IDPSecret, whose String, GoString, Format (every verb, including %d, which a String method alone does not cover — it would print the struct fields), MarshalJSON and MarshalText all yield "[redacted]"; only Reveal() returns it, and only the token exchange and the revocation call use it.

MISREADING TO AVOID: 'env wins' is the envOr convention, not a second allow path for weaker storage; both sources are owner-controlled.

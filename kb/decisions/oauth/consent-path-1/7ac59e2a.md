# OAuth consent without accounts, path 1: /oauth/authorize PARKS the request and shows only its id; an operator decides with `knomit oauth approve <id> --as <subject> [--scopes …]` or `deny`; the browser's /wait long-poll wakes on the decision and collects the code once

CHOSEN (F19 phase 3a, plan Global Constraints + master rulings D12/D13, 2026-09-23): knomit has no user table, so consent is an operator act on the instance, not a login form. Paths 2 (master key) and 3 (external IdP) and the web-UI panel are 3b/3c.

FLOW: /oauth/authorize validates everything, then stores a PENDING row (10 min) carrying WHO ASKED — client id and name, requester RemoteAddr and User-Agent, redirect_uri, requested scopes, resource — and renders a page naming the id (no form, no auto-approval) that refreshes to /oauth/authorize/{id}/wait. /wait long-polls (30 s) and is woken in-process the moment Approve or Deny runs; on approval it mints the code and 302s to the redirect_uri with code, state and iss; on denial or expiry it sends access_denied. A second /wait on a completed request is 410.

WHY THE REQUESTER FIELDS: a URL client_id proves domain ownership, not which local process is asking (kb://bc6eac5f37df/kb/gotchas/ai/agents/tools/mcp/security/client-identity/066a9dad.md). The operator judges the requester, and PKCE binds the code to whoever started the flow.

APPROVE: the operator names the subject (1–128 chars of letters, digits and . _ @ + -, starting alphanumeric); the principal is host:<subject>@token (oauth.TokenPrincipal, keyed in grants by String()). CEILING = --scopes when given (any of read, write, push:own, merge:main, operator — NEVER admin; an empty list is refused), else requested ∩ {read, write}, else read, in one canonical order. Approve writes grants for the principal for every ceiling permission, granted_by = the approving principal, BEFORE recording the decision: a decision that loses a race leaves grants the operator intended, never a token with nothing behind it. A revoked token loses everything at once; the grants stay for the next token of that subject (operator choice).

BOUND: /oauth/authorize is unauthenticated on a proxied listener, so at most 100 undecided unexpired requests may wait (temporarily_unavailable beyond); expired rows are purged at each create. There is deliberately NO per-IP rate limit on /oauth/token: behind a same-host proxy every caller is 127.0.0.1 and one bucket is a lockout tool (master ruling D14).

MISREADING TO AVOID: approve/deny/pending being CLI commands does not make them loopback-only by themselves. What restricts them is the gate on their REST endpoints (local socket/pipe principals only, R5), not the fact that a CLI calls them.

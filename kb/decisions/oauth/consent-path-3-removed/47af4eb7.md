# Consent path 3 (GitHub identity-provider approval) is removed: no /oauth/idp/* routes, no knomit_idp_ binding cookie, no Store.SetRefreshCheck / ErrNoLongerAllowed; Pending.IDPBinding and the oauth_pending_idp queries are gone but the table stays as an empty unused table

Auth P0 (branch auth/p0-remove-idp-and-operator-certs) deleted internal/edge/oauth/idpflow.go, internal/edge/oauth/idp/ (GitHub provider, idptest fake), config.OAuthIDPConfig and `knomit oauth idp`. What remains of OAuth consent: path 1 (operator `knomit oauth approve <id> --as <subject>` / the local-principal approval API / same-origin admin UI) and the fleet-root signed approval.

What the removal does NOT touch: the migration 000011 and the `oauth_pending_idp` table stay (control.db up-migrations only ever CREATE ... IF NOT EXISTS); nothing reads or writes it now. `oauth_family_approvals` (the approved_by column behind the Approved logins list) stays, since approvals still record their decider. Store.SetRefreshCheck had no other user, so it, the refresh check in Store.Refresh and ErrNoLongerAllowed were deleted: a refresh is now judged only by token state (expiry, reuse, revocation, client, audience).

CONSEQUENCE: an instance whose knomit.toml still has [oauth.idp] (or KNOMIT_OAUTH_IDP_CLIENT_SECRET set) fails to boot with a removed-key error naming `knomit oauth approve`. Families previously approved as `idp:github:<id>` keep refreshing until the later auth wipe; nothing re-checks an allow list any more.

# OAuth tokens and codes are stored as SHA-256 only, grouped in FAMILIES that are the unit of revocation, with an ABSOLUTE refresh lifetime — and the authorization code is minted when the browser COLLECTS the approval, which is what lets the code be hash-only too

CHOSEN (F19 phase 3a; plan R8, master ruling 2026-09-23): an access or refresh token is 32 random bytes, base64url, and control.db stores only hex(sha256(token)) in `oauth_tokens.hash` — a copied control.db yields nothing a client could present. The opposite case (forge tokens knomit must REPLAY) keeps using the existing Crypt, not this table.

FAMILY = one login: one client, one subject, one ceiling (space-separated permission names), one audience (`resource`, stored EXACTLY as the client named it). Subject, scope and resource live on `oauth_families`, not on each token row. Revocation is `oauth_families.revoked_at`: revoking EITHER kind of token (`/oauth/revoke`, RFC 7009 permits revoking related tokens), presenting an already-rotated refresh token (ErrReused), or replaying a consumed code revokes the whole family, and every token and code in it is dead from that moment. A revoke of an unknown token succeeds (RFC 7009 answers 200 either way).

ROTATION is one transaction: the presented refresh token gets `rotated_at` and the new pair is inserted in the same tx. Races are serialised by control.db's SINGLE connection (repos.OpenRegistryNoSchema sets MaxOpenConns(1)); there is deliberately no RowsAffected re-check on the rotation UPDATE because nothing can interleave. CONSEQUENCE: any Store method that opens a tx must issue every statement through the tx — a statement on the *sql.DB while the tx holds the only connection DEADLOCKS. The store tests open control.db with the production DSN and one connection precisely so that shows up.

ABSOLUTE LIFETIME: `refresh_expires_at` is fixed at family creation (RefreshTTL, default 14 d) and never extended by a refresh; every access token (AccessTTL, default 2 h) is capped at it, so nothing outlives its login. The single expiry check for the family's end is in issuePairTx; its error rolls the rotation back.

CODE MINTED AT COLLECTION: an approval does not mint the code. The browser polling /oauth/authorize/{id}/wait collects the decision, and only then is the code minted and returned in the redirect, once (`oauth_pending.collected_at`). Nobody else ever needs the plaintext code, so it too is stored as a hash.

MISREADING TO AVOID: 'rotated' is not 'revoked'. The access token issued alongside a rotated refresh token stays valid until its own expiry. Only reuse of the rotated refresh token (or an explicit revoke) kills the family.

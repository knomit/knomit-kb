# Binary version = Makefile-authoritative semver + short git SHA, injected via internal/platform/version (formerly internal/version)

All knomit binaries (knomit, knomit-bridge, knomit-desktop) report a build version of the form `Major.Minor.Patch.<short-sha>` (e.g. `0.5.0.2a7ae9d`).

**PATH UPDATE (PR #191, 2026-09-14):** the package is now `internal/platform/version`, moved from `internal/version` when the process tier was grouped under `internal/platform/` (see the internal-package-layout decisions). The Makefile carries the import path ONCE, as `VERSION_PKG := knomit/internal/platform/version`, and `VERSION_LDFLAGS` is built from it — so a future move edits one line. Everything below about the mechanism is unchanged; read `internal/version` in older refs as this package.

**UPDATED (PR #55):** the Makefile constant is now `BASE_VERSION`, not `VERSION` — `BASE_VERSION := 0.5.1` is the last RELEASE, and `VERSION` is DERIVED from it per `RELEASE_CHANNEL` (stable → `BASE_VERSION`; dev → `<next patch>-dev.<committer epoch>`). The single-source-of-truth property below is unchanged; only the name of the hand-edited constant moved. Bump `BASE_VERSION` on release. See [[dev-channel]] for the derivation and its constraints.

**Options considered** (resolved via AskUserQuestion):
1. *Version source of truth* — (a) Makefile authoritative (the semver lives only in the Makefile, injected via `-ldflags`; the version package defaults to `dev`) vs (b) bake `0.5.0` as the Go default and inject only the hash. **Chose (a)** — no semver duplicated across two files that can drift; release builds always go through `make`; a bare `go build`/test/IDE reports `dev`.
2. *CLI surface* — (a) both `version` subcommand and `--version` flag vs (b) subcommand-only. **Chose (b)** — `knomit version`, `knomit-bridge version`; the desktop GUI has no subcommands so it gets `--version`.
3. *Dirty flag* — append `-dirty` vs hash-only. **Chose hash-only** — matches the requested string exactly.

**Implementation:** the `version` package is the single source of truth: package-level `Version` (default `"dev"`) and `Commit` (default `""`) vars, injected at link time via `-ldflags "-X $(VERSION_PKG).Version=$(VERSION) -X $(VERSION_PKG).Commit=$(GIT_COMMIT)"` (plus `UpdatePublicKey` for desktop self-update). `String()` returns `Version+"."+Commit`, or bare `Version` when `Commit==""`. The package has ZERO imports, so the no-CGO `knomit-bridge` build (plain `go build`, no onnx/tokenizers) can import it safely — and that zero-import property is now also what qualifies it for `internal/platform/`, whose archtest forbids any knomit import. The Makefile defines the semver constant, `GIT_COMMIT := $(shell git rev-parse --short HEAD)`, and `VERSION_LDFLAGS`, applied to all three binaries; the desktop's prior separate `git describe --tags` scheme (`DESKTOP_VERSION`, `-X main.version`) was removed and folded into the unified one (desktop's `var version` deleted; `bootServer` now gets `version.String()`, still recorded in the server lockfile).

Surfaces: `knomit version` (cobra subcommand in cmd/version.go), `knomit-bridge version` (early dispatch before flag.Parse, mirroring the `claude` subcommand), `knomit-desktop --version` (checked at top of main before GUI boot). REST: `GET /api/v1/version` returns `{version, commit, full}` HAL, reads the version package directly (NOT threaded through the web.Server struct — it's global build metadata), plus a `version` link on the HAL API root and an openapi.yaml entry. UI: `VersionBadge.tsx` is fixed bottom-right, fetches `/api/v1/version` once on mount via `api.fetchVersion()`, renders `v<full>`, and shows nothing on fetch failure (best-effort, no noisy UI).

**Note:** the dotted `0.5.0.2a7ae9d` format is NOT SemVer-canonical (SemVer build metadata uses `+`, e.g. `0.5.0+2a7ae9d`); it's a deliberate display-string choice — don't feed it to a strict SemVer parser. On the dev channel `FULL_VERSION` is longer still (`0.5.2-dev.1785691723.ace95558`) and even less parseable — the BARE `VERSION` is what `pkg/updater` compares, which is why `updaterConfig` passes `version.Version` and not `version.String()`.

**WHAT THIS DOES NOT MEAN:** not that `-X knomit/internal/version.Version=...` still works. After PR #191 that path names no package, and the Go linker silently ignores an `-X` for a symbol that does not exist — the binary reports `dev` with no error. Any script or workflow that hand-writes the ldflags instead of using `VERSION_LDFLAGS` must use the platform path.

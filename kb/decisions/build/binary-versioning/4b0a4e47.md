# Binary version = Makefile-authoritative semver + short git SHA, injected via internal/version

All knomit binaries (knomit, knomit-bridge, knomit-desktop) report a build version of the form `Major.Minor.Patch.<short-sha>` (e.g. `0.5.0.2a7ae9d`).

**UPDATED (PR #55):** the Makefile constant is now `BASE_VERSION`, not `VERSION` — `BASE_VERSION := 0.5.1` is the last RELEASE, and `VERSION` is DERIVED from it per `RELEASE_CHANNEL` (stable → `BASE_VERSION`; dev → `<next patch>-dev.<committer epoch>`). The single-source-of-truth property below is unchanged; only the name of the hand-edited constant moved. Bump `BASE_VERSION` on release. See [[dev-channel]] for the derivation and its constraints.

**Options considered** (resolved via AskUserQuestion):
1. *Version source of truth* — (a) Makefile authoritative (the semver lives only in the Makefile, injected via `-ldflags`; `internal/version` defaults to `dev`) vs (b) bake `0.5.0` as the Go default and inject only the hash. **Chose (a)** — no semver duplicated across two files that can drift; release builds always go through `make`; a bare `go build`/test/IDE reports `dev`.
2. *CLI surface* — (a) both `version` subcommand and `--version` flag vs (b) subcommand-only. **Chose (b)** — `knomit version`, `knomit-bridge version`; the desktop GUI has no subcommands so it gets `--version`.
3. *Dirty flag* — append `-dirty` vs hash-only. **Chose hash-only** — matches the requested string exactly.

**Implementation:** New `internal/version` package is the single source of truth: package-level `Version` (default `"dev"`) and `Commit` (default `""`) vars, injected at link time via `-ldflags "-X knomit/internal/version.Version=$(VERSION) -X knomit/internal/version.Commit=$(GIT_COMMIT)"`. `String()` returns `Version+"."+Commit`, or bare `Version` when `Commit==""`. The package has ZERO imports, so the no-CGO `knomit-bridge` build (plain `go build`, no onnx/tokenizers) can import it safely. The Makefile defines the semver constant, `GIT_COMMIT := $(shell git rev-parse --short HEAD)`, and `VERSION_LDFLAGS`, applied to all three binaries; the desktop's prior separate `git describe --tags` scheme (`DESKTOP_VERSION`, `-X main.version`) was removed and folded into the unified one (desktop's `var version` deleted; `bootServer` now gets `version.String()`, still recorded in the server lockfile).

Surfaces: `knomit version` (cobra subcommand in cmd/version.go), `knomit-bridge version` (early dispatch before flag.Parse, mirroring the `claude` subcommand), `knomit-desktop --version` (checked at top of main before GUI boot). REST: `GET /api/v1/version` returns `{version, commit, full}` HAL, reads `internal/version` directly (NOT threaded through the web.Server struct — it's global build metadata), plus a `version` link on the HAL API root and an openapi.yaml entry. UI: `VersionBadge.tsx` is fixed bottom-right, fetches `/api/v1/version` once on mount via `api.fetchVersion()`, renders `v<full>`, and shows nothing on fetch failure (best-effort, no noisy UI).

**Note:** the dotted `0.5.0.2a7ae9d` format is NOT SemVer-canonical (SemVer build metadata uses `+`, e.g. `0.5.0+2a7ae9d`); it's a deliberate display-string choice — don't feed it to a strict SemVer parser. On the dev channel `FULL_VERSION` is longer still (`0.5.2-dev.1785691723.ace95558`) and even less parseable — the BARE `VERSION` is what `pkg/updater` compares, which is why `updaterConfig` passes `version.Version` and not `version.String()`.

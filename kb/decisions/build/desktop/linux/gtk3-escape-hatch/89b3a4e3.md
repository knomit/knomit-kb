# Wails v3.0.0 plus a DESKTOP_TAGS Makefile knob (gtk3) lets GTK < 4.14 Linux hosts build the desktop; the empty default keeps CI and release on GTK4

PROBLEM: Debian 12 hosts ship GTK 4.8, and Wails v3's default Linux backend needs GTK >= 4.14, so `make dist` (which builds the desktop since 946c73b3) failed there.

OPTIONS CONSIDERED:
- Bump Wails alone to v3.0.0: no help, the default backend still needs GTK 4.14.
- Wails `gtk3` build tag, exposed through a Makefile DESKTOP_TAGS knob.
- Build in a trixie / Ubuntu 24.04 container: the host has no docker or podman.
- Upgrade the host to Debian 13.
- Skip the desktop locally (`make server`).
- Build GTK from source: rejected, the system WebKitGTK is linked against GTK 4.8.

CHOSEN: Wails v3.0.0 plus DESKTOP_TAGS. The default, empty value leaves the build command unchanged, so CI and release keep building the GTK4 backend.

ACCEPTED COSTS: a gtk3 binary is not the backend that ships, so anything verified with it only partly covers release behaviour. Wails drops the gtk3 tag in v3.1, so the hatch ends when knomit moves past Wails v3.0.

WHAT THIS DOES NOT MEAN: gtk3 is not a supported way to ship on Debian 12; it is a way to build and test there. See kb/gotchas/build/desktop/linux/gtk/1c1421f5.md.

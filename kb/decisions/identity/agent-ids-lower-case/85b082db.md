# Agent ids are lower case everywhere (user ruling, PR #514 round 3): they are minted lower case, refused if they hold an upper-case letter, and compared EXACTLY with no case folding anywhere

OPTIONS: (a) keep ids as typed and fold case at each comparison (the review's F-finding suggested lowercasing in validLeaf to match leafFor and the author-id extraction): REJECTED, because every fold point is a place where the gate, the fleet reader, the audit and a case-insensitive checkout can disagree about whether Vic and vic are one id; (b) refuse an upper-case id at the door and compare exactly: CHOSEN.

WHAT IT MEANS: pki.ValidAgentID refuses an upper-case letter (and empty, '+', '@', white space, control characters); app.sanitizeHostname lowercases the host part when an id is minted; IssueLeaf refuses a non-lower-case agent address and the agent domain in any other case spelling; AgentIDOfEmail does no ToLower (Vic@agents.knomit.io is not an agent address); the judge, the fleet reader, member record paths, the leaf file lookup and `knomit verify audit` compare ids byte for byte (the --key hex-prefix filter of the audit is not an id and is still lowercased). A stored id that is not valid stops boot with repos.ErrStoredAgentIDInvalid; it is never rewritten (no legacy support: kb/decisions/fleet/pki/no-legacy-support/addf9dcd.md).

MISREADING: 'lower case everywhere' does not mean 'case-insensitive': an upper-case id is not valid, it is not folded to a valid one. See kb/invariants/pki/agent-id-binding/efad10db.md for the binding rules.

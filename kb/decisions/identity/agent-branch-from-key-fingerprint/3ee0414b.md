# Agent branch is 'agent/<hostname>-<fingerprint8>'; fingerprint replaces hostname-only naming

Agent branch naming: agent/<hostname>-<fingerprint8>, where fingerprint8 is the first 8 hex chars of SHA256 over the public key's SSH WIRE ENCODING — `ssh.PublicKey.Marshal()`, i.e. length-prefixed "ssh-ed25519" followed by the length-prefixed 32-byte key — NOT over the raw 32 bytes and NOT over an X.509 SPKI. (`internal/app/identity.go` `fingerprint()`; `pki.Fingerprint` is the same hash at full 64-hex length, see kb/invariants/pki/fingerprint-is-ssh-wire.) Example: agent/laptop-a7f3c2b1. Hostname is sanitized — chars invalid in git refs (spaces, ~, ^, :, ?, *, [, \) replaced with -; falls back to 'local' if os.Hostname() fails. `agentBranch` re-reads os.Hostname() on each call, so the host part can change across restarts; only the fingerprint part is stable. Hostname-only naming (agent/<hostname>) was REPLACED because it collides in containerized/CI environments. Key generation: ~/.knomit/id_ed25519 (private, OpenSSH PEM, no passphrase, 0600) + .pub (authorized_keys line + ' knomit@<host>', 0644). On first knomit serve/init, `ensureKeyPair` (unexported, internal/app) atomically writes via os.MkdirAll + temp file + os.Rename (avoids races on concurrent starts), prints the pubkey to stderr so the user can register it. Per-repo override via RemoteAuthConfig.SSHKey or KNOMIT_REMOTE_SSH_KEY env. ssh-keygen -l uses base64; we chose HEX for branch-name readability.

CONSEQUENCE: the 8 hex are 32 bits — enough to keep branch names apart, NOT enough to be an identity. Anything that authorizes (F19 grants rows, instance principal IDs) uses the full 64-hex fingerprint; the certificate SAN carries the 8 hex only as a cross-check.

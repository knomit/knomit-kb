# knomit-desktop is a supervisor of a SEPARATE `knomit serve --supervised` process: it attaches to a knomit already answering on its home's socket/pipe, else spawns the BUNDLED binary, restarts it on crashes with backoff, gives up after 5 unasked exits in 10 minutes, and never stops or restarts a server it only attached to

Built in PR #503 (merge 8be999a0, 2026-10-12), design Q2 of the desktop-as-separate-process plan; it replaced the desktop's own in-process server (tools/desktop/boot.go and friends, deleted). Options for the attach/spawn decision were: (a) always spawn and let the child fail, (b) probe the home's socket first and attach, (c) decide from the pid in server.json. CHOSEN: (b), with (a)'s exit code 3 as the race backstop (kb/decisions/serve/supervised-mode).

THE CONTRACT (tools/desktop/supervisor.go):
- PROBE: `GET /api/v1/version` (its `full` field) dialled through the same local-socket transport as the UI (auth.DialLocal). If a knomit answers, ATTACH: no child is spawned, and the attached server is never stopped on quit and never restarted (RestartApp refuses it with errAttachedServer{pid}). Attach mode re-probes every 2 s.
- SPAWN otherwise: the bundle-relative `knomit` only (never PATH; kb/invariants/desktop/server-binary/266b6326), as `serve --supervised --log-file <server log>`. The child's stdin is a pipe the desktop HOLDS: it is the lifeline (EOF = graceful stop; exit 3 needs stdin open). stdout is discarded; stderr goes to a 64 KiB ring that is logged as stderr_tail on an unexpected exit and quoted (last 20 lines) in the fatal dialog.
- ENV: the desktop's own environment with KNOMIT_HOME pinned to the home. KNOMIT_PORT, KNOMIT_HTTP, KNOMIT_HOST, KNOMIT_TLS_ADDR and KNOMIT_LOG_LEVEL are never ADDED (an env var beats knomit.toml on boot and on reload, kb gotcha 2ab87f74); the user's own values for them pass through.
- RESTART POLICY (pure, unit-tested restartPolicy): backoff 1 s doubling to a 60 s cap, reset after a run of 5 minutes up; 5 unasked exits inside 10 minutes stop supervision with a failed boot status and the fatal dialog. Exit 2 (config, trust, unwritable server.json) or a missing bundled binary is NOT retried: failed status at once. Exit 3 (the socket is held): poll up to 5 s for the holder to answer, then attach; if it never answers it counts as a crash. An UNASKED exit 0 (for example someone `kill`s the child) is a crash and is restarted, not a clean stop.
- QUIT: close the child's stdin, wait, kill after 10 s. Backstops when the desktop itself dies: macOS stdin EOF only; Linux Pdeathsig (set from a thread-locked goroutine that also does the Wait); Windows a Job Object with KILL_ON_JOB_CLOSE.
- TAKEOVER: when an ATTACHED server stops answering (3 missed probes, 2 s apart) the desktop spawns its own. A CLI `knomit serve` started afterwards on that home fails at once with 'address already in use'.
- READINESS is this probe answering; the phases the UI shows come from the supervisor (kb/decisions/desktop/startup/ui/1fe726f1). The supervisor starts on a goroutine before Wails runs (kb/invariants/desktop/startup/wails/fabd21af).

NOT MEANT: (1) 'an unasked exit 0 is a clean stop' - it is restarted; (2) 'attach mode never spawns' - it spawns its own once the attached server stops answering, and an attach, lose, spawn, exit-3 cycle costs at least 6 s per turn without counting against the crash budget; (3) 'the desktop strips KNOMIT_PORT and friends from the user's environment' - it only never adds them; (4) 'one desktop per machine' - the single-instance lock is per home (kb/gotchas/desktop/rebuilding-kills-the-running-server/e964f7b3).

REMEMBER when changing it: the SIGPIPE survival in supervised serve is part of the lifeline (kb/decisions/serve/supervised-mode/30ad3125); a stopped-for-update child is not respawned (kb/gotchas/desktop/self-update/7173001e).

NAME AND SETTINGS (knomit#504, merge 1c6a0934): the binding formerly called RestartApp is RestartServer. It is Settings-window-gated, bounded by restartWait (75 s), and the attach refusal passes through naming the pid ('started outside the app (pid N); restart it where it was started'). Settings offers reload (always) and restart (spawned servers only). Attach-mode UI behaviour and the version-skew rule: kb/decisions/desktop/settings/attach-mode/279d5688.md. Wherever this fact or a linked one says RestartApp, read RestartServer.

# Desktop icons are per-platform: macOS tray = monochrome template, Linux window icon via Options.Icon + .desktop launcher

Decision for the Wails v3 desktop app (tools/desktop) on how to give it icons across platforms.

**macOS tray icon — theme-aware two-tone swap (final).** macOS menu-bar icons should adapt to the bar's light/dark state. Constraint discovered in Wails v3-alpha.98: (1) `SetTemplateIcon` auto-tints but is ALPHA-ONLY/single-tone — a filled diamond + distinct K collapses to a blob; (2) `SetDarkModeIcon` is a NO-OP on macOS (systemtray_darwin.go setDarkModeIcon just calls setIcon; only Windows implements real dark/light switching). So to keep the two-tone app-icon look AND follow the theme we swap the icon OURSELVES: trayicon_darwin.go embeds icon-tray-light.png (dark glyph for a light bar) and icon-tray-dark.png (white diamond + dark graph for a dark bar = 'appicon without the green'), sets the right one via `tray.SetIcon` based on `app.Env.IsDarkMode()`, and re-runs on `app.Event.OnApplicationEvent(events.Common.ThemeChanged, ...)`. `applyTrayIcon(app, tray)` takes the *App so darwin can read theme + subscribe; the !darwin variant ignores it. Both tray icons are the same diamond+graph art as web/public/logo.svg, just recolored.

Rejected en route (both looked bad at ~22px): the full-color logo (clashes with monochrome menu bar), and SetTemplateIcon variants — a black diamond OUTLINE+graph, and an inverted solid-diamond-with-K-punched-out (read as a blob/octagon because the rotate(45) rounded-rect filled poorly). Lesson: preview tray glyphs at TRUE 22px in BOTH light and dark (ImageMagick: composite the PNG, and recolor-to-white for the dark-bar sim) BEFORE building.

**Linux/Windows tray:** stays the COLORED icon.png (64px) via `tray.SetIcon` in trayicon_others.go (`//go:build desktop && !darwin`) — those tray areas have no monochrome-template convention and the full-color mark reads best.

**Linux app/window icon + launcher.** Root cause of 'Linux app has no icon': `application.New(application.Options{...})` set no Icon. On Linux Wails derives the window/taskbar/alt-tab icon SOLELY from `Options.Icon` (application_linux.go setIcon + webview_window_linux.go `w.setIcon(app.icon)`); unlike macOS there is no .app bundle fallback, so an unset Icon shows GTK's generic placeholder. Fix: embed appicon.png (256px colored) and pass it as `Options.Icon` (harmless about-box icon on macOS). For the GNOME/KDE app grid, `make desktop-install` installs the binary to ~/.local/bin, appicon.png as the hicolor 256x256 app icon, and tools/desktop/linux/knomit-desktop.desktop (Exec substituted) to ~/.local/share/applications.

**Asset generation:** all committed PNGs are regenerated by `make desktop-icons` (rsvg-convert + iconutil) and //go:embed-ed into the binary.

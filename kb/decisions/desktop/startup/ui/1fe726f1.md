# The desktop window is Hidden at creation and config.js blocks on the booting server

Two coupled choices in tools/desktop/app.go, decided 2026-07-30:

1. The main window is created with WebviewWindowOptions.Hidden = true. Knomit is a tray app; Wails otherwise shows the window on every launch, including the login-item launch that "Start at login" schedules. The window is reached only via the tray's "Open Knomit".

2. Because the window can now be opened before the server is up, configInjectingHandler takes an `apiBase func(context.Context) (string, error)` (serverBoot.wait) instead of a fixed string, and HOLDS the /config.js request until the port is known, capped at apiBaseWaitTimeout (90s) and then 503. Only /config.js waits — static assets still serve immediately, so the webview is never blank, just briefly un-wired.

Rejected alternatives: disabling "Open Knomit" until ready (refuses the click the user actually wanted), and a React boot splash in web/ (frontend work for a state that lasts seconds). Boot progress is signalled on the tray icon instead — an amber badge (bootBadgeColor) that clears when the server answers.

Also considered and rejected for now: ActivationPolicyAccessory + LSUIElement to drop the Dock icon. Accessory apps need an explicit activate for Show()+Focus() to raise a window above other apps; not worth the risk without testing.

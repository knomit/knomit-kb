# In attach mode (the desktop adopted a server it did not start) Settings may save and reload but RestartServer is refused naming the pid; the banner shows both versions and warns only when parsable major.minor differ - identical strings never skew, an unparsable side is unknown

DECISION (knomit#504, merge 1c6a0934; ruled 2026-10-12 as open question 2, 'all fien'). When the desktop attached to a `knomit serve` already answering on its home's socket/pipe (kb/decisions/desktop/supervisor/d6552a5e.md), Settings behaves so: Save works and sends the reload (the CLI server applied it live in the manual run: applied, generation 2, port answers); `RestartServer` is refused with 'the knomit server was started outside the app (pid N); restart it where it was started' and the button is disabled with that explanation (canRestart false). The desktop never stops a server it only attached to; reload is allowed because it re-reads files and moves no process.

BANNER: Settings shows the attached server's pid, its version AND the desktop's version. SKEW RULE (tools/desktop/supervisor.go versionSkew): identical strings are never skew (a dev build against itself); different strings where either side does not parse as major.minor are 'unknown' - both versions are shown and NO warning; parsable pairs warn only when major.minor differ ('0.5.3.x' vs '0.5.4.y' do not; '0.5.3' vs '0.6.0' do). Reason for the first two rules: round one of the review saw 'different versions (dev and dev)' on two identical dev builds. There is no compatibility layer; the warning is advisory.

RESTART (spawned, not attached): RestartServer is Settings-window-gated like SaveSettings (renamed from RestartApp), bounded by restartWait (75 s) in the binding; the UI settles on success by polling GetSettings until the server names a new pid, on rejection, and on a 90 s UI timeout with a message. The only restart offers are server-reported restart_needed keys (raw toml names such as auth.require) and the first fleet enrolment.

MISREADINGS: (1) 'attach mode is read-only' - save and reload work. (2) 'a version warning means incompatible' - it is major.minor only and advisory; unknown shows no warning. (3) Attach detection is by the supervisor, not by the pid in server.json.

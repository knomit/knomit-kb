# The desktop's HTTP port is ONE Settings choice, Off / This computer only / All networks, saved by writing only the keys that scope moves and applied by reload; fresh installs start Off, upgrades keep it on, and the non-loopback read-only policy is unchanged

DECISION (knomit#504, merge 1c6a0934; ruled by the user 2026-10-12, 'all fien', on design Q5 and open question 1; implemented 2026-10-13). Settings has one 'HTTP port' choice with three scopes: Off (`http = false`), This computer only (loopback bind) and All networks (`host = "0.0.0.0"`), plus the port. The existing Fleet (TLS) port field stays as `[tls].addr`.

OPTIONS FOR 'LISTEN EXTERNALLY' (Q5): (a) plaintext on 0.0.0.0 with today's non-loopback policy only; (b) only the mTLS listener; (c) both, each with its own control. CHOSEN (c). (b) alone gives a browser on another machine nothing; (a) alone has no peer identity. 'All networks' is therefore the plaintext listener on every interface, NOT the fleet path.

THE POLICY IS UNCHANGED, AND THE UI SAYS SO VERBATIM: a non-loopback plaintext peer has no principal; reads pass and the write gate answers 403. The All-networks scope shows the Q5 warning text exactly (exported constant ALL_NETWORKS_WARNING, pinned as a literal in the vitest suite, shown before saving too): "Anyone who can reach this computer can READ every knowledge base and clone it, without signing in. They cannot change anything. To let other machines work with this one securely, enrol it in a fleet and use the Fleet port." `[auth].remote_read = false` is a separate, later decision (Q3); All networks is not hidden until a fleet identity exists.

WHAT SAVE WRITES: only the keys the chosen scope MOVES. Off writes `http = false` and no `host`; This computer only writes `http = true` where it moves and `host = "127.0.0.1"` only when coming back from a non-loopback host (over the default or any loopback spelling it writes no `host` at all); All networks always writes `http = true` first and `host = "0.0.0.0"`; a scope of `other` or empty writes nothing; an unknown scope is refused with the file byte-identical. `http = true` is never written into a file whose default already means it (the optional-key rule of kb/invariants/desktop/settings/save-must-parse/aaa75751.md). The scope is a closed set, so no other host string can be sent. The reload that follows (the reload-client invariant under kb/invariants/serve/reload) applies it live; moving between the default `localhost` and 0.0.0.0 needs no restart (kb/decisions/serve/reload/f44e4370.md).

ENV OWNERSHIP: KNOMIT_HTTP and KNOMIT_HOST beat knomit.toml on reload, so when either is set the whole scope is read-only in Settings (radios disabled, with a note) and scopeEdits refuses it; both are in configKeys with scope: true so one table keeps the 'overridden by environment' display and the writer in agreement.

UPGRADE DEFAULT: the server default stays `http = true` (config.Defaults), so `knomit serve`, Docker and the e2e suite are unchanged. Only a FRESH desktop install gets `http = false`, written before the first spawn (detection rule: the fresh-install-detection invariant under kb/invariants/desktop/settings). Upgrades keep the port on so existing MCP-over-HTTP clients and browser tabs keep working; Settings shows the state. Alternative not taken: off for everyone with a one-time notice.

MISREADINGS: (1) 'The desktop turns HTTP off' - only on a home with neither knomit.toml nor control.db. (2) 'All networks = secure external access' - it is anonymous read-only; fleet is the secure path. (3) 'This computer only always writes host = 127.0.0.1' - it writes nothing over a loopback or default host. (4) The ack for All networks says 'HTTP port on 127.0.0.1:<port>' because server.json spells the dialable URL that way while the socket binds *:<port>; the warning, not the ack, says all networks.

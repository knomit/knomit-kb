# The desktop Settings → Network → Fleet has an External address row: it writes the root external_addresses (https:// only, validated by config.ValidateExternalAddress) ONLY when the list changed, and restarts the app-spawned server ONLY after a reload whose outcome is restart_needed; external_addresses stays restart-only (f44e4370 stands) (#545)

DECISION (user ruling 2026-10-17, option (a); PR #545, merged into dev at 7ce30154; read there). A fleet hosted on this instance needs an external address (the server refuses `addresses_required` without one) and the desktop had no way to set it. Options put to the user: (a) an "External address" field in the desktop Settings with a restart on save; (b) make external_addresses reload-live, which would change decision f44e4370. CHOSEN (a). f44e4370 STANDS: `external_addresses` is not a reload-live key; a reload lists it in server.json `restart_needed` (observed: `needs a restart: [external_addresses]`, GET /fleet keeps `[]` until the restart).

WHAT. A row under the Fleet listener in Settings → Network takes one or more addresses separated by commas or spaces (copy: kb/decisions/fleet/ui-copy/external-address-and-hosting-cards/). `GetSettings` sends `externalAddresses` and never null. The save writes the ROOT key `external_addresses = [...]` with `tomledit.SetStringArray` (a one-line array).

VALIDATION. Go `validateExternalAddresses` (tools/desktop/settings.go) runs `config.ValidateExternalAddress` (exported by this PR from config's own boot check, which accepts any scheme://host[:port]) on each entry, then requires `https://`: members reach the Fleet port over https, and https is the only scheme an enroll accepts. The form mirrors it before the round trip and marks the field inline (it is stricter in places, for example `https://h:`; Go stays the authority). Validation runs before any write, so a refused list leaves the file untouched.

WRITTEN ONLY WHEN THE LIST CHANGED (review finding F2). `applySettings` writes, and validates, `external_addresses` only when the list differs from what the file decodes to (`fileExternalAddresses`; nil equals empty). Reason: `SetStringArray` rewrites ONE line, so on an array the user spelled over several lines it leaves continuation lines behind, the decode gate (aaa75751) then refuses, and EVERY unrelated Settings save failed. The same rule means a hand-written `http://` entry no longer blocks an unrelated save, and an empty list is never created in a file that never had the key (a cleared list becomes `[]`). The form validates only when the field differs from the last saved value.

RESTART ONLY AFTER restart_needed (review finding F3). When the save's reload outcome is `restart_needed` and lists `external_addresses` and the app spawned the server (`canRestart`), the form calls its existing `restart()` (the same RestartServer, notices and timeout as the "Restart server" button), so the fleet pages' 5 s GET /fleet poll clears the wizard's address card with no further click. After `listener_failed`, `refused` or a timeout nothing restarts: the error line stays, and a restart would hide it or act on a file the server would not load. An attached server is never restarted; it keeps the bar's "restart it where it was started".

PINS. tools/desktop/settings_external_test.go (write, clear, empty creates nothing, refusals write nothing, multi-line and unchanged-http saves) and tools/desktop/ui/src/SettingsForm.external.test.tsx (parse, save, four inline refusals, auto-restart, no restart on other outcomes or when applied). NOTE: the //go:build desktop Go tests do NOT run in CI (the desktop job is skipped); run `go test -tags desktop ./tools/desktop/...` locally.

VERIFIED on the real binary (the Settings window itself cannot be driven outside the Wails webview; its effect was reproduced as the toml shape plus `knomit reload`): after the restart the wizard's address card cleared by itself, the create succeeded in the same process and a second instance joined.

MISREADINGS. "external_addresses is now live on reload": it is not; the desktop restarts the server for you. "The browser Settings can set it": the field exists only in the desktop window; a browser-only `knomit serve` user still edits knomit.toml and restarts (the user's ruling put the words "Add it in Settings → Network" in the web card regardless).

# A held [tls].addr is an AVAILABILITY failure: WARN and serve without TLS when the caller is supervised (`knomit serve --supervised`, how the desktop spawns its server), a boot failure for plain `knomit serve`; a TRUST failure (certificate installed but unloadable) fails every caller — app.ErrTLSAddrInUse is how the caller tells them apart

OPTIONS (knomit#256, user ruling 2026-09-25): when the desktop cannot bind [tls].addr, (a) fail the boot, for parity with `knomit serve`; (b) WARN and serve without the TLS listener. CHOSEN: (b) for the desktop only.

WHY: a bind conflict is an availability failure — failing 'open' means NO TLS listener, fewer doors, not more — the same shape as auth.ErrSocketInUse, which both binaries already treat as benign. The desktop and `knomit serve` on one machine share <home>, hence the key, [tls].addr and <home>/pki, so whichever starts second finds the port held; under (a) the desktop user would lose the knowledge UI and MCP server because the other knomit is already serving the fleet. `knomit serve` is a fleet node, and one asked to serve the fleet that cannot must not come up looking healthy, so serve FAILS THE BOOT on every TLS error. Since #261/#286 'fails the boot' means RunE RETURNS the error and main.go exits after RunE's defers (the crash marker's release among them) — never log.Fatal. TestServeTLS_BindConflictFailsTheBoot runs the whole RunE and asserts the returned error wraps ErrTLSAddrInUse AND the marker is gone.

MECHANISM: OpenTLSServer wraps a listen error that is address-in-use as ErrTLSAddrInUse (isAddrInUse: syscall.EADDRINUSE on unix, windows.WSAEADDRINUSE on Windows, where the two are NOT the same errno). Every other error — CRL missing or malformed, older than crl.number, certificate for another key — is returned unwrapped and fails the desktop's boot too. TestOpenTLSServer_AddrInUseIsTypedAndTrustFailureIsNot asserts both directions.

MISREADING TO AVOID: 'the desktop tolerates TLS errors' is false. It tolerates exactly one, a held address; a trust failure fails the boot on both binaries. Consequence for operators: a desktop that logs 'serving without the mTLS listener' is NOT a peer, even though [tls].addr is set.

SINCE #493 (merge 9860c726, 2026-10-12) THE POLICY IS CHOSEN BY `--supervised`, NOT BY BINARY. The paragraphs above describe the two callers as they were at #256: 'the desktop' warns, 'knomit serve' fails. Now app.OpenListeners (internal/app/listeners.go) decides from ListenerOptions.Supervised: plain `knomit serve` still fails its boot on a held [tls].addr (app.ErrTLSAddrInUse) and on a held plaintext port (exit 1); `knomit serve --supervised` - how the desktop will spawn the server - logs a WARN and serves without that listener; the desktop's own bootServer, which had a hand-written warn path, was DELETED by #503 (merge 8be999a0): the desktop has no boot of its own any more, so there is exactly one place (app.OpenListeners) that applies this policy, and the desktop gets the WARN-and-serve behaviour by spawning `knomit serve --supervised`. A TRUST failure still fails every caller and, supervised, is an app.ListenerConfigError that exits 2.

NOT MEANT: 'serve tolerates a held TLS address' is false for a plain `knomit serve`; the tolerance is the flag. A supervised serve that warned is still not a fleet peer. Full flag semantics and exit codes: kb/decisions/serve/supervised-mode. Pins: TestOpen_Supervised and TestOpen_EveryFailureReleasesEveryAddress (internal/app/listeners_test.go), TestServeSupervised_TLSAddrHeldWarnsAndServes, TestServeSupervised_PortHeldWarnsAndServes (cmd/serve_supervised_test.go). TestServeTLS_BindConflictFailsTheBoot still pins the unsupervised row.

UPDATE (PR #503, merge 8be999a0): the first paragraphs describe the policy as it was when 'the desktop' and 'knomit serve' were two callers (TestBootServer_TLSAddrInUseWarnsAndServes is gone with bootServer). Today the policy is purely the flag: supervised warns and serves without the held listener, plain serve fails the boot, and a trust failure exits 2 under --supervised, which the desktop supervisor treats as 'do not retry' (kb/decisions/desktop/supervisor).

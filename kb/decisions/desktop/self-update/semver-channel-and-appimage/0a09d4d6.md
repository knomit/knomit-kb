# Self-update ships macOS-ONLY on a new semver channel; Linux gets an AppImage but is hard-disabled from updating, in code, not merely by feed contents

**Options considered** (2026-07-28 design session, amended same day).

Versioning: (a) add real semver tags/releases alongside the untouched rolling `dev-latest` — CHOSEN; (b) keep `dev-latest` only and write a custom provider comparing commit SHA / `published_at`; (c) both channels from day one.

Linux: (a) AppImage + an upstream `$APPIMAGE` patch carried on a fork — chosen first, then REVERSED; (b) macOS-only self-update, Linux packaged as an AppImage that does not update itself — FINAL; (c) bare `knomit-desktop` binary as the update asset; (d) `WindowNone` on Linux plus a hand-written swap driven from `DownloadedPath()`.

**Rationale — why the current release shape cannot work at all.**

Both providers gate on `semver.IsNewer(tag, req.CurrentVersion)`. knomit's only git tag is `dev-latest`, deliberately deleted and recreated on every run, and the build version is `VERSION.GIT_COMMIT` (e.g. `0.5.0.2a7ae9d`) from the Makefile. NEITHER SIDE PARSES AS SEMVER, so the update check can never fire. This is not a tuning problem; it is a hard block. Semver releases beat a custom SHA-comparing provider because they use the stock code path with zero custom comparison logic. Conveniently `version.Version` is ALREADY the bare semver (`0.5.0`) — `version.String()` is the one that appends the commit — so `Config.CurrentVersion` needs no new plumbing.

**Why Linux self-update was dropped.** The updater replaces EXACTLY ONE path: `target := bundleTarget(selfExecutable())`, not configurable, and `maybeExtractInto` rejects archives with more than one top-level entry. The macOS `.app.zip` is `ditto --keepParent`, so its single top-level entry is `Knomit.app` and `bundleTarget` swaps the whole bundle — works on stock code. Linux cannot: `pkg/updater` has ZERO occurrences of `APPIMAGE` anywhere in `pkg/`, so inside a mounted AppImage `os.Executable()` resolves into the FUSE mount and the swap targets the mount, not the `.AppImage` file.

Fixing that requires patching `selfExecutable` in `pkg/updater/spawn.go`, which knomit CANNOT do locally — it is a package var reassignable only from inside the package (`export_test.go` is the only seam and is test-only). Nor can the broken call be intercepted: `window_lifecycle.go:85-86` shows the built-in update window subscribing to its own `EventUserRestart` and calling `u.Restart(ctx)` itself, so subscribing to the same event would just produce a second, competing swap. That left: carry a fork + `go.mod replace`; or use `WindowNone` on Linux and hand-write the swap around `DownloadedPath()`, owning the wait-for-parent / backup / retry / restore logic `helper.go` already implements; or ship macOS-only. **macOS-only won** — no fork, no upstream dependency, macOS runs entirely on stock code.

**TWO guards enforce macOS-only, and BOTH are required.** `updaterConfig(goos)` refuses to enable on any GOOS but darwin, AND `desktopArtifact` refuses to map `.AppImage` to a feed item. The feed alone is NOT a guard: it is remote data that can change long after a binary ships, so a single future `linux` entry would trigger a broken swap on every installed AppImage. The GOOS check in code is what actually protects them. The tray's "Check for Updates…" item is likewise only added where self-update is live.

**The AppImage survived the reversal, but its justification changed.** It originally earned its place by making the one-path swap possible. With Linux self-update deferred it stands on packaging merits alone — one self-contained file instead of a tarball plus `install.sh` — plus pre-positioning Linux for later. A bare-binary asset was rejected separately because `lib/` (ONNX Runtime) would never update, so an ORT bump would silently break Linux self-updaters.

**The AppImage's cost is UNCONDITIONAL, independent of updating.** `tools/desktop/bundled.go`'s `installBundledTool` resolves `os.Executable()` and symlinks `<home>/bin/<tool>` at the sibling binary. Inside an AppImage that target is inside the FUSE mount, which VANISHES when the app quits — every MCP client wired to `<home>/bin/knomit-bridge` would find a dangling link. Fix: COPY on Linux instead of symlinking, refreshing when the shipped version differs. macOS keeps the symlink, because the `.app` lives at a stable path and the updater replaces the bundle in place. This applies whether or not the app ever updates itself.

Also: the AppDir must place ONNX libs at `usr/bin/lib/`, not `usr/lib/`, because knomit resolves native libs from `<exe>/lib`. And the `.desktop` template carries `Exec={{EXEC}}` and `Icon=knomit-desktop`, so the AppDir needs a `sed` substitution plus the icon renamed to `knomit-desktop.png` — appimagetool matches `Icon=` against the icon's basename.

**Non-scope.** The existing `release.yml` and the rolling `dev-latest` pre-release are UNTOUCHED — this adds a second channel, it does not replace the dev one. Dev builds never self-update. This does NOT mean "Linux self-update is impossible" — it means it is deferred pending an upstream fix; re-enabling is three steps (land the `$APPIMAGE` fix upstream, add `.AppImage -> "linux"` to `desktopArtifact`, relax the GOOS check), and both code sites carry comments saying so. Windows is not a release target.

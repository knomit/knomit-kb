# Optional domain/entity ScopeFilter bounds the discovery seed pool; empty = whole-corpus; a scoped run always full-scans (exempt from the watermark)

knomit_review and knomit_hypothesize accept optional `domain` / `entities` array args → synthesize.ScopeFilter (D7). An EMPTY filter (zero domains AND zero entities) = whole-corpus, the historical default — explicitly NOT a 'match nothing' footgun.

Scope membership is decided in Go via ScopeFilter.Matches, the single definition: UNION semantics — a fact is in scope if it touches ANY requested domain OR entity (not all). It is deliberately NOT pushed into SearchOptions.Domain/Entities: store.Search ANDs those clauses (intersection) and canonicalises domains, which would diverge from Matches.

SEED-POOL PATH (the load-bearing rule): the seed step takes the full-scan path (full epistemic/synthesis search + Matches filter) when EITHER the watermark is empty (first run) OR a scope filter is active. A scoped run therefore ALWAYS full-scans — it never takes the incremental (post-watermark DiffFiles) path. This is because scoped runs are exempt from the watermark on BOTH sides: they do not ADVANCE it (advancing to HEAD would hide out-of-scope facts from future unscoped runs) and they are not BLOCKED by it. The read/write sides must agree — gating a scoped run on the shared watermark meant that once a prior unscoped run pushed it to HEAD, every scoped run diffed an empty changeset and found ZERO seeds (the 'scoped review/hypothesize finds nothing' bug). Only the UNSCOPED path is incremental: empty watermark = first-run full scan, non-empty = DiffFiles since watermark.

A non-empty scope also signals 'already bounded', so the bridge engine skips effort-budget truncation. Regression guards: TestScopedReview_NonEmptyWatermark_StillSeedsInScope (synthesize), TestScopedHypothesize_NonEmptyWatermark_StillSeedsInScope (mcp).

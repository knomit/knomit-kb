# Bridge seeding: a model-less cross-cluster shared-token detector; discovery never feeds on its own output

A bridge is a structural token (entity or domain) shared by ≥2 facts living in DIFFERENT cluster communities — a connection across regions the clustering says are otherwise unrelated (D4). Candidates are enumerated by enumerateBridgeCandidates (group non-discovered seeds by shared token; keep tokens whose ≥2 members span ≥2 communities), then scored by buildScoredBridges: oversized token-groups are reshaped to their cohesive cross-community core (reshapeCohesiveSubset, gated by CohFloor/MaxMembers) and ranked by a composite quality score Q (bridgeQ), with Louvain separation a HARD GATE (sep≥2), never a ranking reward. The old strength = (1/freq)×communities×members formula was retired (it rewarded breadth, producing grab-bags); bridgeSeeds/enumerateBridgeCandidates itself no longer computes strength. It hands the {A..D} seed set to the connected MCP agent. The engine is MODEL-LESS: it only ranks and bounds; the agent is the sole reasoner.

Which axis counts (domain/entity/both) comes from DiscoveryConfig.Bridge via BridgeKindFromString — BOTH directions honor it. Both directions also cluster with the SAME knob the rest of the system uses — RepoInstance.ClusterResolution() / ClusterMinCommunitySize(), nothing hardcoded.

CLUSTERING SOURCE (updated, PR #97 merge over PR #98): both forward (review) and backward (hypothesize) now cluster the SAME way — in-process scoped clustering via ScopedCluster (gonum Louvain over idx.SubgraphEdges on the seeds + nearest neighbours). The old whole-corpus CachedClusterFacts + warm cluster cache the backward path used was DELETED by PR #98; there is no global clustering anymore. The ClusterResult the bridge engine consumes now lives in the synthesize package and is built from ScopedCluster output via clusterResultFromGroups. See the dedicated decision fact for the migration.

IDEMPOTENCY (§7): facts with origin=discovered are NEVER selected as seeds, so discovery cannot drift off the human-authored substrate. A seed absent from every cluster is given a synthetic NEGATIVE community id (in bridgePathCommunities), so it never collides with real community 0 — this also covers facts ScopedCluster drops as sub-floor singletons.

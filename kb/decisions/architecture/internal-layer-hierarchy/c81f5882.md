# internal/ is restructured into seven enforced layers (platform, domain, foundation, engine, corpus, edge, app); a layer is an import rule checked by TestLayers

Ruled by the user 2026-10-20. Context: internal/ had 22 top-level entries and four packages (store, repos, web, synthesize) holding 67% of non-test lines; the tree did not show the dependency ordering the import graph already has (a clean DAG).

OPTIONS (D1). (a) Full plan: layer directories plus splitting the giant packages. (b) Split the giants only and keep internal/ flat. (c) Amend layer names or membership. CHOSEN: (a). (b) remains the fallback if the layering stalls, since the giant splits are independent of it.

THE LAYERS (D4, names as proposed). A package may import its own layer and any layer below, never above; same-layer edges between distinct packages must be listed. Order low to high: platform (OS and binary, nothing about knomit), domain (pure concepts: fact, okf, model params; no I/O, SQLite, git or cgo), foundation (config, auth, pki, serverkey, serveraddr, client sessions (package clientsessions); no corpus), engine (store, embeddings, llm: one external resource each), corpus (repos, refs, federate, resolutions, synthesize: operations on mounted repositories), edge (mcp, web, oauth: protocols facing the outside), app (composition root). internal/testsupport is exempt (only _test.go may import it).

RATIONALE (D2, D3). The #191 objection to grouping subsystems was 'a level with no enforceable property'. TestLayers (test/archtest) is that property: it checks direct imports for the default GOOS, -tags desktop, linux, windows and darwin, fails on empty listings and missing sentinels, and reports any package mapped to no layer. TestLayers is ENFORCING since step 04b (PR #592): every violation is a t.Errorf and a package is mapped to its layer only by its internal/<layer>/ directory (see the CURRENT STATE paragraph below). History: during the moves (steps 01 to 04a) it mapped not-yet-moved flat paths through a shrinking table and shipped report-only behind a single constant; that table and constant no longer exist. Measured on the tree at PR 0: zero upward imports and zero unmapped packages; 15 same-layer edges, all listed. After the sqlite extraction (#548) the table listed 16: store/internal/sqlite -> store/git (today engine/store/internal/sqlite -> engine/store/git) was added because the sqlite child re-exposes the git storer's ctx-carried transaction helpers. The no-new-top-level-packages convention is amended to 'only the listed layer dirs, enforced by TestLayers'; the group-by-what-a-package-knows decision is superseded in part.

SEQUENCING (D5). The store split (store back-edge cuts, then children sessions, sqlite, vcs, fleetrec, verify, facts, merge, index, vocab, sync, gitserve, fsck) lands BEFORE the layer directory moves, so its value lands even if layering stalls. D6 model budget: haiku for mechanical moves, opus for vcs and fleet, sonnet elsewhere.

CONSEQUENCES. embeddings/params moves to domain/modelparams (config in foundation imports it; leaving it under embeddings would be an upward edge). New packages go inside a layer directory, never a new top-level entry.

NON-SCOPE. This does not authorize new top-level directories beyond the seven layers, and does not by itself split any package. (The layer rule was deliberately not enforcing until the moves landed; it is now, see CURRENT STATE.)

STATUS (step 01 of the layer move, PR #588, merged to dev 2026-10-22; historical, superseded by CURRENT STATE). internal/fact (with textnorm) and internal/okf (with source) moved to internal/domain/fact and internal/domain/okf; internal/embeddings/params moved to internal/domain/modelparams and its package clause changed from params to modelparams. legacyLayers lost its fact, okf and embeddings/params entries, so layerOf now resolves those packages by directory; the table keeps shrinking one step at a time. sameLayerEdges keys for the domain layer are now "domain/okf -> domain/fact" and "domain/okf/source -> domain/fact". The TestLayers sentinel for the domain layer is "domain/fact". At that step the layer rule was still report-only and reported 0 violations over 58 packages x 5 configs after the move. Still pending: foundation (step 02), engine (step 03), corpus and edge (step 04). This dated status does not describe the current state.

STATUS (step 02 of the layer move, PR #589, merged to dev 2026-10-22; historical, superseded by CURRENT STATE). The foundation layer now exists as internal/foundation/: config, auth, pki (with pkitest), serverkey and serveraddr moved to internal/foundation/<name>, and client/sessions moved to internal/foundation/clientsessions. The moved package's name changed from sessions to clientsessions (importers that did not alias it had their qualifiers rewritten), so it no longer shares a name with store/sessions. At that step the transitional table had no foundation entries left (only engine, corpus and edge packages remained in it) and the rule was still report-only, with 0 violations over 58 packages x 5 configs. Guard keys that follow the new paths: sameLayerEdges is now "foundation/config -> foundation/auth", "foundation/serveraddr -> foundation/auth", "foundation/serveraddr -> foundation/config"; the TestLayers sentinel for the foundation layer is "foundation/config"; internal/repos/fleet_texts_test.go resolves modroot.Path(t, "internal", "foundation", "pki"); the install_callers, origin_scheme and reload_callers archtests use the prefixes internal/foundation/pki/ and internal/foundation/serveraddr/; TestConformance_NoConfigSurface reads internal/foundation/config/config.go; the fast-unit package list in tests.yml follows the new paths. (Engine, corpus and edge followed in steps 03 and 04.)

STATUS (step 03 of the layer move, PR #590, merged to dev; historical, superseded by CURRENT STATE). The engine layer now exists as internal/engine/ holding embeddings, llm and store (the store's children moved with it, e.g. engine/store/model). the transitional table was down to corpus (repos, refs, federate, resolutions, synthesize) and edge (mcp, web, oauth) entries. At that step TestLayers reported 0 violations but was report-only (a sabotage that made engine/embeddings import oauth/idp logged a report-only message and the test still passed). Lesson that still holds: a go-list sabotage of an upward import that forms a cycle fails for an unrelated reason (the go list error), so it does not falsify TestLayers; use a non-cyclic upward edge.

STATUS (step 04a of the layer move, PR #591, merged to dev as 1ac3a742; historical, superseded by CURRENT STATE). The corpus and edge layers now exist as directories: internal/{repos,refs,federate,resolutions,synthesize} moved to internal/corpus/<same>, and internal/{mcp,web,oauth} moved to internal/edge/<same>, all subpackages included (web/hal, oauth/idp, oauth/idp/idptest); package names are unchanged. The transitional table in test/archtest/layers_test.go was then an EMPTY map, so every package was mapped by directory; the rule was still report-only until step 04b. Guard keys that follow the new paths: sameLayerEdges is now "corpus/federate -> corpus/repos", "corpus/resolutions -> corpus/refs", "corpus/resolutions -> corpus/repos", "corpus/synthesize -> corpus/refs", "corpus/synthesize -> corpus/repos", "edge/web -> edge/mcp", "edge/web -> edge/oauth"; the sentinels are "corpus/repos" (corpus) and "edge/web" (edge). Step 04b then made the rule enforcing.

CURRENT STATE (step 04b, PR #592, merged to dev as 0610c200). TestLayers in test/archtest/layers_test.go is ENFORCING: the constant enforceLayers and the transitional map legacyLayers are deleted. layerOf resolves a package only by its internal/<layer>/ directory (internal/testsupport is exempt, internal/app is the app layer); a package in no layer directory is reported 'maps to no layer'. Violations (upward import, unlisted same-layer edge, unmapped package, launder) are t.Errorf, de-duplicated across configurations. LAUNDER RULE: go list covers all of knomit/... (not only internal/); an internal package may import a non-internal knomit package only if that package imports nothing from knomit (derived from the go list data, no allowlist; a non-internal package missing from the listing also fails). The one real such edge today is edge/web -> knomit/web (the embedded UI); knomit/web importing nothing from knomit makes it a leaf. STRUCTURAL FLOOR: every directory under internal/ holding a .go file (skipping testdata and names starting with _ or .) must be listed as a package by at least one of the 5 configurations (default, desktop, linux, windows, darwin) or the failure names the dir; there is NO package-count constant. Per-layer sentinels still guard against a wrong pattern. STALE KEYS: every sameLayerEdges key must be observed as a real same-layer edge in at least one configuration, else it fails as stale. The desktop configuration is kept but no internal file carries a desktop constraint today, so it adds no coverage of internal/. USER RULING (step 04b): tests may import anything; the layer rule covers production (non-_test.go) imports only, because go list .Imports omits _test.go files. Does NOT mean: cmd/ and tools/ importers are checked (they sit above every layer by construction); production imports of internal/testsupport are caught here (test_signer_isolation_test.go owns that); test imports are checked (they are not, by decision).

MIGRATION NOTE. golang-migrate (v4.19.1) as used by internal/engine/store/migrate tracks only version and dirty in schema_migrations (sqlite3 driver table: version uint64, dirty bool) and stores no content checksum of applied migration files. Editing a comment (or any text) in an already-applied migration therefore cannot trip a checksum check; it just never re-runs. This does not make editing applied migration SQL semantically safe: a changed statement is not re-applied to databases that already passed that version.

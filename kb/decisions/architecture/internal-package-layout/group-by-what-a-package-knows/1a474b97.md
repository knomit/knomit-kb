# internal/ is grouped by WHAT A PACKAGE KNOWS: internal/platform/ holds the process tier (knows the OS and the binary, nothing about knomit), internal/fact/ holds the pure domain leaf, and everything that touches a corpus stays a top-level subsystem

Decided 2026-09-14, landed as PR #191 (merge b0603592). `internal/` had grown to 17 top-level entries with no cue separating a 5-file cgroup reader from the 55-file store, and nothing said where the NEXT small helper should go. It is now 14 entries, sorted by one rule.

**The rule: group by what a package knows.** In this codebase that is the same axis as dependency weight, so it is consistent with the earlier constraint that nesting must be weight-monotone (a child is never heavier than its parent — see the two sibling decisions).

| tier | knows about | members |
|---|---|---|
| process | the OS and the binary; nothing about knomit | `internal/platform/{crashdump,diag,logging,metrics,reqinfo,memlimit,version}` |
| domain leaf | facts as text; no corpus, git or SQLite | `internal/fact`, `internal/fact/textnorm`, `internal/embeddings/params` |
| subsystem | a corpus, a store, a network, a model | everything else, each top-level |

Only the first two tiers are grouped. Subsystems earn a top-level slot.

**Moves.** `internal/obs/*`, `internal/memlimit`, `internal/version` → `internal/platform/<name>` (flat; `obs/` dissolved rather than nested because `platform/obs/metrics` is three levels for one-file packages). `internal/textnorm` → `internal/fact/textnorm`, because its subject is a fact concept (when two tags, domains or motifs are the same token; its rules were tuned on the knomit corpus) and it is lighter than its parent (75 deps vs fact's 156). All 44 files moved as git renames, contents unchanged.

**Options rejected.** `internal/runtime/` for the tier — collides with stdlib `runtime` in every import block that needs both. Keeping `obs/` as `platform/obs/` — legal, same rule, one more level for no gain. Grouping `llm` + `embeddings` as adapters — each is a large subsystem and the grouping would add a level with no enforceable property attached. `refs` under `fact` or `store`, and `federate` under `web` — already ruled out (refs: weight inversion; federate: imports store and repos, and is consumed by both mcp and web, so neither is its parent).

**The property is enforced, not documented.** `TestPlatformKnowsNothingAboutKnomit` (test/archtest/layering_test.go) fails if any package under `internal/platform/` transitively imports a knomit package outside the tier; it also refuses to pass vacuously (fatal on an empty `go list`, fatal if `platform/logging` is missing from the match). `TestTextnormImportsNoInternal` fails if `fact/textnorm` imports any knomit package; the reverse edge (textnorm → fact) is a compile-time cycle since fact imports it. Both were sabotage-verified.

**The one edge the rule broke, and how it was fixed.** `obs/logging` took `config.LogConfig`. Rather than carry an exception list — the way a layering rule stops meaning anything — logging now declares its own `logging.Options`, and the single `config.LogConfig → logging.Options` converter is `app.LoggingOptions` in `internal/app`. It lives there and not on config because config importing logging would add lumberjack/gzip/crc32 to config's closure, and config is imported almost everywhere; `app` already imports config and is already imported by both binaries that build a logger. During review the duplicated field copy was found to be worse than it looked: one of the two copies was in `tools/desktop`, behind the `desktop` build tag, so a plain `go build ./...` never compiled it.

**Consequence to act on — where the next package goes.** Knows nothing about knomit (would pass the platform archtest) → `internal/platform/`. Pure text or fact helper with no corpus access → under `internal/fact/`, and add it to the archtest's pure-leaf guards. Touches a corpus, store, network or model → its own top-level `internal/<name>`, never nested under a lighter parent. A platform package that needs a knomit type takes it as a parameter (the `logging.Options` pattern) or does not belong in the tier.

**WHAT THIS DOES NOT MEAN.** Not "small packages go in platform" — size is not the criterion; `reqinfo` is one file and belongs because it carries a string, `refs` is one file and does not because it imports the store. Not "a platform package may import `internal/config` because config is light" — the archtest has no exception list on purpose; take the values as parameters. Not that `internal/obs`, `internal/textnorm`, `internal/memlimit` or `internal/version` exist anywhere at HEAD; historical `src://` refs to them still resolve by blob, but a grep for those paths finds only comments and this corpus.

**Known reach gaps, pre-existing and left open:** the platform archtest lists packages for the host GOOS only and ignores `_test.go` imports (the tree is clean on darwin, linux and windows today, checked at review), and the shared `deps()` helper passes silently when a package fails to parse, because `go list -deps` exits 0 on a syntax error — shadowed by `go build` in CI.

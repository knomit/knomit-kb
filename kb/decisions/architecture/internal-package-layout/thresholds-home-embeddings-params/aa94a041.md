# Model-dependent cosine thresholds live in internal/embeddings/params — a cgo-free CHILD of embeddings that must never import its parent

The six absolute cosine cutoffs (Dedup, ReflectNovelty, SimilarTo, SearchFloor, RerankHigh, RerankLow) plus DefaultModelID live in `internal/embeddings/params`, formerly the top-level `internal/retrieval`.

**Options considered**

1. `internal/embeddings` itself — the semantically obvious home, since `embeddings.Model` is what declares these per model.
2. `internal/store` — store already defines the `Embedder` interface with a `Thresholds()` method, and store does not import embeddings, so there is no cycle.
3. `internal/config` — config ALREADY holds tuning floats (CohFloor, QualityFloor, WCoh/WGap/WSpec, ConfidenceThreshold, MethodologyMinScore), so "config is not for numbers" is not a real objection.
4. Keep a top-level dependency-free leaf, possibly renamed (`internal/tuning`, `internal/calibration`).
5. A cgo-free CHILD of embeddings that does not import its parent. **Chosen.**

**Rationale**

Option 1 is hard-blocked: `internal/embeddings` carries cgo (`import "C"` in four `cgo_link_*.go` files, ONNX via daulet/yalue). `store` importing it would link the ONNX runtime into every store consumer. Its transitive closure is 388 deps / 189 external.

Option 2 is legal but backwards — `embeddings` would inherit store's 387-dep / 189-external closure (sqlite, go-git, golang-migrate) just to declare one struct field. The low-level embedder should not depend on the storage layer.

Option 3 was rejected on OWNERSHIP, not on tunability. Every `config` field arrives from the user's TOML — each carries a `toml:` tag. Thresholds arrive from whichever ONNX model loaded: they are fields on `embeddings.Model`, delivered via `Embedder.Thresholds()`, consumed through the `store.Embedder` interface. There is deliberately NO TOML key for dedup/similar_to/search_floor. Putting a model-owned value in the user-owned struct invites someone to add that key, and `Dedup` is an absolute point on one model's cosine distribution — setting it without recalibrating silently over-merges facts, which is data-lossy. Config also cannot pick the right set without knowing which model loaded, which would mean importing embeddings (cgo again) or duplicating the model registry.

Option 5 wins because Go packages are independent — a child never implicitly imports its parent — so `store`, `config` and `synthesize` import the child and touch no cgo, while the PATH finally states whose values these are. `internal/retrieval` promised retrieval logic and delivered one struct. Precedent already existed in the tree: `web/hal` is 186 deps / 16 external under `web` at 764 / 523.

The move also retired a hand-synced constant. `embeddings.DefaultModelID` carried the comment "config.Defaults() mirrors this literal ('embeddinggemma') because the config package cannot import this one (it carries cgo); keep the two in sync" — and was itself referenced NOWHERE, while config.go hardcoded the literal beside it. DefaultModelID now lives in params, config references it, and embeddings re-exports it.

**The choice**

`internal/retrieval` → `internal/embeddings/params`. Package `params`, exposing `Thresholds`, `Defaults()` and `DefaultModelID`. The package's identity is "the cgo-free half of the embedding-model contract" — everything a non-cgo caller needs to know about a model without linking one.

**Consequence to act on**

The nesting creates a trap that is the mirror of the one that kept `refs` out of `fact`: adding a helper to `params` that needs the model registry, importing the parent, silently links ONNX into store/config/every binary. Nothing fails; the binary just grows cgo. `TestParamsHasNoDependencies` in `test/archtest` therefore asserts ZERO non-stdlib imports — the strictest available check, foreclosing the mistake rather than enumerating it. Do not weaken it to a list of banned packages. Without that guard the nesting would NOT have been chosen; a top-level leaf would have been safer.

**Non-scope**

This does not establish "nest small leaves under their semantic parent" as a general rule. It was chosen here because (a) the parent genuinely owns the values, (b) the child is dependency-free so the light-child-under-heavy-parent inversion is harmless, and (c) an enforcing test exists. Where the child would be HEAVIER than the parent, nesting is wrong — that is exactly why `internal/refs` was NOT nested under `internal/fact`, recorded in kb/decisions/architecture/internal-package-layout/refs-owns-resolution-not-classification/bfe6bf16.md.

It also does not decide anything about the other tuning floats still in `config` (CohFloor, QualityFloor). Those are derived by `tools/calibrate bridges` from a score distribution built on SIMILAR_TO edges drawn using `Thresholds.SimilarTo`, so by this same ownership test they look mis-homed — but that is an open question, deliberately untouched here because it is a behaviour change rather than a package move.

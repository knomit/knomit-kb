# The same-layer edge foundation/auth -> foundation/pki is ALLOWED (listed in archtest sameLayerEdges): auth.ListenTLS wraps the raw listener with pki.NewListener so a refused handshake delivers its alert (#543); user-approved over moving ListenTLS into pki or having app build the listener

CONTEXT. PR #741 (#543) made auth.ListenTLS call pki.NewListener, which wraps each raw connection under tls.NewListener so a connection whose handshake pki's verifier refused half-closes and drains instead of resetting (the bad_certificate alert then reaches a Windows client). test/archtest TestLayers refuses any same-layer import not listed in sameLayerEdges, so `foundation/auth imports foundation/pki` failed CI.

OPTIONS CONSIDERED.
(1) Allow the edge: add "foundation/auth -> foundation/pki" to sameLayerEdges.
(2) Move ListenTLS (and its doc) into pki.
(3) Have internal/app build the listener itself (net.Listen + pki.NewListener) and drop ListenTLS's role.

CHOICE: (1), reviewed and approved by the user.

RATIONALE. No cycle: pki imports only platform/privdir among knomit packages (plus stdlib, go-git, zerolog), so auth -> pki cannot loop back. The transitive cost is small: the packages that already import auth (foundation/config, foundation/serveraddr, and everything above) now also link pki. ListenTLS stays the SINGLE place the instance-to-instance TLS listener is opened, with its r.TLS warning beside it; options (2) and (3) would split that entry point or move auth's listener doc away from its ConnContext marker.

NON-SCOPE. This lists one edge; it does not make foundation packages free to import each other, and pki must not import auth (that would be a cycle and is not authorised).

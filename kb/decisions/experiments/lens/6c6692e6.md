# A lens experiment forks the lens's WRITE repo only: that member is re-pinned to exp/<name> for reads and writes, every other mount is untouched, and a lens pinned at main for reads stays writable because writeOK consults the pin ONLY while an experiment is active

**Options considered:** (a) v1 supports experiments on repos only and refuses lens binds with an experiment (the master's first plan); (b) lens experiments branch the write repo, other members unchanged (user ruling: "we HAVE to be able to create experiments for lenses"); and for eligibility: (c) compute lens writeOK unconditionally from the write member's pinned branch; (d) consult the pin only when an experiment re-pin is active.

**Rationale:** A lens is a write repo plus read mounts; the experiment is a branch of the write repo, so the isolated world is that member at `exp/<name>` while the read mounts keep their pins. (c) was a trap the reviewer caught before it shipped: `Lens.normalize` keeps an explicit read entry's configured branch for the write member, so a lens that pins its write member at `main` for READS is writable today (binding.go asked about AgentBranch(), not the pin); an unconditional change would have turned every such lens silently read-only. The regression test for that must put the write member in Reads explicitly at `main` and assert WriteMountBranch()=="main" BEFORE WriteOK()==true; the obvious version binds at the agent branch via normalize's empty-branch default and passes for the wrong reason.

**The choice:** Binding.WriteBranch() = the write repo's bound/pinned branch when WritableBranch(it) is true, else the agent branch when that is writable; NewBindingOfLens computes writeOK as `writeBranch != "" || WritableBranch(AgentBranch())`, so a read pin never removes writability. The threading rule (every write path, including its deciding reads, asks WriteBranch()) is the write-branch-threading invariant, cited below. The only repo type without experiments is a subscription.

**Non-scope:** one experiment per lens at a time on the write member; lenses whose write repo differs per member are not a thing; the read mounts never fork.

# Experiments get their own knomit_experiment tool (not folded into knomit_bind); on the UNSCOPED mount the active experiment rides on the BINDING HANDLE; on a --repo/--lens bridge (URL-scoped mount) `open` moves the session INTO the experiment on the fly via state keyed by (session id, mount uid) that may choose a BRANCH only within the URL's repo; no bridge flag, no reconnect

**Options considered:** (a) fold start/commit/rollback into `knomit_bind` (the user's first preference: fewer tools); (b) a dedicated `knomit_experiment {list|open|commit|rollback|sync}` tool; for WHERE the active experiment lives: (c) per MCP client session, keyed (Mcp-Session-Id, write repo uid) in client_sessions — the master's first plan; (d) on the binding handle (a sibling table handle_experiments keyed by handle); (e) an `experiment:` argument on every write tool; and, after the end-to-end demo (2026-09-21), for URL-scoped bridges: (f) a `--experiment` bridge flag / a reconnect URL the caller re-mounts on; (g) server-side state keyed by (MCP session id, mount uid) that re-pins the branch within the URL's repo.

**Rationale:** (a) fails "experiments are for everyone": `knomit_bind` is refused on URL-scoped mounts by design. (c) as originally proposed is the design the 2026-09-17 cross-binding incident removed: session-keyed state could route a write to ANOTHER knowledge base. (e) relocates the destination into tool arguments. (d) keys on the one thing that distinguishes two logical callers on one connection. A column on binding_handles was impossible (control chain admits only CREATE IF NOT EXISTS). (f) was REJECTED by the user, emphatically: requiring an agent restart or a re-mount because it opened an experiment is unacceptable; the demo showed an agent opening an experiment on a `kb --repo` bridge and every later learn landing on the agent branch while the tool result truthfully said so — correct reporting, wrong product. (g) is accepted because the URL already FIXES the repo/lens per connection, so the state can only choose the branch within it: the incident's harmful form (a write to another knowledge base) is impossible by construction, and the invariant is amended knowingly rather than violated.

**The choice:** `knomit_experiment` with actions list/open/commit/rollback/sync on all three mounts. UNSCOPED mount: `open` records the experiment on the caller's handle (handle_experiments); ResolveSessionBinding reads it; commit/rollback clear that handle eagerly and every other handle heals LAZILY on next resolution (existence AND eligibility), the result saying `lapsed_experiment`; a handle carrying both a branch pin and an experiment is UNREPRESENTABLE. URL-SCOPED mounts (PR #240): `open` records (session id, Binding.PinID()) → experiment in the control-DB table mount_experiments; MountExperimentMiddleware swaps the binding on every later call; commit/rollback clear it; same lazy heal and lapsed reporting; rows purge with client_sessions. The re-pin is allowed ONLY on a mount whose URL names this repo's own agent branch, or a lens's default (no {branch} segment) — never main or any non-writable branch (WriteBranch() is "" there, so a binding-based predicate cannot see it: decide from the ROUTE), never a foreign agent branch, never a mount that names an experiment (`/…/branches/exp:<name>/mcp`, `/lenses/{lens}/experiments/{name}/mcp` keep their 404 and ignore session state). An absent or empty Mcp-Session-Id fails CLOSED at the middleware and at `open`. `knomit_bind` gains an optional `experiment: <name>` that RESUMES an existing experiment on the unscoped mount. knomit_repos, instructions.go and the Sessions table name the branch actually served (stored, not derived from the URL). The reconnect URL is gone.

**Accepted hazard, by construction:** a client that multiplexes two jobs over ONE MCP connection (the Cowork shape of the 2026-09-17 incident) on one repo mount shares the row, so one job's `open` moves the other's writes into the experiment; nothing on the wire distinguishes them, both branches share an ontology, so nothing fails loudly. Bounded to the same repo, recoverable by rollback, pinned by a test, and stated in `open`'s result ("every call on this connection now writes to exp/<name>").

**Non-scope:** no per-handle or per-session branch switching in general (binding_handles.branch stays inert; the session state names an EXPERIMENT, not an arbitrary branch); a handle still dies with its session. This fact is the EXPERIMENT decision; the handle model, the tool catalogue and the amended router invariant are their own facts.

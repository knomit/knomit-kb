# Experiment commit merges into the agent branch and DELETES the experiment on success, REFUSES on any conflicting path and changes nothing; sync (agent-branch-wins merge INTO the experiment) is the only exit from a refused commit besides rollback; rollback also clears an orphan ref

**Options considered:** (a) merge-back with experiment-wins (auto-resolve); (b) merge-back refuses on conflict, agent resolves by rolling back only; (c) refuse on conflict PLUS a `sync` primitive that merges the agent branch into the experiment with agent-branch-wins; also (d) merge keeps the experiment branch vs (e) merge deletes it.

**Rationale:** The agent branch keeps moving while an experiment is open (reconcile merges main into it), so experiment-wins would clobber a peer's update silently, the same hazard the local-wins convention accepts only because one machine is the sole writer of its agent branch. Refuse-on-conflict alone is a trap: the three-way base is the fork point, so any path edited on both sides stays in conflict no matter what the agent writes next, and the only exit would be rollback. `sync` gives the agent the consensus version to re-apply its edit against knowingly. Merge-then-delete is transaction-commit semantics; a lingering ref after commit is not a use case. No archive of dropped experiments: whether an unheld belief belongs in the timeline is a designer call left open.

**The choice:** `commit` = mergeIntoBranch(exp → recorded parent, StrategyRefuse) under the parent's branch lock, then teardown (ref, branch tables, experiments row, name-keyed pipeline_watermarks and meta rows). `sync` = mergeIntoBranch(parent → exp, StrategyRemoteWins) — the parent is src on that direction, so parent-wins is RemoteWins. Commit and sync first compare the recorded parent to AgentBranchOwner() and refuse on mismatch; an EMPTY owner is UNKNOWN, not a mismatch. `rollback` deletes, is never gated by the parent check, and also clears an orphan `exp/<name>` ref that has no experiments row, so recovery is "roll back, open again" through the normal surface; `open` REFUSES such an orphan rather than adopting it. The mechanics of each of those three (the refuse strategy's dual-add strictness, the empty-owner rule, the orphan shape rollback cannot clear) are in their own facts, cited below; this fact records WHY the lifecycle has this shape.

**Non-scope:** does not change steady-state origin reconcile (still StrategyLocalWins at its single call site) and does not add ancestry checks or GC for experiments beyond the expiry sweeper.

# The experiments UI browses and does housekeeping only: creation is MCP-only, there is no merge view and no Sync button, a refused commit shows the conflicting paths plus the exact steps to fix it through an agent, and the word "experiment" does not appear in repo browsing (flask icon + bare name)

**Options considered (mock review 2026-09-20, demo walk 2026-09-21, user rulings):** (a) a "New experiment" form and picker entry in the UI vs (b) creation through `knomit_experiment` only; (c) a three-way merge view in the UI (yours | theirs | editable result) as a follow-up PR vs (d) no merge UI and no conflict resolution in the UI at all; (e) a Sync button in the band/panel/dialog vs (f) none; (g) the refusal dialog explaining how knomit_experiment works vs (h) the dialog giving the concrete steps (bridge config snippet with the repo substituted, `open <name>`, `commit`, then `commit` with resolutions, "ours" = this experiment's version stated with the git inversion named); (i) an "exp" badge / the word "experiment" on the chip and band vs (j) a flask icon and the bare name, the word only in title/aria-label.

**Rationale:** The UI does not write facts, so a created experiment would be a dead end from that screen (b). Conflicts are resolved by whoever wrote the facts, which is an agent with the three versions in hand; a human picking in panes is a guess, and the merged-body option is the one that matters and the least workable in a form (d). Without a resolution step, Sync only overwrites the experiment's version and invites the loss the user objected to (f). A user in the dialog will COPY AND RUN what it says, so it must be exact: it must not TELL THE CALLER TO reconnect (after PR #240 a --repo/--lens bridge enters on the fly; the shipped copy says "No reconnect is needed") and must not get "ours" backwards (h). Nobody browsing needs to be told twice what an experiment is (j). Also ruled: the band's button says "Commit", not "Commit to <agent>" (the target is already in "forked from"); the picker has NO empty-state prose (with no experiments the section is simply absent) and the panel says only "No experiments."; the Sessions table shows the experiment a session writes to, read from the stored `mounts` attribution, never derived from the URL; the mcp request log carries `branch=<served>` whenever the URL does not already name the served branch; expiry is displayed read-only as policy (there is no server-config write surface; an editable control would be a config-write subsystem of its own, left open).

**The choice:** UI surfaces = TopBar branch picker (agent branch + this repo's experiments; an experiment whose parent is not this instance's agent branch renders as "orphaned" and non-selectable, per the code, not yet exercised in a browser fixture), the green flask chip, an experiment band under the TopBar (forked-from, changed-since-fork count, expiry, Roll back, Commit), the experiments panel on the repository detail (table: name/description/last commit/expires/actions; Open, Commit, Roll back), the since-fork fact filter (a toggle that exists only inside an experiment, and which must borrow a flat list because the default ontology-tree mode cannot honour a content filter), and the refusal dialog with the fix steps. REST keeps create and sync routes for parity with no UI callers. The read-only gate rides on the branch row's `writable`, not `is_agent_branch`.

**Non-scope:** an editable expiry control; any conflict resolution in the UI; recording anything about a merge-time conflict resolution (the user forbade decision facts and meta observations for those, everywhere).

# Config path agreement: read knomit.toml only from <home>, REFUSE a relative explicit socket (do not Abs it), expand ~\ on Windows for every tilde field, and document (not cache) the server's read-once socket

Four ways the server (config.Load) and the bridge/hooks (config.SocketPath) could still compute different config files or sockets were resolved together. The user approved each choice on the RCA, relayed by the master session.

1. knomit.toml beside os.Executable().
- OPTIONS: (a) drop the lookup, so findConfigFile reads <home>/knomit.toml only; (b) keep it and log which file each binary read, making a mismatch diagnosable.
- CHOSEN: (a).
- RATIONALE: nothing shipped relies on it. The release tarball holds three executables plus lib/, and the macOS bundle ships no knomit.toml. It had no recorded reason (it arrived with the first layered-config commit). It also silently defeated desktop Settings saves, which write <home>/knomit.toml. Logging would have left the divergence possible and only made it visible after the fact.
- COST ACCEPTED: an install with a hand-placed knomit.toml beside the binary loses it silently and must move it to <home>.

2. Relative KNOMIT_SOCKET / TOML socket.
- OPTIONS: (a) refuse it with an error on both sides; (b) make it absolute with filepath.Abs.
- CHOSEN: (a). Both sides return `socket "<v>" must be an absolute path; set KNOMIT_SOCKET or the knomit.toml socket key to one`: Load fails, and the bridge logs it once and uses TCP. Windows pipe names are exempt.
- RATIONALE: Abs resolves against each PROCESS's cwd, and the server, the MCP bridge and the hooks (which run in the project directory) are started from different ones. Abs would therefore reproduce exactly the disagreement it pretends to fix, just without an error.
- A relative data ROOT is treated differently, by the same user decision: it is made absolute in homeAndConfig, because refusing a relative KNOMIT_HOME would break every consumer of Home, not only the socket.

3. `~\` on Windows.
- OPTIONS: expand it only for the socket, or in expandTilde for every path field.
- CHOSEN: every field.
- RATIONALE: one rule for what a leading tilde means, rather than a socket-only special case. It is a small behaviour change for Windows TOML path fields that previously kept a literal `~\`.

4. Hooks re-resolving per dial vs. the server reading once.
- OPTIONS: (a) cache in the client, resolving once per process or keyed on env plus config mtime; (b) have the server publish its bound socket, e.g. in server.json; (c) accept and document.
- CHOSEN: (c). The Config.Socket doc says a socket change needs a server restart.
- RATIONALE: re-resolving costs about 26µs. Each hook is a fresh process, so a client cache saves nothing, and it cannot fix staleness that lives in the SERVER. (b) is deferred: server.json is written only by the desktop, not by `knomit serve`, and lives in the per-user StateDir rather than per data root, so it needs its own design.
- Correction recorded with this choice: a stale socket does not cut the hooks off. They fall back to TCP and lose only the verified identity.

NON-SCOPE: this does not mean every relative path in config is refused (the data root is absolutised), and it does not mean the executable's directory is never consulted: the desktop still installs bundled tools from beside os.Executable(). Only the config search changed.

# Config path agreement: read knomit.toml only from <home> (serve/desktop warn after log setup about an ignored file beside the executable); REFUSE a relative data root and a bad explicit socket (unix: not absolute after ~; Windows: not a \\.\pipe\ name, no ~) rather than Abs either; expand ~\ on Windows in the other path fields; document (not cache) the server's read-once socket

Four ways the server (config.Load) and the bridge/hooks/`kb` (config.SocketPath, knomitapi.CredentialsPath) could still compute different config files, data roots or sockets were resolved together. The user approved each choice on the RCA. Two PR reviews, relayed by the master session, then added the Windows pipe rule, the ResolveHome change, the relative-home refusal and the log placement.

1. knomit.toml beside os.Executable().
- OPTIONS: (a) drop the lookup, so findConfigFile reads <home>/knomit.toml only; (b) keep it and log which file each binary read.
- CHOSEN: (a), plus a migration aid: `config.IgnoredExecutableConfig(home)`.
  - It returns the file beside the executable when it is not the SAME FILE (os.SameFile) as <home>/knomit.toml, so a symlinked or case-variant root does not warn falsely.
  - `knomit serve` and the desktop call it and warn AFTER configuring their logger. NOT in Load: Load runs before logging is set up, so a warning there went to bare stderr and was lost with --log-file and in the GUI. It also kept `kb` and every other Load caller from paying for the os.Executable and stat.
  - A Config field recording the path was considered and rejected for that last reason.
- RATIONALE: nothing shipped relies on the lookup. The release tarball holds three executables plus lib/, and the macOS bundle ships no knomit.toml. It had no recorded reason, and it silently defeated desktop Settings saves, which write <home>/knomit.toml. Logging alone would have left the divergence possible.

2. Relative data root and explicit socket: REFUSE, never Abs.
- OPTIONS: (a) refuse a value that is not position-independent, on every side with the same error; (b) make it absolute with filepath.Abs.
- CHOSEN: (a), for BOTH the data root and the socket. Abs is only consistent within ONE process: a server started from /srv and a bridge or hook started from a project directory would still resolve different roots, just without an error.
  - The first PR revision absolutised the root; review 2 reversed that.
  - ResolveHome expands a leading ~ and refuses what is still relative (`KNOMIT_HOME "<v>" must be an absolute path; set it to one`). Every caller gets this, including knomitapi.CredentialsPath, which used to bypass homeAndConfig.
- The explicit-socket rule is PER PLATFORM (checkExplicitSocket):
  - unix: expand ~, then require an absolute path.
  - Windows: require an auth.PipePrefix name (`\\.\pipe\<name>`) with NO ~ expansion. auth.ListenLocal and auth.DialLocal refuse anything else, so a file path that config accepted would fail only at listen time.
- COST ACCEPTED: these are FATAL at Load for every binary (serve, the desktop and its Settings, every `kb` subcommand that loads config); the recovery is editing knomit.toml or the environment. Credentials saved under a literal `~` or relative root are orphaned and need `kb login` again.
- KNOWN RESIDUAL: `~` expands against each PROCESS's HOME, so a service-run server and a user bridge can still differ. This is documented on the Socket field.

3. `~\` on Windows.
- CHOSEN: expandTilde accepts it for every path field, but not for the socket (see 2).
- An expanded tilde is joined with filepath.Join, so `~/x` on Windows is `C:\Users\u\x`, not `C:\Users\u/x`.

4. Hooks re-resolving per dial vs. the server reading once.
- OPTIONS: (a) cache in the client, resolving once per process or keyed on env plus config mtime; (b) have the server publish its bound socket, e.g. in server.json; (c) accept and document.
- CHOSEN: (c). The Config.Socket doc says a socket change needs a server restart.
- RATIONALE: re-resolving costs about 26µs. Each hook is a fresh process, so a client cache saves nothing, and it cannot fix staleness that lives in the SERVER. (b) is deferred: server.json is written only by the desktop, not by `knomit serve`, and lives in the per-user StateDir rather than per data root, so it needs its own design.
- Correction recorded with this choice: a stale socket does not cut the hooks off. They fall back to TCP and lose only the verified identity.

NON-SCOPE:
- The executable's directory is still consulted elsewhere: the desktop installs bundled tools from beside os.Executable(). Only the config search changed.
- Windows does not stop expanding tildes: only the socket value skips it.
- Nothing here says Load may log. It still must not.

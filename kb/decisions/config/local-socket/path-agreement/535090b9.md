# Config path agreement: read knomit.toml only from <home> (warn once about an ignored file beside the executable); ResolveHome returns an expanded absolute root for every caller; REFUSE a bad explicit socket (unix: not absolute after ~; Windows: not a \\.\pipe\ name, no ~) rather than Abs it; expand ~\ on Windows in the other path fields; document (not cache) the server's read-once socket

Four ways the server (config.Load) and the bridge/hooks/`kb` (config.SocketPath, knomitapi.CredentialsPath) could still compute different config files, data roots or sockets were resolved together. The user approved each choice on the RCA; the PR review (both relayed by the master session) then added the Windows pipe rule and the ResolveHome change.

1. knomit.toml beside os.Executable().
- OPTIONS: (a) drop the lookup, so findConfigFile reads <home>/knomit.toml only; (b) keep it and log which file each binary read, making a mismatch diagnosable.
- CHOSEN: (a), plus a migration aid. Load logs ONE warning per process when a knomit.toml exists beside the executable and is not <home>/knomit.toml, naming the ignored file and the file that is read. The bridge stays silent, since it never calls Load.
- RATIONALE: nothing shipped relies on it. The release tarball holds three executables plus lib/, and the macOS bundle ships no knomit.toml. It had no recorded reason (it arrived with the first layered-config commit). It also silently defeated desktop Settings saves, which write <home>/knomit.toml. Logging alone would have left the divergence possible and only made it visible after the fact.
- COST ACCEPTED: an install with a hand-placed knomit.toml beside the binary no longer reads it. The server's warning says where to move it.

2. Relative or ~ data root and explicit socket.
- DATA ROOT: ResolveHome itself tilde-expands and absolutises the root, so EVERY caller gets it. That includes knomitapi.CredentialsPath (`kb login`, the bridge), which bypassed homeAndConfig; the review caught that it still resolved against cwd or a literal ~.
- EXPLICIT SOCKET: OPTIONS were (a) refuse a value that is not position-independent, on both sides with the same error, or (b) make it absolute with filepath.Abs. CHOSEN: (a). Abs resolves against each PROCESS's cwd, and the server, the MCP bridge and the hooks (which run in the project directory) start from different ones, so Abs would reproduce the disagreement silently.
- The rule is PER PLATFORM (checkExplicitSocket):
  - unix: expand a leading ~, then the value must be absolute.
  - Windows: the value must be an auth.PipePrefix name (`\\.\pipe\<name>`), and ~ is NOT expanded. auth.ListenLocal and auth.DialLocal refuse anything else, so a file path that config accepted would only fail at listen time, and a `~\` socket could never work. The error names the pipe form.

3. `~\` on Windows.
- CHOSEN: expandTilde accepts it for every path field it covers, but not for the socket (see 2).
- Also: an expanded tilde is joined with filepath.Join, so `~/x` on Windows is `C:\Users\u\x`, not `C:\Users\u/x`.

4. Hooks re-resolving per dial vs. the server reading once.
- OPTIONS: (a) cache in the client, resolving once per process or keyed on env plus config mtime; (b) have the server publish its bound socket, e.g. in server.json; (c) accept and document.
- CHOSEN: (c). The Config.Socket doc says a socket change needs a server restart.
- RATIONALE: re-resolving costs about 26µs. Each hook is a fresh process, so a client cache saves nothing, and it cannot fix staleness that lives in the SERVER. (b) is deferred: server.json is written only by the desktop, not by `knomit serve`, and lives in the per-user StateDir rather than per data root, so it needs its own design.
- Correction recorded with this choice: a stale socket does not cut the hooks off. They fall back to TCP and lose only the verified identity.

NON-SCOPE:
- Not every relative path in config is refused: the data root is absolutised.
- The executable's directory is still consulted elsewhere: the desktop installs bundled tools from beside os.Executable(). Only the config search changed.
- Windows does not stop expanding tildes: only the socket value skips it.

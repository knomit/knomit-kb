# A block-level affordance goes in the block heading's right-aligned action slot — never as a flex sibling of the body, because a body that is a bounded scroller reserves the sibling's column for its WHOLE height

**The choice.** On the manage-page blocks, an affordance that acts on the block as a whole (the Description/Note pencil, and its Save/Cancel while editing) lives in the block heading's right-aligned action slot. The body below gets the full column width.

**Options considered.**

1. *Pencil as a flex sibling of the body* — what Description actually shipped with, and the bug. The rendered body is a **bounded scroller** (`maxHeight: DESC_BODY_MAX = 360`, `overflowY: 'auto'`). A flex sibling therefore reserves its column for all 360px, so a README long enough to scroll wrapped early down its *entire* length to leave a gutter for a 13px glyph that is only ever visible at the top. The cost scales with the body's height, not the glyph's.
2. *Unmount the pencil while editing* — rejected: the heading reflows mid-edit. It is **disabled** rather than removed, and Save/Cancel (`descBtn`) are sized to exactly `cardIconBtn`'s height so the heading row is the same height whether it holds one control or two. Swapping one control for two inside a fixed-height slot moves nothing.
3. *Heading action slot* — chosen. **Read mounts already did this**; Description was the outlier, and nothing in the corpus said so, which is why the rule had to be re-derived from the bug.

**Rationale.** The heading already reserves the slot, so putting the control there costs no layout at all, while putting it beside the body costs width for the body's full height. The general shape to watch for is: *icon button as a flex sibling of a child that has `maxHeight` + `overflowY`*. Any such row silently narrows its content for that child's whole height.

**Supporting structure this forced.** `editing` lifts to the caller (`RepoDetail`, `LensDetail`) so the heading half (`DescriptionActions`) and the body half (`DescriptionBody`) stay one control across two DOM locations. The draft is `string | null`, falling through to `markdown` when untouched — which removes the seeding step the split would otherwise need and makes Cancel discard by construction.

**WHAT THIS DOES NOT AUTHORIZE.** This is about affordances scoped to *the block*. An affordance that acts on a specific row or item inside the body still belongs on that row — moving it to the heading would detach it from its target. The test is what the control acts on, not where it looks tidiest. Note also that empty-state copy must be re-read when a control moves: the Description empty state had to change from pointing at "the pencil" locally to "the pencil in the heading", because the eye no longer finds it on that row.

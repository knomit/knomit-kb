# Three view modes (tree/chrono/history) collapse to single Library view with sort axis

The UI replaced the three-mode model (tree | chrono | history) with a single Library view whose ordering is a sort axis (path | recent | relevance). Default is 'recent' (not 'path'). When freeText or a non-path filter is active, the effective sort is overridden at READ TIME to 'relevance' (do not mutate the stored value). The 'history' mode is deleted entirely — no standalone History page, no deep-link destination. Numeric shortcuts 1/2/3 are removed. The state.view field is kept as the constant 'library' (rather than deleted) only to avoid touching every reducer case and navStack snapshot. The API mapping in the original FLAVOR3.md proposal was WRONG: listFacts has no sort param (recent is default and only ordering); getTopic returns mixed dirs+facts; the per-fact /facts/{path}/commits endpoint exists but is not in openapi.yaml.

E2E mapping (checked at dev a2439e31): the specs reach the former modes through e2e/helpers/nav.ts: tree = the 'Sort by Path' button, chrono = 'Sort by Recent', history = the per-fact version walker (data-testid version-walker) opening timeline-nav; there is no repo-wide history view to open. The 'ep' filter category is NOT removed from the web code (Library.tsx still handles it), so do not assume ep: filters are gone; the PR only dropped the e2e specs that relied on the old repo-wide history.

# The EdgesRail reports emptiness to App keyed by the anchor it describes — App owns the column width, the rail owns the fetch, and a bare boolean would strand a stale collapse

A fact with no incoming and no outgoing edges no longer gets a Connections column; the 300px slot disappears and the fact body reclaims it.

THE SPLIT, AND WHY IT IS A SPLIT. Only EdgesRail knows the answer — it owns the api.explain fetch. Only App owns the column's width — EDGES_RAIL_SLOT exists so that a CRASHED rail still reserves 300px for its inline error boundary, which renders at `width: 100%` and would collapse to nothing in an unsized slot. So the rail cannot collapse itself, and App cannot decide alone. The rail REPORTS via `onEmpty`; App decides.

THE REPORT IS KEYED BY ANCHOR, NOT A BOOLEAN. App holds `emptyEdgeRailKey: string | null` and renders the rail when `edgeRailKey !== emptyEdgeRailKey`, where edgeRailKey is `repo + branch + path + anchorCommit + isLive` — the exact tuple EdgesRail's fetch effect depends on, so the two move in lockstep.

A boolean was tried in design and rejected: the rail UNMOUNTS the moment it reports empty, so a boolean needs a reset effect on every anchor change, and between the anchor changing and that effect running there is a render where a stale `true` hides a rail that DOES have edges. Comparing keys makes a report from a previous anchor simply not match — no reset, no window.

EMPTY IS NOT THE ONLY FALSY ANSWER. onEmpty fires only when the fetch RESOLVES with zero on both sides. It does not fire while loading, and it does not fire on error: an unreachable server is not the same claim as "this fact stands alone", and collapsing on a failed fetch would present a failure as a layout change and leave the error message nowhere to render.

onEmpty is held in `onEmptyRef`, synced in its OWN effect declared BEFORE the fetch effect (effects run in declaration order, so the ref is current before any fetch can resolve; useRef's initial value covers the first render). It is deliberately NOT a dep of the fetch effect: App rebuilds the callback whenever the anchor changes, so a dep would re-run the fetch on the render after every report.

CONSEQUENCES A CONSUMER ACTS ON:
- Adding a new fetch dependency to EdgesRail means adding it to edgeRailKey too, or a collapse will persist across a change that should re-check.
- Do not "simplify" onEmpty to a boolean or move the collapse inside EdgesRail; both re-introduce a named failure above.

WHAT THIS DOES NOT MEAN:
- Not "the rail hides when it has nothing to show". It hides only on a RESOLVED empty result. Loading and error both keep the column.
- Not a general pattern for hiding panels. It exists because the width lives in a parent that must survive the child crashing.

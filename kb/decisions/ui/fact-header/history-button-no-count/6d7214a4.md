# The fact band's history button (VersionWalker) carries no count: it is a bare ↺, only an entry point to history (user, 2026-11-08)

**The choice (user decision, 2026-11-08).** The version button in the fact band is "just a jump point to history". It shows no number. It used to read '⏱ vN'. It is now the glyph ↺ (U+21BA, HISTORY_GLYPH in web/src/utils.ts) as plain text, styled like the band's other glyphs ↙ ↗ ≈ (fontSize 10, opacity 0.9). title and aria-label both read 'Open history', so the button keeps an accessible name without visible text. A click still opens history at the fact's newest version. No other words were added. Browse and the chat side panel both get it through FactView → FactActions.

**Why no count.** N was the length of the fact's GET …/facts/{path}/commits page. That list is not a version count. It includes the commit that RETRACTED the fact (a retracted citer showed '2 versions' in the timeline: its create and its retract), merge commits that carried the file in (commit_log records them as 'added'), and commits from side branches. It is also one page capped at the API's default limit of 50. So 'v51' could never appear and 'v3' could mean two edits and a retract. Fixing the number would mean a new definition of 'version'; the user ruled the number unnecessary instead.

**Why ↺.** ⏱ (stopwatch) is drawn by macOS as a colour emoji, unlike the plain-text arrows beside it.

**The fetch stays.** VersionWalker still calls api.factCommits: it needs the newest version commit to open history at, and the fact read does not carry it (a live read's as_of.commit is the branch tip, an anchored read's is the anchor; as_of.date is a date, not a hash). The fetch also hides the button for a fact with no recorded versions. The currentCommit prop, used only to position the count, was removed.

**What this does NOT mean.** It does not remove the version date beside the button (kb/decisions/ui/fact-header/version-timestamp/00dc5265.md), and it does not change the timeline, which still lists the /commits entries.

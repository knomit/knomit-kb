# The fact header's history button wears the Materialize button's styling (k-bare k-materialize, rest FACT_ACTION_REST #8a96a8, opacity 0.75 -> 1, no inline radius): muted at rest, the accent #7c9 only on hover, a rounded keyboard ring (chat review, 2026-11-09)

VersionWalker used to set `color: '#7c9'` inline, so the history icon sat in the accent at rest (user screenshot t-history) and no :hover rule could outrank it; it also set inline `outline: none`, which hid the keyboard ring too. It now mirrors the Materialize button beside it in FactChrome exactly: class `k-bare k-materialize`, `--k-materialize-rest` set to FACT_ACTION_REST (#8a96a8, one constant in utils.ts that FactChrome's Materialize uses too), opacity 0.75 lifted to 1 on mouse enter. It sets NO inline border-radius: an inline `borderRadius: 0` outranked `.k-bare:focus-visible { border-radius: 4px }` and drew a square keyboard ring where Materialize's is rounded (seen in Chromium in the review of #811, then fixed). App.css's one `.k-materialize:not(:disabled):hover { color: #7c9 }` rule lights both, so the two cannot drift; VersionWalker.test.tsx renders FactActions with both buttons and pins them equal.

What the shared rule does NOT do: it does not colour on :focus-visible. Keyboard focus draws .k-bare's ring (2px #4a7ab5), not the accent, on BOTH buttons. Neither button has an active state in the fact header (no prop for 'history open' or 'materialize open'), so there is no active-state behaviour to keep in step. Measured in Chromium at the merge candidate: rest rgb(138,150,168) on both, hover rgb(119,204,153).

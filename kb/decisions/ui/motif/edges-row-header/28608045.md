# The fact header is three rows, and the edges row was DELIBERATELY reinstated for name-controls — partially superseding the do-not-reinstate rule, which governed count-readouts. The row is BORDERLESS.

Options considered across design rounds 3–5 (adversarial designer/critic canvases, PR #177): motif names as a cell in the existing control group; names in the path's slot; a dedicated row. The owner chose the dedicated row with a restructured header — row 1 metadata badges, row 2 path, row 3 the edges row: `↙ cited by N  ↗ cites N  ≈ motif-name count … [+N]`.

**THE STRIP HAS NO BORDER (PR #180, 2026-08-31).** It shipped as one bordered strip with a fill, a radius and hairline dividers; all four are gone. Nothing else in the fact's chrome wears a border, and a box around three of the header's cells read as a widget bolted onto the fact rather than part of it. `controlStrip` (FactChrome.tsx at 70826ce6, formerly RightPanel.tsx) carries no border, fill or radius; since PR #742 it also wraps (`flexWrap: wrap`, `minWidth: 0`). With the dividers gone the PADDING is the spacing, so `CELL_PAD_X` is shared by every cell and the strip cancels exactly that much on its left edge (`marginLeft: -CELL_PAD_X`), putting the row's first glyph in the same column as the path and meta lines above it — three header rows that start in one column. `overflow` is deliberately NOT hidden: there is no radius left to clip, and clipping would eat the inset underline an open cell draws on its bottom edge.

Everything else in this decision survives, and is stated more plainly now that the border is not carrying it:

**The reopening rationale is unchanged.** kb/decisions/ui/connections/header-cells/7a757d22.md removed two designs for spending permanent horizontal space on COUNT-READOUTS a reader consults occasionally. This row carries NAME-CONTROLS — every drawn name is a button (click opens the motif panel focused on that name; first click inspects, pivot is a second deliberate click inside the panel). The old rule's rationale doesn't transfer, and the reopening was made deliberately by the owner with the tradeoff drawn (~34px → ~78px header). The empty-collapse protocol stays dead.

**Version, date and retract still sit apart from the panel-openers** — they always did, and the point of the separation (everything in the opener group opens the panel below; version's click changes mode elsewhere and it vanishes while loading) is unchanged. What ENFORCES the separation is now the left/right split in `fact-band-edges`, not a border. A reader looking for the border to tell them which cells open the panel will not find one.

**The three-state count discipline** (value / `···` / `!`, never a false 0) is unchanged — and with the border gone it is doing more work than before, because colour and cursor are now the WHOLE of what separates inert from live. Verified in the browser after the restyle: inert `#333`, live accent, failed red, open `#151515` fill plus an inset underline in `currentColor`.

Also from the same round: in/out cells carry the text labels 'cited by'/'cites' (chosen over 'in edges'/'referenced by' on clarity + width; panel headings and aria renamed to match — one vocabulary per gesture); layout stability holds by counters pinned left, version/date right, only names flexing; names render whole or drop into a `+N` cell, ordered carrier_count-desc so row and panel agree on order.

**Misreadings to avoid.** This does NOT reopen count-column rails or the collapse protocol — a future surface wanting a permanent row of count-readouts still hits the original rule. And the row is NOT a container: there is no bordered box owning the cells' radius or dividers, so nothing may be styled on the assumption that one exists.

**State at 70826ce6 (re-read).** The edges row is FactEdgesGroup in FactChrome.tsx (left, the panel-openers) beside FactActions (right), inside FactBand's `fact-band-edges` row. Row 1 is FactMetaLine and row 2 is the path (FactBandPath), or the title once it has scrolled away. Browse's fact view moved from RightPanel.tsx into FactView.tsx, and the chat's side panel mounts the same FactView, so this header is the same in both. `CELL_PAD_X` (7) lives in ConnectionsMenu.tsx; `EDGE_LABEL` is `{ in: 'cited by', out: 'cites' }` in utils.ts; orderMotifs (MotifRow.tsx) ranks by carrier_count descending, with unknown counts last and a name tie-break.

**Scope of the three-state discipline, checked at 70826ce6:** `···` exists on the MOTIF cells only (MotifCell: `failed ? '!' : loading ? '···' : count`). A connections cell (ConnectionsCell) has two states: the count, or `!` when the edge fetch failed. While edges are loading, useFactEdges holds empty arrays, so a connections cell shows 0, drawn inert. Do not read the rule above as already true for the connections cells.

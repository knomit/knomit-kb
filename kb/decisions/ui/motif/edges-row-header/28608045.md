# The fact header is three rows, and the edges row was DELIBERATELY reinstated for name-controls — partially superseding the do-not-reinstate rule, which governed count-readouts

Options considered across design rounds 3–5 (adversarial designer/critic canvases, PR #177): motif names as a cell in the existing control group; names in the path's slot; a dedicated row. The owner chose the dedicated row with a restructured header — row 1 metadata badges, row 2 path, row 3 the edges row: `↙ cited by N | ↗ cites N | ≈ motif-name count … [+N]` in one bordered strip.

Rationale and the supersession's scope: kb/decisions/ui/connections/header-cells/7a757d22.md recorded two designs removed for spending permanent horizontal space on COUNT-READOUTS a reader consults occasionally. This row carries NAME-CONTROLS — every drawn name is a button (click opens the motif panel focused on that name; first click inspects, pivot is a second deliberate click inside the panel). The old rule's rationale doesn't transfer, and the reopening was made deliberately by the owner with the tradeoff drawn (~34px → ~78px header). The empty-collapse protocol stays dead; three-state count discipline (value / ··· / !, never a false 0) carries over per cell.

Supporting decisions in the same round: in/out cells gained text labels 'cited by'/'cites' (chosen over 'in edges'/'referenced by' on clarity + width; panel headings and aria renamed to match — one vocabulary per gesture); version + date + retract sit OUTSIDE the border so the border means exactly one thing (everything inside opens the panel below — version's click changes mode elsewhere and it vanishes while loading); layout stability rule replaced (counters pinned left, version/date right, only names flex); names render whole or drop into a +N cell, ordered carrier_count-desc so row and panel agree on order (shortest-first rejected by simulation — banded benefit vs continuous order agreement).

Misreading to avoid: this does NOT reopen count-column rails or the collapse protocol — a future surface wanting a permanent row of count-readouts still hits the original rule.

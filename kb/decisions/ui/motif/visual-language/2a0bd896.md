# Motifs are the COLOURLESS element — no hue, the ≈ relation glyph, text-first — because every neighbouring hue names a subject and a motif's whole claim is subject-independence

Settled in design round 1 and strengthened by implementation: motifs get no colour anywhere (chips, cells, browser rows). The palette is spent (domain green #7c9, entity blue #8af, episode orange #fa8, twelve type hues, lens accent), and in the edges row specifically — in blue, out orange, version green — the motif being the one cell whose colour makes NO claim about subject is itself the axis statement. The mark is ≈, the only RELATION glyph in a set of object glyphs. The register is text-first: with every cell labelled, the row reads as a sentence (cited by 3, cites 2, same shape as these).

Consequence: a real chipColors.motif entry exists specifically to say 'no colour' — chipStyle() falls through to path-grey for unknown categories, so omitting the entry renders silently wrong rather than deliberately colourless.

Misreading to avoid: 'motifs have no colour yet' is backwards — colourlessness is permanent and load-bearing, not a slot awaiting a freed-up hue. Giving motifs a colour would re-file them as a seventh subject facet, which is the exact reading the design exists to prevent.

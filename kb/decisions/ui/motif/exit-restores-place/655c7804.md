# EXIT_MOTIF restores the folder PIVOT_MOTIF displaced, via a returnPath stash carried ON the pivot's chip — not a top-level field, and never for FilterBar-typed motif chips

**Options considered.** A code review found that the ≈ segment's exit ("Leave this motif and go back") restored the MODE the reader came from but landed an ontology browser at the ROOT: PIVOT_MOTIF drops the path chip on entry (a shape cuts across the ontology) and EXIT_MOTIF removed only the motif chip, so nothing remembered the folder. Options: (a) stash the displaced path and restore it on exit; (b) keep root-landing and reword the segment's title so it stops promising "go back".

**Rationale.** (a) won because EXIT_SEARCH's own comment states the governing rule — leaving a derived mode should not also teleport you out of the folder you were in. Search honours it for free (it never drops the path chip); the pivot MUST drop the chip on entry, so honouring the same rule requires the exit to undo the drop. Root-landing also put two adjacent "back" gestures (the chevron, which restores fully via navStack, and the ≈ segment) in different places under the same word — the same-words-two-meanings failure the motif UI repeatedly bans. The stash lives ON the chip (`FilterChip.returnPath`), not in a new AppState field, because pushNav snapshots filters: the stash rides through NAV_BACK for free and dies with the chip, where a top-level field would need its own lifecycle in every arm touching filters or history.

**The choice.** PIVOT_MOTIF stashes the displaced path chip's value as `returnPath` on the motif chip it mints; a re-pivot (no path chip present) carries the previous chip's stash forward, since the place the reader was last standing is still the record. EXIT_MOTIF re-adds a path chip from the stash — unless a path chip is already present, which wins because it says where the reader is NOW. A motif chip typed into the FilterBar (ADD_FILTER) never carries returnPath, and that absence is load-bearing: absent means "restore nothing", never "restore root".

**Non-scope.** This does not change REMOVE_FILTER: deleting the motif chip with the FilterBar's × still lands wherever the remaining chips say, with no restore — only the ≈ segment's EXIT_MOTIF restores. It also does not revisit PIVOT_MOTIF dropping the path (that remains correct and is a separate decision, see the pivot-and-widen fact).

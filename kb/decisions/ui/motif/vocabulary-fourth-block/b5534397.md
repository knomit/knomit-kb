# The motif vocabulary is a FOURTH summary-panel block ('Motifs'), not a nav entry — the ontology path SCOPES it, and client-absence is a distinct state beyond resolved/loading/error

Options: a nav destination vs a fourth block beside Domains/Entities/Types in the summary panel. The block won via the ways-of-looking invariant: motif vocabulary is per-repo (no cross-mount cluster identity), so a nav entry would go dark whenever a lens is selected — 'an entry live for two of the four things above it is a feature with a switch, not a way of looking.' The block borrows the sibling grammar (ranked rows, share bar, overflow row opens the full-width browser, pick closes and adds a chip→pivot) but NOT the data source: motifs are deliberately out of /stats, which is also why each row can show a definition and the sibling columns cannot.

**IT IS CALLED MOTIFS, NOT SHAPES (PR #180, 2026-08-31).** `ShapesBlock.tsx` → `MotifsBlock.tsx`, every `shapes-*` test id → `motifs-*`, and the copy with them — the pivot header, the edges-row cell, the panel heading, the empty and loading states. 'Shapes' survives nowhere in the UI; cite this fact, not the old name, when naming the block.

**THE ONTOLOGY PATH SCOPES THE VOCABULARY (PR #180).** `ClustersUnder(ctx, branch, pathPrefix)` and `VocabularyHealthUnder(...)`; the unscoped calls delegate with `""`. Under a prefix: a cluster no fact in the subtree carries is ABSENT, `DF` counts carriers in the subtree, and `DFTotal` keeps the branch-wide figure — both computed in ONE pass so they cannot disagree. **Members and the elected canonical stay BRANCH-WIDE**, so a scoped view never renames a cluster the pivot heading names differently. The split by parameter is deliberate: `?path=` is SCOPE, so it narrows the health block too; `q` is a way of READING one page and does not.

**The singleton fold keys on the branch-wide count, not the scoped one.** The fold was written for a whole-repo vocabulary, where `df == 1` means 'minted once and never reused'; under a path scope it means 'one fact HERE carries it', which is true of almost any small folder and says nothing about hygiene. `branchWide = e.df_total ?? e.df`. It also folds ONLY while the overflow row can reopen the band — at six ranked names or fewer there is no `+N more`, so a folded band would be content with no door. Two rules, one invariant: **nothing the block holds may be unreachable, and it never shows a count with nothing under it.** (The first fix landed the second: at a folder holding one carrier the block drew `Motifs 1` over empty space.)

**`+N more` opens the browser; it is not an in-place expansion.** It borrows `FacetBrowser`'s grammar to the letter — which is the point, since the same words a few pixels apart must not mean two different things: `← Back` replaces the glyph, search takes focus, Escape closes, the list scrolls inside a fixed 232px so Highlights is not shoved down the panel, back drops the query, a pick closes.

Other shipped particulars (PR #177): the singleton tail folds into one plain-text band (36 of 73 clusters at the time — the modal case — not N rows of empty bars); the health strip is authored-facts-only and is NEVER narrowed by the search while the header count IS, a contrast the UI states outright; search reaches names AND definitions with placeholder 'Search names and meanings…'; a singleton pivot is suppressed ('only this fact', plural grammar via `carrierLabel` so '1 carriers' is unrepresentable); the browser's search and picker rows carry the full three-state treatment (a failed load must never render as an empty vocabulary — that would claim the corpus has no shared shapes).

The /explore lesson: the vendored read-only build swaps only api.ts, so `typeof api.motifs !== 'function'` is the seam — and CLIENT-ABSENCE is a fourth state distinct from error: the Motifs block and picker row absent themselves without layout holes rather than erroring, because reporting a fault in a build working as intended would be false. The pivot survives there (filtering is navigation, not an edit); the block wraps the CALL not just the promise, so a synchronously-throwing client cannot take down a dashboard whose other three blocks don't depend on motifs.

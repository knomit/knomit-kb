# The pivot's subject is PATH SEGMENT 3 (never the domain field) and the shape-heading appears only at exactly one motif chip — but the widen rungs are RETRACTED: they shipped correct and were removed for having no signal in any corpus

Three bindings/behaviours were settled for the landed pivot (Library state after clicking through a motif) in PR #177. **Points 1 and 3 STAND unchanged. Point 2 — the widen control — is RETRACTED (PR #180, merged 2026-08-31); the control no longer exists.**

1. SUBJECT = the fact path's third segment (kb/<topic>/<SUBJECT>/…), explicitly NOT the domain field: domain[0] diverges from it on 209 of 1,183 facts (18%), is an arbitrary pick from a multi-valued field (mode 3 domains, up to 7), and is absent on 82 facts; using ALL domains gave 53 distinct labels over 26 carriers — more variety than facts, inverting the spread indicator. motifSubject.ts also strips the kb://<id12>/ lens prefix first, or every lens row would shift by one segment. The spread summary uses whole-names-or-none + '+N more', computed from the full landed rows, never the capped carriers[] preview.

2. **RETRACTED — the widen control (exact→stem→token-2) is gone.** Its two design rules were honoured to the letter and neither is what failed: each rung showed its MEASURED delta before the click, an empty rung rendered inert (grey, not a button) because a dead-looking control reads as broken, nothing was hard-coded (corpus-property-constants), stem's delta derived FREE from the already-fetched aliases[] (any method:"judge"), token-2 took one count-only request after rows landed, and a FAILED measurement left the rung LIVE — a rung was never declared empty until something looked. The control was removed anyway, because **the measurement it existed to display had no signal in it.** Counted across all four live corpora before deciding: agentic-engineering 50 clusters / 0 stem-live / 3 token-2-live; knomit-kb 50 / 0 / 3; core 50 / 0 / 9; knomit-io-kb 28 / 0 / 2 — **178 clusters, stem live on 0 (0%), token-2 on 17 (10%).** stem was dead everywhere for the reason this fact itself gave: it can differ from exact only on a judge-merged cluster, and there are zero judge merges in any corpus. And the 10% where token-2 fires is WORSE than the 90% where it does not — on `control-coarser-than-failure` it admits three `failure-faster-than-success` facts because the two names share `than` and `failure`: two motifs about unrelated things, joined by a stopword, presented to the reader as a fact about the corpus.

   Removed with the control: `state.motifMatch`, `SET_MOTIF_MATCH`, its `NavEntry` field and both `NAV_BACK` restores, the count-only token-2 probe fired once per pivot, the `admittedBy`/`near` row marker, and FilterBar's dashed widened chip. The server's `motif_match` and the MCP tool's are UNTOUCHED — the client now sends no tier at all, so the server's default is the single definition of exact. Grep still finds `motifMatch` in web/src/api.ts: that is the plumbing, and Library.motif.test.tsx pins that Library never sets it.

   **THE LESSON, which is why this is an update and not a deletion.** The feature died of its own measurement, not of neglect: the inert-rung rule was right and `stemCanAdd` deriving the answer for free was right. **A control whose VALUE is a corpus property has to be measured against the corpus before it ships, not only after.** That is the neighbour of kb/principles/anti-patterns/corpus-property-constants/63e6ecca.md — that principle forbids hard-coding a corpus property; this one adds: do not ship a control for one without first checking the distribution is non-degenerate.

3. The cluster heading replaces the location line ONLY at exactly one motif chip and no free text — two chips are an OR-union with no honest single name; free text is a search WITHIN the pivot, a different question. And PIVOT_MOTIF is the only chip operation that clears the path chip (a shape cuts across the ontology; folder-scoping a pivot contradicts it) — no other chip op drops path, so don't cite one as precedent. (PIVOT_MOTIF now STASHES that displaced path on the chip so EXIT_MOTIF can restore it — see kb/decisions/ui/motif/exit-restores-place/655c7804.md.)

**WHAT THIS DOES NOT MEAN.** Not that the inert-when-empty rule was wrong — it is the right rule for any measured control that ships. Not that widening is impossible in principle: it is dead because THIS corpus has no judge merges and this tokeniser's near-miss class is noise, and the server side that could serve it is intact.

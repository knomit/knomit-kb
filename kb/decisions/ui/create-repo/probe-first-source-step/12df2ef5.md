# The create-repo wizard asks for a URL and lets the PROBE classify the remote — the user never self-selects join-vs-seed, and the probe may only claim what ls-remote can see

# Context

The old `CreateRepoForm` presented three mode tabs (preset / custom / clone) and required the user to classify themselves before they had the information to do it. "Clone remote" implies the remote already holds a knowledge base; the empty-remote case worked but was undiscoverable.

# Options considered

1. **Fork-in-the-road**: two explicit up-front choices, "join existing" vs "start fresh". REJECTED — users often genuinely do not know whether the repo they were pointed at already has facts in it.
2. **Probe-first** — CHOSEN. One URL field plus a "Check repository" action; the probe result decides the remaining steps.

# The choice

Step 1 offers two PEER choices — "Connect a git repository" (listed first, described more fully) and "Keep it on this machine". No "recommended" badge: ordering and detail carry the preference without making the peer read as a mistake.

A new collection-level `POST /api/v1/repos:probe-origin` returns one of three outcomes, which decides the flow:

- **has refs** → join it; the ontology step is NOT shown (ontology comes from the remote)
- **empty** → seed it; ontology step shown, mode `seed`
- **no remote** → local only; ontology step shown, mode `preset`/`custom`

# Rationale

Probing before asking is what makes the `seed` mode safe (see sibling decision): the wizard only ever asks for an ontology once it already knows the seed will be used, so the half-obeyed request cannot be constructed from the UI.

# CRITICAL constraint — what the probe may claim

A probe is `remote.ListContext` and sees **REFS ONLY**. It can report reachability, whether auth was required, whether the remote is empty, and the resolved upstream branch. It CANNOT report fact counts, commit counts, or the remote's ontology id without an actual fetch. Those belong in the post-create result, never in the pre-create summary. A review screen that shows "1,240 facts · ontology source-code" before creating is claiming knowledge the probe does not have.

The probe MUST go through `Manager.ValidateLocalOrigin` for filesystem origins — the local-origin-gate invariant admits no trusted exemption, and a probe that skipped it would be a new hole.

# Non-scope

Does not change `RemoteConnectWizard` or the origin-session flow, which operate on an EXISTING repo and therefore cannot serve pre-create probing.

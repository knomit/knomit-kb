# Edge counts live in the fact header as ConnectionsCell — zero renders inert rather than disappearing, and a FAILED fetch must never render as a zero

Connections (incoming/outgoing edge counts) are rendered as cells in the fact header's edges row. SUPERSEDED IN PART (2026-08-29, PR #177): the row now reads `↙ cited by N  ↗ cites N  ≈ motif…` — labelled cells whose contents ALL open the panel below — with version, date and retract kept apart from them. See kb/decisions/ui/motif/edges-row-header/28608045.md for the reinstated dedicated row and why the reopening was legitimate: the rule below governed COUNT-READOUTS; the new row carries NAME-CONTROLS. (PR #180, 2026-08-31, took the strip's border, fill, radius and dividers away; the cells sit on the band's own ground, spaced by a shared `CELL_PAD_X`.)

**How it got here (two superseded designs).** Connections were first a 300px column, then a 36px gutter with a sliding drawer. Both spent PERMANENT horizontal space on something a reader consults occasionally. That rationale still binds for count-readouts: a future surface wanting a permanent column of counts still hits this rule.

**ZERO IS NOT A BUTTON.** A count of zero renders with no accent, no hover, no pointer and no panel — but it still RENDERS. It does not disappear, so the header's control area does not collapse between a fact with edges and one without. (The layout-stability guarantee evolved with the motif row: counters pinned left, version/date pinned right, only the variable-width motif names flex in the middle.)

**A FAILED FETCH IS NOT A ZERO.** `useFactEdges` CLEARS both edge arrays when the request fails, so gating on the count alone would render an unreachable server as an inert `0` — visually identical to a fact that genuinely stands alone. The cell therefore takes an `error` prop: when present it stays a button and replaces the count with a warning. `interactive = count > 0 || failed`.

**BOTH RULES ARE LOAD-BEARING, AND MORE SO SINCE THE BORDER WENT.** With no border, no fill and no dividers, COLOUR AND CURSOR ARE THE WHOLE of what separates inert from live from failed. Nothing else in the chrome is left to carry it. Verified in the browser after the restyle: inert `#333`, live accent, failed red, open = `#151515` fill plus an inset underline in `currentColor`.

**Operational consequence:** any new surface showing an edge count must distinguish three states — resolved-zero, loading, and error — and must not collapse the latter two into the first. This is the one principle that survived both redesigns and the restyle, and it carried into the motif cells (`···` pending / `!` failed, never a false 0) and the Motifs vocabulary browser.

**WHAT THIS DOES NOT MEAN.**

- *Not* "the accent colour belongs on the glyph or the count." It is set on the CELL, so glyph, count and open-indicator all resolve `currentColor` from one place.
- *Not* that the cells are drawn inside a bordered container that owns their radius and dividers. They are BORDERLESS cells on the band's own ground; `controlStrip` contributes a gap, a negative left margin cancelling one `CELL_PAD_X`, and (since PR #742) wrapping; it draws nothing. Do not style a cell on the assumption that a box encloses it.
- *Not* that `EdgesRail`, `onEmpty`, `edgeRailKey`, `emptyEdgeRailKey` or `EDGES_RAIL_SLOT` still exist. That empty-collapse protocol was deleted with the rail and remains dead — the 2026-08-29 row reinstatement did NOT bring the collapse back; the motif segment is always present, inert at zero.
- *Not* that the row's cells are glyph-only any more — they carry the words 'cited by'/'cites', the SAME vocabulary as their panels and aria labels (one vocabulary per gesture).

**State at 70826ce6 (re-read).** ConnectionsCell is in ConnectionsMenu.tsx: `failed = !!error`, `interactive = count > 0 || failed`, the colour is set on the cell (inert `#333`, accent, `EDGE_ERROR`), and an open cell has a `#151515` fill plus an `inset 0 -2px 0 currentColor` underline. The cells are rendered by FactEdgesGroup in FactChrome.tsx. They used to be rendered in RightPanel.tsx, before Browse's fact view moved into FactView.tsx, which the chat's side panel also mounts. useFactEdges still clears both arrays on failure. EdgesRail and the empty-collapse protocol are gone; they survive only in comments.

**Known gap against the operational consequence above.** The connections cells distinguish only TWO of the three states. useFactEdges exposes `loading`, but ConnectionsSlot does not pass it to the cell. So while edges load, the arrays are empty and the cell shows an inert `0`, identical to a resolved zero. The motif cells do have all three states (`···` / `!`). A new edge-count surface should not copy the connections cell's loading behaviour.

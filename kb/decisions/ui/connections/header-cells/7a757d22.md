# Edge counts live in the fact header as ConnectionsCell — zero renders inert rather than disappearing, and a FAILED fetch must never render as a zero

Connections (incoming/outgoing edge counts) are rendered as cells in the fact header's control row, which reads `↙2 ↗3 ⏱v1 ⊗` — connections, then version, then retract. The panel they open is transient.

**How it got here (two superseded designs).** Connections were first a 300px column, then a 36px gutter with a sliding drawer. Both spent PERMANENT horizontal space on something a reader consults occasionally; putting the counts beside the version chip costs nothing that was not already header.

**ZERO IS NOT A BUTTON.** A count of zero renders with no accent, no hover, no pointer and no panel — but it still RENDERS. It does not disappear, so the header's control row does not reflow between a fact with edges and one without. This reverses the earlier rail-era decision to collapse the whole column when a fact had no edges.

**A FAILED FETCH IS NOT A ZERO.** `useFactEdges` CLEARS both edge arrays when the request fails, so gating on the count alone would render an unreachable server as an inert `0` — visually identical to a fact that genuinely stands alone, and with the panel carrying the error text no longer openable. The cell therefore takes an `error` prop: when present it stays a button and replaces the count with a warning, so the failure is legible at a glance and clickable through to the message. `interactive = count > 0 || failed`.

**Operational consequence:** any new surface showing an edge count must distinguish three states — resolved-zero, loading, and error — and must not collapse the latter two into the first. This is the one principle that survived both redesigns.

**WHAT THIS DOES NOT MEAN.**

- *Not* "the accent colour belongs on the glyph or the count." It is set on the CELL, so glyph, count and open-indicator all resolve `currentColor` from one place; putting it on a child makes the indicator inherit the ambient colour and render grey beside a coloured count.
- *Not* that `EdgesRail`, `onEmpty`, `edgeRailKey`, `emptyEdgeRailKey` or `EDGES_RAIL_SLOT` still exist. That whole empty-collapse protocol was deleted with the rail; do not grep for it and do not reinstate a collapse.

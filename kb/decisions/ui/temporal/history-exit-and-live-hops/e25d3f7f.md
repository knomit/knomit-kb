# History excursions exit only via return-to-live; scrub never demotes to live, and a live ref-hop stays live unless the target is retracted

Two related UI rules for the web temporal navigation, chosen to fix reported bugs where the UI dropped into (or out of) read-only history mode unexpectedly.

**Options considered.** (1) Keep the prior 'edge reasoned over a specific version' semantics — following a ref to a target that changed since the edge formed (a 'superseded' target) pins it in history; and selecting the newest timeline version demotes back to live. (2) Treat history as an explicit excursion the user enters and leaves deliberately: live ref-hops stay live, version selection stays in history, and the only exit is the return-to-live control.

**Rationale.** Option 1 surprised users: clicking an EdgesRail connection to a fact that is perfectly live yanked them into a read-only history view, and re-selecting the newest version silently exited the excursion. The user directive: 'clicking refs in live mode should not switch to history mode if the refs are still live' and 're-selecting the latest version in history should stay in history'. A superseded-but-existing target IS still live, so it should display live. Option 2 chosen.

**The choice.**
- `scrub(commit)` (useTimeTravel.ts) always sets `{mode:'history', commit}` — the `isLatest`→live branch and the `isLatest` parameter were removed from the whole onScrub chain (useTimeTravel, LeftPanel, RightPanel, VersionWalker, TimelineNav). TimelineNav.handleRowClick no longer passes isNewest; selecting any row (including the HEAD row) stays in history.
- `resolveHopAnchor` now takes the current `fromAsOf`. From a history/diff excursion it stays `{history, pinnedCommit}` (no HEAD read). From live it does a single HEAD read: 200 → stay live (superseded targets included); 404 (retracted) → `{history, pinnedCommit}` so RightPanel's ?fallback=before surfaces the last-valid version. The old `head.commit_hash === pinnedCommit` comparison was the bug: a HEAD read stamps as_of.commit = branch tip (WithHash:false in handlers_fact_read.go), never the fact's own commit, so EdgesRail hops (pinnedCommit = target's own commit) always mismatched → history.
- The only way out of a history excursion is now the return-to-live control (TimelineNav 'live' button / 'h' key → returnToNow).

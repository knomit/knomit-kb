# A server.json that cannot be written is a WARN for plain `knomit serve` (it keeps serving, nothing is advertised) but exit 2 for `knomit serve --supervised` — and a serve that does not hold its home's socket writes no file at all

OPTIONS (knomit#493 review finding 2): failing a plain `knomit serve` boot when Advertise fails (as the desktop's boot does) vs warning and serving. CHOSEN: plain serve WARNs ('server.json not written') and keeps serving; supervised serve returns an app.ListenerConfigError, exit 2. WHY: before #493 plain serve wrote no lockfile, so a read-only or hardened state directory (the default home keys to <StateDir>/server.json, outside the home) never stopped it; the file is a discovery convenience, not part of serving. A supervised child is different: the desktop needs the file, and no restart fixes an unwritable directory, which is exactly what exit 2 ('do not retry') means.

RELATED RULE: Advertise skips the write when this process does not hold its home's local listener (auth.ErrSocketInUse): the holder owns the file, and a TCP-only sibling must not repoint kb at itself. So a plain serve beside a running server on the same home leaves the first server's file untouched, before and after it exits.

PINS: TestServe_AdvertiseFailure (cmd/serve_supervised_test.go; a directory sits where the file goes; the plain row asserts the socket still answers and the directory is untouched; the supervised row asserts exit 2 naming the lockfile write; sabotage making the plain branch fatal turns the plain row red), TestAdvertise_SkippedWhenAnotherProcessHoldsTheLocalListener (internal/app/listeners_test.go).

NOT MEANT: a plain serve that warned is not undiscoverable - kb's unnamed path still tries the socket first; and 'server.json is optional' is false for a supervised child. Exit codes: kb/decisions/serve/supervised-mode.

# FactSet fact identity = 64-bit FNV-1a FactHash(repo id12, path), the anchor f-<16 hex>; a collision is DETECTED by an independent check hash stored beside each key (32 bits in the frozen results/reserved tables, 64 bits in the extra written set), not by storing (repo, path), to keep the cache inside its per-FactSet budget

The plan (PR C, factset-streaming-plan.md section 2) said the written set maps hash -> (repo, path) so a collision fails the call with a 500 instead of dropping a subtree. As built (factset_plan.go: factHash, factCheck; factset_state.go: fsState.lookup, markWritten, freeze), every structure keyed by FactHash stores factCheck(repo, path), FNV-1a over path, 0xff, repo, beside it: 64 bits in the extra written set, 32 bits in the frozen results and reserved tables (24-byte entries); a lookup or insert whose check differs returns ErrFactIdentity (500) and logs. An undetected collision then needs a FactHash collision (about 3e-10 at 100k facts) AND a 32-bit check collision. Reason: (repo, path) costs about 60 bytes per entry and the written set reaches 250k entries at the rulings' maxima (500 units x 500 facts), past the 16 MiB per-FactSet cache target; the check hash costs 4 to 8. An undetected collision needs a 64-bit FactHash collision AND a check-hash collision: 32 bits for an entry of the frozen results or reserved tables, 64 bits for an entry of the extra written set.

The written set also keeps blob64 (the first 64 bits of the written blob) so a back link's different_version is computed server-side without holding the blob.

CONSEQUENCE: a test that forces a collision must replace FactHash only (SetFactHashForTest); the check hash is deliberately not replaceable. F22 pins it.

WHAT THIS DOES NOT MEAN: anchors are not unique per appearance: every appearance of a fact shares f-<16 hex>, so only a written (or unavailable) section emits <a id> in the export.

SINCE fix/factset-random-access the written state also records the unit that first wrote each fact (a uint16 beside each frozen-table entry; a unit field in each extra-set entry, now 32 bytes). The check hashes are unchanged (32 bits frozen, 64 bits extra), and a lookup reports a check mismatch as a collision whatever the entry's unit (kb/invariants/materialize/factset/first-appearance-prefix/479400a8.md).

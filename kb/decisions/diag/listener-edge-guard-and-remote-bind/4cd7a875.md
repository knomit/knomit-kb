# The runtime diag listener ([runtime].addr) is guarded at ITS OWN edge — non-loopback peer → 403, any Origin header or cross-site Sec-Fetch-Site → 403, foreign DNS Host → 421 — and a non-loopback bind address is REFUSED by config.Validate unless [runtime].allow_remote = true; chosen over a Host check alone (which leaves blind CSRF open), per-request loopback-only refusal, and putting the routes behind AuthMiddleware

Context (issue #288, RCA 2026-09-25 at dev 1af30efe): internal/platform/diag/server.go's listener has no middleware, no peer check, no Host check and no Origin check. Its mutating routes (POST /runtime/{loglevel,gc,heapdump,profile/mutex,profile/block}) take their arguments from the QUERY STRING with no body, so they are CORS "simple requests": any web page can `fetch("http://127.0.0.1:6060/runtime/loglevel?level=trace", {method:"POST", mode:"no-cors"})` and the side effect happens WITHOUT DNS rebinding (Chrome's Local Network Access prompt mitigates in Chrome only). Rebinding is needed only to READ responses (/debug/pprof incl. cmdline and full goroutine stacks, /debug/vars, /runtime/status repo names). /runtime/heapdump writes unbounded files under <home>/dumps and /debug/pprof/profile?seconds=N holds the profiler, so both directions are abuse levers. [runtime].addr is a bare string never validated, so ":6060" or "0.0.0.0:6060" binds every interface despite the comment saying local only. The desktop app opens no diag listener.

Options considered:
(a) Host check only, as the issue proposed (the #281/PR #289 rule): stops rebinding reads and writes, does nothing against the blind CSRF POST (Host is then an IP literal, which passes) and nothing on a 0.0.0.0 bind.
(b) Loopback-peer-only per request: stops LAN exposure, does nothing against rebinding (the rebound browser IS a loopback peer), and silently 403s a remote Prometheus.
(c) a+b: closes rebinding and LAN, still leaves blind CSRF.
(d) Routes behind AuthMiddleware on the main listener: anonymous loopback gets pprof/gc by loopback_default anyway, exposes pprof on the public/TLS/OAuth ports, crosses diag's "never reachable from the public API" design, much larger. Rejected.
(e) CHOSEN: c plus an Origin/Sec-Fetch-Site refusal. curl, Prometheus and `go tool pprof` send neither header, so they are unaffected; every browser-initiated request (fetch, <img>, <script>, form) carries one and is refused. Guard order: peer 403, Origin/Sec-Fetch-Site 403, Host 421.
For the bind address the USER CHOSE: refuse a non-loopback [runtime].addr at boot in config.Validate unless [runtime].allow_remote = true (loud and simple; nothing in the repo scrapes /metrics remotely today), over a per-request loopback-only 403 or allowing remote with only the Host/Origin checks. Also chosen: fix the diag listener's bind order in the same PR as a separate commit (net.Listen before "knomit ready", bind failure returned, per bind-all-then-ready-then-serve), since today it logs "listening" before binding and a failure is only a Warn.

AS BUILT (PR #292, head 995aa55c): allow_remote does TWO things, not one — it lets Validate accept the non-loopback bind AND sets diag.Options.AllowRemotePeers, which skips ONLY the peer check. Without the second half the opt-in bind would be a port nobody could use (even an SSH tunnel to a 0.0.0.0 bind arrives from the external IP when it targets that IP). The browser (403) and Host (421) checks ALWAYS apply, so a remote Prometheus scraping by DNS name must have that name in [auth].loopback_hosts; scraping by IP works. The guard's Host list is EffectiveLoopbackHosts(cfg.Host) plus the runtime addr's own host when that is a DNS name. Pinned by TestGuard_AllowRemotePeers and cmd TestOpenDiagServer_AllowRemoteIsWired.

Layering: PR #289's loopbackHostOK is unexported in internal/web and archtest TestPlatformKnowsNothingAboutKnomit forbids platform→web, so the pure-stdlib RULE moves DOWN to internal/platform/hostguard (LoopbackHostOK + LoopbackPeer) and web calls it from there. This does NOT move the main listener's CHECK: per the host-guard-placement decision it stays inside AuthMiddleware's anonymous branch and keeps answering 421; only the function relocates. A listed name grants no anonymous permissions on the diag listener, so no separate list is needed. The diag Origin refusal is consistent with the web UI's same-origin proof: neither the web UI nor the desktop UI calls any /runtime, /debug or /metrics route.

Non-scope: the diag routes stay stdlib-only and stay off the public API; loopback on this listener means a TCP peer address, never a principal (local-listener-single-site is untouched). This is a distinct decision from the loopback-anonymous-host invariant (main listener, principal assignment) and from the host-guard-placement decision (where the MAIN listener's check lives and why it is 421).

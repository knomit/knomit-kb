# With SilenceErrors on the root, the "Run 'knomit --help' for usage." hint is restored by MAIN.GO, appended only to cobra PARSE errors (unknown command, bad arg count, unknown flag) and never to a RunE error — chosen over leaving the hint out or turning SilenceErrors back off

Context: PR #286 put SilenceUsage and SilenceErrors on the root command so main.go prints each error once with no usage block. Cobra prints its "Run '<path> --help' for usage." hint inside `if !c.SilenceErrors` (cobra v1.10.2 command.go:1130-1132), so silencing errors also dropped the hint; `knomit bogus` printed only `unknown command "bogus" for "knomit"` and `knomit grants add x` only `accepts 2 arg(s), received 1`.

Options on 2026-09-25: (1) leave the hint out and document it (the reviewer would not have blocked on it: "did you mean" suggestions survive in the error string); (2) turn SilenceErrors off again and lose the single-printer property; (3) have main.go append the hint for errors that come from cobra's parsing/arg validation, not from RunE. The user chose (3).

How RunE errors are told apart: NOT by matching error text. A root PersistentPreRun (which cobra runs only after flag parsing, command resolution and Args validation succeed, immediately before RunE) records that execution reached the command; main.go appends the hint only when that did not happen. So a serve boot failure prints one line with no hint, while a typo or wrong arg count prints the error plus the hint.

Non-scope: the usage BLOCK stays suppressed everywhere; verify.go's own printing and exit codes are untouched.

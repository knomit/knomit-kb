# With SilenceErrors on the root, the "Run 'knomit --help' for usage." hint is restored by MAIN.GO, appended only to cobra PARSE errors (unknown command, bad arg count, unknown flag) and never to a RunE error — chosen over leaving the hint out or turning SilenceErrors back off

Context: PR #286 put SilenceUsage and SilenceErrors on the root command so main.go prints each error once with no usage block. Cobra prints its "Run '<path> --help' for usage." hint inside `if !c.SilenceErrors` (cobra v1.10.2 command.go:1130-1132), so silencing errors also dropped the hint; `knomit bogus` printed only `unknown command "bogus" for "knomit"` and `knomit grants add x` only `accepts 2 arg(s), received 1`.

Options on 2026-09-25: (1) leave the hint out and document it (the reviewer would not have blocked on it: "did you mean" suggestions survive in the error string); (2) turn SilenceErrors off again and lose the single-printer property; (3) have main.go append the hint for errors that come from cobra's parsing/arg validation, not from RunE. The user chose (3).

How it is built (commit 37eb6111): cmd.Execute(ctx, root) in cmd/root.go installs a root PersistentPreRun that sets a call-local `reached` flag, runs root.ExecuteContextC, and if there is an error and the hook never ran wraps it as fmt.Errorf("%w\nRun '%s --help' for usage.", err, c.CommandPath()) — %w keeps errors.Is working, and CommandPath names the resolved command (`knomit grants add --help` for a bad arg count, `knomit --help` for an unknown command). main.go calls cmd.Execute and remains the single printer. Errors are told apart by WHETHER EXECUTION REACHED THE COMMAND, not by matching error text. TestRoot_NoSubcommandReplacesTheRunHook fails if any subcommand defines PersistentPreRun(E), because with EnableTraverseRunHooks off a child hook REPLACES the root's and the flag would never be set.

CAVEAT (cobra v1.10.2 command.go execute, ~L968-1011): ValidateArgs runs BEFORE the persistent hooks but ValidateRequiredFlags and ValidateFlagGroups run AFTER them, so an error from MarkFlagRequired or a flag group would count as "reached" and get NO hint. No command uses either today; the Execute doc comment says so. If one is introduced, either accept the missing hint or move the flag-setting later.

Non-scope: the usage BLOCK stays suppressed everywhere; verify.go's own printing and exit codes are untouched.

# serve's six post-marker log.Fatal sites become errors RETURNED through RunE (sync TCP bind before "ready", buffered errCh for the async Serve goroutines, then the normal Shutdown), NOT "release the marker then exit" — and SilenceUsage/SilenceErrors go on the ROOT command so main.go is the single error printer for all nine subcommands; shipped as one PR, #262 first

Context (issues #261 and #262, RCA 2026-09-24 at dev 08d9528b): cmd/serve.go had SIX log.Fatal calls after crashdump's running marker is set (:184 TCP ListenAndServe goroutine, :239 local-listener Serve goroutine, :250 openTLSServer error, :256 tlsSrv.Serve goroutine, :267 openOAuthServer error, :274 oauthSrv.Serve goroutine), not the two the issue named. log.Fatal calls os.Exit, which runs no defers, so `defer marker.EndUnlessPanicking()` never ran: the next boot reported `previous run exited uncleanly (possible crash)` for a shutdown that was not a crash, migrate-registry (which reads the same running.marker) believed a server was still running, and a.Close and closeSocket were skipped too. The TCP bind was also asynchronous, so "knomit ready" was logged BEFORE a taken port failed. Separately, serveCmd set neither SilenceUsage nor SilenceErrors while main.go:29-31 already prints the returned error, so every serve error printed "Error: …", the usage block, then the error again; grants/oauth/identity printed it twice without usage; only verify silenced both (and prints its own).

Options considered for #261:
1. Return the error through RunE: the two synchronous sites return; TCP binds synchronously with net.Listen before the ready log and returns on error; the four async Serve failures send to a buffered errCh that the existing `<-ctx.Done()` wait selects on, followed by the existing Shutdown sequence, returning errors.Join(serveErr, shutdownErr); log.Error before returning so the failure still reaches the log file and crash ring. CHOSEN. Desktop (tools/desktop/boot.go) already binds synchronously and returns.
2. Release the marker, then exit. Rejected: still skips a.Close and the socket-file cleanup, and every future exit site would have to remember it.

Options for #262: (a) silence on serveCmd only (the issue's scope); (b) silence on the root command — Cobra ORs the root's and the command's settings, so all nine subcommands stop double-printing and main.go becomes the one printer. The USER CHOSE (b), accepting that every command's error output changes and that a mistyped flag no longer prints usage.

Packaging: one PR, two commits, #262 first, because #261 alone would make a runtime bind failure print after the flag list and twice — worse than the single zerolog Fatal line it replaces.

Non-scope: openLocalListener stays the single local-listener site (invariant), TLS/OAuth listener failures stay fail-closed (the process still exits non-zero, via a returned error), and verify.go's own error print and exit codes are untouched.

# The chat's tool guess fuses the embedding and lexical rankings by reciprocal rank fusion (k = 60, tied scores share a rank, ranks only, no cutoff); a failed embedder leaves the lexical ranking to guess alone, and on a flat embedding it can only reorder tools the lexical ranker clearly prefers

Live acceptance: the embedding ranker's scores over every tool were flat (0.17 to 0.19) for a plain knowledge question, so the ranking was nearly arbitrary (knomit_review and knomit_skill picked, knomit_query never in the top five). Short one-line texts embed poorly (1d564e96), and no cosine cutoff may be applied to tool descriptions (9f110192). chat.newRanker now builds llm.NewBlendedRanker(embedding, lexical) when the process has an embedder and the lexical ranker alone when it has none. Each ranking is turned into 1-based ranks (tied scores share the best rank of their group, so a ranker with no opinion adds the same to every tool), and a tool's fused score is the sum of 1/(RRFConstant + rank) over the rankers; ties go by name. Raw scores are never mixed or compared: scaling one ranker's scores changes nothing (TestBlend_UsesRanksNotScores). A ranker that errors is left out; both failing returns the error and the loop proceeds with no preload. The preload record says blended, or lexical when the embedder failed that turn (with embedding_error, a class: timeout, canceled or error, never the raw text).

RRFConstant = 60 is a policy constant: the value of the method's authors (Cormack, Clarke and Buettcher, SIGIR 2009), kept because nothing here is measured better; with k that large a ranker's first place is worth little more than its tenth, so no single ranker's top pick outvotes a tool both rankers place well.

Limits, measured on the real descriptions: the lexical ranker (TF-IDF over name plus full description) puts knomit_query LAST for "what do we know about how agents recover from tool errors?" (no shared word), and knomit_hypothesize, knomit_experiment and knomit_explain first. Rank fusion cannot rescue a tool neither ranker likes, and when the embedding ranking is flat it only moves a tool the lexical ranker prefers by about two places: knomit_explain above review and skill in the test, with the embedder placing explain one place below review. That is why knomit_query is a core tool rather than a guess. The embedder already embeds each tool's FULL description (EmbedDocument(name, description)), not the one-line catalogue purpose. Does NOT mean the guess is good, only that a flat embedding no longer decides it alone.

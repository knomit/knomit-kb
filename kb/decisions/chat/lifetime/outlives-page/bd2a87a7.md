# A chat ends ONLY on DELETE or when the server's lifetime ends (desktop quit, server stop); its page stream going away no longer ends it, idle chats are not auto-cleaned, and chats are still NOT persisted across a restart (user decision 2026-11-09)

DECISION (the user, 2026-11-09): a chat must no longer end because its page events stream went away. It lives until it is deleted (DELETE /chats/{id}) or until the server's lifetime ends (quitting the desktop app or stopping the server). A page that reconnects simply picks it up again (ready, then GET /chats).

WHY: chats disappeared from the chat list after a while of not using the app. Before this, a chat ended 60 s (chatStreamGrace) after its owner's last page stream closed, or 60 s after creation with none attached. A closed tab, a sleeping laptop, a network drop, or a hidden desktop window whose stream Wails reaped after 10 min without a poll (kb/gotchas/desktop/wails/streams/session-reap/ddf1016d.md) all removed the user's chats; only the session log file survived.

OPTIONS weighed: (a) keep the grace and make the page's liveness more robust (heartbeats, reopen; partly done for the desktop by PR #809) — still loses chats on sleep or a closed tab; (b) a long grace or idle auto-cleanup — still loses chats, just later, and needs a policy nobody asked for; (c) chats end only on DELETE or server stop — CHOSEN. Persisting chats across a restart is explicitly OUT of scope (a later project), and there is NO auto-cleanup of idle chats.

CONSEQUENCES: a server that runs for a long time keeps every chat nobody deleted, in memory and in its run directory, until it stops; that is accepted. Nothing in the chat package may add a clock or liveness check that ends a chat (see kb/invariants/chat/lifetime/3a4b7d86.md for the enforcing tests). A turn waiting for approval with no page attached keeps waiting indefinitely; Stop, DELETE or shutdown unwinds it.

WHAT THIS DOES NOT MEAN: a chat does not survive a restart (it is gone from GET /chats after the server comes back; its session log file in <home>/chat-logs remains). It does not mean the page's stream liveness work (ping, STALE_STREAM_MS reopen) is obsolete: a page with a dead stream still sees no events until it reconnects.

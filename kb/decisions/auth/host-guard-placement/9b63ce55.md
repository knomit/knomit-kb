# The #281 Host check lives INSIDE AuthMiddleware's anonymous branch, not in a separate middleware or in apiRouter, and refuses with 421 rather than 403

CHOSEN (issue #281; RCA and proposal approved by the user on 2026-09-25). The options:
- (a) inside apiRouter: rejected. It misses /git, /docs and the SPA, which sit on the outer router, and it would run on the OAuth listener, which reuses apiRouter behind a bearer edge.
- (b) a separate middleware in Server.Handler() above AuthMiddleware: rejected. One Handler() also serves the socket and TLS listeners, so that middleware would have to re-derive "is this plain TCP and not a peer and not TLS", duplicating AuthMiddleware's first two branches where the two could drift.
- (c) inside the branch that mints anonymous@none: CHOSEN. It runs exactly when that principal is about to exist, after the listener classification is done, and it covers every route because AuthMiddleware is on the outer router.

STATUS 421, not 403. AuthMiddleware's contract is that the 403 TITLES distinguish "Authentication required" from "Permission denied", and clients key on them. A wrong Host is not an authorisation outcome: the server does not answer for that authority. The 3b approval gate still answers 403 for the Host classes it alone refuses (other ports, other loopback IPs), because that is a permission decision.

OPTIONS REJECTED:
- an allowlist applied to every peer: breaks non-loopback deployments and buys nothing, since non-loopback peers get no principal;
- an Origin-based check: misses rebound GETs, which carry no Origin;
- minting no principal instead of refusing: reads still leak;
- automatic Tailscale MagicDNS admission: rebinding-safe, but it couples auth to Tailscale and silently exposes a funneled name. The user deferred it;
- a report-only release: rejected.

IP literals pass because rebinding needs a DNS name. os.Hostname() and .local names are NOT auto-admitted: a hostile LAN resolver or an mDNS reply can answer them.

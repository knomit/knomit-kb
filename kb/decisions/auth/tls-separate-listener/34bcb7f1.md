# Mutual TLS runs on a SEPARATE port with its own http.Server over the same handler, off until [tls].addr is set and a certificate is installed — not on the plaintext port, not by protocol sniffing; since knomit#256 BOTH `knomit serve` and the desktop app open it, through app.OpenTLSServer

OPTIONS (master ruling 1, F19 phase 2, 2026-09-22): (a) turn the existing TCP port into TLS once a certificate is installed; (b) sniff TLS vs plaintext on one port; (c) a separate TLS listener on its own port. CHOSEN: (c).

WHY: (a) breaks every plaintext client on the port the day a certificate lands — the bridge's TCP fallback (`knomitapi/dial.go` speaks http://), the desktop lockfile consumers, the web UI, and every `curl` and `git clone http://…/git` in docs. (b) is more machinery for no gain. (c) is purely additive: nothing about the plaintext port changes, which the end-to-end test asserts as its positive control.

SHAPE: `[tls].addr` (env KNOMIT_TLS_ADDR, default EMPTY = off) and `[tls].dir` (env KNOMIT_TLS_DIR, default `<home>/pki`, set in config.Load after tilde expansion — the one definition of that default). `app.OpenTLSServer` (internal/app/tls.go; it was cmd's openTLSServer until knomit#256) returns a SECOND `http.Server` sharing the plaintext server's Handler and BaseContext — with its OWN timeouts, not the plaintext server's — with `ConnContext: auth.TLSConnContext` and a zerolog-backed ErrorLog; each binary serves it and shuts it down beside its plaintext one. Outcomes: addr empty → off silently; addr set but no instance.crt → WARN 'run `knomit identity install`' and plaintext only (so configuring early is harmless); certificate installed but unloadable (CRL missing/malformed, older than crl.number, certificate for another key) → error, fail closed; addr already bound → app.ErrTLSAddrInUse, which `knomit serve` returns from RunE and so fails its boot (after its defers, #261), and which the desktop turns into a WARN and serves without TLS (kb/decisions/desktop/tls/bind-conflict). The certificate must wrap the key `App.KeyPath()` returns — the same file app.New resolved.

WHY A SECOND SERVER rather than a second listener on the same server: the marker that tells AuthMiddleware a request came in on the TLS listener comes from the server's ConnContext, and wrapping the conn instead breaks r.TLS (see the linked gotcha). Measured by sabotage: giving the TLS server the plaintext ConnContext made a LOOPBACK peer the anonymous principal, and its POST reached the handler past the write gate — the listener's 'never anonymous' rule depends on this wiring.

DISTINCT FROM the unix-socket rule (kb/invariants/auth/local-listener-single-site): that one opens a local listener in both binaries through auth.ListenLocal. This one is network-facing. Until knomit#256 only `knomit serve` opened it; the user then decided the desktop should be a fleet peer, and tools/desktop/boot.go bootServer now calls app.OpenTLSServer as the LAST listener before the lockfile (kb/invariants/desktop/boot/listener-order). The desktop's plaintext TCP bind stays loopback-only; only the TLS listener faces the network. MISREADING TO AVOID: 'the desktop is a peer' means it accepts enrolled peers once [tls].addr is set AND a certificate is installed — a default desktop install opens no network port.

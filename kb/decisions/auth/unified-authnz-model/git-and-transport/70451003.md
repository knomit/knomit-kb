# Decided (user, 2026-11-09, amends the unified authn/z model): git stays on the main HTTP(S) port with token Basic auth via `kb auth setup-git` (GitHub model, no SSH server, no new port); token pushes land on the instance's ONE agent branch; NO commit-signing features; external_addresses = issuers; guest role + chat:use; plain http on any bind; no upgrade path

STATUS: design decision, NOT YET BUILT (HEAD 8024d51b still has the old model). Amends kb/decisions/auth/unified-authnz-model; design doc .claude/plans/2026-11-09-unified-auth-design.md §14 and §15 (§15 overrides §14).

OPTIONS CONSIDERED for git: (1) tokens embedded in remote URLs — rejected as the documented path: plaintext in .git/config, shell history, process lists, logs, and every rotation means repointing; (2) git over SSH with registered SSH keys on a dedicated SSH server — rejected by the user: no additional port; (3) GitHub/Bitbucket model — HTTPS Basic with a token as password, a credential helper supplying and refreshing it — CHOSEN. Branch: (a) a separate agent/<name> branch per token like fleet nodes — rejected: humans and agents are meant to collaborate on the same branch (commit author already distinguishes them: agent commits are <agent-id>+<op>@agents.knomit.io), and per-token branches drag in push/sync/merge machinery; (b) token pushes land on the instance's ONE agent branch — CHOSEN. Signing: SSH public keys registered and linked per token with a 'verified' badge — REJECTED by the user as a lot of work (keys kept in perpetuity) and wrong (changes reach branches via merges done elsewhere); verified already means F09: signed AND in the branch AND enforce on.

THE CHOICE (all components): git over HTTP(S) on the main port; Basic auth ignores the username, password = knomit token (OAuth or personal access token). People: `kb auth setup-git` configures git to call the helper `kb auth git-credential`, refreshing after `kb auth login`. Scripts/CI: PAT from environment (http.extraHeader / KNOMIT_TOKEN; tools/okf keeps working). Fetch needs kb:read; push needs repo:push (contributor and above, plus node). Token pushes land on the instance's own agent branch under ALL of: the store's branch write lock with non-fast-forward refused; pushed commits indexed like the server's own; the existing commit judge and dot-path guard; refusal of any pushed commit authored with an @agents.knomit.io address (no agent spoofing); refusal on verify_signatures=enforce repos and on the fleet repository (allowed on off/log). receive-pack's 'not the host's own branch' rule stays for node pushes only. No signing-key registration, no token↔key link, no badge. Subscribers fetch another knomit's /git with a reader PAT as origin credential.

ALSO DECIDED: plain http on any bind is the deployer's job; the existing external_addresses list is the issuer list (no new key; default from bind when unambiguous; never from Host; Host allowlist removed) and a token is valid on ANY of the instance's external addresses; new role guest (kb:read only) and permission chat:use (reader and above) — anonymous bindable only to guest, read-only mode injects anonymous→guest in memory, all other read-only code deleted; diagnostics port stays unauthenticated on its own port; fleet mTLS port stays separate; no upgrade path — old auth data dropped.

NON-SCOPE: does not make humans' pushes bypass content checks, does not let anyone author agent commits, and does not change node push or F09 verification rules.

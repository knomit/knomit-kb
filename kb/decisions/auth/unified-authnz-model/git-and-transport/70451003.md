# Decided (user, 2026-11-09, amends the unified authn/z model): git stays on the main HTTP(S) port with token Basic auth via a kb credential helper (GitHub model, no SSH server, no new port); signing optional; owner-registered SSH PUBLIC keys linked per token verify; plain http allowed on any bind; no upgrade path

STATUS: design decision, NOT YET BUILT (HEAD 8024d51b still has the old model). Amends kb/decisions/auth/unified-authnz-model; design doc .claude/plans/2026-11-09-unified-auth-design.md §14.

OPTIONS CONSIDERED for git: (1) tokens embedded in remote URLs — rejected as the documented path: plaintext in .git/config, shell history, process lists, logs, and every rotation means repointing; (2) git over SSH with registered SSH keys on a dedicated SSH server — rejected by the user: no additional port; (3) GitHub/Bitbucket model — HTTPS Basic with a token as password, a credential helper supplying and refreshing it, signing keys registered separately — CHOSEN. For signing: server re-signing pushed commits rejected (rewrites hashes, client diverges); server-held private keys rejected by the user (option a); public-key verification chosen (option b).

THE CHOICE (all components): git over HTTP(S) on the main port; Basic auth ignores the username, password = knomit token (OAuth or personal access token). People: `kb git-credential` acts as git credential helper after `kb login`, refreshing transparently. Scripts/CI: PAT from environment (http.extraHeader / KNOMIT_TOKEN, also read by tools/okf so okf export keeps working — go-git does not call credential helpers). Fetch needs kb:read; push needs repo:push (contributor and above, plus node) and is allowed ONLY to the agent branch the token was created/approved for. Commit signing is OPTIONAL like GitHub: the owner registers SSH PUBLIC keys in the secrets store and may link a token to one at OAuth approval or PAT mint; a token-push commit signed by the linked key is marked verified, unsigned/other-signed commits are accepted but unverified. Fleet nodes keep the mTLS port and today's signer = pusher rule. Subscribers fetch another knomit's /git with a reader PAT as origin credential.

ALSO DECIDED: plain http on any bind is the deployer's job (no boot refusal, desktop All networks stays); one [server].public_urls list = external URLs = issuers, Host allowlist removed; read-only mode injects anonymous→reader in memory and all other read-only code is deleted; diagnostics port stays unauthenticated on its own port; fleet mTLS port stays separate for now; no upgrade/migration — old auth data is dropped.

NON-SCOPE: does not mean the server ever signs with a user's key, and does not make signatures mandatory on token pushes; does not change node push signing rules.

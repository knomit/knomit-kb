# A loopback mutation (any method but GET/HEAD/OPTIONS) that carries an Origin header is refused with 403 unless that Origin's authority equals r.Host (http or https) or it is in the CORS allowlist — checked inside AuthMiddleware's anonymous branch right after the Host check, with NO client changes and NO Content-Type rule; the shared JSON decoder is a separate later PR (issue #287)

Issue #287: a web page on any origin can POST a CORS-simple request (text/plain or no Content-Type, no preflight) to the plain listener on 127.0.0.1. The Host is a genuine loopback name so the #281 check passes, AuthMiddleware mints anonymous@none, and the fact handlers json-decode the body regardless of Content-Type. Reproduced by the reviewer on an isolated serve at dev 131376e3: cross-site text/plain POST /facts with Origin https://evil.example returned 201; POST /repos:probe-origin cross-site returned 200 (server fetches an attacker-chosen URL). Only POST is CORS-simple; PUT/PATCH/DELETE always preflight and are refused.

OPTIONS CONSIDERED
1. The issue's own direction: require exact application/json AND X-Knomit-Client on every mutating route of the plain listener.
2. Origin check inside AuthMiddleware's anonymous branch: for a mutating method, if Origin is present it must have the same authority as r.Host (http or https) or be in the CORS allowlist (wails://localhost for the desktop); absent Origin passes; OPTIONS exempt.
3. Sec-Fetch-Site as the primary or an additional signal.
4. A global Content-Type rule on every mutation.
5. Option 2 plus, in the SAME PR, a shared decodeJSON helper returning 415 unless the media type is exactly application/json, replacing the 13 blind json.NewDecoder sites.

RATIONALE (the designer's, 2026-09-26)
Option 1 and option 4 break existing clients with no security gain: the worker's inventory at 131376e3 shows the CLI, README curl and every SPA call except OAuth decide send no X-Knomit-Client; the bridge sends a STRUCTURED X-Knomit-Client (id=...;transport=stdio;...), not `web`; the SPA synthesize POST is text/plain, ontologies:validate is text/yaml, and there are 4 no-body SPA POSTs plus 7 no-body DELETEs; /git-upload-pack on the plain listener is application/x-git-upload-pack-request; `knomit oauth deny` sends a nil body. Option 3 adds nothing on POST: every browser that sends Sec-Fetch-Site also sends Origin, and Sec-Fetch-Site is only sent to trustworthy URLs (gotcha 77a08b65). Option 2 refuses the measured attack because browsers send Origin on EVERY POST including same-origin, while non-browser clients send none, so no client changes: served SPA sends http://<Host>, desktop sends wails://localhost (allowlisted), vite dev proxy forwards Host localhost:5173 with a matching Origin, a code-server/tailscale proxy in loopback_hosts presents https://<Host>. Comparing to r.Host (not browserProof's arrival-port ownHost) is what makes the proxy and vite cases pass; a rebound Host is already 421 before this check. It reuses the single chokepoint of decision a6505b7d instead of a second classifier. OPTIONS must be exempt because AuthMiddleware runs before corsMiddleware on the outer router. Option 5 was deferred: the decoder change touches 13 handlers and changes the response for any caller with a missing or wrong Content-Type; the inventory is a code read, not a runtime trace; the security fix should stay one small obviously-correct change that can be reviewed and merged fast, and hardening that might hit a compatibility problem should not hold it up or be reverted with it.

THE CHOICE
Option 2, alone, on branch fix/287-origin-guard. The decoder helper (option 5's second half) is a SEPARATE later PR; when built it must reject an ABSENT Content-Type too, because fetch no-cors with a typeless Blob body sends none, and ships only once every caller of the 13 handlers is confirmed to send application/json.

RESIDUALS ACCEPTED
- A pre-October-2019 Firefox omitted Origin on cross-site form POSTs.
- Origin: null (sandboxed iframe, data: URL, no-referrer page per gotcha 56edf2e6) is present and not ours, so it is refused: fails closed.
- Any local process can already act as anonymous with curl; that is the loopback_default model and unchanged.
- The TLS listener shares the handler but returns before this branch; a browser auto-presenting an installed client cert is an ambient credential not covered here.

WHAT THIS DOES NOT MEAN
- It does not require X-Knomit-Client anywhere outside the existing 3b OAuth approve gate.
- It does not make Origin REQUIRED: absent Origin passes, by design, for non-browser clients.
- It does not apply to the socket, TLS or OAuth listeners' identity paths.
- Foreseeable misreading: "same-origin means same port as the listener". It means Origin authority == r.Host as the browser sees it, which is why proxies and vite pass.

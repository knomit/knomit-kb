# ViaPipe is its own Via rather than a reuse of ViaSocket, because the grants key is <kind>:<id>@<via> — a row or a log line has to distinguish a SID read off a pipe from a uid read off a socket

auth.ViaPipe ("pipe") joins ViaCert, ViaToken, ViaSocket and ViaNone rather than reusing ViaSocket. The grants table key and client_sessions.principal are both auth.Principal.String(), i.e. `<kind>:<id>@<via>`, so the Via is the part that lets a stored row or a log line tell WHICH mechanism vouched for a caller.

On Windows a local bridge therefore renders `bridge:sid:S-1-5-21-...@pipe`, and on unix `bridge:uid:501@socket`. auth.LocalVia is the per-platform constant that picks one; it is a CONSTANT and not a parameter precisely because the boot seeding and the request-time middleware must choose the same one, or the seeded grant never matches the request.

CONSEQUENCE FOR ANYONE ADDING A Via: every closed-set validator over this type has to learn it too. ParsePrincipal's switch did not, and the whole grants CLI broke on Windows as a result.

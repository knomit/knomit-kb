# The verified pid goes in client_session_peers, a SIDE TABLE, and sits BESIDE the self-declared pid rather than replacing it — and filling client_sessions.principal still does not make the row an authorization input

F19 phase 1 records TWO new things about an MCP client session: `principal` (the existing nullable column from migration 000003, filled at last) and the kernel-reported pid of a unix socket peer.

THE PID IS A SIDE TABLE, `client_session_peers(session_id PRIMARY KEY, verified_pid, seen_at)`, not a column. That is forced, not preferred: the control migration chain is replayed as ONE concatenated script by `knomit migrate-registry` and admits only idempotent `CREATE ... IF NOT EXISTS` statements, which `TestControl_UpMigrationsAreIdempotentDDL` enforces with a regex. `ALTER TABLE ADD COLUMN` cannot be expressed in this chain AT ALL. This is the 000007 `handle_experiments` precedent and, before it, `repo_subscriptions`. Absence of a row means the session arrived over TCP and has no peer — there is no zero row to tell apart from a missing one. It has no foreign key, so `Store.Purge` collects its orphans the way it collects `client_session_bindings`.

THE DECLARED PID STAYS. `client_sessions.pid` comes from a header the client wrote about ITSELF; `client_session_peers.verified_pid` is what the kernel said. Keeping both is the whole point: collapsing them into one column throws away the only evidence a mismatch ever leaves. Same reasoning that keeps `clientInfo` beside `parent_app`. A blank observation does NOT erase either — the upserts use a CASE on NULL, because a later request carrying no principal means "not observed this time", not "no longer verified".

THE PART THAT IS EASY TO GET WRONG: this does NOT make `client_sessions` an authorization input, and the standing invariant that nothing in that table may gate, authorize, or attribute blame is UNCHANGED. Permission lives in `grants`, keyed by `Principal.String()`, and is read only through `auth.Allowed`. Nothing reads `client_sessions` or `client_session_peers` to decide anything. What changed is narrower and should be stated precisely: the `principal` column, which that invariant described as an empty slot reserved for future verified identity, is now FILLED for socket callers — so the clause "the identity is self-declared" is true of the bridge headers and false of `principal`. The row is still an observational trail; it now contains one field that an authority asserted rather than a client.

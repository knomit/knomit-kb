# knomit tool-description headlines are keyword-dense subject descriptions with NO exclusion clauses — measured; the "NOT for X" half is harmful, not load-bearing

**Options considered.** The 2026-08-12 binding-aware-tool-descriptions design (`.claude/plans/`) specified a per-binding headline whose authoring contract was "subject, then exclusion", asserting the exclusion was "the load-bearing half: without it both servers are attractors and the model takes the first plausible one". Measured alternatives, all one flat line under a 250-char cap: (A) no headline; (B) subject + exclusion clause; (C) full per-repo union; (P) subject keywords only, exclusion stripped and the characters respent on vocabulary.

**Rationale.** B and P were run paired in one invocation to control run-to-run drift (144 Claude Code sessions). P beat B: write-intent call rate 10% vs 37% within the paired run, 17% (10/60) vs 37% (11/30) pooling B across both runs, Fisher exact p = 0.062; clear-codebase non-use 29% -> 0%. The read path was already saturated at 100% under both.

The decision does not rest on the p-value, which is short of the conventional bar. It rests on there being nothing to lose: the exclusion clause exists solely to stop the model choosing the wrong sibling server, and misrouting never occurred in 630 measured calls (see the linked non-use fact). The clause defends against a failure that does not happen while consuming budget that measurably helps retrieval. Even at half the measured effect the trade is one-sided.

**The choice.** Headlines are keyword-dense subject descriptions. Do not write "NOT for ..." exclusion clauses; do not put them in the authoring contract, the UI help text, or validation guidance. Section 4 of the 2026-08-12 design doc is INVERTED by this.

**Non-scope.** This does NOT authorise building the headline feature itself. The per-repo `.knomit/mcp.yaml` headline is deferred pending a retest AFTER a `UserPromptSubmit` hook ships, because the hook targets the same write-path metric and may leave the headline with near-zero marginal value. It also does NOT authorise the rest of that design — the `lenses.headline` override, control migration 000002, lens composition, fair-share capping and the mount-count threshold were all justified by the misrouting story that did not survive measurement, and are deferred indefinitely. Finally, this rule governs descriptions used for TOOL SELECTION; it says nothing about how fact bodies or UI-facing lens descriptions should be written.

**Do not re-open on cost grounds.** Tool definitions render at position 0 and are the most cacheable content in a request; measured prompt-cache hit rate across 180 API calls was 98.6%, so description length is billed at roughly a tenth of a cent. Two separate token-cost arguments for this design were constructed and both were wrong.

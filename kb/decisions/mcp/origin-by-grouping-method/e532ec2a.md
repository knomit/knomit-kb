# Fact origin is decided by candidate grouping method at proposal time, not by the review act

A fact's origin (authored/distilled/discovered) records HOW its candidate group was formed, never whether an agent previewed/reviewed it. Mapping: cross-cluster BRIDGE (discover work-item, effort medium/high) -> discovered; regular cluster (distill work-item) -> distilled; single-fact, self-reasoned hypothesis (per-fact hypothesize loop) or any direct write -> authored (default). Origin is load-bearing because a forward discover and a distill both emit type=synthesis; origin is the ONLY discriminator between a bridged-emergent synthesis and a distilled-cluster synthesis.

**Context / bug:** The corpus had zero discovered facts. The auto-apply pipeline already stamps origin structurally (applyDiscoveredProposals -> discovered; ApplyDistillDecisions -> distilled). The gap is the preview-then-save path: when an agent previews proposals and persists via knomit_learn instead of submitting back to auto-apply, the grouping signal (which lives in the work-item) is dropped and the fact defaults to authored/distilled. PR #103 first recovered it by instructing the agent to set origin=discovered 'when you previewed before saving' — wrong trigger (the review act) and wrong location (the per-fact hypothesize loop, which is never a bridge).

**Options considered:** (A) global required origin on knomit_learn — rejected: taxes every ordinary authoring call and only guarantees a value is present, not the right one. (B) a new preview/commit pipeline path bypassing knomit_learn — rejected: does not remove the agent's instruction-dependence (choosing the path vs learn is itself instruction-following) for a much larger diff. (C) CHOSEN: keep origin OPTIONAL on knomit_learn (default authored) + make it MANDATORY at proposal time, in the discover/distill work-item prompt where the grouping context is local and explicit.

**Rationale:** The discriminator the agent needs already exists explicitly — HypothesizeItem.Type / ReviewItem.Type is 'discover' vs 'distill' vs 'hypothesize', and discover items carry a bridge payload. So the instruction keys off item.type; nothing new is plumbed. Friction lands only in the discovery/distill flow; ordinary learn is untouched. Prefer the structural auto-apply route, treat learn-with-origin as the documented fallback for the curate/edit case.

**Also fixed (latent):** evidence_weight self-citation — a dedup-merge appends the fact's own resulting path to refs as lineage; the weight loop must exclude the fact's own path so a merged distilled/discovered fact does not count its predecessor as evidence (baseline 0.615 vs inflated 0.701 in the regression test).

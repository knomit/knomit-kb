# A learn dedup merge never turns a stored non-hypothesis into a hypothesis: the stored type and confidence are kept and the response says the prediction was NOT written (user ruling 'fix it', #642)

THE DEFECT. Review found that an incoming HYPOTHESIS whose top dedup match was a stored observation (or any other non-hypothesis type) could win the merge and rewrite the stored fact as a hypothesis, with the hypothesis's confidence. The user ruled 'fix it'.

THE RULE (as built, #642, merge 77896f0a). absorbedHypothesis(new, existing) is true when new.Type is hypothesis and existing.Type is not. Then (1) incomingIdentityWins returns false, so the stored title, body, kind, type and origin are kept; (2) mergeFacts keeps the STORED confidence instead of the max of the two; (3) sources are unchanged (mergeCorroborates already refuses a hypothesis). Domains and entities still union. (4) ONE response note replaces the generic statement-not-applied and uncounted notes: 'fact N: incoming hypothesis absorbed by <type> <path>; stored type and confidence (<c>) kept, the prediction was NOT written; to keep it, resubmit with distinct_from: [<path>].'

WHY. A hypothesis's confidence is a PREDICTION probability, not evidence. Letting it raise a stored observation's confidence, or letting it change the observation's type, converts a guess into corpus knowledge behind a response that said 'wrote 1 fact'. This is the same principle as review's dedup tiebreak, where a non-hypothesis ALWAYS beats a hypothesis regardless of confidence (kb/decisions/synthesize/dedup-merge-tiebreak/02422cde.md); learn now matches it.

CONSEQUENCES. An absorbed hypothesis is NOT stored anywhere; the only way to keep a prediction worded close to an existing observation is distinct_from naming that observation. When a caller sees 'absorbed by', the prediction needs re-submitting.

WHAT THIS DOES NOT MEAN. It does not stop a hypothesis merging into a hypothesis (that still takes the max confidence and gets the kept/DROPPED note, kb/decisions/mcp/learn/distinct-from-honoured-by-merge/91cf6418.md). It does not stop a non-hypothesis from settling (subsuming) a stored hypothesis. It guards only the hypothesis-into-non-hypothesis direction; a non-hypothesis of one type can still take over another non-hypothesis type, see kb/gotchas/mcp/learn-hypothesis-report/ for the known gaps.

UPDATE (#643, merge a20152c9): the clause 'a non-hypothesis of one type can still take over another non-hypothesis type' no longer holds for learn. A learn dedup merge now never changes a stored fact's type (kind and, when types differ, origin stay too): kb/decisions/mcp/learn-hypothesis-report/489f36ae.md. The absorbed-hypothesis rule above is unchanged and still has its own, different note.

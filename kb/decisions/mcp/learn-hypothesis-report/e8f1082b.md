# Report a subsumed hypothesis with a short note plus one `settled:` commit line and no new response field (user ruling, #642, Option A) -- chosen over a structured response field or refusing the write

CONTEXT. knomit_learn silently retracted a stored hypothesis whenever a similar non-hypothesis fact arrived (subsumeHypothesis). Nothing in the response or the commit message said so. The trigger is similarity, not a verdict, so the deleted prediction may have been REFUTED rather than confirmed (issue #641).

OPTIONS put to the user: (A) a short response note per subsumed hypothesis plus one `settled:` commit-message line, no new response field; (B) a structured response field (for example a `settled` list beside `retracted`); (C) refuse the write and make the caller choose between distinct_from and an explicit retract.

CHOSEN: (A), the user's ruling. Rationale: the harm was invisibility, and a note plus a commit line removes it. A new response field widens the learn contract that `retracted`/`commit` define as the caller's own atomic-move paths (kb/invariants/mcp/learn/atomic-move/e4fff5d1.md) and would invite consumers to treat a similarity side effect as a verdict. Refusing would break the established, documented lifecycle (an observation settles its hypothesis) to guard a case that a report already lets the caller undo.

CONSEQUENCES. The note is deliberately short and does not quote the new fact's title. `retracted` stays the caller's own paths only. Behaviour of subsumption itself is unchanged. See kb/gotchas/mcp/learn-hypothesis-report/612294ef.md for the exact wording and the undo.

WHAT THIS DOES NOT MEAN. Not a precedent for adding a response field per side effect; and not a statement that subsumption is correct for refutations (issue #641 is open).

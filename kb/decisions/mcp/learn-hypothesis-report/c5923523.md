# A learn dedup merge's origin is last-wins: with the same type the merged origin is the incoming fact's (unset resolved first), with differing types the stored origin stays (user ruling, #647)

THE RULING (user, on #647, quoted verbatim): "merged keeps the origin on the newest fact, because that is assumed to have arrived last - essentially last wins".

AS BUILT (#647, merge 76d2b017; internal/edge/mcp/learn.go mergeFacts). SAME TYPE: merged.Origin = newFact.ResolvedOrigin(), the INCOMING fact's origin, whichever side wins on confidence or identity (incomingIdentityWins). An UNSET incoming origin is resolved first (authored, or distilled for synthesis), so it merges exactly as if the caller had sent that value explicitly: re-learning a stored discovered hypothesis verbatim with origin unset makes it authored. DIFFERING TYPES: the stored type is kept (kb/decisions/mcp/learn-hypothesis-report/489f36ae.md) and the stored origin stays with it. That one exception is not a preference, it is forced by Origin.ValidateForType (distilled only on synthesis; discovered only on synthesis or hypothesis): an incoming origin on the kept type could fail serialization or reattribute pipeline output. No new response note: an origin change on a merge is silent.

OPTIONS. (a) origin always stays with the stored fact; (b) an unset incoming origin never replaces the stored one; (c) CHOSEN: last-wins on the resolved incoming origin, stored origin only when the types differ.

WHY Fact.ResolvedOrigin() IS EXPORTED (internal/domain/fact/validation.go, one method delegating to defaultOriginForType, the single source of the per-type default; it replaced the unexported resolvedOrigin wrapper, whose one caller, the rule sandbox, now calls the method). The learn handler lives in another package and needs the value that lands on disk. A raw empty origin would elide on disk and read back the same for equal types, but in memory computeEvidenceWeights gates on the RAW f.Origin, so an unset incoming synthesis would silently stop being re-weighted; and restating 'authored, or distilled for synthesis' in mcp would duplicate the default that once round-tripped authored synthesis into distilled.

CONSEQUENCES. To keep a stored fact's origin through a re-learn, pass the same origin explicitly, use distinct_from, or use knomit_update; origin is immutable in update, so a wrong relabel needs retract plus re-learn. Relabelling changes how OTHER facts' evidence weights are computed (the lineage walk recurses only through distilled and discovered facts); a relabelled fact keeps its older stored evidence_weight, which is stale but not overstated. Last-wins can attach the incoming origin to a kept STORED statement (a hypothesis merge keeping the existing prediction, or a different statement whose text lost), which departs from kb/decisions/mcp/origin-by-grouping-method/e532ec2a.md for merges; the ruling says 'whichever side wins' so this is accepted.

WHAT THIS DOES NOT MEAN. Origin does not follow the identity winner (that was the pre-#647 rule). The stored type still never changes. It is learn's merge only.

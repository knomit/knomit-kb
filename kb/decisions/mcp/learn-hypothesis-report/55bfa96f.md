# A hypothesis is settled when the settling fact cites it and the hypothesis is retracted in the SAME commit; the verdict is a Knomit-Outcome commit trailer, never a frontmatter field (user ruling, #641/#648)

THE RULING (user, #641, built in #648, merge 2782d21c). Settling a hypothesis means two things in ONE commit: the settling fact cites the hypothesis in its refs, and the hypothesis is deleted. The verdict (confirmed or refuted) is recorded only as a commit trailer, one line per hypothesis in the commit's last paragraph: `Knomit-Outcome: <hypothesis path> confirmed|refuted`. There is NO new frontmatter field and no stored `outcome` anywhere on a fact.

WHY. #641 found that learn's similarity subsumption deleted a hypothesis whenever a similar observation arrived, so a REFUTED prediction was indistinguishable from a confirmed one and reflect could only say 'retracted'.

OPTIONS the user was shown and REJECTED: (a) keep the hypothesis alive and add an `outcome` field to it (rejected by the user: a settled hypothesis is retracted, not kept, and a new field widens the fact format); (b) a synchronous judge inside learn that decides the verdict (rejected: learn stays a deterministic writer); (c) a negation heuristic over the new fact's text (rejected: guesswork presented as a verdict).

THE TRAILER NAME IS GENERIC ON PURPOSE. It is `Knomit-Outcome`, not a hypothesis-specific name, so the same trailer can carry other outcomes later. Today only confirmed and refuted are valid (model.ValidOutcome); a reader must not assume the value set is closed forever, and a writer must not invent a value.

WHO WRITES A VERDICT. Only these paths: knomit_learn `settles` (a per-fact, request-only declaration), review's prune `settle {path, outcome, by}`, and distill `settle [{path, outcome}]`. The undeclared similarity path in learn (and review's dedupCluster) still settles by citing and retracting in one commit but writes NO trailer: nothing judged it.

A request-only `settles` on learn was the ruling's other half: like distinct_from it is never stored on the fact. See kb/invariants/mcp/learn/settles/ for its contract.

WHAT THIS DOES NOT MEAN. It does not mean a trailer-less retraction was a confirmation: an absent trailer means no verdict was recorded. It does not mean the verdict is a fact-level record: it lives in git history and is read by walking commits (facts.Repo.SettlementsSince).

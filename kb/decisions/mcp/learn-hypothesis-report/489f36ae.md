# A learn dedup merge never changes a stored fact's type: kind, type and (when the types differ) origin move together and stay with the stored fact (user ruling, #643)

THE RULING (user, on #643): a dedup merge never changes a stored fact's type. Kind, type and origin move together.

OPTIONS. (a) Only guard the hypothesis direction, as #642 did (absorbedHypothesis), and leave another non-hypothesis type free to take over a stored fact on identical text. (b) Keep the stored type, and take the winner's kind and origin anyway. (c) Keep the stored kind, type and, when the types differ, origin. CHOSEN: (c). Review round 1 of #643 showed why (b) fails: each type belongs to one kind, and Origin.ValidateForType couples origin to type (distilled only on synthesis, discovered only on synthesis or hypothesis), so a winner's origin on a kept type either fails serialization (call refused) or reattributes pipeline output as authored.

AS BUILT (#643, merge a20152c9, internal/edge/mcp/learn.go mergeFacts). merged.Kind = existing.Kind; merged.Type = existing.Type; origin is existing.Origin when the types differ; when they agree it is the INCOMING fact's resolved origin (newFact.ResolvedOrigin(), last-wins, user ruling #647, merge 76d2b017: kb/decisions/mcp/learn-hypothesis-report/c5923523.md), no longer winner.Origin. Title, body, expires, context and motif order still follow the identity winner (incomingIdentityWins = same statement AND newFactWins); confidence (max), sources and refs rules are unchanged; the absorbed-hypothesis rule (kb/decisions/mcp/learn-hypothesis-report/91e88bb3.md) is unchanged. typeKept(new, existing) = types differ AND same statement AND not an absorbed hypothesis; it is true WHICHEVER side won the identity tiebreak (round 1 had gated it on the incoming side winning, so a stored-wins merge was silent). It emits ONE short note: 'fact N: merged into <type> <path>; stored type kept (incoming was <type>); use knomit_update to change it.' with ' Sources unchanged: <why>.' folded in when the merge added no sources. A different statement is excluded: the existing text wins and the statement-not-applied note covers it.

CONSEQUENCE. To change a stored fact's type, call knomit_update on its path; re-learning the same text under another type will not do it. A caller that sees 'stored type kept' has NOT had its type applied.

WHAT THIS DOES NOT MEAN. It is learn's merge only. Review's judged prune (ApplyPruneDecisions) is governed separately since #644 (merge 13abafd3): its merged type is derived from the members, never the judge's (kb/decisions/synthesize/review-prune-merge-type/f2a31b00.md); review has no stored side, so a mixed-type prune merge takes the dedup tiebreak winner's type. Review's mechanical dedup is kind-guarded separately (kb/incidents/synthesize/cluster/cross-kind-dedup-merge/94172e81.md). It does not freeze origin on SAME-type merges: since #647 origin there is last-wins (the incoming fact's, unset resolved first) by user ruling, and the relabelling consequence is recorded in kb/gotchas/mcp/learn-hypothesis-report/17a78459.md.

Anchors: TestLearnHandler_MergeKeepsStoredType (rows for type, kind, origin, stored-wins note); mutations 'winner type', 'winner kind', 'winner origin', 'typeKept gated on incoming winning', 'typeKept ignores type', 'drop !absorbedHypothesis' each go red.

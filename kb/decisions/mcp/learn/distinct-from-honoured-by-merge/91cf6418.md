# knomit_learn's dedup merge declines a match the call names in `distinct_from` (the fact lands at its own path), and a hypothesis-into-hypothesis merge names the kept and DROPPED predictions; `distinct_from` stays request-only and is never stored

F-R2 (first mission, verified 2026-10-03 as a bug): `applyDedupMerge` never read `distinct_from` — only the later same-subject stage did, and that stage skips every merged index and never offers hypothesis candidates. So a counter-hypothesis worded close to its target (at or above the per-model Dedup cosine, same category prefix) was always merged into it: the lower-confidence prediction was discarded, or the original overwritten at its own path, behind "wrote 1 fact".

THE USER (2026-10-03, verbatim), on persisting distinct_from in the fact: "dedup) no, I do not want to do that, no additional "distinct_from" because that can drift as facts get updated. Leave it as is, and let's start the work"

OPTIONS: (a) persist `distinct_from:` in frontmatter, honored by learn, same-subject, review dedup and prune; (b) keep it request-only and make learn's merge stage honor the call's value, and report merges truthfully. CHOSEN: (b). Rationale: a stored path list drifts as facts move, merge and are retracted.

AS BUILT (#412, merge 55a47911):
- In applyDedupMerge, after the consumed and retracting declines and BEFORE reading the match or hypothesis subsumption: `if namedIn(distinctFrom[i], match.Path) { continue }` (case-insensitive, the same matcher the same-subject bypass uses). The fact is written at its own freshly-minted path; an observation naming a hypothesis does not subsume (retract) it.
- The index stays UNtouched, so checkSameSubjectCollisions still judges the fact and still validates that every distinct_from path exists — a nonexistent path refuses the whole call even when the fact would otherwise have merged.
- `distinct_from` never reaches fact.Fact or SerializeFact; the written file carries no such key.
- When an incoming hypothesis merges into an existing hypothesis, the response note (in `notes` and `summary`) names the path, "kept the <incoming|existing> prediction ..." and "DROPPED the <other> prediction ..." with titles and confidences, and the distinct_from escape. It replaces the generic "incoming is a hypothesis, sources unchanged" note.

WHAT THIS DOES NOT MEAN:
- Not a durable "keep apart" marker: review's dedup (dedupCluster) is unchanged and can still merge the two later.
- A declined top match is NOT replaced by the next-best match (Search runs with Limit 1), exactly like the consumed and retracting declines.
- Naming some OTHER path does not stop the merge: only a match named in the list is declined.

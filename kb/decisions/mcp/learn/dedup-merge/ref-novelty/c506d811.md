# #361: a learn-time dedup merge adds to `sources` only when the incoming fact is not a hypothesis AND cites at least one ref the existing fact lacks (compared by classified identity, not raw string); refs and confidence still merge; a non-corroborating merge gets one learn-response note

DECISION (designer, 2026-10-01, issue #361).

PROBLEM: mergeFacts (internal/mcp/learn.go) did `merged.Sources = newFact.Sources + existing.Sources` unconditionally, so re-learning one fact from one URL N times gave sources: N with a single ref. It also counted an incoming HYPOTHESIS, which the review-side merge (loserCorroborations, internal/synthesize/dedup.go) already refuses.

CHOICE:
1. The learn merge adds newFact.Sources to the existing count ONLY IF (a) the incoming fact is not a hypothesis AND (b) it cites at least one ref the existing fact does not already carry. Otherwise the count is unchanged. Refs are still unioned and confidence still takes the max; only the count is gated.
2. Novelty is decided on a ref IDENTITY key built from fact.ClassifyRef, in one shared helper used by both learn and discovery REINFORCE (discovery_reinforce.go already gates on `added == 0`): local kb ref -> path; foreign kb ref -> repo id + path; src:// -> repo + path + BLOB (commit and #L range ignored; no blob -> repo + path + commit); URL -> lowercase scheme/host, fragment and one trailing '/' stripped, query kept. A ref naming the merged fact itself is never novel. Comparison is on keys only; stored refs are not rewritten by the merge.
3. Two ref-less learns merging do NOT count: with no refs the code cannot distinguish two independent agents from one agent repeating itself. This deliberately reverses the earlier assumption in TestMergeFacts_TransfersLoserSources.
4. The amount added on a novel ref is newFact.Sources (usually 1), not a fixed 1.
5. Reporting: no new structured fields. The learn response's existing `notes` list gains one note ONLY for a merge that did not count (e.g. "fact 0: merged into X; no new refs, sources unchanged"); ordinary learns and corroborating merges add nothing. Chosen to keep response tokens near zero while telling the caller in the one case it would otherwise be misled.

REJECTED: raw-string ref comparison (incoming kb refs are still bare at merge time while stored ones are canonical kb://<id>/...; violates the compare-classified-not-raw invariant); counting ref-less merges; adding a fixed 1; new merged_into/corroborated response fields.

WHAT THIS DOES NOT MEAN: it does not stop the merge itself (dedup-not-append still holds) and does not change review prune/dedup transfer, which moves an already-stored fact's count rather than counting a re-read.

# The same-subject anchor excludes generic entities via the MOTIF df ceiling — reused for its shape, and measured on the entity axis before being trusted

An entity can anchor a same-subject refusal only if its document frequency on the branch is at or below `synthesize.DFCeiling(n)` = `max(motifDFCeilingFloor, motifDFCeilingPerCent% of n)` — the derivation the motif df band already used, extracted and shared rather than restated. It encodes no fixed corpus property: it is a RATIO of the corpus's own size with a small-corpus floor, so it resolves to a different df on every corpus.

THE TRANSFER IS THE RISK, AND IT WAS MEASURED, NOT ASSUMED. Both of that rule's justifications in `bridge_motif.go` are about MOTIF recurrence, and the file itself notes the three axes (motif/entity/domain) have different df distributions. Entities are more numerous and longer-tailed — every fact carries entities, not every fact carries motifs — so reusing the rule is reusing its SHAPE, not inheriting a validated cutoff.

THE CEILING IS BRANCH-RELATIVE. Two measurements of the same corpus, days apart: N=2122 / ceiling 42 on the agent branch, N=1810 / ceiling 36 on `main`. Same rule, different denominators. Never quote a ceiling as a fixed number — it is a function of whichever branch is being written to. On the agent-branch measurement only 15 of 3724 entities exceeded it, and they were exactly the big-tech names (Anthropic, OpenAI, Google, Microsoft, Nvidia, Meta, Apple, Claude, Cursor, Claude Code, Hugging Face, DeepSeek, CISA, ChatGPT, GitHub). Known collision pairs' anchors sit at df 0–12, far from the cutoff on either denominator, so the transfer holds at this operating point.

THE UPPER BOUND IS SCOPE-CONDITIONAL (decision 9d, PR #189), and the reason is a guarantee that was narrower than its citation. The band originally excluded every candidate at or above `Dedup` because "a hit at or above Dedup belongs to `applyDedupMerge`, which has already folded it". That is true ONLY inside the incoming fact's own category directory — `applyDedupMerge` searches with `Path: categoryDir` and looks nowhere else. For a cross-category candidate at or above `Dedup` the merge never saw it and the band excluded it, so NOTHING caught it. Measured under embeddinggemma, three of the four locatable known collision pairs sat above `Dedup` and every one was cross-category, which is why they collided at all: Coursera Project Helix 0.8752, Forethought nightwatchman 0.8384, TPUv7 Ironwood 0.9179; only Ramp AI Index (0.7033) was in band. `Dedup` now caps the band only for a candidate inside the incoming fact's own category directory; outside it there is no upper bound. `categoryDirOf` is the single definition of that scope, called both where the merge sets its search scope and where the gate tests membership, because two derivations that drifted would put the bound somewhere the merge does not cover — this defect again.

CONSEQUENCE: if the entity df distribution shifts (a corpus dominated by one vendor, or a bulk import), re-measure before trusting the ceiling; a green test suite says nothing about whether the cutoff is right, because the tests assert the mechanism, not the outcome on real data.

CORRECTION (2026-09-14): an earlier revision said the TPUv7 pair's only shared entity is `Google`, which the ceiling excludes, and concluded that pair could not be caught at all. That is WRONG for the pre-merge bodies, which share `TPUv7 Ironwood` at df 0 — a perfectly good anchor. The error came from reading the POST-merge survivor, which names its subject three ways (TPU / TPUv7 Ironwood / Google TPU), and generalising backwards to the facts that were merged. Spelling variance remains a real limit of an entity anchor in general; this pair is simply not an instance of it, and no measured pair currently is.

df comes from `TokenDF(…, "entity")` so there is one definition of df. NOTE the two folds do NOT fully agree: `TokenDF` counts over a `COLLATE NOCASE` column (ASCII-only) while `EntityTagMatches` folds full Unicode, so `Café`/`CAFÉ` is one entity to the match and two to the count. The df lookup is keyed exactly as the count was requested, which confines the disagreement to that non-ASCII case rather than spreading it. Reconciling the folds is open work.

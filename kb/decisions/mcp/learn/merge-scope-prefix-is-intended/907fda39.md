# Keep knomit_learn's auto-merge search as a raw path prefix (path LIKE dir%): a near-duplicate in a prefix sibling or descendant directory MERGES rather than being refused — issue #260 closed wontfix

Issue #260 reported that applyDedupMerge (internal/mcp/learn.go) searches with `Path: categoryDirOf(paths[i])`, which newFactFilter (internal/store/search_query.go) turns into `f.path LIKE 'kb/ops/task%'` with no trailing slash. That scope reaches (a) prefix siblings such as kb/ops/tasks/, (b) descendants such as kb/ops/task/child/, (c) `_` treated as a one-character LIKE wildcard, (d) ASCII-case variants. The comments in applyDedupMerge and sameCategoryDir describe the scope as the incoming fact's "own category directory", which the code does not implement.

OPTIONS CONSIDERED
1. Exact category directory: add a `Dir` option to store.SearchOptions (escaped LIKE on dir/ plus a no-further-slash check), switch applyDedupMerge to it, leave `Path` as a raw prefix for knomit_query and the synthesize callers. Prefix siblings and descendants fall through to the same-subject gate and get a refusal instead of a silent merge.
2. categoryDir + "/": excludes prefix siblings but keeps descendants; would force sameCategoryDir in the same-subject gate to widen to descendant-or-equal.
3. Keep the raw prefix and fix only the misleading comments and the gotcha fact.

RATIONALE (the designer's, 2026-09-25)
The merge only fires when the candidate clears the dedup similarity threshold, so the candidate is always a near-duplicate in CONTENT; it is "unrelated" only by location. Under the designer principle dedup-not-append (kb/principles/philosophy/dedup-not-append/adf1c4a5.md) two similar facts must collapse into one regardless of path. The caller may simply have supplied the wrong path, in which case the fact already in the kb is the one that should win. Once that view is taken the remaining harms are negligible: wrong-topic validation is theoretical because the topic is the first path segment and a prefix sibling shares it unless a fact sits at the topic root and two topic names are prefixes of each other (none are); `_` and case leaks are harmless because fact paths are lowercase-canonical and every hit still has to clear the similarity threshold.

THE CHOICE
Option 3. Issue #260 is closed as wontfix. The prefix scope is INTENDED behaviour. The only follow-up is a comment-only change stating the real scope in learn.go and learn_same_subject.go and re-wording the gotcha fact kb/gotchas/mcp/learn/dedup-search-scope-is-a-string-prefix/047f3cdd.md as intended behaviour, so the ticket is not re-filed.

WHAT THIS DOES NOT MEAN
- It does not say the scope should be the WHOLE corpus. The reach is bounded by the string prefix of the incoming directory; another topic or an unrelated category is never searched. Today a near-duplicate there is refused by the same-subject gate (kb/decisions/mcp/learn/same-subject-refusal/f77be375.md) rather than merged; widening the merge to the corpus would be a separate decision and this one does not authorise it.
- It does not make the two stages agree. sameCategoryDir in the same-subject gate skips only EXACT-directory candidates, so a prefix-sibling or descendant candidate above the dedup threshold that the merge did not take (not top-1, already consumed, declined by the candidate-side LearnDedupOff check, or starved out of the KNN k-window) is still eligible for a same-subject refusal, while a same-directory candidate in the same position is skipped. That asymmetry is known and accepted here; changing it is a behaviour change needing its own issue.
- It does not endorse the `_`/case leakage as a feature; it judges it harmless on a lowercase-canonical corpus.
- It does not touch the k-window starvation of the KNN pool (kb/gotchas/store/vec0/k-window-precedes-where/fbb0d36d.md), which can make an in-scope duplicate miss the merge entirely; that is a separate, pre-existing limitation.
- Foreseeable misreading: "the merge scope is a bug that nobody got around to". It is not; a PR that narrows the scope to the exact directory contradicts this decision and the dedup-not-append principle.

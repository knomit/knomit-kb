# knomit_learn refuses a write that shares a subject with an existing fact — whole call, entity-anchored, fail-open on every missing signal

`knomit_learn`'s original dedup searched ONLY the incoming fact's own category directory, over title+body, at the `Dedup` floor, and never looked at entities. Two sessions recording one event under two different categories therefore never collided at write time, and the corpus grew near-duplicate pairs that only a later review prune would find. `checkSameSubjectCollisions` adds a corpus-wide band BELOW the auto-merge floor: a candidate is an existing fact in `(ReflectNovelty, Dedup)` sharing at least one NON-GENERIC entity.

THE CONTRACT, every clause load-bearing:

- Runs AFTER `applyDedupMerge` (so a fact the auto-merge folded is not also refused) and BEFORE any write, including before `computeEvidenceWeights` — a refused call pays for nothing.
- Skips EVERY index the merge touched, not only those that "merged": `mergeFacts` inherits title and body from whichever fact won, so for a touched index the precomputed vector no longer describes what would be written.
- The WHOLE call is refused, never part of it. One learn call is one commit, so writing the innocent facts would report success for a batch that only half landed.
- Caller escapes, both logged as bypasses with distinct messages: `distinct_from: [paths]` asserts distinctness, and a candidate the incoming fact already CITES in refs is declared lineage and skipped for any origin.
- `origin` in {distilled, discovered} is exempt: the synthesis prompts construct a fact carrying the union of its sources' entities and citing them, so pipeline output collides with its own sources by construction, and it already passes the review prune. Note `Origin` is empty on the struct unless the caller passed it, so the refs limb — not this one — carries most pipeline traffic.
- Candidates whose existing type is `hypothesis` (:136) or `signal` (:145) are skipped. Both are TYPE matches in the candidate loop, not kind matches, and they are skipped for different reasons. `hypothesis`: `subsumeHypothesis` settles those in the same commit, and refusing would block the write that resolves one. `signal` (added by F01, PR #247): a signal's entity is a task id rather than a subject and it is consumed rather than believed, so two signals naming one task are not a duplicate, and the refusal's "update the existing fact" advice is nonsense for a message someone else sent. The `signal` skip is NOT redundant with the synthesis seed filter's kind exclusion, which governs a different path — see [[same-subject-skips-signal-by-type]] before removing it.

EVERYTHING FAILS OPEN. No entities, no sufficiently specific entity, no embedder, no calibrated band for the running model, no query vector, and ANY infrastructure error (corpus size, entity df, the search itself) all return nil and refuse nothing. A refusal is a hard block on the caller, so it must never rest on a signal we do not have; this is the same direction `applyDedupMerge` takes on its own failures.

Refusals AND both bypass kinds emit a structured log event carrying the band endpoints and model id in force. Nothing durable is written on a refusal — learn is a one-shot call with no session row, and a counter would turn an all-or-nothing refusal into a partial commit.

CONSEQUENCE: when adding a caller or a stage near this one, state which side of `applyDedupMerge` it belongs on, and never convert a fail-open branch to fail-closed without deciding what a false refusal costs the caller.

WHAT THIS DOES NOT MEAN: it is not a coherence or misroute gate. `kb/decisions/lens/no-write-time-coherence-gate` rejected refusing on LOW similarity because novel knowledge looks exactly like a misroute; this is the HIGH-similarity, entity-anchored case that decision explicitly left to dedup. It is also NOT a throttle — nothing rate-limits on the refusal count.

The learn_same_subject.go ref is pinned at f8142735 (the PR #247 merge), which carries the two-type skip bullet; the learn.go ref is unchanged since #187 and stays at its original pin.

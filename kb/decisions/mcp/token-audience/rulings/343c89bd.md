# Decided (user, 2026-10-29): MCP honours an OAuth token's repo or lens audience the way REST does — knomit_repos lists only what the token reaches, MCP cursors and tasks are owned by endpoint + principal, a lens token cannot add repos to its lens, and a lens's knomit_changes reads only pinned member branches

The user's final rulings on the mcp-token-audience audit (gaps G1, G2, G4; G5 shipped in PR #675), implemented in PR fix/mcp-token-audience on the #675 reach mechanism (auth.WithRepoReach recorded by BearerMiddleware / AuthMiddleware, copied by mcpHTTPContext). Reach per caller: local edges reach all repos; the unscoped /api/v1/mcp token reaches all; a repo-audience token its repo only; a lens token NO repo by name; trigger/script hosts their own repo.

1. G4 — a lens token may add to a lens only repos it can already read (kb/invariants/lens/membership/add-needs-reach).
2. G1 — knomit_repos shows a lens token its lens and that lens's members, a repo token its repo; unscoped and local callers unchanged. Built with a LENS reach beside the repo reach (auth.WithLensReach / ReachesLens / AllLenses, default deny; tokenLensReach: /api/v1/lenses/L… → L, /api/v1/lenses or wider and /api/v1/mcp → all, a repo token → none). `reposInReach` keeps a repo row (live or unavailable) when ReachesRepo(name) or the repo is a member of a reached lens; `lensesInReach` keeps reached lenses. The `bound` section is unchanged (it is the caller's own binding).
3. knomit_changes on a lens binding (Binding.FromLens) reads each member ONLY at the branch the lens pins it to, plus, for the write repo, its own agent branch and its exp/* branches (experiments are local, so every exp/* of the write repo is its own). `branch` or `consensus` naming anything else is refused BEFORE the branch is looked up (no existence oracle). A repo binding keeps every branch. This matches lens REST, which serves only pinned branches and has no changes route.
4. Token→uid binding (audience survives rename; a recreated name is not the old repo) is a SEPARATE PR, not this one.
5. G2 — MCP tasks and tool-session cursors are owned by endpoint + principal, the principal being the identity (OS user, or the OAuth subject) — kb/invariants/mcp/ownership/endpoint-and-principal. The OAuth subject names the person/approver-chosen identity, not the client app (kb/architecture/oauth/token-subject).

6. N1 — Decided (user, 2026-10-29), option (a): a token whose audience is /api/v1/mcp OR ANY PATH UNDER IT (/api/v1/mcp/<suffix>) is the request the router already serves as the unscoped endpoint, so it reaches ALL repos and ALL lenses, exactly like the bare /api/v1/mcp audience. One predicate, `httpx.IsUnscopedMCP`, built on the same constants as the router's unscoped routes (`httpx.UnscopedMCPPath` / `UnscopedMCPPattern`), so the two cannot drift; a scoped endpoint's audience (/api/v1/repos/X/…/mcp, /api/v1/lenses/L/mcp) and a look-alike (/api/v1/mcpx) are NOT widened. Before this, such a token got an EMPTY reach (knomit_repos listed nothing, cross-KB denied) while knomit_bind still bound anything — an inconsistency, not an escape.

NOT DONE: the audit's reach asserts in gateBinding and BindHandler. After the N1 ruling both are unreachable: on a scoped endpoint the binding is the URL and every audience covering a scoped URL reaches that repo or lens; on the unscoped endpoint every token that reaches it (by audience) reaches everything. Review/hypothesize session_id is not owned by principal, but since review N2 a session_id continues only on the branch the session was opened on (Pipeline.activeSession): knomit_review and knomit_hypothesize pass the binding's write branch on every path (start, current, continue). Lens membership: since review B1 a changed write repo or re-pinned read member needs reach too (kb/invariants/lens/membership/add-needs-reach/bc6a8362.md).

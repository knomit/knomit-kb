# explain falls back to the last valid version when a ref no longer exists at the expected commit

knomit_explain BFS used to silently skip refs that failed ReadFileAtCommit (the 'merge wall' — a retracted ref breaks the depth-N traversal chain). The fix: when the commit-anchored ReadFact (AtCommit) fails, fall back to ReadFact(BeforeCommit=commit) to read the file from JUST BEFORE retraction. The returned content is marked retracted: true with last_commit_hash = the commit where the file was last present (NOT the retraction commit). The retracted fact is added to the explain result normally and its local refs enqueued so the full depth-N chain remains traversable (explainFactEntry has Retracted bool + LastCommitHash string).

MECHANISM UPDATE (PR #77): the BeforeCommit fallback (factIndex.readFileLastCommit) is now INDEX-BASED, not a go-git log walk — the original title's 'git log' is obsolete. It resolves the last added/modified version via fi.rh.resolveActiveCommitForPath (first-parent ancestry over commit_log + commit_parents, stepping over deletions) and reads the blob there, with 'before' kept exclusive by starting from firstParentCommit(beforeCommit). This also FIXED a latent bug: the old gogit.LogOrderCommitterTime walk landed on the deletion commit and returned ErrPathNotFound at any commit AFTER a retraction, so explain's fallback only worked when anchored exactly at the retract commit; the index walk steps over the deletion and works at any later commit too. (MCP explain still uses LastCommitForPath separately for the HEAD-anchored retraction probe in explain.go.) Aligns with the rule that history navigation reads the rebuildable index, not a live git walk.

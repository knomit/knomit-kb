# explain falls back to the last valid version when a ref no longer exists at the expected commit

knomit_explain's BFS used to silently skip refs that failed ReadFileAtCommit (the 'merge wall' — a retracted ref breaks the depth-N traversal chain). The fix: when the commit-anchored `ReadFact(AtCommit)` fails, fall back to `ReadFact(BeforeCommit=commit)` to read the file from JUST BEFORE retraction. The retracted fact is added to the explain result normally and its local refs are enqueued, so the full depth-N chain stays traversable.

**MECHANISM UPDATE (PR #77):** the BeforeCommit fallback (`factIndex.readFileLastCommit`, internal/engine/store/facts/fact_read.go) is INDEX-BASED, not a go-git log walk — the original title's 'git log' is obsolete. It resolves the last added/modified version via first-parent ancestry over `commit_log` + `commit_parents`, stepping over deletions, and reads the blob there, with 'before' kept exclusive by starting from `firstParentCommit(beforeCommit)`. This also FIXED a latent bug: the old `gogit.LogOrderCommitterTime` walk landed on the deletion commit and returned `ErrPathNotFound` at any commit AFTER a retraction, so the fallback only worked when anchored exactly at the retract commit; the index walk steps over the deletion and works at any later commit too. MCP explain's HEAD-relative flags now come from `FactQuery.CitedVersionState` (PR #693 round 5); `FactQuery.LastCommitForPath` is gone. Aligns with the rule that history navigation reads the rebuildable index, not a live git walk.

**WHAT THIS DOES NOT MEAN — the wire contract (verified at commit 4baae4ed).**

- *Not* "the entry carries `Retracted bool` and `LastCommitHash string`." Neither field exists. `explainFactEntry` (internal/edge/mcp/explain.go) carries **`Deleted bool`** (`json:"deleted,omitempty"`) and **`Superseded bool`** (`json:"superseded,omitempty"`). A client keying off `retracted` or `last_commit_hash` will read nothing — the flag on the wire is `deleted: true`.
- *Not* "deleted and superseded mean the same thing." `deleted` means the reading branch holds no live version of the source (retracted, or never on that branch). `superseded` ("changed since cited") means the source is live but the BLOB the branch holds for that path now (branch_facts) differs from the cited blob. They are mutually exclusive.
- *Not* "superseded = the branch's latest commit for the path differs from the pinned commit." That was the rule until PR #693 round 5 (F1, also on dev). After a merge carried an unchanged fact, the branch's latest commit_log row for it was the merge, so the unchanged target was flagged. It is a blob comparison now (FactQuery.CitedVersionState, called from readNode). Under option 1, a target resolved on another branch is superseded on a reading branch whose own version differs.
- *Not* "the fallback returns the retraction commit." It returns the commit where the file was last PRESENT, which is the commit the returned content came from.

See also the write-time counterpart: the ref gate deliberately ACCEPTS a citation to a retracted fact, because `FactExistsAt` walks back through retractions exactly as this read path does — kb/decisions/mcp/learn-rejects-unresolvable-local-refs/6341b5ef.md.

**CHANGED SINCE CITED IS RELATIVE TO THE READING BRANCH (user ruling, PR #693; verified at 866eb303).** `superseded` is always computed against "current", and current is the blob the READING BRANCH holds for the target path now (branch_facts, read inside FactQuery.CitedVersionState, called by readNode with the branch being read). It is never the commit being viewed. Example: fact F cites R; R is unchanged on main but changed on an agent branch. Read on main, F's reference to R shows NOT changed; read on the agent branch, it shows changed. Time-travelling to an old commit does not change the comparison: the commit only locates the CITED blob, the other side stays the branch's present one.

MISREADING: "changed is relative to the viewed commit." It is not. Do not 'fix' an old-commit view that still flags a target as changed, and do not expect a flag to differ between two commits of the same branch.

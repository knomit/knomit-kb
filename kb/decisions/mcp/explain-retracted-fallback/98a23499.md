# explain falls back to the last valid version when a ref no longer exists at the expected commit

knomit_explain's BFS used to silently skip refs that failed ReadFileAtCommit (the 'merge wall' — a retracted ref breaks the depth-N traversal chain). The fix: when the commit-anchored `ReadFact(AtCommit)` fails, fall back to `ReadFact(BeforeCommit=commit)` to read the file from JUST BEFORE retraction. The retracted fact is added to the explain result normally and its local refs are enqueued, so the full depth-N chain stays traversable.

**MECHANISM UPDATE (PR #77):** the BeforeCommit fallback (`factIndex.readFileLastCommit`, internal/engine/store/facts/fact_read.go) is INDEX-BASED, not a go-git log walk — the original title's 'git log' is obsolete. It resolves the last added/modified version via first-parent ancestry over `commit_log` + `commit_parents`, stepping over deletions, and reads the blob there, with 'before' kept exclusive by starting from `firstParentCommit(beforeCommit)`. This also FIXED a latent bug: the old `gogit.LogOrderCommitterTime` walk landed on the deletion commit and returned `ErrPathNotFound` at any commit AFTER a retraction, so the fallback only worked when anchored exactly at the retract commit; the index walk steps over the deletion and works at any later commit too. MCP explain still calls `LastCommitForPath` separately for the HEAD-anchored retraction probe (explain.go). Aligns with the rule that history navigation reads the rebuildable index, not a live git walk.

**WHAT THIS DOES NOT MEAN — the wire contract (verified at commit 4baae4ed).**

- *Not* "the entry carries `Retracted bool` and `LastCommitHash string`." Neither field exists. `explainFactEntry` (internal/edge/mcp/explain.go) carries **`Deleted bool`** (`json:"deleted,omitempty"`) and **`Superseded bool`** (`json:"superseded,omitempty"`). A client keying off `retracted` or `last_commit_hash` will read nothing — the flag on the wire is `deleted: true`.
- *Not* "deleted and superseded mean the same thing." `deleted` means the source fact was retracted since the citing edge formed; `superseded` means the source is still live but its HEAD revision is newer than the version the referrer reasoned over. They are set independently on summary nodes.
- *Not* "the fallback returns the retraction commit." It returns the commit where the file was last PRESENT, which is the commit the returned content came from.

See also the write-time counterpart: the ref gate deliberately ACCEPTS a citation to a retracted fact, because `FactExistsAt` walks back through retractions exactly as this read path does — kb/decisions/mcp/learn-rejects-unresolvable-local-refs/6341b5ef.md.

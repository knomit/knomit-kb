# explain falls back to git log when a ref no longer exists at the expected commit

knomit_explain BFS used to silently skip refs that failed ReadFileAtCommit (the 'merge wall' — a retracted ref breaks the depth-N traversal chain). The fix: when ReadFileAtCommit fails, fall back to gs.LastCommitForPath(path) to find the retraction commit, then gs.ReadFileLastCommit(path, retractCommit) to read the file from JUST BEFORE retraction. The returned content is marked retracted: true with last_commit_hash = the commit where the file was last present (NOT the retraction commit). The retracted fact is added to the explain result normally and its local refs enqueued so the full depth-N chain remains traversable. explainFactEntry gained two fields: Retracted bool, LastCommitHash string. The interface GitStore in internal/mcp/server.go gained LastCommitForPath and ReadFileLastCommit. The merge wall is broken: provenance can now traverse through retracted intermediate nodes.

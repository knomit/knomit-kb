# A tool's main-argument marker lives in its _meta ("io.knomit/key"), not in its input schema, because the schema is what the model is sent and is part of the chat's cached tool prefix

Decided 2026-11-06 (feat/chat-tool-titles). Each knomit tool marks the argument a person should see beside its title with withKeyArgs(names...), which sets Tool.Meta["io.knomit/key"] to a list of argument names (first non-empty string value wins; e.g. knomit_bind [repo, lens], knomit_query [text], knomit_changes [prefix, repo], knomit_experiment [name, action]; knomit_repos, knomit_review, knomit_hypothesize mark none). The option considered and rejected was an `x-knomit-key` keyword on the property in the input schema: mcp.toolDef copies inputSchema verbatim into llm.ToolDef.Schema, which every adapter sends to the model and which is hook 1 of the cached prefix, so a schema marker would change prompt bytes (one cache miss per chat after deploy, and a non-standard keyword shown to every external MCP client's model) for a word on a screen. _meta is outside the schema; toolDef reads it and annotations.title into ToolDef.Title/Key, which are json "-" and which no adapter reads (anthropic.go and ollama.go pick Name, Description, Schema explicitly). TestToolDef_TitleAndKeyDoNotChangeThePrefixBytes asserts a tool with title+marker encodes into Snapshot.CanonicalPrefix byte for byte as the same tool without them.

Consequence: adding or renaming a title or a key never touches what the model sees. Misreading to avoid: this does not mean annotations are invisible to MCP clients; external clients do receive annotations.title and _meta in tools/list and may display them.

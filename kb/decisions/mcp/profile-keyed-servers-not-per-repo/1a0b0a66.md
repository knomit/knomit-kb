# MCP servers are profile-keyed (3 instances), NOT per-repo — handlers resolve repo from ctx

MCP went from N repos × 3 profiles instances down to exactly 3 profile-keyed instances (code, chat, generic) shared across all repos. Each tool handler resolves the repo from the request context at call time via repos.RepoFromContext(ctx) — nil-check returns ToolResultError('no repository in context'). mcp.NewServer signature is NewServer(profile, defaultOntologyRoot, embedders...) — no per-repo state. Per-session instructions are computed via server.WithHooks + Hooks.AddAfterInitialize callback that reads ri := repos.RepoFromContext(ctx) from the initialize request's context and mutates result.Instructions = ProfileInstructions(profile, ri.OntologyRoot(), ri.Ontology()). buildMCPHandlers() is called ONCE at server startup; SetupMCP and OnRepoReady are DELETED — new repos work at runtime without MCP rewiring. After SwapStore (origin session commit), no MCP rebind is needed — handlers pick up the new svc via ri.WithRead on the next request.

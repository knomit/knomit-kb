# knomit_review opts into MCP tasks capability; handler detaches via context.WithoutCancel

knomit_review advertises WithTaskSupport(mcpgo.TaskSupportOptional) — clients implementing the MCP tasks capability run the call asynchronously and poll tasks/get for completion; clients without task support get original synchronous behavior. Why optional: a new review session on a large KB takes 60-120s (clustering + dedup of dirty facts) which exceeds typical client tool-call timeouts. Server-wide: NewServer calls server.WithTaskCapabilities(true, true, true) to advertise the capability. CRITICAL: when invoked as a task (req.Params.Task != nil), the handler detaches via 'ctx = context.WithoutCancel(ctx)' because mcp-go runs the work in a goroutine but uses the HTTP request ctx, which net/http cancels as soon as the initial CreateTaskResult response is sent. Without detach, the work would see context.Canceled on the first SQL query. Client-initiated cancellation via tasks/cancel still works because mcp-go uses a separate cancel func.

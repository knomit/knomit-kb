# Decided (user, 2026-10-29, #685): on a URL-scoped MCP endpoint the connection's DEFAULT binding is fixed to the repo's or lens's default (agent) branch; knomit_experiment open returns a handle bound to exp/<name> on every endpoint and callers must pass it; there is no opt-in to move the default

TRIGGER (#685). On a URL-scoped endpoint (`/api/v1/repos/<r>/mcp`, a lens's mcp URL, any `--repo`/`--lens` bridge), `knomit_experiment open` without a `binding` handle used to move the whole MCP SESSION's default binding onto exp/<name> (the session-keyed mount_experiments row). Subagents share their parent's MCP session and the server cannot tell agents on one session apart, so one agent's open moved every agent on the session: default-binding READS went stale (the experiment forked before later commits, e.g. another experiment's commit to the agent branch, so those facts were invisible), and default-binding WRITES from unrelated agents landed in someone else's experiment and were committed or rolled back with its PR. Nothing in query or write results said which branch was used.

OPTIONS (from the issue). (1) open returns a handle and leaves the session default alone, optionally with an opt-in to move the default; (2) every query/write result names the branch and experiment used; (3) warn on or refuse default-binding writes into an experiment the caller did not open.

THE USER'S RULINGS (2026-10-29, final):
- On a URL-scoped endpoint the connection's DEFAULT binding is FIXED: always the repo's or lens's default branch, the agent branch. Nothing may move it: not knomit_experiment open, not knomit_bind, not anything else.
- knomit_experiment open returns a handle bound to exp/<name> on EVERY endpoint, the same way the unscoped endpoint already scopes to the handle. Callers must pass that handle ("they must use the handle. that's why it's there for"). There is NO opt-in to move the default; the old behaviour is removed entirely.
- commit / rollback / sync act on the experiment named by `name`, or by the passed handle's experiment. Without a name or a handle they are REFUSED with a clear message (the default can no longer be inside an experiment, so "the experiment you are currently in" means the handle's).
- Option (2) REJECTED: do not add the branch name to query or write results; the handle already names the branch.

RATIONALE. A movable default moves every agent sharing the session, and the session cannot be split into callers: only a value the caller carries (the handle) can name the caller (kb/decisions/mcp/session-binding/per-bind-handle). This SUPERSEDES the URL-scoped half of kb/decisions/experiments/mcp-surface (option g, the session-keyed (session id, mount uid) row and its "accepted hazard").

CONSEQUENCE FOR CALLERS. Keep the handle `open` returns and pass it as `binding` on every call that should read or write the experiment, and on commit/rollback/sync (or name the experiment). A call without `binding` on a URL-scoped endpoint always reads and writes the agent branch.

WHAT THIS DOES NOT MEAN. Not that handle-less calls are refused on a scoped endpoint: they still work, on the default branch. Not that URL-addressed experiment mounts (`/branches/exp:<name>/mcp`, `/lenses/{l}/experiments/{n}/mcp`) changed: their URL names the experiment. Not that the unscoped endpoint changed: there a handle was always required and open always moved only that handle.

FOLLOW-UP RULINGS (user, 2026-10-29, on the PR #686 open questions):
- Dead Sessions-UI code (web/src/SessionsTable.tsx `mounts` join, `ClientSessionMount` in web/src/api.ts) is removed in a SEPARATE small PR after #686 merges, not in #686.
- `repos.WithoutMountState` is REMOVED in #686 (with the gate's call and the test assertion that only exercised it). Standing rule: delete unreachable guards rather than keep them as defence in depth.
- NO one-time `lapsed_experiment` warning for legacy mount_experiments rows: `knomit_experiment list` already shows the state, and this is pre-release. The purge simply drops them.
- commit / rollback BY NAME must say what actually happened — which experiment went into which branch — and, only when a handle was passed, where that handle now points ("; this handle stays on X" / "; this handle is back on X"). They must never say "this connection's default binding is back on …", on any scoped mount or on an experiment-URL mount, because the default never moves.

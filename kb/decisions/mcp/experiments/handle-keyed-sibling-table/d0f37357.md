# The active experiment lives in handle_experiments keyed on the BINDING HANDLE — session keying would repeat the 2026-09-17 incident with a WORSE ending, and the control chain could not have added a column anyway

TWO INDEPENDENT REASONS converge on the same shape, and each is sufficient on its own.

1. WHY NOT THE SESSION ID. An earlier draft keyed the active experiment on (Mcp-Session-Id, write repo uid) in client_sessions. That is the design removed on 2026-09-17: one client connection carries several logical jobs, so state keyed on that id serves whichever job acted LAST (incidents/mcp/session-binding/cross-binding-overwrite). The experiment version fails worse than the original. Those five misrouted writes failed only because the two repos' ontologies shared no topic — an experiment and its parent share an ontology BY CONSTRUCTION, so a misrouted write commits silently and looks correct.

2. WHY A SIBLING TABLE AND NOT A COLUMN. The control chain is replayed as one concatenated script by `knomit migrate-registry`, so it admits only `CREATE (TABLE|UNIQUE INDEX|INDEX) IF NOT EXISTS` — TestControl_UpMigrationsAreIdempotentDDL enforces exactly that by regex, and SQLite has no idempotent ADD COLUMN. This is the repo_subscriptions pattern's second instance, not a new idea. Watch the trap 000005's header records and 000007 repeats: the guard splits on `;` BEFORE stripping comments, so a semicolon anywhere in the SQL prose reads as a statement break and fails the test.

FOUR NEIGHBOURING FACTS, FOUR DIFFERENT SUBJECTS — they cluster because they share entities, not claims. decisions/mcp/session-binding/per-bind-handle is WHY routing moved off the session id at all. architecture/mcp/session-binding/handle-model describes binding_handles itself. architecture/mcp/client-sessions/binding-set describes client_session_bindings, the OBSERVATIONAL set where nothing may gate. THIS fact is about a further table: routing state for experiments, keyed by handle alone, with no session_id column — and about the migration constraint that forced a table rather than a column, which none of the three discusses.

No foreign key to binding_handles, following client_session_bindings' precedent: Store.Purge collects the orphans by anti-join after deleting the handles, so delete order cannot matter. The experiment therefore inherits the handle's lifetime — it dies with the handle, which is why re-entry after a reconnect needs knomit_bind {experiment}.

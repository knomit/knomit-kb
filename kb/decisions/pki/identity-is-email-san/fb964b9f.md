# A knomit certificate's identity is its ONE email SAN: <agent id>@agents.knomit.io makes it an INSTANCE certificate (implicit read + push:own); any other address or none is not an instance certificate and the TLS listener refuses it (there is no operator certificate); there is no role field and no knomit:// URI SAN (user ruling R1/R3, PR #514; operator half removed in auth P0)

pki.IssueLeaf(root, pub, email, validity, now) writes the email SAN only (no URIs; extensions stay the standard set). pki.IdentityOf reads it: exactly one email SAN that pki.AgentIDOfEmail turns into a non-empty id -> Identity.AgentID set, IsInstance() true, PrincipalKind() "instance"; anything else (another domain, a lookalike like x@agents.knomit.io.example.com or x@sub.agents.knomit.io, two email SANs, none, a legacy knomit://instance/x URI) -> operator. The principal is always keyed by the KEY's full fingerprint: instance:<64-hex>@cert or operator:<64-hex>@cert (AuthMiddleware in internal/edge/web/auth_middleware.go; earlier internal/web). VerifyInstanceChain no longer refuses on names (ErrSANMissing, ErrRoleUnknown, pki.Role, pki.SAN, parseSAN are deleted); it verifies chain, CRL, ed25519 and returns IdentityOf.

OPTIONS the user weighed (ruling R1-R3, handoff of 2026-10-14): (a) keep the knomit://<role>/<label> URI SAN for the role and add an email SAN for the id: REJECTED by the user (two names for one identity); (b) a separate role field or extension: REJECTED, because only agents have @agents.knomit.io addresses, so the address itself says 'agent' and a role field would be a second source of the same truth; (c) the email SAN alone, the same form as the git committer: CHOSEN. Any certificate address that is not <id>@agents.knomit.io belongs to an operator; there is no third kind.

At PR #514 `knomit identity enroll` took --agent-id <id> (instance) or --operator [--email <addr>] and --host and --role were gone; that command has since been removed and enrollment is POST /api/v1/fleet/enroll. Issued records carry `email` (the old san/label fields are gone; old local ledger lines still parse because unknown JSON fields are ignored).

CONSEQUENCE: certificates issued before PR #514 (knomit://instance/<label>, no email SAN) now read as OPERATOR certificates and lose the implicit read/push:own: re-issue them (no legacy support was built, by decision).

MISREADING: 'any cert chained to the root is an instance' is WRONG; only an agent address makes one. The SAN does not carry permissions; grants rows do. It also does not mean the id is parsed: pki.AgentIDOfEmail is the one string operation and the id it returns is only compared.

UPDATE (auth P0, PR #814, merge b5d17520): the 'operator' half of this decision is gone. Identity.PrincipalKind() is deleted (displays print `instance:<fp>@cert` only when Identity.IsInstance(), else say it is not an instance certificate); pki.InstallBundle and PreviewBundle refuse a bundle whose leaf is not an instance certificate with pki.ErrNotInstanceCertificate (checkBundle), writing nothing; IssueLeaf with no email names the certificate "knomit <short fp>" instead of "knomit operator ..."; AuthMiddleware refuses a non-instance certificate on the TLS listener with 403 ("the TLS listener accepts only enrolled instance certificates; this certificate's email address is not an instance address"); auth.OperatorPrincipal and auth.KindOperator are deleted. pki.IdentityOf still parses any chained certificate (a non-instance one can still be minted and dialled, e.g. a server cert with no SAN), it just authenticates nothing and cannot be installed as this instance's identity. Read every 'operator' in the body above as 'non-instance, refused'.

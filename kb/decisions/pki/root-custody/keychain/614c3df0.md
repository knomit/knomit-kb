# The fleet root key lives in the OS keychain (service "knomit", account "fleet-root/<RootID>", RootID = fingerprint of the root's OWN key read from root.crt) with the passphrase-encrypted <dir>/root.key as the fallback; export-root MOVES the key by default, --keep copies it (a hot spare the designer wants kept), and it refuses an --out that is the fleet root directory's own root.key

Fleet design D9, built in internal/pki/custody.go and cmd/identity.go (PR #512, merge 8e86308d).

SCHEME. One keychain item per root: service `knomit` (pki.KeychainService), account `fleet-root/<RootID>` (pki.KeychainAccount). RootID is `pki.RootID(root.crt)` = `pki.Fingerprint` of the root certificate's OWN Ed25519 public key (64 hex, SHA-256 of the SSH wire encoding), the same value the CRL watermark is keyed by and `identity install --root` takes. It is derived from the key, never parsed from a name. The item holds the root key UNENCRYPTED as OpenSSH PEM. Library: github.com/zalando/go-keyring v0.2.8 (macOS `security -i` with the secret on stdin, Windows Credential Manager, Linux Secret Service).

OPEN. `OpenRoot(dir, kc, pass)` reads `<dir>/root.crt` FIRST (it names the item), tries the item and returns the source (`keychain` | `file`). FILE FALLBACK: when the keychain Get errors in ANY way (not found, locked, no Secret Service) it opens `<dir>/root.key` with the passphrase callback, which is called only on that path. It does NOT fall back when an item EXISTS but does not hold this root's key (or does not parse): that is an error. Neither present is `ErrNoRootKey`, naming the item and the file.

CREATE. `CreateRoot` (`knomit identity init-root`; init-master was renamed in PR #513) writes root.crt, then `kc.Set`; only when Set fails does it write the encrypted root.key (needs a passphrase). With a working keychain NO root.key is written, and init-root prints a hint to back the key up with `export-root --keep --out <file>`.

EXPORT. `export-root --out <file>` (--out mandatory, stdin must be a terminal, no HTTP route or UI) writes the key encrypted exactly as root.key is, followed by the root cert PEM, O_EXCL 0600, reads it back and decrypts it, fsyncs its directory, and only then removes the keychain item AND <dir>/root.key. That MOVE is the default (no two fleet roots by accident). `--keep` leaves the local copy: a backup or hot spare. The designer explicitly wants `--keep` kept as a hot-spare option; do not remove it as a footgun.
- It REFUSES an --out that is the fleet root directory's own root.key (pki.ErrExportOntoRootKey): before writing, by cleaned absolute path and again with parent symlinks resolved; after writing and before ANY removal, by os.SameFile against <dir>/root.key (catches a case-aliased spelling on a case-insensitive filesystem). On that late refusal nothing is removed and the written file is a valid root.key. Without this, the move deleted the export it had just written together with the keychain item, and the key existed nowhere (PR #512 review finding 1).
- The export passphrase is CONFIRMED: typed a second time (both entries with --passphrase-file -, a terminal confirmation of a passphrase file's content otherwise); a mismatch aborts before anything is written or removed.
- A keychain delete that fails while the key was read from root.key is reported (ExportResult.KeychainErr) and the CLI warns that the keychain may STILL hold the key instead of claiming the machine can no longer sign. A failed delete when the key came FROM the keychain is an error (the key is in two places).

IMPORT. `import-root <file>` stores the key into the keychain (root.key fallback), writes root.crt if missing, refuses a dir holding a DIFFERENT root, and removes the root.crt it wrote on any later failure.

CLI. init-root, enroll, revoke, export-root, import-root, root-fingerprint and `oauth ... --sign` default --dir to `<home>/fleet` (was `<home>/master` before PR #513). --passphrase-file is needed only for file custody. `knomit identity root-fingerprint` prints RootID from root.crt (no key needed); the `install --root` help points there.

CONSEQUENCES. To find the key you need root.crt: a fleet root directory without root.crt cannot open a keychain-held root. For a keychain-held key the export passphrase is the ONLY remaining secret once the key is moved: losing it is losing the fleet root (D9: root loss ends the fleet). After a default export this machine can no longer enroll, revoke or sign approvals until the file is imported again.

MISREADING. 'Keychain first' does not mean a bad keychain item is skipped: a mismatched item fails closed. The fallback file is not an automatic backup: with a working keychain there is no file.

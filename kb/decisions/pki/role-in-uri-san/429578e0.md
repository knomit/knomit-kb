# SUPERSEDED by PR #514 (the email SAN <agent id>@agents.knomit.io is the identity, no role, no URI SAN): the knomit:// URI SAN carried a certificate's role because a private X.509 extension under a 2.25 UUID arc cannot be written or parsed by Go; that Go limit still holds

STATUS: SUPERSEDED. Since PR #514 a certificate has no role field and no knomit:// URI SAN: its identity is ONE email SAN, <agent id>@agents.knomit.io for an instance and any other address (or none) for an operator, decided by pki.IdentityOf (kb/decisions/pki/identity-is-email-san/fb964b9f.md). pki.Role, pki.SAN, parseSAN, ErrRoleUnknown and ErrSANMissing are deleted. The sections below record why a private extension was NOT used and how the URI SAN worked on dev before #514; do not build on the SHAPE or CONSEQUENCES text. A certificate that carries only the old URI SAN now reads as an operator certificate.

WHAT STAYS TRUE (the Go limit): F19 revision 2 wanted the role and the F13 election capability in a private X.509 extension under a UUID-derived 2.25 arc. IMPOSSIBLE in Go, measured on go1.26.6: `pkix.Extension.Id` is `asn1.ObjectIdentifier` = `[]int`, and a v4 UUID's integer is at least 2^76, so the extension cannot be expressed in `ExtraExtensions`. It cannot be READ either: `crypto/x509/parser.go:233` (`parseExtension`) calls `ReadASN1ObjectIdentifier(&ext.Id)`, which returns false on an arc wider than int, and the parse fails with `x509: malformed extension OID field`. A hand-built certificate carrying one would be unparseable by every Go peer, our own verifier included. `x509.OID` holds big arcs, but only `Certificate.Policies` uses it. Option 2 (an IANA Private Enterprise Number) fits `[]int` but costs days of latency for one integer.

HISTORY (decided 2026-09-22, F19 phase 2; superseded 2026-10-14): the role (instance | operator) was carried in the URI SAN `knomit://<role>/<label>` (role in the URI authority, `<label>` restricted to [A-Za-z0-9._-], opaque, no fp8). Leaf certificates carried only standard extensions; the F13 `host: true|false` capability lived in the F10 peers fact, not the certificate; a permission was always a grants row, never certificate contents. The user's ruling for #514 (R1-R3) replaced the URI SAN with the committer-form email SAN because the cert must name the agent id and only agents have @agents.knomit.io addresses, so the address itself says 'agent' and a separate role field would be a second source of the same truth.

MISREADING TO AVOID: this fact is not the current certificate format. Read kb/decisions/pki/identity-is-email-san/fb964b9f.md.

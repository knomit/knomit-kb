# Enrollment install and show orchestration lives in internal/pki (InstallBundle, SplitBundle, Status), not in cmd and not in internal/app: both the CLI and the desktop's Settings bindings call it, it needs no server, and pki stays import-free by taking (dir, keyPath) instead of a config

`knomit identity install` and `identity show` used to do their work in package `cmd` (`installBundle`, `splitBundle`, `showIdentity`, `writeAtomic`). The desktop app ships without the `knomit` CLI and cannot import `cmd`, so knomit#256 moved that orchestration into `internal/pki` as `InstallBundle(dir, keyPath, raw, replaceRoot)`, `SplitBundle(raw)` and `Status(dir, keyPath)`. Both `cmd/identity.go` and the desktop's Wails bindings call those functions, so there is ONE set of install checks: key match, chain, same root unless replacing, and the per-root CRL watermark.

Why `pki` and not `internal/app`: the orchestration needs no server, no handler and no boot state, only the pki directory and the key path. `pki` imports no knomit package, and it keeps that property by taking strings rather than a `config.Config`.

Consequences for a caller:
- Resolve `[tls].dir` and the key yourself (`cfg.TLS.Dir`, `app.ResolveKeyPath(cfg)`).
- Anything that depends on `[tls].addr` stays in the caller. For example, the CLI's "add [tls] addr" hint and the `tls_listener:` line are printed by `cmd`, not produced by `pki`.

Refusals are CLASSIFIED so a UI can name the problem without showing the bundle: `ErrMalformedBundle`, `ErrKeyMismatch`, `ErrRootDiffers` (as `*RootDiffersError`, carrying both roots' CommonName and RootID fingerprint), `ErrCRLRollback`, `ErrCRLInvalid`, or a `VerifyInstanceChain` sentinel. Each classified error's `Error()` text is exactly what the CLI printed before the move. A differential run of the old and new `knomit` binaries through the same install/show/refusal flow gave byte-identical output and identical pki files.

The writes use pki's own `writeFileAtomic` (a unique temp name per file, then rename). The old cmd `writeAtomic` (a fixed `<name>.tmp`) was deleted rather than moved, so pki keeps a single atomic writer.

Misreading to avoid: `Status` is not a verifier. It reads the certificate with `IdentityOf`, which does not check the chain or the CRL, so its output must never be used to decide whether to trust anything.

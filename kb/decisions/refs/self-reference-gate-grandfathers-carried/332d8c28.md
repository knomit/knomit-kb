# A guard whose violating population cannot be repaired must reject the NEW and grandfather the CARRIED — and the access constraint that forced this is what makes #132 compatible with #151

**The rule as built (#132, PR #166).** `refs.Gate.CheckBatch` rejects a NEWLY-ADDED ref whose classified path equals the fact's own path, and lets a CARRIED one through. The asymmetry is deliberate and is NOT the usual never-re-judge-the-past reasoning: that rule is about RESOLUTION, a claim about the corpus at a commit, whereas self-reference is a claim about the fact alone and is malformed at every commit. The reason here is ACCESS, not epistemics.

**Why.** Facts written before the fix carry a self-ref on disk, in BOTH stored forms — measured: `kb://d88770a51516/kb/technology/security/vulnerabilities/linux-kernel/69694fd7.md` canonical, and `kb/technology/cybersecurity/agentic-security/f1d14b64.md` bare, where it is the fact's ONLY ref. Those facts live in the `core` mount, which every session in reach mounts READ-ONLY, so they cannot be repaired from anywhere they can be read. Rejecting a carried self-ref would have made them UNEDITABLE — bricking records nobody can fix. Leaving them costs nothing: they are inert on read, because `localEvidenceRefs` drops the self-path before it reaches an evidence weight and the recursive lineage walks absorb it as a back-edge. That read-side drop is KEPT for exactly this reason.

**Correction (#280): the producer was NOT gone, and the exemption is how it got through.** When this was written, mcp.mergeFacts was believed to be the only producer of self-refs, and it had been fixed. There was a second one: synthesize.dedupMergeRefs, the review dedup merge, unioned the LOSER's refs onto the winner. When the loser cited the winner, the survivor cited itself (revision 106d32b3). The gate did not stop it, because dedupCluster passes the operands' refs as `prior`, and the self-ref WAS carried, by the loser. So this carried exemption does not only grandfather legacy rows; it also admits a NEW self-ref whenever a writer grafts another fact's refs onto a fact that other fact cites. dedupMergeRefs now filters the winner's own path by classified path, the way mergeFacts does. Both producers now filter their own output (see kb/incidents/synthesize/dedup/survivor-self-ref). The gate's check is defence in depth, not the guarantee: any NEW write path that unions refs from another fact must filter its own path itself.

**The payoff nobody predicted.** The grandfathering is what keeps #132 compatible with #151's discovery-reinforce path, which builds its write list from a fact's existing refs plus the cited seeds and passes a prior SNAPSHOT to the gate. When the target is a legacy carrier its self-ref arrives as CARRIED, so reinforce still works. Under the stricter rule reinforce would have failed outright on precisely the facts nobody can repair. Pinned by `TestGate_CarriedSelfRefPlusNewRef_ReinforceShape`, which asserts BOTH halves: carried-self-ref-plus-new-seed is accepted, AND an unresolvable new ref beside it is still rejected — so the grandfathering does not quietly weaken the real check.

**Consequence — do not tighten this as cleanup.** Rejecting carried self-refs is only safe once the legacy population is actually repaired, and that repair (#132b(3), deferred) is blocked on getting WRITE access to every mount holding one. Tighten the gate before then and reinforce breaks in the same move. The #280 lesson points the other way: since the gate cannot be tightened, every ref-unioning writer carries the filtering obligation.

**The generalisable half.** When a new invariant has an existing violating population, the REACHABILITY of that population is a design input, not an implementation detail: a guard that cannot be satisfied by the data it governs converts a cosmetic defect into an availability one. Ask who can write the violators before choosing between reject-all and reject-new. And when you choose reject-new, enumerate every producer before claiming the state has none: the exemption for carried violators is also an exemption for any writer that makes a violation LOOK carried.

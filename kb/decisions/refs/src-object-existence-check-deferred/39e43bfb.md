# Checking that a src:// ref's blob actually exists at its commit (issue #249 layer 2) is NOT being built for now — the user chose to move on after PR #282 closed the shape hole; if it is ever built, the recommended shape is a pre-check in the kb bridge (author's own checkout), with a missing commit meaning UNVERIFIED, never rejection

Context: issue #249 asked for two layers of src:// ref validation. Layer 1 (syntactic: a newly added src:// ref must be the full form src://<12 lowercase hex>/<path>@<40-hex>:<40-hex>) shipped in PR #282 (merged 2026-09-24, dev 08d9528b) at the single write chokepoint refs.Gate.CheckBatch, with carried refs exempt under historical-not-current; the issue was closed. Layer 2 (semantic: blob == `git rev-parse <commit>:<path>`) was deferred by #282 to a separate decision.

Options considered on 2026-09-24:
1. Pre-check in the kb bridge: it already runs in the author's checkout, can run `git rev-parse <commit>:<path>` before forwarding knomit_learn/knomit_update, needs no new server state, and keeps the "no source-repo registry, by design" gotcha intact. Estimated 150–250 lines including tests. RECOMMENDED if layer 2 is ever built.
2. Server-side registry mapping src repo ids (source root commits) to checkouts, read with go-git. Catches refs from any client but adds config and reverses the no-registry design. The server today has NO handle on source repos: LensRead.Source is a display-only slug and the object DB holds only fact blobs.
3. Only fix the stale doc comment in internal/fact/ref.go (~L294-296) that still says legacy src forms are accepted unconditionally (true of ValidateRefs, not of the gate).
4. Nothing. CHOSEN by the user.

Rationale: the hole that actually bit (a placeholder landing silently) is closed; what remains is a well-formed but invented 40-hex hash, which no shape check can catch, and the measured corpus has 51 of 1425 full-form refs citing commits absent from the local clone, so any future check must degrade to "unverified" rather than refuse. Not worth a PR now. Until then the compute-refs-never-recall methodology (git cat-file -e before writing) is the only existence check there is.

Non-scope: this does not reopen layer 1 or the carried-ref exemption, and it does not mean the semantic check is a bad idea — only that it is unscheduled. The stale comment in ref.go is still stale.

# Bug-fix workflow: main session orchestrates only; code/review/research go to subagents on the models the subagent tool exposes (inherit/pro/flash/flash_lite), not per-name model picks

Options considered:
1. Pick any model by name per subagent (e.g. Claude Sonnet 5.5, Opus, Gemini) — what the user first asked for.
2. Workaround: user switches the session's /model to Sonnet, orchestrator launches subagents with Model=inherit, user switches back. Unverified whether running subagents keep Sonnet after the switch-back; also requires user action per launch.
3. Use only the models the Antigravity invoke_subagent tool exposes: inherit (= the session model, Claude Opus), pro, flash, flash_lite.

Rationale: the invoke_subagent Model parameter is a fixed enum (inherit/pro/flash/flash_lite); it does not accept model names, even though the user's /model menu lists Claude Sonnet 5.5. Option 2 is fragile and pushes work back to the user. The user chose option 3 (2026-10-04).

Choice: the main session does reasoning, RCA synthesis, knomit recall/writes and orchestration only. Writing code, review, research go to subagents: research/exploration on flash (read-only research agents); fixes on inherit (Opus) or pro in an isolated/branched workspace; review on a DIFFERENT model than the one that wrote the fix; trivial jobs on flash/flash_lite. Per-ticket flow: pick ticket -> RCA -> show proposal -> user approves or rejects -> implement -> open PR against `dev`. The orchestrator recalls on behalf of subagents and puts findings in their brief; subagents report discoveries back and the orchestrator writes facts (into the PR's experiment).

Non-scope: this does not mean Sonnet is forbidden — if the user explicitly wants Sonnet for a task, the /model-switch workaround remains available on request. It describes the Antigravity CLI's subagent tool as of 2026-10-04; if the tool gains named-model selection, revisit.

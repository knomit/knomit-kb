# Facts carry an optional, ontology-declared `context:` map of short typed labels (F22) — chosen over a task id in the path, in entities or in the body; it describes the FACT, unlike #349's `trace`, which describes the commit

Options considered (F22, 2026-10-03) for finding facts by a property that is not their subject ("every verdict for task t-17"):
1. The property in the path (a per-task category with learn_dedup off). Works for ONE property; "every disagree verdict" needs a directory per question.
2. The property in `entities`. Entities name what a fact is ABOUT and feed learn's dedup and same-subject refusal; a task id there changes how learn treats the fact.
3. The property in the body. Not queryable, not typed, invisible to trigger `if`.
4. A typed per-fact map, declared per topic in `.knomit/ontology.yaml`.

The choice: 4, named `context` (user: "I don't want to call it 'fields' - 'context' I think it would be a better name for it"). Built in PR #413.

User rulings (2026-10-03, verbatim where quoted): "Yes on primitive types, and no lists." "Make sure the length is bound as well, no newlines, etc. We cannot have a key storing like multiline paragraphs." "Yes, everyone should see the context" (queries, rules, triggers, review, hypothesize, UI, OKF). A key not declared in the `context:` block of the fact's topic walk is refused on write. Update: absent keeps the map, an object replaces it whole, `{}` clears it. Merges: dedup keeps the winner's whole map, prune keeps only agreed keys and warns, distill/reflect/discovery inherit nothing, the F20 merge goes per key. OKF: `knomit_context` frontmatter plus a Context line in Related, round-tripped. Later the same day, on bidi formatting characters: "yes, context should refuse those characters."

NOT #349's `trace`: trace lives in commit trailers and describes the WRITE (this commit was made for task t-17); context lives in the frontmatter and describes the FACT (this verdict is about task t-17), survives updates and merges, and is queryable.

WHAT THIS DOES NOT MEAN: knomit never acts on a context value. It is data, never an instruction, and is never rendered into prompt instruction text. Automation keyed on a value is a trigger's job.

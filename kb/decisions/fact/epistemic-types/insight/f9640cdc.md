# insight is a GROUNDED epistemic type (10th); author-declared, treated as observed in the learn batch check

PR #70 (commit 5b28466) added `insight` as the 10th epistemic Type, ordered between Synthesis and Hypothesis in epistemic_type.go (Type constant, EpistemicTypes set, and the AllEpistemicTypes() stable ordering). Total Type leaves is now 12 (10 epistemic + 2 pragmatic).

SEMANTICS: a non-obvious GROUNDED conclusion drawn from connecting facts you already trust ("X and Y together imply Z"). It is GROUNDED — unlike `hypothesis`, which is an uncertain prediction. It is distinct from `synthesis`: synthesis is set AUTOMATICALLY by the synthesize pipeline from clustered source facts; insight is author/agent-DECLARED when manually connecting trusted facts.

LEARN-BATCH CLASSIFICATION (load-bearing): the knomit_learn observed-vs-inferred batch guard tests only `eType == fact.Hypothesis || eType == fact.Methodology` for the inferred bucket (learn.go ~line 104). Because insight is neither, it falls into the OBSERVED bucket — so a single learn call MAY mix insight with observation/concept/process/etc., but may NOT mix insight with hypothesis/methodology. This matches its grounded nature (see [[learn-batch-type-consistency]]).

AUTOCOMPLETE: PR #70 also changed searchIndex.Completions' `case "type"` (store/index.go) to derive the completion list from fact.AllEpistemicTypes()+fact.AllPragmaticTypes() instead of a hardcoded string slice. The old hardcoded list was a drift hazard — it would have silently omitted insight. Now any new Type added to the authoritative maps shows up in `type:` autocomplete automatically. See [[kind-and-type-taxonomy]].

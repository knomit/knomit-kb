# Pragmatic vs epistemic facts use a flat (kind, type) sum discriminator

Facts now distinguish descriptive (epistemic) from prescriptive (pragmatic) knowledge via a `kind` field (epistemic | pragmatic, default epistemic) paired with the existing `type` field (leaf taxonomy: 9 epistemic types + 2 pragmatic: policy, heuristic). Modeled as a FLAT (kind, type) pair, not a nested sum. Backward compatible: omit `kind` and you get today's semantics. SerializeFact emits `kind` only when pragmatic so existing on-disk files round-trip byte-identically. Kind.AllowsType(Type) is the SINGLE source of truth tying kind↔type. The Go EpistemicType was COLLAPSED into a single Type umbrella so existing call sites (synthesize/dedup.go, synthesize/decision.go) no longer need string casts — the strong-typing role the field had is now Kind.AllowsType at runtime, because validity depends on a sibling field that Go's type system alone can't express. Pragmatic facts have NO default type (policy and heuristic are not interchangeable).

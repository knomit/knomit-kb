# Everything under .knomit/ MUST remain READABLE by its exact path through the fact tools (any file type, raw content); only WRITES to .knomit/ are closed, and agents' writes to the root artifacts/ keep working

User ruling (2026-10-06, verbatim): "yes, reopen reads by path, writes MUST WORK for artifacts in the root still." and "do record a fucking fact that stuff under .knomit MUST REMAIN READABLE".

The rule:
- READ: any file under .knomit/ (ontology.yaml, trigger and recipe .js, skills, guidance, templates, job slots; any type) is readable through MCP by its EXACT path, read-only, returning its content. This is how agents reach system files and the playbooks repo's templates: facts in kb/ name the exact .knomit/ path and the agent reads it by that path.
- WRITE: .knomit/ stays closed to every fact tool (it changes through git only), as F25 decided.
- artifacts/<area>/... at the repo root stays writable by agents through the fact tools.
- .knomit/ stays out of the index, queries and listings: reachable by exact path only.

CODE STATE when written: F25 (#422, 74fa6cd3) closed .knomit/ to reads as well; that read closure is REVERSED by this ruling and must be undone in code. Until it is, a read by path of a .knomit/ file is refused on builds that include #422 (pre-#422 builds read .knomit/<area>/*.md job slots by path, but refuse non-fact files such as .knomit/ontology.yaml).

WHAT THIS DOES NOT MEAN: it does not make .knomit/ writable by agents, and it does not make .knomit/ files appear in knomit_query results or listings. It also does not mean the content must be copied into facts: a fact names the path; the file is read where it is.

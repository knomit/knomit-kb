# Any path segment beginning with '.' is private and excluded from fact DISCOVERY — enforced in four walkers and rejected at three creation sites, but deliberately NOT in store.validatePath

A KB repo accumulates directories that are machinery rather than knowledge — `.github/`, and now `.domains/`. They should be excluded by a stated rule rather than by each walker's incidental prefix test.

**Options considered.** (a) Any dot-prefixed segment — folder OR filename — private, skipped by every walker, AND rejected at the fact-creation boundary. (b) Same skip, but writes unchecked. (c) Dot-FOLDERS only, discovery-only, which is the literal original request.

**Rationale.** (a) won on two counts. Covering filenames as well as directories removes an asymmetry nobody would remember (`kb/architecture/.wip.md` would otherwise index as a fact). Rejecting on write prevents the worst available outcome: (b) would return 201/success for a fact that never appears in search — silent knowledge loss, and the hardest class of bug to trace to its cause. (c) was the smallest diff but left the filename asymmetry permanently.

**The choice.** `fact.IsPrivatePath(path) bool` — true when any `/`-separated segment begins with `.`. Consumed by: `store.isFactPath` (which covers the search indexer AND both Verify call sites), the OKF fact walk, the OKF history walks, and rejected at three fact-creation sites (`handlers_fact_create.go`, `mcp/learn.go`, `synthesize`'s `validateOutputPath`).

**Private means excluded from DISCOVERY, never from ACCESS.** knomit still reads specific known paths by name — that is precisely what lets it load `.domains/ontology.yaml`. The rule governs walking, never opening. A human may still place files under `kb/.drafts/` by hand and knomit respects them as a private stash; the rejection binds only knomit's own write path.

**The trap.** This check must NOT go into `store.validatePath`, which looks like the ideal chokepoint because all three write sites reach it. It also guards the writes for `README.md` and `.domains/ontology.yaml` — putting the private rule there breaks the boot-time ontology refresh.

**In the OKF exporter, order matters:** skip private paths BEFORE the `looksLikeFact` check, or every hand-placed draft is reported as lost knowledge on every export — a permanent false alarm that trains readers to ignore a real one.

**Relation to the ontology-root invariant.** This is still a LOCATION test, so it extends `kb/invariants/store/indexing/ontology-root-scope/1b35d56b.md` rather than competing with it: membership is decided by where a file sits, never by whether its bytes happen to parse.

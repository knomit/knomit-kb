# Ontology `guidance:` (F23) holds only PATHS (`guidance/<file>.md` under .knomit/) for two keys, hypothesize and review, on the root or any topic node; every problem is a warning on open and fatal for a new ontology; a refused value fails CLOSED (shadows the parent); a guidance-only difference blocks the preset refresh

User ruling (2026-10-03, verbatim): "F23) ok, let's just make sure that does not mean we pollute the ontology with 200 lines of text for each. If that's the case, I would actually prefer the guidance to be a path to the actual guidance text stored into a file under .knomit/guidance or something similar maybe", then "F23 approved". Also ruled: NO per-call `instructions` argument on any tool (task-body data would become instructions).

AS BUILT (PR #423, merge commit 3bb2c230 on dev; `internal/fact/guidance.go`):
- `guidance: {hypothesize: guidance/x.md, review: guidance/y.md}` on the ontology ROOT and/or any topic or child node. A value is relative to `.knomit/`, so `guidance/x.md` names `.knomit/guidance/x.md`. The ontology never holds the text.
- Path rule (`guidancePathProblem`), judged AS WRITTEN: one line, <= 256 bytes, no control char, no backslash, not absolute, no `..` segment, `path.Clean(v) == v`, starts `guidance/` with a file part. Inline multi-line text is refused as not a path.
- `GuidanceBlock` keeps the raw yaml node and its UnmarshalYAML NEVER errors (like TriggerList): a malformed block can never make the open path fatal. Every problem (not a mapping, unknown key such as `distill`, non-string value, bad path) is a `newOnly` warning: `ParseOntology` opens, `ParseNewOntology` refuses.
- Resolution: `GuidanceFor(topicPath, kind)` returns the ROOT's path first, then the nearest declaring node on Attr's walk (lowercased, stop at the first undeclared segment), deduplicated. A REFUSED value at a node resolves to NO file for that key and SHADOWS the parent (fail closed, after F22's poisoned-declaration rule) — a typo must not hand a topic its parent's policy. The root's path still shows.
- `Serialize` writes the raw block back (unknown keys preserved). `SubsetDivergence` reason `guidance` (root or node block differing): the boot preset refresh leaves such a stored ontology alone.
- Helpers added beside it: `ValidationsFor(topicPath)` (root + each declared node's validations on the walk, ValidateFact's order), `DeclaredTopic(topicPath)` (the declared prefix the walk resolves — the ONLY topic label a prompt may print), `GuidanceDeclarations()` (path -> declaring scopes).

WHAT THIS DOES NOT MEAN: a valid path does not mean the file is used — the file is read only at the consensus tip, and a missing or unusable file there is skipped (see the consensus-tip invariant). And an unknown key is ignored (warning), not treated as a bad value: it does not shadow anything.

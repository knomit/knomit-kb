# A trigger has THREE states: active, invalid (a problem: warning diagnostic, ERROR log once per name@blob, bookmark frozen) and unsupported (valid syntax this knomit version does not act on — do: script|push|run, or any `due` in `on` — not an error, no bookmark); invalidity is decided before support, and the node path is lowercased so an uppercase grandchild topic's triggers are not permanently invalid

internal/fact/triggers.go, F07 PR 1b's two fixes to the 1a gate notes (user ruling 2026-09-27, verbatim "1) ok, 2) need to fix 3) ok").

TriggerUnsupported = "unsupported". compileTrigger returns (compiled, unsupportedReason, err): every validity check runs FIRST (problem, name, on values known, do value known, script/recipe names, placeholders, glob, literal prefix, if compiles); only a VALID entry is then checked for support: `do` not in activeTriggerDo (only emit is active) or any `on` value not in activeTriggerOn (learn, update, retract — `due` waits for PR 2's sweep) makes the whole trigger unsupported with the reason text "… is not supported in this knomit version; the trigger waits for a version that implements it". So a `do: script` entry with a bad glob is `invalid` and the author still learns about the typo (TestTriggers_InvalidBeatsUnsupported). A trigger listing `on: [learn, due]` is unsupported AS A WHOLE in 1b (TestTriggers_DueIsUnsupported); PR 2 changes that.

What each state means downstream: invalid → triggerDiags warning in the editor, the dispatcher logs ERROR "invalid trigger skipped" once per (repo, name, blob) with the error verbatim (TestDispatch_ErrorLoggedOncePerBlob), the endpoint shows invalid/frozen, and the bookmark freezes (M3). unsupported → NO diagnostic, NO error log, endpoint state `unsupported` with the reason, NO bookmark (deleted if one exists), so when a later version activates it it starts at the head of that advance and never back-fills (TestDispatch_UnsupportedNoBackfill). TriggerState now also carries Match/On/Do as written so the endpoint can show a trigger that did not compile. TriggerSet.Declared holds every name in every state.

The lowercase fix: collectTriggers lowercases each node-path segment (strings.ToLower on topic and child keys). Topic and first-level child keys are forced lowercase by the ontology diagnostics, but deeper keys are not validated, and an uppercase grandchild (tasks/research/Deep) yielded an uppercase Node that the lowercased glob's literal prefix could never start with — every trigger under such a node was permanently invalid ("match leaves its topic"). TestTriggers_UppercaseGrandchildNodeIsActive pins it. This supersedes the 1a facts' wording that reserved do values are `invalid`.

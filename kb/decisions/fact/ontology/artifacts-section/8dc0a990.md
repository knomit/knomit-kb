# The ontology's top-level `artifacts:` section declares rules for files under artifacts/ by pattern (relative to artifacts/, trigger glob syntax, ASCII case-insensitive): change write-once|append-only|replace, replace_when crl-newer|leaf-renewal, revoked_set superset, pki root|crl|leaf|issuance|revocation, max_size. Unknown key = warning on open, fatal on create; bad value or inconsistent block = FATAL everywhere (R7)

Why a new section: topic attributes cannot reach artifacts/ (the topic walk is kb/-only). Code: internal/domain/fact/artifact_rules.go; compiled in ValidateOntologyYAML; resolved by Ontology.ArtifactAttrs(repoPath) and Ontology.PKILayout().

OPTIONS (user ruling R7, option i): (1) hardcode artifacts/fleet/... paths and rules in the judge and the fleet reader, as the first P3 draft did: REJECTED, because the trust-file policy is repository policy and a hardcoded path is a second place that must agree with the template; (2) ontology-declared rules enforced by a fixed set of Go primitives: CHOSEN, the ontology says WHICH file gets WHICH primitive, Go decides what a primitive does, so a repository cannot invent a check (and members cannot strip the rules, since the ontology lives under .knomit/, which push and merge refuse to change). Every key has a closed value set because a security rule must have a closed meaning. No hardcoded artifacts/fleet path may remain in the judge or the reader.

COMBINATION: max_size = the SMALLEST of all matching patterns; pki, and change with replace_when and revoked_set, come from the MOST SPECIFIC matching pattern that declares them (fewer ** segments, then fewer wildcard segments, then more segments); two equally specific matches that disagree -> ArtifactAttrs error -> the judge refuses (artifact-rules), never guesses.

CONSISTENCY (fatal): replace needs replace_when and vice versa; crl-newer needs pki: crl, leaf-renewal pki: leaf; revoked_set needs pki: crl; pki: root, issuance and revocation need write-once; pki: crl/leaf need their replace rule; root and crl patterns are literal; a leaf pattern is literal except one '*' in its last segment (the id); one root, one crl, one leaf pattern; crl/leaf/issuance/revocation need a root. Every key has a CLOSED value set. revoked_set is a NEW KEY rather than a new crl-newer value (closed-value rule, fd8a7cec).

THE FLEET PRESET: verify_signatures: enforce plus fleet/root.crt {pki root, write-once, 16KiB}, fleet/crl.pem {pki crl, replace, crl-newer, revoked_set superset, NO max_size}, fleet/certs/*.pem {pki leaf, replace, leaf-renewal, 16KiB}, fleet/issued/*.pem {pki issuance, write-once, 16KiB}, fleet/revocations/*.txt {pki revocation, write-once, 4KiB}. There is no fleet/** catch-all and no ledger (issued.jsonl/revoked.jsonl are gone). Its comment documents the setup order: root.crt and crl.pem FIRST, members after. The preset text is the knomit-playbooks fleet template byte for byte.

RULE FOR CAPS: never declare max_size on a file that grows without bound. The CRL grows with every revocation and can never shrink under revoked_set: superset, so a cap would turn a legitimate revocation into a permanent refusal (review F3, the 16KiB ledger ceiling). A family pattern such as fleet/** (a max_size for everything beneath) is allowed and is not a file declaration: see the artifact-not-a-file rule in the judge fact. Serialize writes the section back (unknown keys kept).

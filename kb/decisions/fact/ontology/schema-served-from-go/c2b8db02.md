# The ontology's field list is served from Go with a reflection test — a hand-maintained TypeScript copy is the version of the editor-completions feature that was REJECTED

# The choice

The create wizard's ontology editor (CodeMirror 6) offers completions for the ontology's YAML field names. Those names come from `GET /api/v1/ontologies/schema`, backed by `fact.OntologySchema()` — **11 entries across 3 structs**: `Ontology`{id,name,description,topics,validations}, `OntologyNode`{description,children,validations}, `Validation`{name,message,rule}.

`TestOntologySchema_CoversEveryYAMLTag` reflects over those three structs and fails if any exported `yaml:`-tagged field is missing from the served list. **That test is a CONDITION of the decision, not a nicety.**

# Rationale, including the reasoning that was wrong

The first recommendation was to skip completions entirely, on the grounds that a client-side schema is a second source of truth that will drift. That was wrong here for two measured reasons:

- **The shape is tiny** — 11 names, not 200. "It will drift" is a fair worry about a large schema and a weak one about eleven strings.
- **The expensive work is shared.** Multi-error collection and `yaml.Node` line positions inside the parser are needed whether or not there are completions. Charging that to the plain-editor option and then charging the editor option for CodeMirror on top made the last rung look like the tall one when it was the shortest.

The decisive argument for the editor at all: YAML is indentation-sensitive and a bare `<textarea>` gives Tab to focus, not to indent — so the plain-textarea option lacked the one affordance the format most needs.

# The trap this guards

A drifted completion list is WORSE than no completions: it teaches confidently wrong field names. The reflection test turns that drift into a build failure instead of a silent lie. Inlining the field list in TypeScript to "save a request" reintroduces exactly the failure mode.

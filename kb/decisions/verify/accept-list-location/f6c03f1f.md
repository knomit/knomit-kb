# F09's accept list is per INSTANCE in control.db (verify_accepted, control migration 000012), not in each repo's database — because E4 refuses during a clone, before the repo DB exists, and a failed create discards it

DECISION (user ruling on F09 PR 4): the operator's accept list lives in control.db, one per instance, as table `verify_accepted(commit_hash PK, repo_uid NULLABLE, note, accepted_at)` (control migration 000012). repos.VerifyAccepts owns it. Each Service gets it as a store.AcceptList bound to its repo uid (builder, SwapStore's rewire, the lifecycle stores, the origin wizard's clone store), beside the root of trust. A NULL repo_uid applies to that commit in ANY repository; commit hashes are content-addressed, so a global waiver by hash is precise.

OPTIONS CONSIDERED:
- (a, chosen) Instance-level list in control.db. `knomit verify accept <commit>` works before any clone exists and survives SwapStore and repo re-create.
- (b, rejected) Keep PR 3's repo-DB table for the steady-state fold and add CreateSpec.Accept to carry hashes into a create. It needs a CLI/UI path into create that the wizard lacks, and the list dies with a SwapStore.

WHY: E4 (the clone-time own-lineage check) refuses DURING a create, when the repository's database is brand new, and a failed create discards it. E4's remedy is 'accept the commits, clone again', so the accept must live somewhere that exists before the repository does.

CONSEQUENCES:
- The fold reads ONLY this list (repoHandler.acceptList). The repo-database table verify_accepted from repo migration 000027 is never read or written: migrations are immutable so it stays, empty, and TestRepoVerifyAcceptedTableIsNeverUsed guards that no non-test store source uses it.
- SCOPE of an accept (unchanged, enforced by the fold): it waives a failing signature on one commit, or an unsigned merge failing M3. Never an unaccepted parent, a policy change or an author claim. `knomit verify accept --repo` refuses at accept time when the dry run already shows the commit as a policy change or an author claim (repos.CheckWaivable); without --repo it cannot check and says so.
- `knomit verify report` lists the accept entries that matched commits in the history, with their scope.
- E4's ForeignLineageError prints a ready `knomit verify accept <full hash>` line per refused commit.

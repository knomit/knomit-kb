# Release knomit under FSL-1.1-ALv2 with commercial exceptions for competing use

knomit is licensed under the Functional Source License FSL-1.1-ALv2 (source-available, each release auto-converts to Apache 2.0 two years after publication). The copyright holder / licensing entity is **Knomit LLC**. The project is hosted at **github.com/knomit/knomit**.

**Goal driving the choice:** maximize adoption while preventing others from cloning knomit and running it for profit. The owner is fine with anyone — including commercial entities — using knomit internally for free; payment is only expected when someone monetizes it competitively.

**Options considered:**
- BSL 1.1 — rejected: its native restriction gates ALL production use (including internal commercial use), which contradicts the goal of free internal use. Would require a custom Additional Use Grant to re-permit internal use, effectively rebuilding a competing-use license with clunkier boilerplate plus a mandatory time-bomb.
- Elastic License v2 — rejected: its restriction is hosting-as-a-service only (narrow); a non-hosted commercial clone could slip through.
- PolyForm Shield — viable sibling of FSL (competing-use bar, but no time conversion); rejected in favor of FSL because the owner valued the adoption/trust signal of eventual open source.
- FSL-1.1-ALv2 — CHOSEN: restricts only Competing Use (offering knomit, or a substantially similar substitute, to others as a commercial product/service); explicitly permits internal use (even commercial), non-commercial education/research, and professional services. Auto-converts to Apache 2.0 after 2 years.

**Key clarifications captured during the decision:**
- FSL gates COMPETING use, not commercial use. Internal commercial use is free — do not describe the license as 'commercial requires a license'.
- Dual-licensing as user-pickable FSL-OR-Apache would defeat the purpose (most-permissive option always wins). The correct dual model is FSL (public default) + a privately-sold commercial/proprietary license for competing use. Apache is already present as FSL's 2-year Change License, not a second public option.
- Open-core (permissive client + restricted server) was considered but is N/A: knomit is a single binary.

**Distribution consequence:** FSL is not OSI-approved, so knomit cannot go into homebrew-core. Install path is a personal Homebrew tap (`knomit/homebrew-tap` → `brew tap knomit/tap`), shipping prebuilt binaries because the CGO build pulls native libs (ONNX Runtime, graphqlite).

**Artifacts, and where they actually live:** `LICENSE` (FSL-1.1-ALv2, Copyright 2026 Knomit LLC), `COMMERCIAL-LICENSE.md` (contact k@knomit.io, licenses offered by Knomit LLC), and a trimmed `README.md` pointing to knomit.io/docs with a WIP/no-guarantees caveat — all three present in this repo and verified at commit 4baae4ed.

**WHAT THIS DOES NOT MEAN.** *Not* "there is a `packaging/homebrew/` directory in this repo." There is no `packaging/` directory at all, and no commit in this repo's history ever added or deleted `packaging/homebrew/knomit.rb` — the tap's formula and README belong to the SEPARATE `knomit/homebrew-tap` repository, which is the whole point of a personal tap. Do not cite them as paths in this repo.

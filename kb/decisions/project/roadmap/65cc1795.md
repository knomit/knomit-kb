# knomit refines ANY knowledge; roadmap designs are ontology-neutral with three domain plug points

knomit is a knowledge refinery for any knowledge — AI trends, cybersecurity incidents, markets, people — not only code. The user set this explicitly (2026-07-04) after the .claude/future roadmap read as code-specific, and the roadmap was reworked accordingly.

Design rule for all roadmap/proposal work: designs are specified against a domain-blind neutral core (facts-as-IR, anchor graph, graph analyses, dataflow passes, entailment oracle, lifecycle state); code examples are examples, not requirements. Domain enters at exactly three plug points:

1. Anchor recognizers — what counts as an identifier-class token (backtick spans for code; CVE IDs, arXiv IDs, model names, tickers elsewhere) is per-ontology configuration.
2. Source resolvers with verifiability tiers — Tier 1 versioned+diffable (git sources: pins are commits, drift ships the exact diff, change events free via hooks); Tier 2 fetchable+archivable (URLs/feeds: snapshot pins, polled/subscribed events); Tier 3 attested (age and contradiction only). Tier is a property of the ref-target node; detectors tier-weight, never assume Tier 1.
3. Relation and observable vocabularies — the relation-extraction predicate set and settlement observable kinds are designer-owned per-ontology artifacts.

Every proposal in .claude/future carries a '## Value' section tagged 'ontology: generic' or 'ontology: code'. Genuine code-only advantages (e.g. free commit-hook change events for invalidation, exact-diff drift payloads) stay in the roadmap but must be tagged, with the tiered generic mechanism designed in. knomit-bench must include at least one non-code fixture corpus so domain transfer is scored, not assumed.

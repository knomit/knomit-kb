# Decided (user, 2026-10-02; PR #393): ONE variable, KNOMIT_SERVER, names the server for everything `kb` does (argument > KNOMIT_SERVER > lockfile > localhost:19278; http(s)://, unix://, npipe://; a named address used exactly as given); the server sets it for its recipe children and exec waits for it rather than start a child without it; rejected a KNOMIT_BASE_URL alias, KNOMIT_HOME choosing the server, ports in recipes, and stripping an inherited value instead of waiting

CONTEXT: first-mission rehearsal, 2026-10-02 — `KNOMIT_HOME=<rehearsal home> kb --repo X` reached the MAIN instance (kb/incidents/bridge/server-address/knomit-home-did-not-choose).

USER, VERBATIM:
1. "ok. we obviously need this to be fixed. how about this: - change KNOMIT_BASE_URL to KNOMIT_SERVER; default as now - accept a command line argument which will override that - use KNOMIT_SERVER as the base (proto://host:port) for the API calls"
2. "4. the KNOMIT_SERVER itself can point to the unix socket, can't it ? 5. No compabitility, nothing shipped yet. Rip and replace. Agreed on the addition, and it can set it the unix socket it if wants to. Leave out: agreed."
3. "go ahead"

CHOSEN: KNOMIT_SERVER for the MCP role and the hooks alike; precedence argument > KNOMIT_SERVER > desktop lockfile > http://localhost:19278; forms http(s)://host:port, unix:///abs/path.sock, npipe:////./pipe/<name> (Windows); a malformed value fails naming its source; a NAMED address is used exactly as given (a named socket never falls back, a named http address is never rerouted onto the socket); only the default path keeps 'local socket first'. The server records its own address once its listeners bind (local socket only if it bound, else TCP) and gives it to recipe exec children as KNOMIT_SERVER; the recipe's exec env may override it. KNOMIT_HOME keeps its meaning (the instance's folder).

REJECTED:
- Keeping KNOMIT_BASE_URL as an alias — 'No compabitility, nothing shipped yet. Rip and replace.' Two names would be two ways to name the server; an archtest now fails on any file naming the old one.
- KNOMIT_HOME choosing the server — it is the instance's folder; tying the address to it was the wrong belief the incident came from, and the socket path is not even derivable from it (KNOMIT_SOCKET, toml socket, the long-home /tmp fallback).
- Ports (or addresses) written into recipes / the mission template's MCP config — the server knows its own address and passes it in the environment, which Claude Code hands to its stdio MCP servers (measured, 2.1.287).
- Stripping an inherited KNOMIT_SERVER and starting the child anyway during the boot window (the PR's first version) — review F1: the child's kb would then reach the lockfile's server. Coordinator's call: the exec host WAITS (bounded) for the address and otherwise fails the run recipe-error ('server address not ready'); the dispatcher's start-up stays unchanged, and delaying the dispatcher was not taken.

# Slow-request WARN carries request/route/client detail plus the MCP tool name; the fields stay OUT of the metrics counter

The slow-request WARN in `metricsMiddleware` used to emit only route/method/status/elapsed, which made every slow MCP call (`POST /api/v1/repos/{repo}/branches/{branch}/mcp`) an identical, undiagnosable line. Decided 2026-08-12 to widen it.

**Options considered**

For the added fields: (a) request identity — concrete path, raw query, chi request id; (b) route params — repo/branch/lens pulled from chi URLParams; (c) client identity — RemoteAddr, User-Agent, Mcp-Session-Id; (d) response size + Content-Type. For the MCP tool name: plumb it through a mutable context annotation filled by an mcp-go `BeforeCallTool` hook, versus keeping the change confined to the HTTP layer and accepting that slow MCP calls stay indistinguishable.

**The choice**

(a) + (b) + (c), and yes to plumbing the MCP tool name. Response size / Content-Type were dropped — the point is identifying WHICH request was slow, not characterising its payload. Every added field is omitted when empty, so a plain `GET /repos` line stays short.

The tool name travels via a new leaf package `internal/obs/reqinfo`: the HTTP middleware puts a mutable `*Info` in the request context before calling the handler, and `internal/mcp`'s `BeforeCallTool` hook sets the tool name on it. This works because mcp-go's streamable HTTP server derives tool-call contexts from `r.Context()` (`server/streamable_http.go:420`). `reqinfo` lives under `internal/obs/` alongside crashdump/metrics so both `web` and `mcp` can import it — `web` imports `mcp`, and `mcp` must never import `web`. `FromContext` is nil-safe so stdio and test paths that carry no `Info` are unaffected.

`middleware.RequestID` was added to the API router at the same time; it was not registered before, so `req_id` would otherwise always have been empty.

**Rationale**

Diagnosing a slow request needs the identity of the request, not a bigger aggregate. Logs are the right home for high-cardinality identity; metrics are not.

**Non-scope**

This does NOT authorise adding any of these fields as labels on `knomit_http_requests_total` — that counter keeps its three bounded labels (route pattern, method, status) precisely so repo/fact/tool cardinality cannot blow up the series count. The decision is log-only. It also does not change the streaming exclusion: `text/event-stream` responses are still never reported as slow.

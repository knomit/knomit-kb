# Logging defaults to stdout/stderr; app-managed file rotation is opt-in (containers must log to stdout)

**The choice:** The binary never writes a log file unless explicitly told to. `[log].format` is `console` (human, stderr) by default or `json` (structured); `[log].file` is empty by default and, when set, adds a rotating lumberjack JSON sink (now `Compress: true`). Level via `[log].level` (validated at boot) with a live runtime toggle at `/runtime/loglevel`.

**Options considered:** default file-logging on (my initial proposal) vs. default stdout with file opt-in.

**Rationale:** Containers MUST log to stdout so the Docker/orchestrator log driver captures and rotates them — an in-container file sink is an anti-pattern. So the Docker image just sets `KNOMIT_LOG_FORMAT=json` and writes no file; only a non-container/systemd/bare central box opts into `KNOMIT_LOG_FILE` for app-managed rotation. The same stdout-not-file principle applies to the crash file (`KNOMIT_CRASH_LOG`): off in containers. Logging is assembled by the unit-tested `cmd.buildLogger`; serve loads config first, then builds the logger (CLI `--log-*` flags override config), tee'ing through the `crashdump` ring buffer so crash bundles keep a recent-log tail.

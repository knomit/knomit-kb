# Logging defaults to stdout/stderr; app-managed file rotation is opt-in (containers must log to stdout)

**The choice:** The binary never writes a log file unless explicitly told to. `[log].format` is `console` (human, stderr) by default or `json` (structured); `[log].file` is empty by default and, when set, adds a rotating lumberjack JSON sink (`Compress: true`). Level via `[log].level` (validated at boot) with a live runtime toggle at `/runtime/loglevel`.

**Options considered:** default file-logging on (initial proposal) vs. default stdout with file opt-in.

**Rationale:** Containers MUST log to stdout so the Docker/orchestrator log driver captures and rotates them — an in-container file sink is an anti-pattern. So the Docker image just sets `KNOMIT_LOG_FORMAT=json` and writes no file; only a non-container/systemd/bare central box opts into `KNOMIT_LOG_FILE` for app-managed rotation. The same stdout-not-file principle applies to the crash file (`KNOMIT_CRASH_LOG`): off in containers.

**Where it lives (as of commit 4baae4ed):** logging is assembled by `internal/obs/logging` — `logging.Build(lc, consoleOut, jsonOut, ring)` and `logging.BuildWriter(...)`. `serve` loads config first, then builds the logger (CLI `--log-*` flags override config), tee'ing through the `internal/obs/crashdump` ring buffer so crash bundles keep a recent-log tail.

**WHAT THIS DOES NOT MEAN.** *Not* "the entry point is `cmd.buildLogger`" — that symbol no longer exists; the logic moved out of `cmd/logging.go` into the `internal/obs/logging` package, where it is unit-tested independently of cobra. Grep for `logging.Build`.

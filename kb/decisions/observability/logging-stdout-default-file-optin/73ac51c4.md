# Logging defaults to stdout/stderr; app-managed file rotation is opt-in (containers must log to stdout)

**The choice:** The binary never writes a log file unless explicitly told to. `[log].format` is `console` (human, stderr) by default or `json` (structured); `[log].file` is empty by default and, when set, adds a rotating lumberjack JSON sink (`Compress: true`). Level via `[log].level` (validated at boot) with a live runtime toggle at `/runtime/loglevel`.

**Options considered:** default file-logging on (initial proposal) vs. default stdout with file opt-in.

**Rationale:** Containers MUST log to stdout so the Docker/orchestrator log driver captures and rotates them — an in-container file sink is an anti-pattern. So the Docker image just sets `KNOMIT_LOG_FORMAT=json` and writes no file; only a non-container/systemd/bare central box opts into `KNOMIT_LOG_FILE` for app-managed rotation. The same stdout-not-file principle applies to the crash file (`KNOMIT_CRASH_LOG`): off in containers.

**Where it lives (as of commit b0603592, PR #191):** logging is assembled by `internal/platform/logging` — `logging.Build(o logging.Options, consoleOut, jsonOut, ring)` and `logging.BuildWriter(...)`. `Options` is a struct OWNED BY logging (Format, Level, File, MaxSizeMB, MaxBackups, MaxAgeDays); the sink no longer takes `config.LogConfig`. The one conversion from the operator-facing config is `app.LoggingOptions(cfg.Log)` in `internal/app/logging.go`, and BOTH binaries that build a logger call it: `serve` (loads config first, then builds the logger; CLI `--log-*` flags override config) and `tools/desktop`'s `applyLogConfig` (which rebuilds the sink on every Settings save, and is compiled only under the `desktop` build tag). Both tee through the `internal/platform/crashdump` ring buffer so crash bundles keep a recent-log tail.

Why the inversion: `internal/platform/` is the process tier and `TestPlatformKnowsNothingAboutKnomit` (test/archtest) fails on any import of a knomit package from inside it, so logging cannot see `config`. The converter is in `app` rather than as a method on `config.LogConfig` because config importing logging would drag lumberjack, gzip and crc32 into config's closure, and config is imported almost everywhere. `Options` is deliberately a SUBSET of `LogConfig`: `SlowRequestMS` and `CrashFile` are read by the HTTP middleware and by crashdump, never by the logger, and listing them would imply they were wired here.

**WHAT THIS DOES NOT MEAN.**
- *Not* "the entry point is `cmd.buildLogger`" — that symbol no longer exists; the logic moved out of `cmd/logging.go` into the logging package, where it is unit-tested independently of cobra. Grep for `logging.Build`.
- *Not* "`logging.Build` takes a `config.LogConfig`" — it did until PR #191. A new `[log]` rotation key must be added in THREE places: `config.LogConfig`, `logging.Options`, and the field copy in `app.LoggingOptions`. Nothing enforces the third; forgetting it means the key parses, validates, and is silently dropped before it reaches the sink, in both binaries at once.

UPDATE (PR #503, merge 8be999a0, 2026-10-12): the desktop no longer builds the SERVER's logger. The server (`knomit serve --supervised --log-file <path>`) owns the server log: `[log] file` when set, else `<logs dir>/knomit.log`, and the desktop passes that path with --log-file. The desktop's own shell log (supervisor, UI proxy, tray) is ALWAYS the sibling `knomit-desktop.log` (tools/desktop/logging.go applyLogConfig), never the server's file - two processes must not rotate one lumberjack file (each would rotate on its own size count and rename the file under the other), and TestApplyLogConfigNeverWritesTheServersFile pins that the desktop never opens the server's file. The desktop's crash-dump tap on the logger is gone. app.LoggingOptions is therefore no longer called by the desktop: the desktop keeps its own `desktopLoggingOptions` COPY because internal/app is forbidden in its link closure (kb/invariants/desktop/links-no-server), and a parity test (tools/desktop/logging_parity_test.go, built `desktop && !windows`) fails when the two converters drift - so the 'THREE places' rule above still applies, and the parity test is what catches a forgotten desktopLoggingOptions field. Where the text above says 'BOTH binaries that build a logger call app.LoggingOptions' read: serve calls it, the desktop mirrors it.

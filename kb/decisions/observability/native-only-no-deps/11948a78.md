# Production observability is built-in and native-stdlib-only; no 3rd-party deps or external supervisors

**The choice:** All production observability (crash dumps, logging, live introspection, metrics) is delivered inside the binary using only the Go stdlib (`runtime`, `runtime/debug`, `runtime/pprof`, `net/http/pprof`, `expvar`, `os/signal`, `syscall`) plus already-vendored `zerolog`/`lumberjack`. No new dependencies; no reliance on a deployed third-party tool.

**Options considered:** (a) pull in `prometheus/client_golang` for metrics + rely on systemd/Docker watchdog, journald rotation, and `coredumpctl`; (b) build everything native and leave watchdog/restart/probe-contract to whoever operates the box.

**Rationale:** The deployment target is a central long-running instance; the owner wants capabilities that work regardless of how/where it's run, with zero steady-state cost. Operators who want a watchdog/Prometheus server/core limits are welcome to add them, but the binary must not *require* them. `prometheus/client_golang` (protobuf + transitive deps, binary bloat) was rejected — `/metrics` is rendered as Prometheus text by a hand-rolled dep-free registry instead. Health-probe contract and request correlation IDs were explicitly dropped as out of scope.

**Architecture (paths as of commit b0603592, PR #191).** The observability packages live under `internal/platform/`, the process tier: `internal/platform/crashdump` (post-mortem), `internal/platform/diag` (the live surface), `internal/platform/metrics` (the registry), plus `internal/platform/logging` and `internal/platform/reqinfo`. They sit beside `platform/memlimit` and `platform/version` because they share the tier's one property — they know the OS and the binary and nothing about knomit — which `TestPlatformKnowsNothingAboutKnomit` in `test/archtest` enforces: no package under `internal/platform/` may import a knomit package outside the tier. The live surface is a SINGLE optional `http.ServeMux` listener bound to a localhost addr via `cfg.Runtime.Addr` — TOML `[runtime] addr`, env `KNOMIT_RUNTIME_ADDR` — OFF unless set, carrying `/runtime/*` controls + `/debug/pprof/*` + `/debug/vars` + `/metrics`. pprof is mounted ONLY on this gated port (not `http.DefaultServeMux`). Block/mutex profiling stay off and are runtime-toggleable via `/runtime/profile/{block,mutex}` so their continuous cost is paid only during an incident; heap sampling already runs in every Go binary, so enabling the endpoints adds ~zero steady-state cost.

**WHAT THIS DOES NOT MEAN.**

- *Not* "`KNOMIT_PPROF_ADDR` still works as a deprecated alias." It does NOT exist at HEAD — `internal/config/config.go` reads `KNOMIT_RUNTIME_ADDR` and nothing else for this setting, so setting the old name turns the diagnostics port silently OFF rather than erroring.
- *Not* "the packages are `internal/crashdump` and `internal/runtimeobs`", and *not* "they are under `internal/obs/`" either. The history is top-level → `internal/obs/` (PR #107) → `internal/platform/` (PR #191); `internal/obs` no longer exists. Grep for `internal/platform/`.
- *Not* "a platform package may read `config.RuntimeConfig` itself." `diag` takes its address from cmd; the config edge stays in the caller, because the archtest fails on any import of `internal/config` from inside the tier.
- *Not* "the diagnostics port is on by default." It is off unless `Addr` is set, and it is meant for a local address only — it never faces the network.

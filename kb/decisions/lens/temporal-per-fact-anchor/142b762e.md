# Lens browsing has NO lens-wide temporal anchor — time travel stays per-fact, anchored on the open fact's source mount

**Options considered:** (1) disable at:/vs:/scrub in lens context; (2) anchor the global asOf to the write repo's timeline (in three sub-variants: mixed-time union, union-collapses-to-write-repo, write-repo-as-clock with per-mount timestamp resolution); (3) keep the spec's per-fact rule only.

**Rationale:** inspection of the actual UI dissolved the question — state.asOf is global *state* but drives only the open fact: when off-live, LeftPanel hides the Library entirely and shows TimelineNav (which requires state.factPath), RightPanel re-reads the open fact at the anchor, and the Library/search/tree are HEAD-only always. There is no "browse the repo as of T" surface even in single-repo mode, so a lens-wide anchor would be answering a question the UI never asks. The write-repo-anchor variants were therefore not needed; the mixed-time variant was additionally ruled out because first-mount-wins dedupe would make facts silently appear/disappear while scrubbing.

**The choice:** per-fact anchoring, exactly as the design handoff states: in a lens context the open fact carries its source (repo, branch), and TimelineNav / EdgesRail / useTimeTravel / RightPanel anchor on that mount instead of state.repo/state.branch. Typed at:/vs: tokens resolve against the open fact's mount (same as scrubbing) and warn when no fact is open. isReadOnly = serverReadOnly || !isLive is unchanged and composes with the lens write rule (editable only when the fact's source mount IS the write repo and the view is live).

**Non-scope:** this does not preclude a future honest union-as-of-T (per-mount timestamp resolution via an at= param on the lens read endpoints); it records that v1 ships without any lens-wide anchor.

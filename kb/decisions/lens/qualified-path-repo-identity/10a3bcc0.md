# Lens facts use ONE canonical form everywhere — kb://<root-commit-hash>/path on REST and MCP; the API is faithful, name mapping is UI-only

**Options considered:** (a) extra `repo` argument on MCP tools; (b) attribution as a side-channel metadata field with unqualified paths; (c) qualified paths with repo names; (d) dual-form: repo-name-qualified paths on the wire, kb://<id> refs at rest, server translating at the boundary (revision 2); (e) one canonical kb://<repo-id> form everywhere, no server-side mapping — faithful API.

**Rationale:** A repo argument reintroduces argument-value misrouting; a metadata field doesn't survive copy-paste; names in durable content break on rename and differ across machines. The root commit hash (`init: create knowledge base` commit, store.InitRepo) is clone-stable, rename-safe, collision-free, and needs zero migration. Option (d) — server-side name↔ID translation — was briefly chosen, then rejected by user ruling 2026-07-16: hidden rewriting makes the API unreliable (the same fact renders differently per machine and per binding), callers cannot trust payloads as stable identifiers, and they end up maintaining the mapping themselves anyway.

**The choice:** Repo ID = root commit hash (RepoInstance.ID(), 12-hex display). ONE form everywhere on REST and MCP: read-mount facts are `kb://<repo-id-12>/kb/...` in query results, tool arguments, AND refs stored inside facts; unqualified paths = the write repo ("current directory"); lens-of-one stays unqualified byte-for-byte. The server NEVER maps IDs to repo names in API payloads — refs are returned exactly as stored. Friendly names are presentation: the UI maps ID→name (repo REST resources expose `id`); agents get the mount table (name, ID, branch, source) via AfterInitialize instructions and knomit_repos. Tools route kb:// paths via Binding.byID; update/retract on a non-write ID → read-only error; unmounted ID → not-mounted error.

**Non-scope:** Does not authorize semantic cross-repo lineage machinery (walking kb:// refs) — only the syntax ships in v1. Error MESSAGES may name repos (prose, not addressing). The lens registry still stores repo names (machine-local config; Manager updates on rename).

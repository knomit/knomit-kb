# No write-time coherence gate on learn — embedding similarity cannot distinguish misroutes from novel knowledge

**Options considered:** (a) warn-only coherence gate on learn (RFC revision 1: embed the fact, search the write repo's corpus, warn below EmbedderThresholds.SimilarTo); (b) hard-reject gate; (c) no gate, with review-time misplacement detection deferred.

**Rationale:** The gate's signal is confounded at its core: genuinely NEW knowledge also has low similarity to the existing corpus — that is what makes it worth writing down. The most valuable learns look exactly like misroutes, so precision is poor, the warning becomes noise, agents learn to ignore it, and an ignored warning is worse than none. The real guards against misrouted writes already exist: the write repo is chosen deliberately and once (at lens definition, by a human), and AfterInitialize states what the write repo is for (ontology, profile, kb.md description). The RFC's original pseudocode was additionally scoped to the fact's category dir, which would warn on every first fact in any new category.

**The choice:** No coherence gate in v1. Category-scoped DEDUP on learn is unaffected and stays (different job). "Does this fact belong elsewhere in the lens" detection is deferred to review-time (knomit_review pipeline), which has LLM judgment and can actually MOVE a misplaced fact.

**Non-scope:** This does not reject review-time misplacement detection — it relocates the concern; it is listed as deferred work in the RFC.

**Non-scope (added 2026-09-14, PR #187): this decision does NOT forbid the same-subject refusal that learn now performs.** The two are opposites in the signal they read, which is the whole reason this decision's argument does not reach the new gate:

- THIS decision rejects refusing on LOW similarity. That signal is confounded because novel knowledge and a misroute look alike, and the question it tried to answer was "does this fact belong in this repo/category?".
- The same-subject gate refuses on HIGH similarity — a band of `(ReflectNovelty, Dedup)`, ABOVE the recall floor and BELOW the auto-merge floor — and additionally requires a shared NON-GENERIC entity. The question it answers is "is this the same subject as a fact already here?", which is the dedup question this decision explicitly kept ("category-scoped DEDUP on learn is unaffected and stays — different job"). The new gate is that same job widened from the category directory to the whole branch, which is what let two sessions file one event under two categories without ever colliding.

The entity anchor is the direct answer to the confound named above: text similarity alone is not trusted to refuse anything, so an anchor that similarity cannot fake is required alongside it.

The warning this decision feared — ignorable, so ignored — is still the live risk on the new gate, in the shape of `distinct_from` becoming a reflex. That is why every refusal AND every bypass emits a structured log event carrying the band and model in force, so the rate is measurable rather than assumed.

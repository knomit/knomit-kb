# Lens browsing UI reads through real lens REST endpoints — the client fan-out stopgap is rejected, not deferred

**Options considered:** (A) add lens-scoped REST read routes — `GET /api/v1/lenses/{lens}/facts`, `/search`, `/completions`, `/facts/{path}` — behind LensMiddleware, reusing the union machinery already built for MCP (readTargetsFor fan-out, RRF search fusion, recency merge, first-mount-wins dedupe, kb://<id12>/ path qualification), extracted to a shared package; (B) an interim client-side fan-out where web/src/api.ts queries each mount's existing repo endpoints and merges in JavaScript, migrating to A later (the design handoff explicitly offered B as a stopgap).

**Rationale:** the union logic already existed server-side — A is extraction plus four thin handlers, not new algorithm work, which removes B's only advantage (schedule). B costs one request per mount per screen, a merge/dedupe layer that is deleted when A lands, and — decisive — client-side score interleaving cannot reproduce RRF, so humans and agents would see different result orderings for the same lens.

**The choice:** build A first; B is never built. Responses carry each fact's path in canonical form (bare = write repo, kb://<id12>/… = read mount) plus a `source: {repo, id, branch}` convenience field; a `repo=` filter param and a `repo` completions category power source filtering. Routes are read-only-gated exactly like repo reads (the /mcp subtree stays the only gate bypass).

WHERE THE CODE ACTUALLY LIVES (corrected 2026-07-22 — the extraction in option A HAPPENED, so the old locations are gone): there is NO `internal/edge/mcp/federate.go`. The shared union machinery was extracted into its own package, `internal/corpus/federate` (internal/corpus/federate/federate.go), and the fan-out helper is the EXPORTED `federate.ReadTargetsFor(binding, path)` — not an unexported `readTargetsFor` in the mcp package. Consumers at HEAD: internal/edge/web/handlers_lenses_read.go (the four REST handlers this decision authorized), handlers_lenses_stats.go, handlers_lenses_topics.go, and internal/edge/mcp/query.go. If you grep for `internal/edge/mcp/federate.go` and find nothing, the decision was IMPLEMENTED, not abandoned — look in internal/corpus/federate.

**Non-scope:** this decision does not add lens-scoped history or write endpoints — per-fact history uses the existing repo endpoints anchored at the fact's source mount, and writes use the existing repo endpoints on the write repo's agent branch.

# Writes are gated by a branch write-eligibility classification (writableBranch) — v1 allows only the repo's own agent branch; experiments widen it later

**Options considered:** (a) honor the URL/lens branch for writes unconditionally (symmetric with the Phase 0 read fix); (b) lens carries a WriteBranch setting; (c) hard-wire writes to the repo's own agent branch and strip branch from the write path; (d) keep the write plumbing branch-parameterized and gate writes behind a per-branch eligibility CLASSIFICATION.

**Rationale (stress test + user ruling 2026-07-16):** store.factIndex.writeFile mechanically commits to ANY branch, but two branch classes must never be authored directly: the consensus branch (bypasses reconcileAgentMerge and the watermark model) and other machines' agent/* branches (corrupts their watermarks). Option (a) is a correctness trap. Option (c) — the first draft of this decision — was overturned because it forecloses EXPERIMENTS: the planned future flow of forking a working branch from the agent branch, authoring facts there, reviewing, and merging back into the agent branch (or dropping). The danger was never "non-agent branch" per se — it is specific branch classes. So the policy is a classification, and the classification (not the plumbing) is the extension point.

**The choice:** writableBranch(ri, branch) classifies: own agent branch → writable (v1); experiment branches forked from agent → writable when experiments land; consensus branch and foreign agent/* → never. Binding.writeOK derives from this classification; write tools on a non-writable binding fail with a clear read-only-view error (MCP twin of internal/web/readonly.go's non-live-views-are-read-only invariant). writeFile KEEPS its branch parameter. Reads honor any branch. Named lenses write to the write repo's agent branch in v1 (no WriteBranch column); a write-branch setting constrained to writable-class branches may be added when experiments arrive. Bridge unaffected (it pins the discovered agent branch).

**Non-scope:** Does not design the experiment flow itself (parentage tracking or exp/* naming, merge/drop mechanics) — that is deferred work in the RFC; this decision only guarantees the seam (writableBranch) is where it plugs in.

# internal/app wiring tests boot through app.Options.Embedder (a store.BatchEmbedder test seam, testenv.DeterministicEmbedder in practice) rather than pre-caching the ONNX model in CI or skipping when ORT is absent — nil keeps the production path and embeddings stay mandatory

Context: race.yml was red on every dev push from PR #243 to PR #278 because TestApp_AuthConfigReachesMiddleware, TestBoot_GrantsOwnUIDLoopbackDefaultOnce and TestApp_OAuthWiredOnlyWhenConfigured call app.New, which built a real ONNX embedder; no PR job ran the package. See the race-workflow gotcha.

Options considered:
1. Set ORT_LIB_PATH in race.yml and pre-cache the embeddinggemma model (as tests.yml's embed-smoke job does with KNOMIT_EMBED_TEST_CACHE), and point cfg.Home at it. Rejected: each boot uses filepath.Join(cfg.Home, "models") and the tests use a fresh t.TempDir() as Home, so either the tests share a Home (they cannot: the grants seed test depends on a fresh control.db) or every boot downloads 612 MB. Three network-bound downloads per run under -race, and still nothing on PRs.
2. t.Skip the three tests when ORT cannot be loaded. Rejected: auth_wiring_test.go's own doc says the test is what makes the nil-LoopbackDefault fallback in web.Server.grants() acceptable — a skipped guard is the failure mode the test exists to prevent, and it would skip everywhere `go test` runs.
3. An Embedder field on app.Options (store.BatchEmbedder). When non-nil it replaces the production embedder: no embeddings.Lookup, no ORT init, no download, and New does NOT append its Close. When nil, New calls newProductionEmbedder(ctx, cfg), the old block moved verbatim, so TestNew_EmbedderRequired still fails the boot on an unknown model id. CHOSEN.

Rationale: the seam exercises exactly the production wiring the tests exist for (cfg.Auth into web.Server, the grants seed, the OAuth listener) at 0.7 s with no native-lib environment, clean under -race, and it makes the tests runnable on PRs, so ./internal/app/ was added to tests.yml's bridge/platform/cmd step on all three OSes. test/testenv does not depend on internal/app, so the tests can import its DeterministicEmbedder without a cycle; the archtest harness-isolation guard only forbids testenv in SHIPPED binaries, and _test.go imports are fine.

Non-scope: Options.Embedder is a test seam, not a configuration surface. Neither production caller (cmd/serve, tools/desktop) sets it and none should; "embeddings are mandatory" is unchanged. It is also not a way to run a server without vectors — an injected embedder still writes vectors, just deterministic ones.

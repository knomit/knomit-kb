# The mTLS listener's http.Server is built in ONE place, app.OpenTLSServer in internal/app, and both server binaries call it; it owns its timeouts and takes only Handler and BaseContext from the caller's plaintext server

OPTIONS (knomit#256, user ruling 2026-09-25): (A) share one TLS-server assembly between `knomit serve` and the desktop; (B) copy it into tools/desktop/boot.go as the issue first sketched; (C) one assembly for ALL listeners (TCP, local, TLS, OAuth). CHOSEN: A, placed in the EXISTING package internal/app, not a new internal/serve.

WHY A: the TLS server's correctness depends on every part being wired — pki.NewServer, auth.ListenTLS unwrapped, ConnContext: auth.TLSConnContext, ConnState: ps.ConnState, go ps.Run(ctx) — and it already changed once after landing (#258/#268 added ConnState and Run). A copy made before that would have kept a revoked peer's kept-alive connection open, silently. C was rejected because it touches the plaintext listener and the Windows pipe, which #256 put out of scope.

WHY internal/app: it already imports auth, config, pki and zerolog (no new edges), only the two binaries import it (no cycle possible), and it already holds what both binaries share at boot — checkLocalListener (first half of the [auth].require rule), KeyPath, installGitTransport. internal/auth could not host it without dropping config (config imports auth) and gaining pki+zerolog; internal/pki would have had to import auth; internal/web is the handler layer. A future consolidation of the duplicated local-listener policy (cmd/listen.go openLocalListener vs tools/desktop/boot.go) lands beside checkLocalListener in the same package.

TIMEOUTS ARE THE FUNCTION'S OWN (10s header, 30s read, 0 write for SSE, 60s idle — serve's historical values), NOT copied from `like`. The desktop's plaintext server sets no ReadTimeout; copying would have given the desktop's network-facing TLS port no body-read deadline and made the two binaries' TLS servers differ wherever their plaintext servers do. CONSEQUENCE for tests: a test that wants a short IdleTimeout on the TLS server sets it on the RETURNED server (cmd/fleet_origin_test.go does); setting it on `like` no longer reaches it.

A CHANGE TO THE MOVED CODE MUST BE MADE HERE: #286 edited cmd/serve_tls.go (the 'tls listener on %s: %w' wrap of the pki.NewServer error) while this move was in flight, and the merge carried it into internal/app/tls.go by hand — a merge that simply kept the deletion would have reverted it silently.

MISREADING TO AVOID: 'the desktop and serve share the listener code' does not mean they share the listener POLICY on every error. app.ErrTLSAddrInUse is the one error the two treat differently: `knomit serve` returns it from RunE and fails the boot (after its defers, per #261; pinned by TestServeTLS_BindConflictFailsTheBoot, which runs the whole RunE through the serveAppOptions embedder seam), the desktop warns and serves without TLS. Trust failures fail the boot in both.

# Each agent writes only its own branch; consensus is reached by merge into main

Knomit is a decentralized, distributed KB. Every agent operates on a
long-lived personal branch — `agent/<id>`, derived from machine hostname
plus a short hash. All learn/update/retract/subsume operations land on
that branch and push to origin. No agent writes `main` directly. Consensus
into `main` (the repo's configured consensus branch) is reached by merge,
never by an agent writing it: a human merges, the host's operator merges a
peer's pushed branch in the web UI, or the opt-in `consensus: auto` policy
merges it, and in every case the merge lands on the HOST's agent branch. The
consensus branch itself advances through the store's background reconcile and
sync paths, off the write path and on no tool call's timeline.

Why: there is no central writer to coordinate against, and no global
lock to acquire. Agents on different machines, offline or online, can
write concurrently without conflict — each one is committing to its own
branch. Conflicts surface only at merge time, where they belong: at the
moment two beliefs meet. This is what makes knomit safe for a swarm of
agents rather than just a single-process KB.

What NOT to do:
- Write `main` from the MCP server, ever
- Share a single agent branch across multiple machines (collapses
  identity, breaks attribution)
- Acquire global locks or coordinate writes across agents

Amended by the designer on 2026-10-12: the Librarian agent (F12) was dropped on 2026-10-01, and consensus does not flow back "on the next tool call"; see the consensus-merger and main-is-consensus-everywhere facts in refs for how merge and reconcile work today.

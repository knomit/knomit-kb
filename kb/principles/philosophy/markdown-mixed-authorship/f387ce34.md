# Facts are plain markdown so humans and machines author them through the same operations

Every fact is a plain markdown file: YAML frontmatter for structured
metadata, markdown body for natural-language content. The file IS the
fact — no binary blobs, no database rows, no opaque embeddings, no
proprietary serialization. Humans edit them with any text editor and
git client; agents write them via MCP tools. Both paths land at the
same files, on the same branches, through the same commit conventions.

Why: knowledge work is unavoidably mixed-authorship. An LLM-only KB
that humans can't inspect, correct, or hand-author is a black box;
a human-only KB that agents can't extend at machine speed doesn't
scale. Markdown is the lingua franca that lets a human fix a typo
without touching the MCP server, and lets an agent batch-write a
hundred facts without spawning an editor. Diffs are reviewable in
any PR tool. Migrations are search-and-replace. The format outlives
the implementation.

What NOT to do:
- Add an "agent-only" or "human-only" fact format / write path
- Encode structured data in the markdown body that should be in frontmatter
- Let the index schema or embedding format become load-bearing for reads

# Git is the only source of truth; everything else is rebuildable cache

The git repository is the canonical store. The SQLite search index, embeddings, commit_log/branch_commits/commit_parents tables, sqlite-vec virtual tables, cluster caches, and any future derived state are EPHEMERAL caches that can be rebuilt from git at any time.

Why: git provides the proof system (signed commits), the temporal model (history), and the distribution model (push/pull/merge). Cache state cannot provide any of these. If a query depends on data that doesn't exist in git, the query is wrong — that data isn't durable.

Applies to: index design, embedding storage, synthesis intermediates, review/hypothesize watermarks, methodology weights, any new derived store.

What NOT to do:
- Commit the SQLite database, embedding tensors, or any cache artifact to git
- Add a query path that returns data which has no underlying fact file or commit it can be regenerated from
- Persist agent decisions (review outcomes, hypothesis verdicts) only in the index without a corresponding commit
- Treat the index schema as a contract — it must be safe to drop and rebuild
- Use cache-only fields in API responses without a path back to the git source

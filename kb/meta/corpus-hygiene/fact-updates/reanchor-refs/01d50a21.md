# A knomit_update that changes a body to describe NEW code must resend the full refs list re-anchored at a commit containing that code — a current body with refs at an older commit reads as "the fact is stale" to exactly the reader who verifies

RULE: whenever you update a fact's body to describe behaviour that landed after the fact's refs were written, re-anchor every src:// ref in the same update (`git rev-parse HEAD` and `git rev-parse HEAD:<path>` at a commit that contains the behaviour), and resend the FULL refs list — knomit_update replaces refs wholesale, so an omitted ref is dropped. Re-anchor once, after the PR merges, rather than per review round.

WHY: the blob form exists so a citation can be verified with `git cat-file blob`. The /knomit-recall and /knomit-why procedures tell a reader to compare the ref's blob against HEAD and to trust the fact when they match. If the body says "the unscoped mount does X" and the cited blob predates the mount, the reader finds no such code in the citation and concludes the FACT is wrong, when only the citation is. That is worse than a stale body, because it punishes the careful reader.

This is distinct from compute-refs-never-recall (which is about never FABRICATING a ref) and from the ref-scheme convention (which is about the FORMAT): here every ref is real and well-formed, and the defect is that the body outran them.

OBSERVED TWICE on 2026-09-16: the tool-catalog architecture fact (kb/architecture/mcp/tool-catalog) had a correct-enough table with refs in the legacy August form, and the session-bound decision fact (kb/decisions/mcp/session-binding/unscoped-mount/a1019a29.md) was rewritten for PRs #209 and #210 while its five refs stayed at the pre-#209 commit 6f0fcc53 — `git show 6f0fcc53:internal/web/router.go | grep -c 'Unscoped MCP mount'` is 0. Both were found by the reviewer session, not by the author.

WHAT THIS DOES NOT MEAN: do not re-anchor refs on a fact whose body did not change just because HEAD moved — a ref that still matches HEAD is current, and one that differs is a signal to re-verify the body, not noise to refresh. And do not drop a ref you cannot re-anchor (file deleted): keep the old blob, which `git cat-file` still resolves, and say in the body where the code went.

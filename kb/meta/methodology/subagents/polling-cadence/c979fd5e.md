# A subagent that waits for a file, a PR state or another agent's output must poll in MINUTES, not seconds: every wake is a model turn that consumes context and the account's quota, and a tight loop can burn a session's budget while producing nothing

Learned during the 2026-10 multi-session work (fleet specs, F22–F24, the KB audit), when the operator was at the weekly quota ceiling and every wasted turn counted. A subagent told "wait until <file> exists" or "wait for the PR to merge" tends to write `sleep 5` loops or re-check on every turn. Each re-check is a full model turn: it re-reads the prompt, spends output tokens, and counts against the weekly quota, while the thing it waits for changes on a scale of minutes (a reviewer's pass, a CI run, a human's answer).

RULE: wait with a single blocking command whose interval is minutes — a shell `until`/`sleep 120`-style loop inside ONE tool call, or the harness's long-wait primitive where one exists — and put an upper bound on the wait so a dead producer does not hold the session forever. Write the handoff (what you need, where you will look) to a file before waiting, so a replacement agent can pick it up if this one is killed. Never re-check from a fresh turn "just to see".

WHAT THIS DOES NOT MEAN: not that a subagent should block indefinitely — after the bound, report what is still missing and stop; and not a rule about the SERVER's own loops (sync, reconcile, triggers), whose intervals are config and cost no model turns.

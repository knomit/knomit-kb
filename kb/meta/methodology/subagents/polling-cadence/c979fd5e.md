# A subagent waiting on CI, a long test suite or any slow external state must NOT poll: start ONE background command that blocks until the thing finishes (e.g. `gh run watch <id> --exit-status` with run_in_background) and make no tool calls until the harness wakes it; every check from a fresh turn re-reads the whole context and burns quota

Learned during the 2026-10 multi-session work (fleet specs, F22–F24, the KB audit), when the operator was at the weekly quota ceiling and every wasted turn counted. A subagent told "wait until <file> exists", "wait for the PR to merge" or "wait for CI" tends to write `sleep` loops or re-check on every turn. Each re-check is a full model turn: it re-sends the whole conversation (100–200k tokens for a worker deep in a PR, mostly cache reads but still counted) and spends output tokens, while the thing it waits for changes on a scale of minutes.

RULE (operator, 2026-10-07, verbatim: "yes, do that - I mean I'm seeing my tokens evaporating waiting on a stupid CI job to complete"): never poll. To wait for a CI run, start ONE background command that blocks until it ends and then prints the result — in Claude Code, Bash with `run_in_background: true`: `gh run watch <id> --exit-status -R <owner/repo> >/dev/null 2>&1; gh run view <id> -R <owner/repo> --json conclusion,jobs` — and make NO further tool calls until the harness wakes the agent on that command's exit. The same for long local suites (run once in the background) and for any other slow external state: one blocking command, with an upper bound so a dead producer does not hold the session forever. Write the handoff (what you need, where you will look) to a file before waiting, so a replacement agent can pick it up. Never re-check from a fresh turn "just to see". Every brief a coordinating session writes carries this rule; it replaced "poll at most every 3–5 min".

WHAT THIS DOES NOT MEAN: not that a subagent should block indefinitely — after the bound, report what is still missing and stop; not a ban on the coordinator reading a run's state ONCE when it needs a fact (e.g. which head merged); and not a rule about the SERVER's own loops (sync, reconcile, triggers), whose intervals are config and cost no model turns.

# A source-level conformance check that BLACKLISTS an identifier is bound to a spelling, not a property — drive it off the declaration and it survives both the intermediate-variable evasion and the rename false positive

Implementer's framing from the #109 round, adopted. The evidence is unusually clean: the evasion was measured GREEN under the blacklist form, then measured RED under the whitelist form.

**The claim.** A conformance test that parses source and forbids NAMED identifiers pins a spelling, not a property. Two failures follow, in opposite directions: (1) a **false negative** one refactor wide — hoist the forbidden expression into an intermediate local and the blacklist no longer sees it; (2) a **false positive** on rename — correct code reddens because an allowed name changed.

**The fix shape.** Read the permitted set FROM THE DECLARATION, and require every identifier the checked assignment reaches for to be one of: a parameter, a result, a package qualifier, or a predeclared builtin. The check then binds the PROPERTY rather than the spelling. Worked instance: *`carried` is built only from the operands, by construction of the check* — which catches the copy, the clone, the dropped assignment, and the hoisted local, while renaming the results cannot redden correct code.

**When source-level checking is the ONLY option available.** The two shapes this distinguishes were BEHAVIOURALLY INDISTINGUISHABLE — a copy of the write list and a derivation off the operands agree element-for-element at every input, in separate arrays — so no runtime test could tell them apart. The reviewer demonstrated exactly this by lifting the copy shape into the helper and watching the package stay green. Source-level checking is what remains when the property is about CONSTRUCTION rather than behaviour.

**Generalises to the MN4/MN6 family** and to every future conformance test built the same way.

**The residual limit — A PROPERTY OF THE PATTERN, NOT OF ANY ONE CALL SITE.** Any identifier whitelist read from a declaration can be defeated by deliberately REASSIGNING something the whitelist trusts (`winnerRefs = write`). This is not a refactor anyone performs by accident, and a reader spots it instantly. Chasing it is where guard-the-guard recursion stops paying: the guard's job is the ordinary edit, which it now catches. A future author hardening ANY source-level conformance test should find this note rather than re-derive it.

The invariant this particular guard protects is `kb/gotchas/refs/gate/prior-aliasing/0ee925f4.md` — passing the same slice as both `refs` and `prior` silently disables the gate.

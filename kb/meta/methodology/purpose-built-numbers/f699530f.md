# A number is believed precisely BECAUSE it was purpose-built for the decision reading it — so for any new descriptor or metric, ask what will read this and does it mean what its label says

Standing review question adopted for Phase 4, from the M4/M5 remediation. Implementer's formulation.

**The question, asked of every metric before it ships.** *What will read this number, and does it mean what its label says?*

**Why the purpose-built ones are the dangerous ones.** A metric invented FOR a pending decision arrives with the decision's authority already attached. Nobody audits it, because it exists to be trusted; and its label was chosen to describe the DECISION, not the quantity actually computed.

**Both late Phase-3 findings were this class:** a guard proven correct but never proven CALLED, and a counter purpose-built for a Phase-4 decision that conflated two causes under one label.

**Applied in Phase 4, it caught FOUR more — all the author's own:**
- `bridgeable_pairs` counting AUTHORED facts rather than the post-`AcceptSeed` seed pool (a quarter to a half of every corpus's motifed facts are pragmatic and can never bridge).
- `written: 4` counting commit ROWS, not facts.
- "token pairs also claimed by a motif arm: 7" counting ALL drops.
- `line-added:refs 157` double-counting a quote-only change.

**The companion rule that makes reports honest: state the POPULATION before any number.** Most of the errors above are population errors, not arithmetic errors — the count was right for a set that was not the set the label named.

**Corollary on absent evidence.** "Measured EMPTY" and "measured and fine" are different claims, and a report that blurs them is making the purpose-built error one level up. Several motif register entries closed as *re-deferred on absence of population*, with counters shipped so the denominator exists when a corpus produces one — that is the honest form.

**Companion practice.** Stating "a number that does not reproduce is a HIGH finding" BEFORE the reviewer sees any code is what turns a review into a measurement rather than a reading — and it surfaced two findings that were neither code defects nor findable by any test.

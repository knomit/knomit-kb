# A code REMOVAL needs three DIFFERENT completeness sweeps — consumers-before, orphans-after, filenames-as-strings — because no single sweep can see all three failure classes

When you delete a subsystem, the completeness check is not one sweep but THREE, each answering a different question with a different answer, and skipping any one leaves a class of breakage that the others structurally cannot catch:

1. **Consumers, BEFORE the deletion** — grep every removed SYMBOL repo-wide and account for each hit (delete / edit / keep). Catches the build break where a symbol you're deleting is used outside the feature's own files. (In the backfill rip-out this caught `sharedClusterMotifs`, used by distill — it had to be RELOCATED, not deleted, and the relocation was split into its own behaviour-preserving commit so it wasn't buried in the deletion.)

2. **Orphans, AFTER the deletion** — ask what the deletion just made DEAD: a callee whose only caller was the removed feature. This is UNDISCOVERABLE beforehand — the code wasn't dead until the removal happened, so every pre-removal sweep correctly misses it, and `go build`/`go vet` do NOT flag an unused EXPORTED method. You must reason about the removed feature's former callees. (This caught `store.MotifIndex.LiveFactIDs`, whose sole caller was the backfill pass.) An instance of repair-recursion — the same bug-class reappears one step out from the change, and cleanups manufacture it more than fixes do.

3. **Filenames as STRINGS** — grep the literal deleted FILENAMES repo-wide, not just the symbols. Source-scanning conformance tests (`readSourceFile("motif_backfill.go")` asserting on file contents), `//go:embed` directives, and generated-file manifests reference files by NAME as string literals. The compiler cannot see them (runtime file read) and the symbol sweep cannot see them (a filename is not a symbol). This is the ONLY one of the three with NO compiler backstop — running the tests is its sole net. (This caught `motif_writers_test.go`; fix by RETARGETING the conformance test, not deleting it.)

Consequence a reader must act on: run all three, and prove each sweep actually executed (a zero-hit sweep that silently matched nothing — e.g. an unquoted zsh loop variable that never word-splits, or `head`-truncated output — reads as 'all clean' and is not). What this does NOT mean: it is not satisfied by one up-front grep; the after-sweep is a distinct question from the before-sweep and answerable only post-deletion. Sibling of build-the-merge-result: verify the RESULT of the change, not the plan for it. Grounded in the motif-backfill rip-out (PR #161): all three fired, each caught a real defect the others missed; suite stayed green, MN1 went exception-free, migration drop sabotage-proven.

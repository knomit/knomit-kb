# A safety gate keyed on a PROXY can invert against the property it protects — check the proxy's correlation direction separately for every source of the input

A gate that serializes embedding inference to bound memory was triggered on "was the derived budget clamped below the ceiling?" as a stand-in for "can this memory ceiling absorb overlapping runs?". Those two agree on some inputs and INVERT on others.

For a cgroup source they are anti-correlated by construction, because the sizing fraction (0.8) spends the available headroom on the first batch as soon as one batch is affordable. So the moment the machine could afford a full-size batch, the budget hit the ceiling, the proxy read "not clamped", and the gate switched OFF — at exactly the memory sizes where a second concurrent run would not fit.

Measured consequence: a 4400 MiB cgroup derived 1821 MiB of headroom against an 1820 MiB requirement — budgeted for exactly one run with 1 MiB to spare — and then disabled the mechanism that kept it to one run. Two overlapping runs need 5339 MiB. A container at 4300 MiB was SAFER than one at 4400 MiB: adding memory removed the guarantee.

CONSEQUENCE — what to do, not just what happened: when a safety decision is keyed on anything other than the property itself, enumerate the SOURCES the input can come from and check the proxy's correlation direction under each. A proxy that tracks the property for one source can invert for another, and the inversion shows up precisely where the sizing policy differs. Where the property is cheaply computable — here, ceiling minus known costs versus K times the measured per-run cost — key on it directly and skip the proxy.

SECOND-ORDER, and the reason a threshold was not the fix either: on a HARD boundary (a cgroup, where breaching is instant death with no absorber) any K-run threshold is beatable by K+1 concurrent workers, so a threshold moves the cliff rather than removing it. Hard boundaries want an unconditional guarantee; soft boundaries (physical RAM, where unclaimed memory is a real absorber) can take a threshold, and it must be evaluated against the REAL envelope rather than against the fraction you claimed of it.

WHAT THIS DOES NOT MEAN: not "never use proxies". The proxy here was cheap and correct for the source it was designed against; the defect was assuming it held for the other source without checking.

# A safety inequality whose two sides derive from the SAME model is unsatisfiable, not conservative — and its tests pass, because a check that never fires never fails

A gate meant to serialize inference when a machine could not absorb K overlapping runs was written as `absorber < K * worstCasePerRun(tokens)`. Both sides came from the same measured ladder, and `tokens` had just been chosen as the largest budget whose worst case FITS the available memory. So `worstCasePerRun(tokens)` was identically the available memory, and the condition reduced to `H(1 - Kf) < C(1 - K)` — unsatisfiable for any K, f with `Kf <= 1`.

With f = 0.25 and K = 2 the gate could only ever fire inside the floor clamp: ON below ~2.1 GiB of RAM, OFF at 2149 MiB and above, never returning. It was shipped believing it protected every machine.

WHY IT SURVIVED REVIEW. Nothing looked wrong. The inequality reads as a safety check, the constants are individually defensible, and a monotonicity test passed — passed VACUOUSLY, over a condition that was false everywhere it was sampled above 2.1 GiB. A test asserting "the gate never switches off as memory increases" cannot distinguish a correct gate from one that is already off.

THE DIAGNOSTIC, and the part worth acting on: SWEEP THE SAFETY CONSTANT. Changing K from 2 to 3 — a 50% change in how much concurrency the rule tolerates — moved the boundary by 256 MiB, and K = 8 was needed to reach a boundary any real machine would cross. When tuning a safety parameter barely moves the behaviour, the parameter is not in the binding path, and the condition is probably degenerate. That sweep is cheap and it is the check that finds this class; reading the expression is not, because the expression looks fine.

GENERAL FORM: whenever a threshold compares a REQUIREMENT against a BUDGET, ask whether the budget was itself computed from the requirement. If it was, the comparison is asking a question it already answered, and it will report whatever the sizing step decided rather than an independent fact about the machine. The two sides of a safety inequality must come from different sources — here, the fix asks about the MACHINE (physical memory and fixed costs) rather than about the resolved budget.

RELATION TO ITS SIBLING: a proxy that inverts against the property is one failure (see the proxy-versus-property fact); this is the other. Not an inverted check but a SELF-SATISFYING one. Both are cases of the gate's input not being independent of what the gate is supposed to judge.

WHAT THIS DOES NOT MEAN: not that deriving a budget from measurements is wrong — that part was sound and stayed. The defect was reusing the SAME derivation on both sides of a comparison meant to test it.

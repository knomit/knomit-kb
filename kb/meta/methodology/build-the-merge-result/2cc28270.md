# A semantic merge conflict — two branches each valid on its own base, incompatible combined — is caught only by building the MERGE RESULT, never either branch

When two branches are queued for merge and both touch a SHARED SIGNATURE — one changes it, the other adds a call site to it — each can be independently correct: green on its own base, cold-reviewed clean, and text-mergeable (git has nothing to conflict on — different lines, different files). The COMBINED tree still fails to compile. 'Re-assert the base before every commit' proves a branch sits on current dev; it says NOTHING about a second queued branch changing a signature that branch calls. Both branches can be current, correct, and mutually incompatible.

The only check that sees this class is building the MERGE RESULT: run `go build ./... && go vet ./...` (and the affected test package's compile) on dev IMMEDIATELY AFTER each merge; and before merging the SECOND of two queued branches that touch a shared signature, do a TRIAL MERGE and build it first.

Concrete (knomit, 2026-08-26): #123 added a `createdBy` parameter to `CreatePipelineSession` and swept every call site that existed ON ITS BRANCH. #117b (merged first) added five NEW call sites its sweep could not have seen (its branch was cut before #123 merged). Both PRs were green on their own bases and merged cleanly at the text level; the combined dev did not compile (`not enough arguments in call to CreatePipelineSession` in two test files), which silently made `go test ./internal/synthesize/` unrunnable — so anything reporting that package green after the merge had not actually run it.

What this does NOT mean: it is not caught by re-reviewing either branch (each is correct in isolation), and it is not a git merge conflict (no textual overlap, nothing to resolve). Responsibility sits with the MERGER / coordinator at merge time — a reviewer correctly builds only the branch under review, on its own base. Sibling of repair-recursion (a change's effect shows up one step away from the change) applied to the merge boundary rather than to a fix's neighbours.

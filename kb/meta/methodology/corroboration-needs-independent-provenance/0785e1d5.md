# Two sources agreeing is not verification when they share an ancestor — a corpus fact and a code comment can both descend from one design note and be wrong together

When two sources agree — two facts, or a corpus fact and a code doc-comment — that agreement is evidence ONLY if the sources were verified INDEPENDENTLY against ground truth (the code, a measurement). If they descend from a common ancestor (the same design note, the same original stated intent), they corroborate by INHERITANCE, not by verification, and can both be wrong the same way. A knowledge base manufactures false corroboration this way: the more it documents an intent, the more mutually-reinforcing sources exist for that intent, none of which is a check on the code.

Concrete instance (knomit throttle, 2026-08): a probe-consumption fix was argued to need no designer ruling because 'the contract is already written down twice' — a code doc-comment on probeAllowed AND the corpus fact self-defunding-latch/3875d229. Both stated the INTENDED behaviour (consume the probe only when a pair was really SERVED). The code did something else (gated on SELECTED, not served); the divergence had opened silently when an earlier fix split 'selected' from 'served' and nothing re-read the older claims against the new distinction. The two sources agreed because they shared a design-note ancestor, not because either had been checked against the code — so 'written down twice' was zero independent corroboration, and I (the coordinator) accepted it as proof.

What this does NOT mean: it is not that agreement between sources is worthless. It is that agreement across sources of SHARED PROVENANCE is not INDEPENDENT corroboration. Before treating agreement as verification, establish that the sources have independent provenance; if they do not, verify at least one against ground truth (the code / the measurement), never against its sibling. This is the corroboration analogue of prove-the-regression-test-fails (a stated red is not an observed red) and instrument-reads-truncated-values (a comparison inside the lossy step reports no loss).

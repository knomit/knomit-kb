# Do not add design artifacts nobody asked for (a principle, a rule, a mechanism) and route them through the user as if required — ask whether the work is wanted, and put mission instructions where the agents read them: in the tasks

During the first mission run (2026-10-02) the master session tried to have a mission "principle" written into the mission repo before the agents could start, then asked the user to write it. The user's ruling: nobody asked for that principle; knomit is programmed by putting the mission text into the tasks, and the master should ask for the work it wants done instead of inventing prerequisites.

Operational consequence: when a plan step exists only because an earlier design draft had it, check it against the user's rulings before acting on it. If no ruling asks for it, drop it or ask. Mission-specific instructions travel in task bodies and the mission template's skills, not in new ontology topics or principles.

WHAT THIS DOES NOT MEAN: designs still get proposed — as proposals for review, marked as such, not as steps the user must perform before work can continue.

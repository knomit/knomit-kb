# A coordinating session never hands the user a step an agent can do — posting the charter, running a synthesis, starting a follow-up task are agent work; the user gets only merges, decisions and steps that truly need their machine

During the first fleet mission (2026-10-02) the master session asked the user where to put the mission charter and told them to run a synthesis by hand. The user had already given the charter, and a session mounting the repo with knomit's MCP tools could post it and run the synthesis as a follow-up task. The user's correction: put the mission text into the tasks, and ask an agent to do the work you want done.

Operational consequence: before writing "you can now…" or "run …" to the user, ask whether a session with the repo mounted could do it. If yes, post it as a task, or brief a worker. What remains for the user: merging PRs, rulings, and actions that need their own machine or credentials (rebuild and restart of their own instance, creating a GitHub repo they own).

WHAT THIS DOES NOT MEAN: it does not license acting on outward-facing or hard-to-reverse things without asking (merging, publishing, filing issues); those still need the user's go.

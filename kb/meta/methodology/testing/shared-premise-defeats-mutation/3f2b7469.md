# When a suite and the code it tests rest on the SAME premise, mutation cannot reach the defect — every mutation preserves the premise, so the suite stays green by construction and only measurement against real data can disagree

`kb/meta/methodology/corroboration-needs-independent-provenance` says two sources agreeing is not verification when they share an ancestor. This is that principle's worst case, because of WHICH two sources: a test suite and the code it tests. A suite is written from the same understanding as the implementation, so when that understanding contains a false premise the suite encodes it too — and then agreement between them is guaranteed rather than informative.

WHY MUTATION CANNOT REACH IT, which is the part that is not obvious and the reason this is worth its own fact. Sabotage works by perturbing the CODE and watching the suite object. But every mutation of the code leaves the shared premise untouched, because the premise is not in any one line — it is in what both artefacts were built to believe. So the suite stays green under every mutation, and it stays green CORRECTLY: it is faithfully reporting that the code still does what its authors meant. The instrument and the subject are not independent, so the instrument cannot falsify them jointly.

THE INSTANCE. `knomit_learn`'s same-subject gate excluded every candidate at or above the `Dedup` floor, because "a hit at or above Dedup belongs to `applyDedupMerge`, which has already folded it". `applyDedupMerge` searches ONLY the incoming fact's own category directory, so for a cross-category candidate the merge never looked and the gate excluded it — nothing caught it. Measured under the shipped model, three of the four locatable known collision pairs sat above `Dedup` and every one was cross-category, which is precisely why they had collided. The feature caught one of four.

What that survived: three review rounds, two reviewers, an automated review pass, a full green suite, and a doc comment that contained BOTH halves of the contradiction in the same block (it said category scoping is why these pairs collide, then justified the bound with a category-scoped mechanism having caught them). A reviewer quoted both halves in his own notes and approved. Reading did not catch it, and by the argument above nothing mutation-based could have. It was found by a SCHEDULED measurement of real pre-merge fact bodies against the real embedding model, run after the code had already merged.

CONSEQUENCE a reader must act on: when a design rests on a premise about ANOTHER mechanism's coverage — "X already handles that", "Y has folded it", "Z guarantees this" — that premise is settled by MEASUREMENT against real data, not by more tests, more mutation, or another reviewer. Write the premise down as a claim about scope, and schedule the measurement; do not let a green suite stand in for it. Two cheap probes: verify the cited mechanism's own SCOPE (here, one grep for `Path: categoryDir` would have done it), and check whether the doc comment states the premise and its contradiction in the same breath.

WHAT THIS DOES NOT MEAN — the misreading to refuse: **not** "more mutation testing would have caught it". It would not, by construction, and believing otherwise is the expensive error, because it prescribes more of the one instrument guaranteed to return green. It is also not an argument against sabotage, which catches a different and more common class — the point is that sabotage and measurement answer different questions, and a premise about another mechanism's coverage is only ever answered by the second.

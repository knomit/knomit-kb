# To fix a probabilistic assertion, change the KIND of evidence — narrowing the sampling window only moves the odds

A fixture asserted "the heal was still held when the event fired" by sampling a state flag at one instant. It caught the corresponding mutation 5 times in 30.

Narrowing the window helped and did not solve it. Adding an arrival signal, so the fixture waited for the goroutine to reach the gate before sampling, took detection to 28/30. The residue is structural: arrival and passage are TWO events with an instruction window between them, and a sample landing inside that window reads "arrived, not yet past" and passes. A smaller window is still a window.

Asking WHICH SELECT ARM the goroutine took moved it to 119/120, because it is a different kind of claim: a fact about what happened rather than about when we looked. A hold that fails to block normally takes neither arm, and no amount of scheduling luck changes which arm was taken.

IT IS NOT 120/120, and the escape is worth knowing rather than rounding away: `hold` closes its arrival channel and THEN selects — two statements. If the goroutine is preempted between them, the test's wait returns, the test opens the gate, and the resumed non-blocking select finds the release channel already closed and takes that arm. THE FIXTURE CLOSES ITS OWN WINDOW by being the thing that opens the gate. Closing that gap would require observing that a goroutine is parked, which Go does not expose.

METHODOLOGY NOTE, and the reason it is IN this fact rather than beside it: A DETECTOR'S RATE NEEDS MORE RUNS THAN THE THING IT DETECTS IS RARE. Every number above was first reported wrong by someone, in both directions:

- The author reported a single sabotage run as a rate ("fails both tests"), when the real figure was 5/30.
- The author then reported one batch of 30 as "every time".
- The REVIEWER reported 29/30 off a single batch as the rate; it took four batches to establish 119/120.

Three over-claims, two people, opposite signs. That is what makes this a property of the measurement rather than of anyone's care: a rare event and a rare miss are indistinguishable in a small sample, and the sample size that feels sufficient is set by how often the test PASSES, not by how often the mechanism fires.

# Subagents share the parent session's knomit MCP connection, and the experiment binding is per connection: parallel workers never open experiments or write facts (they record intended facts in a file); one agent writes them per branch after merge, one experiment at a time

Claude Code subagents spawned from a session use that session's knomit MCP server connection and binding. An experiment opened with `knomit_experiment` binds the session's writes to `exp/<name>`, so two subagents writing facts at once would land in whichever experiment is bound — misattributing facts across PRs.

Rule used by the fleet master (2026-09-27 onward, restated 2026-09-30): only ONE fact-writing subagent (a worker with an open experiment) runs at a time; the next PR's worker starts only after the previous PR's experiment is committed (after the user merges). Reviewer subagents never call knomit_learn/update/retract/experiment, so they may run in parallel. A separately started Claude Code session (its own MCP connection) is not bound to this session's experiment and may write in parallel.

Consequence for planning: independent PRs that each write facts are built sequentially, not in parallel, when all are this session's subagents.

WHAT THIS DOES NOT MEAN: it does not forbid parallel subagents in general — only concurrent fact WRITERS on the same session binding.

Mechanism and the options weighed (serialize, unscoped bridge with per-agent handles, separate session per issue) are in kb/decisions/experiments/concurrency/0829b72e.md: on a URL-scoped bridge a second `open` switches every agent on the connection, and any commit or rollback clears it for all.

Recurrence, 2026-10-10 (facets build): a master that had not recalled this fact briefed two parallel workers to each `open` an experiment named after its branch. The second `open` switched the shared session; the first worker's later UNNAMED `rollback` then destroyed the other worker's experiment (`name` on commit/rollback defaults to the experiment the session is currently in). No facts were lost only because none had been written yet. The alternative that keeps parallel workers: workers call no knomit write tool at all and put each fact's full draft (topic, category, title, body, refs) in their report under "Facts to write after merge"; one session writes them after the PR merges, with refs pinned to the merge commit. That keeps the invariant the experiment protects (nothing reaches the agent branch before merge) without serializing the build. Whichever way: always pass `name` on commit and rollback, and recall this fact before briefing any subagent that may write facts.

Recurrence 2026-10-12: a worker subagent opened an experiment for its PR's facts, and the coordinating session's own `knomit_experiment {action: "list"}` then reported `active_experiment` set and `current: true` for it, although the coordinator had never opened one. The cheap check: a coordinator that delegates experiment work runs `knomit_experiment list` before any knomit write of its own, writes nothing while the summary says it is inside an experiment, and resumes writing only after the worker's commit or rollback returns the session to the agent branch.

Recurrence 2026-10-13 (fleet P1 #511 and P2 #512, two parallel workers in one Claude Code session): the knomit experiment binding is per MCP CONNECTION, not per agent. P2 opened `feat-pki-root-custody`; P1 then opened `feat-receive-pack-content-closure`, which moved P2 too, so P2's `knomit_learn` of 4 facts landed in P1's experiment (exp commit b835273b). P2 retracted them there (56b1207d) and its own experiment stayed empty; the master re-wrote them per branch after both merges. The stray pair netted to zero in the tree, but it stays in P1's history.

RULE THAT FOLLOWS (default for any parallel build in one session): parallel workers call NO knomit write tool and NEVER `knomit_experiment open`. Each worker records its intended facts (topic, category, title, full body, refs, amendments to existing facts) in a file beside its report. After each PR merges, the master (or one dedicated agent) writes them per branch, ONE experiment at a time: open, write, re-pin refs to the merge commit, commit, then the next. Checking `knomit_experiment list` before every write is the guard that shows another agent moved the connection.

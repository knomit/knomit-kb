# Subagents share the parent session's knomit MCP binding: run only ONE fact-writing subagent (open experiment) at a time

Claude Code subagents spawned from a session use that session's knomit MCP server connection and binding. An experiment opened with `knomit_experiment` binds the session's writes to `exp/<name>`, so two subagents writing facts at once would land in whichever experiment is bound — misattributing facts across PRs.

Rule used by the fleet master (2026-09-27 onward, restated 2026-09-30): only ONE fact-writing subagent (a worker with an open experiment) runs at a time; the next PR's worker starts only after the previous PR's experiment is committed (after the user merges). Reviewer subagents never call knomit_learn/update/retract/experiment, so they may run in parallel. A separately started Claude Code session (its own MCP connection) is not bound to this session's experiment and may write in parallel.

Consequence for planning: independent PRs that each write facts are built sequentially, not in parallel, when all are this session's subagents.

WHAT THIS DOES NOT MEAN: it does not forbid parallel subagents in general — only concurrent fact WRITERS on the same session binding.

Mechanism and the options weighed (serialize, unscoped bridge with per-agent handles, separate session per issue) are in kb/decisions/experiments/concurrency/0829b72e.md: on a URL-scoped bridge a second `open` switches every agent on the connection, and any commit or rollback clears it for all.

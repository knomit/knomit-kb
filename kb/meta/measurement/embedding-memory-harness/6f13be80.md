# Embedding memory measurement harness — one process per config, env-driven, reproducible to within 0.7%

The harness used to measure embedding inference memory on 2026-08-29 lives in `.claude/plans/2026-08-29-embed-memory-{measure.sh,results.txt,results-2.txt,measure_test.go.txt}` on the authoring machine. IT IS NOT IN THE REPO — `.gitignore` excludes `.claude/*` apart from `skills/` and `settings.json` — so it is local-only and will be lost with that machine.

SHAPE: a Go test inside `package embeddings` (so it can call unexported `embedBatch`/`encode`), driven by `KNOMIT_MEASURE_BATCH` and `KNOMIT_MEASURE_SEQ`, run as ONE PROCESS PER CONFIGURATION because the ONNX arena retains its high-water mark. It resets `VmHWM` via `/proc/self/clear_refs` after a warm-up run, so the reported delta is the batch's cost above the resident model rather than the model load.

To restore: copy the test file into `internal/embeddings/`, build with `go test -c`, and run with `ORT_LIB_PATH` pointing at `dist/<platform>/lib/libonnxruntime.so` and `KNOMIT_EMBED_TEST_CACHE` at `~/.knomit/models`.

REPRODUCIBILITY: the four shape-invariance configs re-run hours apart agreed to within 0.7% (1154/1161/1143/1683 vs 1154/1159/1144/1683 MiB).

CONSEQUENCE: a planned follow-up (PR 2) needs this harness again — to measure non-embedding RSS and to test whether concurrent `session.Run`s buy any throughput. Promote it into the repo as a checked-in tool at that point rather than weakening the `.claude` ignore rule.

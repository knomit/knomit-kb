# As of 2026-10-26 (onnxruntime-genai v0.17.0): constrained JSON via guidance exists (since v0.16.0) and LFM2 is supported (v0.17.0), but there is no Go binding and no osx-x64 release asset

DATED SNAPSHOT, researched 2026-10-26 from public pages only (materialize research spike, round 6; evidence in the git-ignored .claude/plans/materialize-spike/round6-local-models/RESEARCH.md). Nothing was built or run; this is what the release notes, README, C header and a web search showed. The project releases fast (0.15.x in August, 0.16 and 0.17 in September 2026), so it will date.

1. Constrained decoding: the C API has OgaGeneratorParamsSetGuidance(params, type, data, enable_ff_tokens) with types json_schema, regex and lark_grammar (llguidance-based); release v0.16.0 (2026-09-22) notes 'enforce structured output with guidance'. Fast-forward tokens work only with batch size 1 and beam 1.
2. Architectures: the README lists LFM2 (language, vision, audio), Granite, Granite MoE Hybrid, Phi, Qwen, Gemma and SmolLM3; the v0.17.0 release notes (2026-09-28) add LFM2 including MoE and VL. Qwen3.5 and Gemma 4 are not named by version. Whether Liquid AI's official ONNX exports (which ship no genai_config.json per their model card) load unchanged, or must be rebuilt with genai's model builder, was NOT verified.
3. Distribution: v0.17.0 release tarballs for linux-x64, linux-arm64, osx-arm64, win-x64 and win-arm64 plus cuda/winml variants; NO osx-x64 (Intel Mac) asset. A Python wheel and a NuGet package exist.
4. Bindings: no official Go binding; a web search (2026-10-26) found only Go wrappers for core ONNX Runtime, not for genai. The C API is pre-1.0, not thread-safe, and requires OgaShutdown after everything is destroyed.
5. Version coupling between a genai release and a pinned onnxruntime (knomit pins ORT 1.24.3 in tools/fetchlibs) was NOT verified.

WHAT THIS DOES NOT MEAN: 'constrained decoding is available' does not mean it was tested on any model here; the missing osx-x64 asset is for the release tarballs, and building from source was not checked. The earlier objection that the ORT path has no constrained decoding no longer holds for genai, but only for the architectures genai supports. Nothing here says genai would or would not be a good runtime choice.

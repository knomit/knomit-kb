# refs.Gate's `prior` fails silently in BOTH directions: too large (the write list itself) and the gate launders everything; too small (nil while carrying refs forward) and the writer refuses its own inheritance — prior must be exactly what the replaced or merged versions carried

Mechanism: a check that exempts whatever the caller declares as already-present is only as correct as that declaration, and the declaration can be wrong in two opposite directions, each of which fails without any error.

refs.Gate judges only refs NOT in `prior` (local refs compared by classified path, src refs by raw string). So `prior` decides what the gate sees, and it has two failure modes:

- TOO LARGE — passing the write list itself as prior (`gate.Apply(ctx, path, refs, refs)`) exempts every ref unconditionally. The call compiles, canonicalizes and reads like a gate, but can never reject anything, now or after a later change appends a ref to the write list (gotchas/refs/gate/prior-aliasing). Fix: build the carried set as its own copy at the point where 'every element came from an existing fact' is provably true.
- TOO SMALL — passing nil while carrying refs forward from existing versions makes every inherited ref read as newly added. Since the src-form rule, that refuses any inherited short-form src ref: an experiment {body} resolution, or a review prune-merge, touching a fact that carries one was refused or warn-and-skipped (decisions/refs/src-ref-gate-new-refs-only). Fix: prior is the UNION of what the replaced or merged versions carried — for a resolution, that path's refs at the fork commit, parent tip and experiment tip; for a prune-merge, the members' refs SNAPSHOTTED before the call deletes any member.

THE RULE: prior is exactly the refs the versions this write REPLACES or MERGES already carried — no more (else the gate is decorative), no less (else the writer is refused for its own history). Review a call site by asking both questions: could anything be in the write list and not in prior; and does prior contain every ref the replaced versions had.

WHAT THIS DOES NOT MEAN: the exemption itself is not a bug — refs are checked once, against the commit their write lands on (historical-not-current), and removing prior would make one retraction anywhere in history render every fact that ever cited it uneditable. And it does NOT mean every caller should pass the cited facts' refs: a writer that CITES sources without replacing them (distill, discovery) inherits none of their refs and correctly passes nil; knomit_learn and REST create a new fact and pass nil.

# HYPOTHESIS: the once-seen miss of a newly created repo in the desktop rail on Windows (about 6 min idle, window freshly shown, absent 8 s after the create, present a minute later) is a paint delay of a just-shown window or a first-poll-after-long-idle effect, not event loss — NOT reproduced in three later trials

ONE OBSERVATION, UNEXPLAINED. 2026-10-12, Windows 10 22H2, merged build at 2104fd6d, scratch home, desktop run in the console session: in the very first repo create after about 6 minutes with no events and with the window freshly shown from the tray, a screenshot taken about 8 s after the create (via curl on the loopback port, not the UI's own '+') did NOT show the new repo in the rail; a screenshot a minute later did. REPRO CONDITIONS: long idle (about 6 min), window freshly shown, create made by another client. NOT REPRODUCED in three later trials: 1 min idle, 2.5 min idle (rail updated 40 ms after the POST returned), and hidden-then-shown (repo already present). Both candidate causes could produce the observation and could not be separated: (a) a paint delay of a just-shown window, (b) a first-poll-after-long-idle effect on the parked Streams poll. A related KNOWN behaviour is that a create finished by another client stays a 'created' pending row until clicked (kb/gotchas/web/rail/foreign-creates-stay-pending/3b72c58b); that fact is about the row's state, not about the row being absent, and it is NOT shown to explain this miss.

PREDICTION (falsifiable): with a person watching the Windows desktop and creating a repo with the UI's own '+' after a long idle, the repo appears in the rail within a few seconds; a persistent absence (more than about 30 s with the window visible) would falsify the paint-delay explanation and point at event delivery after idle. Confidence is low because it is a single un-repeated sighting with a screenshot as the only instrument (no DOM-level driver was available).

WHAT THIS DOES NOT MEAN: it is not evidence that Streams lose events on Windows (the idle, close, resume and burst measurements were clean); and it is not a confirmed defect.

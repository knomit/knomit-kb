# MEASURED on Windows 10: killing knomit-desktop kills its supervised server through the KILL_ON_JOB_CLOSE job within ~0.3 s, so the server never runs its stdin-EOF shutdown and server.json plus running.marker stay stale; the next start recovers (about 9 s warm); a killed CHILD is respawned about 5 s later (1 s backoff plus the bundled version probe) and answers after the server's own init

Measured 2026-10-12 on one Windows 10 22H2 machine against the build at PR #503's last commit (merged as 8be999a0); every figure is DATED SUPPORT for the mechanism, not a constant of the code - do not derive a timeout from them.

MECHANISM. The desktop's supervisor (tools/desktop/supervisor_windows.go) assigns the child `knomit.exe serve --supervised` to a Job Object with KILL_ON_JOB_CLOSE and CREATE_NO_WINDOW (no visible child window). When the desktop dies, the OS closes the job and kills the child.

OBSERVED.
- Desktop killed (taskkill /F): the desktop was gone at +0.22 s and the child at +0.32 s. Nothing orphaned. It is a KILL, not a shutdown: the server's stdin-EOF path (the clean one on macOS/Linux) loses the race to the job, so server.json and running.marker stay behind and the next server logs 'previous run exited uncleanly (possible crash)'. A desktop started over the stale files spawned a child that answered in 9 s (warm model cache); a COLD first start downloaded the embedding model and took 2 min 34 s. Tray Quit instead closes stdin and the server removes server.json within ~1 s.
- Child killed (taskkill /F on knomit.exe): 'exited unexpectedly', respawn about 5 s after the kill (the 1 s backoff plus a `knomit.exe version` skew probe that took ~3 s on a cold 124 MB exe), answering 17 s later (the server's own init). Meanwhile the UI's SSE streams logged 'upstream dropped ... retry' every 5 s and reconnected on their own; no reopen needed.
- The detached grandchild of a recipe died 0.2 s after the desktop kill (kb/gotchas/repos/triggers/recipes/process-groups/116de6c4).
- Native Windows tests that first ran here and passed: TestSupervisor_KilledDesktopEndsTheServerThroughTheJob and ...ThroughStdin, TestMutexNameIsPerPathAndCaseInsensitive, TestAcquire_LockDiesWithItsProcess. The PATH-decoy refusal test is skipped on Windows (its decoy is a shell script), so it is NOT proven there by tests.

CONSEQUENCES. (1) Do not read a leftover server.json as proof the server is alive or was shut down cleanly; probe the pipe (clients dial the pipe, which is gone). (2) The 'unclean exit' WARN after a desktop kill is expected, not a crash report. (3) A tool that kills the desktop (taskkill, an installer) also kills the server and any detached recipe process, by design.

NOT MEANT: this is not a hang, leak or bug in the job code; and 'stdin EOF is the shutdown path' does not hold on Windows when the desktop is killed.

# A macOS self-update replaces the WHOLE .app, so the bundled `knomit` and `knomit-desktop` always move together, but the running server child holds the old binary during the swap: the desktop must stop it before relaunch (owed to desktop PR 5)

In Wails v3.0.0-beta.28 `pkg/updater/helper.go`, `runHelperSwap(target, ...)` backs up the whole target (`target + ".bak"`), replaces it with the new one and relaunches; line 94 maps a darwin executable inside a `.app` to the `.app` directory. So `Contents/MacOS/knomit` and `knomit-desktop` are replaced in one swap and can never be a mixed old/new pair. The updater is darwin-only (tools/desktop/update.go); Linux and Windows have no updater.

**Consequence for PR 5:** once the desktop launches the bundled server as a child, that child still runs the OLD binary when the swap happens. Unix unlink-and-rename tolerates the open inode, but the desktop should stop its server child before it triggers the relaunch, or the old server keeps its listeners and lock while the new app starts. This is owed to desktop PR 5; #500 does not do it because nothing launches the child yet.

**What this does NOT mean:** it does not say the swap is unsafe today; with no child process there is nothing to stop. Third-party internals: pinned to Wails v3.0.0-beta.28, so re-read helper.go after any Wails upgrade.

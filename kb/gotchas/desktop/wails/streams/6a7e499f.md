# Wails Streams match the stream name EXACTLY (no path, query or headers), so the desktop opens one name, knomit-sse, and sends the API path as the first frame; a Stream's lifetime is its handler goroutine's, and the per-window queue blocks Send when full

At github.com/wailsapp/wails/v3 v3.0.0-beta.28 (pkg/application/stream.go; JS side internal/runtime/desktop/@wailsio/runtime/src/stream.ts). Streams arrived in beta.8.

- app.HandleStream(name, handler) looks the name up in a map (exact match; no wildcard, path, query or header reaches the handler). knomit therefore registers ONE name, knomit-sse, and the page sends {path, last_event_id} as its first frame; the handler reads it (readSubscribe), validates it (validSSEPath) and subscribes. A stream with no subscribe frame is closed.
- A connection's lifetime is its handler goroutine's: returning from the handler closes the stream; the client closing cancels StreamConn.Context(), which is how a page close reaches the upstream request.
- Limits in the source: 256 frames and 8 MiB queued per window going to the page (Send blocks when full, streamOutQueueDepth/streamOutQueueBytes), 256 live connections (streamMaxConnections, commented as "a page normally has only a handful"), 16 sessions per window. The desktop opens at most one stream per live EventSource site (repo-events, the selected branch's events, session events, job streams, logs).
- JS: Stream(name) returns synchronously a WebSocket-shaped object (binary frames); web/ imports it from /wails/runtime.js at run time rather than depending on @wailsio/runtime.

CONSEQUENCES: a new SSE path needs no Go change (the path is data), but it must pass validSSEPath (absolute /api/v1/, no '..'); a stream handler that blocks in Send with a stalled page holds a goroutine and queue space until the window closes, so the handler must end on c.Context().

WHAT THIS DOES NOT MEAN: a Stream is not a WebSocket upgrade (the ddceb81b constraint that the wails:// scheme handler cannot carry an upgrade still holds); and the page does NOT get EventSource's automatic reconnect for free from it: WailsEventSource and the Go loop re-implement reconnect, and do not emulate withCredentials or MessageEvent fields beyond type, data and lastEventId.

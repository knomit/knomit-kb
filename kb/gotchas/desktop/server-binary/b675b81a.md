# `knomit` has NO `--version` flag (`unknown flag`), only the `knomit version` subcommand, which prints its first line to STDOUT (it used to go to stderr via cobra's Println, which silently disabled the desktop's skew check); the desktop runs `knomit version` and reads line 1 of stdout, so do not rename, drop or re-route the subcommand (parity flag tracked in issue #501)

Running `knomit --version` fails with `unknown flag`; the root command has only the `version` subcommand (cmd/version.go), whose first line is the full build string (for example `0.5.3.4a9018c4`). `knomit-desktop --version` and `kb` do take a flag. tools/desktop/serverbin.go (`serverVersion`, `checkServerVersion`) therefore runs `<bundled knomit> version`, parses the first line, and compares it with the desktop's own build string to detect skew between the two shipped binaries.

**Consequence:** scripts and smoke checks of a bundle must call `knomit version`, not `--version`. Anything that changes the `version` subcommand's first-line output or removes it breaks the desktop's skew check. Adding a root `--version` alias is a separate follow-up (issue #501) and must keep `version` working.

**What this does NOT mean:** a mismatch between the two build strings is not itself a failure of the locator; `checkServerVersion` reports skew as a value for the caller (desktop PR 5) to decide on.

UPDATE (PR #503, merge 8be999a0, 2026-10-12): `knomit version` now writes through `fmt.Fprintln(cmd.OutOrStdout(), version.String())`. Before, cmd/version.go used cobra's `cmd.Println`, which writes to STDERR, so serverVersion (which reads stdout) got nothing and the 'could not read the bundled server's version' WARN fired on every spawn - the skew check shipped in #500 never ran in production. Its test fakes `echo`ed to stdout, so they could not see it: the fixture diverged from the real binary. cmd/version_test.go TestVersionCmd_PrintsToStdoutInARealProcess runs the real root command in a child process and reads the real stdout and stderr separately (red before the fix: stdout empty, stderr 'dev'). On Windows the probe is a 124 MB cold start and cost about 3 s of a crash restart (measured once; dated support).
CONSEQUENCE: any test of a consumer of a subcommand's output must run the real command (or assert stdout vs stderr separately); an `echo` stub proves nothing about which stream the real binary uses. Smoke checks of a bundle may use `knomit version 2>/dev/null`.
WHAT THIS DOES NOT MEAN: the 'skew is a value for the caller' wording above still holds; the desktop only WARNs on a mismatch and attach mode compares major.minor from the server's own /api/v1/version.

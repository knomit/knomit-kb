# Since #488 the desktop UI's API traffic arrives as the local-socket peer (bridge:uid:<n>@socket, Via == auth.LocalVia), not anonymous@none over TCP — so the UI passes the OAuth-approval gate WITHOUT the browser proof, and audit/client_sessions attribute UI actions to the bridge principal

Derived from reading the code at 2104fd6d (PR #488), not from a run that approved an OAuth request. Raised in review as finding 4; the security review is tracked in issue #492.

WHAT CHANGED. Before #488 the desktop webview called the server's TCP port as a loopback browser page: principal anonymous@none, so approving an OAuth request needed the full browser proof (Host with arrival port, X-Knomit-Client: web, Sec-Fetch-Site, Origin exactly http://<Host>, JSON Content-Type; kb 8a0aafb0) and the anonymous principal holding admin. Now every UI call is made by apiProxy, which dials the server with auth.DialLocal, the same dialer the kb bridge uses. The server's ConnContext therefore stamps the verified socket/pipe peer: bridge:uid:<n>@socket (unix) or bridge:sid:<SID>@pipe (Windows), Via == auth.LocalVia. The OAuth approval gate (kb 6d4a8514, requireLocalOrSameOriginAdmin) admits any LocalVia principal with no further proof, so the desktop UI, and any script running in a desktop webview window, can approve or deny OAuth requests without the browser proof. client_sessions and audit rows attribute UI actions to the bridge principal rather than to anonymous.

CONSEQUENCE: the UI proxy is now exactly as trusted as the desktop process; the server cannot distinguish a click in the UI from a bridge call by the same OS user (the proxy also strips x-wails-* and Origin, kb a95a53e1, so not even the window is visible). Any server rule that relied on 'the UI is anonymous loopback and so needs browser proof' no longer protects the desktop UI. The desktop never opens the OAuth listener, but the plain router's pending routes are mounted only when [oauth] is configured, so the exposure exists only on a desktop whose config enables OAuth.

WHAT THIS DOES NOT MEAN: it is not a new capability for local processes of the same OS user (they could always use the socket); it is not a defect the PR claims to have fixed or introduced silently (it is the design: the UI rides the socket); and the browser build, `knomit serve`'s served SPA and every TCP client are unchanged (still anonymous@none with browser proof). Not verified by a live approval.

# Since #488 the desktop FAILS to boot, with a dialog naming the socket path, when its own server could not bind the local socket/pipe (path held by another process, path too long, unsafe dir) — bootServer still degrades to TCP-only, bootKnomit no longer accepts that

BEHAVIOUR CHANGE (PR #488, merge 2104fd6d). Before: a held local socket (auth.ErrSocketInUse), a too-long path or an unsafe directory made bootServer serve TCP only and the desktop booted anyway (kb cd92bf55, TestBootServer_SocketInUseServesTCPOnly). Now bootServer records `server.local`, the path THIS server actually bound (empty when it did not), and bootKnomit, right after bootServer, shuts the server down, closes the app and returns an error when `srv.local == ""`: "the local socket <path> could not be opened (another process holds it, or the path is unusable); the desktop UI needs it — stop that process or set [socket] in knomit.toml".

WHY: the webview has exactly one route to the server, the local socket/pipe (the archtest forbids TCP on the UI path). Dialing a path somebody else holds would hand the window to a FOREIGN server: split-brain, where the UI shows another instance's repos while this process's tray, lockfile (server.json) and Settings readout describe its own. Falling back to the TCP port for the UI was rejected: it contradicts "no TCP for the webview".

CONSEQUENCE: a user who runs `knomit serve` on the same home (it owns the default socket) and also launches the desktop now gets the fatal dialog instead of a working window. This is a regression for that setup, accepted until the server is a separate process (then the desktop attaches to it instead of booting one). bootServer's own TCP-only fallback is unchanged and still pinned (srv.local must be "" in that test); only the caller changed.

WHAT THIS DOES NOT MEAN: it is not a rule for other listeners (a held [tls].addr still only WARNs and serves without TLS, kb 43f0bf91); and it is not about [auth].require (kb 0f2335f4 is the separate lockout rule). Test gap: the bootKnomit failure path itself has no test; what is pinned is the precondition (server.local equals the bound path, and is empty for a held socket) and that nothing on the UI path dials TCP.

# Browsers send Sec-Fetch-Site (Fetch Metadata) ONLY to potentially-trustworthy URLs — http://127.0.0.1, http://[::1] and http://localhost qualify, a DNS-rebound http://attacker.example and an http://10.x LAN IP do NOT — so "no Sec-Fetch-Site" means "not a browser" only when combined with a loopback Host check; the diag guard's order (peer, Origin/Sec-Fetch-Site, Host) relies on this, and its residual is a GET from a pre-2019 browser

The Fetch Metadata request headers (Sec-Fetch-Site, Sec-Fetch-Mode, Sec-Fetch-Dest) are attached only when the destination is a potentially trustworthy URL (W3C Fetch Metadata; Chrome ≥76, Firefox ≥90, Safari ≥16.4). Loopback IPs and localhost are trustworthy over plain http, so a modern browser hitting the runtime diag port at 127.0.0.1 always sends Sec-Fetch-Site and PR #292's guard refuses it with 403. A DNS-rebound page reaches the same port as http://attacker.example, which is NOT trustworthy, so no Sec-Fetch-Site arrives — and that case is caught by the Host check (421) instead. A LAN IP over http gets no Sec-Fetch-Site either, but is reachable only with [runtime].allow_remote, where any non-browser client can already do anything.

What still passes all three checks: a GET with neither Origin nor Sec-Fetch-Site, i.e. an <img>/<script> from an obsolete browser. It cannot READ (no CORS headers) and cannot MUTATE (every mutating diag route is POST-only, and a cross-origin POST carries Origin in every browser in use), but it can cost availability: /debug/pprof/profile?seconds=N and /trace?seconds=N have no cap on N and hold the single CPU profiler until the tab closes; /debug/pprof/heap?gc=1 forces a GC; goroutine?debug=2 stops the world. Accepted as a residual in #292 (Chrome's Private Network Access also blocks public→loopback). If it ever needs closing, cap `seconds` in a wrapper; do NOT require Sec-Fetch-Site, because curl, Prometheus and `go tool pprof` never send it.

WHAT THIS DOES NOT MEAN: Origin is a different header with different rules — it is sent on every cross-origin POST regardless of trustworthiness, which is why the Origin check, not Sec-Fetch-Site, is what stops the blind CSRF POST.

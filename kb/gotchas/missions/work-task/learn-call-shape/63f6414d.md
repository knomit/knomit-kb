# The mission work-task skill never names knomit_learn's required `moment_name` (or the `facts` array), and Claude Code defers MCP tool schemas, so a session's first take is refused with "moment_name is required" and some sessions give up having taken nothing

Observed in the first IPO mission real run (2026-10-02, f05522da): in every headless session the first knomit_learn (the take, work-task step 2) was sent as flattened fields without `facts` or `moment_name`, because Claude Code had loaded only knomit_bind and knomit_skill's schemas and the skill text (examples/mission/.knomit/skills/work-task/SKILL.md) describes the fact's fields but not the call shape. Most sessions recovered by loading the schema (ToolSearch) and retrying; 2 of 13 sessions concluded the tool was broken and exited after ~25 s and ~0.22 USD having taken nothing. The `lease` trigger re-woke the machine at the copy's lease and the next session drained the queue, so no task was lost, but each give-up cost an extra session start and ~5 minutes.

Fix direction: state the call shape in the skill ("knomit_learn with moment_name and facts: [ ... ] and retract: [...]") for the take and the ack, or have the recipe prompt tell the session to load the knomit write tools' schemas first. What this does NOT mean: the server is not wrong to refuse; the refusal message is accurate.

ADDRESSED by knomit PR #410 (mission-template-post-run, merged at 8bbd7963; examples/mission): the work-task skill now has a "Call shapes" section with one copy-able JSON skeleton per knomit call (knomit_bind, knomit_skill, knomit_repos, knomit_query, knomit_explain, knomit_learn for the take/results/ack with moment_name, facts, retract and trace, knomit_update, knomit_retract, knomit_experiment open/commit/rollback, knomit_review and knomit_hypothesize start/continue), post-task has the posting skeleton, and the recipe prompt tells the session to load a knomit tool's schema first if it is listed without one. TestMissionTemplate_SkillCallShapes holds every skeleton against the schema each tool serves (unknown key, missing required key, missing binding, or a write without trace is red). This fact stays as the record of the observed run; see kb/architecture/examples/mission/knowledge-base/005163fe.md for the template side.

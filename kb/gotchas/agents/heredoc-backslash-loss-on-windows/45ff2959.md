# On this Windows box EVERY backslash PAIR in the agent Bash tool's command string collapses to one, whatever the quoting — heredocs, perl -0pi and single-quoted arguments all lose it; a LONE backslash survives, and the PowerShell tool is unaffected

MEASURED on the Windows dev box, writing four literals through the agent's Bash tool with `printf '%s\n' '<literal>'` (single-quoted, so bash itself does nothing to them) and reading the file back through the PowerShell tool:

    sent  A\B        -> on disk  A\B        (lone backslash SURVIVES)
    sent  A\\B       -> on disk  A\B        (pair collapses to one)
    sent  A\\\\B     -> on disk  A\\B       (four collapse to two)
    sent  \\.\pipe\x -> on disk  \.\pipe\x  (the real case)

SO THE RULE IS: runs of backslashes are HALVED — the command string is processed one extra time as if by a backslash-escape layer. A single backslash is not touched, which is why most commands never reveal this and why it looks like a heredoc quirk when it bites.

THE SCOPE IS THE BASH TOOL'S COMMAND STRING, not any particular construct in it. Observed losing a pair via a QUOTED heredoc (`<<'EOF'`), via `perl -0pi -e`, and via a plain single-quoted argument to `gh issue edit --title`. The same PowerShell literals through the PowerShell tool come back byte-identical, including `\\.\pipe\x`.

NAMED MISREADING, and it cost an extra round trip: **"single quotes make it safe"**. They do not. Nothing about the quoting inside the command changes this, because the halving happens before bash parses anything. "Use a quoted heredoc" is the same mistake wearing a different hat.

WHY IT HURTS: it COMPILES. The failure surfaces far from the cause — in knomit#245 as `ListenPipe: Incorrect function` on a path that LOOKS right in the log, because `%q` of `\.\pipe\x` prints `"\\.\\pipe\\x"`, which reads exactly like the correct value to anyone scanning output. It also silently corrupted a Markdown file and a GitHub issue title in the same session.

TWO VERIFIED REMEDIES:

1. Put the text in a FILE with the Write/Edit tools, then pass the file: `--body-file <path>`, or `--title "$(cat <path>)"`. No backslash ever appears in the command string, so nothing can halve it.
2. Use the PowerShell tool with single-quoted literals. Measured unaffected above; it is how GitHub issues #262 and #265 were repaired after the Bash route failed.

VERIFY AFTERWARDS with `grep -nF` on the raw line, or read the value back through the PowerShell tool — NOT by echoing it through another Bash command, which can halve it a second time and show you what you expected to see.

This is a property of the AGENT HOST's shell layering on this machine, not of Go, winio, gh or knomit.

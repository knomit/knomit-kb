# Observed: opening a fact's version timeline does not push state.navStack (SET_AS_OF only sets asOf), so Backspace/Back from the timeline pops the step BEFORE the fact was opened and the fact disappears; tracked as knomit#486 (a product decision, not a settled design)

Observed at the dev merge of PR #484 (a2439e31): in web/src/state.ts the reducer case `SET_AS_OF` is `{ ...s, asOf: a.asOf }` (no `navStack: pushNav(s)`), whereas the cases that change facts, filters or sort push. NAV_BACK restores the entry on top of navStack, which was pushed when the fact was opened and so describes the state before the fact. Opening the timeline therefore adds no step, and Back from it leaves the fact view rather than returning to the fact. The old UI returned to the same fact. e2e/tests/ui/history.spec.ts ('Backspace from history leaves the timeline') asserts only that `timeline-nav` is gone and the left panel is visible, and says so in a comment; it neither covers nor hides the behaviour. Found by reading the reducer and the spec comment, not re-run as a separate experiment. Tracking issue: https://github.com/knomit/knomit/issues/486 (open at 2026-10-12), whose expectation is that Backspace returns to the fact.

Consequence: do not write an e2e expectation that Back from the timeline returns to the open fact; and do not 'fix' it by pushing in SET_AS_OF without reading kb/architecture/ui/navigation/navstack-is-also-the-trail/1dd158ac.md, because navStack is also the time-travel breadcrumb trail and every SET_AS_OF (scrubbing, exiting a diff) would then push too.

WHAT THIS DOES NOT MEAN: this is not a decided design and not a statement that the timeline should not be a navigation step; it is the behaviour as it stood, awaiting a product decision. Re-check state.ts before relying on it; it is expected to change when #486 is resolved.

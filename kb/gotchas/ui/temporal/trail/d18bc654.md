# Browse as of a commit with no fact open must not build a trail crumb or fetch a fact title: an empty factPath made the breadcrumb request a fact with no path and the server answered 400 Missing fact path

selectTrail built the current crumb with factPath '' whenever no fact was open, and TrailBreadcrumb fetched a title for every crumb, so any non-live view without a fact (the filter bar's at: with no fact open) sent a fact read with an empty path; handlers_commit_anchored.go answers that 400 Missing fact path. Fix at the client (the server's 400 for a genuinely missing path stays): selectTrail returns no crumb for a view that names no fact (live or not), TrailBreadcrumb skips any crumb whose factPath is empty, and StatusFooter clamps the hop count at 0 because the trail can now be empty. Tests: state_asof.test.ts (selectTrail with no fact open) and TrailBreadcrumb.test.tsx (never asks for a fact title when a crumb names no fact). Misreading to avoid: the trail is not guaranteed to be non-empty; callers must not index trail[trail.length-1] without a check.

Leftover crumbs: with no fact open the trail can still hold a crumb. Reach it through the bar alone: open a fact, add a path chip (the fact closes and its departure is on the stack), then anchor with at:<commit>; the trail is [that fact]. The last crumb used to be drawn in the current style by position alone. TrailBreadcrumb now takes factOpen (default true) and FilterBar passes (state.factPath ?? '') !== ''; a crumb is current only when factOpen and it is the last, so with no fact open every crumb is an ordinary clickable back-crumb. TrailCrumb gained no field. Tests: TrailBreadcrumb.test.tsx (current crumb) and FilterBar.breadcrumb.test.tsx (that path, through the bar's input and the real reducer).

Trail boundary: selectTrail stops at a navStack entry stamped fromChat (a landing in Browse from a chat), because back from there is the chat; what Browse held before it is not a crumb.

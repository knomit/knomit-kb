# Browse as of a commit with no fact open must not build a trail crumb or fetch a fact title: an empty factPath made the breadcrumb request a fact with no path and the server answered 400 Missing fact path

selectTrail built the current crumb with factPath '' whenever no fact was open, and TrailBreadcrumb fetched a title for every crumb, so any non-live view without a fact (the commit link's Browse as of a commit) sent a fact read with an empty path; handlers_commit_anchored.go answers that 400 Missing fact path. Fix at the client (the server's 400 for a genuinely missing path stays): selectTrail returns no crumb for a view that names no fact (live or not), TrailBreadcrumb skips any crumb whose factPath is empty, and StatusFooter clamps the hop count at 0 because the trail can now be empty. Tests: state_asof.test.ts (selectTrail with no fact open) and TrailBreadcrumb.test.tsx (never asks for a fact title when a crumb names no fact). Misreading to avoid: the trail is not guaranteed to be non-empty; callers must not index trail[trail.length-1] without a check.

# currentPath() never returns '' — it falls back to the ontology root, so "am I at the root" is a comparison against that root, never an emptiness check

`currentPath(state)` is `state.filters.find(f => f.category === 'path')?.value || state.ontologyRoot || 'kb'`. With no path chip it returns the ONTOLOGY ROOT — `'kb'` — never the empty string.

So the root test is `path === (state.ontologyRoot || 'kb')`. Writing `path ? path.split('/') : []`, the natural shape if you assume an unscoped path is empty, yields `['kb']` at the root: the Library header would render a folder literally named `kb` instead of its root state, and every ancestor computation would be off by the root segment.

This is easy to get wrong from the call site, because `api.browse(repo, branch, path, ontologyRoot)` takes the path and the ontology root as SEPARATE arguments — which reads as though `path` excludes the root. It does not.

WHAT THIS DOES NOT MEAN:
- Not "the ontology root is always 'kb'". It comes from the server (SET_STATUS) and is per-repo; the literal 'kb' is only the pre-bootstrap fallback. Compare against `state.ontologyRoot`, do not hard-code.
- Not "a path chip always exists when scoped". Navigating to the ontology root itself writes a chip whose value IS the root, which is why the comparison is against the VALUE and not against chip presence.

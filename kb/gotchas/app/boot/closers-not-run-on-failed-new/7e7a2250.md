# app.New appends the production embedder's Close to a.closers as soon as it is built, but every later error return in New (manager.Start, grants seed, OAuth setup) returns nil, err WITHOUT running a.closers — a boot that fails after the embedder exists leaks the ONNX session and tokenizer

In internal/app/app.go, New builds the embedder (newProductionEmbedder, via Options.Embedder == nil) and does `a.closers = append(a.closers, e.Close)`. Every error path after that point returns `nil, err` directly; only a successful New hands the caller an *App whose Close runs the closers. So a boot that fails at manager.Start, at seedOwnPrincipal, or at OAuth wiring has already created an ONNX session and a tokenizer that nothing destroys. Both server boot paths (cmd/serve and tools/desktop) exit or report the error and do not retry in-process, so today the leak lasts only until process exit — which is why it has not shown up.

Consequence: anyone adding an in-process retry of New (the desktop app rebooting on a settings change, a test that boots repeatedly expecting failure) will accumulate ONNX sessions. The fix shape is a `defer func(){ if err != nil { a.Close() } }()` style unwind at the top of New, or building the embedder last. Tests that pass Options.Embedder are unaffected: New does not own an injected embedder's lifetime.

Found by the reviewer session during PR #284's review; pre-existing, not introduced there. Not fixed in #284 (out of scope).

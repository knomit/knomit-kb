# A directory NAMED knomit is not the plugin dir — locatePluginDir must corroborate the name with an mcp_config.json, or a workspace called knomit shadows its own plugin

`locatePluginDir` resolves the directory holding the Antigravity plugin's `mcp_config.json`, primarily from the hook's working directory, since agy runs a hook with cwd set to the directory containing the `hooks.json` that registered it — `<workspace>/.agents/plugins/knomit`.

The sanity check on that cwd was `filepath.Base(cwd) == pluginDirName` (`pluginDirName == "knomit"`) with an unconditional early return, and no check that an `mcp_config.json` was actually present. A workspace directory that is itself named `knomit` therefore satisfied it: knomit's own checkout is `.../knomit/knomit`, and any user who clones into `~/src/knomit` has one too. cwd at the workspace root matched on the name, returned the workspace root, and — because the match returned early — skipped BOTH remaining probes: the `cwd/.agents/plugins/knomit` descent and the `workspacePaths` fallback. `pluginBinding` then found no `mcp_config.json`, and the user was greeted on every single conversation with `skipNoBinding`: "knomit found no usable knomit server in this plugin's mcp_config.json … Re-run `knomit-bridge antigravity init`" — advice that cannot fix it, because a perfectly good plugin dir was sitting one level down, never read.

**The consequence to act on.** A directory-name convention is a HINT, never evidence. When code identifies a directory by name, pair the name with a file that only the real directory has, and let a failed corroboration fall through to the remaining probes rather than returning. The fix is one clause — `filepath.Base(cwd) == pluginDirName && isPluginDir(cwd)` — and `TestPreInvocation_WorkspaceNamedKnomit_StillBinds` is the regression guard; it fails against the previous code with the exact `no_binding` notice.

**WHAT THIS DOES NOT MEAN.** This is not "stop trusting cwd" — cwd remains the primary and correct source, and the `workspacePaths` fallback exists for a platform change to hook cwd, not for this bug. Nor is it "validate more": the extra probes were already written and correct, and the defect was the EARLY RETURN that prevented them from ever running. A name check that falls through on failure would have been harmless.

**Why it survived review.** Every test used a temp dir with a random basename, so no test ever exercised the one basename that triggers it — and the repo where the code was written is itself the failing case.

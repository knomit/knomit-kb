# Two Antigravity platform facts that contradict its shipped docs: invocationNum is 0-BASED, and workspace customizations need a REGISTERED workspace (cwd is not enough)

Verified live against `agy` 1.1.14; both contradict what the shipped documentation implies.

**1. `invocationNum` is 0-based.** The first model invocation of a conversation reports `invocationNum: 0`. The only example in the shipped hooks doc shows the value `3`, which invites the assumption that it counts from 1. A `== 1` guard therefore SKIPS the first turn and fires on the second — the exact opposite of a session-start hook's intent, and it looks like it works because something is still injected. `hookPreInvocation` gates on `invocationNum == 0` AND a per-`conversationId` marker file, because the numeric value's behaviour across `/clear`, `/fork` and `/resume` is unspecified by the platform; the marker is what holds regardless.

**2. Workspace customizations require a REGISTERED workspace — being in the directory is not enough.** Running `agy -p …` from inside a project directory registers nothing: `workspacePaths` arrives as `[]` and the ENTIRE plugin — skills, rules, hooks, MCP servers — is absent, silently, with no error and no warning. Passing `--add-dir <workspace>` loads all of it; launching `agy` interactively from the directory registers it normally. Measured directly: `agy -p "/skills" --add-dir <ws>` listed 10 knomit skills, and the identical command without `--add-dir` listed 0.

**Consequence for anything driving agy programmatically:** it MUST pass `--add-dir`, or it gets a silently inert integration. This is why `antigravity init` prints the requirement and the README carries it as a callout — there is no other signal a user could notice.

**A testing trap this creates.** `os.UserCacheDir()` honours `XDG_CACHE_HOME` on Linux but returns `$HOME/Library/Caches` on darwin and ignores it. A test that redirects only `XDG_CACHE_HOME` and then asserts about the marker directory is checking a path the code never writes to — it PASSES while guarding nothing. Redirect both `HOME` and `XDG_CACHE_HOME`, and derive the expected root from `os.UserCacheDir()` rather than from the environment variable.

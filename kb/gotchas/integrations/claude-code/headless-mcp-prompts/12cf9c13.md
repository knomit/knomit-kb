# Measured on Claude Code 2.1.284 (2026-09-29): headless `claude -p "/mcp__<server>__<prompt> <args>"` DOES expand an MCP prompt — it calls prompts/get with {"args": "<args>"} and runs the returned messages; the docs only promise this for skills and custom commands

Hand check for F08 PR C (informational, not a gate). A throwaway stdio MCP server exposing one prompt `magic` (one optional argument `args`) was attached with `claude -p "/mcp__hc__magic" --mcp-config mcp.json --strict-mcp-config`. The server's request log showed initialize → notifications/initialized → tools/list → prompts/list → prompts/get {"name":"magic","arguments":{}}, and the output was exactly the token the prompt asked for. With `/mcp__hc__magic task-7` the call was prompts/get {"arguments":{"args":"task-7"}} — the whole remainder lands in a single declared argument named args, which is the one argument knomit's skill prompts declare.

Consequence for F08 PR D: a recipe-started `claude -p` session CAN be started on a repo skill by putting `/mcp__knomit-repo-<repo>__<skill> <task path>` in the prompt string (server key from internal/serverkey). The knomit_skill tool remains the model-invocable path for a session that is merely TOLD to follow a skill.

What this does NOT mean: it is a measurement of one Claude Code build, not a documented contract (code.claude.com headless docs name only skills and custom commands); re-check on a later version before relying on it, and no knomit code depends on it.

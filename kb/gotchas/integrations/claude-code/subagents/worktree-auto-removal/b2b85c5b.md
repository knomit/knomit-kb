# A worktree-isolated Claude Code subagent whose only changes are gitignored files (.claude/…) loses them: the worktree is auto-removed when the agent finishes

When a Claude Code subagent is spawned with isolation "worktree" and every file it writes lies under a gitignored path (in knomit: anything under `.claude/`, e.g. `.claude/plans/`, `.claude/future/`), git sees the worktree as unchanged, and the harness removes the worktree when the agent completes. Its outputs are deleted with it. The completion notification for such an agent carries no worktreePath.

Observed 2026-09-29: a documentation subagent edited 26 files of `.claude/future/fleet/` in its worktree; on completion the worktree and all edits were gone. Recovered by resuming the same agent (its transcript survives) and having it rewrite the files into the session scratchpad.

Consequence: any subagent whose deliverable lives under a gitignored path (plans, reports, review verdicts, design docs) must ALSO write it to the session scratchpad (`/private/tmp/claude-501/<project>/<session-id>/scratchpad/`), and the coordinator copies it from there. Workers that make git commits on a branch keep their worktree and are not affected.

WHAT THIS DOES NOT MEAN: it does not mean every worktree agent's files are lost — a worktree with committed or tracked changes persists; and reviewers whose worktree persisted earlier did so only because something tracked changed or the harness kept it, so do not rely on that.

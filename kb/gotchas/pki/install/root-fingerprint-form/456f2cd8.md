# `knomit identity install --root` takes ONE form — 64 hex, SHA-256 of the root KEY's SSH wire encoding (RootID) — and `openssl x509 -noout -fingerprint -sha256` is NOT it (that hashes the root CERTIFICATE's DER): a different digest, so no reformatting can make it match; anything not 64 hex is refused as malformed, naming the form and where to get it

Rehearsal finding F3 (2026-10-02): the operator expected the openssl certificate fingerprint to work. The user's ruling (relayed by the master, overriding the brief's 'accept both'): keep one form and document it. Built on branch fix/rehearsal-findings (cmd/identity.go parseRootFingerprint, rootFingerprintForm): --root is trimmed and lower-cased, must match ^[0-9a-f]{64}$, else 'is not a fleet root fingerprint' + the form + the ways to get it (+ a hint naming the openssl certificate hash when the value contains ':' or 'fingerprint='); a well-formed value that differs is still 'is not the bundle's fleet root'.

Ways to get the value, MEASURED on a throwaway root (OpenSSH 10.3, OpenSSL 3.6.4, macOS LibreSSL 3.3.6): (1) `knomit identity init-master` prints it on a `# fleet root fingerprint:` line (added in the fix); (2) in the master directory: `ssh-keygen -y -f root.key | awk '{print $2}' | base64 -d | shasum -a 256` (asks the root passphrase) gives exactly knomit's hex; `ssh-keygen -l -E sha256` on that public key prints the SAME digest in base64 (SHA256:…, unpadded), not hex; (3) from root.crt alone with OpenSSL 1.1.1+/3.x: `{ printf '\000\000\000\013ssh-ed25519\000\000\000\040'; openssl x509 -in root.crt -noout -pubkey | openssl pkey -pubin -outform DER | tail -c 32; } | shasum -a 256` reproduces it — macOS's /usr/bin/openssl (LibreSSL 3.3.6) CANNOT load the Ed25519 key and prints a wrong hash after an error, and `ssh-keygen -i -m PKCS8` cannot import the Ed25519 key from root.crt's PUBLIC KEY block; (4) on an instance, `knomit identity install` without --root prints `bundle fleet root: <fp>`, and `knomit identity show` prints the installed root as `root: <fp> ("<cn>")` (added in the fix).

What this does NOT mean: the openssl certificate fingerprint is not 'the same value in another format' — it identifies the certificate, so even a format-normalising parser comparing it to RootID could never match (the reviewer's gate block). Tests: TestIdentity_RootFingerprintForm (expected value computed independently with ssh.NewPublicKey+sha256; openssl values from sha256(cert DER) in OpenSSL-3 and LibreSSL spellings; truncated, SHA-1-length and junk refused; nothing installed).

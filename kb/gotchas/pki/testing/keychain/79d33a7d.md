# No test may touch the real OS keychain: internal/pki and cmd TestMain call keyring.MockInit(), pki tests inject a fake pki.Keychain, and cmd tests swap the rootKeychain variable — a new test binary that reaches pki.OSKeychain needs the same TestMain

`pki.OSKeychain()` calls github.com/zalando/go-keyring, whose provider is a PROCESS-GLOBAL variable. `keyring.MockInit()` swaps it for an in-memory map; nothing else stops a test from writing items into the developer's real macOS Keychain or Secret Service.

WHAT IS IN PLACE. `internal/pki/main_test.go` and `cmd/main_signer_test.go` call `keyring.MockInit()` in TestMain. pki custody tests pass a `fakeKeychain` (injectable Get/Set/Delete errors). cmd tests replace `rootKeychain` via `useKeychain(t, kc)`, and `stdinIsTerminal` via `onTerminal(t)` because export-root refuses off a terminal.

CONSEQUENCE. Any OTHER package whose tests run `knomit identity init-master`/`import-root` through cmd, or call `pki.CreateRoot`/`OpenRoot` with `pki.OSKeychain()`, must add the same TestMain line first. Fixtures built with `pkitest`/`pki.NewRoot` are file-only and never touch a keychain.

SIDE EFFECT. Because cmd tests' default rootKeychain is the go-keyring mock, `init-master` in an existing cmd test now stores into the mock keychain and enroll no longer needs a passphrase; a test that means to exercise the passphrase file must make the keychain refuse (TestIdentity_EnrollNeedsAPassphraseAndTheRightOne does).

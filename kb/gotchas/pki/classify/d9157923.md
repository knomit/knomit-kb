# root.crt present without instance.crt or the CRL makes ClassifyOrigin refuse EVERY https attach, forges included ('trust files unusable'): it fails closed with a named message, and is only an edge state since pki.Uninstall removes all three files

WHAT (review nit N8, verified at merge 0488c05d). ClassifyOrigin decides 'this instance holds no fleet trust' by one test: root.crt is absent in [tls].dir. If root.crt EXISTS, it builds pki.ClientConfig(dir, keyPath), which needs instance.crt, root.crt and crl.pem together. A directory with root.crt but without instance.crt or the CRL makes ClientConfig fail, and ClassifyOrigin returns 'this instance's fleet trust files are unusable, so the origin cannot be judged' for ANY https origin, an https forge such as GitHub included. Nothing is dialled and nothing is stored.

WHY IT IS ACCEPTED. It fails closed and names the cause. The state is an edge: pki.Uninstall removes all three files, pki.InstallBundle writes the set (an I/O failure between its renames can leave a mixed set, which the next install repairs), and fleet join/create refuse when ANY of the three exists (trust_installed).

CONSEQUENCE. If a user reports 'I cannot add a GitHub remote' on an enrolled-looking instance, check [tls].dir for a lone root.crt before blaming the network; the fix is to complete or remove the set (join/leave), not to special-case forges. Do not weaken the test to 'any of the three files' or 'ClientConfig error means not a peer': that would turn unusable trust into stock https for a host that might be a peer.

MISREADING. 'Classification refuses https whenever the instance is in a fleet': it refuses only when the trust set is incomplete; with a complete set a forge is simply 'not a peer'.

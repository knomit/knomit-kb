# drone runs in a git worktree that contains only TRACKED files; gitignored .claude/skills and dist/ artifacts need --link

tools/drone runs claude headless in a fresh `git worktree` checked out off the base branch. A worktree contains only TRACKED files, so anything gitignored is ABSENT from the run's working dir — even though CLAUDE_PROJECT_DIR resolves to the worktree.

WHAT IS AND IS NOT TRACKED (changed since this fact was first written). `.gitignore` no longer ignores `.claude/` wholesale. Commit 324b0e08 ("chore: track .claude skills and settings.json in git") replaced `.claude/` with `.claude/*` plus `!.claude/skills/` and `!.claude/settings.json`. So today:

- `.claude/skills/` — TRACKED, present in the worktree. Project skills (the /knomit-* slash commands) load with no linking.
- `.claude/settings.json` — TRACKED. Hooks and permissions DO apply, so the SessionStart auto-recall fires.
- `CLAUDE.md` — tracked at the repo root, always present.
- `dist/` — still gitignored (`.gitignore:52` `/dist/`), so `dist/knomit-bridge` is ABSENT and still needs `--link dist`.
- everything else under `.claude/` (worktrees, plans, local state) — still ignored.

So the remaining drone requirement for knomit is `--link dist` plus the default `--allow-local` (loopback for the bridge MCP server on :19278).

TRAP — `--link .claude/skills` NOW FAILS. linkArtifacts checks only that the link SOURCE exists; it then calls os.Symlink with no test on the destination, so symlinking onto the worktree's real, tracked `.claude/skills` directory returns "file exists" and drone errors out. An older drone config carrying `link = ["dist", ".claude/skills"]` must drop the second entry. This is a hard failure, not a no-op.

WHAT THIS DOES NOT MEAN:
- Do NOT conclude `.claude/` is tracked. Only `skills/` and `settings.json` are; the directory is otherwise ignored.
- Do NOT `--link .claude` (the whole dir) — the worktree itself lives at `.claude/worktrees/<name>`, so that creates a symlink loop. This was true before and remains true.
- Do NOT assume every gitignored artifact is now handled: `dist/` is still absent and still needs linking. The tracked-vs-ignored split is the thing to check, not a blanket rule about `.claude/`.

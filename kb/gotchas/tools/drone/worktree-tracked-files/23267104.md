# drone runs in a git worktree that contains only TRACKED files; gitignored .claude/skills and dist/ artifacts need --link

tools/drone runs claude headless in a fresh `git worktree` checked out off the base branch. A worktree contains only TRACKED files, so anything gitignored is ABSENT from the run's working dir. In this repo `.claude/` is fully gitignored, so the project skills under `.claude/skills/` (the /knomit-* slash commands), `.claude/settings.json` (hooks, permissions), and gitignored build outputs like `dist/knomit-bridge` are all missing — even though CLAUDE_PROJECT_DIR resolves to the worktree.

Consequences and fixes (verified end-to-end with a real drone run): (1) CLAUDE.md IS loaded — it's tracked at the repo root, so it's in the worktree. (2) Project skills are NOT loaded unless materialized; drone's `--link PATH` (repeatable; TOML `link=[...]`) symlinks repo-relative paths from the main checkout into the worktree. Use `link = ["dist", ".claude/skills"]` to bring in the bridge binary and skills. (3) The knomit MCP loads (it's in the tracked `.mcp.json`) but needs `--link dist` (bridge binary) + `--allow-local` (looknomitck). (4) Hooks in `.claude/settings.json` do NOT run (gitignored, not linked) — the SessionStart auto-recall won't fire; the drone prompt instructs knomit use instead. WARNING: never `--link .claude` (whole dir) — the worktree itself lives at `.claude/worktrees/<name>`, creating a symlink loop; link `.claude/skills` specifically.

# A FactSet back link carries the unit that FIRST wrote its target (recorded in the written prefix: extra.unit, wRoot, wRes) and NO number: a target first written as a descendant sits at a tree position only that unit's plan knows, so a number would cost a re-plan or a stored string per fact

As built on feat/factset-ui (after dev 3f4a8b84): fsState.lookup (internal/corpus/materialize/factset_state.go) returns every BACK link with plink.unit = the unit that first wrote the target and no number, in all cases: the extra written set (xentry.unit), a result already written (wRoot[i]) or a reserved fact already written (wRes[i]); linkTo builds the remaining case (a result or reserved fact whose designated unit is earlier) the same way, so no back link carries a number any more. Forward links are unchanged: unit plus number ('N' for a result, 'N.k' for a reserved direct reference). factsetNode emits l.unit for both directions and l.number only where set. The lens facade needs no new code: lensEntry.remap maps any link with Unit > 0, so a lens back link names the GLOBAL unit (TestLensFactSet_BackLinkNamesTheGlobalUnit). The MCP instructions text changed with it (instructions_version materialize-factset/3).

WHY NO NUMBER: the number of a target first written as a descendant ('w.x.y') is assigned in planner.sections and lives only in that unit's plannedUnit (kept plans: an LRU of 8 per entry). Getting it would need either the first writer's ordinal stored beside the unit plus a planUnitOf(w) per distinct earlier unit at page time (a re-plan when not kept), or a number string stored per written fact against session.factset_memory_mib. The user ruled instead that links show the target's title, not a number (kb decision fact on FactSet link stubs), so the unit, which is free, is all a back link needs: a reader who sought past the target seeks to that unit.

CONSEQUENCE: never read link.number on a back link (it is absent); use link.unit to seek and the anchor to scroll. The agent export is unaffected: renderFactSetNode resolves a back link's '(see N)' through factsetNumbers, filled in document order.

WHAT THIS DOES NOT MEAN: it does not mean the unit is where the fact sits at its own designated place (a result written earlier as someone's descendant names the unit that wrote it first, not its own unit); and it does not make section headings unnumbered (nodes keep number and tree_depth).

# TestFactSet_F4_FrameAncestors flaked under -race because its seed assumed every write lands in ONE wall-clock second: the recent-sorted search orders by whole-second commit time (newest first), then path, so a write that crosses a second boundary reorders the roots; fixed by write order, not timing

Observed while verifying PR #706 at 56c34eb7: `go test -race ./internal/corpus/materialize/` failed once in TestFactSet_F4_FrameAncestors. The failure text was not captured. The test then passed in 5 isolated -race runs, 3 whole-package -race runs and the full non-race suite. The test touches only the repo path (frames on one repo, sort=recent), which the lens facade does not change. Its seed comment says 'All in one second, so the search lists by path (e before f before n)'. PREDICTION: when the seed's writes straddle a second boundary (more likely under -race, which slows writes), committed_at ties break differently and the unit order, and so the expected rows, change. CHECK: capture the failure text, or stamp the seed commits explicitly. Until then, treat a lone F4 failure under -race as this flake, not as a regression, and do not cite it as one.

CONFIRMED (PR #707). Forced by sleeping 1.1 s after every seed write (every commit in a different second): the subtest 'ancestor reserved for a later unit is a forward link' failed with rows starting {1 u/n}, {1.1 f/a}, {back 1.1 f/a}, {f/b}, {f/m}, {2 u/f} instead of {forward 2.1 f/a}, {f/b}, {f/m}, {1 u/f}, {2 u/n}, {2.1 f/a}. Cause: n (path after f) was written LAST and the test expected f before n, true only on the path tie-break inside one second; the 'e' subtest was already safe because e (path before f) was written last, so it is newest or tied.

FIX (test only): write the other root BEFORE the frame writes when its path sorts after f/ (so f is newer or tied, f before n either way), AFTER when it sorts before. RULE: a seed that relies on the recent-sorted order must write so the wanted order holds both within one second (path asc) and across seconds (newest first); seedABC already does (c, b, a). WHAT THIS DOES NOT MEAN: the product's ordering is not buggy; commit times are whole seconds by design.

TRIAGE of a full -run FactSet sweep with a 1.1 s sleep after every seed write (3 failures). (a) TestFactSet_RepoUnpinnedReplayGolden shared the assumption: v was written after u and the golden expects u first, true only on the path tie-break inside one second; fixed (PR #707) by writing v before u, golden file unchanged, passes under the gap and at -race -count=20. (b) TestFactSet_F18_WatermarkRace and TestLensFactSet_SyncOnR2DuringTheFanOutIsBusy are artifacts of the gap, left alone: their search hook writes a fact inside a 300 ms anchor-wait deadline, so a 1.1 s write overruns the deadline (F18: 'the index moved while the search ran'; lens: the hook ran once, not twice). No real environment makes a single write outlast the deadline. RULE: gap-sweep a seed change by sleeping in the seed writers only, not in writes made by a search hook.

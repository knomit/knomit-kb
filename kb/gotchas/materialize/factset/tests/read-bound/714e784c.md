# The F14 per-unit bound (MaxUnitQueries <= Depth+2) cannot detect a LOST read-ahead: without it a unit still reads within Depth+2; compare per-unit and per-page reads against a baseline FactSet over the same data instead

Found while testing refactor/factset-pinned-seam. Stats.MaxUnitQueries counts a unit's own index reads BEYOND the read-ahead. On the seedABC fixture with the read-ahead working, every unit reads 0 itself (the window supplied its roots' rows and metas); with the read-ahead keyed by the wrong repo (planner.wireID instead of homeID for a home that is not the write repo), units read 2 each at depth 1, still far under Depth+2 = 3. So 'MaxUnitQueries <= Depth+2' (TestFactSet_F14_QueryBoundAndNoGit's assertion) passes with the read-ahead entirely disabled for that repo.

OPERATIONAL CONSEQUENCE: to prove the read-ahead covers a new case (a lens sub-FactSet over a non-write home, a new window shape), assert EQUALITY of MaxUnitQueries and of the later pages' IndexQueries against a baseline FactSet that is known to use the read-ahead over the same data, as TestFactSet_Pinned_ReadBoundHoldsOnTheHome does (sub over R vs R's own repo FactSet, depth 1 and 3).

WHAT THIS DOES NOT MEAN: F14 is not wrong; it bounds the planner's level reads (no per-fact reads, no git). It just is not a read-ahead test.

# A lens member that has NEVER had a settled watermark (HistoryQuery.SettledOnce false: no settled_once:<branch> marker and no watermark) is EMPTY on a lens FactSet: no roots, no search leg, not waited on, no anchor; a member settled once and now syncing or rebuilding still makes the call wait; a path filter whose first segment is not a member's ontology topic drops that member from the fan-out

RULING (user, 2026-11-01, option b; built on fix/lens-factset-strings, PR #708): a lens member that has NEVER had a settled watermark is EMPTY. lensFactSetFirstPage drops it from the searched targets BEFORE the fan-out (fsCall.neverSynced), so no leg reads its unsettled index, the sandwich does not wait on it, env.anchors leaves it out, and it stays an empty sub (its name still labels refs into it, ruling Lens 1). No page note, no new visible text.

THE PREDICATE: neverSynced(m) = !HistoryQuery.SettledOnce(ctx, m.branch), where SettledOnce is true when meta settled_once:<branch> (index.SettledOnceKey) is present OR last_commit:<branch> is non-empty (one statement). The marker is written ('1') by the index whenever the watermark is set to a commit (casLastCommit, setLastCommit), by Index.Rebuild BEFORE it clears the watermark when the branch already had one (a backfill for stores indexed before the key existed; no migration), and by vcs CreateBranch together with the inherited watermark; nothing but vcs DropBranch removes it.
- A member settled once and now rebuilding (watermark "", generation set) or syncing (watermark set, pending marker) is NOT never-synced: it waits exactly as before (TestLensFactSet_RebuildingMemberIsNotNeverSynced, TestLensFactSet_SyncOnR2DuringTheFanOutIsBusy).
- A member whose FIRST build is an Index.Rebuild (how a new member is built: stages.go spec.full) reads ("", "1") while that Rebuild runs: no marker, so EMPTY; if that initial Rebuild FAILS it stays empty (never permanently busy). TestLensFactSet_InitialRebuildMemberIsEmpty pins both; sabotage 'the old (watermark "" AND generation "") predicate' makes the in-flight case busy.
- A first incremental sync in flight, a dropped branch and a store whose index DB was wiped have no marker and no watermark: empty.
- A store indexed before this change reads settled through its watermark, and stays settled through a Rebuild via the backfill (TestSettledOnce_LegacyStoreRecreatedAndDroppedBranches, which also checks that a created branch carries its own marker and a dropped one has none).

THE STORE-WIPE WINDOW (accepted under ruling b): a member whose index DB is lost (wiped, recreated, restored without its index) reads as never-synced until its first build finishes, so for that window its facts are SILENTLY ABSENT from every lens FactSet created then: no root, no anchor, no note. Such a FactSet is frozen that way (anchors and roots are frozen at creation); a new FactSet after the build includes the member.

REPO FACTSETS ARE UNCHANGED: a plain repo FactSet on a never-synced repo still waits out factset_anchor_wait and answers ErrIndexMoved (searchAnchored); the ruling covers lens members only.

OTHER (unchanged): the fused lens read's target selection (federate.ReadTargetsFor) skips a member whose ontology lacks the path filter's first segment as a topic, so on fixtures built with the real default ontology search.path "kb/u/" selects NO member while the same search on the repo path finds the facts; use a real topic path (kb/architecture/...) in lens fixtures. Engine lens fixtures write one seed fact per member (newLensMember) so every member has synced; newUnsyncedLensMember is the never-synced one.

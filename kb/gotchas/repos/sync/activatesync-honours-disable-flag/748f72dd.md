# ActivateSync starts a reconcile loop, so it must honour DisableBackgroundSync — clone-mode Create smuggled one past the flag

`Deps.DisableBackgroundSync` was checked in `startSyncLoops` (the open path) but NOT in the `ri.startSync` closure behind `ActivateSync`. Since `Manager.Create` ends clone mode with `ri.ActivateSync(url)`, every clone-mode create started a background `runReconcileLoop` even under a harness that had asked for none — the flag looked honoured at boot and leaked on create.

Fixed 2026-08-07: `startSync` returns before `go runReconcileLoop` when the flag is set. The SYNCHRONOUS reconcile still runs — that is the caller's explicit request, and it is what makes a bad token surface immediately at `PUT /api/v1/{repo}/origin` — only the periodic loop is suppressed.

This surfaced when the storyboard harness moved `Connect` off a config-level origin onto `Manager.Create` in clone mode. Any future path that activates sync inherits the same obligation.

WHAT THIS DOES NOT MEAN: the flag does not disable syncing. A test calling `.Sync()` or `.Push()` still reconciles; the flag only stops the timer-driven loop from racing assertions.

A second activation path inherits the obligation: ri.startLocalSync (RepoInstance.StartLocalSync, run by DELETE .../origin since fix/no-hardcoded-consensus-branch) drains the running loops and then returns before starting the local loop when the flag is set. (Since PR #397 the experiment sweep is not on syncCtx and startLocalSync does not restart it; the flag is honoured for the sweep in build(), where ri.sweep is left nil.) The CONSEQUENCE for tests: a test that must OBSERVE a loop (TestDeleteOrigin_StartsTheLocalReconcileLoopAtOnce) has to run with background sync ON and a short Git.LocalReconcileInterval. Under the flag it would pass vacuously or fail for the wrong reason.

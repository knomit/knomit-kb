# A background loop that does not depend on the origin must NOT run on syncCtx/syncWg: ActivateSync and StartLocalSync cancel syncCtx and relaunch only the reconcile loop, so anything else on it dies silently for the life of the process

syncCtx/syncWg (internal/repos/builder.go build()) belong to the ORIGIN-DEPENDENT reconcile loops. ri.startSync (behind ActivateSync: clone-mode Create, PUT .../origin, origin-session handlers) and ri.startLocalSync (behind StartLocalSync: DELETE .../origin) both do syncCancel() + syncWg.Wait() and then relaunch exactly one loop: runReconcileLoop or runLocalReconcileLoop. Any OTHER goroutine started on syncCtx is cancelled by that drain and never relaunched; nothing logs an error, it just stops.

This has bitten twice: the background index heal (kb/incidents/repos/clone-create-index-stuck-indexing, fixed with indexCtx/indexWg) and the experiment sweep (issue #377, PR #397, fixed with experimentSweeper). The trigger dispatcher, the consensus merger and the experiment sweep now each own a context derived from b.ctx plus their own WaitGroup, are started ONCE from repoBuilder.activate(), and are stopped (cancel + wait) by RepoInstance.shutdown and Manager.Close before closeFn.

CONSEQUENCES for a new background loop: (1) if it does not need the origin, give it its own ctx from b.ctx and its own WaitGroup and start it in activate(); do NOT add a relaunch to startSync/startLocalSync (that copies the launch condition into every restart path and the next restart path forgets it). (2) Leaving syncWg also removes it from the syncWg waits that SwapStore/shutdown/Close perform, so it may NOT hold a raw *store.Service: reach the store via ri.Acquire per unit of work and release on every path (kb/invariants/repos/store-lifetime), and treat a failed Acquire (ErrStoreUnavailable mid-swap, ErrRepoClosed) as skip-this-tick. (3) Add an explicit stop to BOTH RepoInstance.shutdown and Manager.Close (the latter is a separate copy of the teardown and is easy to miss — before #397 it stopped neither the dispatcher nor the merger), placed after indexWg.Wait so the start in activate() (inside the heal goroutine) happens-before the stop.

WHAT THIS DOES NOT MEAN: it does not mean every loop should leave syncCtx. runReconcileLoop and runLocalReconcileLoop are chosen by whether an origin exists and MUST restart with it.

# Degenerate config (upstream == agent branch) force-resets unpushed facts; guard makes it push-only, recover by changing upstream

GOTCHA + GUARD (PR #82). A repo can end up with its consensus ('main') branch configured to its OWN agent branch (remotes.branch == agentBranch) — e.g. a clone whose remote HEAD was an agent branch, adopted as upstream by a pre-#82 InitFromRemote. In that state the reconcile loop's reconcileMain treats the agent branch as 'main' and, seeing local ahead of origin after every fact write, FORCE-RESETS the local agent branch down to origin ('origin/agent... is not a descendant of local; force-updated') — silently destroying just-written, not-yet-pushed facts. Symptom: a new/updated fact appears in the UI, then vanishes ~1 reconcile cycle later. GUARD: remoteIndex.reconcileNow now detects upstreamMain == agentBranch and returns a no-op (skips ALL pull/reconcile); the per-tick Push still runs, so the branch is push-only and local commits are preserved instead of clobbered. RECOVERY: point the upstream back at a real consensus branch via store.SetUpstreamBranch (updates remotes.branch + rewrites the fetch refspec WITHOUT touching auth), exposed as PATCH /repos/{repo}/origin/upstream and an inline 'change...' control in the Remote panel; the reconcile loop reads the remote fresh each tick so it takes effect next cycle (no reconnect). The Remote panel shows a caution indicator whenever upstream == agent branch.

WHERE THIS LIVES NOW (verified at the PR C merge ba59d2b2): the guard is remotesync.Index.reconcileNow in internal/engine/store/remotesync/remote_sync.go (`if upstreamMain == agentBranch` logs a warning and returns an empty SyncResult, push-only); the 'remoteIndex' name above is the pre-hier-11 name. store.SetUpstreamBranch NO LONGER EXISTS: the discipline it enforced (rewrite the fetch refspec without touching auth, update remotes.branch) is now done in the web handler, internal/edge/web/handlers_origin_hal.go (handleHALSetOriginUpstream, PATCH /repos/{repo}/origin/upstream, whose comment records the move). The behaviour claims (force-reset symptom, push-only guard) were not re-run on the new code; the unversioned src refs below are historical.

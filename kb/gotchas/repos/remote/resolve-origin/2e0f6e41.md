# ResolveOrigin DIALS, so it runs on the caller's goroutine before an event is queued; the 'decided' marker spares a second dial only within ONE call, so CreatePreflight and Create each classify and a create with fleet trust installed makes two handshakes (Create is authoritative)

WHAT (verified at merge 0488c05d). ResolveOrigin performs network I/O (pki.ClassifyOrigin dials), so it must not run inside the repo state machine. Manager.Send classifies evAttachOrigin and evSwapStore on the caller's goroutine BEFORE the event is queued; the machine then stores the decided method. The same place decides for Create (every mode, join and fleet create pass through it), CreatePreflight, probeOrigin and beginRemoteProbe.

THE 'decided' MARKER. ResolveOrigin returns the spec with an unexported decided=true; passing that spec to a later step of the SAME operation costs no second dial, and a decided spec with a cert method is not refused as 'cert is an input'. The marker spans ONE call chain only: CreatePreflight and Create each receive the caller's original spec (the preflight's copy is local), so each classifies. A create or join with trust installed therefore makes TWO handshakes. That is harmless: Create is authoritative and the preflight's answer is only a fail-fast. (Review nit N7.)

CONSEQUENCE. Do not assert 'one dial per operation' in a test that goes through the preflight and the create; count per call. Do not move classification into the machine (it would hold the machine on the network). A preflight verdict is not a promise: the host can change between the two calls, and Create's answer wins.

MISREADING. 'decided means the origin is a peer': decided only means ResolveOrigin ran; the method (cert or the caller's) is the answer. A fleet create is not affected beyond this: it cannot have trust installed (trust_installed refuses), so it dials nothing.

# ActivateSync refuses an origin whose agent branch is governed by a DIFFERENT ontology id ("this remote is a different knowledge base") — a test that commits triggerOntology (id `trig`) on a real origin and then restarts sync must keep the repo's own ontology id

ActivateSync (builder.go's startSync closure) is the choke point for 'a repository is a knowledge base iff it has an ontology' on the attach side: via b.checkOriginOntology it compares ri.Ontology().ID with the ontology governing the origin. The trigger tests' triggerOntology helper writes `id: trig`. Once a reconcile tick has pushed that commit to a real (file://) origin, the origin's agent branch is governed by `trig` while ri.Ontology() still reports the repo's loaded id (e.g. `general` for a clone of seedBareRemote), and ActivateSync fails with 'this remote is a different knowledge base'. Fix in the fixture, not the code: replace `id: trig` with ri.Ontology().ID before committing (TestPush_KickAcrossActivateSync does this). Tests that never call ActivateSync after pushing are unaffected.

# A fleet-renewal test that installs its leaf at wall-clock now races any renewal issued in the same second: certificate NotBefore has one-second precision and installMainLeaf installs only a strictly-later leaf, so fixtures back-date installed leaves; production cannot hit this

SYMPTOM: a fleet renewal/leave test intermittently saw no leaf installed after a renewal round (CI run 39434692379; fixed in PR #568). CAUSE: an X.509 certificate's NotBefore has ONE-SECOND precision, and Manager.installMainLeaf (internal/repos/fleet_tick.go) installs main's leaf only when its NotBefore is STRICTLY LATER than the installed one (pki.InstallLeaf's rule). A fixture that installs the master's own leaf as 'issued now' shares the same NotBefore second with a renewal the master issues a moment later in a fast test, so installMainLeaf installs nothing.

FIX / CONVENTION: a test fixture back-dates the leaf it installs (installMasterLeaf in internal/repos/fleet_leave_test.go issues it an hour in the past), so it starts strictly before any renewal the test issues, whatever second the test runs in.

WHY PRODUCTION CANNOT HIT IT: Manager.renewalIssueTime (internal/repos/fleet_membership.go, used by both enrollment and renewFleetLeaves) issues a leaf at max(now, pki.IssueTimeAfter(old.NotBefore)) when the master's agent branch already holds a leaf for that id; pki.IssueTimeAfter (internal/pki/issue.go) is the first issue time whose NotBefore is strictly later at one-second precision. So a renewal is strictly later than main's old leaf by construction (the production same-second case is the incident kb/incidents/fleet/master-switch/same-second-reenroll/2326053f.md, closed by that function).

CONSEQUENCE: when a fleet test installs a leaf and later expects a renewal to replace it, back-date the installed one; do not add sleeps. SetFleetClockForTest moves ONLY the decision clock (fleetNow, which decides when a renewal is due); signing stays on time.Now (renewalIssueTime reads time.Now), so moving the fleet clock does not move a leaf's NotBefore.

MISREADING: this is NOT a production bug and needs no change to installMainLeaf or InstallLeaf; the strictly-later rule is the invariant (kb/invariants/pki/install/leaf-only/b3c976eb.md), the fixture was the thing wrong. See kb/architecture/fleet/tick/renewal/51be595b.md for the renewal round.

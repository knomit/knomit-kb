# `Origins.Get` uses an UNDECRYPTABLE auth token as plaintext and only logs a Warn — and control.db is now the ONLY copy, so a rotated agent key degrades to a confusing 401 rather than a clear error

When `o.crypt != nil` and `org.AuthToken != ""`, `Origins.Get` attempts `crypt.Decrypt`. On failure it does **not** return an error: it logs `origins: token decrypt failed; using stored value as plaintext` at Warn and returns the stored bytes as the credential. The reason is stated in the code — without a schema flag it cannot distinguish *legacy plaintext* from *ciphertext we can no longer decrypt* (rotated agent key, corruption), and it mirrors the contract `store.GetRemote` always had.

**What changed is the stakes, not the behaviour.** Before the registry moved into control.db, the repo's own `remotes` table also held `auth_token`; migration `000017` dropped those columns. `control.db` is now the **only** copy of the credential. So a lost or rotated agent key no longer degrades to "fall back to the other copy" — it yields an unusable credential that surfaces as a 401 from the remote, with the real cause visible only in one Warn line.

**Note the read/write asymmetry.** `Origins.Set` is strict where `Get` is lenient: without a Crypt it REFUSES to store a credential at all (`"refusing to store credential for repo %q: encryption unavailable (agent key unreadable); credentials are never stored in plaintext"`). Writes never produce plaintext; only reads tolerate it.

**Operational consequence:** when a sync or push starts 401ing after anything touched `~/.knomit/id_ed25519` or the agent key, grep the logs for `token decrypt failed` BEFORE suspecting the remote, the token's validity, or the network. The system is designed to keep going here, which means it will not tell you loudly.

**WHAT THIS DOES NOT MEAN:** not that tokens are stored in plaintext, and not that the leniency is a security hole — `Set` forbids plaintext writes. The lenient path exists to read rows written before encryption existed; its cost is diagnostic clarity, not confidentiality.

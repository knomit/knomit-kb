# HISTORICAL (true from #358 until fix/no-hardcoded-consensus-branch): removing a live repo's origin (DELETE /api/v1/repos/<repo>/origin) stopped its remote reconcile loop and started NO local one, so nothing fast-forwarded the consensus branch until the repo reopened. DeleteOrigin now calls RepoInstance.StartLocalSync, which starts the local loop at once

WHAT WAS TRUE: defaultOriginProvider.DeleteOrigin (internal/web/handlers_origin_hal.go) deleted the git remote and the control.db origins row, called svc.SetOrigin(nil) and then ri.DeactivateSync(), which only cancels the sync ctx. The local loop (runLocalReconcileLoop, kb/decisions/store/local-reconcile/main-is-consensus-everywhere) was chosen only in repoBuilder.startSyncLoops at open (internal/repos/builder.go), when GetRemote("origin") was nil. So after a detach the consensus merger's wakeSync and do: push triggers woke nothing, and the mission README told the user to restart the host. The same cancel also stopped the experiment sweep, which shares that ctx.

THE FIX: repoBuilder.build wires ri.startLocalSync, startSync's origin-less twin, sharing its syncCancel/syncWg and syncLoopMu. It drains the running loops (cancel, then Wait under syncLoopMu) and makes a fresh ctx. It then starts the experiment sweep and runLocalReconcileLoop on the CURRENT store (ri.Acquire, so a SwapStore is followed), with ri.triggerKick and ri.syncWake. It honours DisableBackgroundSync: the drain runs and the loops do not (kb/gotchas/repos/sync/activatesync-honours-disable-flag). DeleteOrigin calls ri.StartLocalSync() AFTER svc.SetOrigin(nil). Order matters: the local loop exits on a definite origin, so starting it before the origin is gone ends it at once. A start failure is logged; the detach still answers 204. An instance built without the builder falls back to DeactivateSync. The README's restart step is gone.

PINNED BY TestDeleteOrigin_StartsTheLocalReconcileLoopAtOnce (internal/web/consensus_branch_web_test.go). It runs with background sync ON (DisableBackgroundSync makes startSyncLoops return early, so a test under it could not observe a loop) and a 250ms LocalReconcileInterval. It clones a trunk KB, DELETEs the origin, records trunk's tip, writes a fact, and requires trunk to reach the agent tip within 8 intervals with no reopen. Trunk's tip is read BEFORE the write: on a fast runner the new loop's push wake moved trunk before a post-write read, which failed macOS CI once (run 36788960076) on the very behaviour under test. Sabotages: DeactivateSync instead of StartLocalSync → red; StartLocalSync called before the origin is removed → red.

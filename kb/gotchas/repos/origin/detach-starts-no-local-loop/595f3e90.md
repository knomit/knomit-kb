# Removing a live repo's origin (DELETE /api/v1/repos/<repo>/origin) stops its remote reconcile loop and starts NO local one: until the repo reopens, nothing fast-forwards its consensus branch from the agent branch, so merged peer work and the host's own facts do not reach it

defaultOriginProvider.DeleteOrigin (internal/web/handlers_origin_hal.go) deletes the git remote and the control.db origins row, calls svc.SetOrigin(nil) and ri.DeactivateSync(), which only cancels the sync ctx. The local loop (runLocalReconcileLoop, kb/decisions/store/local-reconcile/main-is-consensus-everywhere) is chosen only in repoBuilder.startSyncLoops at open (internal/repos/builder.go), when GetRemote("origin") is nil. So after a detach the consensus merger's wakeSync and do: push triggers wake nothing.

CONSEQUENCE: the mission template README's knomit-hosted route says to restart the hosting instance after removing the origin. Found during F08 PR D review round 2; not fixed there (scope: making UpstreamBranch honest). A fix would start the local loop in the DELETE path the way ActivateSync starts the remote one.

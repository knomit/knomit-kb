# Attaching an origin probes the remote BEFORE persisting anything: an unreachable remote or a refused credential returns 502 'Origin not attached' with nothing changed (GET origin stays 204), so a client or test cannot assume the origin row exists after a failed attach

internal/repos/events.go guardAttach runs before the attach is applied: it re-checks the local-origin policy, then ProbeOriginRefs, and returns ErrOriginUnreachable ('origin was not attached') when the remote is unreachable OR requires auth the supplied credential does not satisfy; then, if the repo has an ontology, CheckOriginOntology. internal/web/handlers_origin_hal.go maps these to: 502 'Origin not attached' (unreachable / credential refused; nothing persisted, running sync loop untouched), 400 'Origin not allowed' (local origin denied), 409 'Different knowledge base' (ontology mismatch). internal/web/static/openapi.yaml documents the 502 as 'nothing changed'.

Consequence: an API client or e2e spec that sets an origin to an unreachable URL gets 502 and GET origin keeps returning 204 (no origin); the older e2e assumed the row persisted and then asserted on it. Test 'origin set' behaviour against a reachable remote (a local bare repo allowed by the local-origin policy), and test the failure path by asserting the 502 and the absent origin. The probe has a network timeout budget (cfg.Git.NetworkTimeout) shared by its two reads.

WHAT THIS DOES NOT MEAN: a 502 is not a partial attach to be retried or cleaned up; there is nothing to undo. It also does not mean a reachable remote is accepted: an ontology mismatch is a separate 409.

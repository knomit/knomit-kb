# TestDue_SweepNotReachableFromWritePath scans the whole module minus .git, node_modules, dist, .claude and the repo-root web/ only; a directory named web elsewhere (internal/edge/web) is scanned

The structural guard walks every non-test .go file in the module and fails if DueCandidates, DueMarks, trigger_due_fires or sweepDue appears outside internal/engine/store/facts/triggers.go and internal/corpus/repos/triggers.go. Until PR store-slim-a its skip list contained the bare directory name web (added with the due suite in 38ba2a4c, meant for the root web/ Svelte frontend and its Go embed shim), so internal/edge/web, which can reach the store, was never scanned. It now skips only a directory whose path relative to the module root is exactly web.

CONSEQUENCE: a due-sweep call from any Go file under internal/edge/web fails the guard. Verified by sabotage on a throwaway commit: a file in internal/edge/web naming DueCandidates fails with 'internal/web/zz_sabotage.go: DueCandidates'; the same file in the root web/ directory still passes. At the fix commit no real violation existed in internal/edge/web.

DOES NOT MEAN: the guard proves the sweep is unreachable at run time; it is a text scan of identifiers, so an alias or a reflective call would slip it.

# There are two recipe helper binaries: the repos parent's TestMain runs maybeRunRecipeHelper for recipes fired through a repo, and the trigger child has its own TestMain and a small KNOMIT_TRIGGER_EXEC_HELPER; neither test binary can exec the other's helper

At ee850fd6 (PR #632). The parent's TestMain still runs maybeRunRecipeHelper (env KNOMIT_RECIPE_HELPER; triggers_run_helper_test.go) for the recipe tests that fire through a repo. The trigger child has its own TestMain (main_test.go: maybeRunRecipeHelper, testsigner.Install, storetest.SetFastDurability) with a SMALL helper (env KNOMIT_TRIGGER_EXEC_HELPER: echo and flood modes) that recipe_exec_test.go drives through recipeExec.call directly (argv verbatim, env merge, stdin, exit status, output cap). The two are separate test binaries; a test in one package cannot exec the other's helper, so a recipe test written in the wrong package fails with a missing-helper error, not an assertion. CONSEQUENCE: a recipe test that needs a Manager goes in the parent; one that exercises exec.go in isolation goes in the child.

# Dispatcher test harness traps: waitTriggerHead(h) never returns when a LATER commit moved the head past h (completedHead is the latest head, never an old one); TestingCommitFiles skips notifyCommit so nothing kicks the dispatcher and nothing syncs the index (kick by hand, SyncLocked by hand); WriteFact with a raw body bypasses SerializeFact, so a test of a write-gate rule must serialize through fact.SerializeFact first; and a `due` trigger's bookmark moves on every run, so 'the head before the fact' must be captured before writing it, not read from the watermark

Four traps hit while writing the F07 PR 2 due suite, each a 20 s timeout or a wrong-fixture failure rather than a real bug:
1. waitTriggerHead(t, ri, h) waits for completedHead == h from ri.triggers.RunSequenceForTest() AND ri.triggers.FlushedForTest() (runSequence() and flushed() before 14c, PR #632: the dispatcher is now the child package internal/corpus/repos/trigger and the parent's tests reach it through the *ForTest doors of trigger/testseams.go, kb/gotchas/repos/triggers/testing/testseams/73ec836f.md). If the test wrote another commit after h, the dispatcher's completedHead is the newer head and the wait times out. Wait on the FINAL commit of a burst (TestDue_MarkedCandidatesCostNothing wrote pairs of facts and had to wait on the second of the last pair).
2. svc.TestingCommitFiles moves the ref but skips notifyCommit: no commit_log row, no index Sync, no observer, no kick. A test that needs the index must call IndexManager().SyncLocked(ctx, branch) itself, and a test that needs a run must kick by hand (kickAndWait: ri.triggers.Kick() + wait for the RunSequenceForTest seq to grow and FlushedForTest(); triggerKick before 14c); waitTriggerHead on that commit never returns.
   CORRECTION (#445, merged a6ef5739): 'no observer' holds only for the commit itself. An observer notification ARMED by an earlier ordinary write (e.g. setOntology in newTriggerRepo) is still pending for 1 s, and when it fires it syncs the index to the head AT FIRE TIME. If the commit made with TestingCommitFiles lands inside that second, the callback indexes the whole advance; if it has not fired yet, commitObserver.Stop does it at teardown. In TestDispatch_Tx1Bounded (12,000 files) the test still passed, but took 30.6 s and logged 'close: repo did not finish unmounting within the drain bound'. Call waitObserverIdle(t, ri) (triggers_perf_test.go: a state wait for pending == "" && !running under o.mu) BEFORE the un-indexed advance. The slow per-path tree build used to outlast the debounce and hid this, until #445 made the build one-pass.
3. svc.Facts().WriteFact(ctx, branch, path, content, ...) stores content verbatim. A test of a rule that lives in SerializeFact (e.g. expires normalised to UTC) must build the content through fact.ParseFact + fact.SerializeFact (as the store's writeExpiresFact does), or it tests nothing. The MCP and REST POST paths do go through SerializeFact; the REST PUT has its own gate check for the same reason.
4. An active `due` trigger has a bookmark like any trigger and it moves to the head on every run, so watermarks()[name] after a write is the head AFTER the write — useless as 'the head before the fact' for a rewind fixture. Capture head(t, ri) before writing the fact.
The fake clock (`now` hook, fakeClock in triggers_due_test.go) is how time moves in these tests: set/add the clock and kick a run; never sleep past a real date.

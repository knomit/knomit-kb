# Test doors into the trigger child live only in trigger/testseams.go, each starting with mustBeTest, and are pinned by TestTriggerSeamsDeclaredInTestseams; the trigger tests stay in the parent because a commit kicks the dispatcher through the Manager

At the 14c merge ee850fd6 (PR #632). Every trigger test that fires needs a Manager and RepoInstance (a commit kicks the dispatcher through ri.onCommit), so they stay in package repos (H7: a child's white-box test may not import the parent). They reach the child through *ForTest doors in internal/corpus/repos/trigger/testseams.go, each starting with mustBeTest (panics outside a test binary): SetTestHooksForTest and HooksForTest (the exported TestHooks struct replaces the old triggerTestHooks; process-wide, so not for t.Parallel tests), SetRecipeAfterStartForTest, SetRecipeServerAddrWaitForTest (returns the restore), RecipeMCPForTest, and on *Dispatcher RunSequenceForTest, FlushedForTest, StatsViewForTest, RunStatsForTest, RunOnceForTest, FlushForTest, IndexIsReadyForTest, ScriptCompilesForTest, HomeForTest, SlowForTest, IdentityForTest; consts RecipeWaitDelayForTest, RecipeOutputCapForTest, P95WindowForTest. The getter is named HooksForTest (not TestHooksForTest) so a non-test function does not read like a test.

ENFORCEMENT. test/archtest TestTriggerSeamsDeclaredInTestseams pins each door: declared once, in that file, with mustBeTest as its first statement; an unlisted *ForTest in that file fails. B2 (TestTestSeamsNotReachedFromProduction) flags a production use of any *ForTest name (the reviewer sabotaged it: `_ = d.SlowForTest` in stages.go is red). The doors return values or copies, never a pointer into mutable state.

CONSEQUENCE: a new test door goes in trigger/testseams.go AND in the triggerSeams list (test/archtest/test_seams_test.go) in the same PR. WHAT THIS DOES NOT MEAN: the doors are not a way for production code to reach the child; B2 makes that red.

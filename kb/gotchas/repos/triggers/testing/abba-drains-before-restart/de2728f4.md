# BusyIf's `restartServe < 2s` timed an idle restart (abba ends on a BASE block, whose switch drains the busy backlog first), so it was removed; NoStoreHeldDuringIf at 1aaaf983 is the event-based test that restarts during a slow `if` (#659)

The `restartServe < 2 s` at the end of BusyIf was meant to show "teardown does not wait for the backlog". But abba with rounds=2 runs its blocks base, loaded, loaded, base, so it ends on a BASE block. Its switch to the trigger-less ontology waits up to 3 minutes for the dispatcher to reach that commit (waitTriggerHeadFor), which drains the whole busy backlog first. The restart therefore met no backlog, and the bound timed an idle restart: no sabotage of phase B's per-evaluation ctx check could turn it red, while load could. It was removed in #659.

Where the property is guarded at merge 1aaaf983: TestDispatch_NoStoreHeldDuringIf (triggers_test.go) restarts during a slow `if` backlog. Its version at this merge is the event-based one (merged before #659 through #656): EvalDelay signals a channel when the run is in phase B and returns 2 s per evaluation, the swap and the restart carry only 20 s hang detectors, and restartServe has its own hang detector, so it can pass only if cancellation stops the run. It no longer has the 400 ms sleep or the 1 s / 500 ms bounds that the #659 review flagged on the earlier version. It guards cancellation, not store leases (see the phase-b-lease-tests incident).

Consequence: before you add a teardown assertion after abba, put a backlog in place first (park the dispatcher, write, release). Otherwise nothing is in flight.

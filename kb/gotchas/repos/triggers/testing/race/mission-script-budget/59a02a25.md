# The mission e2e's scripts make real MCP writes inside the 5 s script budget, so under -race load a correct protocol failed with "script awards exceeded 5s"; the mission tests and the web script e2e tests now run under a 24 h ScriptBudget (#659, #661)

fact.ScriptEvalTimeout (5 s) bounds the whole fire, host calls included (the host ctx carries the deadline). In the mission e2e every host call is a real write through mcp.NewScriptTools on one of two instances. Under `go test -race` on a loaded machine, the award script of TestMission_HostAwardedExactlyOnce (mission_protocol_test.go) took longer than 5 s. Its fire was recorded as script-timeout ("script awards exceeded 5s"), and requireNoFailedFires failed a protocol that was correct.

Fix: newMissionClock (mission_e2e_test.go) calls repos.SetMissionTriggerHooksForTest (mission_export_test.go; formerly SetTriggerClockForTest). It installs the run clock AND `ScriptBudget: 24h` as one hook set. These tests assert what the template's scripts do, not how fast this machine runs them. A script that never ends still fails: QuiesceTriggersForTest's 30 s Eventually is the hang detector (it calls FailNow), and Close interrupts the script.

Consequence: a test that runs real scripts through real tools must not inherit the production budget. Its own budget must be unreachable, and the hang detector must sit elsewhere. Since #661, internal/edge/web/script_e2e_test.go does the same: `longScriptBudget(t)` installs a 24 h ScriptBudget through trigger.SetTestHooksForTest, copying the hooks from trigger.HooksForTest() and restoring the previous ones at cleanup. Each of its tests also calls `requireRan`, which waits (20 s, a hang detector) for the fire on the expected path and requires its outcome to be `ran`. Without that check a budget-cut fire whose write had already landed passed: with the budget cut to 1 ms and no hook, the reviewer saw TestScript_RealToolsEndToEnd and TestScript_MoveThroughRealTools stay green while every fire logged "trigger script exceeded its budget" (only TestScript_ArtifactsLandThroughRealTools, which already asserted the outcome, went red). internal/edge/mcp's script tool tests are not affected: they call the ScriptTools adapter directly with a ctx that has no deadline, never through the dispatcher, so no script budget is involved.

What this does NOT mean: the production budget is not too small. A mission script takes milliseconds on an unloaded machine; the timeout came from the race detector and machine load.

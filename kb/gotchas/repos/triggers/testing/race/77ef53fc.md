# TestScript_NoIOPrimitives fails deterministically under `go test -race` on an Apple-silicon laptop (at origin/dev 85470984 as well): its 1.5M-iteration clock-probe loop overruns the 5 s script budget, the script times out before knomit.emit, and the test reports '1 payload(s) never arrived' after 15 s — a budget-versus-race-slowdown failure, not a race

Observed 2026-09-29 while verifying F07 PR 5: `go test -race ./internal/repos/ -run 'TestScript_NoIOPrimitives$'` failed 3/3 at the PR's head and 2/2 at origin/dev 854709848e1e (a clean detached worktree), idle machine, macOS arm64. Without -race it passes in about 1 s. The probe script spins `for (i < 1500000)` between two Date.now() reads to prove the clock is pinned; under the race detector goja's interpreter is several times slower, so the fire hits fact.ScriptEvalTimeout (5 s) → `script-timeout`, and no payload is emitted. Not reproduced or checked on the Race workflow's ubuntu runner. Consequence: a local -race run of internal/repos is red on this test independent of the change under test; a fix would shrink the loop or raise the budget via triggerHooks.scriptBudget in that test. Not filed as an issue (findings are triaged with the user first).

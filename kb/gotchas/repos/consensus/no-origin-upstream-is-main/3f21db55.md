# A repo with no origin always has "main" as its consensus branch (store.UpstreamBranch), so consensus: auto only ever acts on a branch named main today; a non-main consensus branch needs an origin row, which makes auto inert

store.Service.UpstreamBranch() returns the origin row's Branch when an origin row exists and "main" otherwise (internal/store/local_reconcile.go). The consensus merger acts only when the repo has NO origin, so on every repo where auto can act the consensus branch is "main" by construction. Code must still never spell "main" (user addendum 2026-09-29): the merger asks UpstreamBranch().

Consequence for tests: a test that wants a non-main consensus branch has to set an origin (e.g. svc.SetOrigin(&store.Origin{Branch: "develop"})), which is exactly the case where auto is inert. PR B's T-B3 does this: it proves the setting is read at develop's tip (a reader hardcoding main finds no auto and never warns → red) and that the origin makes it inert. Every test in which auto acts necessarily runs on "main".

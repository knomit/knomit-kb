# HISTORICAL (true before F08 PR D, #358): a repo with no origin always answered "main" as its consensus branch (store.UpstreamBranch), so a repo detached from a trunk/master origin switched to a main it did not have. Since #358 the branch is RECORDED in the repo database and kept when the origin is removed

HISTORICAL. Up to F08 PR D (#358), store.Service.UpstreamBranch() returned the origin row's Branch when an origin row exists and "main" otherwise (internal/store/local_reconcile.go). The consensus merger acts only when the repo has NO origin, so on every repo where auto can act the consensus branch is "main" by construction. Code must still never spell "main" (user addendum 2026-09-29): the merger asks UpstreamBranch().

Consequence for tests: a test that wants a non-main consensus branch has to set an origin (e.g. svc.SetOrigin(&store.Origin{Branch: "develop"})), which is exactly the case where auto is inert. PR B's T-B3 does this: it proves the setting is read at develop's tip (a reader hardcoding main finds no auto and never warns → red) and that the origin makes it inert. Every test in which auto acts necessarily runs on "main".

SINCE #358: this is no longer true. UpstreamBranch answers the origin's branch, else the name recorded in the repo database's meta table (key consensus_branch), written by local init (the branch it creates), clone/subscription (the branch resolved) and every SetOrigin with a branch; removing the origin keeps it. A repo written before the key resolves its one non-agent/exp/okf branch and records it. So a knomit-hosted repo with consensus: auto CAN run on a non-main consensus branch (cmd/mission_route_test.go runs trunk and master); a test that wants one no longer needs an origin row. See kb/invariants/store/consensus-branch-recorded (F08 PR D). MISREADING to avoid: knomit's own local init still CREATES a branch named main by default (InitRepo); what changed is that the name is read back, never assumed.

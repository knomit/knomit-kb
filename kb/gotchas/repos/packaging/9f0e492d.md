# internal/corpus/repos must NOT import internal/app (app imports repos → cycle); repo creation inlines store init

internal/app/app.go imports knomit/internal/corpus/repos (the server wires up repos.Manager), so internal/repos can NOT import internal/app — that would be an import cycle. Consequently Manager.Create (lifecycle.go) keeps repo creation fully self-contained: it inlines the on-disk init (os.MkdirAll + store.Open + svc.InitRepo for preset/custom, svc.InitFromRemote for clone) rather than delegating to internal/app. Create uses m.deps.AgentBranch (resolved once at Manager construction) instead of re-deriving the agent branch from the key fingerprint. Historical note: an app.InitRepoOnDiskBytes helper briefly existed for the old `knomit init` CLI path; both the CLI command and that helper were removed when repo creation became API/UI-only (see kb/decisions/repos/lifecycle/5a08fcd2.md). The import-cycle constraint itself still stands, so any future shared init logic must NOT live in internal/app.

# mirrorIndexing's FIRST emit is conditional, not immediate — a create can complete without ever reporting an index phase

`mirrorIndexing` reads `IndexStatus()` ONCE at the top of its loop and returns WITHOUT EMITTING ANYTHING if the state has already left `indexing`. There is no unconditional first event.

Two test comments asserted the opposite for months — "mirrorIndexing emits once immediately and then sleeps 250 ms" — and the 250ms sleep half is true, which is what made the wrong half survive reading. The sleep only happens on iterations that emit.

WHY A CREATE CAN MISS IT ENTIRELY. `openOne` calls `markIndexing()` and starts the heal goroutine; `Create` then does `RecordRepoID` and, for a remote, `ActivateSync`; only then does it call `mirrorIndexing`. So there is a window whose width is that intervening work, and a heal shorter than the window finishes first. With a small corpus the heal is microseconds, so on a loaded runner it wins and NO `PhaseIndex` event is produced at all. Observed in CI on three jobs (105650652457, 105598133397 ubuntu; 105665517180 macos) and reproduced locally at 5 failures in 30 runs under CPU load.

CONSEQUENCE FOR TESTS: "the create reported an index phase" is a RACE, not a property, and any fixture asserting it must hold the heal rather than hope. Do NOT fix this by making the mirror always emit — an "indexing" event for a heal that has already finished is a lie told to the UI, and the mirror exists to avoid exactly that. Do NOT fix it by enlarging the fixture either: more corpus MOVES the race, it does not remove it, and the test then passes because of how fast the machine is. This is the same shape as guard-setup-outruns-hazard, one layer down: there the fixture's own setup finished the hazardous work; here the heal finishes before the observer looks.

CONSEQUENCE FOR CONSUMERS: absence of a `PhaseIndex` event does not mean indexing did not happen. It means the index was already out of `indexing` when the mirror first looked. A UI or client inferring "no index phase, therefore no index work" would be wrong.

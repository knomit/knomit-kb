# Whoever cancels a repo's background work while the repo stays live must restart it: the cancelled heal skips activate() and marks nothing, and activate() runs from nowhere else

A repo's background work has two lifetimes: the initial index heal (indexCtx/indexWg), whose successful exit runs activate() and marks the index state, and the sync loop (syncCtx/syncWg). The heal's cancelled exit (`if b.indexCtx.Err() != nil { return }` in Manager.openOne) skips BOTH activate() and the terminal mark. activate() has exactly two call sites, both in openOne, so a skipped activation is permanent for the process. The sync loop is likewise relaunched only by ActivateSync/StartLocalSync.

That is correct for TEARDOWN (shutdown, Manager.Close), where the repo is going away. It is a silent, process-lifetime outage for any path that cancels the same work while the repo stays LIVE. SwapStore was misclassified as teardown (ebd96069) and caused issue #400: index pinned at 'indexing' (the rebuild endpoint 409s), trigger dispatcher / consensus merger / experiment sweep never started, and sync dead after a failed swap.

CONSEQUENCES for any path that cancels indexCtx or syncCtx on a repo that stays open: (1) if the heal may not have activated (ri.activated false after indexWg.Wait), start the lifetime components (ri.startLifetime; idempotent and refused after stop via lifetimeGuard), never the store-bound half of activate() (ensureLocalUpstream, recoverFromOrigin, startSyncLoops), which is bound to the build-time store and syncCtx; (2) whoever then owns the index cell must mark it (MarkIndexRebuildStart/Done around the rebuild, or a terminal), or 'indexing' sticks and handleStartRebuild 409s forever; (3) restart sync on EVERY return path, including errors: ActivateSync with the origin in force, else StartLocalSync. The fix for #400 (PR #404) does all three for SwapStore and its only caller, the origin-session commit.

WHAT THIS DOES NOT MEAN: it does not mean the heal's cancelled exit should activate or mark. On a swap that exit holds the store being discarded; activating there was considered and rejected (kb/decisions/repos/swapstore/owns-what-it-cancels/848fff29.md). The obligation sits with the canceller, after the drain.

KNOWN GAPS in what merged (low severity): on a failed swap the origin-session handler restores the previous sync (a synchronous ActivateSync reconcile) BEFORE it marks a writerless 'indexing' as 'error', so the stuck state outlasts that restart; and no test asserts the index is 'indexing' DURING the post-swap rebuild (the web test seeds 'indexing' by hand and asserts 'ready' after, so it passes even without MarkIndexRebuildStart).

# A custom go-git scheme needs a wrapper that rewrites Protocol to https on a COPY, is installed once into an unsynchronised map, and must re-expose errors that go-git's UnexpectedError hides — go-git v5.19.2

Structural facts about go-git v5.19.2 that shape knomit's knomit+https transport (internal/pki/gittransport.go). Line numbers are dated support, not the claim.

ONE — REGISTERING IS NOT ENOUGH. `client.Protocols` is a plain map keyed by `Endpoint.Protocol`, and `client.InstallProtocol("knomit+https", t)` adds a key without touching `"https"`. But go-git's http transport builds every request URL from `endpoint.String()` (plumbing/transport/http/common.go advertisedReferences, upload_pack.go UploadPack), which writes the Protocol verbatim, so registering `githttp.NewClient(c)` directly fails in net/http with 'unsupported protocol scheme'. The redirect guard (`ModifyEndpointIfRedirect`) also compares against `endpoint.Protocol` and MUTATES the session's endpoint. So knomit registers a wrapper whose sessions pass `pki.RewriteEndpoint(ep)` — a COPY with Protocol "https" — to the inner http transport. The caller's endpoint is never changed.

TWO — THE MAP IS UNSYNCHRONISED. Install exactly once, before any clone or sync goroutine (app.New, before Manager.Start). `pki.InstallGitTransport` is once-per-process. It resolves its mTLS client lazily from the pki files at each session, and returns ErrNotEnrolled until a certificate exists. That is why tests can switch identity by swapping the source without writing to the map again.

THREE — go-git HIDES ERROR CAUSES. `plumbing.UnexpectedError` and `plumbing.PermanentError` have NO Unwrap method. The upload-pack POST (`doRequest`) wraps the net/http error in UnexpectedError, so `errors.Is(err, pki.ErrRevoked)` is false above go-git unless something peels it. The info/refs GET returns net/http's *url.Error unwrapped, and that one DOES unwrap. Measured by sabotage: with classification disabled, the other-root test (fails on info/refs) stayed green while the UploadPack test went red. `pki.ClassifyPeerError` peels the two go-git types and re-exposes the cause. It maps a remote TLS alert (`*net.OpError` with Op "remote error") to ErrRefusedByPeer and to nothing more specific, because an alert does not say why. It leaves errors with no go-git wrapper unchanged, so go-git's sentinel `==` checks still hold.

FOUR — ENDPOINT TLS FIELDS EDIT THE CLIENT. If an Endpoint carries ClientCert/ClientKey/CaBundle/InsecureSkipTLS or a Proxy, `newSession` clones the http.Transport and `configureTransport` edits its tls.Config (CaBundle appends to the SYSTEM pool). The knomit+https wrapper therefore REFUSES those fields, any go-git AuthMethod and URL userinfo, before dialling.

FIVE — THE SCHEME IS LOWERCASED. go-git parses with url.Parse, so KNOMIT+HTTPS:// arrives as Protocol "knomit+https". Checks on the raw URL string elsewhere (validateURLAuth, the wizard, resolveAuthWithOrigin) must be case-insensitive.

MISREADING TO AVOID: this is not 'go-git cannot do mTLS'. It can (ClientCert/CABundle), but those options use tls.X509KeyPair on the key, the system pool and a hostname check, and all three are wrong for knomit peers. See kb/gotchas/pki/openssh-key-is-not-x509keypair-input.

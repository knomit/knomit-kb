# packp.ReferenceUpdateRequest.Decode sets Packfile to the rest of the body even when nothing follows the commands — parsing it fails with 'empty packfile'

go-git's ReferenceUpdateRequest.Decode (packp/updreq_decode.go setPackfile) always assigns the remaining request reader to req.Packfile. A push that sends no pack — an update to a commit the receiver already holds, or a raw client's delete/update — therefore arrives with a non-nil Packfile that is EMPTY, and packfile.Parser.Parse on it fails with `empty packfile`. knomit's receive-pack peeks one byte (bufio.Reader.Peek) and treats io.EOF as 'no pack'. Checking `req.Packfile != nil` alone is not enough.

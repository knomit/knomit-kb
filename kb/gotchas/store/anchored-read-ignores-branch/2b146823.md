# facts.Index.ReadFact ignores the branch argument whenever AtCommit or BeforeCommit is set, by design, so a test of an anchored read cannot pin which branch the caller passed

In internal/engine/store/facts/fact_read.go, ReadFact(ctx, branch, path, opts) looks at BeforeCommit first, then AtCommit, then WithHash, then the default HEAD read.
- AtCommit: vr.ReadFileAtCommit(ctx, path, commit). It takes no branch.
- BeforeCommit: readFileLastCommit, which resolves vr.ResolveActiveCommitForPath(ctx, branch, path, firstParent) and reads the blob at the result. That walk follows the commit's first-parent chain through commit_log, and the branch argument is discarded (`_ = branch`, 'branch is implicit').
This is INTENDED, not a bug: it is the SCHEMA INVARIANT in internal/engine/store/internal/vcs/revisions_before.go (branch_commits holds a full-reachability walk from the tip, so any first-parent ancestor of an on-branch commit is on-branch; the commit_log JOIN restricts to indexed commits) and kb/invariants/store/branch-commits-reachability/d186925e.md and kb/invariants/store/resolver/first-parent-not-wall-clock/00a49427.md.

CONSEQUENCE: a test of commitDetail's title fallbacks (or of any caller of an anchored read) cannot observe the branch it passes; swapping that branch is an EQUIVALENT mutant (W0g1 sabotage D7 stayed GREEN, and the reviewer accepted it). Say so in the PR instead of building a fixture for it. Tests that must tell the two anchored reads apart install facts.Index.SetReadFactFaultForTest(f), whose hook receives (path, opts) and so sees AtCommit versus BeforeCommit.

DOES NOT MEAN: (1) that HEAD reads (nil opts, or WithHash) ignore the branch: they read the tip of the named branch via vr.ReadFile / ReadFileWithHash. (2) that the commit passed may be off the named branch: RevisionsBefore does add a branch_commits JOIN because its anchor can be on another branch (d186925e); only the ResolveActiveCommitForPath walk relies on the anchor being on-branch.

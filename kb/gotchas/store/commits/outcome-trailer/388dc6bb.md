# Knomit-Outcome rides model.Trailers.Extra (WithOutcomes) so it sits in the LAST paragraph with an agent's Knomit-Trace and an agent trace cannot forge it; model/trailers.go may only make calls the triggers guard allowlists

WHAT HAPPENS (internal/engine/store/model/trailers.go, #648 merge 2782d21c). model.WithOutcomes(ctx, []Outcome) adds one `Knomit-Outcome: <path> <verdict>` entry per hypothesis to the trailer set on the context (Trailers.Extra), deduplicated and formatted in one place. The commit writer then stamps it into the commit's final trailer paragraph, the same paragraph as an agent's Knomit-Trace, so a message with both stays one trailer block. Readers use model.TrailerValues(message, TrailerOutcome) and model.ParseOutcome (path plus verdict, verdict checked by ValidOutcome); there is one TrailerValues, in model.

NO FORGERY. An agent's `trace` may carry only Knomit-Trace, Knomit-Cause and Knomit-Run among Knomit- names (kb/invariants/mcp/write-tools/trace-entry-rules/d34ff943.md), so Knomit-Outcome in a trace is refused; only knomit stamps it, on the settle paths. A verdict in history therefore always came from a settle call.

THE GUARD. internal/engine/store/triggers_guard_test.go (TestTriggers_StoreCallsAreAllowlisted) scans every call inside model/trailers.go, because the trigger dispatcher reads trailers through that file and its store surface must stay read-only plus its own tables. #648 added the pure string compare ValidOutcome to the allowlist. Do not add a call to trailers.go (a store read, a write, a log walk) without checking that test; the failure shows up as the guard test, not as a trailer test.

WHAT THIS DOES NOT MEAN. Trailers are not facts: nothing is stored on the fact, and a hypothesis retracted without a settle has no Knomit-Outcome line. A trailer is per COMMIT: a commit that retracts several hypotheses carries one line per hypothesis.

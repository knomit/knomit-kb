# commit_log records EVERY changed path, including paths the fact index's isFactPath filter excludes (artifacts/ files, dot paths) — so knomit_explain on an artifacts/<area>/ file returns the file's own last commit and a real history, not the branch HEAD

The store keeps two per-path records with DIFFERENT admission rules:

- The fact index (branch_facts, search, graph) admits only `repoHandler.isFactPath` paths: under the ontology root, `.md`, and no dot-prefixed segment (`fact.IsPrivatePath`). A `.knomit/<area>/` slot is never indexed, never queryable.
- `commit_log` is filled by `AppendCommitLog` / `populateCommitLog` from a first-parent tree diff of each commit that records EVERY changed path. Since #347 that is derivation's own diff (`deriver.commitChanges` / `diffTrees`), pinned equal to the older `changedFilesInCommit`. There is no `isFactPath` or `IsPrivatePath` filter on this path.

Consequence a consumer acts on: history-backed reads that go through `commit_log` WORK for private-state paths. `knomit_explain` on `.knomit/jobs/x/y.md` returns `commit` = the last commit that touched the slot on the first-parent line, a populated `history` (store.PathHistory, read from path_changes, which is derived from the same first-parent tree diff, never from commit_log rows — .knomit/ slots included, since the derivation keeps every .md path; for a merge-delivered write its newest revision is the write itself, while `commit` is the merge that delivered it — see kb/architecture/mcp/explain/history-paging/2ae1425a.md), and no `deleted` flag (its liveness check, `FactQuery.LastCommitForPath`, is also commit_log-backed). A caller may pass that commit back as `knomit_update`'s `if_commit` exactly as for a public fact; `TestUpdateOps_IfCommitFromExplainPasses` pins that flow end to end.

WHAT THIS DOES NOT MEAN: it does not make private paths discoverable. knomit_query, the UI and export still never see them, because those read the fact index, not commit_log. And it does not mean the two filters are deliberately different — nothing states that. Do not infer commit_log's contents from isFactPath (this exact misreading was made while designing if_commit: reading the index filter and assuming commit_log shared it predicted explain would return branch HEAD for a slot; a test showed the slot's own commit).

F25 (2026-10-06): the agents' working files moved from `.knomit/<area>/` to repo-root `artifacts/<area>/` (fact.IsArtifactPath), and `.knomit/` is now closed to every fact tool, explain included. Everything above holds unchanged for an artifact path — it sits outside the ontology root, so isFactPath excludes it from the index while commit_log and path_changes still record it, and explain/update/if_commit work on it exactly as they did on a slot (TestThreeRoots_ArtifactRoundTrip; the update_ops tests now use artifacts/jobs/x/y.md). Read `.knomit/jobs/…` in the paragraphs above as `artifacts/jobs/…`: explain on a `.knomit/` path is refused before any lookup.

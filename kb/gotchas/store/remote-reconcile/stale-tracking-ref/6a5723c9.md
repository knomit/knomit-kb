# Gotcha: a stale refs/remotes/origin/<agent branch> from an earlier origin made Push send nothing to a new origin that lacked the branch; a fetch from an origin without the agent branch now drops it (#544)

SHAPE (fixed by PR #544, merge 8a01d3ca on dev). Neither the watermark nor the refs/remotes/origin/* refs are reset when the origin URL changes. After a switch to an origin that has no branch for this copy's agent branch, the strict fetch finds no match for the agent refspec and fetchOrigin retries with the upstream refspec only. The old refs/remotes/origin/<agent branch> then stayed, and Push read it as 'the origin already has this tip' and sent nothing: the new origin never received the branch (the same happens for a branch deleted on the forge).

FIX. In fetchOrigin's fallback (after the upstream-only fetch succeeded), every configured non-wildcard fetch refspec other than the upstream one has its destination tracking ref removed; a removal that fails logs a Warn and does not fail the fetch. The tracking ref mirrors what the origin has, so an origin without the branch must have no ref. Do not narrow the removal to the URL-change case: a branch deleted on the forge has the same shape.

MISREADING. 'Tracking refs are reset on a switch': no, only the ones the current origin lacks are dropped by a fetch; a ref the new origin does have is overwritten by the fetch as before.

PINNED BY TestSync_SwitchPushesTheBranchTheNewOriginLacks (red at dev and when the mirror is removed) and TestSync_FailedFirstRoundWithANewOriginIsStillASwitch (store, remote_origin_switch_test.go).

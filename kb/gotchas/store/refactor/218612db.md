# One store test scans triggers.go and trailers.go by file name, so moving a function in or out of those files changes the guard's allowlist

TestTriggers_StoreCallsAreAllowlisted (internal/store/triggers_guard_test.go) parses triggers.go and trailers.go and requires that the set of call expressions they make equals triggersAllowedCalls: an extra call fails, and an allowlist entry that is no longer called fails too ('allowlist entries no longer called'). The key for a call is its textual receiver form, so `s.rh.commitSigner()` is `?.commitSigner` while `rh.commitSigner()` is `rh.commitSigner`.

CONSEQUENCE: a pure file-placement refactor in internal/store that moves a function out of or into triggers.go or trailers.go (or renames a receiver there) fails this test even though behavior is identical. Fix by keeping the body in the guarded file and moving only a one-line delegator, or by editing the allowlist in the same change, and re-run `go test ./internal/store -run TestTriggers_StoreCallsAreAllowlisted`. It surfaced when Service.SignerFingerprint moved to a facade file and isTrailerParagraph moved into trailers.go (PR 05 of the internal/ hierarchy stack).

WHAT THIS DOES NOT MEAN: the guard is not about which file a function lives in; it is the dispatcher's no-write contract. Adding an allowlist entry is only right for a call that is a read or a pure helper.

SINCE hier-07 trailers.go lives in the vcs child, so the guard's key is "internal/vcs/trailers.go" (paths are relative to internal/store), and a call to a child helper from triggers.go is keyed with its package qualifier (`vcs.WalkHistory`). The same move showed which other store tests pin structure rather than behaviour, and each had to follow: TestChanges_CallsAreAllowlisted (changes_guard_test.go) parses internal/vcs/changes.go by path; TestVerifyIsNeverInTheWritePath reads fact_write.go and internal/vcs/sign.go by path; TestPathHistory_RebuildDoesNotBlockWriters pauses on stack frames through callerIs, which matches the FULL function name prefix (now `knomit/internal/store/internal/vcs.`) plus the method name, so renaming or moving a derivation function silently makes the test fail with 'the rebuild returned before pausing'; the archtest signer/agent-id guards allow files by module path. A renamed accessor also changes callKey: a field read (`rh.db`) is not a call, its accessor (`rh.DB()`) is, so turning field reads into accessors adds allowlist entries without widening the contract.

OUTSIDE internal/store, source-scanning tests read store files too, and a move into a child package either FAILS them (a by-path allowlist: internal/fact TestRefClassification_HasNoSecondImplementation names store files) or, worse, silently NARROWS them: a scan of `../store` with os.ReadDir or filepath.Glob("*.go") does not descend into internal/store/internal/*, so moved code leaves the guard's scope while the test stays green. Seen in hier-07: internal/mcp TestMotifMatch_LooseTiersAreNeverReachedByAutomation and store TestRepoVerifyAcceptedTableIsNeverUsed (both widened in that PR to the children), and internal/synthesize TestConformance_ReviewPipelineOnly (a `../store/*.go` glob until #551, which made it a recursive WalkDir). CONSEQUENCE: before moving store files, grep every *_test.go in the module for `../store`, `"internal", "store"` and Glob/ReadDir, and run `go test ./...`, not only the store packages.

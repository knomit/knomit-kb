# TestChanges_CallsAreAllowlisted keys each call as <qualifier>.<name> (a bare name for a same-package call), so moving a helper to another package fails it twice, and both failures are cured by requalifying the allowlist entry

internal/engine/store/changes_guard_test.go (TestChanges_CallsAreAllowlisted, with the allowlist changesAllowedCalls) walks the AST of the changes read's files, including internal/edge/web/handlers_changes.go, and keys every call by callKey: a bare identifier call is its name (writeStoreError), a package-qualified call is "<qualifier>.<name>" (httpx.WriteStoreError), and a method call on a non-identifier receiver is "?.<name>".

CONSEQUENCE. When a helper moves to another package (12b, PR #622, merge commit 3e67923b on dev, re-read there, moved writeStoreError, writeStoreUnavailable, selfWithQuery and BranchFromContext into httpx), the guard goes red in two places at once: the new qualified call is "not on the changes allowlist", and the old bare entry is reported by the stale-entry check ("allowlist entries no longer called"). Replace the entry with its qualified key (httpx.WriteStoreError, httpx.WriteStoreUnavailable, httpx.SelfWithQuery, httpx.BranchFromContext) rather than adding the new key beside the old one: leaving the old key fails. The check is non-vacuous: it requires every entry to be observed in the walked file, and the walk must have seen more than a minimum number of distinct calls.

WHERE TO LOOK. The test lives beside the store, not beside the web handler you edited, so a package list derived from the diff misses it; run internal/engine/store when a call in handlers_changes.go changes package.

DOES NOT MEAN: that a qualified key widens what the guard permits. It allows exactly the named call in exactly the listed file, and the rule it protects (the changes read is two trees, no store write, no clock, no commit log) is unchanged by a move. The running log of every guard key that followed a move is kb/gotchas/store/refactor/218612db.md.

# The BatchEmbedder and Embedder mockgen //go:generate directives live in internal/engine/store/model/embedder.go (the mcp and synthesize destinations are depth-relative) and run `go tool mockgen`, pinned by go.mod's tool directive

At 653fb08c (PR #593) the mock interfaces are declared in internal/engine/store/model/embedder.go and so are the THREE //go:generate lines, all `go tool mockgen`: Embedder -> ../../../corpus/synthesize/mock_embedder_test.go (package synthesize, the line PR #593 ADDED; the base had two directives), BatchEmbedder -> ../mock_batch_embedder_test.go (package store) and BatchEmbedder -> ../../../edge/mcp/mock_batch_embedder_test.go (package mcp); source package knomit/internal/engine/store/model for all three. The destinations are RELATIVE to the directive's directory, so they are the only go:generate lines in the module with a relative path to a moved package; any further move of edge/mcp, corpus/synthesize or store must move them again. History: the mcp destination gained a `../` when store moved under internal/engine (PR #590) and then pointed at internal/edge/mcp after PR #591; earlier (32414d74) the file was internal/store/model/embedder.go; E7a deleted internal/store/interfaces.go. The old Embedder mock header named the stale source knomit/internal/engine/store. All three MockGen files in the module (the synthesize, store and edge/mcp mock_*_test.go) have a directive. No CI job checks generated mocks are current. CONSEQUENCE: change a directive where the interface is, and keep the source package argument equal to the interface's package.

Tool dependency: go.mod has `tool go.uber.org/mock/mockgen`, with go.uber.org/mock pinned at v0.6.0 in go.mod/go.sum and golang.org/x/tools v0.50.0 (indirect) now in go.mod/go.sum, so `go generate ./internal/engine/store/model/` works from a clean checkout with no globally installed mockgen. This fixes the earlier failure of `go run go.uber.org/mock/mockgen` (missing go.sum entry for golang.org/x/tools). Bump mockgen by bumping go.uber.org/mock in go.mod (the tool and the runtime library share one version); never `go install` mockgen. Generated headers record the command as `mockgen -destination=...` with no version. The x/tools pin (and the x/net, x/crypto, x/text bumps it pulls through MVS) is forced by the tool dependency; the PR review verified the shipped binary links those bumped versions. MISREADING: the tool directive does not add mockgen to the shipped binary; it only affects go.mod resolution and `go tool`.

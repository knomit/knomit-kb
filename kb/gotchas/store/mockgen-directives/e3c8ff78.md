# The BatchEmbedder mockgen //go:generate directives live on the interface in internal/engine/store/model/embedder.go, the mcp destination is depth-relative, and `go run go.uber.org/mock/mockgen` fails in this module on a missing go.sum entry for golang.org/x/tools

At fb6cf903 (after step 03 of the layer move, PR #590) the BatchEmbedder interface is declared in internal/engine/store/model/embedder.go, and its two //go:generate mockgen lines are there too: destination ../mock_batch_embedder_test.go (package store) and ../../../mcp/mock_batch_embedder_test.go (package mcp), source package knomit/internal/engine/store/model. The mcp destination is RELATIVE to the directive's directory, so it gained one `../` when store moved under internal/engine (it was ../../mcp); step 04 (mcp to internal/edge/mcp) will need it to follow. (Earlier, at 32414d74, the file was internal/store/model/embedder.go with destination ../../mcp and source knomit/internal/store/model.) They used to sit in internal/store/interfaces.go and named knomit/internal/store, which no longer declares BatchEmbedder; E7a deleted interfaces.go (internal/store/interface_guards.go too), so there is no store file to look in. CONSEQUENCE: change the directive where the interface is, and keep the source package argument equal to the interface's package.

Gotcha reported by the PR author and NOT re-run by the curator: `go generate` through `go run go.uber.org/mock/mockgen` fails in this module with a missing go.sum entry for golang.org/x/tools (it failed before E7a too); the installed mockgen v0.6.0 with the same flags regenerates the mocks, and the only diff is the header, import grouping and method order. MISREADING: the go.sum failure is pre-existing and not caused by the directive move.

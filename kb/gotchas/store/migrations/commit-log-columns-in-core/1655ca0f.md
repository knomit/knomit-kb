# Add new commit_log columns via a forward ALTER migration, not by editing 000001

To add a column to commit_log, write a NEW numbered ALTER migration (e.g. 000011_commit_log_author_name.up.sql: `ALTER TABLE commit_log ADD COLUMN ...`), with a matching .down.sql (`ALTER TABLE commit_log DROP COLUMN ...` — SQLite here supports DROP COLUMN, see 000006). Do NOT just edit 000001_schema.up.sql.

WHY editing 000001 fails for existing DBs: golang-migrate tracks only the current version integer in schema_migrations (no checksum re-validation), so an in-place edit to an already-applied migration is silently skipped. The main KB DB is persistent (store.Open → migrate.All → Up()); existing on-disk caches (e.g. ~/.knomit/repos/*.db, observed at version 10) would never get the column and the next CommitLogSync INSERT would fail with 'no such column'. A forward ALTER at version 11 IS run by Up() (10→11) and auto-heals existing DBs with no file deletion and no :rebuild needed. (:rebuild = searchIndex.Rebuild rebuilds facts/embeddings/graph only; it never runs migrations and never touches commit_log.)

The earlier worry that commit_log columns MUST live in 000001 because migrate.Core (v1-only, used by storegit.NewMemoryStorer) bootstraps the git package's commit_log writes is THEORETICAL: NewMemoryStorer and migrate.Core have zero callers anywhere in the repo (no internal/git package exists), so nothing exercises the Core path. author_email happens to sit in 000001 for historical reasons, but new columns should use a forward ALTER.

Backfill tip: existing commit_log rows get the column with its DEFAULT only — CommitLogSync is INSERT OR IGNORE so a re-walk won't update them. For author_name, a best-effort UPDATE recovers the agent-id from agent rows (`substr(author_email,1,instr(author_email,'+')-1)` where `instr(author_email,'+')>1`); human/PR-merge rows (no '+' subaddress, e.g. k@knomit.io) stay '' because the name was never stored. Verified on a copy of trunk.db: agent rows backfilled correctly, ~1368/2397 non-subaddressed rows left empty as expected.

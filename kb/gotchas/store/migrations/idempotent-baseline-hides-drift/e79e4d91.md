# An IF NOT EXISTS baseline makes schema DRIFT invisible to ordinary tests — only a shape-equality test catches it

A baseline migration written as `CREATE TABLE IF NOT EXISTS` is deliberately a no-op against databases that already have the table — that is what lets it be adopted by live homes. The consequence nobody expects: it is ALSO a no-op against a table whose shape has silently diverged from the migration text, so the two can drift apart forever with no test failing.

Measured, not theorised: changing `profile TEXT NOT NULL DEFAULT 'code'` to `DEFAULT 'generic'` in the control.db baseline left `internal/store/migrate`, `internal/repos`, `cmd` and `internal/web` ALL GREEN. Fresh homes would have got one `repos` shape and every existing home another, permanently.

The two obvious tests do not help. A "no-op on an existing shape" test no-ops past the divergence by construction. A "fresh database" test that checks `sqlite_master` for object NAMES never looks at columns.

**What actually catches it:** build database A by hand from the legacy DDL pasted as a literal, build database B via the migrator, and compare. The comparison must cover four dimensions, and two of them are the ones a naive version misses:

- `PRAGMA table_info` — name, type, notnull, dflt_value, pk.
- `PRAGMA foreign_key_list` — `table_info` CANNOT see `ON DELETE CASCADE`. Removing the cascade from `repo_origins` passes a table_info-only comparison.
- `PRAGMA index_list` + `index_info` — but these do NOT expose a partial index's `WHERE` predicate. `repos_active_name` and `repos_active_repo_id` are partial; flipping `state='active'` to `'archived'` passes an index_info-only comparison.
- The index's `sql` text from `sqlite_master` (whitespace-collapsed) — this is what catches the predicate.

**Known residual, deliberately accepted:** the comparison omits the TABLE's own `sqlite_master.sql`, so a `CHECK` constraint, `WITHOUT ROWID`, a collation, or a generated column added to the baseline still slips through. Verified. Closing it is one line reusing the same whitespace-collapse trick.

**Pasting the DDL literal into the test is the point, not a smell.** An independent copy that must be kept in step deliberately is the mechanism; importing the constant would make the test tautological. There are now three copies of the lens DDL (baseline, `upgradeLensSchema`'s rebuild, the test literal), and each needs its own pin — `internal/store/migrate` cannot import `internal/repos`, so the third is pinned by a separate test in the `repos` package.

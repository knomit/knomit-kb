# go-git v5.19.2: a push whose refspec source is a hash it cannot read as a commit sends NOTHING and returns NoErrAlreadyUpToDate — a caller mapping that to Pushed:false reports success for a push that never happened

In go-git v5.19.2 remote.go, addOrUpdateReferences handles a non-wildcard refspec whose source is not a local ref name by calling object.GetCommit(storer, hash); if that fails it returns nil WITHOUT adding a command. PushContext then sees zero commands and returns NoErrAlreadyUpToDate. knomit's Push maps NoErrAlreadyUpToDate to Pushed:false with no error, so a snapshot push of an unreadable commit would silently look like 'nothing to push'.

The guard: Push calls repo.CommitObject(snapshot) before PushContext and returns an error ('snapshot commit <sha> is unreadable'), which is persisted as the push status. Pinned by TestPush_UnreadableSnapshotIsAnError (the commit object is deleted with DeleteObjectForTest; dropping the guard turns the error into nil/Pushed:false).

Also from the same code: when the advertised remote value already equals the hash (cmd.Old == cmd.New), addCommit adds no command either, so 'already up to date' is also go-git's answer when the origin has the snapshot but the local tracking ref was stale; in that case the tracking ref is NOT updated by go-git. Version-pinned claim: re-check on a go-git upgrade.

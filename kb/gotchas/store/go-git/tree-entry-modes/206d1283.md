# go-git's filemode.FileMode.IsFile() is true for a SYMLINK (and for an executable): a reader that gates on IsFile alone serves a symlink's blob, which is the link-target NAME, as if it were file content

In go-git v5 (checked at v5.19.2, the version knomit's go.mod pins; plumbing/filemode/filemode.go), `FileMode.IsFile()` returns true for Regular, Deprecated, Executable AND Symlink. Submodule and Dir are the only false cases. A symlink's blob holds only its target's path text. So a reader gated on `entry.Mode.IsFile()` alone does not follow the link. It serves the target NAME as if that were the file's content, and it treats the entry as present.

Where knomit handles this explicitly:
- store.SystemFileAt and the skill loader refuse `filemode.Symlink` (isSystemFileMode) and read it as absent (#428 follow-ups; user ruling 2026-10-08 "we do NOT want to follow symlinks, so 404").
- GuidanceAt refuses symlinks.
- Templates (#433) accept only Regular/Deprecated, refusing symlinks, submodules and executables alike.

The skill loader (store/skills.go) now refuses symlinks too, through the same test (#438, merge ea683690, the follow-up to #437). A folder whose SKILL.md is a symlink is no skill. If a regular skill.md sits beside such a symlink, the regular one is the skill. A symlinked bundled file is neither inlined nor listed. This holds at every door that loads skills: prompts/list, prompts/get, and knomit_skill list and get.

STILL ON IsFile ALONE at ea683690 (#438's merge), so these readers still accept a symlink entry: OntologyAtCommit (internal/store/triggers.go ~376, the ontology file) and privateFileAt (~465, used by ScriptAt and RecipeAt for trigger scripts and recipes). They are out of scope for #437 and #438.

THE ONE TEST: store.isSystemFileMode(m) = m.IsFile() && m != filemode.Symlink. It is shared by SystemFileAt and the skill loader. Use it for any new reader of entries under .knomit/; do not spell IsFile again.

CONSEQUENCE: any new reader of git tree entries must decide on symlinks EXPLICITLY. `IsFile()` is not "regular file". Do not refuse Executable by accident either: trigger scripts may legitimately be +x.

WHAT THIS DOES NOT MEAN: go-git never follows a symlink inside a tree. The risk is serving or accepting the link text, not path traversal.

# DERIVED_FROM edge ids do NOT follow a fact's refs order (sync pass 2 writes intra-batch refs later); the exact order is facts.refs JSON — but a pinned OLD version often has no facts row at all, only its graph node

Three things a reader of the graph must not assume, measured on a real-size store (knomit-kb copy, 253k facts rows, 520k DERIVED_FROM edges, 2026-10-30):

1. edges.id order is NOT the frontmatter refs order. graphAddDerivedFromAtCommitTx inserts in refs order within one call, but Sync's pass 1 skips a ref whose target node is in the same batch and not yet committed, and pass 2 (search_index.go, the writePostCommitDerivedFrom retry loop) writes it later with a higher id. One (path, blob) node also accumulates edges from every ref-event of that blob (re-commits, merges, rebuilds: 3,340 multi-edge pairs). Measured: 40 of 935 real-KB sources that have a facts row and >=2 edges (4.3%) have edge-id order != refs order. A rebuild re-creates edges with new ids, so edge-id order is not even stable over a store's life.

2. The exact order IS in the index: facts.refs is the frontmatter refs JSON in written order; json_each(f.refs).key is the position. Use it (or the parsed blob) for 'refs order'; never ORDER BY edges.id.

3. A version's facts row is not guaranteed to exist. Upsert keeps old rows on edit, but a rebuild re-creates facts only for live versions and a retract that orphans a version deletes its row (search_crud.go delete, refcount 0); the graph keeps a Fact node for every historical (path, blob) (graphSyncHistoricalFactTx: title, type, confidence, deleted=true — no kind, no refs). On the real store 3,775 of 6,116 source nodes with edges, and ~76% of pinned real-KB target versions, had no facts row. Anything that walks pinned versions (materialize) must fall back to parsing the blob for refs order and kind — which is ONE row read from the objects table, not a tree walk (see the objects-table fact).

What this does NOT mean: edges are not missing or wrong — the SET of edges out of a version is correct; only their row order carries no meaning.

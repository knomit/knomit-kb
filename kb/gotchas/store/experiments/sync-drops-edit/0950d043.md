# knomit_experiment sync can silently drop your experiment edit to a fact the agent branch also changed, and knomit_explain at HEAD no longer lists the dropped revision; read your facts before a sync and re-read them after

Where the experiment and the agent branch both changed a fact, sync keeps the agent branch's version (see kb/decisions/experiments/lifecycle/7a2357c2.md, which records that sync overwrites the experiment's version; this fact does not repeat why). What that decision does not say is what you are left with afterwards: the sync answers with one summary line, the fact reads back as the agent branch's text, and knomit_explain on that fact at HEAD no longer lists the dropped revision as part of its history. The only trace of the drop is the sync merge commit. Seen on this branch: a correct experiment edit to kb/conventions/web/chat/3daeb497.md (revision 09063a4f) was dropped by a sync run to fetch another fact, and the fact came back with its old, false text and no sign anything had been lost.

What to do: before a sync, read (include_body) every fact you have written in the experiment and keep what you need to re-apply; after the sync, read them again and compare. Re-apply a dropped edit with knomit_update; do not assume an earlier write that returned a commit is still in the fact. If you sync only to see a fact the experiment lacks, query the agent branch (no binding) instead.

What this does NOT mean: sync is not wrong or lossy for facts only one side changed; those keep both. And explain's missing revision is not a sign the write never happened: the write landed, then sync replaced it.

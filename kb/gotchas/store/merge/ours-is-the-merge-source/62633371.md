# For an experiment commit "ours" is the EXPERIMENT — the merge SOURCE — which is the opposite of git's convention, so the store refuses both words and says src/dst

`commit` merges the experiment INTO the agent branch, so the experiment is `src` and the parent is `dst`. From the seat of an agent working inside the experiment, "ours" is its own work — the source. Git means the opposite: there "ours" is the branch you are merging INTO.

Because which branch is "ours" depends on who is asking, nothing below the tool boundary uses the words at all. `ResolutionSide` is `ResolveSrc`/`ResolveDst`, and the translation happens exactly once, at the MCP and REST boundaries where the asker is known.

WHY IT MATTERS MORE THAN A NAMING PREFERENCE: a caller who reads these backwards discards their own work while believing they kept it, and the commit SUCCEEDS. The tool description and the refusal text both state the inversion explicitly for that reason.

SAME SHAPE AS RemoteWins. conventions/store/sync/strategy-local-wins already records that the strategy names which SIDE wins, and that reading RemoteWins as "the remote" rather than "src" silently keeps the experiment's version of exactly the path a sync was run to resolve.

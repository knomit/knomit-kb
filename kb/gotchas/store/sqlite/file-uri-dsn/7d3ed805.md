# A SQLite file URI for a read-only open must come from internal/platform/fileuri on an ABSOLUTE path: a hand-built url.URL renders file://C:/... on Windows (SQLite rejects it), and go-sqlite3 v1.14.34 silently drops the query string (mode=ro) of any DSN not starting with `file:`

Two independent traps when building a SQLite DSN with options (here `?mode=ro&_busy_timeout=5000`) for a local path:

1. WINDOWS AUTHORITY. `(&url.URL{Scheme: "file", Path: filepath.ToSlash(p)}).String()` renders a drive path as `file://C:/Users/x/.knomit/control.db`: "C:" lands in the URI authority and SQLite rejects the open with `invalid uri authority: C:` (the project's go-sqlite3 build does not enable sqlite_allow_uri_authority). It is correct on Unix, where paths start with `/`, so it passes every macOS/Linux test. Use `fileuri.New(absPath)` (internal/platform/fileuri, introduced by #212), which yields `file:///C:/Users/x/...`. In repos this is `controlReadOnlyDSN(abs) = fileuri.New(abs) + "?mode=ro&_busy_timeout=5000"`, pinned by TestControlReadOnlyDSN_Form on every OS.

2. RELATIVE PATH DROPS THE OPTIONS. `fileuri.New` deliberately keeps a RELATIVE path relative, so the result has no `file:` prefix. github.com/mattn/go-sqlite3 v1.14.34 (sqlite3.go, the DSN parsing near the `file:` check) discards the query string of any DSN that does not start with `file:`, so `mode=ro` is silently lost and the handle becomes the default read-write-create: it can create a missing control.db and flip a rollback-journal file to WAL. Nothing errors. So run `filepath.Abs(path)` BEFORE `fileuri.New`. This is claimed for go-sqlite3 v1.14.34 only: re-check sqlite3.go when the module is upgraded. Production `home` is already absolute, so the Abs is a guard for the helper, pinned by TestOpenControlReadOnly_RelativePathStaysReadOnly.

OPERATIONAL CONSEQUENCE: any new SQLite open that relies on a URI option (mode=ro, immutable, cache) takes an absolute path, goes through fileuri.New, and ships a test that proves the option took effect (a read-only handle must FAIL on a missing file and leave the directory empty), not merely that the URI string looks right.

WHAT THIS DOES NOT MEAN: it is not true that every go-sqlite3 option is dropped for non-`file:` DSNs. Driver-parsed keys like _busy_timeout are consumed by go-sqlite3 itself; the loss is of what SQLite itself would parse from the URI query, such as mode=.

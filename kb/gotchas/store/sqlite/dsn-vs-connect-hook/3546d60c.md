# go-sqlite3 applies DSN pragmas like _synchronous BEFORE ConnectHook runs, so the sqlite3_knomit hook's PRAGMA synchronous = NORMAL silently overrides any _synchronous in the main store DB's DSN

In github.com/mattn/go-sqlite3 v1.14.34, SQLiteDriver.Open parses DSN params (_journal_mode, _synchronous/_sync, ...) and executes them on the new connection, and only afterwards calls d.ConnectHook(conn) (sqlite3.go ~L1400 parses _synchronous; ~L1774 runs ConnectHook). The sqlite3_knomit driver's ConnectHook (internal/engine/store/internal/sqlite/vec.go, registerVec; see kb/architecture/store/sqlite3-knomit-driver/82f341be.md) executes `PRAGMA synchronous = NORMAL` on every connection (since PR #398, OFF instead when a test binary has called store.SetTestFastDurability(true); see internal/engine/store/internal/sqlite/test_durability.go).

Consequence: adding `&_synchronous=OFF` (or FULL) to the main store DB's DSN in service.go has NO effect: the hook resets it to NORMAL on every connection, and nothing errors. Any per-connection synchronous setting for the store DB has to be applied inside the hook (that is where #365's test-only fast-durability switch lives), or the hook's own PRAGMA must change.

Scope: only DBs opened through sqlite3_knomit. DBs opened with the stock `sqlite3` driver (control.db in internal/corpus/repos/registry.go, the session sidecar) honour their DSN's _synchronous.

Related: with _journal_mode=WAL and no _synchronous, go-sqlite3's default for the connection is synchronous=NORMAL, not SQLite's compile-time FULL.

Misreading to avoid: DSN params are not ignored in general. They are applied; a hook that sets the SAME pragma later wins.

# configureRemote with an empty agent branch must write ONE refspec — interpolating an empty branch name yields a refspec git accepts and every later fetch then fails on

`configureRemote(url, upstreamMain, agentBranch)` builds fetch refspecs by interpolating branch names into `+refs/heads/%s:refs/remotes/origin/%s`. With `agentBranch == ""` — a subscription, which has no branch of its own — that produces the literal `+refs/heads/:refs/remotes/origin/`.

That string is NOT rejected. Git stores it in the remote's config quite happily; it is only when a fetch tries to use it that the operation fails, and it fails for every fetch from then on, including the ones for the branch the repo actually needs.

**Consequence for a consumer:** the guard is `if agentBranch != ""` around the SECOND refspec, so a subscription's remote carries exactly one. Any future code that composes refspecs from a possibly-empty branch name needs the same guard — the error surfaces far from the cause, at the next sync tick rather than at config time.

The comparison helper `sameRefspecs` exists because the idempotence check now compares a variable-length want-set, not a fixed pair.

WHERE THIS LIVES NOW (verified at the PR C merge ba59d2b2): the guard `if agentBranch != ""` and sameRefspecs are in vcs.Repo.ConfigureRemote, internal/store/internal/vcs/branch.go (not internal/store/branch.go); Service.ConfigureRemote in internal/store/service.go forwards to it. InitSubscription is remotesync.InitSubscription in internal/store/remotesync/bootstrap.go, which calls rh.ConfigureRemote with an empty agent branch; Service.InitSubscription in internal/store/repo.go is a forward. The 'repoHandler.configureRemote' name above is the pre-split name.

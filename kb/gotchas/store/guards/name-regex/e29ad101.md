# TestVerifyIsNeverInTheWritePath's NAME list let fleetrec.* calls through after the move into a child package; it now also rejects ANY package-qualified call into fleetrec (and verify) from fact_write.go and vcs/sign.go

internal/store/verify_not_in_write_path_test.go greps the SOURCE TEXT of fact_write.go and internal/vcs/sign.go (it is a text scan, so a comment counts) with two rules. Rule 1 is a fixed alternation of call names (CheckRange, Audit, LoadFleet, LoadFleetAt, FleetMembersAt, FleetPKIAt, FleetAt, loadMembers, loadFleetPKI, newJudge, ...). Rule 2, added after hier-08 (PR 552), is the package-qualified pattern `\bfleetrec\.\w+\(`: ANY call into the fleetrec package fails the guard, whatever its name.

WHY RULE 2 EXISTS: rule 1 is bound to spellings, not to the property 'no verification in the write path'. When hier-08 moved the fleet read into internal/store/fleetrec, the same read became reachable as fleetrec.At, FileAt, KeysOf, Since, MainLog and ResolveCommit; none is in the name list, so a call to fleetrec.At( from fact_write.go PASSED while the old spelling FleetAt( failed. The first fix (listing LoadMembers, LoadMembersOfTree, LoadFleetAtCommit) only chased names. Sabotage on throwaway commits confirmed: fleetrec.At( and fleetrec.KeysOf( now fail with 'calls into the fleetrec package from the write path'; FleetAt( still fails rule 1. The verify extraction (PR 553, stacked on 552) adds the same rule for `\bverify\.\w+\(`, so a new verify export such as verify.Audit or any future name fails too.

CONSEQUENCE for future extractions: when a verify- or fleet-reading function moves into a child package, add the child's package qualifier (`\b<pkg>\.\w+\(`) to the guard in the same change, and prove it bites by putting a call to a name NOT in the list (e.g. <pkg>.KeysOf() into fact_write.go on a throwaway commit. Do not rely on extending the name list.

WHAT THIS DOES NOT MEAN: the guard does not forbid fact_write.go from importing a child package; it forbids calls qualified by the fleetrec or verify package names. A call through an import alias, a dot-import, or a method on a value returned from another package is still invisible to a text scan; the guard is not a call-graph check.

# TestVerifyIsNeverInTheWritePath matches verification calls by NAME in fact_write.go and vcs/sign.go, so exporting or renaming a loader into a child package makes the guard pass vacuously until its pattern is extended

internal/store/verify_not_in_write_path_test.go greps the SOURCE TEXT of fact_write.go and internal/vcs/sign.go for a fixed alternation of call names (CheckRange, Audit, LoadFleet, LoadFleetAt, FleetMembersAt, FleetPKIAt, FleetAt, loadMembers, loadFleetPKI, newJudge, ...). It is a name list, not a call-graph check. When hier-08 moved the member loader into internal/store/fleetrec the unexported loadMembers became fleetrec.LoadMembers: `\bloadMembers\(` no longer matches it, so a fact write calling the loader would have passed. The pattern now also lists LoadMembers, LoadMembersOfTree and LoadFleetAtCommit.

CONSEQUENCE: when a verify- or fleet-reading function is moved or exported, add its NEW name to the alternation in the same change, and prove the guard bites by adding one of the names to fact_write.go on a throwaway commit (it fails with 'calls verification in the write path'). Do the same for the verify extraction. WHAT THIS DOES NOT MEAN: the guard does not forbid fact_write.go from importing a child package; it forbids the named calls.

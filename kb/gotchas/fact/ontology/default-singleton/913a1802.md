# fact.DefaultOntology() returns a process-wide SINGLETON (sync.Once): mutating it — even in a test — leaks into every later preset repo in the process; parse a copy first

`fact.DefaultOntology()` builds the embedded default ontology once (`defaultOntologyOnce.Do`) and returns the SAME *Ontology to every caller. Setting `o.Attributes` (or anything else) on the returned pointer changes the default for every subsequent `Mode: "preset"` repo created in that process.

Observed in F21 S2: a test set `sync: {pull: realtime}` on DefaultOntology() to seed a bare origin; a LATER test's freshly created preset repo then read pull: realtime at its own main, and failed only when run after it (order-dependent, -count=2).

Consequence: to derive a variant, serialize the default and re-parse it (`fact.ParseOntology(def.Serialize())`), then mutate the copy. Misreading to avoid: the name sounds like a constructor; it is an accessor to shared state.

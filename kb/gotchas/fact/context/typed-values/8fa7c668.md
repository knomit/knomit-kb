# Context values are typed by YAML tag: an unquoted number under a key declared `string` reads as a number and is refused on the next write; `time` normalisation lives in the typed layer, not SerializeFact; invalid UTF-8 never reaches the MCP handlers

- An unquoted `task: 017` in a hand-written file is YAML int → float64 17. A key declared `string` then refuses a number on the next MCP or REST write (the file still reads and indexes). Knomit itself always writes strings !!str-tagged (quoted only where needed), so only hand-written files hit this — quote the value.
- An unquoted 2026-10-01 is NOT a time.Time (the expires trap): decodeContext reads the !!timestamp tag as its text.
- SerializeFact has no ontology, so it cannot know a key is a `time`. NormalizeContext (called on learn, update, REST PUT and resolutions, before the typed gate) rewrites time values to UTC with a Z at whole seconds. The F22 design text placed this in SerializeFact; that was not possible.
- MCP arguments pass through decodeArg's JSON round trip, which replaces invalid UTF-8 with U+FFFD before a handler sees it; the UTF-8 rule is enforced, and tested, at SerializeFact. A goja int64 from a script becomes float64 through the same round trip.

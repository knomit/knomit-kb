# Renaming the .mcp.json server silently strips the knomit tools from every session — the old name stays approved and the new one lands in the local DISABLED list, which hides it from /mcp with no prompt

DISTINCT FROM the neighbouring Claude Code gotchas: mcp-startup-ordering is about knomit not LISTENING when the session starts; init-merge is about a rewritten `command`; bridge-path is about `kb` missing from $PATH for hooks. This one is about the APPROVAL LISTS in the developer's local settings, with the server configured correctly and the binary healthy.

On 2026-09-18 the kb rename (#218, #220) changed the project's `.mcp.json` server from `knomit` (command `dist/knomit-bridge`) to `knomit-lens-knomit-dev` (command `dist/kb`). Every Claude Code session started that day had NO `knomit_*` tools: ToolSearch found none, `/mcp` and `claude mcp list` did not list the server, and nothing errored. Three sessions spent the day drafting facts as PR comments because none could write.

CAUSE: the gitignored `.claude/settings.local.json` still carried `enabledMcpjsonServers: ["knomit"]` (the old name, now matching nothing) and `disabledMcpjsonServers: ["knomit-lens-knomit-dev"]` (the new name, presumably from a one-time "don't use this server" answer). A project server in the disabled list is hidden from `/mcp` ENTIRELY, so the usual approval prompt never reappears — there is no surface that says "disabled". The per-project lists in `~/.claude.json` were empty and were a red herring; the local settings file is the one that decides.

WHY IT PRESENTS AS ABSENCE: from the agent's side a disabled server and a never-configured server look identical. It reads like the skills are unavailable, not like a config problem, so the natural move is to debug the knomit stack — which is healthy.

FIX: set `enabledMcpjsonServers` to the CURRENT `.mcp.json` server name and empty `disabledMcpjsonServers` in `.claude/settings.local.json`, then restart the session (`/exit`, then `claude --resume` and pick the session; with several sessions in one directory `--continue` reopens whichever was most recently active, not the one you are in). The lists are read at session start only.

CHECK ORDER when knomit tools are missing: (1) the server name in `.mcp.json`; (2) that name against both lists in `.claude/settings.local.json`; (3) cwd is the repo root — `${CLAUDE_PROJECT_DIR:-.}/dist/kb` resolves relative to cwd, so a subdirectory start gives ENOENT (the older, separate cause); (4) `dist/kb --help` runs; (5) only then the startup-ordering gotcha and the knomit stack itself.

WHEN RENAMING THE SERVER AGAIN: the rename PR cannot fix anyone's local settings, so its description must tell every developer to move the new name into `enabledMcpjsonServers` and restart.

# config.SocketPath must NOT call config.Load: Validate and every unrelated KNOMIT_* parse would turn a non-socket config problem into a silent TCP fallback for the bridge

The bridge needs exactly one thing from config: where the local listener is. So config.SocketPath resolves only that. It starts from config.homeAndConfig, the same starting point Load uses: ResolveHome's tilde-expanded root (a relative one is refused), then `<home>/knomit.toml`. It reads the knomit.toml `socket` key and passes that plus os.Getenv("KNOMIT_SOCKET") to config.socketFor, the same function Load uses. It deliberately does not call Load.

WHY: Load runs Validate and parses every KNOMIT_* variable (ints, bools, durations, floats), and any failure is an error. knomitapi.SocketPath maps any error to "" (use TCP). Routing it through Load would therefore drop the bridge to TCP, and lose the verified identity, for reasons that have nothing to do with the socket: an invalid KNOMIT_LOG_MAX_SIZE, a bad [auth] combination, or simply a bridge launched by an MCP host with a DIFFERENT environment from the server's. The failure would log one WARN and otherwise look like the server not running.

WHAT IT DOES DECODE: knomit.toml into a zero `Config`, reading only `.Socket`. That reuses Config's own `toml:"socket"` tag instead of repeating it. Unknown and other keys are ignored: Load warns about them, SocketPath does not need to.

WHAT IT DOES RETURN AS ERRORS: only failures of the listener's own inputs, which Load refuses identically:
- a data root ResolveHome refuses (relative after ~ expansion);
- a decode error, wrapped with the file's path (`config: <path>: …`) so that the operator learns WHICH knomit.toml is broken; the default would be a listener nobody opened;
- socketFor's refusal of an explicit socket that breaks this platform's rule (unix: not absolute after ~; Windows: not a pipe name).

The same trap applies to the agreement TESTS, which run the full Load: they clear every KNOMIT_* variable first, so a stray KNOMIT_LOG_* in a developer's shell cannot fail a socket test.

MISREADING TO AVOID: "the bridge should just call Load to be sure it agrees". Agreement comes from the shared homeAndConfig + socketFor, not from sharing Load; see the listener-layering invariant.

# config.SocketPath must NOT call config.Load: Validate and every unrelated KNOMIT_* parse would turn a non-socket config problem into a silent TCP fallback for the bridge

The bridge needs exactly one thing from config — where the local listener is — so config.SocketPath resolves only the socket's inputs (ResolveHome, tilde expansion, the knomit.toml `socket` key, KNOMIT_SOCKET) through config.socketFor, the same function Load uses. It deliberately does not call Load.

WHY: Load runs Validate and parses every KNOMIT_* variable (ints, bools, durations, floats), and any failure is an error. knomitapi.SocketPath maps any error to "" — use TCP. So routing it through Load would make an invalid KNOMIT_LOG_MAX_SIZE, a bad [auth] combination, or simply a bridge launched by an MCP host with a DIFFERENT environment from the server's, drop the bridge to TCP and lose the verified identity for a reason that has nothing to do with the socket. The failure would log once at WARN and otherwise look like the server not running.

It decodes knomit.toml into a local struct holding only `Socket string toml:"socket"`; unknown keys are ignored (Load warns about them, SocketPath does not need to). A decode error IS returned, because Load refuses the same file and the default would be a listener nobody opened.

MISREADING TO AVOID: "the bridge should just call Load to be sure it agrees" — agreement is guaranteed by the shared socketFor, not by sharing Load; see the listener-layering invariant.

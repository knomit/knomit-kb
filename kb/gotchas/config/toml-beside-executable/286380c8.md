# knomit.toml is read ONLY from <home>/knomit.toml — findConfigFile no longer looks beside os.Executable(), because the server and the bridge/kb are different binaries and a file beside one of them was read by that binary alone

`config.findConfigFile(home)` returns `<home>/knomit.toml` if it exists, else "". It does NOT look beside `os.Executable()` any more. Until knomit#274 (PR #293) it checked `filepath.Dir(os.Executable())/knomit.toml` FIRST. Every binary evaluated that against itself (`knomit serve`, the desktop, the bridge / `kb`), so a knomit.toml beside only ONE binary was read by that binary alone. The two sides then resolved different local listeners, the bridge fell back to TCP, and the verified identity was lost with no error.

WHY IT WAS DROPPED, not merely documented (user decision on #274): the lookup came in with the first layered-config commit (672fbf5b) with no recorded reason. Nothing shipped relies on it: the release tarball carries only the three executables plus lib/, and the macOS bundle ships no knomit.toml. It also broke the desktop: Settings writes `<home>/knomit.toml` (tools/desktop/app.go newNativeService), so a stray file beside the executable would have made every Settings save silently ineffective. The rejected alternative was to keep the lookup and log which file each binary read.

CONSEQUENCES:
- Do not reintroduce a per-binary search location: any location evaluated against the running executable, its cwd or its own environment is a divergence channel between server and bridge (see the rendezvous-inputs synthesis).
- An operator who had a knomit.toml beside the binary must move it to `<home>/knomit.toml`. Before the fix it was read; after, it is silently ignored. That is the only behaviour change for existing installs.
- Enforced by `TestFindConfigFile_OnlyHome` (internal/config/config_test.go), which plants a knomit.toml beside the test binary and requires findConfigFile to ignore it.

WHAT THIS DOES NOT MEAN: not that the desktop's bundled tools stopped being found beside the executable. installBundledTool (tools/desktop/bundled.go) still copies binaries from beside os.Executable(). Only the CONFIG search changed.

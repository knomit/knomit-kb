# Ollama can fail mid-stream with an {"error":...} NDJSON line under HTTP 200; the v2 adapter turns it, a missing done line and any undecodable line into errors

Per Ollama's errors doc (docs/api/errors.mdx, main read 2026-11-04) an error after the response started arrives as a final object such as {"error":"an error was encountered while running the model"} and the HTTP status stays 200. OllamaChat.Stream returns that text as an error; a stream that ends before a done:true line (dropped connection) and a line that is not JSON are also errors (the v1 adapter skipped undecodable lines). Every decoded line calls StreamOptions.Progress, including thinking-only lines that reach no sink, which is what keeps WrapChat's first-activity timer from cutting off a thinking model. Non-200 statuses are formatted "ollama: HTTP <code>: <body>" so the existing isRetryable overload classifier (429/503/529) still matches. Tool-call arguments that are not a JSON object are stored as {} with the bytes in ToolUse.RawArgs (ArgsErr), null arguments are an empty call.

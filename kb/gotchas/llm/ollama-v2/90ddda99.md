# Ollama v2 Usage: prompt_eval_count is ALL prompt tokens and prompt_eval_cached_count the cached part (v0.35.0+), so Input = count - cached and CacheRead = cached; only a server with no cached field gets an estimated CacheRead

On Ollama v0.35.0 and later (checked at v0.35.0, v0.40.0 and v0.40.14) the final stream line carries prompt_eval_count = ALL prompt tokens, cached ones included (llm/llama_server.go promptEvalCount returns cache_n + prompt_n), and prompt_eval_cached_count = the prompt tokens read from the KV cache (api/types.go Metrics, a pointer: absent when the server does not report it). The field is NOT in api/types.go at v0.30.0. usageFromFinal, when the cached field is present: Input = prompt_eval_count - cached, CacheRead = cached, PromptEval = prompt_eval_count, Output = eval_count, nothing estimated, Estimated false. Input therefore means the same as in the Anthropic adapter (uncached input), and Input + CacheRead == PromptEval, with no double count. A reported cached count of 0 is a real 0, not the fallback. When the field is ABSENT (an Ollama older than v0.35.0, where prompt_eval_count is only the tokens evaluated), the fallback applies: Input = PromptEval = prompt_eval_count and CacheRead = max(0, bytes/4 estimate of the snapshot (Snapshot.Record) - prompt_eval_count); only then Estimated is true, and Usage.EstimatedFields is ["cache_read"], naming the one estimated field. Consequence: never read Usage.Estimated as 'the whole Usage is a guess'; check EstimatedFields. Does NOT mean the fallback CacheRead measures reuse on a current Ollama: it never runs there. A cache hit still requires a byte-stable prefix up to the newest turn plus the model staying loaded (keep_alive); renderOllama puts hooks 2-5 in one system message and tools in name order, and the mcp chat_prefix test compares those wire bytes across two instances and two runs. Documented keep_alive default is 5m (Ollama API docs, main read 2026-11-04); this adapter sends 30m. Supersedes the earlier version of this fact, which said prompt_eval_count counted only evaluated tokens: false from v0.35.0.

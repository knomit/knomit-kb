# Ollama cache visibility is estimated: Usage.CacheRead = max(0, bytes/4 estimate of the whole snapshot - prompt_eval_count), always flagged Estimated

Ollama reports no cache counters; its final stream line has prompt_eval_count (prompt tokens it actually EVALUATED, smaller than the prompt when the runner reused its KV cache) and eval_count. usageFromFinal sets Input and PromptEval to prompt_eval_count, Output to eval_count, and CacheRead to the local estimate (sum of Snapshot.Record().Tokens, i.e. canonical bytes/4) minus prompt_eval_count, floored at 0; Estimated is always true. Consequence: CacheRead is a hint of reuse, not a measurement, and the bytes/4 estimate over- or under-counts real tokens, so a model with a different tokenizer shifts it; never bill or alert on it. A cache hit requires a byte-stable prefix up to the newest turn plus the model staying loaded (keep_alive); renderOllama puts hooks 2-5 in one system message and tools in name order, and the mcp chat_prefix test compares those wire bytes across two instances and two runs. Documented keep_alive default is 5m (Ollama API docs, main read 2026-11-04).

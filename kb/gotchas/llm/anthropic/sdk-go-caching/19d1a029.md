# anthropic-sdk-go v1.26.0: ToolInputSchemaParam.ExtraFields marshal in random map order, and Message.Accumulate drops the cache counts of message_delta — both silently break caching or usage

Two properties of github.com/anthropics/anthropic-sdk-go v1.26.0 (pin the version; line numbers are dated support):

1. ToolInputSchemaParam.MarshalJSON goes through param.MarshalWithExtras (packages/param/encoder.go), which ranges over the ExtraFields MAP and applies each key with sjson.SetBytes. With two or more extra schema keys the output key order follows Go's random map iteration, so the tools block (the very start of the cached prefix) can change bytes between requests and the prompt cache silently misses. knomit's renderAnthropic therefore never uses ExtraFields: it sets the whole schema with param.Override[anthropic.ToolInputSchemaParam](canonical schema bytes).

2. Message.Accumulate (messageutil.go) copies ONLY Usage.OutputTokens from a message_delta event. MessageDeltaUsage documents its input/cache counts as cumulative, and on current API versions message_delta carries them, while message_start carries the initial input and cache counts. Usage built by Accumulate can therefore report zero cache reads. AnthropicChat.Stream takes, per field, the max of message_start's and message_delta's values; TestAnthropicChat_StreamMapsEventsAndUsage runs both shapes (counts only in message_delta, counts in message_start with output only in message_delta) and expects {input 11, cache_read 22, cache_write 33, output 44} from each; a sabotage dropping the delta cache_read fails the first shape.

Also: cache_control is not accepted on thinking blocks, and current models (Opus 5.5 and peers) reject thinking budget_tokens with a 400, so ThinkingBudget must stay 0 for them (no thinking parameter is sent then).

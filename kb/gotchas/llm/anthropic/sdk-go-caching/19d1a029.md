# anthropic-sdk-go v1.26.0: ToolInputSchemaParam.ExtraFields marshal in random map order, Message.Accumulate drops the cache counts of message_delta, and adaptive thinking has no display field — and on current models thinking is always on, so effort (always sent) is the control

Two properties of github.com/anthropics/anthropic-sdk-go v1.26.0 (pin the version; line numbers are dated support):

1. ToolInputSchemaParam.MarshalJSON goes through param.MarshalWithExtras (packages/param/encoder.go), which ranges over the ExtraFields MAP and applies each key with sjson.SetBytes. With two or more extra schema keys the output key order follows Go's random map iteration, so the tools block (the very start of the cached prefix) can change bytes between requests and the prompt cache silently misses. knomit's renderAnthropic therefore never uses ExtraFields: it sets the whole schema with param.Override[anthropic.ToolInputSchemaParam](canonical schema bytes).

2. Message.Accumulate (messageutil.go) copies ONLY Usage.OutputTokens from a message_delta event. MessageDeltaUsage documents its input/cache counts as cumulative, and on current API versions message_delta carries them, while message_start carries the initial input and cache counts. Usage built by Accumulate can therefore report zero cache reads. AnthropicChat.Stream takes, per field, the max of message_start's and message_delta's values; TestAnthropicChat_StreamMapsEventsAndUsage runs both shapes (counts only in message_delta, counts in message_start with output only in message_delta) and expects {input 11, cache_read 22, cache_write 33, output 44} from each; a sabotage dropping the delta cache_read fails the first shape.

Also: cache_control is not accepted on thinking blocks.

Thinking on current models is ALWAYS ON, and effort is the control. Omitting the thinking parameter does NOT mean thinking is off: it means adaptive thinking with display "omitted" (empty thinking text, a long silent pause before output in a chat UI). Haiku 5.5, Sonnet 5.5 and Opus 5.5 all reject {type: enabled, budget_tokens} with a 400; {type: disabled} is a 400 on Sonnet 5.5 and Opus 5.5 (Haiku 5.5 takes it only at effort high or below). knomit therefore removed ThinkingBudget: AnthropicChat sends thinking {type: adaptive, display} and output_config.effort on EVERY request, from the caller-supplied llm.ModelProfile{Effort, MaxOutput, ThinkingDisplay}; zero fields take DefaultModelProfile (effort medium, max_tokens 64000, display summarized). Per-model defaults apply (API defaults: Haiku 5.5 medium, Sonnet 5.5 high, Opus 5.5 medium), but knomit never relies on them: effort is always explicit. Thinking counts against max_tokens, so a small max_tokens can end at stop_reason max_tokens before any text. Changing the top-level effort between requests invalidates the prompt cache: keep one effort per conversation.

SDK v1.26.0 gaps: ThinkingConfigAdaptiveParam has no display field, so renderAnthropic sets it with SetExtraFields({"display": …}) (one key, so no map-order instability); OutputConfigEffort has no xhigh constant, so the effort string is converted directly. TestAnthropicChat_RequestShapeFromProfile asserts the received body's thinking, output_config.effort and max_tokens per profile, and that tool_choice, temperature, top_p, top_k, budget_tokens and "disabled" are absent.

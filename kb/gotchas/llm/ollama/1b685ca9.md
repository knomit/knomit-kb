# An Ollama chat's first request can be refused because the toolset plus repo instructions alone exceed num_ctx minus the reply reserve; the loop now says so with the sizes, and no default num_ctx is claimed to be enough

In PR 763 live acceptance an Ollama model with num_ctx 32768 refused its first turn: about 22K tokens of tool schemas and repo instructions plus the window/4 reply reserve left no room. The size of the toolset varies with the tools exposed and the repo instructions, so that measurement is not a property of the code and no constant is derived from it; the example config's num_ctx is left unchanged. Loop.checkBudget (and the adapter ErrContextFull path) on an OPENING request (nothing in hook 6, at most the first user entry in hook 7) returns OpeningTooBigMessage_DRAFT naming the estimated opening tokens, the window, the reserve and the room left, and for provider ollama appends the raise-num_ctx hint. Later turns keep the generic context-full message. Copy is DRAFT awaiting user approval.

Does NOT mean 32768 can never work or that 65536 always works.

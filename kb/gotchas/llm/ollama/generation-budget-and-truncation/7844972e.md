# Ollama counts reasoning tokens against num_predict, and a truncated stream is a SUCCESSFUL HTTP response

Two properties of ollama's /api/chat that together produce a silent empty answer, and that only a reasoning model makes routine.

**1. Reasoning tokens are generated tokens.** They are charged against `num_predict` server-side, before any of them reach the client, so discarding `message.thinking` client-side does not give the budget back. Measured on gemma4:26b-mlx, same prompt and seed: `num_predict=2000` returned `done_reason:"length"` with `eval_count=2000` and EMPTY content; `num_predict=-1` answered correctly using 7565 tokens. A cap sized for a metered API (knomit's shared defaultMaxTokens = 8192) is therefore spent on reasoning and the answer is never written.

**2. Truncation arrives as HTTP 200.** The final NDJSON frame carries `done:true` with `done_reason:"length"`. Nothing else distinguishes it from a completed answer — `scanner.Err()` is nil and the body is well-formed. Reading only `message.content` and ignoring `done_reason` yields `("", nil)`, and internal/corpus/synthesize's pipeline checks only `err`, so an empty string flows onward as though the model had answered. The adapter now guards against this: internal/engine/llm/ollama.go reads done_reason from the final frame and returns an error when it is "length".

**Consequence for consumers:** never treat a done frame as success without reading `done_reason`, and do not inherit a cross-provider max-tokens constant on a local model — there is no spend to bound, so the cap only truncates.

**What this does NOT say:** it is not a claim that ollama truncates prompts. Ollama 0.32.5 auto-sizes the context window — a ~20k-token prompt returned HTTP 200 with `prompt_eval_count=20023`, no 400 — so the "input length exceeds context window" 400 described in resilience.go's overloadStatusRe comment is stale as a description of the common case, though the anchored regex is still worth keeping as defence.

The JSON-constraint decision on the same adapter (kb/decisions/llm/ollama/forcejson-mechanism-per-model) is the companion fact: both came out of the same investigation, and both are about a mechanism that is safe on a non-reasoning model and harmful on a reasoning one.

# LLMAdapter decorators erase BatchAdapter; TracingAdapter already does

llm.BatchAdapter (CompleteBatch/BatchEnabled, internal/llm/adapter.go:62-66) is implemented only by GeminiAdapter and has ZERO consumers anywhere in the repo — nothing calls CompleteBatch or BatchEnabled outside internal/llm itself as of 2026-07-21. Consequence: any decorator that wraps an LLMAdapter into a plain struct (TracingAdapter, trace.go:16, wrapped at internal/app/app.go:94-101 when KNOMIT_LLM_TRACE is set) silently erases the BatchAdapter interface from the value, so a batch-enabled Gemini adapter loses batching under tracing today — latent because no consumer exists yet, but it will silently pre-break the first future CompleteBatch caller. Any new decorator (e.g. the P1.2 retry/timeout wrapper) must conditionally return a batch-preserving variant via `if ba, ok := inner.(BatchAdapter)`, and a type-assertion test should pin this. Misreading to avoid: 'no consumers' does NOT mean the interface is safe to drop — config.LLMConfig.Batch exists and gemini implements the path; it is future-load-bearing.

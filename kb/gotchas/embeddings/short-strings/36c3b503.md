# Short-string embeddings (tags, motifs, slugs) are anisotropic and model-dependent — center them, and re-validate on any model swap

Embedding short strings (2-4 word tags, path slugs, motif names) behaves very differently from embedding documents, in two measured ways. (1) Anisotropy: raw vectors sit in a narrow high-similarity band; subtracting the vocabulary mean and re-normalising brings mean off-diagonal similarity to ~0 and is REQUIRED before any threshold is meaningful. (2) Model dependence: on nomic-v1.5 a semantically true pair (ai-adoption ~ ai-coding-agents, 0.771) and a false pair (operations ~ business, 0.776) are indistinguishable — short-string similarity is unusable; on embeddinggemma the same pairs separate (0.677 vs 0.581). Even centered embeddinggemma stays blind to some same-mechanism pairs (single-copy-invariant ~ single-source-of-truth = 0.22). Consequence: any feature matching short strings by embedding must (a) center over the string vocabulary, (b) treat thresholds as model-calibrated, and (c) be re-validated when the embedding model changes — porting a threshold across models by value is meaningless here.

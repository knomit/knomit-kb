# Idle RSS EQUALS peak RSS after any large batch, so non-embedding RSS is measurable only BEFORE the first inference

A natural way to measure a server's non-embedding memory footprint is to wait for it to go quiet and read RSS. For knomit this is WRONG and produces a figure roughly 4x too large.

Because the ONNX arena retains its high-water mark for the process lifetime, once any large batch has run there is no quiescent baseline left to read: idle RSS IS peak RSS. Measured 2026-08-29 after indexing — 4203 MiB idle against a 4219 MiB peak.

Any 'non-embedding RSS' derived that way is mostly retained arena, not Go heap plus go-git plus index. Feeding it into a memory-derived batch-size formula shrinks the derived budget far below what the machine can actually support — the failure is silent and in the conservative direction, which is why it survives review.

THE ONLY VALID WINDOW is after boot completes but BEFORE the first embedding batch. In a knomit boot that window sits between the `knomit ready` log line and `rebuild: phase 2 (embeddings)`.

CONSEQUENCE: make the measurement self-taking rather than remembered — have the embedder log process RSS immediately before its first `session.Run`. This was gotten wrong once already by someone who had written down the arena-retention fact hours earlier, which is the argument for building it in rather than documenting it.

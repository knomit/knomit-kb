# knomit_experiment names must be kebab-case and REJECT slashes, so an experiment cannot be named identically to a feature branch like `feat/signal-type`

The /knomit-experiment skill says to open an experiment named after the git branch and to "keep the name identical to the git branch — that is what lets anyone match an orphaned experiment to its PR later". For any branch carrying a `type/` prefix, that instruction cannot be followed.

`knomit_experiment {action: "open", name: "feat/signal-type"}` is refused with: `experiment name must be kebab-case (lowercase letters, digits and single hyphens): got "feat/signal-type"`. The refusal is immediate and nothing is created.

The working convention is to kebab-ise: branch `feat/signal-type` becomes experiment `feat-signal-type`, and the `description` (local-only, never committed) records the real branch name so the two can still be matched by a human later. Do this deliberately rather than dropping the prefix, because `signal-type` alone would collide with any other branch touching the same feature.

What this does NOT mean: it is not a reason to skip the experiment or to write PR facts on the agent branch. The name is a label; the branch association that matters is recorded in the experiment's parent and description.

The skill's wording is the thing that is wrong here, not the tool — a validator that accepted slashes would be creating `exp/feat/signal-type`, a two-level ref under the `exp/` namespace.

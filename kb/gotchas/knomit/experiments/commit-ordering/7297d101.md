# An experiment can be committed by ANY session or the UI, not only the session that opened it — the owning session learns nothing and heals onto the agent branch silently, so the post-merge re-pin is advisory and must be checked on the agent branch afterwards

THE MECHANISM: an experiment (exp/<name>) is a repo-local branch, not a per-session lock. Any session bound to the same repo, or the web UI, can run `knomit_experiment commit` on it. The session that opened it is not notified; its next call simply finds itself on the agent branch, and `list` reports zero experiments with no lapsed marker.

WHAT HAPPENED (F01, PR #247, 2026-09-22): the worker session left experiment feat-signal-type open with five facts carrying 're-pin src:// refs to the merge commit before this fact leaves the experiment' notes. The experiment was committed to the agent branch at 22:46Z (commit c431092b), two minutes BEFORE the PR merged at 22:48Z (f8142735), by a different actor than the session that wrote the facts. The five facts therefore landed on the agent branch with a7bed673 pins, no refs for the new code, and the re-pin notes still in their bodies. The CLAUDE.md workflow — commit the experiment AFTER the PR merges, re-pinning first — did not run.

WHY NO HARM THIS TIME: #247 was a true two-parent merge, so a7bed673 stayed reachable and no ref went dead. Had it been a squash merge, eight facts would have shipped to the agent branch with dead anchors and nobody watching.

CONSEQUENCES a consumer must act on:
- Before committing an experiment for a PR'd branch, check that the PR has MERGED and that the experiment's facts no longer carry 're-pin at merge' notes. If you did not write the facts, ask the session that did, or read them.
- If you discover an experiment was committed early, the remedy is knomit_update on the agent branch: re-derive blobs at the merge commit (`git rev-parse <merge>:<path>`), replace the notes, re-read each claim. That is what was done for F01 (revisions 894ae135, 70c6bc73, 122b3e86, 525b623b, 93fd5fbc).
- A session that owns an open experiment cannot assume it still does; run `knomit_experiment list` before a write that must land in the experiment.

WHAT THIS DOES NOT MEAN: it does not mean experiments are unsafe or that the agent branch should be written directly for PR'd code. It means the ORDER (merge, re-pin, commit) is enforced by people, not by the tool.

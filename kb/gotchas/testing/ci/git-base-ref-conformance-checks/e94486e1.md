# ANTI-PATTERN: a conformance check that diffs against a git base ref enforces NOTHING in CI — it skips on PRs and fails on the base branch itself

`TestConformance_BridgeFilesUntouched` resolved a base ref (`dev`/`origin/dev`/`master`/`origin/master`), diffed the working tree against the merge base, and asserted the constraint over the changed files. It could not run where it mattered and could not pass where it ran:

- ON A PUSH TO THE BASE BRANCH, actions/checkout does `git checkout -B dev refs/remotes/origin/dev`, so the ref exists and `merge-base dev HEAD == HEAD`. The diff is EMPTY BY CONSTRUCTION and the anti-vacuity guard fails. 11 of 11 dev runs went red, on three legs each.
- ON A PULL REQUEST, the depth-1 checkout is detached and carries none of those refs, so the test SKIPS and `go test` reports `ok`.

Red exactly where it was meaningless; absent exactly where it was meaningful. The `-skip` in race.yml that papered over half of it claimed the test was "still enforced on a branch, before merge" — true only for a developer's local run, which is not CI.

THE DEEP ERROR IS IN THE ANTI-VACUITY GUARD, not the plumbing. "The diff is empty, therefore the base ref is wrong" is a non-sequitur: AN EMPTY DIFF MEANS "HEAD IS THE BASE" AS OFTEN AS IT MEANS "WRONG BASE REF", and the check has no way to tell those apart. A guard that cannot distinguish its own vacuity from its own success is not a guard.

THE FIX SHAPE: ask a question about the ARTEFACT rather than about the checkout. A pinned SHA-256 of the protected file answers identically on the base branch, on a PR and on a laptop, because it does not consult git at all. Reach for this whenever a conformance check is tempted to shell out to git.

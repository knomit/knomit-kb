# A chat started through POST /api/v1/chats ends on its own when no events stream is attached (chatStreamGrace), and chats do not survive a server restart: for a UI check, open the page first, then start the chat

Observed 2026-11-09 on a scratch server: chats created by API while no browser had the page open came back 404 'no such chat' a short while later, and every chat was gone after the server restarted. chat.go arms a grace timer (chatStreamGrace, graceFired) when no stream holds the chat, and ends it when the timer fires. Consequence: for a real-browser check of a chat feature, load the app page (which opens GET /chats/events) BEFORE creating the chat, and recreate chats after any restart. Also: on that build `knomit serve` did not take its port from a [server] table in knomit.toml and tried the default 19278; pass --host and --port explicitly so a scratch server never collides with the user's.

# Chats do not survive a server restart, so a UI check must recreate its chats after any restart; give a scratch `knomit serve` an explicit --host and --port

Chats live only in the running server: after a restart every chat is gone from GET /chats (observed 2026-11-09 on a scratch server; only their session logs remain). Consequence: for a real-browser check of a chat feature, recreate the chats after any restart of the scratch server.

Since PR #817 a chat ends only on DELETE, server stop, or a refused first turn (kb/invariants/chat/lifetime/3a4b7d86.md). A chat created through POST /api/v1/chats with no page open therefore lives, and a page opened later lists it via GET /chats; the order of opening the page and creating the chat no longer matters. (On 2026-11-09, before #817, such chats came back 404 'no such chat' after the 60 s chatStreamGrace; that is gone.)

Also observed 2026-11-09: on that build `knomit serve` did not take its port from a [server] table in knomit.toml and tried the default 19278; pass --host and --port explicitly so a scratch server never collides with the user's.

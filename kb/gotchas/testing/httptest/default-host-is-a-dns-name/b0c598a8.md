# httptest.NewRequest defaults Host to "example.com" — a DNS name — so any handler behind a loopback Host guard answers 421 in tests unless req.Host is set to an IP literal or localhost; the Host-side sibling of the RemoteAddr-is-192.0.2.1 gotcha

net/http/httptest.NewRequest fills two fields that look harmless and are not: RemoteAddr = "192.0.2.1:1234" (a non-loopback TEST-NET address, already recorded as the httptest-remoteaddr-is-not-loopback gotcha for PEER checks) and Host = "example.com" (when the target URL has no host). "example.com" is a DNS name, so hostguard.LoopbackHostOK refuses it: every existing internal/platform/diag test would have flipped to 421 after PR #292 added the Host guard even with RemoteAddr fixed. The serve() helper in internal/platform/diag/server_test.go now sets both (RemoteAddr "127.0.0.1:1", Host an IP literal), and guard_test.go forges each on purpose.

Consequence: a test that drives any loopback-guarded handler (AuthMiddleware's anonymous branch, the diag guard) through httptest must set BOTH req.RemoteAddr and req.Host explicitly for the admitted case, or use a real loopback TCP connection as internal/web/auth_host_guard_test.go's rebound() helper does. A 421 in such a test is a fixture problem before it is a code problem. This fact is about the HOST default; the sibling fact is about the RemoteAddr default and the write gate.

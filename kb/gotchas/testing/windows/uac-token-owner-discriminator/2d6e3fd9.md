# A Windows test that asserts 'the pipe (or file) we created is owned by our own SID' passes from an elevated session-0 shell and from an unelevated one, and FAILS only under a UAC split token (an Interactive RunLevel Highest scheduled task, the token the desktop runs with), because only that token has TokenOwner = BUILTIN\Administrators; to see the owner trap in a test, run the test binary under such a task

**Measured (worker session, 2026-09-27, Windows 10 19045, knomit#265 forced red R2).** Three tokens for the same user: SH = the Claude session-0 elevated shell (High IL, TokenOwner = user); HI = an interactive scheduled task with RunLevel Highest (High IL, TokenOwner = BUILTIN\Administrators: the UAC-elevated kind the desktop gets); LO = an interactive scheduled task with RunLevel Limited (Medium IL, TokenOwner = user). With the `O:` part removed from ownerOnlySDDL, TestListenLocal_PipeIsOwnedByTheCaller PASSED from SH and FAILED under HI with 'the pipe is owned by S-1-5-32-544, want our own SID'; with `O:<sid>` present it passed under all three. The same TokenOwner=BA effect is what made %LOCALAPPDATA%\knomit owned by Administrators in the knomit#301 survey.

**Consequence.** An 'owned by me' assertion run only from the developer's shell or from CI (GitHub's runneradmin is an elevated session-0-style token, TokenOwner = user) cannot catch a missing `O:`; the SDDL-prefix assertion (TestOwnerOnlySDDL_NamesTheOwner) is the one that holds under every token, and the ownership assertion is the discriminator only when the binary runs under a UAC split token. When a change concerns who OWNS a created object on Windows, run the test binary under an Interactive RunLevel Highest task once, by hand, and say so in the test comment.

**Misreading to avoid.** 'Elevated' is not one thing: the session-0 elevated shell and a UAC-elevated interactive process differ in TokenOwner even though both are High IL and both pass IsElevated. Measurements of object ownership taken from the former do not transfer to the desktop.

# A Go test that builds a JSON request body by string concatenation and embeds a filesystem path breaks only on Windows: C:\Users\RUNNER~1\... puts \U in a JSON string, the server answers 400 'invalid character U in string escape code', and PR CI never runs the Windows tests — encode the body with json.Marshal

Eight TestOriginEscalation_* tests in internal/edge/web were red on every dev push from dd73ed85 (2026-10-29) in the Windows job 'tests / build-test (windows-2025)', step 'Story, web + desktop-helper tests'. They built bodies like `{"url":"`+bare+`","branch":"main"}` where `bare` is a raw t.TempDir-derived path. On Windows that is C:\Users\RUNNER~1\..., and `\U` is not a valid JSON escape, so httpx.DecodeJSON answered 400 'Invalid request body ... invalid character 'U' in string escape code' at byte 12. Tests whose url came from seedKnomitRemoteForTest (a file:///C:/... URL, forward slashes) passed, which hid the pattern. Pull-request CI does not run the Windows tests, so PRs were green.

This fact alone does NOT prevent recurrence: PR #722 added credFixture (origin_credential_api_test.go) with the same concatenated `bare` path after this fact existed, and three TestOriginCredentialAPI_* tests went red on Windows CI until issue #732 fixed it. No lint or guard test enforces the rule (the user declined one), so the check happens when you write or review a test: any body that embeds a variable which could hold a path gets encoded.

What to do: build any test request body that embeds a path or URL variable with encoding/json - in internal/edge/web use mustJSON(t, map[string]any{...}) (handlers_repos_hal_test.go), in cmd use the t-taking fleetBody(t, ...) - never by concatenation. Do NOT 'fix' it by filepath.ToSlash on the input: the defect is that the body was not encoded, and a path with a quote or backslash would still corrupt it.

What this does NOT mean: pure literal bodies like {"branch":"main"} need no change, and the server is not at fault - rejecting the malformed JSON is the correct behaviour. Concatenations whose variable is an http test-server URL, a secret id or a token value (origin_secret_test, secret_link_api_test, restore_credential_test) cannot carry a backslash and are not broken. PR #712 also converted the sibling sites that concatenated a url variable (internal/edge/web consensus_branch_web, handlers_fleet_membership, handlers_origin_hal, handlers_repo_events, handlers_repos_create/initialized/probe; cmd fleet_*); the cmd ones were not broken on Windows (their URLs are https or file:///), so there it is hardening only. Exception, do not 'fix': origin_url_test.go builds bodies from pad forms that are deliberately JSON escape text (\t, \n), so encoding them would change what the test sends. A new test that embeds a path or URL must use the helper from the start.

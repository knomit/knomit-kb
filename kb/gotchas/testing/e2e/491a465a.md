# Two remote-migration e2e specs ('migrate' and 'remote_wins') are skipped (knomit#485): the harness cannot seed the remote's published main, because facts written through the remote's HTTP API land on its agent branch and never reach main

e2e/tests/journeys/remote-migration.spec.ts wraps the 'with a seeded remote' describe in `test.skip(true, SEED_SKIP)`. Reason (from the skip message): the connectivity step counts facts on the remote's published `main`; `seedFact` through the remote instance's HTTP API writes to the remote's agent branch, there is no merge endpoint, and a git push needs an enrolled instance certificate, so the harness has no way to put facts on the remote's main. Needs a bare-repo remote via KNOMIT_LOCAL_ORIGIN_ROOT or a promote step. Tracked in https://github.com/knomit/knomit/issues/485 (open at 2026-10-12). The same PR fixed the spec's setup (it never created the repo and got 404 on /branches, leaking three servers per run).

Consequence: a green e2e run says nothing about the migrate or remote_wins flows (the e2e total after #484 was 122 passed, 6 skipped). Test those flows by other means until #485 is resolved, and remove the skip when it is.

WHAT THIS DOES NOT MEAN: the skip is not evidence the migration feature works or is broken, and it is not a product limitation: seeding the remote's main is a harness limitation. Check #485 before relying on this fact; it is meant to expire when the issue closes.

# The e2e harness does NOT build: `make e2e` and global-setup need dist/knomit AND web/dist/index.html already present, and a missing one stops the run before anything is spawned; E2E_BUILD=1 re-enables `make server`, E2E_BINARY=<path> replaces dist/knomit

Since PR #484 (merged 2026-10-12) neither `make e2e`/`make e2e-ui` (now `cd e2e && npx playwright test [--headed]`, no `dist` prerequisite) nor e2e/global-setup.ts builds anything. global-setup calls `requireBuild()` (e2e/helpers/binary.ts), which checks that BOTH the binary and `web/dist/index.html` exist and otherwise throws an error naming the by-hand commands (`cd web && npx tsc -b && npx vite build`, then `CGO_ENABLED=1 go build -o dist/knomit .` or `make server`) before any home is created or server spawned.

Two environment switches, both read in binary.ts: `E2E_BINARY=<path>` launches that binary instead of `dist/knomit` (the ONNX runtime is looked up in a `lib/` directory next to the symlink-RESOLVED binary, so a binary copied elsewhere without its `lib/` runs without ONNXRUNTIME_SHARED_LIBRARY set); `E2E_BUILD=1` runs `make server` first, which runs `npm ci` in web/. Since PR #508 (merge 7cae543c) it is `make server`, NOT `make dist`, because `dist` is now end to end and also builds the desktop app (needs the desktop toolchain); the harness only needs the server and web UI.

Consequence: before running the suite, build `web/dist` and the binary yourself, and rebuild after every Go or web change you want tested. A stale `dist/knomit` or stale `web/dist` is used silently: the harness checks existence only, not freshness, so a green run proves nothing about code changed since the last build. In a worktree with a symlinked `web/node_modules` never set E2E_BUILD=1 (see kb/gotchas/build/git/worktrees/node-modules-symlink/e07d5204.md).

WHAT THIS DOES NOT MEAN: E2E_BUILD=1 does not build the desktop app, and a by-hand `make dist` is no longer a way to prepare the suite (it works but compiles far more than needed). It does not mean the suite is unsafe to run without building (it stops with a message), nor that `make e2e` ignores E2E_BINARY (it honours it). Playwright's own browser download is a separate step (`make e2e-setup`).

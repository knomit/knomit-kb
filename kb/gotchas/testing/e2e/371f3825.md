# The @playwright/test version in e2e/package.json is pinned (1.61.0) to the one whose bundled chromium revision (1228) matches the browser already in the local cache; a stalled `npx playwright install` half-unpacks and deletes the cached revision

Playwright launches only the chromium REVISION its own playwright-core lists in browsers.json; a different @playwright/test version wants a different revision and fails at launch if that revision is not in the browser cache. e2e/package.json pins `@playwright/test` to exactly `1.61.0` (no caret). Per the PR #484 worker, reading each version's playwright-core browsers.json: 1.60.0 bundles chromium rev 1223, 1.61.0 rev 1228, 1.62.0 rev 1234; the cache held `chromium-1228` and `chromium_headless_shell-1228`, so pinning 1.61.0 made the suite run with no download and no `executablePath` workaround. Revision numbers are third-party facts as of Playwright 1.60 to 1.62 and may differ in other releases; the structural claim is that version and revision are tied one to one.

The cache is also fragile: a `npx playwright install` (also run by `make e2e-setup`) that stalls half-unpacks a revision and deletes the previously cached one, leaving no working chromium. Before that PR the suite ran on a newer browser than the cache expected and 49 specs failed (80 passed, 49 failed, 7 skipped); after pinning, 122 passed, 0 failed, 6 skipped.

Consequence: do not bump @playwright/test (or let a caret/Dependabot bump it) without checking that the new version's chromium revision is cached or can be downloaded; and do not run `npx playwright install` casually on a machine whose cache is the only working browser. If the revision and cache disagree, re-pin to the version matching the cache rather than adding an `executablePath` override.

WHAT THIS DOES NOT MEAN: the pin is not a statement that 1.61.0 is the right Playwright for the project, only that it matches the cache on the machines where this was measured; another machine's cache may hold another revision.

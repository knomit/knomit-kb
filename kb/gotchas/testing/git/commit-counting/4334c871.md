# `git log -- <path>` hides a commit that rewrites a file with identical bytes, so a 'no commit was written' test must compare the branch tip (or rev-list --count), not the path's log

Found while sabotaging F10's fleet boot reconcile: the sabotages 'write on every boot' and 're-register without comparing' stayed GREEN because the tests counted record VERSIONS with `git log --format=%H <branch> -- <record path>`. knomit's WriteFact happily commits a byte-identical rewrite (a new commit, unchanged tree for that path), and git's path-limited log only lists commits that CHANGE the path, so the noise commit was invisible. Fixed by asserting on the branch tip (`git rev-parse <branch>` unchanged) and on `git rev-list --count from..to` for 'exactly one commit'.

CONSEQUENCE: any test claiming 'nothing was written' or 'exactly N commits' in knomit must count commits on the branch, not path history; path history is right only for 'earlier values are earlier versions'. Do not assume the store skips no-op writes: it does not.

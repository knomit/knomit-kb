# A package-level http.Client whose transport is chosen from AMBIENT machine state at init makes "verify at the pushed commit" silently untrue for that package — the suite then reports the developer's machine, not the commit

`var HTTPClient = NewHTTPClient(SocketPath(), os.Getenv("KNOMIT_BASE_URL") != "", httpTimeout)` reads the environment and the filesystem at PACKAGE-INIT time — before any test body runs — and freezes the resulting transport for the life of the process. Every `t.Setenv("KNOMIT_BASE_URL", srv.URL)` in the package then became a no-op, because the variable it sets had already been read and the installed transport ignored the request URL entirely.

MEASURED, same commit, same machine, the only difference being whether a socket file existed at the resolved home:

    $ go test ./tools/bridge/knomitapi/                  # no socket
    ok      knomit/tools/bridge/knomitapi   0.193s

    $ # stale socket planted at ~/.knomit/knomit.sock
    $ go test ./tools/bridge/knomitapi/
    --- FAIL: TestSessionContext_PrinciplesComeFromTargetedQueryNotRecentWindow
    --- FAIL: TestSessionContext_PrincipleNotRepeatedUnderRecentWork
    --- FAIL: TestSessionContext_InvariantsFallbackOnlyWithoutPrinciples
    FAIL

WHY THIS IS A GOTCHA ABOUT VERIFICATION AND NOT ABOUT TIDINESS: the repo's convention is to verify in a clean worktree at the SHA that was pushed. A clean worktree controls the CODE. It does not control `$HOME`, so a package whose behaviour is decided at init from `$HOME` is exactly the case that convention does not cover — and the green run looks identical either way. Both the author's and the reviewer's runs were green here only because no socket happened to exist at `~/.knomit/knomit.sock` at that moment.

THE PASSING CASE IS WORSE THAN THE FAILING ONE. A DEAD socket produces a loud failure. A LIVE one lets those tests reach the developer's real local server instead of their `httptest` one, where they can pass for entirely the wrong reason — a false green that survives review.

WHAT TO DO. Two changes, and the first alone is not enough: (1) build the client on FIRST USE rather than at init, and (2) decide per DIAL, reading the environment inside `DialContext`, because laziness alone only moves the freeze to whichever test runs first. Then pin the suite to a temp home — `isolateHome(t)` sets `KNOMIT_HOME`, `KNOMIT_REPO` and `KNOMIT_BASE_URL` — in every test that could touch the socket path.

THE GENERAL TEST, worth applying to any package-level var: does its initialiser read `os.Getenv`, the filesystem, the network or the clock? If so, ask what the suite would do on a machine where that answer differs. If the answer is "something else", the suite is evidence about the machine and not about the commit.

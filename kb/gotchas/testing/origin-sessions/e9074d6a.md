# A session-manager test that builds a second manager over the same base can have the FIRST manager's late startup sweep still holding the dead run's lock file open, so on Windows the second manager's unlink fails: wait on <-dead.staleDone before Create

A manager built over a base starts a background reclaimDeadRuns sweep. A test that then Creates a run, 'crashes' it (unlocks and closes the lock) and builds a second manager can have the first manager's late sweep still holding the lock file open. On Windows the second manager's unlink of that lock then fails ('dead run's ...lock survived', seen once, in TestSessionManager_StartupSweepReclaimsADeadRun at 91c5d29e).

Fix, in the test at the merge commit: wait on <-dead.staleDone before Create.

In production this race is benign, because the next start retries the reclaim.

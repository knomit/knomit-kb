# A real-store web test whose Server uses a non-"kb" OntologyRoot must also call svc.SetOntologyRoot with the same root, or the index holds no fact under it and enrichment comes back empty

The store indexes only paths for which vcs.Repo.IsFactPath holds: the path starts with the store's ontology root plus "/" (default "kb"), ends in .md, and is not a private path. In production the repos builder (internal/corpus/repos/lifecycle.go) calls svc.SetOntologyRoot(cfg.OntologyRoot) on each store, the same value the web Server gets.

newRealStoreManager builds bare store.Open services and never calls SetOntologyRoot. So a test that sets Server.OntologyRoot to e.g. "ontology" still lists ontology/ from git, but GetByPath returns nil for every fact because the index holds none under that root; type and title then come back empty and the failure looks like a handler bug.

DO: call svcs[name].SetOntologyRoot(root) before writing the facts, as topicsRepo in handlers_topics_test.go does (it deliberately uses "ontology" so a handler hard-coding "kb" lists the wrong directory).

DOES NOT MEAN: ListDir is root-aware. It walks the git tree at any path, so listing succeeds while enrichment silently fails.

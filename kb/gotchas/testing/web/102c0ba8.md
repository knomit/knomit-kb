# newRealStoreManager writes go to "agent/test" (URL "agent:test"); a request for branches/main lists an empty tree, so a "hidden" or "count 0" assertion passes vacuously

Found in W0f (PR #612) by a guard-off sabotage. With a stub lister the branch in the URL never mattered. On a real store, the old TestTopicBrowsersSkipPrivateNamespace repo subtests requested /branches/main while writeFactsInOneCommit writes to ri.AgentBranch() ("agent/test", URL form agent:test). main exists after InitRepo but holds nothing, so ListDir returned an empty list and "count 0" passed even with the private-path guard disabled.

DO: when porting a stub test to a real store, make the URL branch the branch the fixture wrote to. Add a fixture precondition that the store DOES return the entry the guard must hide (call svc.Facts().ListDir on the write branch directly, then require.Len), then run the guard-off sabotage and confirm RED. At the merge commit the subtests do this (ListDir on agent/test, require.Len 1, then request branches/agent:test).

DOES NOT MEAN: every request must use the agent branch. A test of branch-selection logic must use a DIFFERENT branch with a decoy on the agent branch (see kb/conventions/testing/web/99f75ede.md).

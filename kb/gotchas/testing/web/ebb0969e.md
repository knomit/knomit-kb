# A text-less facts read's arguments (depth, offset, filters, path) cannot be observed from outside the store, so they are proved by what the lens union returns; maxLensRecencyDepth and a text read's per-mount Limit are the two limits of that proof

At c3571f43 (PR #610) index.Overrides.Reads receives only the METHOD NAME of a read, and there is no RecentFacts options observer, so a web test cannot assert the Limit, Offset, filters or Path a facts read was called with. Depth, offset, filters and path are therefore proved by what the union returns from a corpus built to separate them. Two limits of that proof:
(a) maxLensRecencyDepth (10000, handlers_lenses_read.go) is observable only with more than 10000 facts per mount; in the PR author's run indexing 10,010 facts took about 96 s, so no test does it. The clamp value stays pinned by TestLensFanoutDepth_OverflowingOffsetStillClamps, and the handler's use of the depth is shown by reachability past 500 facts (a 520-fact mount).
(b) a text read's per-mount Limit is overwritten by the store's recentFactsSearch (it searches with Limit 500, Offset 0 and slices afterwards), so TestLensFacts_TextQueryReachesPastTheFirstPage proves only that the depth covers offset+limit, not what Limit the store saw.

CONSEQUENCE: do not write a test that asserts a facts-read argument through a counter; build a corpus where a wrong argument changes the returned rows. DOES NOT MEAN: that depth, offset or path are untested; they are pinned by outcome, not by call arguments.

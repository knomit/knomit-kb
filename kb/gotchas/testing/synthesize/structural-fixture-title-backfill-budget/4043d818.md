# TestStructural_* in internal/synthesize failed with `expected "rare-token", actual ""` on a slow Windows runner because seedShortlist backfilled title vectors under the PRODUCTION 15 s latency budget (titleBackfillBudget) and ensureTitleVectors returns partial coverage SILENTLY; the fixture's pair has the two highest fact ids, so it sat in the last of 13 batches and was the first thing a stall dropped. FIXED in PR #304 (knomit#298): the fixture seeds to full coverage and asserts it; the production constant is untouched

**Observed.** CI job 108283236877 (run 36199632457, PR #295, `tests / slow-tests (windows-2025 synthesize)`, 2026-09-25): `--- FAIL: TestStructural_RareTokenStaysClosed (49.63s)` at restatement_structural_allowance_test.go:193, `expected: "rare-token" actual: ""`, message `fixture must produce a rare-token match, or the gate is not being tested`. The PR changed nothing in synthesize or store; the leg passed on the ten dev runs before it and on the two PR runs after it. One occurrence.

**Mechanism (at dev 131376e3, before the fix).** `seedShortlist` (restatement_helpers_test.go) called `ensureTitleVectors(ctx, deps, branch, titleBackfillBudget)`; that constant is the production latency budget, `15 * time.Second` (restatement.go:39). `ensureTitleVectors` (restatement.go:57-94) embeds titles 32 at a time `for time.Now().Before(deadline)` and then returns whatever coverage it reached WITH NO ERROR, by design: the session's health output reports partial coverage and later sessions finish. `LiveFactsMissingTitleVector` orders `BY f.id ASC` (store/abstraction.go:79 then; now internal/engine/store/vocab/abstraction.go:79). `structuralEnv` writes ~404 filler facts and THEN the pair under test, so the pair holds the two highest ids: 406 facts = 12 full batches + 22, both halves in batch 13, the last. A stall of ~15 s anywhere in the backfill left the pair with no title vector; it was then never minted by KNN nor by the structural pass (structuralCandidates only returns pairs touching the on-axis requeue), and `pairKindIn` returned "" (its 'never stood' value). Nothing logged the shortfall and the fixture never asserted coverage.

**Evidence.** Forced locally (worker session, `go test -overlay` scratch test): fill the axis for 12 batches only -> coverage 384/406 -> refresh -> `pairKindIn` = ""; finish the backfill -> "rare-token". The real backfill on an i5-3470 takes ~0.6 s for 406/406, refresh ~1.9 s, so CI had to be ~25x slower or stall once. In the failing job the gap from the failing instance's last `index sync: incremental update` line to the next test's `git store initialized` is 16 s (23:24:56 -> 23:25:12) against 1-3 s for every passing instance: the 15 s budget plus the refresh. Another instance in the same job also shows a 16 s gap and its test passed (the dropped batch did not hold its pair). The stall's own cause is not visible in the log. 17/17 local runs passed. The wall clock was the only nondeterministic input between write and assertion: rarity cuts, the hash embedder, id order and candidate ordering are all fixed for a fixed fixture.

**Exposure.** `seedShortlist` has 41 call sites in 8 test files (identity_test 10, restatement_test 11, restatement_dynamics 7, restatement_structural_allowance 7, throttle_honesty 3, certainty 1, emission_honesty 1, standing_work 1); which one failed depended on fixture size and on which batch a stall dropped. One direct caller of `ensureTitleVectors(…, titleBackfillBudget)` with a two-batch fixture (TestRefreshShortlist_SeedsThenGoesIncremental, 40 facts, asserting NeighbourQueries == 40) had the same exposure; the remaining direct callers use one batch or less, or loop to completion.

**Fix (PR #304, branch fix/298-synthesize-fixture-backfill, commits 8cd9651b + 4d1dba0d).** (1) `seedShortlist` requires a non-nil embedder (with none, ensureTitleVectors returns 0,0,nil and have == total == 0 would pass over an empty axis), calls `ensureTitleVectors(…, time.Hour)` (cannot expire in a test; the loop exits when nothing is missing, and it cannot livelock: PutTitleVectors writes the same key the missing-query checks, every failure returns an error, and go test's -timeout is the backstop) and asserts `have == total` with the message `title backfill incomplete (have/total): the fixture's axis must be fully covered, or every downstream assertion is about the wrong corpus`. Forced red: with budget 0, TestStructural_RareTokenStaysClosed fails as `title backfill incomplete (0/406)`, the truth, instead of the old `""`. (2) TestRefreshShortlist_SeedsThenGoesIncremental's two direct calls use time.Hour too. (3) `TestEnsureTitleVectors_ExpiredBudgetReturnsPartialCoverageWithoutError` pins the PRODUCTION contract the fixture bypasses (budget 0 -> no batch runs, coverage reported as it stood, no error) as the deterministic half of TestEnsureTitleVectors_StopsAtTheLatencyBudget's 'partial is not an error' assertion, so nobody 'fixes' the fixture problem by making partial coverage an error in production. `titleBackfillBudget` and `ensureTitleVectors` are untouched: the budget is a latency budget by design (restatement.go:31-39).

**Consequence for readers.** A red synthesize leg with `title backfill incomplete` is a slow or stalled runner, stated honestly; a red one with `actual: ""` on a pairKindIn fixture assertion after PR #304 is a NEW cause and needs its own look. Do not raise the production constant for a test's sake, and do not call ensureTitleVectors with titleBackfillBudget from a fixture whose corpus is more than one batch (32 facts).

**Misreadings.** This was NOT the golang/go#81238 heap corruption (no fatal, no panic; a clean assertion failure) and NOT an index-lag problem (every instance logs the same 405 incremental-update lines). It is also not the dev-box scheduling advice in kb/conventions/testing/dev-box-limits: that fact is about how to run suites on the shared machine; this one is about a fixture that lied when the machine was slow.

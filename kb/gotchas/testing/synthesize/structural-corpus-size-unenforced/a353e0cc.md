# No test enforces the TestStructural corpus size: with the filler cut to a quarter (101 facts) every TestStructural_* still passes, because shortlistBudget and selectRestatementCandidates are fed the CONSTANT structuralFiller+2, never the corpus's own count

identity_test.go says that the 404-fact filler "cannot simply be lowered", because shortlistBudget is corpus-scaled (5 per 1000) and the structural reservation only exists at budget >= 2. Nothing checks that claim.

EVIDENCE (sabotage at the #441 head 93943596, which matches merge 19a6a6da for these files): writeFiller was changed to write n/4 facts, i.e. 101 filler. Every TestStructural_* test passed. With ZERO filler, 15 of them fail, because the rarity cuts need a token distribution. So the filler's existence is enforced; its size is not.

WHY: every test computes the budget from the constant, never from the store. Examples are shortlistBudget(structuralFiller+2) in ReachesTheJudge and AllowanceSurvivesAFullOrdinaryBand, and selectRestatementCandidates(..., structuralFiller+2) in about six tests. The n argument is the corpus size the selector BELIEVES it has. The fixture can therefore shrink without any test noticing that the corpus no longer matches the number the selector is given.

CONSEQUENCE: shrinking the filler to save time would be silently accepted, and it would be exactly the change the comment forbids. Equally, the comment's rationale is unverified. Before trusting either, add a fixture precondition that ties the two together. For example, require the count of live facts to equal structuralFiller+2, or derive n from the store instead of the constant.

NOT MEANT: this does not show that 404 is unnecessary. It shows that no test would notice if the corpus stopped matching the n the selector is told. Production passes the real corpus size, so a smaller real corpus would budget differently.

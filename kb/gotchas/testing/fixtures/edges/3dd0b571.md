# Rewriting a fact with byte-identical content creates no new version: its DERIVED_FROM edges stay on the old blob, so a fixture that 're-saves' a fact to re-pin its refs silently keeps the old pins

OutgoingAtCommit matches edges by the source fact's BLOB node, and a WriteFact whose content equals the current blob changes nothing (the index logs added:0 modified:0). So a test that rewrites A unchanged, expecting A's ref to C to re-pin at C's newer version, still sees the OLD pin.

Hit on feat/materialize building a ref cycle (R→A→C→R): every pinned edge only carries the cycle if each rewritten fact's content actually changes (a different body, or a different confidence when the body must stay the same).

CONSEQUENCE: when a fixture needs a new version of a fact, change its content; to make a version whose BODY is unchanged (e.g. to test body-vs-commit comparison), change another field such as confidence.

Since #432 such a WriteFact makes no commit at all (WriteFactResult.Unchanged, CommitHash = the tip): kb/invariants/store/writes/no-op/767f16fe.md. The same holds for knomit_update (unchanged: true, no commit). kb:// refs carry no version, so there is nothing a re-save could move.

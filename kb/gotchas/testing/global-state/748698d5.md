# A test that makes the code under test change `[log].level` (any Listeners.Apply/Reload or serve run) changes the PROCESS-WIDE zerolog level, so it must save zerolog.GlobalLevel() and restore it in t.Cleanup, or later tests in the package that read log lines fail

MECHANISM (knomit#497, merge 4a9018c4): a reload applies `[log].level` with zerolog.SetGlobalLevel, exactly as boot does, so a test that runs Apply/Reload, or the whole serve RunE, with a level change leaves the package's global log level changed for every test that runs after it. The worker found it when internal/app TestLogLLMSetup_* (which capture log lines at Info and read what was emitted) failed after a leaked `warn`; the failure points at the llm log tests, not at the leaking test. Observed by the PR's author while writing the tests; the llm tests' dependence on the global level was not re-derived here.

CONVENTION: there is NO shared helper; each test saves the level inline and restores it in a cleanup. Do the same:

    prev := zerolog.GlobalLevel()
    t.Cleanup(func() { zerolog.SetGlobalLevel(prev) })

Present at 4a9018c4 in internal/app/listeners_reload_test.go (the test setup and the log-level tests), cmd/serve_supervised_test.go and cmd/serve_tls_bind_test.go (saved with the logger and serve options), and internal/platform/diag/guard_test.go. Restore the level even when your test only asserts the level did NOT change (a refused bad level), since an earlier line of the same test may have set it.

NOT MEANT: t.Parallel does not make this safe (the level is global); and restoring log.Logger does not restore the level, they are separate globals. A new helper would be reasonable, but until one exists, grep for GlobalLevel in the neighbouring tests.

# A guard test that hardcodes the CURRENT version of the thing it protects fails on every correct bump — and the tempting fix re-pins it to a version the artifact no longer ships

Two instances in one stack, which is what makes it a pattern rather than an anecdote.

`TestRunInit_ExistingClaudeMd_OlderMarker_ReplacedInPlace` asserted the summary named "v4", the CLAUDE.md block marker of the day. The first legitimate bump to v5 failed it — while the block had in fact been replaced correctly.

`internal/store/migrate/control_test.go` asserted the control chain's head version as a literal in FOUR places. Adding migration 000008 failed three of them. Worse: bumping those literals alone would have turned the suite GREEN while leaving the new table unverified, because the thing actually checking it is `controlObjects`, a separate list the version number says nothing about.

BOTH NOW DERIVE the target from the shipped artifact — `blockVersion(blockMarkerCurrent)` off the embedded template, `newestControlVersion(t)` off the embedded migration chain — and both fail loudly when the derived value is empty or equal to the fixture's own version. Without that guard the assertion degrades to `Contains(out, "")`, true of every string: a test that passes while testing nothing.

# In jsdom (vitest, tools/desktop/ui) fireEvent.click on a DISABLED radio still flips its `checked` property, with no React onChange — so 'click it and assert it did not move' is not a valid test of a disabled radio there

Observed 2026-10-13 writing the KNOMIT_HTTP scope-lock test in tools/desktop/ui/src/SettingsForm.test.tsx: after fireEvent.click on the disabled 'All networks' radio, the previously checked 'This computer only' input reported checked=false, although React's onChange never fired (component state unchanged; a later Save still sent httpScope 'local'). A real webview does not activate a disabled input on click.

CONSEQUENCE: test a disabled radio group by asserting each input is disabled and by asserting what Save SENDS (component state), not by clicking and reading `.checked`.

NOT MEANT: it does not mean React controlled radios are broken; the DOM property drifted only because no re-render followed the synthetic click.

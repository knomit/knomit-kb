# A SABOTAGE note that names a deleted function is vacuous: following it leaves the test green; two notes targeted the dead Manager.fleetMembersAtMain until step 15a deleted it

Before PR #609 two test comments told a reviewer to sabotage Manager.fleetMembersAtMain (consensus_branch_repos_test.go: restore `upstream := "main"`; fleet_revoked_test.go: drop the Revoked derivation). That function had no caller in production or tests, so mutating it could not turn any test red: the note was vacuous, and a reviewer who followed it and saw green had learned nothing. 15a deleted the function and repointed the note in fleet_revoked_test.go at the live code (drop the deriveRevoked(f) call in FleetMembers, fleet.go).

Consequence: when deleting or renaming a function, grep the test comments for SABOTAGE notes that name it; a note naming a function that is gone, or dead, passes silently. Before trusting 'green under sabotage', confirm the mutated code is reachable from the test. DOES NOT MEAN: that every green sabotage run is vacuous; see the existing sabotage methodology facts for the other causes.

# TestPrompts_NeverInterpolateContext scans prompt-builder files for a .Context selector in prompt text; the hard-coded parent list lost types.go in 13b and the scan now globs every non-test step/*.go instead

At 774f177d (PR #596, step 13a) TestPrompts_NeverInterpolateContext (internal/corpus/synthesize/context_test.go) checks that no prompt template action names 'context' and that no fmt/strings.Builder/template call (Sprintf, Fprintf, Printf, WriteString, Execute, ExecuteTemplate) in a HARD-CODED list of Go files takes a `.Context` selector as an argument. The list is prompts.go, prompt_review.go, review_strategy.go, hypothesize_strategy.go, discovery.go and types.go. 13a moved factsForLLM and WorkItemContent (the Context-carrying payload) out of review_strategy.go and prompt_review.go into types.go and ADDED types.go to the list rather than leaving the payload unscanned. Review sabotage: a Sprintf(f.Context) appended to types.go is RED; the same line in discover_step.go stays GREEN, because that file is not on the list (discover_step.go builds no prompt text). CONSEQUENCE: any later move of the payload (13b makes the step package's types.go the home) must carry the list key with it; do not drop the key or the scan silently narrows to green. DOES NOT MEAN: every file in the package is scanned; only the listed builder files are, so a NEW file that builds prompt text must be added to the list by hand.

UPDATE (step 13b, PR #597, merged as 67642eff; re-read there): the Context-carrying payload (FactsForLLM, WorkItemContent) now lives in internal/corpus/synthesize/step/types.go. The parent's hard-coded list is now prompts.go, prompt_review.go, review_strategy.go, hypothesize_strategy.go and discovery.go, and the test ADDITIONALLY globs every non-test file of step/ (step/*.go, non-vacuous: step must have files), so a NEW step file that builds prompt text with a `.Context` argument is RED (review fix fa196a01; sabotage of Sprintf of f.Context in types.go and in a new step file are RED). The 13a statement above that types.go is a list key is HISTORICAL as of 67642eff. DOES NOT MEAN: the parent is globbed; a new parent file that builds prompt text still has to be added to the list by hand.

UPDATE (step 13g, PR #608, merged as b50d817e; re-read there): discovery.go is no longer a key of the parent's hard-coded list, which is now prompts.go, prompt_review.go, review_strategy.go and hypothesize_strategy.go. The discover prompt builder (renderDiscoverPrompt) moved into the discovery child, and the test now ALSO globs every non-test file of internal/corpus/synthesize/discovery/ via modroot (non-vacuous: at least one file must be found), so a prompt-building function added to any discovery file is covered without a list edit. The statement above that discovery.go is a list key is HISTORICAL as of b50d817e. DOES NOT MEAN: the parent is globbed; only step/ and discovery/ are.

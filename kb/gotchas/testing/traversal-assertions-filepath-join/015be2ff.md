# A path-traversal test that asserts on the UNCLEANED path is vacuous — filepath.Join calls Clean, so "../../escape" lands INSIDE the base, not above it

The only test guarding an untrusted, agent-supplied string against escaping a cache directory guarded nothing, and it passed for months of review attention.

`markerPath` builds `filepath.Join(cache, "knomit", "agy-sessions", id)`. `filepath.Join` CLEANS its result, so an id of `../../escape` collapses to `<cache>/escape` — one level inside the cache root. The test asserted that nothing existed at `filepath.Join(cache, "..", "..", "escape")`, two levels ABOVE the cache root, which no code path ever creates. Proven vacuous by patching the sanitiser to `return true` and re-running: still PASS.

**How to write it instead.** Two assertions, not one. (1) Stat the path the VULNERABLE implementation would actually produce — derive it by hand from the join, after cleaning. (2) Assert the sanitiser directly: `markerPath("../../escape") == ""`. The second is independent of any join semantics and is the one that survives a refactor of the path construction.

**The general check, which is cheap and catches this class:** disable the defence and re-run the test. If it still passes, it was never testing the defence. This applies to every sanitiser, allowlist and validation guard, not just path traversal.

**Related trap in the same function:** `os.UserCacheDir()` honours `XDG_CACHE_HOME` on Linux but returns `$HOME/Library/Caches` on darwin and ignores it, so a test that redirects only `XDG_CACHE_HOME` is asserting about a directory the code never writes to — the same vacuous-pass failure by a different route. Redirect BOTH, and derive the expected root from `os.UserCacheDir()` rather than from the environment variable.

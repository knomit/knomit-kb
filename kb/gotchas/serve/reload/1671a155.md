# The Windows reload event is `Local\knomit-reload-<hash of the data root>` with an owner-only DACL: any process of the same user in the SAME Windows session can fire it (elevated or not), SYSTEM is denied, and a server in another session is invisible because `Local\` objects are per session, so cross-session reload is impossible

WHAT IT IS (cmd/signals_windows.go, internal/config/paths.go, knomit#497 merge 4a9018c4): an auto-reset event named `Local\knomit-reload-` + the first 8 bytes (16 hex) of sha256(lower(Clean(home))); the same normalisation as the pipe name, spelled on every OS so the rule is testable anywhere. Two data roots never share an event. Creation refuses to share an existing name. DACL: protected, one ACE granting the owner's user SID everything (`O:<sid>D:P(A;;GA;;;<sid>)`), no SYSTEM, Administrators or integrity label.

MEASURED (Windows 10 22H2, one machine; a measurement of that box, not a constant): (1) SYSTEM, in the same session namespace, got ACCESS_DENIED on all four OpenEvent access masks, while the owner succeeded, so the denial is the DACL and not a missing object. (2) An ELEVATED server in the console session was reloaded by a NON-elevated `knomit reload` of the same user: it worked, because the DACL is by user SID, the elevated token has the same user SID, `Local\` is per session and not per token, and there is no integrity label. (3) An elevated server in session 0 (an ssh session) could not be reloaded from a session-1 process: the event does not exist from session 1. That is namespace scoping, not the DACL.

CONSEQUENCES: do not tell users an elevated server needs an elevated reload. DO tell them the server and `knomit reload` must share a Windows session; a server run as a service, over ssh/RDP, or by another logon cannot be reloaded from the console session and must be restarted or reloaded from its own session. Code reports this: when the event is missing and the pid in server.json is alive, the message says the server is probably in a different Windows session; only a dead pid says 'no running knomit serve'. For a data root held by a service the only live-config path is therefore a restart.

MISREADINGS: the DACL is not what stops a cross-session reload, the namespace is; 'owner-only' is by user SID, so it does not isolate processes of the same user (any of them can fire the event, which only asks the server to re-read its own files). Not verified: an ordinary second user account, an Administrators member exercising SeTakeOwnership. The sibling trap for tokens: a test asserting ownership by 'our own SID' behaves differently under a UAC split token (kb/gotchas/testing/windows/uac-token-owner-discriminator/2d6e3fd9.md).

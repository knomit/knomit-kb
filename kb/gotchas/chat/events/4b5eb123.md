# A turn end no page stream received is kept PER CHAT and replayed once to the next page stream right after ready; a stream that took it, or a newer turn, clears it

chat.emitEnd (turn_done and turn_error) records the tagged frame in chat.missedEnd only when manager.broadcast reached no page stream of the owner; attachPage then moves each of the owner's chats' missedEnd into the new stream's buffer through manager.deliverTo, which sends under pageMu and only while the stream is still registered (broadcast closes the channel of a stream it drops, and a bare send would panic); an undelivered end stays for the next stream (TestPageStream_ReplayToADroppedStreamDoesNotPanic). It goes (it follows the stream's ready, which the handler writes first) and clears it, so it is delivered once and only for the chat it belongs to. Any delivery to a stream clears it, as does starting a new turn. Recording and the broadcast happen under the chat's mu (lock order chat.mu then manager.pageMu; attach never nests them), so an attach cannot slip between 'no stream took it' and 'remember it'. NOTE: this PR's base did not yet have missedEnd (it lives on feat/chat-adaptive-tools-v3, commit 08e1d4b1); this is a fresh implementation of the same contract that will conflict textually with that branch and should replace it on merge. Does NOT mean events other than the terminal one are replayed: text_delta and the rest are lost to a stream that was down, the snapshot recovers them.

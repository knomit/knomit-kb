# A turn end no page stream received is kept PER CHAT and replayed once to the next page stream right after ready; a stream that took it, or a newer turn, clears it

chat.emitEnd(kind, data, turn) (turn_done and turn_error; turn is the view index of the turn that ended, captured in finishTurn before running goes false) calls sendLocked(kind, data, terminal=true, turn). sendLocked broadcasts the tagged frame and parks it in chat.missedEnd ONLY when turn == c.turnAt AND !c.running, and records the parked end's turn in chat.missedTurn. In that case missedEnd is cleared first and set again only if the broadcast reached no page stream of the owner. An end whose turn is no longer the latest, or that arrives while a newer turn runs, is never parked: finishTurn releases c.mu before emitEnd runs, so turn N+1 can start in between, and a stale end must not be handed to a page that attaches while the newer turn runs.

Delivery: attachPage registers the stream, then calls chat.adoptPage for each of the owner's chats; adoptPage delivers missedEnd (manager.deliverTo, which sends under pageMu and only while the stream is still registered, since broadcast closes the channel of a stream it drops and a bare send would panic) ONLY when missedEnd != nil, !c.running and c.missedTurn == c.turnAt. The frame lands behind the stream's ready, which the handler writes first, and missedEnd is cleared once delivered, so the end is delivered once and only for the chat it belongs to. An undelivered end (deliverTo false) stays for the next stream (TestPageStream_ReplayToADroppedStreamDoesNotPanic).

Clearing: starting a turn clears it (the send path sets c.missedEnd = nil when it sets running = true: the previous turn's end is history, a snapshot refetch has it), so an undelivered end does NOT survive into the next turn; before this fix it did, and a page that attached mid-turn N+1 was handed turn N's end. Delivery by adoptPage clears it; the next parked end replaces it. Recording and the broadcast happen under the chat's mu (lock order chat.mu then manager.pageMu; attach never nests them), so an attach cannot slip between 'no stream took it' and 'remember it'.

Tests: TestPageStream_MissedTurnEndIsDeliveredOncePerChat, TestChat_StartTurnClearsThePreviousTurnsMissedEnd, TestChat_AnEndThatLandsAfterTheNextTurnStartedIsNotParked (uses the betweenRunAndEnd seam in finishTurn), TestChat_EveryTurnEndReachesTheClientOnce.

Does NOT mean events other than the terminal one are replayed: text_delta and the rest are lost to a stream that was down, the snapshot recovers them. Does NOT mean a missed end is kept across a new turn or for a turn that is no longer the latest.

Testing it: a test that checks the replay must attach only after the end has been SENT, which is after running=false shows in a snapshot (finishTurn sends chat_state and the end after releasing c.mu). Wait on finishTurn's afterEnd seam, and wait for a dropped stream to be detached server-side; see kb/gotchas/chat/events/test-waits/e3f50677.md. Polling the snapshot made TestChat_EveryTurnEndReachesTheClientOnce and TestChat_AnEndThatLandsAfterTheNextTurnStartedIsNotParked flaky under load; the park and replay logic described above was correct throughout.

# An idle chat keeps working past the session reaper's tool_idle_ttl (15 min): only its paging CURSORS are reaped ('session expired or not found'); past session.client_retention (168 h) idle, its binding HANDLE is purged too ('unknown binding handle — call knomit_bind'), both actionable tool errors, never an ended chat

Now that a chat lives until DELETE or server stop (kb/decisions/chat/lifetime/outlives-page/bd2a87a7.md), it can sit idle longer than two server-wide expiries. Measured on fix-chat-outlives-page with the chat test harness:

1. Session reaper, session.tool_idle_ttl (defaultToolIdleTTL 15 min, swept every session.sweep_interval 5 min): ReapIdle deletes tool_sessions (and pipeline_sessions) rows whose last_used_at is older than the TTL. A tool session exists ONLY for a query or explain whose results exceed one page (the cursor). After a reap, the chat's next knomit_query through the same binding handle answers and pages as before (a new tool session); resuming the OLD cursor returns 'session expired or not found — omit cursor to start a new query'. TestChat_IdleChatSurvivesTheToolSessionReaper asserts all three, after a real ReapIdleSessions pass that deleted >= 1 row.

2. Client-session purge, session.client_retention (default 168 h, rides the same reaper tick): deletes client_sessions rows and binding_handles whose last_seen_at / last_used_at is older than retention (client_session_bindings orphans go with them). For a chat idle > 7 days: its client_sessions row disappears and is re-created by the next tool call (RecordRequest upsert), and DELETE still records ended_at; but the handle the model holds is gone, so its next call answers 'unknown binding handle — call knomit_bind' (observed with a probe at Purge(now+169h); not kept as a test). The model can re-bind; approval grants are keyed by the resolved pin, so a new handle on the same repo keeps them.

CONSEQUENCE: neither expiry ends or breaks the chat itself; both are the same rules every MCP client lives by. Do not 'fix' them by exempting chats from the reaper without a decision: they bound the session DB and control.db.

WHAT THIS DOES NOT MEAN: the client_sessions state (live/idle/dead) going dead for an idle chat changes nothing functional; those columns are observational and gate nothing. The origin-session 10-min idle expiry is unrelated (origin connections, not chats).

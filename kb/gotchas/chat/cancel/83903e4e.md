# A Stop that overtakes its send withdraws it by send_id: POST /chats/{id}/cancel with {send_id} before POST /turns arrives makes that send answer 409 Send withdrawn and start no turn; a cancel without a body still ends only the running turn

The page tags every POST /chats/{id}/turns with a client-made send_id. Stop while the send is unanswered calls POST /chats/{id}/cancel with the same id. The chat keeps a bounded (256) map of send ids. A cancel naming a send whose turn is running cancels that turn. A cancel naming an id never seen marks it withdrawn, and startTurn then refuses it (errWithdrawn, 409). A cancel naming a send whose turn already ended is a no-op and must not poison later sends. A cancel naming a DIFFERENT id leaves the running turn alone. A cancel with no body is unchanged: it ends the running turn.

Consequence: the page can drop its local turn and restore the draft at once on Stop and still be safe when the POST arrives late. This does NOT mean the server holds the send: a send accepted before the cancel arrived is a running turn and is cancelled like any other (the page shows it as stopped after the next snapshot, and its text may then be both in the transcript and in the restored draft).

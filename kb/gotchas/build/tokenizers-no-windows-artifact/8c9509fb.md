# daulet/tokenizers ships NO Windows libtokenizers.a (darwin/linux only through v1.27.0) — Windows builds blocked upstream

`internal/embeddings/cgo_link.go` statically links `libtokenizers.a` (`-L dist/lib`), so EVERY build of the main binary needs that static lib. But daulet/tokenizers publishes only darwin/linux assets — verified against the v1.27.0 release (latest) and the recent release list: there is NO `libtokenizers.windows-*` artifact at any version. A prior CI comment claiming 'daulet/tokenizers does ship a windows-amd64 static lib (v1.27.0)' was FALSE and has been corrected.

Consequence: `tools/fetchlibs` `tokenizersSpec` returns an actionable error on goos=windows rather than fetching a 404. ONNX Runtime and graphqlite DO publish Windows assets, so fetchlibs is otherwise Windows-ready. A real Windows build is blocked on an upstream/from-source libtokenizers.a plus an MSYS2/mingw CGo toolchain — not on the fetch tooling. Re-check upstream releases before attempting Windows CI.

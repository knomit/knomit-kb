# On Linux hosts with GTK < 4.10 (Debian 12 has 4.8.3) the default Wails v3 desktop build cannot compile; `make dist DESKTOP_TAGS=gtk3` / `make desktop-deps DESKTOP_TAGS=gtk3` select Wails' GTK3 + webkit2gtk-4.1 backend instead, which is NOT the backend that ships

The default Wails v3 Linux backend is GTK4, and it uses GtkFileDialog, a GTK 4.10 type. On a host with GTK older than 4.10 (Debian 12 ships 4.8.3) the desktop binary therefore fails to compile.

ESCAPE HATCH (knomit PR #667): the Makefile variable DESKTOP_TAGS holds extra Go build tags joined onto `desktop` for the desktop binary only.
- `make dist DESKTOP_TAGS=gtk3` builds against Wails' GTK3 + WebKit2GTK 4.1 backend.
- `make desktop-deps DESKTOP_TAGS=gtk3` installs libgtk-3-dev and libwebkit2gtk-4.1-dev instead of the GTK4 pair.
- The default, empty DESKTOP_TAGS leaves the build command byte-identical, so release and CI stay on GTK4.

CONSEQUENCES:
- A gtk3 binary is a different backend from the one that ships. Anything verified with it (tests run with -tags desktop,gtk3, a hand run) only partly covers release behaviour: Go-side logic is shared, but the native window, dialog and webview code is not.
- Do not set DESKTOP_TAGS in CI or release targets; that would change what ships.
- The hatch is temporary: Wails drops the `gtk3` tag in v3.1, so it ends when knomit moves past Wails v3.0. At that point a GTK < 4.10 host has no supported desktop build.

WHAT THIS DOES NOT MEAN: "gtk3 is a supported way to ship on Debian 12." It is a way to build and test on such a host; the shipped Linux backend remains GTK4.

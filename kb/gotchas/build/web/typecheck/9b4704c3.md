# `npx tsc --noEmit` in web/ type-checks ZERO files and always exits 0 — only `npm run build` (tsc -b) checks anything

`web/tsconfig.json` is a solution-style config: `"files": []` plus `"references"` to `./tsconfig.app.json` and `./tsconfig.node.json`. It declares no `include`. `tsc --noEmit` does NOT follow project references, so run against that root config it compiles the empty file list and exits 0 unconditionally.

This is not "a weaker check" — it is a no-op. Verified by appending `const deliberateTypeError: number = "not a number";` to `web/src/HighlightsPanel.tsx`: `npx tsc --noEmit` exited 0 with no output, while `npx tsc -b` reported TS2322 and TS6133 on the same line.

The real gate is `npm run build`, whose script is `tsc -b && vite build`. Build mode follows the references and compiles `tsconfig.app.json` (`"include": ["src"]`, which covers `*.test.tsx` as well as components) and `tsconfig.node.json`. Both enable `noUnusedLocals` and `noUnusedParameters`, which the root config never applies to anything.

CONSEQUENCE: verification of any change under `web/` MUST run `cd web && npm run build`. Running `npx tsc --noEmit` plus `npx vitest run` is NOT sufficient — vitest transpiles per-file without whole-program type checking, so between them nothing type-checks the tree. An agent that reports "tsc clean" has reported nothing. Put `npm run build` explicitly in the verification steps of any plan touching web/, and in the instructions of any subagent implementing UI work.

WHAT THIS DOES NOT MEAN: not "tsc --noEmit is useless everywhere" — it is the normal check in a single-config project. The defect is specific to this repo's solution-style root config. Nor does it mean the app config is merely stricter: an ordinary assignment type error, not just an unused-symbol lint, passes the root config unseen.

OBSERVED FAILURE: this broke `make desktop` on two consecutive PRs. Most recently PR #62, where a `describe` imported but never used in `web/src/HighlightsPanel.test.tsx` (every test declared as a top-level `it()`) failed `tsc -b` with TS6133 after the branch had been reviewed and merged-ready under a green `tsc --noEmit`.

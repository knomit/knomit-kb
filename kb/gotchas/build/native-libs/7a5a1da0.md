# cgo ${SRCDIR}/../.. depth in internal/engine/embeddings/cgo_link_*.go is layout-coupled, and a stale depth fails only at LINK time, not at a package build

The five internal/engine/embeddings/cgo_link_*.go files carry `#cgo LDFLAGS: -L${SRCDIR}/../../../dist/<goos>-<goarch>/lib`. ${SRCDIR} is the package directory, so moving embeddings one level deeper (internal/ to internal/engine/, step 03 of the layer move, PR #590) needed one more `../`.

A stale depth does NOT fail `go build ./internal/engine/embeddings/` (a package compile does not link). It fails only at link time (`ld: library 'tokenizers' not found`), i.e. in `go build .`, `go vet`, or any test binary that links embeddings. Proven in the step-03 worktree: reverting one darwin-arm64 file to `../../dist` made `go build -o /dev/null .` fail at link; the fixed path linked.

CONSEQUENCE: any future move of internal/engine/embeddings must be proven with a LINKING build, not a package build.

DOES NOT MEAN: the Makefile/fetchlibs staging changes. dist/<goos>-<goarch>/lib stays at the repo root. It is also a different failure from the worktree one (gitignored dist/ absent): same `ld` message, different cause.

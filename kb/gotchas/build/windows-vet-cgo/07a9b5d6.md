# GOOS=windows go vet cannot run off a Windows host: the store's sqlite-vec cgo bindings are excluded when cross-compiling, so the windows-only files (e.g. the recipe exec twin) are checked only by CI's windows-2025 legs

At PR #632 (ee850fd6). `GOOS=windows go vet ./internal/corpus/repos/...` fails on darwin before vetting anything: 'build constraints exclude all Go files ... sqlite-vec-go-bindings/cgo' (no Windows C toolchain). Unlike the file-list vet in 98022041, this is not a choice of instrument: any package that imports the store cannot be cross-vetted for windows here. CONSEQUENCE: a change to a *_windows.go file (for example internal/corpus/repos/trigger/trigger_recipe_exec_windows.go) cannot be vetted locally; say so in the PR and rely on CI's windows-2025 build-vet leg, which passed for #632. A green local go vet does not cover windows files.

# In a worktree whose web/node_modules is a symlink to the main checkout, `make e2e` (via dist → build → web, which runs `npm ci`) empties the MAIN checkout's web/node_modules

`make e2e` and `make e2e-ui` depend on `dist`, and `dist` depends on `build`, which reaches the `web` target: `cd web && npm ci && npm run build` (Makefile on dev at eb5a5554, lines 287–288, 338, 370–373). `npm ci` deletes `web/node_modules` before reinstalling. When a git worktree has `web/node_modules` SYMLINKED to the main checkout's directory (the usual shortcut so vitest and tsc work in a fresh worktree), the deletion follows the link: the main checkout's `web/node_modules` is emptied and the worktree gets a fresh real directory in its place. Observed 2026-10-10: the main checkout's install was empty for about 77 minutes; every vitest or `tsc -b` run in the main checkout or in any other symlinked worktree during that window failed; the worker restored it by copying its byte-identical npm-ci tree back.

Consequence: from a worktree with a symlinked `web/node_modules`, never run `make e2e`, `make e2e-ui`, `make dist`, `make build` or `make web`. Build `web/dist` by hand (`cd web && npx tsc -b && npx vite build`) and run the suite with `cd e2e && npx playwright test` (`make e2e-setup` once if browsers are missing; it only touches `e2e/`). Alternatively copy `web/node_modules` instead of symlinking it.

WHAT THIS DOES NOT MEAN: the e2e suite itself is not the hazard; it starts its own server on a free port with a temp KNOMIT_HOME and is safe to run. The hazard is only the `npm ci` reached through the Makefile dependency chain, and only when `web/node_modules` is a symlink.

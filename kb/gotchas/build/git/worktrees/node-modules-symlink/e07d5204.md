# In a worktree whose web/node_modules is a symlink to the main checkout, `make server`, `build`, `dist`, `desktop` and `web` (and `make e2e` only with E2E_BUILD=1) run `npm ci` and empty the MAIN checkout's web/node_modules

Since PR #508 (merge 7cae543c) the chain is `server: web tokenizers-lib download-ort` (Makefile line 281), `build: server` (alias, line 343), `desktop: server desktop-ui` (line 469) and `dist: server desktop` (line 350). `web` runs `cd web && npm ci && npm run build`, so `server`, `build`, `dist` and `desktop` all reach it; `desktop-ui` runs its own `npm ci` in tools/desktop/ui (a symlinked tools/desktop/ui/node_modules is the same hazard), and `dist`/`desktop` reach both. `npm ci` deletes `web/node_modules` before reinstalling. When a git worktree has `web/node_modules` SYMLINKED to the main checkout's directory (the usual shortcut so vitest and tsc work in a fresh worktree), the deletion follows the link: the main checkout's `web/node_modules` is emptied and the worktree gets a fresh real directory in its place. Observed 2026-10-10: the main checkout's install was empty for about 77 minutes; every vitest or `tsc -b` run in the main checkout or in any other symlinked worktree during that window failed; the worker restored it by copying its byte-identical npm-ci tree back.

Since PR #484 (merged 2026-10-12) `make e2e` and `make e2e-ui` are `cd e2e && npx playwright test [--headed]` and no longer depend on `dist`; the harness does not build (see kb/gotchas/testing/e2e/7d273c30.md). They reach `npm ci` in web/ ONLY when `E2E_BUILD=1` is set, because then e2e/helpers/binary.ts runs `make server`. Before that PR, plain `make e2e` and `make e2e-ui` did.

Consequence: from a worktree with a symlinked `web/node_modules`, never run `make server`, `make build`, `make dist`, `make desktop`, `make web` or `make desktop-ui`, and never set `E2E_BUILD=1`. Build `web/dist` by hand (`cd web && npx tsc -b && npx vite build`) and the binary with `CGO_ENABLED=1 go build -o dist/knomit .`, then run `make e2e` (or `cd e2e && npx playwright test`). `make e2e-setup` runs `npm ci` and `npx playwright install` inside e2e/ only, never in web/; it is safe for a symlinked web/node_modules but would do the same clobbering if e2e/node_modules were itself a symlink to another checkout. Alternatively copy `web/node_modules` instead of symlinking it.

WHAT THIS DOES NOT MEAN: the e2e suite itself is not the hazard; it starts its own server on a free port with a temp KNOMIT_HOME and is safe to run. Plain `make e2e` is now safe in such a worktree, but only when dist/knomit and web/dist/index.html already exist (otherwise it stops with a message naming the build commands); it is not safe on a version of the Makefile older than #484, and `make server/build/dist/desktop/web/desktop-ui` are as dangerous as ever (`dist` and `desktop` are no safer for being server-plus-app: both still run `make web` first).

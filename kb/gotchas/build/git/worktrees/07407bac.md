# A git worktree of knomit carries .claude/skills and .claude/settings.json (tracked) but NOT dist/ — the split is per-entry, not a rule about .claude

A `git worktree` checkout contains only TRACKED files, so anything gitignored is ABSENT from it even though the working directory otherwise looks like the repo. For knomit the split is per-entry, set by `.gitignore` lines 55–58:

```
.claude/*
!.claude/skills/
!.claude/settings.json
```

So in a fresh worktree: `.claude/skills/` is PRESENT (the /knomit-… slash commands load with no extra setup), `.claude/settings.json` is PRESENT (hooks and permissions apply, so the SessionStart auto-recall fires), `CLAUDE.md` is present (tracked at the repo root), and everything else under `.claude/` — `worktrees/`, `plans/`, local state — is ABSENT. `dist/` is still ignored (`/dist/`), with the single deliberate exception of the tracked `dist/.gitkeep`, without which `//go:embed all:dist` in tools/desktop/ui/embed.go fails to compile on a fresh checkout.

**Operational consequence:** if a worktree-based workflow needs a built artifact from `dist/`, it must link or rebuild it; if it needs project skills or settings, it already has them.

**WHAT THIS DOES NOT MEAN.**

- *Not* "`.claude/` is tracked." Only `skills/` and `settings.json` are; the directory is otherwise ignored. Check the tracked-vs-ignored status of the specific entry you need — do not generalise from either direction.
- *Not* "symlinking `.claude/skills` into a worktree is a safe way to make skills available." The directory is already really there, so symlinking ONTO it fails with "file exists".
- *Not* a claim about `.claude` as a whole being safe to link: the worktrees themselves live at `.claude/worktrees/<name>`, so linking the whole directory creates a symlink loop.

This fact preserves the durable half of a retracted gotcha about `tools/drone`, which was retired on 2026-08-07 (commit 1f729975) and no longer exists.

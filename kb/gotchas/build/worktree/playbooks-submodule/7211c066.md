# A fresh git worktree fails the internal/repos Mission and SampleRecipe tests AND cmd's mission route test (TestMission_ReadmeKnomitHostedRoute) until git submodule update --init checks out third_party/knomit-playbooks

These tests read `.knomit/templates/mission/...` from the `third_party/knomit-playbooks` submodule, and a new worktree does not check out submodules. Without it they fail with "knomit-playbooks checkout ... is missing or empty", which reads like a regression in the diff.

Run `git submodule update --init` in the worktree, alongside the `dist/` and `web/node_modules` symlinks, before claiming the Go suite green. WHAT THIS DOES NOT MEAN: the failures are not flaky and not caused by the change under test.

SCOPE CORRECTION (observed on PR 497 reviews, macOS and Windows worktrees): the empty submodule also fails package cmd, not only internal/repos: cmd/mission_route_test.go (TestMission_ReadmeKnomitHostedRoute) reads the template from the same checkout and fails with 'knomit-playbooks checkout ... is missing or empty ... run git submodule update --init', so a `go test ./cmd/...` run in a fresh worktree shows one failure that is environment, not the diff. Three separate agents hit it in one day; each first read it as a regression. Run `git submodule update --init` in the worktree before the Go gate, or, if you cannot, name this single failure in the report as environmental and say the suite was not green. A hand-copied third_party directory without its .git file satisfies the tests but is not a checkout.

# <home>/running.marker only produces ONE Warn line at the next `knomit serve` boot after an unclean exit — nothing else reads it, the desktop app never writes it, and it is not a liveness lock

`knomit serve` (cmd/serve.go:132) creates `crashdump.NewMarker(<home>/running.marker)` and calls `Begin(now)`. Begin reads any existing marker first: present means the previous run never called End, so it returns priorCrash=true with that run's recorded start time, then overwrites the file with the new start time. serve turns priorCrash into ONE log line, Warn "previous run exited uncleanly (possible crash); see crashes/ for any bundle", with prior_start. A Begin error is logged as Warn "crash marker unavailable" and the boot continues.

On the way out, serve defers `marker.EndUnlessPanicking()`, NOT `End()`: during a panic unwind it leaves the file in place and re-panics, because reporter.Guard (deferred earlier) recovers the panic to write its bundle, and an unconditional End would have erased the crash signal first. A clean return removes the file.

WHAT IT CATCHES that crash bundles do not: exits that never unwind Go defers — SIGKILL, OOM kill, a CGO/runtime fatal, power loss. A Go panic on the serve path ALSO leaves a bundle in <home>/crashes/ via reporter.Guard, which does not depend on the marker.

WHAT IT IS NOT:
- Not read by anything else. Since merge 1cc5413c (#326, which removed `knomit migrate-registry` and its "is a server running" check on this file) the only reader is Begin itself, at the next serve boot.
- Not written by the desktop app (nothing under tools/desktop creates it), so a desktop-hosted server never produces the warning.
- Not a liveness signal. A crash leaves it behind with nothing running, and two concurrent serves share the one file (the first to exit cleanly deletes it under the other). For "is a live server on this socket" the answer is the socket's own flock / pipe namespace (auth.ListenLocal), not this file.
- Not a reason to exit via os.Exit/log.Fatal on the serve path: that skips RunE's defers, including EndUnlessPanicking, and the next boot then reports a crash that never happened (#261; see the serve return-errors-not-fatal decision).

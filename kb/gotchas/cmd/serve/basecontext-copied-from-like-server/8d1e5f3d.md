# The TLS server (internal/app.OpenTLSServer since PR #290, formerly cmd/serve_tls.go), the OAuth server (cmd/serve_oauth.go) and the runtime diag server (cmd/serve.go openDiagServer) all build their http.Server by copying fields from the plaintext server (`like`), INCLUDING BaseContext — so the plaintext server's BaseContext is load-bearing for all four: since PR #286 it is serveCtx, a cancellable child of cmd.Context(), and ONE cancel in serveUntil unblocks every open request (SSE streams, running pprof profiles) on a listener failure

internal/app/tls.go (OpenTLSServer, moved there by PR #290 so the desktop app can open the same mTLS listener; it was cmd/serve_tls.go before), cmd/serve_oauth.go (openOAuthServer) and cmd/serve.go (openDiagServer, since PR #292) construct their *http.Server from the plaintext one (`like`): handler, timeouts and BaseContext are copied. Before PR #286 that BaseContext was cmd.Context() (signal.NotifyContext from main.go), which is cancelled only by SIGINT/SIGTERM. On the new listener-failure path (a Serve goroutine sending to errCh) nothing cancelled it, so an open SSE stream held every Shutdown for the whole 5 s grace and the returned error carried context.DeadlineExceeded (reviewer finding on #286). The fix sets `serveCtx, cancel := context.WithCancel(cmd.Context())` as the plaintext server's BaseContext, which the other servers inherit by the copy, and serveUntil calls cancel on the errCh branch before the Shutdown sequence; on SIGINT the parent cancels anyway. serveCtx also bounds the TLS pki re-check loop. TestServeUntil_ListenerFailureUnblocksStreams pins it (a handler blocked on r.Context().Done() must return promptly; it takes the full 3 s if the cancel is removed).

For the diag server this means pprof's /debug/pprof/profile?seconds=N and /trace sleep on r.Context(): a listener failure or a signal ends a running profile at once instead of the profile holding Shutdown for the grace period. The diag listener is the fifth errCh sender (buffer 5).

Consequence: if you ever give the TLS, OAuth or diag server its own BaseContext, or stop copying from `like`, the single cancel no longer reaches it and the 5 s hang comes back. Conversely, anything you put on the plaintext server's BaseContext applies to all four listeners. Note the desktop app calls OpenTLSServer with ITS OWN `like` server (tools/desktop/boot.go), so the desktop's BaseContext story is separate from serve's.

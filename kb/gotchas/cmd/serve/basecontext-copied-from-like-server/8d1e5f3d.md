# openTLSServer and openOAuthServer build their http.Server by copying fields from the plaintext server (`like`), INCLUDING BaseContext — so the plaintext server's BaseContext is load-bearing for all three: since PR #286 it is serveCtx, a cancellable child of cmd.Context(), and ONE cancel in serveUntil unblocks every open request (SSE streams) on a listener failure

cmd/serve_tls.go and cmd/serve_oauth.go construct their *http.Server from the plaintext one (`like`): handler, timeouts and BaseContext are copied. Before PR #286 that BaseContext was cmd.Context() (signal.NotifyContext from main.go), which is cancelled only by SIGINT/SIGTERM. On the new listener-failure path (a Serve goroutine sending to errCh) nothing cancelled it, so an open SSE stream held every Shutdown for the whole 5 s grace and the returned error carried context.DeadlineExceeded (reviewer finding on #286). The fix sets `serveCtx, cancel := context.WithCancel(cmd.Context())` as the plaintext server's BaseContext, which the TLS and OAuth servers inherit by the copy, and serveUntil calls cancel on the errCh branch before the Shutdown sequence; on SIGINT the parent cancels anyway. serveCtx also bounds the TLS pki re-check loop. TestServeUntil_ListenerFailureUnblocksStreams pins it (a handler blocked on r.Context().Done() must return promptly; it takes the full 3 s if the cancel is removed).

Consequence: if you ever give the TLS or OAuth server its own BaseContext, or stop copying from `like`, the single cancel no longer reaches it and the 5 s hang comes back. Conversely, anything you put on the plaintext server's BaseContext applies to all three listeners.

# 

When merging a STACK of PRs (each based on the previous one's branch), retarget the next PR to `dev` BEFORE deleting the merged PR's branch: `gh pr edit <next> --base dev`, THEN `gh pr merge <this> --merge --delete-branch`. Deleting the base branch first makes GitHub auto-close the dependent PR (timeline: `base_ref_deleted` then `closed`), and a closed PR can no longer be retargeted (`gh pr edit --base` fails with "Cannot change the base branch of a closed pull request") or merged.

Happened on 2026-09-15 merging the five-PR stack #197→#201: #198 and #200 were closed this way. Their commits still reached dev, because each stacked branch carried the commits below it and the next PR up merged fine, but the two PRs show as CLOSED, not MERGED, and needed an explanatory comment. Alternative that also works: merge without `--delete-branch` and delete every branch at the end. Verify with `gh pr list --state merged` that every number in the stack shows MERGED.

Misreading to avoid: "the code made it to dev" is not the success condition; the merge record on GitHub should reflect that every reviewed PR merged.

# chi's middleware.Compress with no types compresses ONLY its built-in list, which has application/json but NOT application/hal+json or application/problem+json — so knomit's API was never compressed despite the 'mandatory' comment; passing any types REPLACES the defaults, so the allowlist must be complete and must never include text/event-stream

`middleware.Compress(level)` with no content types uses chi's unexported `defaultCompressibleContentTypes`: text/html, text/css, text/plain, text/javascript, application/javascript, application/x-javascript, application/json, application/atom+xml, application/rss+xml, image/svg+xml. Matching is on the response's Content-Type. knomit writes every API body as `application/hal+json` (`hal.WriteHAL`) or `application/problem+json` (`hal.WriteProblem`), neither of which is in that list, so the bare `middleware.Compress(5)` that was installed in `internal/edge/web/router.go` passed every response through uncompressed. That is now fixed: `internal/edge/web/compress.go` holds the complete allowlist (`compressibleTypes`: the chi defaults plus `hal.ContentType` and `hal.ProblemContentType`, never `text/event-stream`) and `compressor()` wraps both the API router and the static routes. Verified 2026-09-18: `curl -H 'Accept-Encoding: gzip'` on a 56 KB motifs response returned no Content-Encoding, and the browser's encodedBodySize equalled decodedBodySize for every API entry.

**Consequences.** (1) A comment or convention saying 'compression is on' is not evidence; check `Content-Encoding` on a real hal+json response. (2) When you pass types to `Compress(level, types...)` chi uses ONLY those — the defaults are gone — so the list must carry html/css/js/json as well as the hal and problem types. (3) NEVER add `text/event-stream` or a `text/*` wildcard: chi's matcher accepts wildcards, and compressing SSE stalls every stream silently (see the proxy-compression gotcha). (4) Already-compressed types (font/woff2, image/png) must stay off the list; compressing them costs CPU for nothing.

**Misreading to avoid.** This does not mean chi's Compress is broken — it is doing exactly what its allowlist says. The trap is that `application/json` looks like it covers `application/hal+json` and it does not: matching is exact on the media type.

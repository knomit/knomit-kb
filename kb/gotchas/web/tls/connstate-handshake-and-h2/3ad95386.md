# net/http reports StateNew BEFORE a TLS handshake and never runs ConnState hooks for an ALPN-negotiated h2 connection — so a ConnState-fed connection registry must track from the first StateActive and depends on the listener negotiating no ALPN (go1.26.6)

Three net/http facts (go1.26.6 `net/http/server.go`, `conn.serve`) that shape any `http.Server.ConnState` hook that wants the PEER CERTIFICATE of a TLS connection:

1. `StateNew` fires in `Serve` BEFORE `conn.serve` runs `tlsConn.HandshakeContext`. At StateNew there is no peer certificate; `ConnectionState().HandshakeComplete` is false.
2. For HTTP/1.x, `StateActive` (with hooks) fires in the read loop only after request bytes were read, i.e. after the handshake completed. So the first `StateActive` is the earliest reliable point. A connection that handshakes and then sends nothing stays in StateNew, invisible to the hook, for up to `ReadHeaderTimeout`.
3. If ALPN negotiated a protocol with a `TLSNextProto` handler (h2), net/http marks the connection active with `skipHooks` and hands it off: ConnState is NEVER called for it with StateActive.

In knomit (`pki.ConnRegistry`): tracks on StateActive/StateIdle only when `HandshakeComplete`, forgets on StateClosed/StateHijacked, and ignores non-`*tls.Conn` conns. The listener negotiates no ALPN because `configFor` sets no `NextProtos`, and `GetConfigForClient` replaces the whole config per ClientHello, so even an `h2` net/http would add to a server-level TLSConfig never reaches the handshake. `TestServer_NeverNegotiatesH2` dials offering `h2, http/1.1` and requires `NegotiatedProtocol == ""`.

CONSEQUENCES:
- Do NOT add `"h2"` to the listener's `NextProtos` without moving connection tracking to the listener (an Accept-side register that still returns the bare `*tls.Conn`, because a wrapper type breaks r.TLS). Otherwise every h2 connection silently escapes revocation. The test will go red first.
- A conn untracked in StateNew is judged when first tracked, which is why `ConnRegistry.ConnState` checks at insert time.

WHAT THIS DOES NOT MEAN: not that ConnState is unreliable for HTTP/1.1. It is complete there for tracking; it is just late (first bytes, not handshake) and blind to h2.

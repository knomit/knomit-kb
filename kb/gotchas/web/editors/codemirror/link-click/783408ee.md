# In CodeMirror a press inside an existing selection keeps the selection until release, so 'the selection is empty' cannot tell a click on a link from a drag; JsonView's kb:// links compare press and release positions (3px slop) instead

Seen in a real browser (Chromium via Playwright, 2026-11-09): after drag-selecting text, a plain click on a .k-json-fact link inside that selection reached the click handler with view.state.selection.main non-empty, so a guard of 'open only when the selection is empty' swallowed the first click. JsonView's factLinks plugin records the mousedown position and, on click, ignores the click when the pointer moved more than CLICK_SLOP_PX (3) since the press; otherwise it opens the fact. That still satisfies 'a click that ends a drag selection opens nothing'.

Consequence: for any click-to-act decoration inside a CodeMirror view, use pointer travel, not selection state, to detect a drag. JsonView.test pins both cases (drag ending on a link opens nothing; a click inside a selection opens).

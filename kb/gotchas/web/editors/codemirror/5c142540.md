# CodeMirror 6's EditorView already sets autocapitalize/autocorrect/spellcheck off on contentDOM by default

In @codemirror/view's EditorView.updateAttrs() (node_modules/@codemirror/view/dist/index.js), the base `contentAttrs` object unconditionally includes `spellcheck: "false"`, `autocorrect: "off"`, `autocapitalize: "off"`, plus `writingsuggestions: "false"` and `translate: "no"`, applied to `contentDOM` (the actual contenteditable element) before any app-supplied editorAttributes facet is merged in. Verified during the Task 6 create-repo-wizard spike: commenting out web/src/OntologyEditor.tsx's explicit `v.contentDOM.setAttribute('autocapitalize'|'autocorrect'|'spellcheck', ...)` calls and re-rendering (in jsdom and in a real WebKit browser via Playwright) left all three attributes present and set to the same values — CodeMirror's own default, not the app code, was producing them.

Consequence: any CodeMirror 6 editor gets this guard for free; you do not need to add it yourself to get baseline protection against a host's autocapitalize/autocorrect/spellcheck UI. WHAT THIS DOES NOT MEAN: it does NOT mean the explicit setAttribute calls in OntologyEditor.tsx are unnecessary or should be removed — they were kept anyway, because they're cheap, document intent for the next reader, and protect against CodeMirror changing this default in a future major version. It also does NOT mean the macOS-level WKWebView autocorrect/autocapitalize bug that hit CreateRepoForm's plain <input> (web/src/CreateRepoForm.tsx:81-83) is proven fixed for CodeMirror — see the sibling fact on the synthetic-event verification gap.

# An origin URL is trimmed of surrounding whitespace at all FIVE JSON entry points through one helper (trimOriginURL), and the wizards send the value they classified; a padded URL previously reached the git route URL-encoded and 404'd, and could be PERSISTED via PUT /origin — never fix a stored padded row by normalising ActiveRepoWithOrigin's comparison, because the reconcile loop fetches the STORED string

Reported 2026-09-16 by the user: an origin URL pasted into the desktop wizard with trailing spaces failed the check with "repository not found: 404 page not found". Cause: the wizard trimmed the URL for host classification but sent the raw field; nothing on the server trimmed; the spaces travelled URL-encoded into /git/<repo>%20%20/info/refs and the git route looked up a repo named "arxiv-kb  ". Measured: a TRAILING space is the only whitespace url.Parse tolerates; leading space, tab and newline already failed isGitURL at the two endpoints that validate (PUT origin, create-session) and were unvalidated at the other three (probe, initialized probe, create).

Fix (PR #206): trimOriginURL (strings.TrimSpace) at the JSON decode seam of all five inbound entry points — probe, initialized probe, create, setOriginRequest (PUT origin), createSessionRequest (POST /origin/session, the wizard's connectivity test). At the decode seam rather than at OriginSpec construction because PUT /origin reads req.URL separately for validateLocalOrigin, CheckOriginOntology and SetOrigin, and the local-origin gate and the use must see ONE string. Widening is deliberate: leading space/tab/newline go from rejected to accepted-after-trim. Client side, one originURL(string) helper feeds both CreateRepoWizard and RemoteConnectWizard so they classify and send the same value. The two outbound json:"url" fields (originView, sessionSummary) need nothing. Test: TestOriginURL_EveryEntryPointTrims pins each caller separately (removing any one caller's trim fails only its rows); on PUT origin the response is 502 either way against an unresolvable host, so only the PERSISTED row can pin the trim.

Origin identity: a padded URL and its clean twin are now ONE origin for ActiveRepoWithOrigin/reserveNameAndOrigin. A padded row CAN already exist in a deployment: PUT /origin persists before it clones (the row is kept when ActivateSync fails) and skips CheckOriginOntology when the repo has no ontology. After the fix such a row is no longer matched by the cheap uniqueness preflight — bounded, because RecordRepoID after the clone is the real guard — and it self-heals on re-save. If that residual is ever closed, the fix is a one-time MIGRATION trimming the stored value. Do NOT normalise on read inside ActiveRepoWithOrigin: the reconcile loop reads the origin fresh each tick and fetches the URL as stored (measured on the wire as .../kb.git%20/info/refs), so a read-side trim would make the preflight claim a repo legitimately owns an origin it still cannot sync — the compared value decoupled from the used value, which is the original defect one layer down. Two people proposed the read-side fix independently before it was shown wrong.

Scope stays at whitespace on purpose: TrimSpace removes characters that cannot be part of an address, so it can never change WHICH repository is named. A zero-width space or smart quote produces the same 404 today and is left alone — rewriting into a different URL silently is worse than an honest 404, especially where the URL is an identity key.

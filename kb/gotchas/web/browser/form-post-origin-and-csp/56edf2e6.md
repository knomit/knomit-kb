# Two browser rules an http.Client test cannot see broke knomit's OAuth consent POST: a page served with Referrer-Policy: no-referrer makes its form POST send Origin: null (even same-origin), and CSP form-action is enforced on the WHOLE redirect chain of the submission, so form-action 'self' blocks a POST that 303s onward to another origin

Found in F19 phase 3c. The consent page's decide POST checks Origin == the issuer's origin. It then 303s to /oauth/authorize/{id}/wait, which 302s to the OAuth client's redirect_uri on another origin. The in-process Go tests were green throughout; two things broke in Chromium:

1. ORIGIN NULL FROM no-referrer. Fetch's 'append a request Origin header': for a request that is neither GET nor HEAD and not CORS, if the request's referrer policy is no-referrer the serialized origin is "null" — including for a same-origin form POST. knomit's OAuth pages all sent Referrer-Policy: no-referrer, so every real approval was refused as 'Origin: null'. The final reviewer reproduced it with Playwright; the tests had missed it because the fixture set Origin by hand. Fix: the consent page sends strict-origin (the page URL still never leaves as a Referer; at most the origin does), and the fixture now DERIVES Origin from the page's own Referrer-Policy the way a browser does (browserOrigin in internal/oauth/idpflow_test.go).

2. form-action COVERS REDIRECTS. With CSP form-action 'self', Chromium blocked the submission once the redirect chain left the origin, reporting 'Sending form data to <the form action> violates … form-action' although the action itself was same-origin; the OAuth client never received its code. Fix: no form-action on these pages (they hold no injectable markup, which is what form-action would guard); TestIDP_PagesCarryNoFormAction pins it with this reason.

CONSEQUENCE FOR ANY FUTURE PAGE: a same-origin form whose server checks Origin must not be served with no-referrer; and a form whose POST ends in a cross-origin redirect (OAuth, SSO) cannot use form-action 'self'. A fixture that sets Origin or ignores CSP proves nothing about either — drive the real flow in a browser (Playwright against the real handlers with fake upstreams) before calling a browser flow done.

WHAT THIS DOES NOT MEAN: it does not mean Origin checks are unreliable — with a referrer policy other than no-referrer, same-origin POSTs carry the real origin in every current browser; and fetch()/XHR calls (the web panel's approval proof) follow CORS-mode rules, not this form-POST rule.

# internal/edge/web handlers_branches_test.go carried a dead stubBranchLister (embedding store.BranchIndex) that E7a deleted rather than replaced; W0b then deleted the func seam branchesLister too, so the branch handler tests now run over a real store

History: before E7a (PR #584, merged as 32414d74) internal/edge/web/handlers_branches_test.go declared `stubBranchLister` (embedding store.BranchIndex) and `newTestRepoWithBranches`, with a TODO about generating a mock. Neither had any caller: the branch handler tests injected `storeProviders.branchesLister`, a func, directly. E7a deleted the stub together with BranchIndex instead of replacing it, because the stub proved nothing.

CURRENT STATE (W0b, PR #600, merged as fa631358; re-read there): `branchesLister` and `branchRootReader` no longer exist anywhere under internal/ (they were the func-typed seams branchesListerFunc / branchRootReaderFunc); the handlers call package functions (listRepoBranches, readBranchRoot) and handlers_branches_test.go builds a real store through newRealStoreManager. So a real-store test for the branches endpoint now EXISTS; the earlier advice to write one as new coverage is discharged.

MISREADINGS: (1) this was never a claim that the branches handler was untested, only that the deleted stub never ran. (2) A function-typed seam such as the former branchesLister is NOT caught by the web-declares-no-interfaces guard (known gap, see kb/conventions/go/package-boundaries/web-no-interfaces/d36fa222.md); its removal here was by review, not by the guard.

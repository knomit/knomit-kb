# The job event streams (synthesis-runs and index-rebuilds /events) write the shared `: keepalive` comment every jobEventsKeepalive (30 s) while idle — handleJobEvents had none before, so a synthesis waiting on the model emitted nothing for minutes; but the helper does not own the ticker, each SSE handler hand-rolls its own

At c4f1ec74 (PR #625): handleJobEvents in internal/edge/web/api/jobs/handlers.go (it was handlers_jobs.go until PR #627) starts a time.NewTicker(jobEventsKeepalive) after the first frame (and only when that frame is not already terminal), and on each tick calls stream.Keepalive() — the httpx sseStream method that writes `: keepalive` through the same bounded, checked write path as every other frame — returning when it reports false. jobEventsKeepalive is 30 s. Before this change the job stream (mounted twice: synthesis-runs/{id}/events and index-rebuilds/{id}/events) wrote nothing between the initial frame and the terminal, so a synthesis waiting on the model could sit silent for minutes and a proxy or browser could drop the idle stream.

CONSEQUENCE: a new SSE handler that can sit idle needs its own keepalive ticker; adopting httpx.StartSSE does not give you one.

WHAT THIS DOES NOT MEAN: the helper does not own the ticker. httpx.StartSSE and stream.Keepalive() only provide the bounded write of the comment frame; each handler that wants keepalive (events, repo events, client sessions, logs, jobs) still hand-rolls its own 30 s time.Ticker around stream.Keepalive(). The origin-session flows (beginSSE in internal/edge/web/api/origins/handlers.go) have no keepalive ticker at all; each is bounded by its own terminal condition.

MOVED (12c, PR #627, merge 97ae7c19, re-read there): handleJobEvents and jobEventsKeepalive are in internal/edge/web/api/jobs/handlers.go and behave as above; jobEventsKeepalive is now private to that package, and TestJobs_EventsKeepaliveOnAnIdleStream lives in internal/edge/web/api/jobs/keepalive_test.go (see kb/gotchas/web/jobs/3b78d93c.md).

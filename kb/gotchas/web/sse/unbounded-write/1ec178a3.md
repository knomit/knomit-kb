# Every SSE handler here writes through internal/edge/web/httpx/sse.go (httpx.StartSSE + Write + Keepalive): a per-write deadline AND a checked write error, because the server sets WriteTimeout 0 for streaming on purpose — the branch-events gap is closed as of PR #203, and go vet enforces constant format strings on Write

knomit's HTTP server runs with `WriteTimeout` 0 deliberately: any non-zero value would cut every SSE stream at the timeout. Nothing else bounds a write, and the hubs never block Publish — so a client that stops draining its socket wedges the handler's `Fprintf` indefinitely, holding the goroutine and the subscription while events accumulate behind it.

The fix is TWO changes, and the first without the second makes things worse:

1. `http.NewResponseController(w).SetWriteDeadline(time.Now().Add(N))` before EVERY write, the `: keepalive` included.
2. Check the error from every write AND from `SetWriteDeadline` itself, and `return` on failure. A deadline with unchecked errors inverts the failure rather than fixing it: the deadline fires, the write fails, and a loop that ignores it spins on a dead connection at full event rate. Returning is what ends the subscription — net/http cancels the request context when the handler returns, which is what `Subscribe(ctx)` is waiting on.

**As of PR #203 (dev 53a331f0) this lives in ONE place** (now `internal/edge/web/httpx/sse.go`, see RE-READ below): `StartSSE(w)` sets the headers and checks `http.Flusher`; `(*sseStream).Write(format, args...) bool` bounds one write, checks the error, flushes, and reports whether the stream is still usable; `Keepalive()` writes the comment verbatim through the same path. Every SSE handler uses it (full list under RE-READ below); zero bare `fmt.Fprint` remain in them. **Callers MUST `return` on false** — with one stated exception: `beginSSE` (now in internal/edge/web/api/origins/handlers.go) keeps `sendEvent func(v any)` with no result because its four flows (test connectivity, preview, apply, commit) are procedures that cannot stop half-way (a clone that has swapped a store must finish). Safety there comes from the `dead` latch in `sseStream`: set on both the deadline-error and write-error paths, checked as the FIRST statement of Write, so every send after the first failure is a free no-op rather than another blocked write. The code names itself as the one place a write result is not turned into a return.

**Failing closed is safe here, and that is tested rather than assumed.** `NewResponseController` reaches the connection only through `Unwrap`, and both `middleware.Compress` and `metricsMiddleware` wrap the ResponseWriter — so an unsupported deadline would turn "refuse to start" into a silently dead endpoint. `TestSessionEvents_WorksThroughTheRealMiddlewareChain`, `TestLogEvents_WorksThroughTheRealMiddlewareChain` and `TestBranchEvents_WorksThroughTheRealMiddlewareChain` stream over a real `httptest.NewServer` through the whole chain with gzip requested. They pass, and they are what will catch a future middleware that stops unwrapping.

**Format strings are machine-enforced.** go vet recognises `sseStream.Write` as a printf wrapper, and `printf` is in the vet subset `go test` runs by default, so passing a payload (a log line, a commit message — the two user-controlled strings that flow through these writers) as the FORMAT fails the build with "non-constant format string". Always pass payloads as arguments.

**Bounding memory is not bounding writes.** A bounded per-subscriber buffer (or goob's unbounded one) is a separate concern: the buffer decides what happens to events while the handler is stuck, the deadline decides whether it stays stuck.

**A test double must implement SetWriteDeadline.** `httptest.ResponseRecorder` does not, so a recorder without the method sends the handler down the refuse-to-start branch and the symptom is an EMPTY BODY, not an error naming the missing method — eight existing tests went red that way when the helper was adopted. Use the shared `streamRecorder` in `internal/edge/web/sse_recorder_test.go` (deadline count + write-failure mode) for every stream test.

**Keepalive coverage (corrected at c4f1ec74, PR #625):** the job stream gained a keepalive (see kb/gotchas/web/sse/4a1d419d.md); only the origin-session flows (beginSSE) still have none, each bounded by its own terminal condition. `Connection: keep-alive` is set once in httpx.StartSSE and is stripped by Go's HTTP/2 server, harmless.

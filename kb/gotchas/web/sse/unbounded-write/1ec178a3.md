# An SSE handler here needs BOTH a per-write deadline and a checked write error — the server sets WriteTimeout 0 for streaming on purpose, and handleHALEvents (branch events) still has neither

knomit's HTTP server runs with `WriteTimeout` 0 deliberately: any non-zero value would cut every SSE stream at the timeout. Nothing else bounds a write, and the hubs never block Publish — so a client that stops draining its socket wedges the handler's `Fprintf` indefinitely, holding the goroutine and the subscription while events accumulate behind it.

The fix is TWO changes, and the first without the second makes things worse:

1. `http.NewResponseController(w).SetWriteDeadline(time.Now().Add(N))` before EVERY write, the `: keepalive` included.
2. Check the error from every write AND from `SetWriteDeadline` itself, and `return` on failure. A deadline with unchecked errors inverts the failure rather than fixing it: the deadline fires, the write fails, and a loop that ignores it spins on a dead connection at full event rate. Returning is what ends the subscription — net/http cancels the request context when the handler returns, which is what `Subscribe(ctx)` is waiting on.

**Failing closed is safe here, and that is tested rather than assumed.** `NewResponseController` reaches the connection only through `Unwrap`, and both `middleware.Compress` and `metricsMiddleware` wrap the ResponseWriter — so an unsupported deadline would turn "refuse to start" into a silently dead endpoint. `TestSessionEvents_WorksThroughTheRealMiddlewareChain` and `TestLogEvents_WorksThroughTheRealMiddlewareChain` stream over a real `httptest.NewServer` through the whole chain with gzip requested. They pass, and they are what will catch a future middleware that stops unwrapping.

**LIVE EXPOSURE, as of 19b63d81:** `handleHALEvents` in internal/web/handlers_events.go — the branch task/status/sync/push stream — sets no deadline and discards every write error. It was deliberately left out of scope when the sessions and logs streams were fixed. Fixing it is the outstanding follow-up.

**Bounding memory is not bounding writes.** A bounded per-subscriber buffer (or goob's unbounded one) is a separate concern: the buffer decides what happens to events while the handler is stuck, the deadline decides whether it stays stuck.

**A test double must implement SetWriteDeadline.** `httptest.ResponseRecorder` does not, so a recorder without the method sends the handler down a different branch and the deadline path is never exercised at all; `streamRecorder` in handlers_client_sessions_events_test.go adds it plus a write-failure mode for this reason.

# vitest 4 runs afterEach hooks in STACK order, so RTL cleanup() from test-setup.ts runs LAST: App.boot's own afterEach uninstalls the fake EventSource and clears mocks while the App is still mounted with passive effects pending

knomit#270, fixed in PR #273 (commit 985bdfe8). Two App.boot 'desktop, server still booting' tests failed as a PAIR on a loaded run (Node 22, 2026-09-23, 1 of 4 full runs). (1) `adopts the reported API base…` failed with `ReferenceError: EventSource is not defined` at App.tsx:826, thrown from flushPassiveEffects, i.e. the SSE effect MOUNTING. (2) The next test, `lets NOTHING leave the page while booting`, found calledApiFns(api) = ['activity x1','browse x1','stats x1'].

MECHANISM, verified. vitest 4 resolves `sequence.hooks ??= "stack"`, so afterEach hooks run in reverse registration order. web/src/test-setup.ts registers `afterEach(cleanup)` first, so it ran AFTER App.boot.test.tsx's file-level afterEach (uninstallFakeEventSource + vi.clearAllMocks), and the App was still mounted between the two. A test ending on the commit that drops the boot screen leaves that commit's passive effects pending. The file's afterEach then deleted globalThis.EventSource. RTL's unmount flushed the pending effects, and the SSE effect threw. The throw aborted cleanup, and the still-mounted App's later post-boot calls landed after clearAllMocks, where the NEXT test counted them.

REPRODUCED DETERMINISTICALLY: a test whose last act is awaiting a promise resolved by a MutationObserver at the exact boot-screen-removal commit (so vitest enters the afterEach chain before React's passive flush) gives the CI pair 3/3. That test is now the regression test 'tears down cleanly when a test ends at the commit that drops the boot screen', placed directly before 'lets NOTHING leave the page'.

FIX. `cleanup()` FIRST in App.boot.test.tsx's file-level afterEach, with a comment naming the stack order. The suite-wide sequence.hooks is deliberately unchanged. 'adopts the reported API base' also stubs getRepo (unstubbed, a post-boot passive effect threw at App.tsx:572 when given time) and ends on the branch event stream, not on the boot-screen commit.

RULE FOR OTHER FILES. A file-level afterEach that REMOVES a global the component uses, or clears mocks, must call cleanup() first. Otherwise, under vitest 4's stack order, it runs against a live tree. The nested describe's own afterEach in App.boot (restorePoll, deleting __KNOMIT_API_BASE__) still runs before cleanup. It was harmless in every run here, but it has the same shape.

# vitest 4 runs afterEach hooks in STACK order, so RTL cleanup() from test-setup.ts runs LAST: any test file's own afterEach runs against a still-mounted tree, and uninstallFakeEventSource used to DELETE the global EventSource that cleanup's unmount could then need

knomit#270, fixed in PR #273 (commits 985bdfe8, d51ca566 and 0a8d24d8). Two App.boot 'desktop, server still booting' tests failed as a PAIR on a loaded run (Node 22, 2026-09-23, 1 of 4 full runs). (1) `adopts the reported API base…` failed with `ReferenceError: EventSource is not defined` at App.tsx:826, thrown from flushPassiveEffects, i.e. the SSE effect MOUNTING. (2) The next test, `lets NOTHING leave the page while booting`, found calledApiFns(api) = ['activity x1','browse x1','stats x1'].

MECHANISM, verified. vitest 4 resolves `sequence.hooks ??= "stack"`, so afterEach hooks run in reverse registration order: innermost describe first, then the file level, and the `afterEach(cleanup)` that web/src/test-setup.ts registers LAST of all. Every test file's own afterEach therefore runs while the component tree is still mounted. test-setup.ts also installs FakeEventSource as globalThis.EventSource for EVERY test (L40), but `uninstallFakeEventSource` used to `delete` that global. So in any file that calls it in afterEach, a passive effect still pending from the test's last commit was flushed by cleanup's unmount against a MISSING EventSource. The throw aborted cleanup, and the still-mounted App's later calls landed after vi.clearAllMocks, where the NEXT test counted them.

REPRODUCED DETERMINISTICALLY. A test whose last act awaits a promise resolved by a MutationObserver at the exact boot-screen-removal commit (so vitest enters the afterEach chain before React's passive flush) gives the CI pair 3/3. That test is now the regression test 'tears down cleanly when a test ends at the commit that drops the boot screen', placed directly before 'lets NOTHING leave the page'. It asserts it saw the boot screen and fails after 2s instead of hanging. With both cleanup() calls removed it fails again (mutation-checked).

FIXES, two layers.
(a) App.boot.test.tsx calls `cleanup()` FIRST in BOTH its file-level afterEach and the nested 'desktop, server still booting' afterEach, which runs even earlier and used to restore the poll interval and delete __KNOMIT_BOOTING__/__KNOMIT_API_BASE__ under a mounted App. cleanup() is idempotent. The suite-wide sequence.hooks is deliberately unchanged.
(b) ROOT: `uninstallFakeEventSource` (web/src/testEventSource.ts) now RESTORES the test-setup baseline, the same FakeEventSource class with default emitReadyOnConnect, instead of deleting the global. That needs no import of the setup file, because the baseline IS that class. A contract test in web/src/test-setup.test.ts pins it; it failed with `expected undefined to be FakeEventSource` before. This reaches every file that uninstalls in its own afterEach: App.index.test.tsx:78, App.sse.test.tsx:143 and ManageSessions.test.tsx:39, as well as App.boot. The unattributed App.index flake seen during #273's verification is hypothesised to be this, and is tracked separately.
'adopts the reported API base' also stubs getRepo (unstubbed, a post-boot passive effect threw at App.tsx:572 when given time) and ends on the branch event stream being constructed, not on the boot-screen commit.

RULE FOR OTHER FILES. Under vitest 4's stack order, a test file's afterEach that REMOVES or changes a global the component uses, or clears mocks, runs against a live tree unless it calls cleanup() first. A test helper that 'uninstalls' something the setup file installs for every test must restore the baseline, never delete it.

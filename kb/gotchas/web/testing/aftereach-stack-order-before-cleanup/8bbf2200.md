# vitest 4 runs afterEach hooks in STACK order, so RTL cleanup() from test-setup.ts runs LAST: App.boot's own afterEach uninstalls the fake EventSource and clears mocks while the App is still mounted with passive effects pending

knomit#270, App.boot 'desktop, server still booting' flakes (seen in 1 of 4 loaded full runs on Node 22, 2026-09-23). Two tests failed together. (1) `adopts the reported API base…`: `ReferenceError: EventSource is not defined` at App.tsx:826, thrown from flushPassiveEffects, i.e. the SSE effect MOUNTING. (2) The next test, `lets NOTHING leave the page while booting`: `calledApiFns(api)` = ['activity x1','browse x1','stats x1'], where it expected [].

FACTS VERIFIED. vitest 4 resolves `sequence.hooks ??= "stack"` (node_modules/vitest/dist/chunks/coverage.*.js), so afterEach runs in reverse registration order. web/src/test-setup.ts registers `afterEach(cleanup)` first, so it runs AFTER App.boot.test.tsx's file-level `afterEach(() => { uninstallFakeEventSource(); vi.clearAllMocks(); … })` (L88). Between those two hooks the App is still mounted. The `adopts` test ends on `waitFor(boot-screen gone)`, which is a DOM commit, with post-boot work still pending: a probe that only waited 50ms longer surfaced a DIFFERENT passive-effect error, at App.tsx:572, because this test's primeApi never stubs getRepo.

MECHANISM (plausible; consistent with every observation, not yet deterministically reproduced). Under load, the SSE effect of the boot commit is still pending when the file's afterEach deletes globalThis.EventSource. RTL's unmount then flushes the pending passive effects, and the effect constructs EventSource: ReferenceError. The throw aborts cleanup, so the App stays mounted, and its later post-boot calls (activity/browse/stats) land AFTER vi.clearAllMocks. They are counted by the NEXT test's `calledApiFns`. That is why the two tests fail as a pair.

SHARED WITH Library.lens only at the class level: a DOM commit treated as 'settled' while passive effects are pending. The fix site is different: teardown order here, not a ref mirror.

CONSEQUENCE: a file-level afterEach that REMOVES a global the component uses, or clears mocks, must run cleanup() first (or the removal must move after unmount). Otherwise it runs against a live tree.

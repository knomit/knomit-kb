# vitest 4 runs afterEach hooks in STACK order, so RTL cleanup() from test-setup.ts runs LAST: any test file's own afterEach runs against a still-mounted tree, and uninstallFakeEventSource used to DELETE the global EventSource that cleanup's unmount could then need

knomit#270, fixed in PR #273 (merged as ec38e06d; commits 985bdfe8, d51ca566, 0a8d24d8, bb8868c3, f17e0f90 and 60ad47a1). Two App.boot 'desktop, server still booting' tests failed as a PAIR on a loaded run (Node 22, 2026-09-23, 1 of 4 full runs). (1) `adopts the reported API base…` failed with `ReferenceError: EventSource is not defined` at App.tsx:826, thrown from flushPassiveEffects, i.e. the SSE effect MOUNTING. (2) The next test, `lets NOTHING leave the page while booting`, found calledApiFns(api) = ['activity x1','browse x1','stats x1'].

MECHANISM, verified. vitest 4 resolves `sequence.hooks ??= "stack"`, so afterEach hooks run in reverse registration order: innermost describe first, then the file level, and the `afterEach(cleanup)` that web/src/test-setup.ts registers (L9) LAST of all. Every test file's own afterEach therefore runs while the component tree is still mounted. test-setup.ts also installs FakeEventSource as globalThis.EventSource for EVERY test (L40), but the helper `uninstallFakeEventSource` used to `delete` that global, and three files deleted it themselves. So in any such file, a passive effect still pending from the test's last commit was flushed by cleanup's unmount against a MISSING EventSource. The throw aborted cleanup, and the still-mounted App's later calls landed after vi.clearAllMocks, where the NEXT test counted them. Even with the global present, a file-level vi.clearAllMocks before unmount lets such late calls leak into the next test.

REPRODUCED DETERMINISTICALLY. A test whose last act awaits a promise resolved by a MutationObserver at the exact boot-screen-removal commit (so vitest enters the afterEach chain before React's passive flush) gives the CI pair 3/3. That test is now 'tears down cleanly when a test ends at the commit that drops the boot screen' (App.boot.test.tsx:280 at the merge), placed directly before 'lets NOTHING leave the page' (L318).

FIXES, two layers, and which test guards which (mutation matrix at f17e0f90, 3 runs each; the layers are unchanged at the merge):
(a) CLEANUP-FIRST: App.boot.test.tsx calls `cleanup()` FIRST in both its file-level afterEach (L88) and the nested 'desktop, server still booting' afterEach (L221), which runs even earlier. GUARDED BY the teardown regression test TOGETHER WITH its neighbour. With cleanup-first removed but the helper restoring, the teardown test itself passes and 'lets NOTHING' fails 3/3 on mocks cleared under a live tree. With both layers removed, the original pair fails 3/3.
(b) HELPER RESTORES THE BASELINE: `uninstallFakeEventSource` (web/src/testEventSource.ts) re-installs the same FakeEventSource class (default emitReadyOnConnect) instead of deleting it; the baseline IS that class, so there is no import cycle with the setup file. Every file that removed the global now goes through the helper: App.index.test.tsx:78, App.sse.test.tsx:143 and ManageSessions.test.tsx:39 (via the helper), and App.manage.test.tsx:97, App.norepos.test.tsx:76 and App.resilience.test.tsx:166, which used to `delete` it THEMSELVES and now call the helper (the last two keep their own local FakeEventSource classes). GUARDED BY two tests in web/src/test-setup.test.ts, NOT by the App.boot test (cleanup-first masks this layer in App.boot: with the helper deleting but cleanup-first present, App.boot passes). The first is a contract test (L30): uninstall leaves globalThis.EventSource === FakeEventSource. The second is a SOURCE GUARD (L45): it reads every *.test.ts(x) under web/src via import.meta.glob ?raw, requires MORE THAN 100 sources (there are 122, so a glob that lost part of the tree fails), and fails if any matches /delete\s*\(?\s*(globalThis|window)[^;]*EventSource/. `window` is included because it is the same global under jsdom. Its message names the helper and the stack-order reason. It failed on exactly the three self-deleting files before bb8868c3.
The suite-wide sequence.hooks is deliberately unchanged ('list' was ruled out).

INCIDENTAL EVIDENCE: in one run with BOTH layers removed, two more App.boot tests also failed: 'falls back to a branch fetch when the server did not embed one', and 'feeds a remembered lens's embedded write_branch straight into status'. The latter is listed as a baseline flake in kb/conventions/testing/dev-box-limits. That suggests, without proving it, that it was this mechanism. The single unattributed App.index failure seen during #273's verification is hypothesised to be this too (knomit#276, to be re-measured).

RULE FOR OTHER FILES. Under vitest 4's stack order, a test file's afterEach that REMOVES or changes a global the component uses, or clears mocks, runs against a live tree unless it calls cleanup() first. Something the setup file installs for every test must be RESTORED (uninstallFakeEventSource for EventSource), never deleted; the source guard enforces that for EventSource.

SHARED WITH Library.lens only at the class level: a DOM commit treated as 'settled' while passive effects are pending.

# In jsdom, after fireEvent.mouseDown/click on an element, el.matches(':hover') is true, so cascade.testutil's computed() returns the :hover rule's value; move the pointer away (mouseLeave + mouseOver on body) before asserting a resting style

cascade.testutil.ts resolves the real App.css cascade by testing each rule's selectorText with el.matches(). jsdom's selector engine tracks a hover state from the mouse events a test fires: after fireEvent.mouseDown and fireEvent.click on a chat fact chip, el.matches(':hover') was true and computed(chip, 'border-color') returned the .k-fact-link:hover colour (rgb(79, 106, 150)), not the resting one, which read like the 'selected border' bug still being there. Firing mouseLeave on the element and mouseOver on document.body cleared it (assert chip.matches(':hover') === false first, so the test proves it).

Consequence: in a test that checks the look an element is left with after a click, move the pointer off it before calling computed(), and assert the :hover state explicitly. Also: computed() returns colours as rgb(...) strings, not the hex in App.css. Found while pinning the no-selected-border fix (ChatFactLinks.test.tsx).

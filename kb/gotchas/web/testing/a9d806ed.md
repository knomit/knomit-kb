# The route-table golden fingerprint drops the package and the export case, so moving a handler between web-family packages leaves route_table.golden byte-identical, and a same-named handler swapped in from another web-family package is invisible to it

Verified at 33eb0307 (PR #630, 12f). mwFingerprint in internal/edge/web/route_table_golden_test.go strips the import path, the package qualifier, the closure suffix and the first letter's case, keeping only the function's own name. 12f moved 32 KB routes from router.go into kb.Mount with ZERO diff lines in testdata/route_table.golden.

CONSEQUENCE: a zero diff after a move between packages is the EXPECTED result and does not show the test failed to look.

DOES NOT MEAN: that a handler swapped for another one with the same function name in a different web-family package would be caught. Only the function's own name is compared, so the swap is invisible. This is a known LOW from the #630 review; no guard for it exists yet (a follow-up guard was proposed). Until one does, a review of a PR that touches router.go or a Mount must check by eye that each handler constructor still comes from the package it came from. The same blindness applies to middleware names (kb/conventions/testing/web/9b96b2df.md).

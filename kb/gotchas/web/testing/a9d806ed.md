# The route-table golden fingerprint drops the package and the export case, so a same-named handler swapped in from another web-family package leaves route_table.golden byte-identical; since #636 TestWebFamily_RouteTableNamesAreUnique closes that by refusing any golden name declared in more than one web-family package

Verified at d8198dd7 (PR #636; first found at 33eb0307, PR #630, 12f). mwFingerprint in internal/edge/web/route_table_golden_test.go strips the import path, the package qualifier, the closure suffix and the first letter's case, keeping only the function's own name. 12f moved 32 KB routes from router.go into kb.Mount with ZERO diff lines in testdata/route_table.golden.

CONSEQUENCE: a zero diff after a move between packages is the EXPECTED result and does not show the test failed to look.

THE GAP IS NOW GUARDED. test/archtest/web_route_names_test.go TestWebFamily_RouteTableNamesAreUnique reads internal/edge/web/testdata/route_table.golden, collects every function name in any middleware or handler column (lowering the first letter the way mwFingerprint does), parses the non-test files of every web-family package, and fails when a golden name is declared in more than one package (message: 'the golden cannot tell them apart; rename one'). It is non-vacuous: a positive control requires handleFactDelete and authMiddleware to be in the golden and declared exactly once, and TestWebFamily_RouteNameDetector_Discriminates pins the golden parse (method-value decoration, case lowering) on synthetic input. Sabotage (#636 review): copying handleFactDelete into api/manage turns it red.

DOES NOT MEAN: that the golden now identifies which package a route's handler comes from. The guard compares DECLARATIONS, not what a route resolves to, so it prevents the collision rather than detecting a swap; the golden itself is still package-blind. Names declared outside the web family, and names declared only in _test.go files, are not scanned. A review of a PR that moves a handler between web-family packages still sees a zero golden diff, which remains the expected result. Fix a red TestWebFamily_RouteTableNamesAreUnique by renaming one of the colliding functions, never by editing the guard. The same blindness applied to middleware names (kb/conventions/testing/web/9b96b2df.md) and is covered by the same guard, since it scans both columns.

# TestFactAsOfDate_FallbackBeforeView sleeps 1.1s on purpose: commit dates have one-second resolution, so without real elapsed time the shown version, the retracting commit and the tip share a date and the test would pass for any stamp

Verified at d8198dd7 (PR #636). internal/edge/web/fact_as_of_date_wire_test.go TestFactAsOfDate_FallbackBeforeView asserts that as_of.date on the commit-anchored ?fallback=before view (URL names a retracting commit; the fact is shown at its prior version) is the SHOWN version's commit date, not the retracting commit's and not the branch tip's. Commit dates are stored in whole seconds (CommittedAt is a Unix second), so the test writes v1, time.Sleep(1100ms), retracts, then writes an unrelated tip; it reads the expected date back via RevisionsBefore and first requires it to be strictly less than the tip's date (fixture non-vacuity), and requires body.AsOf.Commit == v1 (the fallback fired).

CONSEQUENCE: do not remove the sleep or shorten it below one second to speed the suite; the assertion would then compare equal dates and pass for any stamp. The 1.1s cost is deliberate (not flaky in 10 runs at the #636 review; a commit-date seam would avoid it, NIT, not done).

DOES NOT MEAN: that stamping the retracting commit's date would be caught as a distinct failure. The #636 review found it passes, and that is equivalent rather than a gap, because RevisionsBefore on the retracting commit returns the prior version. Replacing the stamp with the current time does fail the test.

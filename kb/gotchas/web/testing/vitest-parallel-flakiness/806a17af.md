# web vitest suite flakes nondeterministically under parallel file execution; use --no-file-parallelism for deterministic verification

The web/ vitest suite (`vitest run`, default file parallelism) has pre-existing nondeterministic flakiness under CPU load: the clean branch fails roughly 3 of 4 parallel runs, with a DIFFERENT test failing each time. Confirmed by stashing all working changes and running the clean branch repeatedly.

Observed failures are React effect/`waitFor` races that lose under parallel worker pressure, not logic bugs:
- Library.sort.test.tsx "highlights the row matching state.factPath (on return to live)": `selectedIdx` is set by an effect (Library.tsx ~L123-128) that commits ONE render after the rows appear, so asserting `rows[1].style.background` immediately after a row-count `waitFor` reads `transparent` before the highlight lands.
- An infinite-scroll sentinel test ("calls api.recent with offset=facts.length when the sentinel intersects") intermittently times out (~1s) under load.

Adding more tests anywhere in the suite increases worker load and tips these races over, so a green local run is not a reliable signal.

Verification workaround: `npx vitest run --no-file-parallelism` runs files sequentially and passes deterministically. Hardening pattern for the racy tests: wrap the state you actually assert on inside `waitFor(...)` rather than asserting eagerly after a separate row-count `waitFor`.

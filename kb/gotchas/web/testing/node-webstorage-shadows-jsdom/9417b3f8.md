# Under vitest 4 + jsdom on Node >= 25, `localStorage` in a test is NODE's (undefined without --localstorage-file) and `sessionStorage` is Node's in-memory one, not jsdom's — every test file that calls `localStorage.clear()` in a hook fails every test; web/src/test-setup.ts installs jsdom's Storage to fix it, removable only once web/ is on vitest >= 5

SYMPTOM (issue #259, 2026-09-23, dev at bba1ea54). `npx vitest run` in web/ failed 98 of 1694 tests: App.boot.test.tsx 11, App.sse.test.tsx 44, ManageSessions.test.tsx 43. Every failure had the same first line, `TypeError: Cannot read properties of undefined (reading 'clear')`, from the `localStorage.clear()` in each file's beforeEach. The same tree gave 0/1694 on Node 22.23.2. It gave 98/98 passing on the three files with `NODE_OPTIONS=--no-experimental-webstorage` on Node 26.7.0. The worker and reviewer sessions reproduced this independently in separate worktrees.

MECHANISM. Since Node 25, `localStorage` and `sessionStorage` are lazy accessors on `globalThis`. localStorage is undefined unless `--localstorage-file` is given, and it emits "ExperimentalWarning: localStorage is not available". sessionStorage is Node's own in-memory Storage. vitest 4's DOM environment copies window keys onto the global with `getWindowKeys`, which SKIPS every key the global already has unless it is allowlisted, so jsdom's Storage objects are never installed. A probe in the jsdom environment showed: Node 22: `typeof localStorage === 'object'`, identical to `jsdom.window.localStorage`. Node 26: `localStorage` is undefined, and `sessionStorage` is a Storage that is NOT `jsdom.window.sessionStorage`. In both, `window === globalThis` and vitest exposes a `jsdom` global whose `window` carries working Storage.

WHY IT IS NOT FIXED BY UPGRADING vitest 4. Upstream fixed it in vitest 5 (vitest-dev/vitest#10293, `fix!`, merged 2026-07-01). The v4 backport (#10873) was closed unmerged by a maintainer: "You cannot backport a breaking change". As of 2026-09-23 no 4.1.x release (latest 4.1.11) carries it.

FIX. At the end of web/src/test-setup.ts, a loop over ['localStorage', 'sessionStorage'] defines `globalThis[key]` as `jsdom.window[key]` whenever the two are not the same object. It is keyed on identity, not on "is it defined", because Node 26's sessionStorage IS defined but is the wrong object. It is a verified no-op on Node 22: instrumenting the branch showed it fired zero times on Node 22, and once per key per file on Node 26. web/src/test-setup.test.ts asserts that both globals are jsdom's working Storage. Without the block it fails 2/2 on Node 26 ("expected undefined to be Storage", "expected Storage{} to be Storage{…}") and passes on Node 22. That is exactly why CI needs a Node >= 25 leg to see it. The `web-ui` job in .github/workflows/tests.yml runs web/ on Node 22 AND 26 for that reason.

CONSEQUENCES. (1) Remove the test-setup block when web/ moves to vitest >= 5, NOT when "Node is fixed": Node's behaviour is intended, and the bug is in vitest 4's key-copying. (2) Any new vitest project in this repo on vitest 4 with a jsdom environment (tools/desktop/ui is one; its CI runs Node 22 only) has the same latent failure on a developer's Node >= 25. (3) Take a web/ suite baseline and record WHICH Node it ran on. The same commit gives 0 or 98 failures depending on `node` on PATH (the box has /opt/homebrew/bin/node 26.7.0 by default and /opt/homebrew/opt/node@22 alongside).

MISREADINGS TO AVOID. The count grew 11 → 54 → 98 as #227 (App.boot), #244 (ManageSessions) and #246 (App.sse) added `localStorage.clear()` to hooks. That growth does NOT make those commits regressions: #246 was the CORRECT fix for a real order leak (kb/gotchas/web/testing/app-sse-localstorage-order), and reverting any of them re-opens that leak. A `git bisect run` with a failure threshold will name one of them anyway, which is why #259's bisect was dropped. `--no-experimental-webstorage` also makes the suite pass, but it is a Node-version-specific flag, not the fix. This is not load-related flakiness either: the TypeError is deterministic.

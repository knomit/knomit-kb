# Rail tests that list a section's rows with getAllByRole('button') now also get the header toggle (rail-<section>-toggle) and must filter it out, like the + button

Since the rail section headers became collapse toggles (2026-11-09), each section's header contains a <button data-testid="rail-<section>-toggle"> (chats, repos, lenses, fleet). Tests in web/src/TargetRail.test.tsx that enumerate rows with within(section).getAllByRole('button') and filter out only the `+` (rail-new-repo / rail-new-lens) see the toggle as row 0 and fail ('the draft row is the FIRST row', 'a create sorts where its name goes', and App.norepos.test.tsx 'forces the rail open with the draft as the only Repositories row'). They now filter the toggle too.

Consequence: a new test that asserts row order inside a rail section must exclude BOTH the section's + and its toggle, or select rows by their own testid prefix (rail-repo-*, rail-lens-*, rail-chat-*).

# The web UI's experiment Commit applies the repo's `conflicts` setting since #412 but the REST action returns 204 with no body, so a person committing from the UI is never told which paths were settled or that the experiment's version of a fact was DROPPED — the only record is the merge commit's Knomit-Merge / Knomit-Conflict trailers on the agent branch; knomit_experiment commit reports the same drops in its summary

Verified at origin/dev ba748e2b (2026-10-06).

THE PATH: `POST /api/v1/repos/{repo}/experiments/{name}/commit` (internal/web/handlers_experiments.go) calls `svc.Experiments().CommitExperiment(ctx, name, adjudications)`, which since #412 (merge 55a47911) picks the strategy from the repo's `conflicts` root attribute read at the consensus branch, parent = consensus side, and returns `AgentReconcileResult{Mode, NewTip, Settled []SettledPath}`. The handler then takes the `action != "sync"` branch: `w.WriteHeader(http.StatusNoContent)` and returns. `res.Settled` is never serialised. Only `sync` renders a body ({experiment, mode}), and it too omits Settled. The React side (`web/src/ExperimentsPanel.tsx`, the Commit button's `run(...)` callback) just calls `onEnterBranch(agentBranch)` on success; there is no toast or dialog for a settled commit — the ExperimentConflictDialog shows only a REFUSED commit's `conflicting_paths` (409).

CONTRAST: `knomit_experiment commit` (internal/mcp/experiment.go, `settledSummary`) names every settled path and says when a version was dropped (`dropped=<side>-modify|-delete|-add`), because the experiment is deleted on success and a plain "merged" would hide a loss nobody chose (kb/decisions/fleet/first-mission/experiment-commit-honors-conflicts/211e894d.md).

WHERE THE RECORD IS: the merge commit on the agent branch carries one trailer per settled path in its last paragraph — `Knomit-Merge: <path> strategy=… base=… src=… dst=… out=… decided=… [dropped=…]` for a field merge and `Knomit-Conflict: <path> kept=<src|dst> dropped=<side>-<modify|delete|add> strategy=… [reason=…]` for a side pick (internal/store/conflict_merge.go; kb/conventions/store/merge/conflict-trailers/d2a5bcb5.md). After a UI commit, `git log -1 --format=%B <agent branch>` (or knomit_explain's history on the touched fact) is how to learn what happened; the experiment branch itself is gone.

CONSEQUENCE: do not commit an experiment from the UI when the experiment and the agent branch may have touched the same facts and the loss would matter — under `consensus: auto` with no `conflicts` key that is the default merge behaviour (kb/decisions/fleet/conflict-merge/set-once-and-auto-default/53bb4e13.md). Commit through knomit_experiment to see the drops, or read the trailers afterwards. For an agent, the UI 204 is also why kb/gotchas/knomit/experiments/commit-ordering/7297d101.md's warning matters: a human can commit (and silently settle) an experiment a session still thinks it owns.

WHAT THIS DOES NOT MEAN: the UI is not applying a DIFFERENT policy from the MCP tool — both call the same CommitExperiment; the gap is reporting only. And a 409 (refused: conflicts the setting could not settle, or the setting off) IS shown, with the paths and the repair steps (kb/decisions/experiments/ui/536e62a8.md). Named as a possible follow-up in 211e894d's non-scope; not built as of ba748e2b.

# A repos.Manager-created repo in web tests has ri.OntologyRoot() == "", so a topic derived from it keeps the "kb/" prefix and every "not declared" assertion passes vacuously; REST handlers take the root from Server.OntologyRoot, as POST create does

Found while building F22's REST PUT typed gate. Deriving the topic with strings.TrimPrefix(path, ri.OntologyRoot()+"/") gave "kb/verdicts" under a test Manager, because its instances never set ontologyRoot; the topic then matched no declaration, so an undeclared key was refused for the wrong reason and a test asserting "not declared" stayed green. A positive control (a declared key must return 200) exposed it. Fix: handleFactUpdate now takes the ontology root from the router (s.OntologyRoot), as handleFactCreate always did. In production the config defaults ontology_root to "kb" and validates it as non-empty.

CONSEQUENCE for test authors: any web-handler logic keyed on the ontology root needs a positive-control case, or it can pass without exercising the path.

# A chat turn's end is applied at once and the transcript is re-read when a turn ends; only the latest snapshot read started is applied, and usage, a turn's error and the warning are carried across a snapshot

Every SSE connect starts with `ready`, and the page answers with an async GET /chats/{id} that replaces the transcript. Events that arrive between the server cutting that snapshot and the page applying it are not replayed, so a turn_done or turn_error that lands in that window used to be overwritten by a snapshot that still said running:true, leaving Stop up and send blocked for good.

The rule now: (1) turn_done and turn_error update the page at once AND start a fresh snapshot read; (2) snapshot reads are numbered and only the latest started is applied, so the stale one cannot undo the end; (3) Stop dispatches `stopped` locally whether or not the cancel request succeeds; (4) snapshotState carries usage, error and the warning over from the state it replaces, matched per turn by index and user message, because the snapshot holds none of them; (5) a cancelled turn_error (the person's Stop) sets no error and keeps the partial text; (6) tool_call only moves a call forward (a repeated running after done is ignored) and a usage event is counted once per `seq` (the server numbers a chat's requests). Do not 'replay buffered events' instead: text_delta frames cannot be told from ones the snapshot already holds, so a replay would duplicate text. Tests: the N1 race test in ChatFacet.test.tsx fails without the refresh or without the latest-read check.

Round 3 additions. (7) turn_error starts the same snapshot read as turn_done (tested by a race test that fails without it). (8) A message sent from here is a LOCAL turn until a snapshot lists it: snapshotState keeps local turns past the snapshot's length and keeps the chat running for them, because a read cut before the server took the POST would otherwise drop the follow-up and show the next reply without the person's message; once the server lists it the snapshot owns it, with no duplicate. (9) A send the server refuses (409 while a stopped turn still unwinds, or any non-2xx other than 404) takes the turn that never began back out of the transcript (send_failed) and shows the error in the transcript's action-error line; a 404 still means the chat is gone. (10) Carry-over also accepts an old turn with no message (one the page joined mid-way): the first snapshot names it, so a turn_error that arrived before it keeps its message. Seq: the usage seq increments per RESPONSE, so a pause_turn continuation gets the next seq (TestChat_UsageSeqIncreasesAcrossAPauseTurnContinuation).

# Chat prose is .k-prose for spacing only: its code chip, table grid and blockquote rule are restated once in App.css on the doubled selector .k-prose.k-chat-answer / .k-prose.k-chat-user, not patched per property

The chat answer and the user strip carry class k-prose (for paragraph/list spacing) and so inherited the fact pane's blue-tinted inline code (#b9c6e6 on #1c1c2b), the full cell grid on th/td, and a violet blockquote rule. The fix is one block in App.css whose selectors are .k-prose.k-chat-answer X, and for code and pre also .k-prose.k-chat-user X (specificity 0,2,x) so it outranks .k-prose X whichever stylesheet loads last; an earlier fix with single-class selectors only recoloured borders and left the left/right cell borders, so the table stayed a grid. If you add a new element rule to markdown.css, check what it does inside a chat block. Scope: the code chip and pre are restated for both blocks; the table (rounded frame, horizontal rules only), blockquote and block-rhythm rules are restated for .k-chat-answer only, so a table or quote in the user strip still gets the fact pane's .k-prose look. Does NOT mean k-prose can be dropped from chat blocks: the spacing rules (first-child reset, list indent) come from it.

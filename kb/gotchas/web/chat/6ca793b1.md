# FIXED by the page stream (one GET /chats/events per page): a stream per mounted chat used to exhaust a browser's HTTP/1.1 connections per origin at about six chats and stall every other API call

Before the page stream, App kept one ChatFacet per listed chat and each opened its own SSE stream. Browsers cap HTTP/1.1 connections per origin (Chromium: 6): with 9 chats in headless Chromium against a plain-HTTP server every page fetch stalled, a reload queued behind the old page's streams, and the rail's x could not send its DELETE; five chats already starved the page. The page stream (chatEvents.ts, one connection however many chats subscribe) removes the limit: re-checked with 8 live chats over plain http, the page loads, the rail updates and the x deletes. Consequence for new code: never open a per-chat stream; subscribe through subscribeChatEvents. The browser number (6) is the browser's, not the code's.

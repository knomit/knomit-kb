# The page is told nothing about the window's loaded set except the loader row: no tools field on the user item, turn_done or snapshot, and no tools SSE event; the loader row names what the loader loaded, not what the model asked for, and the window's changes live in the session log's tools records

SUPERSEDES the earlier shape of this fact. By the user's ruling (2026-11-06) the "Tools in context: k of n (about t tokens)" line was removed from the screen, and with it every path that fed only that line: the user item has no `tools` field, turn_done has no `tools` key, the snapshot has none, and there is no `tools` SSE event, for adaptive and static chats alike. The page client has no ChatTurnTools, no ChatTurn.tools, no toolsInContextLine copy. Do NOT re-add a per-turn tools summary to the snapshot or to turn_done to feed a new display without a new ruling; the dead path would be a second source of truth beside the session log.

What remains. (1) The transcript row of a call to load_tools names what the loader LOADED (its wording, 'Load tools · Query, Explain', is in kb/conventions/web/chat/loader-row/e81d7ca8.md). What it names comes from the loader's own ToolsChange (reason `model`), which the window reports just before the call's result: the chat keeps them in adaptiveState.loadRow and attaches them to the call's view item and its `done` tool_call event as `loaded` (raw names; the row's key_arg is built from them as titles, in load order, a tool with no title by its raw name). Do NOT derive the row from the call's `names` argument: a requested name that is not in the catalogue, or was refused for lack of room, would be shown as loaded. A loader call that loaded nothing shows the ordinary row. Changes with reason stale_call (a call to an unloaded tool) and preload do not feed the row. (2) Every change to the window is still written as a `tools` record in the session log (sessionLog.Tools, see kb/architecture/web/api-chat/session-log/e7401825.md); that log is the diagnostic record, and onToolsChanged writes it whether or not the page shows anything. The window opens with the core tools loaded and the opening writes no record.

What this does NOT mean: the loop still emits LoopToolsChanged and the window still tracks loaded tools; only the page's view of the counts is gone. The `thinking_delta`, `tool_call` and other events are unchanged.

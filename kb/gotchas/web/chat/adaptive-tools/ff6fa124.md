# A chat turn's loaded-tools view lives on its user item, turn_done and tools events, never derived from the loader call's arguments: the snapshot is authoritative, a quiet turn still shows the window's state (the core tools from the very first turn), and the loader row names what the loader loaded, not what the model asked for

Extends kb/gotchas/web/chat/turn-end/31e6c2a7.md (the snapshot is authoritative, events name their turn). In an adaptive chat the user item of every turn carries `tools` {loaded, evicted (this turn's changes), loaded_now, total (catalogue size), tokens (definition tokens, bytes/4, of the loaded set)}. startTurn sets it from the window's state at the turn's start, each LoopToolsChanged replaces it with a NEW value (a snapshot copies the item and encodes it after the lock is released), and turn_done carries the same object. So a turn that changed nothing still shows how many tools it ran with, and the page words the line "Tools in context: k of n (about t tokens)" from the snapshot after a reload. The window opens with the core tools loaded, so the first turn of a chat already says 2 loaded with their size: openWindow seeds the state from Window.Observe(builder snapshot), and the opening writes no tools event. A `tools` SSE event ({turn, reason, loaded, evicted, loaded_now (names), total, tokens}) updates the open page between turn_done reads. A static chat has no `tools` field anywhere: no event, no turn_done key, no snapshot key.

The transcript row of a call to load_tools reads "Loaded tools: a, b". Its names come from the loader's own ToolsChange (reason `model`), which the window reports just before the call's result: the chat keeps them in adaptiveState.loadRow and attaches them to the call's view item and its `done` tool_call event as `loaded`. Do NOT derive the row from the call's `names` argument: a requested name that is not in the catalogue, or was refused for lack of room, would be shown as loaded. A loader call that loaded nothing shows the ordinary row. Changes with reason stale_call (a call to an unloaded tool) and preload do not feed the row.

The `tokens` figure and the token count in the line are bytes/4 estimates, shown as `4.1K` from 1000 up.

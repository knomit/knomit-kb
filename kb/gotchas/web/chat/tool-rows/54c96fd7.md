# A failed knomit_bind is still worded as a success in the chat: the activity line says 'Bound to <target>' and later calls are attributed to the target the failed bind named

chatCopy.activitySummary counts every call of kind 'bind' into 'Bound to <target>' without looking at is_error (SummaryCall has no error field), and chatState.boundAfter / boundBeforeCall move the binding in force to bindTarget(c) for every bind call, failed or not. Seen live 2026-11-06 with lfm3:1.7b: binds to 'nosuch-kb' that returned 'no repo named "nosuch-kb"' produced the activity line 'Bound to agentic-engineering · Bound to nosuch-kb · ...', and a later successful knomit_query's panel breadcrumb read 'nosuch-kb / Searched'. The row itself is drawn failed (red text, red dot) but its verb is still 'Bound'. The server is NOT the source: internal/edge/web/api/chat summarize() returns no summary for an errored call; this is client wording. Consequence: do not trust the activity line or the crumb's repo after a failed bind. Any fix changes approved row copy and needs the user's approval first.

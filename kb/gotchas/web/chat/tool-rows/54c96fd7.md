# A failed knomit_bind binds nothing in the chat: it adds nothing to the activity line and leaves the binding in force unchanged; its timeline row reads '<title> · <key_arg>' (e.g. 'Bind · nosuch') in red, and no verb says it failed

Fixed on feat/chat-panel-row-header (2026-11-06). Before the fix, chatCopy.activitySummary counted every bind into 'Bound to <target>' and chatState.boundAfter moved the binding in force to every bind's target, failed or not. Seen live with lfm3:1.7b: binds to 'nosuch-kb' that returned 'no repo named "nosuch-kb"' produced 'Bound to nosuch-kb' on the activity line, and a later successful query's panel breadcrumb read 'nosuch-kb / Searched'. Now: SummaryCall carries failed (ChatToolGroup passes c.isError), and a failed bind is skipped entirely, so the activity line is whatever the other calls produce. A failed bind with no target adds nothing either. boundAfter only follows a bind whose isError is false, so boundBeforeCall (the panel breadcrumb), each group's starting binding (ChatPanel) and callTarget for later calls keep the binding from before the failed bind. Failed calls of other kinds are counted exactly as before ('Query in all'; a count shows only when N > 1). Misreadings to avoid: (1) rows have no verbs on this branch: a failed bind's timeline row and its panel header read '<title> · <key_arg>' as the server sends them (title 'Bind', key_arg the target, e.g. 'Bind · nosuch'), drawn red; nothing says 'Bound' or that it failed. (2) A group whose only calls are failed binds has an EMPTY summary: the chat-activity-summary span is then not drawn at all (no empty flex item, no double gap, no stray separator), leaving only the mark and the step count; no failure wording was added. (3) The server was never the source: summarize() in internal/edge/web/api/chat returns no summary for an errored call.

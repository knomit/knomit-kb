# The chat context meter reads the latest request's prompt from the live usage event; a snapshot only has per-turn sums, so it is averaged over tool calls + 1

The composer's context meter and the top-bar pill show used tokens = input + cache_read + cache_write of the LATEST request. Only the live `usage` event carries one request; GET /chats/{id} sums usage over a turn's requests. snapshotState therefore keeps the live value when prev.lastUsageSeq >= snapshot.usage_seq, and otherwise falls back to the latest turn's summed prompt divided by (its tool calls + 1), an estimate. Using the raw per-turn sum showed 92.6K of a 32.8K window in a browser run (a turn with several tool requests). /context gives only the window, never the used size. Consequence: if the server ever reports the last prompt's size, replace the fallback; do not sum turn usage for the meter. Not meant: the footer's '<in> in' (uncached input of the turn) is a different number.

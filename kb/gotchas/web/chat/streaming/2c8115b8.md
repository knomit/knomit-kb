# The turn footer's cost card opens ABOVE the footer when the scrolling transcript has room for it there (room >= card height + 8px) and BELOW otherwise; the choice is measured in a layout effect on hover, not fixed in CSS

Below the footer the card hid behind the composer on the latest turn; always above, it was clipped by the transcript scroller's top edge when the footer sat within about 170px of it. ChatTurnFooter now renders the card, measures it and the room between the footer and the nearest overflow:auto ancestor, and sets data-side to above or below via cardSide(roomAbove, cardHeight) (chatCardSide.ts; a plain module because a component file may export only components). At a 330px-tall viewport it opens below and its top is inside the scroller, though its bottom can then pass the viewport edge: neither side fits, and top rows are the ones that matter. A portal was rejected as heavier than the problem. Does NOT mean the card is always above (the mockup's direction).

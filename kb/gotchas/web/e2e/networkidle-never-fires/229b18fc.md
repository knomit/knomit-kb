# Playwright's `waitUntil: 'networkidle'` NEVER fires on any page of knomit's web UI — every view holds SSE streams open, so page.goto just times out at 30s; use 'domcontentloaded' plus an element wait

`networkidle` resolves when there have been no network connections for 500ms. Knomit's UI never reaches that state: every view holds at least one EventSource open for the life of the page — the branch task/status stream, the client-sessions change stream, and on Manage → Logs the log stream. A held SSE connection is an in-flight request as far as the driver is concerned, so the condition is unsatisfiable and `page.goto(url, {waitUntil: 'networkidle'})` fails with `Timeout 30000ms exceeded` having actually loaded the page perfectly.

**Consequence:** in e2e/ use `waitUntil: 'domcontentloaded'` and then wait on what you actually need — `page.getByTestId(...)` / `locator.waitFor()`. Never `networkidle`, and never raise the timeout to "fix" it: no timeout is long enough, because the streams are supposed to stay open.

**Why it misleads.** The failure names the navigation, not the streams, so it reads as "the server is slow" or "the app did not load" — the two things it is not. The page is fully rendered and interactive at the moment the call throws. Anyone debugging a UI problem through Playwright will hit this on their first script, before they have learned anything about the actual bug, and may well conclude the page is broken.

**WHAT THIS DOES NOT MEAN:** it is not a reason to close the streams for tests, or to add a test-only flag that disables them. The streams are the feature (see the live-refresh and logs-tab decisions); the driver's idle heuristic is simply the wrong tool against a streaming UI. It is also not specific to one page — the branch and sessions streams are open in browse mode too, so `networkidle` is unusable app-wide, not just on Manage.

**Verified 2026-09-15** against the dev server at ebc15ccf, in both Chromium (channel 'chrome') and Playwright's Firefox: `networkidle` timed out; `domcontentloaded` plus `getByTestId` waits worked first time in both.

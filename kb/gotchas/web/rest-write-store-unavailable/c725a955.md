# HISTORICAL (fixed by PR #618): at 660cc910 the web write helpers ignored WithRead's error, so a REST fact write to a repo with no reachable store answered 201/200/204 and wrote nothing; since PR #618 it answers 503

HISTORICAL. This fact describes the web layer at 660cc910 (W0h, PR #617). It is NOT the current behaviour. PR #618 (merged as 54d6c65b; dev tip 585974c5, re-read there) fixed the write half: factResolves, systemFileResolver, priorRefs, writeFact and deleteFact now return WithRead's error, and the REST write routes answer 503 "Repo not ready". Current behaviour and rationale: kb/decisions/web/rest-write-store-unavailable-503/5ce4cfbc.md.

WHAT WAS TRUE at 660cc910: RepoInstance.WithRead (internal/corpus/repos/instance.go) calls its closure only when Acquire succeeds; with no store handle Acquire fails with ErrStoreUnavailable (errPopulating while the populate stage runs, or ErrRepoClosed) and WithRead returns that error WITHOUT calling the closure. The write-path helpers discarded the return value, so they returned zero values and a nil error. By endpoint: POST answered 201 with a view of a fact that was never written, PUT 200, DELETE 204, and nothing reached git. A write carrying a new ref was instead refused with 422, because factResolves yielded (false, nil). PR-REPORTED (not checkable in code): the 201/200/204 outcome was measured at the W0h branch head on a store-less writable test instance (repos.NewTestInstanceWithDeps with an agent branch and no Svc).

WHAT STILL HOLDS, and where it went: the same discard-the-error shape remains in the web READ helpers (readFact, loadStats, listTopicDir and others); see kb/gotchas/web/read-helpers-drop-withread-error/88e05f43.md. The W0 series facts cite this note as the defect's record, which is why it is kept as a pointer rather than retracted.

DOES NOT MEAN: that REST writes to a store-less repo still report success (they do not), nor that every WithRead caller in web behaves the same: check each caller.

UPDATE (12f, PR #630, merge 33eb0307; re-read there): handlers_fact_write.go moved to internal/edge/web/api/kb. The ref at 660cc910 is deliberately LEFT at that pin: it records the defective state this note describes. The 'fixed' state (factResolves, systemFileResolver, priorRefs, writeFact and deleteFact return WithRead's error; the handlers answer 503) is re-read at 33eb0307 in api/kb/handlers_fact_write.go.

# Under path=, a lens mount with no commit touching the path reports last_commit EMPTY, and the lens union must let the empty string lose to any stamp; real-store lens stats tests need a one-second sleep to order stamps

W0c (PR #602, merged 58949ece; re-read there). HistoryQuery.Activity (index/search_history.go) returns last_commit "" whenever no commit touches the path (r.LastCommit.Valid is false). That is reachable in production: the subtree view of a lens dashboard (?path=...) gives mounts without the path an empty last_commit, and ?repo=<such mount>&path=... gives a union last_commit of "". The lens union keeps the max stamp (act.LastCommit > resp.LastCommit in handlers_lenses_stats.go), so "" loses to any real stamp. A PR-body claim during review that an empty last_commit 'cannot occur on a real store' was FALSE and the dropped assertion hid this branch; TestLensStats_LastCommitUnderAPathIgnoresMountsWithNoCommitThere pins it with the only fact under the path on the FIRST mount (a last-wins reduction would return ""; sabotage turns it and LastCommitIsTheMaxAcrossMounts RED).

TEST MECHANICS: preset repos already hold commits from their own creation, so activity totals are baseline-relative and, WITHOUT path=, last_commit is non-empty. Commit stamps have one-second resolution: a test needing a strictly later last_commit on one mount sleeps past the second boundary (TestLensStats_LastCommitIsTheMaxAcrossMounts, about 1.1 s, beta in the middle of binding order so first-wins, last-wins and min all fail). Pooled default_axis: build corpora by out-edges (refs); alpha's own impact axis needs top out-degree above 3x the observation out-degree, and a mount whose observations derive from earlier observations drags the pooled ratio under 3.0.

DOES NOT MEAN: that last_commit is generally nullable; it is empty only when nothing under the path was ever committed on that mount.

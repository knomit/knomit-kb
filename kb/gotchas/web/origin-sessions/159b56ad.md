# FIXED (PR #635, issue #629): /test on an origin session in stateError is refused with 409, because a failed clone leaves clone.db behind and a re-open would fail with "repository already exists"

FIXED in PR #635 (issue #629, https://github.com/knomit/knomit/issues/629); merge commit 4eef195b. handleTestConnectivity (internal/edge/web/api/origins/handlers.go) now refuses a second /test with 409 (problem document, title "Session state conflict") when the session holds a RemoteStore, is tested/previewed/applied/committed, OR is in stateError. The stateError message is "this session failed; create a new session to test again".

Mechanism: /test opens store.Open(<session folder>/clone.db); go-git's Init writes HEAD into clone.db before the clone runs, so a failed clone (CloneFrom error, or the same-knowledge-base refusal) leaves clone.db on disk with RemoteStore nil. Before the fix the guard did not cover stateError, so a retry on the same session reopened the leftover clone.db and CloneFrom failed with "repository already exists".

Why refuse instead of deleting clone.db: the only client (web/src/RemoteConnectWizard.tsx) creates a new session per test, and concurrent /test on one session is not serialized beyond sm.Use, so a cleanup could race a running clone. A session in stateError can still be retired by DELETE (204); retirement does not depend on state.

DOES NOT MEAN: that every failed /test locks the session. Failures before store.Open (origin refused, auth resolution, opening the clone db) do not set stateError and can still be retried on the same session. stateError is set only after a clone failure, the held-by-another-repo verdict, or a replay failure in /apply. Nor does it mean the 409 wording is exact for the held-by-another-repo case (the clone succeeded and was closed there); the guard keys on state alone.

Test: internal/edge/web/api/origins/retest_after_error_test.go (fails a first clone, re-runs /test, expects 409 problem+json; sabotaging the condition back to the tested-only form reproduces "repository already exists").

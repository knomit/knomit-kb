# An origin session in stateError answers /test with 409; create a new session to retest (failures before store.Open stay retryable)

After a /test whose clone failed, the origin session is in stateError and every further /test on it returns 409 ("this session failed; create a new session to test again"). The way out is a new session (POST origin-sessions replaces the old one; DELETE also works and returns 204). The wizard (web/src/RemoteConnectWizard.tsx) already creates a session per test, so no client changes were needed.

DOES NOT MEAN: that any failed /test is terminal. A failure before store.Open (origin refused, auth resolution, opening the clone db) does not set stateError, so the same session can still be retried.

If you add a path that sets stateError, check it leaves nothing the guard would not cover: the guard keys on state alone.

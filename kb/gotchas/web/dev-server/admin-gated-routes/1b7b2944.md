# Through the vite dev server (npm run dev, or KNOMIT_DEV_BASE behind code-server's /absproxy/<port>/) the admin-gated routes /api/v1/secrets, /api/v1/oauth/pending and /api/v1/oauth/grants are refused with 403: requireLocalOrSameOriginAdmin's browser proof needs the server's OWN Host/Origin, and the browser's are the dev server's

The secrets API (router.go: r.Route("/secrets") with r.Use(s.requireLocalOrSameOriginAdmin)), the pending OAuth approvals (mountOAuthPending) and the approved logins (mountOAuthGrants) are all behind requireLocalOrSameOriginAdmin (internal/edge/web/oauth_pending_api.go). It admits only (a) a local-listener principal (Via == auth.LocalVia: unix socket or Windows named pipe), or (b) the anonymous loopback principal of the plain listener that holds admin AND whose request passes browserProof. browserProof requires ALL of: Host is localhost, 127.0.0.1 or [::1] WITH THE PORT THE CONNECTION ARRIVED ON (ownHost compares against http.LocalAddrContextKey); X-Knomit-Client: web; Sec-Fetch-Site, when present, is same-origin; Origin, when present, is exactly http://<Host> (required on a mutation); a mutation's Content-Type is application/json.

The vite dev server (web/vite.config.ts) proxies /api to API_TARGET http://localhost:19278 without changeOrigin, so the server sees the browser's Host: localhost:5173 under a plain `npm run dev` (loopback name, wrong port -> ownHost fails), or the code-server hostname under KNOMIT_DEV_BASE + /absproxy/<port>/ (not a loopback spelling at all; depending on [auth].loopback_hosts the request may even be refused earlier by AuthMiddleware). Any Origin the browser sends is the dev server's (http://localhost:5173 or the code-server https origin), never http://localhost:19278. So every call to these routes from the dev-served UI comes back 403 "Permission denied" and the Access page (Secrets and Authorizations sections) shows nothing or an error. Routes NOT behind this gate keep working through the dev proxy, which is why the rest of the UI looks fine.

Consequence: to preview Access UI work in the dev server, fake the data in the CLIENT (a preview-only layer over web/src/api.ts that answers listSecrets / OAuth pending / grants from fixtures), not on the wire. Do not rewrite the dev proxy to impersonate the server's own origin (changeOrigin plus a forged Origin/Host); the agent permission system blocks that as weakening security, and it is exactly the forgery the gate exists to refuse. To exercise the real routes, use the built UI served by `knomit serve` itself on its own port (or the local socket).

WHAT THIS DOES NOT MEAN: it is not a bug in the secrets API or the OAuth endpoints, and it must not be "fixed" by relaxing requireLocalOrSameOriginAdmin, adding the dev port or dev host to ownHost, or adding a dev-only bypass. The Host-with-own-port check is the DNS-rebinding defence and the Origin check is the cross-origin defence; a stored secret is what a remote or cross-origin caller must never read or redirect.

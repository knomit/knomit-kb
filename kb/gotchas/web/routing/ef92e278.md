# chi v5.4.0 registers the HTTP QUERY method on every Mount, so the API route table gains QUERY rows for /mcp mounts; regenerate the golden, do not treat it as a regression

Bumping github.com/go-chi/chi/v5 from v5.2.5 to v5.4.0 makes chi's method table include QUERY (RFC 10008), and Mount registers every method in that table. Consequence: internal/edge/web/testdata/route_table.golden gains 8 QUERY rows (the /mcp, /mcp/*, /lenses/{lens}/mcp, /lenses/{lens}/experiments/{name}/mcp and /repos/{repo}/branches/{branch}/mcp mounts, each with and without /*), and TestRouter_RouteTableMatchesGolden fails with 'route not in golden' until regenerated with `go test ./internal/edge/web -run TestRouter_RouteTableMatchesGolden -update-route-table`. The middleware chains on the new rows are identical to the POST rows; nothing else in the table changed. Before this bump a QUERY request to a mount got 405 from chi; now it reaches the mounted handler, which decides. Does NOT mean any new endpoint was added by us. If the golden diff on a future chi bump contains anything other than QUERY rows, that is a real routing change.

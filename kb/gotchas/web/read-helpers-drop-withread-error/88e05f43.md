# HISTORICAL (fixed by PR #620): at 585974c5 most web read helpers discarded RepoInstance.WithRead's error, so a GET on a repo whose store could not be reached ran no store code and answered an empty 200 or an empty fact; since PR #620 reads answer 503

HISTORICAL. This fact describes the web layer at 585974c5; PR #620 (merged as 1a860912 on dev) fixed it. Current behaviour: kb/decisions/web/read-store-unavailable-503/d5d606a6.md. Kept, not retracted, because other facts cite it (kb/gotchas/web/rest-write-store-unavailable/c725a955.md, kb/gotchas/web/origin-endpoints-no-store-status-matrix/c0507256.md) as the record of the pre-fix state.

MECHANISM (still true, the reason the fix was needed): RepoInstance.WithRead runs its closure only when Acquire succeeds; otherwise it returns ErrStoreUnavailable (or the populating wrapper, or ErrRepoClosed) WITHOUT calling the closure. A helper that drops that return value leaves its result variables at their zero values with err nil.

WHAT WAS TRUE AT 585974c5 (verified there by grep and reading, then): about 25 call sites dropped WithRead's return as a bare `ri.WithRead(func...)` statement, across loadActivity, logPaginated, completions, domains, the events head snapshot, readFact, the five fact_sub helpers (explainFact, incomingAtCommit, outgoingAtCommit, factLiveAtCommit, factExistsAt), recentFacts, motifs (five), search, loadStats and loadHighlights, listTopicDir and topicFactByPath, and listRepoBranches / readBranchRoot in server.go. List-style helpers therefore answered an empty or zero 200 and readFact answered a 200 with an EMPTY fact (PR-reported at the time: path "" and title ""); commitDetail answered 404 "Commit not found" with detail "repo store is unavailable"; listRepoBranches documented nil, nil. Routes that did check it (experiments, changes, jobs, pushed-branches, experiment diff) answered 503 "Store unavailable" with the raw error as detail.

WHAT IS TRUE NOW (1a860912, verified by grep): every ri.WithRead call site in internal/edge/web assigns and returns or answers the error, except the two deliberate best-effort ones: handleHALEvents (SSE head snapshot, a bare ri.WithRead) and factVersionDate (`_ =`), plus the experiment sync's post-sync re-read (`_ =`, not ruled, still answers 204 if the store goes away). The answer is 503 "Repo not ready" with the fixed detail; the lens exceptions are in the decision fact.

DOES NOT MEAN: that the pre-fix effects listed above still happen, or that no discard remains: three `_ =` / bare sites are intentional or unruled.

# streamLifecycle returns (sendErr, narrated): the send error comes back even when it was already written to the stream as an error phase, because whether the stream is open says nothing about whether the machine changed anything

After #416, streamLifecycle (internal/edge/web/api/origins/handlers.go) returns (sendErr error, narrated bool). narrated is true when the error was written as an error phase on the open event stream and false when the caller must answer it as an HTTP problem. Before, a narrated error returned (nil, false) and the caller could not classify it, so handleCommit could not tell a refusal that changed nothing from anything else.

Consequence: classify with repos.IsRefused on the returned error, never on narrated. A refusal that arrives as an error phase (for example with cancel_indexing set, where the stream is already open) must still reopen the clone. The #634 Watch-drain and the 'configuring' fallback are unchanged.

Related: isCommitRefusal now also accepts repos.IsRefused, so guard refusals with no specific mapping reach writeCommitProblem; client-input ones (ErrPeerCredential, ErrCertNotAnInput, pki.ErrUnsupportedOriginScheme, fact.ErrSymlinkNotFollowed) answer 422 'Origin refused', and the rest (incoming-store identity read, probe, acquire, get-remote, branchHoldsNoFacts failures) stay 500 'Commit failed'.

# A repository create finished by another client stays a created pending row in the rail until it is clicked, because App does not refetch repos when a create reaches done

Observed in the browser passes of PRs E and F (a repo created by another client, `knomit-kb` in the scratch run): the rail keeps showing the finished create as a pending 'created' row until the reader clicks it, because the shell does not re-read the repo list when a create it did not start reaches `done`. The follow-up was not done before the merge, so this still holds at the merge of the facets stack.

Consequence: do not assume the rail row for a create reflects the registry the moment the job is terminal. WHAT THIS DOES NOT MEAN: a create the reader started in this tab registers through the draft's own callback and refreshes the lists; only creates started elsewhere are affected. Retract this fact once App refetches repos on a create's terminal state.

# With no reachable store every origin route that reads it answers the one 503 "Repo not ready" (GET, PUT, PATCH upstream, DELETE via ErrNotOpen); a PUT whose prior-origin read fails for another reason is 500, and a GET /repos row simply has no remote key

Status of each origin route when the repo's store cannot be reached, at 1a860912 (PR #620; before it the five routes disagreed, see HISTORY). getOrigin and setOriginUpstream return WithRead's error as-is (errOriginNoStore and acquireFailed are deleted) and each handler answers storeUnavailable with writeStoreUnavailable. Read from handlers_origin_hal.go and handlers_repos_hal.go; the tests are PR-reported (the three origin tests were renamed *Is503, TestStoreUnavailableAnswers_AreOne covers the action routes).
- GET /origin: 503 "Repo not ready", fixed detail "the repo's store is not available; try again".
- PUT /origin (handleHALSetOrigin, prior-origin read via getOrigin): 503 "Repo not ready". A getOrigin error that is NOT store-unavailable is 500 "Failed to get origin" with the error text (untested: it needs a DB fault).
- PATCH /origin/upstream: 503 "Repo not ready". A never-started or stopped manager is still 500 "Failed to set upstream branch" with ErrManagerStopped's text (originsOf runs before the store read; a distinct condition, unchanged).
- DELETE /origin: no getOrigin call; m.Send(DetachOrigin) and writeLifecycleProblem: ErrNotOpen is now 503 "Repo not ready" (the same answer, since in production ErrNotOpen means the Open stage is not live, the state Acquire refuses with ErrStoreUnavailable); ErrClosed and ErrUnavailable still 503 "Repo unavailable".
- GET /repos row: unchanged. remoteHealthOf returns nil on any getOrigin error or an absent origin, so the row has NO remote key (omitempty pointer). A consumer must read absence as "nothing to show", never as healthy (kb/decisions/web/repos/remote-health-on-listing/fd41124e.md).

HISTORY (585974c5, W0i / PR #619 status matrix, ruled away on 2026-10-24 by PR #620): GET origin 500 "Failed to get origin" with the error text; PUT 503 "No store available"; PATCH upstream 500 "No store available"; DELETE 503 "Repo not open" with the error text. Decision: kb/decisions/web/read-store-unavailable-503/d5d606a6.md.

DOES NOT MEAN: that a client can tell a store outage from a stopping server by status alone on PATCH upstream (ErrManagerStopped is 500 there, and PUT's attach leg answers 503 "Server stopping" for it), or that the old wording "No store available" still exists anywhere in handlers_origin_hal.go.

NAMES AFTER 12b (PR #622, merge commit 3e67923b on dev, re-read there): writeLifecycleProblem and writeStoreUnavailable in this fact are now httpx.WriteLifecycleProblem (internal/edge/web/httpx/lifecycle.go, which maps repos.ErrNotOpen to the same 503) and httpx.WriteStoreUnavailable. The status matrix is unchanged. handlers_index.go no longer holds the lifecycle mapper (it keeps only handleCancelIndex), so that ref was replaced by lifecycle.go.

UPDATE (PR #676, merge dd73ed85): the origin handlers now live in internal/edge/web/api/manage/handlers_origin_hal.go, and PUT, PATCH upstream and DELETE sit behind requireOperator (route-level middleware). A caller without `operator` therefore gets 403 BEFORE any of the 503s above; the matrix describes what a caller who passes the gate sees. GET /origin is still a read and is unchanged. The 503 and 500 answers themselves are unchanged at the merge (handlers use httpx.WriteStoreUnavailable).

PATCH UPSTREAM AFTER PR #682 (merge b038ab37 on dev, re-read there; refs re-pinned to it; see kb/invariants/repos/remote/upstream-change/6a1447e1.md): the handler now reads the origin itself BEFORE the branch guard and fails closed. Store unavailable is still 503 "Repo not ready" (now answered by the handler's own read, not setOriginUpstream's); another read error is 500 "Failed to get origin" (PUT's mapping); NO ORIGIN is now 409 "No origin" (it was 500 "Failed to set upstream branch" with detail "SetOriginUpstream: no origin configured"); an origin re-pointed or removed during the check is 409 "Origin changed". A stopped manager is unchanged: 500 "Failed to set upstream branch" with ErrManagerStopped's text, checked first.

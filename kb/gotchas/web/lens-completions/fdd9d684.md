# Lens completions tests over real stores assert the SET of values plus mount order, not the order inside one mount: the domain query is SELECT DISTINCT ... LIMIT with no ORDER BY

W0b (PR #600, merged fa631358): with real stores behind lens completions and domain-facts handlers, the order of values WITHIN one mount is the store's (SELECT DISTINCT ... LIMIT, no ORDER BY in index/index.go), so a test must not assert values[0] or Facts[0]. The UI sorts them itself (web/src/FilterBar.tsx) and openapi.yaml promises only first-seen order ACROSS mounts, which tests still assert (a later mount's new value comes last). The old canned stubs gave a stable per-mount order that was never part of the contract. DOES NOT MEAN cross-mount order is free: mount order is asserted.

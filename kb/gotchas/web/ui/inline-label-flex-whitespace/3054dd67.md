# Adding display:flex to an inline label deletes whitespace-text spacing — and with the global `*` margin reset already in force, the control and its words collapse COMPLETELY rather than merely tightening

A `<label>` whose control and words are spaced by a JSX `{' '}` text node loses that spacing the moment it becomes a flex container: whitespace between flex children is not rendered. In this repo the result is not a tighter label but a TOUCHING one, and the second half of that compound is the part worth remembering.

**The compound.** Two independently reasonable decisions:

1. `web/src/App.css` line 1 is a global reset — `*, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; }` — which, being an author rule, overrides the UA's `margin: 3px 3px 3px 4px` on a checkbox. The control therefore has NO margin of its own.
2. `display: flex` added to an inline label (here to centre the box against the words) drops the whitespace text node.

Either alone is harmless. Together they remove EVERY source of separation at once, so the control sits flush against the first letter and, in the desktop WebKit view, the native control's box overlaps it. The reset is what turns "tighter" into "touching", because it had already removed the only fallback. **Neither decision contains the defect; their composition does.**

**Fix:** spacing must come from `gap` on the flex container, and the now-dead `{' '}` should be deleted rather than left to read as if it still did something. Do NOT also zero the control's margin "for safety" — measured in the browser, the computed margin is already `0px` with and without such a rule, so it asserts something globally true while reading as load-bearing to the next person.

**Why it survived review.** The spacing lived in a TEXT NODE, not in CSS, so it is invisible in a style-object diff — a reviewer read this exact style object closely enough to comment on its inherited `fontSize` and did not see it. It is invisible to jsdom too, which does not lay out. It was caught only by a user looking at the running desktop app.

**Guard that works:** assert the container's `gap` AND that the label's `textContent` equals the words exactly (`'Show hidden'`, not `' Show hidden'`). The second half catches the specific regression where someone "restores the space" by reinstating `{' '}` — a string change with no visible effect.

# The web app has no router and a relative asset base, so materialize options go into the query string only (replaceState), never the path or hash

vite.config.ts builds with base './' on the stated premise that the app has no router and the document URL never changes. Materialize options (materialize=1, mat_depth, mat_facts, mat_cross_kb, mat_unpin; only non-defaults written, other params preserved) are written with history.replaceState on location.search only, so relative assets keep resolving. They are read once when RightPanel mounts. Limit: nothing else restores the open fact from the URL, so a shared URL carries the options and the open flag but still needs the recipient's own fact selection before the view appears. Adding a real router means revisiting this and the base.

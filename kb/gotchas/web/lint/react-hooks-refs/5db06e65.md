# react-hooks/refs flags a handler FACTORY called in JSX (onClick={make(x)}) when the handler it returns reads a ref; an inline arrow (onClick={() => handle(x)}) passes

In web/ (eslint react-hooks plugin, rule react-hooks/refs), writing `const plus = (s, kind) => () => { release(); ... }` and passing `onClick={plus('repos', 'repo')}` is reported as 'Cannot access refs during render' (one error per call site), because `release` blurs searchRef and the factory is CALLED during render. Rewriting as `const newDraft = (s, kind) => { release(); ... }` with `onClick={() => newDraft('repos', 'repo')}` is clean.

Consequence: the web lint gate counts problems against a baseline (104 on 2026-11-09); a factory like this silently adds one error per use and breaks the 'add none' rule. Prefer inline arrows for handlers that touch refs.

WHAT THIS DOES NOT MEAN: reading the ref inside an event handler is fine; only producing the handler by a call during render is flagged.

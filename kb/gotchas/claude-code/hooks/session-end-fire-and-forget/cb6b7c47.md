# CC SessionEnd hook is fire-and-forget — cannot inject context

Claude Code's SessionEnd hook has its exit code ignored and its output discarded. Context injection via `hookSpecificOutput.additionalContext` does NOT work from SessionEnd. This is why the knomit-CC memory design (Shape B) drops SessionEnd entirely.

If you find yourself reaching for SessionEnd to push context into the next conversation, that path is blocked — use PreCompact, or write the digest as a fact via a /knomit-* skill before the session ends.

**WHAT THIS DOES NOT MEAN.**

- *Not* "the session-digest role is covered by knomit's rate-limited Stop hook." This fact said so, and that hook is GONE: `hook_stop.go` was deleted, and the bridge registers exactly four events — session-start, post-edit, post-ask, pre-compact. Nothing in knomit runs on Stop today. See [[four-hooks-chosen]] (kb/decisions/integrations/cc-memory/four-hooks-chosen/a7043709.md).
- *Not* a claim that Claude Code lacks a Stop event. Stop exists in CC's hook API; knomit's bridge simply does not register it. If you want digest-on-stop behaviour you would be adding a hook, not re-enabling one.

**Scope caveat:** the SessionEnd behaviour above was observed against the Claude Code version current when this was written (2026-05) and has not been re-verified since — it describes an external tool, not knomit code, so nothing in this repo pins it.

# claude --settings sandbox: network/filesystem keys must nest under sandbox.network / sandbox.filesystem; misplaced keys are silently dropped

In claude's `--settings` JSON (verified against claude 2.1.150), the sandbox schema nests its keys: `allowedDomains`, `deniedDomains`, `allowLocalBinding`, `allowUnixSockets` live under `sandbox.network`, and `allowWrite`/`denyWrite` under `sandbox.filesystem`. The schema (zod) strips UNKNOWN keys silently rather than erroring, and in `--print`/headless mode an invalid settings object is silently ignored entirely. So a key placed at the wrong level (e.g. `sandbox.allowedDomains` instead of `sandbox.network.allowedDomains`) is dropped with no warning, quietly disabling that guard while `bypassPermissions` stays on.

This bit tools/drone: it originally emitted `allowedDomains` flat under `sandbox`, so its network allowlist never applied (the network was effectively unrestricted). Confirmed by probe: with the corrected `sandbox.network.allowedDomains`, a non-allowlisted domain is blocked by the sandbox CONNECT proxy (curl exit 56, HTTP 403); before the fix nothing was enforced. Correct shape: `{"sandbox":{"enabled":true,"filesystem":{"allowWrite":[...]},"network":{"allowedDomains":[...],"allowLocalBinding":true}}}`. Re-verify the schema after major claude upgrades.

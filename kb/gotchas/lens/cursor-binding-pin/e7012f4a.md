# The §7.3 cursor pin is the binding's uid (repo:<uid> / lens:<uid>), so it IS rename-stable and a recreated lens gets a new pin; since fix/mcp-token-audience a cursor is ALSO owned by endpoint + principal

Tool-session cursors (`tool_sessions`, resumed by `queryResume`, `explainResume`, `materializeResume`) are pinned to their binding by `Binding.PinID()` — `repo:<uid>` for a lens-of-one, `lens:<uid>` for a lens (internal/corpus/repos/binding.go `pinOf`) — plus the read-set fingerprint (each mount at its branch). The earlier version of this fact said the pin was the binding NAME; the accepted fix (kb/decisions/mcp/sessions/cursor-pin-on-ids/642dc805.md, lens uid kb/decisions/lens/identity/lens-uid/853359e7.md) has LANDED:

1. *Rename-stable.* `Manager.RenameRepo` / a lens rename change `Binding.Name()` but not the uid, so an in-flight cursor keeps resuming.
2. *Delete+recreate of a same-name lens mid-cursor* mints a fresh lens uid, so the old cursor no longer matches and reads as expired.
3. `pinOf` fails CLOSED on an empty uid (""), and the resume checks reject a stored "" outright, so uid-less bindings can mint but never resume.

`ErrLensNameConflictsRepo` (validateLensLocked) is no longer load-bearing for cursor soundness — the `repo:`/`lens:` prefixes make the two pin spaces disjoint. Keep it as a UX rule; do not cite it as why the pin is sound.

OWNER (since PR #680, user ruling G2): the pin is per BINDING, not per caller, so two callers that reach the same binding used to share every cursor. A cursor now also stores `tool_sessions.owner` = the MCP endpoint path + the caller's principal (`mcp.callerOwner`), and every resume compares it; another principal, or the same principal through another endpoint, reads the expiry text. See kb/invariants/mcp/ownership/endpoint-and-principal/d870cc94.md.

WHAT THIS DOES NOT MEAN: foreign-binding and foreign-owner rejection are deliberately byte-identical to real expiry; do not add a distinct message. The materialize cursor additionally re-checks the RESUMING caller's repo reach (kb/invariants/materialize/cross-kb/caller-reach/89b26b07.md).

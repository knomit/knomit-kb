# Lens browsing UI v1 ships with named accepted gaps — cross-mount ref-hop classification, repo-scoped lens _links, at:HEAD write-repo resolution

The lenses-ui branch (34b1127..e06a5e3, final review approved 2026-07-19; post-incident sweep 2026-07-20) deliberately ships these known gaps; do not report them as new bugs, and close them knowingly:

1. **Cross-mount ref hops**: a ref inside a fact that names a fact on a DIFFERENT mount (already `kb://<other-id>/…`-qualified) passes through hop qualification untouched, but its temporal classification (live/retracted probe in useTimeTravel.resolveHopAnchor) runs against the OPEN fact's mount, not the target's. Same-mount hops are correct (qualifyHopTarget re-qualifies bare targets with the source mount's id). Pre-existing gap, not worsened.
2. **Lens fact `_links` are repo-direct URLs** (`/repos/<mount>/…`), not lens-scoped — deliberate (the handler comment documents it); the web client never follows them. A HAL-native client following links round-trips correctly but leaves the lens surface.
3. **`at:HEAD` in a lens context resolves against `state.headCommit`** — the write repo's head — even when the open fact is on a read mount. Explicit-sha `at:` anchors are fine (they resolve against the open fact's mount like scrubbing).
4. **Flat-envelope asymmetry**: lens read endpoints return flat `{facts,total}` / `{results,total}` / `{values}` / `{path,children}` (served with hal+json content-type) while their repo twins are HAL `_embedded`; lens facts `sort=` is accepted-and-ignored (recency only); per-mount 500-row snapshot bounds `total`. All deliberate; document in API docs rather than "fixing". The `/lenses/{lens}/stats` and `/lenses/{lens}/topics` endpoints follow the same flat-envelope convention.
5. **Live updates watch only the write repo**: the SSE events stream (App.tsx EventSource) is repo-scoped to `state.repo` = the lens's write repo, so the union list/tree/stats do NOT auto-refresh when a READ mount commits; the user sees new read-mount facts only on the next manual refetch (filter change, context re-entry, reload). STILL OPEN.
6. **RESOLVED (771a608d, 2026-07-20)** — was: the browse stats panel showed write-repo-only stats in a lens context. Now `GET /lenses/{lens}/stats` fans out over federate.ReadTargetsFor, exact-sum union roll-up + per-repo breakdown; RightPanel LensStatsView renders it (union header + merged histograms), with an explicit error state (never a false "no facts").

**Lens-read surface is now complete.** The full set of lens union reads behind LensMiddleware: `/facts`, `/facts/*`, `/search`, `/completions`, `/stats`, and — RESOLVED (1191f89, 2026-07-20) — `/topics[/*]`. The Library's **Path** sort in a lens context previously did nothing (fell through to the flat chronological `listLensFacts`); it now browses a **unified, merged-by-topic, lazy per-level** ontology tree (internal/web/handlers_lenses_topics.go): directories dedup by name into plain nodes, fact leaves stay per-mount but are **deduped write-first via writeFirstWinners** (a fork whose upstream is read-mounted shares fact UUIDs — the tree MUST agree with the flat facts union, not show the shadowed copy), each leaf carrying a {repo,id} source tag and the canonical lensWirePath address. Frontend: api.lensBrowse + Library `lensTree` branch. All lens union reads pass the ontology-rooted dirPath/path to ReadTargetsFor so the decision-17 topic-skip fires uniformly.

**Why:** each gap was adjudicated during the wave's reviews or the 2026-07-20 sweep as pre-existing, deliberate design, or low-impact; fixing was traded against shipping v1. Gaps 6 (stats) and the tree/Path browse were subsequently built out once the read-endpoint pattern was established.

**How to apply:** when extending lens browsing (cross-mount walking is deferred feature #2 in the backlog), start from gap 1; when writing API docs, fold in gap 4 (now covering /stats + /topics). Gap 5 is the one remaining gap — the natural scope of a "lens live-refresh" follow-up: the same SSE work that makes the union list auto-refresh would also live-refresh the tree and stats panel.

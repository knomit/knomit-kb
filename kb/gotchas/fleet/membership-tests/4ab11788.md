# TEST GOTCHA for multi-instance fleet tests: the knomit+https git client is ONE per process, so each step must call pki.InstallGitTransport(dir, key) for the instance about to talk; a member's join makes TWO ref updates at the hub (the mount's round, then the record); and a hub only ever sees main's tip on a refused join

(PR #525, verified at merge commit fd991d4f.) 1. The knomit+https scheme is registered once per process (go-git's transport table is global), pointing at the certificate directory and key of whichever instance last called `pki.InstallGitTransport(dir, key)`. A test that runs several Managers in one process (the knomit-hosted e2e in cmd: master hub, members, a decommission) must call it for the instance about to fetch or push, or the request goes out with another instance's certificate and is refused or, worse, admitted as the wrong peer. 2. A member's mount round pushes its bare agent branch BEFORE the join writes its record, so a successful join is two ref updates (two receive-packs) at the hub; assertions on push counts must say 2 for a join and 1 for a leave. 3. A refused join on a knomit host leaves the hub's agent/<id> ref (main's tip, no record) because receive-pack refuses deletes; the assertion is 'no member row and no record', not 'no ref'. 4. A route-level test of a refused branch on the master can get 404 instead of 409 because the merger demotes it (kb/invariants/fleet/fetch-judge/88eb5593.md). MISREADING: a green single-instance test says nothing about the transport state.

# Fleet create's known gaps, stated as limits: the generic create can leave its forge branch when it fails late, a create whose store never remounts leaves its forge branch, and a foreign agent/<id> tip makes the rollback fail forever with create_unfinished until someone deletes the branch by hand

PR #518 (merge 537f2019) knowingly ships these limits. Each is a FORGE-ONLY leftover (a fleet hosted here has no origin and no remote branch); the local side is always cleaned. They are limits to state, not bugs the next reader should 'discover'; none was fixed in this PR and they were ruled acceptable for now in the review follow-up.

1. THE GENERIC CREATE FAILS LATE, after its own initialize push. m.Create (mode initialize) pushes agent/<id> with the ontology commit, and its own rollback (agentBranchAlreadyPushed paths in lifecycle.go) deletes the local repository by itself. The fleet's undo then finds no repository to retract from, so the forge keeps agent/<id>. Since the create runs detached from the request (a client hang-up no longer cancels it), what is left is a failure in Create's own late stages: a mount-stage failure, or createTimeout. A retry then runs InitFromRemote, adopts the branch, finds an ontology and fails with ErrRemoteAlreadyInitialized advising mode clone, which a fleet-id ontology refuses (reserved id). So the forge cannot host a fleet again until the branch is deleted by hand. The fix belongs in initialize's own rollback (a RetractPushedBranch there) and would help every repository, not only the fleet. MISREADING: the text agentBranchAlreadyPushed adds ('creating this repository again will adopt that branch') is WRONG for a fleet (review nit R4).

2. THE STORE NEVER REMOUNTS. A create that died inside the repo create, after its push and before the store was whole, is a registered repository that does not mount (unavailableFleetCreateRepo). The rollback deletes it locally but cannot read it to retract what it pushed. Same leftover, same manual way out.

3. A FOREIGN TIP ON agent/<id>. If someone else pushed to this instance's own agent branch and this instance had not fetched it, RetractPushedBranch refuses ('left alone', both hashes) and the rollback fails every time: the marker stays and create AND registration answer create_unfinished (409) until the branch is deleted on the forge by hand. The message says 'left alone' with both hashes but does not name the way out (review nit R3). A foreign tip this instance HAD fetched is deleted instead (kb/architecture/store/remote-sync/retract-pushed-branch). It needs a second writer on this instance's own agent id, which is unsupported.

WAY OUT for all three: delete the branch agent/<this instance's agent id> on the forge, then retry the create (or, for 3, the retry of the rollback happens by itself at the next start, create or registration).

ALSO NOT TESTED: a rollback that fails (marker kept, 409, last_error, retry) has no test (review nit R2); a foreign tip on the bare remote would exercise it.

UPDATE (PR #525, verified at merge commit fd991d4f): the three limits above still stand, but the review nits attached to them were fixed. (R4) `agentBranchAlreadyPushed(..., fleet bool)` now gives a fleet create text that says the fleet create's rollback deletes the branch and never offers to adopt it, so the 'will adopt that branch' misreading in limit 1 is gone from the message (a join gets its own text via `fleetUndoText`: it says the refused join takes the branch back from the origin where the origin allows a delete). (R3) The `create_unfinished` message now ends with the way out: 'If the forge's agent/<id> moved to a tip this instance did not push, delete that branch on the forge by hand, then retry'. (R2) The failing rollback is tested: TestCreateFleet_FailedRollbackIsRetriedUntilTheForgeBranchIsGone (a foreign tip on the forge keeps the marker, create and JOIN both answer create_unfinished, last_error says 'rollback incomplete', and after the branch is deleted by hand the retry succeeds). In limit 3 'registration' now means the join (RegisterFleet no longer exists).

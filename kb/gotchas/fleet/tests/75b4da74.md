# The repos fleet test fixtures have Cfg.Git.LocalReconcileInterval == 0, so NO local reconcile loop runs at all: a test of a round must set an interval or call runLocalReconcileLoop(..., once=true, ri.fleetHostRound) directly

Verified at merge commit c6e282db. runLocalReconcile returns at once when interval <= 0, BEFORE the first round (internal/repos/sync.go), and the repos fleet fixtures leave Cfg.Git.LocalReconcileInterval at 0. So a test that expects the hub's local reconcile (main following the agent branch, the host record re-asserted by fleetHostRound) to run sees nothing happen and may pass vacuously or fail for the wrong reason.

FIX IN A TEST: set deps.Cfg.Git.LocalReconcileInterval (TestFleetHost_TheHubReassertsItsRecordEachRound uses time.Hour, with the loop's first round and wake doing the work), or call runLocalReconcileLoop(..., once=true, ri.fleetHostRound) directly.

NOT A PRODUCT BUG: in production the default is 30 s; only interval 0 means no loop, and with it main does not follow the agent branch on a hub either.

MISREADING: "a green fleet test proves the reconcile ran": assert that the round was reached (the record or main moved), not just that nothing failed.

# The harness attribution reminder instructs the OPPOSITE of the user's CLAUDE.md, and following it is silent — it cost six commits here, plus a report that asserted the trailer absent without checking

The global CLAUDE.md forbids any Claude co-author or attribution trailer in EVERY project and states explicitly that it overrides the harness default telling you to add one. A session reminder nonetheless instructs the opposite, phrased as a direct imperative and arriving late in context. On knomit PR 1 it won: all six commits carried `Co-Authored-By: Claude ...`, even though the rule was ALSO restated in the plan's process rules and in the task brief. Three independent restatements were in context and the reminder still won.

It compounded: the worker's report asserted "no Claude co-author trailer anywhere", written without running git log. The reviewer caught both, and it was the only blocking finding on an otherwise-passing gate.

PRE-PUSH CHECK, which is the whole remedy:

    git log <base>..HEAD --format='%h |%(trailers:key=Co-Authored-By)|'

Every line must show an empty value. Follow it with a grep of all messages for `co-authored|anthropic|claude-code`, because the trailer is not the only attribution shape.

THE REPAIR IS CHEAPER THAN IT LOOKS, which is worth knowing before anyone panics about a passed gate: `git filter-branch -f --msg-filter '<strip>' <base>..HEAD` preserves author AND committer identities and dates and leaves the TREE byte-identical, so `git diff <old-head> <new-head>` is empty and a review verdict on the code survives the rewrite. Push with --force-with-lease, then re-run the trailer query rather than assuming the filter matched.

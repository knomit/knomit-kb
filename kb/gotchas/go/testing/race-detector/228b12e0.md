# The Go race detector does not treat socket I/O as a synchronization point on unix: a test whose HTTP handler goroutine writes a plain variable that the test body reads after the response has a real race, and stays quiet only through incidental synchronization inside net/http

On unix (darwin, linux) the Go race detector does not model socket reads and writes as happens-before edges. The ioSync annotation exists only in internal/poll/fd_windows.go of the Go source. So when an HTTP handler goroutine (the server side) writes a plain captured variable and the test goroutine reads it after the response came back, there is NO detector-visible ordering between the two, and under the Go memory model it is a real data race even though the response 'obviously' happened after the write.

Such tests usually stay quiet only because of incidental synchronization inside net/http on the normal response path (the server writing a response and the client reading it pass through locks and channels the detector does see). A handler that Hijacks the connection and Closes it WITHOUT writing a response loses that incidental edge, and the detector fires. That is what happened in TestFleetCLI_DroppedConnectionIsAnError (cmd/fleet_test.go): the Race workflow failed on dev in run 40703894300 (head bf166c68) and PR #670 fixed it by making the 'hijacked' flag an atomic.Bool.

CONSEQUENCE: always use an atomic or a mutex for any state shared between a test's handler (server goroutine) and the test body, even when the HTTP response orders them in wall-clock terms. Do this for every httptest/http.Server handler that records anything, not only hijacking ones.

WHAT THIS DOES NOT MEAN: 'the detector did not flag it, so the round trip makes it safe'. It does not; the quiet is incidental and can vanish when the handler path changes (hijack, early close, a dropped connection) or when the Go runtime changes. Likewise a green Race run on such a test is not evidence that it is race-free. It also does not say sockets are unsynchronized at the OS level; the claim is about what the detector models and what the Go memory model guarantees.

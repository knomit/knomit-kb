# HISTORICAL (fixed 2026-09-20, PR #233): tools/bridge's lockfilePath had no Windows case, so `kb` never discovered the desktop's server.json port on Windows; it now delegates to config.LockfilePath (%LOCALAPPDATA%\knomit\server.json), and since #393 the reader lives in tools/bridge/knomitapi and feeds level 3 of ResolveServer for the proxy AND the hooks

WHAT IT WAS (until 2026-09-20): tools/bridge/main.go carried its own copy of the per-OS state-dir switch with cases for darwin and linux only (it could not import tools/desktop/internal/paths, Go's internal rule). On Windows lockfilePath returned "unsupported platform windows"; the caller logged that at Debug and fell back to the default base URL, so `kb` silently talked to localhost:19278 while the desktop's server.json sat in %LOCALAPPDATA%\knomit unread.

FIX: commit dc5087ab (PR #233, refactor(config,platform)) made lockfilePath delegate to config.LockfilePath() = <userdirs.StateDir()>/knomit/server.json, the same function the desktop writes through, so the two cannot look in different places. TestLockfilePath_ResolvesOnThisPlatform fails on any platform with no state-dir case.

SINCE PR #393 (KNOMIT_SERVER, 2026-10-02): the lockfile reader (readLockfileBaseURL, lockfilePath) moved from tools/bridge/main.go to tools/bridge/knomitapi/server.go, together with its test (tools/bridge/knomitapi/lockfile_test.go). The lockfile is now level 3 of ResolveServer (argument > KNOMIT_SERVER > lockfile > http://localhost:19278) and the HOOKS read it too, not only the proxy. See kb/architecture/bridge/server-address/resolution.

WHAT THIS DOES NOT MEAN: the lockfile is not how to reach a particular instance among several — it names only the one that wrote it; use KNOMIT_SERVER for that.

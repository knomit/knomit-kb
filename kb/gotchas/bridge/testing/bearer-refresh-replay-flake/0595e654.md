# TestBearer_ExpiredAccessRefreshesOnceAndReplays (tools/bridge/knomitapi) flakes on windows-2025 with `after refresh: 401 ""` because the OAuth store truncates access-token expiry to WHOLE SECONDS (accessExp.Unix()) — a 1 s-TTL test token minted at wall time S+φ lives only 1−φ s, so the REFRESHED token can already be dead when its replay arrives, and the transport refreshes only once by design; pre-existing on dev, not a PR #292 defect

Mechanism (origin/dev 1af30efe): the fixture uses accessTTL = 1 s (tools/bridge/knomitapi/login_test.go ~L211, newIssuerFixture(t, time.Second)). internal/oauth/store.go computes accessExp := now.Add(s.accessTTL) (~L183) and stores accessExp.Unix() (~L188); Verify compares against time.Unix(exp, 0). Truncation means a token minted at S.97 expires at S+1 and lives about 30 ms. The test sleeps 2.1 s so the FIRST token is certainly expired, then bearerTransport refreshes (bearer.go ~L41-61: refresh at most once) and replays with the SECOND token, also 1 s TTL. If the replay's Verify runs after the next whole-second boundary, the new token is expired too, the fixture answers 401 with an empty body (login_test.go ~L91-94), and the test fails at ~L226. The failure window is (refresh→replay latency)/1 s: a few ms on macOS, tens of ms on a windows-2025 runner where refreshShared takes the cross-process LockFileEx credentials lock and rewrites the file (credlock_windows.go), so Windows hits it at a few percent. The failing run took 2.73 s: 2.1 s sleep plus ~0.6 s of login and refresh I/O. First seen 2026-09-25 on PR #292's Windows leg, which touches nothing under tools/bridge; the test and bearer.go were last changed by the F19 3b bridge work (a86f3706, 70f9fa25) on 2026-09-23/24.

Consequence (BEFORE #379's fix): a red on this test in the Windows build-test leg was a fixture race, not a bearer bug. Once #379 merges, a red here is a REAL failure; do not just re-run it. The original fix-shape suggestion, SUPERSEDED by the FIX USED section below: stop sleeping through wall time — the Store already has an injectable `now` (store.go ~L63); advance it past the first token's expiry instead of sleeping 2.1 s, which removes both the flake and the sleep. Widening the TTL (3 s TTL, 3.1 s sleep) only narrows the window. Only one test uses newIssuerFixture(t, time.Second) as of 1af30efe.

WHAT THIS DOES NOT MEAN: the whole-second expiry is not itself a bug — tokens have minute-scale TTLs in production and the truncation is at most 1 s of early expiry; it bites only tests that pick a 1 s TTL and race it.

FIX USED (#379, PR #408, merged as dfaaa48b; also asserts LookupAccess returns oauth.ErrExpired right after the UPDATE): the clock injection suggested above was NOT used. Store.now is unexported, and the test lives in package knomitapi, so injecting the clock would need a production test setter. Instead the test:
- uses a 1-minute access TTL;
- after login, expires the single access token in the fixture's own control.db: UPDATE oauth_tokens SET expires_at = now-1min WHERE kind = 'access', asserting exactly 1 row affected.
The 401 still comes from the real expiry check (LookupAccess: !s.now().Before(expiresAt)), the refreshed token lives a full minute, and the 2.1 s sleep is gone. The test now takes about 0.3 s per run.
Forced failures still go red: no replay, no refresh, and an UPDATE that does not expire the token.

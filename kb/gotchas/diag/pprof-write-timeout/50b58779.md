# On go1.27 net/http/pprof no longer REFUSES a `seconds` longer than the server's WriteTimeout — configureWriteDeadline EXTENDS the write deadline by WriteTimeout + seconds for profile, trace and every delta profile (heap?seconds=N, allocs?seconds=N) — but the SNAPSHOT dumps (heap, allocs, goroutine?debug=2 without ?seconds=) get no such extension, so the runtime diag http.Server keeps WriteTimeout = 0 (with Read, ReadHeader and Idle timeouts copied from the plaintext server) or a large dump is cut off mid-write

Older net/http/pprof answered `/debug/pprof/profile?seconds=N` with "profile duration exceeds server's WriteTimeout" when N was larger than the server's WriteTimeout. That is gone: in go1.27.1 (GOROOT/src/net/http/pprof/pprof.go, configureWriteDeadline, ~L123-130) the handler reads http.ServerContextKey, and when srv.WriteTimeout > 0 it sets a per-response write deadline of now + WriteTimeout + seconds via http.NewResponseController. It is called from Profile (~L151), Trace (~L177) and serveDeltaProfile (~L287), so /profile, /trace AND the delta forms heap?seconds=N, allocs?seconds=N, block?seconds=N, mutex?seconds=N all work under a nonzero WriteTimeout. What does not get the extension is the SNAPSHOT form of every dump — heap, allocs, goroutine?debug=2, block, mutex with no ?seconds= — which streams a dump whose size scales with the process; under a 30 s WriteTimeout a big process's snapshot is truncated mid-write with no error the client can distinguish from a complete file.

Hence PR #292's openDiagServer (cmd/serve.go): ReadHeaderTimeout, ReadTimeout, IdleTimeout and BaseContext are copied from the plaintext server (`like`); WriteTimeout is explicitly 0 with a comment giving THIS reason. TestOpenDiagServer_GuardIsWired pins all four with distinct values on `like` (WriteTimeout 17 s on `like` is the negative control).

WHAT THIS DOES NOT MEAN: it does not mean a nonzero WriteTimeout would break profiling — an earlier brief said so and was wrong for this toolchain; do not cite the refusal as the reason. It also does not mean the diag port has no write bound at all: the request context (serveCtx) still ends a running profile on shutdown or listener failure.

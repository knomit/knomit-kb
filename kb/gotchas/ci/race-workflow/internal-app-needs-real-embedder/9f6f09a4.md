# The Race workflow has been red on every dev push since PR #243 (2026-09-22) with NO `DATA RACE` in any log: internal/app's wiring tests call app.New, which builds a REAL ONNX embedder, and under `go test` that needs ORT_LIB_PATH (race.yml exports only LD_LIBRARY_PATH) plus a ~612 MB model download into <Home>/models per boot — and internal/app is run by no job in tests.yml, so PR CI was green

Runs 35775080345 (PR #243) through 36025605402 (PR #278) of .github/workflows/race.yml all fail in exactly one package, knomit/internal/app, and none of their logs contains `WARNING: DATA RACE`. The last green run was 35754019410 (2026-09-22 16:25 UTC). The failing tests are TestApp_AuthConfigReachesMiddleware (auth_wiring_test.go) and TestBoot_GrantsOwnUIDLoopbackDefaultOnce (grants_seed_test.go), both added by PR #243, and TestApp_OAuthWiredOnlyWhenConfigured (oauth_wiring_test.go), added by PR #278. Each calls app.New with cfg.Home = t.TempDir(), and app.New built a real embedder via embeddings.NewEmbedder(ctx, model, filepath.Join(cfg.Home, "models"), ...). The CI error is `embedder init failed for model "embeddinggemma" ... Error loading ONNX shared library "onnxruntime.so": cannot open shared object file`, and the package fails in under 0.1 s, i.e. at ORT init, before any model download.

Why the library is not found: initORT (embedder.go:62) uses ORT_LIB_PATH when set, else stats <exeDir>/lib/libonnxruntime.so and two system paths. Under `go test` the executable is a temporary build binary, so <exeDir>/lib does not exist, and onnxruntime_go then dlopens the bare name "onnxruntime.so", which is NOT the file `make setup` downloads (libonnxruntime.so). LD_LIBRARY_PATH cannot fix a wrong basename. race.yml sets LD_LIBRARY_PATH/DYLD_LIBRARY_PATH and never ORT_LIB_PATH; tests.yml's embed-smoke job documents exactly this pitfall and sets ORT_LIB_PATH="$LIBDIR/libonnxruntime.so".

Why nothing caught it on the PR: tests.yml names packages explicitly and internal/app was in none of its lists (see the explicit-package-lists gotcha); tests.yml only BUILT ./..., and ci.yml runs no go test. race.yml's `./...` was the only CI invocation of these tests. PR #243's checks were all green.

Why ORT_LIB_PATH alone was not the fix: with it set, the three tests pass locally but take ~107 s, because each boot downloads the 612 MB embeddinggemma model into a fresh TempDir. In CI that becomes three network-bound downloads per run under -race.

THE FIX (PR #284, branch fix/race-internal-app-embedder): app.Options gained Embedder (store.BatchEmbedder), a test seam; the three tests pass &testenv.DeterministicEmbedder{} and boot in 0.7 s with no native-lib environment. nil keeps the production path (newProductionEmbedder). ./internal/app/ was added to tests.yml's bridge/platform/cmd step on all three OSes, and race.yml's -timeout was raised to 45m from the runner measurement. See the decision fact for the options that lost.

Side effect to know about: before #284, TestNew_EmbedderRequired (unknown model id) PASSED in CI partly by accident — it only checks that the error mentions "embedder", which the ORT dlopen failure also satisfies. TestBoot_RequireWithoutLocalListenerFails passes legitimately because checkLocalListener (app.go:97) runs before the embedder is built.

WHAT THIS DOES NOT MEAN: it does not mean the race job is safe to ignore or that -race is the problem. race.yml's own header warns that a red there may be an ordinary test failure in a package nothing else runs; this was that case. Check for a `DATA RACE` block before calling any red a race.

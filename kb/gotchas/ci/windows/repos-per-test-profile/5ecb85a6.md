# Measured (dev run 37854454646, before #445): internal/repos on the Windows runner is 538 s of top-level tests, of which the TestMission_* e2e family (package repos_test) is ~146 s against ~17 s locally, and playbooks.SourceRepo's copy-plus-five-git-processes costs anywhere from 2 to 19 s per call for identical work

Source: the 'gotest-json slow-tests (windows-2025 repos)' artifact of dev run 37854454646 (head 897453ff). The package took 548 s there; its 674 top-level tests sum to 538 s.

By family (Windows s / tests): TestMission 137.5/16, TestDispatch 57.0/36, TestCreateFromTemplate 35.7/11, TestCreate 25.6/39, TestListTemplates 23.6/2, TestRun 22.9/25, TestCreateLens 15.9/2, TestScript 15.4/24.

The top single tests: _BusyIf 21.5 s (21 s on every platform, the busy-if backlog; cut to ~6 s by #445), ListTemplates_NotOpenRepoIsNotAWarning 19.7 s (0.4 s locally), Mission_OneTaskTwoClaimersOneTakes 19.4 s, Tx1Bounded 15.3 s (tree build; fixed in #445), CreateFromTemplate_Fleet 11.9 s (0.6 s locally).

The template outliers have one cause: the gap between 'session reaper started' and 'resolveUpstream adopted' (SourceRepo plus clone) was 2.1 s in TestListTemplates, 9.7 s in CreateFromTemplate_Fleet and 18.8 s in ListTemplates_NotOpenRepoIsNotAWarning, for the same work.

This is MEASURED ENVIRONMENT on one runner image at one time, not a property of the code. Re-measure from the uploaded json before relying on it; do not derive a constant or a timeout from these numbers.

Open levers named at the time:
- per-Manager trigger hooks plus a recipe PATH that is not process env, which would let the Mission e2e family run in parallel (but see #446 for their transport use);
- a once-per-process cache of the SourceRepo bare repo for edit == nil callers.

# From #626 (merge c3c293b0) until #652, every web test that opened an origin session failed on windows-2025 at t.TempDir cleanup ("unlinkat ...\knomit-origin-sessions-*\run-*.lock: The process cannot access the file because it is being used by another process"): a test web.Server has no Lifetime, so its origin-session manager never ends and never closes the run lock or the session stores

originSessionsRouter mounts the manager with context.Background() when Server.Lifetime is nil. The manager holds an open *os.File on <base>/run-<id>.lock for its whole life (pki.LockFile), and a session that cloned keeps clone.db open until it is finalized. Windows cannot unlink a file with an open handle, because Go opens files without FILE_SHARE_DELETE. macOS and Linux unlink open files, so the suite was green there.

TestConnect_ReconnectToOwnRemoteNotRefused was already red on windows-2025 build-test before #626 for the same reason (its session's clone.db was never closed): dev CI runs at 01e405e4, c4f1ec74 and 97ae7c19, all ancestors of c3c293b0, failed on that test.

Fix: tests use withOriginSessionLifetime(t, &Server{...}). It points TMPDIR/TMP/TEMP at a t.TempDir, sets a Lifetime, and at cleanup ends the Lifetime, then waits on Server.originSessionsReleased, a *sync.WaitGroup that the router passes to origins.Mount (Mount returns nothing), with a 30 s guard that only bounds a hang. It then fails the test if a knomit-origin-sessions-* dir is left behind, which makes it falsifiable on macOS and Linux too. The cleanup is registered after its TempDir, so it runs first (LIFO).

DOES NOT MEAN that production leaks. App sets a Lifetime and ends it in Close.

Consequence: any new web test that POSTs /origin-sessions must build its Server through withOriginSessionLifetime or newServerWithSessions. A bare &Server{} leaks the lock and fails only on Windows. Do not 'fix' this by making Mount return a channel: TestWebAPI_ExportsOnlyMount requires Mount to have no results.

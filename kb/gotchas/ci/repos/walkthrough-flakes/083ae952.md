# Two known load flakes in internal/corpus/repos walkthrough tests, neither caused by the PR that hit them: TestWalkthrough_ArchiveMidIndexWithAParkedSyncRound fails inside its own git clone setup, and TestWalkthrough_Detach can see ErrIndexing where it expects ErrSubscriptionOrigin

Observed on dev and on PR CI runs between 2026-10-16 and 2026-10-25 (re-read at dev ee850fd6, where both tests and the helper still exist in internal/corpus/repos). Each passed on rerun and on repeated local runs, and in each case the failing PR did not touch the area.

1. TestWalkthrough_ArchiveMidIndexWithAParkedSyncRound (machine_test.go) fails with a `git clone` error inside t.TempDir ("failed to copy file ... tmp_objdir-incoming" or "maintenance.lock: No such file"). The failure is in the test's setup helper pushToBareMain (sync_mode_test.go), which clones the bare origin into a temp dir and pushes while the manager's own sync round may still be writing to the same bare repo. The reviewer of the sync-extraction PRs measured it as pre-existing (about 1 in 200 on dev, 0 in 220 on the PR head). It is a load/timing flake of the test's fixture, not a defect of the code under test.

2. TestWalkthrough_Detach (machine_test.go) fails with "repo is indexing" where it expects ErrSubscriptionOrigin: the DetachOrigin on a subscription arrives while the repo is still healing/indexing and the lifecycle machine answers ErrIndexing first. Seen on macOS slow-tests and in a -race job. The cause was inferred from the failure text and the order of the machine's checks; it has not been proven with a fix.

CONSEQUENCE: when slow-tests or the race job is red on one of these two tests alone, rerun the failed job before investigating the PR, and record the rerun result; do not weaken the assertions. A fix belongs in the fixture (wait for the machine to settle before the detach, and do not push to the bare origin while a sync round can write to it), not in the production check order.

WHAT THIS DOES NOT MEAN: it does not make every red internal/corpus/repos test a flake. Treat a failure of any OTHER test, or a repeat of these two on the same PR after a rerun, as real. And the Windows teardown race in the sibling gotcha is a different failure (cleanup after all assertions passed).

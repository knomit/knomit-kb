# knomit_learn's dedup merge folds ANY non-hypothesis top match into the incoming fact even when the incoming fact cites it: citing in refs escapes only the same-subject gate, which runs after the merge; the escape from the merge is distinct_from

applyDedupMerge (internal/mcp/learn.go, loop at ~709-934, called at ~1114) searches Path: categoryDirOf(path) — a raw path prefix, so the same directory, its descendants and prefix siblings — with Limit 1 and MinSimilarity at the model's Dedup floor, and takes only results[0]. It declines to merge for exactly: learn_dedup off on the incoming topic (~747) or on the match's topic (~806); the match already absorbed an earlier fact of this call (`consumed`, ~809); the call retracts the match (~818); or the match is named in this fact's distinct_from (~838). Nothing in the loop reads the incoming fact's refs. A non-hypothesis match is therefore folded into (and written at) the existing path even when the incoming fact's refs cite that very fact; an existing hypothesis matched by a non-hypothesis is instead subsumed (the new fact is written at its own path and the hypothesis retracted in the same commit, ~855).

Citing is the escape only for the later same-subject gate: in internal/mcp/learn_same_subject.go the caller skips a candidate the incoming fact already cites (citedIn, ~468 and ~505-511, 'declared lineage'). checkSameSubjectCollisions is called at ~1131, after the merge at ~1114, and never sees a fact the merge touched.

Consequence: to write a fact beside a near-identical one (a derived restatement, a counter-claim, a settling observation), a cite is not enough; name the existing path in distinct_from, otherwise the new fact silently becomes a revision of the cited one. Misreading to avoid: this is not a bug in the cite escape; it is the stage order, and the merge scope is the intended string prefix (see the prefix-scope fact).

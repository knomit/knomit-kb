# knomit_learn's duplicate-path guard runs BEFORE applyDedupMerge retargets paths[i], so it structurally cannot see dedup-induced collisions — a `consumed` set in applyDedupMerge is what closes that half

knomit_learn has TWO ways for two facts in one call to land on one path, and the guard in the handler only covers one of them.

The handler's guard (internal/mcp/learn.go, the `seen` map) walks `paths[i]` right after `validateAndBuildFacts` and rejects a call where two inputs share a freshly-minted or explicitly-supplied path. Its own comment names the failure it prevents: "one file, two commit entries, one body silently gone."

`applyDedupMerge` then runs and MUTATES `paths[i] = match.Path`, retargeting an incoming fact onto the existing fact it merged into. That happens AFTER the guard, so the guard cannot see it. `Search` runs with `Limit: 1`, so two inputs in the same category directory can both come back pointing at the SAME existing fact — and both used to retarget onto its path: `delete(files, paths[i])` then `reserialize(files, match.Path, merged)` for each, so the second overwrote the first, the second merge was computed against the STORE's copy rather than the first merge's result, `commits` still emitted two entries naming one file, and the summary asserted `wrote 2 facts`.

The fix (feb92f80) is a `consumed map[string]bool` keyed by `match.Path` inside applyDedupMerge, set in both the hypothesis-subsume branch and the merge branch: one existing fact absorbs at most ONE incoming fact per call, and a second matcher is skipped so it is written at its own freshly-minted path. This is the same discipline `applyGreedyMerges` already uses in internal/synthesize/dedup.go ("each fact index participates in at most one merge").

CONSEQUENCE: when adding any new stage that can rewrite `paths[i]`, the handler's duplicate-path guard gives you NO protection — it has already run. Guard inside the stage that does the rewriting. Regression-anchored by TestLearnHandler_DedupMergeOneExistingFactAbsorbsOneIncoming.

WHAT THIS DOES NOT MEAN: skipping the second matcher is not a claim that two near-duplicates should coexist. It is the safe direction to fail — a redundant fact is recoverable by a later review prune, a body discarded inside a call the caller believes wrote everything it sent is not.

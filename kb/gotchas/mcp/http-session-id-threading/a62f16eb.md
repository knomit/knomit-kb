# knomit's MCP HTTP endpoint requires Mcp-Session-Id threaded from initialize into later calls, else tools/list 404s 'Invalid session ID'

Any non-MCP client integrating over knomit's streamable-HTTP MCP endpoint (e.g. the new `knomit-bridge claw` scaffolder's one-shot `tools/list` snapshot) MUST capture the `Mcp-Session-Id` response header from the `initialize` call and send it back on every subsequent request (`tools/list`, `tools/call`, `tasks/get`, ...). Without it the server returns HTTP 404 with a JSON-RPC 'Invalid session ID' error — NOT a 400/401, which makes it easy to misdiagnose as a wrong URL.

Exposed by Task 5 of the OpenClaw integration: the initial `rpc` helper did a stateless POST per call and `tools/list` 404'd against the live server until the session id was threaded. `tools/bridge/main.go` (the stdio proxy) already does this dance — it captures the header on the initialize response and forwards it — but the pattern is easy to omit when writing a fresh HTTP client. The fix in `tools/bridge/claw/manifest.go` threads a `*string sessionID` across the handshake (sent as the `Mcp-Session-Id` request header when non-empty, updated from each response header). The TS plugin path avoids this because it reuses `knomit-bridge`'s existing proxy over stdio.

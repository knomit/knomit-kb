# The `binding` parameter description is chosen per (endpoint kind, gate mode); never build one text from another (knomit_repos once served "Optional. ... REQUIRED on the unscoped endpoint")

bindingArg(required) returns one of two constants: bindingRequiredDescription for gateRequired tools, bindingOptionalDescription for gateOptional (knomit_repos). knomit_bind (gateUngated) declares no `binding`. Before #657, bindingArg(false) prefixed "Optional." onto the required text, so knomit_repos served a description that said both optional and REQUIRED.

The optional text states what gateBinding does in that mode: a missing handle passes; an unresolvable handle is reported as bound.status "unresolvable", not raised; a handle sent to knomit_repos is routed or reported as above on every endpoint kind (superseded: before PR #664 a handle on a URL-scoped endpoint was refused on presence).

Consequence: TestBindingArg_DescriptionMatchesGateMode pins each registration's text to its gate mode and requires every gate mode to be exercised. Changing a tool's gate mode means changing its bindingArg argument in the same edit.

PER ENDPOINT KIND (PR #664). The text is now bindingDescription(mode, endpointKind) over three kinds from endpointKindOf, which reads the same mount marker the gate enforces: endpointUnscoped (/api/v1/mcp, handle required for gated tools), endpointScoped (a --repo/--lens URL at the default branch: handle optional, absent means the URL's own repo or lens, a handle must come from knomit_bind on THIS endpoint) and endpointFixed (a URL naming one branch or experiment: "Not accepted on this endpoint"). Tools register with the unscoped text; endpointToolFilter (endpoint_tools.go) swaps the texts per tools/list without mutating the registered tools, serves the scoped knomit_bind schema (only `experiment`), and does NOT list knomit_bind on an endpointFixed URL. TestBindingArg_DescriptionMatchesGateMode runs per kind through the filter, and TestScopedBind_SchemasAndInstructionsPerEndpoint checks the exp: and main mounts.

WHAT THIS DOES NOT MEAN: `binding` is never schema-required, not even for gateRequired tools, because a scoped endpoint takes it optionally. Do not write that it "must NOT be passed on a URL-scoped endpoint": that was true before PR #664.

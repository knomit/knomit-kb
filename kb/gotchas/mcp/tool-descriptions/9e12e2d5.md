# The `binding` parameter description is chosen per gate mode; never build one text from the other (knomit_repos once served "Optional. ... REQUIRED on the unscoped endpoint")

bindingArg(required) returns one of two constants: bindingRequiredDescription for gateRequired tools, bindingOptionalDescription for gateOptional (knomit_repos). knomit_bind (gateUngated) declares no `binding`. Before #657, bindingArg(false) prefixed "Optional." onto the required text, so knomit_repos served a description that said both optional and REQUIRED.

The optional text states what gateBinding does in that mode: a missing handle passes; an unresolvable handle is reported as bound.status "unresolvable", not raised; a handle sent on a URL-scoped endpoint is refused, as for every gated tool, because the presence check runs before the mode check.

Consequence: TestBindingArg_DescriptionMatchesGateMode pins each registration's text to its gate mode and requires every gate mode to be exercised. Changing a tool's gate mode means changing its bindingArg argument in the same edit.

WHAT THIS DOES NOT MEAN: `binding` is never schema-required, not even for gateRequired tools, because a URL-scoped endpoint refuses it.

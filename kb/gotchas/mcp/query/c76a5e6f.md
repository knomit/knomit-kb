# knomit_query with sort=recent AND text is ranked by relevance (score, then committed_at desc, then path), not by date; only a text-less sort=recent is newest-first

store recentFactsSearch re-sorts by score when a query is present (pinned by TestRecentFacts_WithQuery_SortsByRelevanceNotDate), and queryRecent fuses per-mount lists with RRF in that case. Recency only breaks ties.

Consequence: to get "the newest facts about X", use a text-less sort=recent with a structural filter (path, domain, entities, context). Adding text yields the most relevant facts.

Since #657 the sort parameter, the tool description and the server instructions say so. The earlier decision fact kb/decisions/mcp/query/explore-merged-as-sort-recent/780d9dca.md carries a matching correction.

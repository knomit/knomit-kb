# knomit_learn refuses an undeclared top-level argument; a top-level distinct_from used to be silently ignored and let the dedup merge fold the fact into the very path it was meant to keep apart

BEFORE #643, knomit_learn was the one tool that did not call rejectUnknownArguments. A top-level `distinct_from` (it belongs inside each fact object, facts[i].distinct_from) was dropped without a word, the dedup merge then ran with no decline list, and the fact could be folded into the path the caller meant to keep apart, behind a 'wrote N facts' response.

AS BUILT (#643, merge a20152c9). LearnHandler calls rejectUnknownArguments(req, learnTool()) first, before anything is read or written, so a refused call writes nothing. When the offending key is distinct_from the error gets an extra hint: 'distinct_from belongs on each fact (facts[i].distinct_from), not at the top level of the call'. Underscore-prefixed transport keys stay exempt (see kb/conventions/mcp/args/unknown-keys/ace7f836.md).

CONSEQUENCE. Pass distinct_from PER FACT. A client or script that still sends it at the top level now gets an error instead of a silent no-op.

WHAT THIS DOES NOT MEAN. It does not validate the contents of a distinct_from list (every path must exist, checked by the same-subject stage), and it does not change distinct_from being request-only and never stored (kb/decisions/mcp/learn/distinct-from-honoured-by-merge/91cf6418.md).

Anchored by TestLearnHandler_RejectsUnknownTopLevelArgument; both the refusal and the hint were sabotaged red in review.

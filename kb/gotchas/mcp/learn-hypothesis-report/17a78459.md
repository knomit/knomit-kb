# Known consequence of last-wins origin (#647): re-learning a stored fact verbatim with the same type relabels its origin to the incoming one, and an UNSET incoming origin reads as authored, so re-learning a discovered hypothesis makes it authored

CURRENT BEHAVIOUR since #647 (merge 76d2b017), BY DESIGN: the pending decision this fact used to record is settled by the user ruling in kb/decisions/mcp/learn-hypothesis-report/c5923523.md ('essentially last wins'). Supersedes the #643-era text, which described origin following the identity winner (`merged.Origin = winner.Origin`) and asked the user to choose. The same-type branch of mergeFacts (internal/edge/mcp/learn.go) is now `merged.Origin = newFact.ResolvedOrigin()`.

When the incoming and stored types agree, the merged fact takes the INCOMING fact's resolved origin, whichever side wins. Probe rows (same text, incoming confidence 0.9 over stored 0.6):
- stored synthesis/distilled, incoming synthesis with explicit origin authored -> authored (same outcome as before #647, now by design).
- stored synthesis/authored, incoming synthesis distilled -> distilled (before #647: the identity winner's, which here was the same value).
- stored hypothesis/discovered, incoming hypothesis with origin UNSET -> authored (by design). This is the realistic one: the tool tells agents to leave origin unset for facts they write directly, an unset origin is elided on disk, a non-synthesis type reads an elided origin back as authored, and an elided origin on a synthesis reads back as distilled. The hypothesis-merge note says nothing about origin.

CONSEQUENCE. Re-learning a discovery-engine prediction verbatim, origin unset, silently relabels it authored; re-learning a distilled synthesis with an explicit authored origin credits pipeline output to a human. To keep a stored fact's origin, pass the same origin explicitly, use distinct_from, or use knomit_update. Origin cannot be repaired with knomit_update (immutable): the fix is retract plus re-learn. Evidence-weight gating reads origin, so a relabel changes how other facts' weights are computed (kb/decisions/mcp/origin-by-grouping-method/e532ec2a.md says origin records how the candidate group was formed; the ruling knowingly overrides that for merges).

WHAT THIS DOES NOT MEAN. It is no longer an open question or a bug to fix. When the types DIFFER, origin stays with the stored fact (type-keep ruling, #643; Origin.ValidateForType forces it). It is not specific to hypotheses; the rows span synthesis and hypothesis.

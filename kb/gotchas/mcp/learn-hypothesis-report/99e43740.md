# Gaps #642 left open: another non-hypothesis type can still take over a stored fact's type on an identical-text merge, review's judged prune takes whatever non-hypothesis type the judge returns, and the incoming-side learn_dedup: off check has no isolating test

STATUS AT #644 (merge 13abafd3): ALL THREE GAPS ARE CLOSED. Gap 2 closed in #644: ApplyPruneDecisions no longer takes the judge's type; the merged type is derived from the members (mergedTypeFromMembers, internal/corpus/synthesize/decision.go; kb/decisions/synthesize/review-prune-merge-type/ holds the decision). Earlier status at #643 (merge a20152c9): gap 1 and gap 3 closed, gap 2 open. The text below describes the state at the #642 merge commit (77896f0a), where gaps 1 and 2 were read from the code and gap 3 was reasoned from the tests, none of them sabotaged. Gap 1: since #643 mergeFacts takes existing.Kind, existing.Type and (when the types differ) existing.Origin, and a ONE-note 'stored type kept' is emitted whichever side wins (kb/decisions/mcp/learn-hypothesis-report/489f36ae.md). Gap 3: TestApplyDedupMerge_IncomingSideLearnDedupOffIsolated (internal/edge/mcp/learn_dedup_attr_test.go) seeds a flagged incoming topic whose top match sits in an unflagged topic, so deleting the incoming-side check now fails; sabotage was verified. The last paragraph ('Do not read the absorbed-hypothesis rule as dedup never changes a stored fact's type') is superseded for learn by #643: learn's merge now never changes a stored type; review's judged prune (gap 2) still can.

1. TYPE TAKEOVER BETWEEN NON-HYPOTHESES. The #642 guard (absorbedHypothesis, see kb/decisions/mcp/learn-hypothesis-report/91e88bb3.md) covers only an incoming HYPOTHESIS meeting a stored non-hypothesis. An incoming non-hypothesis of a DIFFERENT type (say an insight over a stored observation) with the SAME title and body and a higher confidence (or equal confidence and at least as many sources) still wins incomingIdentityWins = sameStatement && newFactWins, so mergeFacts writes the winner's type and kind at the stored path. Needs identical text, so it is rare, and it is not reported by a type-change note.

2. REVIEW'S JUDGED PRUNE. ApplyPruneDecisions (internal/corpus/synthesize/decision.go) refuses a merged output whose type is hypothesis, but otherwise sets merged.Type from the type the judge returned (validated only by ValidateOutputType). The learn-side rule 'a merge never makes a hypothesis out of a stored non-hypothesis' is therefore learn-only in effect; in review the hypothesis refusal is the equivalent, and the non-hypothesis type is whatever the judge says. The deterministic dedup tiebreak (synthesize/dedup.go mergeFacts) is a different path and keeps non-hypothesis over hypothesis (kb/decisions/synthesize/dedup-merge-tiebreak/02422cde.md); cross-KIND merges there are separately blocked (kb/incidents/synthesize/cluster/cross-kind-dedup-merge/94172e81.md).

3. INCOMING-SIDE learn_dedup: off HAS NO ISOLATING TEST. applyDedupMerge checks learn_dedup on the incoming topic (before the search) and again on the match's topic (after it). TestApplyDedupMerge_LearnDedupOffSkipsSearchKeepsDonation seeds its flagged fact in the same flagged topic, so deleting the incoming-side check still passes: the match-side check declines the same-topic match. A test needs an incoming fact in a flagged topic whose top match sits in an UNflagged topic inside the path prefix. Until then treat the incoming-side skip as unverified.

WHAT THIS DOES NOT MEAN. None of these is a regression from #642; each pre-dates it. Do not read the absorbed-hypothesis rule as 'dedup never changes a stored fact's type'.

AFTER #643: gap 1 closed (learn dedup merge never changes the stored type, kind or, on differing types, origin; same-type origin reattribution remains, see kb/gotchas/mcp/learn-hypothesis-report/17a78459.md); gap 3 closed (isolating test exists); gap 2 was untouched by #643 and is closed by #644: review's judged prune now keeps its members' type too (shared type, or the 02422cde tiebreak winner's when members differ). So 'a merge never changes a stored type' now covers learn dedup AND review's judged prune. It still does not cover distill, which can retract a hypothesis and cite it in a new synthesis fact.

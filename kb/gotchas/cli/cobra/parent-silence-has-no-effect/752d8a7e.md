# SilenceUsage / SilenceErrors set on a PARENT cobra command do NOTHING for its subcommands — cobra (v1.10) consults only the command that ran and the root, so grants, oauth and identity each carried a dead setting with a comment claiming it worked; since PR #286 the two flags live on the root command and main.go is the single error printer

Cobra's ExecuteC decides whether to print usage and the error by looking at the executed command's SilenceUsage/SilenceErrors OR'd with the ROOT command's — never an intermediate parent's. So `knomit grants add x` on dev before PR #286 printed the usage block even though `grants` (the parent) set SilenceUsage: true, and the same for oauth and identity. There was no test, and the comments beside those settings said they suppressed usage for the subcommands.

Since PR #286 (fixes #262): cmd/root.go sets SilenceUsage: true and SilenceErrors: true, the parent-level settings were removed as dead code, and main.go's `fmt.Fprintln(os.Stderr, err); os.Exit(1)` is the one place a RunE error is printed — once, no usage block. verify.go keeps its own settings on the command that runs and prints its own "Error:" because it exits with its own codes. cmd/root_test.go pins the behaviour through RootCmd with SetArgs/SetErr.

WHAT ELSE SilenceErrors ON THE ROOT REMOVES: cobra's "Run '<cmd> --help' for usage." hint is printed by the same error path as the "Error:" prefix, so with errors silenced an unknown command prints ONLY `unknown command "bogus" for "knomit"` — no pointer to --help. The same applies to arg-count errors (`accepts 2 arg(s), received 1`) and unknown flags. This is the UX the user chose for #286; if the hint is wanted back, main.go is the place to append it (e.g. when the error starts with "unknown command"), not the cobra flags.

Consequence: to control usage/error printing for a subcommand, set the flags on that subcommand itself or on the root — never on a group command. WHAT THIS DOES NOT MEAN: it does not mean cobra ignores the flags on a leaf command; a leaf's own SilenceUsage works, which is why verify.go's always did.

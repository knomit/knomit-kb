# `knomit grants bogus` (and `knomit grants` alone) prints grants' help and EXITS 0 — cobra's legacyArgs rejects unknown subcommands only on the ROOT, and a non-runnable group command (grants, oauth, identity) answers ErrHelp, which ExecuteC turns into nil; put `Args: cobra.NoArgs` on the group commands if a typo should be an error

Cobra v1.10.2's default Args handling (legacyArgs) returns `unknown command` only when the command is the root; for any other non-runnable command with subcommands it falls through, execute() sees !Runnable and returns flag.ErrHelp, and ExecuteC maps ErrHelp to (cmd, nil). So a mistyped subcommand under a group command prints that group's help and exits 0. Observed on PR #286's branch (37eb6111): `knomit grants bogus` → help text, exit 0; whereas `knomit bogus` → `unknown command "bogus" for "knomit"` plus the --help hint, exit 1. This is pre-existing and independent of the SilenceUsage/SilenceErrors and --help-hint changes in #286, which neither introduced nor could fix it.

Consequence: a script that typos `knomit grants revoek …` succeeds silently. Fix shape if wanted: set `Args: cobra.NoArgs` on each group command (grants, oauth, identity); cobra then returns an arg error for a stray word, which reaches main.go with the hint appended. Not done as of #286; it would be its own small change.

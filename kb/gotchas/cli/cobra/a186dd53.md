# `Args: cobra.NoArgs` on a command GROUP that has no Run/RunE is never consulted: cobra answers help and exit 0 first, so `knomit identity import-root x` (a removed subcommand) exited 0; the fix is NoArgs PLUS a help-printing RunE, which makes the group runnable

Found in the PR #519 review (finding F4) and fixed in the merge (72919aa0, cmd/identity.go identityCmd). After export-root and import-root were deleted, `knomit identity import-root backup.key` still printed the identity help and EXITED 0, so an old runbook or script that restores a key silently 'succeeded'.

MECHANISM. For a non-root command with subcommands and NO Run/RunE, cobra's execute() returns flag.ErrHelp before it validates Args, and ExecuteC maps ErrHelp to a nil error. So `Args: cobra.NoArgs` on such a group is dead code: it never runs. The earlier fact 6ed9b0b3 suggests 'put Args: cobra.NoArgs on the group commands'; on its own that does NOT work for a group without a RunE.

THE FIX (as built): identityCmd sets `Args: cobra.NoArgs` AND `RunE: func(cmd, _) error { return cmd.Help() }`. With a RunE the group is runnable, so a stray word (an unknown subcommand) is refused by NoArgs with a non-zero exit and the usage hint, while bare `knomit identity` still prints the help and exits 0. The test (cmd/identity_test.go) asserts the error contains `unknown command "import-root"` and that the command tree has no export-root/import-root, with an `enroll` control.

CONSEQUENCES. Any group command (grants, oauth, identity, ...) that should refuse a typo or a removed subcommand needs BOTH settings. A test for a removed subcommand must assert on the error text or on the command tree, not on a flag error: running it with flags the group lacks (--dir) fails for the wrong reason and passes whether or not the subcommand exists.

MISREADING. 'identity now rejects every unknown word': yes for identity; the other groups were not changed by PR #519 and still exit 0 on a typo unless they are given the same pair.

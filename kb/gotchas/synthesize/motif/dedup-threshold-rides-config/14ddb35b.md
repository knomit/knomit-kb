# The motif scorer's corpus dedup threshold rides QualityConfig (OverDedupAt/OverDedupKnown); it can no longer be injected by wrapping the search handle

PR E8 (#580, merged into dev as 0c24a7ab; re-read at 0c24a7ab). Before E8, tools/calibrate wrapped synthesize.SearchQuery in a motifThresholdIndex and dedupThresholdFor found MotifDedupThreshold() on it by type assertion. With the search handle now a concrete *index.Facade there is nothing to wrap, so tools/calibrate/bridges.go sets cfg.OverDedupAt and cfg.OverDedupKnown (from corpusDedupThreshold) and dedupThresholdFor(cfg) (internal/corpus/synthesize/bridge_motif.go) reads them from QualityConfig (internal/corpus/synthesize/bridge_score.go). The zero value is UNKNOWN, never a default (M-5). The old `Embedder() store.Embedder` branch had no implementer and was deleted.

GUARD CHANGES: dedupThresholdFor keeps its name and now names no motif, so its entry in the by-name allowlist of TestMN6_MotifsDoNotDriveMechanics (internal/domain/fact/motif_conformance_test.go) was REMOVED (that test fails on a permission nothing uses); the internal/engine/store/index/search_query.go entry lists "RecentFacts", "recentFactsSearch" and "search" (it was "Search") because the body moved to the unexported fq.search. The behaviour is pinned by TestScoreMotifCandidate_DedupThresholdRidesTheConfig (internal/corpus/synthesize/bridge_motif_test.go).

KNOWN GAP (pre-existing on dev, not introduced by E8): the calibrate wiring itself, `cfg.OverDedupAt, cfg.OverDedupKnown = dedup, dedupKnown` at tools/calibrate/bridges.go line 277 at 0c24a7ab, is untested; the old motifThresholdIndex wrapper was untested too.

MISREADING: this does not make the threshold a user-facing setting; QualityConfig carries it only for the calibrate report, and production pipelines leave it UNKNOWN as before.

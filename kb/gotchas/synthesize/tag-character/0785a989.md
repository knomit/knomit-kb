# Tag character decides which bridge axis pays: concept-vocabulary entities make the existing token detector a mechanism bridge (75% blind precision)

Blind-judged experiment across three live corpora (2026-08): the existing shared-token bridge detector scored 75% mechanism-analogy precision on agentic-engineering versus 25% (knomit-kb) and 8% (core) — with zero code difference. The cause is the corpora's ENTITY CHARACTER: agentic-engineering's entities are largely concept vocabulary (fail-open, idempotency, blast radius, level-triggered), so shared-entity matching IS mechanism matching there; knomit-kb's entities are code identifiers and core's are companies/products, so shared-entity matching is subject matching. Consequence: where a corpus's tags name mechanisms, mechanism-level bridging already works with shipped machinery and needs no new axis; where tags are proper nouns, mechanism-level connections currently have NO axis at all. Any per-corpus budget for a future mechanism axis should be set by this property, not globally. WHAT THIS DOES NOT MEAN: it does not mean writers should stuff concepts into entities — the 75% arm measured organically accumulated tags, not a retrofitted convention.

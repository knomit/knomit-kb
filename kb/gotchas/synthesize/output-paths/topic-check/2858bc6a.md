# The review and discovery pipelines write fact paths without the ontology topic check - an LLM-proposed topic not in the ontology is accepted and then hidden from every lens (known gap, deferred by the user 2026-11-03)

The synthesize write paths gate a new fact's path ONLY on step.ValidateOutputPath (internal/corpus/synthesize/step/validation.go:192), which checks that the path is under the ontology root and not private - it does NOT check the top-level topic against the repo's ontology. Affected sites (at ada36e41): internal/corpus/synthesize/decision.go:154 (merge, mf.Path), :417 (distill, df.Path) and :691-692 (propose: the LLM's topic_path goes through fact.BuildFactPath, then ValidateOutputPath), and internal/corpus/synthesize/discovery/discovery.go:350 (p.Path).

CONSEQUENCE: an LLM in the review/discovery pipeline can write a fact under a topic the repo's ontology lacks. Lens reads then drop that member for that topic (internal/corpus/federate/federate.go:259, the TopicNames skip), so the fact is invisible in every lens Path view, lens search/Recent with a path filter, MCP knomit_query path filters and lens FactSets - while the repo's own views still show it. This violates the user's rule (2026-11-03): "the first level MUST always match the ontology, LLMs cannot just willy nilly invent topics." MCP knomit_learn and (after PR #748) REST create/PUT-create enforce it through fact.ValidatePlacement; these pipeline paths do not.

STATUS: known and deliberately NOT fixed yet - the user ruled (2026-11-03) to take on the whole review/discovery pipeline later. The intended fix shape is to run fact.ValidatePlacement (topic + category against ri.Ontology()) on every pipeline output path, alongside ValidateOutputPath.

WHAT THIS DOES NOT MEAN: it does not mean the lens topic skip is wrong (the user kept it, relying on every write path validating), nor that existing user data is affected (an audit of the user's four lenses on 2026-11-03 found no off-ontology folders). It means only that these four pipeline write sites are an open bypass of the topic rule.

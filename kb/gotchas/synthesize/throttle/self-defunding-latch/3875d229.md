# A mechanism that defunds itself on bad outcomes CANNOT recover if being defunded also stops it producing outcomes — "a resolution restores it" is unreachable by construction

The restatement shortlist is funded by its own judge verdicts: enough pairs judged with none resolved defunds the corpus. The naive design says "a later resolution refunds it" — but a defunded corpus emits no pairs, so it generates no verdicts, so no resolution can ever occur. The recovery path is not merely unlikely; it is unreachable by construction. The mechanism is a LATCH, not a governor.

**The fix shape, in two parts.** (1) A bounded probe path: a defunded corpus still spends one pair every Nth session (`throttleProbeInterval`, counter in `restatement_throttle_state`), so feedback keeps arriving at a known price. (2) The probe slot must be consumed only when it ACTUALLY PRODUCED EVIDENCE — a probe that found nothing to offer has bought no information, and charging it an interval re-introduces the latch at a slower rate.

**Part (2) was DESIGN INTENT, not implemented behaviour, until knomit#117b (commit 810cd286, 2026-08-26).** `probeAllowed`'s doc comment said "consumed by the caller, and only when a pair was actually emitted", and an earlier revision of THIS FACT said the same — but the code consumed the slot on `len(out) > 0`, where `out` is the SELECTED set. Once knomit#117a established that selected != served (a pair whose half no longer resolves is dropped at item creation), a probe could select one pair, serve NOTHING to a judge, and still buy a full interval of silence: the latch reintroduced at a slower rate, inside the very mechanism written to prevent it. Consumption now happens in `planRestatementShortlist` AFTER enqueue, gated on `served`; `applyEmissionOutcome` downgrades `Probing` so the health line cannot report a probe that never reached a judge. A failed consumption write is non-fatal and self-healing, because `probeAllowed` HOLDS its counter at the interval rather than bumping past it.

**Generalises.** Any kill-switch keyed on its own results has this shape. The vocabulary kill switch in the motif work is the same design. When you write "X turns back on when Y happens", check whether being off is what prevents Y.

**The named misreading.** "There is a recovery path, so it cannot latch" — the existence of a recovery CONDITION is not the existence of a recovery PATH. Ask what generates the evidence the condition reads, and whether the off-state still generates it.

**The second named misreading — and why this fact was wrong for two releases.** "The doc comment and the fact both say the slot is consumed only on real evidence, so it is." A stated contract is not an implemented one. Both asserted the served-gated behaviour while the code was selected-gated; the divergence opened SILENTLY when #117a split selected from served, and nothing re-read the older claims against the new distinction. When a fact and a code comment agree, they may share an ancestor rather than a verification — neither is evidence for the other.

Bound by `TestDynamics_DefundAndProbeRecoveryOverSessions`, `TestDynamics_ProbeIsNotConsumedWhenNothingIsEmitted` (selection found nothing to offer) and `TestProbe_IsNotConsumedWhenTheSelectedPairIsNeverServed` (selection found something that never reached the judge — the case the first two structurally could not see).

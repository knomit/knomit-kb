# ScopedCluster restricts every seed's neighbour search to the seed's OWN category directory, so two facts filed under different freeform categories can never co-cluster — at any similarity

`ScopedCluster`'s subgraph step searches each seed's neighbours with `Path: categoryDir(seed.File)` — a hard restriction to the seed's own parent directory. Every cluster in the system is a Louvain community over that subgraph.

So a fact under `.../vulnerabilities/cisco/` can only ever draw neighbours from `.../vulnerabilities/cisco/`. Its twin under `.../vulnerabilities/networking/cisco/` is structurally unreachable AT ANY COSINE — measured at 0.969 on the live corpus and still in a different cluster.

This matters because `category` is freeform BY DESIGN (the ontology validates `topic` and generates the uuid). The same event ingested on a different day gets a different freeform category. That CREATES the second copy — there is no path collision to notice — and this line then HIDES it from every consumer of clustering: prune items, distill groups, dedupCluster's mechanical merge, both bridge axes, and discover.

CONSEQUENCE for anyone touching clustering or dedup: do not reason about cluster membership as "similar facts end up together". It is "similar facts IN THE SAME DIRECTORY end up together". Any mechanism that assumes the mechanical merge will catch a near-duplicate is assuming co-location, not similarity.

STILL PRESENT at the cited commit, tracked as issue #149 and gated on a designer ruling. It was deliberately NOT fixed alongside #127: removing the restriction re-clusters the whole corpus and moves EffortNormal's output, which collides with the MN5 byte-identical guarantee. #127 routed around it instead, by repairing the restatement shortlist — the vehicle built for pairs whose halves cluster apart.

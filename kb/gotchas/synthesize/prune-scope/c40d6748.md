# Prune's consolidation judge is cluster-scoped — CLOSED for epistemic facts by the restatement shortlist (PR #99); pragmatic restatements remain unjudged

knomit's consolidation is two-stage: a mechanical embedding gate at learn time (conservative by necessity — no LLM in the call path), then the prune work item, whose LLM judge CAN do full consolidation (MergeEntry replaces N facts with one newly authored body under a fidelity contract, new path and title). But prune items are built per Louvain cluster, so the judge only ever sees facts that landed in the SAME cluster. Two semantic restatements that cluster apart are compared by nothing, at any threshold, ever — and those are precisely the pairs that satisfy all three bridge gates and pollute discovery as fake 'bridges'.

Measured (2026-08 spike): a title-only-embedding shortlist (high title-cos, blended-cos below dedup, different communities) found a real cross-community restatement pair (two DERIVED_FROM facts) on knomit-kb in one pass, but floods on news-style corpora (483 same-actor-headline candidates on core).

The diagnosis: the duplicate problem in bridges is a consolidation SCOPE gap, not a threshold problem — loosening the mechanical gate would destroy data without fixing it.

**STATUS: ADDRESSED, not merely known (motif Phase 0, PR #99, merged to dev 2026-08-24).** The fix is the one this fact predicted: the existing prune judge is fed bounded cross-cluster candidates from a title-only abstraction axis, as ordinary `prune` work items — shape-identical to cluster items, so no prompt, schema, or apply-path change was needed. Selection is a percentile of the repo's own pair-similarity distribution; enforcement is the corpus's own judge verdicts. The flood case is BOUNDED rather than suppressed: core's high candidate rate costs at most the judge-slot cap (8) per session. See `kb/decisions/synthesize/consolidation-scope-fix/467f51b7.md` and `kb/architecture/store/abstraction-axis/75a47ad3.md`.

**THE RESIDUAL — the gap is closed for EPISTEMIC facts only.** The abstraction axis is epistemic-only, so restatements among PRAGMATIC facts are still judged by nothing, exactly as described above. This is forced, not chosen: prune's decision path does not carry `Kind` through `mergedFact`, so a pragmatic fact reaching synthesis would be silently rewritten as epistemic. Lifting it means fixing that first.

**The named misreading.** "Prune scope is fixed" is too strong. Cite this fact for the pragmatic half, and the consolidation-scope-fix decision for the epistemic half.

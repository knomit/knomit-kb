# Prune's consolidation judge is cluster-scoped — cross-cluster restatements are never judged by anything and live forever

knomit's consolidation is two-stage: a mechanical embedding gate at learn time (conservative by necessity — no LLM in the call path), then the prune work item, whose LLM judge CAN do full consolidation (MergeEntry replaces N facts with one newly authored body under a fidelity contract, new path and title). But prune items are built per Louvain cluster, so the judge only ever sees facts that landed in the SAME cluster. Two semantic restatements that cluster apart are compared by nothing, at any threshold, ever — and those are precisely the pairs that satisfy all three bridge gates and pollute discovery as fake 'bridges'. Measured (2026-08 spike): a title-only-embedding shortlist (high title-cos, blended-cos below dedup, different communities) found a real cross-community restatement pair (two DERIVED_FROM facts) on knomit-kb in one pass, but floods on news-style corpora (483 same-actor-headline candidates on core). Consequence: the duplicate problem in bridges is a consolidation SCOPE gap, not a threshold problem — loosening the mechanical gate would destroy data without fixing it; the fix is feeding the existing prune judge bounded cross-cluster candidates, enabled per-corpus (engineering-style first).

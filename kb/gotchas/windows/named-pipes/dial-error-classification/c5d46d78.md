# A MISSING pipe classifies as fs.ErrNotExist and an INACCESSIBLE one does not, so the bridge's quiet/loud fallback split needs no Windows special case and no string matching

tools/bridge/knomitapi's fallback logs a MISSING local listener at Debug (the ordinary case: no server running) and an UNREACHABLE one at Warn ONCE (the anomaly). The split keys on errors.Is(err, fs.ErrNotExist) and works unchanged on Windows.

MEASURED:

- **No pipe at the path**: winio returns *os.PathError{Op:"open", Err: windows.Errno(ERROR_FILE_NOT_FOUND)}, and syscall.Errno.Is maps that onto fs.ErrNotExist. -> Debug, quiet fallback.
- **Pipe present but its ACL excludes us**: `open \\.\pipe\knomit-...: Access is denied.` — NOT fs.ErrNotExist. -> Warn once, fall back.

Both classifications are asserted INSIDE the fixtures that produce them (unreachableLocalListener, absentLocalListenerPath in dial_fixtures_windows_test.go), so a fixture that stopped producing the condition it claims fails rather than passing vacuously.

NOTE ON THE WINDOWS ANALOGUE OF A STALE SOCKET: there is none. The kernel reaps a pipe with the process that created it, so no inode survives an ungraceful exit. The equivalent condition — "a listener is there and this bridge cannot use it" — is a pipe whose ACL excludes us, which is what a knomit running as another user leaves in the namespace.

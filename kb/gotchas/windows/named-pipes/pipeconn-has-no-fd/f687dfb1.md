# winio.PipeConn is net.Conn + Disconnect + Flush and does NOT carry Fd() — reading a pipe client's identity needs TWO type assertions, and asserting only on Fd() would admit any conn that happens to expose one

winio.PipeConn (go-winio v0.6.2) is `net.Conn` plus `Disconnect() error` and `Flush() error`. It has NO Fd(). The accepted connections are the unexported *win32Pipe, and `Fd() uintptr` is promoted from the embedded, also unexported *win32File (file.go:277).

Server-side code that needs the HANDLE therefore needs two assertions, and both earn their place:

- `conn.(winio.PipeConn)` proves it is a winio pipe and nothing else. THIS is what keeps a TCP connection from ever yielding a peer.
- `conn.(interface{ Fd() uintptr })` gets the handle. Asserting only this would admit any future net.Conn that happens to expose an Fd().

Several handoff notes on knomit#245 said the handle comes off PipeConn directly. It does not — checked in the module source.

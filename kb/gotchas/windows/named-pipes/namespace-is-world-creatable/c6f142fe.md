# The pipe's ACL gates who may OPEN the name, NOT who may create it — \\.\pipe\ is world-creatable, so the "ACL is the credential, like the 0700 data root" parallel is true for opening and false for creating

knomit's pipe is created with SDDL `D:P(A;;GA;;;<our SID>)(A;;GA;;;SY)` — protected, this user and SYSTEM only, no deny ACE (a DACL with no matching ACE already denies, and an explicit deny would also lock US out if our SID ever appeared in the denied group).

That controls who may OPEN knomit's pipe, which is the real parallel to 0600 under a 0700 data root. It does NOT control who may CREATE a pipe by that name: the `\\.\pipe\` namespace is world-creatable, so another local process can take `knomit-<hash>` before knomit boots and receive the bridge's traffic. The 0700 data root on unix gates creation too; the pipe namespace does not.

IT IS NOT A SILENT HIJACK, and the difference matters. knomit then fails to create the name (FILE_CREATE on an existing name -> access denied -> ErrSocketInUse) and says so, so the server is visibly not serving the pipe. What happens next depends on [auth].require: with it FALSE both callers warn and serve TCP only, so a bridge that reached the squatter gets no signal from either side — that is the residual exposure. With it TRUE the boot fails outright.

NAMED MISREADING: "the ACL makes the pipe as safe as a 0600 socket under a 0700 root". It does not, in this one direction. Closing it needs the CLIENT to verify the server's owner at dial time, which auth.DialLocal does not do; that is phase 2 (certificates) material.

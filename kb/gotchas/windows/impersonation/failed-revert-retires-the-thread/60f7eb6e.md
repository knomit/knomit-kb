# Impersonation is a property of the OS THREAD, so knomit reads a pipe client's SID on a dedicated LockOSThread goroutine — and when RevertToSelf fails the thread is deliberately left LOCKED so the Go runtime terminates it

While ImpersonateNamedPipeClient is in effect, every syscall THAT OS THREAD makes runs as the client. Go moves goroutines between threads at any preemption point, so the impersonate -> OpenThreadToken -> RevertToSelf sequence runs on a dedicated goroutine under runtime.LockOSThread with no other work on it.

IF RevertToSelf FAILS the thread is still impersonating and must never go back to the scheduler — some later, unrelated goroutine would then run as the client. The disposal is to leave the thread LOCKED: the Go runtime terminates a locked thread whose goroutine exits. So the unlock is CONDITIONAL, never a defer.

readClientSID returns a third value, `clean`, meaning "this thread either never impersonated or reverted successfully"; only then does pipeClientSID call runtime.UnlockOSThread. The deferred RevertToSelf is the only writer of `clean`, including on a panic, so the returns past it are naked.

Also here: ImpersonateNamedPipeClient is not in x/sys/windows v0.46 and is resolved as an advapi32 LazyProc, guarded with Find() first — LazyProc.Call PANICS on a missing proc, and a server must not die because one connection could not be identified.

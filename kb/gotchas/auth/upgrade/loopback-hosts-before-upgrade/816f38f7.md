# A same-host proxy or tunnel that forwards the browser's Host unchanged (code-server's /proxy/<port>/, tailscale serve, Codespaces/dev tunnels, an nginx keeping Host) gets 421 from knomit ≥ #281 until its name is in [auth].loopback_hosts — add the key BEFORE upgrading, older binaries only warn about it

SHAPE. Such a proxy connects to knomit from loopback and forwards the Host the browser used. The maintainer's path is Tailscale → code-server → /proxy/<port>/. Verified in code-server 4.112.0's source: http-proxy 1.18.1 `createProxyServer({})` with no changeOrigin, targeting http://0.0.0.0:<port>. At the plain listener that request is indistinguishable from a DNS-rebound page except by the NAME. So after #281 it is refused with 421, and the detail names `[auth].loopback_hosts`.

FIX, zero-break order: add `loopback_hosts = ["<name>"]` under `[auth]` in knomit.toml BEFORE installing the new binary. Older binaries decode it into nothing and only log "unknown config key, ignored" (config.warnUndecoded), so nothing breaks at either step.

NOT AFFECTED:
- a proxy addressed by an IP literal (a Tailscale 100.x address);
- vite's `npm run dev` (Host localhost:5173);
- the desktop webview (127.0.0.1:<port>);
- kb over TCP or the socket;
- the OAuth listener's reverse proxy (it never runs AuthMiddleware);
- any non-loopback deployment (Docker, LAN).

WHAT LISTING MEANS: everyone who reaches knomit through that name holds [auth].loopback_default. That is what already happened silently before #281. Never list a name whose DNS you do not control; a .local mDNS name can be claimed by any LAN host.

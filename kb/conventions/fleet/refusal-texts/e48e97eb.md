# Fleet refusal and error texts name the Fleet page action (e.g. `Fleet → Settings → Leave`), never a REST route; TestFleetTexts_NameNoRESTRoutes scans every string literal of internal/repos/fleet*.go and a second test scans pki.ErrNotEnrolled and oauth.ErrNoFleetRoot

Convention (PR #527, N2; verified at merge commit c6e282db). The fleet's errors are shown verbatim on the Fleet page, so a text names the page's action, never a REST route (`POST /api/v1/...`, `/api/v1/`).

ENFORCEMENT. (1) TestFleetTexts_NameNoRESTRoutes parses internal/repos/fleet*.go (non-test) and checks EVERY string literal, a const's or a variable's as much as one written inside the call (so a route held in a `const msg` and passed to fleetErr is caught), except an import path, a struct tag, and a literal passed to a zerolog event method (Msg, Msgf, Str, Strs, Err, Int, Bool, Dur: log lines are read by an operator, not the page); the counts are asserted so a scan that reads nothing cannot pass. (2) TestFleetTexts_PKIAndOAuthErrorsNameNoRESTRoutes checks, in internal/foundation/pki and internal/edge/oauth, only the literals passed to errors.New or fmt.Errorf (plus an identifier there that names a package const/var holding literals), because those packages also hold real route patterns and log lines; it requires that pki.ErrNotEnrolled and oauth.ErrNoFleetRoot were checked.

CONSEQUENCE: a new fleet refusal text, or a new error in pki/oauth that can reach a page, must not name a route; the failure to look for is a literal anywhere in fleet*.go, not only inside fleetErr.

MISREADING: "every error in pki and oauth is scanned": only those passed to errors.New / fmt.Errorf; a text built another way is not.

# Set up a fleet repository ROOT FIRST: commit artifacts/fleet/root.crt and crl.pem when the repository is created, and add members only afterwards. root.crt is added only while it is missing (write-once), so whoever adds it first owns the fleet's PKI

Ruling (PR #514 round 3, ruling 4) answering review F5 (trust on first root). OPTIONS: (a) declare the expected root fingerprint in the ontology: not taken; (b) build 'root + members in one commit' tooling: REJECTED, no new mechanism; (c) keep the existing write-once rule (a root is added only if missing) and DOCUMENT the order: CHOSEN. The documented order closes the window in which an already-admitted member could commit a rogue root. It is written in the fleet preset's comment (internal/fact/ontology_fleet.yaml), the knomit-playbooks fleet template README, and the design doc (D7).

A root alone without a CRL leaves every member's next commit refused no-cert (rule B fails closed), so the CRL lands with it.

MISREADING: this is not enforced by code; a fleet created another way still accepts the first root.crt anyone commits, and write-once makes a wrong first add irreversible inside the gate (only a hand commit with verification off can undo it).

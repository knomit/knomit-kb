# In `knomit serve`, bind EVERY listener first (plaintext, local socket, TLS, OAuth), THEN log "knomit ready", THEN start the Serve goroutines — and defer each server's Close AFTER its listener's Close so LIFO stops the server before its listener or socket file goes away

Since PR #286 (fixes #261) cmd/serve.go's RunE is ordered: bind plaintext (net.Listen), open the local socket, open TLS, open OAuth; only when all four are bound does it log "knomit ready"; only then do the Serve goroutines start. Every early return therefore happens before any Serve is running, and each listener has its own defer (ln.Close, closeSocket, tl.Close, ol.Close) registered BEFORE the defer of the server that uses it, so on return Go's LIFO order stops servers first, then closes listeners and removes the socket file.

Why both rules: before #286 the plaintext bind happened inside ListenAndServe in a goroutine, so a taken port logged "ready" and then log.Fatal'd; and `defer closeSocket()` was registered after `defer srv.Close()`, so on an early return the local listener was closed UNDER a running Serve, which sends a spurious "use of closed network connection" (harmless only because errCh is buffered). A TLS or OAuth setup failure could also strand an already-serving server until os.Exit.

Consequence for anyone adding a fifth listener: bind it before the ready log, give it its own defer registered before the server's, add its Serve to errCh (and grow the buffer: one slot per possible sender), and keep the ready log last. WHAT THIS DOES NOT MEAN: the runtime diag server is not part of this; it only warns on failure, as before.

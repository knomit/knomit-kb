# A test that needs the playbooks templates as F24 reads them mounts the pinned checkout as a REPO: playbooks.SourceRepo builds a bare git repo of the whole checkout (one commit, byte for byte) for a Manager to clone or subscribe under LocalOriginRoot; the two-instance mission tests create the host's repo from it with mode "template"

Since F24 (knomit-playbooks submodule at main 39fc744, no TEMPLATE.md, `playbooks.ManifestFile` deleted; bumped by #435 to main 040f6868, where only the mission README changed under .knomit/templates/): `playbooks.SourceRepo(t, bare, branch, edit)` copies every file of the checkout except .git into a work tree, lets `edit` change it, commits once on `branch` and pushes to a bare repo at `bare`. Mount it with `CreateSpec{Mode: "clone" | "subscribe", Origin: {URL: fileuri.New(bare)}}` on a Manager whose `LocalOriginRoot` contains `bare`, then create with `Mode: "template", Template: {Repo, Name}`.

`newMissionHost` (internal/repos/mission_e2e_test.go) now does exactly that for H: the old path (custom create with the ontology, then one `WriteFact` per file) LOWERCASED `SKILL.md` and `README.md`; the new one asserts every template file lands at its exact path. Its `mutate` hook now edits the template in the SOURCE before the commit (editTemplate). `cmd/mission_route_test.go` deliberately stays on the clone-and-delete-origin route, which at 040f6868 is the README's "With your edits" route of Knomit-hosted step 1 (the default "Create it" is mode template); it is the only route whose repo can have a consensus branch other than main, so it is the one that pins trunk/master (a localConsensusBranch hardcoding main turns it red). Since 040f6868 the README names a git host's `main` (a create request's origin branch, and the GitHub-hosted section): TestMissionTemplate_Settings cuts only those TOKENS (readmeWithoutForgeBranches: the `"branch": "..."` literals and the backticked `main` inside the GitHub-hosted section, each cut asserted present) before its no-branch-names check; the rest of that section, its ontology snippet included, is still scanned.

CONSEQUENCE: H's manager now holds TWO repos (playbooks and kb); a mission test that iterates `m.Names()` must not assume one.

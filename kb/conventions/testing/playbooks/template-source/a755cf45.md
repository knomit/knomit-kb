# A test that needs the playbooks templates as F24 reads them mounts the pinned checkout as a REPO: playbooks.SourceRepo builds a bare git repo of the whole checkout (one commit, byte for byte) for a Manager to clone or subscribe under LocalOriginRoot; the two-instance mission tests create the host's repo from it with mode "template"

Since F24 (knomit-playbooks submodule at main 39fc744, no TEMPLATE.md, `playbooks.ManifestFile` deleted): `playbooks.SourceRepo(t, bare, branch, edit)` copies every file of the checkout except .git into a work tree, lets `edit` change it, commits once on `branch` and pushes to a bare repo at `bare`. Mount it with `CreateSpec{Mode: "clone" | "subscribe", Origin: {URL: fileuri.New(bare)}}` on a Manager whose `LocalOriginRoot` contains `bare`, then create with `Mode: "template", Template: {Repo, Name}`.

`newMissionHost` (internal/repos/mission_e2e_test.go) now does exactly that for H: the old path (custom create with the ontology, then one `WriteFact` per file) LOWERCASED `SKILL.md` and `README.md`; the new one asserts every template file lands at its exact path. Its `mutate` hook now edits the template in the SOURCE before the commit (editTemplate). `cmd/mission_route_test.go` deliberately stays on the README's clone-and-delete-origin route (it pins the trunk/master consensus-branch behaviour).

CONSEQUENCE: H's manager now holds TWO repos (playbooks and kb); a mission test that iterates `m.Names()` must not assume one.

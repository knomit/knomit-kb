# Convention: in cmd fleet tests a knomit-hosted hub's local reconcile round is run by hubRound, a DetachOrigin send that restarts the Sync stage and, Synchronous, runs one local round inline (the hub's duties, then main follows the agent branch)

cmd/fleet_leave_test.go (PR #532, verified at a1b0ca5d) defines hubRound(t, hub): hub.mgr.Send(ctx, ri, repos.DetachOrigin()) on the hub's fleet repository. A hub has no origin, so the detach changes no data but restarts the Sync stage, which, in Synchronous test mode, runs one local reconcile round inline: fleetHostRound (host-record re-assert, then the leave duty), then main follows the agent branch. Use it whenever a cmd-level test needs 'the master's next round' on a hub, instead of sleeping for local_reconcile_interval. It is a test seam, not production behaviour: a running hub's rounds come from runLocalReconcileLoop on an interval. The repos-level fixtures have no local reconcile loop at all (kb/gotchas/fleet/tests/75b4da74.md). A forge master's round is a restart or a direct call of the origin round.

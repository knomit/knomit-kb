# The job contract tests in internal/edge/web decode every api/jobs envelope with decodeStrict (DisallowUnknownFields) into a test-side jobEnvelope, so a new field on the api/jobs wire envelope fails list, get, delete and rebuild tests until jobEnvelope is updated

Verified at d8198dd7 (PR #636). internal/edge/web/handlers_jobs_hub_test.go defines decodeStrict, which decodes with DisallowUnknownFields, and a test-side jobEnvelope struct (the wire shape api/jobs serves; the web tests keep their own copy because api/jobs' type is unexported). The list test (listJobs) and jobOf in handlers_jobs_rebuild_index_test.go route every job-envelope decode through decodeStrict.

CONSEQUENCE: adding a field to the api/jobs envelope fails the list, get, delete and rebuild job tests with 'unknown field' until jobEnvelope in internal/edge/web/handlers_jobs_hub_test.go is updated to carry it. That failure is the guard working: update the struct (and assert the new field), do not loosen decodeStrict. #636 review: an extra field on the envelope turned those four tests red.

DOES NOT MEAN: that every JSON decode in those tests is strict. The remaining Unmarshals decode a map[string]any check and the SSE TaskEvent, which are different shapes and stay lenient. It also does not pin field types or values by itself, only that no undeclared field is present.

# To force a timing window inside a third-party Go module (e.g. mcp-go), copy the module out of GOMODCACHE, patch in a sleep, and run `go test -modfile=<scratch go.mod>` whose `replace` points at the copy — `-overlay` cannot do it because it refuses files in GOMODCACHE

Recipe (used 2026-09-29 to reproduce the mcp-go SSE-ordering flake in TestOAuthMCP_TaskPathRespectsTheCeiling):
1. `cp -R $(go env GOMODCACHE)/github.com/mark3labs/mcp-go@v0.45.0 <scratch>/mcp-go && chmod -R u+w <scratch>/mcp-go`. Module cache files are read-only.
2. Patch the window into the copy, e.g. `time.Sleep(300 * time.Millisecond)` just before `return &mcp.CreateTaskResult{...}` in server/server.go.
3. `cp go.mod go.sum <scratch>/`, then append `replace github.com/mark3labs/mcp-go => <scratch>/mcp-go` to the scratch go.mod.
4. `go test -modfile=<scratch>/go.mod ./internal/web/ -run ...`. The repo's go.mod stays untouched; nothing lands in the working tree.

Why not -overlay: go build's -overlay refuses to replace files inside GOMODCACHE, so it cannot patch a dependency.

Keep the scratch copy in the session scratchpad, never in the repo. Run the check both with and without the fix: the unfixed run must fail with the same error CI showed, or the forcing did not hit the real window.

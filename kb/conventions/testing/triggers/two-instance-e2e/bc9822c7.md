# Two-instance trigger e2e with REAL script tools lives in package repos_test (internal/mcp imports repos) with seams in an export _test.go file; quiesce by polling 'last completed run read the CURRENT head and the buffer is flushed', never by waiting for one head, and put a fake `claude` first on PATH whenever a template's wake recipe can fire

How F08 PR D's mission e2e is built (internal/repos/mission_e2e_test.go, mission_protocol_test.go, mission_export_test.go):
- mcp.NewScriptTools cannot be used from package repos (import cycle), so the test is package repos_test and mission_export_test.go (package repos, test-only) exports SetTriggerClockForTest (the dispatcher's run clock, which is also the sandbox's Date, shared by every instance in the process), QuiesceTriggersForTest, KickTriggersForTest (a due sweep), SettleConsensusForTest and ConsensusForTest (the merger's Merges/Refused counters).
- Waiting for 'a run at head H' (waitTriggerHead) can hang: a script's write is the next advance, and chained runs move completedHead past H between polls. Poll instead: runSequence().completedHead == the branch head now && flushed() && the head did not move during the check.
- Background sync off on both instances; a round is driven by hand (host AdvanceLocalUpstream, peer Sync, Push, host merger settle), so time only moves with the fake clock.
- The template's wake runs a recipe that execs `claude` via the child's PATH (lookPathIn over os.Environ()); a dev box has a real claude on PATH. The test hard-links the test binary as claude(.exe) into a temp dir prepended to PATH and sets KNOMIT_RECIPE_HELPER, so TestMain turns the child into the recipe helper that records argv.
- 'Exactly one take' must be asserted over HISTORY (every non-merge commit that ADDED a working copy), not only final state: the dup-check backstop hides a double take in the final state (sabotage: decide picks itself -> final state 1 copy, history 2).

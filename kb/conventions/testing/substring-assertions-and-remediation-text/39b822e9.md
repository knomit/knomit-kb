# An error message that says how to FIX a setting repeats that setting's name, so a bare-name substring assertion on it is satisfied by the remediation clause alone and tests almost nothing

TestBoot_RequireWithoutLocalListenerFails asserted `strings.Contains(err, "[auth].require")`. The error names the failing condition AND how to fix it ("...or set [auth].require = false"), so the needle is satisfied by the REMEDIATION half alone.

Found by forced failure: rewriting only the DIAGNOSIS clause to "auth is on but no listener..." left the test GREEN, while the message no longer named the failing condition at all.

An error that tells you how to fix a thing usually repeats the setting's name, so a bare-name substring assertion on such a message tests almost nothing. Assert on the phrase that ONLY the diagnosis can produce — here `"[auth].require = true"`, which the remediation clause (`= false`) cannot satisfy. Stripping the diagnosis now fails it.

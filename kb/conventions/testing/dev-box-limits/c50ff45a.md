# On the Windows dev box, helper Claude sessions run in Windows session 0 with no interactive desktop: GUI behaviour of knomit-desktop.exe (console window, tray icon, surviving terminal close) can only be verified by the human; and `make` must be run as C:\msys64\usr\bin\make.exe from PowerShell, not from Git Bash

Observed 2026-09-19/20 by the worker and reviewer sessions while making knomit-desktop.exe a GUI-subsystem app. Two limits, unrelated to the Linux dev-box fact in this category:

1. The worker and reviewer sessions run in Windows SESSION 0 ([Environment]::UserInteractive = False, SessionId 0). Session-0 isolation has no visible desktop, so a Wails window cannot be created: knomit-desktop.exe boots, logs "UI starting (tray up, server still booting)", installs kb and knomit-okf, then exits 1 with nothing logged after ~18 s. A CONTROL binary without -H windowsgui exits the same way at the same point, so this exit is the environment, not the change under test. Consequence: any check that needs a window, a tray icon, a console appearing or not, or a process outliving its launching terminal MUST be handed to the human on the interactive session; an agent report that claims to have seen those is wrong. What agents CAN measure: PE subsystem (optional header offset 68: 2 = GUI, 3 = CONSOLE), std handle types (GetFileType), and console screen-buffer contents via ReadConsoleOutputCharacterW against a synthetic console.

2. `make desktop` from Git Bash dies with "build cache is required, but could not be located: GOCACHE is not defined and %LocalAppData% is not defined"; exporting GOCACHE does not help because Git Bash and MSYS2 are different msys runtimes. Run C:\msys64\usr\bin\make.exe from PowerShell (tools/desktop/README.md documents this). Not a VC++ 14.40 problem.

Also: unlike the Linux dev box, the desktop build tag (-tags desktop) DOES compile and test locally here (Windows uses the system WebView2, no GTK), so `CGO_ENABLED=1 go test -tags desktop ./tools/desktop/...` is a valid local gate. GOOS=linux cross-vet does not work (CGO_ENABLED=0 excludes sqlite-vec's cgo files; no Linux cross-toolchain).

Misreading to avoid: "the binary exits 1 in the helper session" is not evidence that a desktop change is broken.

# The script-budget test brackets the host ctx's deadline between two clock reads (before+budget <= deadline <= entered+budget) instead of bounding latency (#659)

TestScript_TimeoutIsOutcome had a 3 s bound for three fires, a 1.5 s bound on the blocked call, and a 50 ms bound on "own" time. Under -race load it failed at 81.7 ms. Now the blocking host call returns only when its ctx ends, and the loop never returns, so both fires can end only through the 300 ms budget; settle's 20 s is the hang detector. The deadline is checked by bracketing it: runScript sets it to (its start + budget), and that start lies between the test's write (read `before`) and the stub's entry (read `entered`), so `before + budget <= deadline <= entered + budget` holds whatever the load, and the error must be DeadlineExceeded. A stub that sees no deadline, or one past the bracket, REFUSES at once rather than blocking, so the sabotage is red in under a second of test time instead of after the hang detector. The host-time check moved to TestScript_HostTimeIsNotTheScripts (24 h budget, stopwatch).

Sabotage (measured on the branch): a host ctx without the deadline is red with "the host ctx carries a deadline".

Weakening to know about: the case "a host call that RETURNS inside a short budget is not cut" is now checked only under a 24 h budget, where it holds trivially (the old 100 ms-under-300 ms case was itself load-sensitive). It is no longer covered under a short budget.

What this does NOT mean: a fire the budget must NOT end still needs real-time headroom under a short budget; that is why that case runs under a 24 h budget.

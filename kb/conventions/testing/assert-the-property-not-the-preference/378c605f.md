# A component preferred for a PROPERTY must have that property asserted — the bridge's dial suite proved transport SELECTION and stayed green while the bridge silently became anonymous on the pipe it had just preferred

tools/bridge/knomitapi's dial suite asserted WHICH server answered ("via-socket" vs "via-tcp") and nothing about who the caller was when it got there.

Under a forced downgrade of auth.DialLocal to the anonymous impersonation level, internal/auth and internal/config went RED and tools/bridge/knomitapi stayed GREEN: the bridge still preferred the pipe, still reached it, and was simply nobody on arrival. That is the entire failure the feature exists to prevent, and the package closest to it could not see it.

The serveLocalAt fixture now installs the REAL auth.ConnContext and fails any test whose request arrived without a verified peer carrying the test process's pid. The same forced red now fails four bridge tests.

THE GENERAL FORM: when a component is preferred for a PROPERTY (here, a verified identity) rather than for reachability, its tests must assert the property. Asserting that the preferred path was taken is a test of the preference, not of the reason for it.

# A guard test that reads another package's files resolves them through internal/testsupport/modroot from the module root, never with a relative path like ../sibling or ../..

A guard test that reads source files belonging to another package must locate them with internal/testsupport/modroot (modroot.Dir(t) for the module root, modroot.Path(t, elems...) to join slash-separated elements onto it), never with a relative path such as "../sibling" or "../..". Moving a package changes both the depth and the sibling names, so a relative scan either breaks loudly or, worse, silently narrows to a smaller tree and keeps passing. Allowlists whose keys name files use slash paths from the module root (for example the changesAllowedCalls keys "internal/store/internal/vcs/changes.go" and "internal/web/handlers_changes.go"), so a key is a property of the file and not of where the test lives.

Converted in layer-move step 01 (PR #588): fact/ref_consumers, mcp/motif_surfaces, repos/fleet_texts, repos/triggers_due, store/changes_guard, store/consensus_branch_literals, store/motif_acceptance, synthesize/restatement_conformance, synthesize/bridge_motif_acceptance, config/crosslang, cmd/verify_signatures, tools/bridge/antigravity/rules_sync and tools/bridge/skills. The two env-gated ones (store/motif_acceptance, synthesize/bridge_motif_acceptance) only run with their environment variable set; store/motif_acceptance also reads a fixture under .claude/plans/motif/memora-harness/ that does not exist in a clean checkout. Non-vacuity assertions were added to ref_consumers (it must walk at least 100 files and see every allowlist key) and triggers_due (it must walk more than 200 files and see both allowed files); the other converted scans already failed when nothing matched.

Not converted, because they have no cross-package relative scan (the plan row was over-inclusive): fact/guidance, fact/triggers, repos/template, repos/triggers_run (it walks "." only), tools/desktop/native, and test/archtest (already derived from the root, and it does not move). Do not read this list as a to-do.

modroot imports "testing", so it is test-only: it is in the forbidden list of TestHarnessNotLinkedIntoShippedBinaries and no shipped binary links it. It is NOT a new top-level package; it is a child of the exempt internal/testsupport tree, so the no-new-top-level-packages rule is not engaged. The convention does not mean every test must use modroot: a test that scans only its own package directory keeps using ".".

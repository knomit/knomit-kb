# A guard the compiler makes unreachable reads as coverage it does not provide — delete it, and record WHY so it is not re-added

The hash-pin test read a `.go` file and asserted both `require.NoError` on the read and `require.NotEmpty` on the bytes. The second cannot fire: the bytes are empty only for a zero-byte `.go` file, which fails the BUILD ("expected 'package', found 'EOF'") before the test binary runs.

The read assert IS reachable, and the distinction was established by removing the file: the package still compiles without it, so `require.NoError` fires with its named message. That contrast — one guard demonstrably fires, its neighbour demonstrably cannot — is what separates a live guard from a theoretical one, and it is worth spending the two minutes to check rather than reasoning about it.

DELETING IT IS NOT ENOUGH ON ITS OWN. The next reader sees a bare read and adds the empty check back, because it looks like an omission. The comment left in its place records both facts: that the read assert is reachable (and how that was shown) and that there is deliberately no empty check beside it (and why). A silent deletion loses the reasoning that justified it.

# A fixture that pins field WIRING needs pairwise-distinct values — and falsifiability beats corpus fidelity when the two conflict

A test that asserts a response field is wired to the right source field is vacuous wherever two fixture values coincide: with Recurring == EpistemicRecurring == 1, wiring authored_epistemic_recurring to health.Recurring stayed green (sabotage-confirmed), and the same fixture also had Clusters == Mints, hiding a second possible swap nobody had flagged. The rule: give every field a value distinct from every OTHER value visible in the same response (sibling fields AND unrelated counts like the collection total), assert one field per assertion so a failure names the mis-wired field, and sabotage-check each field by wiring it to a sibling and watching the test go red.

Why: count/delta-style checks certify numbers, not which source produced them — identical values make correct and swapped wiring indistinguishable.

How to apply — including the tradeoff: distinctness may require values the real system can never produce (the store increments Clusters and Mints on the same row, so they are ALWAYS equal in reality). For a wiring fixture, choose falsifiability and say so in a comment telling future readers not to 'correct' the values back into realistic agreement — restoring fidelity silently disarms the check. Keep whatever real invariants cost nothing (here EpistemicRecurring <= Recurring <= Clusters). Named misreading: this policy is for WIRING fixtures; a fixture exercising the arithmetic itself must of course stay realistic.

# Invariant suite hard rules: doc-comment+t.Log, never-modify-prod-to-pass, AssertIntegrity-everywhere

Three HARD rules for the invariant test suite: (1) Every test MUST have a Go-style doc comment describing the scenario AND a t.Log(...) call at the top restating it in one sentence — the t.Log appears in CI failure output so the scenario is visible without reading source. (2) Production code is NEVER modified to make a test pass. When a test fails: STOP, diagnose if test bug or divergence between production and blueprint. If divergence: write up and bring to user. (3) Every test ends integrity-clean. testenv.NewStoryboard(t) registers t.Cleanup that auto-verifies every tracked repo; every DSL mutation (Write, Update, Delete, Batch, MergeFrom, Push, Sync) ALSO calls Verify (StoryboardOpts.AutoVerify default true). Narrow exception: G-category tests that deliberately corrupt call r.ExpectDirty() to tell teardown to skip AssertIntegrity. Any G test that corrupts WITHOUT ExpectDirty() will fail teardown — deliberate loud failure.

# Invariant test suite: doc-comment + t.Log + never-modify-production-to-pass + AssertIntegrity-on-teardown

Three HARD rules for the invariant test suite in test/storytests/ (moved out of internal/ into the sibling test/ tree; see kb/decisions/testing/package-layout): (1) Every test MUST have a Go-style doc comment describing the scenario AND a t.Log(...) call at the top restating it in one sentence — the t.Log appears in CI failure output so the scenario is visible without reading source. (2) Production code is NEVER modified to make a test pass. When a test fails: STOP, diagnose if it's a test bug or a divergence between production behavior and the blueprint. If divergence: write up and bring to user. Do NOT 'fix' production to make the test green. (3) Every test ends integrity-clean. testenv.NewStoryboard(t) registers t.Cleanup that auto-verifies every tracked repo via AssertIntegrity; every DSL mutation (Write, Update, Delete, Batch, MergeFrom, Push, Sync) ALSO calls Verify (StoryboardOpts.AutoVerify default true). Narrow exception: G-category tests that deliberately corrupt (via CorruptObject, RawSQL, RawGitWrite) call r.ExpectDirty() to mark the repo so teardown skips AssertIntegrity. Any G test that corrupts WITHOUT ExpectDirty() will fail teardown — deliberate, loud failure if corruption doesn't stick.

# The fused lens read is pinned by wire-byte goldens on BOTH edges (testdata/lens_fused and testdata/query_fused); only repo ids, commit hashes, committed_at and cursors are normalized, and the failure cases invert completion order against binding order

Two characterization suites pin the output of the shared fused lens read:
- REST: `internal/edge/web/lens_fused_golden_test.go`, with goldens in `internal/edge/web/testdata/lens_fused/`. Regenerate with `go test ./internal/edge/web/ -run TestLensFused -update-lens-fused`.
- MCP: `internal/edge/mcp/query_fused_golden_test.go`, with goldens in `internal/edge/mcp/testdata/query_fused/`. Regenerate with `go test ./internal/edge/mcp/ -run TestQueryFused -update-query-fused`.

The corpus is the same on both edges. It is a three-mount lens with the WRITE repo in the MIDDLE of binding order (alpha, mid=write, zulu), so write-first is not positional:
- a path shared by alpha and mid, where alpha's copy scores higher and mid's copy must win;
- `config-drift` on alpha and `drift-config` on zulu, so only the union's widening reaches zulu;
- each mount committed in its own second, so recency is a total order.

Cases: semantic and filter-only relevance, limit/max_results, MCP cursor paging, recency with and without text, repo= and its 422, qualified and unmounted path filters, the min_similarity notice, the empty lens, the one-member lens, and two failing members.

In the failure cases the LOWER-indexed mount is delayed 150 ms and the higher one fails at once: a probe-only delay through index.Overrides.Reads, plus the error through SetReadFaultForTest. The store IGNORES an Overrides.Reads error on Search/RecentFacts, so the delay hook alone cannot fail a read.

When you change the fused read ON PURPOSE, regenerate BOTH suites and review both diffs together. A diff on one edge only means the edges have diverged again.

Sabotage at eb6a6ef8 showed both edges are falsifiable:
- flipping the RRF tie-break fails both corpus goldens;
- reporting the highest-indexed failure in FanOut fails REST failure_search and MCP failure/failure_recent;
- reporting the last failure on the serial path fails REST failure_facts.

# master, worker and reviewer share ONE checkout that stays on dev — worker and reviewer edit only in their own git worktrees (knomit-worker, knomit-reviewer) and never switch the shared tree's branch

The master, worker and reviewer Claude Code sessions all run against ONE checkout, /home/pba/data/knomit/knomit, which stays on `dev`. The worker edits ONLY in its own git worktree (/home/pba/data/knomit/knomit-worker) with its own GOCACHE; the reviewer reviews from its own worktree (knomit-reviewer). Nobody switches the shared tree's branch. On 2026-09-16 the worker branched in the shared tree and switched it under the other two sessions: a branch switch or half-finished edits there corrupt the reviewer's test runs, and parallel `go test -p 1` runs fight over one build cache and temp fixtures.

PATHS ARE PER MACHINE. The /home/pba/... paths above are the shared Linux dev box. On the user's Mac (Pauls-iMac.local) the same layout is /Users/pba/data/knomit/knomit and /Users/pba/data/knomit/knomit-worker, and on 2026-09-24 no knomit-worker worktree existed there yet: the worker had to `git worktree add` it, run `make tokenizers-lib`, and give it its own GOCACHE (~/Library/Caches/go-build-worker). Derive the root from `git rev-parse --show-toplevel` of the shared checkout rather than copying a path from this fact. The convention binds the MASTER too: on 2026-09-24 the master switched the shared tree to a feature branch and the worker had to abort a half-done merge there and restore dev.

Consequences when dispatching: tell the worker up front to `git worktree add <root>/knomit-worker <branch>` (or `git -C knomit-worker checkout -B <branch> origin/dev` if the worktree exists) and to work there. Two things bite in a fresh worktree:

- `dist/<goos>-<goarch>/lib` is gitignored and holds the prebuilt native libs (libtokenizers.a, libonnxruntime.so), so a fresh worktree cannot link cgo — `go build ./...` dies with `ld: cannot find -ltokenizers`. Run `make tokenizers-lib` in the worktree (`make test` and `make build` depend on it and self-heal). Do NOT symlink the main checkout's dist/: it silently breaks the worktree when that tree is cleaned. This is an environment gap, never a code error.
- Do not `git checkout dev` in the shared tree on the assumption it is clean — verify first. If it holds uncommitted work: `git stash push -u`, checkout dev, create the worktree, `git stash pop` inside the worktree; stashes are shared across worktrees of one repo.

A REAL BOOT (`knomit serve`) from a worktree needs two more things, because `make tokenizers-lib` fetches only the tokenizers lib: ORT_LIB_PATH pointing at an ONNX runtime library (the shared checkout's dist/<platform>/lib/libonnxruntime.dylib or .so is fine to READ), and a models dir with embeddinggemma already downloaded (the worker symlinked ~/.knomit/models on 2026-09-25). Tests do not need either.

Misreading to avoid: this does NOT mean the worktree is disposable between tasks — it persists on this machine and may still be on an old feature branch from the previous dispatch; reset it to origin/dev before branching.

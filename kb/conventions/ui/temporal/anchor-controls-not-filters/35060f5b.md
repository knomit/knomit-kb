# at: and vs: are anchor controls (ephemeral), NOT filter chips (persistent)

The 'at:' and 'vs:' chip parses are anchor CONTROLS — they set state.asOf and then disappear. They are NOT panel filters and do NOT enter state.filters. Rationale: the StatusFooter pill is the single source of truth for the anchor; a persistent chip would duplicate it, and Esc semantics stay clean (clears filters; does not touch anchor). Format: at:<7-char-sha> -> {mode:'history', commit}; at:HEAD -> {mode:'live'}; vs:<from>..<to> with both 7-char SHAs (HEAD accepted on either side, resolved at parse time via lookupHead) -> {mode:'diff', from, to}. Strict 7-char hash (regex /^[0-9a-f]{7}$/i) to match StatusFooter and HistoryList display — prefix matching is a follow-up if users complain. Anchor tokens are stripped as a side-channel in parseFilterQuery BEFORE chip extraction (web/src/api.ts), so they never become FilterChips. Round-trip canonicalization: at:HEAD parses to mode:'live'; the emitter NEVER emits at:HEAD for live mode — the two encodings collapse to one canonical state.

WHAT THIS DOES NOT MEAN: the history-anchored AsOf mode is NOT called 'scrubbed'. The AsOf union has exactly three members — {mode:'live'} | {mode:'history'; commit} | {mode:'diff'; from; to} (web/src/state.ts). Code that branches on asOf.mode === 'scrubbed' matches nothing and silently treats a history anchor as neither live nor diff. A single-commit temporal anchor is mode:'history' (web/src/api.ts, SHORT_SHA branch).

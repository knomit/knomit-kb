# at: and vs: are anchor controls (ephemeral), NOT filter chips (persistent)

The 'at:' and 'vs:' chip parses are anchor CONTROLS — they set state.asOf and then disappear. They are NOT panel filters and do NOT enter state.filters. Rationale: the StatusFooter pill is the single source of truth for the anchor; a persistent chip would duplicate it, and Esc semantics stay clean (clears filters; does not touch anchor). Format: at:<7-char-sha> → {mode:'scrubbed', commit}; at:HEAD → {mode:'live'}; vs:<from>..<to> with both 7-char SHAs (HEAD accepted on either side, resolved at parse time) → {mode:'diff', from, to}. Strict 7-char hash to match StatusFooter and HistoryList display — prefix matching is a follow-up if users complain. Dispatch order in FilterBar submit: SET_AS_OF first, then ADD_FILTER for each chip, then SET_FREE_TEXT — so panels re-querying on filter change already see the new anchor (no wasted render at HEAD with new filters). Round-trip canonicalization: at:HEAD parses to mode:'live'; the emitter NEVER emits at:HEAD for live mode — the two encodings collapse to one canonical state.

# In the create wizard, amber/warning styling is reserved for things that actually FAIL — trade-offs get plain text, because if every consequence is amber nobody reads amber

# The rule

Warning styling (amber borders, ⚠ glyphs, bold "permanently") is reserved for conditions that block or break: an unreachable remote, an ontology that will not parse, a repo name already taken.

Trade-offs — choices that work fine but cost something — get PLAIN TEXT, stated once, in the user's terms.

# Why

This came out of a draft that described local-only creation as: "⚠ Attaching a remote later replays every fact into a separate history rather than merging — the two have no commits in common. Pointing at an empty remote now avoids that permanently."

Three alarming words for a consequence the user cannot evaluate and probably will not hit. It made a legitimate choice feel like a mistake. The designer's correction: "we're scaring users shitless — it's NOT that dire, it will just work anyway."

The mechanism was accurately described; the volume was wrong. `store.Replay` carries every fact across — deduped by path, latest version of each. What does NOT follow is each fact's earlier revisions. That is a small trade worth one calm sentence.

The replacement: *"You can connect a remote whenever you like, and all your facts come across. The only thing that doesn't follow is each fact's earlier revisions — starting from a remote keeps that full timeline."*

# Corollary — no "recommended" badge on peer choices

When two options are genuinely peers, a badge on one makes the other read as the wrong answer. Preference is carried by ORDERING and by describing the preferred option more fully, not by decoration.

# The general principle

If every consequence is painted amber, the reader stops reading amber — and then misses the one that mattered.

# Filter multi-chip semantics: domain/type/ep are OR, entity is AND, path is single-only

Filter chips combine differently by category: (1) multiple domain chips → OR (fact matches any specified domain); (2) multiple type chips → OR (fact matches any specified epistemic type); (3) multiple ep chips → OR (commit matches any specified operation); (4) multiple entity chips → AND (fact must have ALL specified entities); (5) only ONE path chip allowed (last one wins). Removing the path: chip resets scope to ontology_root from /status. The path: chip serves the role of breadcrumb — no separate breadcrumb component. UPDATED (library unification, 2026-05): state.view collapsed to a single constant 'library' — the old 'tree' | 'chrono' | 'history' modes were unified into a single Library list whose ordering is a sort axis (default 'recent'; effective sort overridden to 'relevance' at read time when freeText or a non-path filter is active; also 'path'). History-as-a-view-mode is gone; the right-panel mode is DERIVED from whether a fact is selected. NavStack is 20 deep (state.ts:125).

# Filter multi-chip semantics: domain/type/ep are OR, entity is AND, path is single-only

Filter chips combine differently by category: (1) multiple domain chips → OR (fact matches any specified domain); (2) multiple type chips → OR (fact matches any specified epistemic type); (3) multiple ep chips → OR (commit matches any specified operation); (4) multiple entity chips → AND (fact must have ALL specified entities); (5) only ONE path chip allowed (last one wins). Removing the path: chip resets scope to ontology_root from /status. The path: chip serves the role of breadcrumb — no separate breadcrumb component.

**Where OR is actually implemented — and where it gets broken.** The semantics are honoured SERVER-side: the facts collection handler splits each multi-value query param with `splitCSV` into `SearchOptions.IncludeTypes` / `Domain` / `EpisodeOps`, and the endpoint has always accepted a list. The client is the narrow end, and therefore the end that breaks it. `api.recent` took a single `typeFilter` STRING until the chips stopped routing through `/search`; from that point a second type chip collapsed it to `undefined`, which silently dropped ALL type filtering — the list WIDENED while both chips still sat in the filter bar, the most misleading possible failure. It now sends CSV like every other multi-value facet (`p.set('type', opts.types.join(','))`).

**Consequence to act on.** When you add a facet to the chip bar, the convention is not satisfied by the reducer holding a list: check that the API client sends a LIST-shaped param end to end. A single-string parameter anywhere on the path from `state.filters` to the query string is where OR quietly becomes "drop the filter". Enforced by `Library.chrono.count.test.tsx`, which asserts both that every type chip is forwarded (`forwards EVERY type chip, so a second one widens rather than disabling the filter`) and that a single chip goes as a one-element list rather than a bare string.

History-as-a-view-mode is gone; the right-panel mode is DERIVED from whether a fact is selected. The nav stack is 20 deep (`pushNav` in state.ts).

# Filter multi-chip semantics: domain/type/ep are OR, entity is AND, path is single-only

Filter chips combine differently by category: (1) multiple domain chips → OR (fact matches any specified domain); (2) multiple type chips → OR (fact matches any specified epistemic type); (3) multiple ep chips → OR (commit matches any specified operation); (4) multiple entity chips → AND (fact must have ALL specified entities); (5) only ONE path chip allowed (last one wins). Filters persist across view switches (Tree, Chrono, History). In History view, filters narrow the expanded commit children (not the commit list itself), EXCEPT path: which also scopes the commit list. Removing the path: chip resets scope to ontology_root from /status. The path: chip serves the role of breadcrumb — no separate breadcrumb component. View modes collapse to a single state.view: 'tree' | 'chrono' | 'history'. Right panel mode is DERIVED (no fact → summary; fact in tree/chrono → fact view; fact in history → time-travel view).

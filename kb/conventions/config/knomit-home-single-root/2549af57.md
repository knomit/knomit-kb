# KNOMIT_HOME is the SINGLE root for all knomit data; everything derives from it

KNOMIT_HOME is the SINGLE root for ALL knomit data. Everything else derives from it:
- repos and DBs under $KNOMIT_HOME/repos/;
- the SSH keypair at $KNOMIT_HOME/id_ed25519;
- the ONNX model cache at $KNOMIT_HOME/models/;
- the config file at $KNOMIT_HOME/knomit.toml. This is the ONLY place it is read: nothing looks beside the executable any more.

HOW THE ROOT IS RESOLVED: config.ResolveHome takes KNOMIT_HOME, else KNOMIT_REPO (an alias for the same root, kept for backward compatibility), else config.DefaultHome, which is per-OS: ~/.knomit on unix, %LOCALAPPDATA%\knomit\home on Windows. It then expands a leading `~` and REFUSES a value that is still relative (`KNOMIT_HOME "<v>" must be an absolute path; set it to one`), because each process would resolve it against its own working directory.

The root is NOT layered like other fields: a `repo` key in knomit.toml cannot move it. Load restores Home after decoding the TOML, since the root is where the TOML is found.

This is the ONE backend change that enabled e2e test isolation. Tests start the binary with KNOMIT_HOME=<absolute temp dir> and KNOMIT_PORT=0 for full isolation, with no risk of touching the developer's home knomit data.

Anti-pattern: do NOT hardcode subpaths under ~/.knomit/ in code; always resolve them via Config.Home, or config.ResolveHome where Load is too broad (the bridge's credentials do this).

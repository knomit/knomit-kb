# The chat activity line names calls by their titles, counted per (title, target) in first-appearance order: 'Bind demo-kb · Query 2× in knomit'; a failed bind adds nothing; a call shows ' in <target>' only when the server's in_base flag says it acts in a repo or lens

chatCopy.activitySummary takes {title, target, bind, failed} per call (ChatToolGroup builds it: title = toolCallLabel, bind = isBind(name), target = callTarget). Pieces: '<title>' then, for a bind, ' <target>' (strong); then ' N×' (strong) only when N > 1; then, for any other call, ' in <target>' when there is one; joined with ' · '. A failed bind is skipped entirely (it bound nothing), and a bind with no readable target is skipped when another bind in the group named one; a failed call of any other kind is counted like any other and no word says it failed. callTarget: a bind's target is what it names (bindTarget, from the bind's own small arguments); any other call's is the server's `target` field (the repo or lens its arguments name explicitly, lens before repo, cut at 200 bytes like key_arg), else the binding in force, but ONLY when the call has the server's in_base flag (its arguments carry binding, repo or lens), so the loader and an unbound knomit_repos read 'Load tools' / 'List repos' with no ' in '.

Live/reload rule: the page must NEVER decide in_base or the target from the call's arguments. The running tool_call event drops arguments over 16 KiB (maxApprovalArgs) and the done event carries none, so an argument-based rule worded a large call (e.g. a big knomit_learn) 'Learn' live and 'Learn in knomit' after a reload. The server computes both from the whole arguments (inBase and callTarget in labels.go) and sends in_base: true and target on the running and done events, the snapshot's tool_call row and the stored call record; the page reads no repo or lens from arguments for any non-bind call. ChatToolTitles.test.tsx asserts the live and snapshot paths give the same line for a >16 KiB call ("Learn in knomit" via the binding; "Changes in alpha" via an explicit repo), and TestChat_InBaseIsSentWithoutTheArguments / TestChat_TargetIsSentWithoutTheArguments that both ride on a running event that has no arguments. While the turn runs, the same line is drawn amber; there is no separate live step ('Searching <t> for "q"…' is gone). The old rules 'used N tools' and 'read N facts' and the capitalized first word are gone: every call has a title (or its raw name).

Consequence: do not reintroduce per-tool kinds into the summary; a new tool is summarized by its title automatically. Misreading to avoid: repeated binds to the same target are now counted ('Bind all 2×'), not deduplicated as the old 'Bound to all' was.

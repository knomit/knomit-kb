# The chat activity line names calls by their titles, counted per (title, target) in first-appearance order: 'Bind demo-kb · Query 2× in knomit'; a failed bind adds nothing; a call shows ' in <target>' only when it carries binding, repo or lens

chatCopy.activitySummary takes {title, target, bind, failed} per call (ChatToolGroup builds it: title = toolCallLabel, bind = isBind(name), target = callTarget). Pieces: '<title>' then, for a bind, ' <target>' (strong); then ' N×' (strong) only when N > 1; then, for any other call, ' in <target>' when there is one; joined with ' · '. A failed bind is skipped entirely (it bound nothing), and a bind with no readable target is skipped when another bind in the group named one; a failed call of any other kind is counted like any other and no word says it failed. callTarget: a bind's target is what it names; any other call's is its own lens/repo argument, else the binding in force, but ONLY if the call's arguments carry binding, repo or lens, so the loader and an unbound knomit_repos read 'Load tools' / 'List repos' with no ' in '. While the turn runs, the same line is drawn amber; there is no separate live step ('Searching <t> for "q"…' is gone). The old rules 'used N tools' and 'read N facts' and the capitalized first word are gone: every call has a title (or its raw name).

Consequence: do not reintroduce per-tool kinds into the summary; a new tool is summarized by its title automatically. Misreading to avoid: repeated binds to the same target are now counted ('Bind all 2×'), not deduplicated as the old 'Bound to all' was.

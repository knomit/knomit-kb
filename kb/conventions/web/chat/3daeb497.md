# A chat tool row's words come from the tool's own MCP metadata: '<annotations.title> · <main argument>' as the server sends them (title, key_arg); a tool with no title shows its raw name; web/src holds no per-tool wording

The chat server reads each tool's annotations.title and its main-argument marker (_meta "io.knomit/key": a list of argument names, first non-empty string value wins) from tools/list (mcp.toolDef -> llm.ToolDef.Title/Key, both json "-"), keeps a name->label map per chat (chat.labels, built in mount.go from the tools plus llm.LoaderDef), and sends `title` and `key_arg` on the tool_call running and done events, on the snapshot's tool_call rows and on GET .../calls/{id}. The page's toolCallLabel(c) is just `c.title || c.name`; ToolCallLine draws label, a '·' separator and the key argument in mono (data-call-part label/sep/arg), then size and time. The side panel header (ToolCallHead) and breadcrumb use the same function, so row and header can never differ. A running, done or failed call reads the same: failure is only the red dot and red text (data-error), never a verb. The loader's title is "Load tools" (llm.LoaderTitle) and its key_arg is what the call LOADED, as titles in load order (see kb/conventions/web/chat/loader-row/e81d7ca8.md), set server-side on the done event.

Consequence: to change how a tool reads in the chat, change its WithTitleAnnotation / withKeyArgs in internal/edge/mcp; never add wording to web/src. TestToolTitles_EveryToolHasItsApprovedTitle fails for a tool without a title; ChatToolTitles.test.tsx fails if web/src spells a tool name outside the behaviour allow-list (chatState BIND_TOOL, the two knomit_materialize renderer branches) or reintroduces toolVerb/toolRowLabel/'Searching'.

Misreading to avoid: the label is wording, never an identifier. Code still keys on the tool NAME where behaviour differs: knomit_bind for bind tracking (boundAfter, callTarget, the panel crumb) and knomit_materialize for the fact renderer. The old client tables (toolKind, toolVerb, toolRowLabel's 'knomit: Knomit <rest>' derivation) and the per-kind verbs (Bound, Searched, Searching, Read) are gone; the server sends the words.

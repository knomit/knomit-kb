# The chat's tools-loaded row reads 'Load tools · Query, Explain': the server words the loader call's key_arg with the loaded tools' titles in load order (a tool with no title by its raw name); the page renders key_arg verbatim

On the loader tool's done event, snapshot row and call record, key_arg is the loaded tools' titles (each tool's MCP annotations.title, via chat.labels) joined with ', ' in load order, cut at 200 bytes; a loaded tool with no title, or one the chat does not know, appears under its raw name. The row is therefore 'Load tools · Query, Explain'. The `loaded` field of the event and snapshot item stays the RAW tool names (an API list, not wording). The wording is chat.loadedTitles (labels.go), applied in the LoopToolResult case of chat.go; the page (ToolCallLine) renders title, a middle dot and key_arg and holds no name-to-title table.

The activity summary line ('Bind demo-kb · Query 2× in knomit') names the loader only by its title ('Load tools') and never lists loaded tools, so it needs no change and stays consistent with the row.

Does NOT mean: external MCP clients see different titles (they get the same plain annotations.title, no 'knomit:' prefix); nor that `loaded` carries titles. A load that loads nothing new (every asked tool already in the window) has no key_arg: the row is just 'Load tools'.

Checked live with lfm3:1.7b: the model's own load_tools call showed 'Load tools · Explain, Review' at 1280px.

Tests: TestChat_LoaderCallCarriesTitleAndWhatItLoaded, TestLoadedTitles_TitlesInLoadOrderRawNameWithoutOne, and the loader case in web/src/ChatToolTitles.test.tsx.

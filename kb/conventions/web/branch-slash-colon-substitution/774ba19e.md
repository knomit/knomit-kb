# Branch names with slashes use / → : substitution at URL boundary

Branch names containing slashes (e.g. agent/test) are encoded as agent:test in URLs. Substitution happens in middleware at the URL boundary — internally, downstream handlers see the real branch name (agent/test). The encode/decode pair lives in hal.EncodeBranch / hal.DecodeBranch (internal/edge/web/hal/anchor.go); BranchMiddleware (internal/edge/web/branch_middleware.go) reads chi.URLParam(r, 'branch'), substitutes ':' → '/', and stashes the canonical name in context under a private key. Rationale: ':' is git-ref-safe per git check-ref-format and cannot collide with any valid ref. Invisible to clients that follow HAL links. Same pattern flips for outgoing URLs in serializers via URLBuilder. {sha} in URLs accepts full commit hash or short hash (7+ hex chars). Symbolic refs like HEAD, HEAD~3, or branch names are NOT accepted — git-CLI sugar doesn't belong in stable URIs. NOTE: an earlier version of this fact claimed ambiguous short-hash returns 409 Conflict with a problem document listing candidates — that behavior is NOT currently implemented in handlers (verified at 77f70cf).

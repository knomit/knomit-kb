# Branch names with slashes use / → : substitution at URL boundary

Branch names containing slashes (e.g. agent/test) are encoded as agent:test in URLs. Substitution happens in middleware at the URL boundary — internally, downstream handlers see the real branch name (agent/test). Rationale: ':' is git-ref-safe per git check-ref-format and cannot collide with any valid ref. Invisible to clients that follow HAL links (they just paste the href). The middleware reads chi.URLParam(r, 'branch'), substitutes ':' → '/', stashes decoded name in context. Same pattern flips for outgoing URLs in serializers. {sha} in URLs accepts full commit hash or short hash (7+ hex chars). Symbolic refs like HEAD, HEAD~3, or branch names are NOT accepted — git-CLI sugar doesn't belong in stable URIs. Ambiguous short hashes return 409 Conflict with a problem document listing candidates.

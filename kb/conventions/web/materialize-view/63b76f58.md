# Section numbers come from the walk tree: a fact's parent is the LATEST earlier non-ancestor node whose builds_on cites it

The walk writes facts in pre-order depth-first order, each at its first visit, so the tree is recoverable on the client without new wire fields: a fact t was written by the fact that first reached it, which is the latest-written earlier node that cites t (one that finished before t would already have written it; the ones still being walked are on the stack and the deepest is the latest). Node.builds_on lists the written facts a node cites, so parent(t) = latest earlier non-ancestor node with a builds_on entry whose n is t.n; children are numbered in order under the parent's number. Consequences: numbers never change as pages arrive (parents are always earlier); the 'depth' field is BFS distance, NOT tree depth, so it must not be used to derive numbers; frame ancestors are skipped as parents because the walk never expands them. It does NOT work on hand-built data where a fact cites only EARLIER facts (every fact then falls back to the top).

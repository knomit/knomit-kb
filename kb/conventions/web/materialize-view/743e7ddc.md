# A count raise 'continues in place' by starting a NEW first call and reading past the ordinals already on screen, because a cursor is frozen to its first call's options

MCP/REST materialize cursors refuse every argument except the cursor, so raising Max facts cannot extend the old cursor. MaterializeStream (web/src/useMaterializeStream.ts) therefore issues a new first call with the larger count, drops nodes whose ordinal n is already rendered after checking path+repo match, and appends from the first new ordinal; the on-screen sections are never replaced or dimmed. If a re-read ordinal names a different fact the order was not prefix-stable and the stream falls back to a dimmed restart. optionChange() in materializeOptions.ts is the single classifier (same / continue / restart). Consequence: a 'continue' costs extra page fetches proportional to what is already shown, made back to back without waiting for scroll. It does NOT mean the cursor is reused.

# FactView elides Kind when epistemic and elides Body in collection items (HAL hard rule)

FactView.Kind uses `json:"kind,omitempty"` AND BuildFactView explicitly sets kind = '' when f.Kind == knomitfact.DefaultKind (= epistemic). This mirrors fact.Fact.MarshalJSON and mcp/query-elides-default-kind — epistemic facts omit the field on the wire; pragmatic facts always carry an explicit kind. Symmetric across ALL three serialization surfaces (file frontmatter, MCP response, HAL response). Same omitempty treatment applies to FactView.Body which is omitted in collection items via `json:"body,omitempty"` — this implements the HAL hard rule §3 #8 'no body in collection items'; only GET /facts/{path...} (the single-fact handler) populates Body. Anti-pattern: emitting kind:epistemic or body:'' on every result — bloats responses and breaks symmetry with the file format.

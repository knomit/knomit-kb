# A wizard test that mocks api.createRepo cannot see poll-loop bugs — test the create/poll loop at the fetch seam, and keep isTerminalCreateState in api.ts as the ONE definition of "the job is over" used by the loop, the wizard's adoptStatus and useRepoCreates

The wizard's create-and-poll loop lives in api.createRepo (web/src/api.ts). When the non-terminal state 'cancelling' was added, the loop's `while (status.state === 'running')` exited on the cancel's 202 body and CreateRepoWizard.handleCreate — which treated anything not 'failed' as success — navigated to the settings page of a repo that did not exist (four 404s). Every wizard unit test was green, because they mock './api' and so replace the very loop that was broken; the bug was found only by driving the built UI in Chromium against a real server. The fix and the rule: (1) api.ts exports isTerminalCreateState(state) and RepoCreateState; createRepo polls `while (!isTerminalCreateState(status.state))`; the wizard's adoptStatus (a terminal state never goes back to 'running'; 'cancelling' after 'done' is allowed) and useRepoCreates' anyRunning/runningCreates use the same helper — do not restate the union or the terminal set anywhere else. (2) handleCreate calls onDone ONLY on final.state === 'done' (a positive claim that the repo exists), never on "not failed". (3) Tests for this path live at the two real seams: web/src/api.createCancel.test.ts stubs fetch (202 running → poll cancelling → poll cancelling → poll cancelled) and asserts the resolved state and the poll count; CreateRepoWizard.cancel.test.tsx feeds handleCreate a create that resolves in 'cancelling' and asserts onDone is never called. Both were force-failed against the old code. Consequence for anyone mocking './api' in a wizard test: spread `await importOriginal()` first so the real helpers stay (four test files broke on the new exports with whole-module factories), and remember `vi.clearAllMocks` clears calls, not implementations.

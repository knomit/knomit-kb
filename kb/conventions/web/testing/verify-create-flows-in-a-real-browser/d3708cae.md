# For any change to the create/cancel path, the built UI driven in a real browser is the oracle — two of PR #230's defects were invisible to every unit suite and found only with Playwright from e2e/node_modules against `dist/knomit.exe serve` and the real remote

Procedure that found what vitest and go test did not: build (`make build`; note it fails with npm EPERM -4048 on web/node_modules while a vite dev server is running), start `dist/knomit.exe serve` against a home whose repo list is empty, and drive http://127.0.0.1:19278 with Playwright required from e2e/node_modules (`createRequire('<repo>/e2e/package.json')` then `require('@playwright/test').chromium`, headless) — subscribe https://github.com/knomit/knomit-kb.git, press Cancel at a chosen offset, and log every /api/v1/repo-creates* response, the OutcomeCard/progress texts, console errors, and screenshots per step. Found this way: the cancel 202 making the wizard navigate to a non-existent repo's settings page (poll loop exited on 'cancelling'); the late cancel parked at step=sync for the whole index. Practicalities: Playwright's innerText()/locator waits auto-retry for 30s — pass {timeout: 800} on reads of elements that may be absent, or timings are polluted; after a reload the app lands on the browse view once a repo exists, so open the manage surface via data-testid toknomitr-manage-btn before reading the rail; the Knowledge table row is fleet-open-<repo>; wait on the job's real state from the API rather than on rail rows; the task wrapper's exit code is its own, read the output. UI-only changes can be driven without rebuilding Go because the vite dev server proxies to localhost:19278. A full subscribe of knomit-kb takes ~65s to the index phase and ~20 min to index with the embedder on this box, so cancel timings must be read against that. Misreading to avoid: a green vitest run on a wizard test that mocks './api' says nothing about the poll loop (see the fetch-seam convention).

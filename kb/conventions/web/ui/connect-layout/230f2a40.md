# The Connect two-column layout is the shared .k-connect-grid / .k-connect-rail classes in App.css, stacked below 640px; every connect-style page uses them and none puts a grid template inline; long URLs wrap in the refusal box and OutcomeCard

As of PR #530 (4bdcf031). The Connect page's form-beside-progress-rail layout (RemoteConnectWizard and FleetFollowFlow) is the pair of CSS classes .k-connect-grid (columns minmax(0,1fr) 178px) and .k-connect-rail in web/src/App.css. At max-width 640px the grid collapses to one column and the rail moves ABOVE the form (order -1, static position, 12px top margin, both !important to beat the inline sticky style). web/src/connectStyles.ts exports them as gridClass and railClass; the inline `grid` style no longer carries gridTemplateColumns, and `column` has minWidth 0 so a long unbroken URL cannot stretch the grid cell.

WHY classes: an inline style cannot hold a media query. CONSEQUENCE: a new connect-style page applies className={gridClass} / railClass beside the shared grid and rail styles; it must NOT write its own inline gridTemplateColumns, which would silently beat the class at every width and bring the phone overflow back.

Long URLs: the Refusal box (wizardErr in web/src/manageStyles.ts) and OutcomeCard (headline and body, with minWidth 0 on the card and headline; the url line already used break-all) set overflowWrap: anywhere, so a long URL in a refusal or outcome wraps instead of widening the page. OutcomeCard and Refusal are shared, so new cards inherit this; a new text box showing a URL in a Connect page needs the same overflowWrap.

DOES NOT MEAN: that the tests prove the layout. jsdom does no layout, so web/src/connectNarrow.test.tsx resolves the CSS cascade itself (it reads the real App.css rules, applies the media query for the width under test, and checks which declaration wins over the inline style); the wrap test asserts the overflowWrap style on the rendered elements. A real-browser pass is still the gate for layout claims (kb/conventions/web/ui/manage-page/browser-pass-gate/325835cd.md). Two phone-width defects were left open by the PR (rail-open squeeze and top bar clip, recorded as a gotcha).

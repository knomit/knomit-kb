# clampTitle contract: 120 UTF-16 units INCLUDING the ellipsis; word-boundary cut unless it leaves only whitespace; never a lone surrogate; trailing whitespace trimmed; full title in title/aria-label only when clamped

clampTitle(title, max = LIST_TITLE_MAX = 120) in web/src/utils.ts:
- The cap counts the "…". A clamped result is at most 120 UTF-16 units including it; a fully hard-cut result is 119 units of text + "…". A title of 120 units or fewer is returned unchanged.
- The cut goes back to the last space within the budget, unless the text before that space is only whitespace (a title with leading spaces and no other space); then it is a hard cut.
- A hard cut never ends in a lone high surrogate: it steps back one unit instead.
- Trailing whitespace of the kept text is trimmed before the "…".
- Only ' ' is a word boundary; tab and newline are NOT boundaries.
- EntryRow sets title and aria-label to the full title only when the title was clamped; unclamped rows carry neither.

Misreading to avoid: "120 is a CSS width". It is not; it is a count of UTF-16 code units (so an emoji counts 2, and 120 units is not 120 grapheme clusters or pixels). Also not: "the result is 120 characters of title"; it is up to 119 plus the ellipsis.

Pinned by tests in web/src/utils.test.ts (describe clampTitle) and web/src/Library.titleClamp.test.tsx; each rule was sabotaged once and turned a test red (PR #681).

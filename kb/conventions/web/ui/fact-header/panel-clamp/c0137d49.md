# A panel hanging inside an overflow:hidden pane clamps itself with usePanelClamp against the nearest [data-panel-bounds] ancestor — the pane marks the element that CLIPS, the panel takes maxWidth and min(nominal, maxHeight), and its list (not its header) is the flex:1/minHeight:0 scroller

**The mechanism (web/src/hooks.ts).** `usePanelClamp(ref, active)` runs in a layout effect while `active`:
- It finds `el.closest('[data-panel-bounds]')` (`PANEL_BOUNDS_ATTR`) and the panel's `parentElement`, which is its containing block.
- It returns `maxWidth = bounds.right − PANEL_BOUNDS_GUTTER(8) − parent.left` and `maxHeight = bounds.bottom − 8 − (parent.bottom + PANEL_GAP(6))`, each floored at 0.
- It re-measures on window `resize` and, where available, via a `ResizeObserver` on the bounds element. The list rail's drag resizes the pane without resizing the window.

With no bounds ancestor it returns `{}`, meaning no clamp.

**Consumers:** ConnectionsPanel and MotifPanel pass `maxWidth` through and use `maxHeight: Math.min(NOMINAL, clamp.maxHeight ?? NOMINAL)` (`CONNECTIONS_PANEL_MAX_HEIGHT` 360, `MOTIF_PANEL_MAX_HEIGHT` 420). Their nominal widths are unchanged. RightPanel puts `data-panel-bounds` on the fact view's `flex:1; minHeight:0; overflow:hidden` wrapper, the box that actually clips the header's panels.

**Why measure the PARENT, not the panel:** ConnectionsPanel slides in with `translateY(-8px → 0)`, so its own rect is up to 8px off during the first frames. The parent is the stable anchor that `top:100%; left:0` hangs from.

**Why measure the PANE, not the viewport:** the pane is what clips. Whenever the list rail is open, the viewport extends past the pane on the left, so a viewport clamp would still let the pane cut the panel.

**A clamp is only a scroll if the list is what gives.** Each panel is `display:flex; flexDirection:column; overflow:hidden`, the header is `flexShrink:0` (so esc and × stay), and the list is `flex:1; minHeight:0; overflowY:auto`. Drop `minHeight:0` and the list's min-content propagates up and pushes past the clamp (kb gotcha flex-min-content-propagation). `panelClamp.test.tsx` pins all of these for both panels.

**Consequence for a new panel in an overflow:hidden region:** call usePanelClamp with the panel's ref, make sure the region that clips carries `data-panel-bounds`, and make the panel's own parent its containing block (position:relative). The RightPanel wiring test asserts both for ConnectionsPanel.

**What this does NOT mean:**
- *Not* a viewport or portal clamp. The panel stays in-tree (see the panel-clamp-in-tree decision).
- *Not* a flip or reposition. The anchor is fixed (left:0, top:100%), and the panel only ever SHRINKS. If the anchor itself is at or past the pane edge, the result is 0, and the panel collapses rather than moving.
- *Not* verified by jsdom. The tests stub getBoundingClientRect and pin the arithmetic and wiring. Whether the panel visibly fits is a browser-pass claim (kb convention browser-pass-gate).

# CredentialFields (web/src/fleetParts.tsx) is the one forge-credential field set for New fleet -> Access and every Fleet Settings flow, and hostPortOf is the fleet's host label because it keeps a non-default port

As of PR #529 (60ddfb1c). The Access step of the New fleet wizard and the Fleet Settings flows (Move the fleet to a forge, Move to another forge, Update access, Point at the new host, Host here) render ONE credential field set, CredentialFields (method select with auto-detect/none/token/basic/ssh, username for basic, a password-type token field that is never prefilled), and assemble the request with credentialFor (see the new-fleet-wizard architecture fact under kb/architecture/web/fleet). A new flow reuses both and does not copy the fields. Update access prefills the STORED METHOD (never the secret) and keeps Next disabled with 'nothing to change yet' while nothing differs, sending nothing.

hostPortOf(url) is hostOf with a non-default port kept (#528 N6), so two fleet instances on one machine are told apart in headlines and the Move member item; a host-less URL (file://) is named in prose, not as an unbreakable headline (the 375 px overflow found in the browser walk).

KNOWN FOLLOW-UP (not fixed): the follow flows reuse the repo Connect page's grid (connectStyles.grid), whose 178 px progress rail stays beside a ~100 px form column at 375 px; the fix belongs in the shared style.

MISREADING: 'each flow may have its own credential inputs': the credential assembly (and the never-prefilled token field) lives in one place.

# CodeMirror views share one colour list, web/src/codePalette.ts (keys #8af, strings #c9a97a, literals #a8a4f0, punctuation #6a6a6a, text #ddd, selection #24405e, ground #0c0c0c, error #f88); ontologyTheme.ts and JsonView.tsx both import it

The ontology editor's theme used to hold these constants privately; the chat's JSON view needed the same palette, so they moved to codePalette.ts (CODE_KEY, CODE_VALUE, CODE_LITERAL, CODE_COMMENT, CODE_PUNCT, CODE_TEXT, CODE_ERROR, CODE_SELECTION, CODE_GROUND), with the rationale comment for each colour. Consequence: a new code view imports these rather than re-typing hex values; change a syntax colour there, once. Misreading to avoid: theme chrome (borders, radii, the error text colour #e0a0a0 of a failed tool result) is NOT in the palette; each view keeps its own.

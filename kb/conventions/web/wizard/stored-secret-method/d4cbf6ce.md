# In the create, connect and fleet wizards a stored secret is the UI-only auth method 'secret' plus a secretId; authFor / credentialFor turn it into secret_id with NO pasted fields, and SecretPicker lists only secrets that fit the URL, never creates one, keeps the reader's pick, and preselects only where a test still follows (the wizards)

wizardState.ts (`authMethod: 'secret'`, `secretId`, action `SET_SECRET`), fleetWizardState.ts (`FleetAuthMethod` includes 'secret'; `credentialFor(url, method, user, token, secretId)`) and RemoteConnectWizard (local state) all model a stored secret the same way: the method never reaches the wire; `authFor` returns `{auth_method: '', auth_token: '', secret_id}` and `credentialFor` returns `{secret_id}`, because the server refuses secret_id together with a pasted credential (400) and derives the method from the secret. `remoteKey` includes secret_id, so choosing another secret invalidates a probe like a new token does. SecretPicker (web/src/SecretPicker.tsx) filters with secrets.ts `secretFits` (token or basic over http(s), ssh_key over SSH; host matched as the server's HostAllowed does, a host entry with a port matches only that port). Since PR #799 SecretPicker NEVER creates a secret: there is no 'Create a new secret…' option, no inline SecretForm, no allowCreate prop, and no host pre-fill (SecretForm is imported only by SecretsTab.tsx, guarded by a test in SecretPicker.test.tsx). Its select lists ONLY the fitting secrets; a disabled 'Choose a stored secret…' option shows only while nothing is chosen. The value is always '' or a fitting secret, under these rules:
- PRESELECT is opt-in (`preselect` prop) and only for the surfaces that still test before saving: the connect wizard (RemoteConnectWizard), the create wizard's access step (StepAccess) and New fleet (FleetWizard via CredentialFields preselectSecret). It applies only while the value is '' AND the reader never picked, and chooses the first fitting secret that has not expired (an expired one only when nothing else fits). The repo-settings credential box ('Use a stored secret…' / 'Use another secret…' in RemoteCredential), Restore of an archived repo (ArchivedSettings) and fleet Update access (FleetFollowFlow, where no secret means keep the stored link) do NOT preselect: they start empty and their confirm starts disabled; the currently linked secret is never preselected.
- The reader's PICK (or the value the caller started with) is remembered apart from the value. If it stops fitting (URL edited, secret's hosts changed) the value is cleared and the line '<name> isn't allowed for <host>; pick another.' (testid <testid>-lost) says why; it is never swapped for another secret, and it comes back by itself when the URL fits it again, so a host typed letter by letter does not lose the pick.
- With none fitting there is no select, only a line naming the KIND of secret the URL needs: 'No SSH-key secret is allowed for <host>.' or 'No token or username + password secret is allowed for <host>.', followed by 'Add one in Access → Secrets.' only where the server has an Access page (AccessSecretsLink.exists; a read-only server has none and gets no pointer). The value is cleared, so callers that gate on a non-empty secretId (canTest, CreateRepoWizard's access gate, FleetWizard, Use this secret, Restore) stay disabled.
'Access → Secrets' is a button only where App's AccessSecretsLink (web/src/accessLink.ts) gives `open`: it opens the server pages on Access with the Secrets section picked; it is plain text while the gear is locked. App keeps the Settings facet (repo, lens, and the fleet's pages while on Settings) MOUNTED but hidden (display:none wrapper, display:contents when shown) under the server pages, as it does the drafts, so coming back finds a half-filled connect wizard, credential box or restore prompt as it was; the picker re-reads the secrets each time the server pages close (AccessSecretsLink.returns), and so do the Remote card (useRemote, quietly) and the fleet's Access row. The link calls `open(e.currentTarget)`; on return App puts the focus back on the link (or on the picker, marked data-return-focus, if the link is gone), and when the re-read then replaces the focused link with a select, the picker moves the focus to the select. That hand-off happens only after a trip that began at this picker's own link (a flag set by the link's click, consumed by the first list read after the return), never after a gear trip, and only while the focus is on nothing (body).

Consequence: a new credential surface should reuse SecretPicker and the same 'secret' method shape rather than sending auth_method alongside secret_id, and should gate its confirm on a non-empty secretId. Pass `preselect` only if a test step still stands between the choice and a save. Misreading to avoid: 'the picker preselects' is false for the credential box, Restore and Update access. Do not add a create path to a picker: secrets are created only in Access → Secrets. Not meant: the client filter is not the check; the server re-checks host and type when linking and at every git operation.

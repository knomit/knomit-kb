# In the create, connect and fleet wizards a stored secret is the UI-only auth method 'secret' plus a secretId; authFor / credentialFor turn it into secret_id with NO pasted fields, and SecretPicker lists only secrets whose type fits the URL scheme and whose hosts allow its host, preselects the first, and never creates one

wizardState.ts (`authMethod: 'secret'`, `secretId`, action `SET_SECRET`), fleetWizardState.ts (`FleetAuthMethod` includes 'secret'; `credentialFor(url, method, user, token, secretId)`) and RemoteConnectWizard (local state) all model a stored secret the same way: the method never reaches the wire; `authFor` returns `{auth_method: '', auth_token: '', secret_id}` and `credentialFor` returns `{secret_id}`, because the server refuses secret_id together with a pasted credential (400) and derives the method from the secret. `remoteKey` includes secret_id, so choosing another secret invalidates a probe like a new token does. SecretPicker (web/src/SecretPicker.tsx) filters with secrets.ts `secretFits` (token or basic over http(s), ssh_key over SSH; host matched as the server's HostAllowed does, a host entry with a port matches only that port). Since PR #799 SecretPicker NEVER creates a secret: there is no 'Create a new secret…' option, no inline SecretForm, no allowCreate prop, and no host pre-fill (SecretForm is imported only by SecretsTab.tsx, guarded by a test in SecretPicker.test.tsx). Its select lists ONLY the fitting secrets, with no placeholder option, and chooses the first as soon as the list arrives (or when the chosen one stops fitting); nothing links on that, because every caller still needs the reader's Test/Next/Save/Restore. With none fitting there is no select at all, only 'No stored secret is allowed for <host>. Add one in Access → Secrets.', and the picker calls onChange('', null), so callers that gate on a non-empty secretId (canTest, CreateRepoWizard's access gate, FleetWizard, the Use this secret / Restore buttons) stay disabled. 'Access → Secrets' is a button only where App provides AccessSecretsLink (web/src/accessLink.ts): it opens the server pages on Access with the Secrets section picked; it is plain text on a read-only server or while the gear is locked. A picker kept mounted under the server pages (a draft wizard) re-reads the secrets when they close.

Consequence: a new credential surface should reuse SecretPicker and the same 'secret' method shape rather than sending auth_method alongside secret_id, and should gate its confirm on a non-empty secretId. Do not add a create path to a picker: secrets are created only in Access → Secrets. Not meant: the client filter is not the check; the server re-checks host and type when linking and at every git operation.

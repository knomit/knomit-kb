# A wizard step that asks one binary uses the shared segmented control from manageStyles, and its tone encodes state (remote vs neutral), never rank

The rule: when a wizard step settles ONE binary and then discloses what the answer means, draw it with segGroup + segment(on, tone) + segDot + segSub from web/src/manageStyles.ts, with segDisclosure as the rule between the choice and what it discloses. Do not write a private copy of these styles in the step file; StepSource used to carry its own and PR #193 moved them so StepReview could ask its join-or-subscribe question with the same control.

Tone is SegTone = 'remote' | 'neutral'. 'remote' is #8af, the hue this UI already spends on branches and remote refs, for the side that has a remote to talk about (connect a repository; join and push). 'neutral' is slate #8b9199 for the side that does not (keep it local; subscribe and never write). The tone says what state the choice puts you in. It does NOT rank the options: amber, green and purple stay reserved for failure, write target and lens.

Preference between the two sides is carried by ORDER (the led option first) and by the fuller subtitle, never by a badge — see the warning-styling convention.

What this does not mean: it is not a general-purpose radio replacement for the web UI. Known limitation as of PR #193: the control is role=group with aria-pressed buttons, so it lacks radiogroup semantics (mutual exclusion announced as 1 of 2, arrow-key roving focus, a single tab stop). If that is fixed, fix it in the shared styles and both call sites together, or the two questions diverge again.

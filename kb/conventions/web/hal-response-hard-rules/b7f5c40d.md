# HAL response hard rules: compression, minimal embedded items, no body in collections

Three hard rules keep HAL+JSON response size bounded: (1) chi.middleware.Compress(5) is MANDATORY on the API router (not optional); (2) items embedded in collection responses carry ONLY a minimal summary of display fields plus a single _links.self — NO other links on embedded items; clients fetch self to get the full envelope; (3) the full fact envelope (with body) appears ONLY in GET /facts/{path...} responses; everywhere else (collections, embedded items) the body is OMITTED. With these rules: single fact ~1.3x current size; collection page of 50 summaries ~1.5x. Without them: 2-5x bloat. Errors use application/problem+json (RFC 9457) with no HAL links. Templated links (RFC 6570) for query-parameterised endpoints emit 'templated':true.

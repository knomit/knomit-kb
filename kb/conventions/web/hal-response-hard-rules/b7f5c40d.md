# HAL response hard rules: compression, minimal embedded items, no body in collections

Three hard rules keep HAL+JSON response size bounded: (1) compression is MANDATORY on the API router — but a `middleware.Compress(5)` line is NOT the rule being met, see below; (2) items embedded in collection responses carry ONLY a minimal summary of display fields plus a single _links.self — NO other links on embedded items; clients fetch self to get the full envelope; (3) the full fact envelope (with body) appears ONLY in GET /facts/{path...} responses; everywhere else (collections, embedded items) the body is OMITTED. With these rules: single fact ~1.3x current size; collection page of 50 summaries ~1.5x. Without them: 2-5x bloat. Errors use application/problem+json (RFC 9457) with no HAL links. Templated links (RFC 6570) for query-parameterised endpoints emit 'templated':true.

**RULE 1 WAS UNMET FROM THE DAY hal+json SHIPPED UNTIL PR #223 (dev aa37eb35, 2026-09-18).** `middleware.Compress(5)` with no types uses chi's built-in allowlist, which has `application/json` but not `application/hal+json` or `application/problem+json`, so every API response went out uncompressed while this fact and the code comment beside it ("mandatory per design spec §3 rule 6") both said compression was on. Since PR #223 the rule is enforced by construction: `compressibleTypes` in `internal/web/compress.go` is spelled from `hal.ContentType` and `hal.ProblemContentType`, `compressor()` is the only way the middleware is installed (API router and static group both), and `TestAPI_*`/`TestCompressor_*` in `internal/web/compress_test.go` assert `Content-Encoding: gzip` AND gunzip the body on hal+json, problem+json and application/yaml responses. **The test is the rule; the comment is not.** If you add a new response content type, add it to `compressibleTypes` and a test that asserts the encoding, or it will be silently uncompressed exactly as hal+json was. Never add `text/event-stream` or any `family/*` wildcard (guarded by `TestCompressibleTypes_CannotCoverSSE`). See kb/gotchas/web/http/chi-compress-allowlist/72631d2b.md.

NOTE ON NAMES: the live types are exported — `FactView` (internal/web/fact_view.go), `hal.CollectionView`, and `hal.Problem`. The unexported `factView` / `collectionView` / `problemView` this fact once listed do not exist.

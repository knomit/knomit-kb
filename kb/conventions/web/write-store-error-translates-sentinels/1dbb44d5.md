# httpx.WriteStoreError is the universal store-error→HTTP-status translator; web stays independent of git

httpx.WriteStoreError(w, r, err, defaultTitle, branch) in internal/edge/web/httpx/errors.go is the universal store-error to HTTP-status translator. Its cases, in the order the function tests them (verified at 585974c5):
1. storeUnavailable(err), that is repos.ErrStoreUnavailable (the populating refusal wraps it) or repos.ErrRepoClosed, the refusal RepoInstance.Acquire / WithRead gives when the store cannot be reached: 503 title "Repo not ready", FIXED detail "the repo's store is not available; try again" (writeStoreUnavailable; the detail is not err.Error() so the ref gate's wrapped chain is not leaked). Added by PR #618; see kb/decisions/web/rest-write-store-unavailable-503/5ce4cfbc.md. It is tested FIRST, so it wins over every case below.
2. model.ErrBranchNotFound: 404 "Branch not found", detail `no branch named "<branch>"`.
3. facts.ErrInvalidPath: 400 "Invalid path".
4. *facts.FactInvalidError (a write refused at the source by the ontology's validations): 422 "Fact fails the ontology's validations", the ontology's own message as detail.
5. index.ErrFactNotLive: 404 "Fact not found", detail mentioning that the fact may have been retracted (use the commit-anchored endpoint for older versions).
6. ANY other error: 500 with the caller-supplied defaultTitle and err.Error() as detail.

ALL store errors in handlers go through this, NEVER call hal.WriteProblem directly with a store error. A helper built on ri.WithRead must RETURN WithRead's error so this translator can see it; a helper that discards it turns an unreachable store into a zero-valued success (the web read helpers did until PR #620, see the historical kb/gotchas/web/read-helpers-drop-withread-error/88e05f43.md; since PR #620 they return it, and the deliberate exceptions are the SSE stream handleHALEvents and factVersionDate).

CRITICAL DESIGN RULE: the web layer is INDEPENDENT of git internals: no handler imports go-git's plumbing package. Add new sentinels at the store boundary (for example store.ErrXNotFound) rather than bleeding plumbing errors through. When adding a new sentinel: extend writeStoreError with the new case and pick a stable problem-title string.

READERS SHARE IT (PR #620, 1a860912): the read routes answer through this translator too. Routes that call WithRead directly call writeStoreUnavailable (changes, experiments list/open/actions, experiment diff, pushed branches, synthesis Pin, writeExperimentError), and writeLifecycleProblem answers repos.ErrNotOpen with it as well (in production ErrNotOpen is the Open stage not live, the state Acquire refuses with ErrStoreUnavailable). Lens fan-out routes fail whole through it.

DOES NOT MEAN: that writeStoreUnavailable is the only answer to an unreachable store anywhere. Exceptions: the lens single-fact route, its sub-resource gate and its `.knomit/` read hide it behind the missing-fact 404 on a READ mount only (lensFactMount.answersNotFound; the write mount answers the 503); the git smart-HTTP route answers text/plain 503 "repo store unavailable"; handleHALEvents and factVersionDate drop it on purpose. ErrClosed, ErrUnavailable and ErrManagerStopped through writeLifecycleProblem keep their own answers. See kb/decisions/web/read-store-unavailable-503/d5d606a6.md.

MOVED (12b, PR #622, merge commit 3e67923b on dev, re-read there): the helpers this fact calls writeStoreError, storeUnavailable, writeStoreUnavailable and writeLifecycleProblem are now the exported httpx.WriteStoreError, httpx.StoreUnavailable, httpx.WriteStoreUnavailable (internal/edge/web/httpx/errors.go) and httpx.WriteLifecycleProblem (internal/edge/web/httpx/lifecycle.go). Read every lowercase name in the text above as its httpx name. Behaviour is unchanged (case order, 503 "Repo not ready" with the fixed detail, 404 branch, 400 invalid path, 422 FactInvalidError, 404 ErrFactNotLive, else 500 with the caller's title). There is no forwarding alias in web: call sites say httpx.X, so a grep for the lowercase names in web finds nothing live. handlers_index.go keeps only handleCancelIndex. See kb/architecture/web/httpx/ for the package.

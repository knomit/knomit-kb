# writeStoreError is the universal store-error→HTTP-status translator; web stays independent of git

writeStoreError(w, r, err, defaultTitle, branch) in internal/edge/web/errors.go is the universal store-error to HTTP-status translator. Its cases, in the order the function tests them (verified at 585974c5):
1. storeUnavailable(err), that is repos.ErrStoreUnavailable (the populating refusal wraps it) or repos.ErrRepoClosed, the refusal RepoInstance.Acquire / WithRead gives when the store cannot be reached: 503 title "Repo not ready", FIXED detail "the repo's store is not available; try again" (writeStoreUnavailable; the detail is not err.Error() so the ref gate's wrapped chain is not leaked). Added by PR #618; see kb/decisions/web/rest-write-store-unavailable-503/5ce4cfbc.md. It is tested FIRST, so it wins over every case below.
2. model.ErrBranchNotFound: 404 "Branch not found", detail `no branch named "<branch>"`.
3. facts.ErrInvalidPath: 400 "Invalid path".
4. *facts.FactInvalidError (a write refused at the source by the ontology's validations): 422 "Fact fails the ontology's validations", the ontology's own message as detail.
5. index.ErrFactNotLive: 404 "Fact not found", detail mentioning that the fact may have been retracted (use the commit-anchored endpoint for older versions).
6. ANY other error: 500 with the caller-supplied defaultTitle and err.Error() as detail.

ALL store errors in handlers go through this, NEVER call hal.WriteProblem directly with a store error. A helper built on ri.WithRead must RETURN WithRead's error so this translator can see it; a helper that discards it turns an unreachable store into a zero-valued success (the web read helpers still do, see kb/gotchas/web/read-helpers-drop-withread-error/88e05f43.md).

CRITICAL DESIGN RULE: the web layer is INDEPENDENT of git internals: no handler imports go-git's plumbing package. Add new sentinels at the store boundary (for example store.ErrXNotFound) rather than bleeding plumbing errors through. When adding a new sentinel: extend writeStoreError with the new case and pick a stable problem-title string.

DOES NOT MEAN: that 503 "Repo not ready" is the only 503 the web layer gives for an unreachable store: several routes call WithRead directly and answer 503 "Store unavailable" with the raw error as detail.

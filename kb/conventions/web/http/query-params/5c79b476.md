# internal/edge/web/params.go is the ONLY place limit/offset/CSV params are parsed; out-of-range is a 400, never a silent clamp

All API query-parameter parsing lives in internal/edge/web/params.go: limitParam, offsetParam, splitCSV, selfWithQuery. Semantics, uniform across every endpoint as of P1.4 (2026-07-21): limit absent → 50; otherwise an integer in [1,500]; anything else — non-integer, zero, negative, OR ABOVE 500 — is an RFC 9457 400. offset absent → 0; otherwise non-negative; non-integer or negative is a 400.

**Why >500 is a 400 and not a cap.** Silently capping is the same silent-success failure the strict parsing exists to eliminate: a client that asked for 900 and received 500 rows cannot distinguish that from 'there were only 500 rows'. The ceiling is a contract, not a courtesy.

**Consequence for anyone adding a collection endpoint:** call limitParam/offsetParam, and return immediately when they report not-ok (they have already written the problem response; touching w again corrupts it). Do NOT hand-roll a parser — that is exactly how the six pre-P1.4 sites drifted into four incompatible behaviours.

**The bug this fixed, as a warning about clamping.** handlers_search_hal had no lower guard at all, so ?limit=-5 reached the store, whose `limit <= 0` clamp turns it into 100. A NEGATIVE limit returned MORE rows than the default. Two layers each doing a 'reasonable' silent clamp composed into nonsense; neither layer was wrong on its own.

**What this does NOT mean:** it is not a rule that all invalid input everywhere must 400. It is specifically about pagination bounds, where silently serving a different page size than requested is undetectable by the caller.

MOVED (12b, PR #622, merge commit 3e67923b on dev, re-read there): selfWithQuery is no longer in internal/edge/web/params.go; it is httpx.SelfWithQuery in internal/edge/web/httpx/params.go (the collection self-link helper). limitParam, offsetParam and splitCSV stay in internal/edge/web/params.go, so the rule that this file is the only place limit, offset and CSV params are parsed is unchanged.

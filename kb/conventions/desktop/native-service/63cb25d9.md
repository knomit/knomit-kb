# NativeService.SaveFileAs: the page supplies only a suggested name and the bytes; the destination comes from the native save dialog, so it needs no exports-dir confinement

WriteFile is safe to expose to any window only because it confines the name to <StateDir>/exports. SaveFileAs deliberately writes OUTSIDE it, to a path the user chose, and is still safe for the same reason in a different form: the binding never accepts a path. It takes a suggested name (reduced to its base name) and the contents, calls n.pickSavePath (wired in app.go to wapp.Dialog.SaveFile() attached to the main window, with the suggested filename), and writes only to what the dialog returns. Script injected into the UI can at most pop a save dialog the user can cancel. '' means cancelled (nothing written, no error); a dialog error is an error. The file is 0644 (it is the user's document, unlike WriteFile's owner-only fleet secrets). Do NOT widen it to take a path argument, and do not use it for trust material (the fleet root key stays on WriteFile). Tested with a stub pickSavePath in native_test.go; not exercised against a real Wails dialog.

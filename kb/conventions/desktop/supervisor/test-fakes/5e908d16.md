# To test 'another server answers while our child is alive', use the supervisor fake's exit3-on-eof mode, which holds the doomed child open until its stdin closes - not a linger sleep

CONVENTION (knomit#517, merge fe86cc9c). tools/desktop/supervisor_fake_test.go has two fake modes that exit 3 (the local listener is held by another live process). 'exit3' sleeps a fixed 300 ms and then exits 3: the window in which the child is alive while a stand-in holder answers lasts only that long. 'exit3-on-eof' prints the held-listener error, then blocks reading stdin and returns 3 only when the supervisor closes it (restartServer / terminate), so the child stays alive and never answers for as long as the test needs. Use exit3-on-eof for any test that must observe the supervisor while another server answers and our child is alive (TestSupervisor_HolderAnsweringBeforeExit3IsNotOwnedReady waits for a COUNT of 3 answered probes, asserts not-ready, then calls restartServer and asserts errAttachedServer naming the holder's pid, then attached+ready, one spawn, no backoff). No sleep decides the outcome; the test was 50/50 under -race.

RELATED RULE: every fake that is meant to become ready as our child must write server.json with its OWN pid after binding and before serving, as the real server does (the fake's ready path does, and removes it if it still owns it on exit). A stand-in holder writes a different pid (4242 in the test). A fake that writes no server.json, or the wrong pid, never becomes ready (see the owned-ready invariant in kb/invariants/desktop/supervisor/owned-ready).

MISREADING: do not treat the 300 ms linger of 'exit3' as what makes Exit3SwitchesToAttach pass; that test passes because its holder answers only once s.child == nil (kb/gotchas/desktop/supervisor/readiness-probe-meets-holder/d9b774ee.md).

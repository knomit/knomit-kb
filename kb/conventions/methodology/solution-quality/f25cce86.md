# Pre-release: rank by best end result, never by integration effort or 'drop-in'-ness

Knomit is pre-release / not yet shipped. When researching options or recommending solutions for this project, do NOT prioritize "quick wins", "drop-in" changes, or "minimum changes" — and do NOT rank/tier options by integration effort. Rank purely by which produces the BEST end result. Treat existing architecture as mutable when a better solution requires it: e.g. the hardcoded `factsVecDim = 768` const, the hand-rolled BERT-WordPiece-only `embeddings.Tokenizer`, and the in-process ONNX/model choices are all changeable, not constraints to design around. Pre-release means there is NO migration-cost penalty (the SQLite index is rebuildable from git anyway), so greenfield the right design rather than retrofitting. Stated and reinforced by the user 2026-06-04 ("we're still building this software, it was not released yet... Do NOT take 'quick wins' or 'minimum changes' as something that has priority"). This generalizes the user-wide best-over-fastest preference to a project-phase policy. Revisit once knomit ships and migration cost becomes real.

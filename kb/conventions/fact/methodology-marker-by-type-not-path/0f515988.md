# Methodology facts are identified by type='methodology', NOT by path

The kb/meta/reasoning/ path convention for methodology facts is a SOFT norm — not load-bearing for any retrieval or filter. The canonical marker is the schema-validated `type: methodology` field. Reasoning: paths can be renamed/moved; type is schema-enforced. Anyone writing code that 'gets methodology facts' MUST filter by type, never by path prefix — RelevantMethodologyForFact (internal/engine/store/index/methodology.go) selects candidates with `WHERE f.type = 'methodology'`, and the synthesize reinforce path (internal/corpus/synthesize/decision.go) validates the target fact's Type == methodology, not its path.

WHAT THIS DOES NOT MEAN: this does NOT mean the kb/meta/reasoning/ path is meaningless or safe to key on — code MUST NOT match methodology facts by path prefix (a methodology can live anywhere; the type is the only guarantee). Conversely, a fact under kb/meta/reasoning/ that is NOT type=methodology is not treated as one. Enforced at internal/engine/store/index/methodology.go (`WHERE f.type = 'methodology'`).

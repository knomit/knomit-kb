# Fact validation runs in BOTH ParseFact and SerializeFact for round-trip safety

validateKindAndType is called from both ParseFact AND SerializeFact — not just on read. Rationale: symmetry guarantees a Fact value that round-trips successfully has a valid (kind, type) pair, AND bad values cannot escape onto disk. SerializeFact gained validation it never had — callers that previously serialized facts with empty or invalid Type fields now receive an error. This is the intended outcome: silent serialization of malformed facts was a latent bug. Defaulting: kind=epistemic + missing type → type defaults to observation (preserves today's behavior). kind=pragmatic + missing type → error (no default).

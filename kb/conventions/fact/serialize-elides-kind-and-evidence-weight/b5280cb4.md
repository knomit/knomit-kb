# SerializeFact elides default fields (kind, evidence_weight, origin) for byte-identical round-trip

SerializeFact emits a frontmatter key ONLY when it diverges from the default, preserving BYTE-IDENTICAL round-trip for the pre-existing corpus:

- `kind` ONLY when Pragmatic — epistemic facts omit it entirely (preserves the entire pre-pragmatic corpus).
- `evidence_weight` ONLY when > 0 — facts that haven't been through synthesis (no computed weight) round-trip byte-identical to pre-evidence-weight files.
- `origin` ONLY when != authored (Plan 01) — authored facts, i.e. the ENTIRE pre-origin corpus, emit no origin line; only distilled/discovered facts carry it. See decisions/architecture/fact-model/origin-field.

Field emission order is FIXED: kind (if pragmatic) → type → domain → confidence → sources → evidence_weight (if > 0) → origin (if != authored) → entities → refs. Anti-pattern: reordering field emission 'for readability' — breaks byte-identical round-trip and pollutes git diffs for facts that were unchanged but happened to be re-serialized.

# Pass *repos.RepoInstance, NOT individual indices — RepoInstance bundles all repo deps

Operations that need multiple store indices (FactIndex, SearchIndex, PipelineIndex, BranchIndex, ToolSessionIndex) plus AgentBranch + Ontology + Embedder should take a SINGLE *repos.RepoInstance, not a long list of individual interfaces. Inside, extract what you need under ri.WithRead(func(svc *store.Service)). Example: synthesize.NewReviewer went from 7 params to 2 (ri, onProgress) (internal/synthesize/review.go:41); callers in web/ collapsed from ~15 lines of index extraction to a one-liner (internal/web/handlers_jobs.go). The RepoInstance.Embedder() accessor (internal/repos/instance.go:120) was added in this refactor to complete the dependency bundle.

WHY (load-bearing): passing individual extracted indices leaks store internals into upstream code AND breaks when SwapStore is called — the stale extracted index references would read from the now-closed DB. Bundling ri + extracting freshly under WithRead each call is what survives a swap.

WHAT THIS DOES NOT MEAN: NOT 'every function should take *repos.RepoInstance.' The rule targets operations that need MULTIPLE indices plus AgentBranch/Ontology/Embedder. A function needing exactly one index is fine taking that one interface — the goal is avoiding leaked store internals and surviving SwapStore, not a blanket 'always pass ri.' Anti-pattern: extracting indices in the caller and passing them as individual args.

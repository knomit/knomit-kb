# PRs merge into dev, so "Fixes #N" never auto-closes the issue; close and relabel by hand after merge

Feature and fix PRs in knomit/knomit target the dev branch, but GitHub's closing-keyword automation ("Fixes #N", "Closes #N") only fires when a PR merges into the repository's DEFAULT branch, which is master. So a PR that says "Fixes #324" and merges into dev leaves issue 324 OPEN and still carrying the "status: in-progress" label that was added at pickup. Consequence for a session closing out a PR: after the merge, explicitly (1) remove "status: in-progress" and add "status: implemented", and (2) close the issue with a comment naming the PR and the dev merge commit. Do this in the same close-out step as committing the knomit experiment and posting the fact-listing comment; the issue is not done until the label and state say so. Misreading to avoid: this does NOT mean the keyword is useless — it still links the PR to the issue in the sidebar, and it WILL auto-close later if the issue is still open when dev is merged into master. It only means nobody should rely on it for the dev merge. Observed on #324 / PR #329 (merged into dev at 15f5c9af on 2026-09-27; issue stayed open and in-progress until closed manually).

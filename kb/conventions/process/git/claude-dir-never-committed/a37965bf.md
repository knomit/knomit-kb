# Nothing under .claude/ except .claude/skills/ and .claude/settings.json is ever committed — plans and worker reports never go into a branch or PR, and `git add -f` on .claude/ is forbidden

`.gitignore` ignores `.claude/*` and re-includes only `!.claude/skills/` and `!.claude/settings.json`. Plans, worker reports, session logs and commit-message drafts under `.claude/plans/` are deliberately local working files of the person, not repo content.

Consequences:
- Never `git add -f` (or `git add --force`) any path under `.claude/` other than skills/ and settings.json.
- A brief must never ask a worker to put a report in `.claude/plans/` "in the branch" or "committed". Name where it goes instead: the master session's scratchpad, or the MAIN checkout's `.claude/plans/` by absolute path. A worktree-isolated worker that writes a gitignored file inside its own worktree loses it when the worktree is auto-removed (kb/gotchas/integrations/claude-code/subagents/worktree-auto-removal/b2b85c5b.md), and that loss is the pressure that tempts a force-add.
- Reviewers gate on `git diff --stat origin/dev...HEAD -- .claude` printing only skills/ or settings.json changes, and `git ls-files .claude/plans` printing nothing.

Incident: PR #508 (makefile targets) and PR #510 (desktop settings sidebar) both carried force-added `.claude/plans/2026-10-13-*-worker-report.md` files, because the master's brief said "put a worker report in .claude/plans/ in the branch". The user had excluded the directory on purpose.

WHAT THIS DOES NOT MEAN: it does not mean worker reports are unwanted. They are wanted, just not in git. The project CLAUDE.md line "Commit messages and session logs go in .claude/plans/" is about where to write the files on disk, not a licence to commit them.

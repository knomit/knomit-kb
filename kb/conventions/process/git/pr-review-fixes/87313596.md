# Review fixes on a pushed PR go on as new commits; never rewrite pushed commits (rebase + force-push) just so each intermediate commit passes tests

Decided by the user (2026-11-09, PR #814): when a review finds problems in a PR whose commits are already on GitHub, the fixes are added as ordinary new commits on top and pushed with a plain fast-forward push. Do not reorder, squash or edit pushed commits and force-push so that every intermediate commit builds and passes tests by itself. The user judged per-commit test cleanliness not worth a history rewrite, and auto mode blocks force-pushes anyway. Whether to squash at merge time is the user's call.

Consequences:
- When a reviewer flags a red intermediate commit, drop that finding, or at most mention squash-merge as an option.
- Before proposing any fix, say plainly whether it needs a destructive git action (force-push, history rewrite).
- Explain git terms in plain words when talking to the user.

What this does NOT mean:
- Commits on a local, never-pushed branch may still be tidied before the first push.
- A red final PR head is still not acceptable. The whole PR must pass.

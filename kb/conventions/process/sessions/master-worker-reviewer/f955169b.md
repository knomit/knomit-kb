# Three-session protocol on the Windows dev box: the MASTER session (Fable) writes NO code, not even a one-line fix; it briefs the WORKER session for every code change, briefs the REVIEWER for every PR, verifies claims against code and CI, owns PRs, merges, tickets and the knomit experiments; tickets get `status: in-progress` plus an agent-id comment at pickup and an RCA with a proposal before any code change

**The protocol (stated by the owner on 2026-09-25 and again, emphatically, on 2026-09-26).** Three peer Claude sessions run on this machine: `master` (Fable 5.1, the expensive budget), `worker` (Opus 5.5) and `reviewer`. Roles: the master scopes, recalls from knomit, writes the RCA and proposal, dispatches; the worker makes every code change in its own git worktree under its scratchpad and pushes branches; the reviewer reviews read-only and reports findings CONFIRMED/PLAUSIBLE with file:line; the master reads the diff, opens the PR, dispatches review, merges on green, closes the ticket, and owns the knomit experiment named after the branch. The master does not edit source, tests or workflow files itself, because Fable tokens are what the owner is protecting: 'DO NOT SPEND MY FABLE TOKENS in this session to write code'.

**Ticket etiquette.** At pickup: label `status: in-progress` (created 2026-09-25; the repo's other status labels are draft/proposed/accepted/implemented/rejected) and comment with the knomit agent id (`DESKTOP-DESE6AF-b3545310` for this box's master). Before any code: post the RCA and proposal and wait for the go-ahead. At close: swap the label to `status: implemented`, close with a comment naming the merge commit (PR bases are `dev`, so GitHub never auto-closes), and list the knomit facts on the PR.

**Briefs.** A worker brief names the branch, base, files, the exact change, the verification command (foreground, one at a time on this 8 GB box; see kb/conventions/testing/dev-box-limits), the commit message, and asks for the hash back. A reviewer brief names the PR, the commits, what to check, and asks for a verdict. Each session's commit trailer names ITS OWN model (the worker's says Opus 5.5); that is correct attribution, not a deviation.

**Misreading to avoid.** 'It is a two-line change' is not an exception; the point is where the tokens are spent, not the size of the diff. Reading code, logs and diffs in the master to VERIFY is fine and expected.

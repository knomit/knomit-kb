# Deps.DisableBackgroundSync is a test-only flag; production never sets it

Deps.DisableBackgroundSync bool suppresses the background pull and push loops that would otherwise run on every managed repo. Used ONLY by tests to prevent non-deterministic sync/push behavior — the loops call doSync/doPush immediately on startup which can race with test assertions about remote state. Production NEVER sets this flag. When set, startSyncLoops is a no-op; manual reconcile via ri.ActivateSync (which always runs one synchronous reconcile regardless of the flag) or SwapStore still works for tests that need to drive sync explicitly. Anti-pattern: setting DisableBackgroundSync in production to 'silence' a noisy log line — the right fix is to address the underlying sync failure.

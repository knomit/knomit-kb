# indexHealGate holds the index heal for tests — nil in production, and it MUST wait on indexCtx or every teardown deadlocks

`internal/repos/index_heal_gate.go` parks the background index heal at one point — after `ri.markIndexing()`, before `healIndexBranches` — so a test can observe the `indexing` state instead of racing it. `Manager.healGate` is an `atomic.Pointer` written only by `setIndexHealGate`, which has NO production caller, and `hold` returns immediately on a nil receiver. The production path is the old path plus one nil pointer load.

THE indexCtx ARM IS LOAD-BEARING, not defensive coding. `hold` selects on `ctx.Done()` as well as its release channel, and the ctx passed is `b.indexCtx`. Every teardown path — `Manager.Close`, `Archive`→`shutdown`, `SwapStore` — cancels `indexCtx` and THEN `indexWg.Wait()`s before closing the SQLite handle. A gate waiting only on release would hang all three, forever, whenever a test returned with the gate still shut — and hang them with no assertion naming the cause. `TestManagerClose_DrainsAHealHeldAtTheTestGate` is the fixture for this and fails in exactly that way when the arm is removed.

This does NOT weaken the invariant from the clone-create incident that the heal runs on the MANAGER's context and never the create's. The gate takes that context as a parameter, so it is a consumer of the contract rather than a way around it.

ANTI-PATTERN THIS REPLACES: the two create tests previously asserted "the create reported an index phase" and hoped. Both claimed determinism in their comments ("pins it DETERMINISTICALLY … no measurement, no flake") and neither had it.

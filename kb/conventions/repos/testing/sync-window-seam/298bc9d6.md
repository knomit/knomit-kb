# Testing the push countdown: hold the syncHooks.window seam on a fake clock and COUNT its opens — an auto-releasing seam cannot tell a fixed countdown from a debounce; count ticks with a failing resolveAuth, or syncHooks.tick for loops the test did not start

sync.go has mutex-guarded test seams (nil in production): window func(d) <-chan time.Time replaces time.After for the push countdown, and tick func(ctx, repo) runs at the top of each runReconcileLoop tick and before each local-loop advance. triggerHooks.flushGrace (non-zero) replaces the 20 ms phase-C flush grace, so a long value keeps the write-behind buffer pending and makes overlayPending the only thing stopping a re-fire.

Pattern (triggers_push_test.go): the window seam records each open and its requested duration, and returns a channel; a fake clock gives each open a deadline t+d and advanceTo releases exactly the windows now due. The burst test fires at fake 0/400/900 ms, asserts ONE open with d = 1 s, nothing at 999 ms and exactly one tick at 1000 ms. A debounce sabotage opens a second window and ticks nothing at 1000 ms; with an auto-release seam both versions tick once and the test cannot fail. Negative 'stays at N' checks sleep a quiet period and assert BOTH the tick count and the open count unchanged (any wake that would become a tick must first open a window).

Tick counting: drive runReconcileLoop directly against example.invalid with a resolveAuth that counts and fails (every doTick calls it exactly once) and can park the Nth tick on a gate; for ActivateSync's or startSyncLoops' loops, whose auth cannot be wrapped, use syncHooks.tick (it may park on ctx.Done so a restart can cancel it).

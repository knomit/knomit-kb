# resolveOriginUpstream falls back to 'main' but emits WARN — silent default hides misconfig

repoBuilder.resolveOriginUpstream(auth) queries the configured origin's symbolic HEAD via store.DetectRemoteUpstreamFromURL. On detection failure (bad auth, unreachable URL, no symbolic HEAD on remote), it falls back to 'main' BUT emits a log.Warn FIRST naming the repo + origin and noting that the operator should check auth/connectivity if the remote uses a different default. WHY warn: silently picking 'main' for a 'master'-default repo creates a configuration mismatch that surfaces much later when origin/main forever appears empty (operator sees no sync activity but no error either). Anti-pattern: silently defaulting without warning — the misconfiguration is invisible until the user notices empty sync results. The captured upstream is later passed to ensureBranch (for SetRemote) and setupIndex (for sync).

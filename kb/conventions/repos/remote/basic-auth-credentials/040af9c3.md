# Basic auth credentials travel as 'user:password' in the single auth_token field, split on the first colon

There is one auth_token field/column for all auth methods. For auth_method=="basic" it carries credentials packed as "user:password", split on the FIRST colon (strings.Cut / strings.SplitN(...,2)) so a password may itself contain colons. Producers and consumers must all agree on this format:
- assembleAuthToken(method,token,user,password) packs user+":"+password for basic (the RemoteConnectWizard path, which collects user/password as separate fields).
- remoteAuthFromRecord splits a persisted basic auth_token back into User/Password.
- authConfigFromSpec splits it for the IMMEDIATE clone on repo-create (added in PR #87; before that it set Password=token with an empty Username, so basic clone-on-create always failed — real hosts reject an empty username). token auth is unaffected: resolveAuth defaults Username to "x-token".

Consequence for UIs: any form offering basic auth MUST collect a username. CreateRepoForm has a dedicated Username field for basic and BLOCKS submit (disabled button + hint) until it is filled, so it can never ship a colon-less token the backend would read as an empty-username credential. A username containing ':' would corrupt the split — acceptable since git-hosting usernames don't contain colons.

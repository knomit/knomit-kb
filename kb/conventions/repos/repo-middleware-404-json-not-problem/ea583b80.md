# RepoMiddleware returns plain JSON 404 — the one non-problem+json error in the API (predates HAL)

RepoMiddleware(m).ServeHTTP returns a plain application/json body {'error':'repository not found: <name>'} with status 404 when the repo isn't registered — NOT a problem+json. This predates the HAL redesign and is the ONE remaining non-problem+json error path in the API. Migrating to problem+json requires importing internal/web/hal from internal/repos, which would create a cycle (internal/web depends on internal/repos via the types Server uses). The pragmatic fix: keep the JSON shape in repos and have the web layer wrap/transcode if it ever matters. Anti-pattern: importing internal/web/hal here to 'fix' the inconsistency — see repos/package-extraction rationale for the cycle constraint. Future option: define a tiny problem+json type in internal/repos that internal/web/hal can interop with by structural assignment.

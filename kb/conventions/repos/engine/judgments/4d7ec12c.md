# Every engine judgment is ONE knomit.model call with a named closed schema whose `reasoning` property is sent FIRST and additionalProperties false; a thrown call is recorded as `failed:` and never ends the run as an error — a failed choice, draft or assessment reads as its safe default, but a failed relevance or support judgment leaves its facts UNJUDGED, which blocks EMIT until a retry succeeds or the run ends in a gap naming them

Judgments and their schemas (schemaOf in engine_reason.js): relevant {labels:[{fact, yes|no}]}, support {verdicts:[{fact, supports|contradicts|restates|unrelated}]}, choose_move and backtrack_choice {choice 0..n}, synthesize {claim, consequence, misreading, carriers}, carry (modes M2/M4/MF) {labels:[{fact, relevant, verdict}], moves}, assess {answers|partly|not, missing}, hypothesize {claim, settlement, observable}, seek {search}; each with reasoning (maxLength 1200) first. The script passes `name`, which the host sends as response_format.json_schema.name (validated [a-z0-9_]{1,64}), and marshalReasoningFirst writes the top-level properties with reasoning first — Go sorts map keys, which would make a schema-to-grammar server emit e.g. `claim` before the reasoning.

One verdict per fact (fix-later 3): judgeRelevance and judgeSupport keep the FIRST verdict a reply gives an index and ignore later ones; support state is keyed by path, so a fact can never count twice in the posterior or the answer's sources (TestEngineOracle_DuplicateVerdictsDeduped).

Failures: judge() catches the host's throw (truncated, off-schema, unreachable, a recovered Go panic), records {judgment, verdict: 'failed: …'} and returns null. A failed choose falls back to the top-ranked entry, synthesize to no claim, assess to `not`, hypothesize to a harness-built one. A failed RELEVANCE batch leaves its facts labelled `no` for exploration but records them in st.unjudged (for every role except open/excluded/history); a failed SUPPORT batch leaves its facts with no verdict (neither for nor against) and records them too. A later successful judgment of the fact clears it. EMIT will not write while unjudgedLive() is non-empty: it re-judges them (MAX_REJUDGE = 1 round: relevance, then support for what is now relevant evidence), re-drafts from SYNTHESIZE, and if any is still unjudged the run ends in a gap whose ReasonGap.Unjudged lists them and whose hypothesis body names them. DECIDE's gaps carry the list too. A deadline/cancel error is rethrown so the run ends `interrupted`.

Why not 'safe default = unrelated' (review blocker B4, chosen 2026-10-12 over capping the posterior at the trust bar minus epsilon): the weakest-link posterior is non-monotone — dropping a contradiction or the weakest support can only RAISE it — so reading a failure as unrelated turned gaps into answers (one 0.9 support vs a failed C = 1.8 batch answered at 0.9 instead of 0.3; supports 0.9 + 0.4 with the 0.4 batch failed answered at 0.9 instead of 0.4). Blocking with a retry gives the better end result: a transient failure recovers the true verdict and the true posterior (pinned: the retried 0.8 support is the weakest link, posterior 0.8 not 0.9), a persistent one yields a gap that says exactly which facts are unknown, and the reported posterior is never a fabricated cap. Pinned by TestEngineBlocker_B4_FailedJudgmentNeverAnswers (both crossing cases, plus a failed relevance batch) and TestEngineOracle_ModelThrowMidAssessYieldsGap.

Misreading to avoid: 'a failed judgment never ends the run as an error' does NOT mean a failed judgment is harmless to the outcome — a failed relevance or support judgment on a fact that could matter prevents an answer unless the retry succeeds. And E07 §3's grammar-after-reasoning-block (R3) is NOT done here; the reasoning field is a schema field, not the model's think segment.

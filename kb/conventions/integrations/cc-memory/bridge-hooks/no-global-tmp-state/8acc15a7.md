# Bridge hooks MUST NOT carry global tmp-file state across subprocess invocations

Each `knomit-bridge claude hook <event>` is spawned by CC as a FRESH subprocess for every event (current events: session-start, post-edit, post-ask, pre-compact — the Stop hook was later removed entirely; see hook.go's event switch). There is NO in-process state that persists across invocations — package-level vars reset on each spawn. Do NOT bridge that gap with /tmp counter files (or any other process-shared file/lock) to gate hook firing, rate-limit emits, or coordinate behavior. The intent matcher in tools/bridge/claude/intents.go already gates emits to substantive moments — turns without a regex hit emit nothing, and `seen` dedup within a single invocation prevents duplicate-quote spam. That IS the rate control.

History (archival — the files named here no longer exist): PR #66 originally shipped rateLimitFire() in a since-deleted hook_stop.go writing /tmp/knomit-stop-rate to fire 1-in-5 turns. Removed in 828b176 after the user asked three times; the PR description had even claimed the counter was removed when it wasn't — proof this smell is easy to miss in review. The Stop hook itself was subsequently dropped from the bridge.

Why global tmp files are the wrong tool: (1) collide across concurrent CC sessions in different projects (one counter shared machine-wide); (2) hide the real rate signal (matcher precision) behind a redundant guard; (3) leak world-writable state into /tmp on shared dev hosts; (4) make hook tests require setup/teardown of an external file. If genuine cross-invocation persistence is ever required (rare), put it under the agent branch in the knomit repo, not /tmp.

WHAT THIS DOES NOT MEAN: this is NOT about the Stop hook specifically (it's gone) — the no-process-shared-state rule applies to EVERY current hook subprocess (session-start / post-edit / post-ask / pre-compact). Do not dismiss the policy because hook_stop.go is missing.

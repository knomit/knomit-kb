# knomit skills use 'knomit-' prefix and CC's per-skill-directory layout

All skills in the knomit-CC integration use a 'knomit-' prefix to avoid clashing with built-in Claude Code skills like /review. Current skill set in tools/bridge/claude/templates/skills/ — ELEVEN skills (grew 6 -> 9 -> 10 -> 11): /knomit-bootstrap (formerly /knomit-kickoff-area), /knomit-decided, /knomit-harden, /knomit-hypothesize, /knomit-principle, /knomit-recall, /knomit-remember, /knomit-retract, /knomit-review, /knomit-update, /knomit-why. (/knomit-harden is the most recent addition — periodic adversarial corpus audit.) They live at .claude/skills/<name>/SKILL.md — CC requires the per-skill-directory layout, not flat .md files. Project-scoped (the project's .claude/skills/, not the user's ~/.claude/skills/) so contributors inherit the integration by checking out the repo. Skills are deployed by `knomit-bridge claude init` from embedded templates (//go:embed all:templates in tools/bridge/claude/init.go; init.go treats .claude/skills/** as owned files, always overwritten) — never edit .claude/skills/ directly.

WHAT THIS DOES NOT MEAN: the count is NOT frozen at ten (or eleven) — verify against the templates dir, not this list. The enumerated set is a snapshot; a skill absent from this list (as /knomit-harden was) is not necessarily foreign or stale.

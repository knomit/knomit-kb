# knomit skills use 'knomit-' prefix and CC's per-skill-directory layout

All skills in the knomit-CC integration use a 'knomit-' prefix to avoid clashing with built-in Claude Code skills like /review. Current skill set in tools/bridge/claude/templates/skills/ — TEN skills (was nine, then six in the original integration): /knomit-bootstrap (formerly /knomit-kickoff-area), /knomit-decided, /knomit-hypothesize, /knomit-principle, /knomit-recall, /knomit-remember, /knomit-retract, /knomit-review, /knomit-update, /knomit-why. (/knomit-principle is the most recent addition — user-invoked only; agents must not author principles.) They live at .claude/skills/<name>/SKILL.md — CC requires the per-skill-directory layout, not flat .md files. Project-scoped (lives in the project's .claude/skills/, not the user's ~/.claude/skills/) so contributors inherit the integration by checking out the repo. Skills are deployed by `knomit-bridge init` from embedded templates — never edit .claude/skills/ directly (see [[skills-deployment]]).

# knomit_query elides the kind field when it equals epistemic (the default)

The knomit_query response includes a kind field on each result fact, BUT elides it when it equals the default kind (fact.DefaultKind == fact.Epistemic). The output struct has 'Kind string `json:"kind,omitempty"`' and the code sets kind = '' when 'fact.Kind(kind) == fact.DefaultKind', so json:omitempty drops it. This mirrors fact.Fact.MarshalJSON elision so the on-the-wire shape matches what fact files look like on disk: epistemic facts omit kind, pragmatic facts include it explicitly. Same applies to any future API surface returning facts — keep symmetry with the file format. Anti-pattern: emitting `kind: epistemic` on every result — bloats the response and breaks symmetry with the file format and with fact.Fact's JSON round-trip.

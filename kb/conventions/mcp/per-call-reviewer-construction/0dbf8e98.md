# ReviewHandler constructs a fresh synthesize.Reviewer per call; logProgress is the universal sink

ReviewHandler constructs a FRESH Reviewer PER CALL — never caches one between calls. This honors the Reviewer-is-stateless contract from the synthesize layer (see synthesize/per-call-objects-no-session-state): any per-session cache on Reviewer would lose state across calls because the MCP handler doesn't memoize.

The constructor is now synthesize.NewReviewerWithOptions(ri, logProgress, effort, scope) (Plan 03). NewReviewer(ri, logProgress) still exists as a thin wrapper defaulting to effort=normal + empty scope — byte-identical to the pre-discovery path. ReviewHandler parses the new `effort` (normal|medium|high, validated; default resolved via ri.DiscoveryEffortDefault()) and `domain`/`entities` (-> ScopeFilter) arguments and threads them in. knomit_hypothesize parses the same three args and passes them down its own start path.

logProgress (defined in review.go) remains the universal progress sink for synthesize.ProgressEvent: 'warn' phases (validation rejections, normalize/validate failures, and discovery gate rejections) log at WARN; everything else at DEBUG to keep server logs usable during long sessions. Same pattern for any future per-call orchestrator wrapper: construct fresh inside the handler, pass logProgress for the onProgress callback.

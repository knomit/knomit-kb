# Tool descriptions are PROMPT ENGINEERING for the calling agent, NOT human docs

Tool descriptions in MCP are NOT user-facing docs — they are PROMPT ENGINEERING for the calling agent. Knomit tool descriptions are prose that includes: (1) what the tool does; (2) when to use it; (3) when NOT to use it; (4) explicit boundaries with other tools. Examples: knomit_hypothesize says 'Do NOT invoke as a follow-up to knomit_review or other maintenance tools without an explicit user request'. knomit_review says 'When a user asks for a review, they want only this tool; do not chain to knomit_hypothesize unless the user explicitly requests hypothesis generation'. knomit_explore notes 'Use knomit_explain for history on individual facts'. Anti-pattern: writing a one-line 'Reviews the KB' description — the agent will chain it incorrectly. Treat the description field as a prompt that runs on every tool-call decision, not as metadata.

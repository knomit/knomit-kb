# knomit_query's list of accepted filters is one constant, queryFilterList, used by both the tool description and the no-filter error

The two hand-kept filter lists (tool description and the "at least one filter is required" error) had drifted from hasAnyFilter: motifs, context, expired and expires_before/after were missing. Both now interpolate the single constant queryFilterList (internal/edge/mcp/query.go).

TestQueryFilterList_EveryNameIsAFilter checks every listed name both ways: it is a declared argument, and it satisfies hasAnyFilter on its own; and every value the test sets is listed.

Rule: when adding a selecting filter to hasAnyFilter, add its name to queryFilterList and give it a value in that test; do not write a second list in prose.

WHAT THIS DOES NOT MEAN: sort, limit, include_body, cursor, domain_exact and min_similarity are not selecting filters and are not in the list. Several `domain` values are ANDed (a fact must match every one), and the domain description now says so.

# extractJSON strips <think> blocks AND code fences; flexStrings accepts string OR array

extractJSON(text) (types.go) is the unifying preprocessor for ALL three LLM response parsers (parsePruneResponse, parseDistillResponse, parseReflectResponse). It (1) trims whitespace; (2) strips <think>...</think> blocks (used by small reasoning models like deepseek-r1 for chain-of-thought — they emit it inline before the JSON); (3) strips ``` or ```json code fences. Always call it BEFORE json.Unmarshal — raw LLM output WILL contain these in practice. Companion type flexStrings accepts either a JSON string ('x') OR array (['x','y']) on Unmarshal — small LLMs sometimes return a bare string where an array is expected. Used on mergedFact.Domain/Entities/Refs, distillFact.Domain/Entities/Refs, ProposeEntry.Domain/Entities/Refs. Anti-pattern: adding a fourth parser without piping through extractJSON — you'll get json.Unmarshal failures on the first deepseek-style response.

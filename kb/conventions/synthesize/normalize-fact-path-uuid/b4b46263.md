# LLM-emitted fact paths flow through normalizeFactPath (8-char UUID filename) + validateOutputPath/Type

All LLM-emitted fact paths in synthesize (merged facts from prune, synthesized facts from distill) flow through normalizeFactPath(path) which REPLACES the filename with an 8-char UUID, matching the convention used by knomit_learn. Example: 'kb/security/chrome-extension-threat-surface-2026.md' → 'kb/security/<uuid>.md'. WHY: prevents LLM-generated filenames from clashing with each other or with learn-generated facts; keeps the path-uniqueness invariant (one fact per path). Directory case is normalized separately by fact.NewFact (lowercases the full path unconditionally). Companion guards in decision.go: validateOutputPath rejects paths outside ontologyRoot (case-insensitive prefix check); validateOutputType rejects empty/invalid epistemic type — empty type historically slipped to disk and was masked by Upsert's `default 'observation'` on the SQL column, hiding the bug for months. Anti-pattern: writing an LLM-emitted path directly to gs.WriteFact without going through both normalize+validate.

# Cluster + dedup searches use errgroup with limit 8; goroutines swallow search errors

Both ScopedCluster (neighbor lookup per seed) and dedupCluster (pair discovery) dispatch idx.Search calls concurrently via errgroup.WithContext + g.SetLimit(8). Constants: maxConcurrentNeighborSearches = 8 (cluster.go), maxConcurrentDedupSearches = 8 (dedup.go). Rationale: each search is I/O-bound (vector query + optional embedding) so a small worker pool keeps wall-clock time low without overwhelming the search backend. ERROR TOLERANCE: goroutines that fail their search swallow the error (log.Debug + skip), matching the serial behavior — a partial neighbor set is better than aborting the whole cluster. A single mutex protects shared maps (subgraph, factByPath). Goroutines never return errors so g.Wait() is effectively a barrier. Anti-pattern: raising g.SetLimit too high — contention on the search backend dominates wall-clock at high concurrency.

# The desktop bundle carries the ONE `knomit` that `make server` produced, copied not recompiled: `desktop` depends on `server` (`build` is its alias), the targets copy `$(DIST)/knomit`, and a second `go build` of the server for the bundle is forbidden

Since desktop PR 4 (#500, merge 5ee881bc) the desktop targets reuse a single server compile; since PR #508 (merge 7cae543c) the target is named `server` and the Makefile reads `desktop: server desktop-ui`. `server` is the former `build` recipe (web UI, native libs, then `knomit`, `kb`, `knomit-okf` into `$(DIST)`); `build: server` is kept as a compatibility alias. The server is compiled exactly once, by `server` (`go build ... -o $(DIST)/knomit .`); the desktop targets compile only `knomit-desktop`, `kb` and `knomit-okf`. `dist: server desktop` therefore compiles the server once too, not twice (see kb/conventions/build/dist-end-to-end/ for the target layout). Placement: macOS `desktop-app-macos` runs `cp $(DIST)/knomit $(APP)/Contents/MacOS/knomit`, guarded by `test -x $(DIST)/knomit`; the AppImage copies `$(DIST)/knomit` to `usr/bin/knomit`; Windows/Linux standalone `desktop` asserts `test -f $(DIST)/knomit$(EXE)` and the binary stays beside `knomit-desktop` and `lib/` (the layout in kb/gotchas/desktop/windows/build/fcffd02b).

On macOS the copy is re-signed with the desktop's flags, so the bundle's bytes differ from `dist/knomit` ONLY in the signature; `knomit version` of both and `knomit-desktop --version` print the same build string.

**Consequence:** never add a second `go build .` of the server to a desktop target, and never give `dist` its own server compile. Two compiles can embed different version strings or tags and let the bundled server drift from the tarball server; the version cross-check in tools/desktop/serverbin.go exists to catch exactly that skew.

**What this does NOT mean:** the desktop binary has NOT stopped linking the server in-process; until desktop PR 5 it still boots its own server. The shipped `knomit` is not yet launched by the desktop. Nor does it mean `make desktop` can skip `server`: running a desktop target with `dist/knomit` absent fails with a message telling you to run `make server` (or `make desktop`). `make build` still works but is only an alias; new docs and scripts say `make server`.

# branchCommitsJoin(0) returns empty join + '1=1' tautology so callers concatenate unconditionally

branchCommitsJoin(branchID) returns three strings + args: when branchID==0, returns ('', '1=1', nil) so callers can unconditionally concatenate '... <join> WHERE <where> AND <other_conds>'. When branchID > 0, returns ('JOIN branch_commits bc ON bc.commit_hash = cl.commit_hash', 'bc.branch_id = ?', []any{branchID}) (commitlog.go). It has exactly TWO callers: CommitLogQuery (commitlog.go) and CommitLogActivity (commitlog.go). The tautology + empty-join lets both share one code path instead of separate 'with branch' / 'without branch' variants. Same idiom as commitLogPathCond for path filtering.

WHAT THIS DOES NOT MEAN:
- It is NOT used by a method called CommitLogWalkChanged — no such method exists (grep of internal/ finds zero matches; the Storer commit-log methods are CommitLogAvailable / Sync / Query / FileCounts / Activity). The two real consumers are CommitLogQuery and CommitLogActivity (two, not three).
- branchID==0 is not a normal-operation code path: the code comments 'branchID == 0 means no branch filter (not used in normal operation)'.

Anti-pattern: introducing an if branchID == 0 { ... } else { ... } per query — the tautology branch keeps the common case clean.

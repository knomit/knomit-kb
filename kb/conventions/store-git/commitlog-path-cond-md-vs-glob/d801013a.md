# commitLogPathCond: empty→1=1, .md→exact match, otherwise GLOB subtree

commitLogPathCond(path) returns three SQL fragment shapes: empty path -> '1=1' (no filter); path ending in .md -> 'path = ?' (exact match for a single fact); other path -> 'path GLOB ?/*' (subtree match) (commitlog.go). GLOB (not LIKE) is case-sensitive, simpler, and index-friendly via commit_log_path_time (repo/000001_schema.up.sql). commitLogPathCondPrefixed(path, 'cl.') adds the table alias when commit_log is joined with branch_commits. In practice ONLY the prefixed form is called — by CommitLogQuery and CommitLogActivity (commitlog.go); the bare commitLogPathCond wrapper currently has no callers.

WHAT THIS DOES NOT MEAN:
- It is NOT shared by a method called CommitLogWalkChanged — no such method exists in internal/. The real consumers are CommitLogQuery and CommitLogActivity (two, not three).
- Editing the unprefixed commitLogPathCond does NOT change query behavior — it is dead code; edit commitLogPathCondPrefixed (its callee) to affect both real queries.

Anti-pattern: rolling your own path filter inline — would diverge from the exact-vs-subtree behavior and lose the .md disambiguation.

# SetEncodedObject rejects delta objects — knomit stores every object FULL

Storer.SetEncodedObject rejects plumbing.REFDeltaObject and plumbing.OFSDeltaObject with 'storegit: delta objects not supported'. The store keeps every object FULL — no pack-file delta chains. Why: SQLite over a content-addressed object table doesn't gain from delta encoding (storage cost is small; resolution complexity is large). go-git's smart-fetch path would normally write deltas during pack-file decompression, but our flow always materializes objects via plumbing.MemoryObject (the constructor result of NewEncodedObject) before SetEncodedObject sees them. Anti-pattern: enabling a code path that passes delta objects to SetEncodedObject — would error at write time; you'd need to wrap with object.DecodeObject upstream to resolve deltas before they reach the storer.

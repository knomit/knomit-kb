# Do not add a new top-level package directory under internal/, tools/, cmd/ or the repo root: put new code into the existing package that owns the concern, and name the owner in the PR

RULE (user ruling, knomit#493 fix round 2, 2026-10-12): a change does not create a new directory for a package under internal/, tools/, cmd/ or the repository root. The code goes into the existing package that already owns the concern.

OCCASION: #493 first landed the listener set as internal/serve and the server.json code as internal/lockfile. Both were removed before merge: the listener set went into internal/app/listeners.go (it extends OpenTLSServer, checkLocalListener and IsAddrInUse already there, and needs OpenTLSServer, which internal/auth cannot import); the server.json code went into internal/serveraddr/lockfile.go (the file is a server's address advertised, serveraddr is 'the ONE spelling of a server's address', and the code is stdlib-only, with no import cycle either way). Names were prefixed to avoid clashes (LockInfo, WriteLock, ReadLock, RemoveLock, RemoveLockIfOwner, ErrLockCorrupt; OpenListeners, ListenerOptions). Behaviour and tests were unchanged by the move.

HOW TO APPLY: before creating a directory, find the package that owns the nearest existing concept, check the import graph for a cycle (go list / go build), and rename to avoid collisions. If no package can host it without a cycle, stop and ask - do not create the directory as the fallback.

NOT MEANT: it does not forbid sub-packages that already have a parent convention (for example a new file or an internal/ subfolder within tools/desktop/internal/ for that tool), and it does not forbid splitting a file; it forbids a NEW directory at the top level of those four roots. A reviewer checks `git diff --name-status` for added directories.

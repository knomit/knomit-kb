# Bytes that enter a cached prompt prefix go through llm.CanonicalJSON: decode with UseNumber, re-encode with encoding/json (which sorts map keys) and SetEscapeHTML(false)

Go map iteration is random, so JSON marshalled from a map without a canonical step can differ between runs. llm.CanonicalJSON (internal/engine/llm/canonical.go) decodes into any with UseNumber (numbers keep their literal spelling: 1.50 stays 1.50, a 20-digit integer is not rounded through float64), re-encodes through encoding/json, whose map-key sorting IS the canonicalisation, turns HTML escaping off ("<" stays "<") and drops the trailing newline. mcp.LoadPrefix canonicalizes every tool's inputSchema with it, and Snapshot.CanonicalPrefix encodes with the same encoder settings.

CONSEQUENCE: never put a schema or other structured value into hooks 1-5 from json.Marshal of a struct with map fields plus hand-concatenation, or from an SDK helper that iterates maps (see the anthropic-sdk-go ExtraFields gotcha). WHAT THIS DOES NOT MEAN: the bytes the Anthropic API receives are not CanonicalJSON's bytes verbatim: the SDK's json.Marshal of a RawMessage re-escapes HTML (<). That is still deterministic, which is all caching needs.

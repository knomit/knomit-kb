# To write facts in a knowledge base that the current session's URL-scoped bridge does not mount, run a SEPARATE headless Claude session whose kb bridge is started with no --repo/--lens and have it knomit_bind to that repo; a subagent cannot do it because it inherits the parent's scoped bridge

SITUATION (2026-10-28): a session whose only knomit server is the project's `.mcp.json` bridge `dist/kb --lens knomit-dev` needed to update facts in the knomit-playbooks knowledge base, which that lens does not mount. On a URL-scoped bridge knomit_bind changes only the branch, never the repo (kb/decisions/mcp/session-binding/scoped-endpoint-bind/3408dd94.md), and subagents share the parent session's MCP servers — so neither the session nor any subagent it spawns can reach that repo.

WHAT WORKED (user's instruction): write a scratch MCP config with the SAME binary and NO scoping args — {"mcpServers":{"kb":{"command":"<repo>/dist/kb","args":[]}}} — and start a separate headless session from the repo root: `claude -p "<brief>" --model <m> --strict-mcp-config --mcp-config <that file> --allowedTools "mcp__kb__knomit_repos mcp__kb__knomit_bind mcp__kb__knomit_query mcp__kb__knomit_explain mcp__kb__knomit_update ..."`. The brief tells it to call knomit_repos, knomit_bind to the target repo id, pass the returned handle as `binding` on every later call, and confirm with a query that it reads the target repo. It updated three knomit-playbooks facts that way.

CONSEQUENCES. Use this only for a repo no mounted lens reaches; for a mounted repo stay in-session. The child is a separate MCP session: it has its own binding and is not inside the parent's open experiment, so its writes land on the bound repo's agent branch directly — commit the parent's experiment first or keep the two unrelated. --strict-mcp-config keeps the project's scoped bridge out of the child. Give it read-only git on the source checkout it cites; headless permission patterns refuse commands with variable expansion or a leading `cd`, so brief absolute paths.

MISREADING. 'Spawn a subagent and have it bind elsewhere' — a subagent inherits the parent's URL-scoped bridge and cannot change repo; it must be a separate `claude` process with its own --mcp-config.

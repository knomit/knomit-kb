# No re-export or facade layers and no consumer-defined interfaces that restate a provider's methods: callers import the owning package and use its concrete types; a PR that adds an interface or re-export must name a live reason in its body, and reviewers block unnamed ones

RULE (project owner, 2026-10-21). Two shapes are forbidden, and they are the same fault seen from the two sides of an import:

1. A FACADE LAYER: aliases (`type X = pkg.X`), var or const forwards, function forwards, or pass-through methods that exist ONLY so callers can avoid importing the package that owns the thing. No "uber" package or file that re-exports a family of packages under one roof.
2. A CONSUMER-SIDE RESTATING INTERFACE: an interface declared by the consumer (or beside the provider) whose method set merely copies the methods of one provider type, justified as "accept interfaces, return structs is idiomatic Go".

What to do instead: the caller imports the owning package and uses its concrete types and functions.

CONSEQUENCE for briefs: tell the implementer, in the brief, to import the owning package directly and not to add an alias, forward or interface to avoid an import. CONSEQUENCE for the review gate: a PR that adds an interface, an alias, a forwarder or a re-export must name the live reason in the PR body (a second production implementation, a real import cycle that cannot be broken by moving the type down, a documented external contract, a named test double that cannot be built from the concrete type). The reviewer BLOCKS one with no named reason; "it is idiomatic", "it decouples", "it may be needed later" are not reasons.

WHAT THIS DOES NOT MEAN:
- It does NOT ban interfaces that have more than one real implementation in production, or an interface whose reason is named in the PR body. The rule bans unnamed ones.
- It does NOT ban the existing transitional store seams. At 7a721802 (E6 merged, PR #578) the transitional files that still exist in internal/store are vcs_seam.go, sqlite_conn.go and sessions_conn.go, and only those; E6 deleted the six seams fleetrec_seam.go, fsck_seam.go, gitserve_seam.go, index_seam.go, verify_seam.go and vocab_seam.go (with the alias block in interfaces.go), and remotesync_seam.go, merge_seam.go and facts_seam.go went in E5, E4 and E3. HISTORICAL (b4d232ee): the list at that commit named the six E6 files as still existing. The re-exports those files hold exist to keep the parent package compiling while the store hierarchy refactor moves code into child packages, and they are TEMPORARY: they are scheduled for deletion in the hierarchy refactor's remaining PRs (E7 for vcs_seam.go and the unexported child aliases, E7b for sqlite_conn.go and sessions_conn.go and the vcs, sessions and sqlite value types). Do not copy their shape into new code, do not cite them as precedent, and do not add a new seam entry to a file that is scheduled for deletion; and do not read this rule as licence to delete one early, out of order, in an unrelated PR.
- It does NOT forbid a package-level function or type that does real work (validation, ordering, error mapping) on its way through; a forward that adds behaviour is a function, not a facade.

EXCEPTION (project owner ruling, 2026-10-21; built through PR E3, f41adda1): Service operations backed by vcs, sessions or sqlite are the store's own API, not facades. The current ones are Service.OntologyAt and OntologyFileAt, Service.HasSharedHistory and Service.DiffFacts (kb/decisions/store/pr-e/diff-facts/926c22a2.md; internal/store/service_vcs.go; HasSharedHistory is declared in internal/store/service.go). They are allowed because those packages live under store/internal/ on purpose: nothing outside the store may write raw git objects or refs around the write path (the lock order, the signer, the derived-state sync and NotifyCommit under the lock), and a caller outside the store cannot import them, so the Service method is the only door and is the whole of its surface. CONSEQUENCE: a new read of the git layer that a caller outside the store needs is a Service method over rh with its own allowlist key, not a *vcs.Repo handed out and not a forward on a facts or merge type.

MISREADING 1: the exception does NOT cover forwards into importable children (merge, facts, remotesync). Those are handed out as concrete handles instead (Service.Facts() and Service.FactsRepo() since E3; Service.Merge() landed in E4, f3c32912, and Service.Remote(), a *remotesync.Index, in E5, b4d232ee), callers import the owning package, and the forwards are deleted. A Service method that merely calls a facts, merge or remotesync method is a facade even though a Service method that calls vcs is not.

MISREADING 2: test-only registration hooks guarded by mustBeTest (internal/store/storetest and the children's testseams.go) are not facades either. They forward nothing in production: they exist so a test outside the store reaches a vcs-backed seam without a Service method, and they panic outside a test binary.

HISTORICAL (was the KNOWN CURRENT INSTANCE; store.RemoteIndex was DELETED in E5, merged as b4d232ee, and there is no current instance of this paragraph's shape in the store; the text below is as verified at the PR C merge ba59d2b2): store.RemoteIndex, declared in internal/store/interfaces.go, restates the method set of *remotesync.Index; its only implementation is *remotesync.Index (the guard `var _ RemoteIndex = (*remotesync.Index)(nil)` in interface_guards.go), and the type name appears nowhere outside internal/store: callers in internal/repos reach it only as the return type of Service.Remote() (service.go) and call the methods on it. It was the template for what not to add; E5 removed it (Service.Remote() now returns the concrete *remotesync.Index), and `git grep RemoteIndex` finds nothing at b4d232ee.

WHAT THIS DOES NOT MEAN, for the handed-out remotesync handle (E5, merged as b4d232ee): RecordConsensusBranch and RecordedConsensusBranch are deliberately methods of the handed-out *remotesync.Index. Package store calls them (InitRepoWithUpstream calls s.ri.RecordConsensusBranch in repo.go), so they are not facades, and the writer is guarded by TestStoreConsensusRecord_OnlyInsideStore (test/archtest/store_write_internals_test.go), which fails on any selector of RecordConsensusBranch outside internal/store/**; the reader RecordedConsensusBranch is not in the guard (kb/invariants/store/consensus-branch-recorded/bcde3d66.md).

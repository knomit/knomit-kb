# internal/edge/web declares no interface type (webInterfaceAllowlist is empty since W0i): a new named interface or inline interface literal with methods fails, a stale allowlist entry fails, the guard proves it scanned web, and function-typed seams are an undetected gap

Guard TestWeb_DeclaresNoInterfacesBeyondTheAllowlist (test/archtest/web_no_interfaces_test.go), added in W0b (PR #600, merged as fa631358; re-read there). internal/edge/web declares no interface type except the names in webInterfaceAllowlist: 12 names after W0b (FactReader, FactWriter, TopicLister, searchProvider, commitsProvider, factSubProvider, statsProvider, motifsProvider, factsCollectionProvider, activityProvider, originProvider, RefResolver). The list only shrinks: each later W0 PR deletes its entries, and an entry whose interface is gone FAILS as stale, so the deleting PR must also delete the entry.

WHAT IT SCANS: web's non-test files from go list (GoFiles + CgoFiles + IgnoredGoFiles, so build-constrained files count); test files are NOT scanned (a test-helper interface is not a seam of the package). After review (88c86de1) it also flags every inline interface literal with methods outside a top-level type declaration: struct field, parameter, result, var, alias target, type assertion. Empty interface{} / any is allowed. Non-vacuity: web must come back from go list with files and every file must have been parsed.

KNOWN GAP, deliberate: a FUNCTION-TYPED seam (the former branchesListerFunc shape, a func field injected by tests) is not an interface and is not detected. Do not read a green guard as proof that web has no injected test seams; review for func-typed fields separately.

CONSEQUENCE: a web handler takes the concrete type (for example *store.Service or *oauth.Verifier) and its test builds a real store; failures come from the owner's SetReadFaultForTest hook (kb/decisions/store/web-provider-removal/a8b768db.md).

# A store path that writes a git ref and THEN its SQL rows must skip on "ref exists AND its bookkeeping is recorded", not on "ref exists"

When a store path writes a git ref and THEN its SQL bookkeeping (branches row, commit_log / branch_commits, notify), and later calls early-return on "ref exists", the skip test must be "ref exists AND its bookkeeping is recorded" (vcs.Repo.CommitRecorded). Otherwise one failure between the two writes (SetReference cannot be undone) leaves a permanent half-state that no later call repairs. If the test is false, run the idempotent SQL half at the ref's own hash; never move the ref.

Applies to bootstraps that early-return on ref presence (EnsureLocalUpstream, PR #637). It does NOT apply to fast-forward paths, which re-run their bookkeeping on every advance anyway.

vcs.Repo.CommitRecorded(branch, hash): (false, nil) on a missing branches row; true when commit_log is unavailable; otherwise whether hash is in branch_commits for the branch. It only reads, so a caller that acts on it must hold the branch's write lock. It is a probe for a branch TIP, not a general membership test: with no commit_log it answers true for any hash, and true says nothing about stale rows from a history the ref no longer reaches (use RepopulateBranch to drop those).

# HEAD reads of /incoming and /outgoing resolve active_commit via branch_facts.commit_hash

ExplainFact (HEAD reads) and the commit-anchored handlers share the same store method (IncomingAtCommit / OutgoingAtCommit). The only difference is what 'commit' the caller passes: commit-anchored uses the URL-supplied SHA; HEAD uses 'active_commit_for(P, B)' — the commit on branch B at which path P's currently-visible version was last changed. That value is already stored in branch_facts.commit_hash for path P on branch B (internal/store/migrate/repo/000001_schema.up.sql) — ONE indexed lookup, no git walk. Don't write a separate HEAD-specific query path; resolve active_commit_for and reuse the commit-anchored primitive.

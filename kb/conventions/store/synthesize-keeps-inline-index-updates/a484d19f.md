# MCP handlers DROP inline idx.Upsert/Delete; synthesize KEEPS them for immediate consistency

After the observer landed, MCP handlers (learn, update, retract) NO LONGER call idx.Upsert/idx.Delete inline — the observer's debounced callback handles it via idx.Sync. The interfaces were narrowed: mcp.SearchIndex lost Upsert, Delete, SetLastCommit, Sync, GetLastCommit; keeps only Search, GetByPath. CRITICAL EXCEPTION: the synthesize pipeline KEEPS inline idx.Upsert/idx.Delete because it requires IMMEDIATE index consistency — dedup searches for near-duplicates between writes (write winner, delete loser, search again). A 50ms-debounced observer cannot provide that consistency. synthesize.SearchIndex keeps Upsert, Delete, ClusterFacts, GraphAddDerivedFrom; loses Sync, GetLastCommit. The observer's idx.Sync fires after the pipeline completes and no-ops (already up to date). The store.Service.DeleteFact's idx.Delete call is REMOVED — only used in tests. Anti-pattern: do NOT add idx.Upsert/Delete to a new MCP handler — let the observer handle it.

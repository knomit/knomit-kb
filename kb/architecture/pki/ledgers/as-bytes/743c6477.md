# Issuance and revocation are pure in internal/pki — IssueLeaf(root, pub, host, role, validity, now) and RevokeSerial(root, prior, current, r, thisUpdate, next) return the leaf/CRL PEM and the exact ledger line; IssueInstance, Revoke and IssueCRL are thin wrappers that place them in the master dir

So the fleet reconcile can write certificates, the CRL and the two ledgers as fleet-repo artifacts (design D7/P5), the signing is split from file placement:
- `IssueLeaf(...) (Issuance{CertPEM, Record, Line}, error)` writes nothing; `Line` is the JSON record plus '\n', byte-identical to what `IssueInstance` appends to issued.jsonl. The SAN's fp8 comes from `Fingerprint(pub)`, never from a name.
- `RevokeSerial(root, prior []Revoked, current *big.Int, r, thisUpdate, next) (Revocation{Line, CRLPEM, Number}, error)`: the CRL lists prior + r, Number = current+1 (1 when current is nil). Callers holding ledger bytes parse them with `ParseRevokedLedger`. r is listed as the ledger reads it back (JSON round trip), so a later reissue from the ledger lists the same time.
- `SignCRL(root, revoked, number, thisUpdate, next)` is the pure form of `IssueCRL`.
- The wrappers (`IssueInstance`, `Revoke`, `IssueCRL`) stay because cmd/identity.go and internal/pki/pkitest call them.

Renewal windows are derived in renew.go: `NeedsRenewal(cert, now)` / `CRLNeedsResign(crl, now)` are true when less than a third (renewWindowDivisor = 3) of the artifact's OWN lifetime remains (NotAfter-NotBefore, NextUpdate-ThisUpdate); no day-count literal. A CRL without NextUpdate never falls due.

TEST SEAM. `newSerial` is a package variable only so a test can pin the serial and compare the pure and file variants field by field (TestIssueLeaf_EquivalentToIssueInstance, TestRevokeSerial_EquivalentToRevoke). DER is not compared.

MISREADING. The pure functions take the clock as a parameter; they do not read time.Now(). A caller that passes a stale `now` issues a stale certificate.

# Issuance and revocation are pure in internal/pki: IssueLeaf returns the leaf PEM (which IS the fleet repository's issuance record) and RevokeSerial returns the root-signed revocation statement and the new CRL built from the CURRENT CRL; RecordIssuance and RecordRevocation then place the master's LOCAL copies (issued.jsonl/revoked.jsonl audit log, atomic crl.pem) in the fleet root DIRECTORY, and IssueInstance and IssueCRL remain thin directory wrappers (pki.Revoke is gone); the fleet repository holds no ledger; renewal falls due in the final THIRD of an artifact's own lifetime

So the fleet reconcile can write certificates, the CRL and the per-operation records as fleet-repo artifacts (design D7/P5), signing is split from file placement (PR #512, reshaped by PR #514):
- `IssueLeaf(root, pub, email, validity, now) (Issuance{CertPEM, Record, Line}, error)` writes nothing. The identity is the ONE email SAN (<agent id>@agents.knomit.io for an instance, any other address or none for an operator; no host/role arguments, no URI SAN: kb/decisions/pki/identity-is-email-san/fb964b9f.md). `Issuance.CertPEM` is BOTH the member's leaf (certs/<id>.pem) and the fleet repository's per-operation issuance record (issued/<name>.pem, checked by pki.CheckIssuance); `Issuance.Line` is the JSON record plus '\n', byte-identical to what `IssueInstance` appends to the fleet root DIRECTORY's LOCAL issued.jsonl. The wrappers place files in the fleet root directory (default <home>/fleet).
- `RevokeSerial(root, current *x509.RevocationList, r Revoked, thisUpdate, next) (Revocation{Statement, CRLPEM, Number, Line}, error)`: the new CRL lists EVERY serial of the CURRENT CRL (with their revocation times) plus r, and Number = current.Number+1 (1 when current is nil). `current` must be root-signed (CheckCRL) or the call fails. A serial already on it is `ErrAlreadyRevoked`. r.At is truncated to UTC whole seconds. `Statement` is SignRevocation's knomit-revoke/v1 file (kb/invariants/pki/revocation-statement/014890c4.md); `Line` is the LOCAL revoked.jsonl line. It no longer takes the prior ledger or a `current *big.Int`: the old claim 'the CRL is a projection of the whole ledger' is WRONG now; the new CRL is a SUPERSET of the CRL it replaces, so the fleet repository's revoked_set: superset rule holds by construction.
- `SignCRL(root, revoked, number, thisUpdate, next)` is the pure form of `IssueCRL`.
- `RecordRevocation(dir, rv)` (PR #525; it replaced the deleted directory wrapper `pki.Revoke`) keeps the fleet root directory's LOCAL copies of a revocation RevokeSerial built: it appends rv.Line to <dir>/revoked.jsonl and replaces <dir>/crl.pem with rv's CRL through `writeFileAtomic` (temp file + rename), so a crash never leaves a torn crl.pem, the file `GET /fleet/root` hands the next master. The fleet repository's main is the authority and the CRL RevokeSerial builds comes from MAIN's current CRL, not from <dir>/crl.pem. The old `Revoke`'s refusals (crl.pem missing while revoked.jsonl lists revocations; crl.pem lagging the log) are GONE with it: nothing checks that the local crl.pem lists every logged serial, because the local files are copies (the `revoked_set: superset` artifact rule judges main's CRL). The POST /fleet/revoke route is the one production caller of RevokeSerial and RecordRevocation (kb/architecture/fleet/revoke/0ebbe07c.md records the route). `knomit identity revoke` no longer exists.
- The fleet REPOSITORY holds no ledger: issuance and revocation are one write-once root-signed file per operation (kb/decisions/fleet/pki/per-operation-records/235c9dd9.md). The LOCAL ledgers in the master's fleet root directory remain, as an audit log and as the check above.
- `RecordIssuance(dir, is)` (PR #525) appends is.Line to the local issued.jsonl. POST /fleet/enroll calls `IssueLeaf`, commits certs/<id>.pem and issued/<serial>.pem on the master's agent branch, and ONLY THEN calls `RecordIssuance`, so the audit line exists only for a leaf the fleet repository holds; a failed write is a WARN, not a refusal. `IssueInstance` (IssueLeaf + RecordIssuance together) stays for fleet create and the pki tests; `IssueCRL` stays as the thin directory wrapper over SignCRL. cmd/identity.go no longer calls any of them (the identity enroll/init-root/revoke verbs were removed in #525).

RENEWAL WINDOW (renew.go): `NeedsRenewal(cert, now)` / `CRLNeedsResign(crl, now)` are true when less than ONE THIRD (renewWindowDivisor = 3) of the artifact's OWN lifetime remains (NotAfter-NotBefore, NextUpdate-ThisUpdate); no day-count literal. The check is `end.Sub(now) < life/renewWindowDivisor`, with no time.Duration overflow (the earlier `remaining*3 < life` form overflowed past about 97 years left and made a long-lived cert due from day one). Zero or negative lifetime is due; a CRL without NextUpdate never falls due.

TEST SEAM. `newSerial` is a package variable only so a test can pin the serial and compare the pure and file variants field by field (TestIssueLeaf_EquivalentToIssueInstance, TestRevokeSerial_AndRecordRevocation; the latter replaced TestRevokeSerial_EquivalentToRevoke). DER is not compared.

MISREADINGS. The pure functions take the clock as a parameter; they do not read time.Now(). A caller that passes a stale `now` issues a stale certificate. 'RevokeSerial needs the ledger' (the pre-#514 signature) is wrong: give it the CRL you are replacing.

# REST GET .../facts/{path}/materialize/pages serves the knomit_materialize HUMAN page byte for byte from one shared builder (materialize.FirstPage/NextPage); first call takes depth/max_nodes/unpin/cross_kb, later calls ONLY cursor; the cursor is owned by the route URL + principal; /materialize is the attachment export

Route (three mounts, dispatched as a fact sub-resource by serveMaterializeSub in internal/edge/web/api/kb/handlers_materialize.go, no new chi route):
- /api/v1/repos/{repo}/branches/{branch}/facts/{path}/materialize/pages (anchor: branch tip, resolved on the first call)
- /api/v1/repos/{repo}/branches/{branch}/commits/{sha}/facts/{path}/materialize/pages (anchor: sha)
- /api/v1/lenses/{lens}/facts/{path}/materialize/pages (through the lens binding; every not-found is the lens's byte-identical 404)

First call: no `cursor`; reads depth (0-10, default 4), max_nodes (1-500, default 200), unpin, cross_kb, and limit (facts per page, 1-5, default 3); anything else or out of range is 400 (never a clamp). The limit is frozen in the cursor: the tool-session `tool` value is "materialize:<audience>:<limit>" (sessionTool/parseSessionTool in pages.go), so NextPage knows it before it dequeues. Later calls: `?cursor=<id>` on the SAME URL and nothing else; any other parameter with it (limit included) is 400 and consumes nothing; `cursor=` empty is 400.

Payload: application/json, exactly materialize.Page with audience "human" (the struct knomit_materialize marshals): envelope root, anchor, order (refs|frame), audience, unpinned, cross_kb, depth, max_nodes, total, truncated{depth,nodes}, instructions_version, instructions (page 1 only), facts[], n_from, n_to, cursor (null at the end), has_more. Each fact is materialize.Node: n, path, repo, commit, depth, role (root|ancestor|focal|ref), title, type, kind, confidence, date, body, builds_on[{n,title,id,anchor_id,different_version}], not_included[{title,id,path,reason}], sources[{label,url}], marks ([latest_other_kb]), anchor_id, section. No field was added for the UI: every field the UI needs already existed. Pages hold whole facts, at most the frozen limit (default materialize.HumanDefaultLimit 3, max materialize.HumanMaxLimit 5) and within materialize.PageCap (32 KiB of JSON); one fact larger than that comes alone. knomit_materialize also keeps the first call's limit on a resume that passes none (an explicit MCP `limit` with cursor still overrides that one page; REST refuses it), so a REST page equals the MCP human page for the same first call at every limit (TestMaterializePages_RESTIsTheMCPHumanPage compares the bytes at the default and at limit 5, cursor ids aside).

Shared builder: internal/corpus/materialize/pages.go (PageEnv, Page, CursorScope, FirstPage, NextPage, fillPage, snapshotItems, ErrCursorExpired); internal/edge/mcp/materialize.go now only parses arguments and maps ErrCursorExpired to its expiry text.

Ownership: CursorScope.Owner. MCP passes callerOwner (MCP endpoint path + principal); REST passes restCursorOwner = r.URL.Path + " " + principal, so the owner already names the fact and the anchor route: the same cursor on another fact's or another commit's URL, another principal's, an MCP cursor on REST and the reverse all read as expired. Every expired case is the same 404 problem (title "Cursor not found", fixed detail) and leaves the queue intact. Pin (Binding.PinID) and read set (federate.ReadSetFingerprint) are checked too.

Export: GET .../facts/{path}/materialize (all three mounts) sends Content-Disposition: attachment; filename="<slug>-<id8>.md" from materialize.ExportFileName (title lowercased, non-[a-z0-9] runs to one '-', cut at the last '-' within 48 chars or hard at 48, id8 = file id; no [a-z0-9] gives <id8>.md). The pages route never sets it. The export takes no `limit` (400) and is gzip-compressed for a client that accepts it: text/markdown is in compressibleTypes (internal/edge/web/compress.go). Every unservable cursor is a 404, never a 410 (a 410 would say the cursor once existed).

WHAT THIS DOES NOT MEAN: the pages route is not paginated by offset and cannot be resumed with different options; and /materialize is not the streaming source. A new surface that pages materialize must call FirstPage/NextPage with its own CursorScope.Owner, never copy the fill loop.

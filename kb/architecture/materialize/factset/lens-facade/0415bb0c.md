# A FactSet on a lens (Binding.IsLens) is the lens FACADE: one fused anchored search, one sub-FactSet per member through the F2 seam, ONE v2 session row and ONE cache entry, pages/seek/export over GLOBAL units with a four-field number remap

Since feat/lens-factset-facade (F3 of the lens FactSet plan), materialize.FactSetFirstPage DISPATCHES on Binding.IsLens(): a binding that reads more than its write repo goes to lensFactSetFirstPage (internal/corpus/materialize/factset_lens.go); a ONE-member lens is not IsLens and stays on the repo path (ruling Lens 6 / Q-L9). The old B1 refusal is gone.

CREATION (lensFactSetFirstPage):
1. Every Binding.Reads() mount is opened and readiness-checked; planLensSearch runs federate.PlanFused with the request's search, every mount asked for MaxFactSetFacts (500) results the way REST /lenses/{lens}/search asks for maxLensSearchCandidates, search.repo as FusedQuery.Repos, the edge's motif cluster reader (FactSetRequest.Clusters), the edge's embedder. A StageTargets/StageRepos PlanError is ErrInvalid.
2. lensSearchAnchored: the N-mount settle sandwich (see the lens-sandwich invariant fact), then federate.FusedSearch (relevance) or FusedRecent (sort=recent), legs reading each mount's opened store keyed by the target's repo id, NEVER by plan position; truncated to Facts; partitioned by Hit.Target.Mount (the stable Reads() index) keeping fused order. So the first 50 roots ARE the REST lens list (TestLensFactSet_FirstFiftyRootsAreTheRESTLensList, internal/edge/web).
3. One sub per member through the F2 seam: freezePinned(home = member, wire = lens write repo, env with that member's anchor, CrossKB false), then attachLens + ensureState per sub with roots. A member with no roots is a legal empty sub.
4. ONE session row (lensCall.create, CreateFactSet in the WRITE repo's session DB, CursorScope as every lens cursor): frozen v2 = lensFrozen {v:2, env, limit, wire_repo, order: sub index per global unit, subs: [{repo id12, name, branch, anchor, roots}]}. Subs are NOT rows. v1 repo rows stay readable (openFactSet peeks the version).

CACHE CHOICE: ONE facade fsEntry (lens set, fr nil) holding the N sub fsEntries, which are never inserted in the cache map and carry parent = facade; fsCacheAccount(sub) charges the facade; the facade's accountedSize is the sum of its subs'. Chosen over per-sub keys because #702's cache evicts by entry: per-sub keys could evict one sub while the others live, and every page would then have to treat a missing sub as expired. One entry = one thing to evict, drop on store close and account.

A CALL (fsCall with lc *lensCall): c.e is swapped to the sub being planned; attachLens registers EVERY sub home in the reader after openFactSet's owner/pin/read-set checks (084b9245 order) and sets ONE planning reservation for the whole call. lensCall.planGlobal plans in GLOBAL order (every global unit < g first), so the planned extent is a global prefix and units_walked/sections stay global (sections = sum of each sub's sectionsThrough of its local count). lensCall.cover is the read-ahead: one window of prefetchWindow GLOBAL units, grouped by sub, one readAhead per sub on its own home's LevelReader (level readers opened on the caller goroutine), the next window read in the background (not for the export). Cursor stays <id>.<unit>.<section> in GLOBAL units. inflate runs once over a page's sections of any number of homes (a registered home is never 'gone').

REMAP at emission (lensEntry.remap): exactly FactSetNode.Unit, the first component of Number, FactSetLink.Unit and the first component of FactSetLink.Number (forward links only; back links are anchor-only). The export (lensCall.export) remaps before rendering, so headings and (see N) are global.

WIRE ADDITIONS, lens pages only (omitempty, so repo bytes are unchanged): env.anchors {member id12: anchor} (Lens 4; env.anchor stays the write member's); repo_name on every unit root (Lens 7); the Lens 1 leaf (see the rulings fact); env.search.repos.

CONSEQUENCES: a change to how a lens FactSet's roots are chosen belongs in federate (the lens list) or planLensSearch, never in a second fan-out. Never key per-mount state on plan position. A new lens FactSet entry point must go through openFactSet + attachLens (row checks first).

WHAT THIS DOES NOT MEAN: no REST lens FactSet route exists yet (F4); MCP has no export, so the facade export is reached only by FactSetExport callers (tests today). Subs do not share a written set: a fact of R1 cited from W is a not-followed leaf, never planned.

REVIEW FIXES (PR #706 review, commit 56c34eb7):
- M1: only the SEARCHED mounts (plan.Targets; the write member alone under since_fork) are opened, readiness-checked and sandwiched; env.anchors lists only them. Unsearched members stay in the v2 row as empty subs with an empty anchor.
- M2: sort=recent with no text uses federate.FusedRecentDeep (the merge-horizon deepening moved out of REST /lenses/{lens}/facts, which now calls it too), starting at depth MaxFactSetFacts, need = Facts, backstop federate.MaxRecencyDepth (10000). A fork whose newest rows are all copies losing write-first dedupe no longer hides its own facts from the FactSet (TestLensFactSet_RecentFirstFiftyAreTheRESTFactsList: the first 50 roots equal REST /facts, fork case).
- L1: MCP passes the server embedder (MaterializeHandler(mgr, embedders...)); a lens FactSet embeds its query ONCE through fanoutQueryVec, as knomit_query on the lens does (a repo FactSet still leaves embedding to its store).
- L2: resume refuses as ErrCursorExpired a v2 row with two subs of one repo (decodeLensFrozen), a wire repo other than the binding's write repo, or a read member mounted at another branch than the row froze (attachLens).
- L4: fsCall.page and lensCall.page share fsCall.buildPage over a pageSource (plan, unitOf, emit, sections callbacks); repo pages stay byte-identical (F2 goldens).
- L6: kept plans are PER SUB: the LRU of 8 (keptPlans) lives on each sub fsEntry, so a facade keeps up to 8 x N plans, all charged to the facade entry's accounted size.

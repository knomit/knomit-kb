# FactSet streaming (PR C): frozen inputs in ONE session row, state in an in-memory cache rebuilt by replay, the reading position in the cursor token, and every level of every unit one batched index read with no per-fact git

internal/corpus/materialize serves a materialized SEARCH (FactSet) as follows, built on ref_edges (PR B):

- FROZEN INPUTS, written ONCE at the first call in ONE transaction (sessions.ToolIndex.CreateFactSet, BEGIN IMMEDIATE): a tool_sessions row (owner = endpoint + principal, binding pin, read set) plus factsets.frozen = JSON of the search, options, anchor, the frozen tips of every repo the caller reaches (only when cross_kb is on), and the roots as (path, commit, blob, title, date). The same owner's previous FactSet is deleted in that transaction.
- ANCHOR = the write mount's INDEX WATERMARK (meta last_commit:<branch>, HistoryQuery.Watermark), read with the sync_pending marker (HistoryQuery.SettledWatermark) before and after the search; while the watermark is unsettled (a sync in flight, an empty watermark mid-Rebuild) or moves across the search, the first call waits and searches again, bounded by the request context and session.factset_anchor_wait (default 5s), then ErrIndexMoved (503, Retry-After). Never git HEAD. branch_facts describes the watermark only when no sync is rewriting it (gotcha 68218e91), so only then is each hit's (commit, blob) its version at the anchor.
- PLANNER (factset_plan.go) is the ONE walk for a single fact (Plan) and every FactSet unit: per BFS level ONE read per KB through index.LevelReader (one per call, two prepared statements: the ref_edges rows of the level's blobs, then the facts rows and commit_log dates of ONLY the targets the unit has not seen, keyed by (path, blob, commit) so one blob pinned at two commits keeps each commit's date), so a unit costs at most Depth+2 index reads beyond the read-ahead (root metadata + Depth+1 levels; the depth-limit level is read for the titles of cut refs). A FactSet call also READS AHEAD (fsCall.readAhead): windows of 6 units, roots then level by level speculatively to the unit's depth within a max_nodes-per-unit budget, in parallel chunks, pipelined behind the planner (pages only: the export makes its PLANNING reads inside its planning slot, never in a background window; its body and RULE 1 reads, inflate's BlobsByHash and CurrentBlobs, run after it releases the slot, bounded by the export slots and exportChunk); a unit whose data was not read ahead reads it itself with the same answer. UNPIN reads no ref_edges rows at all: the targets are the fact's frontmatter refs (local fact refs in ord order, each once, self skipped), each versioned by HistoryQuery.LiveAt at the anchor, so a ref that had no row at write time (cited before its target existed) still resolves; reserve() takes the N.k targets the same way so the reservation mirrors the planner. Cross-KB versions also come from LiveAt, at the frozen tips. Bodies are read by blob (FactQuery.BlobsByHash) only for the sections a page emits.
- STATE (results and reserved map as frozen sorted 24-byte tables, the written set as bitsets over them plus a small extra set, and the plans of the units a later page may start in) lives in a process cache (factset_cache.go) under session.factset_memory_mib, LRU-evicted; a miss replays units 1..u-1 without bodies. An export's own state (its written set, the frozen tables and roots it keeps alive, the window and plan it holds between units) is charged to the same budget (fsCharge), evicting idle entries; a charge, like an entry in use, is never evicted and is bounded by the export slots. Store close drops that store's entries (ToolIndex.OnClose hook run by Service.Close).
- CURSOR = "<id>.<unit>.<section>": the position after the page. Pages write nothing; two calls with one cursor return the same bytes (no CAS, no 409). The ROW decides ownership on every call; a position past the extent is ErrInvalid (400); another owner or an unknown id is ErrCursorExpired (404). The only later write is the heartbeat, at most once per tool_idle_ttl/4 (SetFactSetIdleTTL, wired in internal/app because repos cannot import materialize).

CONSEQUENCE: never add a per-page or per-fact session write, a git read, or OutgoingAtCommit to this path; F13 and F14 (factset_engine_test.go) fail on each.

WHAT THIS DOES NOT MEAN: the single-fact pages route still pages through its tool_queue snapshot (its wire contract is unchanged); only its walk and bodies moved onto the planner.

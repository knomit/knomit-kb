# FactSet streaming (PR C): frozen inputs in ONE session row, state in an in-memory cache holding a first-appearance prefix (any unit re-planned alone, never replayed), the reading position in the cursor token, and every level of every unit one batched index read with no per-fact git

internal/corpus/materialize serves a materialized SEARCH (FactSet) as follows, built on ref_edges (PR B):

- FROZEN INPUTS, written ONCE at the first call in ONE transaction (sessions.ToolIndex.CreateFactSet, BEGIN IMMEDIATE): a tool_sessions row (owner = endpoint + principal, binding pin, read set) plus factsets.frozen = JSON of the search, options, anchor, the frozen tips of every repo the caller reaches (only when cross_kb is on), and the roots as (path, commit, blob, title, date). The same owner's previous FactSet is deleted in that transaction.
- ANCHOR = the write mount's INDEX WATERMARK (meta last_commit:<branch>, HistoryQuery.Watermark), read with the sync_pending marker (HistoryQuery.SettledWatermark) before and after the search; while the watermark is unsettled (a sync in flight, an empty watermark mid-Rebuild) or moves across the search, the first call waits and searches again, bounded by the request context and session.factset_anchor_wait (default 5s), then ErrIndexMoved (503, Retry-After). Never git HEAD. branch_facts describes the watermark only when no sync is rewriting it (gotcha 68218e91), so only then is each hit's (commit, blob) its version at the anchor.
- PLANNER (factset_plan.go) is the ONE walk for a single fact (Plan) and every FactSet unit: per BFS level ONE read per KB through index.LevelReader (one per call, two prepared statements: the ref_edges rows of the level's blobs, then the facts rows and commit_log dates of ONLY the targets the unit has not seen, keyed by (path, blob, commit) so one blob pinned at two commits keeps each commit's date), so a unit costs at most Depth+2 index reads beyond the read-ahead (root metadata + Depth+1 levels; the depth-limit level is read for the titles of cut refs). A FactSet call also READS AHEAD (fsCall.readAhead): windows of 6 units, roots then level by level speculatively to the unit's depth within a max_nodes-per-unit budget, in parallel chunks, pipelined behind the planner (pages only: the export makes its PLANNING reads while it holds its per-unit planning reservation, never in a background window; its body and RULE 1 reads, inflate's BlobsByHash and CurrentBlobs, run after it gives the reservation back, exportChunk sections at a time); a unit whose data was not read ahead reads it itself with the same answer. UNPIN reads no ref_edges rows at all: the targets are the fact's frontmatter refs (local fact refs in ord order, each once, self skipped), each versioned by HistoryQuery.LiveAt at the anchor, so a ref that had no row at write time (cited before its target existed) still resolves; reserve() takes the N.k targets the same way so the reservation mirrors the planner. Cross-KB versions also come from LiveAt, at the frozen tips. Bodies are read by blob (FactQuery.BlobsByHash) only for the sections a page emits.
- STATE (since fix/factset-random-access) lives in a process cache (factset_cache.go): results and reserved map as frozen sorted 24-byte tables, and the planned PREFIX (units 1..planned): per written fact the unit that FIRST wrote it (a uint16 per frozen-table entry, plus an extra set of 32-byte entries carrying the unit), each planned unit's section count, and an LRU of 8 kept unit plans. A fact is written at most once in a FactSet, so 'written before unit u' = 'first unit < u' and ONE growing prefix answers every u <= planned: a unit within it is re-planned alone (lookup bounded by u), never by replaying units 1..u-1; extending it is done by the one call holding the entry's extension token (others wait on their own context; reads of planned units never touch the token and run concurrently: there is no per-FactSet mutex). The export plans on the same prefix (extending or re-planning). Eviction drops the entry; the next call plans again up to what it needs. Store close drops that store's entries (ToolIndex.OnClose hook run by Service.Close).
- BUDGET: session.factset_memory_mib (default 64 MiB) bounds cached entries PLUS a planning reservation every call that must plan takes BEFORE the token (fsPlanReserve: two read-ahead windows at about 4 KiB per node, or while the tables are unbuilt 128 bytes per depth-1 entry, both measured on synth B). Over budget idle LRU entries are evicted; an entry in use is not, but it is CHARGED as it grows (after its tables are built and after every unit an extension applies), so an export or far seek holding it stays visible to the budget. A call that still does not fit WAITS (granted at once when no other reservation is in flight, so the budget is SOFT by one reservation plus the entries in use), bounded by its context and config.FactSetStallLimit, then ErrFactSetBusy (503). A call waiting for another call's extension or table build holds NO reservation while it waits (acquireToken gives it back and reserves again when woken; giving the token back wakes waiters). Admission is not FIFO: a large reservation can be overtaken by small ones (unmeasured follow-up). The old caps (4 planning slots, 8 export slots, ErrFactSetExportsBusy) are gone. A page reserves only when it must plan; the export reserves per unit and releases before it writes; the export keeps only the edge's 1-minute per-write stall limit, no overall deadline.
- PAGE FIELDS: UnitsWalked/Sections are the highest unit the page itself walked and the sections of units 1..it (what sequential paging reports), never the cache's extent, so a page is a pure function of (FactSet, position).
- CURSOR = "<id>.<unit>.<section>": the position after the page. Pages write nothing; two calls with one cursor return the same bytes (no CAS, no 409), in any order and concurrently (TestFactSet_RandomAccessIsByteIdentical). The ROW decides ownership on every call; a position past the factset's last unit is ErrInvalid (400) (a position past the planned prefix is valid: it extends the prefix); another owner or an unknown id is ErrCursorExpired (404). The only later write is the heartbeat, at most once per tool_idle_ttl/4 (SetFactSetIdleTTL, wired in internal/app because repos cannot import materialize).

CONSEQUENCE: never add a per-page or per-fact session write, a git read, or OutgoingAtCommit to this path; F13 and F14 (factset_engine_test.go) fail on each.

WHAT THIS DOES NOT MEAN: the single-fact pages route still pages through its tool_queue snapshot (its wire contract is unchanged); only its walk and bodies moved onto the planner.

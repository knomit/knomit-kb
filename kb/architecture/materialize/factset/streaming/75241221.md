# FactSet streaming (PR C): frozen inputs in ONE session row, state in an in-memory cache rebuilt by replay, the reading position in the cursor token, and every level of every unit one batched index read with no per-fact git

internal/corpus/materialize serves a materialized SEARCH (FactSet) as follows, built on ref_edges (PR B):

- FROZEN INPUTS, written ONCE at the first call in ONE transaction (sessions.ToolIndex.CreateFactSet, BEGIN IMMEDIATE): a tool_sessions row (owner = endpoint + principal, binding pin, read set) plus factsets.frozen = JSON of the search, options, anchor, the frozen tips of every repo the caller reaches (only when cross_kb is on), and the roots as (path, commit, blob, title, date). The same owner's previous FactSet is deleted in that transaction.
- ANCHOR = the write mount's INDEX WATERMARK (meta last_commit:<branch>, HistoryQuery.Watermark), read before and after the search; a move in between is retried once, then ErrIndexMoved (503). Never git HEAD: branch_facts describes the watermark, so each hit's (commit, blob) is its version at the anchor.
- PLANNER (factset_plan.go) is the ONE walk for a single fact (Plan) and every FactSet unit: per BFS level ONE read per KB through index.LevelReader (one per call, two prepared statements: the ref_edges rows of the level's blobs, then the facts rows and commit_log dates of ONLY the targets the unit has not seen), so a unit costs at most Depth+2 index reads beyond the read-ahead (root metadata + Depth+1 levels; the depth-limit level is read for the titles of cut refs). A FactSet call also READS AHEAD (fsCall.readAhead): windows of 6 units, roots then level by level speculatively to the unit's depth within a max_nodes-per-unit budget, in parallel chunks, pipelined behind the planner; a unit whose data was not read ahead reads it itself with the same answer. Unpin and cross-KB versions come from HistoryQuery.LiveAt. Bodies are read by blob (FactQuery.BlobsByHash) only for the sections a page emits.
- STATE (results and reserved map as frozen sorted 24-byte tables, the written set as bitsets over them plus a small extra set, and the plans of the units a later page may start in) lives in a process cache (factset_cache.go) under session.factset_memory_mib, LRU-evicted; a miss replays units 1..u-1 without bodies. Store close drops that store's entries (ToolIndex.OnClose hook run by Service.Close).
- CURSOR = "<id>.<unit>.<section>": the position after the page. Pages write nothing; two calls with one cursor return the same bytes (no CAS, no 409). The ROW decides ownership on every call; a position past the extent is ErrInvalid (400); another owner or an unknown id is ErrCursorExpired (404). The only later write is the heartbeat, at most once per tool_idle_ttl/4 (SetFactSetIdleTTL, wired in internal/app because repos cannot import materialize).

CONSEQUENCE: never add a per-page or per-fact session write, a git read, or OutgoingAtCommit to this path; F13 and F14 (factset_engine_test.go) fail on each.

WHAT THIS DOES NOT MEAN: the single-fact pages route still pages through its tool_queue snapshot (its wire contract is unchanged); only its walk and bodies moved onto the planner.

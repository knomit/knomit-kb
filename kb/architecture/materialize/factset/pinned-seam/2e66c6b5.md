# A FactSet over SUPPLIED pinned roots is freezePinned + startPinned (+ createPinned for a session row); FactSetFirstPage is the search + anchor part followed by all three with home = wire = the write mount

Since refactor/factset-pinned-seam (F2 of the lens FactSet plan), internal/corpus/materialize/factset.go builds a FactSet in two parts:

1. SEARCH + ANCHOR (FactSetFirstPage only): validation, the IsLens refusal, open the write mount, searchAnchored (settled watermark sandwich), the env (title, search line, options, anchor).
2. THE PINNED SEAM, over roots someone else already found and anchored:
   - freezePinned(home pinnedHome{ID, Branch}, wireID, env, limit, hits) *factsetFrozen: pure; the roots in the order given, env.Anchor is the home's settled watermark the hits were read at; WireRepo set only when wireID != home.ID.
   - (*fsCall).startPinned(fr, toolIndex): takes fr.Tips (empty map when none), registers the home in the call's reader, makes the cache entry (not yet cached) and builds the results/reserved tables (ensureState). Writes NO session row.
   - (*fsCall).createPinned(sc): marshals fr, writes the ONE session row (CreateFactSet), caches the entry, serves page 1; deletes the row if page 1 fails.
   With cross_kb, FactSetFirstPage freezes tips between freezePinned and startPinned (a sub-FactSet never does).

CONSEQUENCES:
- A lens facade (F3) calls freezePinned + startPinned ONCE PER MEMBER over that member's slice of federate.FusedSearch/FusedRecent, and writes one facade row itself. It must NOT call createPinned per member: sub-FactSets are not session rows (design 7.4).
- A repo FactSet's frozen bytes and pages are byte-identical to before the split: pinned by TestFactSet_Pinned_RepoPathIsByteIdentical (the seam called directly with the roots the search froze vs FactSetFirstPage: same row bytes, pages, seek, export).

WHAT THIS DOES NOT MEAN: the seam does not run or validate a search, take an anchor or check reach; the caller must supply hits that are versions AT env.Anchor in the home (a facade's N-mount settle sandwich is F3's job). It is also not exposed on REST or MCP: home != wire is test-only until F3.

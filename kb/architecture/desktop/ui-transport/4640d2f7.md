# How the desktop UI path is wired: apiProxy in front of the asset handler (503 + Retry-After while booting, page's own origin as the API base), the knomit-sse Wails Stream with the API path in its first frame, and the __KNOMIT_EVENT_TRANSPORT__ flag that switches openEventStream

State at merge 2104fd6d (PR #488); the why is in the decision fact under kb/decisions/desktop/ui-transport.

SERVER SIDE (tools/desktop)
- app.go: Assets.Handler = apiProxy(configInjectingHandler(...), ready, uiUp). Only paths under /api/ are proxied; /config.js, /boot/status, /desktop/ and the SPA fallback go to the inner handler. registerSSEStream(wapp, uiUp) registers the stream.
- uiUpstream holds the path of the local socket/pipe THIS in-process server bound (server.local, filled by bootKnomit after bootServer). Every UI-path dial is auth.DialLocal on that path, so the server sees the same verified local peer as the kb bridge. Empty until bound.
- Proxy transport: DisableCompression (a compressing hop stalls SSE, kb gotcha a762359e), FlushInterval -1, keep-alive on. The stream opener's transport has keep-alive OFF so closing one subscription closes exactly its own connection.
- While booting (boot.status().Ready false) /api/ answers 503 problem+json with Retry-After: 1 (not 502, not held: a first launch spends minutes downloading models). Observed live: the single ungated request during boot is GET /api/v1/repo-creates; useRepoCreates swallows it and polls again.
- API base: uiStatus replaces the TCP base with desktopOrigin() (wails://localhost; http://wails.localhost on Windows) once ready, so /config.js and /boot/status report the page's own origin and every API call is same-origin. boot.status() itself still carries the TCP base, used only by Settings' effective-port readout.
- /config.js also writes window.__KNOMIT_EVENT_TRANSPORT__ = "wails-stream" in BOTH boot states: a page that loaded while booting adopts its base from /boot/status and never re-reads /config.js, so the flag cannot depend on readiness.
- Stream knomit-sse: Wails stream names are exact (no path/query), so the page opens that one name and sends {path, last_event_id} as the first frame. validSSEPath accepts only an absolute /api/v1/ path, no '//' prefix, no backslash, no '..' segment, no scheme/host/userinfo; anything else gets an error frame (400) and the stream closes without dialing. The Go side GETs the path over the socket with Accept: text/event-stream (and Last-Event-ID when it has one), parses SSE (event, multi-line data, id, retry, comments) and forwards frames; a server 4xx/5xx is FINAL (as EventSource), 502/503/504 are retried (server absent); reconnect backoff 500 ms doubling to 5 s unless the server sends retry:; closing the page stream cancels the upstream request.

PAGE SIDE (web/src/eventStream.ts)
- openEventStream(url) is the single place the app constructs an SSE connection (six sites: api.ts x4, App.tsx, logStore.ts). Default: new EventSource(url) (browser build; vitest's global double). With the flag: WailsEventSource, which lazily imports /wails/runtime.js (served by Wails itself, so web/ takes no @wailsio/runtime dependency), maps frames to open/error/named/message events, and if the Wails stream itself ends reopens with the same 500 ms to 5 s backoff, resending last_event_id.

EVIDENCE: Go tests (uiproxy_test.go, uistreams_test.go incl. an end-to-end over a real local socket, uitransport_test.go) and a macOS WKWebView run on a scratch home: transport flag and booting=true at page start, 503 during boot, /boot/status ready with base wails://localhost, /api/v1/repos|version|archived|lenses 200 through the proxy, one knomit-sse stream opened for repo-events, a bodied POST /api/v1/repos 202, the rail showed the new repo 150 ms after the create, and the desktop process held exactly one TCP socket (the server's own listener). NOT run: Windows, Linux, the Logs page tail and stream close/reopen in the live UI.

WHAT THIS DOES NOT MEAN: Settings' readout of the TCP port is still real, the server still listens on TCP; the flag being set does not mean a stream is open (the boot gate keeps every stream closed until /boot/status says ready); and a held local socket no longer degrades to a TCP-only desktop (see the held-socket gotcha under kb/gotchas/desktop/boot).

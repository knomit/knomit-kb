# Manager.Start opens core.db first then globs; launches the session reaper; Close is two-pass cancel-then-wait over index-heal+sync loops

Manager.Start() opens the DEFAULT repo FIRST (config.DefaultRepoName = 'core', i.e. core.db) with isDefault=true so a fresh DB gets initDefaultGit (clone-from-origin or create-with-default-ontology). Then it globs repos/*.db (sorted) and Adds each, skipping session sidecars (store.IsSessionDBFile), invalid names (warn log), and the already-opened default. Finally it launches the background idle-SESSION REAPER via m.startSessionReaper(parseSessionReaperConfig(cfg.Session)), storing its stop func in m.sessionReaperStop (a misconfigured [session] block fails Start at boot rather than silently disabling the reaper).

Manager.Close(): (1) stop the session reaper first (m.sessionReaperStop); (2) snapshot the instances list, then PASS 1 cancels each repo's index-heal (indexCancel) AND sync loop (syncCancel) so they wind down in PARALLEL; (3) PASS 2 waits indexWg THEN syncWg per repo (heal's activate() does syncWg.Add for the reconcile loop, so indexWg must settle first), then hub.Shutdown() + closeFn(). Two passes because cancelling everything up front lets loops wind down concurrently instead of serializing a cancel-wait roundtrip per repo. Returns nil; the error return matches io.Closer for forward compatibility. Callers MUST pair Start with Close.

WHAT THIS DOES NOT MEAN: the default repo is NOT 'knomit'/'knomit.db' — it is 'core'/core.db (config.go:20). Start does NOT launch a 'cluster-cache warmer' / startClusterChecker / clusterCheckerStop — that background Louvain goroutine was DELETED (commit d526c3e); the background goroutine Start launches today is the session reaper. Close pass-1 is NOT 'stop the cluster checker first'; it cancels index-heal + sync loops.

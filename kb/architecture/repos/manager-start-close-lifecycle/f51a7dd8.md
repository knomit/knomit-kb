# Manager.Start reads the control.db repo registry (no glob); Close is two-pass cancel-then-wait over index-heal+sync loops

**UPDATE (repo-registry-in-control.db, 2026-08): Start no longer globs `repos/*.db`.** It makes `<home>/repos/`, opens `<home>/control.db` twice — `OpenLensRegistry` (lens tables) and `OpenRegistry` (the `repos` table) — then builds one shared `*store.Crypt` from `m.deps.KeyPath` (a nil crypt on an unreadable key only disables credential STORAGE, logged at warn, never fails Start) and opens `OpenOrigins(repoReg.DB(), crypt)` on the registry's `*sql.DB` handle. It then calls `repoReg.List(StateActive)` and `m.openRegistered(rec)` for each row — existence and enumeration come from the registry, not the filesystem, so a repo's presence no longer depends on a filename. A repo that fails to open (`missing` file, `unopenable`, or root-commit `conflict`) is recorded via `markUnavailable` and STAYS VISIBLE instead of vanishing (see the 'stays visible' behaviour in internal/repos/manager.go openRegistered/Unavailable). `warnOrphanFiles` then flags any `<home>/repos/*.db` file not matched by a registry uid. Boot guard: if `repoReg.SchemaJustCreated()` is true (this OpenRegistry call created the `repos` table — never existed before) AND a stray `.db` is found in `repos/`, Start refuses with a message pointing at `knomit migrate-registry`; a schema that already existed but is currently empty (e.g. every repo purged) boots fine. Finally it launches the background idle-SESSION REAPER via m.startSessionReaper(parseSessionReaperConfig(cfg.Session)), storing its stop func in m.sessionReaperStop (a misconfigured [session] block fails Start at boot rather than silently disabling the reaper).

Manager.Close(): (1) stop the session reaper first (m.sessionReaperStop); (2) close the registry (`m.registry`) and repo-registry (`m.reg`) handles — `m.origins` shares `m.reg`'s `*sql.DB` and has no Close of its own; (3) snapshot the instances list, then PASS 1 cancels each repo's index-heal (indexCancel) AND sync loop (syncCancel) so they wind down in PARALLEL; (4) PASS 2 waits indexWg THEN syncWg per repo (heal's activate() does syncWg.Add for the reconcile loop, so indexWg must settle first), then hub.Shutdown() + closeFn(). Two passes because cancelling everything up front lets loops wind down concurrently instead of serializing a cancel-wait roundtrip per repo. Returns nil; the error return matches io.Closer for forward compatibility. Callers MUST pair Start with Close.

WHAT THIS DOES NOT MEAN: Start does not open a default repo first and then glob the rest — that two-step shape, the isDefault flag, and initDefaultGit were all removed (2026-08-07); see the no-default-repo invariant. There is no config.DefaultRepoName constant to consult. Start also does NOT launch a 'cluster-cache warmer' / startClusterChecker / clusterCheckerStop — that background Louvain goroutine was DELETED (commit d526c3e); the background goroutine Start launches today is the session reaper. Close pass-1 is NOT 'stop the cluster checker first'; it cancels index-heal + sync loops. Start does NOT glob `repos/*.db` to discover repos — that was the pre-control.db-registry behaviour; `Manager.Rescan` and the glob-based discovery loop are DELETED (retracted separately). Enforcing code: internal/repos/manager.go (Start, Close, openRegistered); internal/repos/registry.go (OpenRegistry, List, SchemaJustCreated); internal/repos/origins.go (OpenOrigins); internal/repos/session_reaper.go (startSessionReaper).

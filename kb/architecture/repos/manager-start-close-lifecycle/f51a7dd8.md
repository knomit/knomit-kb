# Manager.Start reads the control.db repo registry (no glob); Close sends Unmount to every repo's lifecycle Machine concurrently and waits for each

**UPDATE (repo-registry-in-control.db, 2026-08): Start no longer globs `repos/*.db`.** It makes `<home>/repos/`, opens `<home>/control.db` ONCE (`control.OpenRegistryNoSchema`, then `control.ControlUp` migrates it) and shares that single `*sql.DB` handle with the lens registry (`control.NewLensRegistry`), then builds one shared `*model.Crypt` from `m.deps.KeyPath` (a nil crypt on an unreadable key only disables credential STORAGE, logged at warn, never fails Start) and opens `control.OpenOrigins(repoReg.DB(), crypt)` on the same handle. It then calls `repoReg.List(StateActive)` and `m.openRegistered(rec)` for each row — existence and enumeration come from the registry, not the filesystem, so a repo's presence no longer depends on a filename. A repo that fails to open (`missing` file, `unopenable`, or root-commit `conflict`) is recorded via `markUnavailable` and STAYS VISIBLE instead of vanishing (see the 'stays visible' behaviour in internal/corpus/repos/manager.go openRegistered/Unavailable). `warnOrphanFiles` then flags any `<home>/repos/*.db` file not matched by a registry uid. There is no stray-file boot guard any more: `SchemaJustCreated` and the `knomit migrate-registry` refusal no longer exist, and `warnOrphanFiles` only reports (never refuses on) a `.db` file with no registry row. Finally it launches the background idle-SESSION REAPER via m.startSessionReaper(parseSessionReaperConfig(cfg.Session)), storing its stop func in m.sessionReaperStop (a misconfigured [session] block fails Start at boot rather than silently disabling the reaper).

Manager.Close(): (1) stop the session reaper (m.sessionReaperStop); (2) drain detached repo creates (drainCreates) and wait for the boot fleet reconcile (fleetBootWg), both before control.db closes; (3) close the lens registry (a no-op, it borrows the handle) and the repo registry `m.reg`, which owns the single control.db handle that `m.origins` also borrows; (4) send Unmount to EVERY repo's lifecycle Machine concurrently (Unmount cancels that machine's root context from the caller's goroutine before queueing, so all repos wind down at once) and wait for each, bounded by the unmount drain bound (default 30 s). Returns nil today; the error return matches io.Closer for forward compatibility. Callers MUST pair Start with Close.

WHAT THIS DOES NOT MEAN: Start does not open a default repo first and then glob the rest — that two-step shape, the isDefault flag, and initDefaultGit were all removed (2026-08-07); see the no-default-repo invariant. There is no config.DefaultRepoName constant to consult. Start also does NOT launch a 'cluster-cache warmer' / startClusterChecker / clusterCheckerStop — that background Louvain goroutine was DELETED (commit d526c3e); the background goroutine Start launches today is the session reaper. Close is NOT 'stop the cluster checker first'; it unmounts every repo's lifecycle Machine, which stops that repo's index and sync lives. Start does NOT glob `repos/*.db` to discover repos — that was the pre-control.db-registry behaviour; `Manager.Rescan` and the glob-based discovery loop are DELETED (retracted separately). Enforcing code: internal/corpus/repos/manager.go (Start, Close, openRegistered); internal/corpus/repos/control/registry.go (OpenRegistryNoSchema, ControlUp, List; the registry, origins and lens code moved into package control at merge 6c0f1a78); internal/corpus/repos/control/origins.go (OpenOrigins); internal/corpus/repos/session_reaper.go (startSessionReaper).

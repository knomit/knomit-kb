# An experiment's "activity" is any commit on it, recorded at the notifyCommit chokepoint, and experiments.expiry_days = 0 stops the sweeper STARTING rather than sweeping with a zero-length window

Activity is defined ONCE, because it is recorded in one place: touchExperimentActivity hangs off notifyCommit, the single chokepoint every ref mutation already passes through (invariants/store/notify-commit-single-chokepoint). It short-circuits on the `exp/` prefix, so every other branch's every commit pays one string compare. A sync counts as activity because it commits; a write on the PARENT does not.

The loop copies the local reconcile's shape (invariants/store/local-reconcile/never-reset-never-exit): it ticks once at start, recomputes the cutoff fresh each tick, logs and retries on error, and exits only on ctx cancel. A sweeper that returned on a DB error would stop expiring for the life of the process and nothing would look wrong — experiments would simply accumulate, which is indistinguishable from a busy user. It reports what it dropped AND the error, because ExpireExperiments can return both.

expiry_days = 0 means NEVER, and the loop does not start at all. Rolling an experiment back is irreversible (there is no archive), so "no policy configured" must never resolve to a cutoff of `now`, which would expire every experiment in the repo on the first tick. A negative value fails at boot in Config.Validate for the same reason. Subscriptions are skipped: no agent branch, so no experiment can be forked from one.

The sweep CADENCE is deliberately NOT a setting — defaultExperimentSweepInterval (1h) in internal/repos, passed as a parameter so the loop's error path stays testable at millisecond ticks. Tests that need a short tick on a real Manager use the test-only seam experimentSweepIntervalOverride (atomic, read when a sweeper starts); production never sets it. How stale is too stale is the operator's policy; how promptly we notice is not.

LIFETIME (rewritten for issue #411). experimentSweeper (internal/repos/experiment_sweep.go) is built in Manager.newInstance only when the repo is not a subscription and experiments.expiry_days > 0 (ri.sweep is nil otherwise). It is started and stopped by the Serve stage's Life: Serve.Enter calls life.Go("experiment-sweep", s.run) unless Options.Synchronous is set; it exposes run(ctx) only. An origin attach or detach restarts Sync, not Serve, so it never stops the sweep (the issue #377 bug — the sweep sharing syncCtx and dying on every attach — cannot recur); a SwapStore rewinds to Open and restarts Serve with the rest.

Store access: the loop holds NO *store.Service. Each tick calls the acquire func (ri.Acquire) and releases before returning on every path; a failed acquire (ErrStoreUnavailable, ErrRepoClosed) is a failed tick — logged as 'experiment sweep: failed; will retry next tick', never an exit. Regression test: TestExperimentSweep_StoreUnavailableIsATickNotAnExit (experiment_sweep_test.go).

# TaskHub.Start enforces AT MOST ONE active task per op; second call returns error (409 via handler)

TaskHub.Start(op, fn) enforces AT MOST ONE active task per op name: the second Start('sync') returns an error (the HAL handler converts to 409 Conflict). Internal state: active map[string]TaskEvent (op → latest running event) and lastDone map[string]TaskEvent (op → last terminal event for snapshot replay). Task IDs are generated as <op>-<counter> (e.g. synth-1, synth-2, sync-1). The emit function captures op + id, marks terminal events (status=='done' or 'error') to update lastDone + delete from active + cancel the task ctx. Termination is IDEMPOTENT via terminated bool + termMu — a panicking task's recover() also calls emit(error), so double-terminal is safe. Panic recovery wraps fn so a crashing task emits an error event and the server stays up. Subscribe atomically registers a subscriber AND collects the current snapshot (active + lastDone, EXCLUDING active ops from lastDone) so reconnecting SSE clients see the correct UI state immediately.

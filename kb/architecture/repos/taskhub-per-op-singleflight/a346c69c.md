# TaskHub.Start enforces AT MOST ONE active task per op; second call returns error (409 via handler)

TaskHub.Start(op, fn) enforces AT MOST ONE active task per op name: the second Start('sync') returns an error (the HAL handler converts to 409 Conflict). Internal state: active map[string]TaskEvent (op → latest running event) and lastDone map[string]TaskEvent (op → last terminal event for snapshot replay). Task IDs are generated as <op>-<counter> (e.g. synth-1, synth-2, sync-1). The emit function captures op + id; for a terminal event (status=='done' or 'error') it records the terminal (delete from active and cancels, set lastDone) under h.mu BEFORE publishing it, then cancels the task ctx - the order publishTask uses. Publish-first let a Subscribe see the task still running and never receive its end, hanging a per-job stream (PR #623 F1; regression TestTaskHub_SubscribeRacingATerminalNeverMissesIt). Termination is IDEMPOTENT via terminated bool + termMu — a panicking task's recover() also calls emit(error), so double-terminal is safe. Panic recovery wraps fn so a crashing task emits an error event and the server stays up. Subscribe atomically registers a subscriber AND collects the current snapshot (active + lastDone, EXCLUDING active ops from lastDone) so reconnecting SSE clients see the correct UI state immediately.

Reads used by the web job routes: Task(id) (the op's running task or its last terminal event), Tasks(op) (running first, then last terminal; at most two, none before the first run) and Cancel(id) (cancels only the op's RUNNING task that the hub itself started via Start; a publishTask-recorded rebuild is refused and is cancelled through CancelIndex instead; the task is still running when Cancel returns). The hub keeps no pending state and no older history.

MOVED (14b, PR #631, merge 37dc65d5, re-read there): TaskHub now lives in internal/corpus/repos/events (events/hub.go, test events/hub_terminal_order_test.go), unchanged in behaviour. Start, Subscribe, Task, Tasks and Cancel are on the consumer-facing *events.TaskHub; the methods that record a task the hub did not Start (PublishTask), cancel everything (CancelTasks) and Shutdown are on events.TaskPublisher, held only by the repos parent (kb/decisions/repos/events/hub-publisher-split/f6d5c104.md). The single-flight therefore cannot be wedged by a phantom running entry from outside repos.

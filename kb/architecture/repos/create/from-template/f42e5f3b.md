# Create from a template (F24): mode "template" (local) or "initialize" with template {repo, name} reads .knomit/templates/<name>/ at the SOURCE repo's consensus tip and writes it as ONE signed commit on the new repo's agent branch, on top of the usual unsigned root commit

WHAT HAPPENS. `POST /api/v1/repos` takes `template: {repo, name}` as the third ontology source beside `ontology_preset` and `ontology_yaml`. Mode `template` (a LOCAL create, no origin) requires it and refuses the other two; mode `initialize` takes exactly one of the three; `preset`/`custom` refuse it; `clone`/`subscribe` refuse it through `rejectOntologySpecForClone` (validateOntologySources, lifecycle.go).

1. `template.repo` is a repo NAME resolved with `Manager.Get` (an active repo on this instance; unknown, archived or a lens name is ErrTemplateSourceNotFound). The source store is held through `Acquire` for the whole read, never kept.
2. The tree is read at `UpstreamTip(UpstreamBranch())` of the source: its consensus branch, or the followed branch of a subscription. Never its agent branch or an experiment (TestCreateFromTemplate_ReadsConsensusNotAgent).
3. `ResolveTemplate` checks it (refusals: kb/invariants/repos/create/template-refusals). `CreatePreflight` runs it so every refusal is a status before the 202; `populate` re-runs it and the commit IT read is the one recorded.
4. Local: `InitRepo(ctx, nil, agent)` makes the unsigned root commit exactly as every local create does (README.md, nonce), then `writeTemplate` writes every template file in ONE commit through `Service.WriteSystemTree` on the agent branch, with `SetSigner(m.deps.Signer)` so it is signed by THIS instance. The template's README.md replaces knomit's root manifest in that commit. The consensus branch follows through the local reconcile, like any origin-less repo.
5. Initialize: the single ontology `WriteFact` is replaced by the same one-commit write on the agent branch; the rest of initialize is unchanged (refused when the branch already has an ontology; files at the same path are replaced on the agent branch only; the remote's consensus branch is never written; the agent branch is pushed). User ruling 2026-10-07: initialize + template follows today's initialize rules exactly, no new collision rule.

CONSEQUENCE: a repo created from a template is ordinary afterwards: nothing links it back except the provenance trailers on that one commit (kb/decisions/repos/create/template-provenance).

MISREADING: 'read at the consensus tip' does NOT mean the search index: the index is per branch and on a writable mount it is the agent branch; both the create and the listing read git at the tip.

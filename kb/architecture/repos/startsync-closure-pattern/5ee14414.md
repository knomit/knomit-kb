# ri.startSync runs synchronous reconcile FIRST so credential errors surface immediately

ri.startSync(remoteURL) is a closure built in repoBuilder.build() that captures ri, cfg, keyPath, ctx, name, agentBranch. When invoked (e.g. via ActivateSync from the HAL handler): (1) reads current svc under RLock; (2) reads remote record via svc.Remote().GetRemote('origin'); (3) cancels the existing sync loops + waits; (4) creates a new sync ctx + replaces ri.syncCancel under withWrite; (5) re-applies ri.onCommit to currentSvc; (6) runs ONE SYNCHRONOUS reconcile — FAIL-FAST: if reconcile errors, return error to the HAL handler so the HTTP response surfaces a bad token (or unreachable origin) IMMEDIATELY. The loops are NOT started on failure — user must retry SetRemote (typically with fixed credentials); (7) starts new background loops via startSyncLoops. The closure captures ri-the-pointer so it always sees the current svc after SwapStore. Anti-pattern: starting new loops without a synchronous reconcile first — credential errors wouldn't surface until the next background tick (silent failure).

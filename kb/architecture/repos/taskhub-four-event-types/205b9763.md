# TaskHub publishes 4 event types via goob: TaskEvent, StatusEvent, SyncEvent, PushEvent

TaskHub broadcasts FOUR distinct event types via goob.Observable: (1) TaskEvent (Op + ID + Status + Phase + Message + Repo — for synth/sync long-running tasks); (2) StatusEvent (Head — for HEAD changes from the commit observer); (3) SyncEvent (Remote + Status 'sync_ok|sync_error' + Main *MainReconcileResult + Agent *AgentReconcileResult + Error — used by SSE clients to render sync outcomes per-side: main fast-forward/rewound, agent merge/ff/rebase/noop, instead of collapsing both into a single merge-commit hash); (4) PushEvent (Remote + Status 'push_ok|push_error' + Error). SSE handlers type-switch on the published value to write the appropriate event: line. Anti-pattern: collapsing sync outcomes into a single string field — clients can no longer distinguish 'main fast-forwarded' from 'agent merged' which carries different UX meaning. broadcastStatus / broadcastSyncOK / broadcastSyncError / broadcastPushOK / broadcastPushError are the unexported emitters; only the package-internal callers (observer, sync loop) trigger them.

MOVED (14b, PR #631, merge 37dc65d5, re-read there): the file is now internal/corpus/repos/events/hub.go (package events). The four event types are unchanged (JSON tags byte-identical), but the lowercase broadcast helpers named above are now EXPORTED methods of events.TaskPublisher (BroadcastStatus, BroadcastSyncOK, BroadcastSyncError, BroadcastPushOK, BroadcastPushError, plus BroadcastIndex and BroadcastTrigger), reachable only from the repos parent; consumers of *events.TaskHub can Subscribe but not broadcast (kb/decisions/repos/events/hub-publisher-split/f6d5c104.md).

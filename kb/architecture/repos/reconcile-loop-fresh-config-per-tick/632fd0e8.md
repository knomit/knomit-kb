# runReconcileLoop re-reads remote config FRESH every tick; 5 consecutive failures escalate WARN→ERROR

runReconcileLoop re-reads svc.Remote().GetRemote('origin') FRESH on every tick so DB-stored config changes (auth update, interval change) are picked up on the NEXT tick without restarting the loop. The initial config read at loop start is only for log context — the actual sync uses the fresh record. Failure escalation: reconcileFailureEscalateThreshold = 5 consecutive failures escalate the log line from Warn to Error (a repo stuck on revoked credentials otherwise looks identical to a healthy one after log rotation drops the early warns). The counter resets to 0 on first success after failures, with an 'after_failures' log line so operators can see recovery. Order within a tick: Sync runs FIRST, then Push. On sync success, hub.broadcastSyncOK fires with the full SyncResult (Mode discriminators included) when either branch moved or when the previous persisted status was an error (shouldBroadcastSyncOK: the recovery edge). syncFails and pushFails are INDEPENDENT counters — each escalates on its own consecutive-failure streak.

WHAT THIS DOES NOT MEAN: a Sync error does NOT skip the Push. The sync-error branch in doTick logs and increments syncFails but does NOT return — execution falls through and Push still runs, gated by pushAllowed(readOnly, agentBranch) and the push circuit breaker (pushDue = canPush && pushBrk.allow), never by the fetch outcome. Do not assume a failed pull suppresses the push attempt. What skips BOTH Sync and Push: an AUTH-RESOLUTION failure (charged to the fetch breaker), a local-origin policy block, a nil or failed fresh remote read, both breakers open, and a tick abandoned by the loop's own cancellation (tickAbandoned: nothing counted, no push). No line numbers are cited here; the sync.go ref is pinned at the merge commit.

A MISSING OR UNREADABLE REMOTE SKIPS THE TICK; THE LOOP NEVER EXITS ON IT (issue #411). Before the lifecycle machine, a nil fresh remote read made the loop return (sync.go's `if remote == nil { return }`), silently ending sync for the life of the process. Now a failed per-tick read logs and skips the tick ('reconcile tick: remote read failed; skipping tick'), a nil one skips silently, and the between-tick wait logs and falls back to the default wait ('reconcile loop: remote read failed; skipping to the next tick' / 'the repo has no remote; skipping to the next tick'); the loop ends only on its Sync life's ctx. Which loop runs is decided at Sync.Enter; an origin change is an Attach/Detach event that restarts Sync.

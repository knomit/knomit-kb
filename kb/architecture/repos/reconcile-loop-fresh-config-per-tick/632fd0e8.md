# runReconcileLoop re-reads remote config FRESH every tick; 5 consecutive failures escalate WARN→ERROR

runReconcileLoop re-reads svc.Remote().GetRemote('origin') FRESH on every tick so DB-stored config changes (auth update, interval change) are picked up on the NEXT tick without restarting the loop. Initial config read at loop start is only for log context — the actual sync uses the fresh record. Failure escalation: reconcileFailureEscalateThreshold = 5 consecutive failures escalate the log line from Warn to Error (a repo stuck on revoked credentials otherwise looks identical to a healthy one after log rotation drops the early warns). Counter resets to 0 on first success after failures, with an 'after_failures' log line so operators can see recovery. Sync runs FIRST, then Push — push doesn't fire if sync errored (no point pushing if we couldn't pull). On sync success with mainChanged OR agentChanged, hub.broadcastSyncOK fires with the full SyncResult including Mode discriminators.

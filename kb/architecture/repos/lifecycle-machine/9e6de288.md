# Every mounted repo is driven by ONE per-repo lifecycle Machine: foundation stages Populate→Open→Identify, worker stages Index→Serve→Sync, external events with guard+apply, one driver goroutine, status as a projection published at one point

internal/corpus/repos/machine.go, stages.go, events.go (issue #411). Replaces repoBuilder (build/activate/startSync), ActivateSync/StartLocalSync/DeactivateSync, Manager.SwapStore, lifetimeGuard, the index mark* cell, DisableBackgroundSync and indexHealGate.

STAGES. Foundation stages (Populate, Open, Identify) do their work inside Enter; an Enter error makes the repo Unavailable (StageError, which unwraps to ErrUnavailable and the cause). Worker stages (Index, Serve, Sync) launch background work with Life.Go and return at once. A Life is a ctx + WaitGroup + generation; a panic inside Life.Go posts `crashed`. Open.Enter is the ONE wiring function for first open and every reopen (store.Open, network timeout, ontology root, read-only, origin from control.db, embedder, signer, accept list, own keys, OpenRepo, observer, SetOnCommit, attach). Index plans a heal or runs a full rebuild and posts indexDone; Serve runs the trigger dispatcher, the consensus merger and the experiment sweeper via their run(ctx); Sync runs the reconcile loop the origin selects.

EVENTS. External: Mount, AttachOrigin, DetachOrigin, SwapStore, Rebuild, CancelIndex, Unmount — each has a guard (may read the network, bounded by cfg.Git.NetworkTimeout) and an apply. A foundation target rewinds every stage at or above it: SwapStore targets Populate, entered with mount mode none (MountExisting), so Populate does nothing and Open reopens what the apply left on disk; a worker target (Attach/Detach → Sync, Rebuild → Index) restarts only that stage. Internal events (indexDone, indexProgressed, crashed, drained, reenter) arrive through an unbounded mailbox, so a post never blocks or drops.

DRIVER RULES. One event at a time. Send answers cheap refusals from the status snapshot first (ErrClosed, ErrUnavailable, ErrNotOpen, ErrIndexing). exitStages cancels all affected lives then drains newest-first (kb/invariants/repos/lifecycle/exit-cancels-all-then-drains). The driver never waits on background work: crash restart goes through a waiter goroutine (kb/decisions/repos/lifecycle/crash-restart-via-waiter). No stage Sends to its own machine (kb/invariants/repos/lifecycle/no-stage-sends-to-own-machine). Options.Synchronous is consulted only in Serve.Enter (no sweep), Sync.Enter (one inline round, no loop) and computeStatus (Sync.Running reads false). Unmount cancels the root ctx from the caller's goroutine before queueing, so a Populate clone aborts at once.

STATUS. computeStatus derives Stage, Index{State, Done, Total, Reason}, Serve/Sync from the cursor, the lives and the Index verdict; publish() stores the snapshot, emits the IndexEvent and the rebuild TaskEvent, then wakes watchers, all under the broadcaster lock that a new Watch takes for its first value. No event goes out once the machine is closed, and unmount itself never calls publish: it stores the final status directly and closes the watchers with it left readable. Readers (HTTP, create job) only observe.

Manager.Close sends Unmount to every machine concurrently, bounded by UnmountDrainBound (30 s); DefaultCrashBackoff is 5 s. Both are class-2 budgets.

What this does NOT mean: the machine does not make indexing gate anything — request paths never wait on index readiness (see kb/decisions/repos/index/accepted-partial-index-degradation and kb/decisions/repos/lifecycle/indexing-exclusive-with-attach-detach-swap).

SWAP APPLY ORDER (PR #414 review): the irreversible step is last — read the stored origin row, back up the store, save the new origin (reversible), then copy the new database in. A failed save aborts with nothing changed; a failed copy restores the backup and the previous origin row. There is no 'warning' reply: Reply carries JobID, Absorbed and Status only. The Sync stage holds its store Acquire for the life of its loop (released when the loop returns), like the index job.

STATUS TYPES SINCE 14b (PR #631, merge 37dc65d5, re-read there): the Status and IndexStatus named above are now events.Status and events.IndexStatus (internal/corpus/repos/events/status.go), the PUBLIC projection that Machine.Status() returns and callers outside the machine read. The machine's bookkeeping (open, terminal, job, jobFull, phase, gens) is in the unexported repos.snapshot, which embeds events.Status; Transition embeds snapshot. computeStatus and publish are unchanged in shape; publish and unmount reach the hubs through the publisher (pub.PublishTask for the rebuild task, m.r.pub.Shutdown in unmount, which still publishes nothing).

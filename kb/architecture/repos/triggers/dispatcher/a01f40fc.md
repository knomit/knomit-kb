# The trigger dispatcher is one actor per writable repo with its OWN context, kicked by a non-blocking send from ri.onCommit filtered to the agent branch; a run is phase A (Acquire: head, ontology-at-head, watermarks, one DiffFacts per watermark, glob match, change built once per matched path), phase B (no store: if + emit), phase C (Acquire: two short transactions)

internal/repos/triggers.go (F07 PR 1b). The write path does no trigger work: the ONLY addition to the commit observer closure `ri.onCommit` (internal/repos/builder.go) is `if branch == agentBranch { ri.triggerKick() }`, a `select { case kick <- struct{}{}: default: }` on a 1-slot channel. The channel IS the coalescing pending flag: a second kick while one is pending merges into it, and the send never blocks the writer (it runs under the writer's branch lock inside store notifyCommit). main and exp/* never kick, so an experiment's writes fire only when CommitExperiment merges them into the agent branch.

The dispatcher is built in repoBuilder.build() (so the kick slot exists during the background heal) and STARTED in activate() after the initial index, with its own ctx derived from the manager ctx and its own WaitGroup — never syncCtx, which ActivateSync cancels to restart the reconcile loop (the experiment sweep shares syncCtx and dies on every origin attach; the dispatcher must not). It is NOT built at all when cfg.ReadOnly, when the repo is a subscription, or when there is no agent branch: ri.triggers is nil and the kick is a nil check. shutdown() stops it (cancel + wait) after the sync loops and before closeFn closes the store. It runs regardless of DisableBackgroundSync: it writes no ref and no fact. It self-kicks once at start so advances made while the server was down fire on restart (at-least-once via the watermark).

The kick is RECEIVED before the head ref is read (`for { select ctx / kick → run } }`): the reverse order would swallow the kick of a commit landing between the ref read and the drain — the F06 lost-wake-up shape. A run is level-triggered: it processes watermark → CURRENT head, so coalesced advances are diffed once and nothing is lost.

Phase A (Acquire): head; the ontology file at that head (TriggerIndex.OntologyAtCommit, the first of fact.OntologyPathsNewestFirst that is a file) → fact.TriggerCache.Get by blob (an unparseable head keeps the last good set and logs ERROR once per blob); ERROR once per name@blob for each invalid trigger; the watermarks; ONE IsAncestor(W, head) per distinct watermark decides linear vs nonlinear; ONE DiffFacts(W, head) per distinct watermark (normally all triggers share one W, so one diff per advance); each row is matched in memory against the triggers of that W (OnEpisode && Matches on the root-relative path); for a row with at least one match `change` is built ONCE and shared by every trigger that matched it, timed as knomit's cost (change_ms), not the trigger's. Release. Phase B (no store): per (trigger, path), ctx checked per path, EvalIf then emit, timed as the trigger's own work. Phase C: write-behind, flushed in tx1 (fire rows + one run row per run) then tx2 (watermarks + prune) — see the write-behind fact.

Misreadings: (a) 'the dispatcher runs per commit' — no, per kick, and kicks coalesce; an add-then-delete between two runs fires nothing (F05 net semantics on purpose). (b) 'a long if delays SwapStore or teardown' — no, phase B holds no Acquire; ctx is checked per evaluation so stop returns within one 100 ms evaluation. (c) 'the dispatcher reads ri.Ontology()' — never; triggers come from the ontology at the head of the agent branch, cached by blob (D-b), while validations keep the open-time snapshot.

# The trigger dispatcher is one actor per writable repo with its OWN context, kicked by a non-blocking send from ri.onCommit filtered to the agent branch; a run is phase A (Acquire: head, ontology-at-head, watermarks, one DiffFacts per watermark, glob match, change built once per matched path), phase B (no store: if + emit), phase C (Acquire: two short transactions)

internal/repos/triggers.go (F07 PR 1b). The write path does no trigger work: the ONLY addition to the commit observer closure `ri.onCommit` (built once in Manager.newInstance) is `if branch == agentBranch { ri.triggerKick() }`, a `select { case kick <- struct{}{}: default: }` on a 1-slot channel. The channel IS the coalescing pending flag: a second kick while one is pending merges into it, and the send never blocks the writer (it runs under the writer's branch lock inside store notifyCommit). main and exp/* never kick, so an experiment's writes fire only when CommitExperiment merges them into the agent branch.

LIFETIME (rewritten for issue #411). The dispatcher object is built in Manager.newInstance (so the kick slot exists from the first commit, including during the index) and is STARTED and STOPPED by the Serve stage's Life: Serve.Enter calls life.Go("triggers", d.run); the dispatcher exposes run(ctx) only and returns when that ctx is cancelled (flushing phase C first). An origin attach/detach restarts Sync, not Serve, so it never touches the dispatcher; a SwapStore rewinds to Open and so restarts Serve with the new store. It is NOT built when cfg.ReadOnly or when there is no agent branch (a subscription has none): ri.triggers is nil and the kick is a nil check. It runs under Options.Synchronous too: it writes no ref and no fact. It self-kicks once at start so advances made while the server was down fire on restart (at-least-once via the watermark).

INDEX GATE. The `on: due` sweep reads index tables (branch_facts ⋈ fact_expires), so a run skips sweepDue while the repo's index state is not `ready` (the indexReady func, reading ri.Status()); advances still fire. The Index job's successful indexDone kicks the dispatcher (handleInternal calls r.triggerKick()), so a due sweep skipped during indexing runs as soon as the index is ready.

The kick is RECEIVED before the head ref is read (`for { select ctx / kick → run } }`): the reverse order would swallow the kick of a commit landing between the ref read and the drain — the F06 lost-wake-up shape. A run is level-triggered: it processes watermark → CURRENT head, so coalesced advances are diffed once and nothing is lost.

Phase A (Acquire): head; the ontology file at that head (TriggerIndex.OntologyAtCommit, the first of fact.OntologyPathsNewestFirst that is a file) → fact.TriggerCache.Get by blob (an unparseable head keeps the last good set and logs ERROR once per blob); ERROR once per name@blob for each invalid trigger; the watermarks; ONE IsAncestor(W, head) per distinct watermark decides linear vs nonlinear; ONE DiffFacts(W, head) per distinct watermark (normally all triggers share one W, so one diff per advance); each row is matched in memory against the triggers of that W (OnEpisode && Matches on the root-relative path); for a row with at least one match `change` is built ONCE and shared by every trigger that matched it, timed as knomit's cost (change_ms), not the trigger's. Release. Phase B (no store): per (trigger, path), ctx checked per path, EvalIf then emit, timed as the trigger's own work. Phase C: write-behind, flushed in tx1 (fire rows + one run row per run) then tx2 (watermarks + prune) — see the write-behind fact.

Misreadings: (a) 'the dispatcher runs per commit' — no, per kick, and kicks coalesce; an add-then-delete between two runs fires nothing (F05 net semantics on purpose). (b) 'a long if delays a SwapStore or Unmount' — no, phase B holds no Acquire; ctx is checked per evaluation so the Serve life drains within one 100 ms evaluation. (c) 'the dispatcher reads ri.Ontology()' — never; triggers come from the ontology at the head of the agent branch, cached by blob (D-b), while validations keep the open-time snapshot.

UPDATE (F07 PR 2, branch feat/f07-due): phase A has a second half. After the advance (the tree diff per watermark) the SAME run sweeps `on: due`: the liveness join branch_facts(agent) ⋈ fact_expires at the run's clock (read once, UTC), glob → marks → head confirmation → `change` per path (sweepDue; kb/architecture/repos/triggers/due-sweep). Phase C's tx2 now carries the due marks (trigger_due_fires, migration 000030) next to the watermarks, and the overlay applies them too. The kick has a second source: the reconcile tick (both loops) kicks the dispatcher on every tick (kb/architecture/repos/triggers/tick-kick), so a run happens without a write; a run that evaluated nothing writes no run row. The three-phase shape, the own context and the non-blocking kick are unchanged.

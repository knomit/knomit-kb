# The reconcile tick KICKS the trigger dispatcher instead of the sweep having a timer: `defer kick()` is the FIRST statement of runReconcileLoop's doTick (so every early return — remote unreadable, blocked origin, auth failure, abandoned sync, failed push — still kicks) and the local loop kicks unconditionally on every ticker tick before it reads the origin or advances; both loops take a nil-safe `kick func()` that the Sync stage (stages.go) wires to r.triggers.Kick

F07 PR 2, M3. Why a kick and not a timer: the design forbids a new timer (asynchrony ruling: 'the sweep runs on the existing reconcile tick'); a sweep inside doTick would run on syncCtx (killed by ActivateSync), be absent wherever the loops are absent, and sit next to a lockBranch(agent) holder; the dispatcher already has its own goroutine, context and phases. So the tick does what a write does: one non-blocking send on the dispatcher's 1-slot channel, and the dispatcher's next run sweeps.

Placement is the whole point. runReconcileLoop(..., kick func()): `if kick != nil { defer kick() }` is the first statement of doTick, BEFORE the remote read and every early return (remote read failed, remote gone, origin blocked by the local-origin policy, auth resolution failed, sync abandoned, push abandoned, push failed) — an offline laptop fails its push on EVERY tick and returns early; the sweep needs no network, so it must not depend on the tick's outcome. runLocalReconcile(..., kick func()): kickTriggers() runs once after the start and then FIRST in every `case <-t.C`, before ownsMain() and before advance(), so a failing advance or an unreadable origin row never silences the sweep. Both loops accept nil (unit tests of the loops).

Wiring: the Sync stage's Enter (internal/corpus/repos/stages.go) passes r.triggers.Kick to both loops (nil-safe on an instance without a dispatcher: read-only server, subscription: Dispatcher.Kick returns on a nil receiver and ri.triggers is never reassigned after newInstance, so the method value binds the same pointer the old r.triggerKick method read). The kick coalesces with write kicks (the channel is the pending flag), so a tick during a run merges into the pending kick and the next run sweeps. Under machine Options.Synchronous (formerly Deps.DisableBackgroundSync) the Sync stage runs one inline round and starts no loop, so there are no periodic ticks: test harnesses kick by hand (ri.triggers.Kick(), as kickAndWait in triggers_due_test.go does), as the 1b tests do; the dispatcher's own start kick still runs the first sweep at boot, so facts that came due while the server was down fire on restart.

Lateness bound: a due fire lands on the first run after the instant — the next write on the agent branch or the next tick (30 s default for an origin-less repo, config.Git.LocalReconcileInterval; the remote's Interval, default 300 s, otherwise), whichever comes first. Not seconds-exact by design.

Sabotages that redden the tests: move the defer below doTick's early returns (TestDue_SweepRunsOnReconcileTick_FailedRemoteTick, which fails auth resolution on every tick); make the local kick conditional on advance() == nil (TestDue_SweepRunsOnReconcileTick_FailedLocalTick); remove the kick (TestDue_SweepRunsOnReconcileTick, background sync ON with a 100 ms interval, a fact comes due with no write). The dispatcher allowlist (internal/corpus/repos/trigger/triggers_guard_test.go since 14c, PR #632, merged as ee850fd6) forbids time.After/time.NewTicker in trigger/triggers.go but lists time.NewTimer (the flush grace), so the guard alone does not prove 'no new timer'; the tick tests and review do.

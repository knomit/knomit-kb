# Trigger statistics live in memory per repo per trigger (evaluations, fires, outcomes by kind, slow, and the duration of the trigger's OWN work as exact count/min/max plus a p95 over the last 1,024) and are exposed ONLY on GET /api/v1/repos/{repo}/branches/{branch}/triggers; the slow-trigger detector logs WARN "slow trigger" when if+action exceeds [log].slow_trigger_ms (default 50, env KNOMIT_LOG_SLOW_TRIGGER_MS, 0 disables), never charging the change build

internal/corpus/repos/trigger_stats.go, internal/corpus/repos/triggers.go phaseB, internal/edge/web/handlers_triggers.go, internal/foundation/config/config.go LogConfig.SlowTriggerMS.

WHAT IS TIMED (R2-2): per (trigger, path) evaluation, ONLY the trigger's own work — its `if` plus its action (emit in PR 1; later PRs add their actions to the same timer). Building `change` (the toucher walk, the signature check, the trailer read) depends only on the path, is done once per matched path shared by every trigger that matched, and is reported separately as change_ms on the run row and the run statistics — it reaches 72 ms on real knomit-kb merges and must not make an innocent trigger read as slow (TestDispatch_ChangeCostNotChargedToTrigger). The diff is timed as diff_ms.

STATISTICS (triggerStats, reset on restart like the metrics registry; the fire log is the durable record): per trigger evaluations, fires (emitted + unparseable), if_false, if_error, if_timeout, unparseable, slow; duration count, min_ms, max_ms exact since start, p95_recent_ms over a ring of the last 1,024 evaluations with p95_window: 1024 shown beside it (nearest-rank; an exact since-start p95 would need every sample forever; TestDispatch_P95MovesWithASlowTrigger: 4 slow of 44 puts the p95 on a slow sample). Run statistics: runs and the last run's range, paths, evaluated, fires, duration_ms, diff_ms, change_ms. Updated only by the dispatcher goroutine under a small mutex REST reads also take.

EXPOSURE (user ruling D-d, 2026-09-27): GET …/branches/{branch}/triggers ONLY — no `triggers` block in …/stats, no `knomit triggers stats` CLI, no Prometheus counters (label values would come from repo content). The body: enabled/reason (false on a read-only server or a subscription), branch (the observed agent branch whatever branch is in the URL), head, ontology_blob, runs, triggers[] {name, node, match (after substitution for an active trigger), on, do, state active|invalid|frozen|unsupported, error, watermark, stats}, fires (the newest ?log=N rows, 0–500), _links self/events. The branch root links it as `triggers` (templated {?log}).

SLOW DETECTOR: modelled on metricsMiddleware's "slow request": when slow > 0 and elapsed > slow, one log.Warn with repo, branch, trigger, path, episode, commit (8 hex), outcome, Dur elapsed, Dur threshold, change_ms as context, message "slow trigger"; the trigger name and path are capped at 256 bytes like the request log's client fields; the trigger's `slow` count increments. Threshold: LogConfig.SlowTriggerMS, TOML [log].slow_trigger_ms, env KNOMIT_LOG_SLOW_TRIGGER_MS, default 50 for a STRUCTURAL reason (the sandbox caps an if at 100 ms, so half the budget is worth naming; the request default of 1000 could never fire), 0 disables. The dispatcher reads it from Deps.Cfg (repoBuilder.cfg.Log.SlowTriggerMS), never a constant. A test manager built with a zero config.Config has it disabled.

EMIT: a log.Info line "trigger fired" (repo, branch, trigger, episode, source, path, commit, trace) plus repos.TriggerEvent published straight to the per-repo TaskHub (broadcastTrigger) — NOT through the 1 s debounced observer, so it arrives within the run under steady writes (TestDispatch_EmitReachesStreamWithoutDebounce, 500 ms under 150 ms writes). The branch SSE handler forwards it as `event: trigger` with {trigger, path, episode, source, commit, trace} ONLY to the stream of the branch it happened on (TestSSE_TriggerOnlyOnItsBranchStream); the repo-wide /repo-events stream is untouched.

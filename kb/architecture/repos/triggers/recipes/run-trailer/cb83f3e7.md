# A recipe's own writes (knomit.learn/update/retract from the recipe) carry `Knomit-Run: <run id>` after Knomit-Trace/-Cause/-Trigger, the same run id as the fire's `started` and result rows, KNOMIT_RUN and run.id — so `git log --all --grep='^Knomit-Run: <id>'` finds everything one run wrote (#349 decision 4)

User decision 4 on #349 (verbatim): "sure, stamp." The recipe host builds its ctx with store.WithTrailers(Trailers{Trace: j.p.trace, Cause: j.p.commit, Trigger: j.p.trig.Name, Run: j.id}) in execRecipe (internal/repos/trigger_recipe.go); appendTrailers writes Run after Trigger. A plain `do: script` fire's writes carry NO Knomit-Run (a script is not a run; knomit.run from a script returns a run id but the script's own writes are not part of it). The session a recipe starts gets the run id only through its prompt, and its writes carry Knomit-Run only if it passes the MCP `trace` argument (kb/architecture/mcp/write-tools/trace-argument/9512adc3.md). The sample recipes (examples/recipes/claude-session.js, examples/mission/.knomit/recipes/work-task.js) put {Knomit-Cause: change.commit, Knomit-Run: run.id, Knomit-Trace: change.trace} in the prompt as a JSON literal, and include Knomit-Trace ONLY when it matches /^[A-Za-z0-9._:-]{1,256}$/: a trace can be a task's entity or a copied-forward toucher value (author text), and the mission rule is that task text never enters the prompt. Pinned by TestRun_RecipeWritesStampedAndGuarded, TestSampleRecipe_ArgvHasPathNotBody (a non-plain trace is left out) and TestMission_OneTaskTwoClaimersOneTakes (the wake prompt's Knomit-Trace is the task id).

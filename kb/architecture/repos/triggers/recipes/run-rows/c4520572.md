# GET …/triggers?run=<id> answers ONLY that run's rows ({branch, run, fires, _links}, TriggerRunRows) — never the trigger state — and a recipe result row puts its text in `message` (migration 000033) for done/spawned/delivered and in `error` only for unreachable, recipe-error and recipe-timeout (store.IsRecipeFailure)

Rehearsal finding F5 (2026-10-02), fixed in PR #396 (merged as 13a785e6). Before: handleHALTriggers built the whole TriggerReport (triggers, statistics, run summary, head, ontology blob) and only swapped `fires` for TriggerFiresByRun, so a caller following one run got the full state with the two rows inside it; and runJob (internal/corpus/repos/trigger_recipe.go) stored the recipe's result text ('exit 0 cost=1.03') in the row's `error` for EVERY outcome, so a successful session read as an error.

Now: with `?run=<id>` the handler never calls TriggerReport; it answers {branch: the repo's agent branch, run, fires, _links{self, triggers}} (OpenAPI schema TriggerRunRows; the 200 response is oneOf Triggers | TriggerRunRows). The `log` parameter is ignored there. A malformed id is still a 400 and an unknown id is 200 with empty fires.

The fire log gained `message` (TEXT NOT NULL DEFAULT ''), migration 000033, built like 000031 by copy-out / DROP / CREATE / copy-back (never ALTER TABLE ADD COLUMN: kb/conventions/store/migrations/idempotent-up-bodies). A re-run of 000033's body resets message to '' (it copies the 24 older columns); a re-run of 000031 at head must be followed by 000033, as recovery's Up() does (TestMigration000031_ReRunsAndKeepsTheLog). runJob writes Error when store.IsRecipeFailure(outcome) (recipe-error, recipe-timeout, unreachable), else Message. Non-recipe failure rows (busy, script-error, rate-limited, ...) keep using `error`.

Consequences for consumers: read a session's cost/exit from `message`, not `error`; rows written before 000033 still have it in `error`; a client that expected `triggers` in a ?run= answer must call the plain endpoint. Tests: TestREST_TriggersByRun (two runs; asserts no triggers/runs/head/ontology_blob/enabled keys), TestMigration000033_MessageColumn, TestRun_MainWinsOverLocal (done row: empty error). Sabotage verified: re-wrapping in the report, or writing every text to error, turns them red.

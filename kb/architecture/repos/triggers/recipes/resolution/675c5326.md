# A `do: run` / knomit.run recipe is resolved per fire in THIS order: `.knomit/recipes/<name>.js` at the tip of the repo's MAIN (UpstreamTip(UpstreamBranch()), never the agent branch, no signer/cert/last-writer check), else `<home>/recipes/<name>.js`, else unbound (counted, no row); a repo with no main has no repo tier, and a broken main recipe is recipe-error with NO fall-back

internal/repos/trigger_recipe.go resolveRecipe → mainRecipe → localRecipe (F07 PR 5, user ruling D1: "A, recipes run only from main. No enforcement on who actually adds the recipes in main for now").

1. Repo tier: mainRecipe takes a brief Acquire, reads tip = UpstreamTip(svc.UpstreamBranch()) — the same consensus ref verifiedBelow reads — and RecipeAt(tip, name) (store/triggers.go, a twin of ScriptAt). A zero tip (no upstream branch) SKIPS the tier. Absent file → next tier. Present: compiled and cached by the BLOB at main's tip (d.rc.repo[name].rev == blob); recipe_source=repo, recipe_rev=<blob>. A compile or header error is a `recipe-error` and resolution STOPS (D7) — the local recipe of the same name never runs in its place. A store that is mid-swap is also a recipe-error, never a fall-through.
2. Local tier: <Config.Home>/recipes/<name>.js, cached by (mtime, size) with the sha256 re-checked when either moves; recipe_rev = sha256[:12]. A broken local file is a recipe-error, logged at ERROR once per (name, rev) ("invalid recipe skipped").
3. Neither: unbound — `do: run` records outcome `unbound` in the statistics and writes NO fire-log row; knomit.run returns {bound: false}.

What this does NOT mean: nothing reads a signature, a certificate, a Toucher or verify_signatures for recipes — the reviewer greps for that. A recipe committed on the agent branch (or an experiment) but not on main is invisible (TestRun_AgentBranchRecipeNeverRuns); the recipe on main SHADOWS the machine's own recipe of the same name on every machine that has the repo, so a machine that wants its own behaviour uses a different name. Name validation: kebab-case (fact.ValidRecipeName) at ontology compile time AND at knomit.run call time, so `../x` never names a file outside either folder.

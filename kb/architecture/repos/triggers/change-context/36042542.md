# `change` for a fire is built ONCE per matched path from the ORIGINAL commit found by the treesame walk (follow the FIRST same-blob parent; a commit with no same-blob parent is the toucher; reaching the root means not found → fallback), `source` is decided by the verified SIGNER not the author text, `verified` needs F09 on at the head AND the commit below the anchor (with a once-per-run history walk when F09's cache is empty), `trace` is the Knomit-Trace trailer, `before` is the version at the watermark

internal/repos/triggers.go buildChange/changeReader and internal/store/triggers.go (TriggerTrees.Toucher, CommitSignerOf, VerifiedAnchor, AncestorSet, TrailerValue in trailers.go).

COMMIT (Toucher): start at the head; at each commit compare the path's blob with its parents'; follow the FIRST parent, in parent order, that carries the SAME blob (the change came through that side, so merges are skipped); a commit with NO same-blob parent is the toucher — the usual non-merge whose parent differs, or a merge that produced the blob itself (MergeToucher, a textual three-way merge; knomit's own merges resolve per file so always have a same-blob parent). A path touched twice in one advance names the LAST toucher (TestToucher_SamePathTwiceInOneMerge). A GitHub-style bot merge names the underlying commit (TestToucher_BotMergeNotAuthor). It is NOT bounded with IsAncestor(candidate, W) (~30 ms per path in the reviewer's probe). TERMINATION: in a linear advance every learn/update/retract ends at a real toucher; a RETRACT in a NONLINEAR advance (rewind replay) is not walked at all (the same-absent-blob walk would run to the root), and any walk that reaches a commit with no parent returns Found=false. Fallback: commit = the advance's new head, author {kind unknown, id '', fp '', verified false}, source merged, trace '' (TestDispatch_NonlinearRewindDiffs).

AUTHOR: id = the author name; kind = agent when the email ends @agents.knomit.io, unknown when name and email are both empty, human otherwise; fp = the SSHSIG signer's full pki.Fingerprint ONLY when the signature verifies over the payload (CommitSignerOf → verifyCommitSignature), never from the embedded key alone; unsigned or PGP-signed commits have fp ''.

SOURCE: `local` iff fp != '' and fp == this store's SignerFingerprint (its commit signer, or the test fallback), else `merged`. By the SIGNER, not the author text: an experiment's commits are authored exp/<name> with no fingerprint yet signed by this instance, so they are local (TestDispatch_SourceLocalVsMerged). A peer's commit merged from main is merged. After a key rotation this machine's old commits read merged.

VERIFIED: true only when the ontology blob at the head has verify_signatures log|enforce AND the commit is in the set of commits below F09's anchor refs/knomit/verified/<upstream>. The set is F09's own in-memory cache (repoHandler.cachedBelow) when a fold filled it in this process; that cache is NIL after every restart until the first sync tick, after an operator accept, and forever on a verify-on repo with no origin (R2-1), so the dispatcher then walks the anchor's history ONCE (AncestorSet) and reuses the set while the anchor does not move (TestDispatch_VerifiedAfterRestart). Your own unmerged writes are verified:false until they come back through main.

TRACE: TrailerValue(message, 'Knomit-Trace'): the last paragraph of the full message, Key: value lines, last occurrence wins, case-insensitive; '' when absent. Nothing stamps it before PR 3.

FACT / BEFORE: fact is the version at the head (at the WATERMARK for a retract, since the path is gone at the head); before is the version at the WATERMARK for update/retract (this machine's last-processed version — NOT the toucher's parent, which could be an intermediate version this machine never saw) and null for learn. An unparseable fact gives fact = null, the if still runs (a read then throws → false), and an emit records outcome `unparseable`.

COST: one TriggerTrees reader per run caches every decoded tree (go-git decodes a commit's root tree afresh on every Commit.Tree(); without the cache a 12,000-entry folder was decoded per lookup and a large advance took minutes; with it 12,000 matched paths run in ~0.7 s), and a per-commit changeReader cache reads author, signer and trailer once per commit however many paths it touched.

# A `do: script` trigger's host object is EIGHT closures built per fire in internal/corpus/repos/trigger_script.go (query, explain, learn, update, retract, emit, push, run); the five tool functions reach the UNCHANGED MCP handlers through the injected repos.ScriptTools (mcp.NewScriptTools, wired by internal/app across the mcp→repos import cycle) with a ctx that carries the budget deadline, the agent-branch binding and the trailer set — set ONCE per fire, never by the script

The dispatcher (internal/corpus/repos) cannot import internal/edge/mcp (mcp imports repos), so the tool set is injected: `repos.Deps.ScriptTools` is an interface `Call(ctx, tool, args) (text, isError, err)`; `mcp.NewScriptTools(embedder)` holds the SAME closures the MCP server registers (LearnHandler with the server's embedder, UpdateHandler, RetractHandler, QueryHandler, ExplainHandler) and passes the ctx through unchanged; `internal/app/app.go` puts it in Deps beside Embedder. A build with nil ScriptTools still runs scripts, and every host call throws "no script tools".

The host ctx for one fire is built by `runScript`: `context.WithTimeout(runCtx, budget)` (fact.ScriptEvalTimeout = 5 s; test hook scriptBudget), then `WithBinding(NewBindingOfRepo(ri, agentBranch))` — the lens-of-one every direct handler call uses, never an experiment pin — then `store.WithTrailers({Trace: fire's derived trace, Cause: firing commit, Trigger: trigger name})`. No host argument names a branch, an author, a key or a trailer: the script writes as THIS machine (author from the branch name, signer = the store's key) and cannot pass its own trailer set.

The host object is a map of closures (fact.ScriptHost), frozen and bound as a non-writable non-enumerable global; binding a Go struct would have exposed every exported method. Arguments are JSON round-tripped (numbers arrive as float64, as through the MCP transport); results are the tool's JSON parsed back; a tool error (IsError) or a call failure is thrown as a real JavaScript `Error` (constructed through the VM's Error, so `instanceof Error` and `.message` hold). learn's `moment_name` defaults to `trigger:<name>`; update/retract take `(path, opts)` with `file`+`moment_name` filled by the host. `push()` and `run()` answer `{ok:false, status:"not-supported"}` until PR 4/5. `emit(payload)` is the dispatcher's emit with `TriggerEvent.Payload` (json.RawMessage, omitempty) — one event shape for the action and the script.

Misreading to avoid: "same code path as the MCP tools" does NOT mean the MCP gates run — gateBinding/gatePermission wrap at REGISTRATION only; an in-process call is the server acting on its own store, and the binding in the ctx is what the handler resolves.

# Five remote auth methods (token/basic/ssh/none/cert); cert is transport-level with no token; tokens encrypted at rest by ONE control.db-owned Crypt, not one per repo

A repo origin supports five auth methods, stored in Origin.AuthMethod (control.db `repo_origins.auth_method`) and inferred from the URL/fields if empty. **token** (GitHub PAT etc.): AuthToken=<token>, sent as HTTP basic auth with username defaulting to x-token; auto-detected for https URLs with a token. **basic**: AuthToken="user:password" stored in the single field, split on the FIRST colon. **ssh**: key path from KNOMIT_REMOTE_SSH_KEY, falling back to the agent key ~/.knomit/id_ed25519; auto-detected for git@/ssh:// URLs. **none/anonymous**: public repos. **cert** (F19 phase 2b): the origin is another enrolled knomit instance at `https://<host>:<tls port>/git/<repo>` (plain https since PR #526), and the credential is the instance CERTIFICATE presented by the fleet go-git transport (internal scheme knomit+https, spelled only by pki.GitURL and the derived .git/config), so resolveAuth returns no go-git AuthMethod and nothing is stored in AuthToken. The method is SET BY CLASSIFICATION and is never an input: when an origin is entered, Manager.ResolveOrigin asks pki.ClassifyOrigin once and stores cert for a peer (an https URL whose server chains to the installed fleet root and accepts this instance's certificate); a token or basic typed for a peer is refused (ErrPeerCredential), cert given by a caller is refused (ErrCertNotAnInput), and remoteAuthFromRecord, keyed on the STORED method and not the URL, gives such an origin nothing from the global [remote] credential (kb/invariants/repos/remote/no-plaintext-fallback-for-fleet-origins). The upstream consensus branch is Origin.Branch (default main, configurable e.g. master). Local-path origins are disabled unless KNOMIT_LOCAL_ORIGIN_ROOT is set, then gated to within that root via validateLocalOrigin.

**UPDATE (repo-registry-in-control.db, 2026-08): credential storage and encryption moved from per-repo to the control-plane.** Auth tokens are NEVER stored plaintext — AES-256-GCM with a key derived (HKDF-SHA256) from the agent SSH private key — but the ciphertext now lives in control.db's `repo_origins.auth_token` (internal/repos/origins.go), not in each repo's own `remotes.auth_token` column (migration 000017 DROPPED `remotes.url/.branch/.auth_method/.auth_token` from every repo database). There is exactly ONE `*store.Crypt`, built once in `Manager.Start` from `m.deps.KeyPath` and shared by the whole `Origins` tenant across every repo, instead of one Crypt per repo instance. `store.NewCrypt` has no per-repo salt, so ciphertext encrypted under the old per-repo scheme stays readable under the shared one. If the agent key is unreadable, Start logs a WARN and proceeds with `crypt == nil`; a nil crypt disables credential STORAGE only (`Origins.Set` REFUSES to persist any non-empty AuthToken — "encryption unavailable"), never the server itself.

WHAT THIS DOES NOT MEAN: this does not mean each repo lost the ability to have its own credential — `repo_origins` is still keyed per-repo (by `repo_uid`), so different repos can use different tokens/methods. What changed is WHERE the encryption key material and the Crypt object live: one shared instance in the Manager/registry layer, not one instantiated per repo store. And `cert` in resolveAuth alone is NOT 'authenticated': it resolves to no go-git credential, which is safe only because pki.GitURL maps a stored cert origin onto the fleet transport; and since #526 cert is refused as an INPUT everywhere (validateURLAuth at the API edge and ResolveOrigin below it; the wizard offers no certificate option), where before it was refused only with a non-knomit+https URL.

UPDATE (PR #529, verified at merge 60ddfb1c): ProbeResult carries `fleet_peer` (probe.go: res.FleetPeer = the decided method is cert), which the Fleet follow flow reads to tell a peer (no credential, the certificate is the credential) from a forge (own credential). A fleet follow of a FORGE is probed by probeFleetForge before anything is attached, and its refusals read 'the forge could not be reached: ...' or 'the forge refused the credential: ...' (still ErrOriginUnreachable, 502 unreachable), no longer wrapped in 'origin was not attached'. The scheme/method rule (ssh method on an http(s) URL, token or basic on an ssh URL) is repos.MethodMismatch in internal/repos/origin_method.go, shared by the REST edge's validateURLAuth and the fleet follow (422 auth_invalid); 'none' on an ssh URL is the deliberate force-anonymous override and is not refused.

# Five remote auth methods (token/basic/ssh/none/cert); cert is transport-level with no token; tokens encrypted at rest by ONE control.db-owned Crypt, not one per repo

A repo origin supports five auth methods, stored in Origin.AuthMethod (control.db `repo_origins.auth_method`) and inferred from the URL/fields if empty. **token** (GitHub PAT etc.): AuthToken=<token>, sent as HTTP basic auth with username defaulting to x-token; auto-detected for https URLs with a token. **basic**: AuthToken="user:password" stored in the single field, split on the FIRST colon. **ssh**: key path from KNOMIT_REMOTE_SSH_KEY, falling back to the agent key ~/.knomit/id_ed25519; auto-detected for git@/ssh:// URLs. **none/anonymous**: public repos. **cert** (F19 phase 2b): the origin is another enrolled knomit instance at `knomit+https://<host>:<tls port>/git/<repo>`, and the credential is the instance CERTIFICATE presented by the knomit+https go-git transport, so resolveAuth returns no go-git AuthMethod and nothing is stored in AuthToken. For a knomit+https URL the method is FORCED to cert: '' / none / ssh resolve to cert, an explicit token or basic is an error, and remoteAuthFromRecord gives such an origin nothing from the global [remote] credential (kb/invariants/repos/remote/no-plaintext-fallback-for-fleet-origins). The upstream consensus branch is Origin.Branch (default main, configurable e.g. master). Local-path origins are disabled unless KNOMIT_LOCAL_ORIGIN_ROOT is set, then gated to within that root via validateLocalOrigin.

**UPDATE (repo-registry-in-control.db, 2026-08): credential storage and encryption moved from per-repo to the control-plane.** Auth tokens are NEVER stored plaintext — AES-256-GCM with a key derived (HKDF-SHA256) from the agent SSH private key — but the ciphertext now lives in control.db's `repo_origins.auth_token` (internal/repos/origins.go), not in each repo's own `remotes.auth_token` column (migration 000017 DROPPED `remotes.url/.branch/.auth_method/.auth_token` from every repo database). There is exactly ONE `*store.Crypt`, built once in `Manager.Start` from `m.deps.KeyPath` and shared by the whole `Origins` tenant across every repo, instead of one Crypt per repo instance. `store.NewCrypt` has no per-repo salt, so ciphertext encrypted under the old per-repo scheme stays readable under the shared one. If the agent key is unreadable, Start logs a WARN and proceeds with `crypt == nil`; a nil crypt disables credential STORAGE only (`Origins.Set` REFUSES to persist any non-empty AuthToken — "encryption unavailable"), never the server itself.

WHAT THIS DOES NOT MEAN: this does not mean each repo lost the ability to have its own credential — `repo_origins` is still keyed per-repo (by `repo_uid`), so different repos can use different tokens/methods. What changed is WHERE the encryption key material and the Crypt object live: one shared instance in the Manager/registry layer, not one instantiated per repo store. And `cert` in resolveAuth alone is NOT 'authenticated': on a non-fleet URL it resolves to anonymous, and only validateURLAuth at the API edge (and the wizard) refuses cert with a non-knomit+https URL.

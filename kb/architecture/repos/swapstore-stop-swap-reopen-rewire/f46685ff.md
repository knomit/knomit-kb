# SwapStore: cancel heal+sync, drain, detach/close old, .bak, copy, reopen, rewireStore, attach, start lifetime components if never activated, broadcastHead, record identity

Manager.SwapStore(ri, tempDBPath) (internal/repos/swapstore.go) replaces a live repo's SQLite store. The repo stays OPEN afterwards: SwapStore is not teardown. Order:

(1) Cancel indexCtx (the initial heal) and syncCtx; wait indexWg, then syncWg (the heal's activate() may have started the loop). After indexWg.Wait the heal has either run activate() (ri.activated set) or exited on the cancel without activating.

(2a) In-memory (ri.dbPath empty, tests only): store.Open(tempDBPath) + OpenRepo; on failure keep the existing service and return nil. Otherwise rewireStore, SetOnCommit(ri.onCommit), detachStore, attachStore(new), drain the old handle's refcount, close it. The caller must NOT delete the temp dir in this branch (the new svc holds the file).

(2b) File-backed: detachStore + drain the refcount + close the old svc FIRST (new Acquires get ErrStoreUnavailable meanwhile); copy dbPath to dbPath.bak (non-fatal on failure); copyFile(tempDBPath, dbPath); store.Open + OpenRepo; reattach(svc). On a failed copy/open/git-open: restore from .bak, reattach(reopenLocal()), return the error. The .bak is removed only after success.

(3) reattach = rewireStore (embedder, signer, accept list, own fleet keys, network timeout, ontology root, read-only flag, and the origin re-injected from control.db Origins; see kb/invariants/store/lifecycle/reopen-rewire/a3f07a9a.md) + SetOnCommit(ri.onCommit) + attachStore. If attachStore returns false (instance closed concurrently) the new svc is closed and nothing else runs.

(4) startLifetimeAfterSwap(ri), on every path that leaves a store attached (success, recovery reattach, and the in-memory keep-existing fallbacks): if ri.activated is false, call ri.startLifetime, which starts the trigger dispatcher, the consensus merger and the experiment sweep (the swap-safe half of activate(); they reach the store via Acquire). Starts are idempotent and refused after stop (lifetimeGuard), so this is safe against a second swap and a concurrent Archive.

(5) broadcastHead (in the file-backed path it runs inside reattach, right after startLifetimeAfterSwap), then, on the success paths only (not after a failed swap or the in-memory keep-existing fallbacks), recordSwappedIdentity (registry repo_id follows the new root commit).

WHAT SWAPSTORE DOES NOT DO, and the caller must: (a) restart sync. It stops the sync loop and never restarts it, on success or failure: call ActivateSync (origin) or StartLocalSync (no origin) on every return path; the origin-session commit restarts the PREVIOUS mode on a swap error. (b) mark the index state. A cancelled heal leaves it at 'indexing'; the caller that rebuilds on the new store brackets that rebuild with MarkIndexRebuildStart/MarkIndexRebuildDone. On a failed swap the origin-session commit marks 'error' if the state is still 'indexing', but only AFTER restoring the previous sync (restorePreviousSync, a synchronous ActivateSync reconcile), not before. Known gap: no test asserts 'indexing' DURING the post-swap rebuild (the web test seeds 'indexing' by hand and would pass without MarkIndexRebuildStart). (c) run activate()'s store-bound half (ensureLocalUpstream, recoverFromOrigin, startSyncLoops), which is bound to the discarded store and cancelled syncCtx and is deliberately never re-run.

Never hold an Acquire on ri across SwapStore: the drain would wait on the caller's own reference (kb/invariants/repos/store-lifetime/77005364.md). The only production caller is the disjoint-history origin-session commit (internal/web/handlers_origin_session.go).

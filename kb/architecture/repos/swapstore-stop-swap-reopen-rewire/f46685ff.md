# SwapStore: cancel-wait → close → .bak → copy → reopen → rewire embedder+onCommit → broadcastHead

Manager.SwapStore(ri, tempDBPath) follows a STRICT order: (1) cancel sync loops + wait; (2) close old svc; (3) if ri.dbPath is non-empty, copy ri.dbPath → <dbPath>.bak (non-fatal on failure — we can proceed without backup), then copyFile tempDBPath → ri.dbPath; (4) reopen via store.Open(ri.dbPath) + svc.OpenRepo(); (5) re-apply embedder via svc.SetEmbedder; (6) replace ri.svc under withWrite; (7) re-apply ri.onCommit via svc.SetOnCommit; (8) broadcast new HEAD via hub.broadcastStatus. On reopen failure: restore from .bak via copyFile(backupPath, ri.dbPath). The backup file is removed only AFTER the swap succeeds. In-memory mode (ri.dbPath == '') skips file copy and opens tempDBPath directly — CRITICAL: caller must NOT clean up the temp dir in that branch (the new svc holds the file). The 8-step order is load-bearing: skipping embedder re-apply leaves vector search broken; skipping onCommit re-apply leaves the observer dangling on the closed svc.

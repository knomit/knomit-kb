# Manager.openOne orchestrates an explicit step chain on repoBuilder: openStore→openGit→loadOntology→ensureBranch→setupIndex→seedWatermarks→build

Manager.openOne(name, dbPath, isDefault) orchestrates a step-by-step repoBuilder chain in builder.go: (1) openStore — SQLite + Crypt; (2) openGit — OpenRepo, or initDefaultGit if missing AND isDefault (clone-from-origin or create-with-default-ontology); (3) loadOntology — parse domains/ontology.yaml from the agent branch, fall back to fact.DefaultOntology() with WARN log on missing/unparseable; (4) ensureBranch — create agent branch + seed origin row in remotes table; (5) setupIndex — SetEmbedder + Sync(agentBranch) + Sync(upstreamMain) when origin configured; (6) seedWatermarks — set pipeline watermark to HEAD for each tool (review, hypothesize) so first run doesn't sweep the entire KB; (7) build — allocate RepoInstance, start observer, start sync loops, wire closures. On failure mid-chain, b.close() cleans up. Accumulated state lives on repoBuilder fields. Anti-pattern: jumping a step (e.g. skipping seedWatermarks) — the first review would cluster every existing fact.

# repos.ConsensusGuidance caches ONE snapshot per consensus-tip commit (built under a mutex): an edit that reaches main applies on the next work item with no restart, and each skipped file warns once per (path, commit); GuidanceAt accepts only a regular/executable UTF-8 blob <= 16 KiB under .knomit/guidance/

`RepoInstance.guidance` (`guidanceCache`, zero value ready, lazily used) keeps the latest tip's snapshot `{Branch, Commit, Ontology, texts}`. `at()` reads the tip every call; same tip and `built` -> the cached snapshot (pointer-identical); a new tip resets the per-commit `warned` set and rebuilds. A store error (not the file's own state) leaves `built` false so the next call retries instead of caching the gap.

Warnings (log WARN, plus `SetGuidanceWarnHookForTest` for tests): a missing or unusable file names the file and its declaring scopes ("declared by root, forecast") and the branch@short sha; no consensus branch (once per instance); no ontology / unparseable ontology at the tip (once per commit). The once-per-(path, commit) behaviour comes from BOTH the per-commit cache and the `warned` set — sabotaging either alone: dropping the cache is caught by the pointer-identity assertion; dropping only the `warned` dedup is invisible while the cache holds (build runs once per commit).

`store.GuidanceAt(ctx, commit, file)` (TriggerIndex, in triggers.go, so its calls are on `triggersAllowedCalls`): re-checks `file` is under `.knomit/guidance/`, `path.Clean`-clean and has no `..` segment; mode must be exactly Regular, Executable or Deprecated — NOT `IsFile()`, which is true for Symlink; size checked BEFORE reading (> `fact.MaxGuidanceBytes` = 16 KiB refused); invalid UTF-8 or NUL refused. Absent -> `ErrNoGuidanceAtCommit`; anything else wrong -> wrapped `ErrGuidanceUnusable`. Both make the reader skip that key; the rest renders. The rendered section is separately capped at 16 KiB, cut at a line, ending `[guidance truncated: limited to 16 KiB]`.

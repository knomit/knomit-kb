# Cluster checker fires Louvain only when HEAD advanced AND activity settled (quiet threshold)

startClusterChecker launches a background goroutine that periodically scans every open repo and triggers a Louvain refresh on branches that satisfy BOTH conditions: (1) HEAD ADVANCED — head != row.HeadCommit in cluster_cache (or no row at all); (2) activity SETTLED — now - committed_at >= QuietThreshold (default 10s). Both gates: don't waste compute on a single-fact change that will be followed by more (settled gate), AND don't compute against an outdated head (stale gate). CheckInterval=0 disables entirely. MaxConcurrent caps cross-repo Louvain runs via disp.sem chan struct{}. Per-Service singleflight in CachedClusterFacts collapses checker's trigger and any concurrent review-path call to ONE compute. disp.wg.Add(1) is called BEFORE launching the goroutine so stop() cannot race past wg.Wait while the goroutine hasn't yet incremented. Refreshes run with context.WithTimeout(5min) and detached background ctx so they survive HTTP request cancellation.

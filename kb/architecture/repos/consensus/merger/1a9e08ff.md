# consensus: auto merges every pushed peer branch into the HOST's AGENT branch (never the consensus branch), asynchronously, only on a no-origin, writable, non-subscribed repo; a conflict is refused, warned once per (branch, tip) and left for a human UI merge

F08 PR B (ruling R5). The root ontology attribute `consensus` (`off` | `auto`, absent = off, scope root; registry entry AttrConsensus in internal/fact/ontology.go) is read by `fact.ReadConsensus` from the ontology at the tip of the repo's CONSENSUS branch, resolved with `svc.UpstreamBranch()` and read through `store.Service.OntologyAt` — never at the agent branch and never at a hardcoded "main". Any value other than off/auto reads as OFF with one WARN per ontology blob (safe: off only means 'leave it to a human'), so a later value such as a recipe reference is ignored by this binary.

The merger (`consensusMerger`, internal/repos/consensus.go) is built in `repoBuilder.build()` under the same guard as the trigger dispatcher — agent branch non-empty, not subscribed, not `cfg.ReadOnly` — started in `activate()` on its own context from b.ctx (not syncCtx) and stopped in `RepoInstance.shutdown` before the store closes. It runs regardless of DisableBackgroundSync.

Kick: `ri.onCommit` sends one non-blocking kick for every commit on a branch that is NOT the agent branch and NOT `exp/*` (`consensusKicks`). That covers a peer's push (receive-pack's register → notifyCommit on the peer branch) and the consensus branch advancing (N2: turning auto on takes effect without a new push). onCommit never reads the store (it runs under the writer's branch lock); the merge runs on the merger goroutine, so the push POST never waits for it (T-B7).

Run: not auto → nothing. Repo has an origin (GetRemote("origin") != nil) → nothing, WARN once naming the origin URL (the origin owns the consensus branch). Otherwise, for every branch `isPushedBranch` accepts, `Service.MergeConsensus(peer, agentBranch, tip)`: StrategyRefuse with NO side, host-signed merge commit [agent tip, peer tip] (MergePushed's record semantics). Conflict / unrelated histories / no signer → the (branch, tip) is memoised and not retried until that branch's tip moves, WARN once, the branch stays in the Pushed branches list. ErrBranchMoved → ignored (the new push kicked again). Other errors → WARN once per (branch, tip, error), retried at the next kick. After any merge it calls `ri.wakeSync()`, so the local reconcile fast-forwards the consensus branch within the push countdown instead of the interval.

Why the agent branch: AdvanceLocalUpstream only fast-forwards and skips when the consensus branch is not an ancestor of the agent branch; a merge written into the consensus branch would freeze it for the host's own facts forever (T-B1's sabotage).

Consequence: once merged, a peer's fact fires the HOST's triggers with change.source = "merged" (T-B6), including `do: run` recipes — F11's 'host triggers do not fire on pushed branches' still holds for the pushed branch itself, not for what the merger brings into the host's own branch.

Misreading to avoid: 'auto merges into main' is false; so is 'auto resolves conflicts' — it never picks a side (but see the F1 gotcha: the PEER's own sync can make the retry clean).

# reason.js is a harness-owned state machine — GATHER, ASSESS, WIDEN, BACKTRACK, SYNTHESIZE, DECIDE, HYPOTHESIZE, SEEK, EMIT, GAP — where the harness runs every read and the model makes every judgment through one schema'd knomit.model call

internal/repos/engine_reason.js (PR 3 of the expert spike) runs one state per loop step over one explicit `st` object. GATHER: neighbours(question) via knomit.query. ASSESS: a `relevant` judgment on every newly surfaced fact (titles + snippet), then each relevant fact is read in full at HEAD (explain plus its walk's next pages until all depth-1 refs are in), then one `support` judgment per batch on the relevant evidence; a fact judged irrelevant gets verdict `unrelated` without a second call. WIDEN: the model picks one entry (or 0 = stop) from a menu of the ranked frontier, the harness executes it. Moves and their reads: neighbours(f) = query{text: title + first sentence}; entity/motif/domain = query{entities|motifs|applies_to: [one value]}; ontology = query{path: <root>/<topic>/<category>/}; kind_type = query{type: [t]}; refs_out(f) = the cached explain's depth-1 nodes; refs_in(f) = knomit.incoming; history(f) = explain at the previous revision's commit; supersession(f) = re-read at HEAD. SEEK is a text query by the fact the model says would settle the hypothesis (recorded as move `seek`, which the graders ignore). The frontier is ranked by move base × the origin fact's type rank (+0.5 when it supports) + the move's count, with a +4 bonus for kind_type(methodology) until a methodology is read and −1 for an entity/motif/domain the question already names; the menu shows at most 12 entries and at most 4 of one move kind.

Type table, applied mechanically: pragmatic facts (policy, heuristic) are obeyed — put into briefings as rules and into the answer's refs when relevant — never weighed; `principle` the TYPE is a premise weighed like evidence (the principles/ topic has no standing); methodology goes into every later briefing and the refs; a relevant hypothesis carries no mass and queues a SEEK on its settlement; signal is excluded.

Budgets: ReasonOptions{Budget (wall clock, capped at MaxReasonBudget = 1h), MaxMoves (default 12: gather, widen moves, seeks), MaxSteps (default 60; when spent the loop stops exploring and closes, hard ceiling +12 then GAP), Trust (default 0.5)} via Engine.RunWith; the MCP tool still takes only `budget`.

Consequence: a new move needs a queryFor/execute case, a MOVE_BASE entry and an expand() source; its name must be one of synthesize.ScenarioMoves or the graders will not count it. Misreading to avoid: the menu choice is the model's, but the frontier ranking and the menu cut are the harness's and steer the model (E02's menu-bias risk).

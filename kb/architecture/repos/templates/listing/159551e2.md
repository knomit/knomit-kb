# Template listing (GET /api/v1/templates, /repos/{repo}/templates) parses `part: template` facts from GIT at each repo's consensus tip and lists one only when its .knomit/templates/<name>/ folder exists at the same commit; description = the fact's title, plus its path

Shape: `{"templates": [{repo, name, description, commit, fact}]}`, sorted by repo then name, `[]` when none. For each mounted, open repo (or the one named): read the direct `*.md` children of `<ontology root>/templates/<folder>/` at `UpstreamTip(UpstreamBranch())` (store.TemplateFactsAt), keep those whose context is `part: template` with `template` equal to the folder (fact.ParseTemplateFact), then require the folder at the same commit (TemplateExistsAt). User rulings 2026-10-07: description is the fact's title and the fact's path is returned; a folder without a fact is NOT listed but IS creatable by name; a fact without a folder is neither; two template facts for one name list neither (logged) and the create refuses that name. A repo that is not open is left out of the all-repos list, logged at DEBUG (listingSkipLevel: ErrTemplateSourceUnavailable or ErrTemplateSourceNotFound, i.e. populating/closing or renamed away since Names(); the listing runs on every GET /templates, so a Warn there was noise); any OTHER error on an open repo is still skipped at WARN (TestListTemplates_NotOpenRepoIsNotAWarning); the per-repo route answers 503 for a repo still populating, and RepoMiddleware answers 404 for an unknown name or a lens name and 409 for a registered repo with no store.

WHY GIT, NOT THE INDEX: the index is per branch, and for a writable mount (the playbooks owner's) the read branch is the agent branch, so an index query would list templates the create will not read. TestListTemplates puts a template on a source's agent branch and asserts it is not listed.

MISREADING: the topic name `templates` is the playbooks repo's convention, read by path; knomit does not require a source's ontology to declare it.

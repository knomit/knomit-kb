# internal/corpus/repos/events owns TaskHub, RepoEventHub, the event types and the public Status projection; the machine's bookkeeping stays in the parent's unexported snapshot, and Manager.RepoEventHub() is a handle getter, not a forward

At 37dc65d5 (PR #631, step 14b of the internal/ hierarchy) package internal/corpus/repos/events holds: hub.go (TaskHub and TaskPublisher with NewTaskHub; TaskEvent, StatusEvent, SyncEvent, PushEvent, TriggerEvent), index.go (IndexEvent, RepoEventHub, RepoEventPublisher, NewRepoEventHub), remote.go (RemoteEvent, RemoteHealth, RemoteStatusValue) and status.go (Status, IndexStatus and the IndexState* constants), plus tests. It imports no other repos code (engine/store, remotesync and goob only). Consumers import events directly; the repos parent re-exports nothing (no-facades 44ec3b17). The concrete type is *events.TaskHub and RepoInstance.TaskHub() returns it. The publisher half of each hub is a decision of its own: kb/decisions/repos/events/hub-publisher-split/f6d5c104.md.

STATUS SPLIT. events.Status is the PUBLIC PROJECTION: Stage, Index{State, Done, Total, Reason}, IndexRunning, Sync{Running, Origin}, Serve{Running}, Err; it is what callers outside the lifecycle machine read. The machine's own bookkeeping (open, terminal, job, jobFull, phase, gens) lives in the unexported repos.snapshot, which EMBEDS events.Status; Machine.Status() returns the projection, Machine.snap() the snapshot. Transition embeds snapshot (unexported), so outside the package only the promoted Status fields are reachable and an outside package cannot construct a Transition with state; the old second copy of the status on Transition is gone. CONSEQUENCE: a new machine-internal field goes on snapshot, never on events.Status; exporting it there hands every importer of events a door into the machine. MISREADING: events.Status is not the machine's state; Send's cheap refusals decide from the snapshot (terminal, open), not from Status. events.Status is never JSON-encoded whole (summaryFor and the handlers copy fields into their own payloads), so adding a field to it does not change the wire.

PUBLISHING STAYS IN THE PARENT. Machine.publishIndex (index_events.go, the one publish point, throttle indexProgressInterval) and publishRemoteEdge/remoteEdgeSink (remote_events.go) stay in repos and publish through the publishers (m.r.pub.BroadcastIndex, sink.pub.Publish); Machine.publish calls pub.PublishTask for the rebuild task and unmount calls m.r.pub.Shutdown.

HANDLE GETTER. Manager.RepoEventHub() returns the child's concrete *events.RepoEventHub and callers Subscribe on it. The old forwarding Manager.RepoEvents(ctx) is gone because guard P (ba1210d3) flags a one-call method forwarding into a child; the shape is the same as 14a's LensRegistry(), Origins() and Repos() (f016f455).

GOTCHA. A local variable named events shadows the child package: handlers and tests had events := ...Subscribe(...); name the stream updates or stream.

SIBLING CHILD (PR #632, merged as ee850fd6): the trigger dispatcher is now the third repos child (kb/architecture/repos/triggers/dispatcher/a01f40fc.md). It takes the repo's *events.TaskPublisher as a constructor parameter held in an unexported field (f6d5c104) and gets no hub or Status access; its only ways back into the instance are four injected funcs (kb/decisions/repos/triggers/injected-funcs/732df37c.md). The events and trigger children follow the same rule: capabilities (publisher, run func) are received by construction and never exposed (kb/decisions/repos/triggers/run-func-capability/03d92e7a.md).

# Forge-hosted fleets take a stored secret through fleetSecretFits; Update access with no credential keeps the stored link, a pasted credential or none replaces it

Manager.fleetSecretFits (internal/corpus/repos/fleet_join.go) vets an OriginSpec.SecretID for the fleet URL (400 auth_invalid with a pasted token, 422 auth_invalid when it names nothing or does not fit host/scheme) and sets AuthMethod to the secret's transport. It runs in CreateFleet's create spec (forge origin), JoinFleet and CheckFleetJoin (before installing anything), and followFleetHost (before the move/credential branch). A fleet hosted on an instance refuses a secret: ResolveOrigin treats SecretID like a pasted credential for a peer (ErrPeerCredential -> 422 auth_invalid), and CheckFleetJoin's peer branch does the same. changeFleetCredential (Update access on the same forge) keeps prev.SecretID when no credential is given (FleetFollowUnchanged when method, token and SecretID all match); a SecretID links; a pasted credential or auth_method none unlinks. A move carries the secret into the AttachOrigin of the new forge, and restoreFleetOrigin keeps it on a failed move.

Testing note: fleets need https origins (refuseFleetOrigin), so the HTTPS forge tests live in cmd/fleet_secret_test.go, which serves a forge with test/testenv/gitserver.NewTLS and swaps go-git's https transport for the test (only safe in a package with no t.Parallel tests: InstallProtocol writes an unsynchronised global map).

# Manager runtime lifecycle: Create/Archive/ListArchived/Restore/Purge live in internal/repos/lifecycle.go

internal/repos/lifecycle.go adds full runtime repo lifecycle on Manager (no process restart, no CLI):

- Create(ctx, CreateSpec, emit func(Event)): one entry for three modes — preset, custom (ontology YAML bytes), clone (svc.InitFromRemote + persist origin via svc.Remote().SetRemote + ActivateSync). It seeds the .db on disk then calls the existing Add→openOne step chain to register. An in-flight set (m.creating, guarded by m.inflightMu, via reserveCreate) rejects concurrent same-name creates with ErrCreateInFlight. On any failure the partial .db (+wal/shm) is cleaned up. CreatePreflight runs the cheap checks (name validity, name-active, in-flight, clone origin-uniqueness) that must surface as an HTTP status BEFORE the NDJSON stream starts.
- Archive(name): the not-found check, last-active check (len(m.repos)<=1 → ErrCannotArchiveLast), and map delete happen atomically under m.mu.Lock(); the default repo (trunk) is blocked (ErrCannotArchiveDefault). It captures origin, calls ri.shutdown() to release the SQLite handle, then moves the .db to <home>/repos/archive/<name>.<unix>.db plus a <name>.<unix>.json manifest. The archive/ subdir is NOT matched by the non-recursive repos/*.db glob, so archived repos drop out of the active set automatically. The ephemeral .sessions.db is dropped. On rename/manifest failure it re-registers the repo (best-effort) so the repo is never lost.
- ListArchived() reads the manifests (newest id first); Restore(id, newName) moves the .db back (rename-on-collision via newName, blocks if target name active or origin already active), registers via Add, and removes the manifest ONLY after Add succeeds (moves the .db back on failure); Purge(id) permanently deletes the archived .db + manifest. ActiveRepoWithOrigin enforces origin-uniqueness on both clone-create and restore.

Manager.Rescan stays discovery-only; this is the direct in-process create/remove path that Rescan never provided.

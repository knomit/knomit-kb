# Manager runtime lifecycle: Create/Archive/ListArchived/Restore/Purge live in internal/repos/lifecycle.go; Archive/Restore/Purge are registry state flips — the .db file never moves

internal/repos/lifecycle.go adds full runtime repo lifecycle on Manager (no process restart, no CLI):

- Create(ctx, CreateSpec, emit func(Event)): one entry for three modes — preset, custom (ontology YAML bytes), clone (svc via store.Open + InitFromRemote, then persist the origin via m.origins.Set(uid, Origin{...}) into control.db's repo_origins, + ActivateSync). It mints a fresh uid (ksuid.New()) and INSERTs the registry row FIRST (m.reg.Insert), so the file path `m.RepoPath(uid)` = `<home>/repos/<uid>.db` is fresh by construction — there is no 'leftover .db file' collision to guard against, because a name can no longer collide with a file (the name never appears in the path). It then seeds the .db on disk and calls the existing Add→openOne step chain to register. An in-flight set (m.creating, guarded by m.inflightMu, via reserveNameAndOrigin) rejects concurrent same-name creates with ErrCreateInFlight, and same-origin clones with ErrOriginInUse. On any failure the partial .db (+wal/shm) and the registry row are cleaned up (rollback). CreatePreflight runs the cheap checks (name validity, name-active, in-flight, clone origin-uniqueness) that must surface as an HTTP status BEFORE the NDJSON stream starts. After Add succeeds, Create calls `m.reg.RecordRepoID(uid, ri.ID())` to enforce the one-local-copy-per-knowledge-base uniqueness constraint (repos_active_repo_id) — an ErrRepoAlreadyRegistered here rolls the whole create back.

- **UPDATE (repo-registry-in-control.db, 2026-08): Archive/Restore/Purge no longer move the database file.** Archive(name): the not-found check, lens-reference check (`m.registry.RefsRepo(uid)` — keyed by registry UID, never name), and the state flip happen atomically under m.mu.Lock(): `m.reg.SetState(uid, StateArchived, now)` is a single control.db UPDATE, then the repo is removed from the live maps (m.repos/m.byUID/m.unavailable). ANY repo may be archived, including the last one — there is no default/trunk repo to protect (the old ErrCannotArchiveLast/ErrCannotArchiveDefault guards and the isDefault concept are gone with the default-repo removal). ri.shutdown() releases the SQLite handle; the ephemeral `.sessions.db` sidecar is deleted. **The .db file itself is never renamed or moved** — there is no `repos/archive/` directory and no `<name>.<unix>.json` manifest anymore; the repo simply stops appearing in `registry.List(StateActive)`. ArchiveInfo.ID is the repo's uid (the same identity Create minted and the key Restore/Purge take), and ArchiveInfo carries the on-disk SizeBytes (stat'd after shutdown, once the WAL has folded back) precisely because archived repos are no longer visible under an obvious filename to `ls`.

- ListArchived() reads `m.reg.List(StateArchived)` (newest archived_at first, then uid as a total-order tiebreak) instead of parsing manifest files. Restore(uid, newName) is a state flip back to active (`m.reg.SetState(uid, StateActive, 0)`) plus an optional `m.reg.Rename(uid, newName)`, then Add — the database path (`m.RepoPath(uid)`) never changes, so restore is TWO UPDATEs, not a file move; a failure after the state flip rolls both UPDATEs back so the file is always left untouched. Purge(uid) checks RefsRepo, then deletes the registry row (`m.reg.Delete`, cascading to repo_origins via ON DELETE CASCADE) BEFORE removing the .db file — row first, file second, deliberately: a failed unlink leaves a harmless orphan file (logged, cleaned by hand), whereas the reverse order would leave a registry row pointing at nothing, which presents as a MISSING repo offering to rehydrate itself. ActiveRepoWithOrigin (backed by m.origins.ActiveRepoWithURL, a JOIN over repos+repo_origins) enforces origin-uniqueness as a cheap preflight on both clone-create and restore; the authoritative identity-uniqueness guard is repos_active_repo_id via RecordRepoID (see kb/invariants/repos/one-local-copy-per-knowledge-base).

Manager.Rescan and the repos/*.db glob-discovery loop are DELETED (see the retracted rescan-discovery-only fact); Start now reads the registry directly (see manager-start-close-lifecycle) and this lifecycle.go is the only in-process create/archive/restore/purge path.

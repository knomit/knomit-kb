# The origin loop has TWO circuit breakers (fetch = auth + Sync, push = Push), consulted by EVERY round: 3 consecutive failures open one for 2× the loop interval, doubling per failed probe, capped at 30 min; one success closes it; a skipped step makes no request, writes no status row and broadcasts nothing

runReconcileLoop (internal/repos/sync.go) owns two breaker values (internal/repos/breaker.go) on the loop goroutine and checks them inside doTick, so the first round, timer rounds and woken rounds (do: push, knomit.push(), the consensus merger's wake) all respect them. Schedule: failures 1-2 keep the normal cadence; the 3rd opens for breakerOpenFor(base,1) = 2×base where base is loopInterval(remote) (min(interval, push_interval), 300 s default); each failed half-open probe re-opens for the next doubling; breakerMaxOpen = 30 min is a code constant. breakerOpenFor doubles only while below the cap and never shifts, so it cannot overflow (B1 sweeps opens to 1000).

Separate breakers: a refused push opens only the push breaker and the fetch keeps running every round, and vice versa (pushing one's own branch without a fresh fetch is still a correct force-push). Auth-resolution failure is charged to the fetch breaker when the fetch is due (persisted via RecordSyncError, as before); when only the push is due (fetch breaker open) it is charged to NOTHING: the push is skipped with a Debug line, no broadcast, no push-breaker charge (review F1). Misreading to avoid: do not 'fix' that by charging the push breaker or broadcasting push_error there — no push status row records it, so the recovery edge (wasPushFailing, read from the row) never sends push_ok and the UI push banner never clears (pinned by TestSyncBreaker_AuthFailureWhileFetchOpenIsNotAPushFailure). A tickAbandoned round counts as neither.

While open, the persisted last_status/last_push_status keep the last REAL failure, so the probe's success is the existing error→ok recovery edge and clears the banner. Logs: WARN on open and on each failed probe (consecutive_failures, open_for, open_until), INFO on close, Debug on skip. The origin view (GET /repos/{repo}/origin) carries fetch_breaker/push_breaker {state closed|open|half_open, consecutive_failures, open_until} from RepoInstance.SyncBreakers().

State is in memory: a loop restart (ActivateSync) or server restart starts closed. NOT gated: the one-shot network calls (recoverFromOrigin's startup Sync, ActivateSync's synchronous Sync, the create-time push, the fleet register/unregister push). But a PENDING fleet register/unregister completes only via the loop's push (onPush), so while the push breaker is open it waits for the probe — up to 30 min. The no-origin local loop has no breaker.

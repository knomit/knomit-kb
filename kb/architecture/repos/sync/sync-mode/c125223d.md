# `sync: {push, pull}` is read by the SYNC LOOP at the consensus branch's tip (at start and before every wait) into a per-loop syncMode; onCommit only Loads the cached ri.realtimePush atomic, so a change takes effect at the loop's NEXT iteration, never at the commit that made it

How the F21 S2 root attribute `sync: {push: realtime|interval, pull: realtime|interval}` reaches behaviour (internal/repos/sync_mode.go):

- **Who reads it:** each sync loop owns one `syncMode`, built when the loop starts (startSyncLoops, ActivateSync, startLocalSync). `refresh` reads `svc.OntologyAt(ctx, svc.UpstreamBranch())` — the consensus branch's tip, never a fixed name — once before the first round and again at the top of every iteration, after the round returns. A bad value, an unreadable ontology or a missing consensus branch reads as absent (today's behaviour), warned once per ontology blob.
- **push: realtime:** refresh stores `pushAllowed(readOnly, agentBranch) && RealtimePush()` into `ri.realtimePush` (atomic.Bool). `ri.onCommit`'s agent-branch arm does `if ri.realtimePush.Load() { ri.wakeSync() }` — the same 1-slot wake and 1 s countdown as a `do: push`. onCommit runs under the writer's branch lock, so it never reads the store.
- **Consequence a consumer acts on:** setting `push: realtime` on the consensus branch does NOT make the very next learn wake the loop; the flag flips only when the loop's next iteration refreshes (up to one wait later — 300 s on an idle origin repo with pull: interval). Pinned by TestSyncMode_FlagIsCached.
- **pull: realtime:** `wait(base)` returns [git].realtime_pull_interval instead of the loop's base wait (origin: loopInterval; local: local_reconcile_interval). The SAME value is doTick's circuit-breaker base, so at N = 3 s a breaker opens for 6 s, doubling. No goroutine or ticker is added: the wait is recomputed only after a round returns, so rounds never overlap or queue.
- **What does NOT wake:** exp/*, peer pushed branches and consensus-branch commits (the other onCommit arms). The sync's OWN merge commit on the agent branch DOES wake: one bounded idle round per consensus advance, stated not filtered (TestSyncMode_MergeConverges pins exactly one).
- **Subscriptions** (agentBranch == "") read nothing: always absent. **Read-only** servers honour pull, never publish push.
- **Loop exit clears the flag** (`defer mode.clear()`), and the local loop returns on `interval <= 0` BEFORE reading the setting, so with local_reconcile_interval = 0 neither key does anything and the flag stays false.
- Misreading to avoid: `sync` is not read at the agent branch, and is not re-read per commit; there is no live path from an ontology edit to onCommit.

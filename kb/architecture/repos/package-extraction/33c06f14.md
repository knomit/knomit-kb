# internal/repos owns lifecycle; internal/web is pure HTTP; cmd/serve.go is thin wiring

internal/repos package owns ALL repo lifecycle management: RepoInstance, TaskHub, Manager (Boot/Add/Shutdown), sync loops (runSyncLoop, runPushLoop), MCP wiring (setupMCP), context/middleware helpers (RepoFromContext, RepoMiddleware), SwapStore. internal/web becomes pure HTTP — router, handlers, SSE, git remote. cmd/serve.go is thin wiring: repos.New(ctx, deps) + m.Boot() + HTTP server. CRITICAL: internal/repos NEVER imports internal/web (no import cycle). internal/web imports internal/repos for types. cmd imports both. Anti-pattern (FORBIDDEN): adding HTTP-aware code to internal/repos — if a handler needs repo state, it accesses via ri.WithRead or accessor methods through the *repos.Manager. Why this matters: the package boundary makes the HTTP layer testable in isolation and makes the lifecycle layer reusable by other entry points (TUI, future CLIs).

# internal/repos owns lifecycle, internal/web is pure HTTP — repos NEVER imports web (no import cycle)

internal/repos owns repo lifecycle management: RepoInstance, TaskHub, Manager, the background reconcile loop, context/middleware helpers (RepoFromContext in context.go, RepoMiddleware in middleware.go), SwapStore. internal/web is pure HTTP — router, handlers, SSE, git remote.

CRITICAL INVARIANT (verified at HEAD): internal/repos NEVER imports internal/web (no import cycle); internal/web imports internal/repos for types; cmd imports both via the internal/app package. Anti-pattern (FORBIDDEN): adding HTTP-aware code to internal/repos — a handler needing repo state accesses it via ri.WithRead / accessor methods through *repos.Manager. Why the boundary matters: the HTTP layer stays testable in isolation and the lifecycle layer is reusable by other entry points.

WHAT THIS DOES NOT MEAN: this fact was seeded from the extraction PLAN and several plan-era symbol names are now STALE — do not rely on them. The lifecycle entrypoint is Manager.Start() (manager.go), NOT Boot(). Sync is ONE goroutine, runReconcileLoop (sync.go), doing Sync-then-Push — NOT separate runSyncLoop/runPushLoop. There is NO setupMCP in this package. cmd/serve.go reaches the Manager through internal/app (app.New -> a.Manager()), it does NOT call repos.New/m.Boot inline. Only the package-boundary invariant (no cycle; repos=lifecycle, web=HTTP) is load-bearing; verify any symbol name against code before relying on it.

# The lens list read is ONE function in internal/corpus/federate/fused.go: PlanFused then FusedSearch/FusedRecent, called by REST /lenses/{lens}/search and /facts and by MCP knomit_query (relevance and sort=recent); edges supply only legs, error rendering and paging

Since PR #704 (branch refactor/federate-fused-search), the fan-out, fusion and dedupe that REST and MCP each carried a copy of live in `internal/corpus/federate/fused.go`.

PIPELINE, in this order:
1. `PlanFused(ctx, FusedQuery)` runs motif widening over the FULL read set (`ExpandMotifTerms` with the edge's cluster reader), then target selection (`ReadTargetsFor`), then `repo=` narrowing (`NarrowByRepo`), then ONE query vector (`FusedQuery.Embed`). The first failing step returns `*PlanError{Stage, Err}`: StageMotifs, StageTargets, StageRepos or StageEmbed. `Error()` is the cause's text unchanged, and Unwrap exposes the cause.
2. The caller may adjust `plan.Opts` before running the plan. REST applies its expiry and context params there, which keeps its error precedence (embedding failure outranks a bad `expires_*`). REST /facts sets `Opts.Limit` once per depth round.
3. `FusedSearch(ctx, plan, SearchLeg, FusedOptions)` or `FusedRecent(ctx, plan, RecentLeg, FusedOptions)`:
   - runs one caller-supplied LEG per target. The leg receives the Target, whose `Mount` field is the mount's STABLE identity: its index into `Binding.Reads()`, set by `ReadTargetsFor` and kept by `NarrowByRepo`. It is not the target's position in plan.Targets, which topic skipping, a qualified path and repo= narrowing all shift;
   - reduces in binding order;
   - reports the LOWEST-INDEXED failing mount as `*MountError{Mount, Err, Panicked}` (b9c7ab96);
   - orders the union by RRF; FusedRecent with empty `Opts.Text` uses `MergeRecent` over every fetched row instead;
   - drops a row when another mount wins its repo-relative path (`WriteFirstWinners`: the write mount first, then binding order).
   - Result: `Fused[T]{Hits, Lists, Totals, Diags}`. Each Hit carries `Mount` (its POSITION in plan.Targets, which narrowing shifts) and `Target` (Target.Mount = the stable binding index, RT.RI = the repo, RT.Branch = the branch read). The row itself carries CommitHash/BlobHash, the pinned version. NOTHING is truncated.
4. `FanOut(targets, fn)` is the ONLY concurrent lens fan-out. REST `fanOutMounts` is a thin title-carrying wrapper over it. Its only callers (re-read at the merge, 8f34e391) are the two /lenses/{lens}/stats fan-outs: the aggregates (handlers_lenses_stats.go:160) and the axis-correction pass (:284). The lens topics, completions and motif handlers do NOT use it; they loop over their mounts themselves.

WHAT STAYS IN THE EDGES:
- how one mount is read (REST: `searchRepo`/`recentFacts` via `ri.WithRead`; MCP: `mcpSearchLeg`/`mcpRecentLeg` via `storeIndices`);
- error rendering (REST `planLensRead` maps stages to problem documents; MCP returns the error text);
- diagnostics logging;
- paging (REST offset/limit and the recency depth loop; MCP max_results and the cursor snapshot);
- wire-path qualification, which happens AFTER the dedupe (2e15f944).

CONSEQUENCES:
- A change to lens list ordering, failure choice, dedupe or widening belongs in fused.go. Changing it in one edge recreates the mirrored drift this extraction removed (096bb34b).
- A lens FactSet (F3, built on feat/lens-factset-facade) gets the same root list: materialize.planLensSearch runs PlanFused (every mount at MaxFactSetFacts = 500, search.repo as Repos, the edge's cluster reader) and FusedSearch/FusedRecent with legs reading each opened mount, keyed by the target's repo id, between two settled-watermark reads of every mount; hits are partitioned by Hit.Target.Mount. No second fan-out. A third caller: corpus/materialize -> corpus/federate is an allowed archtest edge. Key per-mount state on `t.Mount` (or the repo id), NEVER on the position in plan.Targets.

WHAT THIS DOES NOT MEAN:
- The edges are not identical. Each still has its own depth, error text, store acquisition and serial-vs-concurrent choice (see the companion gotchas fact on the remaining REST/MCP edge differences).
- `fused.go` does not qualify paths. A caller that qualifies BEFORE dedupe defeats write-first.

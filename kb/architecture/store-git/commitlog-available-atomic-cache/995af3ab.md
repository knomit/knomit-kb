# CommitLogAvailable lazily caches sqlite_master probe in atomic.Bool

Storer.CommitLogAvailable() lazily caches whether the commit_log table exists via s.commitLog atomic.Bool. First call probes sqlite_master WHERE type='table' AND name='commit_log'; if found, the atomic is set. Subsequent calls hit ONLY the atomic — no SQL roundtrip. The atomic is also set to true on first successful CommitLogSync write OR on confirmed-exists probe. Callers check this before doing commit_log work so the storer can run in commit-log-disabled mode (e.g. NewMemoryStorer with module-style schema) without erroring. Anti-pattern: probing sqlite_master in hot paths — the atomic cache is the right granularity (one probe per storer lifetime).

# Storer.Module returns a per-submodule storer backed by SEPARATE :memory: SQLite (inline schema)

Storer.Module(name) returns a per-submodule *Storer backed by a SEPARATE :memory: SQLite database. The parent storer records submodule presence via kvSet('module:<name>', '1'). Per-module schema is INLINE in the Module method (CREATE TABLE objects + refs + kv) — explicitly NOT the full migration schema, so module storers CANNOT call CommitLogSync (no commit_log table) and have no facts/branches/index. The map s.modules caches returned storers so subsequent calls with the same name return the SAME instance — idempotent. Why in-memory: submodules in knomit are not first-class — they exist for go-git interface compliance (some go-git internals iterate modules), not because users use git submodules. The isolation prevents submodule object writes from polluting the parent's objects table.

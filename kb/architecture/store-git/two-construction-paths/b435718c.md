# NewStorer wraps existing DB (ownsDB=false); NewMemoryStorer opens :memory: with migration-1 schema (Core), excluding vec0/GraphQLite/commit_parents

Two construction paths for *Storer: (1) NewStorer(db *sql.DB) wraps an EXISTING DB — ownsDB=false; the caller (typically store.Service.Open) manages lifecycle and runs migrate.All for the full schema (storer.go). (2) NewMemoryStorer() opens :memory: SQLite, applies storemigrate.Core(db), ownsDB=true (storer.go). Core runs migrations up to version 1 only (migrate.go). Close() is a no-op for non-owned DBs and closes the in-memory DB for owned ones (storer.go). NewMemoryStorer is used by tests that need a real Storer without the full search-index stack.

WHAT Core (migration 000001) ACTUALLY CREATES: objects, refs, kv, meta, branches, facts, branch_facts, pipeline_watermarks/sessions/work_items, remotes, tool_sessions/seen_paths/queue, commit_log, branch_commits, fact_entities, fact_domains (repo/000001_schema.up.sql).

WHAT THIS DOES NOT MEAN:
- Core does NOT omit the facts / pipeline / tool tables — all are in migration 000001 and present in a NewMemoryStorer DB. The earlier 'NO facts/pipeline/tool tables' wording was WRONG.
- Core DOES omit everything from migration 000002 onward: facts_vec (vec0), GraphQLite, commit_parents (000007), facts_kind, facts_origin, dynamic embed vec. In particular commit_parents is absent, so CommitLogSync's parent-edge INSERT has no target table under a bare NewMemoryStorer. (Note: migration 000010 later relocated the tool_* and pipeline_session tables out of the main DB into a separate ephemeral session DB; Core still creates them at version 1.)

Anti-pattern: calling Close on a NewStorer-wrapped DB — the upper layer's *sql.DB would be closed under it, causing use-after-close in store.Service.

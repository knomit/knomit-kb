# CommitLogActivity returns 5 aggregates (LastCommit + Total + Changes7d/30d/90d) in ONE SQL roundtrip

CommitLogActivity(branchID, path, cutoff7, cutoff30, cutoff90) returns FIVE aggregates in ONE SQL round-trip: LastCommit sql.NullInt64 (MAX(committed_at), nullable because the path may have no commits), Total int (COUNT(DISTINCT commit_hash) — distinct commits touching the path), and three Changes7d / Changes30d / Changes90d int (COUNT(DISTINCT CASE WHEN committed_at > cutoff THEN commit_hash END) for each window). The cutoffs are passed as args so the caller computes them from time.Now() at the right moment — the storer is time-source-agnostic. One query is significantly cheaper than 5 separate queries against the same indexed (commit_hash, committed_at) tuple. Anti-pattern: fetching the same path's commits in Go and computing the aggregates there — pulls all rows into memory and loses index acceleration on commit_log_path_time / commit_log_time.

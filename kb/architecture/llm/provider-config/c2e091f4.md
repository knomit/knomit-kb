# [llm.providers.<name>] config: kind anthropic or ollama only; the API key resolves api_key_file (mode 0600 checked), then api_key_env (default ANTHROPIC_API_KEY), then a plaintext api_key, which is accepted; model ids, context windows and price cards live in config, never in code

A provider table is [llm.providers.<name>] with kind "anthropic" or "ollama"; "bedrock" and "gemini" are refused at load until they have a chat adapter. models is a required, non-empty allowlist; a [llm.providers.<name>.model.<id>] table for an id outside it is refused. Per-model: effort (low|medium|high|xhigh|max, always sent), max_output_tokens, thinking_display (summarized|omitted), context_window, and a price card of one or two tiers chosen per request on ALL prompt tokens (input + cache read + cache write), cache read/5m/1h multipliers and warn_prompt_tokens. Ollama defaults (keep_alive 30m, num_ctx 32768) are applied at Load.

Secret order, a planner call (P21): api_key_file (stat'ed: any group/other bit is an error on POSIX), then the env var named by api_key_env, then a plaintext api_key. A plaintext key is NOT refused (user decision Q6). api_key_env holds the NAME of an environment variable: a value outside [A-Za-z_][A-Za-z0-9_]* (a pasted sk-ant-... key has hyphens) does NOT fail config Load (unlike a gemini kind): the provider loads, and ResolveKey never reads a bad name. When that leaves an anthropic provider with no key (api_key_file and api_key both unset or empty) llm.Registry.List marks EVERY model of it unavailable (config.APIKeyEnvBlocked); a usable api_key_file or a plaintext api_key keeps it available, and an ollama provider is never blocked (it uses no key). The warn log fires in every case. When blocked, List marks every model unavailable with config.APIKeyEnvNotANameMessage (provider name only, never the value) as the reason GET /chat-providers shows, Registry.Open refuses a blocked provider with ErrNoCredentials, and app logs the same text once at warn when it builds the registry; other providers are unaffected (config.APIKeyEnvProblem, validEnvVarName; TestRegistry_APIKeyEnvHoldingAKeyMakesOnlyThatProviderUnavailable, TestLogLLMProviderProblems_WarnsOnceWithoutTheValue). An empty api_key_env still loads (the anthropic default applies). The check is on the name's shape only: a well-formed name that is unset in the environment still resolves to no key. Before it, a key pasted there was reported only as no API key configured. The key is never logged: llm.Registry.Open is the only reader, and a test greps the process log, the session log, the temp files and every response for it. The SDK's error text carries the HTTP response body, so a proxy or endpoint that echoes request headers would put the key into a provider-list reason or a stream error: llm.redactKey blanks the key to [redacted] in both (TestRegistry_EchoedAPIKeyIsRedacted); the original error stays reachable through Unwrap.

The shipped example is the embedded llm_example.toml (config.ExampleLLMProvidersTOML), parsed and validated by a test: it carries claude-haiku-5-5 (first, the chat default, effort medium, tiers 100K/0.10/0.50 then 0.50/2.50, warn 95K), claude-sonnet-5-5 (effort high, its documented default; Haiku 5.5 and Opus 5.5 default to medium) and claude-opus-5-5, each with a 1M context_window. The Sonnet 5.5 cache-read multiplier is 0.1 ($0.20 per MTok on $2), not the 0.05 the plan assumed; Opus 5.5 is 0.05.

Consequence: changing a price or window is a config edit, not a code change; do not add a model id or price to non-test Go code. Does NOT mean the config validates trained context length: that half of 'max_output < min(num_ctx, trained)' is only knowable from Ollama /api/show and is refused by llm.Registry.Open.

Does NOT mean a key-shaped api_key_env is repaired or ignored, nor that it stops the server: that one provider is unavailable until the value is a variable name.

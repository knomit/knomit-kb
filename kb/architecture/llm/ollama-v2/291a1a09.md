# Ollama v2 adapter sends each tool call's id as tool_calls[].id and tool_call_id (plus tool_name); ToolUse.ID stays knomit's and the server's id is kept in ToolUse.ProviderID

Ollama's api types accept ids on tool calls: ToolCall.ID (json id) and Message.ToolCallID (json tool_call_id), both present at v0.30.0 and later (checked v0.30.0, v0.35.0, v0.40.14, api/types.go); the server assigns 'call_<8 random chars>' ids to the calls it parses (server/routes.go toolCallId, v0.40.14) and the native path forwards tool_call_id to llama-server (llm/llama_server.go). The adapter (renderOllamaChecked, ollamaAssistant) walks hook 6 then hook 7, records for each assistant tool_use its tool name and a wire id under the knomit id (tu_<n>), and renders (a) the replayed call as tool_calls[] with id, and (b) each tool_result as {role:tool, tool_name, tool_call_id, content} with the same id and the name of the call it answers. The wire id is ToolUse.ProviderID when the server sent an id on that call (Stream copies ToolCall.id into it), else the knomit id. ToolUse.ID is always knomit-assigned; the neutral history never takes Ollama's id as its key, so a later provider switch still works. tool_name is still sent, so a server that ignores ids still gets name-plus-order matching: that is the fallback, not the mechanism. Consequence: two parallel calls to the SAME tool in one turn are told apart by id (tested with and without server ids, results answered in reverse order). A tool_result whose id answers no tool_use earlier in the snapshot makes Stream return an error BEFORE any HTTP request (renderOllama, the test variant, emits empty ids/name instead). The ids sit in hooks 6 and 7, never in the shared prefix, so byte-stability is unaffected. Not verified live: whether any Ollama chat template validates the id format; knomit's tu_<n> ids are sent when the server sent none. Does NOT mean Ollama requires ids: matching by name remains what older servers do. Supersedes the earlier claim that Ollama matches by name and not by id, which was a statement about the adapter, not about Ollama.

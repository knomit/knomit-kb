# kb resolves ONE server for every call — argument > KNOMIT_SERVER > the server.json of the home KNOMIT_HOME selects (the state dir's file for the default home) > http://localhost:19278 — spelled by internal/foundation/serveraddr as http(s)://host:port, unix:///abs/path.sock or npipe:////./pipe/<name>; a malformed value is an error naming its source; local-listener requests carry the placeholder host http://localhost

Since PR fix/knomit-server (2026-10-02; replaced KNOMIT_BASE_URL, which the hooks read only, with no alias).

RESOLUTION (tools/bridge/knomitapi/server.go ResolveServer): (1) kb's positional argument (the proxy only — hooks have none, and knomitapi.ClassifyArgs never sees it), (2) KNOMIT_SERVER, (3) the server.json lockfile (written by the desktop and, since #493, by every `knomit serve` for its own home) config.LockfilePath() = <state dir>/knomit/server.json -> http://127.0.0.1:<port>, (4) http://localhost:19278. Env and lockfile are read on every call, never cached. KNOMIT_HOME is NOT an input to the ADDRESS CHOICE - it never makes kb pick a different named server - but since #493 (merge 9860c726) it DOES select which lockfile level 3 reads: config.LockfilePath() = LockfilePathFor(ResolveHome()), the state dir's server.json for the default home and <home>/server.json for any other home. It also decides where the default path's local listener is (config.SocketPath), and the socket is still taken ONLY from there, never from the file's address/socket fields. The file's `http` base URL is read before `port` (kb/architecture/bridge/server-address/server-json). The hooks now read the lockfile too (before, they went straight to 19278).

EVERY CALL: tools/bridge/main.go connect() builds discovery's client (3 s) and the proxy's (timeout 0, SSE) from the SAME Server by the same rule, so discoverAgentBranch — plain TCP to the lockfile/default before the fix, the rehearsal bug's first call — now follows a named socket too; terminateSession reuses the proxy client.

SPELLING (internal/foundation/serveraddr): http/https need a host and allow no path (other than '/'), query, fragment or credentials; unix:// is taken LITERALLY (no %-decoding, so 'Application Support' and '%' round-trip) and must be absolute (unix://relative is refused) and SHORTER than auth.SunPathCap() (the cap auth.ListenLocal enforces; a longer one is refused at parse naming its length and the limit, instead of the bare 'connect: invalid argument' a dial gives); Windows uses npipe:////./pipe/<name> (Docker's spelling) and refuses unix://, unix refuses npipe://. Parse errors do not name the source; ResolveServer wraps them as 'KNOMIT_SERVER: ...' or 'the server argument: ...', and kb exits 2. ForLocal/ForTCP format the server's own address (ForTCP turns a wildcard bind host into 127.0.0.1).

REQUEST URLS for a local listener are built on serveraddr.LocalBase = http://localhost (a placeholder: the transport dials the socket whatever the URL says); TestLocalBase_HostIsAcceptedByTheServer pins that hostguard.LoopbackHostOK accepts it, though socket requests are judged by peer credentials before any Host check. The hooks client disables keep-alives because every local listener shares that placeholder host, so a pooled connection could otherwise serve a request meant for another listener.

A malformed KNOMIT_SERVER in a hook: BaseURL logs at ERROR and returns the placeholder; the hooks client's dial resolves the same value and fails naming KNOMIT_SERVER, so no request leaves (TestClient_HooksMalformedKnomitServerSendsNothing).

WHERE TO GET THE VALUE: both server entry points log the address they recorded — 'this server's address (KNOMIT_SERVER for kb)', field knomit_server — already in this spelling. Copy that; do not build unix://<home>/knomit.sock, which is wrong whenever KNOMIT_SOCKET, the toml socket key or the long-home /tmp fallback moved the socket. kb's --help prints the precedence and the forms.

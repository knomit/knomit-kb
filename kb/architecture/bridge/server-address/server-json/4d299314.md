# server.json schema 2: `http` is the plaintext listener's full base URL ("" when http = false) and a reader takes it BEFORE `port`; v1 readers keep working because `port` keeps its meaning (0 = no TCP), and no field names the socket kb dials

CONFIG KEY (knomit#493, merge 9860c726): `http` (bool, default true; env KNOMIT_HTTP) switches the plaintext TCP listener. http = false binds NO TCP port and the server is reached over the local socket/pipe alone. config.Validate refuses http = false with an empty socket, and OpenListeners refuses 'nothing to serve on' when http is off and the local path is held by another process. It does not touch the mTLS listener ([tls].addr).

FILE FIELDS (serveraddr.LockInfo, internal/serveraddr/lockfile.go): schema 1 was {pid, port, version}. Schema 2 (`schema: 2`, written by every `knomit serve` for its own home, after its listeners bind) adds home, http, address, socket, tls, generation. `http` is ALWAYS written: the base URL, e.g. http://127.0.0.1:19278, or the empty string when http = false - so an off listener is distinguishable from a schema-1 file. `port` is the TCP port, 0 when there is no TCP listener. `address` is the server's KNOMIT_SERVER spelling (the socket when it bound, else TCP). `generation` is 1 after boot (a later PR bumps it on reload).

READER ORDER (tools/bridge/knomitapi/server.go readLockfileBaseURL): `http` if non-empty, else `port` if > 0 as http://127.0.0.1:<port>, else none, in which case the caller falls through to the unnamed-address policy (local socket first, then the default TCP). The cases, all with exact-value assertions and a port that differs from the http URL: v1 {port:4242} -> that port; v2 http wins over port; v2 http alone; v2 http "" + port 0 -> none; v1 port 0 -> none; http "" + port N (what the desktop's own v1-shaped write produces) -> the port URL.

V1 COMPATIBILITY: an older kb reads port only; on a server with TCP off it sees 0 and uses the default base, which tries the socket first. That is why `port` stays and does not become a URL.

NOT MEANT: (1) kb does NOT take `address` or `socket` from the file as its listener - it still derives the socket from KNOMIT_HOME via config.SocketPath, so a file that can be shared between homes never decides which instance a client talks to (the 2026-10-02 wrong-instance incident); those fields are for people and diagnostics. (2) `http` set does not prove the port is up (a stale file); the dial policy applies. (3) The reader returns `http` verbatim, without serveraddr.Parse; the file is 0600 and server-written. (4) Until PR 5 the desktop's own boot ignores http = false (it always binds TCP) and writes a v1-shaped file with an empty `http` key; only OpenListeners honours the key. Which file: kb/architecture/bridge/server-address/resolution and kb/gotchas/bridge/windows/lockfile-unsupported-platform.

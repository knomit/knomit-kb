# Approved OAuth logins are listed and revoked at /api/v1/oauth/grants (plain router only, requireLocalOrSameOriginAdmin): the list is only families that CAN be used (not revoked, refresh_expires_at in the future, AND an issued token or a live unspent code), newest first; revoke sets revoked_at by the replay path and records the revoker in oauth_family_revocations

GET /api/v1/oauth/grants (Issuer.Logins -> Store.ListLogins) returns token families with ALL of: revoked_at IS NULL, refresh_expires_at > now, and a way in, meaning an oauth_tokens row for the family OR an oauth_codes row with consumed_at NULL and expires_at > now. Ordered created_at DESC. So a family whose code was never exchanged and expired, or whose code was SPENT by an exchange that then failed (ConsumeCode spends the code before the PKCE check), is NOT listed: it can never yield a token. A revoked or lapsed family is not listed either, so the list is not an audit history. POST /api/v1/oauth/grants/{id}/revoke (Issuer.RevokeLogin -> Store.RevokeFamily(ctx, id, by)) revokes through revokeFamilyTx, the same UPDATE ErrReused/ErrNoLongerAllowed use, so the family's access AND refresh tokens fail at once (401 on the OAuth listener), and in the same transaction INSERT OR IGNOREs the revoking principal (auth principal String(), e.g. bridge:uid:501@local or anonymous@none) into oauth_family_revocations (control migration 000021). It answers 200 {id, revoked_at, revoked_by}. A second revoke of a revoked family writes nothing and answers the FIRST revocation's record; a family the server revoked itself (replayed code or refresh token, an approval that no longer stands) has no revoker row, revoked_by ''. Unknown id: ErrUnknownFamily -> 404. Both routes are mounted by mountOAuthGrants beside mountOAuthPending in NewAPIRouter, only when OAuthIssuer is set, behind requireLocalOrSameOriginAdmin: local listener principals, or anonymous loopback holding admin WITH the browser proof; a bearer or an operator certificate holding admin is refused 403. Without [oauth] the route is 404, which the web UI reads as 'no Approved group'. They live in package web (oauth_grants_api.go), not under internal/edge/web/api, like the pending endpoints. The JSON key is 'grants' although these are OAuth families, NOT auth permission grants (knomit grants ...): do not confuse the two. The family id is a random id, not a token, so exposing it to the admin is not a credential leak.

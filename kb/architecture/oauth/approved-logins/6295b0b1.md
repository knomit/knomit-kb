# Approved OAuth logins are listed and revoked at /api/v1/oauth/grants (plain router only, requireLocalOrSameOriginAdmin): the list is only USABLE families (revoked_at NULL and refresh_expires_at in the future), newest first; revoke sets the family's revoked_at, the same path a replayed refresh token takes

GET /api/v1/oauth/grants (Issuer.Logins -> Store.ListLogins) returns token families that can still be used: revoked_at IS NULL AND refresh_expires_at > now, ordered created_at DESC. A revoked or lapsed family is NOT listed, so the list is not an audit history; a client whose family lapsed or was revoked must ask again and appears under the pending requests. POST /api/v1/oauth/grants/{id}/revoke (Issuer.RevokeLogin -> Store.RevokeFamily) revokes by family id through revokeFamilyTx, the same UPDATE that ErrReused/ErrNoLongerAllowed use, so the family's access AND refresh tokens fail at once (LookupAccess -> ErrRevoked, 401 on the OAuth listener). Revoking an already-revoked family answers 204; an unknown id is ErrUnknownFamily -> 404. Both routes are mounted by mountOAuthGrants beside mountOAuthPending in NewAPIRouter, only when OAuthIssuer is set, behind requireLocalOrSameOriginAdmin: local listener principals, or anonymous loopback holding admin WITH the browser proof; a bearer or an operator certificate holding admin is refused 403. Without [oauth] the route is 404, which the web UI reads as 'no Approved group'. They live in package web (oauth_grants_api.go), not under internal/edge/web/api, like the pending endpoints. The JSON key is 'grants' although these are OAuth families, NOT auth permission grants (knomit grants ...): do not confuse the two. The family id is a random id, not a token, so exposing it to the admin is not a credential leak.

# repos.StoredAgentID is the read-only way to get the persisted agent id for DISPLAY; `knomit identity show` prints it as `agent_id:` — never use ResolveIdentity for display, because it writes an identity when none is stored

`repos.StoredAgentID(home) (id, found, err)` returns the agent id persisted in `<home>/control.db` table `instance_identity` (row id=1) WITHOUT any side effect on the file. `knomit identity show` (cmd/identity.go showIdentity) calls it and prints `agent_id: <id>` as its FIRST output line.

How it stays read-only: it opens control.db through `openControlReadOnly`, a short-lived `database/sql` handle on a SQLite URI with `mode=ro`. That handle cannot create a missing file and cannot write, so it can never create, migrate or flip the journal mode of control.db whatever state the file is in. It does NOT go through `controlUp`/`OpenRegistry`/`OpenRegistryNoSchema` (an early revision of the PR used OpenRegistryNoSchema; that is not read-only, because it is read-write-create and switches a rollback-journal file to WAL).

Outputs (id as stored, opaque, never parsed or trimmed):
- found=true: `agent_id: <id>`. Since PR #514 `showIdentity` also runs pki.ValidAgentID on it (StoredAgentID itself does not validate): an invalid stored id (for example one holding an upper-case letter) is still printed as stored, followed by `(invalid: <reason>; boot refuses it: ... a fresh start is required (stop knomit, delete control.db in the knomit home, and start again ...))`, the rest of `show` follows and the command exits 0 (show is a display command, like its `none` and `unreadable` states). Nothing is rewritten; control.db is byte-identical afterwards (TestIdentityShow_InvalidStoredAgentID).
- found=false: printed as `agent_id: none (assigned when the instance first starts)`. This is returned when control.db does not exist (an os.Stat before the open chooses this answer), when the `instance_identity` table does not exist (a home last booted before migration 000012), or when the row does not exist.
- err != nil (stat error other than not-exist, open error, query error): printed as `agent_id: unreadable: <err>`.

OPERATIONAL CONSEQUENCE: any display, status or diagnostic path that needs the agent id must call StoredAgentID. `ResolveIdentity(home, fresh)` goes through OpenRegistry (migrates control.db) and INSERTS a fresh identity when no row exists, so using it to show the id would create control.db and mint an identity on a machine that has never started, and would migrate the control.db of an instance that last booted, or is still running, on an older binary. ResolveIdentity is the boot path (app.New) only.

WHAT THIS DOES NOT MEAN: `none` does not mean the instance has no identity forever; it means no server has booted against this home yet. StoredAgentID does not read the pki certificate or fingerprint, and `pki.Status` deliberately does not carry the agent id (pki stays free of repos imports), so the desktop Settings identity view, which uses pki.Status, does not show it.

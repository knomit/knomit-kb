# Ontology.Serialize uses sortedKeys for deterministic YAML output; round-trip byte-stable

Ontology.Serialize() produces deterministic YAML via sortedKeys — topic and child keys are alphabetically sorted before emission. Output uses yaml.v3 with indent=2. The ontology stored at .knomit/ontology.yaml (fact.OntologyFile; legacy rungs .domains/ and domains/ still load) in each repo's git tree is the result of this serialization when written by knomit; loading via RepoInstance.loadOntology (internal/corpus/repos/stages.go) → ParseOntology round-trips back to the same in-memory Ontology. Determinism matters because: (1) git diffs are clean when only semantic changes occur; (2) hash-equality testing in unit tests is possible; (3) re-serializing on every load doesn't churn the repo. Anti-pattern: using Go's default map iteration for emission — would produce different byte-output on every Serialize call and pollute git history with no-op churn.

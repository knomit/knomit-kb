# Ontology guide — the three roots: kb/ (facts, placed by topic/category, indexed and searchable), .knomit/ (the system: ontology.yaml, triggers, recipes, skills, guidance, templates; written only through git, readable by exact path) and artifacts/<area>/ (agents' untyped working files, written by explicit path, invisible to search, triggers, UI and export); every dot-prefixed path segment is private, and a merge that would change the host's dot paths is refused

Part of the ontology guide (kb/architecture/fact/ontology/guide/). Describes merged dev at c9c599de.

KB/ (the ontology root; knomit.toml ontology_root, default "kb", per INSTANCE, never "artifacts"). Facts live at kb/<topic>/<category...>/<uuid>.md. The FIRST segment must be a topic the ontology declares; deeper segments walk declared children and, at the first undeclared one, the rest is freeform (ValidatePath). Index membership is decided by LOCATION: under the ontology root with no dot-prefixed segment at any depth, never by whether a file parses. knomit_learn/update/retract, REST fact routes, triggers and review all work here.

.KNOMIT/ (the system; fact.PrivateRoot). .knomit/ontology.yaml (legacy read fallbacks, newest first: .domains/ontology.yaml, then domains/ontology.yaml; a symlinked ontology refuses the repo), triggers/<script>.js, recipes/<name>.js, skills/<name>/SKILL.md, guidance/<file>.md, templates/<name>/. CLOSED to every fact-tool WRITE; READABLE by exact path through knomit_explain (a system_file node) and refs of the form .knomit/<path>. Changed only by people through git (or knomit's own boot preset refresh of the ontology file).

ARTIFACTS/<area>/ (fact.ArtifactsRoot). Agents' non-fact working files (a job's bookkeeping): written with knomit_learn's `path` (at least one folder deep, no dot segment, no ".."), then updated, retracted and explained by exact path. Never indexed, queried, listed by knomit_changes, seen by triggers, shown in the UI or exported. No ontology placement, so no topic validations or context declarations apply there.

PRIVATE (DOT) PATHS. Any segment beginning with '.' (folder or file, at any depth: .knomit/, .github/, kb/.drafts/) is private: skipped by every walker and the index, refused as a fact path, and a trigger `match` may never name one. The guards that keep peers from changing them: receive-pack's dot-path content closure (a fast-fail on push, in every verify mode) and, authoritatively, MergePushed/MergeConsensus refusing any merge whose result changes the host agent branch's dot paths.

CONSEQUENCES. To change the ontology, triggers, recipes, skills or guidance, commit to .knomit/ through git and get it onto the branch that reads it (see the overview's 'where each piece is read'); no MCP tool can. To keep agent state out of search and triggers, use artifacts/, not a kb/ topic.

MISREADINGS. '.knomit/ is hidden from agents': no, it is readable by exact path; only writes are closed. 'An artifact is a fact in a special folder': no, nothing indexes it; find it only by its exact path.

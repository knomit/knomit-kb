# Ontology guide — topic attributes: an `attributes:` map on a topic or child node switches store behaviour for facts under it and is inherited down the tree (nearest declared node wins, an undeclared category inherits from its deepest declared ancestor); the only topic key on dev is learn_dedup: off|on, read by knomit_learn alone; an unknown key is a warning, a bad value for a known key is FATAL

Part of the ontology guide (kb/architecture/fact/ontology/guide/). Describes merged dev at c9c599de.

DECLARATION. Every key is declared in ONE place, attributeRegistry (internal/fact/ontology.go), with: accepts (text for diagnostics), valid(value), absent (the value that means the same as leaving it out) and scope (scopeTopic or scopeRoot). Topic-scoped keys live on topic/child nodes; root-scoped keys in the document's root `attributes:` block (see kb/architecture/fact/ontology/guide/root-attributes).

RESOLUTION. Built once at parse into a per-topic cache: each declared path's map is its own attributes laid over everything inherited. Ontology.Attr(topicPath, key) walks root -> topic -> each DECLARED child (lowercasing segments), stops at the first undeclared segment, and returns the nearest declared value. Callers use a named helper (LearnDedupOff), never the raw node map, which holds only that node's own values.

THE ONE KEY: learn_dedup. Exactly the strings "off" or "on" (a YAML bool is rejected on purpose; the bare scalar off decodes as the string). "on" behaves as absent and lets a child undo a parent's off. off makes knomit_learn skip BOTH its auto-merge search and its same-subject refusal for facts under that topic. Review's dedup, prune and distill never read it.

STRICTNESS. Unknown key on a topic: warning, ignored, preserved on write-back (it may be a newer knomit's). Root-scoped key on a topic: warning that ParseNewOntology refuses (wrong scope), ignored. Bad value for a known topic key: FATAL on every path, including opening an existing repo (the repo then refuses writes), because silently treating it as absent would run dedup a newer binary switched off.

CONSEQUENCES. Use learn_dedup: off for categories of many near-identical coordination facts (claims, verdicts, queues) that must not fold into each other. Remember learn's dedup searches by CATEGORY STRING PREFIX within a topic: a fact written to `x/guide` is compared with facts under `x/guide/...` and can be merged into one of them; pass distinct_from (or set learn_dedup: off) when an overview sits above its components. Setting any topic attribute on a preset-derived repo stops preset auto-upgrades for it.

MISREADINGS. 'Topic attributes are free-form flags': no, an unregistered key does nothing. 'learn_dedup: off disables all deduplication': no, only knomit_learn's.

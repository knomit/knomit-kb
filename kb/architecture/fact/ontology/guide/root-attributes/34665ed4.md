# Ontology guide — root attributes: the root `attributes:` block holds four repository-level keys — verify_signatures (off|log|enforce), consensus (off|auto), conflicts {facts, state}, sync {push, pull} — each read by its own ReadX function over ONLY the root block, at a named branch tip, by a named component; they never inherit into topics, and a bad value is a warning on open, fatal on create, and read as a key-specific safe value

Part of the ontology guide (kb/architecture/fact/ontology/guide/). Describes merged dev at c9c599de. One row per key: values; absent; reader; where read; what a bad value does.

verify_signatures — "off" | "log" | "enforce"; absent = off. fact.ReadVerifySettings, read at the tip of the main being advanced: receive-pack at the HOST's upstream tip (judges pushed commits), `knomit verify ci` at its --main checkout, and the trigger dispatcher at the observed head (change.author.verified). Bad value: the setting is UNKNOWN, never off — the gate cannot run (exit 2 / push refused). It is the ONLY verification setting; who may sign comes from the fleet repository's member records.

consensus — "off" | "auto"; absent = off. fact.ReadConsensus, read by the consensus merger at the CONSENSUS branch's tip. auto: on a no-origin, writable, non-subscribed repo every pushed peer branch is merged into this instance's agent branch; a repo with an origin ignores it (one warning). Bad value: read as off with one warning per ontology blob (off is the safe reading).

conflicts — an OBJECT: facts: off | merge | merge:consensus | consensus; state: off | consensus. fact.ReadConflicts, read at the consensus branch's tip by every merge site (a peer's sync merge, the host's MergePushed and MergeConsensus, experiment commits). Absent key: off, EXCEPT under consensus: auto, where it reads facts: merge / state: consensus. Bad value (the old scalar, unknown inner key, value outside a set): off for BOTH keys, not the auto default, warned once per blob.

sync — an OBJECT: push: realtime | interval; pull: realtime | interval; absent key = interval. fact.ReadSync, read by the sync loop at the consensus branch's tip at loop start and before every wait. Subscriptions ignore it. Bad value: interval for both keys, warned once.

COMMON RULES. Root attributes do not inherit and are not resolved by Ontology.Attr. Each ReadX reads only the root block, through the registry validator, so a problem elsewhere in the file cannot change a repository setting. Strictness: unknown root key = warning (open and create), preserved; topic-scoped key at root, or a bad root value = warning on open (newOnly), refused by ParseNewOntology. The boot preset refresh never adds, changes or drops a root attribute. The keys are documented set-once-and-forget: nothing coordinates a change across instances, and an instance whose consensus branch lags reads the old value for a round.

CONSEQUENCES. To change one, commit the ontology on the KB's main (any principal who can merge there may); each component sees it at its next read of that tip, not at the mount-time snapshot. A preset-derived repo that sets any root attribute stops receiving preset upgrades.

MISREADINGS. 'Root attributes are read from the repo's validation ontology': no, from the named branch tip at each use. 'A misspelt verify_signatures is off': no, it stops the gate; the other three fall back to their off/interval reading.

UPDATE (PR #514): the embedded fleet preset declares verify_signatures: enforce and an artifacts: section (the latter is NOT a root attribute: see kb/architecture/fact/ontology/guide/artifact-rules/e544cf71.md). refreshDivergence never adds a root attribute or artifact rule, so an EXISTING fleet repository whose stored ontology lacks them keeps its file, logs divergence `attributes` and stays at its own setting (verify_signatures off unless it wrote one) until a commit to its main adds them. verify_signatures: log/enforce is also the switch that makes the artifacts rules run; off means they are neither read nor enforced. MISREADING: 'upgrading knomit turns on enforcement for an existing fleet repository': no.

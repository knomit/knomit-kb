# Ontology guide — topics, presets and the ontology's lifecycle: an ontology is chosen once at create time (preset `default`/`code`, custom YAML, or a repo template; never `fleet`, a reserved id built into the product), lives at .knomit/ontology.yaml, is snapshotted per repo at mount from its read branch, and changes afterwards only by git commits or the boot refresh that rewrites a preset-derived file when it is a strict subset of the newer embedded preset (the fleet ontology is refreshed separately, wholesale, by the master)

Part of the ontology guide (kb/architecture/fact/ontology/guide/). Describes merged dev at 3e2e83b0 (PR #514), except the preset list, fleet and refresh passages, which describe 1a6c03f7 (PR #520).

SHAPE. Document root: id, name, description, topics (required, at least one), validations, attributes (repository-level), artifacts (rules for files under artifacts/, PR #514), guidance. Topic/child node: description, children, validations, attributes (topic-level), triggers, context, guidance. Topic and child keys are lowercase kebab-case. A bare key (`alpha:` with nothing under it) is a nil node that is still declared. Unknown fields are reported (warnings) and preserved by Serialize so a newer knomit's keys survive.

PRESETS (embedded in internal/fact). Two: name "default" -> id general (ontology_default.yaml), "code" -> id source-code (ontology_code.yaml: invariants, architecture, conventions, decisions, gotchas, incidents, meta, principles). The create wizard lists both (GET /api/v1/ontologies/presets). EmbeddedPresetByID maps a stored id back to its preset. The FLEET ontology (id fleet; ontology_fleet.yaml: one `members` topic, the root attributes verify_signatures: enforce and consensus: auto, and an artifacts: section for artifacts/fleet/) is NOT a preset: it is built into the product as fact.FleetOntology, GET /api/v1/ontologies/presets/fleet is 404, and the id is reserved (kb/invariants/fleet/baked-ontology/reserved-id/4cdcf99e.md).

CREATE. resolveOntology: mode custom (and initialize with YAML) parses with ParseNewOntology (strict: warnings that the open path tolerates are refused); a preset name otherwise; the default preset when nothing is given. Templates: a folder .knomit/templates/<name>/ (README.md + .knomit/** only) at an active mounted repo's consensus tip; its ontology must parse as a NEW ontology and may carry a preset id only if it IS that preset; a template with the fleet id is refused in every mode (ErrFleetOntologyReserved). Clone and subscribe take the remote's ontology, except that a fleet-id one is refused at Identify and rolled back.

LOAD. At the lifecycle Identify stage, RepoInstance.loadOntology reads the READ branch (agent branch when hosted, upstream when subscribed) and NEVER substitutes a default: missing, empty or unparsable means the repo opens readable but unwritable; a symlink refuses the repo. That snapshot drives every write-time check (ValidatePath, validations, context, learn_dedup) until the repo is re-identified; an ontology commit arriving by sync is not seen until then.

REFRESH. If the stored id is a preset's and the repo is not a subscription: when refreshDivergence finds nothing (SubsetDivergence = "", which also counts root attributes and the artifacts: section, AND root attributes identical) and the bytes differ, the preset is written over the file (a signed commit on the read branch). Divergence reasons, by priority: shape (a topic, child or validation name the preset lacks), attributes (a topic attribute the preset does not carry identically, ANY root-attribute difference, or a stored artifacts: rule the preset lacks or declares differently), triggers, context, guidance. A diverged repo keeps its file and forgoes upgrades, with a warning naming the reason. Validations match by NAME only, so a preset can fix a rule's body.

FLEET REFRESH (separate path). A fleet-id ontology skips the preset loop: loadOntology calls refreshFleetOntology, which replaces the stored file with the built-in one wholesale, on the master only (root.key is a regular file in <home>/fleet AND the local root.crt equals artifacts/fleet/root.crt on the fleet repository's main) and only for the mount that has the fleet door. Members and unadmitted mounts never write it. See kb/invariants/fleet/baked-ontology/master-refresh/d62746d2.md.

CONSEQUENCES. A preset repo that sets learn_dedup, any root attribute, a trigger, a context key or guidance stops receiving preset upgrades. Removing or renaming a topic orphans facts: there is no editor and no migration. A new topic attribute added to an embedded preset reaches existing subset repos at their next boot; a new ROOT attribute in a preset never does (and blocks refresh for every repo that lacks it). The fleet ontology's verify_signatures: enforce, consensus: auto and artifacts: section reach NEW fleet repositories at create and an EXISTING one through the master's wholesale refresh.

MISREADINGS. 'Immutable after create' means no knomit editor and no tool write; the file is still a git file that a human commit can change, and root attributes are routinely changed that way. 'The repo validates against the consensus tip': no, against its mount-time snapshot of the read branch.

UPDATE (PR #514, corrected by PR #520): a stored artifacts: rule that a preset does not declare identically is reported as divergence reason `attributes` (SubsetDivergence via artifactsNotSubset; there is no separate reason name), so such a repo is never refreshed. fact.ArtifactRulesEqual no longer exists: a preset that would ADD an artifacts: section is not blocked, which cannot arise today because neither preset declares one. See kb/architecture/fact/ontology/guide/artifact-rules/e544cf71.md.

# TriggerCache holds the compiled triggers of ONE ontology blob: a different blob recompiles every trigger and its `if`, and the old programs become unreachable; an unparseable blob keeps the last good set

`TriggerCache.Get(blob, data, id)` (internal/fact/triggers.go):
- It returns the cached `TriggerSet` when the blob hash and instance identity are unchanged. It does not compile, and the `compiles` counter is a test hook.
- On a different blob it parses the ontology and `CompileTriggers` REPLACES the single entry. So a changed `if`, `match` or `do` runs as the new program on the next evaluation, and the previous compiled `*goja.Program` is no longer referenced.
- On a blob that does not parse at all it returns the LAST GOOD set together with the error, so one broken commit does not switch every trigger off.
- A replacement that breaks one trigger makes that trigger `invalid` (still declared, bookmark frozen), and the old program is NOT used in its place.

WHY a single entry keyed by blob: the user requirement "if a loaded trigger or recipe is changed in the repo, then knomit must reload that trigger / recipe goja VM" (2026-09-27), plus decision D-b: triggers come from the ontology at the observed branch's HEAD, not from the open-time snapshot `RepoInstance.Ontology()`, which is never re-read while the server runs.

`CompiledTrigger.EvalIf` runs a condition in a FRESH `goja.New()` per call, with `process`/`require` deleted and the validations' `ruleEvalTimeout` (100 ms) enforced through `vm.Interrupt`. The globals (`fact`, `agent`, `change`) are passed as JSON copies that a JS deepFreeze freezes: a condition can neither mutate the caller's maps nor keep state between evaluations. A throw or timeout is returned as an error; the dispatcher counts it as false.

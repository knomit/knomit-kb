# An inline `js:` trigger script (F08, R9) is compiled in compileTrigger with the ontology — a bad one is `invalid`, never a per-fire script-error — through a PROCESS-WIDE cache keyed by (trigger name, sha256 of the source), so an ontology edit elsewhere recompiles nothing; the dispatcher installs it keyed by JSKey = "js:"+16 hex

F08 PR A (M4). `js: <code>` on a `do: script` trigger replaces the `.knomit/triggers/<script>.js` file; exactly one of `script` and `js` (both → invalid "js and script are mutually exclusive"; neither → "do: script needs script (a file name) or js (inline code)"; `js` on another `do` → invalid). A YAML block scalar `js: |` decodes verbatim and Serialize writes it back.

Where it compiles and why it matters:
- compileTrigger calls compileInlineJS(name, src). A compile error makes the trigger INVALID ("js does not compile: …"), logged ERROR once per blob and shown on the endpoint — stricter than a missing file script, which stays active and logs a script-error per fire. The code is right there, so it is judged with the entry.
- TriggerCache recompiles the whole TriggerSet whenever the ontology BLOB changes (any edit anywhere in the file). The inline program survives that because compileInlineJS keeps a process-wide map keyed by name + "\x00" + sha256(src) (bounded at 4096 entries, then dropped and refilled). fact.InlineJSCompilesForTest counts misses.
- The dispatcher's loadScripts has a js arm: it installs compiledScript{script: "<name>:js", blob: ct.JSKey, prog: ct.JSProgram()} and replaces it only when the key or program changes; no second compile. rateAllows, warnOnce keys (<trigger>@<blob>), the loop guard (Knomit-Trigger = the trigger NAME) and runScript work unchanged.
- TriggerState.JS / TriggerView.JS (json `js`) expose the code on GET …/triggers; openapi documents it.

Consequence for a consumer: to test a js change, assert the EDITED program's effect on the next fire, not only a compile counter — a cache keyed by trigger name alone would bump nothing and keep running the old code (TestTriggers_InlineJSCacheBySource does both).

NOT in scope (R9): recipes stay files (`.knomit/recipes/<name>.js` on main or `<home>/recipes/`); an older knomit marks a js trigger invalid ("unknown key"), which the user ruled is not a concern.

# fact.MergeVersions merges two versions of ONE fact against their common base, field by field. A field only one side changed keeps that side, and the strategy decides only fields both sides changed differently. Title and body are taken whole, lists get a three-way set merge, and sources/confidence are never summed or maxed

`fact.MergeVersions(path, base, src, dst, strategy) (out, rec, ok)` is the git-merge-time counterpart of dedup. Dedup merges two DIFFERENT facts with no ancestor, so it guesses: union, max, sum. Here the ancestor exists and is used.

PER FIELD, compared to the base:
- neither side changed it: base;
- one side changed it: that side, with no strategy involved;
- both changed it to the same value: that value;
- both changed it differently: the strategy's winner, listed in `rec.Decided`.

Kind+type+origin form ONE field (`type`), because they validate together. Title and body are picked WHOLE from one side, never spliced (ruling 4; blending is the future LLM merger's job). Lists (domain, entities, motifs, refs) are merged as sets: `(src ∪ dst) − (base − src) − (base − dst)`, with the winner's order first, then the loser's additions. A list only one side changed is taken exactly as that side wrote it. Motifs are cut at MaxMotifs, and the cut is recorded as decided. A bare self-ref is dropped. `base == nil` (add/add) makes every differing field the strategy's, and lists union.

STRATEGIES (`MergeStrategy{Rule, Upstream}`):
- `confidence` (the default) is dedup's winner rule made symmetric: higher confidence, then more sources, then non-hypothesis, then the smaller git blob hash of the input bytes.
- `upstream` takes the consensus side (`Upstream` names which argument that is).
- `trusted` is not built (there is no member rank).

ok=false makes the caller fall back to its site's side-pick. It happens when a side does not parse, the kinds differ, a side is NOT LOSSLESS through ParseFact→SerializeFact (an unknown frontmatter key, a dropped ref, motif or expires, a round trip that differs), or the output does not round-trip exactly. A merge must never drop what a side wrote.

CONSEQUENCE: the function is pure. It uses no clock, no embedding and no local state, and its choices depend on content, never on argument position. Merge(b,x,y) == Merge(b,y,x) byte for byte, so the peer and the host compute the same bytes and converge in one round.

MISREADINGS:
- 'it merges like dedup' is wrong: sources are NOT summed and confidence is NOT maxed. A side that lowered confidence keeps its lower value when the other side left it alone.
- 'ok=false is an error' is wrong: it means 'pick a side as the site always did, and record it'.

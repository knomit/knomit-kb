# ValidatePath constrains the PREFIX of a fact path; tail is freeform once tree walk fails

Ontology.ValidatePath(path) walks the path against the ontology tree: first segment MUST match a top-level topic (case-insensitive); subsequent segments walked against defined children; ONCE no matching child is found, the remaining segments are accepted as FREEFORM. This means the ontology constrains the PREFIX of a path but not its tail — 'kb/technology/some/freeform/leaf.md' is valid even if 'some'/'freeform'/'leaf.md' aren't in the tree, as long as 'technology' is a defined topic. The lowercase comparison (strings.ToLower(parts[0])) means ontology lookups are case-insensitive even though the keys themselves must be lowercase by validateKeys. Anti-pattern: requiring full-tree match — would force the ontology to enumerate every possible category, defeating the freeform-tail design that lets categories grow organically.

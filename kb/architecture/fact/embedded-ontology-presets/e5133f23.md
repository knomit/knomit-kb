# Three embedded ontology presets — default (id general), code (id source-code), fleet (id fleet); lazy sync.Once parse that panics on a broken file; OntologyByPreset selects by name, EmbeddedPresetByID by id

internal/fact/ embeds THREE ontology presets via //go:embed: ontology_default.yaml (name 'default', id 'general', general-purpose), ontology_code.yaml (name 'code', id 'source-code', source-code knowledge with topics invariants/architecture/conventions/decisions/gotchas/incidents/meta/principles) and ontology_fleet.yaml (name 'fleet', id 'fleet', FleetOntologyID: one `members` topic with the `members-are-policy` validation and no root attributes; a repo with this id IS the fleet repository). Each is parsed lazily via sync.Once (DefaultOntology / CodeOntology / FleetOntology) — the parse PANICS on failure to guard against shipping a broken yaml file. OntologyByPreset(name) selects by name ('default', 'code' or 'fleet') and errors on unknown; EmbeddedPresetByID(id) selects by ontology id ('general', 'source-code', 'fleet') for the boot-time refresh. The create wizard's preset list (GET /api/v1/ontologies/presets, presetNames in internal/web/handlers_ontologies.go) offers only default and code; fleet is reached by preset name in a create request or by a fleet-id template. Adding a new preset: add the .yaml file under internal/fact/, add a //go:embed var + sync.Once accessor, add a case to OntologyByPreset AND EmbeddedPresetByID, and add it to presetNames if the wizard should list it.

UPDATE 2026-10-14 (verified at dev c9c599de): the earlier version said TWO presets and mentioned a `knomit init --ontology-preset` flag; the fleet preset was added since and no such flag exists in cmd/ at that commit.

WHAT THIS DOES NOT MEAN: the source-code topic list is NOT frozen — the authoritative list is ontology_code.yaml itself, not this fact. Do not hardcode the topic set from this fact; read the yaml or call CodeOntology().TopicNames(). See the ontology guide, kb/architecture/fact/ontology/guide/topics-and-presets.

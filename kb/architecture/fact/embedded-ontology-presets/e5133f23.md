# Two embedded ontology presets — default (id general) and code (id source-code) — plus the built-in fleet ontology (id fleet), which is NOT a preset; lazy sync.Once parse that panics on a broken file; OntologyByPreset selects by name, EmbeddedPresetByID by id, and neither knows fleet

internal/domain/fact/ embeds TWO ontology presets via //go:embed: ontology_default.yaml (name 'default', id 'general', general-purpose) and ontology_code.yaml (name 'code', id 'source-code', source-code knowledge with topics invariants/architecture/conventions/decisions/gotchas/incidents/meta/principles). Each is parsed lazily via sync.Once (DefaultOntology / CodeOntology) — the parse PANICS on failure to guard against shipping a broken yaml file. OntologyByPreset(name) selects by name ('default' or 'code') and errors on anything else, including 'fleet'; EmbeddedPresetByID(id) selects by ontology id ('general', 'source-code') for the boot-time refresh and templates, and returns nil for 'fleet'. The create wizard's preset list (GET /api/v1/ontologies/presets, presetNames in internal/web/handlers_ontologies.go) offers default and code, and GET /api/v1/ontologies/presets/fleet is 404 (unknown preset). Adding a new preset: add the .yaml file under internal/domain/fact/, add a //go:embed var + sync.Once accessor, add a case to OntologyByPreset AND EmbeddedPresetByID, and add it to presetNames if the wizard should list it.

THE FLEET ONTOLOGY IS EMBEDDED BUT NOT A PRESET (since PR #520, verified at merge commit 1a6c03f7). ontology_fleet.yaml (id 'fleet', FleetOntologyID: one `members` topic with the `members-are-policy` validation, root attributes verify_signatures: enforce and consensus: auto, and an artifacts: section; a repo with this id IS the fleet repository) is parsed lazily the same way (FleetOntology, which panics on a broken file) but is reached only from fleet code: no create mode offers it, and the id is reserved at every generic door (kb/invariants/fleet/baked-ontology/reserved-id/4cdcf99e.md). Do not add a fleet arm back to OntologyByPreset or EmbeddedPresetByID: the boot refresh, template preset identity and the preset picker would all start treating it as an ordinary preset.

UPDATE 2026-10-15 (PR #520): the earlier version of this fact said THREE presets, including fleet reachable by preset name or by a fleet-id template; both are gone.

WHAT THIS DOES NOT MEAN: the source-code topic list is NOT frozen — the authoritative list is ontology_code.yaml itself, not this fact. Do not hardcode the topic set from this fact; read the yaml or call CodeOntology().TopicNames(). See the ontology guide, kb/architecture/fact/ontology/guide/topics-and-presets.

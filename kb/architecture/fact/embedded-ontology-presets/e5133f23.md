# Two embedded ontology presets (default, code); lazy sync.Once parse; OntologyByPreset selects

internal/fact/ embeds TWO ontology presets via //go:embed: ontology_default.yaml (id 'general', general-purpose) and ontology_code.yaml (id 'source-code', source-code knowledge with topics invariants/architecture/conventions/decisions/gotchas/incidents/meta/principles). Each is parsed lazily via sync.Once (defaultOntology / codeOntology package vars) — the parsing PANICS on failure to guard against shipping a broken yaml file (release would never start). DefaultOntology() returns the general preset; CodeOntology() returns the code preset; OntologyByPreset(name) selects by name ('default' or 'code') and errors on unknown; EmbeddedPresetByID(id) selects by ontology id ('general'/'source-code') for boot-time refresh. Added via the `knomit init --ontology-preset <name>` flag. Adding a new preset: add the .yaml file under internal/fact/, add a //go:embed var + sync.Once accessor, add a case to OntologyByPreset.

WHAT THIS DOES NOT MEAN: the source-code topic list is NOT frozen at seven topics — `principles` is present (8 total), and the authoritative list is ontology_code.yaml itself, not this fact. Do not hardcode the topic set from this fact; read the yaml or call CodeOntology().TopicNames(). The topic set grows as presets evolve.

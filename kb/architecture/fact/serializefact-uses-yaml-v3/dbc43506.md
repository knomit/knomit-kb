# SerializeFact uses yaml.v3 with strScalar !!str tag so list items like 'null', 'yes' round-trip

SerializeFact uses gopkg.in/yaml.v3 (the SAME library as ParseFact) instead of hand-rolled string concatenation. Why this matters: list items like 'null', 'yes', 'No', 'true' would auto-resolve to YAML null/bool by yaml.v3's resolver — 'entities: [No, yes, null, true]' would parse back as ['No', 'yes', 'true'] (null becomes Go nil and is dropped from the slice). strScalar pins Tag: '!!str' on list items so yaml.v3 quotes them when needed to preserve the string tag. Items that don't collide with YAML keywords stay unquoted (yaml.v3 only quotes when needed). Inline lists use yaml.FlowStyle to preserve the compact one-line-per-key layout. Anti-pattern: hand-rolled fmt.Sprintf('[%s, %s]', ...) for list emission — gets escaping wrong for any path containing [, ], ',', or yaml keyword.

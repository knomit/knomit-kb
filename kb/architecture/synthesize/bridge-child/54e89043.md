# internal/corpus/synthesize/bridge holds the bridge enumeration, scoring, filtering, reshape, lineage, motif and report code; the parent keeps only MotifComponentReport (the seed pool via reviewStrategy.AcceptSeed), which hands the pool to bridge.MotifReportFromSeeds

The bridge child (PR 607) holds bridge, bridge_filtered, bridge_lineage, bridge_motif, bridge_report, bridge_reshape, bridge_score, quality_config, motif_disjoint and the report half of bridge_motif_report. DECISION on the split of bridge_motif_report.go: the parent keeps MotifComponentReport (it builds the seed pool through reviewStrategy.AcceptSeed, Search and FactsForLLM) and calls bridge.MotifReportFromSeeds with that pool. Leaving the whole report in the parent would have exported scoredMotifRow's fields and about 15 helpers for one calibrate report. The parent function does real work first, so it is not a forward.

ForwardDiscoverPriority lives with maxBridgeSeeds in bridge: maxBridgeSeeds is defined from the priority band (step.ForwardDiscoverPriorityBase - step.ReflectPriority), and the test that proves the deepest rank stays above reflect needs both, so the constant stays unexported and the band test moved with it. EnumerateBridgeCandidates is a test-only export, kept because the fixture check must enumerate the SAME hand-built partition the session test uses (BuildScoredBridges/BuildFilteredBridges apply gates, BridgeComponentReport re-clusters), and its doc comment says why.

Layering: bridge imports exactly repos, graph, step, domain/fact (+textnorm), store/index and store/vocab; the only repos user is QualityConfigFromRepo(*repos.RepoInstance), which predates the move. No bridge -> parent edge. MotifResolverFor, PairCosFor and MotifBridgeHealthLines are exported but use unexported types (motifResolver, pairCosFn, motifEnumHealth) on purpose; do not export the types to 'fix' that.

Does NOT mean: any behaviour changed. The review diffed all nine moved production files; only package clause, export renames and comments differ.

# The expert eval runner (synthesize.RunEval, driven by TestEvalRun with EXPERT_EVAL_CONFIG) writes one JSON record per (world, question, arm, mode) under <out>/records/<arm>/<mode>/<world>/<question>.json, Test J records under mode J, and summary.json/summary.md with percentile-bootstrap intervals per arm x mode, overall and per family and ontology

internal/synthesize/eval_runner.go (RunEval), eval_summary.go (Summarize), eval_config.go (EvalConfig, YAML, strict). Entry: `EXPERT_EVAL_CONFIG=/abs/eval.yaml go test -count=1 -timeout 0 -run '^TestEvalRun$' -v ./internal/synthesize/` — a go test driver, not a knomit command, because the runner needs mcp.NewScriptTools (internal/mcp imports synthesize) and the real-embedder wiring the loader validation already uses.

EvalRecord fields: world, question, family (the question's), ontology (spec ontology_shape), pool, arm, mode (H|M2|M4|MF), spec_hash, script_sha (sha256 of the embedded reason.js), reason_run, outcome, gold_outcome, score (GradeChain's ChainScore), result (the full ReasonChain), failed_judgments (every chain step whose verdict starts `failed:`), unjudged (the gaps' ReasonGap.Unjudged), model_calls, wall_ms, rolled_back (read back from the store after RollbackExperiment, not assumed), kept, error. ReplayRecord (mode J): one per (world, question, arm) with items [{step, judgment, n, correct, accuracy, failed, gold_on_menu, top_matches, output, reason_run, wall_ms}].

Summary rows (MetricRow {arm, mode, by: all|family|ontology, group, metric, n, mean, lo, hi}): per chain correct, outcome_correct, move_accuracy, move_recall, relevance_precision/recall, support_accuracy, misattribution, chain_recall/precision, answer_validity, ref_correctness, brier, failed_judgments, unjudged, error, model_calls, wall_s; per set gap_recall, false_gap_rate, ece (10 bins). Replay rows: <judgment>_accuracy (pooled correct/asked), <judgment>_failed, choose_move_top_baseline (the harness's top-ranked entry is a gold move — E01's mechanical baseline) and choose_move_gold_on_menu. Intervals: 95% percentile bootstrap over questions (items for J), resamples from config (default 1000), seeded per row from config seed + row name so a row does not depend on others. Bars: none in code; `bars:` in the config compares an arm/mode mean to ratio x a reference arm/mode or to a value (direction higher|lower), per the ruling that bars are fixed relative to Opus and the 1.2B after they are scored.

Resumable: an existing record is skipped; one written for a different spec_hash or script_sha is refused (use a new out dir). Every engine run is keyed by reason_run in the engine's own log lines, and the runner adds one `eval record` / `eval replay` line per record carrying reason_run, world, question, arm, mode.

What this does NOT mean: a record's `correct` with the gold oracle is not 1 everywhere — on the scenarios repo's six pilot worlds plus one F1, F11 and F13 world the oracle reaches 10 of 18 (F4 and F7 zero), so a low arm score must be read against the oracle's ceiling on the same worlds.

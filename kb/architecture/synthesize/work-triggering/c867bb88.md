# Pipeline work is two channels — edge-triggered seeding from the watermark diff, and a standing-pairs restatement shortlist — but post backfill-ripout the shortlist is only PLANNED when the dirty set is non-empty

Edge-triggered channel: dirtyFacts seeds review from the watermark's commit diff — only facts changed since the last run. Standing-state channel: the cross-cluster restatement shortlist (motif phase 0, PR #99) reads standing `restatement_pairs` each session — corpus-wide detection, no watermark, no scope.

Why the second channel exists: two unchanged facts that restate the same claim are STRUCTURALLY invisible to edge-triggered review — once the watermark passes them, neither is ever dirty again unless edited, so per-cluster review can never re-surface the pair. The standing-state channel is the repair loop for exactly that debt, budget-bounded, not a rescan.

SINCE THE BACKFILL RIP-OUT (dev 97f54077, PR #161): the level-triggered planning machinery (#128's planLevelTriggered / HasLevelTriggeredWork) was REMOVED with backfill, and planRestatementShortlist is called inside reviewStrategy.Plan — which pipeline.go's empty-seed early return short-circuits BEFORE reaching. So on a session with an empty dirty set, the shortlist is NOT planned: a quiet (caught-up) corpus does not drain its standing-pair backlog; the sweep advances only while the corpus keeps changing. The early return carries a warning comment naming this exact trap: "a pass whose trigger is corpus state cannot be planned from an edge-triggered seed scan, and this early return is where it would be silently starved again."

Consequence: any corpus-state-triggered work (the #155 structural sweep above all) must be planned from corpus state, not from inside the edge-triggered Plan — or it silently starves on exactly the corpora that are caught up. Growth of `restatement_pairs` is still detection INVENTORY, not an offer queue: the offer rate is capped by the budget reserve.

WHAT THIS DOES NOT MEAN: it does not mean the watermark gates DETECTION (pair detection remains corpus-wide when it runs), and it does not mean shortlist pairs are unrelated facts — pair members are related TO EACH OTHER (path identity, shared rare token, title cosine); they are merely unrelated to the current session's changes.

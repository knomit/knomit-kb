# internal/corpus/synthesize/motif holds motif_alias.go and motif_define.go (alias pair selection, judge decode/apply, blind definition pass) and imports only step, store/model and store/vocab; the parent reaches it through 18 exported names that all have a production user

The motif child package (PR 606) holds motif_alias.go (alias pair selection plus judge decode/apply) and motif_define.go (the blind definition pass) with the tests that need neither Pipeline/Reviewer nor the parent's prompts. It imports step, store/model and store/vocab only; TestLayers gained the edge motif -> step.

The parent reaches it through 18 exported names, each with a production user in review_strategy.go or prompt_review.go: AliasStepType, DefineStepType, AliasResult, DefineResult, DefineItem, JudgeItem, Parse/Validate/Apply/Plan for both Alias and Define, DefineItemsFromPayload, VocabularySection, AliasResponseSchema, DefineResponseSchema. Tests that read prompts/large/motif_*_user.txt or render the reflect payload (RenderReflectWorkItem) stay in the parent. synthtest.NumberWord is the one test-only export (used by the motif tests and three parent tests).

Does NOT mean: the motif gate moved. The effort gate (Effort.MaintainsVocabulary(), effort >= medium; invariant def9f8b4) still wraps RebuildAliases, PlanAliasWork and PlanDefineWork in review_strategy.go, and the mechanical alias merge stays ungated. Motif code still calls no model (MN2); the child's package doc says so.

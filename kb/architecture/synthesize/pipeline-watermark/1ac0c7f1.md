# The pipeline watermark is branch-scoped sqlite in the repo DB, and CreateBranch does NOT copy it — a fresh agent branch is FULL-CORPUS DIRTY on its first pipeline run

The dirty-fact watermark lives in `pipeline_watermarks(tool, branch, commit_hash)` in the repo DB (migration 000001). It deliberately stays in the main DB rather than the per-session DB (session_schema.sql: "progress (pipeline_watermarks) deliberately stays in the main DB"), and migration 000010 intentionally does not drop it. It is NOT in git and NOT inherited on branch creation: CreateBranch clones branch_commits, branch_facts, and the SYNC watermark (`meta` key `last_commit:<branch>`) only — no `pipeline_watermarks` rows. dirtyFacts then takes the full-scan path on "no watermark → first run, all facts are dirty" (seedScanFull).

Consequence: a branch-per-agent workflow pays a full-corpus reprocess on every new branch's first pipeline run, and any state keyed to the old branch (e.g. branch_id-scoped verdict caches) does not shield it. The same applies after any rebuild that loses the repo DB.

STILL TRUE OF CreateBranch AFTER EXPERIMENTS (PR #235), and deliberately so. `OpenExperiment` copies the parent's `pipeline_watermarks` rows ITSELF, after calling CreateBranch — a sibling step rather than a flag, precisely so this fact needed no exception. So an EXPERIMENT is not full-corpus dirty on its first review: it seeds its own delta since the fork. Every other CreateBranch caller still is. If you fork a branch by any other route and want the pipeline watermark, you must copy it yourself; see decisions/store/experiments/fork-copies-watermarks.

WHAT THIS DOES NOT MEAN: steady-state runs do not rescan — with a watermark present, seeding is an incremental commit diff, exactly as designed. The full scan fires only on first-run-per-branch, DB loss, or a scoped run (scoped runs are watermark-exempt by decision, see scope-filter).

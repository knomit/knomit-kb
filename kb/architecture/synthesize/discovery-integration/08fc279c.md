# Discovery rides existing pipeline infra: a `discover` work-item step, pipeline_sessions.effort, and a [discovery] config section

Discovery reuses the work-stealing pipeline rather than new infra. A new `discover` StepType carries a DiscoverWorkPayload{Direction, Bridge} as FactsJSON; review.StartSession (forward) and hypothesize enqueueBackwardBridgeItems (backward) insert them, the dispatchers render the strict default-skip prompt (RenderDiscoverWorkItem), and ContinueSession applies the response through the gate chain. Discover items are priced BELOW the standard prune/distill/hypothesize items so they run last (backward uses Priority = -100 - i over the blast-ranked list — always negative, can't leapfrog a positive standard item). pipeline_sessions gained an `effort` column (CreatePipelineSessionWithEffort); the session DB is deleted+recreated fresh on every Service.Open, so this schema edit needs NO migration. Thresholds come from a new [discovery] config section (effort_default, confidence_threshold, blast_radius_threshold, bridge) + env overrides + four RepoInstance accessors. Genuine per-repo overrides remain a follow-on — no per-repo config layer exists yet; these are global Config fields surfaced through RepoInstance, the existing idiom.

# Discovery rides existing pipeline infra: a 'discover' work-item step + a [discovery] config section (effort is in-memory on the Reviewer, NOT a persisted session column)

Discovery reuses the work-stealing pipeline rather than new infra. A new `discover` StepType carries a DiscoverWorkPayload{Direction, Bridge, ScopeLabel} as FactsJSON; review.StartSession (forward) and hypothesize enqueueBackwardBridgeItems (backward) insert them, the dispatchers render the strict default-skip prompt (RenderDiscoverWorkItem), and ContinueSession applies the response through the gate chain. Discover items are priced BELOW the standard prune/distill/hypothesize items so they run last: forward uses forwardDiscoverPriority (base -10 minus rank), backward uses Priority = -100 - i over the blast-ranked list — both always negative, can't leapfrog a positive standard item, and both stay above reflectPriority (-100).

WHAT THIS DOES NOT MEAN: there is NO pipeline_sessions.effort column and NO CreatePipelineSessionWithEffort. An earlier revision added them; commit 6fb6a79 ('drop dead session effort persistence') removed both. Effort is now carried in-memory on the Reviewer (r.effort, internal/synthesize/effort.go), resolved from config/args at session start — never read back from a session row. CreatePipelineSession(ctx, tool, branch) is the only constructor and inserts no effort. Do NOT query or write pipeline_sessions.effort — it does not exist.

Thresholds come from a [discovery] config section (effort_default, confidence_threshold, blast_radius_threshold, bridge) + env overrides, surfaced through RepoInstance accessors (DiscoveryEffortDefault/DiscoveryConfidenceThreshold/DiscoveryBlastRadiusThreshold/DiscoveryBridge, plus later coherence/quality/weight accessors). Genuine per-repo overrides remain a follow-on — these are global Config fields surfaced through RepoInstance, the existing idiom.

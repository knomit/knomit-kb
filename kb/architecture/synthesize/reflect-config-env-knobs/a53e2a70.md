# Reflect server-side guards are env-tunable: KNOMIT_REFLECT_PROPOSE_CAP, KNOMIT_REFLECT_NOVELTY_THRESHOLD

Reflect-step server-side guards are tunable via env vars in reflect_config.go: KNOMIT_REFLECT_PROPOSE_CAP (default 1, max new methodologies per reflect response) and KNOMIT_REFLECT_NOVELTY_THRESHOLD (cosine similarity floor at which a proposed methodology is rejected as too similar to an existing one; the baseline is the active embedder's calibrated model default passed to reflectNoveltyThreshold(modelDefault), and 0.85 is only the fallback when that default is not positive). Both are validated at runtime via reflectProposeCap() / reflectNoveltyThreshold(modelDefault) helpers — invalid values are logged via log.Warn and the default (for the novelty threshold, the model default) is used. Both are explicitly named 'rarity-bias knobs' in code comments — keep propose capped LOW and novelty threshold HIGH so new methodologies remain rare and unique. The strictest mode is PROPOSE_CAP=0 (operator can fully disable new methodology emission via reflect, forcing all reflect responses to either reinforce existing methodologies or emit nothing). NOVELTY_THRESHOLD is checked in [0, 1] range; out-of-range falls back to the model default (then 0.85).

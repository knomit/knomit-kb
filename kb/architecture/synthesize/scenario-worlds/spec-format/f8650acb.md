# knomit-scenario/v1 is one strictly decoded spec.yaml per world: inline or file ontology, facts by spec-local id, a replayed history of learn/update/retract steps, and questions with gold chain, support/forbidden sets and a gold answer or gap — while role, questions and gold are never written into the world

internal/synthesize/scenario.go defines the format. One spec.yaml per world, decoded with yaml KnownFields(true) and a single document (an unknown key or a second document is an error). Required: format 'knomit-scenario/v1', id; the ontology comes from exactly one of `ontology` (inline) or `ontology_file` (path relative to the spec file); both set is an error. Facts are authored once each, addressed by spec-local `id` (the server mints paths). A ref is `fact:<id>` naming a fact written by an EARLIER history step and not retracted at that point, an https:// URL listed in `external_sources` (never fetched), or a `.knomit/<path>` system file of the world; `src://` is refused (a world has no source checkout). `history` is the commit sequence: a `learn` step (one knomit_learn call, optionally with `retracts`, the atomic move), an `update` step (id plus `set` fields, `refs` being the whole list), or a `retract` step. Each question carries `family`, `outcome` (answer|partly|gap), a gold `chain` (steps with alternative moves, `requires` giving the partial order, `optional`, `surfaces`, `relevant`/`support` labels, `backtrack`), `support` and `forbidden` fact-id sets, `assess`, and a gold `answer` (claim, types, topic/category, must_cite, should_cite, must_not_cite, confidence band, entities, motifs) or a gold `gap` (missing_premise, settlement, partial_support). `tell_check` is only the author's generator-tell self-check note.

What is never written into the world: a fact's `role` (ScenarioRoles), `description`, `families`, the questions and their gold; writing them would hand the engine the answer. Consequence: an author puts planted-structure labels only in the labelled fields, and a loader or grader change must keep them out of the learn arguments (learnArgs copies only knomit_learn fields, plus distinct_from resolved to paths).

Misreading to avoid: `fact:<id>` is a spec-local reference resolved by the loader, not a knomit ref form; it never appears in a stored fact.

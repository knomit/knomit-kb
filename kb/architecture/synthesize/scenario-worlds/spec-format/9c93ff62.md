# A scenario world (knomit-scenario/v1) is ONE strictly decoded spec.yaml: ontology inline or by file, facts by spec-local id, a history of learn/update/retract steps, and questions whose gold is never written into the world

internal/synthesize/scenario.go defines the format. One world is one spec.yaml decoded with yaml KnownFields(true) and a single document, so an unknown key anywhere (a typo) is an error and never drops a field silently. Fields: format (exactly knomit-scenario/v1), id (kebab-case), families (F1..F99, first is primary), ontology_shape, description, tell_check, ontology (the world's own .knomit/ontology.yaml inline) OR ontology_file (a path relative to the spec file; setting both is an error), external_sources, facts, history, questions.

Facts are named by a spec-local id, never a path (the server mints paths). A ref is `fact:<id>`, an https:// URL that is listed in external_sources (stub, never fetched), or a .knomit/ system file of the world; src:// is refused because a world has no source checkout. A `fact:<id>` ref and every distinct_from entry must point at a fact written by an EARLIER history step and still live. History is a list of steps, exactly one kind each: learn (optionally with retracts, knomit_learn's atomic move), update (with a `set` of updatable fields; a refs set replaces the whole list), or retract. Every fact is learned by exactly one step. Each question (1-3 per world) carries a family, an outcome (answer, partly or gap), an assess label, a support set and a forbidden set (disjoint), a gold chain (steps in a partial order via requires; each step lists acceptable alternative moves, the fact ids it should surface, relevant yes/no and support labels, optional and backtrack flags), and a gold answer (outcome answer or partly) or a gold gap (missing_premise and settlement, required for outcome gap).

NEVER written into the world: `role`, `description`, `families`, `tell_check`, the questions and their gold. They are the generator's labels and would hand the engine the answer. tell_check is only an optional authoring note (the author's generator-tell self-check line).

Consequence: a generator emits this shape and the loader (scenario_load.go) replays it; Check is only the static half, so a spec that passes Check can still be refused by the write path. Misreading to avoid: the fact ids in a spec are not paths and not stable across loads; map them with LoadedWorld.Paths and IDOfPath.

# RAPTOR multi-depth distill runs through the SAME work item queue; priority orders depth

RAPTOR (multi-depth distill) doesn't have its own pipeline — it runs through the SAME pipeline_work_items queue as everything else. When a distill work item completes: (1) apply distill decisions (write new synthesized facts to git); (2) if response produced new facts AND depth < maxDepth (3): upsert new facts to index with embeddings (embedder.Embed + idx.Upsert), ScopedCluster on new facts, enqueue new distill items at depth+1; (3) return next work item, or complete session if queue empty. PRIORITY ORDERING: prune items first (priority = cluster size, highest first), then distill depth 0 (priority = -1), then depth 1 (-2), then depth 2 (-3). The depth column on pipeline_work_items is needed by ContinueSession to decide whether to enqueue deeper RAPTOR items. ScopedCluster (after removing the allFacts param) uses idx.Search to find neighbors and cluster.

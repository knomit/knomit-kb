# RAPTOR multi-depth distill runs through the SAME work item queue; priority orders depth

RAPTOR (multi-depth distill) doesn't have its own pipeline — it runs through the SAME pipeline_work_items queue as everything else. When a distill work item completes: (1) apply distill decisions (write new synthesized facts to git); (2) if response produced new facts AND depth < maxRaptorDepth (3): upsert new facts to index with embeddings (embedder.Embed + idx.Upsert), ScopedCluster on new facts, enqueue new distill items at depth+1; (3) return next work item, or complete session if queue empty. PRIORITY ORDERING: prune items first (priority = cluster size, highest first). Distill items use Priority = -nextDepth directly (depth 0 = 0, depth 1 = -1, depth 2 = -2) so SQLite ORDER BY priority DESC drains shallow distill before deeper RAPTOR layers — NOT the fixed -1/-2/-3 tiers an earlier version of this fact described. The depth column on pipeline_work_items is needed by ContinueSession to decide whether to enqueue deeper RAPTOR items. ScopedCluster (after removing the allFacts param) uses idx.Search to find neighbors and cluster.

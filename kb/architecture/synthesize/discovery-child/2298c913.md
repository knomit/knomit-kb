# internal/corpus/synthesize/discovery holds the discover prompt, response parsing, proposal ingest gates and REINFORCE; the discover step itself (decode, apply, enqueue) stays in the parent discover_step.go and reaches the child through three exported functions

At b50d817e (PR #608, step 13g of the internal/ hierarchy; re-read there) package internal/corpus/synthesize/discovery holds discovery.go (the discover prompt, the response schema, ParseDiscoverResponse, the proposal ingest gate chain ApplyDiscoveredProposals) and discovery_reinforce.go (ApplyReinforcements, the REINFORCE write contract) with the tests that need neither Pipeline nor Reviewer. The discover STEP itself (decode the response, apply it, enqueue follow-ups) stays in the parent file discover_step.go, which calls discovery.ParseDiscoverResponse, ApplyDiscoveredProposals and ApplyReinforcements; hypothesize_strategy.go builds the work item through discovery.RenderDiscoverWorkItem. The layer edges (TestLayers) are discovery -> corpus/repos, discovery -> synthesize/bridge and discovery -> synthesize/step; the child imports nothing else from synthesize.

Conventions that follow from the split:
- Parent tests reach the discover response schema through discovery.RenderDiscoverWorkItem(...).ResponseSchema and the prompt through .Prompt. renderDiscoverPrompt and discoverResponseSchema stay UNEXPORTED, so do not export them to satisfy a parent test.
- The shared REINFORCE fixture is synthtest.NewReinforceCorpus (used by the discovery tests and by the parent's bridge_motif_dynamics_test.go reinforcement test). A fixture that names discovery types cannot live in synthtest: the discovery in-package tests import synthtest, so synthtest importing discovery would be an import cycle.
- The mockgen directive for model.Embedder (in internal/engine/store/model/embedder.go) now writes discovery/mock_embedder_test.go in package discovery; regenerating from the old destination in the parent would recreate a dead mock.

DOES NOT MEAN: that the whole discover pipeline moved. The step, its payload dispatch and the [discovery] config wiring are still parent code (see the discovery-integration fact). Sibling children follow the same pattern: step, restatement, graph, motif, bridge.

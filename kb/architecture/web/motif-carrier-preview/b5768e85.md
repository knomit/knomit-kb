# The /motifs/{key} carriers preview IS the pivot query — recentFacts with Motifs=cluster.Members, exact tier — so preview and /facts pivot cannot diverge, and the test follows the facts link and asserts the same carriers

handleHALMotifCluster builds its carriers preview by calling the SAME package function recentFacts (handlers_facts_collection.go) that the /facts endpoint calls, with index.SearchOptions{Motifs: cluster.Members, MotifMatch: index.MotifMatchExact, Limit: carrier limit}, and advertises the full pivot as a _links.facts URL carrying exactly those members + exact tier. (Until W0d2, PR #610, this went through factsCollectionProvider.RecentFacts; that provider is gone and recentFacts is the shared path. The lens cluster detail in handlers_lenses_motifs.go calls recentFacts per mount the same way.) Passing EVERY member spelling (not just the canonical) is what keeps the union correct on an unrebuilt corpus, where exact-tier resolution treats each spelling as its own singleton.

How it is tested at the W0e merge (PR #611, b261c400): the old stub test that asserted the recorded RecentFacts options field-by-field no longer exists, because tests run on a real store. TestHandleHALMotifCluster_ByClusterKey instead asserts the carriers (every member spelling at the exact tier, the stranger out, a spelling written after the last rebuild included, newest first), asserts the facts link equals /facts?motif_match=exact&motifs=<members>, FOLLOWS that link and requires it to list exactly the carriers the detail previewed with the same count. A drift between preview and pivot therefore still fails a test, by behaviour rather than by recorded options.

Consequence: to change pivot semantics, change the store query path — both surfaces move together; do not add a second carrier query.

Misreading to avoid: store.MotifIndex.CarrierTitles is NOT this preview's source — it returns bare titles, capped, for the judge pass and knomit_explain siblings. The REST carriers come from recentFacts and carry path/type/committed_at plus the honest total (carrier_count is the store's count, not len of the page).

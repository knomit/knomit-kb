# The /motifs/{key} carriers preview IS the pivot query — RecentFacts with Motifs=cluster.Members, exact tier — so preview and /facts pivot cannot diverge, and the test asserts the recorded options

handleHALMotifCluster builds its carriers preview by calling the SAME factsCollectionProvider.RecentFacts the /facts endpoint uses, with SearchOptions{Motifs: cluster.Members, MotifMatch: exact, Limit: carrier limit}, and advertises the full pivot as a _links.facts URL carrying exactly those members + exact tier. Passing EVERY member spelling (not just the canonical) is what keeps the union correct on an unrebuilt corpus, where exact-tier resolution treats each spelling as its own singleton. The handler test asserts the recorded RecentFacts options field-by-field, so a drift between preview and pivot fails a test rather than shipping.

Consequence: to change pivot semantics, change the store query path — both surfaces move together; do not add a second carrier query.

Misreading to avoid: store.MotifIndex.CarrierTitles is NOT this preview's source — it returns bare titles, capped, for the judge pass and knomit_explain siblings. The REST carriers come from RecentFacts and carry path/type/committed_at plus the honest total (carrier_count is the store's count, not len of the page).

# internal/edge/web/api/origins exports only Mount(r, rm, agentBranch) and creates its own session manager; web calls Mount once per Server via originSessionsRouter (sync.Once), shared by Handler() and OAuthHandler()

internal/edge/web/api/origins serves the connect-a-remote wizard (/repos/{repo}/origin-sessions: list, create, get, delete, test, preview, apply, commit). It exports exactly `func Mount(r chi.Router, rm *repos.Manager, agentBranch string)` with no results (archtest guard M). Mount registers the eight routes on r and CREATES the session manager they share; the manager, session type, state constants and handlers are unexported. There is no Server.SessionManager and internal/app constructs none (both removed in PR #624).

Consequence: each Mount call is a separate session store. web's router calls Mount ONCE per Server (Server.originSessionsRouter, guarded by Server.originSessionsOnce, a sync.Once) and mounts that one subrouter with r.Mount("/origin-sessions", ...) in every apiRouter, so the plain listener (Handler) and the OAuth listener (OAuthHandler) see the same sessions and the one-session-per-repo rule holds across both. DOES NOT MEAN: that calling origins.Mount inside apiRouter is equivalent; it would give each listener its own manager (TestRouter_OriginSessionsShareOneManagerAcrossRouters fails).

The subtree sits inside the /repos/{repo} RepoMiddleware group: its handlers read the instance with repos.RepoFromContext and panic without it.

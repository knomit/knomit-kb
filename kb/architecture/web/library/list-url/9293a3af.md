# The Library list's URL state (listUrl.ts): ctx_repo|ctx_lens by registry uid plus ctx_branch, and l_q, l_f, l_rp, l_sort, l_src, l_since_fork. useListUrl restores it once per page load (pending, then resolving, then done) and writes it back with replaceState after that

As built in PR #713. web/src/listUrl.ts holds parseListUrl, writeListUrl and contextOf, which are pure, and the hook useListUrl, which App calls.

Context keys:
- ctx_repo = RepoInfo.uid. Never the name: the uid survives a rename (gotcha ae7a7d41).
- ctx_lens = Lens.uid.
- ctx_branch is written only with ctx_repo, because the lens lists read the union and take no branch. Having both ctx_repo and ctx_lens, or neither, counts as no context.

List keys, written only when off their defaults:
- l_q: freeText.
- l_f: one 'category:value' per FilterChip, the path chip included.
- l_rp: the motif chip's returnPath.
- l_sort: librarySort when it is not 'path'.
- l_src: lensSources, lens context only. Absent means null (every mount); a single empty 'l_src=' means [] (none).
- l_since_fork=1: repo context only.

A list is never written without its context: a null ctx removes every ctx_*/l_* key. None of these keys collide with materialize, mat_*, factset or fs_*.

Restore phases:
- 'pending' until App's boot either calls adopt(name), when the URL uid resolved, or abandon().
- 'resolving' waits for state.branch. A different ctx_branch is entered with api.status, the way enterBranch does. A lens also waits for state.lens with the same uid. RESTORE_LIST is then dispatched in the same batch as phase 'done'.
- 'done' arms the factset flag (factsetView.arm) for Library to re-create, and writes the URL from state on every change after that.

abandon() drops the factset flag. The 'done' write-back then rewrites the keys from the actual context with the actual, un-restored list.

Consequences:
- A new list control needs parse, write and RESTORE_LIST support here, as well as listSearch.ts, or a reload silently loses it.
- Tests: test-setup.ts resets the URL to '/' before every test, because App now reads it at mount and jsdom keeps one URL per file. A test that wants a reload sets the URL BEFORE render.

What this is NOT: the URL is not read again mid-session. History (asOf) and the open fact are not in it.

# kb:// paths in a chat result become links only when POST /facts/resolve answers them (batches of 100, once per path for the page's life); src:// refs stay plain text because the app has nowhere to open a source file

jsonViewLinks.useKbLinks(text) collects kbRefs(text) (kb://<store>/<path>, trailing dots/slashes trimmed), asks resolveFactHandles with no prefer list (the kb:// URI names its repo by id or name, which the server resolves), in batches of RESOLVE_BATCH = 100 (the server's maxResolveHandles), and caches each answer, null included, in a module map. An answer that names a commit is dropped. JsonView decorates only resolved paths (class k-json-fact, #cbd6e6, underline on hover) and a click opens the fact in the side panel with {kind:'fact', repo, branch, path} from the resolver, the same entry a fact chip opens. A path the server does not answer stays plain text.

src:// refs: knomit stores no source objects and has no source-repo registry (FactBody's refLabel/sourceRefCommand only offer a git command to copy), so there is no in-app target; the view leaves them as text. Bare repo-relative fact paths (kb/... with no kb://) are not linked either.

Consequence: links appear a moment after the view (they wait for the resolve); tests must waitFor them. resetResultLinks() clears the cache between tests.

# serverPagesFor answers ['access', 'logs'] (Access first) since feat/access-layout, and TOGGLE_SERVER opens the server pages on 'access', the first tab

web/src/facets.ts serverPagesFor(false) is ['access', 'logs'] and the top bar draws the server tabs in that order. Opening the server pages is a separate decision in viewReducer's TOGGLE_SERVER, which returns server: 'access', so the gear lands on the FIRST tab (facets.test.ts pins open.server to serverPagesFor(false)[0]). The two are kept in step by hand: reordering serverPagesFor does NOT move the landing page; change TOGGLE_SERVER too. Consequence for tests: App tests that open the gear land on AccessPage, which calls api.listSecrets at once, so every App test api mock that opens the server pages must mock listSecrets (a missing mock crashes the page into the ErrorBoundary), and tests that want Logs click server-tab-logs. The gear's tooltip reads 'Server: access and logs'. On a read-only server serverPagesFor is [] and there is no gear. The lit gear is the accent #7c9 on the glyph with a transparent background (no #1a231d fill).

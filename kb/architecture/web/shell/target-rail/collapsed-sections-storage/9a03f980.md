# The rail's collapsed sections persist per viewer under localStorage knomit.rail.collapsed, held in TargetRail's own state (not facets.ts's view reducer); absent, garbage or throwing storage means every section open

web/src/repoSelection.ts holds loadRailCollapsed / saveRailCollapsed beside the other chrome keys (knomit.rail, knomit.facet): key RAIL_COLLAPSED_KEY = 'knomit.rail.collapsed', value a JSON list of section names from 'chats' | 'repos' | 'lenses' | 'fleet'. Both wrap every storage access in try/catch: unparseable JSON, a non-array, unknown names, or a throwing getItem read as nothing collapsed (every section open, as before the feature); a throwing setItem is swallowed.

The set lives in TargetRail's useState (initialised from loadRailCollapsed), NOT in facets.ts's useViewState/viewReducer and NOT in AppState or NavEntry. It survives the rail being hidden because the rail unmounts when hidden and re-reads storage on mount.

Consequence: the older statement that 'only the facet and the rail preference persist' is about the view reducer's fields; it does not mean knomit.rail is the only rail state in storage. A reader looking for everything the shell persists must also read repoSelection.ts's RAIL_COLLAPSED_KEY.

# The chat side panel holds a browser-style history of mixed entries (a tool result by callId, or a fact by repo, branch and path); opening drops what was ahead, closing keeps the history, and its width is remembered under knomit.chatPanelWidth

chatPanelState.ts owns the panel: PanelState {entries, index, open}. open(entry) truncates entries after the current index then pushes (opening the entry already showing is a no-op; reopening it after close just sets open); back/forward move the index; close only clears `open`, so the history ('N of M opened' in the footer) survives. ChatFacet derives the highlighted timeline step from the shown entry (selectedId = callId of a result entry), so a fact entry highlights no step. A fact entry is complete by itself: ChatFactView fetches api.fact, api.explain (cited by/cites counts) and api.factCommits (vN) from {repo, branch, path, commit?}, so a fact link (chat UX PR 6) only has to dispatch open; a load failure shows the server's sentence (the text after fetchJSON's '<url> → <status> ') in a blocked NoticeLine, never the request URL. Width: default 470px, min 320, max PANEL_MAX_FRACTION (0.6) of the CHAT BODY's width (the row holding column and panel, not the window; App.css `.k-chat-result` max-width is the same 60% of the same box and a test pins the two). It reaches the stylesheet as the CSS variable --k-panel-w (width: var(--k-panel-w, 470px)), so no inline width fights the phone-width rule. A splitter drag starts from the width the panel is SHOWN at (offsetWidth), not the stored value, and is clamped by clampPanelWidth(w, container); persisted to knomit.chatPanelWidth only on mouse release, like the Library width. Open in Browse for a materialize result reads `file` (path or kb://<store>/<path>, the real argument shape; `binding` is an opaque handle) and takes the target from repo/lens/target else the binding in force when the call ran (boundBeforeCall in chatState.ts); App resolves it to a repo or a lens. The header crumb is repo / path / dir when the call names a file, else the repo then the call's row label (toolCallLabel of the transcript's ToolCall from callFor, else of the loaded call; the same label its timeline row shows, e.g. 'B / Bound'); for a bind call the repo is the bind's own target (bindTarget in chatState.ts: lens, repo, name, target), not the binding in force before it ran. The module is chatPanelState.ts, NOT chatSidePanel.ts: on a case-insensitive filesystem that collides with ChatSidePanel.tsx and tsc -b fails with TS1149. Narrow windows (<=640px): the panel stacks above the chat, full width, max-height 50%, splitter hidden; those rules sit AFTER the base .k-chat-result rule in App.css so source order wins without !important (an earlier media block ABOVE it lost to the base max-width: 60% and showed a 225px panel at 375). Answer tables sit in a .k-chat-table-scroll box (overflow-x: auto) so a wide table scrolls instead of being cut off by the panel.

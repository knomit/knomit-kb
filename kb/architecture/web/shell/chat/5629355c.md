# The chat side panel holds a browser-style history of mixed entries (a tool result by callId, or a fact by repo, branch and path); opening drops what was ahead, closing keeps the history, and its width is remembered under knomit.chatPanelWidth

chatPanelState.ts owns the panel: PanelState {entries, index, open}. open(entry) truncates entries after the current index then pushes (opening the entry already showing is a no-op; reopening it after close just sets open); back/forward move the index; close only clears `open`, so the history ('N of M opened' in the footer) survives. ChatFacet derives the highlighted timeline step from the shown entry (selectedId = callId of a result entry), so a fact entry highlights no step. A fact entry is complete by itself: ChatFactView fetches api.fact, api.explain (cited by/cites counts) and api.factCommits (vN) from {repo, branch, path, commit?}, so a fact link (chat UX PR 6) only has to dispatch open. Width: default 470px, min 320, max 60% of the window, dragged with the shared FacetSplitter (drag left widens), persisted to localStorage only on mouse release, like the Library width (knomit.leftPanelWidth). The module is chatPanelState.ts, NOT chatSidePanel.ts: on a case-insensitive filesystem that collides with ChatSidePanel.tsx and tsc -b fails with TS1149. Narrow windows (<=640px): the panel stacks above the chat, full width, max-height 50%, and the splitter is hidden, so there is no horizontal scroll.

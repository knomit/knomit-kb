# The rail is live from the page's one events stream: useChats subscribes each listed chat (mounted or not) and applies its chat_state to the row; a reconnect re-reads GET /chats; a new answer is client-side (completed turns beyond the last seen)

useChats subscribes every listed chat id through subscribeChatEvents (chatEvents.ts, the page's single GET /chats/events stream) and applies each chat_state (title, state, turns, cost_usd, last_activity, started_at) to that chat's row, so rows of chats with no ChatFacet mounted update too. The connect-time ready is not a change (the list was just read); a later ready is a reconnect and re-reads GET /chats (only the first subscription answers it, not one per chat). The list is also read at load and on window focus. A chat created in another tab is unknown until the next read. A chat is 'new answer' when it is idle, not on screen, and completedTurns(row) (turns minus the running one) exceeds the value useSeenTurns last recorded; first sight sets the baseline so a reload shows nothing as new. Not meant: chat_state does not announce a chat this page has never listed.

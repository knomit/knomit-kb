# The rail has no chats event stream: it stays live because each mounted ChatFacet's own events stream calls notifyChatActivity, which makes useChats read GET /chats again; a new answer is client-side (completed turns beyond the last seen)

Server state, title and cost reach the rail only through GET /chats, read at load, on window focus, and on notifyChatActivity (fired by ChatFacet when its run flag, pending approvals, turn count or last error change, once more after 1s because the send POST can land after the first read). A chat is 'new answer' when it is idle, not on screen, and completedTurns(row) (turns, minus the running one) exceeds the last value useSeenTurns recorded; first sight sets the baseline so a reload shows nothing as new. Consequence: a chat nobody has mounted (no ChatFacet) is never refreshed by events, and the rail depends on every listed chat keeping a ChatFacet mounted.

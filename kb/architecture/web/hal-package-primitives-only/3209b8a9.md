# internal/edge/web/hal is primitives-only; domain views (FactView, RefView) live in internal/edge/web

internal/edge/web/hal/ is a primitives-only package — NO domain knowledge of facts, branches, or stores. Exports: Link (Href + Templated for RFC 6570 URI templates), LinkMap (map[string]Link with Clean() to drop zero-value entries); CollectionView[T any] generic envelope with Count + Links + Embedded map[string][]T (relation name is the embedded key); Problem (RFC 9457 problem+json with Type defaulting to 'about:blank'); WriteHAL (sets Content-Type: application/hal+json), WriteHALCreated (also sets Location + Content-Location to same URI for POST-to-collection), WriteProblem (sets Content-Type: application/problem+json); Anchor, URLBuilder, EncodeBranch/DecodeBranch. Domain-specific view types (e.g. FactView, RefView, FactSummaryView) live in internal/edge/web/ and USE these primitives. Anti-pattern: importing internal/engine/store or internal/domain/fact into the hal package — keep it primitives-only so it's reusable/mockable and has no circular-dep risk.

# The KB surface lives in internal/edge/web/api/kb, whose only export is Mount(branch, lens chi.Router, ontologyRoot string, emb model.Embedder); router.go builds both subrouters and their middleware and calls it once

Verified at 33eb0307 (PR #630, web split step 12f, squash merge on dev). internal/edge/web/api/kb holds the KB surface moved out of internal/edge/web; its only export is `func Mount(branch, lens chi.Router, ontologyRoot string, emb model.Embedder)` with no results. router.go builds both subrouters and their middleware and calls it once.

WHAT LIVES THERE. The routes under /repos/{repo}/branches/{branch}: facts (collection, POST, GET/PUT/DELETE by path), topics, changes, commits and the commit-anchored facts and topics, search, activity, completions, domains (and /domains/{name}), motifs (and /motifs/{key}), stats, events, triggers. The lens reads under /lenses/{lens}: facts, facts by path, search, completions, motifs, motifs/{key}, stats, topics. 32 routes in all (23 branch, 9 lens). Also every helper those handlers share: factView and refView (the single-fact wire view), params, context_params, expires (timeNow), lens_fanout, system_file_read, fact_version_date, fact_closed_paths.

HOW IT IS MOUNTED (user ruling 2026-10-24, kb/decisions/web/route-tree-built-by-router/ab86ee4f.md). router.go builds the tree:
- `branch` is /repos/{repo}/branches/{branch} inside httpx.FleetRepoRefused (on repoOuter), RepoMiddleware (on the repo group) and httpx.BranchMiddleware.
- `lens` argument is `lensBound := lens.Group(nil)` with LensMiddleware(s.Manager) applied. The lens MCP group (MountExperimentMiddleware) also hangs off lensBound.
- The lens CRUD (api/manage) is registered on the OUTER `lens` router, outside LensMiddleware, because it resolves {lens} through the registry itself. So does /lenses/{lens}/experiments/{name}/mcp, which runs LensExperimentMiddleware instead.

ARGUMENTS. ontologyRoot is config OntologyRoot (s.OntologyRoot). emb is the server's query embedder (s.Embedder, passed straight through); when it is nil the handlers do not embed the query themselves and leave it to each repo's store.

CONSEQUENCES. A new KB route is added inside kb.Mount, not in router.go. A new middleware on these subtrees is added in router.go, before kb.Mount runs (chi panics on Use after the first route on a router). A helper that kb and another api package both need goes in httpx.

DOES NOT MEAN: that kb owns the /repos/{repo}/branches/{branch} or /lenses/{lens} subtree. manage.Mount and jobs.Mount register into the same `branch` router, and the lens MCP group shares `lensBound`. Nor that every lens route runs LensMiddleware: the lens CRUD and the experiment MCP route do not.

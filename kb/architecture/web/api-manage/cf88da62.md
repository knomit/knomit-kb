# internal/edge/web/api/manage exports only Mount(top, repoOuter, repo, branch, lens chi.Router, rm, agentBranch, embeddingsEnabled, expiryDays, operator); the CALLER builds the subrouters and every middleware on them, and repoOuter exists because Archive must stay outside RepoMiddleware

Verified at a8bf8d7a (PR #628, web split step 12e, squash merge on dev). internal/edge/web/api/manage holds the repo, lens and fleet lifecycle handlers moved out of internal/edge/web; its only export is `func Mount(top, repoOuter, repo, branch, lens chi.Router, rm *repos.Manager, agentBranch string, embeddingsEnabled bool, expiryDays int, operator func(http.Handler) http.Handler)` with no results.

WHAT EACH ROUTER IS. top is the API root: manage registers fleet (reads, and the local-only group behind httpx.RequireLocalVia), archived, repos, repo-creates, probes, ontologies, templates, repo-events and the lens collection there; none is wrapped by RepoMiddleware. repoOuter is /repos/{repo} behind the fleet gate only. repo is the Group inside it behind RepoMiddleware. branch is /repos/{repo}/branches/{branch} behind httpx.BranchMiddleware. lens is /lenses/{lens} OUTSIDE LensMiddleware (lens CRUD resolves {lens} through the registry itself). operator is built by router.go from its grants (requireOperator) so the package does not know the auth model; the pushed-branch merge sits behind it.

WHY THE CALLER BUILDS THEM. The KB routes (still in router.go until 12f) and the MCP mounts share the /repos/{repo}, /branches/{branch} and /lenses/{lens} subtrees with manage, and chi panics on a second Mount of one pattern, so one package cannot own a subtree another also fills. router.go therefore creates the subrouters, Use's each one's middleware (FleetRepoRefused on repoOuter, RepoMiddleware on repo, BranchMiddleware on branch) BEFORE any route is registered (chi panics on Use after the first route), and passes them in. The ruling is recorded in kb/decisions/web/route-tree-built-by-router.

WHY repoOuter AND repo. DELETE /repos/{repo} (Archive) is registered on repoOuter because it resolves {repo} through m.Archive and attributes its own errors; under RepoMiddleware a generic 404 would replace them. Archive is still behind the fleet gate.

DOES NOT MEAN: that manage owns any middleware (it owns none; passing a subrouter in does not make the callee responsible for what is on it), or that manage holds every /repos/{repo} route (the KB, jobs and origin-sessions routes register into the same subtrees from router.go, api/jobs and api/origins).

TESTS. Tests moved with their code only when they call a private symbol and no router: the *ErrStatus mappers, indexPercent, createdFleetStatus, fleetMemberRow(s), repoSummary, createStatusBody, setOriginUpstream, writeFleetError and the lifecycle-helpers case of TestReadHelpers_ReturnAcquireRefusal; the router-level tests stay in web. api/manage/harness_test.go holds COPIES of web fixtures (newTestManagerWithRepos, seedBareRemoteForTest, a Manager-only newControlDBManager), so a fixture fix may need making in both places.

# The lens mount carries an experiment as a URL SEGMENT because the URL names the experiment, so a non-empty handle is refused there (errFixedEndpoint; "" counts as absent) and knomit_bind is not listed — an unknown experiment is a 404 rather than a heal; `open` on a URL-scoped mount that names the agent branch (or a lens default) moves the session INTO the experiment in place, while a mount whose URL already fixes another branch refuses the switch

A lens pins a branch per member, so it has no single branch segment to carry an experiment the way `/repos/{repo}/branches/exp:<name>/mcp` does. It gets its own: `/lenses/{lens}/experiments/{name}/mcp`, which re-pins ONLY the write member.

WHY A URL SEGMENT AND NOT PER-SESSION STATE. The lens MCP mount is URL-scoped, so `repos.SessionScoped` is false. Since PR #664 a non-empty `binding` is refused here because the URL names ONE experiment (errFixedEndpoint, endpointFixed; rule 3 of handle-is-the-only-router as amended) and tools/list does not list knomit_bind; an empty string passes (it counts as absent). Before #664 the refusal was on mere presence. There is therefore no per-call value that could name the caller, and the only ambient key left is Mcp-Session-Id — the key the 2026-09-17 incident removed. Putting the experiment in the path makes it part of the endpoint's identity, as the branch segment already is, and keeps the server stateless about who is calling.

A 404, NOT A HEAL, when the experiment is unknown or this instance may not write it. The session-scoped mount heals because the caller is mid-session and its call must still run; here the experiment IS the endpoint, so serving a different branch than the URL names would be the silent misroute the design exists to remove. The two rules differ because the question differs.

MIRRORED SURFACE, applied deliberately rather than discovered as drift (architecture/web/096bb34b). The new middleware sets the SAME two context values LensMiddleware does — the Binding and the write repo as the context RepoInstance. The repo mount needs no middleware at all, because BindingFromContext synthesizes the lens-of-one from the RepoInstance plus the {branch} segment; that asymmetry is deliberate, so both mounts are tested rather than made identical.

TWO CONSEQUENCES FOR ANYONE ADDING ROUTES HERE. (1) `{name}` is classified userNamed in paramClass: experiment names are chosen by whoever calls `open`, so NO static route may ever sit beside it — TestRouter_NoStaticSiblingsOfUserNamedParams fails an unclassified subtree on purpose rather than defaulting either way. (2) SUPERSEDED, see the 2026-10-12 note below: this paragraph used to say that `knomit_experiment open` on a URL-scoped mount only creates the experiment and returns a reconnect URL. That behaviour is gone.

Updated 2026-10-12 (drift sweep against HEAD 2104fd6d): the title's and consequence (2)'s claim that `open` on any URL-scoped mount returns a reconnect URL is FALSE at HEAD, and `experimentReconnectURL` no longer exists in the tree. Now (internal/edge/mcp/experiment.go, the block from line 326): with no binding handle, `open` looks up the session id and mount (repos.MountSessionFromContext). On a plain-branch mount (the URL names this repo's own agent branch, or a lens default) it records the experiment for that session via setMountExperiment and answers 'THIS SESSION IS NOW INSIDE IT ... No reconnect needed' (lines 370-377). On a mount that does not qualify (the URL names main, a foreign agent branch, or an experiment) it creates the experiment and returns an ERROR saying the endpoint is bound by its URL and cannot be switched, telling the caller to connect to the experiment's own mount (lines 340-361); if the URL already names that very experiment it reports nothing changed. With no MCP session id it fails closed (lines 363-369). CONSEQUENCE: an agent on a plain-branch URL-scoped mount no longer needs to reconnect, and one on a non-plain mount must treat the error as 'created but NOT inside'. Which mounts qualify is decided from the ROUTE, per kb/invariants/mcp/experiments/mount-eligibility-from-the-route/711ae81d.md. WHAT STILL HOLDS: the lens experiment URL segment (/lenses/{lens}/experiments/{name}/mcp, router.go:461-462, LensExperimentMiddleware at lens_middleware.go:85) still exists and still 404s an unknown experiment; the 'URL segment, not per-session state' argument stands for the lens-experiment endpoint. Do NOT read the old 'returns the URL to reconnect on' wording as a surviving fallback.

# The FactSet UI: Library builds the FsSearch from the SAME listSearch builders its list calls use, a module store (factsetOptions.factsetView) carries it to RightPanel, FactSetView renders ONE run from FactSetStream (seek replaces it), and shared parts live in materializeParts.tsx

As built in #710 (merged at c785c88e; web/src, flat):
- listSearch.ts: listSearchParams (repo /search, /facts) and lensListSearchParams (lens /search, /facts) return exactly what a results list sends minus paging; api.search, api.recent, lensSearch and listLensFacts call them, and Library builds the FactSet's FsSearch {target repo|lens, sort relevance|recent, params} from the same builders with the ONE listFilters object its list calls use. They live outside api.ts because many tests vi.mock('./api') wholesale; a builder in api.ts made those suites throw on render. The lens /facts list now sends its text as q (the handler reads query or q).
- LibraryHeader: the entry control sits beside the count on every search list (absent in the path tree, disabled when !isLive). A lens of any size uses the lens route.
- factsetOptions.ts: the open flag and options in the query string (factset=1, fs_depth, fs_refs, fs_cross_kb, fs_unpin; replaceState); the frozen search in memory in factsetView (useSyncExternalStore). Since #713 the list's search and its context are in the URL too (listUrl.ts: ctx_* and l_* keys), so a reload RE-CREATES the FactSet: load() keeps factset=1 as pending 'wait'. useListUrl restores the list (RESTORE_LIST), then arm()s it to 'ready', and Library's effect then opens the FactSet from its own factsetSearch, a new first call from the same builders. Where nothing can be re-created (factsetSearch null in the path tree, !isLive in history, or the URL context gone: abandon), dropPending() removes the flag and keeps the fs_* options in memory. The old L5 clear-on-load is gone. The URL still never carries a FactSet id or cursor.
- RightPanel renders FactSetView (keyed by searchKey) before any other branch when factsetView holds a search. The view exists only in Focus (decision kb/decisions/web/factset-view/focus-exit/8f74df50.md): Back, the Exit focus toggle and Esc outside a text field all close it (useMatFocus(onExit)); the stream's dispose then DELETEs the FactSet and the URL flag is cleared.
- useFactSetStream.ts FactSetStream: one run on screen (loadMore appends, loadBefore prepends a whole unit across pages, seek replaces); one call in flight under a generation counter; any option change restarts and seeks back to the reported top unit; 503 retried per Retry-After (clamped to MAX_RETRY_AFTER_S = 10 s) at most MAX_BUSY_RETRIES (3); a 404 on a CURSOR call re-creates the same search, seeks back and raises notice 'FactSet refreshed' (Q-UI13), at most once in a row: the re-creating first call (and the seek right after it) is not recoverable, so a 404 there (the repo or lens is gone) is shown as an error instead of looping, and the bound resets only when a CURSOR call succeeds (loadMore, loadBefore, reach, seek, the seek inside a restart), never on a first call's own page, so a FactSet whose cursor calls always 404 (another server without sticky routing, an owner mismatch) is re-created once and then shows the 404 where it happened; Retry on an expired tail or head error (the reader's act, so it cannot loop) resets the bound, so the 404 it meets re-creates the FactSet once more; a seek, and reach() for a unit already in the run, read on inside the unit (readOn) until the target anchor or section n has arrived or the cursor passes the unit, so a link or builds-on click lands on its target, not the unit root; a loadBefore failure is headError, shown at the top; a superseded FactSet is closed with DELETE, but a FactSet known to be gone (any cursor call or the export answered 404: markGone records its id, the cursor minus its last two dot parts) is never closed, so the re-creation after a 404 sends no DELETE for the dead cursor while Back, Exit focus, Esc and a superseded live FactSet still do (since #726). Pages are section-limited (limit 5) and can split a unit, so loadBefore reads until the cursor's unit passes the target.
- FactSetView (since #726): the top sentinel is armed per run (armedEpoch === epoch). After a run lands (seek, restart, refresh) its first intersection is ignored, because the sentinel is often in view at landing; only the reader's own scroll arms it. Scrolls the view makes itself (setScrollTop: landing, keeping the place on a prepend) are recognised by their scrollTop and do not arm it, and a scroll UP with the sentinel already in range calls loadBefore directly, since the observer reports only changes (Q-UI9). The progress line 'unit X of N' shows topUnit, the unit at the top of the pane that the Unit stepper also shows, updated on scroll and after every landing; it is NOT env.unit_to (the last unit loaded).
- materializeParts.tsx: Stepper, Switch, Body, Disclosure, Section, NESTING moved out of MaterializeView (useMatFocus lives in useMatFocus.ts: react-refresh keeps hooks out of component files; its optional onExit makes Esc leave the view, used by the FactSet view only); Section takes an optional fs extra (unit, link, repoName, unavailable) plus onLink; a 'Related, not included' entry with reason lens_repo reads '<repo_name> <path in code>' with the kb://<id12>/ prefix stripped and no reason code (ruling S2, as render_agent.go omissionText writes the export), every other reason still reads 'title || id || path (reason)' (MatOmission.repo_name since #726); a stub has no data-anchor and its own heading id, so only the written section is a scroll target.

CONSEQUENCE: a new list filter must be added in listSearch.ts (and Library's listFilters) to reach both the list and its FactSet; never build FactSet params separately.

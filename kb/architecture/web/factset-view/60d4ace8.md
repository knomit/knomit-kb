# The FactSet UI: Library builds the FsSearch from the SAME listSearch builders its list calls use, a module store (factsetOptions.factsetView) carries it to RightPanel, FactSetView renders ONE run from FactSetStream (seek replaces it), and shared parts live in materializeParts.tsx

As built on feat/factset-ui (web/src, flat):
- listSearch.ts: listSearchParams (repo /search, /facts) and lensListSearchParams (lens /search, /facts) return exactly what a results list sends minus paging; api.search, api.recent, lensSearch and listLensFacts call them, and Library builds the FactSet's FsSearch {target repo|lens, sort relevance|recent, params} from the same builders with the ONE listFilters object its list calls use. They live outside api.ts because many tests vi.mock('./api') wholesale; a builder in api.ts made those suites throw on render. The lens /facts list now sends its text as q (the handler reads query or q).
- LibraryHeader: the entry control sits beside the count on every search list (absent in the path tree, disabled when !isLive). A lens of any size uses the lens route.
- factsetOptions.ts: the open flag and options in the query string (factset=1, fs_depth, fs_refs, fs_cross_kb, fs_unpin; replaceState); the frozen search in memory in factsetView (useSyncExternalStore). state.ts is unchanged. The list state is not in the URL at all, so a reload drops the open FactSet (nothing to re-create it from) and the store clears a stale factset=1 when it loads, keeping the fs_* options in memory.
- RightPanel renders FactSetView (keyed by searchKey) before any other branch when factsetView holds a search. The view exists only in Focus (decision kb/decisions/web/factset-view/focus-exit/8f74df50.md): Back, the Exit focus toggle and Esc outside a text field all close it (useMatFocus(onExit)); the stream's dispose then DELETEs the FactSet and the URL flag is cleared.
- useFactSetStream.ts FactSetStream: one run on screen (loadMore appends, loadBefore prepends a whole unit across pages, seek replaces); one call in flight under a generation counter; any option change restarts and seeks back to the reported top unit; 503 retried per Retry-After (clamped to MAX_RETRY_AFTER_S = 10 s) at most MAX_BUSY_RETRIES (3); a 404 on a CURSOR call re-creates the same search, seeks back and raises notice 'FactSet refreshed' (Q-UI13), at most once in a row: the re-creating first call (and the seek right after it) is not recoverable, so a 404 there (the repo or lens is gone) is shown as an error instead of looping, and the bound resets only when a CURSOR call succeeds (loadMore, loadBefore, reach, seek, the seek inside a restart), never on a first call's own page, so a FactSet whose cursor calls always 404 (another server without sticky routing, an owner mismatch) is re-created once and then shows the 404 where it happened; Retry on an expired tail or head error (the reader's act, so it cannot loop) resets the bound, so the 404 it meets re-creates the FactSet once more; a seek, and reach() for a unit already in the run, read on inside the unit (readOn) until the target anchor or section n has arrived or the cursor passes the unit, so a link or builds-on click lands on its target, not the unit root; a loadBefore failure is headError, shown at the top; a superseded FactSet is closed with DELETE. Pages are section-limited (limit 5) and can split a unit, so loadBefore reads until the cursor's unit passes the target.
- materializeParts.tsx: Stepper, Switch, Body, Disclosure, Section, NESTING moved out of MaterializeView (useMatFocus lives in useMatFocus.ts: react-refresh keeps hooks out of component files; its optional onExit makes Esc leave the view, used by the FactSet view only); Section takes an optional fs extra (unit, link, repoName, unavailable) plus onLink; a stub has no data-anchor and its own heading id, so only the written section is a scroll target.

CONSEQUENCE: a new list filter must be added in listSearch.ts (and Library's listFilters) to reach both the list and its FactSet; never build FactSet params separately.

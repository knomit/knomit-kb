# The FactSet UI: Library builds the FsSearch from the SAME listSearch builders its list calls use, a module store (factsetOptions.factsetView) carries it to RightPanel, FactSetView renders ONE run from FactSetStream (seek replaces it), and shared parts live in materializeParts.tsx

As built on feat/factset-ui (web/src, flat):
- listSearch.ts: listSearchParams (repo /search, /facts) and lensListSearchParams (lens /search, /facts) return exactly what a results list sends minus paging; api.search, api.recent, lensSearch and listLensFacts call them, and Library builds the FactSet's FsSearch {target repo|lens, sort relevance|recent, params} from the same builders with the ONE listFilters object its list calls use. They live outside api.ts because many tests vi.mock('./api') wholesale; a builder in api.ts made those suites throw on render. The lens /facts list now sends its text as q (the handler reads query or q).
- LibraryHeader: the entry control sits beside the count on every search list (absent in the path tree, disabled when !isLive). A lens of any size uses the lens route.
- factsetOptions.ts: the open flag and options in the query string (factset=1, fs_depth, fs_refs, fs_cross_kb, fs_unpin; replaceState); the frozen search in memory in factsetView (useSyncExternalStore). state.ts is unchanged. The list state is not in the URL at all, so a reload drops the open FactSet (nothing to re-create it from).
- RightPanel renders FactSetView (keyed by searchKey) before any other branch when factsetView holds a search; Back closes it.
- useFactSetStream.ts FactSetStream: one run on screen (loadMore appends, loadBefore prepends a whole unit across pages, seek replaces); one call in flight under a generation counter; any option change restarts and seeks back to the reported top unit; 503 retried per Retry-After at most MAX_BUSY_RETRIES (3); 404 re-creates the same search, seeks back and raises notice 'FactSet refreshed' (Q-UI13); a superseded FactSet is closed with DELETE. Pages are section-limited (limit 5) and can split a unit, so loadBefore reads until the cursor's unit passes the target.
- materializeParts.tsx: Stepper, Switch, Body, Disclosure, Section, NESTING, useMatFocus moved out of MaterializeView; Section takes an optional fs extra (unit, link, repoName, unavailable) plus onLink; a stub has no data-anchor and its own heading id, so only the written section is a scroll target.

CONSEQUENCE: a new list filter must be added in listSearch.ts (and Library's listFilters) to reach both the list and its FactSet; never build FactSet params separately.

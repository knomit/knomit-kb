# In /incoming and /outgoing, every entry that has a commit carries _links.self at that commit, a retracted (deleted) entry included; the entry's commit is always one where its fact exists

buildGraphRefItems (internal/edge/web/api/kb/handlers_fact_sub.go) links each RefsCollection entry at its own `commit` whenever the commit is non-empty, on the HEAD route and the commit-anchored route alike. Until PR #793 (squash-merged as b7a34667) it skipped the link for `deleted` entries, so a retracted citer or target had no navigable destination in the API.

Why the entry's own commit is safe to link, in both directions:
- incoming: IncomingAtCommit (internal/engine/store/index/search_graph_query.go) does NOT report the raw claim commit (refs_commit, the commit that introduced the citing BLOB). It reports a commit of the requested branch at which the row's PATH holds the citing blob: the edge's source_commit when the row is the claim's own node and that commit is on the branch, else branch_facts' commit for it now, else the latest one in its history (blobHoldings). So a citer that was moved to a new path (same bytes, same blob) is listed at a commit where the NEW path exists, not at the commit that wrote the blob at its old path.
- outgoing: target_commit comes from resolveTargetCommit → ResolveActiveCommitForPath, the target's last added/modified commit at or before the citer's commit, never a deletion.

Measured on the knomit-kb corpus (2026-11-08): all 13,294 retracted outgoing targets had an add/modify event at their target_commit. 2 of 4,406 retracted incoming rows had no event for their path at the raw refs_commit; both were renames, and the read's commit rewrite above is what makes them land.

The `deleted` mark is unchanged and means the version is retracted NOW (user ruling 2026-11-08), even when the collection is read at an older commit. It does NOT mean the entry cannot be followed. The web client (EdgeRow) already hopped on `versions[0].commit` for deleted rows and keeps the retracted look (strike-through, hatch, 'retracted' badge).

What this does NOT mean: a link is not a promise that the fact is live at HEAD. Following it opens the fact as it stood at that commit. An entry with an empty commit still has no link.

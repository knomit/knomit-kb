# Which REST edges take secret_id, and the gate each applies: admin for linking, unlinking and a URL change on a linked repo; operator stays on the route; fleet routes are local-listener only

secret_id (a stored secret instead of a pasted credential) is accepted on: PUT /repos/{repo}/origin/credential (string links, JSON null unlinks: both need admin), POST /repos origin.secret_id, POST /repos:probe-origin and :probe-initialized, POST /repos/{repo}/origin-sessions (the session's commit), POST /archived/{id}/restore, and the fleet bodies (POST /fleet/create origin.secret_id, /fleet/join, /fleet/join:check, /fleet/follow). Gates: every non-fleet secret_id passes the local-or-same-origin admin gate (requireLocalOrSameOriginAdmin) IN the handler via httpx.Admits (manage.admitSecretID does admin + CheckSecretForURL), on top of the route's own gate (operator for origin writes and probes, write for create/restore). A URL change through PUT /origin on a linked repo, DELETE /origin on a linked repo, and an origin-session commit that would replace a linked repo's origin (which unlinks it) also need admin. Restore with a pasted credential needs operator; with no_credential nothing extra. The fleet routes are httpx.RequireLocalVia (stricter than admin), so they add no gate. Answers: secret_id together with a pasted credential is 400 (fleet: 400 auth_invalid); a secret that names nothing, whose hosts list does not allow the URL's host, or whose type does not fit the scheme is 422 (fleet: 422 auth_invalid); a fleet hosted on an instance (a peer) refuses a secret with auth_invalid. GET /origin shows secret_name/secret_status/secret_expires_at to every reader and secret_id only to an admin (httpx.Passes). PUT /origin never takes secret_id (link through /origin/credential).

Misreading to avoid: operator alone is NOT enough to use, attach or move a stored secret anywhere outside the fleet routes; a new endpoint that accepts secret_id must apply admin itself.

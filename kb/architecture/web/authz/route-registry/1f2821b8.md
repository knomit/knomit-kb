# The HTTP route -> permission registry is internal/edge/web/route_rules.go (apiRouteRules rooted at the API router, outerRouteRules for /git/*, /docs, /assets/*, /*); TestRouteRules_EveryRouteDeclared walks both live routers and requires EXACTLY one rule per METHOD+pattern; it is NOT enforced until the flip (P4)

routeRule{Method, Pattern, Perm | Resolve+Possible}. Patterns are spelled exactly as walkFull prints them: the API router rooted at '/' (no /api/v1), the outer router's own routes. MCP mounts and the /git mount are HandleFunc/Mount routes, so they are declared for every method chi registers: CONNECT DELETE GET HEAD OPTIONS PATCH POST PUT QUERY TRACE (chi v5.4 adds QUERY; net/http has no constant). ruleFor(router, rules, r) finds the rule of the route chi ITSELF would serve r with: it runs router.Match on the path chi routes on (r.URL.RawPath when set, else r.URL.Path, '/' when empty — chi Mux.routeHTTP) and compares chi's Context.RoutePattern() spelling ("/*/" collapsed, no trailing slash) against the table normalized the same way. No route or an unserved method => (zero,false) => deny. For the API router the path must be relative to /api/v1.

Do NOT go back to Mux.Find on r.URL.Path: Find returns a mount root as "/repos/{repo}" while the table spells "/repos/{repo}/", so GET /repos/alpha, /secrets, /oauth/pending, /lenses/x (the no-slash forms the web client and bridge call) found no rule; and on an encoded slash it saw a different route than chi routes to (DELETE /repos/a%2Fbranches%2Fb%2Fsearch%2Ffactset is an ARCHIVE, repo:manage, not a factset close, kb:read). Both were caught in P1 review.

Tests (route_rules_test.go): EveryRouteDeclared and NoDeadRows walk a server built with an OAuth issuer and a git handler and APIOnly=false (otherwise /oauth/*, /git/* and the static routes are not mounted and would go undeclared); WellFormed; ResolversStayInPossible (fixtures per resolver, and the handler still reads the whole body); RuleFor_FindsMountedSubrouterPatterns; RuleFor_EveryRouteByConcretePath (a concrete path for every walked route, plus the no-slash form of every mount root); RuleFor_MountRootsWithoutSlash; RuleFor_FollowsRawPathLikeChi; RuleFor_WebClientPaths (every literal /api/v1 path in web/src/api.ts finds a rule); NormalizedPatternsUnique; Rulings (/chats* chat:use, /secrets* secret:manage, /oauth/* auth:manage, MCP mounts kb:read, sessions/logs ops:run, version public).

Consequence: adding a route now fails these tests until it gets a row. Until P4 the old gates (writeGate, requireOperator, RequireLocalVia, requireLocalOrSameOriginAdmin) still decide; the table changes no behaviour.

Assignments worth knowing: GET /fleet, /fleet/members, /fleet/activity are kb:read but GET /fleet/root is fleet:manage (it RETURNS the fleet root key files); GET /openapi.yaml is public like /docs; POST /facts/resolve and factset DELETEs are kb:read; POST /ontologies:validate is kb:write (today's write gate); GET /chat-providers is kb:read (not under /chats).

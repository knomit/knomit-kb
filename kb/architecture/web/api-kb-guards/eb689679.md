# api/kb is registered in the web-split guards: webKnownTypes gets {factView: fact_view.go, refView: ref_view.go}, the layer map allows api/kb -> hal and httpx only, and two path-keyed allowlists name kb files (handlers_fact_write.go in the motif-gate call sites, handlers_changes.go in the changes-read call allowlist)

Verified at 33eb0307 (PR #630, 12f). Guard changes that came with api/kb:
- test/archtest/web_no_interfaces_test.go: webKnownTypes gets the api/kb entry {factView: fact_view.go, refView: ref_view.go}.
- test/archtest/layers_test.go: sameLayerEdges allows `edge/web/api/kb -> edge/web/hal` and `edge/web/api/kb -> edge/web/httpx`; any other import into another web-family package fails.
- test/archtest/web_split_test.go: the api/kb webAPIExportAllowlist key (empty) is live (kb/invariants/testing/web-api-exports/ebaa68fd.md).
- Two PATH-KEYED allowlists name the new paths: motifGateCallSites (internal/domain/fact/motif_conformance_test.go) names internal/edge/web/api/kb/handlers_fact_write.go, and the changes-read call allowlist (changesAllowedCalls, internal/engine/store/changes_guard_test.go) names internal/edge/web/api/kb/handlers_changes.go.

CONSEQUENCE: moving or renaming either kb file again requires rekeying those two allowlists. They are keyed by repo-relative path, not by function, and the guards live far from the code they police (a different package's test file).

DOES NOT MEAN: that these two are the only path-keyed guards that mention web files. They are the two that 12f had to rekey.

# BranchMiddleware decodes :→/ once and stashes name in ctx; handlers panic if it didn't run

BranchMiddleware (branch_middleware.go) extracts the {branch} chi URL param, percent-unescapes it, then calls hal.DecodeBranch to flip ':' back to '/'. The canonical branch name is stashed under a PRIVATE branchCtxKey{} in the request context. Handlers read it via BranchFromContext(ctx) — which PANICS if the middleware didn't run (programming error, not runtime). The middleware emits 400 problem+json with stable titles ('Missing branch' / 'Invalid branch') on bad input. CONVENTION: every chi route that uses {branch} MUST be registered with r.With(BranchMiddleware).<Verb>(...). The '/'→':' decoding lives ONLY here; downstream handlers never see the URL-form name with colons. Symmetric to the URLBuilder encoding side: encode in one place (URLBuilder), decode in one place (BranchMiddleware).

MOVED (12b, PR #622, merge commit 3e67923b on dev, re-read there): BranchMiddleware and BranchFromContext moved unchanged from internal/edge/web/branch_middleware.go to internal/edge/web/httpx/branch_middleware.go (tests beside it); handlers call httpx.BranchFromContext(ctx), and routes register httpx.BranchMiddleware. Behaviour is the same: percent-unescape, hal.DecodeBranch, stash under the private key, panic from BranchFromContext if the middleware did not run.

# POST /chats accepts an optional message and starts the first turn exactly as POST /chats/{id}/turns would; the 201 carries turn (the view index) only when a message was sent

handleCreate calls c.startTurn(req.Message) after creating the chat when message is non-empty, and the response is the chat item plus turn (pointer, omitted without a message; turn 0 is a real value). The create body limit is 1 MiB like /turns. A message the chat cannot take (it ended between create and start) answers 404. The start screen relies on this: nothing exists until Enter or Start, then one call creates the chat with its first message. Does NOT mean the SSE stream has seen the turn's early events: the client attaches after create, so it re-reads the snapshot on ready (see the turn-end gotcha). Enforced by TestChat_CreateWithMessageStartsTurn.

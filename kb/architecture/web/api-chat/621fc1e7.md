# GET /chats rows carry title, state, last_activity, started_at, turns and cost_usd; state is awaiting_approval over running over error over idle, and the person's own Stop is not an error

The list rows (not POST/GET one) add: title = the first message with whitespace collapsed, cut to 60 runes (word boundary inside the last 15, plus an ellipsis when cut), set once when the first turn is posted and never changed after; state = awaiting_approval when any call is pending, else running, else error when the latest turn item has an Error that is not Cancelled, else idle; turns = user items; cost_usd = sum of priced turns, absent when none was priced; last_activity is bumped by every emitted event and every turn start. Consequence: the rail's error mark means the last turn failed, and a Stop leaves the chat idle. Not meant: the server sorts rows by id, so recency order is the client's job (last_activity).

# GET /chats rows and the chat_state event carry one rowState (title, state, turns, cost_usd, last_activity, started_at); state is awaiting_approval over running over error over idle, and the person's own Stop is not an error

rowState (chat.go) is the chat's rail row. GET /chats embeds it beside the chat's identity (listItem{chatItem, rowState}) and the page stream's chat_state event sends it tagged with the chat id, so the two cannot disagree. Fields: title = the first message with whitespace collapsed, cut to 60 runes (word boundary inside the last 15, ellipsis when cut), set once when the first turn is posted and never changed after; state = awaiting_approval when any call is pending, else running, else error when the latest turn item has an Error that is not Cancelled, else idle; turns = user items; cost_usd = sum of priced turns, absent when none was priced; last_activity = last frame sent or turn start; started_at = creation time. noteState sends chat_state only when the row changed ignoring last_activity (which moves with every frame). Consequence: the rail's error mark means the last turn failed, and a Stop leaves the chat idle. Not meant: the list is sorted by id, so recency order is the client's job (last_activity); a row change that nobody calls noteState for is not announced.

Update 2026-11-06: titleOf now cuts at chatTitleMax = 300 runes (was 60); the same title string rides in GET /chats rows, chat_state and the snapshot. See the title-cap fact in this category.

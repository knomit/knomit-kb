# web.Server struct owns server-wide state (LLMAdapter, Embedder, config); SynthDeps deleted; synth handler is a free func taking only the LLMAdapter

internal/web has a Server struct that owns server-wide state: Manager, GitHandler, EmbeddingsEnabled, OntologyRoot, AgentBranch, SessionManager, LLMAdapter, Embedder (plus ReadOnly, APIOnly, CORSOrigins, JobRegistry, and the pluggable provider fields). cmd/serve.go constructs the Server and calls srv.Handler() (server.go) instead of the old NewRouter(args...); Handler() lazily builds the single MCP handler (`buildMCPHandler`), mounts /git and the API router under APIBase.

The synthesis-run POST handler is `handleStartSynthesis(llmAdapter llm.LLMAdapter) http.HandlerFunc` in handlers_jobs.go — a FREE FUNCTION (not a *Server method), wired in router.go as `handleStartSynthesis(s.LLMAdapter)`. It creates the Reviewer ON-DEMAND per request from the resolved repo instance ri, NOT from server-wide embedder/agentBranch, and runs it in the repo's TaskHub. Returns 503 if llmAdapter is nil, 409 if a synth job is already running.

SynthDeps (the field on repos.RepoInstance that bundled Reviewer + LLM) is DELETED entirely — zero references remain. repos.Deps has no LLM field; the LLM adapter is constructed and held by web.Server. Don't pass LLMAdapter through repos.

WHAT THIS DOES NOT MEAN:
- The synth handler is NOT a method on *Server, and there is no `handleSynthesizeStart` — the function is `handleStartSynthesis`, package-level.
- **It no longer takes a *repos.Manager.** This fact previously gave the signature as `handleStartSynthesis(m *repos.Manager, llmAdapter llm.LLMAdapter)`; at HEAD it takes ONLY the adapter and resolves the repo from request context. Do not wire `s.Manager` into it.
- `SynthDeps` does not exist — do not search for it or reintroduce a bundle type to carry the LLM through repos.

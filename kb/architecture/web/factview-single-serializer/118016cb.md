# One factView struct + buildFactView serializes both HEAD and commit-anchored fact responses

ONE factView struct + ONE buildFactView function (package kb, internal/edge/web/api/kb/fact_view.go since 12f; unexported since the move out of package web) serializes BOTH HEAD-anchored and commit-anchored fact responses. The link set differs by anchor: HEAD view has {self, incoming, outgoing, commits, snapshot, parent, branch}; commit-anchored has {self, incoming, outgoing, commits, live, commit, parent, branch}. 'snapshot' (HEAD only) is the immutable citation pin at the current head sha — the only way to get a stable URL out of a HEAD view. 'live' (commit-anchored only) is the URL back to HEAD. 'commit' (commit-anchored only) points at the parent commit resource. Both shapes carry incoming + outgoing (commit-anchored incoming returns version-aware lineage — see store/derived-from-time-aware-edges). factParentTopic derives the parent topic URL by stripping the ontology root prefix (first path segment) and the filename (last segment) from the fact's path. factView.MarshalJSON is overridden so the Links field emits under the canonical '_links' key.

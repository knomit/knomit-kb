# App.New gives the web Server a Lifetime derived from context.Background() (not the signal ctx) and OriginSessionsDir <home>/origin-sessions; App.Close ends the lifetime first, which removes every origin session and its run

WIRING. internal/app New makes `lifetime, endLifetime := context.WithCancel(context.Background())`, stores endLifetime on App, and sets web.Server{Lifetime: lifetime, OriginSessionsDir: filepath.Join(cfg.Home, "origin-sessions")}. App.Close calls endLifetime FIRST, before the manager closes. web's originSessionsRouter reads Server.Lifetime once, inside its sync.Once (nil becomes context.Background(), i.e. never ends) and calls origins.Mount(ctx, r, s.Manager, s.AgentBranch, s.OriginSessionsDir). The manager arranges sm.close with context.AfterFunc(ctx).

WHY BACKGROUND, NOT THE SIGNAL CTX. A signal cancels the serve ctx BEFORE the graceful shutdown drains in-flight requests, and an origin-session commit may be one. Close runs after serveUntil's Shutdown returned, but Shutdown gives in-flight requests only a 5 s grace, so a slow step can still be running: the manager does not pull its session away; a session in use is closed and removed when its handler returns, and only then is the run removed (see the store-close-and-use invariant).

DOES NOT MEAN: that a process always leaves no folders. The AfterFunc goroutine is not awaited, so an immediate exit can leave a run, which the next manager reclaims (per-process-runs invariant). A Server with no Lifetime and no OriginSessionsDir (tests) lives forever and keeps a private base under os.TempDir().

Test: TestNew_OriginSessionsHaveTheAppsLifetimeAndHomeDir (internal/app) checks the dir sweep and that Close ends Lifetime.

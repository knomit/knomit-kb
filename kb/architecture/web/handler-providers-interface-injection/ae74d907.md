# Server has 14 pluggable provider fields (interfaces); default*Provider delegates to store via WithRead

The web.Server struct has 14+ pluggable provider fields: factReader, topicLister, searchProvider, commitsProvider, factSubProvider, statsProvider, domainsProvider, completionsProvider, factsCollectionProvider, activityProvider, factWriter, originProvider, branchesLister, branchRootReader. Each is an interface (e.g. FactReader, TopicLister, searchProvider). Production code uses defaultXxxProvider{} instances that delegate to the store via ri.WithRead. Test code injects mocks. The pattern in NewAPIRouter is: `xxx := s.xxxProvider; if xxx == nil { xxx = defaultXxxProvider{} }` then pass to the handler factory closure. CONVENTION: handlers depend on the NARROWEST provider interface they need, not on *repos.Manager or *store.Service directly. Anti-pattern: handlers reaching into s.Manager.Get(repo).WithRead(...) inline — instead dispatch through a provider so tests can mock without spinning up a full store.

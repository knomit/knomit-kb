# Server has 14 pluggable provider fields (interfaces); default*Provider delegates to store via WithRead

The web.Server struct has 14+ pluggable provider fields: factReader, topicLister, searchProvider, commitsProvider, factSubProvider, statsProvider, domainsProvider, completionsProvider, factsCollectionProvider, activityProvider, factWriter, originProvider, branchesLister, branchRootReader. Each is an interface (e.g. FactReader, TopicLister, searchProvider). Production code uses defaultXxxProvider{} instances that delegate to the store via ri.WithRead. Test code injects mocks. The pattern in NewAPIRouter is: `xxx := s.xxxProvider; if xxx == nil { xxx = defaultXxxProvider{} }` then pass to the handler factory closure. CONVENTION: handlers depend on the NARROWEST provider interface they need, not on *repos.Manager or *store.Service directly. Anti-pattern: handlers reaching into s.Manager.Get(repo).WithRead(...) inline — instead dispatch through a provider so tests can mock without spinning up a full store.

HISTORICAL as of the W0 series (kb/decisions/store/web-provider-removal/c501f55f.md): this describes the design BEFORE the provider interfaces were deleted. Do not follow the 'dispatch through a provider' convention or the NewAPIRouter nil-default pattern for new code. After W0h (PR #617, merged 660cc910) only 1 interface remains in internal/edge/web (originProvider) and storeProviders has 1 member (origin); FactWriter (now the package functions factResolves, priorRefs, writeFact and deleteFact in handlers_fact_write.go) is gone too, as is RefResolver (deleted in W0g4, PR #616, merged ed6aefc2) (BuildRefViews and BuildFactView now take the concrete readerRefResolver), FactReader (now the package function readFact), factSubProvider and commitsProvider are gone too; the rest of the list above (including commitsProvider, TopicLister, statsProvider, activityProvider, searchProvider, factsCollectionProvider and motifsProvider) are gone, and handlers take concrete types and are tested on real stores. DOES NOT MEAN the remaining one is the recommended pattern: it is scheduled for deletion (W0i). The '14 provider fields' count in the title is the pre-W0 count, not the current one.

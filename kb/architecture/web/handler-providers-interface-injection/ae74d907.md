# HISTORICAL (pre-W0, gone since W0i): web.Server had 14 pluggable provider fields (interfaces) and default*Provider delegated to the store via WithRead

HISTORICAL. Nothing described here exists at 585974c5. After W0i (PR #619, merged 585974c5) no provider interface, storeProviders, withDefaults, Server.providers or default*Provider remains in internal/edge/web (providers.go is deleted); handlers take concrete types and are tested on real stores. The history of the deletion is kb/decisions/store/web-provider-removal/c501f55f.md, one fact per step; the final step is kb/decisions/store/web-provider-removal/ff7a74aa.md. The src ref to providers.go below is pinned at 660cc910, the last commit where the file existed, and is dated support only.

WHAT WAS TRUE before the W0 series: the web.Server struct had 14+ pluggable provider fields: factReader, topicLister, searchProvider, commitsProvider, factSubProvider, statsProvider, domainsProvider, completionsProvider, factsCollectionProvider, activityProvider, factWriter, originProvider, branchesLister, branchRootReader. Each was an interface (FactReader, TopicLister, searchProvider, ...). Production code used defaultXxxProvider{} instances that delegated to the store via ri.WithRead; tests injected mocks. NewAPIRouter applied `xxx := s.xxxProvider; if xxx == nil { xxx = defaultXxxProvider{} }` and passed the result to the handler factory closure. The convention was that handlers depend on the NARROWEST provider interface they need rather than on *repos.Manager or *store.Service, and that handlers must not call s.Manager.Get(repo).WithRead(...) inline.

DO NOT FOLLOW any of the above for new code. The convention is inverted: a handler takes the concrete type (*repos.RepoInstance, *repos.Manager, *store.Service) and its test builds a real store, failing reads through the owning package's fail-only hook (kb/decisions/store/web-provider-removal/a8b768db.md). The archtest guard fails a new interface in web (kb/conventions/go/package-boundaries/web-no-interfaces/d36fa222.md).

DOES NOT MEAN: that web has no test seams of any shape; a function-typed seam is not detected by the guard.

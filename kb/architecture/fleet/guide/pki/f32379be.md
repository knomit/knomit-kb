# Fleet guide — PKI and transport: an operator-held fleet root (its key a plain owner-only file root.key: no OS keychain, no passphrase, no export/import) signs instance and operator certificates over each instance's EXISTING ssh-ed25519 key; enrollment, renewal, revocation and CRL delivery are MANUAL CLI/desktop steps on dev (`knomit identity enroll` -> bundle -> `install`; `revoke`), which stay until the fleet membership verbs land; the certificate admits a peer to the mTLS listener with implicit read and push:own, and it carries no signing authority

Part of the fleet guide (kb/architecture/fleet/guide/). Describes merged dev at 3e2e83b0 (PR #514), except the ROOT paragraph, which describes the root key as of 72919aa0 (PR #519).

ROOT (fleet root side, the operator's machine, default <home>/fleet). `knomit identity init-root` creates root.crt and an initial crl.pem (enroll and revoke append the operator machine's LOCAL audit logs issued.jsonl / revoked.jsonl there; the fleet repository holds no ledger); the root KEY is the plain, unencrypted OpenSSH-format file <dir>/root.key (mode 0600, in an owner-only directory; PR #519, merge 72919aa0), like an SSH key: no OS keychain, no passphrase, no prompt, and no export-root/import-root (they were deleted; `knomit identity import-root x` is an unknown-command error). Every root operation (init-root, enroll, revoke, `oauth approve --sign`) reads the file through pki.LoadRoot, which refuses a directory that is not private to the user or a key that is a symlink or wider than 0600; whoever can read the file can sign for the fleet, and a lost or replaced key is a fresh fleet (kb/decisions/pki/root-custody/plain-key-file/781b626f.md). `root-fingerprint` prints the RootID (SHA-256 of the root key's SSH wire encoding) from root.crt alone, which installers confirm.

ISSUE (built, manual). `knomit identity enroll --pubkey <instance key line> (--agent-id <id> | --operator [--email <addr>])` signs the instance's existing key into a bundle (leaf + root.crt + current CRL); default validity 90 days. A certificate names its holder with ONE email SAN <agent-id>@agents.knomit.io (the committer's form; the id is compared for equality, never parsed); there is no URI SAN and no role field. pki.IdentityOf: exactly one email SAN that is an agent address = an INSTANCE certificate (implicit read + push:own); anything else (another address, no email, several emails) = an OPERATOR (grants rows only). Agent ids are lower case everywhere; ValidAgentID refuses an upper-case letter, '+', '@', white space or control characters where an id is minted, read back at boot, or certified, and nothing is case folded (certs/Vic.pem can hold no leaf). Certificates issued before #514 (URI SAN only) read as operators until re-issued. internal/pki splits signing from placement (IssueLeaf, RevokeSerial, SignCRL return bytes; the leaf PEM is the fleet repository's issuance record, RevokeSerial also returns a root-signed revocation statement and builds the new CRL from the CURRENT CRL) so a future fleet reconcile can write them as fleet-repository artifacts; on dev nothing outside internal/pki calls them, and NeedsRenewal / CRLNeedsResign have no caller.

INSTALL (instance side). `knomit identity install` or the desktop Settings Fleet page call pki.InstallBundle: the leaf must be for this instance's key and chain to the bundle's root under its CRL; a first install or a root change (--replace-root) needs the root fingerprint confirmed out of band; the decision is taken against the root the caller saw, under a cross-process lock. Files land in [tls].dir (default <home>/pki): instance.crt, root.crt, crl.pem, crl.number. Trust material changes ONLY through the CLI or the desktop's window-gated bindings, never an HTTP route.

REVOKE. `knomit identity revoke --serial|--fingerprint` appends revoked.jsonl and reissues crl.pem with a higher Number. A listener honours a revocation only once IT holds a CRL listing the serial; on dev the only wired installer is InstallBundle (InstallCRL, the CRL-only install with a per-root, strictly-increasing Number watermark, exists for design P6 and has no caller outside internal/pki). A CRL past NextUpdate is enforced and warned.

TRANSPORT. The mTLS listener ([tls].addr; off until set AND a certificate is installed) is a separate http.Server over the same handler; it requires a client certificate and judges it with pki.VerifyInstanceChain (chain to the installed root, not revoked); open connections are re-judged at first track, after each adoption and on a 10 s ticker. A verified certificate becomes a principal (Kind instance or operator decided by its email SAN, Via cert, ID = the full 64-hex key fingerprint). auth.CertGrants gives every chained INSTANCE read and push:own implicitly and nothing else; anything more, and everything an operator certificate holds, is a grants row (`knomit grants add <principal> <permission>`). Permissions: read, write, push:own, merge:main, operator, admin. Peers dial a host through the knomit+https:// go-git scheme over pki.HTTPClient; there is no plaintext fallback.

CONSEQUENCES. Certificates gate the NETWORK (who may connect, fetch and push to a knomit host); member records gate SIGNING (whose commits a main accepts). They are independent on dev: removing an agent needs both a record change (signing) and a revocation installed on hosts (network).

MISREADINGS. 'The fleet repository distributes certificates and the CRL by itself': it can STORE them under rules the judge enforces, but issuing into it and installing from it are manual or unbuilt (P5/P6). 'openssl's certificate fingerprint is the root fingerprint': no, install --root takes the key's SSH-wire SHA-256. 'A certificate lets a peer write': an instance certificate holds only read and push:own; writing facts needs a grants row.

UPDATE (PR #514): THE FLEET REPOSITORY'S TRUST FILES. Under artifacts/fleet/ the fleet preset declares: root.crt (write-once), crl.pem (replaced only by a root-signed CRL with a strictly greater Number that keeps every previously listed serial), certs/<id>.pem (an agent's current leaf; replaced only by a renewal for the member record's current key with a later NotBefore), issued/*.pem (ONE write-once file per issuance: the issued leaf's PEM, whose root signature is the record), revocations/*.txt (ONE write-once file per revocation: a statement knomit-revoke/v1 + root fingerprint + serial + time + reason, signed by the root). These per-operation files REPLACE the old append-only issued.jsonl / revoked.jsonl ledgers in the fleet repository: there is no ledger to append to there (kb/decisions/fleet/pki/per-operation-records/235c9dd9.md). A file NAME means nothing (uniqueness and readability only); order and meaning come from the signed content (D18). The root key signs X.509, CRLs and revocation statements; the statement's tag makes the three unforgeable as each other. The judge enforces these rules (kb/architecture/fact/ontology/guide/artifact-rules). Commit root.crt and crl.pem FIRST when creating the fleet repository, then members. MISREADING: 'a revocation file revokes': no; only the CRL the judge reads at the fleet revision revokes. A revocation file is a signed, judged record. Nothing writes these files automatically yet (P5).

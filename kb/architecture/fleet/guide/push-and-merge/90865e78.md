# Fleet guide — push and merge: on a knomit host a peer pushes its agent branch over mTLS into receive-pack (one agent/* ref, never the host's own, dot-path fast-fail, judged per verify_signatures), and it reaches the host's main only by a merge into the host's AGENT branch — the operator's web merge or `consensus: auto` — which the local reconcile then fast-forwards main onto; a forge host does all of this with its own push and PR merge

Part of the fleet guide (kb/architecture/fleet/guide/). Describes merged dev at c9c599de.

TWO HOSTINGS. A knowledge base's git lives either on a FORGE (GitHub: peers push their agent branches with forge credentials, a pull request or workflow merges into main, `knomit verify ci` is the gate) or on a KNOMIT HOST: one instance holds the repository with NO origin and serves /git over the mTLS listener; peers mount it with a knomit+https:// origin. Everything below is the knomit-host path.

1. PUSH (receive-pack, F11, knomit's own code over go-git's codec). Who: only a principal of Kind instance authenticated Via a certificate holding push:own (implicit for every instance certificate chaining to the fleet root); a subscription refuses. What: exactly ONE command, not a delete, under refs/heads/agent/, not the upstream, not the host's own agent branch; NO rule asks whose branch it is (any enrolled pusher may push any other agent/* ref; branch ownership is not identity). The pack goes into a quarantine; new commits are those the host does not hold; in EVERY verify mode a new commit whose dot-path content (.knomit/, any segment beginning with '.') matches none of its best merge bases with the upstream is refused (early feedback only). Then, when verify_signatures read at the HOST's upstream tip is log or enforce, each new commit is judged against the fleet repository's records (judgeCommit, the acceptance gate's rules) plus signer = pusher (the SSHSIG key must be the pusher's certificate key, full fingerprint); enforce refuses, log only logs, off never reads the fleet (enforce with no fleet repository refuses). Accepted objects are promoted in one transaction under the branch lock. The pushed branch is readable on the host, never writable there, fires no host trigger and is never forwarded by the host.

2. MERGE into the host's AGENT branch — never main, never a caller-chosen target. Two routes only: the operator's web merge (POST /repos/{repo}/branches/{branch}/merge {expected_tip, resolution?} -> store.MergePushed; requires the `operator` permission; resolution host|peer settles every conflicting path) and, when the ontology at the consensus branch's tip says `consensus: auto` on a no-origin, writable, non-subscribed repo, the consensus merger (store.MergeConsensus, asynchronous, kicked by any commit on a non-agent, non-exp branch). Both write one host-signed merge commit and both REFUSE a merge whose result would change any dot path of the host's agent branch (PrivatePathMergeError; 409 "Merge would change system files") — this merge-time guard, not receive-pack, is the authority that a peer cannot change the host's .knomit/. Conflicts on paths both sides changed are settled by the root attribute `conflicts` {facts, state} read at the consensus branch's tip (absent under consensus: auto reads facts: merge / state: consensus; a key set to off refuses and leaves the branch for a human).

3. MAIN FOLLOWS. On the host (no origin) the local reconcile loop (AdvanceLocalUpstream, every [git].local_reconcile_interval, default 30 s, sooner after a merge's wakeSync) only FAST-FORWARDS main to the agent branch. Peers fetch main on their sync round and merge it into their own agent branches, settling conflicts with the same `conflicts` setting (the incoming consensus branch is the consensus side there).

CONSEQUENCES. A push being accepted is not its content being accepted: nothing reaches main until a merge. Once merged, a peer's facts fire the HOST's triggers (change.source = merged). A GitHub-hosted KB gets the same conflict settlement because it runs in the peer's sync before its push.

MISREADINGS. 'consensus: auto merges into main': false, it merges into the host's agent branch. 'receive-pack protects .knomit/': only as a fast-fail; the merge guard is the authority. 'With verify_signatures off a pushed branch is owned by its pusher': no branch is owned (PR #513 removed the fp8-suffix rule); the certificate is the whole authentication of a push.

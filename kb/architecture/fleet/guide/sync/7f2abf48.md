# Fleet guide — sync and triggers in a fleet: each instance's sync loop pushes ONLY its own agent branch and merges the consensus branch back in; a peer with an origin syncs every 300 s (fixed) unless `sync: {pull: realtime}`, a no-origin host fast-forwards main every 30 s, `sync: {push: realtime}` and `do: push` triggers cut push latency to a 1 s countdown, and both settings are read at the consensus branch's tip

Part of the fleet guide (kb/architecture/fleet/guide/). Describes merged dev at c9c599de.

THE LOOPS. A repo WITH an origin runs the origin loop: fetch, merge the origin's consensus branch into the agent branch (settling conflicts per the root attribute `conflicts`, the incoming consensus branch being the consensus side), push the agent branch when ahead. Its interval is remotes.interval, 300 s by default, and nothing writes it, so a peer's cadence is fixed unless `sync: {pull: realtime}` switches the round to [git].realtime_pull_interval (knomit.toml, 3 s default, 1 s floor). Two circuit breakers (fetch, push) gate every round. A repo with NO origin (a knomit host) runs the local loop: AdvanceLocalUpstream fast-forwards main to the agent branch every [git].local_reconcile_interval (30 s default; 0 disables the loop), or at the realtime interval under pull: realtime. A subscription has no agent branch, pushes nothing and ignores `sync`. The consensus branch's name is recorded per repo, never assumed to be "main".

PUSH LATENCY. `sync: {push: realtime}` makes every commit on the instance's OWN agent branch open the fixed 1 s push countdown; a `do: push` trigger does the same for the commits it matches; one round then carries everything on the branch. On a no-origin repo a push fire wakes the local loop instead.

WHERE SETTINGS ARE READ. `sync`, `consensus` and `conflicts` are read from the ontology at the tip of the CONSENSUS branch (the sync loop at start and before every wait; the merge sites per merge), so an instance whose consensus branch lags reads the older value for that round. They are documented as set-once-and-forget; nothing coordinates a change across instances.

TRIGGERS ACROSS THE FLEET. Triggers fire on the instance's own agent branch only: a pushed peer branch fires nothing on the host, but what a merge brings into the host's agent branch does (change.source = merged), including `do: run` recipes. change.author.verified tells a script whether the change passed the acceptance gate.

CONSEQUENCES. End-to-end latency from a peer's write to every peer's agent branch on a knomit-hosted fleet is bounded by: peer push (1 s realtime or the peer interval) + host merge (consensus: auto, immediate) + host main fast-forward (wakeSync / 30 s) + every other peer's pull (300 s, or 3 s realtime). Against GitHub, realtime push from one busy instance exceeds GitHub's recommended push rate; pull: realtime is for small fleets only.

MISREADING. 'The host pushes peers' branches onward': no; the sync loop's Push sends nothing but an instance's own agent branch. ONE STATED EXCEPTION (PR #518, merge 537f2019): RemoteIndex.PublishUpstream, the fleet root holder's NON-force push of the fleet repository's main to its forge origin. It is run by the fleet create (a forge create) and by fleetPushed after a successful agent-branch push while the fleet is still registering; it is not part of a loop round and never forces (a main that is not an ancestor is refused by the origin). On a fleet hosted here (no origin) nothing is pushed: AdvanceLocalUpstream fast-forwards main.

## UPDATE (PR #524, verified at merge commit 9db8c106): 'pushes ONLY its own agent branch' has one exception

A sync round's push still sends only the instance's own agent branch (remoteIndex.Push, by hash, with the +<sha> refspec to its own branch). The exception is the fleet MASTER (and, before main ever held the root, the holder of the fleet root: RepoInstance.publishesFleetMain): after its own push, if that push did not fail, the same round PUBLISHES main (store PublishUpstream: local main to the origin's main, WITHOUT force), whether or not the own push sent anything, so a main that fleet create or an earlier round failed to publish goes out on the next round. A refusal is recorded on the push status row (RecordPushError). The master's fetch also carries one more refspec (agent/*) for that fetch only, so on a master the round is: fetch main + own branch + all agent/*, judge/promote, merge (async), push own branch, publish main. A member's round is unchanged.

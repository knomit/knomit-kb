# GET /api/v1/fleet contract (PR #527): fleet_urls, host_record, follows_host, host.listener / listener_on / external_addresses / would_serve, public_key, root_fingerprint and `local`; no URL in it carries userinfo, fleet_url and the join's FleetJoined wrapper are gone

Verified at merge commit c6e282db.

FIELDS. `fleet_urls`: the fleet repository URL(s) members use: on the hub (the fleet repository's copy has no origin) one https://<address>/git/<repo> per https external address; on a copy WITH an origin, the host record on main when it holds one, else the origin URL; [] with no fleet repository. `host_record`: the host record as main holds it (omitted when main holds none or an unreadable one). `follows_host`: the SERVER's comparison: true on the hub; on a copy with an origin and a host record, whether the origin is one of the record's URLs under sameFleetURL (scheme and host compared in any case, a default port 443/80 dropped, a trailing slash and credentials ignored; the path otherwise exact); nil (omitted) when there is nothing to compare. false means "this copy follows an old host". `hosting`: the origin URL or "none". `public_key`: this instance's ssh-ed25519 key line. `root_fingerprint`: the root installed in [tls].dir (the join answer is this same FleetStatus, so it carries it). `host` replaces the flat external_addresses: host.external_addresses; host.listener_on (always sent); host.listener, the [tls].addr bind, ONLY for a local caller; host.would_serve, only on the master while its copy has an origin: the URLs members would use if it hosted here (what the Host-here confirm names). `local`: isLocalVia(r), the same test RequireLocalVia makes (the principal arrived over the local authenticated listener; nothing the client sends can make it true), added to EVERY fleetView response (create, join, leave, decommission too; trivially true on those local-only routes), so a page knows whether the mutations are reachable from where it runs. FleetURL (`fleet_url`) and the FleetJoined wrapper were removed. record_state is read from member RECORDS only and never reads `enrolled`.

NO USERINFO: hosting, fleet_urls, host_record and would_serve go through credentialFree. KNOWN GAP (F3, queued for PR7b): the enroll answer's fleet_url and the bundle url: are NOT stripped (they copy a forge origin URL verbatim); see the host-record fact.

MISREADINGS. (1) "The page compares hosting with host_record": it must use follows_host; the raw strings differ by credentials, case, port and slash. (2) "would_serve non-empty means this instance hosts": it is set only while the copy has an origin (it is NOT the host); an empty or absent would_serve also covers "no https external address", which host.external_addresses tells apart. (3) "host.listener is always present": it is deleted for a non-local principal.

## UPDATE (PR #528, verified at merge e417fd76): fields added, and what `listener_on` does NOT say

GET /fleet gained: `host.listening` (the mTLS listener is bound and serving NOW, read live from the listeners' snapshot: `knomit reload` flips it with no restart; Manager gets it from cmd/serve.go through SetTLSListener), `host.listener_reason` (`no_certificate` or `addr_in_use`: why a CONFIGURED listener is down), `sync_interval_seconds` (the copy's origin loop interval) and `last_error_refused` (the recorded last_error is a TLS handshake refusal by the fleet, derived from pki.ErrRefusedByPeer's text, no new state). `host.listener_on` keeps ONE meaning: configured ([tls].addr set), not up. CONSEQUENCE: every page sentence that promises members "can join now" / "push to it" must be gated on `host.listening` (hub master) and never on `listener_on`, which stays true while the listener is down for lack of a certificate (after a create or Host here the certificate appears but the listener only starts on `knomit reload` or a restart). MISREADING: "configured means up". GET /repos rows also carry `fleet: true` on the fleet repository's row (kb/invariants/web/shell/fleet-not-browsable/8a67c851.md). Tests: TestFleetStatus_ListeningIsTheLiveListener, TestFleetStatus_LastErrorRefusedIsTheHandshakeRefusal, TestFleetREST_AddressesAndRecord.

UPDATE (PR #529, verified at merge 60ddfb1c): GET /fleet gained `interrupted_move` ({record_is_here} or {move_back_to}; only on the master whose forge copy does not follow the host record) and `last_error_fleet_moved` (on a member whose follows_host is false and whose last_error is the old host's push refusal); see kb/architecture/fleet/move/interrupted-move/e9c7d31c.md. POST /fleet/follow answers this same FleetStatus plus `change`. Every URL it carries stays credential-free, including the texts of follow errors (kb/conventions/fleet/credential-free-text/48f69bb9.md). On a master that moved onto a forge, hosting is the forge URL, host_record is the forge and follows_host is true; each member's follows_host is false until it points at the forge. MISREADING: 'interrupted_move is set whenever follows_host is false': only on the MASTER with a non-cert origin.

UPDATE (PR #532, squash commit a1b0ca5d on dev, verified in repos/fleet.go there): GET /fleet gained `revokes_left` (omitted when false): THIS instance's rounds run the leave duty, i.e. Master (root AND main's marker names it) AND no master_paused AND main holds the fleet's PKI with a CRL; the Fleet members footer says 'A member that leaves is revoked by this instance's next round once its left record is on main' only when it is true. `record_state` is one of pending, active, left, revoked, and is OMITTED when the instance has no record on its branch or on main (before #532 an instance with neither read pending); the rule is kb/invariants/fleet/status/record-state-rule/b4e16731.md, and the join answer is this same FleetStatus. The openapi file at the merge documents revokes_left, record_state and the members schema's revoke_due. MISREADING: 'revokes_left true means the instance is the master': it additionally needs a PKI with a CRL on main.

# POST /fleet/join:check (local-only) runs the join's pre-flights, then classifies the bundle's URL against the BUNDLE's root from a temporary directory and writes nothing; join and join:check share ONE code set (joinReachErr): bundle_refused 422 only for a genuine refusal, unreachable 502 for any other failure to classify, bundle_invalid 422 for a URL shape a join cannot clone, and a forge's refused credential is 200 with auth_required

Built in PR #526 (merge 0488c05d), internal/repos/fleet_membership.go CheckFleetJoin, web handleCheckFleetJoin, mounted in the local-only RequireLocalVia group (TestFleetMembership_EveryOperationIsLocalOnly has its row). It holds the fleet-op lock like the join, so it waits behind a running fleet operation.

WHAT IT DOES. (1) The join's pre-flights, nothing installed: fleet_present, trust_installed (409), bundle_invalid, key_mismatch, agent_mismatch (422). (2) cert as auth_method is auth_invalid (422) before any dial. (3) The bundle's leaf, root and CRL are written to a private temp directory (removed on return; pinned by requireNoJoinCheckTemp) and pki.ClassifyOrigin judges the bundle's URL against THAT root with this instance's key: the check does not touch [tls].dir. It answers 200 {url, hosting, host, root_fingerprint, agent_id, auth_required, detail}. The operator confirms root_fingerprint and host BEFORE the join installs the root (issue #299; the join itself passes InstallOptions{} and does not demand the confirmation, the caller does).
- hosting `master`: the URL is an instance of the bundle's fleet. A credential given (auth_method not ''/none, or a token) is auth_invalid (ErrPeerCredential).
- hosting `forge`: anything else. The joiner's own credential is probed through ProbeOriginRefs (no 'decided' mark; trust_installed guarantees this instance holds no fleet root so the probe dials nothing fleet-side). A forge refusing the credential is 200 with auth_required true and a detail; a forge that cannot be reached is 502 `unreachable`.

CODES AT PR #526's MERGE (SUPERSEDED by PR #527, see the UPDATE paragraph at the end) for a failed classification (joinReachErr): pki.ErrOriginUnreachable (no TCP, or a stalled handshake before our verifier ran) was 502 `unreachable` ('couldn't reach <host>'); EVERY OTHER classification error was 422 `bundle_refused` ('the fleet at <host> refused this bundle (<cause>): ask the fleet's master for a new bundle'), the realistic case being an old bundle used after a revoke and rejoin. Request errors: bundle_required (400), auth_invalid (422).

KNOWN DISAGREEMENTS AT PR #526's MERGE (a) and (b) are RESOLVED by PR #527; (c) still holds. (a) bundle_refused ALSO catches network failures after the handshake: 'peer did not answer after the handshake' (an i/o timeout or reset), 'handshake failed' after our verifier accepted the host, and pre-dial errors (stat, no host, unusable trust files). Those are not a refused bundle, so the 'ask for a new bundle' advice is wrong for them; narrowing it to ErrRefusedByPeer and verifier verdicts is the fix. (b) POST /fleet/join maps the same errors differently: a pki.ErrOriginUnreachable on the clone path stays 502 `clone_failed`, where join:check says `unreachable`; other classification errors are bundle_refused on both. (c) A forge refusing the credential is 200 auth_required on the check.

MISREADINGS. 'A green join:check guarantees the join succeeds': the clone, root_differs and the push still run. 'join:check is read-only on the network': it dials the bundle's URL.

UPDATE (PR #527, verified at merge commit c6e282db). ONE CODE SET for join and join:check (joinReachErr, the same text for the same cause; reachCause drops ResolveOrigin's `origin was not attached` wrap so no prefix differs): `bundle_refused` 422 ONLY when the host refused this bundle's certificate (pki.ErrRefusedByPeer) or our verifier refused the certificate the host presents as one of this fleet's (the new pki.ErrOriginCertRefused, which ClassifyOrigin's verdict arm now wraps, with the verdict inside); EVERYTHING else is `unreachable` 502: no TCP connection, a hang-up or reset after the handshake, a stall, a handshake that failed after our verifier accepted the host, this instance's own trust files unusable. A join against a dead host therefore answers `unreachable`, not `clone_failed`. NEW pre-flight in joinPreflight, before anything dials, on both routes: bundleURLProblem refuses the bundle's `url:` line with 422 `bundle_invalid` (the text carries the URL through credentialFree, and ends 'enroll this instance again on the master') unless it is an https:// or ssh:// URL with a host, an scp-style git@host:path, or a file:// URL with a path; plain http, the internal fleet scheme, any other scheme, a URL with no host and a non-URL are refused. (The url: line is unauthenticated: SplitBundle checks only the agent, the root and the serial.) Argument injection through an ssh host is not a concern: the clone uses go-git's built-in ssh client, never the git CLI.

KNOWN GAP (F1, queued for PR7b): a forge fleet whose ORIGIN is http:// can be CREATED (origin routes only reject the internal scheme, and neither CreateFleet nor the create handler has a scheme check) and ENROLLED (fleetURLForBundle copies the origin verbatim), but its bundle then fails bundleURLProblem on BOTH join and join:check with `bundle_invalid`, and the advice 'enroll this instance again on the master' cannot work (re-enrolling yields the same URL). Before this check such a join cloned over plain http. The gap reads false once either the create/attach refuses a non-https, non-ssh, non-file forge origin, or bundleURLProblem accepts http:// with a host. MISREADING: "bundle_invalid means the bundle is damaged": for this case it means the master's own origin has a scheme a join refuses.

# POST /api/v1/fleet/create founds a fleet in a fixed order: pre-flights, marker, root minted into <home>/fleet.creating, repository through the fleet door, recordFleetRepo, three commits (root+CRL, then leaf, then member record), bundle install, rename to <home>/fleet, ONE transaction sets the state and deletes the marker, then main is published

Built in PR #518 (merge 537f2019). The route is POST /api/v1/fleet/create, handled by Manager.CreateFleet(ctx, FleetCreateSpec{Name, Origin}). Request body: optional name (default "fleet") and optional origin {url, branch, auth_method, auth_token}. No origin = this instance hosts the fleet (it is the hub: members push to its mTLS listener). An origin = a forge hosts it.

THE ROUTE IS LOCAL-LISTENER ONLY. router.go registers it as r.With(RequireLocalVia).Post("/fleet/create", ...): served on the unix socket or Windows named pipe, and a 403 on every other transport (an mTLS peer, even one granted write, is 403 naming instance:<fingerprint>@cert; a browser page on loopback TCP is 403). The reason is that it mints the fleet ROOT KEY and installs this instance's own certificate; every other route is also served on the mTLS listener. There is NO CLI verb: `knomit fleet create` does not exist (user ruling, REST first; see kb/decisions/fleet/create/rest-first-local-only).

ORDER (fleet_create.go). 0) recoverFleetCreate rolls back an unfinished earlier create; the pre-flights run (kb/invariants/fleet/create/preflights); the marker row is written in control.db instance_fleet_create. 1) pki.NewRoot, an empty CRL (Number 1) and this instance's leaf are minted into the STAGING directory <home>/fleet.creating, and the root id is recorded on the marker. 2) m.Create makes the repository through the fleet door (mode custom with the serialized built-in fleet ontology, or mode initialize onto the origin). 3) recordFleetRepo stores its uid in instance_fleet_repo, or it would not mount after a restart (kb/invariants/fleet/baked-ontology/reserved-id/4cdcf99e.md). 4) On the agent branch, three commits in this order: root.crt + crl.pem (ROOT FIRST), then certs/<agent id>.pem + issued/<serial>.pem, then the member record (state active). 5) pki.InstallBundle(leaf, root, CRL) into [tls].dir. 6) An empty <home>/fleet is removed (only an empty one) and the staging directory is renamed to <home>/fleet. 7) finishFleetCreate: ONE transaction sets fleet_state and deletes the marker (point of no return: kb/invariants/fleet/create/marker-and-rollback). State: registered with no origin, registering with an origin. 8) main is published. No origin: AdvanceLocalUpstream fast-forwards local main to the agent branch. Origin: Push the agent branch, PublishUpstream (main = that tip, never forced), then local main follows; success sets registered, failure keeps registering with last_error.

ROOT FIRST is now enforced by code on the only create path (the convention kb/conventions/fleet/setup/root-first/05bab145.md was prose before). The key is never in <home>/fleet before step 6, so nothing a create undoes is in <home>/fleet until the rename, and an operator command that writes <home>/fleet meanwhile (`knomit identity init-root`) never sees this create's root. It is not blocked either: if it lands a root in <home>/fleet first, the create's move into <home>/fleet fails (only an EMPTY directory is replaced), the create rolls back, and the operator's root is left alone (removeCreatedRoot matches by root id; TestCreateFleet_RootWrittenMeanwhileIsLeftAlone).

DETACHED FROM THE REQUEST. CreateFleet runs under m.createsCtx with createTimeout, counted in createWg: a client that hangs up does not cancel it; Manager.Close does (and drains it). The rollback runs under context.WithoutCancel so the create's own deadline does not cut it short.

STATUS CODE. createdFleetStatus answers 201 only when state is registered AND record_state is active (the own record read at local main); otherwise 202. 202 happens when a forge publish failed (registering, last_error set) and when a hosted-here main has not followed the agent branch yet (registered, record pending). MISREADING: 201 is not 'state registered'. MISREADING: 202 does not mean the create failed or was rolled back; after step 7 nothing is rolled back (a failed publish is retried by fleetPushed, kb/invariants/fleet/registration/registering-needs-main-published).

MASTER. After a hosted-here create the instance is the master (isFleetMaster: root.key regular file AND <home>/fleet/root.crt equals artifacts/fleet/root.crt on main) from the 201 on, because main advanced inside the create. On a forge create it is the master only once main is on the forge and local main follows.

NOT DONE: no reload hint. If [tls].addr is set but the listener is not open (it needs a certificate at boot), create installs the certificate and starts nothing (kb/gotchas/desktop/tls/install-does-not-start-listener/fe172776.md).

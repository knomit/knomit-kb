# Fleet registration is REST on the running server (GET/PUT/DELETE /api/v1/fleet) driving the control.db state machine standalone->registering->registered->unregistering->standalone; the push that completes a pending step is retried by the repo's own reconcile loop (onPush -> Manager.fleetPushed)

repos.Manager: fleetRepo() = the one mounted repo whose ontology is the fleet preset (no name, no URL stored). RegisterFleet(url): refuses registration_pending / unregistration_pending (409) by state, already_registered (409) if another fleet URL is mounted (the same URL re-registers: registerOwnRecord compares the own record on the agent branch head with Manager.advertised() and writes ONE compare-and-swap version only if an advertised field changed or the state is not active; unchanged -> NO commit at all); clones (a clone failure is 502 clone_failed, nothing mounted or persisted, last_error recorded, state stays standalone: master ruling 6.6); a non-fleet ontology is 422 not_a_fleet and the mount is deleted; then writes this instance's record (persisted agent id, CURRENT key, state active, host, branch) on its agent branch at a stable per-agent path (memberRecordPath: members/<id>/<sha256(id)[:4] hex>.md) and pushes. UnregisterFleet: not_registered (409) when standalone; commits state left, enters unregistering, pushes; ONLY a successful push deletes the mount and enters standalone.

Retry: runReconcileLoop takes onPush(repo, err); the Manager wires Manager.fleetPushed, which ignores non-fleet repos, records fleet_last_attempt/fleet_last_error (cleared on success), and on success completes registering->registered or unregistering->(deleteRepo, standalone). FleetRetry pushes once on demand. Guards: Archive/DeleteRepo of the fleet repo while registering/registered -> 409 use_unregister; while unregistering an archive by hand is the escape hatch and enters standalone.

Clients: web handlers (problem+json with code; declared in openapi.yaml, contract-tested), the Fleet tab in Manage (between Knowledge and Sessions), and knomit fleet status|register|unregister as a thin local-socket client (localAPIClient/localCall, never app.New). record_state is read from the fleet repo's local upstream (pending until a human merges the agent branch).

BOOT RECONCILE (F10). Manager.Start ends by launching startFleetBootReconcile: one goroutine, tracked by fleetBootWg (Close waits on it before releasing control.db), that NEVER blocks or fails Start. fleetBootReconcile does nothing unless control.db fleet_state is `registered` (standalone, registering and unregistering are skipped) and the instance is not read-only (INFO line; a read-only instance never pushes). A missing/unopenable fleet repo or a missing own record is one WARN, retried at the next boot or PUT. Otherwise refreshOwnRecord reads the own record at the agent branch HEAD (not main), diffs the advertised fields against advertised() (config external_addresses verbatim, git only when git.serve && !read_only, os/arch from runtime via hostPlatform, version.String(), read_only, hostname, key, branch) and writes at most ONE version via WriteFactIfUnchanged(expectBlob = the blob it read), keeping state and notes verbatim; logs INFO `fleet record current` or `fleet record updated: <fields>`. The ordinary sync loop pushes it; a human merge publishes it on main. This is the only automatic fleet write; TestFleetRecordWriters_OnlyFleetCallers pins the exact call sites of the record writers, and no KB write path reaches it.

STATUS (F10). FleetStatus adds external_addresses ([] never null), notice (while empty), record (own record at agent head), record_current (agent head == advertised now), and record_pending_update = the own record's BLOB differs between agent head and main while main has one. MISREADING: pending update is NOT 'agent branch ahead of main' — the sync loop merges main into the agent branch, so the branch is routinely ahead by merge commits with nothing to accept.

# Drop commit (POST /api/v1/fleet/drop-commit, store.DropUnpublishedCommit) is the only way out when the judge holds the master's main: it rebuilds this instance's branch on main without the named commit, loses nothing but that commit's own changes (a later edit of the same file survives), refuses a merge (merge_commit), another agent's commit (foreign_commit) and a commit main already holds (not_unpublished), and offers a CONFIRMED leave-out-the-whole-merge fallback that loses exactly the commits it listed

WHAT IT IS (PR #533, squash commit 6f241959 on dev, verified there). When judgeOwnRange refuses a commit of the master's own branch (kb/invariants/store/verify/own-range), GET /fleet reports last_error_main_held and last_error_main_held_commit (the commit that WROTE the failing content, introducedBy, not necessarily the tip) and the Settings card (MainHeldNotice in web/src/FleetSettings.tsx) replaces 'Retrying on the next sync' with plain copy and a button 'Drop commit <8-hex>' (local desktop only; otherwise 'Only the desktop app on this machine can drop it.'). The button calls POST /api/v1/fleet/drop-commit {commit}: local-listener only (RequireLocalVia), under the fleet lock, then the branch lock across the rebuild.

WHAT A PLAIN DROP DOES (store.DropUnpublishedCommit(ctx, branch, drop, ownOnly)). It walks the first-parent line from the tip down to main and rebuilds the branch ON main, replaying every commit not yet on main in order, minus the dropped one, each re-signed by this instance (replayCommit; a three-way merge with LocalWins). Replay order is oldest first (TestDrop_ReplaysTheOtherCommitsInOrder). A later commit that edited the SAME file as the dropped one keeps its version of that file, so only the dropped commit's own changes are lost, 'except where a later commit on this branch edited the same file' (TestDrop_KeepsALaterEditOfTheDroppedCommitsFile; the card copy says so). A merge on that line that does not carry the dropped commit is replayed AS A MERGE of the same other parents (replayCommit with extraParents), so members' work merged while main was held survives and reaches main. A merge whose other parents reach the dropped commit is UNFOLDED: its side's commits are replayed one at a time, parents first (post-order, so the last edit of a file wins; TestDrop_AnUnfoldedSideIsReplayedParentsFirst), excluding what the first parent already reaches, the dropped commit and nested merges; the result's MergesDropped counts them. After the rebuild the fleet publishes main, which clears the recorded refusal; the answer is 200 {dropped, replayed, merges_dropped, published, publish_error, left_out}. UI outcome lines: '✓ Dropped <8-hex>. Main moved on.' and 'Dropped <8-hex>, but main still did not move: <publish_error>' (kept in FleetSettings state so it survives the notice unmounting once last_error clears).

REFUSALS (nothing is changed by any of them): 409 not_registered; 422 invalid_commit; 409 not_unpublished (ErrNotUnpublished: a commit main already holds, or one not on the branch; a second drop of the same commit gives this); 422 merge_commit (ErrDropMerge: the target is itself a merge; dropping it would be a silent no-op, so it is refused; drop the commit that wrote the content); 409 foreign_commit (DropForeignError, fleet only, ownOnly=true: unfolding a merge would re-sign ANOTHER agent's commit, and the fleet judge refuses a re-signed foreign commit, so the drop is refused rather than made lossy; the text asks that agent to fix its branch). On a plain knowledge base (ownOnly=false) the commits are re-signed and kept.

THE CONFIRMED FALLBACK. merge_commit and foreign_commit carry `leave_out` (commit, agent, author, subject of every commit that leaving the whole merge out loses) in the problem body, because a member that has left (its branch is demoted, a fix would never be merged) or is gone for good cannot act on 'ask it to fix'. POST {commit, leave_out_merge: true, left_out: [hashes]} runs store.DropUnpublishedCommitLeavingOutMerges, Manager.LeaveOutFleetMerge: it leaves out WHOLE the dropped commit and every first-parent merge whose other parents reach it, with everything their sides brought, unfolding nothing, so nothing is re-signed for another agent. `left_out` must be EXACTLY the hashes shown: an empty list is 422 leave_out_unconfirmed; a list that no longer matches the plan is 409 leave_out_changed carrying the new list and changes nothing. The UI shows the list first ('These N commits are then lost from this instance's branch and never reach main; every other commit not yet on main is kept') and sends the fallback only from the button 'Leave out the merge and these N commits' (outcome '✓ Left the merge out (N commits). Main moved on.').

MISREADINGS. (1) 'Drop keeps the merges': members' merges are replayed as merges, but a merge that carried the dropped commit is unfolded, or left out whole in the fallback. (2) 'Drop loses only the named commit': true of a plain drop; only the confirmed fallback loses more, and only what it listed. (3) 'Drop lets an operator rewrite any history': it removes UNPUBLISHED commits only; it can drop any unpublished commit, not only the held one. (4) 'Retrying fixes a held main': no, the same commit is refused every tick. (5) The held-main notice and Drop are for the master's own refusal; a MEMBER's refused commit has the different 'commit refused' notice (leave, have the master enroll again, rejoin).

CAVEATS. A drop that publishes while a member was revoked meanwhile re-judges that member's branch at the merger, which can demote it (kb/invariants/fleet/fetch-judge/88eb5593.md); merges are replayed with their same parents so the work already merged is kept. The leave-out e2e (TestFleetDrop_ALeftMembersTwoCommitsCanBeLeftOutWholeOnceConfirmed) makes the master's merge directly on the master's copy, bypassing the fetch judge, because no real path admits a member commit that the publish judge then refuses (that is what #533 enforces); everything after the refusal runs the real code.

# GET /api/v1/fleet/members rows are member records plus DERIVED `enrolled` rows (a leaf on main, no record; `revoked` when the CRL lists it), each with `since` (the first-parent commit that brought its current blob, absent beyond 2000 commits); an enrolled row carries last_refusal by the refused tip's author

Built in PR #527 (verified at merge commit c6e282db).

ROWS: every member record at the fleet repository's main (state `revoked` when the same revision's CRL lists its leaf: deriveRevoked), then every agent id that has a leaf file on main and NO record: state `enrolled` (never written to any record), or `revoked` when the CRL lists the leaf; its path is the leaf's. The enrolled id is the master's enroll that has not joined yet, or whose join is not merged.

SINCE: store.FleetSince walks main's first-parent chain, at most maxFleetWalk = 2000 commits, and reports for each row path the committer time of the oldest commit from which that path's blob is the tip's, i.e. when the CURRENT version landed on main. A path whose current version is older than the walk, or that the tip does not hold, has no `since` (absent, not zero).

LAST_REFUSAL (web fleetMemberRows): a record row carries the master's last refusal of the branch its record names (`branch`). An enrolled row has no record and so no branch: it carries the NEWEST refusal whose refused tip's author (PeerRefusal.Agent, the commit's author address) is that id; nothing is parsed out of a branch name. This is how a first join refused in flight appears. KNOWN GAP (F2, queued for PR7b): that agent is the tip's CLAIMED author, so a refused tip authored as another enrolled-but-unjoined id shows on that id's row; display only. The gap reads false once the refusal is hung on an enrolled row only when the tip's signer is that id's key.

MISREADINGS. (1) "every row is a record": enrolled rows have no record, no branch and empty addresses. (2) "FleetStatus.record_state sees enrolled": it does not. (3) "`enrolled` is certain proof the leaf was issued by this master's log": rows come from leaves on MAIN; the Activity `enrolled` event comes from issued.jsonl, which also holds issuances that never reached main.

UPDATE (PR #532, squash commit a1b0ca5d on dev, verified there): a record row for a `left` member carries `revoke_due: true` (FleetMemberRow.RevokeDue; the key is OMITTED when false) exactly when leftLeafDue holds for it on the viewing instance's copy of main: main has the PKI and a CRL, state left as written, leaf_serial non-empty, main's current leaf for the id has that serial, the CRL does not list it (kb/invariants/fleet/leave/master-revokes-left/d2132d6b.md). The web left-row subline says 'the master revokes its certificate once it runs its round' only when revoke_due is set, else 'certificate valid until revoked'. MISREADING: 'revoke_due means THIS instance will revoke it': the row is computed on any instance, member or master; whether this instance runs the duty is GET /fleet revokes_left. The history paths stay as above; store.FleetLandedDepth was added in an earlier build of #532 and does not exist at the merge (fleet_history.go is dev's version).

UPDATE (PR #578, E6, merged into dev as 7a721802; re-read there): repos.FleetMemberRow now embeds fleetrec.Member (it embedded store.FleetMember before the fleetrec seam was deleted), so the embedded field is named Member instead of FleetMember; Go code that wrote row.FleetMember or FleetMemberRow{FleetMember: ...} now writes row.Member / FleetMemberRow{Member: ...} (internal/web/handlers_fleet.go reads mem.Member.Member). The route's JSON is unchanged: it is built field by field in fleetMemberRow (internal/web/handlers_fleet.go), and the #578 review verified the output byte-identical. The row's Since is still filled by Service.FleetSince, whose body is fleetrec.Since (fleetrec/log.go) with maxFleetWalk = 2000 (internal/repos/fleet.go); the store/fleet_history.go ref at c6e282db is HISTORICAL (the file no longer exists) and was replaced by fleetrec/log.go. MISREADING: the rename does not change the wire format or any claim above about rows, since, last_refusal or revoke_due.

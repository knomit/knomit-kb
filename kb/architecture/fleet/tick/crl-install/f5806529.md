# Every copy of the fleet repository, master or member, installs main's CRL into [tls].dir in its own sync round when main's Number is above the one it accepted for the installed root (fleet_tick.go, the P6 duty): a member's mTLS listener refuses a revoked peer only once ITS round has run

WHAT (fleet PR8, PR #536, merge commit 67e19eb3). `RepoInstance.fleetTickRound` runs:
- in the forge origin round (`runReconcileLoop`) right after every SUCCESSFUL fetch, through `fleetPeers.tick` / `runTick`, for master and member alike, BEFORE the master's admit and duties;
- in the hub's local round, at the top of `fleetHostRound`, before it TryLocks fleetOpMu (the tick takes no fleetOpMu).
`Manager.installMainCRL(svc)` reads `svc.FleetAt(main)`; it installs nothing when [tls].dir holds no root, when main has no PKI or no usable CRL, when main's root is not the INSTALLED root (logged at warn: a CRL never moves an instance to another fleet), or when main's Number is not above `pki.AcceptedNumber` for that root. Otherwise `pki.InstallCRL(dir, mainRoot, PEM of main's CRL)`; an ErrCRLRollback there (a revoke on this instance took the Number meanwhile) is nothing to do. The running mTLS listener adopts the new crl.pem at its next handshake or tick.

CONSEQUENCES.
- After a revoke the hub refuses the revoked peer at once (the revoke installs the CRL there), but every OTHER member keeps admitting it to ITS listener until that member's own next round (sync interval, 300 s by default). Proven end to end over real listeners: cmd TestFleetTick_KnomitHostedMemberRefusesTheRevokedPeerAfterItsRound.
- A member whose fetch fails (a hub member refused at the handshake after its own revocation) never runs the tick, so it never installs the CRL that revokes it.
- A forge member that was revoked still fetches main, so its round installs the CRL listing its own serial (TestFleetTick_AMemberInstallsMainsNewerCRLInItsRound).
- test/archtest installCRLCallers lists internal/repos/fleet_tick.go beside fleet_membership.go.

MISREADING. "Members install the CRL when the master revokes": nothing is pushed to members; each pulls main on its own interval.

UPDATE (#536 review nits, head 53a381a1): with NOTHING installed the tick returns at once and logs nothing (it used to warn "another root" every round; TestFleetTick_NothingInstalledLogsNothing). Because the tick runs outside fleetOpMu, it can install main's copy of a CRL a revoke just committed before the revoke's own install: the revoke now goes through `installSignedCRL`, which treats ErrCRLRollback on an EQUAL accepted Number as success, so no spurious `install_error` (TestInstallSignedCRL_AnEqualNumberIsSuccess). An older Number is still an error.

# A fleet member whose certificate is revoked stops its fleet repository's origin rounds (no fetch, no push) while that certificate is installed; the stop lives in memory only, so a restart retries once; a leave and a join with a new certificate run them again

WHAT (fleet PR8, PR #536, merge commit 67e19eb3).
- `Manager.noteFleetRevoked(lastErr)` stores the installed certificate's serial in `fleetHaltSerial` when `fleetRevokedHere` says revoked (installed CRL lists it, or lastErr classifies revoked; never a root holder). Called from `fleetPushed` (every recorded push outcome), from `fleetFetchRefused` and from the tick after it installs a CRL.
- `fleetSyncHalt` (fleetPeers.halt) answers a reason while that serial is still the INSTALLED certificate's; `runReconcileLoop`'s doTick returns right after the local-origin policy check: no breaker step, no request, no status row.
- A FETCH refused at the handshake (errors.Is ErrRefusedByPeer or ErrUntrustedRoot) is recorded as the fleet's last attempt (recordFleetAttempt) by `fleetFetchRefused`, and the round then pushes NOTHING.

WHY THE FETCH IS RECORDED AND THE PUSH SKIPPED. Before PR8 only push outcomes reached the fleet row. `store.Push` returns success WITHOUT dialing when the agent branch equals origin/<branch> (nothing new), so a hub member refused at the handshake with nothing to push recorded nil and cleared last_error every round: last_error_refused almost never showed. Proven by cmd TestFleetRefusal_KnomitHostedRevokedAndMoved.

CONSEQUENCES.
- GET /fleet sync_stopped says the rounds stopped; revoked and last_error_refusal stay derived from the persisted last_error and the installed files, so they survive a restart even though the stop does not.
- The way back is Leave (works offline) then the master's enroll of the same key and a join: the new certificate's serial differs, so the rounds run (TestFleetRefusal_ARevokedForgeMemberStopsItsRounds).
- A forge member learns its revocation from main's CRL in its own round (the tick installs it) and stops from the next round.

MISREADING. "sync_stopped is persisted": it is not; a restart attempts one round, which fails and stops again.

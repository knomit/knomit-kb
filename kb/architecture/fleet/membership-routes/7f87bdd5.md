# The fleet membership routes (PR #525, merge fd991d4f): POST /api/v1/fleet/enroll | join | leave | revoke | decommission and GET | PUT | DELETE /api/v1/fleet/root are ALL served on the local listener only and ALL hold fleetOpMu; GET /fleet and /fleet/members stay open to any admitted principal; PUT /fleet, DELETE /fleet and the identity/fleet CLI verbs are gone

WHAT. One `r.Group` with `r.Use(RequireLocalVia)` in internal/web/router.go holds create (PR #518) and the routes below; each handler calls a Manager method that takes `lockFleetOp` (fleetOpMu) first. RequireLocalVia admits the unix socket / Windows named pipe only: an mTLS peer and a browser page on loopback TCP get 403 and the handler does not run.

ROUTES (request -> success answer; the master-only ones answer 409 `not_registered` on a standalone instance and 409 `not_master` when this instance is not the fleet's master, i.e. the root key file here is absent or its root.crt is not the root on main):
- POST /fleet/enroll {agent_id, public_key} (master) -> 201 {agent_id, serial, bundle, root_fingerprint, published, publish_error}. The bundle is exactly three PEM blocks: the new leaf, the root certificate and the CRL read from MAIN. Rules and refusals: the enroll invariant (ENROLL_PATH).
- POST /fleet/join {url, auth_method, auth_token, bundle} -> 200 FleetStatus + root_fingerprint, state registered. All or nothing: JOIN_PATH.
- POST /fleet/leave -> 200 FleetStatus + pushed + push_error. Member only (the master gets 409 `is_master`): LEAVE_PATH.
- POST /fleet/revoke {agent_id, reason} (master) -> 200 {agent_id, serial, crl_number, published, publish_error, install_error}: REVOKE_PATH.
- POST /fleet/decommission (master) -> 200 FleetStatus. Drops the fleet repository from every lens that reads it, deletes the repository (a forge keeps its copy, inert), runs pki.Uninstall, deletes `<home>/fleet` WITH the root key, sets the state standalone. Members' syncs then fail and each leaves (leave works offline).
- GET | PUT | DELETE /fleet/root (the master switch): ROOT_PATH.

READS (any admitted principal): GET /fleet gained `master` (this instance is the master), `hosting` (`none` = the copy has no origin, so this instance is the hub; otherwise the origin's URL; empty with no fleet repository mounted) and `root_dir` (`<home>/fleet`, where the root key lives on the master and where a switch copies it). GET /fleet/members is unchanged from #524 (`last_refusal`).

REMOVED in the same PR: `PUT /fleet` and `DELETE /fleet` (and `Manager.RegisterFleet`, `UnregisterFleet`, `registerOwnRecord`, the `unregistering` state), the CLI verbs `knomit fleet register|unregister` and `knomit identity init-root|enroll|install|revoke|root-fingerprint` (the CLI keeps `knomit fleet status` and `knomit identity show`), the Fleet page's Join and Leave blocks (a browser gets 403 from these routes; the page shows state and members until PR 7). openapi declares every route, its codes and 'LOCAL LISTENER ONLY'.

CONSEQUENCES. A new mutating fleet route goes INSIDE that group and into TestFleetMembership_EveryOperationIsLocalOnly. A remote operator cannot call these routes; they need a shell on the machine (issue #521 would add a second factor). The desktop's InstallBundle binding and its archtest entry stay until PR 7.

MISREADINGS. 'Local-only means any local process may call it safely': GET /fleet/root returns the root key. 'The routes are mounted next to GET /fleet so they share its access': they do not; the group is the gate.

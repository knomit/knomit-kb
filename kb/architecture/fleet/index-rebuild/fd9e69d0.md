# POST /fleet/index-rebuild rebuilds the fleet repository's agent-branch index (local-only, under fleetOpMu, no DELETE) and its `_links.job` resolves through the generic job route, which falls back to the repo's TaskHub for a lifecycle rebuild

Verified at the merge of PR #529 (60ddfb1c); user ruling 2026-10-16: index rebuild belongs in /fleet. The generic POST /repos/{repo}/branches/{b}/index-rebuilds is 409 fleet_repository like every generic mutation (the gate), so the Fleet page's Settings -> Index -> Rebuild calls POST /fleet/index-rebuild (RequireLocalVia group, defer lockFleetOp). It sends the lifecycle event Rebuild on the fleet repository's agent branch (the branch the generic Rebuild names) and answers 201 {id, repo, branch, absorbed}; absorbed means an identical rebuild already ran and this is it. There is no DELETE: the generic UI never cancels a rebuild.

THE JOB LINK: the answer's `_links.job` is the generic GET .../index-rebuilds/{id}. The lifecycle machine records its rebuilds in the repo's TaskHub, not in the REST JobRegistry, so handleGetJob falls back: a job the registry lacks is read through hubJob from ri.TaskHub() (op `rebuild` for index-rebuild, `synth` for synthesis-run), state = the task status, error = its message. The hub holds a running task and its last terminal one, so an OLDER job id is 404. This fallback serves every repository, not only the fleet. Before the fix (review S1) the link 404'd.

INDEXING REFUSALS: a fleet operation refused because the repository is indexing answers 409 `indexing` naming the Fleet page, with no link (the generic /repos//index:cancel link was broken for the fleet and is gone; index:cancel is not reachable for the fleet at all: indexing ends on its own).

TESTS. TestFleetREST_IndexRebuild (local-only: TCP is 403; agent branch; the job link is GET-ed and resolves; the generic route still 409), TestFleetError_IndexingNamesTheFleetPageAndNoLink.

MISREADINGS. 'The generic job route only reads the JobRegistry': no. 'A rebuild job id stays readable forever': only the running or last terminal task.

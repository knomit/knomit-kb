# The fleet host record (artifacts/fleet/host on the fleet repository's main) says where the fleet is hosted: only the master writes it (create, detach, and the hub's every local-reconcile round), it never carries userinfo, and readers get it as GET /fleet fleet_urls and host_record

Built in PR #527 (verified at merge commit c6e282db).

FORMAT: fact.RenderFleetHost: the header line `# knomit fleet host v1`, then one `url: <URL>` line per fleet repository URL, in order. fact.ParseFleetHost rejects anything else (a record a reader cannot read says nothing about the host). The ontology declares the path `fleet/host` with max_size 4KiB.

WRITERS (all through Manager.writeFleetHost, master only, under fleetOpMu): (1) foundFleet at create: the hub's URLs (hubFleetURLs) or, with an origin, the origin URL; (2) DetachRepoOrigin on the master (the detach makes its copy the hub): write, then publishFleetMainNow; (3) fleetHostRound, the hub's duty in EVERY round of its local reconcile (below). Nothing else writes it; PUT origin does not. writeFleetHost commits nothing when the branch already holds exactly the wanted record.

HUB URLS: hubFleetURLs = https://<address>/git/<repo> for each of the hub's external_addresses that starts with https:// (case-insensitive); other addresses are left out, because members reach the hub's mTLS listener over https only.

NO USERINFO: every URL is written through credentialFree (user, password, token stripped; a string without `://`, such as scp-style git@host:path, is returned as is), and so is the commit message: the record is on main, replicated to every member, forever. KNOWN GAP (F3, queued for PR7b): this covers the HOST RECORD and GET /fleet only. The bundle `url:` line and the enroll answer's `fleet_url` (fleetURLForBundle) copy the origin URL verbatim, so while a forge origin URL embeds a token, every joiner's bundle carries it. This gap is closed once fleetURLForBundle strips userinfo.

SELF-HEALING (fleetHostRound): it runs inside the advance closure of runLocalReconcileLoop, before main follows the agent branch, so only a copy with NO origin runs it (the hub), only on the fleet repository behind the fleet door, and only when isFleetMaster. It costs one read when the record is current, repairs a detach whose record write failed, and follows a change of external_addresses. It takes fleetOpMu with TryLock ONLY (never waits, unlike lockFleetOp): a create or detach holds the lock while its Sync stage runs this very loop inline under Synchronous, so a blocking Lock would deadlock; a skipped round is written by the next one (default local_reconcile_interval 30 s, and on every commit wake). With local_reconcile_interval 0 there is no loop and so no self-heal.

A FAILED WRITE AFTER A DETACH does not fail the detach: DetachRepoOrigin logs a WARN and answers done (the detach stood), and the next round writes the record. A failed fast-forward of main is only logged too.

READERS: GET /fleet (see the GET /fleet fact). Activity's host-changed events read the record's commits on main.

MISREADINGS. (1) "Only create and detach write the record": the hub's local reconcile re-asserts it every round, so a hand edit of the master's copy is overwritten. (2) "The record is the origin the copy syncs from": a copy's origin and the host record can differ; GET /fleet's follows_host compares them. (3) "The page must strip userinfo from the record": it is stripped at write time.

# The fleet host record (artifacts/fleet/host on the fleet repository's main) says where the fleet is hosted: only the master writes it (create, POST /fleet/host, the hub's every local-reconcile round, and the master's move onto a forge), it never carries userinfo, and readers get it as GET /fleet fleet_urls and host_record

Built in PR #527 (verified at merge commit c6e282db).

FORMAT: fact.RenderFleetHost: the header line `# knomit fleet host v1`, then one `url: <URL>` line per fleet repository URL, in order. fact.ParseFleetHost rejects anything else (a record a reader cannot read says nothing about the host). The ontology declares the path `fleet/host` with max_size 4KiB.

WRITERS (all through Manager.writeFleetHost, master only, under fleetOpMu): (1) foundFleet at create: the hub's URLs (hubFleetURLs) or, with an origin, the origin URL; (2) Manager.HostFleetHere on the master (POST /fleet/host, "Host the fleet here"; PR #528 moved it from Manager.DetachRepoOrigin, which no longer exists; the detach makes its copy the hub): write, then publishFleetMainNow; (3) fleetHostRound, the hub's duty in EVERY round of its local reconcile (below). Nothing else writes it; PUT origin does not. UPDATE (PR #529, verified at merge 60ddfb1c): a FOURTH writer, (4) the master's move onto a forge (moveFleetToForge, POST /fleet/follow with a different forge URL), writes the record as the forge URL (credential-free) after the attach and before pushFleet; a failed write there restores the previous origin. writeFleetHost commits nothing when the branch already holds exactly the wanted record.

HUB URLS: hubFleetURLs = https://<address>/git/<repo> for each of the hub's external_addresses that starts with https:// (case-insensitive); other addresses are left out, because members reach the hub's mTLS listener over https only.

NO USERINFO: every URL is written through credentialFree (user, password, token stripped; a string without `://`, such as scp-style git@host:path, is returned as is), and so is the commit message: the record is on main, replicated to every member, forever. F3 (closed by PR #527/#528, verified at merge e417fd76): the bundle `url:` line, the enroll answer's `fleet_url` (fleetURLForBundle), refusal texts and Activity host-changed events are credential-free too. credentialFree also strips `scheme://...@` by regex when url.Parse fails (a malformed URL loses its userinfo too) and KEEPS an ssh:// user (TestCredentialFree).

SELF-HEALING (fleetHostRound): it runs inside the advance closure of runLocalReconcileLoop, before main follows the agent branch, so only a copy with NO origin runs it (the hub), only on the fleet repository behind the fleet door, and only when isFleetMaster. It costs one read when the record is current, repairs a detach whose record write failed, and follows a change of external_addresses. It takes fleetOpMu with TryLock ONLY (never waits, unlike lockFleetOp): a create or detach holds the lock while its Sync stage runs this very loop inline under Synchronous, so a blocking Lock would deadlock; a skipped round is written by the next one (default local_reconcile_interval 30 s, and on every commit wake). With local_reconcile_interval 0 there is no loop and so no self-heal.

A FAILED WRITE AFTER A DETACH does not fail the detach: HostFleetHere logs a WARN and answers done (the detach stood), and the next round writes the record. A failed fast-forward of main is only logged too.

READERS: GET /fleet (see the GET /fleet fact). Activity's host-changed events read the record's commits on main.

MISREADINGS. (1) "Only create and host-here write the record": the hub's local reconcile re-asserts it every round, so a hand edit of the master's copy is overwritten. (2) "The record is the origin the copy syncs from": a copy's origin and the host record can differ; GET /fleet's follows_host compares them. (3) "The page must strip userinfo from the record": it is stripped at write time.

UPDATE (PR #529, verified at merge 60ddfb1c): fleetHostRound still runs only on a copy with NO origin, so a master that moved onto a forge is not self-healed. A move interrupted after the attach is stored and before the record is written persists (the record names the old host, the copy syncs from the forge); GET /fleet reports it as `interrupted_move` and the Fleet page offers Host here or Move back (kb/architecture/fleet/move/interrupted-move/e9c7d31c.md). MISREADING: 'only the hub's round and Host here repair the record': a MOVE writes it too, but nothing retries a move. A credential change and a member's follow never write it.

UPDATE (branch fix/fleet-switch-replay, verified at a78d1b22; re-pin at the merge commit): fleetHostRound now asks actsAsFleetMaster (isFleetMaster and no fleetMasterPause), and in the same round claims the master marker once for a fleet that has none (fleetCandidate then claimFleetMaster at the merge, there is no claimFleetMasterOnce; kb/invariants/fleet/master-marker/13dcd692.md). A hub whose master stood down writes no record (no root key). The host record itself is unchanged by a stand-down: the URLs still say where main is served until the new master hosts. The judge's host-record rule now guards artifacts/fleet/master too.

VERIFIED AT THE MERGE (PR #531, squash commit 8ca72760 on dev, 2026-10-16): fleetHostRound (fleet_host.go) TryLocks fleetOpMu, claims the master marker via claimFleetMaster when fleetCandidate holds (root held, main names no master, copy not following another instance), then returns unless actsAsFleetMaster, and only then re-asserts the host record. The name claimFleetMasterOnce used in an earlier paragraph above does not exist.

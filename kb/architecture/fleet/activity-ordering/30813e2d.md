# Activity events are sorted by full timestamp, then kind rank, then agent, serial, branch, tip and detail, never by source order; mixed precision (commit times are whole seconds) can still invert two events inside one second

Built in PR #527 (N4; verified at merge commit c6e282db). sortFleetEvents orders newest first by the full At, then, at EXACTLY equal instants, by fleetKindOrder (later lifecycle step first: left, revoked, refused, host-changed, admitted, joined, enrolled, created), then agent, serial, branch, tip, detail. The result no longer depends on the order the sources were read in (TestSortFleetEvents_SameSecondIsNotSourceOrder).

KNOWN GAP (F4, queued for PR7b): the sources disagree in precision. A commit's time is whole seconds (main's history), while issued.jsonl, the CRL and the refusal ring keep sub-second times. A `joined` that really landed at :00.9 is stored as :00.0 and sorts BELOW a `revoked` at :00.3; the kind rank applies only to exactly equal instants. This reads false once every source is truncated to seconds before the comparison.

CONSEQUENCE: do not read the order of two events less than a second apart as causal order.

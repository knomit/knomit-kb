# The master's fetch adds the agent/* refspec PER FETCH (not in git config), and its strict fetch prunes tracking refs within that wildcard; a member's clone and round fetch only main and its own branch — branch visibility is behaviour, not an access control

WHAT (PR #524, verified at merge commit 9db8c106, go-git v5.19.2 per go.mod).

1. The refspec is per fetch. The configured refspecs (main and the own branch, written by configureRemote) are NOT changed. The master's SyncWithPeers passes `+refs/heads/agent/*:refs/remotes/origin/agent/*` (peerRefspec) as an extra to fetchOrigin for THAT fetch only, in both the strict and the fallback attempt. A wildcard refspec never fails to match, so it cannot trigger the fallback. Consequence: copying the root key into or out of an instance changes its fetch from the next round with no restart, and members' configs are untouched. The fetched tips are read with RemoteIndex.PeerTips (refs/remotes/origin/agent/*, except the own branch).
2. Prune (N1). With an extra refspec, the strict attempt sets Prune: true, so a member branch deleted on the forge disappears from the master's tracking refs (and the master forgets its refusal). The prune stays within the wildcard because go-git's Remote.fetch runs calculateRefs, which fails the strict attempt with NoMatchingRefSpecError before pruneRemotes whenever an exact configured refspec does not match the origin; so the own branch's tracking ref (RetractPushedBranch's lease, kb/architecture/store/remote-sync/retract-pushed-branch/f0a4ba36.md) is never pruned. The fallback attempt (own branch absent on the origin) does not prune. Pinned by TestFleetMaster_ABranchDeletedOnTheForgeIsForgotten. This rests on go-git v5.19.2 internals (calculateRefs before pruneRemotes, pruneRemotes matching through spec.Reverse()); re-verify on a go-git upgrade. Line numbers are dated support only.
3. Members fetch only main and their own branch. A fleet-door create (repos.fleetCloneOptions, for clone and initialize) passes store.OwnBranchesOnly() to InitFromRemote: one ls-remote, then one exact refspec per non-agent branch plus the instance's own agent branch if present; never the wildcard. A later member round fetches the two configured refspecs only. So a member holds no other agent's objects, unless its home was cloned BEFORE #524 (it still holds them; harmless to main because receive-pack's walk no longer trusts 'held'). Pinned by TestFleetMember_CloneHoldsNoOtherAgentsBranch. A ref deleted on the forge between the listing and the fetch fails that clone (exact refspec): retry.

MISREADING: 'a member cannot see other agents' branches' is FALSE as an access statement. This is behaviour, not an ACL: the forge serves every branch to anyone it lets read, and a member could fetch them by hand. Do not rely on it for confidentiality.

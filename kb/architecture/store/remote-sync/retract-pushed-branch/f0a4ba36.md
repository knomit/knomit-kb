# RetractPushedBranch deletes an agent branch on the origin under a lease on the REMOTE-TRACKING REF, which is the last tip this instance SAW (pushed or fetched), not the hash it pushed; it then removes the origin remote so no later push recreates the branch

PR #518 (merge 537f2019), internal/store/remote_sync.go, declared on the RemoteIndex interface next to PublishUpstream. It exists for a repository that is about to be deleted: the rollback of a fleet create that pushed its agent branch to a forge (mode initialize pushes agent/<id> with the ontology commit).

STEPS, all under the branch's push lock (lockPush, the one every Push takes): (1) no origin remote configured -> return nil (a re-run after the removal lands here). (2) Read pushed = refs/remotes/origin/<branch>. (3) List the origin's refs. (4) Decide: branch absent on the origin -> nothing to delete; present but there is NO tracking ref -> error 'this instance never pushed it: left alone'; present at a hash other than the tracking ref -> error naming both hashes, 'left alone', origin remote KEPT so the caller can retry; present at the tracking ref's hash -> push the delete refspec :refs/heads/<branch> with RequireRemoteRefs <hash>:refs/heads/<branch> (the origin applies the advertised old value as a compare-and-swap; see kb/gotchas/store/go-git/delete-ignores-force-with-lease). (5) Remove the tracking ref and DeleteRemote("origin"), so the reconcile loop's next Push (which skips a repository with no origin remote) cannot recreate the branch between the delete and deleteRepo.

THE LEASE IS NOT 'THE HASH IT PUSHED' (review follow-up R1). The lease value is refs/remotes/origin/<branch>. A successful Push sets that ref to the hash it pushed, BUT so does every fetch: configureRemote's fetch refspecs include +refs/heads/<agent>:refs/remotes/origin/<agent>. So the lease is the last tip this instance saw there, pushed or fetched. A foreign tip that this instance had already fetched IS deleted, not left alone. That is harmless for a fleet create (the loop force-pushes this instance's own agent branch anyway, and the branch belongs to this instance), and it is the wording to keep: the interface comment and the file comment at 537f2019 still say 'the hash this instance last pushed'. MISREADING: do not reuse RetractPushedBranch where a second writer on the branch must be protected from deletion; it protects only against a tip this instance has NOT seen.

SELF-HEALING. If the rollback stops after the remote is removed, the next mount recreates the origin remote from control.db (the git remote is a derived cache rewritten at every open), and the next recover retracts again.

TESTS: TestRetractPushedBranch_DeletesWhatThisInstancePushed (branch gone, tracking ref gone, the next Push sends nothing, a re-run is a no-op; sabotage: drop DeleteRemote -> red), _LeavesAForeignTipAlone, _NeverPushedIsLeftAlone, and at the repos level TestCreateFleet_ForgeFailureRetractsThePushedBranch (a retry on the same forge succeeds).

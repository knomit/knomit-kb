# Domain filtering = slash-hierarchy OR canonical token containment (de-hyphenized, stemmed, order-independent)

PR #70 added pure-SQL (no FTS5, no embeddings) domain-tag matching in internal/store/domain_match.go + the search_query.go factFilter.

CANONICALIZATION (canonicalizeDomain): NFC -> Unicode case-fold (cases.Fold, language-neutral) -> replace hyphens AND Unicode whitespace with a single space -> trim. Underscores are PRESERVED (so commit_log stays one token). Pure + idempotent. Applied to BOTH stored tags (at index time) and query terms (at search time) so they collapse to the same form.

TOKENS (domainTokens): split the canonical form on whitespace AND '/' (so 'multi-tenant/auth' -> [multi, tenant, auth] and each hierarchy segment is reachable as a word), then stem each token via stemDomainToken (see the go-pluralize decision fact), dedup preserving first-appearance order. Stored in fact_domain_tokens(fact_id, domain, token) — one row per (fact, canonical domain, token), KEPT PER-DOMAIN (not flattened per-fact) so a multi-token query is satisfied WITHIN a single domain, never bleeding tokens across two different domains on the same fact.

MATCH SEMANTICS (SearchOptions.Domain, default): a fact matches if EITHER (a) slash-hierarchy descendant-or-equal on raw fact_domains (domain = ? OR domain LIKE ?||'/%'), OR (b) token containment — EXISTS over fact_domain_tokens with t.token IN (...) GROUP BY t.domain HAVING COUNT(DISTINCT t.token) = <#querytokens>. So 'ai' matches 'ai governance'; 'governance ai' matches 'ai governance' (order-independent); plurals stem. SearchOptions.DomainExact=true opts OUT of both, doing canonical string equality only. SearchOptions.DomainAncestor (applies_to / principles scoping) stays slash-based, NOT tokenised, but its query term is now canonicalised too.

GOTCHA — empty-canonical no-op: a degenerate term ('-', '---', whitespace) canonicalises to '' and is SKIPPED entirely, never emitting `domain = ''` (which would silently match zero facts and zero the whole query). Same guard exists on domain autocomplete: a non-empty prefix that canonicalises away returns NO completions (not LIKE '%' = everything); empty input still lists all. repopulateDomainTokens rebuilds the table for EVERY fact version (HEAD + historical) from immutable facts.domain JSON during Rebuild phase 1; raw fact_domains rows are left immutable.

# facts.Repo.SettlementsSince(branch, since) is the ONE walk over the commits not reachable from the review watermark: it returns Knomit-Outcome verdicts (latest wins) and, per deleted path, what the deleting non-merge commit wrote

WHAT IT IS (internal/engine/store/facts/outcomes.go, #648 merge 2782d21c). `SettlementsSince(ctx, branch, since)` walks, once, the commits on branch that are not reachable from `since` (the review watermark; an empty string means the whole history) and returns Settlements{Outcomes, Written}. Outcomes maps a hypothesis path to the verdict of a Knomit-Outcome trailer (latest commit wins). Written maps a deleted path to the fact paths that the commit which deleted it added or modified (latest deleting commit wins). It replaced two earlier exports from this PR's first revisions (OutcomesSince and DeletionPeers, which no longer exist); there is no walk-limit constant.

MERGE COMMITS ARE SKIPPED for Written, because a merge's first-parent diff is the whole merged branch. The merged branch's own commits are walked instead (WalkHistory visits parents before children, so a later commit overwrites an earlier one). Consequence: after an experiment's non-fast-forward commit, Written[hyp] is exactly the settling fact, not the whole experiment diff (pinned by a store-level CommitExperiment test). Delete, re-create, delete gives the LATEST deleter's writes.

TWO CONSUMERS, ONE RANGE. (1) findHypothesisTransitions reads Outcomes to report a deleted hypothesis as confirmed, refuted or (no trailer) retracted. (2) ApplyReflectDecisions reads Written to find the live facts written with a deleted transition's deletion; it calls SettlementsSince at most once per call, however many transitions were deleted, and only reinforces Written peers whose refs actually cite the deleted path. Both use the watermark the review session started from: it is advanced only by completeSession, after reflect, so reflect sees the range findHypothesisTransitions listed.

FAILURE HANDLING. ApplyReflectDecisions returns a failed watermark read; it does not fall back to `since == ""` (a whole-history walk with a DiffTree per commit). In production `since == ""` effectively never reaches it, because findHypothesisTransitions returns nothing without a watermark. The transitions report degrades to 'retracted' with a log warning if the outcomes read fails.

WHAT THIS DOES NOT MEAN. It is not a general commit-log API: it exists so verdicts and deleting-commit writes come from one range. A deletion authored only inside a merge commit would be missed; knomit cannot produce one (a merge resolution only picks a side or supplies a body), so the worst case is one warn-and-skip.

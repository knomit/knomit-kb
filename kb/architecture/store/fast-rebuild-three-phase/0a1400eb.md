# Index rebuild is THREE phases, each in a single transaction; uses custom SQL function + batched ONNX

Rebuild Index is split into three phases, EACH wrapped in a single transaction (eliminates per-op fsync overhead, which was the main bottleneck — ~3000 individual fsyncs in phase 3 alone). PHASE 1 (facts INSERT): register a custom Go SQL function knomit_parse_fact(blob BLOB) → JSON via mattn/go-sqlite3 ConnectHook (registered as deterministic), populate a TEMP table from go-git tree walk, then ONE bulk INSERT with CTE: knomit_parse_fact(o.data) + json_extract(...) into facts. PHASE 2 (embeddings): batched ONNX inference — collect texts in batches of 32, single ONNX call per batch, bulk INSERT into facts_vec. 234 facts ÷ 32 = 8 ONNX calls instead of 234. PHASE 3 (graph): cursor over facts — graphSyncFactTx for each, then graphBuildSimilarityEdgesTx for similarity edges; all in one tx. Existing graphSyncFactTx already accepts an execer interface, so passing tx (not idx.db) works. Target: 56s → ~8s (~7x). Custom SQL function is registered via sql.Register('sqlite3_knomit', ConnectHook) — same driver name everywhere ensures all connections see the function.

# Index rebuild is THREE phases, each in a single transaction; uses custom SQL function + batched ONNX

Rebuild Index is split into three phases, EACH wrapped in a single transaction (eliminates per-op fsync overhead — ~3000 individual fsyncs in phase 3 alone). PHASE 1 (rebuildFacts): the WHOLE phase runs in ONE transaction via beginTxIfNeeded. Mechanics: register knomit_parse_fact(blob BLOB)->JSON via ConnectHook (deterministic), populate a TEMP table from the go-git tree walk, then ONE bulk upsert with a CTE. CRITICAL: the facts upsert is INSERT ... ON CONFLICT(path, blob_hash) DO UPDATE — NOT INSERT OR REPLACE. facts are content-addressed by UNIQUE(path, blob_hash); ON CONFLICT refreshes parsed columns IN PLACE so the rowid is PRESERVED for unchanged blobs. This is load-bearing: INSERT OR REPLACE does DELETE+INSERT, minting a new rowid and firing facts_after_delete (which wipes the facts_vec row), so rebuildEmbeddings (phase 2 — 'WHERE rowid NOT IN (SELECT rowid FROM facts_vec)') would re-embed the ENTIRE corpus on every rebuild. Preserving rowids keeps embeddings (immutable per blob) and re-embeds only genuinely new/changed facts. Phase 1 explicitly clears the rebuilt facts' fact_domains/fact_entities rows (scoped by _rebuild_entries, NOT a global wipe) before repopulating canonical/token derived state.

PHASE 2 (embeddings): ONNX inference runs OUTSIDE any transaction (batcher.EmbedDocuments, 32 per batch) into an in-memory slice; the finished vectors are then written in a SHORT tx. This is load-bearing for concurrency (PR #82): earlier the tx WRAPPED the inference, holding the SQLite single-writer lock (BEGIN IMMEDIATE under _txlock=immediate) for the full inference duration — tens of seconds — which starved concurrent louvain()/reconcile/im.Sync writes and produced the slow-Louvain / 'database is locked' storms during connect/rebuild. searchIndex.rebuilding (atomic.Bool) is set across Rebuild so CachedClusterFacts serves cached/empty instead of contending.

PHASE 3 (graph): cursor over facts, single tx, then bump meta.graph_schema_version. Custom SQL function registered via sql.Register('sqlite3_knomit', ConnectHook) — same driver name everywhere. Progress is reported once per embeddings batch via RebuildProgress(phase, done, total).

# store/gitserve holds the smart-HTTP handler (upload-pack and receive-pack) over a host{*vcs.Repo, *remotesync.Repo}; callers import gitserve for PushPolicy and WithPushPolicy (gitserve_seam.go was deleted in E6, 7a721802), Service.Handler builds the handler, and repoHandler does not embed a gitserve handle

CURRENT (E6, PR #578, merged as 7a721802): gitserve_seam.go is deleted and callers outside the store use gitserve.PushPolicy and gitserve.WithPushPolicy directly. Service.Handler (service_gitserve.go) builds the handler as `gitserve.NewHandler(s.rh.Repo, s.rh.syncRepo, s.ri.UpstreamBranch)`: the vcs handle, the embedded remotesync handle and the consensus-branch resolver of the store's *remotesync.Index (since E5; it was s.UpstreamBranch, a Service method, before). Everything below that says the parent re-exports PushPolicy and WithPushPolicy, or that a gitserve_seam.go or verify_seam.go wrapper exists, is HISTORICAL as of 7a721802 (those src refs were dropped).

Since PR 11b of the internal/ hierarchy stack (#561, merged as 09511ee0; branch refactor/hier-11b-gitserve, stacked on refactor/hier-11-sync), the smart-HTTP handler is the package internal/store/gitserve: httphandler.go (the mux, upload-pack, the sideband writer), httphandler_advrefs.go (the curated advertisement and the root-commit cache), httphandler_pack.go (negotiation, the object-set build, shallow handling), httphandler_receivepack.go (PushPolicy, WithPushPolicy, receivePack: serve, judgeRequest, verify, privatePathClosure, register, heldAdmitted), receivepack_quarantine.go (the quarantine over the host's storer, the new-commit walk) plus host.go, doc.go and testseams.go. It is NOT under internal/store/internal/. It imports vcs, verify, remotesync (the origin-synchronisation child, first named internal/store/sync and renamed before merge because sync collides with the standard library), fleetrec (the Fleet a PushPolicy hands the judge) and merge (the Mode constants a branch move reports); TestLayers lists those five as same-layer edges, the last two being beyond the proposal's arrow (gitserve to vcs, verify, remotesync) and types only. The remotesync child it depends on is described in kb/architecture/store/sync-child/25664ca8.md (PR #560).

THE HANDLE. gitserve.host is `struct{ *vcs.Repo; sy *remotesync.Repo }`: every `rh.Storer()`, `rh.LockBranch`, `rh.CreateBranch`, `rh.NotifyCommit` ... of the old repoHandler-typed code is the vcs handle's, and the one move receive-pack makes through reconcile code is `rp.rh.sy.AdvanceBranchTo` (was rh.advanceBranchTo). The three repoHandler wrappers the handler used (judgeIncoming, privatePathClosure, verifyModeAt in verify_seam.go) are called as verify.JudgeIncoming / verify.PrivatePathClosure / verify.VerifyModeAt with `rh.Repo`, which is exactly what the wrappers passed. HISTORICAL (at 09511ee0): the parent kept judgeIncoming and privatePathClosure for Service.JudgePeerBranch (service_sync.go) and checkOwnLineage for Open/Clone (repo.go), and dropped the verifyModeAt wrapper. Since parent slimming PRs A and C, E5 and E6 package store has no repoHandler wrappers and no verify seam: the handler, the remotesync child and bootstrap call verify.* directly. The parent builds the handler once: `gitserve.NewHandler(s.rh.Repo, s.rh.syncRepo, s.ri.UpstreamBranch)` in Service.Handler (service_gitserve.go), the same pointers repoHandler embeds, so the lock order (branch lock, then AdvanceBranchTo, which ends in NotifyCommit) and the uncancellable registration context (kb/invariants/store/git-serve/receive-pack/ae01265e.md) are unchanged: the receive-pack body moved without an edit beyond the package qualifiers.

THE SEAM (HISTORICAL, deleted in E6; internal/store/gitserve_seam.go): `type PushPolicy = gitserve.PushPolicy` and a one-line WithPushPolicy forward; nothing else of the child is exported to callers outside store. repoHandler gains no embedded gitserve handle: nothing in the parent calls a method of the child.

TESTS: they drive the handler through svc.Handler() and stayed in the parent. Five internals are reached through test doors in gitserve/testseams.go, each calling mustBeTest (panics outside a test binary): SetPushRegisterHookForTest, ObjectBuildsForTest, NoPushPolicyTextForTest, NewCommitsForTest, JudgeRequestForTest. No test moved; the store's top-level test count is unchanged.

CONSEQUENCE: protocol and push-judging code goes in gitserve; a new need from the Service stays a parent function that passes the handles in. MISREADING: the handler is not an override point and holds no state of its own beyond what newGitHTTPHandler caches (the root-commit cache).

UPDATE (refactor/store-e6-seams, PR E6, #578, merged into dev as 7a721802; re-read at 7a721802): gitserve_seam.go is deleted; PushPolicy and WithPushPolicy are called as gitserve.PushPolicy and gitserve.WithPushPolicy from callers outside store. Service.Handler stays in service_gitserve.go because it injects the store's handles. The sentence above that the parent re-exports PushPolicy and WithPushPolicy is HISTORICAL.

# store/internal/vcs holds the git layer as vcs.Repo (the old repoHandler); the parent's repoHandler is `struct{ *vcs.Repo }`, so sub-indices keep `rh *repoHandler` and reach the child by method promotion, while merge/reconcile/triggers/verify/gitserve methods stay declared on repoHandler in the parent

Since PR 07 of the internal/ hierarchy stack (branch refactor/hier-07-vcs), the store's vcs cluster is the package internal/store/internal/vcs. Files: branch, branch_commit, branch_commit_log, path_changes, plumbing, sign, sshsig, trailers, agent_id, backfill_commit_parents, changes, experiment_record, fact_history, factpath, history_walk, ontology_cache, revision_diff, revisions_before, accept_list, branch_errors, branch_roles, embedder, plus repo_access.go and testseams.go. It imports only store/git, store/internal/sqlite, fact, pki and embeddings/params; TestLayers lists store/internal/vcs -> store/git and -> store/internal/sqlite as same-layer edges.

THE SEAM (internal/store/vcs_seam.go): at the PR 07 merge this was `type repoHandler struct{ *vcs.Repo }`; at 2baf56d7 (PR #572) it is `struct{ *vcs.Repo; *factsRepo; *mergeRepo; *syncRepo }`, the later children's methods promoted onto the same handle, and newRepoHandler builds them from the one vcs.Repo. Every sub-index (factIndex, searchIndex, remoteIndex, the query services) still holds `rh *repoHandler` and calls the child's exported methods by promotion: rh.LockBranch, rh.NotifyCommit, rh.CommitSigs, rh.DeriveBeforeAdvance, rh.ResolveRef, rh.BranchID, ... Methods that belong to higher clusters stayed off the vcs child; at PR 07 they were declared on the parent's repoHandler, and by 2baf56d7 the merge, remotesync, facts and gitserve children own the ones that call NotifyCommit (see the per-child architecture facts), while vcs_seam.go still names the parent-side wiring. Go embedding is not virtual and vcs never calls up, so the commit path (LockBranch, CommitSigner before any object is written, CommitSigs before the commit object (before any object in single-file writes; after the blobs and trees in batchWriteLocked, see issue 554), object writes, DeriveBeforeAdvance, ref move, NotifyCommit under the lock: AppendCommitLog, im.Sync, touchExperimentActivity, onCommit) runs inside the child exactly as before.

THE BOUNDARY: Repo's fields are unexported. The parent reads them through accessors (DB(), Storer(), Repository(), Name(), NetTimeout(), FactRoot(), ReadOnly(), ReplaySkip(), AcceptList(), OwnKeys() which returns nil when unset, ConsensusBranchFunc(), RLockConfig() returning the unlock, OntologyCache()) and wires hooks and config through setters called at build/swap time exactly where the field assignments were (SetRepository, SetName, SetOnDrop, SetIndexManager, SetOnCommit, SetConsensusBranchFunc, SetNetTimeout, SetFactRoot, SetReadOnly, SetSigner, SetAgentID, SetAcceptList, SetOwnKeys, SetReplaySkip, SetEmbedder). Free helpers the parent needs are exported under vcs.* (WalkHistory, StoreCommit, BuildTree, WriteFileToStore, TreeOntology, CheckTreeShape, AgentIDOfAuthor, ParentTrees, AppendTrailers, LiveChange, ActiveTables, FirstParentChainCTE, the SSHSig* constants, ...). Public store names declared in the moved files (Experiment, Trailers, PathChange, ErrBranchNotFound, ErrNoSigner, WithAgentTrace, ...) are re-exported unchanged by vcs_seam.go as type aliases, consts, the SAME error values, and one-line func forwards; SetTestFallbackSigner/SetTestFallbackAgentID are forwarded from vcs_testhooks.go, the only parent file test/archtest allows to name them.

TESTS: almost every store test drives the child through a full Service, so they stayed in the parent (the parent still has its own changes_test.go, trailers_test.go, conflict_merge_test.go, methodology_test.go and similarity_graph_test.go, which use a Service). The Service-free ones live in the child's own files, named after the code they cover: internal/store/internal/vcs/trailers_test.go, changes_test.go, history_walk_test.go and revision_diff_test.go (moved by PR #572, store-slim D2, verified at merge 2baf56d7: none of the moved files references a Service constructor), which also placed internal/store/merge/conflict_merge_test.go, internal/store/index/methodology_test.go, internal/store/index/similarity_graph_test.go and internal/store/fsck/integrity_test.go in their children. A test that needs a Service does NOT belong in the child. Parent white-box tests reach derivation internals through *ForTest methods in vcs/testseams.go (each panics outside a test binary) and through exported test hooks/counters (DeriveObjectHook, SwapHook, BranchTipHook, OpenHistoryHook, CommitDiffs, PayloadsComputed, LastSwapDuration).

CONSEQUENCE: new commit-path primitives go in vcs; code that needs a higher cluster stays a method on the parent's repoHandler. A parent file cannot touch a Repo field: add an accessor or setter, do not export the field. MISREADING: the embedding is not an override point; declaring a method on the parent's repoHandler with the same name as a Repo method shadows it only for parent callers, never for code inside vcs.

RE-PINNED at the #572 merge 2baf56d7 (2026-10-21): the child's file list (accept_list ... trailers, plus doc.go and testseams.go), the seam struct above and the TESTS paragraph were re-read there; the claims below were VERIFIED at the #550 merge ad7059d2 (2026-10-20): the child's files, imports (store/git, store/internal/sqlite, fact, pki, embeddings/params), the parent seam files vcs_seam.go and vcs_testhooks.go, and the TestLayers same-layer edges store/internal/vcs -> store/git and -> store/internal/sqlite are as described. KNOWN LAYERING SMELL (not fixed by #550): internal/store/internal/vcs/branch.go still names the restatement_* tables (restatement_pairs, restatement_cache_state, restatement_verdicts, restatement_throttle_state) in the branch-drop path, so the git layer knows review-time table names; TestConformance_ReviewPipelineOnly (internal/synthesize/restatement_conformance_test.go) allowlists that file by path (internal/vcs/branch.go, relative to internal/store). Do not read the vcs child as free of review-pipeline knowledge; the planned fix is to move that table list behind a hook owned by the index side.

UPDATE at the hier-10c merge d73aad37 (PR #559, branch refactor/hier-10c-drop-hook; verified there): the KNOWN LAYERING SMELL above is removed. internal/store/internal/vcs/branch.go no longer names the restatement_* tables: DropBranchLocked runs a hook registered with Repo.SetOnDropBranchRows at the same point (after branch_facts, before the branches row), and newRepoHandler registers vocab.DropBranchReviewState. TestConformance_ReviewPipelineOnly no longer allowlists internal/vcs/branch.go, so the vcs child IS now free of review-pipeline table names, and the scan enforces it. A vcs.Repo with no such hook refuses every drop (ErrNoDropBranchRowsHook) before removing the ref; every production Repo is built by newRepoHandler, which registers it, so the refusal is unreachable in production.

# commit_parents records (child, parent_order, parent) edges; populated in CommitLogSync tx; backfilled once per DB

commit_parents(commit_hash TEXT, parent_order INTEGER, parent_hash TEXT, PRIMARY KEY (commit_hash, parent_order)) records the git DAG's parent edges as relational rows. One row per (child, parent) edge — merge commits have 2+ rows ordered by parent_order; root commits have zero rows.

parent_order = 0 is the FIRST parent, matching git's first-parent semantics (the 'ours' side of a merge). Branch-local history walks (resolveActiveCommitForPath, resolveTargetCommit) restrict to parent_order = 0 in their recursive CTEs; merge-DAG walks can use all rows. Secondary index commit_parents_parent enables reverse traversal ('which commits have parent X?') though no current caller needs it.

WRITE PATH: Storer.CommitLogSync's iterator gained a parents []string return value (parents[0] first). Inserts are INSERT OR IGNORE inside the same transaction that writes commit_log + branch_commits, so visibility + log + parents stay atomic per commit. parentHashes(c *object.Commit) in internal/engine/store/internal/vcs/branch_commit_log.go is the helper that converts go-git ParentHashes to the []string the iterator yields.

BACKFILL: existing repos boot with commit_parents empty. backfillCommitParents(ctx, rh) walks DISTINCT commit_hash from branch_commits, reads parents via go-git, and inserts in one tx. Guarded by meta.commit_parents_backfilled = '1' so it runs at most once per database. Called from Service.OpenRepo immediately after populateCommitLog.

QUERY PATTERN: see [[cte-over-commit-parents]] for the recursive-CTE walk pattern that replaces the retired first_parent_chain vtable.

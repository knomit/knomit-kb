# store.FleetAt / LoadFleetAt read the member records AND the certificate artifacts the fleet ontology DECLARES (pki: root, crl, leaf) from ONE fleet commit; each read is bounded (max_size, else 64MiB for a CRL, 64KiB for another pki file); leaves are looked up by the id EXACTLY; no artifacts/fleet path is hard-coded; PushPolicy.Fleet carries both to receive-pack via repos.Manager.FleetAtMain

fleet_read.go loadFleetAt parses the fleet ontology, loads records and loadPKI(tree, ont). FleetPKI is nil when no pki: root is declared or the root file is absent. FleetPKI.Layout holds the declared paths (LeafPath(id), LeafID(name)). Present-but-broken or oversized files never fail the load: RootErr / CRLErr / a per-leaf error are kept and the rules fail closed. Leaves are read eagerly as raw bytes, keyed by the file name's id EXACTLY (no case folding: Cert("AGENT-X") does not find agent-x.pem). Symlinks and directories in the leaf directory are skipped (the judge refuses them on the way in). The reader reads no issuance or revocation record: those are judged when added and read by nothing else.

READ BOUNDS (readBound): a declared max_size; else crlReadBound (64MiB) for the CRL, which the preset leaves uncapped because it only grows (a memory guard, not a policy cap); else defaultPKIFileCap (64KiB).

CONSEQUENCE: a fleet repo whose ontology declares no pki: root has no PKI at all (FleetPKI nil): rules A/B are inert there even if a root.crt file sits in its tree. The fleet preset declares it.

# The causal-trace trailers are stamped by a ctx-carried store.Trailers (WithTrailers) applied by appendTrailers at the THREE authored-commit call sites in fact_write.go (writeFileExact, deleteFile, batchWriteLocked) — inside the signed bytes, as the LAST paragraph — never at the 19 callers; built in F07 PR 3; the store MINTS nothing: a commit is stamped only when a script host, a recipe host or an agent's `trace` argument (#349) put a set on its ctx

F07 causal trace, revision 2 addendum. The commit message reaches object.Commit.Message byte for byte from every caller (MCP learn/update/retract, web fact create/update, synthesize dedup/decision/discovery — 19 non-store call sites) through factIndex.writeFile / deleteFile / batchWrite (internal/engine/store/facts/fact_write.go), and the commit object is BUILT in exactly three places: writeFileToStore and deleteFileFromStore in internal/engine/store/internal/vcs/plumbing.go and batchWrite in internal/engine/store/facts/fact_write.go, each calling storeCommit, which signs EncodeWithoutSignature — so trailers are INSIDE the signed bytes (go-git encodes "\n\n"+Message into the payload).

BUILT in F07 PR 3: `store.WithTrailers(ctx, Trailers{Trace, Cause, Trigger})` carried on the ctx (precedent: WithPrecomputedEmbeddings); `appendTrailers(message, trailersFromContext(ctx))` runs at the three CALL SITES in fact_write.go — writeFileExact before writeFileToStore, deleteFile before deleteFileFromStore, and batchWriteLocked's commit literal — and appends the paragraph as the LAST paragraph (a blank line, then `Knomit-Trace:` / `Knomit-Cause:` / `Knomit-Trigger:`, empty keys omitted), so TrailerValue's last-paragraph/last-occurrence rule makes the stamped value win over a body line of the same key. The builders' signatures, the four FactIndex write methods and the 19 callers are unchanged; the MCP handlers carry the set because they pass their ctx to the write. The store MINTS NOTHING: the dispatcher derives the fire's trace (trailer, task id, else the firing commit — kb/architecture/repos/triggers/trace-derivation) and a write carries a set only when one was put on its ctx (ruling D-mint 2026-09-28: "agreed, no" — knomit stamps nothing on its own). Since #349 there are three producers: a trigger script's host (Trace, Cause, Trigger), a recipe's host (the same plus Knomit-Run, its run id), and an MCP write call that PASSED the agent `trace` argument (store.WithAgentTrace; kb/architecture/mcp/write-tools/trace-argument/9512adc3.md). A session, REST or synthesize write WITHOUT that argument still gets no trailer. #349 widened the set: Trailers gained Run and Extra (an agent's own keys), and appendTrailers writes Trace, Cause, Trigger, Run, then Extra sorted by key — the F07 three-key paragraph is byte-identical. TestWithTrailers_StampedAtThreeSitesInsideTheSignature pins all three sites, the no-set case, and that one altered trailer character breaks the SSHSIG. One place owns the format; no signature change across the callers; transport commits carry none by construction (merge commits in branch_merge.go and replays in remote_reconcile_rebase.go are not stamped; a replay copies the original message, so Knomit-Trace survives while a Knomit-Cause that pointed at a replayed commit dangles — an origin force-rewind only, for PR 3's brief). The rejected alternative — appending the string at each caller — is six-plus edits and misses synthesize.

PR 1b built only the reader. It reads `Knomit-Trace` from the firing commit's full message with store.TrailerValue (internal/engine/store/model/trailers.go): the last paragraph, Key: value lines, last occurrence wins, case-insensitive; go-git v5.18.0 has no trailer parser and commit_log.message keeps only the first line, which is why the message is parsed, not the log. Since PR 3 change.trace is never '' (derived), and TestDispatch_TraceFromTrailer's no-trailer case expects the commit hash.

ONE EXCEPTION to 'merge commits are not stamped' (first-mission rehearsal F10, PR #396 merged as 13a785e6): an experiment's OWN merge — CommitExperiment (exp into its parent) and SyncExperiment (parent into exp), both through store.mergeExperiment — opts the ctx set in explicitly via mergeOpts.trace. It is written by appendTrailersToParagraph, which JOINS the merge's existing trailer paragraph (the Knomit-Merge/Knomit-Conflict record from appendTrailerLines) instead of opening a new one, because TrailerValues and TrailerValue both read only the last paragraph. Every other merge (MergeBranch, agent-branch sync, reconcile, the peer UI merge) never reads the ctx trace and stays a transport commit, even under a traced ctx (TestExperimentTrace_OnlyTheExperimentsOwnMerge). Do not read trailersFromContext in mergeIntoBranchLockedOpts generically: that would stamp transport merges whenever a traced call happens to trigger one.

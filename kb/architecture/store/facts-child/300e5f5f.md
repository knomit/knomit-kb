# store/facts holds the fact read/write cores, the system-file / template / skill readers and the trigger dispatcher's store half as facts.Index and facts.Repo; repoHandler embeds *vcs.Repo AND *factsRepo (alias of facts.Repo), and the parent keeps every public name through facts_seam.go

Since PR 09 of the internal/ hierarchy stack (PR #555, merged into dev as 6733104c), the facts cluster is the package internal/store/facts (a sibling of git, migrate, fleetrec and verify, not under internal/). Files: fact_index.go (Index: DiffFiles, ChangesUnder; NewIndex, SetAuth), fact_read.go, fact_write.go (the write cores writeFileExact and BatchWriteLocked, WriteFact and friends, ValidatePath, IsInvalidPath), fact_write_validate.go (validateWrite, FactInvalidError, WithCarriedOver), fact_record.go and fact_types.go (FactRecord, NewFactRecord, FactWithBody, ReadFact*, WriteFactResult and the ErrRepoReadOnly / ErrFactChanged / ErrInvalidPath sentinels), system_files.go, templates.go, skills.go, triggers.go (the dispatcher's store half: TriggerIndex, trigger_watermarks / trigger_fires / trigger_due_fires rows, DueCandidates, the commit readers), repo.go and testseams.go. It imports store/internal/sqlite, store/internal/vcs, store/verify, fact and pki (not store/git). THE facts-to-verify EDGE is exactly three uses, none in fact_write.go: verify.IsFactPathUnder (fact_write_validate.go, in validateWrite), verify.VerifyCommitSignature and the verify.CommitSigner type (triggers.go, CommitSignerOf). TestVerifyIsNeverInTheWritePath reads facts/fact_write.go and internal/vcs/sign.go and rejects any `verify.<name>(` call there, so a verify call added to fact_write.go fails it; the edge must stay in the validate and trigger files. TestLayers lists store/facts -> store/internal/sqlite, -> store/internal/vcs and -> store/verify as same-layer edges.

THE SEAM. The methods that used to be declared on repoHandler in these files (SkillsAt, SkillFilesAt, TemplateExistsAt, TemplateFilesAt, TemplateFactsAt, SystemFileAt, OntologyAtCommit, ScriptAt, RecipeAt, GuidanceAt, TreeReader, Toucher, CommitInfo, CommitSignerOf, BlobAt, IsAncestor, UpstreamTip, AncestorSet, the Trigger* / Record* / Due* rows, SignerFingerprint, validateWrite) are declared on facts.Repo, which is `struct{ *vcs.Repo }`. The parent's repoHandler is now `struct{ *vcs.Repo; *factsRepo }` (internal/store/vcs_seam.go; `type factsRepo = facts.Repo` in facts_seam.go gives the embedded field a name that does not collide with the embedded vcs `Repo`), and newRepoHandler builds ONE vcs.Repo and wraps the same pointer with facts.NewRepo, so a setter called on either side configures the same handle. Service keeps `fi *facts.Index` (built with facts.NewIndex(rh.factsRepo); repo.go sets credentials with fi.SetAuth). Promotion keeps every call site (rh.SkillsAt, s.Triggers() returning s.rh as a TriggerIndex) unchanged. facts_seam.go re-exports every public name as aliases, consts, the SAME error values and one-line forwards.

BOUNDARY RULES that were checked: facts.Repo declares no method with the name of a vcs.Repo method or of a parent-declared repoHandler method (a duplicate would silently shadow instead of failing to compile, because depth-1 selectors from two embedded fields are only ambiguous when used); embedding is not virtual, so nothing in facts calls a method declared on the parent's repoHandler, and the write path (LockBranch, CommitSigner before any object is written, CommitSigs, objects, DeriveBeforeAdvance, ref move, NotifyCommit under the lock) runs unchanged.

WHAT STAYED IN THE PARENT: replay.go and consensus_branch.go (Service-level orchestration, counted as facade by the cluster fact), service_facts.go (Service.WriteSystemTree validates with facts.ValidatePath and calls fi.BatchWriteLocked under rh.LockBranch / rh.NotifyCommit itself), service_fsck.go (calls fi.WriteFile for the raw-write test), and triggers_testing.go (Service.TestingCommitFiles's testingTree, a test-only helper whose only caller is the parent). The proposal lists triggers_testing.go under facts; it stayed because exporting its tree builder would add a public test door for no consumer.

TEST SEAMS. The case-preserving write core writeFileExact is reachable from parent tests only through (*facts.Index).WriteFileExactForTest, and SetBatchWriteUnlockedHookForTest now calls mustBeTest; both panic outside a test binary (testing.Testing). TestGitErrInvalidPath_Recovered moved into the child (it pins the unexported gitErrInvalidPath).

CONSEQUENCE: a new fact-file, system-file, template, skill or trigger-row reader goes in facts and, if outside callers use it, gets a line in facts_seam.go; code that needs a higher cluster (merge, index, sync) stays a method on the parent's repoHandler. MISREADING: facts.Repo is not a second git handle and is not an override point; it adds methods to the SAME vcs.Repo pointer, and a same-named method on the parent's repoHandler would shadow it only for parent callers.

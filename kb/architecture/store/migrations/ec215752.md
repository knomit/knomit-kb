# control.db's schema text has ONE applier, the versioned migrator, whose recovery RE-RUNS a body — so the text must be IF NOT EXISTS-idempotent, and that one property constrains what a change may look like and hides drift from ordinary tests

control.db's schema text (internal/store/migrate/control/*.up.sql) is applied by exactly one applier, migrate.Control, against homes in unknown states. Its recovery path (upWithRecovery -> recoverDirty) forces a dirty version N back to N-1 and re-executes N's body against a database that may already hold what that body created, so the text must be safe to re-run — and that single idempotence requirement shapes the downstream rules: it constrains which schema changes are expressible, and it makes divergence between the text and a live shape invisible to no-op and name-only tests. (Until merge 1cc5413c there was a second applier, an operator tool that replayed the whole chain inside its own transaction; it is gone, and the rule did not change with it.)

How each consequence shows up:
- EXPRESSIBILITY. New control.db state is a NEW TABLE, not a new column: TestControl_UpMigrationsAreIdempotentDDL accepts only `CREATE (TABLE|UNIQUE INDEX|INDEX) IF NOT EXISTS` statements, so `ALTER TABLE ... ADD COLUMN` is rejected by the test even though recovery's fallback would happen to tolerate its re-run. That is why a subscription is the PRESENCE of a row in `repo_subscriptions` and `Origin.Mode` is derived at read time — with the second-order effect that an origin writer which rewrites `repo_origins` without carrying Mode silently demotes a subscription to sync. This is specific to the CONTROL chain; the per-repo store schema is migrated differently. Why INSERT/DROP stay dangerous under recovery: see the dffc4f24 gotcha.
- WHY IDEMPOTENT IN THE FIRST PLACE. The baseline is the pre-migrator DDL verbatim with every IF NOT EXISTS retained, so it no-ops on live homes and creates on fresh ones, needs no probe-and-Force stamping (whose failure mode is a home stamped at a version whose schema it lacks), and satisfies the standing policy that up-migration bodies must be re-runnable because recovery can re-run them. It lives in `internal/store/migrate` (`control/` beside `repo/`); `schema_migrations` records version integers only, so directory renames are safe.
- DRIFT IS INVISIBLE. An IF NOT EXISTS baseline is equally a no-op against a table whose shape has silently diverged from the text, so fresh homes and existing homes can carry different shapes forever with every package green. Only a shape-equality test catches it (TestControl_BaselineMatchesLiveShape): build one DB from the legacy DDL pasted as a literal, one via the migrator, and compare `table_info`, `foreign_key_list` (table_info cannot see ON DELETE CASCADE), `index_list`+`index_info`, AND each index's `sqlite_master.sql` text (the only place a partial index's WHERE predicate is visible). The table's own `sqlite_master.sql` is a deliberately accepted residual. Pasting the literal is the mechanism, not a smell — importing the constant would make the test tautological.

WHAT THIS DOES NOT MEAN: 'no migration needed' or 'plain edits' is NOT a property of control.db — that belongs to the ephemeral session DB; control.db keeps the numbered chain. And every opener of control.db must call `controlUp` (the lens re-key before migrate.Control) rather than call migrate.Control directly; there is no longer any exemption.

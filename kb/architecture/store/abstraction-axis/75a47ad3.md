# The abstraction axis is title-only embeddings in a code-managed vec0 table keyed by facts.id — content-addressing makes the cache watermark-incremental by construction

A second embedding axis alongside `facts_vec`: ONE title-only vector per fact version, in a `vec0` table (`fact_titles_vec`) keyed by `facts.id`.

**Why the key matters.** `facts.id` is content-addressed (`UNIQUE(path, blob_hash)`), so an edited fact is a NEW row with NO vector. "Rows lacking a vector" IS therefore exactly the delta — the cache is watermark-incremental by construction, with no watermark column, no bookkeeping table of its own, and nothing to migrate when the corpus changes shape. `LiveFactsMissingTitleVector` is the whole delta query.

**Code-managed, not migrated.** A `vec0` table fixes its dimension at CREATE and cannot be ALTERed, so like `facts_vec` it is created in code at the active model's dimension (`ensureFactTitlesVec`), not by a numbered migration. Migration 000018 ships only the plain tables and the delete trigger.

**What it drifts with.** It shares `facts_vec`'s embedding identity, so an embedding-model change invalidates it and every cache derived from it.

**EPISTEMIC-ONLY, and not by preference.** The axis covers epistemic facts alone. This is FORCED, not chosen: prune's decision path does not carry `Kind` through `mergedFact`, so a pragmatic fact reaching synthesis would be silently rewritten as epistemic. Lifting the restriction means fixing that first. The residual is that restatements among pragmatic facts remain unjudged by anything.

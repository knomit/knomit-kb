# GraphSchemaVersion constant gates forced rebuilds on graph-shape changes

searchIndex.GraphSchemaVersion constant (currently '4', defined in search_index.go) tracks the version of ALL forced-rebuild-on-upgrade DERIVED state — graph layout AND, despite the name, the SQLite-side derived index state (canonical fact_domains, fact_domain_tokens) AND the embedding vectors. Persisted in meta.graph_schema_version (GLOBAL to the DB, not per-branch) after every successful Rebuild. BUMP THE CONSTANT when an indexing-logic change requires a forced reindex on existing deployments — new edge types, node identity changes, canonical/tokenised domain storage, etc.

Version history: v2 = DERIVED_FROM edges carry source_commit + target_commit. v3 = domain tags stored CANONICAL (NFC + case-fold + de-hyphenize) in fact_domains and tokenised into fact_domain_tokens; v2 DBs hold raw domains + an empty token table so domain search silently returns nothing until regenerated. v4 = facts_vec is code-managed (ensureFactsVec) at the active model's dimension rather than a static FLOAT[768] migration.

A SECOND, version-independent rebuild trigger was added in v4: NeedsRebuild ALSO gates on embedding identity (meta.embed_model_id / meta.embed_dim). A model-id or dimension change invalidates every stored vector and forces a rebuild that recreates facts_vec empty and re-embeds the whole corpus — WITHOUT any GraphSchemaVersion bump. So NeedsRebuild returns true on EITHER a version mismatch OR an embedding-identity mismatch (search_index.go).

Self-heal: NeedsRebuild reports stale (persisted != constant, missing row, or embedding-identity drift); repoBuilder.setupIndex checks it ONCE at startup then delegates to healIndexBranches: when stale it full-Rebuilds EACH maintained branch (agent + upstreamMain); when not stale it incrementally Syncs each. PARTIAL-HEAL MASKING BUG (fixed b8a4ca9): Rebuild bumps the GLOBAL version on each branch it completes, so an earlier-branch success + later-branch failure would leave the version current and skip the next heal; fix: healIndexBranches calls IndexManager.MarkRebuildNeeded (clears the persisted version) on ANY rebuild failure so the next startup re-arms. NeedsRebuild + MarkRebuildNeeded are both on the IndexManager interface (internal/store/interfaces.go). Rebuild preserves facts rowids (ON CONFLICT DO UPDATE), so a version-only heal reuses embeddings (no re-embed); an embedding-identity heal re-embeds the whole corpus.

WHAT THIS DOES NOT MEAN:
- The constant is NOT '3'. It is '4' (search_index.go). Do not compare a change against 3 or revert it to 3.
- A version bump is NOT the only thing that forces a rebuild — an embedding model-id/dim change forces one too, with NO version change (search_index.go NeedsRebuild).
- 'GraphSchemaVersion' is NOT graph-only — it gates domain/token derived state AND, since v4, the facts_vec vector layout.

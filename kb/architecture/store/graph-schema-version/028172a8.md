# GraphSchemaVersion constant gates forced rebuilds on graph-shape changes

searchIndex.GraphSchemaVersion constant (currently '2', defined in search_index.go) tracks the GraphQLite layout version. Persisted in meta.graph_schema_version after every successful Rebuild; checked on Open. Version 2 = DERIVED_FROM edges carry source_commit + target_commit properties (commit-anchored /incoming + /outgoing) and the FactVersion subsystem was retired. BUMP THE CONSTANT when the graph schema changes in a way that requires a forced rebuild on existing deployments — e.g. adding new edge types, changing node identity keys, adding required properties. On mismatch the store logs the repo name (commit 0938d83 added that) and refuses to operate on the stale graph until rebuild. No SQL migration needed for graph-shape changes — the version bump triggers rebuild which reconstructs the graph from facts + commit_log.

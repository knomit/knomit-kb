# store/remotesync holds the origin-synchronisation cluster as remotesync.Index (the old remoteIndex) and remotesync.Repo (the reconcile methods of the old repoHandler); the parent keeps replay.go, consensus_branch.go and the Service methods, the receive-pack handler is the gitserve child, and repoHandler gains a fourth embedded handle

Since PR 11 of the internal/ hierarchy stack (branch refactor/hier-11-sync), the store's sync cluster is the package internal/store/remotesync (first extracted as internal/store/sync under a storesync import alias, then renamed before merge because sync collides with the standard library; see kb/decisions/store/remotesync-package-name/feac7433.md). Importers use it unaliased as remotesync. Files: remote.go (the origin and the remotes status rows), remote_sync.go (FetchOrigin, Sync, SyncWithPeers, Push, PublishUpstream, PublishTo, RetractPushedBranch, PublishUpstreamChange, the storeHooks test seams), remote_reconcile.go (reconcileMain, the watermark read/write/seed, AdvanceBranchTo), remote_reconcile_merge.go, remote_reconcile_rebase.go (the rewind replay), local_reconcile.go, origin_identity.go, peer_admit.go, verify_own.go (the publish-time judge of this instance's own commits, JudgeOwnRange, and dropPlan), sync_types.go, plus drop.go (DropUnpublished), repo.go and testseams.go. It imports merge, verify, fleetrec, store/git and internal/vcs; TestLayers lists those five as same-layer edges (store/remotesync -> store/fleetrec, store/git, store/internal/vcs, store/merge, store/verify). It is NOT under internal/store/internal/.

THE TWO TYPES. remotesync.Index (was remoteIndex) owns the origin, the consensus-branch cache and the Sync/Push/Publish entry points; it holds `rh *remotesync.Repo` and reaches UP only. remotesync.Repo is `struct{ *merge.Repo }`: it wraps the merge handle, which wraps the one shared *vcs.Repo, so the methods that were declared on repoHandler in the remote_*.go, origin_identity, peer_admit and verify_own files (reconcileMain, reconcileAgentMerge/Rebase, replayCommit, AdvanceBranchTo, WriteAgentBase, PromotePeer, JudgeOwnRange, ...) are declared on remotesync.Repo. The parent's repoHandler is now `struct{ *vcs.Repo; *factsRepo; *mergeRepo; *syncRepo }` (internal/store/vcs_seam.go); newRepoHandler builds `mr := merge.NewRepo(r)` once and wraps the same pointer with remotesync.NewRepo(mr), so there is still exactly ONE vcs.Repo and ONE merge.Repo per handle. A scripted method-name check found no name declared on two of vcs.Repo, facts.Repo, merge.Repo, remotesync.Repo and repoHandler (a collision would be resolved silently by the shallower embedding).

THE SEAM (internal/store/remotesync_seam.go): type aliases (Origin, Remote, SyncResult, PushResult, MainReconcileResult, MainHistory, LostCommit, OwnCommitRefusedError, DropMergeError, DropForeignError, LeaveOutChangedError), the OwnCommitRefusedText constant and the same sentinel error values (ErrNoAgentBranch, ErrOwnCommitRefused, ErrNotUnpublished, ErrDropMerge, ErrUpstreamMoved). Service.ri is a *remotesync.Index and `var _ RemoteIndex = (*remotesync.Index)(nil)` is in interface_guards.go.

WHAT THE PARENT STILL CALLS (exported for it, nothing else): FetchOrigin (repo.go, Open/Clone), WriteAgentBase (repo.go), AdvanceBranchTo (receive-pack's register), PromotePeer and NewMainHistory/OnMain (Service.AdmitPeerBranch / MainHistory / JudgePeerBranch), JudgeOwnRange (Service.AdvanceLocalUpstream), DropUnpublished (Service.dropUnpublished), and on Index NewIndex, SetOrigin, Consensus/SetConsensus/WarnAmbiguousOnce (consensus_branch.go). The body of Service.dropUnpublished moved into remotesync.Repo.DropUnpublished statement for statement; the Service keeps the up-front refusal (empty upstream or branch, branch == upstream) and the UpstreamBranch lookup, so lock order (branch lock, then the same reads and writes) is unchanged. replay.go, consensus_branch.go and service_sync.go (the Service methods) stayed in the parent; the receive-pack handler is NOT in the parent either, it is the gitserve child (internal/store/gitserve), which calls AdvanceBranchTo.

TESTS: the parent's white-box tests drive the cores through *ForTest methods and functions in remotesync/testseams.go (ReconcileMainForTest, ReconcileAgentForTest, ReconcileAgentMergeForTest, ReconcileAgentRebaseForTest, ReplayOntoUpstreamForTest, ReplayCommitForTest, UnpushedCommitsForTest, ReadAgentBaseForTest, ReadOriginIdentityForTest, Index.ReconcileNowForTest, the status-row updaters, OriginIdentityForTest, AgentBaseRefNameForTest, ClassifyMainRewindForTest, SetStoreHooksForTest), each calling mustBeTest, which panics outside a test binary. Three pure unit tests moved into the child by name: TestRemoteSays, TestOriginIdentity, TestReconcileMain_LogsMergeBaseErrorDistinctly. Every other remote_*_test.go drives a full Service and stays in the parent.

CONSEQUENCE: new origin/reconcile/publish logic goes in remotesync; code that needs a higher cluster (the Service) stays a parent method and calls the exported core. MISREADING: remotesync.Repo is not an override point (embedding is not virtual), and the moved Sync body is the one the load-bearing ordering facts describe: kb/invariants/store/remote-reconcile/watermark-seed/0f9cc562.md (the remote-tracking ref is read BEFORE FetchOrigin, under the config read lock) is unchanged and now lives in internal/store/remotesync/remote_sync.go.

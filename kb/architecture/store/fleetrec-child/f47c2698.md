# store/fleetrec is the reader of a fleet repository's member records, PKI artifacts and main history; the parent re-exports its names as aliases, and the Service's FleetAt/FileAt/FleetKeysOf/FleetSince/FleetMainLog are one-line forwards into it

Since PR 08 of the internal/ hierarchy stack (branch refactor/hier-08-fleetrec, stacked on the vcs PR), the fleetrec cluster is the package internal/store/fleetrec (NOT under internal/: the proposal places fleetrec, verify, facts, ... as siblings of git and migrate). Files: read.go (was fleet_read.go: Member, Fleet, PKI, LoadFleet, LoadFleetAt, LoadFleetAtCommit, LoadMembers, LoadMembersOfTree, the PEM parsers, ReadBound, PKIFileCap, TreeBytesCapped, OpenGitDir, ResolveCommit), history.go (fileHash, errStopWalk), activity.go (RecordChange, MainCommit, recordChanges), log.go (At, FileAt, KeysOf, Since, MainLog, walkFirstParent: the bodies of the Service methods of the same names), testseams.go (MalformedLoggedForTest, panics outside a test binary).

It imports only fact, pki and store/internal/vcs (WalkHistory, CheckTreeShape, TreeOntology, AgentIDOfAuthor), and takes a small Storer interface (go-git EncodedObjectStorer + ReferenceStorer) rather than the store's git storer, so TestLayers lists exactly one same-layer edge for it: store/fleetrec -> store/internal/vcs. The verify cluster (judge, audit, own-range, incoming) and the Service facade reach UP to it.

THE SEAM: internal/store/fleetrec_seam.go re-exports Fleet, FleetMember (= fleetrec.Member), FleetPKI (= fleetrec.PKI), FleetRecordChange, FleetMainCommit as type aliases, ErrNotFleet as the SAME error value, and LoadFleet/LoadFleetAt as forwards, so the public store names callers outside store use did not change. service_fleetrec.go keeps the Service methods as facade one-liners (the facade rule: Service methods live only in facade files). The vcs child (see the vcs-child architecture fact of PR 07) is the pattern this follows.

CONSEQUENCE: new readers of a fleet commit go in fleetrec; the judge calls fleetrec.LoadFleetAtCommit / LoadMembers / LoadMembersOfTree (the folder-binding and tree-shape guards live in LoadMembersOfTree, so a second member loader would bypass them). The one-error-per-blob malformed-record latch is the child's unexported malformedLogged; tests read its size through MalformedLoggedForTest. MISREADING: the child does not judge anything; rules A/B, record-owner and artifact rules stay in the verify cluster, which only consumes what fleetrec returns.

VERIFIED at the #552 merge 2ca72643 (2026-10-20): the child's files (doc.go, read.go, history.go, activity.go, log.go, testseams.go), its imports (fact, pki, store/internal/vcs), the single TestLayers edge store/fleetrec -> store/internal/vcs, the aliases and forwards in fleetrec_seam.go and the Service one-liners in service_fleetrec.go are as described. The write-path guard TestVerifyIsNeverInTheWritePath now rejects any `fleetrec.<name>(` call from fact_write.go and internal/vcs/sign.go (kb/gotchas/store/guards/name-regex/e29ad101.md). The verify cluster is still file placement in package store at this commit; its extraction is PR #553, so 'the verify cluster reaches UP to fleetrec' describes its files in package store, not a package import yet.

UPDATE (refactor/store-e6-seams, PR E6, branch commit 67a49c8c; not yet merged): fleetrec_seam.go is deleted on the branch and callers import knomit/internal/store/fleetrec directly (fleetrec.LoadFleet, fleetrec.LoadFleetAt, fleetrec.ErrNotFleet, fleetrec.Member and the other names). The Service forwards FleetAt, FileAt, FleetKeysOf, FleetSince, FleetMainLog and FleetMembersAt stay in service_fleetrec.go because they inject the storer. The sentence above that fleetrec_seam.go is the parent's seam describes dev and becomes HISTORICAL when E6 merges.

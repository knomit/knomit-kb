# searchIndex read surface split into four concrete sub-services (factQuery/graphStore/historyQuery/methodologyMatcher); *searchIndex keeps only index lifecycle + writes

P1.3 decomposed the searchIndex read surface into four concrete sub-services, each a struct holding ONLY `*repoHandler` (field `rh`) and defined in internal/store/query_services.go:
- `factQuery` -> Service.FactQuery(): Search, GetByPath, LastCommitForPath, Stats, Completions, RecentFacts, FactsIter, FactExistsAt, FactLiveAtCommit (+ recentFactsSearch/queryDistinct/filterByEpisodeOps helpers)
- `graphStore` -> Service.GraphStore(): ExplainFact, IncomingAtCommit, OutgoingAtCommit, SubgraphEdges, BlastRadius, TokenDF, SimilarityAdjacency, ReverseDependentPaths
- `historyQuery` -> Service.HistoryQuery(): Log, LogPaginated, RevisionsBefore, CommitDetail, Activity
- `methodologyMatcher` -> Service.Methodology(): RelevantMethodologyForFact
`searchFacade` embeds all four pointers and backs the composite Service.Search() (the SearchIndex interface); it holds no state of its own.

CONSEQUENCE: depend on the narrowest accessor a consumer actually uses (mcp+web: FactQuery+HistoryQuery+GraphStore; synthesize: FactQuery+GraphStore+MethodologyMatcher; repos: IndexManager) — do NOT reach for Service.Search() unless you genuinely need the composite. A new read query goes as a method on the matching cluster struct; because each sub-service reaches shared state only UP through `rh`, you never wire a sideways call to a sibling sub-service (preserves sub-index-up-not-sideways).

WHAT THIS DOES NOT MEAN: `*searchIndex` was NOT deleted or fully split. It retains the index lifecycle + write/rebuild/graph-write path (Sync/SyncLocked/Rebuild/GC/upsert/embed/ensureFactsVec*, `syncSuspended`) and is exactly what Service.IndexManager() returns — writes still flow through *searchIndex, only the read surface was carved out. `resolveActiveCommitForPath` stays on repoHandler (co-owned by FactQuery existence checks and GraphStore commit-scoped queries); it did NOT move onto a sub-service. Shipped in two independently-green stages: 9c151766 (interface segregation) then c0c298e7 (struct split), each passing go build/vet + full test suite unedited.

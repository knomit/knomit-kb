# A peer's pushed branch is merged into the host's agent branch only by the host's operator, from the web UI (Manage → repo → Pushed branches): POST /repos/{repo}/branches/{branch}/merge {expected_tip, resolution?: host|peer} → store.MergePushed, which ALWAYS writes one host-signed merge commit [agent tip, expected_tip] (never a fast-forward, never a tree-identical no-op) under the agent branch's lock, or refuses

WHAT: F11 lets a peer push its own agent/<peer> branch to a host; this is the only way that branch reaches the host's agent branch (and from there, through the host's ordinary sync, the origin). Nothing merges on its own: no MCP tool, no CLI, no trigger, no loop (user ruling: a human does the librarian's job while F12 is postponed).

REST:
- GET /repos/{repo}/pushed-branches lists every local branch repos.RepoInstance.IsPushedBranch accepts (agent/*, not the own agent branch, not the upstream, not the own -<fp8> suffix = own branch from before a rename) with tip, tip_time, tip_author, to_merge (commits reachable from the tip and not from the agent branch), merge_base, other_files_changed (paths outside the ontology root). A subscription lists none.
- POST /repos/{repo}/branches/{branch}/merge {expected_tip, resolution?} merges into ri.AgentBranch() — the target is NEVER a parameter. It is the FIRST route that enforces `operator` (requireOperator = Require(operator), switched off only with authDisabled like writeGate); writeGate adds `write`. The shipped loopback_default holds both, so the web UI and desktop app need no setup; an instance certificate ({read, push:own}) is refused by writeGate, a certificate granted write but not operator by Require.

STORE (MergePushed → mergeIntoBranchLockedOpts with mergeOpts{srcTip, record, side}; every other caller passes the zero value and is unchanged):
- srcTip: the src ref is read under the dst lock; if it is not expected_tip the call returns *BranchMovedError (409 "Branch moved") before any object is written, else it merges exactly that commit.
- record: never fast-forward (the FF shape gets a merge commit whose tree is the peer's), never a tree-identical Noop (a zero-diff merge commit is written, so the peer tip becomes reachable and to_merge clears — otherwise it would read 1 forever after the peer's reconcile merged main). The only Noop is 'expected_tip already in the agent branch'. Commit-log parity holds: checkCommitLogParity compares against branch_commits visibility and accepts no-op commits.
- side: StrategyRefuse; a conflict is *MergeConflictError → 409 with conflicting_paths, paths_without_base, base_commit, host_commit (dst) and peer_commit (src). With resolution host|peer, EVERY conflicting path detected under the dst lock takes that side (host → ResolveDst, peer → ResolveSrc). ours/theirs are refused with 400: the asker is the host's operator, for whom git's 'ours' is the host — the reverse of knomit_experiment's.
- Disjoint histories wrap ErrUnrelatedHistories (409).

UI: a block under Experiments (hidden for a subscription and while the repo mode is unknown). The confirm dialog lists facts changed since merge_base from /changes and sends that response's `head` as expected_tip, so a push landing while it is open is refused, not merged unseen. A refused merge shows BOTH versions of each fact at host_commit/peer_commit before the whole-set choice. No re-clone/lineage text (user ruling D4a): E4 trusts what an own-signed merge brought in (kb/decisions/store/verify/first-contact).

WHAT IT DOES NOT MEAN: the peer's branch is never written; the host never merges into main (on an origin-less host main follows the agent branch through AdvanceLocalUpstream); the whole-set resolution is taken against the conflicts present at the merge, which can differ from the ones the dialog showed if the HOST's agent branch changed in between (only the peer tip is pinned).

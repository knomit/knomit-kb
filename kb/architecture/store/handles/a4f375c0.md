# Guards A1 and A2 enforce the no-facades rule in package store: no re-export of an importable child, no re-export of a non-importable one without an outside caller, and no one-call Service forward into an importable child

CURRENT STATE (PR E7c, #585, merged into dev as 8bcd5449; re-read there). A1 TestStoreParent_ReexportsOnlyNonImportableWithOutsideCaller (test/archtest/store_reexports_test.go) parses the non-test files of internal/engine/store (depth 1) and finds re-exports: type X = p.Y, const/var X = p.Y, and a function whose single statement calls p.F with exactly its own parameters in order, where p is an import of a store child. It fails when p is IMPORTABLE (anything not under store/internal/), and when p is non-importable but no file outside internal/engine/store/** (tests included) selects store.X; an unexported re-export fails by definition. A2 TestStoreService_NoForwardIntoImportableChild fails on an exported *Service method whose single statement calls s.<field>.M (the field's declared type is in an importable child) or <importableChild>.F; the five survivors are in injectsStoreState with a reason (FleetAt, FileAt, FleetKeysOf, FleetMainLog, FleetSince: each passes the child s.rh.Storer(), which callers cannot obtain). Handler (several statements) is not matched and needs no entry. (At E7c, Verify and PruneGeneratedRefs, `s.integrity().M`, were call-on-call forwards A2 did not match; PR #594 widened A2 and deleted them, see CURRENT STATE 2.)

WHAT A1 FOUND at E7c: only sqlite_conn.go's five unexported forwards (conn, beginTxIfNeeded, registerVec, float32SliceToBytes, groupingKey). They were deleted; package store calls store/internal/sqlite directly. The one forward left, SyncDSNParam, has outside callers (internal/repos, internal/web) and sqlite is not importable from there. vcs_seam.go has no re-export left.

NON-VACUITY CHANGED: the design's floor of 100 distinct outside store.X names is not reachable (the parent's outside surface is a handful of names after E3-E7b); the test instead needs 300+ outside files parsed, 5+ distinct selectors, and the live names Service, Open and SyncDSNParam to be seen.

SUPERSEDED BY CURRENT STATE 2 for the matched shapes; the shape-based MISREADING below still stands: a green A2 does NOT prove that no Service pass-through exists, and a new Service method is reviewed by reading it.

DOES NOT MEAN: the vcs-backed Service operations are flagged (they call a non-importable child and are the ruled exception), nor that a Service method that builds a value first and then calls a child is a facade. Sabotaged red: type Mode = merge.Mode, var ErrZ = vcs.ErrBranchNotFound with no outside user, aliased-import alias, a func Register forward, s.mr / s.fr forwards, a fleetrec.At forward, and a stale allowlist entry.

CURRENT STATE 2 (PR #594, merged as 88d63b71; re-read there; supersedes the A2 description above). A2 TestStoreService_NoForwardIntoImportableChild now matches an exported *Service method whose body is zero or more leading binding statements and then ONE call, where the callee handle is (1) `s.<field>.M(...)` or `<importableChild>.F(...)`; (2) a call-on-call `s.<helper>().M(...)`, where <helper> is a Service method whose first result is an importable child's type (Service.Facts() *facts.Index, Service.Integrity() *fsck.Checker; detector serviceChildHelpers/serviceForwards in test/archtest/store_reexports_test.go); (3) a local bound to a handle, `m := s.mr; return m.M(...)`, `var m = s.mr`, with any number of leading bindings; plus a parenthesised handle `(s.mr).M()` and result forwarding `a, b := s.mr.M(); return a, b` (returns exactly the bound names). Work between binding and calling (a non-define statement, a sync.Once as in Handler) makes it not a forward. CONSEQUENCE: Service.Verify and Service.PruneGeneratedRefs were call-on-call forwards into fsck.Checker and are DELETED; callers use `svc.Integrity().Verify(...)` / `.PruneGeneratedRefs(...)` (service_fsck.go holds only `Integrity() *fsck.Checker`, built per call by fsck.NewChecker(s.rh.Repo, s.fi, s.si)). Integrity is itself an injectsStoreState entry (the checker needs the private *vcs.Repo, which callers cannot build), so that entry is load-bearing; the injectsStoreState keys are now Integrity, FleetAt, FileAt, FleetKeysOf, FleetMainLog, FleetSince. KNOWN GAPS, documented in the guard comment and deliberately open (each needs data-flow): method values (`f := s.fi.M; return f()`), named results assigned from the call with a bare return, helpers returning a struct holding the child (`s.handles().fi.M`), package-level helper functions (`checkerOf(s).M`), closures called immediately. DOES NOT MEAN: the guard resolves types beyond the import + Service-field/helper-result declarations; a helper returning a non-importable child (vcs) stays the ruled exception.

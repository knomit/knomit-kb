# Service holds the facts, merge and remotesync children as named fields fr, mr and rr; repoHandler embeds only *vcs.Repo, and an archtest forbids any other store-package embed

CURRENT STATE (PR E7c, #585, merged into dev as 8bcd5449; re-read there). package store's Service has the named fields fr (*facts.Repo), mr (*merge.Repo) and rr (*remotesync.Repo) beside rh (*repoHandler) and the fact, index and sessions handles. repoHandler is now struct{ *vcs.Repo } and declares no method outside tests. The unexported aliases factsRepo, mergeRepo and syncRepo are deleted. remotesync.Repo holds its merge handle as the named field mr (it used to embed *merge.Repo). A call to a child method therefore names its child: s.fr.X, s.mr.X, s.rr.X.

GUARD. TestStoreTypes_DoNotEmbedStorePackageTypes (test/archtest/store_no_embed_test.go) parses every non-test file under internal/store/** and fails on a struct that embeds a type from another store package, directly (*facts.Repo, aliased imports included) or through a same-package alias (type x = facts.Repo; *x). Exactly three embeds are allowed, each with a reason in embedAllowed: repoHandler embeds *vcs.Repo (the documented vcs exception, unexported), gitserve's unexported host embeds *vcs.Repo, and index.SearchResult embeds facts.FactWithBody (a data struct). A stale allowlist entry fails. Sabotaged red: embed *facts.Repo in repoHandler, alias+embed *mergeRepo, remotesync.Repo embedding *merge.Repo again, and removing an allowlisted embed.

DOES NOT MEAN: that the guard covers embeds in packages outside internal/store (internal/repos.FleetMemberRow embeds fleetrec.Member, a data struct), nor that same-package embeds are banned (index.Facade embeds its four sub-services by design).

# Path-keyed registry binds *repoHandler to SQLite connections lazily

The first_parent_chain vtab cursor needs access to a *repoHandler (go-git) to walk parents, but the ConnectHook fires at sql.Open time — BEFORE Service constructs the repoHandler. To sidestep this bootstrap ordering, internal/store/vtab_first_parent.go maintains a process-wide map[dbPath]*repoHandler (vtabRegistry, guarded by sync.RWMutex). store.Open calls bindVTabRepo(path, rh) after newRepoHandler; Service.Close calls unbindVTabRepo. The vtab cursor calls lookupVTabRepo(dbPath) lazily in its Filter method. The connection's db path is obtained via 'PRAGMA database_list' (column 'file' at index 2). In-memory dbs (':memory:') have empty path — bind/unbind/lookup must no-op gracefully on '', and the vtab will error 'no repoHandler bound' if anyone queries it.

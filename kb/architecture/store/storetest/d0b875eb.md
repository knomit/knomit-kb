# Guard B1 lists every main package (tools/appcast, okf and relnotes were missing) and a completeness test fails on an unlisted one; guard B2 flags bare identifiers, not only bare calls

(PR E7c, #585, merged into dev as 8bcd5449; re-read there.) B1: before E7c, shippedGroups named knomit, tools/bridge, tools/calibrate, tools/fetchlibs and tools/desktop, so a blank import of storetest in tools/appcast, tools/okf or tools/relnotes was not caught. They are listed now, and TestShippedGroupsListEveryMainPackage runs go list over ./... (default tags and desktop) and fails on a main package no group names, so the next new binary cannot be forgotten. Sabotage: a blank storetest import in each of the three tools is red; an unlisted tools/newbin main is red.

B2: seamUses used to flag selectors x.FooForTest / x.TestingFoo and bare CALLS FooForTest(...). It now flags every bare identifier matching the seam name that is not a declaration (func, type, var, field and parameter names, := targets are skipped, selector halves are reported by the selector case), so a function value (f := SetRefForTest), an argument (run(SetRefForTest)) and a dot-imported use are red. Sabotaged: all three shapes in internal/corpus/repos. An identifier that is only declared (a struct field or parameter named like a seam) is clean.

DOES NOT MEAN: the guard resolves types. It matches names, so a production identifier that happens to be named [A-Z]*ForTest is flagged whatever it is.

AT 14c (PR #632, merged as ee850fd6; re-read there): B2 (TestTestSeamsNotReachedFromProduction) also guards the trigger child's doors. Every *ForTest identifier in internal/corpus/repos/trigger/testseams.go (functions, methods and the three consts RecipeWaitDelayForTest, RecipeOutputCapForTest, P95WindowForTest) is listed in triggerSeams (test/archtest/test_seams_test.go), and a new test TestTriggerSeamsDeclaredInTestseams requires each to be declared once, in that file, with mustBeTest as its first statement (an unlisted *ForTest there fails). Sabotage run by the reviewer against the commit: `_ = d.SlowForTest` in internal/corpus/repos/stages.go is red ('stages.go line 753: uses SlowForTest'), and removing mustBeTest("IdentityForTest") is red ('must start with mustBeTest'). CONSEQUENCE: a new trigger test door goes in testseams.go AND triggerSeams in the same PR (kb/gotchas/repos/triggers/testing/testseams/73ec836f.md).

# Guard B1 lists every main package (tools/appcast, okf and relnotes were missing) and a completeness test fails on an unlisted one; guard B2 flags bare identifiers, not only bare calls

B1: before E7c, shippedGroups named knomit, tools/bridge, tools/calibrate, tools/fetchlibs and tools/desktop, so a blank import of storetest in tools/appcast, tools/okf or tools/relnotes was not caught. They are listed now, and TestShippedGroupsListEveryMainPackage runs go list over ./... (default tags and desktop) and fails on a main package no group names, so the next new binary cannot be forgotten. Sabotage: a blank storetest import in each of the three tools is red; an unlisted tools/newbin main is red.

B2: seamUses used to flag selectors x.FooForTest / x.TestingFoo and bare CALLS FooForTest(...). It now flags every bare identifier matching the seam name that is not a declaration (func, type, var, field and parameter names, := targets are skipped, selector halves are reported by the selector case), so a function value (f := SetRefForTest), an argument (run(SetRefForTest)) and a dot-imported use are red. Sabotaged: all three shapes in internal/repos. An identifier that is only declared (a struct field or parameter named like a seam) is clean.

DOES NOT MEAN: the guard resolves types. It matches names, so a production identifier that happens to be named [A-Z]*ForTest is flagged whatever it is.

# internal/store/storetest holds every test door into a *store.Service as a function taking the Service; the store registers Service-to-child-handle lookups from its init, each child's getter calls mustBeTest, and two archtests keep it out of production; it is a test package, not an API

WHAT IT IS. internal/store/storetest (PR E1, #574, merged into dev as 6244da58) is the one package outside package store that tests import to reach a Service's internals: SetRef, DeleteRef, CommitFiles (commit without NotifyCommit or the index), RawWrite (commit malformed fact content), RawSymlink, RawDB, DeleteObject, FetchRefspecs, RemoteURLs, SetExperimentActivity, and the three process-wide installers SetFallbackSigner, SetFallbackAgentID, SetFastDurability. The Service has NO test-only method any more (Testing*, *ForTest) and the parent has no vcs_testhooks.go; the old names are gone, not forwarded.

THE HOOK. storetest cannot read Service.rh or Service.fi (different package) and the Service must not return them (a value of an internal/ type crossing the store boundary is the leak the E2 de-embed closed). So package store registers, once, from init (internal/store/testseams_register.go), a func mapping a *Service passed as any to its child handle, in three places: vcs.RegisterServiceRepo -> vcs.ServiceRepoForTest (the *vcs.Repo), facts.RegisterServiceIndex -> facts.ServiceIndexForTest (the *facts.Index, for RawWrite), merge.RegisterServiceRepo -> merge.ServiceRepoForTest (for SetExperimentActivity). Each getter calls mustBeTest and panics outside a test binary, and a second registration panics. storetest imports store, vcs, facts, merge and sqlite (it lives under internal/store, so the internal rule allows it); the SetFallback*/SetFastDurability installers call vcs/sqlite's own test-binary-only setters directly.

GUARDS. (1) storetest's init panics unless testing.Testing(). (2) TestHarnessNotLinkedIntoShippedBinaries lists knomit/internal/store/storetest in its forbidden set, so no shipped binary's go list -deps may contain it. (3) TestTestSeamsNotReachedFromProduction (test/archtest/test_seams_test.go) parses every non-_test.go file with go/ast and fails on an import of storetest or a selector or bare call named [A-Z]*ForTest or Testing[A-Z]* outside internal/store/storetest, test/, internal/testsupport/ and internal/store/**/testseams.go; it asserts >=500 files scanned, >=12 allowed uses, and that storetest still uses the eleven named doors, and TestTestSeamsGuard_Discriminates runs the detector on inline source. (4) TestFallbackSigner/AgentID/FastDurability archtests now allow the definition files plus storetest.go. (5) TestLayers lists storetest -> facts, merge, internal/vcs, internal/sqlite, but TestLayers is report-only today (enforceLayers=false in test/archtest/layers_test.go), so its storetest edges document intent and do not enforce it.

IN-PACKAGE TESTS. Tests in package store cannot import storetest (storetest imports store: cycle). They call the child seam through svc.rh (svc.rh.CommitFilesForTest, svc.rh.RawSymlinkForTest, svc.rh.Storer().DeleteObjectForTest) and vcs.SetTestFallbackSigner / sqlite.SetTestFastDurability directly.

CONSEQUENCE. A new test door for a Service goes in the owning child's testseams.go behind that child's mustBeTest, plus one storetest function that calls it; never as a Service method and never as an exported accessor on the Service. A test outside the store imports storetest; a test inside package store uses the child seam.

KNOWN GAP (verified at 6244da58). No guard checks that the hook getters (vcs.ServiceRepoForTest, facts.ServiceIndexForTest, merge.ServiceRepoForTest) still call mustBeTest: a reviewer sabotage that removed the call from a getter was not caught by any test. Mitigation: B2 (TestTestSeamsNotReachedFromProduction) still catches any production use of those getters by name, and storetest's init panics outside a test binary and B1 keeps it out of shipped binaries, so the missing mustBeTest alone does not open a production path; it removes only the getter's own last-line panic. Do not read 'each getter calls mustBeTest' as enforced by a test.

MISREADINGS. storetest is NOT a production API and NOT a facade over the Service: it forwards to nothing in the Service, it does the one thing the Service refuses to do (hand a test the child handle). Do not import it from non-test code to 'reuse' a helper (B2 fails, and a binary that links it dies in init). It is not a place for general test fixtures (that is test/testenv). The testsigner and testenv packages import it because they are test-only trees.

# Service.DropBranch and Service.SetDefaultBranch are deleted: storetest.DropBranch and storetest.SetDefaultBranch are the test doors, and no production code outside the store drops a branch or sets HEAD

VERIFIED at origin/dev 32414d74 before the move: every caller of Service.DropBranch and Service.SetDefaultBranch was a _test.go file (internal/mcp, internal/repos, internal/store) or test/testenv/branch_lifecycle.go; the store's own production paths call the vcs handle (merge's experiment drop calls rh.vr.DropBranch). PR E7c (#585, merged into dev as 8bcd5449; re-read there) deleted both Service methods and added storetest.DropBranch(ctx, svc, name) and storetest.SetDefaultBranch(svc, branch), which call vcs.ServiceRepoForTest(svc) (mustBeTest). Tests inside package store cannot import storetest (cycle) and call svc.rh.DropBranch / svc.rh.SetDefaultBranch. The vcs.Repo methods keep their names; only the Service forward is gone. Service.FleetPKIAt was deleted in the same PR (its only caller was one store test, now FleetAt(branch).PKI).

CONSEQUENCE: a new production need to drop a branch from outside the store must be a Service method with its own reason (the vcs-backed-operation exception), not a revival of this forward. DOES NOT MEAN storetest is a production API: B1 and B2 still keep it out of shipped binaries and production source.

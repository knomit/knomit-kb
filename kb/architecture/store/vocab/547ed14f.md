# RebuildAliases records alias method per CLUSTER, not per spelling: every member of a judge-merged cluster is 'judge' with that merge's rationale, mechanical clusters are 'canonical', and a spelling written after the last rebuild has no alias row

In internal/engine/store/vocab/motif_alias.go, methodFor(clusterKey, mergedKeys) decides the method for a whole cluster: 'judge' if a recorded judge merge joined it (the cluster key is a merge survivor), otherwise 'canonical' (the mechanical layer alone). RebuildAliases writes one alias row per member spelling, each carrying its cluster's method and the rationale attributed to the cluster. So in a judge-merged cluster EVERY member row is method judge with the merge rationale, including a member that the mechanical layer alone would have grouped. A purely mechanical cluster's rows are 'canonical'. The store never writes a 'mechanical' method; stub vocabularies in old web tests used one.

A spelling written after the last rebuild has no alias row at all: in the web cluster detail its alias item carries no method (an empty one) and no rationale, although it is still a cluster member through the computed key.

CONSEQUENCE: a web test asserting alias methods must expect per-cluster values and must write late spellings AFTER the rebuild to get the no-row case. DOES NOT MEAN that method records which spelling the judge touched.

# store/index holds the search index and the read-side query services as index.Index / FactQuery / GraphStore / HistoryQuery / MethodologyMatcher / Facade, each reaching UP to the one *vcs.Repo (rh.Repo); callers import internal/store/index directly (the parent's index_seam.go and its lowercase aliases were deleted in E6, 7a721802) and the index is not embedded into repoHandler

CURRENT (E6, PR #578, merged as 7a721802): the parent has no index seam; index_seam.go and the lowercase aliases (searchIndex, factQuery, graphStore, historyQuery, methodologyMatcher, searchFacade) are deleted, and callers import knomit/internal/store/index directly (index.X from outside the store, index.X from inside package store). Service holds *index.Index, *index.FactQuery, *index.GraphStore, *index.HistoryQuery, *index.MethodologyMatcher and *index.Facade. Everything below that describes THE SEAM, the aliases or the re-exports as the parent's is HISTORICAL as of 7a721802; its src ref index_seam.go@8020a455 was dropped because the file no longer exists. store.Replay takes *index.FactsIter (the FactIter interface is gone).

Since PR 10 of the internal/ hierarchy stack (PR #557, merged into dev as 8020a455; branch refactor/hier-10-index), the store's index cluster is the package internal/store/index (a sibling of facts and merge, not under internal/). Files moved: search_index.go, search_query.go, search_crud.go, search_graph.go, search_graph_query.go, search_history.go, index.go, highlights.go, domain_match.go, edge_props.go, derived_from.go, graph_sql.go, similarity_graph.go, subgraph_edges.go, subject_labels.go, token_df.go, blast_radius.go, methodology.go, query_services.go, vec_table.go, path_history.go, history_types.go and textnorm_alias.go (nothing left in package store called it). New: doc.go (constructors and the four production doors), forwards.go (the old unexported sqlite forwards conn, beginTxIfNeeded, float32SliceToBytes, ... under the same names, so the moved bodies did not change) and testseams.go. It imports store/internal/sqlite, store/internal/vcs, store/facts (only FactRecord, FactWithBody, ParseFactRecord) and store/git (the CtxExecer type the graph SQL takes, and WithoutTx); TestLayers lists those four same-layer edges.

THE BOUNDARY. The types are exported under new names: searchIndex is index.Index, factQuery/graphStore/historyQuery/methodologyMatcher are index.FactQuery/GraphStore/HistoryQuery/MethodologyMatcher, searchFacade is index.Facade. Each holds `rh *vcs.Repo`, NOT the parent's repoHandler: every rh.X call the moved files make (DB, BranchID, Embedder, LockBranch, ResolveActiveCommitForPath, CommitLogQuery, ...) was already a vcs.Repo method, so the child calls nothing declared on repoHandler, facts.Repo or merge.Repo. store.Open builds them with index.New(rh.Repo), index.NewFactQuery(rh.Repo), ..., index.NewFacade(fq, gq, hq, mq) at the same point as the old struct literals, and still registers rh.SetOnDrop(si.GC) and rh.SetIndexManager(si) with the same values in the same order. The index is NOT embedded into repoHandler (it was never part of it), so no method-promotion collision is possible. The only production doors added are Index.EnsureFactsVecDefault (Open), Index.SetSyncSuspended (Replay's transient-store suspend; it was a field store) and Index.PersistedEmbedModelID / PersistedEmbedDim (the integrity report), each a one-line call of the unexported core.

THE SEAM (HISTORICAL: internal/store/index_seam.go, deleted in E6 at 7a721802). `type searchIndex = index.Index` and the same for the other five, so Service fields, the interface guards in interface_guards.go and the white-box tests keep their spelling; every public name the moved files declared (SearchResult, SearchOptions, LogEntry, FactsIter, NodeFact, EdgeSimilarTo, MotifMatch*, GraphSchemaVersion, ErrFactNotLive, DomainTagMatches, ...) is re-exported as an alias, a const, the SAME var value, or a one-line forward, so the public surface of package store did not move.

TESTS. Store tests need a full Service, so they stayed in the parent and reach the unexported cores through *ForTest methods and functions in index/testseams.go, each calling mustBeTest (panics outside a test binary): RepoForTest, the four rendezvous hook setters (SetBeforeSimTxHookForTest, SetInSimTxHookForTest, SetInSimEdgeTxHookForTest, SetBeforeGraphTxHookForTest; these were field assignments), SetSubgraphEdgeChunkSizeForTest, SchemaVersionStateForTest (returns "current"/"missing"/"stale"), UpsertForTest, RebuildGraphForTest, the graph SQL primitives (GraphMergeNodeForTest, ...). internal/store/index_testseams_test.go rebinds the free primitives and constants to their old names (graphMergeNode, schemaVersionKey, knnK, schemaMissing, ...), so most test bodies did not change. Pure unit tests with no Service (domain_match_test.go, domain_match_exported_test.go, search_index_refs_test.go, TestSimilarityGraph_DensityAndConnected) moved into the child; total top-level tests 929 before = 920 parent + 9 child after.

SOURCE SCANS that followed the move: internal/synthesize TestConformance_ReviewPipelineOnly allowlists index/vec_table.go (relative to internal/store; it names the restatement_* tables in clearRestatementState) instead of vec_table.go; internal/fact TestMN6_MotifsDoNotDriveMechanics keys internal/store/index/search_query.go. Both were proven on throwaway commits: a restatement_pairs literal in index/search_crud.go fails the first, the old key vec_table.go fails it on index/vec_table.go, a motif-mentioning function in index/search_query.go fails MN6 and the old key fails it as missing.

CONSEQUENCE: new search, graph or history code goes in internal/store/index and reaches up to *vcs.Repo; if it needs a higher cluster it stays a Service/repoHandler method in the parent. A parent test that needs an index internal adds a *ForTest seam that calls mustBeTest. MISREADING: the aliases are not a second implementation, and index.Index is not reachable through repoHandler; code that used rh.<index method> never existed, the parent reaches the index only through Service.si / fq / gq / hq / mq.

# store/index holds the search index and the read-side query services as index.Index / FactQuery / GraphStore / HistoryQuery / MethodologyMatcher / Facade, each reaching UP to the one *vcs.Repo (rh.Repo); callers import internal/store/index directly (the parent's index_seam.go and its lowercase aliases were deleted in E6, 7a721802) and the index is not embedded into repoHandler

CURRENT (E6, PR #578, merged as 7a721802): the parent has no index seam; index_seam.go and the lowercase aliases (searchIndex, factQuery, graphStore, historyQuery, methodologyMatcher, searchFacade) are deleted, and callers import knomit/internal/engine/store/index directly (index.X from outside the store, index.X from inside package store). Service holds *index.Index, *index.FactQuery, *index.GraphStore, *index.HistoryQuery, *index.MethodologyMatcher and *index.Facade. Everything below that describes THE SEAM, the aliases or the re-exports as the parent's is HISTORICAL as of 7a721802; its src ref index_seam.go@8020a455 was dropped because the file no longer exists. store.Replay takes *index.FactsIter (the FactIter interface is gone).

Since PR 10 of the internal/ hierarchy stack (PR #557, merged into dev as 8020a455; branch refactor/hier-10-index), the store's index cluster is the package internal/engine/store/index (a sibling of facts and merge, not under internal/). Files moved: search_index.go, search_query.go, search_crud.go, search_graph.go, search_graph_query.go, search_history.go, index.go, highlights.go, domain_match.go, edge_props.go, derived_from.go, graph_sql.go, similarity_graph.go, subgraph_edges.go, subject_labels.go, token_df.go, blast_radius.go, methodology.go, query_services.go, vec_table.go, path_history.go, history_types.go and textnorm_alias.go (nothing left in package store called it). New: doc.go (constructors and the four production doors), forwards.go (the old unexported sqlite forwards conn, beginTxIfNeeded, float32SliceToBytes, ... under the same names, so the moved bodies did not change) and testseams.go. It imports store/internal/sqlite, store/internal/vcs, store/facts (only FactRecord, FactWithBody, ParseFactRecord) and store/git (the CtxExecer type the graph SQL takes, and WithoutTx); TestLayers lists those four same-layer edges.

THE BOUNDARY. The types are exported under new names: searchIndex is index.Index, factQuery/graphStore/historyQuery/methodologyMatcher are index.FactQuery/GraphStore/HistoryQuery/MethodologyMatcher, searchFacade is index.Facade. Each holds `rh *vcs.Repo`, NOT the parent's repoHandler: every rh.X call the moved files make (DB, BranchID, Embedder, LockBranch, ResolveActiveCommitForPath, CommitLogQuery, ...) was already a vcs.Repo method, so the child calls nothing declared on repoHandler, facts.Repo or merge.Repo. store.Open builds them with index.New(rh.Repo), index.NewFactQuery(rh.Repo), ..., index.NewFacade(fq, gq, hq, mq) at the same point as the old struct literals, and still registers rh.SetOnDrop(si.GC) and rh.SetIndexManager(si) with the same values in the same order. The index is NOT embedded into repoHandler (it was never part of it), so no method-promotion collision is possible. The only production doors added are Index.EnsureFactsVecDefault (Open), Index.SetSyncSuspended (Replay's transient-store suspend; it was a field store) and Index.PersistedEmbedModelID / PersistedEmbedDim (the integrity report), each a one-line call of the unexported core.

THE SEAM (HISTORICAL: internal/store/index_seam.go, deleted in E6 at 7a721802). `type searchIndex = index.Index` and the same for the other five, so Service fields, the interface guards in interface_guards.go and the white-box tests keep their spelling; every public name the moved files declared (SearchResult, SearchOptions, LogEntry, FactsIter, NodeFact, EdgeSimilarTo, MotifMatch*, GraphSchemaVersion, ErrFactNotLive, DomainTagMatches, ...) is re-exported as an alias, a const, the SAME var value, or a one-line forward, so the public surface of package store did not move.

CONSEQUENCE: new search, graph or history code goes in internal/engine/store/index and reaches up to *vcs.Repo; if it needs a higher cluster it stays a Service/repoHandler method in the parent. UPDATE (E8, refactor/store-e8-interfaces, PR #580, merged into dev as 0c24a7ab; re-read at 0c24a7ab): index.Overrides and Facade.SetOverridesForTest (index/testseams.go, mustBeTest) are the test-only way to observe, fail or wrap the READ services of one store. FactQuery, GraphStore, HistoryQuery and MethodologyMatcher each carry `ov atomic.Pointer[Overrides]` (nil in production, set by SetOverridesForTest on all four, which returns a restore func) and call `probe("<Method>")` first in each of their 28 public reads. Overrides has three fields:
- Reads func(method string) error: the observer, strict-mode and failure-injection hook. For SimilarityAdjacency, ReverseDependentPaths, TokenDF and SubgraphEdges the returned error reaches the caller; for the other 24 reads the return value is ignored, so Reads there is an observer only.
- Search func(next SearchFunc) SearchFunc: wraps FactQuery.Search. FactQuery.Search is a thin entry over the unexported fq.search (search_query.go); the search body did not change.
- SubgraphEdges: replaces the clustering edge read ScopedCluster feeds to Louvain (one scripted answer; see the E8 test-doubles decision in kb/decisions/store/pr-e/ for why it is the one canned graph answer).
SCOPE: installed through any accessor (Service.Search, FactQuery, GraphStore, HistoryQuery, Methodology) it applies to the whole store, including other goroutines; install before concurrent use and restore at test end.
NESTED CALLS: probes and the Search wrapper fire on nested calls too. ExplainFact calls IncomingAtCommit and OutgoingAtCommit (three probes for one call), and RecentFacts reaches FactQuery.Search through recentFactsSearch, so a Search wrapper also changes what RecentFacts returns. A strict policy must allow the nested names too.
ENFORCED: internal/engine/store/index/probe_guard_test.go (go/ast) asserts every exported method of FactQuery, GraphStore, HistoryQuery and MethodologyMatcher begins with `<recv>.probe("<its own name>")` and counts exactly 28 (require.Equal(28, seen)); a read added without its probe, or probing under another name, fails it. The sabotage forms (remove one probe; misspell one) were run by the E8 worker, not by the curator. CONSEQUENCE: adding a public read to one of the four services means adding its probe and raising the count.
MISREADING: Overrides cannot supply canned similarity graphs, document frequencies, reverse dependents or FactExistsAt answers; a test that needs those seeds real facts and real graph edges (internal/corpus/synthesize/graph_env_test.go).

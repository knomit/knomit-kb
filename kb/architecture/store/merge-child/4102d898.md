# store/merge holds branch merges, the conflict strategies, the pushed-branch merge core and the experiment lifecycle as merge.Repo; Service.Merge() hands out the *merge.Repo, the five lock-assuming cores are guarded by TestStoreMergeCores_OnlyInsideStore, and Service.MergePushed / MergeConsensus stay in the parent as orchestration

Since PR 09b of the internal/ hierarchy stack (PR #556, merged into dev as d4fbf2fb after 09-facts), the merge cluster is the package internal/engine/store/merge (a sibling of git, migrate, fleetrec, verify and facts, not under internal/). Files: branch_merge.go (MergeBranch, MergeIntoBranchLocked / MergeIntoBranchLockedOpts, MergeTreesWithStrategy, detectConflicts, applyResolution, mergeFactsInvalid, the MergeOpts struct), conflict_merge.go (the `conflicts` strategy: ConflictsPolicy / ConflictsPolicyOf, FactMerge, FactMergeResolutions, ConflictsStrategy, AppendTrailerLines, TrailerValues), pushed_merge.go (private-path guard, merge-only detection, BranchMovedError, PushedBranchInfo), experiment.go (OpenExperiment, CommitExperiment, SyncExperiment, RollbackExperiment, ExpireExperiments, MergeConflictError, Resolution), experiment_rewind.go (MarkExperimentsRewound, rebuildRewoundExperiment), merge_types.go (Mode, AgentReconcileResult, ConflictStrategy and the Strategy* consts), repo.go and testseams.go. It imports store/internal/sqlite, store/internal/vcs, store/verify and fact; it does NOT import facts (nothing in the moved files needs it, although the proposal's arrow lists facts). TestLayers lists store/merge -> store/internal/sqlite, -> store/internal/vcs and -> store/verify as same-layer edges.

THE SEAM (HISTORICAL in full as of PR E4, f3c32912: merge_seam.go no longer exists and its re-exports are deleted; since E2 merge.Repo is `struct{ vr *vcs.Repo }`, not `struct{ *vcs.Repo }`; the repoHandler still embeds *mergeRepo, the alias kept in vcs_seam.go until E7; read the rest of this paragraph as the hier-09b design, not the current code). Every method of the cluster is declared on merge.Repo, which is `struct{ *vcs.Repo }`. The parent's repoHandler is `struct{ *vcs.Repo; *factsRepo; *mergeRepo }` (internal/engine/store/vcs_seam.go; `type mergeRepo = merge.Repo` in merge_seam.go names the embedded field), and newRepoHandler wraps the ONE vcs.Repo pointer with merge.NewRepo, so rh.MergeBranch, rh.OpenExperiment and the BranchIndex / ExperimentIndex guards work by promotion. merge_seam.go re-exports only the names callers outside store use (AgentReconcileResult, ConflictStrategy, Mode*, Strategy*, Resolution, ResolveSrc/Dst, MergeConflictError, BranchMovedError, PrivatePathMergeError, PushedBranchInfo, the Err* sentinels, TrailerMerge/TrailerConflict, TrailerValues, MaxExperimentNameLen) as aliases, consts, the SAME error values and a forward. The names only the parent's own files need (merge.MergeOpts, merge.FactMerge, merge.ConflictsPolicyOf, merge.AppendTrailerLines) are spelled with the package qualifier in the parent and are NOT re-exported, so the store's public surface did not grow.

WHAT STAYED IN THE PARENT (HISTORICAL in full as of PR E4, f3c32912: Service.PushedBranches no longer exists, service_merge.go holds only MergePushed, MergeConsensus and hostConflictStrategy, and consensus_branch.go is not logic any more; see the PR E4 paragraph below): service_merge.go (Service.MergePushed and Service.MergeConsensus take the dst lock with rh.LockBranch, pick the host's strategy with hostConflictStrategy and call rh.MergeIntoBranchLockedOpts with a merge.MergeOpts; Service.PushedBranches is a one-line forward to merge.Repo.PushedBranches since PR D of the parent slimming), consensus_branch.go (Service-level, counted as facade), remote_reconcile*.go, remote_sync.go and the receive-pack handler (the sync and gitserve clusters, which call the exported cores: MergeIntoBranchLocked, MergeTreesWithStrategy, FactMergeResolutions, ConflictsStrategy, MarkExperimentsRewound). The lock order (dst lock, then NotifyCommit under it), tx scope and hook timing are unchanged because embedding is not virtual and the child never calls a method declared on the parent's repoHandler. No hook func and no ordering change was needed.

TEST SEAMS. Parent tests reach the unexported cores through guarded `*ForTest` functions in merge/testseams.go, each calling mustBeTest (panics outside a test binary): Repo.MergeIntoBranchForTest, Repo.MergeIntoBranchResolvedForTest, SetOpenExperimentForkedHookForTest (the hook that was the package var testHookOpenExperimentForked), ExperimentRewoundRefNameForTest and ConflictsStrategyForTest. TestConflictsPolicy_StrategyRoundTrip moved into the child (it builds the unexported policy struct); the parent test file conflict_merge_test.go carries its own blobName so the trailer format is stated independently.

CONSEQUENCE: a new merge door goes in merge; a caller that must hold the dst lock across other store work stays a Service or repoHandler method in the parent and calls the exported core. MISREADING: MergeOpts' fields are exported only because the parent builds the options; GuardPrivate and ValidateFacts are set by exactly the two routes into the host's agent branch (MergePushed and MergeConsensus) and must not be set by a new caller to 'be safe', because they make the merge refuse, not succeed.

UPDATE (refactor-store-slim-d-orchestration, parent slimming PR D; HISTORICAL in full as of PR E4, f3c32912: the Service.PushedBranches forward and the Service.SetExperimentActivityForTest forward are both deleted, callers use svc.Merge().PushedBranches and storetest.SetExperimentActivity): merge.Repo.PushedBranches (pushed_merge.go) holds the body of the pushed-branches report, moved verbatim from the parent; Service.PushedBranches forwards to it. Its only production caller is internal/edge/web/handlers_pushed_branches.go (handleHALPushedBranches); the only caller in internal/corpus/repos is a test (consensus_test.go), and internal/engine/store/pushed_merge_test.go also calls it. SetExperimentActivityForTest's body is merge.Repo.SetExperimentActivityForTest in merge/testseams.go, guarded by mustBeTest; [HISTORICAL as of PR E1, 6244da58: Service.SetExperimentActivityForTest no longer exists; see the PR E1 paragraph below.] Service.SetExperimentActivityForTest stayed at PR D as a one-line forward in service_merge.go because the sweeper's tests live in internal/corpus/repos (experiment_sweep_test.go) and Service exposes no accessor to the merge.Repo behind rh, so they have no other way to reach it. It is NOT because internal/corpus/repos cannot import the package: store/merge is not under an internal/ directory and is importable (only store/internal/vcs is closed to outside callers, which is the reason the vcs *ForTest forwards stay). MergePushed, MergeConsensus and hostConflictStrategy stay in the parent as wrappers because they need Service.UpstreamBranch.

UPDATE (refactor/store-e2-unembed-vcs, PR #573; verified on the branch head 08775aeb): merge.Repo is no longer `struct{ *vcs.Repo }`; it is `struct{ vr *vcs.Repo }`, a named unexported field, so no vcs.Repo method is promoted onto merge.Repo. Inside merge every git-layer call is rh.vr.X (rh.vr.LockBranch in mergeIntoBranch, rh.vr.NotifyCommit after the ref move); lock order and hook timing are unchanged. The parent's repoHandler still embeds both *vcs.Repo and *mergeRepo, so the parent's rh.MergeBranch and rh.LockBranch resolve as before. The exported lock-assuming cores (MergeIntoBranchLocked, MergeIntoBranchLockedOpts, MergeTreesWithStrategy, MarkExperimentsRewound, FactMergeResolutions) stay exported because remotesync calls them; the 'merge.Repo is struct{ *vcs.Repo }' sentence in THE SEAM paragraph above is historical. The 'stay exported because remotesync calls them' list is not the whole caller set: MergeIntoBranchLockedOpts is also called by the PARENT (service_merge.go, Service.MergePushed and Service.MergeConsensus, through rh.MergeIntoBranchLockedOpts) and by merge's own experiment.go; remotesync itself calls MergeIntoBranchLocked (remote_reconcile_merge.go), MergeTreesWithStrategy, FactMergeResolutions and MarkExperimentsRewound (remote_reconcile_rebase.go) and ConflictsStrategy (remote_sync.go). Do not unexport MergeIntoBranchLockedOpts on the grounds that only remotesync needs it. TestChildRepos_DoNotEmbedVcsRepo fails if the embed returns, as a pointer or by value. Verified at the PR #573 merge 2a5bcadf.

UPDATE (refactor/store-e4-merge-handles, PR E4, #576, merged into dev as f3c32912; verified at the merge commit, and the branch heads 68b08ba4 and 7ddf219f are ancestors of it): the merge child is handed out. Service.Merge() returns the *merge.Repo (the repoHandler's embedded mergeRepo, the same pointer MergePushed and the reconcile paths use). merge_seam.go is deleted (the aliases, consts, error vars and the TrailerValues forward); callers import knomit/internal/engine/store/merge for Mode*, Strategy*, Resolve*, AgentReconcileResult, ConflictStrategy, Resolution, MergeConflictError, PrivatePathMergeError, BranchMovedError, PushedBranchInfo, SettledPath, the Err* sentinels and Trailer*. Service.Experiments, Service.PushedBranches and the store.ExperimentIndex interface are deleted; the experiment lifecycle is svc.Merge().OpenExperiment / ListExperiments / CommitExperiment / SyncExperiment / RollbackExperiment / ExpireExperiments, and svc.Merge().PushedBranches. BranchIndex lost MergeBranch (now svc.Merge().MergeBranch) and gained GetExperiment, a vcs read (svc.Branches().GetExperiment). Service.MergePushed and Service.MergeConsensus STAY: they take the destination lock with rh.LockBranch, resolve the consensus branch (Service.UpstreamBranch) to pick the host's conflict strategy, and call rh.MergeIntoBranchLockedOpts; that is orchestration, not a forward. Service.OntologyAt and OntologyFileAt (vcs reads) moved from service_merge.go to service_vcs.go. The 'No exported Service accessor returns the merge handle' sentence in the PR E1 paragraph above is HISTORICAL.

LOCK-ASSUMING EXPORTS. Handing out *merge.Repo exposes its exported methods. The five that assume the caller holds the destination branch's lock (MergeIntoBranchLocked, MergeIntoBranchLockedOpts, MergeTreesWithStrategy, MarkExperimentsRewound, FactMergeResolutions) stay exported because remotesync (and, for MergeIntoBranchLockedOpts, the parent's MergePushed/MergeConsensus) call them; test/archtest TestStoreMergeCores_OnlyInsideStore fails on any selector of them in a .go file outside internal/engine/store/** (tests included). MergeBranch, the experiment lifecycle and PushedBranches take their own locks or only read. ConflictsStrategy is a read of the ontology at a branch tip (conflict_merge.go resolves the ref, reads the commit's ontology and logs once per bad blob; it takes no lock); it is newly reachable from outside the store and is not lock-assuming, and it has NO guard: that is accepted, not an oversight, and it is deliberately not in mergeCores. The three ForTest methods on merge.Repo (MergeIntoBranchForTest, MergeIntoBranchResolvedForTest, SetExperimentActivityForTest) call mustBeTest and are covered by TestTestSeamsNotReachedFromProduction. MISREADING: a caller outside the store that wants a merge under the lock uses MergeBranch, MergePushed or MergeConsensus; it does not call a Locked core after taking LockBranch itself, because it cannot (the vcs handle is not handed out).

TEST HOOK. merge.RegisterServiceRepo and merge.ServiceRepoForTest are deleted; storetest.SetExperimentActivity calls s.Merge().SetExperimentActivityForTest. The TestLayers edge storetest -> store/merge is deleted.

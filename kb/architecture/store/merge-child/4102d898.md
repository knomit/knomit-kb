# store/merge holds branch merges, the conflict strategies, the pushed-branch merge core and the experiment lifecycle as merge.Repo; repoHandler embeds *merge.Repo as `mergeRepo` beside *vcs.Repo, the Service-level MergePushed / MergeConsensus and the reconcile paths stay in the parent and call exported cores

Since PR 09b of the internal/ hierarchy stack (PR #556, merged into dev as d4fbf2fb after 09-facts), the merge cluster is the package internal/store/merge (a sibling of git, migrate, fleetrec, verify and facts, not under internal/). Files: branch_merge.go (MergeBranch, MergeIntoBranchLocked / MergeIntoBranchLockedOpts, MergeTreesWithStrategy, detectConflicts, applyResolution, mergeFactsInvalid, the MergeOpts struct), conflict_merge.go (the `conflicts` strategy: ConflictsPolicy / ConflictsPolicyOf, FactMerge, FactMergeResolutions, ConflictsStrategy, AppendTrailerLines, TrailerValues), pushed_merge.go (private-path guard, merge-only detection, BranchMovedError, PushedBranchInfo), experiment.go (OpenExperiment, CommitExperiment, SyncExperiment, RollbackExperiment, ExpireExperiments, MergeConflictError, Resolution), experiment_rewind.go (MarkExperimentsRewound, rebuildRewoundExperiment), merge_types.go (Mode, AgentReconcileResult, ConflictStrategy and the Strategy* consts), repo.go and testseams.go. It imports store/internal/sqlite, store/internal/vcs, store/verify and fact; it does NOT import facts (nothing in the moved files needs it, although the proposal's arrow lists facts). TestLayers lists store/merge -> store/internal/sqlite, -> store/internal/vcs and -> store/verify as same-layer edges.

THE SEAM. Every method of the cluster is declared on merge.Repo, which is `struct{ *vcs.Repo }`. The parent's repoHandler is `struct{ *vcs.Repo; *factsRepo; *mergeRepo }` (internal/store/vcs_seam.go; `type mergeRepo = merge.Repo` in merge_seam.go names the embedded field), and newRepoHandler wraps the ONE vcs.Repo pointer with merge.NewRepo, so rh.MergeBranch, rh.OpenExperiment and the BranchIndex / ExperimentIndex guards work by promotion. merge_seam.go re-exports only the names callers outside store use (AgentReconcileResult, ConflictStrategy, Mode*, Strategy*, Resolution, ResolveSrc/Dst, MergeConflictError, BranchMovedError, PrivatePathMergeError, PushedBranchInfo, the Err* sentinels, TrailerMerge/TrailerConflict, TrailerValues, MaxExperimentNameLen) as aliases, consts, the SAME error values and a forward. The names only the parent's own files need (merge.MergeOpts, merge.FactMerge, merge.ConflictsPolicyOf, merge.AppendTrailerLines) are spelled with the package qualifier in the parent and are NOT re-exported, so the store's public surface did not grow.

WHAT STAYED IN THE PARENT: service_merge.go (Service.MergePushed and Service.MergeConsensus take the dst lock with rh.LockBranch, pick the host's strategy with hostConflictStrategy and call rh.MergeIntoBranchLockedOpts with a merge.MergeOpts; Service.PushedBranches is a one-line forward to merge.Repo.PushedBranches since PR D of the parent slimming), consensus_branch.go (Service-level, counted as facade), remote_reconcile*.go, remote_sync.go and the receive-pack handler (the sync and gitserve clusters, which call the exported cores: MergeIntoBranchLocked, MergeTreesWithStrategy, FactMergeResolutions, ConflictsStrategy, MarkExperimentsRewound). The lock order (dst lock, then NotifyCommit under it), tx scope and hook timing are unchanged because embedding is not virtual and the child never calls a method declared on the parent's repoHandler. No hook func and no ordering change was needed.

TEST SEAMS. Parent tests reach the unexported cores through guarded `*ForTest` functions in merge/testseams.go, each calling mustBeTest (panics outside a test binary): Repo.MergeIntoBranchForTest, Repo.MergeIntoBranchResolvedForTest, SetOpenExperimentForkedHookForTest (the hook that was the package var testHookOpenExperimentForked), ExperimentRewoundRefNameForTest and ConflictsStrategyForTest. TestConflictsPolicy_StrategyRoundTrip moved into the child (it builds the unexported policy struct); the parent test file conflict_merge_test.go carries its own blobName so the trailer format is stated independently.

CONSEQUENCE: a new merge door goes in merge; a caller that must hold the dst lock across other store work stays a Service or repoHandler method in the parent and calls the exported core. MISREADING: MergeOpts' fields are exported only because the parent builds the options; GuardPrivate and ValidateFacts are set by exactly the two routes into the host's agent branch (MergePushed and MergeConsensus) and must not be set by a new caller to 'be safe', because they make the merge refuse, not succeed.

UPDATE (refactor-store-slim-d-orchestration, parent slimming PR D): merge.Repo.PushedBranches (pushed_merge.go) holds the body of the pushed-branches report, moved verbatim from the parent; Service.PushedBranches forwards to it. Its only production caller is internal/web/handlers_pushed_branches.go (handleHALPushedBranches); the only caller in internal/repos is a test (consensus_test.go), and internal/store/pushed_merge_test.go also calls it. SetExperimentActivityForTest's body is merge.Repo.SetExperimentActivityForTest in merge/testseams.go, guarded by mustBeTest; Service.SetExperimentActivityForTest stays as a one-line forward in service_merge.go because the sweeper's tests live in internal/repos (experiment_sweep_test.go) and Service exposes no accessor to the merge.Repo behind rh, so they have no other way to reach it. It is NOT because internal/repos cannot import the package: store/merge is not under an internal/ directory and is importable (only store/internal/vcs is closed to outside callers, which is the reason the vcs *ForTest forwards stay). MergePushed, MergeConsensus and hostConflictStrategy stay in the parent as wrappers because they need Service.UpstreamBranch.

UPDATE (refactor/store-e2-unembed-vcs, PR #573; verified on the branch head 08775aeb): merge.Repo is no longer `struct{ *vcs.Repo }`; it is `struct{ vr *vcs.Repo }`, a named unexported field, so no vcs.Repo method is promoted onto merge.Repo. Inside merge every git-layer call is rh.vr.X (rh.vr.LockBranch in mergeIntoBranch, rh.vr.NotifyCommit after the ref move); lock order and hook timing are unchanged. The parent's repoHandler still embeds both *vcs.Repo and *mergeRepo, so the parent's rh.MergeBranch and rh.LockBranch resolve as before. The exported lock-assuming cores (MergeIntoBranchLocked, MergeIntoBranchLockedOpts, MergeTreesWithStrategy, MarkExperimentsRewound, FactMergeResolutions) stay exported because remotesync calls them; the 'merge.Repo is struct{ *vcs.Repo }' sentence in THE SEAM paragraph above is historical. The 'stay exported because remotesync calls them' list is not the whole caller set: MergeIntoBranchLockedOpts is also called by the PARENT (service_merge.go, Service.MergePushed and Service.MergeConsensus, through rh.MergeIntoBranchLockedOpts) and by merge's own experiment.go; remotesync itself calls MergeIntoBranchLocked (remote_reconcile_merge.go), MergeTreesWithStrategy, FactMergeResolutions and MarkExperimentsRewound (remote_reconcile_rebase.go) and ConflictsStrategy (remote_sync.go). Do not unexport MergeIntoBranchLockedOpts on the grounds that only remotesync needs it. TestChildRepos_DoNotEmbedVcsRepo fails if the embed returns, as a pointer or by value. Verified at the PR #573 merge 2a5bcadf.

# facts.domain/entities JSON columns preserved; junction tables added for indexed filtering only

facts.domain and facts.entities JSON columns are PRESERVED for API compatibility (serialization, frontmatter round-trip). Indexed filtering uses junction tables: fact_entities(fact_id, entity, COLLATE NOCASE) and fact_domains(fact_id, domain, COLLATE NOCASE), both with indexes on the value column. Upsert populates BOTH the JSON column AND the junction tables. Search queries use junction subqueries (e.g. WHERE EXISTS (SELECT 1 FROM fact_entities WHERE fact_id = f.id AND entity = ?)) instead of json_each EXISTS — ~10-100x faster on large repos. The dead matchesFilters function and its test file are deleted (replaced by SQL filtering). Anti-pattern: do NOT query the JSON columns with json_each for filtering — use the junction tables. CASCADE deletes on facts.id automatically clean up junction rows.

A THIRD junction table was added in PR #70 (migration 000008): fact_domain_tokens(fact_id, domain, token, PRIMARY KEY(fact_id, domain, token)) with an index on token. Unlike fact_domains (which stores one row per RAW authored domain string), fact_domain_tokens stores one row per (fact, CANONICAL domain, stemmed token) and powers de-hyphenized, order-independent, plural-stemmed token-containment matching. It is rebuilt wholesale by repopulateDomainTokens (index.Index since #557) for EVERY fact version (HEAD + historical) during Rebuild phase 1, and is content-self-contained (never joined back to fact_domains). See the domain token-containment matching fact for the algorithm and the GraphSchemaVersion fact for why a rebuild is forced. fact_domains itself stays RAW + immutable; only the derived token table is canonical.

WHAT THIS DOES NOT MEAN: fact_domain_tokens is NOT tied to schema version '3' forever — it was introduced under GraphSchemaVersion v3, but the constant has since advanced (to '7' at dev tip d73aad37, in internal/engine/store/index/search_index.go). It is derived state regenerated by whatever forces the next Rebuild — a GraphSchemaVersion bump OR (since v4) an embedding-identity change — not a fixed 'v3' gate.

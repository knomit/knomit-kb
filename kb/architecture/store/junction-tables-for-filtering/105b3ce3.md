# facts.domain/entities JSON columns preserved; junction tables added for indexed filtering only

facts.domain and facts.entities JSON columns are PRESERVED for API compatibility (serialization, frontmatter round-trip). Indexed filtering uses new junction tables: fact_entities(fact_id, entity, COLLATE NOCASE) and fact_domains(fact_id, domain, COLLATE NOCASE), both with indexes on the value column. Upsert populates BOTH the JSON column AND the junction tables. Search queries use junction subqueries (e.g. WHERE EXISTS (SELECT 1 FROM fact_entities WHERE fact_id = f.id AND entity = ?)) instead of json_each EXISTS — ~10-100x faster on large repos. The dead matchesFilters function and its test file are deleted (replaced by SQL filtering). Anti-pattern: do NOT query the JSON columns with json_each for filtering — use the junction tables. CASCADE deletes on facts.id automatically clean up junction rows.

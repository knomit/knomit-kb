# Derived SQLite index state is regenerated from git, never data-migrated — new derived shapes ship an empty-table migration + a GraphSchemaVersion bump

CROSS-CUTTING PATTERN (synthesized from the rebuild + domain-matching facts): every piece of SQLite-side state that is DERIVED from the git fact tree — facts rows, facts_vec embeddings, the cypher graph, fact_domains/fact_entities junctions, and (PR #70) fact_domain_tokens — is treated as rebuildable cache, never as a thing to migrate data into. Git is the only source of truth.\n\nTHE RECIPE for changing the shape of derived state (e.g. adding a new derived table or changing how an existing one is computed):\n1. Ship a numbered .up.sql migration that creates ONLY the empty table/index shape — NO data backfill in the migration. (migration 000008's own comment: 'Derived index state: rebuilt from git, no data backfill needed here; next rebuild populates it.')\n2. BUMP the searchIndex.GraphSchemaVersion constant. Persisted in meta.graph_schema_version (global to the DB) after each successful Rebuild.\n3. The version mismatch is detected at startup (NeedsRebuild) and triggers a full, rowid-preserving Rebuild (ON CONFLICT(path,blob_hash) DO UPDATE) that regenerates ALL derived state from the git tree + commit_log. Rowid preservation means embeddings survive — the heal does not re-embed.\n\nWHY this works and is safe: because the data is reconstructable from git, a full reindex is ALWAYS a valid no-data-loss operation, so the team never has to write (and test) a forward data-migration for derived state — the migration files carry only schema shape, and correctness of derived content lives in ONE place (the rebuild path). This is the operational form of the philosophy 'git is the only source of truth; everything else is rebuildable cache'. Contrast: AUTHORED state (facts.domain/entities JSON, raw immutable fact_domains rows) is NOT rebuilt-and-replaced this way — it round-trips from the markdown and is left immutable; only the CANONICAL/derived projections of it are regenerated.

# Remote operations live on remoteIndex accessed via svc.Remote(), NOT directly on *Service

GetRemote, SetRemote, Sync, Push, threeWayMerge live on *remoteIndex (internal/store/remote.go + remote_sync.go), exposed via `Service.Remote() RemoteIndex`. Callers MUST use svc.Remote().Sync(...) / .Push(...) / .GetRemote(name) / .SetRemote(...) — there is no svc.Sync / svc.Push. SyncResult and PushResult are EXPORTED (required for the exported RemoteIndex interface). Service has no crypt field of its own; Service.SetCrypt(c) delegates to s.ri.crypt = c.

This is one instance of the general rule: *Service is a thin entry point that exposes sub-indices via accessors, and each sub-index reaches UP through its own `rh` rather than sideways to a sibling. See kb/architecture/store/sub-index-up-not-sideways/360ce7a5.md, which is the authoritative statement of that rule and of the current accessor set.

WHAT THIS DOES NOT MEAN (corrected 2026-07-22):

1. remoteIndex does NOT hold a factIndex. Its fields at HEAD are exactly `{rh *repoHandler; crypt *Crypt}` (internal/store/remote.go). The `fi *factIndex` field this fact used to describe is GONE — it was a sideways sibling reference, and removing it is what made remoteIndex conform to up-not-sideways. If you are adding a remote path that needs fact writes, reach UP through rh, do not re-add an fi field.

2. The accessor list is NOT six entries. This fact previously enumerated 'Facts(), Search(), Pipeline(), ToolSession(), Branches(), Remote()' — incomplete since P1.3. HEAD has: Facts(), Search(), FactQuery(), GraphStore(), HistoryQuery(), Methodology(), IndexManager(), Remote(), Pipeline(), ToolSession(), Branches() (internal/store/service.go). Depend on the NARROWEST accessor you actually need; do not reach for Search() by habit.

UPDATE (PR #518, merge 537f2019): the RemoteIndex interface (internal/store/interfaces.go) gained two methods beside Push, both reached as svc.Remote().X: PublishUpstream(ctx, from, auth) (a non-force push of from's tip to the origin's consensus branch, for the fleet master) and RetractPushedBranch(ctx, branch, auth) (delete an agent branch on the origin under a lease on the remote-tracking ref, then remove the origin remote). See kb/architecture/store/remote-sync/snapshot-push/dee91c70.md and kb/architecture/store/remote-sync/retract-pushed-branch. The list 'GetRemote, SetRemote, Sync, Push, threeWayMerge' above is therefore not the whole method set.

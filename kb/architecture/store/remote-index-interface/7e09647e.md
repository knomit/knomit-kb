# Remote operations live on remoteIndex accessed via svc.Remote(), NOT directly on *Service

GetRemote, SetRemote, Sync, Push, threeWayMerge live on *remoteIndex (internal/store/remote.go + remote_sync.go), exposed via `Service.Remote() RemoteIndex`. Callers MUST use svc.Remote().Sync(...) / .Push(...) / .GetRemote(name) / .SetRemote(...) — there is no svc.Sync / svc.Push. SyncResult and PushResult are EXPORTED (required for the exported RemoteIndex interface). Service has no crypt field of its own; Service.SetCrypt(c) delegates to s.ri.crypt = c.

This is one instance of the general rule: *Service is a thin entry point that exposes sub-indices via accessors, and each sub-index reaches UP through its own `rh` rather than sideways to a sibling. See kb/architecture/store/sub-index-up-not-sideways/360ce7a5.md, which is the authoritative statement of that rule and of the current accessor set.

WHAT THIS DOES NOT MEAN (corrected 2026-07-22):

1. remoteIndex does NOT hold a factIndex. Its fields at HEAD are exactly `{rh *repoHandler; crypt *Crypt}` (internal/store/remote.go). The `fi *factIndex` field this fact used to describe is GONE — it was a sideways sibling reference, and removing it is what made remoteIndex conform to up-not-sideways. If you are adding a remote path that needs fact writes, reach UP through rh, do not re-add an fi field.

2. The accessor list is NOT six entries. This fact previously enumerated 'Facts(), Search(), Pipeline(), ToolSession(), Branches(), Remote()' — incomplete since P1.3. HEAD has: Facts(), Search(), FactQuery(), GraphStore(), HistoryQuery(), Methodology(), IndexManager(), Remote(), Pipeline(), ToolSession(), Branches() (internal/store/service.go). Depend on the NARROWEST accessor you actually need; do not reach for Search() by habit.

UPDATE (PR #518, merge 537f2019): the RemoteIndex interface (internal/store/interfaces.go) gained two methods beside Push, both reached as svc.Remote().X: PublishUpstream(ctx, from, auth) (a non-force push of from's tip to the origin's consensus branch, for the fleet master) and RetractPushedBranch(ctx, branch, auth) (delete an agent branch on the origin under a lease on the remote-tracking ref, then remove the origin remote). See kb/architecture/store/remote-sync/snapshot-push/dee91c70.md and kb/architecture/store/remote-sync/retract-pushed-branch. The list 'GetRemote, SetRemote, Sync, Push, threeWayMerge' above is therefore not the whole method set.

UPDATE (PR #518/#524, verified at merge commit 9db8c106; internal/store/interfaces.go and remote_sync.go): besides Sync and Push the remote index now has `PublishUpstream` (local agent branch to the origin's MAIN, never forced), `RetractPushedBranch` (#518), and, for the fleet master's round, `SyncWithPeers` (Sync plus the agent/* refspec for that fetch only, pruning tracking refs within it), `PeerTips` (the fetched member tips, from refs/remotes/origin/agent/*) and `RecordPushError` (writes a push error on the status row, because PublishUpstream records nothing itself; twin of RecordSyncError).

UPDATE at hier-11 (PR #560, merged as 3e4c6cff; verified there): remoteIndex is now remotesync.Index in internal/store/remotesync (remote.go, remote_sync.go, peer_admit.go, verify_own.go, there), imported by the parent unaliased as remotesync, and `Service.ri` is a *remotesync.Index. Its fields are `rh *remotesync.Repo` (the reconcile handle wrapping the merge handle, which wraps the one vcs.Repo; it replaces *repoHandler, so the 'reaches UP through rh' rule above is unchanged) plus the origin state it guards with originMu (origin, the cached consensus branch, a once for the ambiguous-candidates warning); the crypt field the body above mentions is long gone. The exported names of the old file pair are re-exported by internal/store/remotesync_seam.go, `Service.Remote() RemoteIndex` and the RemoteIndex interface in interfaces.go are unchanged, and `var _ RemoteIndex = (*remotesync.Index)(nil)` is in interface_guards.go. See kb/architecture/store/sync-child/25664ca8.md.

UPDATE at the PR C merge ba59d2b2 (verified there): the structure above is unchanged: `Service.Remote() RemoteIndex` (service.go), the RemoteIndex interface in internal/store/interfaces.go, `var _ RemoteIndex = (*remotesync.Index)(nil)` in interface_guards.go, and remotesync.Index{rh *Repo; originMu, origin, consensus, ...} in internal/store/remotesync/remote.go. PR C added the bootstrap functions (remotesync/bootstrap.go) that take the *remotesync.Index as a parameter for the consensus-branch record; they are package functions, not RemoteIndex methods. Older text naming internal/store/remote.go and remote_sync.go (and the @9f8780e5 pins) is historical.

UPDATE (refactor/store-e5-remotesync-handle, PR E5, #577; verified on the branch head 1e672236, re-pin at the merge commit): THE RemoteIndex INTERFACE IS GONE. store.RemoteIndex (interfaces.go), its `var _ RemoteIndex = (*remotesync.Index)(nil)` guard (interface_guards.go) and remotesync_seam.go are deleted, so every sentence above that names RemoteIndex as the return type of Service.Remote(), says its method set is the exported surface, or says the names are re-exported by remotesync_seam.go is HISTORICAL. Service.Remote() returns *remotesync.Index (internal/store/service.go) and callers import knomit/internal/store/remotesync for SyncResult, PushResult, Remote, Origin and the other names. The rule 'there is no svc.Sync / svc.Push; use svc.Remote().X' stands, and now covers more: UpstreamBranch, SetOrigin, MainHistory, JudgePeerBranch, AdmitPeerBranch, DemotePeerBranch, EnsureLocalUpstream, AdvanceLocalUpstream, DropUnpublishedCommit(LeavingOutMerges), CloneFrom, InitFromRemote and InitSubscription are methods of *remotesync.Index too (their Service forwards were deleted), so svc.UpstreamBranch() is svc.Remote().UpstreamBranch(). The interface had no second implementation, no test double and no outside type-name user (the no-facades convention, kb/conventions/go/package-boundaries/no-facades/44ec3b17.md, named it as the template for what not to add). Consequence for guards that key on call receivers: bind the handle to a name before calling through it (`remote := svc.Remote()`), because `svc.Remote().UpstreamBranch()` keys as the anonymous `?.UpstreamBranch` (kb/gotchas/store/refactor/218612db.md).

# StrategyMergeFacts runs on the REFUSE path: the conflict set is detected, each path gets a Resolution (Body = merged bytes, Side = a retraction or the site's fallback), and the refusing walk applies them. An unmergeable path keeps its site's side-pick: LocalWins on the peer sync, Refuse on the host, agent-wins on the rebase replay

`StrategyMergeFacts` (`merge_facts`, the confidence rule) and `StrategyMergeFactsUpstream` (`merge_facts_upstream`) are ConflictStrategy values. They carry the rule in the value, so no internal signature grew a parameter. `factMergeResolutions` (internal/store/conflict_merge.go) runs `detectConflicts` (the refusing walk). Then, for each conflicting path:
- src and dst hold the same bytes: ResolveDst, silently.
- `!rh.isFactPath` (outside the ontology root, or private): the site fallback, with reason=not-a-fact.
- a fact one side deleted and the other edited: THE RETRACTION WINS (ruling 2). It is applied as a Side, because a Resolution Body can only SET a path, never delete it. The edit stays in the merge commit's other parent.
- otherwise fact.MergeVersions. ok gives Resolution{Body}; not ok gives the fallback with rec.Reason.

The walk then runs under StrategyRefuse with those resolutions.

WHERE A SITE'S FALLBACK AND UPSTREAM SIDE COME FROM:
- `mergeOpts.factUpstream`/`factFallback`. The zero value is the peer sync's: upstream = src (the consensus branch is merged INTO the agent branch), fallback LocalWins. A LocalWins fallback on a dual-add takes src, exactly as the LocalWins walk always overwrote.
- The host (MergePushed with no side, MergeConsensus) sets upstream = dst and fallback Refuse, so an unmergeable path still refuses the WHOLE merge (atomic), naming only that path.
- The rebase replay (`replayCommit`) has an EXPLICIT case with upstream = dst (onto) and fallback RemoteWins (the agent's commit is src). Without it, the `default:` arm would silently map the strategy to agent-wins.

MISREADINGS:
- 'merge_facts resolves everything' is wrong: on the host an unmergeable path is refused as before.
- 'MergePushed always merges when conflicts: merge' is wrong: an explicit `side` (the human's whole-set choice) is never overridden.

Pinned by tests: TestReplay_MergeFactsUpstream_OntoIsUpstream checks that on the replay, merge:upstream takes onto's version. TestReplay_MergeFacts_FallbackAgentWins checks that an unmergeable path keeps the agent's commit, recorded as kept=src strategy=remote_wins.

# store/vocab holds MotifIndex and the title-embedding axis (AbstractionIndex) over the one *vcs.Repo; the axis' alias, guard and Restatement* re-exports live in interfaces.go, NOT in vocab_seam.go, because the review-pipeline conformance scan lets only interfaces.go, service.go and vocab/abstraction.go name them

Since PR 10b of the internal/ hierarchy stack (PR #558, merged into dev as bbc59d47; branch refactor/hier-10b-vocab, stacked on the index child), the store's vocab cluster is the package internal/store/vocab: abstraction.go (AbstractionIndex: the title-embedding axis, the restatement shortlist, verdicts and throttle state), motif_alias.go (MotifIndex: alias resolution, judge merges, verdicts) and motif_definition.go, plus doc.go, forwards.go (the old unexported sqlite forwards as package vars, so the moved bodies did not change) and testseams.go. It imports ONLY store/internal/sqlite and store/internal/vcs; the proposal's arrow vocab -> index is not needed (nothing in the moved files touches the index), so TestLayers lists just store/vocab -> store/internal/sqlite and -> store/internal/vcs. Both types hold `rh *vcs.Repo` (every call was rh.DB or rh.BranchID); store.Open builds them with vocab.NewAbstractionIndex(rh.Repo) and vocab.NewMotifIndex(rh.Repo) where the struct literals were.

WHERE THE PARENT'S NAMES LIVE, and why it is split. internal/synthesize TestConformance_ReviewPipelineOnly AST-scans every non-test store file (recursively) and rejects any identifier or string literal containing 'abstraction' or 'restatement' outside an allowlist of paths relative to internal/store. At the 10b merge bbc59d47 it was vocab/abstraction.go (was abstraction.go), interfaces.go, index/vec_table.go, internal/vcs/branch.go, service.go; at dev tip d73aad37 (after #559, which moved the restatement_* branch-drop cleanup into vocab.DropBranchReviewState, a hook vcs runs without naming the tables) it is exactly four files: vocab/abstraction.go, interfaces.go, index/vec_table.go, service.go. internal/vcs/branch.go is no longer listed. So: (1) vocab's constructors live in abstraction.go and motif_alias.go, not doc.go, because NewAbstractionIndex names the axis; (2) the parent's `abstractionIndex = vocab.AbstractionIndex` alias, the compile-time guard `var _ AbstractionIndex = (*abstractionIndex)(nil)` (formerly in abstraction.go) and the RestatementPair / RestatementPairStats / RestatementVerdict re-exports are declared in interfaces.go next to the AbstractionIndex interface; (3) every other public name (MotifCluster, AliasRow, DefinitionStamp, DefinitionTarget, MotifDefinitionStatus, MotifVocabularyHealth, LiveFactTitle, Title*, MatchTitleKNN, FactIDPairKey) and the motifIndex alias are in vocab_seam.go. In #558 the allowlist kept its size: the abstraction.go entry followed the file and nothing was added; #559 then removed the internal/vcs/branch.go entry. TestConformance_NoCorpusPropertyConstants and TestConformance_BudgetConstantsSayWhatTheyBudget read ../store/vocab/abstraction.go by path.

PROVEN on throwaway commits: a restatement_pairs literal in vocab/motif_alias.go, the old allowlist key abstraction.go, the guard re-added in vocab_seam.go, the old phase-0 path and a 0.42 float literal in vocab/abstraction.go each fail the synthesize conformance tests; removing a vocab layer edge is logged by the (still report-only) TestLayers.

TESTS: no store test moved (all drive a Service); the one unexported helper a parent test uses, pairKey, is reached through vocab.PairKeyForTest (mustBeTest guard) and rebound under its old name in vocab_testseams_test.go.

CONSEQUENCE: a parent file that must name the axis or a Restatement* type has to be one of the allowlisted files; adding a new allowlist entry is a widening of the review-pipeline guard and needs a reason. MISREADING: interfaces.go holding aliases is not a second implementation; the implementation is vocab/abstraction.go only.

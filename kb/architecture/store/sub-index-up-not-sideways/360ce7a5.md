# Sub-indices reach UP to repoHandler; siblings NEVER reach sideways

Since hier-07 the shared backend state lives in vcs.Repo (internal/store/internal/vcs) as unexported fields, and the parent's repoHandler is `struct{ *vcs.Repo }` (internal/store/vcs_seam.go), so `rh.X` in a sub-index reaches the child by promotion and fields through accessors (rh.DB(), rh.Storer(), rh.Repository(), ...). The state: db, gits (*storegit.Storer), repo (*gogit.Repository), signer (ssh.Signer for commit signing), embedder, onCommit (external observer), branchMu (per-branch RWMutex map), cache (branch name→id cache), im (IndexManager back-ref), name, configMu. Sub-indices — facts.Index (formerly factIndex, now in internal/store/facts), searchIndex, remoteIndex, plus the four read-side query sub-services carved out of searchIndex in P1.3 (factQuery, graphStore, historyQuery, methodologyMatcher) — each hold a back-reference `rh *repoHandler` and reach UP for git/commit primitives. pipelineIndex and toolIndex hold no such back-reference: pipelineIndex holds `db *sql.DB` (the main repo database) plus `sessionDB *sql.DB`, and toolIndex holds `db *sql.DB`, so neither reaches repoHandler at all (as of the hier-05 store back-reference cuts). Sibling subsystems NEVER reach sideways through each other. Commit authoring (CommitSigner, CommitSigs) and NotifyCommit live on vcs.Repo precisely because they're shared between facts.Index writes and remoteIndex.Sync merge commits. Service is a thin entry point exposing each sub-index via an accessor: Facts(), Search(), FactQuery(), GraphStore(), HistoryQuery(), Methodology(), IndexManager(), Remote(), Pipeline(), ToolSession(), Branches() — Branches() returns *repoHandler directly because repoHandler satisfies BranchIndex.

Search() returns *searchFacade, a stateless composite embedding pointers to the four query sub-services. It satisfies the SearchIndex composite purely by method promotion and holds no state of its own, so it is NOT an exception to the up-not-sideways rule: every call it promotes still reaches UP through that sub-service's own rh. searchIndex retains the index lifecycle (IndexManager) plus the write/rebuild/graph-write path, and no longer implements SearchIndex. Compile-time guards for the sub-index interfaces live in interface_guards.go since the hier-05 store back-reference cuts, with ONE exception: the `AbstractionIndex` guard is kept out of interface_guards.go, because TestConformance_ReviewPipelineOnly (internal/synthesize/restatement_conformance_test.go) AST-scans every non-test file under ../store, ../mcp and ../web (recursively since #551) and permits the name only in an allowlist relative to internal/store. At dev tip d73aad37 the guard and the Restatement* aliases are in internal/store/interfaces.go (they were in abstraction.go before it moved to vocab/abstraction.go) and the allowlist is exactly vocab/abstraction.go, interfaces.go, index/vec_table.go, service.go; internal/vcs/branch.go is no longer on it. See kb/architecture/store/clusters/afe40e1e.md.

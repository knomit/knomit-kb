# Sub-indices reach UP to repoHandler; siblings NEVER reach sideways

repoHandler owns shared backend state: db, gits (*storegit.Storer), repo (*gogit.Repository), signer (ssh.Signer for commit signing), embedder, onCommit (external observer), branchMu (per-branch RWMutex map), cache (branch name→id cache), im (IndexManager back-ref), name, configMu. Sub-indices — factIndex, searchIndex, remoteIndex, pipelineIndex, toolIndex — each hold a back-reference `rh *repoHandler` and reach UP for git/commit primitives. Sibling subsystems NEVER reach sideways through each other. Commit signature helpers (authorSig, committerSig) and notifyCommit live on repoHandler precisely because they're shared between factIndex writes and remoteIndex.Sync merge commits. Service is a thin entry point exposing each sub-index via an accessor: Facts(), Search(), IndexManager(), Remote(), Pipeline(), ToolSession(), Branches() — Branches() returns *repoHandler directly because repoHandler satisfies BranchIndex.

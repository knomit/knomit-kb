# `context` is indexed in the fact_context side table (migration 000034), one row per (fact VERSION, key), filled by the GraphSchemaVersion 6→7 rebuild; the filter joins the branch's LIVE facts row, and results take the typed map from the BLOB, not the table

fact_context(fact_id REFERENCES facts(id) ON DELETE CASCADE, key, value, num, PRIMARY KEY(fact_id, key)) with an index on (key, value). value is the canonical text (fact.ContextText: the string, true/false, a number in shortest form); num is set for numbers only, ready for range filters. It is a side table, not facts columns, for the same reason as fact_expires (the ADD COLUMN budget is spent).

Writes: the incremental upsert inserts with INSERT OR IGNORE (the facts row is content-addressed). The rebuild DELETEs the rebuilt facts' rows (scoped by _rebuild_entries — a repair path) and re-inserts them from blobs containing the token "context", via json_each over knomit_parse_fact's context map. A map ParseFact dropped writes no row on either path. GraphSchemaVersion went from "6" to "7" so every branch rebuilds once and picks up hand-written context lines a pre-F22 parser dropped.

Reads: SearchOptions.Context adds one EXISTS(... fc.fact_id = f.id AND key = ? AND value = ?) per key, where f is always the branch_facts-joined (LIVE) row. Rows of superseded or retracted versions stay in the table, as with fact_expires, and must never be read alone. With text, the filter applies after the vector window, so it can under-return. Results: GetByPath, Search and RecentFacts fill FactRecord.Context with fact.ExtractContext on the raw blob (RecentFacts fetches the blob only when the fact has context rows), because the table's text cannot tell the string "true" from the bool true.

CONSEQUENCE: a new reader of context must either join the live row and accept text values, or read the blob; never treat fact_context as "facts live at HEAD".

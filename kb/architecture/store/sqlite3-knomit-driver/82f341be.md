# Custom sqlite3_knomit driver carries sqlite-vec + 3 SQL funcs + per-connection pragmas; its ConnectHook does NOT write (no extension load, no vtab)

`registerVec()` (internal/store/vec.go) runs once per process under `vecOnce sync.Once` and does two things: calls `sqlite_vec.Auto()` to load the sqlite-vec extension, then `sql.Register("sqlite3_knomit", &sqlite3.SQLiteDriver{ConnectHook: ...})`.

The ConnectHook does exactly two things per connection:
1. `registerSQLFuncs(conn)` (internal/store/sqlfuncs.go) registers THREE scalar UDFs, all pure: `knomit_parse_fact` (markdown+frontmatter → JSON, used by the bulk rebuild), `knomit_cosine_sim`, and `knomit_canon_domain` (NFC + case-fold + de-hyphenize, so bulk rebuild SQL can store canonical `fact_domains` values).
2. Applies four per-connection performance pragmas: `synchronous = NORMAL`, `cache_size = -65536` (64 MB), `mmap_size = 268435456` (256 MB), `temp_store = MEMORY`. These MUST run in the ConnectHook rather than via `db.Exec()`, because `db.Exec()` reaches only one pooled connection.

No virtual table is registered on this driver. The `first_parent_chain` vtab that once existed has been retired in favour of recursive CTEs.

CONSEQUENCE: **the ConnectHook performs no writes**, so opening a new pooled connection cannot block on a held SQLite write lock. That is what makes lazy connection opens safe under `_txlock=immediate` and why no pool pre-warming exists (see kb/invariants/store/sqlite/write-serialization/9caa7895.md).

WHAT THIS DOES NOT MEAN:
- **The driver does NOT load GraphQLite.** It formerly loaded that Cypher-over-SQLite extension, whose init WROTE to its EAV schema — the reason the pool once had to be eagerly pre-warmed. GraphQLite was removed in PR #28; `graphqliteLibPath` no longer exists and there is no `cypher()` UDF. The property-graph tables (nodes, node_labels, edges, property_keys, node_props_text, edge_props_text) are now owned outright by migration `000014_graph_eav` and written with direct SQL in internal/store/graph_sql.go.
- Registering the driver is not the same as opening a DB: `store.Open` still adds the DSN parameters (`_txlock=immediate` etc.) separately. The ephemeral session DB deliberately uses the STOCK `sqlite3` driver, not this one — it needs no vec extension.

# Custom sqlite3_knomit driver carries pragmas + extensions + vtab registration

Knomit uses a custom SQLite driver name `sqlite3_knomit` (NOT `sqlite3`), registered exactly once per process via registerVec() in vec.go using sync.Once. The driver carries: (1) GraphQLite extension load via the Extensions field; (2) a ConnectHook that runs on EVERY pooled connection — registers SQL functions (registerSQLFuncs), applies per-connection pragmas (synchronous=NORMAL, cache_size=-65536 = 64MB page cache, mmap_size=268435456 = 256MB mmap I/O, temp_store=MEMORY), registers vtabs (registerVTabs for first_parent_chain). PRAGMAS MUST RUN IN ConnectHook — db.Exec() only reaches one pooled connection. sqlite-vec is auto-loaded via sqlite_vec.Auto() inside the once block.

POOL CONFIG (file DBs, updated commit 9fb679c): db.SetMaxOpenConns(4) AND db.SetMaxIdleConns(4) — EQUAL, with SetConnMaxLifetime(0) + SetConnMaxIdleTime(0) so connections NEVER expire — plus Open() PRE-WARMS the pool (warmPool() force-opens all 4 connections up front). The DSN also sets `_txlock=immediate`. This trio is LOAD-BEARING and interdependent: immediate serializes cross-branch GraphQLite writes (which have no internal BUSY handling), but a lazily-opened/churned connection runs the ConnectHook → loads the GraphQLite extension (a write to its EAV schema) → which under a held immediate write lock self-deadlocks. Keeping the pool fully warm + pinned guarantees no connection is ever initialized mid-transaction. Do NOT set MaxIdleConns < MaxOpenConns, a non-zero ConnMax*Time, or drop warmPool. See [[graphqlite-write-serialization]]. (`:memory:` is special-cased to a SINGLE connection — a bare in-memory DB is per-connection, so multiple connections would be separate empty databases; it also skips immediate/warm-pool since one connection cannot self-contend.) The OLD comment 'SetMaxOpenConns(4): SQLite serializes writes internally, limiting the pool avoids SQLITE_BUSY contention' was incomplete — limiting the pool alone never serialized the cross-branch GraphQLite writes.

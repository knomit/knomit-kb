# store/verify is the judge as a package (signatures, tree shape, CheckRange, M3, E4, validations, artifact rules, the incoming-push judge, Audit); it reads a store only through *vcs.Repo and fleetrec, its callers (gitserve, remotesync, fsck) call verify.* directly, and the parent's verify_seam.go holds only aliases, constants, error values and function forwards for names used outside store

Since PR 08b of the internal/ hierarchy stack (branch refactor/hier-08b-verify, stacked on the fleetrec PR), the verify cluster is the package internal/store/verify (a sibling of git, migrate and fleetrec, not under internal/). PATH MAP for readers of older facts, which name the old files: verify_sig.go -> verify/sig.go, verify_tree.go -> verify/tree.go, verify_walk.go -> verify/walk.go, verify_range.go -> verify/range.go, verify_m3.go -> verify/m3.go, verify_e4.go -> verify/e4.go, verify_validations.go -> verify/validations.go, verify_artifacts.go -> verify/artifacts.go, verify_audit.go -> verify/audit.go, verify_incoming.go -> verify/incoming.go. Unexported names in those older facts became exported: judge -> verify.Judge (fields entry/ownOntology -> Entry/OwnOntology), newJudge/judgeCommit -> NewJudge/JudgeCommit, checkM3 -> CheckM3, verifyCommitSignature -> VerifyCommitSignature, signerIsPusher -> SignerIsPusher, branchFactsValid -> BranchFactsValid, loadMembers etc. -> fleetrec.*.

It imports only fact, pki, store/fleetrec and store/internal/vcs (TestLayers lists store/verify -> store/fleetrec and -> store/internal/vcs). It reads a store only through *vcs.Repo; the four repoHandler methods that used to live in the verify files (judgeIncoming, privatePathClosure, verifyModeAt, checkOwnLineage) became functions taking the *vcs.Repo (JudgeIncoming, PrivatePathClosure, VerifyModeAt, CheckOwnLineage); the helpers incomingValid (verify/incoming.go) and acceptedCommit (verify/walk.go) are package functions of verify, not repoHandler methods. HISTORICAL (PR 08b): the parent's verify_seam.go first kept those four as one-line repoHandler forwards. That is no longer true: parent slimming PR A inlined three of them and PR C deleted the last (checkOwnLineage), so package store has ZERO `func (rh *repoHandler)` methods in non-test files and receive-pack (gitserve), the sync path and bootstrap (remotesync) call verify.* directly. verify_seam.go re-exports public names (Refusal, Rule*, Verify*, CommitSigner, Err*, RangeInput/RangeVerdict, CheckRange, Audit, ...) as aliases, consts, the SAME error values and forwards.

HISTORICAL (PR 08b): verify_own.go (judgeOwnRange, the publish-time judge of the master's own commits) and verify.go (the integrity report) stayed in the parent at that commit; they have since moved to remotesync/verify_own.go (#560) and fsck/integrity.go (#562). verify_own.go builds three verify.Judge values and sets Entry or OwnOntology on them before calling JudgeCommit, exactly as it set the unexported fields before; no verification test moved, because every one drives a full Service or shares the parent's fixtures (namedSigner, newRangeFixture, pushHost).

CONSEQUENCE: a new rule goes in the Judge; a new caller of the judge in the parent goes through verify_seam.go or verify_own.go. verify never writes and never moves a ref, and fact_write.go and internal/vcs/sign.go must not call it. TestVerifyIsNeverInTheWritePath (internal/store/verify_not_in_write_path_test.go, merged in 1370c1d4) scans those two files as TEXT with three rules: a name list covering the old and the exported spellings, \bfleetrec\.\w+\( and \bverify\.\w+\(. Because it is a text scan, a call through an import alias or a dot-import of verify slips past the package-qualified rules; do not rely on it to catch those. MISREADING: the exported Judge is not a second entry point for acceptance; CheckRange and JudgeIncoming are, and the Entry/OwnOntology flags are set only by the incoming-push judge and the master's own-range judge.

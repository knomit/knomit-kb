# Per-session instructions computed via AfterInitialize hook using repo's ontology

Instructions are NOT static — each MCP session gets a per-repo instruction string. NewServer registers hooks.AddAfterInitialize(...) which fires after the client's initialize request. The hook reads ri := repos.RepoFromContextOpt(ctx): if present, returns ProfileInstructions(profile, ri.OntologyRoot(), ri.Ontology()); if absent, falls back to generic instructions with the default ontology root. Instructions include the ontology's ACTUAL topic names and descriptions via ontology.TopicNames() + node.Description — so the agent sees the topics this repo defines, not a hardcoded list. The hook mutates result.Instructions in place before mcp-go sends the initialize response. Profile (code|chat|generic) is captured in the closure at NewServer time. This is the key mechanism for ontology-aware agent behavior.

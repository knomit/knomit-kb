# Repo skills (.knomit/skills/<name>/SKILL.md) are served as MCP prompts PER BINDING on ONE global mcp-go prompt map: names registered lazily (BeforeListPrompts + BeforeGetPrompt), AfterListPrompts replaces the list with this binding's skills and clears NextCursor, one shared handler resolves the binding per request

F08 PR C (rulings R6/R8/D2). mcp-go v0.45.0 keeps prompts in ONE server-global name→handler map and knomit runs ONE MCPServer for every mount, so internal/mcp/prompts.go splits names from content:

- NAMES are global and only ever added. BeforeListPrompts registers this binding's skill names; BeforeGetPrompt registers ANY valid kebab-case name it is asked for, because mcp-go's handleGetPrompt refuses an unregistered name with "prompt not found" BEFORE any handler runs — without it, a prompts/get with no prior prompts/list in this process (a client reusing a list cached across a restart) fails for a skill that exists.
- CONTENT is per binding. AfterListPrompts overwrites result.Prompts with exactly this binding's skills and sets NextCursor = "" (mcp-go paginated the GLOBAL map before the hook ran; the cursor only exists under WithPaginationLimit, which knomit does not set — tests use the unexported newServer(extra opts) to make that falsifiable). The one shared handler resolves the binding from ctx again, so repo A's and repo B's `work-task` are one registered name and two different prompts.
- WHICH REPO (skillRepo in internal/mcp/skills.go): the binding's WRITE repo. Repo-scoped mount = that repo; a lens = its write repo ONLY (a repo mounted read-only in a lens serves no skills there); the unscoped mount (repos.SessionScoped with no Binding) lists NO prompts and a get answers "bind a repo: prompts are served on repo-scoped mounts".
- WHICH COMMIT: UpstreamTip(svc.UpstreamBranch()) — the consensus branch, like recipes; never the agent branch or an experiment, and no branch name is spelled (a repo whose origin names "develop" serves develop's skills). A subscription serves skills too.
- WithPromptCapabilities(false): nothing is notified; the list is recomputed per prompts/list.
- A malformed SKILL.md is skipped from every list and WARNed once per (folder, blob); never fatal. A get of it answers a named "is malformed" error.
- Bundled files (every other file under the folder, recursively): text inlined as EmbeddedResource (uri knomit://<repo>/.knomit/skills/<name>/<file>) in path order while the TOTAL stays within 256 KiB; binaries (NUL or invalid UTF-8) and overflow are listed by path in a final text message. One optional prompt argument `args` fills $ARGUMENTS (appended as "Arguments: …" when the body has no placeholder).

What this does NOT mean: knomit copies no skill into .claude/skills or any harness folder (R8), and nothing in `kb claude init` changed. MCP prompts are user-typed slash commands; the model-invocable path is the knomit_skill tool, which reads through the same skillSource.

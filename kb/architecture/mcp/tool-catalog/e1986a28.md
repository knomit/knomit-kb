# knomit registers up to 7 MCP tools (2 in read-only mode) per profile; endpoint is per-branch with 3 profiles

The MCP surface is up to 7 tools: knomit_learn (write facts in one commit), knomit_query (paginated snippet search), knomit_explain (walk versioned provenance), knomit_update (revise in place; refs append), knomit_retract (commit a removal), knomit_review (work-stealing prune/distill/reflect), knomit_hypothesize (generate hypothesis facts; user-initiated). They are mounted at POST /api/v1/repos/{repo}/branches/{branch}/mcp?profile={code|chat|generic}.

TWO INDEPENDENT AXES govern what a live server exposes — do not collapse them:

1. profile (code|chat|generic) — changes ONLY the per-session instruction string sent to the calling model. The SAME tool set registers in every profile. code = technical knowledge (bridge default), chat = conversational, generic = any domain. There are exactly 3 MCP server instances (one per profile) shared across all repos; handlers resolve repo+branch from request context. Per-session instructions are computed from the repo's ontology via an AfterInitialize hook.

2. readOnly — GATES the tool set, orthogonally to profile. NewServer(profile, root, readOnly, ...) runs enabledTools(toolRegistrations(), readOnly): when readOnly=true, every write tool is dropped and only the 2 read tools (knomit_query, knomit_explain) register. So a read-only ('demo') instance exposes 2 tools per profile, NOT 7. When readOnly=false, all 7 register. internal/web/server.go builds one server per profile passing s.ReadOnly, so both axes are live in production.

WHAT THIS DOES NOT MEAN: it does NOT mean every endpoint offers all 7 tools, and it does NOT mean the profile controls tool availability. '7 tools' is the read-WRITE count; profile never adds or removes a tool (readOnly does). Do not assume a client can call knomit_learn/update/retract/review/hypothesize against a read-only instance — those 5 write tools are simply absent from its catalog.

Clients usually reach this via knomit-bridge (stdio).

Enforcing code: enabledTools drops write:true regs when readOnly (internal/mcp/server.go); toolRegistrations lists all 7 with their write flags; buildMCPHandlers loops the 3 profiles (internal/web/server.go).

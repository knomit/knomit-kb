# knomit registers 8 MCP tools (3 in read-only mode) on ONE shared server; mounted per-branch AND per-lens

The MCP surface is EIGHT tools, listed in `toolRegistrations` (internal/mcp/server.go) in registration order with their write flags:

| tool | write? |
|---|---|
| knomit_learn (write facts in one commit) | yes |
| knomit_query (paginated snippet search) | no |
| knomit_explain (walk versioned provenance) | no |
| knomit_update (revise in place) | yes |
| knomit_retract (commit a removal) | yes |
| knomit_hypothesize (generate hypothesis facts; user-initiated) | yes |
| knomit_review (work-stealing prune/distill/reflect) | yes |
| knomit_repos (list the repos/mounts behind this endpoint) | no |

`knomit_update` list fields (domain, entities, refs) replace WHOLESALE: send the complete new list; omit the field to leave it unchanged (internal/mcp/update.go: `updates.Refs != nil` → `fact.Refs = refs`).

**readOnly GATES the tool set.** `NewServer(defaultOntologyRoot, mgr, readOnly, embedders...)` runs `enabledTools(toolRegistrations(embedders...), readOnly)`: when readOnly=true every write tool is dropped and only the THREE read tools register — knomit_query, knomit_explain, knomit_repos. So a read-only ('demo') instance exposes 3 tools, not 8.

**MOUNT POINTS — there are TWO**, both dispatching to the same handler (`mcpDispatch`, internal/web/router.go), each accepting `/mcp` and `/mcp/*`:
- repo+branch-scoped: `/api/v1/repos/{repo}/branches/{branch}/mcp`
- lens-scoped: `/api/v1/lenses/{lens}/mcp`

WHAT THIS DOES NOT MEAN:
- **Profile does NOT key servers and does NOT gate tools.** There is exactly ONE MCP server instance (`s.mcpHandler`), not three. Profile is a per-repo setting in control.db `repo_settings` that changes ONLY the per-session instruction addendum; it never adds or removes a tool — readOnly does. `?profile=` on the endpoint is accepted, logged at debug, and IGNORED. See kb/decisions/mcp/profile-per-repo/f192649f.md.
- '8 tools' is the read-WRITE count. Do not assume a client can call learn/update/retract/review/hypothesize against a read-only instance — those 5 write tools are absent from its catalog entirely.
- The lens mount is not a second server; a lens authors under its WRITE repo's profile.

Clients usually reach this via knomit-bridge (stdio).

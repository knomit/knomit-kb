# The MCP half of the permission registry is CallEffect.Perm on every toolEffects row (internal/edge/mcp/tool_effects.go) and mcp.PermissionFor(tool, args), which classifies by the action the handler will dispatch to; ReadOnly <=> kb:read with no exceptions, every side-effecting row is kb:write, unknown tool/action => denied; not enforced until P4

PermissionFor builds on ClassifyCall, so knomit_review/knomit_hypothesize are classified by reviewMode/hypothesizeMode (argument shape) and knomit_experiment by its action argument, exactly as the handlers dispatch. A tool or action with no row returns ok=false: the caller must deny.

Read actions that today's tool-level gate treats as writes now carry kb:read: experiment list, review page and current, hypothesize current (design §3). knomit_bind is kb:read. Every other row (learn, update, retract, review start/answer/takeover, hypothesize start/answer, experiment open/sync/commit/rollback) is kb:write.

TestToolEffects_EveryRowHasPermission and TestToolEffects_ReadOnlyRowsAreKBRead pin it; TestToolEffects_EveryRegisteredToolHasRows (existing) already forces a row for every registered tool and action, so a new tool cannot be added without a permission. Until the flip the old permissionFilter and gatePermission (auth.Write on write tools) still decide.

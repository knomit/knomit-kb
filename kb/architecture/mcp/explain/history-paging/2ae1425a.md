# knomit_explain history paging: the first call shows 3 revisions and returns history.history_cursor; history_cursor calls return history-only pages of 20, recomputed from the ORIGINAL anchor at an offset. The root's `commit` stays the first-parent resolved version and can differ from history.revisions[0]

Shape:
- `history` holds revisions (commit, date = author date, message, action added|modified, diff from the next OLDER revision in the full list), more_available, and history_cursor (only when more_available).
- The first explain call shows explainHistoryDisplay = 3 revisions next to the body and graph.
- A call with `file` + `history_cursor` returns {path, history} only: no body, no facts, no graph walk. It holds up to explainHistoryPageSize = 20 revisions.
- more_available:false means the list is complete. A complete list ends on the fact's creation (action added), unless the history begins off-branch.

The cursor is opaque base64url JSON {f: the file argument exactly as passed, a: the original anchor, o: the offset}. Each page recomputes store.PathHistory from that anchor and slices it; there is no server-side state and nothing to expire.

Refused, as an error:
- a cursor passed with a different `file`
- a cursor combined with `commit` or `cursor`
- a cursor that is not valid

The cursor does NOT survive a change of mount addressing: it binds the literal file string, so kb://<id>/x and x are different files to it.

The ROOT's `commit` is NOT history.revisions[0].commit. It stays the first-parent resolved version (RevisionsBefore(anchor, 1)), because seen-keys and edge pins are first-parent commits. For a merge-delivered fact the root commit is the PR merge, and revisions[0] is the write behind it. Both are readable with commit=. As if_commit guards they compare file bytes, so either works.

NAMED MISREADING: "to page history, re-call with commit = the oldest revision". That re-anchors the whole explain, re-sends the body, and on a branching history skips the other side's revisions. history_cursor is the paging mechanism.

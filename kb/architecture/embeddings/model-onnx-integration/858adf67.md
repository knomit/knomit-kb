# EmbeddingGemma ONNX export emits a pre-pooled `sentence_embedding`; in-process Go (onnxruntime_go + daulet/tokenizers) is bit-faithful

Validated by PoC #2 (2026-06-05; harness /tmp/knomit_go_emb_poc). The onnx-community/embeddinggemma-300m-ONNX repo is PUBLIC (gated:false). Its ONNX graph has a clean 2-input signature — `input_ids` + `attention_mask` (both int64), NO token_type_ids and NO position_ids — and TWO outputs: `last_hidden_state [*,*,768]` and `sentence_embedding [*,768]`. The `sentence_embedding` output has mean-pooling + the Dense projection + L2-normalization BAKED INTO THE GRAPH, so a consumer reads the final 768-dim vector directly and never reimplements pooling. This removes the single biggest integration risk of swapping off nomic (the current hand-rolled mean-pool path in internal/embeddings/embedder.go would NOT be needed for Gemma).

In-process Go path that works: onnxruntime_go.NewDynamicAdvancedSession(model, [input_ids, attention_mask], [sentence_embedding]) + daulet/tokenizers.FromFile on Gemma's 20MB SentencePiece tokenizer.json (EncodeWithOptions(text, true, WithReturnAttentionMask()) yields IDs + AttentionMask). Output embeddings were bit-faithful to Ollama's embeddinggemma reference (cosine = 1.0000 on identical input). Apply EmbeddingGemma's retrieval prompts: query = `task: search result | query: <q>`, doc = `title: none | text: <d>`.

Cross-platform: proven on darwin/arm64 (ORT 1.26 dylib + libtokenizers.a darwin-aarch64 from daulet release v1.27.0, linked via CGO_LDFLAGS). Structurally portable elsewhere — daulet/tokenizers ships static libs for darwin arm64/x86_64, linux amd64/arm64 (glibc+musl) and windows; knomit already ships libonnxruntime per-OS; the .onnx + tokenizer.json are platform-agnostic. Full close-out = a linux+windows CI build matrix.

Build implication: adopting EmbeddingGemma requires the pluggable-embedder + dynamic-dim refactor (kill the hardcoded `factsVecDim=768` const, derive vec0 width + pooling + prompt templates + ONNX I/O names from a model descriptor). Dimension stays 768 for Gemma, so no vec0 width change is forced, but the embedding VALUES change → the swap must invalidate stored vectors via the derived-state recipe (new facts_vec migration + GraphSchemaVersion bump → forced rebuild re-embeds). See [[f6db3a49]] (derived state regenerated from git) and [[graph-schema-version]]. Earlier PoC #1 (Ollama, 866 real facts) showed EmbeddingGemma best on retrieval (R@1 0.820 vs nomic 0.760).

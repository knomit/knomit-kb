# EmbeddingGemma's cosine distribution runs much cooler than nomic's; all 6 retrieval thresholds ported DOWN

Measured against the real corpus (712 facts from knomit.db + knomit-kb.db) with tools/calibrate (PR #72). EmbeddingGemma produces SUBSTANTIALLY lower cosine similarities than nomic-v1.5 on the same texts:

- distinct same-category doc pairs: nomic mean 0.745 / p99 0.903  vs  gemma mean 0.483 / p99 0.766
- all doc pairs: nomic mean 0.644  vs  gemma mean 0.267
- query->doc pairs: nomic mean 0.568  vs  gemma mean 0.204
- true near-dup pairs (synthetic): both ~0.98 (near-identical text scores high under either model)

CONSEQUENCE: this REVERSES the naive worry that gemma would over-merge at the old 0.92 dedup threshold. The opposite is true — 0.92 sits at gemma's p99.6 of distinct pairs, so under gemma it would almost NEVER fire (silent under-merge / duplicate accumulation), not over-merge. Every absolute cosine cutoff had to move DOWN.

METHOD: distribution-preserving port — for each nomic threshold T on its governing distribution D, find p=CDF_nomic_D(T), then gemma value = p-quantile of gemma's D. Ported values (nomic -> gemma): dedup 0.92->0.82, reflect-novelty 0.85->0.69, SIMILAR_TO 0.60->0.18, search recall floor 0.40->~0 (clamped to 0.05), rerank-high 0.70->0.43, rerank-low 0.50->0.10. Dedup 0.82 validated inside the safety gap [distinct p99 0.766, true near-dup p05 0.959].

To recalibrate for a new model: run `ORT_LIB_PATH=dist/lib/libonnxruntime.dylib DYLD_LIBRARY_PATH=dist/lib go run ./tools/calibrate -cache ~/.knomit/models ~/.knomit/repos/*.db`. It opens DBs read-only (immutable=1) and prints the distribution-preserving port table. These values live as retrieval.Thresholds on each embeddings.Model (see [[model-dependent-thresholds-on-descriptor]]).

# A fact may ref a FILE under .knomit/ — `.knomit/<path>` or `kb://<id>/.knomit/<path>` classify as local_system_file / foreign_system_file (path verbatim, case kept); the write gate refuses one whose file is not at the branch tip; explain pins it at the referrer's own commit with NO graph edge

Built on branch feat/system-file-reads (user ruling 2026-10-06: "if we cannot get to the js file now because it's not a fact, let's fix it"; decision 3: a file ref pins the file at the referrer's commit).

CLASSIFICATION (internal/fact/ref.go, still the single authority). A ref whose repo-relative path starts with the exact, lowercase `.knomit/` — bare, or after `kb://<12-hex>/` — is a SYSTEM FILE, not a fact: `local_system_file` when bare or the id is the caller's own, `foreign_system_file` otherwise. Path is kept VERBATIM (SKILL.md ≠ skill.md); fact paths are still lowercased. Malformed (RefMalformed, refused by ValidateRefs at write): the bare root, an empty segment (`//`, trailing `/`), a `.` or `..` segment. Dot segments BELOW the root are allowed (`.knomit/templates/mission/.knomit/triggers/claims.js`). `.KNOMIT/x`, `.github/x`, `kb/.drafts/x.md` stay fact-kind refs exactly as before (and the gate refuses them as missing facts). RefIdentity keys them as `file|<path>` (plus repo id when foreign).

WRITE GATE (internal/refs). `Gate.WithFiles(resolver)`: a NEWLY ADDED local system-file ref must name a FILE (not a directory) in the tree at the tip of the branch the write lands on — `refs.FromSystemFiles(store.SystemFileIndex, branch)` — or the whole write is refused in the same one-error list, its own section with the fix line "does not exist under .knomit/ at the tip of the branch this write lands on". Carried refs are not re-judged (prior), keyed apart from fact paths. A gate built WITHOUT a file resolver refuses a newly added one ("cannot check refs to .knomit/ files") rather than letting it through. Wired: knomit_learn, knomit_update, REST POST/PUT (writerGate), experiment resolutions (resolveGate: either side). The synthesize pipelines' gates have no file resolver — they only carry such refs (exempt via prior) or cite facts. Foreign system-file refs are never checked. Canonicalize stores a local one as `kb://<own-id>/.knomit/<path>`, case kept.

READING (knomit_explain). There is NO DERIVED_FROM edge and no index change: because the pin is the referrer's own commit, the child is a pure function of (fact version, ref), so explain derives it from the fact's parsed refs at the node's commit (`systemFileChildren`, first call and resume). .knomit/ never enters the graph or the index. This deliberately deviates from design v3 §2 item 3 (an index edge); it keeps the refs→DERIVED_FROM invariant (kb/invariants/store/refs-to-derived-from-edges/eb438c74.md) untouched.

WHAT THIS DOES NOT MEAN: a ref does not make .knomit/ writable, listable or queryable; a `system_file` ref is not "broken" for want of a fact (REST ref views give it kind `system_file`, path, no link); and the gate's tip check is a one-time write check — a file later removed from .knomit/ does not invalidate the fact (explain then shows the node `deleted: true`).

# Hermes Agent lets the AGENT author and edit SKILL.md files (skill_manage), ages them with a Curator (stale 14d, archived 30d), and stages writes for review under write_approval — but has no dedup, provenance, or cross-machine sharing of skills

Verified against Hermes docs 2026-09-13.

Skills live in ~/.hermes/skills/ as SKILL.md (agentskills.io-compatible; frontmatter name, description ≤60 chars, version, platforms, metadata.hermes.{tags,category,requires_toolsets,fallback_for_toolsets,config}). Progressive disclosure: skills_list() (~3k tokens of metadata) → skill_view(name) → skill_view(name, path) for reference files.

The agent itself writes skills: the `skill_manage` tool has create/patch/edit/delete/write_file/remove_file, and the system prompt tells the agent to record a workflow "when it worked out a multi-step workflow worth repeating" or found the working path after dead ends. A background self-improvement review after turns may create or patch a skill (files carry created_by: agent). The Curator ages agent-created skills active → stale (14 days unused) → archived (30 days); optional LLM consolidation (`curator.consolidate`) is OFF by default. With `write_approval: true` every skill_manage write is STAGED under ~/.hermes/pending/skills/ and reviewed via /skills pending|diff|approve.

Distribution: skills hub sources `official/...`, `skills-sh/...`, `well-known:https://site/.well-known/skills/<id>`, GitHub `owner/repo/skills/<name>`, raw URL; trust tiers builtin/official/trusted/community. `/learn` distills reference material into a skill.

GAPS a knowledge base could fill (community complaints + docs): skills duplicate and contradict over time; consolidation is opt-in LLM rewriting, not subsumption; a skill carries no record of WHY it exists or what evidence produced it; skills are per Hermes home, with the docs warning never to share one home between two processes.

CONSEQUENCE for knomit: an agent-authored Hermes skill maps onto a pragmatic methodology/heuristic fact (confidence, applies-to scope, refs to evidence, signed history, review gate before main). Intercept skill_manage via pre_tool_call, store as a fact, and render SKILL.md back from main on session start so Hermes's loader is unchanged. Publish knomit's own ten skills at a well-known URL so `hermes skills install` works.

WHAT THIS DOES NOT MEAN: Hermes skills are not only agent-authored — most installed skills are human-authored from the hub; the round-trip should only own created_by: agent skills unless the user opts in.

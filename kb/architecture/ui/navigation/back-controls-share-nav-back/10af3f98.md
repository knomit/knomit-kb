# Every back control — Backspace/Delete, Cmd+[, Alt+Left, the library header arrow and the timeline arrow — dispatches the identical NAV_BACK, so a back-behaviour fix belongs in the reducer, not in a control

At 0a75075b the back controls have no separate paths: the window key handler in web/src/App.tsx dispatches NAV_BACK for Backspace/Delete, Cmd+[ and Alt+Left; Library.tsx `goBack` (data-testid library-back) and LeftPanel.tsx `goBack` (timeline-back) dispatch the same action; and a trail-crumb jump (`jumpTrail`) is N x NAV_BACK. So the #486 bug (Back from a timeline losing the open fact) was one reducer defect seen through all of them, and PR #506 fixed it once in SET_AS_OF.

CONSEQUENCE: fix or change back semantics in state.ts, and cover them with reducer tests; per-control unit tests add nothing because the routing is identical (the e2e history specs check two controls end to end). WHAT THIS DOES NOT MEAN: not that each key produces exactly one NAV_BACK for free; App and Library both listen on window, and a modified arrow once fired both handlers (kb/gotchas/ui/keyboard/two-window-keydown-listeners/b7c41d6e.md).

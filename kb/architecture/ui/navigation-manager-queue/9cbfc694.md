# useNavigationManager is a thin sync wrapper that dispatches APPLY_NAV; no queue, no async pre-fetch, Library-only HEAD view

useNavigationManager (web/src/useNavigationManager.ts) is a THIN synchronous wrapper: navigate(req) calls resolveNavRequest(req, stateRef.current, dispatchRef.current) directly. It uses the stale-ref pattern (stateRef/dispatchRef updated every render) so callbacks always read current state — but there is NO queue and NO async data resolution. resolveNavRequest is marked async yet performs no fetch: it only dispatches a single APPLY_NAV action.

NavRequest has two shapes: { view: 'library' } (mode-switch — preserves the open fact, demotes any non-live anchor to asOf:{mode:'live'} because Library is HEAD-only by design) and { view: 'library'; factPath } (explicit selection — forces a live anchor). APPLY_NAV (state.ts) still applies the full nav position atomically: { view, factPath, asOf, filters?, freeText?, hop? }.

WHAT THIS DOES NOT MEAN: there is NO request queue, NO api.commitDetail pre-resolution, and NO historyCommit/factCommit/SET_VIEW machinery — those were a superseded design. View is 'library' only (no tree/chrono/history views); temporal anchoring lives in an AsOf object (e.g. { mode: 'history'; commit }), NOT in separate state fields. Only the APPLY_NAV-atomic-apply kernel survives from the original design. Verify: web/src/useNavigationManager.ts and web/src/state.ts.

# The temporal anchor is ONE global AsOf value on app state, but it governs exactly ONE thing — the open fact: the Library, search and tree are always HEAD, navigation applies the whole position atomically and demotes a non-live anchor on a mode switch, and in a lens the anchor resolves against the open fact's SOURCE MOUNT, so any surface holding a lens-originated path must read through the lens endpoint, never a repo-scoped read

A single global time-anchor value is held in application state, but every consumer that could read it except one is defined to be head-only, so the anchor's whole effect is confined to the currently open item and the question 'as of when is the collection shown' is never asked; consequently the anchor is resolved against whichever source the open item came from, and a surface that inherits an item address from a multi-source context must read through that context's own endpoint rather than a single-source one.

The pieces and how they fit:
- ONE VALUE, THREE MODES. `state.asOf` is a union of `live`, `history {commit}` and `diff {from, to}` — the middle mode is `history`, not `scrubbed`, and there is no build-time kill-switch; temporal navigation is unconditional. `factPath` stays orthogonal (WHICH fact vs AS OF WHEN, different invalidation), `SET_AS_OF` is the single mutator, `selectAnchorCommit` and `isLive` are the read surface, and the fact's loaded-at sha reads off the API's `as_of.commit` with no reducer mirror.
- IT DRIVES ONLY THE OPEN FACT. Off-live, the left panel hides the Library entirely and shows the timeline for the open fact, and the right panel re-reads that fact at the anchor; the Library, search and tree are HEAD-only always, even in single-repo mode. That is why lens browsing has NO lens-wide temporal anchor: a lens-wide anchor would answer a question the UI never asks, and the mixed-time variant would additionally make facts appear and disappear while scrubbing under first-mount-wins dedupe. `isReadOnly = serverReadOnly || !isLive` composes with the lens write rule (editable only when the open fact's source mount IS the write repo and the view is live).
- NAVIGATION IS ATOMIC AND DEMOTES. `useNavigationManager` is a thin synchronous wrapper with NO queue and NO async pre-fetch; a mode-switch request preserves the open fact but demotes any non-live anchor to live because the Library is HEAD-only by design, and an explicit selection forces a live anchor; `APPLY_NAV` applies view, factPath, asOf, filters, freeText and hop as one position.
- IN A LENS THE ANCHOR RESOLVES ON THE SOURCE MOUNT. The open fact carries its source (repo, branch); the timeline, edges, time-travel hops and the right panel anchor on that mount, never on the lens's write repo; typed at:/vs: tokens resolve the same way and warn when no fact is open. Any component that receives a fact path originating from lens browsing (trail crumbs, nav-stack entries) holds a CANONICAL `kb://<id12>/…` path and must fetch through the lens endpoint, never repo-scoped `api.fact` — the breadcrumb prefetch that did otherwise handed the write repo a raw canonical path plus a foreign mount's commit and logged server errors. Enumerated-surface sweeps miss the surface nobody listed; the reliable inventory is grepping for repo-scoped read consumers.

WHAT THIS DOES NOT MEAN: it does not preclude a future honest union-as-of-T through a per-mount timestamp parameter on the lens read endpoints — it records that no lens-wide anchor ships; the navigation manager's async signature does not mean a request queue or commit pre-resolution exists (that design was superseded, only the atomic-apply kernel survives); and anchor tokens are ephemeral controls, not persistent filter chips.

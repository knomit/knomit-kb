# Mission cross-checks never update shared facts: each writes NEW verdict facts under verdicts/<its task id>/ for exactly the paths its body lists (check: lines picked by the coordinator from git authorship), and ONE fold task, posted after the round's acks, is the only writer of the hypotheses

Shipped by PR mission-template-post-run (fixes F-R3 and F-R4 of the first mission). Parallel tasks that knomit_update the same fact in per-task experiments cannot all land (kb/gotchas/missions/experiments/parallel-updates-conflict/1133a108.md). The template therefore splits a cross-check round in two:
- Cross-checks, in parallel, each assigned to one checker: the post-task skill's verdict-format block goes in the body. The session writes one knomit_learn fact per checked fact: topic verdicts, category <task id>, body lines verdict:/target:/suggested_confidence:, refs = the target + evidence. It never updates what it checks.
- The fold: ONE task, assigned to ONE agent, posted only after every cross-check acked (Done or Failed). It reads verdicts/<id>/ per cross-check and makes one knomit_update per target (confidence; refs = current refs + verdict paths, because updates.refs REPLACES the list), moment_name 'fold: <task ids>'; strong contradictions become a new counter-hypothesis. It is the coordinator's discipline, not enforced by knomit: an early fold is safe (single writer), only incomplete.
- Paths, not 'not your own': the body lists check: <path> lines. The coordinator picks them from git: writer = `git log --diff-filter=A --format=%an -1 <consensus branch> -- <path>` (merges are not diffed); a checker's own name = the author who added a fact its earlier task wrote, or `git log --no-merges -1 --format=%an <its agent branch>`; a plain `git log -1` can return a sync merge carrying another author.

Why learn_dedup: off on verdicts AND forecast: with dedup on, knomit_learn merges a near-identical fact into an existing one, so a 'new fact' silently becomes an edit of ANOTHER agent's file, the same shared write by another route (TestMissionKB_ForecastNeverMerges / TestMissionKB_VerdictsNeverMerge show the control folding). The work-task skill's 'Shared facts' section says the same from the session's side.

# examples/mission-kb/ is the mission template's knowledge-base ontology (a sibling of examples/mission/, so copying the mission repo never carries it): a renamed-per-lane topic, forecast (hypotheses only, the hypothesis format enforced by validations, learn_dedup: off), verdicts (cross-check verdicts, validated, learn_dedup: off), syntheses, meta; no on: due trigger

Shipped by knomit PR #410 (mission-template-post-run), merged into dev at 8bbd7963. Created like the mission repo: git init, `cp -R examples/mission-kb/. <repo>/`, commit, knomit creates the repo FROM it (the ontology is read when knomit opens a repo and there is no sanctioned edit afterwards, so an existing knowledge base does not gain forecast/verdicts; mount older ones read-only in the lens instead). Attributes as the mission repo: consensus auto, conflicts {facts: merge, state: consensus}, sync realtime.

forecast validations (each refuses by rule name on knomit_learn, the dedup-merged fact, and knomit_update): hypothesis-only (type must be hypothesis, so the format cannot be dodged by writing an insight); predicted (an unindented `predicted: YYYY|YYYY-MM|YYYY-MM-DD` line naming a real period; 2026-02-30 and 2026-13 refused via a Date.UTC round trip); settles-true-if; settles-false-if (each needs a non-space value after the key: a line present but empty or whitespace-only is refused, and TestMissionKB_ForecastValidations pins that, so a rule loosened to the key alone goes red); expires-ends-period (Date.parse(expires) equals the last second of the predicted period, 23:59:59Z on its last day: compared as instants because ValidateFact runs BEFORE NormalizeExpires, so an offset form of the same instant passes; absent expires refused); granularity-in-path (the path segment before the file name is year/month/day matching the period's length).

verdicts validations: verdict (corroborate|contradict line), target (`target: <path>.md`), suggested-confidence (0..1), refs-target (some ref equals the target or ends with '/'+target, which accepts both the bare path and the server-rewritten kb://<id>/ form).

CONSEQUENCE: the post-task skill's hypothesis-format and verdict-format blocks are the text TestMissionKB_ForecastValidations / TestMissionKB_VerdictValidations fill and learn on a real instance; if the skill's block and the rules drift (e.g. bulleted lines), those tests go red. TestMissionKB_ReadmeRoute creates the KB by the README's clone route. MISREADING: 'learn_dedup: off on forecast means review skips hypotheses' is false: learn_dedup governs knomit_learn only (TestDirtyFacts_LearnDedupOffDoesNotAffectSeeds); review still seeds them.

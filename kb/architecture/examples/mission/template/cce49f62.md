# examples/mission/ is a copyable mission repo built from generic primitives only: ontology (consensus: auto + conflicts {facts: merge, state: consensus} written out), one file script per take pattern (claims.js: offer/decide/dup-check; awards.js: bid/award/take-award), inline js: expiry, two skills, and a recipe that tells the session to call knomit_skill work-task

F08 PR D. The template ships under examples/mission/ and is copied with `cp -R examples/mission/. <repo>/` (the trailing /. matters: `cp -r mission/*` drops .knomit/).

Layout (paths under the ontology root):
- tasks/<lane>/ (claim/wait/take), claims/<task-id>/<agent-id>/, inbox/<agent-id>/working/, acks/<task-id>/;
- offers/<awarder-agent-id>/<lane>/, bids/<awarder>/<task-id>/<bidder>/, awards/<winner>/ (host-awarded).
Every topic is signal-only by validation and learn_dedup: off. Triggers are per topic (the Ontology root has no triggers field): inline `js:` for expiry (`expire`, `expire-offer`, and the block-scalar `withdraw-bid`), `script: claims` for offer/decide/dup-check, `script: awards` for bid/award/take-award, `do: push` for push-claim/push-take/push-bid/push-award, `do: run recipe: work-task` for wake (match inbox/{agent}/working/**). 14 triggers, all active on a real host (TestMissionTemplate_LoadsAsIs).

Pattern 1 (claims.js): rank = FNV-1a 32-bit of `task|agent-id`, ties broken by the agent id string (total order, TestMissionTemplate_RankIsTotal). The winner takes with ONE knomit.learn(workingCopy, {retract: [task, own claims, dead claims]}); losers re-arm their claim's expires by knomit.update; a claim more than 2X past its expires no longer ranks (the re-offer). dup-check makes the lower-ranked holder of a second working copy retract its own. The claim window WINDOW_SECONDS is 360 because a peer's origin sync interval is fixed at 300 s.

Pattern 2 (awards.js): the award trigger matches bids/{agent}/**, so it runs on the awarder only; each award is the F04 move 'write awards/<bidder>/..., retract the offer', so a second award is refused by the retract precondition under the awarder's branch lock: exactly one award per offer (TestMission_HostAwardedExactlyOnce).

The recipe passes the working copy by PATH only (task_path); the prompt tells the session to call knomit_skill with name work-task. No template file names a branch (TestMissionTemplate_Settings greps for main/master/trunk/develop).

MISREADING: the template's `conflicts` block is NOT behaviourally load-bearing under consensus: auto (F20's auto default is the same values); only the static settings test pins that it is written out. CONSEQUENCE: an operator who deletes it gets the same behaviour on a knomit host, but the GitHub variant (consensus removed) MUST keep it, or conflicts fall back to off.

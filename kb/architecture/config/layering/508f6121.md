# Config layers defaults -> knomit.toml -> env; KNOMIT_HOME resolved first

config.Load() layers configuration lowest-to-highest: hardcoded Defaults() -> knomit.toml -> environment variables (each env var overlays only if set). KNOMIT_HOME (default ~/.knomit; KNOMIT_REPO is a backward-compat alias) is resolved FIRST because it is the config search root, so it cannot be overridden from inside the TOML (config.go restores Home after loading the TOML). The config file is named knomit.toml (NOT config.toml) and is searched next to the binary, then at KNOMIT_HOME/knomit.toml (findConfigFile). In the TOML, home/host/port/socket/ontology_root/onnx_lib_path/local_origin_root/methodology_min_score are BARE top-level keys (the home key is spelled `repo`); the rest are tables: [llm], [embeddings], [git], [remote], [cluster_cache], [session], [discovery]. Key defaults: host=localhost, port=19278, ontology_root=kb, embeddings.model=embeddinggemma, llm.provider=gemini/model=gemini-2.5-flash, git.serve=true. Malformed numeric/duration env values fail at boot rather than being ignored. Some knobs are env-only (no TOML key): KNOMIT_REFLECT_PROPOSE_CAP, KNOMIT_REFLECT_NOVELTY_THRESHOLD, KNOMIT_PPROF_ADDR, KNOMIT_BASE_URL, KNOMIT_MCP_DEBUG.

WHAT THIS DOES NOT MEAN: the config file is NOT `config.toml` — a config.toml dropped next to the binary or in KNOMIT_HOME is silently IGNORED. The filename is knomit.toml (config.go findConfigFile).

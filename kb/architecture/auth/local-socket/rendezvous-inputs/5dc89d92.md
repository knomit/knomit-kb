# Server and bridge compute the local listener path INDEPENDENTLY, so every input one process evaluates on its own (environment, cwd, executable location, validation scope, time of reading) is a silent divergence channel — each known channel is excluded, isolated, normalised, refused, routed through one function, or documented

Two processes that must arrive at the same rendezvous by computing it separately will diverge whenever any input is evaluated per-process rather than shared. Because the fallback on a miss (TCP) succeeds, the divergence costs the verified identity without raising any error. So the design rule is: the rendezvous may depend only on inputs both processes are guaranteed to see identically, computed by one function. Every per-process input must be deliberately excluded, isolated, normalised, refused or documented.

How each channel is handled (details and evidence are in the members):
- EXCLUDED: environment variables an MCP host may filter from the bridge. The long-root fallback uses the LITERAL /tmp/knomit-<euid>, never TMPDIR, XDG_RUNTIME_DIR or os.TempDir (long-home-fallback decision).
- EXCLUDED: executable location. findConfigFile reads only `<home>/knomit.toml`; the lookup beside os.Executable() was removed. `knomit serve` and the desktop warn after log setup if a file is still there (toml-beside-executable gotcha).
- ISOLATED: failures unrelated to the socket. config.SocketPath deliberately does NOT call config.Load, because Load's Validate and every other KNOMIT_* parse would turn an unrelated config problem, or a bridge launched with a different environment, into a silent TCP fallback (socket-path-not-load gotcha). Misreading to avoid: 'the bridge should just call Load to be sure it agrees'. Agreement comes from the shared functions, not from sharing Load.
- NORMALISED: a leading `~` in the data root is expanded, once, in config.ResolveHome, for every caller including the bridge's credentials. On unix a `~` in an explicit socket value is expanded inside socketFor.
- REFUSED: working directory. A data root still relative after ~ expansion is refused by ResolveHome. An explicit socket (KNOMIT_SOCKET or TOML `socket`) that is not position-independent is refused by socketFor: on unix, not absolute; on Windows, not a `\\.\pipe\` name, which is also the only form auth can listen on. Both are refused on every side with the same message rather than absolutised. `filepath.Abs` is consistent only within one process.
- ONE FUNCTION: the layering itself. config.socketFor (KNOMIT_SOCKET > knomit.toml socket > localListenerName(home)) is reached by both config.Load and config.SocketPath, both starting from config.homeAndConfig; the bridge resolves no layer itself (listener-layering invariant).
- DOCUMENTED: two channels are documented on the Config.Socket field rather than closed.
  - Time of reading: the server resolves once at startup and the hooks per dial, so a socket edit takes effect only after a server restart; until then the hooks use TCP without the verified identity. Only a server-published location could close this, and that is deferred.
  - The user's HOME: `~` expands against each PROCESS's HOME, so a service-run server and a user bridge can still disagree.

CONSEQUENCE: when adding any input to how the listener is located, first ask whether BOTH processes evaluate it identically. If not, it must fall into one of the treatments above before it ships, and the treatment belongs inside ResolveHome, homeAndConfig or socketFor, never in one resolver. A single-process test cannot see this class; only an agreement test that computes both sides (Load().Socket == SocketPath()) under the varied input can.

WHAT THIS DOES NOT MEAN:
- Not that the server and bridge must share a process or a config object. They share functions and inputs, deliberately not Load.
- Not that making a path absolute inside each process makes the processes agree. Refusal is the treatment for cwd-relative input.
